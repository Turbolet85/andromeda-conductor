## Surface: cli

**Tooling context:** clap 4.5 (`conductor-cli` / `scripts/agent-run.sh`) + `owo-colors` 4.x with `std::io::IsTerminal` (styling, TTY-gated per stream) + `indicatif` 0.18 (live counters / spinner) + `comfy-table` 7 (P-ID SLO tables) + `inquire` 0.9 (operator-pause prompts). Line-oriented (ratatui full-TUI deliberately omitted).

**Expression level (this surface):** 0.3 — colored headers, dimmed metadata, `indicatif` honest progress (spinner appears only after ~200ms), `comfy-table` SLO tables. No cursor manipulation, no full-screen redraw, no animate-to-100%. Motion is honest progress feedback, never live-redrawn dashboard animation (per design-system Motion).

**Signature placement (Paused-count hold-point, named on ≥2 distinct components):**
1. **`indicatif` heartbeat spinner** (primary mirror) — during a run the spinner carries the count/heartbeat with a colored phase-line prefix (ANSI 114, the `count-nominal` mapping); on the operator-pause it **STOPS in place (not hides, not animate-to-100%)** at the exact value. The stop is the signature — "paused count shows where it stopped."
2. **HOLD phase line above the `inquire` prompt** — a bold amber (ANSI 179, the `count-hold` mapping) `HOLD — operator pause` line printed **above** the proceed/abort confirm, carrying the frozen count value as text so the held number is legible at the decision point, not just in the stopped spinner.
3. **Results / SLO table caption** (reinforcement) — when a run is held, the `comfy-table` summary is captioned with the frozen step-index in the hold-amber mapping, echoing where the count stopped for the agent reading the artifact.

Every status above is **paired with an ASCII text prefix** (`[PASS]` / `[HOLD]` / `[FAIL]` / `[BLOCKED]`, `✓`/`✗`/`→`/`•`) so the signal is never color-alone and survives `NO_COLOR` / piping / screen readers — this is a stated requirement; a11y / NO_COLOR compliance derives from it.

### Primary screens (commands)

- **`conductor run <scenario>`** — drive one scenario: colored phase headers → live `indicatif` heartbeat → `inquire` operator-pause holds (interactive TTY only) → per-P-ID verdict lines → `comfy-table` SLO summary → run-report path.
- **`conductor suite`** — drive the full coverage suite across the manifest’s accepted set, MCP preflight readiness gate first, then the same run flow, ending in the dense coverage table. **The operator stop** (2026-10-12): after preflight, before driving, the suite takes Ctrl-C — the first prints the stop-requested line on stderr and the suite stops before its next scenario: the spinner is abandoned in place, the envelope caption and results table print over the kept records, `suite stopped: {kept} of {total} scenarios kept` prints on stderr, and the exit is 130. A second Ctrl-C exits 130 at once. A completed suite still exits on the hard-Fail rule.
- **`conductor report <run_id>`** — re-print a stored run as a colored `comfy-table` results view (reads the per-run JSONL journal; the on-disk `<run_id>.md` artifact stays Markdown), pipe-friendly. After the `Run report <id>` line and a blank line it prints the stored run's `[ENVIRONMENT-SUSPECT]` load-envelope caption once when that run's stored standing is suspect (2026-10-12; no flag, no new lamp, label or column), then the unchanged six-column table.
- **`conductor preflight [--json]`** — the MCP readiness gate (no longer boot's FIRST act — the probe below leads, and short-circuits past this gate only when a subject is genuinely unmet): emits the `ReadyState` JSON (or a `[PASS]`/`[BLOCKED]` line) and exits 0 iff `ready:true`, non-zero on a Blocked precondition. **`agent-run boot` REACHES it** — the leading probe runs first and short-circuits only on a genuinely unmet subject; on exit 0 boot proceeds here and emits the `ReadyState` JSON, measured in the full shipped shell SET (`scripts/agent-run.sh` 2026-09-04T17:07:17→17:08:04Z · `scripts/agent-run.ps1` 17:11:16→17:12:03Z, both exit 0 with `ready: true`, zero `skipped preflight` lines, neither script edited; `conductor-0.2.0/chunks/2026-09-04-preconditions-probe-reads-path-handles-by-presence/report.md`). Invoking this verb directly remains a valid entry point, not a forced workaround.
- **`conductor preconditions [--for <SCENARIO>] [--json]`** — the non-mutating live-Pulse probe run BEFORE a leg is scheduled: `:4317` reachability as a connect-and-drop client, `andromeda-pulse-mcp` resolved over the inherited `PATH` without spawning, and the three `ANDROMEDA_PULSE_*` handles read for an affirmative declaration under the deterministic posture — the flagless default. `--for` (2026-09-22) takes a scenario NAME — a `P-NNN`-shaped value is refused at argument parsing (a clap usage error, exit 2), because a P-ID can name several scenarios — and grades the handles under that scenario's declared `l4_posture`: under `real-model` the L4 handle is read for ABSENCE instead, its unmet line reading `declared in this environment, but the real-model posture requires it absent or falsy`. Exits 0 iff every subject is satisfied, non-zero otherwise (the documented `preflight` go/no-go exception, not the scenario-verdict rule) — and **exit 0 IS reachable**: each handle is graded by its own KIND, the PATH-valued member by presence-after-trim and the flag-valued members by an affirmative `"true"`/`"1"`, so `handles-declared` is satisfiable (as measured at `conductor-0.2.0/chunks/2026-09-04-preconditions-probe-reads-path-handles-by-presence/report.md`, 2026-09-04T17:07Z) — and under a `--for` real-model scenario the L4 flag is unmet when EITHER side's truthiness rule declares it (Conductor's `true`/`1` ∪ Pulse's `1`/`true`/`yes`, trimmed and ASCII-lowercased), every other handle graded as before; exit 0 was measured reachable under that posture too (2026-09-23). Both arms of the `[PRECONDITION]` caption are shipped, measured behaviour: ANSI 246, one line per unmet subject naming its statement and candidate causes when any subject is unmet, and the single satisfied line (`[PRECONDITION] every live-Pulse precondition is satisfied`) when none is — so a reader keying on the bracket label must not read it as failure-only. Mints no `Verdict`, no `ReportState` and no per-P-ID row. It fires no canary, so it primes none of the SUT state a preflight would.
- **`conductor coverage [--write]`** — render the static capability-coverage matrix over the manifest's accepted set (`coverage_matrix()` — P-ID / title / category / mode, the definition-of-done classification) as a **4-column** `comfy-table` (P-ID · Title · Category · Mode — no verdict/state column, so no bracket prefix; distinct from the 6-column results/SLO table below); `--write` regenerates `coverage-matrix.md` at the repo root. The table terminates in a **roll-up caption** naming the in-scope denominator beside the full row count — `82 capabilities · 66 in scope (43 auto (N unbacked) · 16 drive+observe · 7 static-only) · 16 not-conductors` — every number manifest-derived (never a literal), the per-mode counts still summing to the row count. The `(N unbacked)` parenthetical **qualifies the auto term only** — `Auto`-classified capabilities no scenario yet names (`conductor_core::UNBACKED_AUTO`, held to the catalog by `check_scenario_backing`). It is a qualifier, **never a fifth summand**: those rows are still classified auto, so counting them separately would break the sum. Plain text, no new token / ANSI / colour, and it is omitted entirely when the count is zero. Rendered identically on both surfaces (the Markdown artifact and the cli), and the out-of-scope token carrying the recessive `status-residual` ↔ ANSI 246 tint over its always-printed label. The same roll-up shape renders on both surfaces (Markdown artifact · cli).
- **`conductor scenarios`** — the scenario catalogue listing (2026-10-12): every scenario loaded through `list_scenarios` and checked against the capability manifest, rendered as a **3-column** `comfy-table` (Scenario · P-IDs · SLO — P-IDs in the ID-cyan mapping behind the stdout TTY gate; no verdict/state column, so no bracket prefix; the one table sized to the terminal width), then a plain roll-up line — `1 scenario` for one, `N scenarios` otherwise, counted from the catalogue, never a literal. An empty catalogue prints `No scenarios found.`; exit 0. An absent or malformed capability manifest is a harness fault (`error:` + `hint:`, exit 1). It takes no argument and mints no token, bracket label or ANSI entry.
- **`conductor cleanup <run_id>`** — the teardown verb (2026-09-06): removes one stored run's rows from all three `runs.db` tables in a single transaction (`RunsDb::delete_run`), printing a plain confirmation line carrying the removed row count with the run id in the ID-cyan mapping. Idempotent — a second call removes nothing and is not an error. Mints NO bracket label, no lamp, no `ReportState` and no new token or ANSI entry; it never prompts, so the headless path stays unblocked. The `run_id` binds as a SQL `?1` parameter only and is never joined into a path (unlike `report`). This is the mechanism `scripts/agent-run.{sh,ps1} cleanup` now invokes behind its existing run-id guard — the shells issue no SQL of their own.
- **`scripts/agent-run.{sh,ps1}`** (both shells ship at identical semantics — test-plan §3; a property of the SCRIPTS together with the invoking environment, since a caller preempting native-command exits diverges the `.ps1` leg with zero script delta — measured 2026-09-07) — the headless, agent-driven source-of-truth path (the 5-command `boot`/`run`/`status`/`cleanup`/`logs` harness; `run` takes `--unit`/`--integration`/`--live` stage flags, default = the full bundled gate). **`--live` is the operator-gated live-Pulse suite** (2026-09-06) — a sibling stage flag, never a sixth command, reachable from no default or CI path. It leads with the non-priming `conductor preconditions` probe: an unmet subject REFUSES the suite at exit 1, printing one host-path-free `[PRECONDITION]` line per unsatisfied subject with its candidate causes, and no leg fires. A third-token selector (2026-09-22) picks the other shape: **`--live real-model`** runs the ONE operator-gated real-model leg (`real-model-interpretation`) instead of the suite, leading with `conductor preconditions --for real-model-interpretation` and refusing the same way; an unknown selector prints `usage: <script> run --live [real-model]` and exits 2 before any probe, in both shells — a selector of `--live`, neither a sixth command nor a new stage flag. `--unit`/`--integration` and the bundled default are same-engine cli legs, TTY-gated so artifacts stay clean and the operator-pause is **never** blocked on an interactive prompt. The `--e2e` webview stage left with the window (2026-10-11); the token now falls to the unknown-token `usage:` exit 2 in both shells.

### Component — Header / banner

The header is printed once per command (never an always-on banner — that wastes terminal real-estate): `CONDUCTOR` + the verb + the scenario/suite + `seed <n>`. Section title is **bold + ANSI 117** (the `color-id-cyan` mapping); the `seed` / metadata is dimmed (ANSI 146, the journal-text mapping). The MCP preflight readiness line follows — protocol version, tool count, canary result — with the negotiated identifiers in ANSI 117 and an `[OK]` / `[BLOCKED]` prefix so the gate reads without color. All styling routes through `owo-colors` gated by `std::io::IsTerminal`, decided independently for stdout and stderr, so output auto-strips ANSI when piped and honors `NO_COLOR` / `TERM=dumb` (a stated requirement; NO_COLOR compliance derives from it).

### Component — Primary navigation (verb structure)

Linear, top-to-bottom stdout — no cursor manipulation, no full-screen redraw (ratatui omitted). Verb-noun via clap: `conductor {verb} {arg}`, flat, one level deep — the verb SET is whichever `Commands` (`crates/conductor-cli/src/cli.rs`) declares, enumerated in §Primary screens below and never baked as a sample here. Help is verb-prefixed (`conductor --help` shows the verb table; `conductor run --help` shows verb flags) — never a separate man page or wiki link; the clap verb table renders flags in the ID-cyan mapping, descriptions in the default foreground. The operator's path is fixed: colored header → live `indicatif` heartbeat → `inquire` operator-pause holds (interactive TTY only) → `comfy-table` coverage/SLO summary → run-report path. Pipe-friendly throughout: raw artifact data is parseable on stdout, human messages route to stderr, and the headless agent path strips ANSI and **never blocks on a prompt** (an interactive gate there would silently break the release gate).

### Component — Hero / signature output (Paused-count hold-point — CLI mirror)

The CLI's hero is the decision moment: the operator-pause go/no-go, line-oriented.

- **`indicatif` heartbeat** carries the count + step index + a live counter with a colored phase-line prefix (ANSI 114, the `count-nominal` mapping). The spinner appears only after ~200ms (honest progress, not instant churn).
- **On the operator-pause**, the spinner **STOPS in place at the exact value** — not a hide, not an animate-to-100%. A bold **ANSI 179** (`count-hold` mapping) `HOLD — operator pause` phase line prints **above** the `inquire` proceed/abort confirm, carrying the frozen count as text (signature placement #2). The stop is the signature — it embodies "paused count shows where it stopped."
- **Checklist lines** (2026-10-12): on the interactive hold, each declared `[[checklist]]` item prints two indented plain lines on stderr between the HOLD phase line and the confirm — `  induced: {induced}` / `  observe: {observation}` — no color, no bracket label, while the spinner is suspended; the headless (non-TTY) path prints none.
- **`inquire` confirm** is gated behind an `isatty` check: an interactive operator gets the colored proceed/abort confirm; when stdin is not a TTY (the agent-driven `agent-run.sh`), the prompt is **skipped** per the configured non-interactive policy and the decision is recorded to the artifact — the headless source-of-truth path is never blocked. The proceed/abort decision is logged to the run report.

Expression rationale: the stop — the deliberate halt of an otherwise-honest spinner — is the 0.3-budget signature; the held silence is the event.

### Component — Primary content block 1 (results / SLO table)

The **`run` + `suite` per-check table.** `comfy-table` with exactly **6 columns**, sized to their content (never hardcoded, never wrapped at arbitrary points, no terminal-width detection): **P-ID** (ANSI 117, the `color-id-cyan` mapping) · **scenario** · **state** (`[PASS]` / `[HOLD]` / `[FAIL]` / `[BLOCKED]` colored prefix — ANSI 114 / 179 / 203 / 60) · **slo_tier** (`<5s` / `<20s` / `<90s`) · **latency_ms** (ANSI 117, right-aligned) · **fingerprints** (ANSI 117). The header row is dimmed. A **`Blocked` row** carries the named precondition string in its detail; its measurement columns render as `—` / null, **never a red error** (`Blocked` ≠ red — never measured). The summary caption rolls up the tally with each count in its status-color mapping and, while a run is held, echoes the frozen step-index in the hold-amber mapping (signature reinforcement #3). Every state cell pairs its color with the bracket prefix so it survives `NO_COLOR` and piping.

**The coverage matrix is a separate, narrower table** — `conductor coverage` renders **4 columns** (P-ID · Title · Category · Mode), sized to their content, with no verdict/state column and therefore no bracket prefix, terminating in its own roll-up caption (§cli Primary screens). **The scenario catalogue is a third shape** — `conductor scenarios` renders **3 columns** (Scenario · P-IDs · SLO), no state column and no bracket prefix, the one table sized to the terminal width, ending in its `1 scenario` / `N scenarios` roll-up line. None of the three is to be conflated with another: the 6 columns above are the results/SLO shape.

### Component — Primary content block 2 (verdict / report-state lines)

Per-P-ID result printed in place, one line each, color always paired with an ASCII prefix:

- `✓ P-009  Pass   1840ms <90s` — `[PASS]`, ANSI 114 (`count-nominal` mapping).
- `⚠ P-008  CalibrationRegion  <20s` — `[HOLD]`, ANSI 179 (`count-hold` mapping) — the calibration-region bucket, never silently a Fail.
- `✗ P-015  Fail  4120ms <slo_tier>` — `[FAIL]`, ANSI 203 (`status-fail` mapping), **no blink** (the tier cell renders the scenario's TOML-declared value from the closed set).
- `? P-035  Manual  halo→burgundy? · no OS toast?` — `[MANUAL]`, ANSI 146 (neutral lavender) — an operator-checklist item (no programmatic read-back; TTY: `inquire` y/n, headless: recorded unconfirmed), never a machine verdict.
- `~ P-032  Residual  recent_commits stub → v0.3.0` — `[RESIDUAL]`, ANSI 246 (muted) — a measured, pre-accepted gap, **never red**.
- `• P-003  Blocked  mcp-server feature + ANDROMEDA_PULSE_MCP_ENABLED + matching data-dir` — `[BLOCKED]`, ANSI 60 (`count-blocked` mapping), with the named precondition; measurement fields render `—` / null.

Those six are the complete set of **per-P-ID verdict / report-state** bracket labels, and the lamp set is closed at six. Each surface additionally carries a **run-level, non-lamp** qualifier SET, printed outside the lamp column — on cli that is `[ENVIRONMENT-SUSPECT]` (load-envelope, once per run) and `[PRECONDITION]` (the `conductor preconditions` probe — one line per unmet subject, or the single satisfied line when every subject is met; both arms are reachable, so it is not a failure-only label) (the `not-conductors` Mode-cell precedent in §Primary content block 1) — a SET adapted per surface, never forked: cli stdout's `[ENVIRONMENT-SUSPECT]` bracket label in ANSI 246 and the Markdown report's banner. It qualifies the run rather than reporting a check, so it is neither a seventh lamp nor a sixth `ReportState`; a parser keying on state labels should read the per-P-ID set plus that non-lamp qualifier SET.

P-IDs, `run_id`, slo_tier, latency_ms, and fingerprints render in the ID-cyan mapping (ANSI 117); report body / dimmed metadata in ANSI 146 (the journal-text mapping). This is the supporting verdict convention, line-oriented.

**Per-check detail region (`runs/<run_id>.md`).** Beneath each P-ID verdict line the Markdown run report carries one INDENTED plain-text line per expected check — that check's ordinal, its comparison kind, its own verdict, its own `latency_ms`, and the deadline it was judged against (its declared budget, or the scenario tier's when it inherits). It is the indented-detail-line precedent (the `Blocked` precondition string, the `KnownResidual` note), applied to the per-check grain: **no new column, no new bracket label — the lamp set stays closed at six — and no new ANSI or token entry.** cli stdout and the 6-column results/SLO table are unchanged; a scenario that graded nothing (blocked, or declare-only) contributes no such line.

### Component — Footer / terminator + error output

- **Terminator:** a single closing line naming the artifact destination — `run report → runs/<run_id>.md` — in the dimmed mapping (ANSI 146), the path left un-colorized when piped. No persistent footer between commands; terminal scroll is the natural footer.
- **Error output** goes to **stderr**, sanitized per the security plan (no absolute host paths / internal struct names / stack traces): `error: <short>` + contextual detail + `hint: <fix>`. Never colorized when piped; stack traces only under `--debug` / `-v`. stdout stays reserved for raw artifact data so a downstream agent parses it cleanly — stdout (data) and stderr (messages) are never mixed without intention.

### IA notes

- **Command model:** verb-noun, flat (one level), help verb-prefixed; output structure is stable across versions because downstream agents parse it — adding a `comfy-table` column without a `--format` flag would be a breaking change.
- **Pipe discipline:** raw artifact data on stdout, human messages on stderr; ANSI auto-stripped when piped; `NO_COLOR` / `TERM=dumb` honored; emoji never used in machine-parseable (piped) output — ASCII prefixes (`[PASS]`/`[FAIL]`/`[HOLD]`/`[BLOCKED]`) only there.
- **Headless invariant:** interactive `inquire` prompts always check `isatty` first; the agent-driven source-of-truth path is **never** gated on a prompt (an interactive gate there would silently break the release gate).
- **Contrast discipline:** ANSI 117 cyan + 114 green chosen for legibility on dark terminals; dark-blue-on-black / dark-red-on-black avoided.
- **Token coordination:** the ANSI codes bind the design-system palette by token name — `count-nominal` → ANSI 114, `count-hold` → ANSI 179, `status-fail` → ANSI 203, `count-blocked` → ANSI 60, `color-id-cyan` → ANSI 117, journal-text → ANSI 146.
- **No URL coupling:** the cli addresses runs by verb and `run_id`, never by URL or deep link.
