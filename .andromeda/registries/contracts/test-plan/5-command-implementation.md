### 5-command implementation

**`boot`** — precondition probe, then preflight readiness gate (no daemon to start):
- Leading arm: `cargo run -p conductor-cli --bin conductor -- preconditions` — non-zero on an unmet subject SHORT-CIRCUITS `boot`, skipping the preflight invocation (and its two derived timeout budgets) rather than paying it; no `ReadyState` JSON is emitted. Identical semantics in `.sh` and `.ps1` — the short-circuit is environment-CONDITIONAL, firing only on an actually-unmet subject (measured 2026-09-04, both shells exit 0 and emit `ReadyState` JSON under a satisfied environment; the 2026-09-03 both-shells-exit-1 witness measured the pre-fix state, when the subject could not be met). The probe mints no `Verdict`, `ReportState` or per-P-ID row, so the envelope / status-read / JSONL shapes are untouched and §3 ↔ obs-plan §3 still agree.
- Command body (**reached through `boot`** — the leading probe's `handles-declared` subject is satisfiable, so `boot` proceeds here and this body plus its two derived timeout budgets are paid; measured in the full shipped shell SET at `conductor-0.2.0/chunks/2026-09-04-preconditions-probe-reads-path-handles-by-presence/report.md`: `scripts/agent-run.sh` 2026-09-04T17:07:17→17:08:04Z and `scripts/agent-run.ps1` 17:11:16→17:12:03Z, both exit 0 with `ready: true` / `canary_round_trip: "ok"` and zero `skipped preflight` lines. Invoking it directly remains valid, not required): `cargo run -p conductor-cli --bin conductor -- preflight --json` — runs the MCP `initialize` handshake through the hand-rolled JSON-RPC client over the spawned sidecar's stdio (arch Standard Contracts: asserts the `protocolVersion` read back from that result against the pinned `2024-11-05`, required-tool presence vs. pinned `contracts/` manifest, then round-trips a canary incident via `query_incident_list` to prove data-dir wiring). In CI the live-Pulse leg is unavailable, so `boot` runs against the hand-rolled `stub_pulse_mcp` child binary (test-research Mocking) which returns a `ready:true` canary; the live-Pulse leg is `workflow_dispatch`/local-only gated on `ANDROMEDA_PULSE_MCP_ENABLED`.
- Readiness signal: stdout JSON `{"ready": true}`; `ready:false` ⇒ every dependent scenario reports `state="Blocked"` with the named precondition string (security anti-pattern: never silently downgrade a failed preflight to pass/fail/manual-check).
- Exit code: 0 on `ready:true` within timeout; non-zero on handshake failure (transport refused surfaces as `Result::Err`, a harness fault — security Vector 5).
- Timeout: **two budgets, both derived — never a literal.** (a) The *in-process* canary poll: `CONDUCTOR_PREFLIGHT_TIMEOUT` seconds (default 30) for the MCP `initialize` + canary round-trip, raised to the run contract's effective floor — `contracts/pulse-run-contract.toml` `[incident_formation].min_canary_poll_seconds`, which must outlast Pulse's L3 digest cadence — so the live-Pulse leg must allow at least that floor. (b) The *wall-clock wrapper* `scripts/agent-run.{sh,ps1}` `boot` applies around `conductor preflight`: both shells derive it per invocation from the same contract as `warmup_ms/1000 + poll + margin`, because the warm-up pre-roll runs BEFORE the poll starts and a wrapper set to the poll alone kills the run mid-poll. A missing contract term is a hard exit 2, never a silent default; a lowered `CONDUCTOR_PREFLIGHT_TIMEOUT` clamps up to the floor. The stub leg still completes in <1s (it drives `CanaryPoll::immediate()`, so no real clock is involved).

**`run`** — invoke test suites + scenario catalog:
- Command body (CI build+test gate, arch CI/CD): `cargo nextest run --workspace --profile ci` (cargo-nextest 0.9.137 → JUnit XML at `.config/nextest.toml` `[profile.ci.junit]`) then `cargo test --workspace --doc` (nextest does not run doctests — test-research baseline-fallback note) then `cargo clippy --workspace --all-targets -- -D warnings`, then (since 2026-10-04) the two feature-gated lint lines `cargo clippy -p conductor-verify --features stub-server --all-targets -- -D warnings` and `cargo clippy -p conductor-run --features live-pulse --all-targets -- -D warnings` — they compile and lint the `stub-server` and `live-pulse` targets, which the workspace pass never builds, and never run them; identical in both shells, and CI reaches them through the `rust` job's dogfood step. Scenario invocation: `cargo run -p conductor-cli --bin conductor -- run <scenario|P-ID> [--seed <s>]` for the named dynamic scenarios (`error-baseline-spike`, `fingerprint-storm`, `restart-suppression`, `pii-scrub`, `connection-lifecycle`, `severity-lifecycle`) and per-P-ID scenarios; `conductor suite` for the full catalog. A P-ID target resolves only where ONE scenario names it: `run` (and the harness's `SCENARIO=`, passed straight through) REFUSES a P-ID that several scenarios name, before any scenario load — a harness fault naming the P-ID, the count and the matching scenario stems (never a host path), rendered as `error:` + `hint: pass one of the named scenarios instead of the P-ID` at exit 1 (`cli_smoke::run_refuses_a_p_id_named_by_several_scenarios`) — and several P-IDs are named by more than one scenario (seven at 2026-09-30, P-018 among them), so name the scenario; a single-owner P-ID still resolves. `preconditions --for` refuses a P-ID outright, at argument parsing. The harness scenario leg (`SCENARIO=<name|P-ID> [SEED=<n>] scripts/agent-run.{sh,ps1} run`) appends `--seed` ONLY when `SEED` is explicitly set — with it unset the TOML-declared seed governs (arch files-over-env-defaults precedence; identical `.sh`/`.ps1` semantics) and the envelope records the effective seed.
- Exit code semantics: 0 = all checks `Pass`; non-zero = at least one hard `Fail` (cargo-nextest `NextestExitCode` 100); `blocked`/`ManualCheck`/`KnownResidual`/`CalibrationRegion` are reported states in the envelope, NOT process-failure exits (Creator Brief assertion-policy split: model-interpretive claims are "calibration-region checks + report-for-human, never hard-failed").
- Output format: machine-parseable — cargo-nextest `ci` profile JUnit XML (parsed by `dorny/test-reporter` into PR annotations) for the test gate; the Run-report envelope JSONL/`runs.db` row for the scenario leg.
- Test selection (fast iteration): `cargo nextest run -p conductor-<seam>` for a single seam crate; `cargo nextest run -E 'test(<name>)'` for a single test; `conductor run <scenario> --seed <s>` for one scenario (a P-ID target resolves only where a single scenario names it; a P-ID several scenarios name is refused, naming them — see `run` above).
- CI stage selectors: the `run` command takes mutually-exclusive `--unit` / `--integration` / `--e2e` flags so the Section 9 pipeline can split it into parallel stages — plus, since 2026-09-06, the operator-gated `--live`, which is NOT a CI stage and is reachable from no default path (a sibling `case` branch on `run`, so the 5-command discipline holds and both shells ship it at identical semantics). `--live` takes an optional third-token SELECTOR (2026-09-22) and composes one of two shapes. **Bare `--live`** is the live-Pulse suite: a leading non-priming `conductor preconditions` probe (an unmet subject refuses at exit 1 with `[PRECONDITION]` lines and no leg fires) → the ordered leg set the shells' own `live_leg_order` owns — at 2026-09-07 that is leg H (`halo-hue-encoding`, budget `live_leg_budget_sec 180`, first because its sustained stream must not sit inside leg A's silence window) → leg B1 → leg B2 → a 150 s quiet window → leg A → the driven a11y arm (read the order from `live_leg_order` in `scripts/agent-run.{sh,ps1}`, never from a count restated here) (`ensure_frontend` + the release build with `--features tauri/custom-protocol` → `npm run a11y:driven`), freezing each leg's `logs/agent-latest.jsonl` to `runs/live-suite/{leg}.jsonl` because that sink truncates per invocation. **`--live real-model`** runs the ONE real-model leg instead of the suite: `conductor preconditions --for real-model-interpretation` (the scenario's real-model posture requires the L4 handle absent or falsy under the union truthiness rule; an unmet subject refuses at exit 1 and no leg fires) → a pre-build of the capture binary → the non-recursive removal of `runs/live-suite/{rm.jsonl,rm-capture.txt,rm-capture.err}` → the grading rule's `rule_record` into `rm-capture.txt` BEFORE the leg (a non-zero exit stops the arm, so no counted drive of the series is spent) → `live_leg rm real-model-interpretation` → the `real_model_live` capture (stdout appended, stderr to `rm-capture.err`, `RUST_LOG` removed for both test invocations) → printed reminders. An unknown selector prints `usage: <script> run --live [real-model]` and exits 2 before any probe, in both shells; `boot` keeps the flagless probe. It adds no port, env var or `CONDUCTOR_*` handle, and leaves the envelope, the `status` disk read and the JSONL shapes untouched — so §3 ↔ obs-plan §3 still agree (`--unit` ⇒ the `cargo nextest run --workspace --profile ci` leg only — `cargo test --workspace --doc` and `cargo clippy` are their own separate Section 9 stages (Doctest / Lint), NOT folded into `--unit`; `--integration` ⇒ the hand-rolled MCP stub + `tauri::test` mock-runtime + in-memory/`TempDir` `runs.db` leg; `--e2e` ⇒ ensure-frontend, then a release build with `--features tauri/custom-protocol` (a plain `--release` binary loads `devUrl` and measures nothing — the feature, not the profile, decides bundle embedding), then the tauri-driver `wdio run` leg — the ROUTINE suite only (wdio default `specs` narrowed to `accessibility.e2e.ts` on 2026-09-01; the `driven` suite sits outside the 5-command harness as the operator leg described in §6/§9. **Since 2026-09-07 both shells ASSERT THE PRINTED VERDICT, not the exit code** — the leg's exit cannot separate a full pass from a total skip, because the handle guard is designed to skip at exit 0 — **and that contract holds only where the INVOKING environment does not preempt the capture-then-print: a PowerShell caller setting `$PSNativeCommandUseErrorActionPreference = $true` turns wdio's non-zero into a terminating error at the `npm run a11y` call, before the script prints the captured output or reaches its assertion, so the caller sees one `NativeCommandExitException` line and none of the verdict (as measured at `2026-09-07-sr-findings-fixed`, with a local control both ways; a third skip is a failure, which is how a fixture-seeding failure surfaces), and the `[webview2 … windows]` driven-session banner. The leg also emits one violation record per run at `runs/a11y/<run_id>.jsonl` — a SEPARATE artifact whose shape is this §3 envelope's eleven fields PLUS the obs §9 resource tags, deliberately outside the harness's non-recursive `"$RUNS_DIR"/*.jsonl` glob so `status` cannot read it as a scenario run. The command count stays five, no stage selector was added, and the `status` disk read and per-run envelope/JSONL shapes are untouched — so §3 ↔ obs-plan §3 still agree), with the tauri-driver child spawned at `cwd` = the workspace root so the app's `resolve_under` can reach `scenarios/` (it rejects absolute paths and `..`, so the launch cwd is the only lever), and the mocha ceiling raised 60s → 15min because wdio enforces `mochaOpts.timeout` itself — headless under `xvfb` on Linux CI, headful on the Windows host). **The leg SEEDS its own subject before the session** (2026-09-02): `wdio.conf.ts`'s `seedFixtureRuns()` clean-re-creates the gitignored `runs/e2e-fixture/` and invokes `cargo test -q -p conductor-run --test envelope_fixture` with `CONDUCTOR_E2E_SEED_DIR` naming that repo-relative dir, so the subject — the committed lamps journal's records PLUS an over-envelope `run_envelope` row — is written through the production writer (`conductor_run::persist`) rather than copied; a non-zero exit or a missing journal THROWS rather than seeding silently. **`status`** — query product state (disk artifact read; no listener):
- Command body: `jq -e '<predicate>' runs/<run_id>.jsonl` for a shell-level CI smoke gate (jq -e exits 1 on a `false`/`null` last output, 4 on parse error — test-research serde_json+jq), OR an in-process `rusqlite::Connection::open` + bound-parameter `SELECT` of the `runs.db` row for typed assertions. **The journal read targets the NEWEST ENVELOPE line — never the file's last line**: the journal carries two report-seam record shapes (§3 Log format), so a run that graded checks ends on a `CheckRecord` and an unqualified last-line read reports ITS fields as the envelope (measured 2026-09-06: `seed: null`, `slo_tier: null`, exit 0). Both shells select that line by the envelope-only `seed` key (`jq -s` filtering `has("seed")` · `Where-Object { $_.PSObject.Properties.Name -contains 'seed' }`). No `curl`/HTTP — there is no inbound listener.
- Polled fields: the Run-report envelope (see Status endpoint shape below) — `run_id`, `seed`, `scenario`, `p_ids`, `verdict`, `state`, `latency_ms`, `slo_tier`, `journal_emitted_at`, `read_back_observed_at`, `fingerprints`.

**`cleanup`** — tear down per-run artifacts:
- Command body: `rm -f runs/<run_id>.jsonl runs/<run_id>.md` in the shells, then `conductor cleanup <run_id>` — **the shells issue no SQL** (2026-09-06). The three bound-parameter deletes (`DELETE FROM runs WHERE run_id = ?1`, `DELETE FROM run_check WHERE run_id = ?1`, `DELETE FROM run_envelope WHERE run_id = ?1`) run inside the binary as three LITERAL statements in one transaction (`conductor_report::RunsDb::delete_run`) — teardown covers every table a run writes, or cleanup leaves orphans (rusqlite bound parameters — security anti-pattern bans `format!`-built SQL, which the `sqlite3` CLI could not have honoured: it has no bind facility, and it is present on neither this host nor any CI runner). In tests this reduces to dropping the `assert_fs::TempDir` sandboxing `CONDUCTOR_RUNS_DIR`. Conductor must NOT touch Pulse (Creator Brief: "NO Pulse process management"). The `:4317` port-occupier fault (security Vector 6) releases its `TcpListener` bind on cleanup.
- Idempotency: cleanup MUST be idempotent — re-running against a clean state is a no-op (file-absence is not an error; `DELETE` of zero rows succeeds).
- Verification: `assert_fs` `.assert(predicate::path::missing())` on `runs/<run_id>.{jsonl,md}` + `SELECT count(*) FROM runs WHERE run_id = ?1`, `... FROM run_check ...` and `... FROM run_envelope ...` each returning 0 + a `TcpListener::bind("127.0.0.1:4317")` succeeding (proving the port-occupier released).

**`logs`** — fetch product logs (emission journal is ground truth):
- Command body: read `runs/<run_id>.jsonl` (the per-run emission journal — "the left side of every SLO check", Creator Brief) directly; sanitized stderr from the CLI subprocess captured by `assert_cmd` `.get_output().stderr`. The journal is emitted via `tracing_subscriber::fmt().json().flatten_event(true)` (test-research Structured Log Parsing), one JSON object per line, with wall-clock stamps from `std::time::SystemTime`/`Instant` (NOT tokio's virtual clock — security anti-pattern).
- Format: see Log format below.
- Retention window: per-`run_id`, append-mostly on disk; tests read the whole journal file for the run under assertion (no rotation needed — bounded synthetic runs).
