### Test data bootstrap

- **Strategy:** self-bootstrapping (no developer-seeded data) — deterministic seeded synthetic generation via `conductor-timeline` (same scenario+seed ⇒ same stream shape, Creator Brief).
- **Mechanism:** rstest 0.26.1 `#[fixture]` producing a seeded `conductor-timeline` generator; table-driven `#[rstest]` `#[case]` rows over the catalog (the manifest’s accepted set) and the garde valid/invalid config matrix; `#[once]` fixture for in-memory `runs.db` schema setup; declarative scenario config files (serde + garde) under `scenarios/`, each naming its P-IDs (a P-ID may be named by several). P-032/P-036 require a real git workspace with known recent commits (Creator Brief environment requirement).
- **Per-test isolation:** `rusqlite::Connection::open_in_memory()` per unit/golden test (parallel-safe under nextest's per-test process model); `assert_fs::TempDir` with `.env("CONDUCTOR_RUNS_DIR", temp.path())` per CLI-subprocess / cross-process test THAT WRITES RUN ARTIFACTS, so the CLI and the Tauri mock-runtime write to the same file `runs.db`. A CLI-edge test of a verb that writes nothing sets the handle NOT AT ALL: `CONDUCTOR_RUNS_DIR` is repo-relative by design and `resolve_under` rejects an absolute `temp.path()` at `Paths::resolve()` — before the verb dispatches — so setting it makes every verb fail with empty stdout (measured 2026-09-03 on the `conductor preconditions` edge tests).
- **Cleanup:** test data cleared by the `cleanup` command / `TempDir` drop per session.
