## Framework Families

### Family: React

**Frameworks:**
- React 19.x — mature, largest ecosystem; React Compiler now stable, but VDOM overhead and runtime weight are heaviest of the families (worst fit for a ~3 MB Tauri artifact + cold-start goal).
- Preact 10.x — 3 KB React-API-compatible runtime; the "React without the weight" route if React DX is desired but bundle size is the binding constraint for a bundled webview.
- SolidJS 1.9.x (listed under Solid below) — adjacent option for teams wanting JSX without the VDOM.

**Recommended CSS approaches:**
- Tailwind CSS v4.1 (`@tailwindcss/vite`) — Rust/Oxide engine, first-party Vite plugin, zero-runtime; all utilities compile to a static stylesheet bundled offline — no CDN, satisfying the no-network-font/script hardening rule.
- CSS Modules (Vite built-in) — zero dependency, fully local, scoped; right-sized for a single-developer control surface with no design-system ambitions.
- UnoCSS 66.x (Vite plugin) — on-demand atomic CSS, smaller emitted output than Tailwind for a tiny UI; viable if minimizing the GUI artifact further.

**Recommended component libraries:**
- shadcn/ui (current CLI, Radix UI + Tailwind) — copy-paste, locally vendored components (no runtime npm dependency, MIT); aligns with "locally-vendored, composable" guidance and the offline-bundle rule.
- Radix UI Primitives 1.x (MIT) — headless, accessible primitives (dialog for operator-pause, etc.); you style and bundle only what the control surface uses.
- Mantine 7.x (MIT) — 100+ batteries-included components; heavier and more than a "control surface, not a dashboard" needs — listed only for completeness.

**Recommended coherent stack:**
- Framework: React 19.x (or Preact 10.x for size)
- CSS: Tailwind CSS v4.1
- Components: shadcn/ui (Radix primitives)
- Reasoning: Fits the Tauri 2 bundled-webview SPA model (Vite-native, no SSR) and the offline/no-CDN hardening since Tailwind v4 emits a static stylesheet and shadcn vendors components locally with no runtime dependency. However, for a personal-scale, single-technical-developer control surface with a ~3 MB artifact and cold-start target, React's VDOM runtime is the heaviest baseline of all families — only justified if the developer already lives in React; otherwise the lighter families win on this project's bundle/scale profile.

### Family: Vue

**Frameworks:**
- Vue 3.5.x / 3.6 (Vapor Mode) — mature, excellent Vite/`<script setup>` DX; Vapor Mode optionally drops the VDOM for lighter output, a good direction for a Tauri artifact.
- Petite-Vue 0.4.x — ~6 KB progressive sprinkles variant; overkill-avoidance option for a minimal control panel, though under-tooled for component libraries.

**Recommended CSS approaches:**
- UnoCSS 66.x (Vite plugin, born in the Vue/Anthony Fu ecosystem) — on-demand atomic CSS, smallest emitted bundle; fully local, no CDN — strong for the offline ~3 MB target.
- Tailwind CSS v4.1 (`@tailwindcss/vite`) — static zero-runtime stylesheet, first-class Vue+Vite support; offline-safe.
- SFC `<style scoped>` (Vue built-in) — zero extra dependency, component-scoped; right-sized for a solo developer with no design-system needs.

**Recommended component libraries:**
- Reka UI 2.x (formerly Radix Vue, MIT) — headless accessible primitives; vendor only the dialog/picker/counters the control surface uses.
- shadcn-vue (current, built on Reka UI + Tailwind, MIT) — copy-paste, locally vendored; matches the offline-bundle + locally-vendored guidance.
- Naive UI 2.x (MIT) — ~90 tree-shakable TS components, no global CSS reset; heavier than a control surface strictly needs.

**Recommended coherent stack:**
- Framework: Vue 3.5.x (Vapor-capable)
- CSS: UnoCSS 66.x
- Components: shadcn-vue (Reka UI)
- Reasoning: Vue's SFC + Vite toolchain compiles cleanly into a Tauri static SPA (no SSR runtime needed) and UnoCSS emits only the atoms used — minimizing the ~3 MB GUI artifact for a personal-scale tool. shadcn-vue vendors components locally with no runtime CDN dependency, satisfying the Minimal-tier offline hardening; reasonable if the developer prefers Vue's template ergonomics over signals-first JSX.

### Family: Svelte

**Frameworks:**
- Svelte 5.x (runes) — compile-time framework, signal-based reactivity, no VDOM; near-zero runtime makes it one of the two best fits for a tiny bundled Tauri webview. Use Svelte (Vite) directly, NOT SvelteKit-SSR (profile rules out SSR).
- SvelteKit 2.x in SPA/`adapter-static` mode — only if routing/SSG scaffolding is wanted; configured static, never as a Node SSR server.

**Recommended CSS approaches:**
- Svelte component `<style>` (built-in, scoped, compiled away) — zero dependency, fully local; ideal for a solo-developer control surface with no design system.
- Tailwind CSS v4.1 (`@tailwindcss/vite`) — static offline stylesheet; pairs with shadcn-svelte.
- UnoCSS 66.x (Vite plugin) — minimal on-demand atoms for the smallest artifact.

**Recommended component libraries:**
- Bits UI 2.x (MIT) — headless, runes-native accessible primitives (dialog for operator-pause, etc.); style and bundle only what's used.
- shadcn-svelte (current, Svelte-5/runes-native, Bits UI + Tailwind, MIT) — copy-paste, locally vendored; matches offline-bundle + locally-vendored guidance.
- Skeleton 3.x (Tailwind + Zag.js, MIT) — fuller design system; more than a "control surface, not a dashboard" requires.

**Recommended coherent stack:**
- Framework: Svelte 5.x (runes, via Vite — not SSR)
- CSS: Svelte scoped `<style>` + Tailwind CSS v4.1 (for shadcn-svelte)
- Components: shadcn-svelte (Bits UI)
- Reasoning: Svelte 5 compiles away its runtime, producing the smallest cold-start and bundle footprint — directly serving the ~3 MB artifact goal and the SPA-only (no-SSR) Tauri model. Runes give clean fine-grained binding for the IPC `Channel`-fed live emission counters / target status, and scoped `<style>` plus locally vendored shadcn-svelte keeps everything offline (no CDN), satisfying the Minimal-tier hardening for a single technical operator.

### Family: Solid

**Frameworks:**
- SolidJS 1.9.x — JSX with true fine-grained reactivity, no VDOM; among the lightest runtimes and the most ergonomic model for streaming signal updates. With React-like JSX it's the natural landing spot for a React-fluent developer who wants a tiny artifact.
- Solid Start 1.x (SPA/static preset) — only for routing/SSG; configured static, never SSR (profile excludes SSR).

**Recommended CSS approaches:**
- Tailwind CSS v4.1 (`@tailwindcss/vite`) — static offline stylesheet; pairs with the Solid shadcn port.
- UnoCSS 66.x (Vite plugin) — on-demand atoms, smallest emitted CSS for the GUI artifact.
- CSS Modules (Vite built-in) — zero dependency, fully local/scoped; right-sized for a solo-developer control surface.

**Recommended component libraries:**
- Kobalte 0.13.x (MIT) — headless WAI-ARIA accessible primitives for Solid; bundle only the dialog/picker/status widgets the panel needs.
- Solid UI (shadcn-style port, Kobalte + corvu + Tailwind, MIT, copy-paste) — locally vendored, no runtime npm dependency; matches offline-bundle + locally-vendored guidance.
- corvu 0.4.x (MIT) — unstyled Solid UI building blocks; complements Kobalte for full styling control.

**Recommended coherent stack:**
- Framework: SolidJS 1.9.x (via Vite — not SSR)
- CSS: Tailwind CSS v4.1 (or UnoCSS 66.x)
- Components: Solid UI (Kobalte + corvu), copy-paste vendored
- Reasoning: Solid's fine-grained reactivity updates the DOM directly with no VDOM diffing — an exact match for high-frequency IPC `Channel` streams of emission counters / target status, and one of the smallest runtimes for the ~3 MB Tauri SPA. Locally vendored Solid UI / Kobalte primitives keep the build offline (no CDN) per Minimal-tier hardening, and the JSX model eases adoption for a single developer coming from React without the React runtime weight.

### Family: Rust CLI (terminal presentation)

Scope: the headless `conductor-cli` release-gate surface. Output is agent-parsed first (machine-readable artifacts must stay clean), with a human operator watching progress and answering operator-pause prompts — so styling must be TTY-gated (auto-disable color/animation when piped to an agent or non-TTY) and stay dependency-light, matching the Minimal-tier / no-network profile.

**Frameworks (core print / TUI crates):**
- `anstream` 0.6.x + `anstyle` 1.x — std-based, auto-detects TTY and strips ANSI when piped; the right default so agent-captured artifacts are uncolored while the operator sees styled output. The agent-first/human-watcher split makes auto-stripping the load-bearing requirement.
- `ratatui` 0.29.x (+ `crossterm` 0.28.x backend) — full-screen TUI if a live multi-pane "control surface" view is wanted; likely heavier than this line-oriented release-gate harness needs, so optional.
- `clap` 4.5.x — argument parsing / subcommands for `conductor-cli` (scenario/suite picker, start/stop); standard companion to the presentation layer.

**Recommended CSS approaches (styling crates):**
- `owo-colors` 4.x — zero-allocation, `no_std`-friendly coloring with `if_supports_color` TTY gating; minimal dependency footprint fits the Minimal tier and keeps piped agent output clean.
- `anstyle` 1.x — lightweight style primitives shared across the `clap`/`anstream` ecosystem; consistent, vendoring-friendly, no heavy transitive deps.
- `nu-ansi-term` 0.50.x — alternative styling crate if richer composed styles are needed; still local, no network.

**Recommended component libraries (table / progress / prompt crates):**
- `indicatif` 0.18.x — progress bars + live counters / `MultiProgress`; the natural fit for "live emission counters + target status," and it auto-hides on non-TTY so agent runs stay quiet.
- `comfy-table` 7.x — UTF-8 run-report / per-capability (P-001..P-060) SLO result tables with auto width; pure-Rust, no network, easy to vendor.
- `inquire` 0.7.x (preferred) or `dialoguer` 0.11.x — interactive operator-pause prompts (confirm/select); both TTY-aware. Guardrail: gate prompts behind an interactive-TTY check so the agent-driven headless source-of-truth path is NEVER blocked on a login/prompt.

**Recommended coherent stack:**
- Frameworks: `clap` 4.5.x + `anstream` 0.6.x / `anstyle` 1.x
- Styling: `owo-colors` 4.x
- Components: `indicatif` 0.18.x (progress/counters) + `comfy-table` 7.x (run-report tables) + `inquire` 0.7.x (operator-pause prompts)
- Reasoning: This set is line-oriented and TTY-gated, so the agent (the primary CLI consumer and release gate) receives clean, parseable artifacts while the human operator sees colored progress, SLO tables, and pause prompts — directly serving the agent-driven development_style. Every crate is pure-Rust, dependency-light, and network-free, matching the Minimal (0) security tier and the no-network, single-host profile; `inquire`/`dialoguer` are gated behind a TTY check to honor the "never add interactive login to the headless path" guardrail. `ratatui` full-screen TUI is intentionally omitted as heavier than this release-gate harness warrants.

## Overall Recommendation

**Recommended family:** Svelte
**Recommended stack:** Framework Svelte 5.x (runes, Vite — not SSR) + CSS Svelte scoped `<style>` + Tailwind CSS v4.1 + Components shadcn-svelte (Bits UI)
**Reasoning:** For this Tauri 2 bundled-webview control surface, the binding constraints are the SPA-only (no-SSR) model, the ~3 MB offline GUI artifact + cold-start target, and a single technical developer audience at personal scale — and Svelte 5's compile-away runtime produces the smallest bundle/startup of the families while its runes give clean fine-grained binding for the Tauri IPC `Channel` live emission counters / target status. shadcn-svelte and Bits UI are MIT, copy-paste, locally vendored components — no runtime CDN dependency — which satisfies the Minimal (0) security tier's offline/no-network hardening (no CDN-loaded fonts/scripts) and the "lean, locally-vendored, composable" guidance for a "control surface, not a dashboard." The only caveat at this tier is ecosystem depth: Svelte's component library catalog is smaller than React's, but that is immaterial here since the control surface needs only a handful of primitives (picker, start/stop, counters, run-report, operator-pause) — and SolidJS 1.9.x + Kobalte is the near-equivalent runner-up, marginally better for a React-fluent developer who prefers JSX, with the same no-VDOM streaming and offline-vendoring benefits. Separately, the `conductor-cli` release-gate surface should use the TTY-gated `clap` + `anstream`/`owo-colors` + `indicatif` + `comfy-table` + `inquire` Rust stack so agent-parsed artifacts stay clean while the operator gets styled progress and pause prompts.
