## Reference Products

### Product 1: Linear — issue-tracker SaaS (desktop-webview)

- **What's exceptional:** Instrument-panel information density without clutter — issue rows carry title, status, priority, assignee, labels, project, and cycle in a single line held together by a strict 4px spacing grid; Inter Variable at 510/590 weights with a monospace (Berkeley Mono) reserved exclusively for IDs, codes, and keyboard shortcuts so technical tokens read as a distinct typographic tier; elevation comes from inset 1px border + drop shadow rather than fill, keeping surfaces flat and low-glare against a near-black ground.
- **Domain match:** Conductor's webview is "a control surface, not a dashboard" rendering a dense run state — scenario/suite picker, live emission counters, target status, a coverage matrix (P-001..P-060). Linear is the canonical proof that a developer-facing React tool can pack high data density into a calm, single-row-state layout instead of card-bloat — exactly the density-without-noise problem Conductor's control surface faces, on the same React 19 + Tailwind stack.
- **Personality match:** Linear's matte dark ground with one restrained accent and flat depth is console-furniture, not SaaS gloss — it reads "armed and nominal," composed under dense state, with no decorative motion. That maps directly onto the calm-and-resolute, low-glare mission-control console feel of Direction 3.
- **What to learn:** (1) The monospace-as-a-typographic-tier move — reserve a mono face strictly for verdicts, P-IDs, SLO timings, and keyboard hints so machine tokens are instantly distinguishable from prose (a "status-light" effect in type). (2) Single-row dense state held by a fixed spacing grid — adapt for the emission-counter / target-status row so the operator scans one calm line, not a stack of cards.

### Product 2: k9s — Kubernetes cluster TUI (CLI/terminal analog)

- **What's exceptional:** A persistent status header that holds live, color-tiered resource state (green nominal / yellow degraded / red failing) updating in place while a fixed keybinding hint row stays anchored — the operator always knows current state and available next actions without the view ever reflowing or scrolling content away under load.
- **Domain match:** Conductor's CLI surface is the source-of-truth release gate — live emission counters (indicatif), target status, P-001..P-060 SLO tables (comfy-table). k9s is the closest proven analog: a single operator watching live system status stream past while keeping a stable command frame — precisely Conductor's "watch the run, hold the frame" CLI job.
- **Personality match:** k9s is a single-operator console watching live status with calm color-tiered callouts and no alarm theatrics — the "armed, nominal, go/no-go" status-light read translated into the terminal. A degraded resource turns amber in place; the operator stays oriented. That is Direction 3's "terse status callouts, no alarm in the tone even on Fail."
- **What to learn:** (1) The fixed status-header + anchored hint-row frame — keep target status and operator-pause affordances pinned while emission counters stream, so the run never visually loses its footing. (2) The color-tier convention (nominal/degraded/failed mapped to a small fixed palette) — adapt directly to Pass / CalibrationRegion / Fail and Blocked-precondition so a verdict reads as a status light, not a sentence.

### Product 3: lazygit — terminal UI for git (CLI/operator-pause analog)

- **What's exceptional:** A multi-panel state console (Status, Files, Branches, Commits, Stash) with a persistent bottom keybinding hint bar (`showBottomLine`) that surfaces the exact shortcuts valid for the focused panel — discoverability is built into the chrome, so destructive/committing actions are always one labeled, deliberate keystroke rather than a memorized command.
- **Domain match:** Conductor's CLI uses `inquire` for operator-pause prompts before committed steps and presents run state across distinct concerns (emission, target, verdicts). lazygit models exactly this: holding several state panels at once and gating mutating actions behind explicit, hinted confirmations — the staged go/no-go rhythm Conductor needs before each committed timeline step.
- **Personality match:** lazygit's bottom hint bar and confirm-before-commit flow is the calm-console "hold before you commit the next step" cadence of a mission-control operator-pause — nothing fires without a deliberate, labeled go. That is the operator-pause-prompt heartbeat of Direction 3.
- **What to learn:** (1) The persistent bottom keybinding hint area scoped to current focus — adapt as Conductor's CLI footer so the valid operator-pause responses (proceed / hold / abort) are always visible, never recalled from memory. (2) Confirm-gating of committing actions — model the operator-pause as a labeled go/no-go prompt, not a free-text entry.

### Product 4: NASA Open MCT — mission-control telemetry framework (web, personality source)

- **What's exceptional:** Production mission-control display conventions: a mission-status panel that names the current operational phase ("Terminal Count," "Go for Launch," or the held hold-point when paused), a countdown clock treated as the visual heartbeat, and a formal go/no-go poll model where each subsystem reports readiness before the sequence proceeds — status communicated as discrete, legible operational states rather than continuous gauges.
- **Domain match:** A Conductor run *is* a launch-style sequence — a suite executing on a seeded timeline with a count, live target status, and a final resolution to Pass/Fail/ManualCheck/KnownResidual/**Blocked**. Open MCT is the literal genre Conductor's vocabulary borrows from; it shows how real telemetry consoles render an unfolding timed sequence with phase + count + readiness.
- **Personality match:** This *is* Direction 3's metaphor in its native habitat — armed/nominal status, a count clock, hold prompts, go/no-go polling, calm under load. It is the purest personality anchor available, not an adjacent approximation.
- **What to learn:** (1) Name the operational phase explicitly (e.g., "Arming," "On timeline," "Hold — operator pause," "Resolving verdicts") as a single prominent status line, mirroring the mission-status panel. (2) Treat the count clock as the heartbeat element and show the explicit hold-point when an operator-pause freezes the timeline — borrow the "paused count shows where it stopped" convention rather than just blanking the timer.

### Product 5: Warp — modern terminal (desktop, run-as-sequence analog)

- **What's exceptional:** Command output is grouped into discrete collapsible blocks ("like git commits for your terminal output") that can be folded, rerun, or shared, paired with a deliberately calm, low-chroma gray aesthetic (e.g. minimal mode disabling block dividers) so a long run reads as a clean stack of committed, inspectable steps rather than an undifferentiated scrollback wall.
- **Domain match:** Conductor's run produces a sequence of discrete committed steps (each scenario's emission + verdict) journaled to disk; the operator watches them accrue. Warp's block-per-step model is a direct analog for presenting a run as an orderly, foldable sequence of completed steps with individually inspectable results.
- **Personality match:** Warp's calm gray minimal surface and "each step is a committed block" structure echoes the mission-control rhythm of discrete go/no-go steps logged in sequence under a composed, low-glare surface. It feels armed-and-orderly rather than busy.
- **What to learn:** (1) Block-per-step grouping — render each scenario step as a self-contained, collapsible unit (step header + emission summary + verdict) so the run reads as a sequence, and a Fail block can be expanded without losing the timeline. (2) The restraint of minimal mode (dropping dividers / low chroma) — confirm the "calm, low-glare console" surface treatment over decorative terminal chrome.
