## 3. Test Harness Contract

_[ALL tiers — central agent-driven mechanism; Section consumed by
setup-project to materialize scripts/agent-run.{sh,ps1}]_

Architecture committed to the harness pattern: **agent-driven — the headless `scripts/agent-run.sh` path is the source of truth and the release gate; the GUI is a thin shell over the same core commands** (upstream-context arch Test Harness Commitment). This section specifies the concrete contract. Conductor has **no daemon and no inbound listener** (security: "zero network exposure ... no inbound listener of its own"), so `boot` is a preflight readiness gate and `status` reads disk artifacts — there is no HTTP/IPC status endpoint.

### 5-command implementation

**`boot`** — preflight readiness gate (no daemon to start):
- Command body: `cargo run -p conductor-cli --bin conductor -- preflight --json` — runs the MCP `initialize` handshake over `rmcp::serve_client()` on `TokioChildProcess` (arch Standard Contracts: asserts negotiated protocol `2024-11-05`, required-tool presence vs. pinned `contracts/` manifest, then round-trips a canary incident via `query_incident_list` to prove data-dir wiring). In CI the live-Pulse leg is unavailable, so `boot` runs against the rmcp in-process/`TokioChildProcess` stub server (test-research Mocking) which returns a `ready:true` canary; the live-Pulse leg is `workflow_dispatch`/local-only gated on `ANDROMEDA_PULSE_MCP_ENABLED`.
- Readiness signal: stdout JSON `{"ready": true}`; `ready:false` ⇒ every dependent scenario reports `state="Blocked"` with the named precondition string (security anti-pattern: never silently downgrade a failed preflight to pass/fail/manual-check).
- Exit code: 0 on `ready:true` within timeout; non-zero on handshake failure (transport refused surfaces as `Result::Err`, a harness fault — security Vector 5).
- Timeout: 30s for the MCP `initialize` + canary round-trip (stub leg completes in <1s; the budget covers the live-Pulse sidecar spawn).

**`run`** — invoke test suites + scenario catalog:
- Command body (CI build+test gate, arch CI/CD): `cargo nextest run --workspace --profile ci` (cargo-nextest 0.9.137 → JUnit XML at `.config/nextest.toml` `[profile.ci.junit]`) then `cargo test --workspace --doc` (nextest does not run doctests — test-research baseline-fallback note) then `cargo clippy --workspace --all-targets -- -D warnings`. Scenario invocation: `cargo run -p conductor-cli --bin conductor -- run <scenario|P-ID> --seed <s>` for the named dynamic scenarios (`error-baseline-spike`, `fingerprint-storm`, `restart-suppression`, `pii-scrub`, `connection-lifecycle`, `severity-lifecycle`) and per-P-ID scenarios; `conductor suite` for the full catalog.
- Exit code semantics: 0 = all checks `Pass`; non-zero = at least one hard `Fail` (cargo-nextest `NextestExitCode` 100); `blocked`/`ManualCheck`/`KnownResidual`/`CalibrationRegion` are reported states in the envelope, NOT process-failure exits (Creator Brief assertion-policy split: model-interpretive claims are "calibration-region checks + report-for-human, never hard-failed").
- Output format: machine-parseable — cargo-nextest `ci` profile JUnit XML (parsed by `dorny/test-reporter` into PR annotations) for the test gate; the Run-report envelope JSONL/`runs.db` row for the scenario leg.
- Test selection (fast iteration): `cargo nextest run -p conductor-<seam>` for a single seam crate; `cargo nextest run -E 'test(<name>)'` for a single test; `conductor run <P-ID> --seed <s>` for one scenario.

**`status`** — query product state (disk artifact read; no listener):
- Command body: `jq -e '<predicate>' runs/<run_id>.jsonl` for a shell-level CI smoke gate (jq -e exits 1 on a `false`/`null` last output, 4 on parse error — test-research serde_json+jq), OR an in-process `rusqlite::Connection::open` + bound-parameter `SELECT` of the `runs.db` row for typed assertions. No `curl`/HTTP — there is no inbound listener.
- Polled fields: the Run-report envelope (see Status endpoint shape below) — `run_id`, `seed`, `scenario`, `p_ids`, `verdict`, `state`, `latency_ms`, `slo_tier`, `journal_emitted_at`, `read_back_observed_at`, `fingerprints`.

**`cleanup`** — tear down per-run artifacts:
- Command body: `rm -f runs/<run_id>.jsonl runs/<run_id>.md` + a bound-parameter `DELETE FROM runs WHERE run_id = ?1` on `runs.db` (rusqlite bound parameters — security anti-pattern bans `format!`-built SQL). In tests this reduces to dropping the `assert_fs::TempDir` sandboxing `CONDUCTOR_RUNS_DIR`. Conductor must NOT touch Pulse (Creator Brief: "NO Pulse process management"). The `:4317` port-occupier fault (security Vector 6) releases its `TcpListener` bind on cleanup.
- Idempotency: cleanup MUST be idempotent — re-running against a clean state is a no-op (file-absence is not an error; `DELETE` of zero rows succeeds).
- Verification: `assert_fs` `.assert(predicate::path::missing())` on `runs/<run_id>.{jsonl,md}` + a `SELECT count(*) FROM runs WHERE run_id = ?1` returning 0 + a `TcpListener::bind("127.0.0.1:4317")` succeeding (proving the port-occupier released).

**`logs`** — fetch product logs (emission journal is ground truth):
- Command body: read `runs/<run_id>.jsonl` (the per-run emission journal — "the left side of every SLO check", Creator Brief) directly; sanitized stderr from the CLI subprocess captured by `assert_cmd` `.get_output().stderr`. The journal is emitted via `tracing_subscriber::fmt().json().flatten_event(true)` (test-research Structured Log Parsing), one JSON object per line, with wall-clock stamps from `std::time::SystemTime`/`Instant` (NOT tokio's virtual clock — security anti-pattern).
- Format: see Log format below.
- Retention window: per-`run_id`, append-mostly on disk; tests read the whole journal file for the run under assertion (no rotation needed — bounded synthetic runs).

### Status endpoint shape

```json
{
  "run_id": "string", "seed": 0, "scenario": "string", "p_ids": ["P-001"],
  "verdict": "Pass | Fail | CalibrationRegion",
  "state": "Pass | Fail | ManualCheck | KnownResidual | Blocked",
  "latency_ms": 0, "slo_tier": "string",
  "journal_emitted_at": "ISO-8601", "read_back_observed_at": "ISO-8601",
  "fingerprints": []
}
```

No HTTP/IPC status *endpoint* exists (no listener). This is the Run-report envelope (arch Standard Contracts), serialized identically into the Markdown report, the `runs.db` row, and each JSONL journal line. The agent polls it by reading the `runs.db` row (bound-parameter SQL) or the JSONL journal during/after each scenario. Artifacts MUST NOT leak absolute host paths or internal seam-crate struct names (security anti-pattern) — enforced by the insta golden snapshot + a tracing field-allowlist redaction layer.

### Log format

- **Format:** structured JSONL — one JSON object per line (arch Test-Relevant Conventions: "per-run JSONL journals stemmed by `run_id`"), emitted by `tracing-subscriber` 0.3.x `format::Json`.
- **Required fields:** `journal_emitted_at` (ISO-8601 from `std::time::SystemTime` — NOT virtual clock), plus the envelope identity fields (`run_id`, `seed`, `scenario`, `p_ids`, `verdict`, `state`, `latency_ms`, `slo_tier`, `fingerprints`). NO absolute host paths, NO internal struct names (security anti-pattern; asserted by a negative test on the journal).
- **Agent parsing:** each line parseable with `jq -c` or `serde_json::from_str::<RunReportEnvelope>(line)`; NEVER multi-line — `tracing` JSON flattening serializes everything onto one line.

### PID file

- **Location:** N/A — no daemon (security: "no inbound listener of its own"; arch: `conductor-cli` is a one-shot `#[tokio::main(flavor="current_thread")]` binary). Nothing to write or signal.
- **Lifecycle:** N/A — `cleanup` removes on-disk run artifacts and `runs.db` rows instead of signaling a long-lived process.

### Test data bootstrap

- **Strategy:** self-bootstrapping (no developer-seeded data) — deterministic seeded synthetic generation via `conductor-timeline` (same scenario+seed ⇒ same stream shape, Creator Brief).
- **Mechanism:** rstest 0.26.1 `#[fixture]` producing a seeded `conductor-timeline` generator; table-driven `#[rstest]` `#[case]` rows over the P-001..P-060 catalog and the garde valid/invalid config matrix; `#[once]` fixture for in-memory `runs.db` schema setup; declarative scenario config files (serde + garde) one-per-P-ID under `scenarios/`. P-032/P-036 require a real git workspace with known recent commits (Creator Brief environment requirement).
- **Per-test isolation:** `rusqlite::Connection::open_in_memory()` per unit/golden test (parallel-safe under nextest's per-test process model); `assert_fs::TempDir` with `.env("CONDUCTOR_RUNS_DIR", temp.path())` per CLI-subprocess / cross-process test so the CLI and the Tauri mock-runtime write to the same file `runs.db`.
- **Cleanup:** test data cleared by the `cleanup` command / `TempDir` drop per session.

**Critical path scenarios** (translated from test-scope Section 4):

#### Scenario: Headless deterministic scenario run with MCP read-back (`error-baseline-spike`)

- **Surfaces involved:** cli + ipc-internal (MCP read-back) + persistent-storage
- **Steps:**
  1. `boot` preflight gate returns `ready:true` (rmcp stub in CI; live Pulse on local gate).
  2. assert_cmd: `Command::cargo_bin("conductor")` `.arg("run").arg("error-baseline-spike").arg("--seed").arg("<s>")` with `CONDUCTOR_RUNS_DIR` → `assert_fs::TempDir`, stdin closed.

- **Verification signal:**
  - `.assert().success()` (exit 0); stdout shows `[PASS]`.
  - `runs.db` row: `verdict="Pass"`, `state="Pass"`, `latency_ms` within `slo_tier` (bound-parameter `SELECT`).
  - `runs/<run_id>.jsonl` exists + parses to the envelope (`serde_json` / `jq -e`).
  - MCP read-back (`query_incident_list`/`retrieve_report`) confirms Pulse's reaction (live leg) / stub canary (CI leg).
  - Same-seed re-run yields identical stream shape (insta golden on the journal, redacting `run_id`/timestamps).
- **Cleanup:** `TempDir` drop removes journal + report + DB rows. (Also covers `pii-scrub` and `connection-lifecycle` as additional auto-scenario instances of this pattern — test-scope Sec 4 note.)

#### Scenario: Fingerprint-storm (fault-injection burst + read-back)

- **Surfaces involved:** cli + ipc-internal + persistent-storage; exercises `conductor-faults` fingerprints
- **Steps:** 1. `boot` ready. 2. `conductor run fingerprint-storm --seed <s>`.
- **Verification signal:** exit 0; per-P-ID `verdict`/`state` rows in `runs.db`; `fingerprints` field populated in the envelope; read-back confirms Pulse fingerprint reaction within SLO (live leg).
- **Cleanup:** `TempDir` drop.

#### Scenario: Restart-suppression incl. one bypass case

- **Surfaces involved:** cli + ipc-internal + persistent-storage
- **Steps:** 1. `boot` ready. 2. `conductor run restart-suppression --seed <s>` (suppression case + bypass case).
- **Verification signal:** suppression logic is a hard pass/fail (`verdict ∈ {Pass,Fail}`); the bypass case reports its expected distinct outcome; journal + `runs.db` row assert the deterministic stream (Creator Brief: "suppression/bypass logic = hard pass/fail").
- **Cleanup:** `TempDir` drop.

#### Scenario: Severity-lifecycle full pass (auto-resolve + resolution summary)

## 11. Test Anti-Patterns (NEVER do these)

_[ALL tiers — single source of truth for all test bans]_

### Test Strategy

- NEVER violate the test pyramid — heavy E2E with sparse unit tests is slow + brittle; the per-seam `cargo nextest run -p conductor-<seam>` unit layer is the bulk, E2E is the 7 critical paths only.
- NEVER over-mock at integration level (you stop testing the integration — e.g., do not fake the `runs.db` instead of using rusqlite `open_in_memory()`).
- **(stack-specific)** NEVER fake Pulse's *reaction* as a CI verdict — the rmcp stub canary proves MCP wiring only; Pulse's actual behavior is a live/local-gate assertion (Creator Brief: validates Pulse "from the outside, as a real workload").
- **(stack-specific)** NEVER escalate to load/saturation testing — bounded P-060 "typical/high" profiles only; 50k+ spans/sec is Pulse's `perf_load_profiles.rs`, explicitly out of Conductor scope.

### Unit

- NEVER test implementation details (private fns / internal struct fields) — test the public seam API + observable behavior (envelope/verdict/state output).
- NEVER write brittle assertions against fixture-internal values — assert on the Run-report envelope contract.
- **(stack-specific)** NEVER assert on a real wall-clock duration in a `conductor-timeline` test — drive `tokio::time::advance` under `start_paused = true` and assert scheduled ordering/shape, not real elapsed time.

### Integration

- NEVER mock the DB at integration level — use rusqlite `open_in_memory()` (in-memory) or `assert_fs::TempDir` (file-backed for cross-process), never a hand-rolled SQL fake.
- NEVER skip cleanup between integration tests — fresh in-memory `runs.db` per test (nextest per-process model); never share a mutable file DB across parallel tests without per-test `TempDir`.
- **(stack-specific)** NEVER build `runs.db` SQL via `format!`/string concatenation — use rusqlite bound parameters even for synthetic data (security anti-pattern); a negative/static test asserts this.

### E2E

- NEVER use xpath selectors — use role / data-testid / text + brand anchors (`[PASS]`/`[FAIL]`/`[HOLD]` labels, `role="alertdialog"`, `aria-live`, "HOLD — operator pause" heading text, P-ID tokens).
- NEVER use `sleep(N)` for synchronization — wait for an explicit signal (envelope `state` field, JSONL journal line, element role/`aria-live`, exit code).
- NEVER use brittle selectors that drift across iterations (hashed Tailwind/CSS class names) — the Color-Only a11y rule guarantees text/role pairing, so use that.
- **(stack-specific)** NEVER treat a `blocked`/`ManualCheck`/`KnownResidual`/`CalibrationRegion` state as a non-zero process exit — those are reported envelope states, not hard `Fail` exits (Creator Brief assertion-policy split); only a hard `Fail` is a non-zero exit.

### Test Data

- NEVER use production data in tests — only self-generated synthetic OTLP from the seeded `conductor-timeline` generator (there is no user data; synthetic-only by classification).
- NEVER share mutable state across parallel tests — in-memory `runs.db` / `TempDir` per test.
- NEVER use non-deterministic generators without seed control — `conductor-timeline` seed + proptest strategies with `proptest-regressions/` persistence.
- **(stack-specific)** NEVER stamp the emission journal/report from tokio's virtual clock — use `std::time::SystemTime`/`Instant`; a paused-clock leak into the ground-truth artifact corrupts SLO checks (security anti-pattern) and must be caught by a golden test.

### Mocking

- NEVER mock what you don't own without an abstraction layer — wrap the live Pulse behind the rmcp transport; do NOT monkey-patch `andromeda-pulse-mcp`.
- NEVER over-stub (you stop testing real behavior) — the cli release-gate scenarios run the real binary via assert_cmd.
- NEVER monkey-patch production code at runtime — use DI (rmcp transport injection, tokio built-in virtual clock, ephemeral-port tonic server).
- **(stack-specific)** NEVER force-fit wiremock-rs onto the gRPC OTLP egress — `tonic` is gRPC, not HTTP/1; use an in-process tonic test server or turmoil; reserve wiremock for any future HTTP surface only.
- **(stack-specific)** NEVER interpolate `ANDROMEDA_PULSE_DATA_DIR` (or any operator value) into the sidecar argv/shell — pass strictly via `.env(...)` after rejecting injection metacharacters; spawn `andromeda-pulse-mcp` as a fixed hard-coded path (rmcp STDIO injection class CVE-2026-30623); a negative test asserts argv-injection rejection.

### CI

- NEVER run sequentially when parallelizable — unit + integration are parallel-safe under nextest's per-test process model with proper `runs.db`/`TempDir` isolation.
- NEVER skip dependency caching (`~/.cargo` + `target/` keyed on `Cargo.lock`) — slows the agent feedback loop.
- NEVER ignore flaky tests — quarantine and fix immediately; do NOT set nextest `retries`.
- **(stack-specific)** NEVER merge / `cargo build --release` without `cargo audit --deny warnings` + `cargo deny check` green and a committed un-drifted `Cargo.lock` (Minimal-tier residual-risk control); NEVER run the live-Pulse scenarios as a CI gate (operator/local `workflow_dispatch` only).

### Quality

- NEVER add retry-once policies for flaky tests (masks real failures; determinism is enforced upstream).
- NEVER lower the coverage threshold to pass the build (raise quality, not the bar — keep `--fail-under-lines 60`).
- NEVER skip quality gates "just this once" (audit-green + coverage + clippy are binding).

### Universal (agent-driven specific)

- NEVER use Percy / Chromatic / Applitools (visual regression with human review) — assert role/text/`aria-live` only; `drive+observe` visual go/no-go is the flagged-untestable operator step.
- NEVER include a manual smoke step ("developer verifies before deploy") — except the explicitly-flagged `drive+observe` operator checklist, which is a product feature, not a test step.
- NEVER use Selenium IDE / WebdriverIO codegen-recorder / `cargo insta review` interactive accept UI as a test author — use headless runners only (`wdio run`; insta CI/assert mode with the `CI` env var flipping it to fail-don't-write).
- NEVER include "human reviews screenshots" in any test step.
- NEVER use real network calls in tests — loopback gRPC/MCP stubs only; the live Pulse leg is local-gate-only, never a CI network call.
- NEVER use real time without injection — tokio `start_paused` virtual clock for scheduling; `std::time` only for ground-truth journal stamps.
- **(project-specific)** NEVER add a scenario without a Pulse P-ID, and NEVER introduce an inbound network listener of Conductor's own (the `:4317` port-occupier is the sole deliberate bind, must release on cleanup, and must never become a general-purpose listener) — both violate the architecture's scope law / loopback-client trust boundary.
