## 1. Obs Scope Summary

**Obs tier:** Minimal (0)

**Justification:** 8 workspace crates + 2 surfaces (CLI headless + Tauri desktop-webview GUI) places Conductor at the lower end of the module-count spectrum. Security tier is Minimal (single-developer, local-only, no cloud, zero network exposure beyond loopback MCP/gRPC client). 7 critical paths identified (Sections 4) — all tightly scoped to single-scenario execution. Creator Brief mandates "production-grade verification rigor" for determinism and assertion-policy split but achieves this via property/golden/contract tests, not comprehensive instrumentation. Tests tier is Minimal (0). Complexity facts: (a) no OTel SDK or exporter for self-observation (creator-explicit anti-pattern §6); (b) self-observation is structured tracing logs only (JSONL via `tracing-subscriber`); (c) paste-to-AI workflow via agent-parseable JSON (no proprietary APM); (d) Tauri frontend browser OTel is optional/frontend-only. Telemetry triggers: 5 total (chaos-instrumentation, perf-budget-instruments, cross-surface-trace-propagation, error-budget-SLO, creator-explicit-telemetry) — all addressable within Minimal scope.

## 2. Telemetry Strategy

**Telemetry signal pyramid (Minimal tier):**

| Signal | Coverage focus | Tier-specific depth |
|--------|---------------|---------------------|
| Spans / Traces | Critical paths (7 scenarios) + module boundaries (emit, verify, report, timeline) | Present; focused on must-trace paths only (no background task instrumentation) |
| Structured Logs | Boundary calls (MCP readback, DB insert, emit batch) + state transitions (run start, verdict classification) + redaction on output | JSONL-per-line via `tracing-subscriber`; fields match tests' binding schema (Section 6); no absolute paths or internal names |
| Errors | Captured panics + module-boundary `Result::Err` at seams (MCP client, rusqlite, tonic) | `std::panic::set_hook()` + `tracing::error!` + anyhow edge bridging; no external error-reporting platform at Minimal |
| Metrics | Counters / histograms per critical path | Skipped for backend (no metrics backend); SLO perf-budget is a JSON field assertion (latency_ms + slo_tier), not a histogram instrument |
| Audit Logs | Compliance trail | N/A (Minimal tier: no compliance requirement) |

**Agent-readable invariants:**
- Every signal produces machine-parseable output (JSONL for logs; structured span fields for `tracing` calls; plain JSON exit codes / message summary for errors)
- No human-only dashboards (no Grafana, Kibana, or Datadog UI required)
- No proprietary APM SDKs as primary exporter (no Datadog agent, NewRelic SDK, AppDynamics)
- No human-review-gated log analysis
- Every panic captured with structured context via `std::panic::set_hook()`
- Cross-surface trace context propagated via Tauri IPC envelope `traceparent` field (W3C format)

**Naming conventions:**
- **Span naming:** `{module}.{operation}` pattern (e.g., `scenario.run`, `timeline.execute`, `emit.batch`, `verify.readback`, `report.generate`, `db.insert_run`)
- **Metric naming:** N/A (Minimal tier, no metrics backend); performance budget is JSON field assertion only
- **Log fields:** structured JSONL matching tests' binding schema (journal_emitted_at, run_id, seed, scenario, p_ids, verdict, state, latency_ms, slo_tier, fingerprints)
- **Resource attributes:** `service.name`, `service.version`, `deployment.environment` (via `env!("CARGO_PKG_*")` + env var override)

## 3. Observability Harness Contract

This section specifies the concrete harness pattern for Conductor's deterministic, emission-journal-driven architecture.

### OTel SDK init

- **SDK packages:** NONE — No OTel SDK for Conductor self-observation (creator-explicit mandate per upstream §6). `opentelemetry-proto 0.32.0` is the PRODUCT (fault telemetry emitted AT Pulse), not self-instrumentation.
- **Init order:** Not applicable (no SDK init)
- **Logging init instead:** `tracing-subscriber::fmt().json().flatten_event(true).init()` at CLI bootstrap (`main` fn) + Tauri backend startup; must complete before any scenario logic

### Service identity

- **service.name:** Hardcoded `"conductor"` (CLI) or `"conductor-tauri"` (Tauri GUI) or `"conductor-ui"` (browser frontend); overrideable via `$CONDUCTOR_SERVICE_NAME` env var at runtime
- **service.version:** Compile-time `env!("CARGO_PKG_VERSION")` from root `Cargo.toml`
- **deployment.environment:** Runtime `std::env::var("CONDUCTOR_ENV").unwrap_or_else(|_| "local".into())`
- **Resource attributes:** Emitted as flat fields on every JSONL log line via `tracing` structured fields (`service.name`, `service.version`, `deployment.environment`)

## 4. Span / Trace Coverage

**Span naming convention:** `{module}.{operation}` pattern (e.g., `scenario.run`, `timeline.execute`, `emit.batch`, `verify.readback`, `report.generate`, `db.insert_run`). Avoid high-cardinality span names (no per-user-ID, per-trace-ID, or per-path-with-user-input).

**Span kinds:**
- **Internal:** internal operations (scenario execution, phase scheduling, report generation)
- **Client:** outbound calls (MCP readback via rmcp, rusqlite DB queries, gRPC emit)

**Auto-instrumentation per surface:**

| Surface | Auto-instrumentation | Manual instrumentation |
|---------|---------------------|------------------------|
| **cli** | None (CLI is not an HTTP service) | `#[tracing::instrument]` on `fn main()` and core scenario handlers |
| **desktop-webview** | Tauri `#[tracing::instrument]` on `#[tauri::command]` handlers | IPC envelope `traceparent` propagation |
| **ipc-internal** | None (not HTTP/gRPC) | Manual trace context in Tauri command envelope |

## 11. Obs Anti-Patterns (NEVER do these)

### Telemetry Strategy

- NEVER over-instrument hot paths — span overhead matters; inner-loop phases (emit batch retry logic, fingerprint generation) profile first before adding spans
- NEVER skip spans on critical paths (Scenarios 1-7, Section 4) — agent loses debug ability
- NEVER introduce an OTel SDK + exporter for self-observation — breaks `current_thread` determinism + pollutes the PRODUCT OTLP stream (creator-explicit anti-pattern, upstream §6)

### Spans / Traces

- NEVER include PII in span attributes — Conductor owns no PII, so this is prevented by architecture (operator IDs / fixture data are synthetic)
- NEVER use high-cardinality span names (per-user-ID, per-trace-ID, per-path-with-user-input) — bounded span name set: scenario.run, timeline.execute*, emit.batch, verify.readback*, report.generate, db.insert_run, fault.silence/ramp/port_occupier, tauri.command.*
- NEVER skip trace context propagation (W3C traceparent) across CLI↔Tauri boundary — agent loses trace continuity for both-surface parity (Scenario 7)
- NEVER leave dangling spans (forgot to call close/end) — each span closed at its phase boundary (Section 4 Cleanup subsections)

### Metrics

- NEVER add an OTel metrics backend / `opentelemetry_sdk` meter provider for self-observation — Minimal tier has no metrics backend; a meter re-introduces the SDK + background tasks the creator banned (breaks `current_thread` determinism). Performance budget is the `latency_ms`/`slo_tier` JSON field assertion, not a histogram instrument.
- NEVER create instruments inside hot path (instrument creation is not free) — N/A (no instruments)
- NEVER skip histogram quantile reporting — N/A (no histogram)

### Logs

- NEVER use unstructured stderr text — agent can't parse fields; all output MUST be structured JSON-per-line or sanitized stderr with machine-parseable hints
- NEVER skip `trace_id` / `span_id` fields — required on every JSONL line (Section 6)
- NEVER use multi-line stack traces without one-line serialization — `std::panic::set_hook()` must JSON-serialize backtrace to a single field
- NEVER log in hot path at `info` level — use `trace` / `debug` gated by `RUST_LOG=conductor_timeline=debug` (opt-in)
- NEVER leak absolute host paths or internal struct names in logs / run-report / runs.db — redaction layer (Section 4 Fault-injection spans subsection + Section 11 PII Scrubbing subsection) scrubs `path::`, `module::`, `backtrace` file paths

### Error Reporting

- NEVER add an external error-reporting platform (Sentry / Bugsnag / Rollbar) for Conductor — explicitly rejected (upstream §1 Inherited Defaults: "no external error-tracking platform"); error capture is `std::panic::set_hook()` + `tracing::error!(...)` + the `anyhow` binary edge only
- NEVER let a panic on the MCP read-back / transport path go uncaptured or crash the run — enforce bounded prost recursion; malformed child/transport input ⇒ `blocked` (typed `Ok(...)` verification value), never a panic (upstream §1 Verdict/error wall; §2 "Letting malformed child/transport input panic")
- NEVER forward an unsanitized panic message / backtrace to stderr or run-report artifacts — strip absolute host paths, internal struct names, and backtrace file paths at the `anyhow` edge before display (upstream §2; redaction layer)

### PII Scrubbing

- NEVER include PII in logs / spans / metrics by default — Conductor owns no PII (only synthetic test telemetry); if a future PII-bearing surface is added, apply allowlist-based field filtering at source
- NEVER scrub only at sink stage — apply redaction at processor stage (tracing-subscriber layer) so failures upstream don't leak via stderr
- NEVER hardcode scrubbing rules in single location — redaction layer applies via: (a) tracing-subscriber field filter on JSON formatter, (b) report generation when writing JSONL, (c) runs.db schema validation on insert
- NEVER skip the field-allowlist / redaction layer — the creator's single obs ownership (upstream §6): preserve ONLY verdict/state/identity/count fields; remove all `path::`, `module::`, `backtrace` paths

### CI

- NEVER lose telemetry artifacts (log file + status) — uploaded as CI artifacts with 14-day retention
- NEVER use human-review-gated log analysis without machine-parseable export — agent reads CI artifacts + JSON status
- NEVER skip zero-unlogged-panics gate — all CI runs must pass `cargo-nextest` + log conformance + panic-hook verification

### SLO

- NEVER skip zero-unlogged-panics invariant — most basic obs guarantee
- NEVER add retry-once policies for panic handling — masks real failures (parallel to tests' zero-flakiness, upstream §5)
- NEVER define soft SLO budgets (no enforcement) — formal SLO assertions MUST be evaluated at report-generation time (JSON field assertion)

### Universal (agent-driven specific)

- NEVER use proprietary APM as ONLY exporter (Datadog APM SDK / NewRelic agent) — vendor schemas break paste-to-AI workflows
- NEVER use dashboards-only obs (Grafana / Kibana as sole consumption) — every signal MUST have agent-readable consumption path (stdout JSONL / runs.db / run report Markdown)
- NEVER use human-review-gated log analysis without machine-parseable export — agent reads artifacts, not ops dashboards
- NEVER use real network OTLP in self-observing project (recursion guard) — Conductor IS an observer = stdout/file-only logging mandatory; no network OTLP exporter for self-observation
- NEVER hardcode service identity — use `env!("CARGO_PKG_NAME")` + `$CONDUCTOR_SERVICE_NAME` override
- NEVER emit spans/logs to the same loopback `127.0.0.1:4317` that conductor-emit sends fault telemetry to — self-recursion (browser frontend console-only sink or distinct loopback target)

### Project-specific bans
