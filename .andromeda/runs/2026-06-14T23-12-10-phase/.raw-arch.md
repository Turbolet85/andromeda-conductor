## Patterns to follow
1. Crate-per-seam dependency graph with a reverse-dependency auditing step; use `cargo-modules` or `cargo-rail` to verify forbidden cross-seam edges are blocked at compile time per arch §Infrastructure Patterns.
2. Workspace `[workspace.dependencies]` table as the single source of truth for all pinned versions; downstream chunks reference dependencies as `.workspace = true` per arch §Infrastructure Patterns (Build system).
3. Rust 2024 edition with MSRV pin in `rust-toolchain.toml` per arch §Stack and Technologies (Language / runtime).

## Anti-patterns to avoid
1. Do NOT introduce cross-seam dependencies (e.g., `conductor-timeline` directly depending on `conductor-emit`); only `conductor-core` is a common dependency per arch §Design Philosophy (compiler-enforced seams).
2. Do NOT omit `Cargo.lock` or leave it un-drifted; committed lock is the gate for reproducible builds and security audits per arch §Infrastructure Patterns.
3. Do NOT pin async runtime in module crates; tokio is core-owned (`conductor-cli` + `conductor-core` only) per arch §Established Decisions ([Async Runtime Flavor]) and focus guide constraints.
