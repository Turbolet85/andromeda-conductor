## Project signals (from arch + input)

- **Product type:** Desktop control-panel app (Tauri 2) over a headless-drivable Rust core — a scenario-driven OTLP fault-injection + verification harness driving a live Pulse through 60 capabilities (P-001..P-060).
- **Surfaces in current scope:** cli (`conductor-cli` / `agent-run` — headless source of truth + release gate) + desktop-webview (Tauri 2 control panel — convenience). No deferred surfaces.
- **Crates / modules:** 8 — `conductor-core`, `-timeline`, `-emit`, `-faults`, `-verify`, `-report`, `-cli`, `-tauri` (crate-per-seam workspace).
- **Capabilities (Established Decisions count):** ~19 (runtime flavor, OTLP raw-type emission, MCP read-back, validation, error/verdict wall, module boundaries, timing-tolerance, read-back posture, assertion-policy split, run-history, …).
- **Standard Contracts:** ~5 — MCP preflight readiness gate, OTLP egress liveness check, run-report envelope, timestamp formats, Tauri live-update Channel (+ 4 consumed MCP tools).
- **Cross-cutting concerns:** 6 — config management, agent-driven dev style, determinism discipline, verdict/error wall, trust boundary, scope law ("no scenario without a P-ID").
- **Security tier (cross-input):** Minimal (0).
- **Project signals from input.md:** Multi-surface (desktop + cli) agent-driven harness with production-grade verification rigor — determinism hard-bar + assertion-policy split; explicit must-work scenarios (error-baseline-spike, fingerprint-storm, restart-suppression, pii-scrub, connection-lifecycle, severity-lifecycle); complete 60-P-ID coverage matrix is the definition of done.
- **Existing Scopes:** None — new project (greenfield 0.1.0).

---

## Calibration outcome

- **Hierarchy depth:** 3 levels (epoch → sub-block → chunk)
- **Reasoning:** Medium-complexity band per heuristic — 2 surfaces × 8 crates falls in the 1-3 surfaces × 5-10 crates range → 3 levels; the dense engine seams (`conductor-emit` ~8 primitives, `conductor-verify` MCP+preflight+verdict, the desktop surface, the scenario catalog) need sub-block decomposition (depth 2), while the simpler seams (`timeline`, `faults`, `report`, `cli`) stay epoch→chunk (depth 1).

### Adjustments applied

No adjustments — base heuristic applies. The crate-per-seam architecture (compiler-enforced seams) is itself the natural epoch structure; mapping epochs to seams + the two surfaces already yields 10 uniform-weight epochs that absorb the input.md "production-grade verification rigor" / 60-P-ID-coverage signal. An additional +epoch/+level bump would over-decompose. (Security tier is Minimal, not Hardened; no v2/v3 deferred features within 0.1.0; Tauri-webview desktop is not multi-platform-native.)

## Notes for Phase 1 synthesis

- **Core types first.** `conductor-core` shared types (`Verdict`/`ReportState`, scenario model, error wall) in Foundation precede every seam crate — they are the compile-time contract all seams depend on.
- **Journal format is owned upstream.** The JSONL emission-journal / run-report-envelope schema is defined by tests §3 + obs §6 (rooted in Foundation's logging stack). Timeline's journal writer (Epoch 2) and Report's envelope serializer (Epoch 6) must both conform — sequence the Foundation logging-stack chunk before either.
- **Design tokens before UI.** The design-token/typography bundle (Foundation) must precede any desktop UI chunk (Epoch 9). It lands in Foundation as universal pre-feature setup.
- **Agent-run harness threads through.** Foundation's harness skeleton feeds the CLI epoch's 5-command discipline (Epoch 8) and is the surface a11y/obs CI gates reuse (Epoch 9 / Epoch 10).
- **Preflight gates the catalog.** The MCP preflight readiness gate (Epoch 5) gates all `auto` scenarios — sequence it before the auto-scenario chunks in the Scenario catalog (Epoch 7).
- **Report before surfaces.** The run-report envelope + `runs.db` (Epoch 6) are consumed identically by both the CLI (Epoch 8) and desktop (Epoch 9) surfaces — Report lands before the surface epochs.
- **Polish consumes everything.** Epoch 10's E2E/parity/coverage proof depends on all engine + surface epochs being in place; it is correctly last.
