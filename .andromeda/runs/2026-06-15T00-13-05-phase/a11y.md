# a11y extract

## Relevance
Partial — the chunk defines core data types (`Verdict`, `ReportState`, `Scenario`) that the a11y plan uses as semantic vocabulary in its state-naming crosswalk (§6 State color tokens) and critical-path envelopes (§4), but introduces NO rendered UI surfaces, keyboard navigation, focus management, or ARIA patterns; therefore the implementation adds type contracts that downstream UI chunks will assert against.

## Constraints
- Per a11y-plan §6 State color tokens: the six display labels (Pass/HOLD/Fail/Blocked/Manual/Residual) map to `verdict` enum values (Pass/Fail/CalibrationRegion) and `state` enum values (Pass/Fail/ManualCheck/KnownResidual/Blocked) with specific meaning — the type definitions MUST follow this crosswalk exactly, with no semantic drift.
- Per a11y-plan §1 A11y Scope Summary § Structured violation JSON schema: `Verdict` and `ReportState` serialize to canonical PascalCase names matching the run-report envelope (e.g., `"verdict": "Pass"`, `"state": "Pass"`); serde round-trips are machine-verifiable.
- Per a11y-plan §4 ARIA Patterns & Roles and §1 Critical paths: scenario model MUST express "no scenario without a P-ID" as a non-optional field (enforceable at the type level before validation).
- Per a11y-plan §2 A11y Strategy: "Status is never color-alone" invariant — both `Verdict` and `ReportState` expose text-label + ASCII status-prefix accessors (`[PASS]`/`[FAIL]`/`[HOLD]`/`[BLOCKED]`) so CLI output carries the never-color-alone contract at the type, not the call site.
- Per a11y-plan §1 A11y Scope Summary § Error handling: `Verdict`/`ReportState` are NOT error variants (verdict/error wall); a separate `conductor-core` `thiserror` error enum exists for harness faults; verification outcomes are `Ok(Verdict)` / `Ok(ReportState)`, never `Err`.
- Per a11y-plan §1 Critical paths § Serde representation: `SloTier` closed enum (`<5s`/`<20s`/`<90s`) is serde-renamed since the wire form is not a Rust identifier.

## Patterns to follow
- Enum variant naming follows the exact canonical PascalCase form in the state-naming crosswalk (§6 State color tokens): `Verdict { Pass, Fail, CalibrationRegion }` and `ReportState { Pass, Fail, ManualCheck, KnownResidual, Blocked }`.
- Serde serialization uses `#[serde(rename_all = "PascalCase")]` to match the obs envelope (obs Section 6 Log Format JSON Schema, reproduced in a11y-plan §3).
- Semantic HTML first — core types carry the semantic contract (text label + prefix accessor); UI layers will render these as labels + glyphs + color tokens, never color-alone.

## Anti-patterns to avoid
- NEVER introduce variant names that diverge from the state-naming crosswalk (§6) — `CalibrationRegion` is the canonical verdict term for HOLD, not `Hold` or `Calibration`.
- NEVER omit the ASCII status-prefix accessor (§2 A11y Strategy) — the CLI output contract requires `[PASS]`/`[FAIL]`/`[HOLD]`/`[BLOCKED]` to pair with color in downstream layers.
- NEVER allow a scenario to exist without a P-ID (§1 Critical paths) — express this as a non-optional field in the `Scenario` struct, enforced at construction.

## Contract bindings
obs ↔ types (state-naming crosswalk: obs envelope's `verdict` and `state` enum values must match the canonical `Verdict` and `ReportState` variant names serialized by this chunk); tests ↔ types (serde round-trip unit tests verify canonical PascalCase serialization per obs Section 6 envelope schema); design ↔ types (text labels and ASCII prefixes used by downstream UI chunks to fulfill the never-color-alone SC 1.4.1 assertion, per a11y-plan §6 not-color-alone verification and §11 Anti-Patterns Visual).

## Acceptance criteria contributions
- `Verdict { Pass, Fail, CalibrationRegion }` and `ReportState { Pass, Fail, ManualCheck, KnownResidual, Blocked }` defined with `Debug, Clone, Copy, PartialEq, Eq` derives and serde serialization matching the obs Section 6 envelope (canonical PascalCase names).
- Both enums expose text-label accessors (e.g., `Verdict::Pass.label() → "Pass"`) and ASCII status-prefix accessors (`Verdict::Pass.cli_prefix() → "[PASS]"`) to fulfill a11y-plan §2 never-color-alone CLI contract.
- `Scenario` struct carries a required non-optional P-ID field (enforces "no scenario without a P-ID" per a11y-plan §1 Critical paths).
- Serde round-trip unit tests verify `Verdict` and `ReportState` serialize to and deserialize from their canonical PascalCase names without loss (binding to obs Section 6 envelope contract).
- (a11y) Status label + ASCII-prefix accessor availability enables downstream UI chunks to pair text + glyph with the six state-color tokens (SC 1.4.1 not-color-alone, per a11y-plan §6 and §11 Anti-Patterns Visual).
