## Relevance — partial

This chunk is primarily about validation logic (garde rules, path guards, error handling), which is backend/core logic rather than surface design. Design guidance applies only to the small surface where config errors are **reported** to the operator (the verdict/error wall and any validation-failure messaging).

## Constraints

1. **Color palette § Semantic Colors:** Config validation errors surface as `ConfigError` harness faults per the verdict/error wall; render as `--status-fail` (red `#F85149`) or `--count-blocked` (slate-violet `#565F89`) depending on error class (harness failure vs. precondition) — never as `Verdict`/`ReportState` (design-system §Color Palette).
2. **Typography § Label + Body:** Any operator-facing config-error message uses IBM Plex Sans body (`--text-secondary` / `--text-tertiary`), never monospace unless citing a specific config value (`P-ID`, `CONDUCTOR_*` env var name) — those in JetBrains Mono ID-cyan (design-system §Typography).
3. **Error messaging § No-color-alone rule:** Config errors paired with text labels or icons, not color alone; the verdict lamp reads the harness-fault state (design-system §Iconography, accepted criteria § State color paired with text label).
4. **Motion § No motion on errors:** Config validation failures are load-time, not live; no `prefers-reduced-motion` override needed here — this is static error state, never animated (design-system §Motion, expression 0.3).
5. **Depth § Borders-only:** If config errors render in a dialog/card, use flat `1px --border-subtle` inset border + `--color-raised-3` fill, no shadows (design-system §Depth Strategy).

## Patterns to follow

1. **Error card pattern:** Config errors that block run start render in a flat `--color-raised-3` card with `1px --border-subtle`, `--radius-lg`, mirroring the operator-pause dialog but non-interactive (read-only error state) — design-system §Component Patterns #2 (Operator-pause dialog) adapted for static display.
2. **Identifier citation:** When a config error names a specific P-ID, scenario name, or `CONDUCTOR_*` handle, render that identifier in JetBrains Mono + `--color-id-cyan`, e.g., "Scenario `my-slo-audit` has no P-IDs" — design-system §Typography (Data tier).
3. **Harness-fault verdict lamp:** The coverage matrix row where a scenario fails to load carries a `--status-fail` (red) or `--count-blocked` (slate-violet) lamp with text label (`ConfigError` / `Blocked`), never color alone — design-system §Iconography (verdict lamp pattern).

## Anti-patterns to avoid

1. **NEVER show bare hex values, absolute paths, or environment-variable names unhighlighted** — cite config identifiers (`P-037`, `CONDUCTOR_SCENARIOS_DIR`) in mono ID-cyan; paths remain relative or symbolic (security plan: no absolute host paths in user-facing messages).
2. **NEVER use a red flashing alert or animated toast for config errors** — render in place, motionless, in the run-report / matrix row (design-system §Anti-Patterns §Brand Personality "no alarm", rejected default: "flashing/pulsing red banner").
3. **NEVER conflate "config invalid" with "scenario blocked at runtime"** — a config validation failure (load-time, `ConfigError` harness fault) is distinct from a `Blocked` precondition; use `--status-fail` red for validation, `--count-blocked` slate-violet for preconditions (design-system §Color Palette §Semantic Colors).

## Contract bindings

- **a11y § Use of Color (SC 1.4.1):** Config error colors (`--status-fail` / `--count-blocked`) paired with text labels; no color-only signal (design-system §Color Palette, focus guide cross-domain bindings).
- **security-plan § Input Validation:** Path-traversal guards are validated at the edge, output never exposes absolute host paths or internal struct names in operator-facing messages (design-system §Anti-Patterns, security-plan §Input Validation).

## Acceptance criteria contributions

1. **(design) Config error messages use only design tokens (`--color-id-cyan` for identifiers, `--text-secondary` for prose, no hardcoded hex).** — design-system §Color Palette, Typography.
2. **(design) Identifiers (`P-ID`, `CONDUCTOR_*`, scenario name) cited in mono ID-cyan (`--color-id-cyan`); error text in prose sans (`--text-secondary` / `--text-tertiary`).** — design-system §Typography, Iconography.
3. **(design) Config validation errors render with `--status-fail` (red) or `--count-blocked` (slate-violet) verdict lamp + text label, never color alone.** — design-system §Color Palette §Semantic Colors, Iconography.
