## Constraints
- Per a11y-plan §6 (Visual Design Verification), all token names in the `@theme` block MUST match the source-of-truth design excerpt identically: `--text-primary`, `--color-base`, `--count-nominal`, `--color-focus`, `--border-emphasis`, `--motion-micro`, `--ease-quiet` and others (no invented tokens).
- Per a11y-plan §3 (Structured violation JSON schema) and obs binding, token names are the cross-skill anchor for contrast assertion tooling; raw values stay in design-system.md, not front-loaded into compiled CSS comments.
- Per a11y-plan §6 (Color contrast pairs) and §Focus ring tokens, the named pairs (`--text-primary`/`--color-base` 4.5:1, `--count-nominal`/`--color-base` 3:1, `--color-focus`/`--color-base` 3:1) are pre-requisite inputs to the downstream contrast-verification harness (colorjs.io + axe-core); this chunk does not run verification itself (deferred to Epoch 9), but the token compilation must be correct.
- Per a11y-plan §1 (A11y-relevant Design Tokens) + scope's auto-mode note, the `@media (prefers-color-scheme: light)` overrides and `@media (prefers-reduced-motion: reduce)` global transition reset are design contracts a11y assertion scripts later depend on; Tailwind must emit both blocks.
- Per a11y-plan §3 (Contrast verification harness), `colorjs.io` and axe-core will resolve token names from the compiled CSS custom properties post-Tailwind; misconfigured property names will break downstream a11y tooling (no recovery path during epoch).

## Patterns to follow
- Reproduce token names verbatim from design-system.md §Tokens and §Typography without renaming (a11y-plan §6, §2 naming conventions, scope §Surfaces/contracts).
- Apply `prefers-color-scheme: light` as a parallel branch (no renaming of property names in light mode; only value swaps per design-system.md).
- Ensure motion tokens `--motion-micro` / `--ease-quiet` are present in the `@theme` block so downstream `prefers-reduced-motion` override can reference them by name.
- Tailor fallback font stacks to maintain monospace/sans-serif invariants (JetBrains Mono → `ui-monospace, monospace`; IBM Plex Sans → `ui-sans-serif, sans-serif`) per a11y-plan §1 system-identity tagging rule for design consistency.

## Anti-patterns to avoid
- Do NOT invent new token names or rename design excerpt tokens for CSS brevity (a11y-plan §2, §6 "no invented tokens").
- Do NOT embed raw RGB/HSL color values in the generated CSS `@theme` block as comment-only; colorjs.io assertion requires CSS custom-property resolution (a11y-plan §3, scope §Boundaries).
- Do NOT use CDN-hosted fonts or @import fallbacks to Google Fonts; per a11y-plan §1 (security-tier=Minimal offline hardening) and scope, self-hosted WOFF2 must be the sole font source.

## Contract bindings
- a11y ↔ design: token names are the cross-domain anchor; this chunk reifies the names that a11y assertion harnesses (§3 Contrast verification harness) later bind to (colorjs.io pair-by-pair mapping).
- a11y ↔ tests: the compiled stylesheet and resolved token names will feed the tests §6 a11y step (axe-core + colorjs.io) once a11y harness is wired in Epoch 9; mismatched names here break downstream verification.
