# security extract

## Relevance
partial — test framework / fixtures / coverage tooling is a dev-only, CI-gating component with two security boundaries: dependency supply-chain (new dev-deps) and CI-gate closure for the release path.

## Constraints
- New dev-dependencies (`rstest`, `proptest`, `insta`, `assert_cmd`, `assert_fs`, `cargo-llvm-cov`) must keep `cargo-audit` ≥ 0.22 and `cargo-deny` ≥ 0.19 green before merge (security plan §Dependency Security).
- `Cargo.lock` must remain committed and un-drifted through all dev-dependency additions (security plan §Dependency Security, universal anti-pattern).
- `ci` profile in `.config/nextest.toml` MUST specify `retries = 0` — retries mask flakes and violate the determinism invariant on which the Epoch-2 replay harness depends (security plan §Threat Model Summary, scope §Determinism invariant).
- No secret-shaped strings or credential files (`.env*`, `*.pem`, `*.p12`) must be introduced into the workspace tree (security plan §Secret Management + anti-patterns §Secrets).
- Exemplar test code MUST NOT commit or reference any real/synthetic PII / credentials / Pulse corpus material — use only self-generated synthetic telemetry (security plan §Data Protection).

## Patterns to follow
- All new dev-crate additions inherit the central `[workspace.dependencies]` declaration pattern established by prior chunks, with explicit version + feature gating per the dependency audit floor (security plan §Dependency Security).
- Exemplar tests stay minimal — zero business logic, pure proof-of-wiring; no domain test logic bleeds into Foundation epoch (scope §Boundaries).
- `cargo-llvm-cov` config is machine-parseable for downstream CI consumption (scope §Surfaces / contracts touched); coverage report names / artifact paths must not leak absolute host paths.

## Anti-patterns to avoid
- NEVER add a dev-dependency without running `cargo audit` + `cargo deny check` afterward; NEVER let `Cargo.lock` drift (security plan §Dependency Security, universal anti-pattern §NEVER run cargo build without cargo-audit green).
- NEVER use dev-test fixtures seeded with real credentials / keychain material / Pulse's `corpus.db` content; keep exemplars synthetic-only (security plan §Data Protection, anti-patterns §Data Protection).
- NEVER skip the `retries = 0` setting in the `ci` profile — retries that mask flakes silently corrupt the determinism invariant (scope §Determinism invariant, security plan §Threat Model Summary).

## Contract bindings
- **CI gate closure**: scope §Surfaces / contracts touched — the `--profile ci` profile name and machine-parseable (JUnit) output is a contract the agent-run `status`/`run` commands depend on; security contributes the `retries = 0` determinism enforcement.
- **Supply-chain integrity**: security plan §Dependency Security §CI integration — `cargo-audit` / `cargo-deny` must be **added to the existing GitHub Actions pipeline** (Epoch 8, next chunk "Base CI + agent-run harness skeleton") as a build gate; this chunk's dev-deps prepare the surface but the CI wiring lands downstream.

## Acceptance criteria contributions
- (security) `cargo audit` runs green on all workspace + dev dependencies; `Cargo.lock` is committed and un-drifted (no advisory misses).
- (security) `cargo deny check advisories bans sources licenses` passes (if `cargo-deny` is adopted per setup-project choice; `cargo-audit` is mandatory floor).
- (security) `.config/nextest.toml` `ci` profile explicitly sets `retries = 0` (grep verifies; determinism + flake-masking prevention).
- (security) Exemplar test fixtures contain **zero** real secrets / PII / Pulse corpus references; `cargo clippy -D warnings` + `cargo test --all` compile and run clean.
