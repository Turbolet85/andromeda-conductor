# design extract

## Relevance
Partial — P-026 is a backend emission primitive with no UI surface; only the animation/motion signature binds indirectly.

## Constraints
1. Per design-system §Brand Identity: expression level `0.3` (functional motion only, zero animation libraries, CSS transitions at 150ms ease-out) — informs any downstream visualization of the ramp shape in operator dashboards, not this chunk itself.
2. Per design-system §Color Palette: Verdict/ReportState color tier applies to P-026's success/fail reporting in the run-report + coverage matrix, never to the emission primitive itself.
3. Per design-system §Motion: `prefers-reduced-motion: reduce` binding is inherited; if P-026 visualization appears in a later chunk, motion must drop to none under this media query.
4. Per design-system §Iconography: any P-026 status lamp in the coverage matrix carries the 6-state verdict/report-state lamp (§Iconography), paired with text label per the Color-Only a11y rule.

## Patterns to follow
1. Per design-system §Surface: cli — if P-026 traces through the CLI, use `comfy-table` dynamic width detection + ANSI 117 (ID-cyan) for timing/rate metadata (the mono status tier).
2. Per design-system §Component Patterns (desktop-webview #3): coverage matrix row for P-026 shows P-ID + SLO tier + latency_ms + status lamp; no new card layout divergence.
3. Emission primitive contracts inherit the determinism discipline (ChaCha8Rng seed-from-u64 mirrored from latency-shaping per scope) — the reproducibility requirement is design-neutral but implies the same infrastructure.

## Anti-patterns to avoid
1. Per design-system §Anti-Patterns Universal Bans: NEVER use progress bars that animate-to-100% or hide during the operator-pause (the signature is the frozen heartbeat; if P-026 rendering adds animation, it must freeze in place, not vanish).
2. Per design-system §Anti-Patterns Per-Surface Bans (cli): NEVER colorize without NO_COLOR / TERM checks; NEVER use emoji in piped output.
3. NEVER introduce a new color outside the Verdict/ReportState tier for P-026's result — use only existing status lamps (Pass/Fail/Blocked/Manual/CalibrationRegion/KnownResidual).

## Contract bindings
- **Motion ↔ a11y:** if P-026 visualization animates (later), the motion binding to SC 2.3.3 `prefers-reduced-motion: reduce` is mandatory (design-system §Motion + amendments history).
- **Status lamp ↔ Color-Only a11y:** P-026 in the coverage matrix must pair its status color with text label (`[PASS]`/`[FAIL]`/`[BLOCKED]`/…) per SC 1.4.1 (design-system §Iconography + §Component Patterns #4).
- **CLI output ↔ NO_COLOR:** any P-026 rate/count journaling to stderr must respect NO_COLOR + TERM=dumb (design-system §Surface: cli / Tokens).

## Acceptance criteria contributions
1. (design) P-026's coverage-matrix row displays the verdict lamp (§Iconography) paired with a text label, not color alone — per Color-Only a11y (SC 1.4.1).
2. (design) If P-026 tracing appears in CLI output, metadata (rate/count) uses ANSI 117 (ID-cyan) + never relies on color alone (e.g., always `[PASS] P-026` + colored prefix, never color-only).
3. (design) Any visualization of the rate-ramp shape in operator-pause or post-run context respects `prefers-reduced-motion: reduce` (motion drops to none) — per Motion §Binding with a11y SC 2.3.3.
