Partial — the chunk defines a pure orchestration mechanism (hold-point model, resolver trait, deterministic resume) with no UI surface; A11y touches only the eventual Tauri/CLI shells (deferred), not this chunk's core.

## Constraints

- a11y-plan §4 ARIA Patterns: `alertdialog` role + `aria-modal` + focus trap + Escape-escapable + Proceed/Abort buttons are the dialog contract, but **deferred to the Tauri resolver** (a11y-plan §3 CI integration names this chunk as "core + headless never-block resolver, shell resolvers in Epoch 8/9")

- a11y-plan §3 Structured violation JSON schema: holds may surface in the obs §6 envelope (`state` = `ManualCheck` if a hold outcome reaches the report), but **verdict/error wall mandates hold resolution as `Ok(...)` value, never `Result::Err`** (a11y-plan §1 Boundaries: "a hold resolution is a VALUE, not a fault")
- a11y-plan §1 Critical Paths: "operator-pause go/no-go (HOLD)" is a must-be-accessible path, but **the pause mechanism itself (hold-awaiting) is runtime-agnostic and decoupled from UI** — the A11y contribution to THIS chunk is the contract for how a hold resolves, so downstream shells can wire accessible dialogs
- a11y-plan §3.5 Bootstrap phases: a11y tooling (axe-core, WebdriverIO) runs on the desktop-webview E2E (Epoch 9), not on this chunk's headless-core orchestration

## Patterns to follow
- Hold-point model: no raw internal struct names / host paths leak through the redaction edge (a11y-plan §1 Scope, item 1: "no host paths or internal struct names leaking through the redaction edge")
- Go/no-go decision type: resolution as `Ok(...)` VALUE (not `Result::Err`), aligning with obs Section 6 envelope where `state` = `ManualCheck` / `Fail` / `Pass` but no error-variant (a11y-plan §1 Scope, item 2 + Verdict/error wall)
- Headless resolver: auto-resolves deterministically with zero blocking, preserving seeded emission-stream shape (a11y-plan §1 Acceptance anchor: "same scenario + seed ⇒ identical stream shape"; a11y-plan §1 Boundaries: "determinism preserved, pause is wall-clock-only")
- CLI/Tauri shells: explicit out-of-scope here; wire accessible resolution via the resolver trait abstraction when building Epoch 8 (CLI) and Epoch 9 (Tauri) — those chunks own the a11y harness (a11y-plan §1 Boundaries: "CLI interactive prompt is Epoch 8, desktop go/no-go UI is Epoch 9")

## Anti-patterns to avoid
- **No user-facing prompt text in the core model** — the hold-point carries a "human-readable prompt" but rendering/announcing it (SR, focus trap, keyboard contracts) is the Tauri/CLI resolver's job, not this chunk's (a11y-plan §11 Anti-patterns would name ARIA violations in the core layer, but core has no DOM)
- **No blocking in headless mode** — the default resolver never blocks on user input; auto-resolve deterministically (a11y-plan §1 Boundaries: "headless never blocks")
- **No `Result::Err` for hold outcome** — if a hold decision fails (e.g. malformed deserialization), that is a harness fault (`Result::Err`); but a user's `no-go` decision is a `Ok(NoGo)` value, never an error (a11y-plan §1 Verdict/error wall)

## Contract bindings
- obs §6 Log Format: hold outcome may surface in run-report envelope as `state` = `ManualCheck` (if the hold was tied to a manual-check claim); a11y violation JSON folds into `fingerprints[]` with no new top-level fields (a11y-plan §3 Structured violation JSON schema)
- tests §6 E2E harness: focus/keyboard/contrast harness runs on the Tauri webview via `@crabnebula/tauri-driver` + WebdriverIO; this chunk's hold-orchestration is tested via a tokio-time `start_paused` stub (not E2E) (a11y-plan §1 Scope, item 4 + CI integration)
- Deferred consumers: CLI resolver (Epoch 8) and Tauri resolver (Epoch 9) will wire the resolver trait to provide interactive a11y surfaces (accessible `inquire` prompt + AlertDialog with focus trap / keyboard nav / contrast verification)

## Acceptance criteria contributions
- (a11y) Hold-point model redaction: no host-path / internal-struct-name leak in the prompt or outcome value serialized to the run-report or IPC (a11y-plan §1 Scope, item 1 + Boundaries "No host-path / internal-struct-name leak through the redaction edge").
- (a11y) Hold resolution contract: resolution is `Ok(HoldOutcome::Go | HoldOutcome::NoGo)`, never `Result::Err` (a11y-plan §1 Verdict/error wall + Scope, item 2).
- (a11y) Determinism preservation: same scenario + seed with auto-resolving (headless) resolver ⇒ identical seeded emission-stream shape as a run with no holds (a11y-plan §1 Acceptance anchor).
- (a11y) Resolver trait abstraction: trait decouples core hold-awaiting from shell-specific resolution (CLI `inquire` / Tauri dialog); interactive resolvers (Epoch 8/9) wire accessible surfaces via this trait (a11y-plan §1 Scope, item 3 + Boundaries).
