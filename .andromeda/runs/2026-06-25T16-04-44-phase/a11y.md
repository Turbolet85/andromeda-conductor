## Constraints
- Per §2 A11y Strategy: POUR principles (Operable keyboard-first nav + Perceivable contrast verification) apply to the picker and buttons; shadcn/Radix semantic-first ARIA (no role overrides on divs).
- Per §4 Critical Paths: "Scenario/suite pick → start run" is a must-be-accessible path requiring keyboard-operable picker (Arrow/Enter), semantic button roles, and visible focus rings.
- Per §5 Keyboard Navigation: focus order must reach picker input → options (with type-ahead) → seed field → start control; active picker item carries `--border-emphasis` so focus never relies on color alone (SC 2.4.3).
- Per §6 Visual Design: not-color-alone assertion on disabled picker options (each disabled state text-paired, not tint-alone); `--color-focus`/`--color-base` ring contrast must meet SC 1.4.11 3:1.
- Per §11 Anti-Patterns ARIA: use shadcn `Command`/`Select` (Radix) for picker (never hand-rolled `role="combobox"` on divs); semantic `<button>` for Start/Stop (never ARIA on divs).
- Per §11 Anti-Patterns Keyboard: visible `--color-focus` ring on every interactive control (no `:focus { outline: none }` without ring); natural DOM/Radix focus order (no `tabindex > 0`).
- Per §11 Anti-Patterns Visual: state-color tokens must remain paired with text labels + glyphs; foreground/background pairs below WCAG minima fail (text/buttons SC 1.4.3 4.5:1, focus ring SC 1.4.11 3:1).

## Patterns to follow
- Picker fully keyboard-operable via Radix primitives: Arrow Down/Up navigates options, Enter selects, Escape closes, type-ahead filtering (§3 Keyboard test harness + §5 Focus order).
- Button controls semantic `<button>` with `aria-label` on icon-only titlebar controls; Start disabled until selection picked, Stop disabled when no run in-flight (§4 Button pattern + §5 Focus order).
- Focus ring visible on all interactive elements via `--color-focus` token, asserted by colorjs.io (§3 Contrast verification) + WebdriverIO (§3 Focus management test harness).
- Picker options: each item text-labeled + P-ID(s) visibly paired (SC 1.4.1 not-color-alone); disabled options never conveyed by visual state alone.

## Anti-patterns to avoid
- NEVER use `role="combobox"` on plain `<div>` — shadcn `Command`/`Select` over Radix supplies roles + trap behavior.
- NEVER omit focus ring — `:focus { outline: none }` without `--color-focus` replacement is SC 2.4.7 violation.
- NEVER rely on color alone for disabled picker state — pair text labels + disabled semantic HTML attribute.
- NEVER use a retry-once policy for a11y violations — zero WCAG AA violations are hard requirement (§10 SLO Invariants).
