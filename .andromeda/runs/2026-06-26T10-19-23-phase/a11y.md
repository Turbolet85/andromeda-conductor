## Constraints
1. Live-counter display tokens (`--text-primary`, `--color-id-cyan` foregrounds over `--color-base` background) must maintain SC 1.4.3 4.5:1 contrast per a11y-plan §6 Color contrast pairs
2. Verdict-lamp state colors (`--count-nominal`, `--count-hold`, `--status-fail`, etc.) must maintain SC 1.4.11 3:1 non-text contrast + SC 1.4.1 use-of-color (text-pair + glyph, not color-alone) per a11y-plan §6 and §4 ARIA pattern Verdict/report-state lamp
3. Live-counter updates emitted to the titlebar must be announced via the existing `aria-live` region (typically `aria-live="polite"` on the lamp or counter span) without stealing focus per a11y-plan §4 Critical Path "View run report" and §3 Screen reader test pattern
4. Verdict-lamp state transitions (including HOLD flip when `verdict == CalibrationRegion`) must follow the verdict-first precedence rule per a11y-plan-amendments.md 2026-06-21 — verdict takes precedence over state for lamp rendering (CalibrationRegion verdict → HOLD lamp regardless of ManualCheck state)
5. Color transitions + tint animations on live-counter hold-state must degrade to instant under `prefers-reduced-motion: reduce` per a11y-plan §6 Motion (SC 2.3.3)
6. Focus order on titlebar remains stable; existing window controls do not lose focus when counters/lamp update per a11y-plan §5 run-console-idle focus-order spec

## Patterns to follow
1. Use semantic HTML for the titlebar region (landmark `banner` role per a11y-plan §4 landmark inventory); live-counter element reuses existing container, not a new ARIA role
2. Pair every state-color token (nominal/hold/fail/blocked/manual/residual) with an accessible text label per the existing Verdict/report-state lamp pattern (a11y-plan §4 ARIA pattern catalog)
3. Wire Channel-driven state updates through the existing `aria-live` region on the lamp; do not create duplicate live regions per a11y-plan §3 Screen reader test pattern
4. Leverage Tailwind's compiled token values (`--text-primary`, `--color-base`, etc.) for live-counter text rendering; no custom color values outside the named token set per a11y-plan §6 Source-of-truth tokens

## Anti-patterns to avoid
1. Do NOT add `aria-live` to multiple elements or nest live regions (avoid duplication/redundant announcements per a11y-plan §3 Screen reader test pattern)
2. Do NOT use color alone to distinguish live-counter state without a text label or glyph; SC 1.4.1 non-color-alone constraint per a11y-plan §1 A11y triggers
3. Do NOT override the verdict-lamp precedence rule (per a11y-plan-amendments.md 2026-06-21); CalibrationRegion verdict always renders HOLD lamp regardless of ManualCheck state
