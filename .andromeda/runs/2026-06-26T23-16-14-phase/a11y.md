# a11y extract

## Relevance
Relevant — this chunk creates three UI components (status lamps, dialog scaffold, checklist primitive) that are part of assertable must-be-accessible entities named in a11y-plan §1.

## Constraints
1. **Tier + WCAG target** (a11y-plan §1) — Minimal tier, WCAG AA baseline (SC 2.1.1 Keyboard + SC 1.4.3 Contrast + SC 2.4.3 Focus Order + SC 1.4.11 / SC 1.4.1 / SC 2.3.3).
2. **Semantic HTML first, ARIA second** (a11y-plan §4 & §11 ARIA) — use `<button>` for dialog actions, native checkbox for checklist; shadcn/ui over Radix Primitives for AlertDialog / Command / Select (do NOT hand-roll over raw divs).
3. **Never-color-alone on lamps** (a11y-plan §6 & §11 Visual) — each of the six lamp variants (Pass / HOLD / Fail / Blocked / Manual / Residual) MUST pair token color with text label + glyph; SC 1.4.1 violation otherwise.
4. **Visible focus indicator** (a11y-plan §5 & §6 & §11 Keyboard) — all interactive controls MUST render `--color-focus` ring on focus; `--border-emphasis` distinguishes selection vs focus.
5. **Dialog focus trap + escape** (a11y-plan §4 & §5) — AlertDialog scaffold MUST trap focus on open, cycle Tab/Shift+Tab, be Escape-escapable (SC 2.1.2), restore focus on close (Radix default).
6. **Motion respects `prefers-reduced-motion`** (a11y-plan §6 & §11 Motion) — any `--motion-micro` / `--ease-quiet` transition MUST drop to zero under `prefers-reduced-motion: reduce` (Tailwind `motion-reduce:`; SC 2.3.3).
7. **Design-token consumption** (a11y-plan §6 & scope.md) — consume named tokens (lamp: `--count-nominal`/`--count-hold`/`--status-fail`/`--count-blocked`/`--status-manual`/`--status-residual`; focus: `--color-focus`/`--border-emphasis`; motion: `--motion-micro`/`--ease-quiet`); add lamp tokens only if `design-system.md` defines ones not yet materialized.

## Patterns to follow
1. **shadcn/ui + Radix semantics** (a11y-plan §3) — AlertDialog (provides `alertdialog` role + `aria-modal` + focus trap default), Command/Select for picker, semantic `<button>`/`<input>`/checkbox base.
2. **Six-state lamp variant naming** (a11y-plan §6 & amendments 2026-06-21) — display text Pass / HOLD / Fail / Blocked / Manual / Residual (HOLD chosen verdict-first per `verdict == CalibrationRegion` regardless of obs `state`; Manual only when `state == ManualCheck` with no verdict).
3. **Render-all gallery** (scope.md) — exercise all lamp/dialog/checklist states (dev affordance).
4. **Token-driven, no hardcoded values** (a11y-plan §2 & §6).

## Anti-patterns to avoid
1. **ARIA on non-semantic HTML** (a11y-plan §11) — forbidden: `role="button"` on `<div>` or hand-rolled `alertdialog`/`combobox`; use semantic elements + shadcn Radix.
2. **State conveyed by color alone** (a11y-plan §11) — all six lamps MUST pair color with persistent text label + glyph (SC 1.4.1).
3. **Missing/broken focus indicators** (a11y-plan §11 & §5) — forbidden: `:focus { outline: none }` without `--color-focus` ring, `tabindex > 0`, or non-Escape-escapable modal.

## Contract bindings
**Design tokens** ↔ design §Color Palette (lamp/focus token pairs must meet SC 1.4.3 4.5:1 / SC 1.4.11 3:1 — contrast harness validates in ch9; component must consume named tokens correctly). **Semantic HTML + ARIA patterns** ↔ a11y-plan §4 (dialog → `alertdialog` + `aria-modal`, checklist → `checkbox` + `aria-checked`, lamp → `status`/accessible name; focus/keyboard from Radix defaults).

## Acceptance criteria contributions
1. (a11y) Each of the six lamp variants renders text label + glyph paired with color token (never color-alone; SC 1.4.1).
2. (a11y) Dialog scaffold button(s) have visible `--color-focus` ring on `:focus`, Tab/Shift+Tab cycle trap, Escape closes without keyboard trap (SC 2.4.3 / 2.1.2 / 2.4.7 / 2.1.1).
3. (a11y) Checklist primitive rows expose `aria-checked`, Space toggles a focused row, unticked-count roll-up keyboard-reachable (SC 4.1.2 / 2.1.1 / 4.1.3).
4. (a11y) Any animation degrades to instant under `prefers-reduced-motion: reduce` (SC 2.3.3, Tailwind `motion-reduce:`).
