## Constraints
1. Per §1 A11y Scope: Coverage matrix is assertable entity requiring list/listitem semantics and keyboard-first row navigation (a11y-plan §4)
2. Per §4 ARIA Pattern Catalog (Coverage matrix): Must implement `list`/`listitem` (or table) semantics; selected row with `aria-selected`/`aria-current` + `--border-emphasis`; empty-state real prose (SC 1.3.1, SC 1.4.1)
3. Per §5 Keyboard: Keyboard-first row navigation required; off-screen virtual-scrolled rows must remain reachable/announceable (SC 2.1.1, SC 2.4.3)
4. Per §3 WCAG Criteria Mapping (Minimal tier): SC 1.3.1, SC 2.1.1, SC 2.4.3, SC 1.4.1 (not-color-alone lamps) apply to this component
5. Per §6 Visual Design: Lamp token pairs must meet SC 1.4.11 3:1 non-text contrast; focus ring `--color-focus`/`--color-base` 3:1; token names verbatim from design excerpt (a11y-plan §6 Color contrast pairs table)
6. Per §1 Scope & §4 Pattern Catalog: StatusLamp reuse only — never re-spell lamp palette/glyph/label set; byte-consistency with `conductor-core::Lamp::for_record`

## Patterns to follow
1. Per §4 ARIA Pattern Catalog: `list`/`listitem` with `aria-selected`/`aria-current` on selected row; `--border-emphasis` selection distinct from focus (SC 2.4.7, SC 1.4.11)
2. Per §5 Keyboard Focus Order (run-console-live): keyboard-first row navigation; every P-ID row reachable via Tab/Arrow; active row marked with `--border-emphasis` (never color-only focus indicator)
3. Per §1 Scope & amendment history: StatusLamp reuse + `ui/src/lamp.ts` `LAMP_META` with verdict-first projection per `conductor-core::Lamp::for_record` (a11y-plan-amendments §2026-06-21)
4. Per §3 Assertion Harness: axe-core `list`/`listitem`/`aria-required-children` rules (SC 1.3.1); WebdriverIO row-navigation assertions (SC 2.1.1, SC 2.4.3)

## Anti-patterns to avoid
1. Per §4 Pattern Catalog: Lamp color alone — must pair with text label + glyph (SC 1.4.1, SC 1.4.11)
2. Per §1 Scope: Do not re-spell lamp palette/glyph/vocabulary; reuse StatusLamp primitive as-is
3. Per §4 ARIA: No custom button/interaction on rows without proper ARIA roles/names (SC 4.1.2)
