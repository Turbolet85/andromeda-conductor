# a11y extract

## Relevance
Relevant — adds two new UI surfaces (run-report view + operator-checklist view) explicitly listed in a11y-plan §1 as assertable entities with required ARIA roles, keyboard contracts, and token-driven color assertions.

## Constraints
1. Minimal tier (§1) baseline: SC 2.1.1 Keyboard + SC 1.4.3 Contrast + SC 2.4.3 Focus Order; plus token-driven SC 1.4.1 Use of Color (never color-alone), SC 1.4.11 Non-text Contrast (status lamps), SC 4.1.2 Name/Role/Value, SC 4.1.3 Status Messages (per §1 & §3)
2. Verdict/report-state lamp MUST render with text label + glyph for all six states (Pass/HOLD/Fail/Blocked/Manual/Residual), never color-alone (§6 State color tokens + §11 Visual ban)
3. Coverage matrix MUST use `list`/`listitem` semantics with keyboard-first row navigation (Arrow-navigate + Enter select) reachable off-screen virtual-scrolled rows (§4 ARIA Patterns + §5 Keyboard Navigation)
4. Operator-checklist rows MUST use native `checkbox` ARIA roles with Space-toggle + unticked-count footer roll-up announced (§4 ARIA Patterns + §5 Keyboard Navigation)
5. Verdict lamp state changes + unticked-count updates MUST announce via `aria-live` without stealing focus (§4 Coverage matrix pattern + §5 no aria-live focus-stealing ban §11)
6. Color contrast pairs (token names verbatim): `--text-primary`/`--color-base` (SC 1.4.3 4.5:1), `--count-nominal`/`--color-base` (SC 1.4.11 3:1), `--status-fail`/`--color-base` (SC 1.4.11 3:1) — verified via colorjs.io (§6 Visual Design Verification)
7. axe-core v4.12.0 via `@axe-core/webdriverio` (injected into tests' tauri-driver/WebdriverIO session) + WebdriverIO keyboard harness + manual SR pass gate the desktop-webview surface (§3 A11y Assertion Harness Contract)

## Patterns to follow
1. Reuse `StatusLamp` component (verdict-first lamp with paired text label + glyph) from ch6 — scope does not author new lamp primitive (§4 Verdict/report-state lamp pattern + scope "No new lamp/checklist primitive")
2. Reuse `OperatorChecklist` component (controlled `items` + `onToggle` + native checkbox rows) from ch6 — scope reuses, does not rebuild (§4 Operator-checklist pattern + scope "CARRY — reuse, don't rebuild")
3. Run-report-terminal state keyboard-first coverage-matrix row navigation (Arrow keys + Enter select; off-screen rows reachable) + operator-checklist Space-toggle (Radix/shadcn native contracts; WebdriverIO harness asserts) (§5 "run-report-terminal" focus order + keyboard test harness)
4. Verdict lamp `aria-live="status"` on state change + unticked-count footer roll-up role="status" — both reuse existing shadcn/Radix primitive ARIA (§4 Verdict lamp + Operator-checklist status patterns)
5. Read-only `#[tauri::command]` returning `conductor-core::RunRecord` / scenario model types + `#[derive(Serialize)]` (reuse ch6 data-sourcing pattern per scope "CARRY — data-sourcing pattern") (§3.5 Bootstrap phases / a11y-tooling-install)

## Anti-patterns to avoid
1. NEVER convey verdict/state by color alone — all six lamps (Pass/HOLD/Fail/Blocked/Manual/Residual) MUST carry text label + glyph supplement (SC 1.4.1 Use of Color); status lamps below 3:1 contrast fail colorjs.io gate (§11 Visual ban + §6 State color tokens verification)
2. NEVER omit focus styles or set `outline: none` without `--color-focus` ring replacement on coverage-matrix rows + operator-checklist rows; every interactive control shows the visible ring (§11 Keyboard ban "NEVER omit focus styles")
3. NEVER hand-roll alertdialog/combobox/checkbox semantics — this chunk reuses shipped shadcn/Radix primitives; no custom component ARIA (§11 ARIA ban "NEVER use ARIA on non-semantic HTML"; scope: "No new lamp/checklist primitive")
