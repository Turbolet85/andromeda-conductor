# a11y extract

## Relevance
Relevant — implements the critical path "Operator-pause go/no-go (HOLD)" UI surface; defers a11y testing to ch9 but must build a11y-compliant structure.

## Constraints
1. **Dialog role + modal state** — per a11y-plan §4, use `alertdialog` + `aria-modal="true"` via shadcn AlertDialog over Radix; do not bypass or override Radix's role assignment (a11y-plan §2 semantic HTML first, ARIA second)
2. **Focus trap escapability** — per a11y-plan §5, Escape must close the dialog (SC 2.1.2 No Keyboard Trap); shadcn AlertDialog + Radix provide this; do not suppress the Escape key binding
3. **Focus restoration** — per a11y-plan §5, focus must return to the triggering control on dialog close (Radix default); do not steal focus or move focus manually during async proceed-in-flight state
4. **Button accessible names** — per a11y-plan §4, Proceed/Abort buttons must carry `aria-label` or visible text (SC 4.1.2 Name/Role/Value); disabled in-flight state must use `aria-disabled` alongside `disabled` attribute
5. **State color never alone** — per a11y-plan §6, HOLD phase-line tint + Proceed disabled color (green→amber→slate-violet token transitions) use only design tokens named in the contrast table; do not introduce color-only state indication (SC 1.4.1 Use of Color, SC 1.4.11 Non-text Contrast)
6. **Reduced-motion fade drop** — per a11y-plan §8, dialog fade-in + paused-count tint transition must vanish under `prefers-reduced-motion: reduce` (SC 2.3.3 Animation from Interactions); rely on design system's global reduce-motion rule, do not add motion without a motion-off override

## Patterns to follow
1. **shadcn AlertDialog scaffold reuse** — per a11y-plan §3 and scope "REUSE, never rebuild," accept controlled `open`/`onOpenChange` + `title`/`body` + `onProceed`/`onAbort`/`allowNoGo` props from the pre-built component; Radix provides `alertdialog` role, focus trap, Escape, and focus restoration implicitly
2. **Tab/Shift+Tab cycle + Escape + Enter/Space keyboard contract** — per a11y-plan §5, scripted key sequences validate focus order (Tab cycles Proceed→Abort→Proceed, Escape exits, Enter/Space activates); rely on Radix defaults, assert them in ch9
3. **Title/body as machine-parseable prose** — per a11y-plan §1 Screen reader test pattern, empty-state + in-progress prose must not be downgraded to Fail state; HOLD dialog title/body must clearly name the step (`title: "${p_id}: ${prompt}"`, `body: "Proceed to continue or Abort to stop"`) for obs cross-correlation

## Anti-patterns to avoid
1. **Do not add redundant ARIA** — Radix AlertDialog already provides `alertdialog` + `aria-modal`; do not wrap it in custom `role="dialog"` or override via props
2. **Do not use color-only to indicate Proceed disabled/in-flight state** — Proceed button must carry both `aria-disabled` attribute and text/glyph signal paired with label; rely on design-token opacity/tint, not color alone
3. **Do not break focus trap** — do not render off-dialog interactive elements or portals inside the trap that steal Tab focus; do not manually move focus during the in-flight proceed state

## Contract bindings
- **Dialog props ↔ `HoldPoint` seam**: `title`/`body` must surface `p_id`/`step`/`prompt` from the `conductor_core::pause::HoldPoint` so obs can cross-reference the run-report verdict lamp state + manual checklist item (a11y-plan §1, a11y-plan §4 Critical Paths operator-pause row)
- **Resolve command ↔ obs schema**: when the resolve command emits the `Decision` to core, downstream logging folds into obs envelope with `service.name="conductor-tauri"` (binding a11y↔obs)
- **Verdict-first lamp precedence**: per a11y-plan-amendments.md 2026-06-21, if `verdict==CalibrationRegion`, the lamp shows HOLD regardless of state; the dialog's title should reflect the held step clearly
- **Focus ↔ layout focus-management anchors**: per a11y-plan §5, focus-trap-entry focuses the Proceed button on dialog open over dimmed/inert console; run-console-HOLD landmark receives the trap (binding to layouts domain)

## Acceptance criteria contributions
1. (build) Dialog wiring type-checks: accepts `HoldPoint` (p_id/step/prompt) + `onProceed`/`onAbort` callbacks emitting `Decision`; renders `alertdialog` with controlled `open` state and `allowNoGo` prop wiring
2. (build) Proceed/Abort buttons carry `aria-label` or visible text; Proceed carries `aria-disabled` during in-flight state (type-gated via shadcn AlertDialog props + TypeScript)
3. (integration, manual for ch8) Resolve command posts `Decision` back to core without type mismatch; state machine accepts Go/NoGo and transitions run correctly
4. (a11y-deferred to ch9) Focus trap: Escape closes dialog; Tab cycles within trap; focus restores on close (WebdriverIO `browser.keys()` + `document.activeElement` check per a11y-plan §3)
5. (a11y-deferred to ch9) HOLD lamp colors + Proceed button state pass axe-core `color-contrast` + colorjs.io token-pair assertions (SC 1.4.3 / SC 1.4.11) — no regressions vs. shipped design tokens
