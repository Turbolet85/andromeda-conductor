# a11y extract

## Relevance
Relevant — Foundation-epoch bootstrap of the a11y harness infrastructure (setup phase that materializes desktop-webview assertability).

## Constraints
1. A11y tier is **Minimal (0)** per §1 — one assertable UI surface (desktop-webview Tauri), four must-be-accessible paths, no WCAG compliance mandate, only token-driven triggers (visual-discrimination / motion-sensitive); no WCAG AA/AAA escalation.
2. WCAG target: no explicit mandate; triggers are token-bound (contrast 4.5:1 text / 3:1 non-text per §6, reduced-motion CSS-native per §6 Motion) and do NOT escalate tier per §1.
3. Testing tool stack per §3.5 Bootstrap phases: **axe-core v4.12.0** via `@axe-core/webdriverio`, **Lighthouse v13.0.3**, **colorjs.io v0.6.1** token-name checker — configured `withTags(['wcag2a','wcag2aa','wcag21aa'])` (Minimal baseline, no `wcag22aa`).
4. Browser driver: **reuse tests §6 `@crabnebula/tauri-driver` + WebdriverIO** session per §3 Harness Contract — one webview-automation stack on Linux+xvfb, NOT a parallel puppeteer/CDP stack.
5. Focus management library: **none installed** — shadcn AlertDialog over Radix Primitives (already in stack) per §3.5 Bootstrap phases; harness asserts Radix defaults via WebdriverIO `document.activeElement` tracking.
6. ARIA component library: **shadcn/ui over Radix Primitives** (already in stack) per §3.5 Bootstrap phases — picker / dialog / form fields / checklist supply roles + keyboard contracts; semantic HTML first, ARIA second.
7. Structured violation JSON: aligns to obs §6 envelope verbatim per §3 Structured violation JSON schema (axe rule-id + WCAG-SC tag + selector tuple fold into `fingerprints[]`).

## Patterns to follow
1. **a11y-tooling-install:** `npm install --save-dev axe-core@4.12.0 @axe-core/webdriverio lighthouse@13.0.3` + configure axe `withTags(['wcag2a','wcag2aa','wcag21aa'])` per §3.5 Bootstrap phases; reuse tests' already-installed `webdriverio` + `@crabnebula/tauri-driver`.
2. **contrast-verification-harness-setup:** `npm install --save-dev colorjs.io@0.6.1` + wire token-name assertion resolving `--text-primary`/`--color-base` (4.5:1), `--count-nominal`/`--color-base` (3:1 non-text), `--color-focus`/`--color-base` (3:1 focus ring) from compiled CSS custom properties per §6 Color contrast pairs + §3.5 Bootstrap phases.
3. **Focus trap assertions via WebdriverIO:** Tab/Shift+Tab cycle on run-console-HOLD `alertdialog`, Escape-escapable, focus restoration to triggering control per §3 Focus management test harness + §5 Focus trap.
4. **Keyboard sequences via WebdriverIO:** Button (Enter/Space), Dialog (Tab/Shift+Tab/Escape), Combobox (Arrow/Enter/Escape), Checkbox (Space) per §3 Keyboard test harness + §5 Keyboard Navigation.
5. **Supply-chain gates:** `npm audit` clean, `cargo audit` + `cargo deny`, committed `package-lock.json` + `Cargo.lock` (no drift) per scope §A.

## Anti-patterns to avoid
1. **Never stand up a second browser-automation stack** (puppeteer / CDP Windows-only) — axe injects via `@axe-core/webdriverio` into tests' tauri-driver/WebdriverIO ONLY per §11 CI.
2. **Never use the axe DevTools browser extension** as the engine — JSON-producing axe-core library is the source of truth per §11 Strategy.
3. **Never use hand-rolled ARIA on non-semantic HTML** — shadcn/Radix supply `alertdialog`/`combobox`/`listbox` roles; `<button>` for start/stop, `<input>` for seed fields, native checkbox for checklist rows per §11 ARIA.

## Contract bindings
- **A11y violation JSON ↔ obs §6 envelope:** emissions fold axe rule-id + WCAG-SC + selector into `fingerprints[]`, resource attributes `service.name` / `deployment.environment` tag artifacts for cross-correlation with `runs.db` row / JSONL journal per §3 Structured violation JSON schema.
- **Contrast token pairs ↔ design §Color Palette:** `--text-primary`, `--count-nominal`, `--color-focus` named pairs must resolve from compiled Tailwind CSS custom properties per §6 Color contrast pairs.
- **Focus trap ↔ layouts §Focus Management Anchors:** run-console-HOLD `alertdialog` trap entry / Tab cycle / Escape / restoration per §3 + §5.
- **Reduced-motion ↔ design §Motion:** `--motion-micro`/`--ease-quiet` transitions drop under `prefers-reduced-motion: reduce` via CSS `motion-reduce:` variant per §6 Motion tokens.
