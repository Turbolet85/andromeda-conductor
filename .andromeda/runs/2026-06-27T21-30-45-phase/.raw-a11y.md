## Constraints
1. Report envelope must respect obs §6 Log Format JSON schema (11 fields: `journal_emitted_at`, `read_back_observed_at`, `run_id`, `seed`, `scenario`, `p_ids`, `verdict`, `state`, `latency_ms`, `slo_tier`, `fingerprints`) — a11y violations fold into `fingerprints[]` without introducing new top-level fields (a11y-plan §3 Structured violation JSON schema)
2. Resource attributes: `service.name` = `"conductor-tauri"` / `"conductor-ui"`, `deployment.environment` per `CONDUCTOR_ENV` fallback `"local"` — all report artifacts tag with these for obs cross-correlation (a11y-plan §2 Naming conventions, §3 CI integration)
3. Verdict-first lamp precedence in Markdown report: when `verdict == CalibrationRegion`, render HOLD lamp regardless of `state` value; use verdict column (not state) to join observation rows back to journal; `ManualCheck` state WITHOUT a verdict renders as Manual lamp (a11y-plan §6 State color tokens line 427)
4. Not-color-alone state-token rendering: each of six lamps (`Pass`/`HOLD`/`Fail`/`Blocked`/`Manual`/`Residual`) displays with text label + glyph supplement in report — never color-only conveyal (a11y-plan §6 State color tokens line 434, SC 1.4.1)
5. CLI surface remains not-assertable — no axe-core/Lighthouse/SR assertions apply; ASCII+NO_COLOR output discipline is implementation-only, not an a11y verification path (a11y-plan §1, §11 universal line 574)

## Patterns to follow
