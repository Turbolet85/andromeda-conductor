## Relevance
**Relevant** — this chunk adds a new on-disk parsed input at a trust boundary inside `conductor-core`, touching §Occupied Resources (artifact + possible env handle), §Standard Contracts (the blocked-precondition shape), §Conventions (error handling / verdict-error wall), and §Cross-cutting Patterns (config management, determinism).

## Constraints
1. **Crate placement is fixed: the accepted-set source lives in `conductor-core`** (the runtime-agnostic engine library every other crate depends on) per arch §Occupied Resources (Crate names) + §Established Decisions [Module Boundaries]. The P-ID validator already sits there; the manifest loader must not introduce a new workspace crate, and must not create a cross-seam edge (e.g. `conductor-core` must NOT depend on `conductor-verify` to reuse its manifest loader — a forbidden cross-seam dep won't compile by design).
2. **Config is local files + env only, files-over-env-defaults, CLI-flags-over-env** per arch §Cross-cutting Patterns (Config management). If the plan grants a path override it MUST live in the reserved `CONDUCTOR_*` namespace (arch §Occupied Resources — Environment variables) and be registered there at wrap; no other namespace, no secrets, no cloud config.
3. **Any operator-supplied path handle is resolved + containment-checked before use** — arch §Occupied Resources reserves `CONDUCTOR_*` for path handles and the established guard rejects absolute paths, `..`, and symlink escapes (`conductor-core::config_path::resolve_under`, returning `CoreError::Config`). Reading the env var and choosing the base happen at the CLI/bin edge, never inside the seam loader.
4. **The verdict/error wall governs the load-failure path** (arch §Conventions — Error handling; §Cross-cutting Patterns — Verdict/error wall): `Result::Err` is reserved for Conductor's own harness faults (config parse, transport down), while `Blocked` is a `ReportState` on a *scenario row* with a named precondition. Arch precedent for a manifest read/parse/bounds failure is **harness fault** (`ContractManifest::load` → `VerifyError::Manifest`, "never a verification verdict"); `Blocked` in arch §Standard Contracts is reserved for the readiness gate's outcome, and a blocked row still requires identity fields (`run_id`/`seed`/`scenario`/`p_ids`/`slo_tier`) that do not exist at manifest-load time. Open question 1 must be resolved against this asymmetry, not against the route line's wording alone.
5. **New format choices must reuse the pinned stack** — arch §Stack and Technologies pins `toml 0.9` for declarative on-disk config, `serde_json 1.0` for the report/journal envelope, and `serde 1.0.x + garde 0.22.1` for load-time bounds checking co-located with the structs in their owning seam crate (§Conventions — Config conventions; §Inherited Defaults — Validation). No new parser/schema dependency should be introduced for this artifact.
6. **Determinism discipline applies to the new input** (arch §Design Philosophy — Determinism under a seed; §Cross-cutting Patterns — Determinism discipline): the manifest must be a committed, deterministically-ordered artifact so "same scenario + seed ⇒ same stream shape" is unaffected; no directory globbing, wall-clock, or filesystem-order-dependent set construction.
7. **Scope law is arch-level** (§Cross-cutting Patterns — Scope law; §Project Intent — How new functionality is added): "no scenario without a P-ID"; the P-ID space belongs to the SUT and `coverage-matrix.md` (all P-IDs classified) remains the definition of done. Widening the space from 60 to the manifest's set must keep both statements true.

## Patterns to follow
1. **The pinned-manifest loader pattern** — `crates/conductor-verify/src/manifest.rs`: a `#[derive(Deserialize)]` struct + `default_path()` returning a workspace-root-relative `PathBuf` + `load(&Path)` that reads, parses, then `validate()`s, with a typed per-seam error carrying a `reason` string that **never embeds the path itself** (artifact hygiene — arch §Standard Contracts / obs constraints on host-path leakage). This is the direct in-repo precedent for a second pinned on-disk manifest.
2. **The `CONDUCTOR_*` path-handle guard** — `crates/conductor-core/src/config_path.rs::resolve_under`, already living in `conductor-core` (documented as "the one sync filesystem helper in `conductor-core`"). If open question 3 lands on a new env handle, this is the existing mechanism; if it lands on a fixed in-repo path, the `default_path()` half of pattern 1 suffices.
3. **Committed reference artifacts under `.andromeda/refs/`** — the four existing files are git-tracked (not ignored), matching the scope's cited precedent for versioned-snapshot naming. Note the arch-level tension in §Contract bindings below: arch §Infrastructure Patterns' directory tree registers `contracts/` (and `scenarios/`) as the *runtime-read* config locations and does not include `.andromeda/` at all.
4. **Typed per-seam `thiserror` enum + `anyhow` only at edges** — arch §Conventions (Error handling) + §Inherited Defaults: the new failure variant belongs on `CoreError` (the `conductor-core` seam enum), surfaced through `anyhow` only in `conductor-cli` / `#[tauri::command]`.
5. **Declarative-config-over-code** — arch §Project Intent (How new functionality is added): "new scenarios are added as declarative config keyed to a Pulse P-ID". Making the capability set a data artifact is the same shape one level up; this is the arch-sanctioned way to make "a Pulse release is a data update, not a code change".

## Anti-patterns to avoid
1. **Do NOT add an HTTP/network fetch of the SUT capability set** — arch §Established Decisions [Backend Framework] and §Cross-cutting Patterns (Trust boundary): Conductor has no inbound listener and its only outbound surfaces are OTLP/gRPC egress to `127.0.0.1:4317` and the MCP stdio session. The manifest is a committed local file, not a remote lookup, and this chunk is explicitly offline.
2. **Do NOT silently widen, clamp, or default the accepted set on a malformed/absent manifest** — arch §Standard Contracts is explicit that a failed precondition is surfaced as a distinct named state, "never silently downgraded", and §Occupied Resources' path guard "never silently clamped". Panicking is equally banned (verdict/error wall: harness faults are `Err`, not `panic!`).
3. **Do NOT introduce a Conductor-owned identifier namespace into the P-ID space, a new workspace crate, or an env var outside `CONDUCTOR_*`** — arch §Occupied Resources fixes the crate-name registry (9 members) and the env namespace; §Cross-cutting Patterns fixes the P-ID space as the SUT's.

- **arch ↔ arch (registration at wrap)** — a new on-disk artifact and/or a new `CONDUCTOR_*` env var are both §Occupied Resources–tracked classes (see amendment precedents for `CONDUCTOR_PREFLIGHT_TIMEOUT`, `CONDUCTOR_AGENT_MODE`, `logs/agent-latest.jsonl`), and the arch §Infrastructure Patterns directory tree currently registers only `contracts/` + `scenarios/` as runtime-read config roots. **Flag for the plan:** placing a runtime-parsed input under `.andromeda/refs/` (a planning-docs subtree absent from arch's directory tree) is an arch-tree deviation that must be either deliberately ratified and amended into §Occupied Resources + the directory tree, or redirected to the registered `contracts/` root. - **arch ↔ report/coverage seam (open question 2)** — `coverage-matrix.md` (all P-IDs classified) is arch's stated definition of done (§Cross-cutting Patterns — Scope law; §Occupied Resources — On-disk artifacts). Whether `coverage.rs` reads the same source now or is re-pointed in `v2-03`, the module-boundary rule stands: the shared source must live in `conductor-core` so no new cross-seam edge is created.

## Acceptance criteria contributions
1. **(arch)** The accepted-set source and its loader live in `crates/conductor-core` with no new workspace member and no new cross-seam `Cargo.toml` dependency edge (arch §Established Decisions [Module Boundaries]; §Occupied Resources — Crate names).
