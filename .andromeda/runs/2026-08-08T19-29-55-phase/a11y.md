# a11y extract

## Relevance
**partial** — a lock-only Rust bump with zero DOM/token/ARIA change, but the declared compile risk (`quick-xml 0.41` through `tauri-build`) lands on `conductor-tauri`, host of the only assertable a11y surface; a11y contributes surface-integrity and gate-scoping constraints only.

## Constraints
1. The a11y SLO invariant (zero WCAG AA violations on the four must-be-accessible paths) is **not re-triggered** by a lock-only change — but it re-arms the moment any bump-forced edit reaches the webview path, per a11y-plan §10 SLO Invariants. The scope's "zero Rust source change expected" is also the a11y no-op condition.
2. The a11y gate is **operator/local + display-gated** (Linux+xvfb + live Pulse), not a CI/always-on gate, per a11y-plan §9 CI Integration and §3 CI integration. Its absence from this chunk's re-prove list is correct and must be recorded as intentional, not as a skipped check.
3. If the conditional Tauri minor bump (2.11.3 → 2.11.5) is pulled in, the **webview engine under the sole a11y surface changes** — Radix `alertdialog` focus-trap/Escape/focus-restore and `aria-live` announcement behavior ride on it (a11y-plan §3 Focus management test harness, §5 Focus trap / Focus restoration), so an operator/local a11y pass becomes owed before the gate is declared green.
4. No `Cargo.lock` bump can alter the design-token contrast pairs (`--text-primary`/`--color-base` … `--color-focus`/`--color-base`), so **no colorjs.io re-assertion is owed** this chunk, per a11y-plan §6 Color contrast pairs.
5. `scripts/agent-run.sh run` and the cli/report output in the re-prove list carry **no a11y obligation** — the cli surface is not-assertable (no DOM/widget tree); its ASCII status prefixes are output-stream discipline, per a11y-plan §1 (cli entity, not-assertable) and §11 Universal.

## Patterns to follow
1. **One webview-automation stack.** Any GUI verification after the bump reuses the existing display-gated harness — `npm run a11y` → `wdio run wdio.conf.ts` in `crates/conductor-tauri/ui` (axe-core + `@axe-core/webdriverio` + colorjs.io over `@crabnebula/tauri-driver`/WebdriverIO), per a11y-plan §3 A11y testing tool pick.
2. **Frontend bundle precedes the Rust build.** `ui/dist` must exist before any workspace `cargo build`/`nextest`/`clippy` that compiles `conductor-tauri` (`generate_context!` resolves `build.frontendDist` at compile time); the `ensure_frontend` step in `scripts/agent-run.{sh,ps1}` already wires this — see `.claude/rules/frontend.md` §Session Additions (2026-06-24). The scope's build re-prove depends on it.
3. **Violation-evidence shape** if any a11y pass runs: axe `violations[]` + colorjs.io ratios + keyboard PASS/FAIL fold into the obs §6 envelope via `fingerprints[]`, no new top-level fields, no absolute host paths or seam-crate struct names — a11y-plan §3 Structured violation JSON schema.
4. **Lamp single-truth mirror as a tripwire:** `ui/src/lamp.ts` mirrors `conductor-core/src/lamp.rs` (display label ↔ obs `verdict`/`state`, verdict-first HOLD precedence) per a11y-plan §6 State color tokens crosswalk. If bump-forced fallout touches verdict/report code, this mapping must stay in sync — and that is itself the "re-examine scope" signal the scope names.

## Anti-patterns to avoid
1. **NEVER stand up a second browser-automation stack** (puppeteer/CDP or a new driver) to verify the GUI post-bump — a11y-plan §11 CI.
2. **NEVER treat the cli surface as a11y-assertable** — its ASCII prefixes / NO_COLOR pairing are not an ARIA verification path (a11y-plan §11 Universal).
3. **NEVER assert "a11y unaffected" by inspection if the webview or its asset pipeline changed** — machine-verifiable evidence only (a11y-plan §2 Agent-runnable invariants, §11 Strategy).

## Contract bindings
- **a11y ↔ tests §6:** the `@crabnebula/tauri-driver` + WebdriverIO session is shared, single-stack; a11y emits through tests' `logs` command of the 5-command harness contract (a11y-plan §3, §9). Any change to those `crates/conductor-tauri/ui` devDeps — explicitly **out of scope** here per the scope's npm-gate exclusion — is a joint tests+a11y change and holds the pinned versions (axe-core 4.12.0, lighthouse 13.0.3, colorjs.io 0.6.1) per a11y-plan §3.5 Bootstrap phases.
- **a11y ↔ obs §6:** violation-JSON envelope binding, dormant this chunk (only activates if an a11y pass runs).
- **a11y ↔ design §Color Palette / §Motion:** token-pair and reduce-motion bindings untouched by a lock-only change — no action.
