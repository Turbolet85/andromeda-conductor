## Relevance
Partial — no engine/seam/contract change, but the chunk moves versions arch registers as locked stack facts (`anyhow 1.0.102`), touches the `[workspace.dependencies]` manifest that carries a decision-contradicting `rmcp` entry, and re-proves the build/CI gate arch owns.

## Constraints
- **anyhow's pinned version is arch-registered in three places** — arch §Stack and Technologies (Error handling row), §Established Decisions [Error Handling], §Inherited Defaults all name `anyhow 1.0.102`. Bumping the lock to 1.0.104 (and any P4 decision to raise the `[workspace.dependencies]` floor at `Cargo.toml:56`) drifts all three and requires a lockstep arch amendment at wrap — the established correction precedent (libsqlite3-sys 0.36.0, garde 0.22.1, indicatif 0.17).
- **Transitive-only bumps land no §Stack row** — arch §Stack registers direct workspace deps; `plist` / `quick-xml` / `crossbeam-epoch` are transitive and unregistered, so they get no new row. The one exception pattern arch has used is a load-bearing transitive pin recorded alongside its parent (rusqlite → libsqlite3-sys/SQLite); nothing here meets that bar. Do not add any of the three as a direct `[workspace.dependencies]` entry.
- **`rmcp = "1.7.0"` at Cargo.toml:45 contradicts a locked decision** — arch §Established Decisions [MCP Read-Back Client] records rmcp REMOVED (hand-rolled line-delimited JSON-RPC is the client), reinforced by the 2026-06-27 amendment. If P4 elects to delete it, that is manifest↔decision alignment, not a new decision; if left, it stays a known contradiction to carry forward.
- **conductor-tauri cannot be compiled without a prebuilt webview bundle** — arch §Infrastructure Patterns (Build system): `tauri-build`'s `generate_context!` resolves `build.frontendDist` (`ui/dist`) at COMPILE time, and a bare `cargo build` does NOT run `beforeBuildCommand`. Since quick-xml 0.41 is consumed by `tauri-build`'s build script, the risk surface can only be exercised through the `ensure_frontend`-wired path (`scripts/agent-run.{sh,ps1}`, CI Rust job), never a bare cargo invocation.
- **MSRV / toolchain floor is locked** — arch §Stack + §Infrastructure + §Inherited Defaults pin Rust 2024, cargo 1.85, MSRV 1.94.1 (`rust-version = "1.94.1"`, Cargo.toml:18). No bump may raise the effective MSRV above that floor; if one does, it is out of the lock-only envelope and escalates.
- **deny.toml is reserved for the non-actionable class** — arch §Infrastructure Patterns records the justified Tauri-tree exceptions (unmaintained gtk-rs/`unic-*`/`proc-macro-error`, `MPL-2.0` / `Apache-2.0 WITH LLVM-exception`) as the standing set, with "audit + deny stay green" as the invariant. Existing entries must survive untouched; new transitives pulled in by `cargo update -p plist` must clear `bans`/`sources`/`licenses` on their own.
- **Committed, un-drifted lockfiles are the arch lockfile policy** — `Cargo.lock` sits at the workspace root in arch §Infrastructure directory tree, and §Inherited Defaults mandates the committed-lock + gate-clean pairing (its npm analogue is the committed `package-lock.json` + `npm audit --omit=dev`). `Cargo.lock` must be committed with no post-gate drift.
- **Tauri floor, not ceiling** — arch §Stack pins Tauri 2 bundler v2.10.x and the 2026-06-24 amendment records the `tauri = "2.10.3"` floor (Cargo.toml:74, resolved 2.11.3). Leaving Tauri untouched is compliant; a forced bump stays ≥ floor and would itself be an arch-registered version move.

## Patterns to follow
- **New-or-moved dep → arch amendment at wrap** (arch §Stack): the serde_json / toml / clap / owo-colors precedent — an audit-green dep change is recorded as a §Stack row edit, with no §Established Decisions fork unless the choice is a consequential one. A pure version correction to the resolved lock follows the libsqlite3-sys/indicatif shape.
- **Security-plan is the authority, arch carries derived one-liners** (arch §Inherited Defaults Frontend / §Infrastructure Build system): the 2026-06-27-desktop-a11y precedent — when a dependency-gate fact changes, the substantive amendment belongs to security-plan §Dependency Security and arch's summaries are updated in lockstep, never independently.
- **Headless path is the release gate** (arch §Design Philosophy, §Cross-cutting Development Style): `scripts/agent-run.sh run` is the source-of-truth proof; CI (§Infrastructure CI/CD) is build+test+clippy+supply-chain only, and dynamic Pulse-dependent proof stays an operator/local gate — so a blocked/absent live Pulse does not block this chunk's gate restoration.
- **Zero-retry nextest `ci` profile** (arch §Infrastructure Build system, `.config/nextest.toml`): re-proof runs with no retries — a flake surfaced by a bump is a real signal, not something to re-run past.
- **Existing CI supply-chain steps are the gate** (`.github/workflows/ci.yml:74-78`, arch §Infrastructure CI/CD): `cargo audit` and `cargo deny check` already exist as separate steps; restoration means making them exit 0, not adding workflow surface.

## Anti-patterns to avoid
- **Do not silence an actionable advisory with a `deny.toml` ignore** — arch §Infrastructure scopes deny.toml to unmaintained-but-non-vulnerable transitives and license exceptions; using it for a fixable vulnerability inverts the instrument.
- **Do not promote a transitive to a direct workspace dependency** to force a version — that would add an unregistered crate to arch's §Stack registry and to the crate-per-seam dependency edges (§Established Decisions [Module Boundaries]) for a lock-only problem.
- **Do not touch locked stack rows opportunistically** while the lock is open (tokio 1.48.x `current_thread`, rusqlite 0.38.0 bundled, rand_chacha 0.9, opentelemetry-proto 0.32.0, tonic 0.14.6) — each is an §Established Decisions fork, and drift there is a determinism/behavior change, not a supply-chain fix.

## Contract bindings
- **arch ↔ security** — arch §Stack / §Established Decisions [Error Handling] / §Inherited Defaults version strings are derived from security-plan §Dependency Security's gate; the anyhow move and any manifest-floor raise must amend both in lockstep (2026-06-27-desktop-a11y precedent), and security owns the RUSTSEC-2024-0429 (glib) open item's disposition.
- **arch ↔ tests** — arch §Infrastructure Build system owns the nextest `ci` profile + `cargo test --doc` split (nextest skips doctests); the 428-test baseline re-proof runs through that pinned runner, and the `ensure_frontend` precondition applies to `nextest`/`clippy` runs that compile `conductor-tauri`, not just `build`.
- **arch ↔ frontend tree** — arch §Occupied Resources (Frontend asset subtree) marks `crates/conductor-tauri/ui/` as npm-managed and NOT a Cargo member; the `npm audit --omit=dev` gate there is a separate gate from cargo audit/deny and is correctly out of this chunk's scope.

## Acceptance criteria contributions
- (arch) Zero Rust source change and zero new workspace member/crate/port/env var; the only tracked-file deltas are `Cargo.lock` (+ optionally `Cargo.toml` version-floor lines) — any other edit re-opens scope (arch §Occupied Resources).
- (arch) `conductor-tauri` is compiled at least once through an `ensure_frontend`-preceded path (`scripts/agent-run.{sh,ps1}` or the CI Rust job), never a bare `cargo build`, so the quick-xml 0.41 `tauri-build` build-script surface is actually exercised (arch §Infrastructure Patterns — Build system).
- (arch) The workspace still builds on MSRV 1.94.1 / Rust 2024 with no toolchain-floor change, and no §Established-Decisions-locked dep (tokio / rusqlite / tonic / opentelemetry-proto / rand_chacha / garde) moves (arch §Stack, §Established Decisions, §Inherited Defaults).
- (arch) `deny.toml`'s existing justified exception set is byte-unchanged and `cargo deny check advisories bans sources licenses` exits 0 without new ignores; `Cargo.lock` is committed and un-drifted after the final gate run (arch §Infrastructure Patterns; §Inherited Defaults lockfile policy).
- (arch) If `anyhow` (or any other arch-registered version string) moves, a wrap-time arch amendment updating §Stack + §Established Decisions [Error Handling] + §Inherited Defaults in lockstep with security-plan §Dependency Security is queued.
