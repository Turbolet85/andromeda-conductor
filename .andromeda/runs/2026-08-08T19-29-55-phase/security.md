## Relevance
Relevant — this chunk IS a §Dependency Security action (advisory remediation restoring the `cargo-audit` + `cargo-deny` gate to green); security is the owning domain.

## Constraints
- The gate is **both tools, not one**: `cargo audit` exit 0 **and** `cargo deny check advisories bans sources licenses` exit 0 — per security-plan §Dependency Security (CI integration; "cargo-audit report-only first, then cargo-deny with advisory blocking"). The scope's own premise-1 correction (RUSTSEC-2026-0190 `unsound` is audit-invisible / deny-denied) is exactly this rule firing live; a single-tool green is not a green gate.
- **No release build, no merge while red** — per security-plan §Security Anti-Patterns § Universal ("NEVER run `cargo build --release` (the release gate) or merge … without cargo-audit (and recommended cargo-deny) green"). This is what makes the chunk blocking.
- **`Cargo.lock` MUST be committed and un-drifted** — per §Dependency Security (Pinning) and §Anti-Patterns § Universal ("NEVER let `Cargo.lock` drift or go uncommitted"). The lock is the determinism contract; a lock-only change means the lock diff *is* the deliverable and must land committed.
- **Actionable advisories are fixed by bumping, never by a `deny.toml` ignore** — per §Dependency Security (Accepted exceptions), which reserves ignores for the unmaintained-but-non-vulnerable / no-upstream-fix class (RUSTSEC-2025-0119 `number_prefix`) and permissive-license additions (Zlib). All four advisories here have fixes, so adding ignore entries would violate that mechanism. The scope's "no new `deny.toml` entries" is the correct reading.
- **Critical-CVE SLA / required-bump discipline**: patch actionable advisories against the tree promptly, immediate bump for anything touching the `cargo build` extraction path or the Tauri IPC surface — per §Dependency Security (Critical CVE response SLA) and §Anti-Patterns § Universal ("NEVER skip bumping a pinned dependency flagged by research"). quick-xml 0.41 lands through `tauri-build`'s build script, i.e. the build path — bump, don't defer.
- **Toolchain + tool floors hold, actuals may exceed**: `rust-toolchain.toml` ≥ 1.94.1 (satisfied at 1.95.0), `cargo-audit` ≥ 0.22, `cargo-deny` ≥ 0.19 — per §Dependency Security (Audit tool, Pinning) and §Bootstrap phases (dep-audit-tooling-install). Any tool at/above floor running green satisfies the gate; do not re-pin tool versions.
- **Scope guard — zero source change expected**: no new dependency, no new env handle, no new spawn/IPC/network surface. Per §Anti-Patterns § Universal ("NEVER introduce an inbound network listener of Conductor's own") and §Threat Model § Attack surface, any source edit forced by a bump must be re-examined against the existing boundaries rather than widening them.

## Patterns to follow
- **Lever-the-parent-crate bump** (scope premise 3: `cargo update -p plist` moves quick-xml, not `-p quick-xml`): this is the §Dependency Security "Update policy — manual review for a single-developer tool; bump versions flagged by cargo-audit/cargo-deny" pattern; the recorded precedent is the Vite 6→8.0.16 bump to clear esbuild GHSA-gv7w-rqvm-qjhr (§Dependency Security, Frontend npm paragraph).
- **Documented-exception mechanism, when it legitimately applies**: the `deny.toml` ignore + license-allow pattern with a justifying comment (§Dependency Security, Accepted exceptions). Reach for it only for the open RUSTSEC-2024-0429 glib `unsound` item if it proves non-actionable — the same shape as the `number_prefix` entry, with the same "justifying comment" requirement.
- **Dev-tree vs shipping-tree grain**: the crossbeam-epoch path is a dev-dependency (`assert_fs` → globwalk → ignore → crossbeam-deque), never in the release binary. §Dependency Security (Frontend npm paragraph) establishes the precedent that non-shipping test tooling is graded at dev-tree grain — but cargo has no `--omit=dev` analogue and `cargo deny` denies it, so fix it; record the severity-in-context, don't use it as a waiver.
- **CI gate shape is already wired**: §Dependency Security (CI integration) + §Bootstrap phases (dep-security-ci-gate) specify `cargo audit` + `cargo deny check advisories bans sources licenses` + lock-drift verification as steps in the existing workflow. The scope's "no new step is expected" matches — restore green against the existing steps, do not re-architect the gate.
- **`libsqlite3-sys` currency**: keep it current so SQLite patch bumps flow in (§Dependency Security, Update policy; §Anti-Patterns § Universal FFI note). If the lock update touches it, that is desirable, not scope creep.

## Anti-patterns to avoid
- NEVER suppress an **actionable** advisory with a `deny.toml` ignore instead of bumping — §Dependency Security (Accepted exceptions) scopes ignores to non-actionable/no-upstream-fix cases only.
- NEVER declare the gate green off `cargo audit` alone, and NEVER let `Cargo.lock` drift or go uncommitted — §Anti-Patterns § Universal (both clauses).
- NEVER let a bump silently pull the toolchain below ≥ 1.94.1 or reintroduce a version flagged by research (`tauri` ≥ 2.10.3 forward-bump remains standing) — §Anti-Patterns § Code Patterns (tar-rs symlink-chmod CVE-2026-33056) + § Universal (final bullet).

## Contract bindings
- **CI security gate ↔ tests §CI Integration**: the `cargo audit` + `cargo deny check` steps are jobs in the single `.github/workflows/ci.yml` alongside build / nextest / clippy (§Dependency Security CI integration; §Bootstrap phases dep-security-ci-gate). The gate's pass/fail is security's contract; the workflow's structure is tests'.
- **npm frontend gate (adjacent, not triggered)**: `npm audit --omit=dev` clean + committed `package-lock.json` is a separate tree (§Dependency Security, Frontend npm supply chain). The scope correctly excludes it — no cargo-side lock bump can affect it; flag only if `conductor-tauri` UI files are touched.
- **`conductor-tauri` build surface ↔ arch**: quick-xml 0.41 is consumed by `tauri-build`'s build script (Info.plist), i.e. the `cargo build` extraction/build path the SLA singles out. Compilation of `conductor-tauri` is the real risk surface and must be exercised, not assumed.
