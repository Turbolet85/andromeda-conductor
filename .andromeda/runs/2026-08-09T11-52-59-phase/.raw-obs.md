# obs extract

## Relevance
Partial — the drift check itself is core-domain logic, but obs owns its failure-output shape: record shape (self-obs line, not envelope), field allowlist, host-path/struct-name hygiene, log level, and the no-new-span/no-metric bounds.

## Constraints
- **Self-obs line, never a Run-report envelope record.** Per obs-plan.md §3 ("two record shapes", line 229) + §6: `verdict`/`state`/`latency_ms`/`slo_tier`/`journal_emitted_at` belong to the scenario-RESULT record (`runs/<run_id>.jsonl` + `runs.db`). A drift failure is a harness-side event and carries only the base set (`timestamp_ms`, `level`, `target`, service-identity, `run_id`). This is the obs-side expression of the scope's verdict/error-wall invariant.
- **Field-name allowlist is enforced at the processor stage, not the sink** (§11 PII Scrubbing; §6). Any structured field the check emits that is not in `conductor-core::redact::ALLOWLISTED_FIELDS` is DROPPED — silently. `p_ids`, `count`, `message` are allowlisted; `missing_p_ids`, `coverage_percent`, `sut_version`, `captured_at` are **not**. Either interpolate them into the `message` string or amend the allowlist (an obs-plan §6 edit, not a free choice).
- **Value scrub anchors on absolute host-FILE paths, not `::` tokens** (§11 Logs + PII Scrubbing). Drive-letter / `/home` / `/Users` / `%APPDATA%` / `~/.cargo` / `.rustup` → `<redacted>`; internal struct names are kept out by the allowlist + `Display`-not-`Debug` at the `anyhow` edge. The manifest's path must never reach the failure text.
- **Log level maps to the P4 gate decision** (§6 level mapping): a hard-gating drift = `error` (unrecoverable harness fault); a surfaced-but-non-gating signal = `warn` (recoverable/degraded). Pick the level with the gate decision, not independently.
- **Bounded span-name set** (§11 Spans; §4 coverage-matrix completeness gate). If the check is instrumented at all, reuse the existing gate names (`report.coverage_matrix_generate` / `report.validate_coverage`); a new name requires an amendment. A test-only check needs no span — §11 bans over-instrumenting non-critical paths.
- **No metric instrument** (§5, §1 Minimal tier): a drift count / coverage percentage is a JSON field assertion, never an OTel meter or histogram.
- **Zero unlogged panics** (§10, §11 Error Reporting): drift is a typed error return, never a `panic!`/`unwrap` on the manifest-vs-classification comparison; the unsanitized message/backtrace must not reach stderr or artifacts.
- **Agent-readable failure** (§2 agent-readable invariants): an agent reading a red gate must recover the drifted ids by machine parse (`jq`/`serde_json`/exit code), not by human prose reading.

## Patterns to follow
- `crates/conductor-core/src/capability_manifest.rs:45` — the existing manifest-load `tracing::info!` is the exact shape to copy: allowlisted `count = …` field plus the variable detail (`sut_version`) interpolated into the message string. Its `load` error also models path hygiene (`io::Error.kind()`, never the path).
- `crates/conductor-core/src/redact.rs` — `ALLOWLISTED_FIELDS` / `is_allowlisted` / `redact_value`; and `conductor_core::sanitize_error` as the Display-not-Debug error edge. Reuse this unchanged infra rather than adding a check-local scrub (§11 "never hardcode scrubbing rules in a single new location").
- obs-plan.md §4 *Coverage-matrix completeness gate* — the pre-existing spec for exactly this comparison shape (`coverage_percent`, `missing_count`, `p_id_count_expected` = the manifest's capability count). Align the drift check's naming to it rather than inventing parallel names.
- obs-plan.md §9 *Log conformance check* — the model for a gate that reads a committed/CI artifact, validates it, and marks FAIL with a machine-readable reason; if the drift check becomes a CI gate it should surface the same way (§10 build/deploy failure conditions).

## Anti-patterns to avoid
- Emitting envelope fields (`verdict`/`state`/`slo_tier`/`latency_ms`) on the drift line, i.e. dressing a harness-side failure as a scenario result (§11 Logs; §3).
- Unstructured stderr text or a multi-line dump of the drifted ids — all output must be one-line-serialized and field-parseable (§11 Logs).
- Debug-dumping `CapabilityManifest`/the coverage rows, or letting the manifest's absolute path into the message (§11 Logs + PII Scrubbing; §11 Error Reporting).

## Contract bindings
- **obs ↔ tests:** the Run-report envelope schema is OWNED by test-plan §3 — obs §3/§6 only reproduce it. If the drift check lands as a test or CI gate, its output binds to obs §3's harness contract (self-obs base line), and must not re-author or extend the envelope.
- **obs ↔ security:** artifact hygiene (no absolute host paths, no internal struct names) is the shared `conductor-core::redact` path — the same layer satisfies security's "leaking absolute host paths in run-report artifacts" ban and this chunk's stated invariant.
- **obs ↔ CI (§9/§10):** if the check is gating, it joins the §10 build-failure conditions and its output must be downloadable/parseable from CI artifacts.

## Acceptance criteria contributions
- (obs) The drift failure output names the drifted ids + `sut_version` + `captured_at` in a machine-parseable form (jq/serde_json or a stable one-line message), not prose-only.
- (obs) No allowlist drop: every structured field the check emits is either in `redact::ALLOWLISTED_FIELDS` or carried inside `message` — asserted by a test that the emitted line still carries the drift detail after the subscriber's processor stage.
- (obs) No host-path / struct-name leak in the drift message: no drive-letter, `/home`, `/Users`, `%APPDATA%`, `~/.cargo`, `.rustup`, and no `Debug`-dumped internal type; the error edge uses `sanitize_error`/`Display`.
- (obs) No new span name outside the §11 bounded set, no OTel SDK init, and no metric instrument introduced by this chunk.
