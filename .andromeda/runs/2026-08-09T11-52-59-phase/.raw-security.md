# security extract

## Relevance
Partial — no new external-input boundary, dependency, secret, or network surface; the applicable rules are artifact/error hygiene, the verdict/error wall, and the standing supply-chain gate.

## Constraints
- The drift check consumes `contracts/pulse-capabilities.toml` **only** through the already-hardened `CapabilityManifest::load` / `default_path` path — no second read, no `CONDUCTOR_*` override, no new `std::fs` call at a new boundary (per security-plan.md §Input Validation, capability-manifest row added by the 2026-08-08 amendment; §Anti-Patterns § Input, env-path-handle rule).
- Any failure message, panic message, or test assertion output must name capability ids + `sut_version` / `captured_at` only — **never** an absolute host path (the resolved manifest path), never an internal seam-crate struct/field name (per security-plan.md §Error Handling, run-report artifact sanitization; §Anti-Patterns § Logging, third bullet). This directly restates the chunk's own "artifact hygiene" invariant.
- A manifest read/parse fault stays a typed harness fault carrying `e.kind()` only — never the path, never a panic on malformed input (per security-plan.md §Error Handling, internal-logging/typed-enum rule; §Anti-Patterns § Universal, "NEVER let a malformed child/transport input panic").
- A drift condition must surface as a harness-side failure, **never** collapsed into `Verdict` / `ReportState` (and never into `Blocked`, which is reserved for the preflight readiness gate) — the verdict/error wall is a security control, not just a modelling one (per security-plan.md §Error Handling, verdict/error wall; §Anti-Patterns § Universal, "NEVER silently downgrade a failed preflight").
- The check must not reintroduce a hardcoded id range/count as a validation source — the accepted set stays DATA. A compile-time id universe would re-create the silent-drift blind spot the check exists to close (per security-plan.md §Input Validation, contract-manifest row: "never silent downgrade"; §Anti-Patterns § Universal, "NEVER add a scenario without a Pulse P-ID").
- If the check becomes reachable from `conductor-cli` / `agent-run` (the open P4 question), its operator-facing output must go through the sanitized `anyhow` edge — no stack trace, no absolute path, no library/struct internals (per security-plan.md §Error Handling, external responses; §Anti-Patterns § Logging, second bullet). If it lands test-only, that surface obligation does not arise.
- Dependency posture: this chunk should add **no** new crate. If any is added, `cargo audit` + `cargo deny check` must be green with `Cargo.lock` committed and un-drifted before the release gate (per security-plan.md §Dependency Security; §Anti-Patterns § Universal, first two bullets).

## Patterns to follow
- `CapabilityManifest::load` at `crates/conductor-core/src/capability_manifest.rs:36` already models the sanitized read fault: `CoreError::Config(format!("could not read capability manifest ({:?})", e.kind()))` — reuse this shape for any new error text; its `load_failure_message_never_contains_the_path` test (same file, line 120) is the pattern for proving hygiene.
- `resolve_under` (`crates/conductor-core/src/config_path.rs:17`, re-exported from `lib.rs:34`) is the shipped traversal guard behind `default_path`; consume it transitively rather than re-implementing a path check (the "consume shipped hardened infra" precedent recorded in the 2026-06-24 amendment).
- `coverage_matrix()` (`crates/conductor-core/src/coverage.rs:60`) is `&'static str`-backed with "no runtime IO" — reading it introduces no boundary and no allocation; keep it that way so the check stays deterministic and side-effect-free (per security-plan.md §Anti-Patterns § Logging, determinism-discipline bullet, applied to artifact-vs-artifact comparison).
- Typed `thiserror` enums internally, type-erased `anyhow` only at the `conductor-cli` edge (per security-plan.md §Error Handling, error format) — the drift error belongs in `conductor-core`'s typed error surface, not as a bare `anyhow!` string minted at the check site.

## Anti-patterns to avoid
- NEVER embed the resolved manifest path (or `CONDUCTOR_RUNS_DIR`-derived paths) in the drift failure message, a report artifact, or a `runs.db` row (per security-plan.md §Anti-Patterns § Logging, third bullet).
- NEVER let a manifest/coverage mismatch, an unparseable id, or a missing artifact panic or silently pass-as-empty — an empty/absent input must be a loud typed failure, never a false green (per security-plan.md §Anti-Patterns § Input, last bullet; § Universal, silent-downgrade bullet).
- NEVER let this check edit, rewrite, or "auto-fix" `contracts/pulse-capabilities.toml` — a self-healing gate is a silent widening of the accepted set (per security-plan.md §Anti-Patterns § Universal, scope-law bullet; chunk boundary "Does NOT edit the manifest").

## Contract bindings
- **Artifact hygiene ↔ obs/tests:** the "no absolute paths, no internal struct names" rule binds to obs's artifact/log-field discipline and to tests — the hygiene assertion belongs as a test (mirroring `load_failure_message_never_contains_the_path`), which is tests' harness, security's criterion.
- **Gate placement ↔ tests §CI Integration:** if the drift check lands as a hard gate, it is a job in the one existing CI workflow alongside `cargo audit` / `cargo deny` (per security-plan.md §Dependency Security, CI integration) — security does not own a second workflow.
- **Verdict/error wall ↔ arch:** whether the drift failure is `CoreError` vs a new variant is arch's call; security only requires it never becomes a `Verdict`/`ReportState` value.

## Acceptance criteria contributions
- (security) The drift check's failure output contains no absolute filesystem path and no internal struct/field name — asserted by a test in the style of `capability_manifest.rs:120`, not by inspection.
- (security) A missing / unreadable / malformed `contracts/pulse-capabilities.toml` produces a typed harness error carrying `e.kind()`-grade detail only, and never a panic and never a silent "zero drift" pass.
- (security) The drift condition is returned/raised as a harness-side error and appears nowhere as a `Verdict` or `ReportState` variant (grep-verifiable on the new code path).
- (security) `cargo audit` exit 0 and `cargo deny check advisories bans sources licenses` ok, with `Cargo.lock` committed and un-drifted (no-op expected: no new dependency).
