## Relevance
Partial — arch governs crate placement, the verdict/error wall, manifest-as-data, and artifact/env resource discipline for this chunk; it prescribes no new external surface.

## Constraints
- Code lands in `conductor-core` only — no new workspace crate, no new cross-seam dependency edge; the crate-per-seam workspace is the compiler-enforced boundary and the member list is LOCKED (per architecture.md §Occupied Resources "Crate names", §Established Decisions [Module Boundaries], §Inherited Defaults "Module boundaries"). This matches the scope's "No new crate edge."
- The drift condition is a **harness fault**: `Result::Err` over a typed `thiserror` enum in the seam crate (`CoreError`), never a `Verdict` or `ReportState`. `anyhow` only if/where it reaches a `conductor-cli` / `#[tauri::command]` edge (per architecture.md §Conventions "Error handling", §Established Decisions [Error Handling], §Cross-cutting Patterns "Verdict/error wall").
- The accepted set stays DATA read through the shipped manifest: no re-hardcoded id range, no second count constant, no re-parse of `contracts/pulse-capabilities.toml`. A malformed/absent/unparseable manifest is a named-reason `CoreError`, never `Blocked` and never a silent widening (per architecture.md §Established Decisions [Accepted Capability Set]).
- No new dependency: the manifest load path already uses the pinned `toml 0.9` + serde stack, and this check consumes in-process Rust calls only (per architecture.md §Stack and Technologies, §Established Decisions [Accepted Capability Set] "no new dependency").
- No new occupied resource: no new `CONDUCTOR_*` env var, no new on-disk artifact, no override handle for the capability manifest (its `default_path()` deliberately has none, unlike `CONDUCTOR_CONTRACT_MANIFEST`) (per architecture.md §Occupied Resources "Environment variables", "On-disk artifacts").
- Offline + deterministic: no gRPC egress, no MCP session, no live-Pulse read-back — the check reads committed artifacts only, so same tree ⇒ same result; nothing here touches `127.0.0.1:4317` or the preflight gate (per architecture.md §Cross-cutting Patterns "Determinism discipline", §Standard Contracts "Liveness equivalent", §Occupied Resources "Ports").
- If the check gains a CLI reachability path (the scope's open P4 question), it is a `clap 4` derive subcommand/flag on `conductor-cli` over the existing `current_thread` bootstrap with `anyhow` at that edge — not a new interface surface (per architecture.md §Stack and Technologies "CLI argument parsing", §Conventions "Interface surfaces").

## Patterns to follow
- Manifest-as-data consumption: `CapabilityManifest::load` / `accepts` / `default_path()` resolved via `resolve_under`, exactly as the three binary-edge load sites do — a single source of "which P-IDs exist" (per architecture.md §Established Decisions [Accepted Capability Set]).
- Two-layer validation split (shape vs. membership): this chunk is neither — it is a third, coverage-universe assertion over the same manifest, so it must not reach into `pid_format` / `check_capabilities` / `from_toml_str_with` (per architecture.md §Established Decisions [Accepted Capability Set]).
- Typed per-seam error enum with `#[from]` conversions carrying a named reason string, the shipped `CoreError::Config` / `CoreError::Validation` shape (per architecture.md §Conventions "Error handling").
- Kebab-case on-disk artifact naming and P-ID keying (`P-NNN`, "no scenario without a P-ID"); the classification universe artifact is `coverage-matrix.md`, the stated definition of done (per architecture.md §Conventions "Naming patterns", §Cross-cutting Patterns "Scope law", §Occupied Resources "On-disk artifacts").
- CI-safe by construction: this is a `cargo build` / nextest / clippy-gateable unit check, matching the build+test-only CI posture (no live Pulse in CI) (per architecture.md §Infrastructure Patterns "CI/CD approach").

## Anti-patterns to avoid
- Reintroducing a compile-time capability bound — a `P-001..=P-082` range, a `[CapabilityRow; 82]` array length, or any second hardcoded count — which would re-lock the exact decision that was reversed (per architecture.md §Established Decisions [Accepted Capability Set]).
- Emitting drift as a scenario outcome (`Blocked`/`Fail`/`ManualCheck`) or letting it flow into the run-report envelope / `runs.db` — verification outcomes are values for SUT behavior, and drift is Conductor's own fault (per architecture.md §Cross-cutting Patterns "Verdict/error wall", §Standard Contracts "Run report envelope").
- Adding a network/live-Pulse probe or a new inbound surface to detect drift — Conductor exposes no service and this check is artifact-vs-artifact (per architecture.md §Established Decisions [Backend Framework], §Cross-cutting Patterns "Trust boundary").

## Contract bindings
- **Verdict/error wall ↔ tests + report:** the drift check must be provably outside `Verdict`/`ReportState`; tests assert it surfaces as `Err`, and the report/`runs.db` envelope gains no field (arch §Standard Contracts "Run report envelope" is unchanged by this chunk).
- **Manifest-as-data ↔ security:** `contracts/pulse-capabilities.toml` is read-only input resolved through `resolve_under` from a fixed default path with no env override — the existing path-resolution hardening applies unchanged (arch §Occupied Resources).
- **Artifact hygiene ↔ obs:** failure text carries capability ids + `sut_version`/`captured_at` only; no absolute host paths (the self-obs redaction discipline, obs-plan §3, referenced from arch §Occupied Resources `logs/agent-latest.jsonl`).
- **Coverage universe ↔ scope law:** `coverage-matrix.md` ("every capability in the SUT capability manifest, zero gaps") is the definition-of-done artifact this detector measures against (arch §Cross-cutting Patterns "Scope law").

## Acceptance criteria contributions
- (arch) All new code lives in `crates/conductor-core/`; `cargo tree`/manifests show no new workspace member and no new dependency edge for `conductor-core` (arch §Occupied Resources "Crate names", §Established Decisions [Module Boundaries]).
- (arch) A drift condition returns `Err(CoreError::…)` with a named reason; no code path maps drift to `Verdict::Fail` or `ReportState::{Blocked, Fail, ManualCheck}`, and the run-report envelope + `runs.db` schema are byte-unchanged (arch §Conventions "Error handling", §Standard Contracts).
- (arch) No hardcoded P-ID range or capability count is introduced; the accepted set is obtained solely via `CapabilityManifest::load`/`accepts`, and `contracts/pulse-capabilities.toml` is never written (arch §Established Decisions [Accepted Capability Set]).
- (arch) No new `CONDUCTOR_*` env var, no new on-disk artifact, no new external dependency in `[workspace.dependencies]`; `cargo audit` / `cargo deny` stay green with no new `deny.toml` exception (arch §Occupied Resources, §Infrastructure Patterns "Build system").
