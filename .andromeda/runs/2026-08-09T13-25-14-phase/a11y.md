## Relevance
Partial — the chunk is mostly Rust core (`coverage.rs` / `drift.rs`) + doc prose, but the new `CoverageMode` variant flows into the single assertable a11y surface (Tauri desktop-webview coverage matrix + `ui/src/lamp.ts`), which sits on a must-be-accessible path.

## Constraints
- Tier stays Minimal; this chunk adds **no new WCAG SCs**. The applicable baseline is SC 2.1.1 / SC 1.4.3 / SC 2.4.3 plus token-driven SC 1.4.1 / SC 1.4.11 (per a11y-plan.md §1 A11y Scope Summary, §3 WCAG criteria mapping). No `wcag22aa`, no AA/AAA escalation.
- The coverage matrix is on the "View run report" must-be-accessible path and has a fixed pattern contract — list/listitem *or table* semantics, `aria-selected`/`aria-current` row marking, keyboard-first row navigation (per a11y-plan.md §1 Critical paths, §4 Per-component pattern catalog, §5 run-report-terminal). Widening 60 → 82 rows must not weaken any of these.
- The mode value is **DOM text** and is the machine-verifiable anchor for not-color-alone. The fourth variant must carry its text label (the `label()` / serde wire spelling) rendered as text from the moment it exists, even though visual treatment is deferred to the next chunk (per a11y-plan.md §6 State color tokens, §11 Visual).
- The six-lamp set is **closed and verdict-first**: a coverage *mode* is not a report *state*. Do not add a seventh lamp, re-spell the set, or project not-Conductor's onto `Blocked`/`Fail` — `Fail`/`Blocked` are load-bearing failure signals (per a11y-plan.md §6 State-naming crosswalk, §11 Visual + SLO).
- Every P-ID row must remain in the accessibility tree and reachable. If the 82-row wall motivates virtualization, off-screen `listitem`/row nodes MUST stay announceable (per a11y-plan.md §11 Screen Reader).
- The `conductor-cli` coverage-table renderer is **not-assertable** — its ASCII/text pairing is output-stream discipline, never an a11y verification path; no a11y assertion is owed for the CLI arm of the exhaustive `match` (per a11y-plan.md §1 A11y scope, §11 Universal).
- Design-token **names** are the binding cross-skill anchor and raw values stay in design-system.md. The `.andromeda/design-system.md` 60→82 reconciliation edits prose counts only — no token renames, no raw values pulled in (per a11y-plan.md §6 Visual Design Verification source-of-truth, `[NO_RAW_DESIGN_VALUES]`).

- **a11y ↔ tests §6/§9** — any a11y check for this UI change rides the existing `@crabnebula/tauri-driver` + WebdriverIO `wdio run` job on Linux+xvfb, surfaced through tests' `logs` command; operator/local gate, not a CI gate. - **a11y ↔ design §Color Palette / §Motion** — token *names* are the anchor for the contrast + reduced-motion assertions; the design-system.md doc reconciliation must leave them untouched (a11y-plan.md §6).
- **a11y ↔ core lamp truth** — `crates\conductor-core\src\lamp.rs` ↔ `crates\conductor-tauri\ui\src\lamp.ts` mirror is the enforcement point for the closed six-state set.
