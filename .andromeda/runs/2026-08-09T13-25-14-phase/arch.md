## Relevance
Relevant — the chunk lands entirely inside `conductor-core` and fans out across four crates, touching a locked manifest artifact, a serde wire spelling, and three arch-owned doc claims.

## Constraints
- The classification table and its `CoverageMode` variant live in `conductor-core`, the runtime-agnostic engine library every other crate depends on; the fan-out consumers (`conductor-report` Markdown render, `conductor-cli` table, `conductor-tauri` view) may depend *down* onto core but core must not gain an edge to any of them — a forbidden cross-seam dep simply will not compile (per architecture.md §Established Decisions [Module Boundaries], §Occupied Resources Crate names).
- The accepted capability set stays sole-sourced from `contracts/pulse-capabilities.toml`, read and bounds-checked at load with the existing `toml` + serde stack; a malformed/absent/unparseable manifest is a harness fault (`CoreError`, `Result::Err`) carrying a named reason — never a report state, never a silent widening. Re-aiming at a newer Pulse is a manifest edit, not a Rust change (per architecture.md §Established Decisions [Accepted Capability Set]).
- The fourth `CoverageMode` variant is a **classification**, not a report state: `ReportState` stays closed over exactly `{Pass, Fail, ManualCheck, KnownResidual, Blocked}` and `Verdict` over `{Pass, Fail, CalibrationRegion}`. A not-Conductor's row must not be expressed by widening either enum (per architecture.md §Standard Contracts run report envelope, §Conventions Error handling).
- `coverage-matrix.md` — "every capability in the SUT capability manifest classified" — is a registered on-disk artifact and the stated definition of done for the scope law; zero gaps is an arch-level invariant, not a chunk convenience (per architecture.md §Occupied Resources On-disk artifacts, §Cross-cutting Patterns Scope law).
- The not-Conductor's boundary must be recorded as a deliberate decision consistent with the standing non-goals ("not a load-tester, no Pulse process management, no UI automation") that §Cross-cutting Scope law already names as the guards against feature creep (per architecture.md §Cross-cutting Patterns Scope law, §Project Intent).
- No new dependency, env var, port, MCP tool, Tauri command, or workspace crate is warranted by this chunk; the `CONDUCTOR_*` namespace and the crate-name registry stay as-is, and the capability manifest deliberately has NO `CONDUCTOR_*` override handle (per architecture.md §Occupied Resources).
- If the representation decision (CARRY 1) resolves toward manifest data, the TOML schema extension must stay within the existing `toml` + serde + garde load path and preserve the manifest-as-single-source rule; arch prescribes no new config format or loader (per architecture.md §Established Decisions [Scenario Config Format], [Accepted Capability Set]).

## Patterns to follow
- Data-over-constant, already established once: the compile-time `001..=060` bound in `pid_format` was superseded by manifest membership via `Scenario::check_capabilities` / `from_toml_str_with` at the three binary-edge load sites. The 60-row `static COVERAGE` is the *same* hardcode class, and the shipped precedent shows the resolution shape either way (per architecture.md §Established Decisions [Accepted Capability Set]).
- Exhaustive-`match` fan-out is the intended cost of the crate-per-seam design: adding a variant to a core enum surfaces every consumer at compile time. Enumerate consumers from the compiler/code graph rather than a list, and let each seam's own render layer decide presentation (per architecture.md §Established Decisions [Module Boundaries], §Design Philosophy compiler-enforced seams).
- Serde canonical-name (de)serialization for the new wire spelling, matching the run-report envelope's existing string-enum treatment of `verdict`/`state`; snake_case/kebab-case per §Conventions naming, with round-trip coverage (per architecture.md §Stack Serialization (JSON), §Conventions Naming patterns).
- `&'static str`-backed, no-runtime-IO static tables are the current shape of `coverage.rs`; the parallel arch precedent is the `runs.db` "column types fixed on first write" discipline — the representation choice is load-bearing and should be settled before the table widens (per architecture.md §Conventions Data model conventions).
- Doc reconciliation follows the established cascade pattern: a superseded spec value in `architecture.md` is corrected in place at the chunk that makes it wrong (the 2026-08-08 de-hardcoding sweep's own residue), with the history entry landing in the amendment sidecar (per architecture.md §Established Decisions [Accepted Capability Set]).

## Anti-patterns to avoid
- Do not re-introduce a compile-time P-ID upper bound or any second source of the accepted set — that is the exact reversal the 2026-08-08 amendment made, and it would make `check_sut_drift` compare a source against itself or fail on the next Pulse release (per architecture.md §Established Decisions [Accepted Capability Set]).
- Do not express "not Conductor's to verify" as `Blocked`, `ManualCheck`, or an absent row: `Blocked` means a named unmet precondition on a *measurable* scenario, and absence is precisely the implied-boundary this chunk is retiring (per architecture.md §Established Decisions [Read-Back Dependency Posture], §Standard Contracts).
- Do not add a `CONDUCTOR_*` env handle, CLI flag, or override path for the classification source; the capability manifest was deliberately given no override handle (per architecture.md §Occupied Resources Environment variables).

- **Crate-name registry → all domains.** `conductor-core` / `-report` / `-cli` / `-tauri` are the locked names every domain's content lands in; design/layouts/tests all reference these paths (arch §Occupied Resources Crate names).
- **Run-report envelope → tests + design.** `verdict ∈ {Pass, Fail, CalibrationRegion}` and `state ∈ {Pass, Fail, ManualCheck, KnownResidual, Blocked}` are fixed; the new `CoverageMode` variant is a *separate* axis, so design's lamp mapping and tests' envelope fixtures must not be widened by it (arch §Standard Contracts).
- **`coverage-matrix.md` artifact → tests + layouts.** The artifact is arch-registered and the definition-of-done gate; its row count and completeness are simultaneously a tests assertion and a layouts render target (arch §Occupied Resources, §Cross-cutting Scope law).
- **Doc reconciliation → design-system + layout-templates.** This chunk corrects arch's own `:33` "60-P-ID coverage tables" claim; the parallel 60/82 claims in `design-system.md` and `layout-templates.md` are those plans' amendments, coordinated in lockstep (the security-plan lockstep precedent, amendments 2026-06-27 / 2026-08-08).
