## Constraints
1. **No new span names.** The bounded span-name set is closed (`scenario.run`, `timeline.execute*`, `emit.batch`, `emit.logs_batch`, `verify.readback*`, `report.generate`, `db.insert_run`, `fault.*`, `tauri.command.*`) per obs-plan.md §11 Spans/Traces. The Tauri coverage view already occupies `tauri.command.coverage_matrix`; widening the table adds no traceable operation.
2. **Do not instrument `coverage_matrix()`.** It is a no-runtime-IO `static` lookup; adding spans/log lines to a pure table read violates obs-plan.md §11 Telemetry Strategy ("NEVER over-instrument hot paths"). Instrumentation belongs only at boundary calls (manifest load, DB, MCP, report write) per §6 "Boundary-call wrappers".
3. **Artifact hygiene: no internal struct/variant names in rendered output.** The new mode's `label()` and any operator-facing string must be a human/agent label, never the Rust identifier — obs-plan.md §11 Logs + PII Scrubbing ("NEVER leak absolute host paths or internal struct names in logs / run-report / runs.db"). The serde wire spelling is a data contract, not an artifact string; keep the rendered cell distinct from the variant name.
4. **New log fields must be allowlisted or they vanish.** Field-name allowlisting is enforced at the tracing-subscriber *processor* stage (obs-plan.md §11 PII Scrubbing: "NEVER scrub only at sink stage"; single-location ownership in `conductor-core::redact`). Currently permitted event fields are the 7 identity fields + `message`/`phase`/`count`/`panic`/`location` + the reserved envelope fields — a field like `mode` or `unclassified_count` is silently DROPPED unless added there (`D:\dev\projects\conductor\crates\conductor-core\src\redact.rs:21`).
5. **The coverage-completeness gate spec stays manifest-relative.** `db.query_all_p_ids`'s `p_id_count_expected` and the `p_ids` log field name the manifest's capability count/set, never a literal — obs-plan.md §4 (coverage-matrix completeness gate) + §1 must-trace table. Building that gate is out of scope (Epoch 6), but nothing this chunk writes may re-hardcode a fixed count into that spec's semantics.
6. **Boundary-log levels.** `info` for boundary-call summaries and state transitions, `debug` for internal control flow (obs-plan.md §6 Log levels mapping); `conductor-core`/`conductor-report`/`conductor-cli` base level is `info`. The existing manifest-load line (`count` at `info`) is the pattern for any classification-count summary.
7. **No panic path on classification failure.** Zero-unlogged-panics is the always-required Minimal-tier SLO invariant (obs-plan.md §10) — a drift/classification mismatch surfaces as a typed `Err` through the `Display`-not-`Debug` `anyhow` edge, never `panic!`/`unwrap` in library code.

- **Adding a `mode`/`p_id`-typed field to a log line without the allowlist** — obs-plan.md §11 PII Scrubbing ("NEVER skip the field-allowlist / redaction layer"; single-location ownership in `conductor-core::redact`). A dropped field is a silent obs regression, not a compile error.
- **Any OTel/metrics reach for the classification counts** (a meter/histogram for coverage percent) — obs-plan.md §11 Metrics + §5: Minimal tier has no metrics backend; coverage counts are JSON field assertions only.
