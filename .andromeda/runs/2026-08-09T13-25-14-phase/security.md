# security extract

## Relevance
Partial — no new trust boundary, subprocess, secret, or network surface; security applies via the capability-manifest input boundary (if the representation decision extends the TOML schema), artifact/error sanitization for the new `CoverageMode` rows, out-of-band sourcing from Pulse-owned data, and the standing dependency/audit gate.

## Constraints
- If P4 resolves the representation question toward **manifest data** (per-capability title/category/mode in `contracts/pulse-capabilities.toml`), every added field is validated at load in the same bounds-check pass that already checks version/date/`P-NNN` shape/duplicates — an extended `serde` deserialize with no matching validation is a widened boundary, not a schema tweak (per security-plan.md §Input Validation, capability-manifest row as registered by the 2026-08-08 amendment; §Security Anti-Patterns § Input).
- The manifest stays a fixed path resolved through the existing traversal guard with **no `CONDUCTOR_*` override**, and read/parse faults keep carrying `e.kind()` / sanitized text only — never the resolved absolute path (per security-plan.md §Input Validation, env-var path-handle row; §Error Handling, external responses).
- The new not-Conductor's rows and the widened table feed `<run_id>.md`, `runs.db` rows and CLI output: those rendered rows may carry identity/classification fields only — no absolute host paths, no internal seam-crate struct/field names (per security-plan.md §Error Handling, run-report artifact sanitization).
- P3's sourcing of titles/categories from `D:\dev\projects\andromeda-pulse\` is an **out-of-band research read**: the result lands as committed Conductor workspace data. Production code must open no Pulse-owned file at runtime and must introduce no path handle into Pulse's tree (per security-plan.md §Data Protection, encryption/ownership scoping; §Security Anti-Patterns § Data Protection, corpus/SUT-owned-data ban).
- Zero dependency delta is expected; `Cargo.lock` must stay un-drifted and committed, and the release/merge gate requires `cargo-audit` + `cargo-deny` green — this is the Minimal-tier residual-risk control, not an optional step (per security-plan.md §Dependency Security; §Security Anti-Patterns § Universal).
- `KNOWN_UNCLASSIFIED → []` must be a genuine retirement, not a suppression: `check_sut_drift` stays a live two-source comparison whose failure surfaces as a typed harness fault, never a silently-downgraded pass (per security-plan.md §Error Handling, verdict/error wall; §Security Anti-Patterns § Universal, never-silently-downgrade).
- Conductor owns no secrets and gains none here: no new env handle, no credential-shaped string in the classification data or the Pulse-sourced titles (per security-plan.md §Secret Management; §Security Anti-Patterns § Secrets).

## Patterns to follow
- `D:\dev\projects\conductor\crates\conductor-core\src\capability_manifest.rs` — `load()` returns `CoreError::Config` built from `e.kind()` / `sanitize_error(&e)`, with `validate()` doing non-empty + `P-NNN` shape + duplicate checks; extend this same function for any new schema field rather than adding a second parse path.
- The regression test `load_failure_message_never_contains_the_path` in that file is the existing enforcement of the no-path-leak rule — keep it green and extend it to any new failure message.
- `D:\dev\projects\conductor\crates\conductor-core\src\config_path.rs` — `resolve_under` is the shipped traversal guard used for artifact/config handles; reuse rather than re-deriving path resolution.
- `D:\dev\projects\conductor\crates\conductor-core\src\coverage.rs` — the `label()` ↔ serde-wire equality plus round-trip tests (`mode_label_matches_serde_wire`) are the existing shape discipline the fourth variant and `ALL` must extend, so no consumer falls back to a permissive catch-all arm.
- `deny.toml` accepted-exceptions discipline (justified per-advisory ignore / license allow, each with a comment) is the only sanctioned way to keep the gate green if a transitive advisory appears — not gate relaxation.

## Anti-patterns to avoid
- NEVER deserialize an extended capability-manifest schema without load-time validation — the load-time bounds check *is* the trust boundary for this artifact (per security-plan.md §Security Anti-Patterns § Input).
- NEVER let the coverage renderers, the `blocked`/classification rows, or any new error string expose absolute host paths or internal struct names to CLI stderr, `#[tauri::command]` returns, or `<run_id>.md` (per security-plan.md §Security Anti-Patterns § Logging).
- NEVER have production code read, copy, or embed a live path into Pulse-owned files/repos to obtain titles or categories — corpus and SUT-owned data are accessed only via MCP read-back, and this chunk needs neither (per security-plan.md §Security Anti-Patterns § Data Protection).

## Contract bindings
- **CI security gate ↔ tests domain:** the chunk-level DoD gate set (nextest, doctest, clippy `-D warnings`, **audit**, **deny**, `agent-run.sh run`) means the security gate rides as jobs in the single existing workflow — tests owns the harness, security owns the pass condition (per security-plan.md §Dependency Security, CI integration; §Bootstrap phases, dep-security-ci-gate).
- **Artifact sanitization ↔ obs/report:** the coverage rows are re-rendered into the Markdown run report and the CLI table; the no-absolute-path / no-internal-struct-name rule is a shared invariant with the report + obs artifact schema (per security-plan.md §Error Handling, run-report artifact sanitization).
- No auth, design, or a11y binding — auth approach is `none` and this chunk adds no identity or UI-automation surface.

## Acceptance criteria contributions
- (security) `cargo audit` exits 0 and `cargo deny check` (advisories, bans, sources, licenses) is ok with `Cargo.lock` un-drifted and committed; the expected dependency delta is zero (per security-plan.md §Dependency Security; §Security Anti-Patterns § Universal).
- (security) If the manifest TOML schema gains per-capability fields, `CapabilityManifest::validate` rejects empty/malformed/duplicate/unknown-mode entries at load, and a test asserts each rejection returns `CoreError::Config` — no unvalidated deserialize path exists (per security-plan.md §Input Validation, capability-manifest row; §Security Anti-Patterns § Input).
- (security) Every manifest/classification failure message and every rendered coverage row is free of absolute host paths and internal seam-crate struct names; `load_failure_message_never_contains_the_path` stays green and covers any new message (per security-plan.md §Error Handling, run-report artifact sanitization; §Security Anti-Patterns § Logging).
- (security) No production code path opens a file under Pulse's repository or data directory, and no new `CONDUCTOR_*`/`ANDROMEDA_*` env handle or secret-shaped string is introduced by the P3-sourced titles/categories (per security-plan.md §Data Protection; §Secret Management).
