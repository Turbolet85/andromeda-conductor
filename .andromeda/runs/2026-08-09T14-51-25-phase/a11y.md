# a11y extract

## Relevance
Relevant — the desktop `CoverageMatrix` + footer roll-up are on a must-be-accessible path (run-report view) and this chunk mints a new visual state treatment; the CLI table and Markdown report fall outside a11y's assertable reach.

## Constraints
- The out-of-scope treatment must be **never-color-alone**: color paired with a text label plus a glyph supplement, machine-verifiable from DOM text-content + axe-core — the same shape the six lamp states already carry (per `.andromeda/a11y-plan.md` §6 State color tokens; §11 Anti-Patterns → Visual).
- The **display-label ↔ obs `verdict`/`state` crosswalk stays six rows**. Out-of-scope is a coverage mode with no envelope enum, so it must not be added to the crosswalk, must not become a seventh lamp, and the not-color-alone assertion set is unchanged (per §6 State color tokens crosswalk — this is also what makes the scope's "no sixth lamp" boundary a11y-consistent).
- Any token the treatment uses must be a **verbatim design-system token name** with a row in the contrast-pair table and a `colorjs.io` token-name assertion — 3:1 SC 1.4.11 if it is a non-text row/status indicator, 4.5:1 SC 1.4.3 if it is text. Never invent a token; raw values stay in design-system (`[NO_RAW_DESIGN_VALUES]`) (per §6 Color contrast pairs; §3 Contrast verification harness).
- Coverage-matrix semantics are fixed: `list`/`listitem` (or table) rows, `aria-selected`/`aria-current` + `--border-emphasis` on the selected row, and **virtual-scrolled off-screen rows stay reachable/announceable** — de-emphasis must not remove out-of-scope rows from the a11y tree (per §4 pattern catalog → Coverage matrix; §11 → Screen Reader).
- The footer status strip is the `contentinfo` landmark; a roll-up count change is an SC 4.1.3 status message announced via `status`/`aria-live` **without stealing focus** during a live run or from the HOLD trap (per §4 landmark inventory; §5 run-report-terminal; §11 → Keyboard).
- Any transition added to the row/roll-up treatment must collapse under `prefers-reduced-motion: reduce`, enforced CSS-natively via the Tailwind `motion-reduce:` variant — no JS motion library (per §6 Motion tokens; §11 → Motion).
- The CLI surface is **not-assertable**: its ASCII prefix + `NO_COLOR` text pairing is output-stream discipline, not a WCAG verification path — no a11y conformance claim or axe reach for `coverage_table_styled` (per §1 A11y scope → conductor-cli entity; §11 → Universal).

## Patterns to follow
- Six-state lamp treatment shape (§6 State color tokens / §4 catalog → Verdict lamp): label + distinct glyph per state (`Blocked`+hollow-ring, `Manual`+checkbox-glyph, `Residual`+dashed-ring) — pick an out-of-scope glyph distinguishable from those three, not just a tint or opacity shift.
- Contrast harness extension pattern (§3 Contrast verification harness / §6 Color contrast pairs): add token pairs to the existing `colorjs.io` token-name checker that resolves compiled CSS custom properties and emits `{ token_fg, token_bg, ratio, required, pass }` — extend the pair list, not the mechanism.
- Violation/ratio JSON folding (§3 Structured violation JSON schema): axe rule-id + WCAG-SC tag + DOM-relative selector / `data-testid` tuple rides in `fingerprints[]` of the obs envelope; no new top-level fields, no absolute host paths or internal struct names.
- Semantic-HTML-first styling (§4 Naming convention; §11 → ARIA): express the treatment as token-driven classes on the existing semantic `listitem`/cell, not as new ARIA or a `role`-decorated `<div>`.
- Keyboard/focus harness reuse (§3 Focus + Keyboard test harnesses; §5): WebdriverIO `browser.keys()` + `document.activeElement` row-nav assertions over the tests' `@crabnebula/tauri-driver` session — no second automation stack.

## Anti-patterns to avoid
- NEVER convey the out-of-scope classification by color/tint/opacity alone (§11 → Visual, SC 1.4.1) — a de-emphasis-only row treatment fails the gate even though it visually "reads" different.
- NEVER `aria-hidden`, `display:none`, or virtualize out-of-scope rows out of the accessibility tree as a way to de-emphasize them (§11 → Screen Reader, SC 1.3.1 / 4.1.2).
- NEVER ship a treatment token pair below its minimum (3:1 non-text / 4.5:1 text) or reuse `--status-fail` / `--count-blocked`, which are bound to the `Fail` / `Blocked` labels in the crosswalk (§11 → Visual; §6 State color tokens).

## Contract bindings
- **a11y ↔ design:** the out-of-scope token name must originate in design-system §Color Palette; a11y reproduces the name verbatim and owns the contrast-pair assertion (§6 Source-of-truth; §3 Contrast verification harness).
- **a11y ↔ obs:** treatment assertions emit through the obs §6 envelope with results in `fingerprints[]`; the crosswalk is the join key and out-of-scope contributes **no** `verdict`/`state` value (§3 Structured violation JSON schema; §6 crosswalk).
- **a11y ↔ tests:** axe-core + colorjs.io + WebdriverIO-keyboard ride the tests `wdio run` webview-E2E job on Linux+xvfb and surface via the `logs` command of the 5-command harness; operator/local gate, not a CI gate (§3 CI integration; §9).
- **a11y ↔ layouts:** the wrap-time `layout-templates.md` §Component block 1 Mode-cell extension must record the label + glyph pairing and the footer roll-up's reachability so the layout spec and the not-color-alone assertion do not diverge (§5 Focus order per layout → run-report-terminal).

## Acceptance criteria contributions
- (a11y) Not-color-alone: with color stripped, an out-of-scope row still exposes its mode text label (and glyph) in DOM text-content; the six lamp display labels are unchanged and no seventh crosswalk row exists (a11y-plan §6 State color tokens; §11 Visual).
- (a11y) Contrast: every token pair introduced by the desktop treatment passes the `colorjs.io` token-name assertion at its required ratio (3:1 SC 1.4.11 non-text / 4.5:1 SC 1.4.3 text) and is added to the §6 Color contrast pairs table.
- (a11y) axe-core with `withTags(['wcag2a','wcag2aa','wcag21aa'])` against the report-terminal state returns `violations.length === 0` — including `list`/`listitem`/`aria-required-children` — with off-screen virtual-scrolled out-of-scope rows still present in the accessibility tree (§3 Configuration; §10; §11 Screen Reader).
- (a11y) Keyboard + status: out-of-scope rows are reachable in natural DOM order (no `tabindex > 0`), and the separated out-of-scope/in-scope roll-up count announces via `status`/`aria-live` without stealing focus (§5; §11 Keyboard).
