# arch extract

## Relevance
Relevant (foundational) — three surfaces across three locked crates plus the non-Cargo `ui/` subtree; no new external surface, no new occupied resource expected.

## Constraints
1. **Crate placement is locked** — the treatment lands only in `conductor-report` (Markdown seam), `conductor-cli` (presentation layer), and `crates/conductor-tauri/ui/`, reading the classification from `conductor-core`. No 10th workspace member, no new cross-seam dependency edge (per architecture.md §Occupied Resources "Crate names" + §Established Decisions [Module Boundaries]).
2. **The `ui/` subtree is not a Cargo member** and its design tokens must be declared on `:root` in `src/styles/tokens.css` — Tailwind v4 `@theme` tree-shakes non-namespace tokens, so a new out-of-scope token declared outside `:root` silently vanishes from the build (per §Occupied Resources "Frontend asset subtree" + §Inherited Defaults "Frontend").
3. **The presentation stack is pinned and closed** — comfy-table 7 + owo-colors 4 for the CLI table, tty-gated, explicitly "never color-alone"; React 19 + Tailwind v4.1 for the webview. Adding a rendering/glyph/color dependency for this treatment would require a §Stack amendment (per §Stack and Technologies, Terminal output rendering + Desktop frontend rows).
4. **`Verdict` and `ReportState` are closed enums behind the verdict/error wall** — coverage mode is orthogonal to that axis; the chunk may not add a state, a lamp, or a `Result::Err` path to express out-of-scope (per §Standard Contracts "Run report envelope", §Conventions "Error handling", §Established Decisions [Probabilistic-Assertion Policy]).
5. **`Blocked` has a contract-defined meaning** — never-measured, identity fields only, all measurement fields JSON `null`, plus a named precondition string. An out-of-scope row is measured-never-in-play, not never-measured; it must not occupy the precondition slot or the null-measurement shape (per §Standard Contracts, readiness gate paragraph).
6. **The accepted set is manifest data; the classification is a code-native no-runtime-IO `static`** held to set-equality by `check_sut_drift`. This chunk consumes both; it introduces no runtime read of `contracts/pulse-capabilities.toml` on a render path (per §Established Decisions [Accepted Capability Set]).
7. **Artifact conventions** — `coverage-matrix.md` is the registered kebab-case on-disk artifact whose definition of done is "every manifest capability classified, zero gaps"; the roll-up change must not turn a separated out-of-scope count into a missing-row count (per §Occupied Resources "On-disk artifacts" + §Cross-cutting Patterns "Scope law").

## Patterns to follow
- **Seam-local rendering over shared render code** — each surface renders in its own crate from the single core classification; the crate-per-seam workspace is the enforcement mechanism, so resist a shared "renderer" helper that would need a new dependency edge (§Established Decisions [Module Boundaries], §Infrastructure Patterns directory structure).
- **Dual-surface adaptation by name** — desktop CSS var ↔ CLI ANSI code named for the same concept, the shipped pattern behind the tty-gated `owo-colors` status lines and the `:root` token bundle (§Stack and Technologies, both rendering rows).
- **Text label carries the semantics, color decorates** — the existing `label()` text is the survivable channel under `NO_COLOR`/piping/monochrome, matching the CLI layer's "never color-alone" rule (§Stack and Technologies, Terminal output rendering row).
- **Frontend-before-cargo build order** — `tauri-build`'s `generate_context!` resolves `ui/dist` at compile time, so any `ui/` edit requires `npm run build` before a workspace cargo build/nextest/clippy that compiles `conductor-tauri` (§Infrastructure Patterns, Build system).
- **Consume the shipped static, don't re-derive** — `tally()` and the row set already sum correctly on every surface; the roll-up separation is a presentation regrouping of existing counts (§Established Decisions [Accepted Capability Set]).

## Anti-patterns to avoid
- **Minting a new report state, a sixth lamp, or an `Err` variant** to represent out-of-scope — the verdict/error wall reserves `Result::Err` for harness faults and the two enums are contract-fixed (§Conventions "Error handling", §Standard Contracts).
- **Any new dependency or new `CONDUCTOR_*` env var to gate the treatment** — the env namespace is an enumerated registry and the rendering stack is pinned; a config handle for a visual choice is out of pattern (§Occupied Resources "Environment variables", §Stack).
- **Hardcoding a capability count** in prose, comments, CSS, or a roll-up string — the accepted set is versioned data (this is exactly the stale "all 60 capabilities" comment the scope's carried nit targets) (§Established Decisions [Accepted Capability Set], §Conventions "Naming patterns").

## Contract bindings
- **Run report envelope (§Standard Contracts) ↔ report/storage seams** — coverage mode is a coverage-matrix concept, not an envelope field; the envelope JSON and the `runs.db` column set must be unchanged by this chunk.
- **Never-color-alone rule (§Stack, Terminal output rendering) ↔ design + a11y plans** — arch fixes the mechanism (tty gating, `:root` tokens); the token names, glyph choice, and contrast targets are design/a11y's call.
- **Frontend build-order coupling (§Infrastructure, Build system) ↔ tests plan** — the negative-guarantee test touching the webview surface inherits the `npm run build` prerequisite in both `agent-run.{sh,ps1}` and the CI Rust job.
- **`coverage-matrix.md` artifact registration (§Occupied Resources) ↔ layouts plan** — arch owns the artifact's existence/naming; the Mode-cell treatment text extended at wrap lives in `layout-templates.md` §Component block 1, not in arch.
