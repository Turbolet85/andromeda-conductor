## Relevance
Relevant — this chunk is purely per-surface visual/layout treatment inside two surfaces I own (desktop-webview coverage matrix + footer roll-up, cli `conductor coverage` table).

## Constraints
- The out-of-scope treatment lands in the **Mode cell** of the coverage-matrix row anatomy, which already enumerates exactly four text values with `not-Conductor's` as the fourth — extend that cell, do not add a new column or re-order the row (per layout-templates §Component — Primary content block 1, `:126`).
- The desktop matrix stays a **dense single-row-per-P-ID list** at `color-raised-1` / `radius-md` / `border-subtle` dividers / row padding `space-md`, borders-only depth, no shadow — an out-of-scope row must not become a card, a section break, or a collapsed group (per layout-templates §Component — Primary content block 1).
- Status/classification is **never color-alone** and never color-only in the Mode cell: the tint must be carried by the existing text value (and any added glyph), so the row survives a color-blind read (per layout-templates §Component — Primary content block 1; §Component — Footer).
- The **header strip tally counts all four modes and sums to the row count**; separating an out-of-scope count from the in-scope denominator must preserve that sum (per layout-templates §Component — Primary content block 1; §cli Primary content block 1 summary caption, where per-state counts sum to the step denominator = the manifest's accepted set).
- The footer status strip is a **single-line Label-role strip** at `space-sm` height, `text-tertiary`, each count token tinted in its own status color and **paired with its label** — an added out-of-scope token joins that same roll-up form, not a second line or a badge (per layout-templates §Component — Footer (status strip)).
- CLI treatment is **adapted not forked**: the cli mirrors desktop tokens by name (desktop CSS var ↔ ANSI code) inside the existing **6-column** `comfy-table` with terminal-detected width; adding a 7th column would be a breaking change to downstream parsers (per layout-templates §Component — Primary content block 1 (cli); §cli IA notes Command model + Multi-surface coordination).
- Every cli state cell pairs color with an **ASCII text prefix** so it survives `NO_COLOR` / piping / screen readers (per layout-templates §Surface: cli signature-placement preamble; §cli IA notes Pipe discipline — and emoji is banned in piped machine-parseable output).

## Patterns to follow
- **Mode cell as text-first classification** — the four-value text cell already renders on all three surfaces; the treatment attaches tint/glyph to that existing text, matching how every other cell pairs signal with label (layout-templates §Component — Primary content block 1).
- **Non-verdict states rendered as visually distinct-but-quiet** — `KnownResidual` (muted dashed-ring dot + `status-residual` note line) and `ManualCheck` (neutral `status-manual` checkbox glyph) are the in-plan precedent for "present, legible, deliberately not the verdict triad." Out-of-scope should read in that quiet register, not the alarm register (layout-templates §Component — Primary content block 2; §Decisions Log Motion trigger placement).
- **Row-state affordances already defined** — selected row = `border-emphasis` left edge, hover = `color-raised-1` lift over `motion-micro`; any out-of-scope de-emphasis must not collide with or suppress these (layout-templates §Component — Primary content block 1, States).
- **Footer roll-up token form** — `3 Pass · 1 Calib · 1 Fail · 1 Manual · 1 Residual · 1 Blocked`, each token count + label in its own status color; the cli summary caption mirrors the same tally shape (layout-templates §Component — Footer; §cli Primary content block 1 caption).
- **Bracket-prefix cli vocabulary** — `[PASS]`/`[HOLD]`/`[FAIL]`/`[MANUAL]`/`[RESIDUAL]`/`[BLOCKED]` with glyph companions (`✓ ✗ ? ~ •`); any out-of-scope marker follows the same prefix+glyph construction rather than inventing a new signalling channel (layout-templates §Component — Primary content block 2 (cli)).

## Anti-patterns to avoid
- **Do not reuse the `status-fail` or `count-blocked` tokens (or ANSI 203 / ANSI 60) for out-of-scope**, and do not give it the `Blocked` hollow-ring lamp or the `Blocked` named-precondition detail slot — `Blocked` ≠ red and out-of-scope ≠ `Blocked` (layout-templates §Component — Primary content block 2; §cli Primary content block 1).
- **Do not mint a sixth lamp state.** The lamp is the 6-state verdict/report-state convention on the verdict axis; coverage mode is an orthogonal cell. Expressing remit through the lamp would collapse two axes (layout-templates §Component — Primary content block 1, status-lamp glyph enumeration; §Decisions Log Cross-surface IA decisions).
- **No motion to signal out-of-scope** — no flash, blink, pulse, glow, or staggered treatment; the surface's only High-impact moment is the operator-pause freeze, and everything else resolves motionless over `motion-micro` at the 0.3 expression budget (layout-templates §desktop-webview Expression level; §Decisions Log Motion trigger placement).

## Contract bindings
- **Never color-alone → a11y**: the desktop Mode tint + optional glyph and the cli prefix are stated here as layout requirements; a11y derives the concrete non-color redundancy and contrast conformance (layout-templates §Notes — accessibility behavior stated as design/behavioral requirements).
- **If the out-of-scope row's Mode change is announced** (e.g. on matrix reload), the live-region attribute is a11y's derivation, not layout's (layout-templates §Component — Primary content block 1, verdict-change announcement).
- **Token names → design**: layout names `status-residual` / `status-manual` / `count-blocked` / `status-fail` / `color-id-cyan` by name only; any new out-of-scope token's hex and its ANSI counterpart are the design plan's to author, and the desktop↔cli name mapping table is the shared contract (layout-templates §IA notes Multi-surface coordination; §Notes).
- **cli column count → tests/CLI contract**: the 6-column `comfy-table` shape is a parsed-output contract; a treatment that changes column count or ordering is a breaking change requiring a `--format` flag (layout-templates §cli IA notes Command model).
- **Reduced-motion / `NO_COLOR`** are stated layout invariants whose enforcement lands with a11y and the cli styling path (layout-templates §Notes; §cli Header/banner).
