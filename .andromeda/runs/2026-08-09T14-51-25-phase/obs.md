## Constraints
- **No new spans required; do not over-instrument the render path.** Coverage rendering is not one of the 7 must-trace critical paths; per obs-plan §11 (Telemetry Strategy) "NEVER over-instrument hot paths" and §4 (auto-instrumentation table: report is manual-span-only). The existing `tauri.command.coverage_matrix` info-span + boundary `info!` line (`crates/conductor-tauri/src/commands.rs:123-130`) is the whole obs surface for the webview leg — extend fields, don't add per-row spans.
- **Bounded span-name set holds.** If any span is added it must be `{module}.{operation}` from the closed set (`report.generate`, `report.coverage_matrix_generate`, `report.validate_coverage`, `tauri.command.*`) — never per-P-ID / per-mode names, per obs-plan §11 (Spans / Traces) and §4 span-naming convention.
- **Field-name allowlist is a hard gate on any new log field.** Per obs-plan §11 (PII Scrubbing) + §3 redaction wiring, a non-allowlisted event field is DROPPED at the `tracing-subscriber` processor stage. `crates/conductor-core/src/redact.rs:21` currently allows only identity + `message`/`phase`/`count`/`panic`/`location` + the 11 envelope fields — a new roll-up field (e.g. an out-of-scope count) either reuses `count` or requires an allowlist addition, which is an obs-plan §6 amendment.
- **No absolute host paths / internal struct names in rendered artifacts.** Per obs-plan §11 (Logs) + §3 log-format schema, all three rendered surfaces (`coverage-matrix.md`, the CLI table, the webview rows) are paste-to-AI artifacts; the value scrub masks absolute host-FILE paths, and struct names are kept out by the allowlist + `Display`-not-`Debug` at the `anyhow` edge — never by `::`-token redaction. This is the chunk's own stated invariant, and obs owns it.
- **Webview frontend: console JSON only.** Per obs-plan §1 (Telemetry surfaces → desktop-webview) and §11 (Universal), `CoverageMatrix.tsx` must add NO OTel JS SDK, NO browser OTLP export (neither `:4317` nor `:4318`), NO `web-vitals` network export — any frontend diagnostic is `console.log(JSON…)` only (recursion guard). Grep confirms the UI currently emits zero console/telemetry calls; keep it that way unless a console-JSON line is deliberate.
- **Zero unlogged panics on the roll-up arithmetic.** Per obs-plan §10 (Always-required SLO invariant) + §11 (Error Reporting), separating out-of-scope from the in-scope denominator must not introduce a divide-by-zero / index panic; any error path is `tracing::error!` + `anyhow` at the binary edge (Tauri: `conductor_core::sanitize_error`), never a raw panic or a retry-once.
- **Structured, not unstructured, stderr.** Per obs-plan §11 (Logs) "NEVER use unstructured stderr text": the CLI coverage table is stdout operator/agent output; any diagnostic the render path emits goes to the JSONL self-obs stream with `run_id` + service identity, not to bare stderr text.

## Patterns to follow
- **Manual `info_span!` inside a `#[tauri::command]`, not the `#[tracing::instrument]` attribute** — `crates/conductor-tauri/src/commands.rs:123` (`tauri.command.coverage_matrix`), the pattern codified in `.claude/rules/observability.md` §Session Additions (2026-06-26); it yields the bounded `tauri.command.*` name and allows allowlisted `count`/`latency_ms` on the boundary `info!`.
- **Boundary-summary `info!` with allowlisted fields only** — the existing "listed coverage matrix" line logs `count` + `latency_ms`; if the roll-up gains a second number, prefer reusing `count` semantics over minting a new field name (see the allowlist constraint above).
- **`#[tracing::instrument(name = "{module}.{operation}", skip_all)]` for library seams** — e.g. `crates/conductor-verify/src/preflight.rs:105`, `crates/conductor-emit/src/client.rs:67` — the shape to copy if (and only if) a report-side span is genuinely warranted.
- **Errors to the webview go through `conductor_core::sanitize_error`** (`crates/conductor-tauri/src/commands.rs:213,222,241`) — Display-not-Debug + host-path scrub at the IPC edge, per obs-plan §11 (Error Reporting).
- **Redaction lives once, at the processor stage** (`conductor-core::redact`) — per obs-plan §11 (PII Scrubbing) "NEVER scrub only at sink stage" / "NEVER hardcode scrubbing rules in single location [other than `redact`]"; render code must not hand-roll its own path-stripping.

## Anti-patterns to avoid
- **No OTel SDK / exporter / `traceparent` anywhere in this chunk** — obs-plan §11 (Telemetry Strategy, Universal): self-obs is `tracing` JSON only; the browser leg produces no OTel spans at all.
- **No high-cardinality instrumentation of the matrix** — obs-plan §11 (Spans): never a span or a metric label keyed by P-ID / capability / mode (82 rows × 4 modes); the roll-up is aggregate counts on one line.
- **No unstructured multi-line output on the diagnostic path** — obs-plan §11 (Logs): the rendered table is a deliberate human/agent artifact, but any accompanying log stays one JSON object per line.

## Acceptance criteria contributions
- (obs) No new telemetry primitive is introduced: zero OTel SDK/exporter references and zero network export added on any surface, including `CoverageMatrix.tsx` (frontend stays console-JSON-only).
- (obs) Any log line added by the render path parses as one JSON object carrying the §3 base fields (`timestamp_ms`, `level`, `target`, `service.name/version`, `deployment.environment`, `run_id`) and uses only allowlisted field names — a non-allowlisted field must be visibly dropped by `conductor-core::redact`, or the allowlist is extended deliberately with a test.

- (obs) The roll-up arithmetic cannot panic: an empty / all-out-of-scope row set yields a defined denominator, and any error surfaces as `tracing::error!` + sanitized `anyhow`, keeping the zero-unlogged-panics CI gate green.
