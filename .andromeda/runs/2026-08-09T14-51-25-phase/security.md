## Relevance
Partial — a render-only presentation chunk; the only live security surfaces are run-report/CLI/webview artifact sanitization and the Tauri webview IPC boundary (no new input boundary, no dependency, no secret, no subprocess).

## Constraints
- Rendered coverage artifacts (`coverage-matrix.md`, the CLI table, the webview matrix) MUST NOT leak absolute host paths (canonicalized `CONDUCTOR_*` dirs, `ANDROMEDA_PULSE_DATA_DIR`) or internal seam-crate struct/field names — they are agent-parseable ground truth shared across hosts (security plan §Error Handling → Run-report artifact sanitization; §Security Anti-Patterns → Logging). This chunk's scope line "no absolute host paths or internal struct names in rendered artifacts" is the same invariant.
- The `blocked` state must keep its distinct semantics: a failed precondition surfaces ONLY as `Blocked` with the named precondition string, never silently reclassified — and conversely the new out-of-scope treatment must not reuse or overload the `Blocked` vocabulary/precondition slot (security plan §Security Anti-Patterns → Universal, "NEVER silently downgrade a failed preflight"). The chunk's negative guarantee (item 4) is the enforcement of this from the other direction.
- The verdict/error wall stays intact: coverage-mode classification is a VALUE returned as `Ok(...)`; no render-path change may convert a mode into a `Result::Err` or a panic (security plan §Error Handling → Internal logging; §Anti-Patterns → Universal "NEVER let a malformed child/transport input panic").
- Operator-visible error text from the render path (`conductor-cli` stderr, `#[tauri::command]` returns) must stay sanitized at the type-erased `anyhow` edge — no stack traces, paths, or library versions (security plan §Error Handling → External responses; §Anti-Patterns → API/Logging).
- Any touch of the Tauri webview surface keeps deny-by-default capabilities: no new `#[tauri::command]`, no `shell-open` plugin use with coverage/scenario-derived strings, no remote-origin iframe in the bundled webview (security plan §Security Anti-Patterns → Code Patterns).
- If any dependency is added for the treatment (glyph/color/table crate on the Rust side, or an npm package under `crates/conductor-tauri/ui/`), `cargo audit` + `cargo deny check` must be green with `Cargo.lock` committed, and `npm audit --omit=dev` clean with `package-lock.json` committed (security plan §Dependency Security, incl. the Frontend (npm) supply chain paragraph). Expectation for this chunk: zero new deps — comfy-table/owo-colors and the existing UI tree already cover it.
- No new external-input boundary is introduced: the classification is read from `conductor-core`, not from a new file/env/CLI handle. Any `NO_COLOR`/tty read is an existing non-path presence-only env trigger requiring no validation, matching the established non-path-handle carve-out (security plan §Input Validation, non-path env-handle note).

## Patterns to follow
- Artifact-sanitization pattern already applied to `<run_id>.md` / `runs.db` rows: identity + verdict/state fields only, no host paths, no struct names — extend the same discipline to the coverage roll-up and Mode cell (security plan §Error Handling).
- `thiserror` typed enums inside the seam crates collapsing to `anyhow` only at the `conductor-cli` / `#[tauri::command]` edges — render helpers should return typed values, not pre-formatted operator strings carrying internals (security plan §Error Handling → Error format).
- Distinct-state-never-collapsed pattern from the readiness gate: `blocked` carries a named precondition string and is never folded into pass/fail — mirror that separateness for the out-of-scope mode rather than borrowing an existing state's vocabulary (security plan §Security Anti-Patterns → Universal).
- Bound-parameter discipline if the roll-up ever reaches `runs.db`: rusqlite parameterized statements, never `format!`-built SQL (security plan §Input Validation, `runs.db` row; §Anti-Patterns → Input). Expected no-op here (render-only), noted as a guardrail.

## Anti-patterns to avoid
- NEVER let the coverage artifacts (`coverage-matrix.md`, CLI table output, webview matrix) emit absolute host paths or internal seam-crate struct/field names (security plan §Security Anti-Patterns → Logging).
- NEVER expose internal error details (stack traces, file paths, library versions, internal struct names) through the CLI stderr or a `#[tauri::command]` return when the render path fails (security plan §Security Anti-Patterns → API + Logging).
- NEVER widen the Tauri IPC surface for this treatment — no unscoped plugin, no permissive capabilities default, no remote-origin iframe in the bundled webview (security plan §Security Anti-Patterns → Code Patterns).

## Contract bindings
- **Artifact sanitization ↔ obs/tests:** the "no absolute paths / no internal struct names in rendered artifacts" invariant is shared with obs (log/artifact field discipline) and must be asserted in the chunk's render golden tests — the same fixtures that carry the item-4 negative guarantee (security plan §Error Handling; focus guide cross-domain bindings).
- **`Blocked` vocabulary ↔ tests:** the negative-guarantee test (no `[FAIL]`/`[BLOCKED]` prefix, no fail/blocked tokens, no precondition slot on an out-of-scope row) is the security-relevant half of the readiness-gate invariant and belongs in the tests plan's golden/render suite (security plan §Anti-Patterns → Universal).
- **Dependency gate ↔ tests §CI Integration:** if any dep lands, the existing single CI workflow's security jobs (`cargo audit`, `cargo deny check`, `npm audit --omit=dev`) are the gate — one workflow, security as a job, not a forked pipeline (security plan §Dependency Security → CI integration).
- **Design tokens:** token naming/color choice itself is design's call; security only binds the "never color-alone" consequence insofar as it keeps state legible in sanitized/piped text output (`NO_COLOR`, piping) — no security ownership of token values.
