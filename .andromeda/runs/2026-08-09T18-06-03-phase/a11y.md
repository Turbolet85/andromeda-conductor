# a11y extract

## Relevance
**Partial** — a11y engages only if the posture caveat (or a P-033 correctness-leg outcome) lands on the desktop-webview run-report surface, one of the four must-be-accessible paths; the `conductor-report` Markdown, `conductor-cli`, and spec/rules homes are outside a11y's reach (cli is flagged not-assertable per a11y-plan §1).

## Constraints
1. **Not-color-alone, and not a seventh lamp state.** If the caveat is signalled visually on the webview it must carry its own always-rendered text label; a token-tinted marker whose label is not one of `Pass`/`HOLD`/`Fail`/`Blocked`/`Manual`/`Residual` is a *classification*, not a lamp state, and must not be folded into the six-label assertion (per a11y-plan §1 A11y triggers → visual-discrimination "non-lamp reuse" note; §6 State color tokens; §11 Visual).
2. **Dynamic caveat = SC 4.1.3 status message.** Content that appears with a run's terminal state must be real prose announced via `role="status"`/`aria-live` (polite; `assertive` reserved for the HOLD phase-line) and must never steal focus (a11y-plan §3 Screen reader test pattern; §11 Screen Reader / Keyboard).
3. **Any new token pair enters the contrast table.** Never invent tokens; foreground/background pairs used by the caveat get a colorjs.io token-name assertion at 4.5:1 (text, SC 1.4.3) / 3:1 (non-text, SC 1.4.11), raw values staying in design-system.md (a11y-plan §3 Contrast verification harness; §6 Color contrast pairs).
4. **Semantic HTML first, ARIA second.** The caveat is native markup inside the `main`/report region (`<section aria-label>`/`<p>`), never `role=note` on a `<div>` and never hand-rolled dialog/disclosure semantics (a11y-plan §4 Naming convention; §11 ARIA).
5. **If it becomes interactive** (expander, link to the deferral record): natural tab order, no `tabindex > 0`, Enter/Space activation, visible `--color-focus` ring (SC 2.1.1 / 2.4.3 / 2.4.7) — asserted in the `run-report-terminal` focus order (a11y-plan §5 Focus order per layout; §11 Keyboard).
6. **Coverage-matrix integrity.** P-033 lives in the matrix; any Mode/Status change keeps `list`/table semantics and keeps every off-screen virtual-scrolled row reachable and announceable (a11y-plan §4 pattern catalog; §11 Screen Reader).
7. **Zero-WCAG-AA-violations invariant with no retry policy** on the run-report path; a not-color-alone failure is itself a gate failure (a11y-plan §10 SLO Invariants).

## Anti-patterns to avoid
- **Never mint a seventh lamp state** for "interpretation not covered", and never convey it by tint or icon alone (a11y-plan §11 Visual; §6 State color tokens).
- **Never render the caveat as a decorative badge/gray skeleton, and never hide it from AT** (`aria-hidden`, `display:none` without an alternative) — it must be real prose in the accessibility tree (a11y-plan §11 Visual + Screen Reader).
- **Never treat the cli/Markdown caveat text as an a11y verification path** and never claim conformance without machine-verifiable JSON evidence (a11y-plan §11 Universal).

## Acceptance criteria contributions
1. **(a11y) Caveat is announced, not just drawn.** If the posture lands on the webview, its text is real prose inside the run-report region and exposed via `role="status"`/`aria-live` without focus theft — asserted by DOM text-content in the wdio spec (a11y-plan §3 Screen reader test pattern; §11 Screen Reader).
2. **(a11y) Not-color-alone holds and the six-label assertion is unchanged.** Any tint/glyph used carries its own always-rendered label, and the lamp-label assertion still keys on the six lamp labels only (a11y-plan §6 State color tokens; §11 Visual).
3. **(a11y) Contrast asserted for any new pair.** Each new foreground/background token pair passes the colorjs.io token-name checker (4.5:1 text / 3:1 non-text) and is added to the §6 pair table (a11y-plan §6; §3 Contrast verification harness).
4. **(a11y) No new AA violations.** `withTags(['wcag2a','wcag2aa','wcag21aa'])` axe run over the report-terminal state returns `violations.length === 0` on the display-gated Linux+xvfb run; if the webview is untouched (Branch B lands only in Markdown/spec/rules), record "no assertable-surface change — no a11y AC" instead (a11y-plan §10; §1 cli not-assertable).
