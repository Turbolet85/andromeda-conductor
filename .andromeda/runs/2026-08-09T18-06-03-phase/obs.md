# obs extract

## Relevance
Relevant — the posture must land in an obs-owned artifact (run-report envelope / JSONL journal / coverage roll-up) and Branch A adds an instrumented scenario leg; the branch choice itself is not obs's call.

## Constraints
1. **Minimal tier — no new signal classes.** Per obs-plan §1 (tier Minimal 0) + §2 + §5: whatever records the posture is a `tracing` JSON field / envelope field. No metrics instrument, no exporter, no new sink. Perf evidence for a real-model leg stays the `latency_ms` + `slo_tier` field assertion, not a histogram.
2. **The Run-report envelope is derived, never re-authored.** Per §3 (Log format JSON schema, 11 fields) + §6: the envelope schema is owned by test-plan §3; a posture marker rides as a *scenario-specific additional field* (the sanctioned extension point), not a schema rewrite. Per §3 "two record shapes", the self-obs base line (`timestamp_ms`/`level`/`target`/service-identity/`run_id`) is a different record and is not the home for a posture field.
3. **`verdict` / `state` are closed enums.** Per §3 + §6: `verdict ∈ Pass|Fail|CalibrationRegion`, `state ∈ Pass|Fail|ManualCheck|KnownResidual|Blocked`. A hypothesis-correctness judgment (Branch A) or a recorded gap (Branch B) must map onto these — §1 Path 4 (CalibrationRegion for the judgment axis) and §1 Path 5 (KnownResidual, explicitly *not* Fail) are the existing carriers. No new token.
4. **Field-allowlist is a hard gate on any new field.** Per §11 PII Scrubbing: `conductor-core::redact`'s field-name allowlist **drops** non-allowlisted field names at the processor stage — a posture field not registered there is silently lost. Values (especially SUT-produced root-cause / hypothesis text) must pass the host-file-path value scrub; `target` stays preserved.
5. **Branch A spans stay inside the bounded set.** Per §4 (must-trace paths, `{module}.{operation}`) + §11 Spans: a real-model read-back reuses `verify.readback*`; the root/leaf chain (`scenario.run` → `timeline.execute*` → `emit.batch` → `verify.readback*` → `report.generate` → `db.insert_run`) is unchanged. No high-cardinality span name (no per-hypothesis / per-root-cause name).
6. **Verdict wall + zero-unlogged-panics survive the non-determinism.** Per §10 (always-required invariant; SLO asserted at report-generation on wall-clock `latency_ms = read_back_observed_at − journal_emitted_at`) + §11 Error Reporting / SLO / project-specific bans: a malformed, empty or absent hypothesis read-back ⇒ typed `blocked`, never a panic and never a false pass; no retry-once to smooth a real-model leg; no soft SLO budget; `std::time::SystemTime` only (never tokio virtual clock).
7. **Operator-gated leg stays out of the §9 CI gate set** (chunk boundary "Never a CI gate"), yet its artifacts must still satisfy §9's conformance rules (per-line base schema, no absolute host paths) so a post-run agent read / paste-to-AI works on the operator-produced JSONL.

## Patterns to follow
- **Assertion-policy split** — §1 Path 4 / §4 severity-lifecycle: mechanical axis hard Pass/Fail, model-judgment axis `CalibrationRegion`, plus a boolean marker field (`severity_choice_calibrated`). This is the shipped precedent for "did the top hypothesis identify the injected root cause".
- **Known-residual classification path** — §1 Path 5 / §4: `report.classify_known_residual` span, `state="KnownResidual"` written to `runs.db`, plus a reason field (`degraded_mode_response`). The existing shape for a deliberate, recorded gap that must not read as a Fail (Branch B's load-bearing home).
- **Scenario-specific additional envelope fields** — §6: `bypass_triggered`, `lifecycle_phase`, `severity_choice_calibrated`, `degraded_mode_response`. Follow this naming/typing style for any interpretation-posture or deterministic-mode marker.
- **Manifest-derived coverage roll-up with a split denominator** — §4 coverage-matrix gate: `p_id_count_expected` = full manifest capability count, `coverage_percent` over the in-scope count, rendered by `conductor_report::coverage::summary_line` / `conductor_cli::render::coverage_summary`. Any P-033 reclassification must flow through the manifest; neither count is ever a literal.

## Anti-patterns to avoid
- **No OTel SDK and no W3C trace context for self-observation** (§11 Telemetry Strategy + Spans) — including any temptation to correlate a real-model leg with Pulse's internals via `traceparent`. Correlation stays `run_id`; the only OTLP Conductor speaks is the PRODUCT fault stream at `:4317`.
- **No prose-only / unstructured posture** (§11 Logs "never unstructured stderr text" + §2 agent-readable invariants) — this is the obs form of the scope's "load-bearing rather than prose alone": the caveat must be `jq`-reachable from the envelope / roll-up, not only Markdown narrative.
- **No leaking SUT free text unscrubbed** (§11 Logs + PII Scrubbing) — model-produced root-cause / hypothesis strings are values like any other: host-file-path scrub applies, and `Display`-not-`Debug` at the `anyhow` edge stands.

## Contract bindings
- **obs ↔ tests (envelope ownership):** the 11-field Run-report envelope is owned by test-plan §3; obs §3/§6 derive from it. A posture field on the envelope is a *tests-binding* change, not an obs-local one.
- **obs ↔ tests (harness / record shapes):** §9's `logs/agent-latest.jsonl` conformance gate asserts the §3 self-obs base schema; the envelope (`runs/<run_id>.jsonl`) has no gate yet — so an envelope-borne posture field is currently unguarded by CI and needs its own assertion in the chunk's tests.
- **obs ↔ security:** redaction/allowlist lives at `conductor-core::redact` (§11 PII Scrubbing) — security §Logging & Monitoring. Separately, §10 Build/deploy failure conditions lists a `cargo-audit` red flag as a gate, which the folded-in PREREQ re-check touches; the remedy choice (floor raise vs `deny.toml`) is security's, obs only requires the gate signal stay machine-readable.
- **obs ↔ a11y:** if the caveat renders in the webview, a11y owns the AT/visual surface; obs owns only the structured-log/JSON shape behind it (frontend telemetry stays console-JSON-only per §1 desktop-webview row).

## Acceptance criteria contributions
1. (obs) Whichever branch lands, the posture is readable as a machine-parseable field from an obs artifact (`runs/<run_id>.jsonl` envelope row, `runs.db`, or the coverage roll-up) via `jq`/`serde_json` — not prose-only (§2 agent-readable invariants, §11 Logs).
2. (obs) Any new field name introduced for the posture is registered in the `conductor-core::redact` field-name allowlist (otherwise dropped at the processor stage), and its value carries no absolute host-file path (drive-letter, `/home`, `/Users`, `%APPDATA%`, `~/.cargo`, `.rustup`) (§11 PII Scrubbing).
3. (obs, Branch A only) The leg's spans use bounded-set names in the `{module}.{operation}` convention (`verify.readback*` for the hypothesis read-back); any genuinely new name is conforming and recorded via the amendment path (§4, §11 Spans).
4. (obs) Zero unlogged panics on the real-model / MCP read-back path: absent or malformed hypothesis ⇒ typed `blocked`/`ManualCheck` row, never a panic and never a silent pass; `latency_ms` computed wall-clock and `slo_tier` asserted at report-generation without softening or retry-to-green (§10, §11 Error Reporting/SLO).
