## Relevance
Relevant — this chunk adds a test leg (Branch A) or a recorded verification-boundary posture (Branch B), plus a supply-chain gate re-check; both are test-plan surface.

## Constraints
- **Test tier is Minimal (0)** per test-plan §1 Scope Summary — breadth is the Minimal baseline plus only §1's named coverage triggers; this chunk must not escalate rigor beyond that.
- **Live legs are never a CI gate** per test-plan §9 (Live-Pulse scenarios) + §6 (driver table): a real-model Branch-A leg runs operator/local via `workflow_dispatch` or `scripts/agent-run.sh`, gated on `ANDROMEDA_PULSE_MCP_ENABLED`; CI runs the rmcp-stub legs only. This matches the chunk's own "Never a CI gate" boundary.
- **Zero-flakiness / zero-retry is standing** per test-plan §10 (Zero-flakiness budget): nextest `retries` stays 0 and a flake is quarantined+root-caused, never retried — so a non-deterministic real-model leg cannot enter the CI test set at all.
- **Assertion-policy split binds the hypothesis check** per test-plan §3 (`run` exit-code semantics) + §6 (severity-lifecycle scenario): model-interpretive claims are `verdict="CalibrationRegion"`, reported-for-human at exit 0, never a hard `Fail`/non-zero exit. A "top hypothesis identifies the injected root cause" assertion is exactly this class.
- **The Run-report envelope is one shared shape** per test-plan §3 (Status endpoint shape + Log format): any caveat field lands identically in the Markdown report, the `runs.db` row and the JSONL journal, carries no absolute host paths or internal seam-crate struct names, and must not be conflated with the self-obs stream.
- **No scenario without a P-ID; catalog assertions stay manifest-relative** per test-plan §1 (Scenario catalog entity) + §6 (coverage-matrix completeness scenario) + §11 Universal (project-specific ban): a Branch-A P-033 scenario must be a checked-in declarative serde+garde config under `scenarios/` keyed by its P-ID, and completeness is set-equality against the SUT capability manifest — no literal counts or P-ID ranges.
- **The supply-chain gate is binding, and CLI tool versions are floors** per test-plan §9 (Supply-chain audit stage / Build failure conditions) + §10 + §4 (Tool-version policy): `cargo audit --deny warnings` + `cargo deny check` green with a committed un-drifted `Cargo.lock`; raising the cargo-audit floor is the sanctioned repair since these tools live outside `Cargo.lock`.

## Patterns to follow
- **Live-gated E2E scenario shape** (test-plan §6 critical-path scenarios): `boot` preflight `ready:true` → assert_cmd `Command::cargo_bin("conductor")` with `CONDUCTOR_RUNS_DIR` → `assert_fs::TempDir`, stdin closed → assert exit code + `[LABEL]` stdout + bound-parameter `runs.db` SELECT + JSONL journal parse; `TempDir` drop is cleanup.
- **KnownResidual precedent for a recorded gap** (test-plan §6 P-032 scenario / §1 Critical Path 5): an acknowledged shortfall reports as a distinct envelope state that is explicitly *not* `Fail` and exits 0 — structurally the same shape Branch B's recorded deferral needs if it lands as state rather than prose.
- **Two-tier golden pattern** (test-plan §4 conductor-report bullet + §7 Golden artifacts): exact-string `assert_eq!` locks the canonical line shape at unit level; insta JSON snapshot with `run_id`/timestamp redaction is the E2E journal golden, CI fail-don't-write.
- **rstest fixture/table pattern** (test-plan §3 Test data bootstrap + §7 Fixture library): `#[fixture]` seeded `conductor-timeline` generator, `#[rstest]` `#[case]` rows for catalog/valid-invalid matrices, `#[once]` in-memory `runs.db` schema — no developer-seeded DB, no raw literals.
- **Preflight state-mapping unit tests against the rmcp in-process stub** (test-plan §4 conductor-verify bullet + §8 mocking table): `ready:false ⇒ Blocked`, `degraded_mode ⇒ KnownResidual`, empty canary ⇒ `Blocked` — the CI-runnable half if the posture is expressed as a precondition/state.

## Anti-patterns to avoid
- **NEVER fake Pulse's reaction as a CI verdict** (test-plan §11 Test Strategy, stack-specific; §8 What NOT to mock) — an rmcp-stubbed "top hypothesis" asserts Conductor's own fixture, not Pulse's interpretation, and would restate the very gap this chunk records.
- **NEVER run a live-Pulse leg as a CI gate, and never absorb its non-determinism with `retries` > 0 / retry-once** (test-plan §11 CI + §11 Quality, backed by §10).
- **NEVER hard-fail (non-zero exit) a model-interpretive claim, and never record the posture as a manual "developer verifies before deploy" smoke step** (test-plan §11 E2E stack-specific; §11 Universal — the only sanctioned human step is the flagged `drive+observe` operator checklist).

## Contract bindings
- **tests §3 Log format ↔ obs-plan §3** — the emission-journal envelope is owned by test-plan §3 and obs derives from it (obs owns only the field-allowlist/redaction layer). If a caveat/interpretation-mode field enters the envelope, obs must follow, and the self-obs stream (`logs/agent-latest.jsonl`, `logs/conductor-tauri.jsonl`) stays a separate schema.
- **tests §9/§10 supply-chain gate ↔ security plan §Dependency Security** — security owns the cargo-audit/cargo-deny floor values; tests owns the gate that must be green. The chunk's "raise the floor, not a `deny.toml` entry, not a CI edit" resolution leaves the tests-side gate command unchanged.
- **tests §1 Critical Path 6 / §6 coverage-matrix scenario ↔ arch coverage classification** (`CoverageMode::Auto` for P-033) — the completeness gate is manifest-relative set-equality only; whether an `Auto` row may legitimately lack a verifying scenario is an arch/coverage-semantics question the tests gate observes, not decides.
- **tests §3 `boot` preflight ↔ arch Standard Contracts** — extending preflight to assert the SUT's L4 mode would change the preflight contract; that is Epoch 2 `v2-18` per the chunk's boundaries, out of scope here.
