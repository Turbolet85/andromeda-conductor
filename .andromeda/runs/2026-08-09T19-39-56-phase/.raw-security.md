# security extract

## Relevance
Partial — no new external-input surface or dependency delta, but the chunk adds three operator-authored config files at a named validation boundary and inherits an unresolved audit-gate deferral.

## Constraints
- New `scenarios/*.toml` files enter through the scenario-config boundary; they MUST deserialize through the garde-validated path (`#[derive(Validate)]` `range` + `#[garde(custom)]` cross-field, co-located with the serde structs in the owning seam crate), never a bare `serde` deserialize — per security-plan.md §Input Validation (scenario-config row) and §Security Anti-Patterns → Input.
- Every new scenario MUST carry a Pulse P-ID and MUST validate against the pinned `contracts/pulse-capabilities.toml` accepted set (non-empty version/date/set, `P-NNN` shape, no duplicates; fixed path through `resolve_under`, no `CONDUCTOR_*` override) — per security-plan.md §Input Validation (capability-manifest boundary, added 2026-08-08) and §Security Anti-Patterns → Universal ("no scenario without a P-ID").
- Validation failures on the new TOMLs MUST surface as `ConfigError` → harness fault (`Result::Err`), never as a verdict, and never as a panic — per security-plan.md §Error Handling (verdict/error wall).
- The three coverage roll-up surfaces (Markdown report · CLI table · webview) and any `blocked`/ManualCheck output MUST NOT leak absolute host paths (canonicalized `CONDUCTOR_*` dirs, `ANDROMEDA_PULSE_DATA_DIR`) or internal seam-crate struct/field names — per security-plan.md §Error Handling (run-report artifact sanitization) and §Security Anti-Patterns → Logging.
- `cargo audit` remains an advisory-DATABASE fault, not a tool fault: the remedy at this chunk's gates is the bounded wait alone — re-run it and VERIFY `cargo deny check advisories bans licenses sources` actually ran green as the overlapping signal. Do NOT raise the floor, do NOT add a `deny.toml` ignore, do NOT edit CI; close the deferral the moment it parses — per security-plan.md §Dependency Security (two-fault split).
- `Cargo.lock` must stay committed and un-drifted even though no dependency delta is expected — per security-plan.md §Security Anti-Patterns → Universal (lock drift makes the audit non-deterministic).
- The two `DriveObserve` scenarios routing to ManualCheck must not be silently downgraded from a genuine `blocked`/preflight failure into pass/fail/manual-check; the distinct state with its named precondition string is required — per security-plan.md §Security Anti-Patterns → Universal (readiness gate).

## Patterns to follow
- The shipped `scenarios/service-constellation-discovery.toml` `DriveObserve` pattern (no `[[expected]]` block, operator-checklist path) — reuse it rather than inventing a new config shape, keeping the garde struct surface unchanged (security-plan.md §Input Validation).
- `Scenario::check_capabilities` P-ID membership assertion against the pinned manifest — the established boundary check for exactly this class of new file (security-plan.md §Input Validation, capability-manifest row).
- `resolve_under` traversal guard for any artifact path derived from `CONDUCTOR_RUNS_DIR` / `CONDUCTOR_SCENARIOS_DIR` — the shipped hardened infrastructure; new scenario loading must consume it, not re-derive path handling (security-plan.md §Input Validation, env-var path handles row; amendment 2026-06-24).
- `thiserror` typed enums inside the seam crates collapsing to `anyhow` only at the `conductor-cli` / `#[tauri::command]` edges (security-plan.md §Error Handling).
- rusqlite bound parameters for any `runs.db` write touched by the roll-up change — never `format!`-built SQL (security-plan.md §Security Anti-Patterns → Input).

## Anti-patterns to avoid
- NEVER deserialize the new scenario TOMLs outside garde validation at load — an unvalidated `serde` path bypasses the trust boundary (security-plan.md §Security Anti-Patterns → Input).
- NEVER paper over the red `cargo audit` with a `deny.toml` ignore, a floor raise, or a CI edit — that suppresses a real signal class for a transient external fault (security-plan.md §Dependency Security; amendment 2026-08-09).
- NEVER let the shrunk-pin / roll-up rendering emit absolute host paths or internal struct names into `<run_id>.md`, `runs.db` rows, or CLI/webview output — these artifacts are agent-parseable ground truth shared across hosts (security-plan.md §Security Anti-Patterns → Logging).
