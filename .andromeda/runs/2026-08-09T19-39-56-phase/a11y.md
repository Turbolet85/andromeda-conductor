# a11y extract

## Relevance
**partial** — the chunk is mostly TOML/data authoring (out of domain), but two deliverables land on a11y-owned ground: the webview `(N unbacked)` roll-up (coverage-matrix component on the "run-report view" must-be-accessible path) and the two `DriveObserve` scenarios that route to the operator-checklist / `Manual` lamp path.

## Constraints
1. The coverage matrix sits on a must-be-accessible path with a fixed semantic contract (table/list semantics, per-row `aria-*`, roll-up announceable) — the `(N unbacked)` edit must not disturb it, and the four per-mode counts must remain a complete partition so no capability is silently uncounted (per a11y-plan.md §4 ARIA Patterns & Roles, coverage-matrix row; SC 1.3.1 / SC 4.1.3).
2. `DriveObserve` scenarios resolve to the `Manual` lamp — display label `Manual` ↔ obs `state` `ManualCheck`, and lamp choice is **verdict-first** (`verdict == CalibrationRegion` ⇒ HOLD lamp regardless of state; a `ManualCheck` state with no verdict is `Manual`) (per a11y-plan.md §6 State color tokens → State-naming crosswalk).
3. Every lamp state must carry its text label **plus** glyph supplement — `Manual` + checkbox glyph — never color alone (per a11y-plan.md §6 State color tokens (not-color-alone) + §11 Anti-Patterns §Visual; SC 1.4.1).
4. The six-label not-color-alone assertion keys on the **lamp** column only. The coverage matrix's Mode cell (where `drive+observe` / `auto` / `not-conductors` render, `--status-residual` tinting the out-of-scope value) is a coverage-mode classification, not a seventh lamp state (per a11y-plan.md §1 A11y triggers → non-lamp reuse note, and §6 same).
5. The operator-checklist path requires `checkbox` per item inside a group/region, `aria-checked` per row, each item exposing **induced-state + expected-observation text** as its accessible name, Space toggling a focused row, and a reachable unticked-count roll-up (per a11y-plan.md §1 Critical paths → Operator-checklist, and §4 pattern catalog).
6. The cli table and Markdown report roll-ups are **not** a11y-assertable — no DOM/widget tree, no ARIA verification path; their ASCII/NO_COLOR discipline is output-stream hygiene owned elsewhere (per a11y-plan.md §1 A11y scope → conductor-cli entity + §11 Anti-Patterns §Universal).
7. Zero WCAG AA violations on the must-be-accessible paths is a hard gate: no soft SLO, no retry-once, non-zero exit on `violations.length > 0` (per a11y-plan.md §10 SLO Invariants).

## Patterns to follow
1. **Single-sourced lamp truth**: `Manual`/`ManualCheck` spellings, tokens and glyphs come from `conductor-core/src/lamp.rs` mirrored in `ui/src/lamp.ts` (`Lamp` union + `LAMP_META` + `lampForRecord`), reused via `StatusLamp` — never re-spelled per surface (per a11y-plan.md §6 crosswalk; established in `D:\dev\projects\conductor\crates\conductor-tauri\ui\src\lamp.ts`).
2. **Derived qualifier, not a summand**: the existing `tally()` in `D:\dev\projects\conductor\crates\conductor-tauri\ui\src\components\CoverageMatrix.tsx` already attaches `(N unbacked)` to the `auto` term only and sources `N` live from the `unbacked_auto` command — shrinking `UNBACKED_AUTO` should need no webview markup change; keep it that way rather than hardcoding 10 in TS.
3. **Semantic HTML first**: the matrix is a real `<table>` with `scope="col"` headers inside a labelled `<section>`; any new checklist rows use native checkbox, not `role="checkbox"` on a div (per a11y-plan.md §4 Naming convention + §11 Anti-Patterns §ARIA).
4. **One webview-automation stack**: any webview assertion added for this chunk rides the existing `@crabnebula/tauri-driver` + WebdriverIO session (axe via `@axe-core/webdriverio`, colorjs.io, `browser.keys()`), display-gated to Linux+xvfb + live Pulse (per a11y-plan.md §3 Harness Contract + §9 CI Integration).

## Anti-patterns to avoid
1. NEVER treat the cli table or Markdown roll-up as an a11y-assertable surface, and never claim a11y coverage from them (a11y-plan.md §11 §Universal).
2. NEVER let the token-tinted Mode cell be read as a missing/extra lamp state, and never convey a mode or state by color alone (a11y-plan.md §11 §Visual + §6 non-lamp-reuse note).
3. NEVER stand up a second browser-automation stack (puppeteer/CDP) or substitute manual NVDA/VoiceOver/Orca review for the machine axe-core/colorjs.io output if the webview roll-up is verified here (a11y-plan.md §11 §CI).

## Contract bindings
- **a11y ↔ obs**: the `Manual` lamp joins its journal row through the display-label ↔ `verdict`/`state` enum crosswalk (a11y-plan.md §6); any a11y violation/assertion artifact folds into the obs §6 envelope via `fingerprints[]` with no new top-level fields, and must not leak absolute host paths or seam-crate struct names (a11y-plan.md §3 Structured violation JSON schema).
- **a11y ↔ tests**: webview a11y assertions ride the tests' `wdio run` tauri-driver/WebdriverIO job and surface through the 5-command contract's `logs` verb; operator/local-gated, not a CI gate (a11y-plan.md §3 CI integration + §9).
- **a11y ↔ design**: `--status-residual` on `.cov__mode--out-of-scope` and the `Manual`/`--status-manual` lamp token pair are asserted against `--color-base` at SC 1.4.11 3:1 (a11y-plan.md §6 Color contrast pairs).
