# arch extract

## Relevance
Partial — arch governs scenario-file placement/format, the P-ID membership + backing gates, and the roll-up envelope; it contributes no scenario semantics of its own.

## Constraints
- Scenario config is declarative TOML under `scenarios/`, serde-deserialized and garde bounds-checked **at load** — no scenario DSL, validation co-located in the owning seam crate (per architecture.md §Established Decisions [Scenario Config Format] · §Conventions Config conventions).
- P-ID validity is two-layered: garde `pid_format` asserts the `P-NNN` **shape** only; membership is asserted by `Scenario::check_capabilities` against `contracts/pulse-capabilities.toml` via `from_toml_str_with` at the three binary-edge load sites. A malformed/absent manifest is a **harness fault** (`CoreError`, `Result::Err`), never `Blocked`, never a silent widening (per architecture.md §Established Decisions [Accepted Capability Set]).
- `check_scenario_backing` holds `UNBACKED_AUTO` to **exact-set equality**; only `Auto`-classified capabilities participate (`DriveObserve`/`StaticOnly`/`NotConductors` are excluded by definition), and a rotted pin is `CoreError::UnbackedCoverage` — an `Err`, not a report state (per architecture.md §Established Decisions [Accepted Capability Set], second integrity gate).
- Scope law + naming: "no scenario without a P-ID"; on-disk artifacts are kebab-case; scenarios are keyed by a P-ID drawn from the manifest's accepted set (per architecture.md §Cross-cutting Patterns Scope law · §Conventions Naming patterns).
- `slo_tier` is a **closed enum** over exactly `<5s`/`<20s`/`<90s`; the seed is the sole non-determinism source and materially shapes timing, so every scenario declares one explicitly (per architecture.md §Conventions Data model conventions · §Established Decisions [Timing-Tolerance Model] / [Determinism RNG]).
- Verdict/error wall: the `DriveObserve` (no `[[expected]]`) path terminates in `ReportState::ManualCheck` as a **value**; only harness faults are `Err`. Default mapping `Pass→Pass` / `Fail→Fail` / `CalibrationRegion→ManualCheck` (per architecture.md §Cross-cutting Patterns Verdict/error wall · §Established Decisions [Probabilistic-Assertion Policy]).
- Crate-per-seam boundaries hold: the pin edit is a data change inside `conductor-core`; no new workspace member, seam or dependency edge (per architecture.md §Established Decisions [Module Boundaries] · §Inherited Defaults Module boundaries).

## Patterns to follow
- **The shipped `DriveObserve` scenario shape** — `D:\dev\projects\conductor\scenarios\service-constellation-discovery.toml` is the exact precedent the scope names: header comment stating the P-ID + Pulse's claim + coverage mode + a "declare-only" list, then `name`/`p_ids`/`seed`/`slo_tier`/`jitter_ms` and `[[phases]]` with `gap_ms`, and **no** `[[expected]]` block (arch §Infrastructure Patterns directory structure — `scenarios/`, one per P-ID).
- **Auto expectations must target the persistent-corpus read-back surface only** — verified live, only the 4 corpus MCP tools (`query_incident_list` · `retrieve_report` · `retrieve_telemetry_slice` · `mark_incident_resolved`) work cross-process from a Conductor-spawned sidecar; the live-buffer tools return empty (arch §Standard Contracts Readiness gate / corpus access · §Occupied Resources MCP tools consumed). P-079's `[[expected]]` should be expressible over that set.
- **Run-report envelope is the shared row shape** the coverage roll-up and `runs.db` both serialize (`run_id`/`seed`/`scenario`/`p_ids`/`verdict`/`state`/`slo_tier`/…) — the three roll-up surfaces render over this, not over ad-hoc shapes (arch §Standard Contracts Run report envelope).
- **The two-source integrity pattern** — accepted set is *data* (manifest), classification is *code-native* (`coverage_matrix()`); scenario backing is a third axis over the same ids. Keep them separate sources; do not collapse one into another (arch §Established Decisions [Accepted Capability Set]).
- **Terminal roll-up rendering** goes through the pinned `conductor-cli` presentation layer (comfy-table capability-coverage table, tty-gated color, never color-alone) (arch §Stack and Technologies Terminal output rendering).

## Anti-patterns to avoid
- Do **not** introduce a `CONDUCTOR_*` override handle (or any new env var / port / artifact class) for the capability manifest — its path resolves from a fixed `CapabilityManifest::default_path()` through `resolve_under` with deliberately no override, unlike `CONDUCTOR_CONTRACT_MANIFEST` (arch §Occupied Resources).
- Do **not** re-express the accepted set or the unbacked pin as a compile-time constant / range, and do not widen validation to make an id pass — the compile-time `001..=060` bound was already superseded once (arch §Established Decisions [Accepted Capability Set]).
- Do **not** route a gate failure (missing manifest, rotted pin, drift) into a report state such as `Blocked`/`Fail` — those are harness faults on the `Err` side of the verdict/error wall (arch §Cross-cutting Patterns Verdict/error wall).

## Contract bindings
- **arch ↔ obs:** the `(N unbacked)` term is a **derived qualifier, not a fifth summand** (obs-plan §4) — the four per-mode counts must still sum to the row total after the pin shrinks; arch owns the envelope the counts render into (§Standard Contracts).
- **arch ↔ tests:** the three files must load through the *validating* path (`from_toml_str_with` + `list_scenarios(dir, &manifest)`), not raw `toml::from_str`; `check_scenario_backing`'s exact-set tests in `conductor-core/src/drift.rs` are the gate fixtures (§Established Decisions [Accepted Capability Set] · §Infrastructure Patterns Build system — nextest zero-retry `ci` profile).
- **arch ↔ design/layouts/a11y:** the three coverage roll-up surfaces are Markdown report · CLI comfy-table · Tauri webview (`crates/conductor-tauri/ui/`, not a Cargo member) — the same derived count must read identically on all three (§Occupied Resources Frontend asset subtree · §Stack Terminal output rendering).
- **arch ↔ security:** `contracts/pulse-capabilities.toml` is a local read-only file resolved under a fixed root; no new input boundary, spawn, or network surface is introduced by this chunk (§Cross-cutting Patterns Trust boundary · Config management).

## Acceptance criteria contributions
- (arch) Three new kebab-case TOMLs live in `scenarios/`, each naming exactly its P-ID, and all three load cleanly through the manifest-validating path with membership accepted — no new crate, seam, or dependency delta (arch §Infrastructure Patterns directory structure · §Established Decisions [Scenario Config Format] / [Accepted Capability Set] · §Inherited Defaults Module boundaries).
- (arch) Each scenario declares an explicit `seed` and an `slo_tier` from the closed set `<5s`/`<20s`/`<90s`; garde bounds hold (non-negative durations, sane ordering) (arch §Conventions Data model + Config conventions · §Established Decisions [Timing-Tolerance Model]).
- (arch) `UNBACKED_AUTO` reads 10 entries with `check_scenario_backing` green at exact-set equality, and `check_sut_drift` stays green — a rotted or newly-unbacked pin surfaces as `CoreError` (`Err`), never as a report state (arch §Established Decisions [Accepted Capability Set] · §Cross-cutting Patterns Verdict/error wall).
- (arch) No new `CONDUCTOR_*` env var, port, MCP tool name, or on-disk artifact class is introduced; the two `DriveObserve` scenarios carry no `[[expected]]` block and terminate as `ManualCheck` values (arch §Occupied Resources · §Established Decisions [Probabilistic-Assertion Policy]).
