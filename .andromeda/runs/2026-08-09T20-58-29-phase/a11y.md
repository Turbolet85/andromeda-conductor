# a11y extract

## Relevance
Partial — the chunk is mostly Rust/CLI/data-model work (out of domain), but its central design fork (`environment-suspect` against the closed `ReportState` set, mirrored into the webview `LAMP_META` at `crates/conductor-tauri/ui/src/lamp.ts`) lands squarely on the assertable desktop-webview lamp/run-report surface.

## Constraints
- The run-report view is one of the four must-be-accessible critical paths, so any classification it renders inherits the zero-WCAG-AA-violations invariant and the SC 1.4.1 / 1.4.11 / 4.1.3 set — per a11y-plan §1 Critical paths (View run report) + §10 SLO Invariants.
- If `environment-suspect` renders as a lamp/state treatment in the webview, it MUST carry a DOM text label + glyph supplement (never color alone) and MUST be added to the display-label ↔ obs-enum crosswalk so a failing lamp joins back to its journal row — per a11y-plan §6 State color tokens (not-color-alone) incl. the State-naming crosswalk.
- Lamp identity is verdict-first (`verdict == CalibrationRegion` ⇒ HOLD lamp regardless of `state`); a run-level qualifier must not break that precedence or make lamp selection ambiguous — per a11y-plan §6 State-naming crosswalk.
- Any color token used to distinguish the classification must be an existing verbatim design token and must be asserted at 3:1 non-text (or 4.5:1 if it is text) against `--color-base` by the colorjs.io token-name checker; no invented tokens, no raw values in a11y — per a11y-plan §6 Color contrast pairs + §3 Contrast verification harness.
- a11y's structured-violation envelope is a verbatim reproduction of the obs §6 run-report envelope (violations fold into `fingerprints[]`); if this chunk mutates that envelope (new field, new `state` value, or a new run-level qualifier), a11y's reproduction must be amended in lockstep — per a11y-plan §3 Structured violation JSON schema.
- The cli surface is not-assertable: ASCII status prefixes / NO_COLOR text pairing for the new classification are output-stream discipline, not an a11y verification path, and yield no a11y coverage claim — per a11y-plan §1 (conductor-cli entity) + §11 Universal.
- Report/artifact text naming the envelope breach must not leak absolute host paths or internal seam-crate struct names into the obs envelope — per a11y-plan §3 Structured violation JSON schema + §11 SLO.

## Patterns to follow
- **Non-lamp classification precedent:** `--status-residual` tinting the coverage-matrix out-of-scope Mode cell is a coverage-mode classification, not a seventh lamp state; its not-color-alone signal is its own always-rendered `not-conductors` text, and the six-label assertion keys on LAMP display labels only. This is the direct template if `environment-suspect` lands as a qualifier rather than a sixth `ReportState` — per a11y-plan §1 A11y triggers (Non-lamp reuse of a state token).
- **Lamp component contract:** `status` role / `aria-live` on state change, always-present paired text label, six visual+text treatments, `Fail` held motionless — per a11y-plan §4 Per-component pattern catalog (Verdict / report-state lamp).
- **Coverage-matrix row semantics:** `list`/`listitem` with `aria-selected`/`aria-current` + `--border-emphasis`, keyboard-first row nav, virtual-scrolled off-screen rows still reachable/announceable — applies if the breach surfaces as a per-row annotation — per a11y-plan §4 catalog (Coverage matrix) + §5 run-report-terminal focus order.
- **Machine-verifiable emission shape:** contrast/not-color-alone/keyboard results emit `{ token_fg, token_bg, ratio, required, pass }`-style PASS/FAIL JSON folded into the obs §6 envelope, run from the tests' `wdio run` webview job — per a11y-plan §3 Contrast verification harness + §9 CI Integration.
- **Real-prose status rule:** in-progress / empty run-report states are real prose announced as status, never downgraded to Fail — the same rule governs how an environment-suspect run is announced — per a11y-plan §3 Screen reader test pattern + §11 Visual.

## Anti-patterns to avoid
- NEVER convey the environment-suspect classification by color alone (token tint without an always-rendered text label / glyph) — per a11y-plan §11 Visual.
- NEVER announce or render environment-suspect as `Fail`, and NEVER `aria-hidden` the lamp / status node that carries it — per a11y-plan §11 Screen Reader + §11 Visual.
- NEVER treat the cli ASCII-prefix / NO_COLOR pairing (or a Markdown lamp glyph) as the a11y verification path for the new classification — per a11y-plan §11 Universal.

## Contract bindings
- **a11y ↔ obs:** a11y §3 reproduces the obs §6 run-report envelope verbatim; a chunk-level change to that envelope (extra field, extra `state` variant, run-level qualifier) requires a matching a11y amendment (precedent: 2026-06-16 amendment).
- **a11y ↔ design:** the state/classification color token and its glyph supplement are design-owned; a11y §6 asserts the pair's ratio (3:1 non-text / 4.5:1 text vs `--color-base`) by token NAME only (`[NO_RAW_DESIGN_VALUES]`).
- **a11y ↔ tests:** the axe-core + colorjs.io + WebdriverIO-keyboard step rides tests' `wdio run` webview-E2E job on Linux+xvfb and emits through the `logs` command of the 5-command harness contract, operator/local-gated (a11y-plan §3 CI integration + §9).
- **a11y ↔ frontend/webview:** `LAMP_META` (`crates/conductor-tauri/ui/src/lamp.ts`) is the DOM-text source the not-color-alone assertion reads; a new entry there is an a11y-asserted surface change.
