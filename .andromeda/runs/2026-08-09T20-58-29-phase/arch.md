## Relevance
Relevant — the chunk lands in locked workspace crates, extends the load-time validation seam, and its central fork touches a pinned §Standard Contracts shape (`state ∈ {…}`).

## Constraints
1. **Crate placement is compiler-enforced.** The load-time envelope assertion belongs in `conductor-core` beside the existing garde bounds / `check_capabilities`; envelope round-trip through the report + `runs.db` belongs in `conductor-report`; any realized-run classification belongs in `conductor-run` (the composition root above the seams, below both bins). A forbidden cross-seam edge must not compile — per architecture.md §Established Decisions [Module Boundaries], §Occupied Resources (Crate names), §Infrastructure Patterns (directory structure).
2. **An envelope breach is a VALUE, not an error.** `Result::Err` is reserved for Conductor's own faults; verification outcomes are typed values matched on — per §Design Philosophy ("Outcomes are values, errors are harness faults"), §Established Decisions [Error Handling], §Cross-cutting Patterns (Verdict/error wall). Corollary from the manifest precedent: a *malformed or absent* committed envelope artifact IS a harness fault (`CoreError`, named reason, never a report state) — per §Established Decisions [Accepted Capability Set].
3. **`state` is a closed, pinned set with a four-surface fan-out.** `state ∈ {Pass, Fail, ManualCheck, KnownResidual, Blocked}` is pinned in §Standard Contracts (run report envelope) and mirrored in §Conventions (Error handling). Widening it is an architecture amendment, not a local change. `verdict` and `state` stay independent and the run-report lamp is chosen verdict-first — per §Established Decisions [Probabilistic-Assertion Policy].
4. **Any new committed constraint artifact lives under `contracts/`** and is read at load via `toml` + serde (no new dependency), resolved through the `default_path()` → `resolve_under` pattern; the capability-manifest precedent deliberately carries **no** `CONDUCTOR_*` override handle. No new env var may be introduced without registering it in §Occupied Resources (Environment variables / On-disk artifacts), §Stack and Technologies.
5. **`runs.db` column types are fixed on first write** — raw SQL, no migration framework to coerce later; a closed enumeration is a closed TEXT enum (the `slo_tier` precedent); blocked rows emit JSON `null` / store NULL and cross-run queries MUST exclude NULL-measurement rows — per §Conventions (Data model conventions), §Standard Contracts (blocked-row rule).
6. **Dynamic (v2-07) detection is journal-relative.** Realized-profile measurement reads the on-disk JSONL journal with `std::time::SystemTime`/`Instant` stamps — never wall-clock-from-test-start, never tokio's virtual clock — per §Design Philosophy (journal-relative ground truth), §Established Decisions [Timing-Tolerance Model], §Cross-cutting Patterns (Determinism discipline).
7. **CI is build + test only.** The `v2-07` integration check must pass with no live Pulse; anything requiring a live SUT is an operator/local gate — per §Established Decisions [CI/CD], §Infrastructure Patterns (CI/CD approach).

## Patterns to follow
1. **Two-layer validation, membership applied at binary edges** — garde asserts *shape*, an explicit `Scenario::check_*` asserts *membership/bounds* against the committed artifact, threaded through a `from_toml_str_with(&str, &Manifest)` at the load sites rather than forced into garde's `Context` (which would change `PId`/`PhaseSpec`/`EmissionSpec` public APIs). Per §Established Decisions [Accepted Capability Set]. This is the direct template for the `v2-06` catalog assertion.
2. **Integrity gate as exact-set equality with a named `CoreError` variant**, never a silent widening (`check_sut_drift`, `check_scenario_backing` / `CoreError::SutDrift`, `CoreError::UnbackedCoverage`); a ledger may only shrink under compulsion. Per §Established Decisions [Accepted Capability Set].
3. **garde bounds co-located with the serde structs in the owning seam crate**; `custom` is field-level only in 0.22.1, so cross-field invariants use garde's `Context` pattern. Per §Conventions (Config conventions), §Established Decisions [Validation Library].
4. **One canonical envelope shape shared by the Markdown report and the `runs.db` row** — the report and index never diverge in field set. Per §Standard Contracts (Run report envelope, Timestamp formats).
5. **Distinct-state-over-downgrade**, the `Blocked` precedent: a state that means "not evidence about the SUT" carries a named precondition string and is never silently mapped to pass/fail/manual-check. Per §Established Decisions [Read-Back Dependency Posture].

## Anti-patterns to avoid
1. **Do not generate or measure throughput as a product feature, and do not manage the Pulse process** — the standing non-goals in §Cross-cutting Patterns (Scope law); this chunk bounds load, it does not become a load-tester.
2. **Do not surface an envelope breach as `Result::Err`, and do not collapse it into `Fail`** — both violate the verdict/error wall (§Cross-cutting Patterns) and the distinct-state discipline (§Established Decisions [Read-Back Dependency Posture]).
3. **Do not reach for a migration framework, an ORM, or any new network/HTTP surface** to carry the new field — §Established Decisions [ORM], [Backend Framework], §Conventions (Data model conventions).

## Contract bindings
- **Run-report envelope ↔ tests / obs / design+layouts / a11y** — a `state` change cascades to golden fixtures, report logging, the CLI ASCII prefixes + Markdown lamp, and the webview `LAMP_META` lamp set (a11y's lamp count); lamp precedence is verdict-first (§Standard Contracts, §Probabilistic-Assertion Policy).
- **`runs.db` schema ↔ report seam + tests** — column types fixed on first write, blocked-row NULL rule, NULL-exclusion in cross-run queries (§Conventions Data model conventions).
- **`contracts/` artifact path resolution ↔ security** — fixed `default_path()` through `resolve_under`, no override handle, no traversal (§Occupied Resources).
- **Envelope's deterministic-L4 conjunct ↔ [Read-Back Dependency Posture]** — if the SUT's record makes `ANDROMEDA_PULSE_L4_DETERMINISTIC` a required term of the proven-good envelope, it binds to the recorded interpretation-correctness deferral pinned in `.andromeda/residuals.md` (conductor-0.3.0), not to new work here.
- **Zero-row read-back signature ↔ `ANDROMEDA_PULSE_DATA_DIR` wiring** — §Occupied Resources already names a data-dir mismatch as a producer of "false pass-as-empty / perpetual blocked"; attribution logic must distinguish that pre-existing cause from an envelope breach.

## Acceptance criteria contributions
1. **(arch)** Load-time envelope assertion lives in `conductor-core` (beside the existing garde/`check_capabilities` gates), report/index round-trip in `conductor-report`, realized-run classification in `conductor-run`; no new cross-seam dependency edge appears in any `Cargo.toml` (§Module Boundaries, §Occupied Resources Crate names).
2. **(arch)** An envelope breach is returned as a typed value on the `Ok` path; only a malformed/absent/unparseable envelope artifact produces `Result::Err` (a named `CoreError`) — no breach path returns `Err`, no artifact fault returns a report state (§Error Handling, §[Accepted Capability Set]).
3. **(arch)** Whichever fork is chosen: if `environment-suspect` becomes a sixth `ReportState`, §Standard Contracts' `state ∈ {…}` is amended and the envelope JSON, `runs.db` column, CLI prefixes, Markdown lamp, and webview `LAMP_META` are updated in lockstep; if it is a run-level qualifier, `state ∈ {…}` is provably unchanged and the qualifier round-trips through the canonical envelope without violating the blocked-row NULL rule (§Standard Contracts).
4. **(arch)** The envelope artifact is a committed `contracts/*.toml` read via the existing `toml` + serde stack — zero new workspace dependencies, zero new `CONDUCTOR_*` env handles, and any resource that does land is registered in §Occupied Resources at wrap (§Occupied Resources, §Stack and Technologies).
