# design extract

## Relevance
**Partial** — half A (envelope artifact + load-time assertion, `v2-06`) is outside design's domain; half B (`v2-07`, rendering an "environment-suspect" classification across the CLI status prefixes, the Markdown lamp, and the webview `LAMP_META`) sits squarely in the status-tier/token/lamp domain.

## Constraints
1. **Distinct-from-Fail is a design invariant, not just an acceptance line.** Per design-system §Color Palette (Verdict-3-vs-ReportState-5 note) and §Anti-Patterns → Rejected Defaults ("conflating no-result-yet with failed"), `ManualCheck` / `KnownResidual` / `Blocked` were each given a *separate visual treatment* precisely so none silently reads as `Fail`. Whatever shape environment-suspect takes (sixth variant vs run-level qualifier), it inherits that rule: never red, never a gray "no result" placeholder.
2. **Zero new colors — reuse an existing tier by name.** Per §Surface: cli Tokens (ANSI map) + §Surface: desktop-webview Tokens (the 34-token `:root` contract) and §Self-Validation → Token Test: no new hex, no new ANSI code, no raw ms. A new palette row requires a design-system amendment; the standing precedent is that an existing tier is reused instead (see amendment history).
3. **Never color alone, on every surface.** Per §Iconography (Rule) + §Surface: cli Tokens (status prefixes `[PASS]`/`[FAIL]`/`[MANUAL]`/`[RESIDUAL]`/`[BLOCKED]` + `✓ ✗ ? ~ •`) + §Component Patterns 4: color is always paired with a persistent ASCII/text label and, in the webview, an `aria-live` announcement. Markdown has no color channel — it carries the signal in text/emphasis.
4. **Motionless resolution.** Per §Motion → Hard limits: no pulse/blink/glow on any status, no flashing red on a fail-adjacent edge; state changes are a single in-place 150ms color transition bound to `--motion-micro` + `--ease-quiet`, dropped under `@media (prefers-reduced-motion: reduce)`.
5. **Reserved mono status tier for the envelope's numbers.** Per §Typography (Data row) + §Color Palette (Primary): realized rate, duration, P-IDs, `run_id`, `latency_ms`, and any envelope term render JetBrains Mono 500/13px tabular-nums in `--color-id-cyan` (CLI: ANSI 117); explanatory prose is IBM Plex Sans in `--text-secondary`. Mono-everywhere is a Rejected Default (§Anti-Patterns).
6. **A breach cause is carried as recessive text, not as an alarm.** Per §Component Patterns 6 (run-report) and §cli Component Patterns 3: `Blocked` rows carry a named-precondition string with measurement columns as `—`/null and never a red error; `KnownResidual` carries an "expected until {fix}" note in the muted tier. The envelope-breach cause string follows that same shape.
7. **CLI colorization is gated, always.** Per §Surface: cli Platform-Specific Notes + §Per-Surface Bans (cli): `owo-colors` through `anstream`, honoring `NO_COLOR` / `TERM=dumb` / pipe status; no emoji in machine-parseable output; the ASCII label stands with color stripped.

## Patterns to follow
- **The 6-treatment verdict/report-state lamp** (§Component Patterns 4 webview + §cli Component Patterns 4): filled dot (verdict triad) · hollow ring (`Blocked`) · checkbox glyph (`ManualCheck`) · dashed-ring dot (`KnownResidual`). Shipped at `crates/conductor-core/src/lamp.rs`, `crates/conductor-core/src/report_state.rs`, `crates/conductor-cli/src/render.rs`, `crates/conductor-tauri/ui/src/lamp.ts`, `crates/conductor-tauri/ui/src/components/CoverageMatrix.css`.
- **`KnownResidual` is the closest existing vocabulary** for "measured, but not evidence of SUT failure" (§Color Palette Residual row + §Iconography): muted `--status-residual` / ANSI 246, dashed treatment, an attached explanatory note, explicitly *not* red. If environment-suspect resolves to a qualifier rather than a sixth variant, this is the visual register it should borrow.
- **Non-verdict states render as prose, not skeletons** (§Component Patterns 6): "Run in progress" / "No run yet" in `--text-secondary` / `--text-tertiary`, never downgraded to a red `Fail`.
- **Token-by-name on plain `:root`** with the `@media (prefers-color-scheme: light)` twin (§Surface: desktop-webview → Tokens, incl. the Tailwind-v4 NOTE): any value added or reused must exist in both blocks.
- **Results/SLO table vs coverage table are separate** (§cli Component Patterns 3): the 6-column results table carries the state column and bracket prefix; `conductor coverage` renders 4 columns with no verdict column. A per-run flag has no home in the coverage table.

## Anti-patterns to avoid
- **No flashing/pulsing/animated alert** on the suspect edge, and **no native OS toast** — those are Pulse behaviors Conductor observes, never performs (§Anti-Patterns → Rejected Defaults; §desktop-webview Platform-Specific Notes).
- **Do not add a palette row / ANSI entry / hex when an existing tier fits**, and do not introduce a raw ms or literal color at the use site (§Self-Validation Token Test; the `hint:` correction precedent).
- **Do not collapse environment-suspect into `Fail`**, nor gray it identically to the empty/"no result yet" state (§Anti-Patterns → Rejected Defaults, conflation entry).

## Contract bindings
- **a11y** — not-color-alone (SC 1.4.1) via the paired text label; status-change announcement via `aria-live` on the lamp (§Component Patterns 4); reduce-motion (SC 2.3.3) on the color transition (§Motion hard limits); **contrast (SC 1.4.3 4.5:1) must be checked for whichever token pair is chosen, in BOTH dark and light blocks** — a11y owns the threshold, design owns the pair.
- **architecture** — `ReportState` is a pinned closed five-variant set (architecture.md §Standard Contracts). A sixth *lamp state* is not a code-only change: it would require a coordinated amendment to design-system §Color Palette (Semantic table), §Iconography (glyph inventory), §Surface: cli Tokens (ANSI map), and §Component Patterns 3/4/6, plus `LAMP_META`. A run-level qualifier orthogonal to the per-check state avoids all of that — design has no preference beyond "distinct, token-bound, label-paired".
- **layouts** — per-row/per-report *placement* of the flag (matrix row vs report header vs footer roll-up) is the layouts distiller's call; this extract supplies token + glyph + label rules only.
- **test-plan** — lamp/prefix assertions live at `crates/conductor-tauri/ui/test/a11y/accessibility.e2e.ts` and the CLI render/snapshot tests (`crates/conductor-cli/tests/cli_smoke.rs`); any new classification string must be added there, not left untested.

## Acceptance criteria contributions
1. **(design)** The environment-suspect treatment binds existing tokens **by name** on every surface (webview `var(--…)`, CLI a mapped ANSI code, Markdown text/emphasis) — zero new hex, zero new ANSI entries, zero raw ms/px; if a new token proves unavoidable, a design-system amendment is filed in the same chunk.
2. **(design)** Color is never the only channel: the classification carries a persistent ASCII/text label on the CLI (bracket prefix + glyph), text or emphasis in Markdown, and lamp + text label + `aria-live` in the webview — verified with `NO_COLOR=1` / piped stdout.
3. **(design)** The rendered classification is visually distinct from `Fail` red **and** from the empty/"no result yet" state on every surface, and the report names the envelope breach as a text cause string (the `Blocked` named-precondition / `KnownResidual` "expected until {fix}" note pattern).
4. **(design)** Any state transition introduced uses `--motion-micro` + `--ease-quiet`, resolves in place with no flash/pulse/blink, and is fully suppressed under `prefers-reduced-motion: reduce`.
