# layouts extract

## Relevance
**Partial** — the chunk is engine/classification work, but if `environment-suspect` surfaces as a report state it lands in three documented layout slots (lamp column, verdict/report lines, footer roll-up) across both surfaces; the authoring-constraint doc surface also inherits the derived-count rule.

## Constraints
1. **The lamp/state tier is a closed, enumerated set on both surfaces** — desktop lists exactly six states (three verdicts + `Blocked`/`ManualCheck`/`KnownResidual`) per layout-templates §Component — Primary content block 1 (coverage matrix) and §Component — Primary content block 2 (run-report view + verdict lamp); cli mirrors the same set as bracket prefixes per §Surface: cli — Primary content block 2. Any new run/check state must either take a slot in that enumeration on **all** render surfaces or deliberately live outside the lamp column — it cannot be added to one surface only.
2. **No state may silently collapse into `Fail`** — the plan's standing rule that `Blocked`, `ManualCheck` and `KnownResidual` are "never red / never silently a Fail" (per layout-templates §Component — Primary content block 2 and §Decisions Log → Cross-surface IA decisions). An environment-suspect result is exactly this class: distinct from `Fail`, never rendered in `status-fail`.
3. **State is never color-only** — every lamp is paired with its status text on desktop (§Component — Primary content block 1) and every cli state cell pairs its color with an ASCII bracket prefix (`[PASS]`/`[HOLD]`/`[FAIL]`/`[BLOCKED]`/`[MANUAL]`/`[RESIDUAL]`) so it survives `NO_COLOR`/piping (§Surface: cli signature-placement preamble, §cli IA notes → Pipe discipline). A new state needs a text label **and** an ASCII prefix, not just a tint.
4. **Tokens are adapted across surfaces, never forked** — desktop CSS var ↔ cli ANSI mappings are 1:1 by name (§desktop IA notes → Multi-surface coordination; §cli IA notes → Multi-surface coordination). If environment-suspect gets a treatment, it reuses an existing named token pair rather than inventing a surface-local color.
5. **A non-outcome classification takes a recessive treatment, not a lamp state** — the precedent the plan already sets for the out-of-scope Mode value: `--status-residual` ↔ ANSI 246 ↔ Markdown emphasis, explicitly *not* `--status-fail`/`--count-blocked`, label always rendered, and "the tint never becomes a seventh lamp state (the lamp column is untouched)" (§Component — Primary content block 1, Mode bullet). This is the plan's authored answer for "a classification that is about REMIT/attribution, not an outcome."
6. **Blocked-row rendering rule for unmeasured values** — measurement columns render `—`/null, never a red error (§Component — Primary content block 2; §cli Primary content block 1). An over-envelope run whose read-backs returned 0 rows must not render zeros as measured values.
7. **Footer/caption roll-ups are derived, never literal** — the roll-up tally counts every state, each token in its own status color and paired with its label, and per-state counts must sum to the denominator (§Component — Footer (status strip); §cli Primary screens → `conductor coverage` roll-up caption). A new state that appears in a run must appear as a roll-up term or the tally stops summing.
8. **cli output shape is a parsed contract** — "adding a `comfy-table` column without a `--format` flag would be a breaking change" (§cli IA notes → Command model). The results/SLO table is **6 columns**; the coverage matrix is **4 columns** — they must not be conflated (§cli Primary content block 1).

## Patterns to follow
1. **`KnownResidual` is the closest existing precedent** — a *measured, pre-accepted, non-Fail* state with a muted dashed lamp plus a note line ("residual: … until {named fix}") carrying the reason inline beneath the row (§Component — Primary content block 2; cli `~ P-032 … [RESIDUAL]` + indented `residual:` detail in §cli Output structure). "Report names the envelope breach as the cause" maps directly onto this note-line shape.
2. **`Blocked`'s named-precondition line** — the row carries a named precondition string below it in `text-tertiary` while measurement columns stay null (§Component — Primary content block 2; §cli Primary content block 1). This is the plan's existing shape for "here is the attribution string for why this wasn't real evidence."
3. **The Mode cell as a non-lamp classification column** — a text-only classification rendered per-row, tallied by the header strip, mirrored as text in the cli 4-column table, with a recessive tint that never becomes a lamp state (§Component — Primary content block 1). This is the template if environment-suspect is decided as a run-level qualifier rather than a sixth `ReportState`.
4. **Run-level context rides the header/footer, per-check state rides the row** — the frozen-count/step-index pattern shows run-scoped facts echoing in the titlebar, the matrix header strip and the footer while rows keep per-P-ID state (§Signature placement, both surfaces). A run-level "environment-suspect" qualifier has an authored home: matrix header strip + footer status strip + cli summary caption.
5. **Empty/non-result states are prose, never a gray skeleton** — "No run yet…", "Run in progress", "No scenarios loaded" in `text-tertiary`/`text-secondary` (§Component — Primary content block 1 States; §Component — Primary content block 2). A zero-row read-back under a breached envelope is a prose state, not an error render.

## Anti-patterns to avoid
1. **Do not render environment-suspect in `status-fail` / red, and do not blink or flash it** — verdict lamps resolve motionless over `motion-micro`; flashing is an explicit Rejected Default (§Component — Primary content block 2; §Decisions Log → Motion trigger placement).
2. **Do not add the state to one surface only, and do not fork a new color** — desktop CSS var, cli ANSI, and the Markdown artifact must carry the same state by the same token name (§desktop IA notes / §cli IA notes → Multi-surface coordination). Likewise do not reuse `--count-blocked` as a "just dim it" treatment: it shares its hex with `--text-muted` and would read as `Blocked` (§Component — Primary content block 1, Mode bullet).
3. **Do not bake literal counts into any layout caption, wireframe sample, or header-strip label** — name the SET (§cli Primary screens → `conductor coverage` roll-up: "every number manifest-derived (never a literal)"; reinforced by four separate amendments below). This applies to the scenario-catalog count if the authoring surface renders one.
4. **Do not widen the results/SLO table to a 7th column, or add a state column to the 4-column coverage table**, without the `--format` breaking-change consideration (§cli Primary content block 1; §cli IA notes → Command model).

## Contract bindings
- **layouts ↔ arch** — §architecture Standard Contracts pins `state ∈ {Pass, Fail, ManualCheck, KnownResidual, Blocked}` as a closed set; the layout enumeration in §Component — Primary content block 1/2 and §cli Primary content block 2 is the render half of that same contract. The P4 fork (sixth variant vs. run-level qualifier) changes layouts iff it changes that set. Concrete render surfaces: `crates/conductor-cli/src/render.rs`, `crates/conductor-report/src/coverage.rs`, `crates/conductor-tauri/ui/src/lamp.ts`, `crates/conductor-tauri/ui/src/components/StatusLamp.tsx`.
- **layouts ↔ design** — the treatment token for a new state is design's to name; layouts only fixes *where* it renders and that it is not `status-fail`/`count-blocked` (§Component — Primary content block 1, Mode bullet, which already carries the design-side rationale).
- **layouts ↔ a11y** — a state/verdict change is announced via a live region and status is never color-alone; layouts states the requirement, a11y derives the attribute (§Component — Primary content block 2; §Notes). Binds to a11y §status-not-color-only and live-region rules.
- **layouts ↔ tests/obs** — the cli output shape (bracket prefixes, 6-vs-4 column tables, roll-up caption summing to the denominator) is the parsed contract downstream agents assert against (§cli IA notes → Command model, Pipe discipline).
- **layouts ↔ the scenario-authoring surface** — the chunk requires the envelope constraint be surfaced "where someone writing a new `scenarios/*.toml` will meet it" (scope §What this chunk builds A). layout-templates authors **no** such surface today: neither §Surface: desktop-webview nor §Surface: cli has a scenario-authoring screen. If the constraint lands as a cli verb or webview panel, that is a genuinely-new surface requiring a layout-templates amendment (the `conductor preflight` / `conductor coverage` verb-registration precedent below). If it lands as a doc/comment/schema, no layout surface is created.

## Acceptance criteria contributions
1. **(layouts) No new `ReportState` renders red or as a `Fail`** — if environment-suspect reaches a render surface, its lamp/prefix is not `status-fail` / ANSI 203, and it resolves motionless (layout-templates §Component — Primary content block 2; §Decisions Log → Motion trigger placement).
2. **(layouts) The state is color-independent on every surface** — desktop lamp paired with status text, cli cell paired with an ASCII bracket prefix that survives `NO_COLOR` and piping, Markdown artifact carries it as text (layout-templates §Component — Primary content block 1; §cli signature-placement preamble; §cli IA notes → Pipe discipline).
3. **(layouts) The attribution string renders with the row/run** — the envelope breach names its cause in a detail line in the `text-tertiary` / ANSI-146 dimmed treatment, following the `Blocked` precondition / `KnownResidual` residual-note shape, with measurement columns rendering `—`/null rather than a measured zero (layout-templates §Component — Primary content block 2; §cli Primary content block 1).
4. **(layouts) Roll-ups still sum** — if the state appears in a run, the footer roll-up (desktop) and the summary caption (cli) include it as a labelled, own-color term and the per-state counts still sum to the denominator; no caption or wireframe label gains a hardcoded literal count (layout-templates §Component — Footer (status strip); §cli Primary screens roll-up caption).
5. **(layouts) Table shapes unchanged** — the results/SLO table stays 6 columns and the coverage matrix stays 4 columns unless a `--format`/breaking-change decision is taken explicitly (layout-templates §cli Primary content block 1; §cli IA notes → Command model).
