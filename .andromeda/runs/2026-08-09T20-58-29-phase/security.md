## Relevance
Partial — no auth/network/secret surface is touched, but three security-plan sections bind directly: §Input Validation (a new committed envelope artifact + the scenario-config load boundary), §Error Handling (the environment-suspect report/`runs.db` sanitization), and §Dependency Security (the folded `cargo audit` PREREQ, which is this domain's gate).

## Constraints
1. **The envelope artifact is a new external-input boundary and must be registered.** If the proven-good bounds land as a runtime-parsed committed file (the `contracts/`-class artifact this chunk describes), it must be validated at load (shape + non-empty + numeric bounds), reached via a fixed path through the shipped `resolve_under` traversal guard with **no `CONDUCTOR_*` override**, and its read faults must carry `e.kind()` only — never the path (security-plan §Input Validation, contract-manifest row + the 2026-08-08 capability-manifest precedent below).
2. **Envelope bounds asserted on `Scenario` stay inside the garde trust boundary.** Any new load-time bound on the scenario model belongs beside the existing garde 0.22.1 `range` / `#[garde(custom)]` cross-field rules in the owning seam crate, with the failed `Report` collapsing to `ConfigError` via `#[from]` as a **harness fault, not a verdict** (§Input Validation, scenario-config row; §Error Handling, verdict/error wall).
3. **`environment-suspect` must never be a silent downgrade.** Whichever way the `ReportState` fork resolves, the classification has to be a distinct, named outcome carrying its precondition string — the plan's standing ban is on collapsing a failed precondition into pass / fail / manual-check (§Security Anti-Patterns § Universal, preflight-downgrade ban; §Error Handling, `blocked`-row rule as the shape precedent for identity-only rows with `null` measurements).
4. **Dynamic (`v2-07`) envelope math must read `std::time::SystemTime`/`Instant`, never tokio's virtual clock.** Sustained-duration ceilings are journal-relative wall-clock comparisons; a virtual clock source corrupts the ground-truth artifact (§Security Anti-Patterns § Logging, wall-clock-stamp ban).
5. **Any new `runs.db` column or write for the classification uses rusqlite bound parameters** — never `format!`/concatenated SQL, even though the content is self-generated synthetic data (§Input Validation, `runs.db` row; §Security Anti-Patterns § Input).
6. **The report and `runs.db` row for an over-envelope run carry verdict/state/identity fields only** — no absolute host paths (canonicalized `CONDUCTOR_*` dirs, `ANDROMEDA_PULSE_DATA_DIR`), no internal seam-crate struct/field names, no stack traces at the `anyhow` / `#[tauri::command]` edge (§Error Handling, run-report artifact sanitization; §Anti-Patterns § Logging).
7. **The folded PREREQ is a bounded wait, nothing else.** Re-run `cargo audit` at this chunk's gates and **observe** `cargo deny check advisories bans licenses sources` green as the overlapping signal; no floor raise, no `deny.toml` ignore, no CI edit; close the deferral the moment the DB parses (§Dependency Security, two-fault split; §Anti-Patterns § Universal, never-merge-without-audit-green + `Cargo.lock`-drift ban).

## Patterns to follow
- **`resolve_under` + fixed-path artifact read** — the shipped traversal guard already used for the agent-mode log path and the capability manifest; reuse rather than adding a new path-handling surface (§Input Validation, env-path-handle row).
- **garde-at-load as the trust boundary** — `#[derive(Validate)]` co-located with the serde structs in their owning seam crate, `range` for scalars and `#[garde(custom)]` for cross-field relations (the p50≤p95≤p99 pattern is the direct analogue for rate/duration ceiling conjuncts) (§Input Validation).
- **Typed-enum-inward, `anyhow`-only-at-the-edge** — `thiserror` 2.0.18 enums (`ConfigError` for the load-time assertion path) collapsing to `anyhow` only at `conductor-cli` / `#[tauri::command]` (§Error Handling, Error format).
- **`blocked` row shape as the template for a non-Fail state** — identity fields populated with a named precondition string, measurement fields JSON `null` (§Error Handling, run-report artifact sanitization).
- **Justified-exception discipline is documentary, not suppressive** — the `deny.toml` accepted-exceptions mechanism exists for non-actionable advisories, which is precisely why it must NOT be reached for this advisory-DATABASE fault (§Dependency Security, Accepted exceptions vs. two-fault split).

## Anti-patterns to avoid
- **NEVER treat the RustSec parse failure as a tool fault** — no floor raise, no `deny.toml` ignore, no CI edit; a floor raise here is unexecutable and would look like compliance while changing nothing (§Dependency Security; §Anti-Patterns § Universal).
- **NEVER source the envelope by having Conductor's production code open, copy, or read Pulse's `corpus.db`** (plaintext SQLite, SUT-owned, out of scope) — the SUT's record is consulted as a document/MCP read-back, and its content is never persisted into Conductor artifacts (§Anti-Patterns § Data Protection; §Data Protection).
- **NEVER add a scenario without a Pulse P-ID while touching the 34-file catalog** — the scope law holds even for a bounds-only pass; the chunk's own "no new capability claims" boundary and this ban agree (§Anti-Patterns § Universal, scope law).

## Contract bindings
- **Report-artifact sanitization ↔ obs** — the environment-suspect fields emitted into the journal/self-obs logs inherit the same no-absolute-path / no-internal-struct-name rule as the Markdown report and `runs.db` row (§Error Handling ↔ obs-plan log-field schema); the scrubbing rule cross-cuts, PII itself is N/A (data classification: PII "none").
- **Audit/deny gate ↔ tests §CI Integration** — the dependency gate is security's, but it runs as a job in the single existing workflow; this chunk explicitly **must not edit CI**, so the fifth re-check is a local gate observation only, recorded verbatim.
- **Catalog assertion ↔ tests** — the "every scenario in-envelope" check is a security-derived invariant executed as a tests-owned unit (`v2-06`); fixtures stay synthetic (no real data — trivially satisfied at this tier).
- **Docs surfaces ↔ design/tests roll-ups** — the derived-count discipline ("name the SET, never a literal") applies to any security-facing count the authoring-surface docs mirror.
