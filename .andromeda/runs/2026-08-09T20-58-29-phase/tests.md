## Relevance
Relevant — `v2-06` is an explicit unit-tier capability and `v2-07` an integration-tier capability, and both land on surfaces this plan owns (catalog static gates, Run-report envelope, exit-code semantics).

## Constraints
1. **Tier discipline: Minimal (0), unit-heavy.** Per test-plan §1 (Test tier) + §2 pyramid — `v2-06` belongs in the per-seam `cargo nextest run -p conductor-core` unit bulk; `v2-07` in the §5 integration tier. No Comprehensive escalation, no new E2E scenario (the §6 set is capped at 7 critical paths).
2. **Bounding load is not testing load.** Per §10 Performance budgets (N/A, no perf-budget trigger) + §2 Performance/Load row (Excluded) — the envelope may be *asserted* but must never be *measured as throughput*; saturation regimes stay with Pulse's `perf_load_profiles.rs`.
3. **CI-runnable, live-Pulse-free.** Per §9 Live-Pulse scenarios (operator/local `workflow_dispatch` gate only) — `v2-06` must be a static gate over committed artifacts (like the §6 coverage-gate scenario-backing leg: "unit-tier over committed artifacts (no live Pulse), so it runs in CI"), and `v2-07` must be drivable against the §5 stub/in-memory tier, not a live SUT stall.
4. **Any classification must round-trip the one canonical envelope.** Per §3 Status endpoint shape — the envelope is "serialized identically into the Markdown report, the `runs.db` row, and each JSONL journal line"; the harness `status` command reads it via `jq -e` or a bound-parameter `SELECT`, so a shape break is a harness break.
5. **Reported states never exit non-zero.** Per §3 `run` exit-code semantics + §11 E2E stack-specific ban — `environment-suspect`, whatever its representation, is a reported envelope state, not a hard `Fail`; only a hard `Fail` may drive a non-zero exit.
6. **Artifact sanitization is asserted, not assumed.** Per §3 Status endpoint shape + §11 Test Data — the report text that "names the envelope breach as the cause" must carry no absolute host paths and no internal seam-crate struct names; this is a negative test, and `drift.rs` already carries the precedent test for exactly that.
7. **Zero-flakiness / determinism bar.** Per §10 Zero-flakiness budget (no nextest `retries`) + §11 Unit stack-specific ban — over-envelope detection from a realized run must assert on journal-stamp/scheduled shape, never on real elapsed wall-clock; and per §11 Test Data, journal stamps stay `std::time::SystemTime`, never the paused clock.

## Patterns to follow
1. **`crates/conductor-core/src/drift.rs` — the committed-artifact static-gate template.** A `pub fn check_*` returning a structured fault + a `#[cfg(test)] mod tests` doing exact-set equality in *both* directions, a message test asserting no host paths / type names, and a byte-identical-message determinism test. This is the shape `v2-06` should take (per §6 coverage-gate scenario-backing leg + §4 "static assertion" bullet).
2. **Load-time validation beside the existing garde bounds** in `crates/conductor-core/src/scenario.rs` (with `phase_spec.rs` / `expected.rs`), fixtured by rstest `#[case]` rows over a valid/invalid matrix and the committed declarative configs under `scenarios/` (§4 Scenario-config validation surface bullet; §7 Fixture-files seed strategy).
3. **Canonical-serialization goldens by exact-string `assert_eq!` at unit level** — the `verdict.rs` / `report_state.rs` / `scenario.rs` pattern (§4 conductor-report bullet). Any new classification token gets locked this way; insta stays the E2E journal-golden mechanism with `run_id`/timestamp redaction (§6/§7).
4. **Integration tier mechanics for `v2-07`:** `rusqlite::Connection::open_in_memory()` per test, `assert_fs::TempDir` + `CONDUCTOR_RUNS_DIR` for the cross-process leg, MCP stub for any read-back (§5 Boundary types table; §7 Persistent-data seed strategy).
5. **CLI-surface anchor:** `crates/conductor-cli/tests/cli_smoke.rs` (assert_cmd + `NO_COLOR`-stable ASCII label assertions, exit-code assertion) is where a new classification's CLI rendering gets asserted (§6 cli driver row + Selector strategy).

## Anti-patterns to avoid
1. **Never escalate to load/saturation testing** (§11 Test Strategy, stack-specific) — this chunk bounds load; generating or measuring 10k/s-class throughput to "prove" the envelope crosses the standing non-goal.
2. **Never treat a reported state as a process failure** (§11 E2E, stack-specific) — an over-envelope run must not become a non-zero exit or a `Fail` row.
3. **Never substitute a literal for a derived set** — the catalog assertion is catalog-relative and manifest-relative; no hard-coded scenario count and no `P-001..P-0NN` range (§6 Selector strategy as amended 2026-08-09; §11 Universal project-specific "no scenario without a P-ID" companion discipline).

## Contract bindings
- **tests §3 Log format ↔ obs-plan §3.** test-plan §3 is the *source of truth* for the emission-journal envelope; obs derives its product-side envelope from here, not the reverse ("format break = harness break"). If the classification adds an envelope field or token, the change originates in §3; obs owns only the field-allowlist/redaction layer, whose boundary this plan asserts via a negative test. The self-obs stream (`logs/agent-latest.jsonl`, `logs/conductor-tauri.jsonl`) is a *separate* schema and must not be conflated.
- **tests §3 Status endpoint shape ↔ arch §Standard Contracts closed `ReportState` set.** The harness's `status` read (bound-param `SELECT` / `jq -e` predicate over the JSONL) is keyed on that closed set; a sixth variant is an arch amendment that must propagate to the CLI ASCII prefixes, the Markdown lamp, `runs.db`, and webview `LAMP_META` before the harness contract still parses. A run-level qualifier orthogonal to per-check `state` leaves §3's polled fields intact — the cheaper binding.
- **tests §9/§11 CI ↔ security-plan §Dependency Security.** `cargo audit --deny warnings` + `cargo deny check` green (and un-drifted `Cargo.lock`) are tests-owned build-failure conditions (§9, §10) — the chunk's folded PREREQ is discharged at *this* plan's gates.
- **tests §6 Selector strategy ↔ design-system / a11y.** Any new lamp or label must be text-paired (color never sole signal) so role/text selectors stay reliable; the webview E2E leg itself is deferred (Epoch 9, §5), so only the CLI ASCII prefix is asserted now.

## Acceptance criteria contributions
1. **(tests)** `cargo nextest run -p conductor-core` passes with the new envelope-bounds gate: it fails when any committed `scenarios/*.toml` sits outside the recorded envelope, is expressed over the *set* of catalog entries (no literal count, no P-ID range), and its fault message names identity without host paths or internal struct names.
2. **(tests)** `cargo nextest run --workspace --profile ci` green with nextest `retries = 0`, `cargo test --workspace --doc` and `cargo clippy --workspace --all-targets -- -D warnings` clean, and `cargo llvm-cov nextest --fail-under-lines 60` still passing (§10).
3. **(tests)** Integration test for `v2-07`: an over-envelope realized run yields a classification distinct from `Fail`, exits **0**, and round-trips byte-identically through the JSONL journal, the `runs.db` row (bound-parameter `SELECT` — never `format!`-built SQL, §11 Integration), and the Markdown report; the report text names the envelope breach as the cause.
4. **(tests)** Supply-chain gate *observed*, not assumed: `cargo audit` re-run (5th consecutive) and `cargo deny check` verified green by observation; no floor raise, no `deny.toml` ignore, no CI edit — deferral closed only if audit parses (§9 Build failure conditions, §11 CI).
