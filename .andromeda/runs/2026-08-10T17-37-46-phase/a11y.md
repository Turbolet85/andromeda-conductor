## Constraints
- The new named precondition is a **reason detail on the existing `Blocked` lamp, not a seventh lamp state** — the six display labels stay exactly `Pass`/`HOLD`/`Fail`/`Blocked`/`Manual`/`Residual`, each with its text label + glyph (`Blocked` + hollow-ring) (per a11y-plan §6 State color tokens (not-color-alone)).
- Envelope join must be preserved: a blocked row records `state = Blocked` with **no verdict**; the not-color-alone assertion keys on the DOM display label and joins back through this crosswalk, so no new `state` enum value may be introduced for the divergence (per a11y-plan §6 State-naming crosswalk).
- The precondition string, wherever it folds into the obs §6 envelope / a11y artifact, MUST NOT leak absolute host paths or internal seam-crate struct names — a11y inherits tests' Status JSON constraint (per a11y-plan §3 Structured violation JSON schema; §9 CI-specific resource attributes). This is the same invariant the chunk scope names under Artifact hygiene.
- Detail rides existing fields only — a11y artifacts fold rule/selector/criterion detail into `fingerprints[]` rather than adding top-level fields; a new precondition surfaced in the same envelope follows that discipline (per a11y-plan §3 Structured violation JSON schema).
- If the precondition renders in the webview, it must be **real prose with an accessible name**, announced through the existing lamp `status`/`aria-live`, and must not steal focus from a live run or the HOLD trap (per a11y-plan §11 § Visual + § Keyboard; §5 Focus order — run-console-live).
- The two-launch probe and all CLI output are **out of a11y harness scope** — the cli surface is not-assertable; ASCII prefixes / `NO_COLOR` pairing are output-stream discipline, not an a11y verification path (per a11y-plan §1 A11y Scope Summary; §11 § Universal).
- No tier or WCAG-scope change: tier stays Minimal (0), baseline SC 2.1.1 / 1.4.3 / 2.4.3 plus token-driven SCs; this chunk introduces no new criterion (per a11y-plan §1; §3 WCAG criteria mapping).

## Patterns to follow
- Six-state lamp pairing: state token + always-rendered text label + glyph supplement; contrast pair asserted like any other (per a11y-plan §6 State color tokens).
- Non-lamp reuse pattern (established 2026-08-09): a new token-tinted or named value carries **its own always-rendered text label** and is explicitly scoped out of the six-label lamp assertion instead of expanding it (per a11y-plan §6 + amendment below).
- Real-prose non-happy states over decorative skeletons, so NVDA/VoiceOver/Orca announce them and an in-progress/blocked state is never announced as `Fail` (per a11y-plan §3 Screen reader test pattern — must-announce list).
- Component roles already catalogued for the surface that would render this: `status`/`aria-live` lamp, `list`/`listitem` coverage matrix row (per a11y-plan §4 Per-component pattern catalog).

## Anti-patterns to avoid
- NEVER convey the divergence state by color/tint alone — any rendered signal needs its text label (per a11y-plan §11 § Visual).
- NEVER let the precondition string carry absolute host paths or internal seam-crate struct names into the obs §6 envelope (per a11y-plan §11 § SLO).
- NEVER treat the CLI two-launch probe output as an accessibility-assertable surface (per a11y-plan §11 § Universal).

## Contract bindings

- **a11y ↔ tests:** the no-absolute-host-paths / no-struct-names Status JSON constraint is inherited from tests and shared with this chunk's artifact-hygiene rule (a11y-plan §3, §9, §11 § SLO); the a11y step itself rides tests' `wdio run` webview job and is not exercised by this chunk (a11y-plan §9).
