# arch extract

## Relevance
Relevant — the chunk touches the preflight readiness gate contract, the sidecar spawn env-var propagation, and the verdict/error wall, all arch-locked surfaces.

## Constraints
- Code lands in `conductor-verify` (preflight gate + read-back client + `spawn.rs`); a new precondition must not create a cross-seam dep edge, since forbidden cross-seam deps are compile-enforced by the crate-per-seam workspace (per architecture.md §Established Decisions [Module Boundaries] · §Occupied Resources Crate names). No new workspace crate is warranted for a precondition string.
- The readiness result's shape is a locked contract: `ready` / `negotiated_protocol_version` / `expected_protocol_version` / `required_tools` / `data_dir` / `canary_round_trip` / `blocked_precondition` / `checked_at`. A new divergence condition must be expressed as a distinct `blocked_precondition` VALUE, not a new field or a new `canary_round_trip` state (per architecture.md §Standard Contracts — Readiness gate).
- `Blocked` is a `ReportState` variant returned as `Ok(...)`; harness faults are the only `Result::Err`. A detected workspace-key divergence is a verification outcome, so it is a typed value — never `Err`, never a panic (per architecture.md §Established Decisions [Error Handling] · §Cross-cutting Patterns Verdict/error wall).
- A blocked row populates only identity fields (`run_id`, `seed`, `scenario`, `p_ids`, `slo_tier`); `verdict` / `journal_emitted_at` / `read_back_observed_at` / `latency_ms` / `fingerprints` are JSON `null` and NULL in `runs.db`, and cross-run latency/P-036 queries must exclude NULL-measurement rows (per architecture.md §Standard Contracts). The new precondition inherits this exactly — no new column, no non-null measurement.
- `ANDROMEDA_PULSE_DATA_DIR` is an already-registered occupied resource whose propagation semantics are locked: Conductor MUST pass the live Pulse's data-dir to the spawned sidecar, resolving the identical platform default (`%APPDATA%\andromeda-pulse` · `$XDG_CONFIG_HOME`/`~/.andromeda-pulse`) when unset (per architecture.md §Occupied Resources Environment variables). This chunk reads that key; it does not add a new env handle.
- No new `CONDUCTOR_*` env var. The reserved namespace is enumerated and this chunk's condition is detected, not configured — the capability-manifest / load-envelope precedent of deliberately withholding an override handle applies (per architecture.md §Occupied Resources Environment variables · On-disk artifacts).
- Conductor never opens `corpus.db` directly and never persists SUT corpus content; the incidents filter column is `workspace` and `corpus.db` is plaintext SQLite (the P-049 encrypted-at-rest assumption is retired) (per architecture.md §Standard Contracts — Corpus access).

## Patterns to follow
- The preflight gate's existing three-failure-mode structure (protocol mismatch · missing tool · empty canary), each producing a named `blocked_precondition` string rather than a generic message — the new divergence condition is a fourth peer in that same shape (per architecture.md §Standard Contracts · §Established Decisions [Read-Back Dependency Posture]).
- Typed per-seam `thiserror` enums: read-back transport/decode/JSON-RPC faults fan out into `VerifyError` variants (`Transport`/`Protocol`/`Decode`/`JsonRpc`) split across blocked/fail/harness-error — a divergence detection classifies into the blocked lane, not a new error class (per architecture.md §Conventions Error handling).
- The hardened sidecar spawn (fixed program path + `.env(...)` data-dir + injection-reject) as the single place Conductor knows the sidecar's workspace key — read it there, do not re-derive (per architecture.md §Established Decisions [MCP Read-Back Client] · §Occupied Resources Service/process names).
- The `initialize`-result-driven negotiation pattern: read what the live server reports rather than assuming a client-side default; the pinned manifest supplies the expected value and the gate compares (per architecture.md §Established Decisions [Read-Back Dependency Posture]).
- Headless-first: the two-launch verdict and the precondition must both be observable from the `scripts/agent-run.{sh,ps1}` / `conductor preflight` path, which is the release gate; GUI is convenience only (per architecture.md §Design Philosophy · §Cross-cutting Patterns Development Style).

## Anti-patterns to avoid
- Do not silently downgrade a divergence to pass/fail/manual-check, and do not leave it as the generic corpus block — absence/mismatch states are `Blocked` with a NAMED precondition, never an opaque or inferred one (per architecture.md §Established Decisions [Read-Back Dependency Posture]).
- Do not surface the divergence as `Result::Err`, `panic!`, or an untyped string error at the seam — that breaches the verdict/error wall (per architecture.md §Cross-cutting Patterns Verdict/error wall).
- Do not add a `CONDUCTOR_*` handle, a new readiness-result field, a `runs.db` column, or a `ReportState` variant to carry this condition — the five-variant `state` set and the envelope shape are closed (per architecture.md §Standard Contracts · §Occupied Resources).

## Contract bindings
- **Readiness-gate envelope ↔ tests:** the `blocked_precondition` value is the assertable surface for the `method: integration` simulated-mismatch check; the fixture must assert against the readiness result shape in §Standard Contracts, not a log line.
- **Readiness-gate envelope ↔ security:** the precondition string is operator-facing and lands in the run report / logs, so it is bound by the no-absolute-host-paths rule (`.claude/rules/security.md` §Error handling) — arch supplies the field, security supplies the content constraint. `data_dir` already exists as a distinct readiness-result field; the new precondition string must not duplicate a host path into it.
- **Readiness-gate envelope ↔ obs:** a `Blocked` outcome is emitted to the self-observation `tracing` stream (`logs/agent-latest.jsonl` / `logs/conductor-tauri.jsonl`) through the existing processor-stage redaction — the same path-free discipline applies (arch §Occupied Resources On-disk artifacts · obs-plan §3).
- **Sidecar spawn ↔ security:** the `.env(...)` data-dir propagation and injection-reject hardening are security-owned; arch fixes only that the propagated value is `ANDROMEDA_PULSE_DATA_DIR` and that it must equal the live Pulse's.

## Acceptance criteria contributions
- (arch) The detection and precondition code lives in `conductor-verify` (preflight gate / `spawn.rs`), adding no new workspace crate and no new cross-seam dependency edge (per architecture.md §Established Decisions [Module Boundaries] · §Occupied Resources Crate names).
- (arch) The new condition is a distinct `blocked_precondition` string value inside the unchanged readiness-result shape — no added/renamed field, and the three existing failure modes are unaltered (per architecture.md §Standard Contracts — Readiness gate).
- (arch) A detected divergence returns `state: Blocked` as an `Ok(...)` VALUE with `verdict`/`journal_emitted_at`/`read_back_observed_at`/`latency_ms`/`fingerprints` null, never a `Result::Err` or panic (per architecture.md §Cross-cutting Patterns Verdict/error wall · §Standard Contracts blocked-row rule).
- (arch) No new `CONDUCTOR_*` env var, port, MCP tool name, or `runs.db` column is introduced; `ANDROMEDA_PULSE_DATA_DIR` propagation semantics are unchanged (per architecture.md §Occupied Resources).
