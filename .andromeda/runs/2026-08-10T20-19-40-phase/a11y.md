# a11y extract

## Relevance
Partial — backend-only chunk (contracts TOML + Rust preflight/loader, no DOM surface added; `ui/src` holds only generated bindings), but it touches the run-report envelope / lamp boundary that a11y governs.

## Constraints
- The `conductor-cli` / headless surface is **not-assertable** — no ARIA, axe, focus, or keyboard gate applies to anything this chunk emits to stdout; ASCII status prefixes / NO_COLOR text-pairing are output-stream discipline, not an a11y verification path (per a11y-plan §1 A11y surfaces & assistive tech reach + §11 Universal).
- The lamp set is **six**; a new named unmet-term/precondition is a *reason detail under the existing `Blocked` lamp*, never a seventh lamp state — the not-color-alone assertion keys on the LAMP display label, and a non-lamp element carrying a state token needs its own always-rendered text label (per a11y-plan §6 State color tokens + §1 A11y triggers, non-lamp-reuse note).
- The display-label ↔ obs `verdict`/`state` crosswalk is **binding** and is the join key for any `Blocked` row; if `ReportState` or `LAMP_META` changed (the scope says they do not), the crosswalk must be amended before any new label is assertable (per a11y-plan §6 State color tokens crosswalk).
- Any a11y emission for this area folds into the obs §6 envelope **verbatim** — no new top-level fields; rule-id / WCAG-SC tag / selector ride inside `fingerprints[]` (per a11y-plan §3 Structured violation JSON schema).
- A11y artifacts and the strings they carry MUST NOT leak absolute host paths or internal seam-crate struct names — the chunk's host-path-free `Blocked` precondition requirement is the same constraint from the a11y side (per a11y-plan §3 Structured violation JSON schema + §9 CI-specific resource attributes + §11 SLO).
- The zero-WCAG-AA-violation invariant binds only the four must-be-accessible desktop-webview paths (scenario pick/start, operator-pause, run-report view, operator-checklist); this chunk touches none, so it adds no a11y gate and must not weaken or skip the existing operator/local one (per a11y-plan §10 SLO Invariants + §11 CI).

## Patterns to follow
- Verdict/report-state lamp: `status` / `aria-live` live region with an always-present text label **plus** glyph supplement (`Blocked` + hollow-ring), six treatments — the shape any blocked-reason presentation must eventually take (a11y-plan §4 per-component pattern catalog + §6 State color tokens).
- Detail-in-`fingerprints[]` folding: per-run artifact keeps a fixed envelope while enumerating specifics in an array — the existing precedent for "name each unmet term individually" without growing the schema (a11y-plan §3 Structured violation JSON schema).
- Real-prose non-decorative states ("No run yet" / "Run in progress"), announced and never downgraded to `Fail` — the model for how a blocked/unready condition reads to assistive tech rather than a gray skeleton (a11y-plan §11 Visual).
- One webview-automation stack: axe injected via `@axe-core/webdriverio` into the tests' `@crabnebula/tauri-driver` + WebdriverIO session, riding the tests' 5-command harness (`logs`) on Linux+xvfb, operator/local-gated — reuse it if this chunk touches that job at all (a11y-plan §3 A11y testing tool pick + §9 CI Integration).

## Anti-patterns to avoid
- NEVER treat the cli surface as accessibility-assertable — its text output is not an ARIA verification path (a11y-plan §11 Universal).
- NEVER convey a state by color alone, and never let a token-tinted classification element pass as an uncovered lamp state — every lamp carries label + glyph; classification cells carry their own text label (a11y-plan §11 Visual + §1 A11y triggers non-lamp reuse).
- NEVER let a11y artifacts leak absolute host paths or seam-crate struct names into the obs §6 envelope (a11y-plan §11 SLO).

## Contract bindings
- **a11y ↔ obs:** a11y violation / contrast / keyboard JSON reproduces the obs §6 log-format envelope verbatim; details go in `fingerprints[]`, no new top-level fields (a11y-plan §3 Structured violation JSON schema).
- **a11y ↔ obs (join key):** display label ↔ `verdict` / `state` enum crosswalk, verdict-first for HOLD, is how a `Blocked` row is joined back to its journal row (a11y-plan §6 State color tokens).
- **a11y ↔ tests:** a11y steps ride tests' binding 5-command harness (boot / run / status / cleanup / logs) on the shared `wdio run` webview job — the `logs` artifact path must stay intact if this chunk touches the readiness/status command surface (a11y-plan §3 CI integration + §9).
- **a11y ↔ design:** `--count-blocked` (Blocked lamp) + `--status-fail` / `--count-nominal` pairs asserted **by token name** against `--color-base`; raw values stay in design-system (a11y-plan §6 Color contrast pairs).
