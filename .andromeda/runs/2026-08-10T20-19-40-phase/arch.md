# arch extract

## Relevance
Relevant — this chunk lands a fourth `contracts/` manifest, extends the readiness gate's named-precondition set, and touches the `conductor-core` load seam + `conductor-verify` preflight, all of which arch governs directly.

## Constraints
- The new run-contract manifest MUST follow the two-manifest precedent exactly: a committed TOML file under `contracts/`, runtime-read and bounds-checked at load, resolved from a fixed `default_path()` through `resolve_under` with deliberately NO `CONDUCTOR_*` override handle — the deliberate asymmetry against `CONDUCTOR_CONTRACT_MANIFEST` (per architecture.md §Occupied Resources — On-disk artifacts, `pulse-capabilities.toml` / `pulse-load-envelope.toml` entries).
- A malformed / absent / unparseable manifest is a **harness fault** (`CoreError`, `Result::Err`) carrying a named reason — never `Blocked` (a blocked row needs `run_id`/`seed`/`scenario`/`p_ids`/`slo_tier`, none of which exist at manifest-load time) and never a silent widening (per architecture.md §Established Decisions [Accepted Capability Set]).
- Every new named precondition string is **host-path-free** and `data_dir` stays redacted in the readiness result; on an unmet term the dependent auto scenarios are emitted `state: "blocked"` with the named precondition — never silently downgraded to pass/fail/manual-check (per architecture.md §Standard Contracts — Readiness gate).
- When Conductor cannot measure a thing, the deliverable is a precondition string naming the condition **and its candidate causes**, never a claimed measurement — the exact shape the fourth precondition took (per architecture.md §Standard Contracts — Readiness gate, the workspace-key-agreement paragraph).
- Contract-file terms transcribed from the SUT are a **transcribed SUT record, never a Conductor measurement**, and the file must say so via a `provenance` field so a reader can tell how far to trust them (per architecture.md §Occupied Resources — `pulse-load-envelope.toml`).
- Code placement is compiler-enforced: the manifest load + bounds-check seam is `conductor-core` (runtime-agnostic, where both existing loaders live), the readiness gate is `conductor-verify`; new workspace crates are not warranted here (per architecture.md §Established Decisions [Module Boundaries] · §Occupied Resources — Crate names · §Infrastructure Patterns directory tree).
- Conductor does not launch, supervise, or configure `pulse-app` — `ANDROMEDA_PULSE_MCP_ENABLED` is asserted **not set by Conductor itself**, and the non-goals (no Pulse process management) are guards against creep (per architecture.md §Occupied Resources — Environment variables · §Cross-cutting Patterns Scope law).

## Patterns to follow
- **Manifest loader pattern**: serde-deserialize TOML via the `toml` 0.9 + serde 1.0.x stack already present (no new dependency), garde 0.22.1 bounds checks co-located with the structs in the owning seam crate, `CoreError::Config` on parse failure / `CoreError::Validation` on garde failure (per architecture.md §Established Decisions [Scenario Config Format] · §Conventions Config conventions).
- **Two-source integrity-gate pattern**: `check_sut_drift` / `check_load_envelope` / `check_scenario_backing` — a code-native ledger held to **exact-set equality in both directions** against committed data, so the ledger can only shrink under compulsion and a divergence is a named `CoreError` variant, never a silent gap. `UNBACKED_AUTO`'s P-073 edit follows this shape (per architecture.md §Established Decisions [Accepted Capability Set]).
- **Readiness-gate precondition pattern**: extend the existing `ReadyState` / `blocked_precondition` shape — a distinct string per unmet term, `Ok(Blocked)` never `Err`, serialized into the conceptual readiness result alongside `ready` / `required_tools` / `canary_round_trip` / `checked_at` (RFC-3339 colon-delimited) (per architecture.md §Standard Contracts — Readiness gate).
- **Verdict/error wall**: unmet contract terms are verification VALUES routed to `ReportState::Blocked`; `Result::Err` is reserved for Conductor's own faults (manifest parse, transport down, MCP unreachable). Typed `thiserror` enums per seam (`VerifyError` / `CoreError`), `anyhow` only at the `conductor-cli` / `#[tauri::command]` edges (per architecture.md §Design Philosophy · §Conventions Error handling · §Cross-cutting Patterns Verdict/error wall).
- **Storm-shape / envelope coupling**: any prescribed storm must sit inside `contracts/pulse-load-envelope.toml`, whose only asserted term is scenario duration (rate terms declared-not-derivable — the scenario model carries no rate or occurrence-count field), with the `[[exempt]]` ledger at exact-set equality (per architecture.md §Occupied Resources — `pulse-load-envelope.toml`).

## Anti-patterns to avoid
- Do NOT add a `CONDUCTOR_*` env-var override handle for the new contract manifest — the capability-manifest and load-envelope precedents deliberately have none, and the reserved namespace is a closed enumerated list (per architecture.md §Occupied Resources — Environment variables).
- Do NOT widen `ReportState` beyond its five variants or `Verdict` beyond its three; a new unmet-term outcome is a new **precondition string** on the existing `Blocked` state, not a new state (per architecture.md §Standard Contracts — run report envelope).
- Do NOT introduce Pulse process management, an inbound listener, or a new external dependency for reading/asserting the contract — Conductor is a gRPC/MCP client with no server surface, and TOML/serde/garde are already in-stack (per architecture.md §Cross-cutting Patterns Trust boundary · §Established Decisions [Backend Framework]).

## Contract bindings
- **Readiness-gate envelope ↔ tests**: the new precondition string(s) and the `ready:false` result shape are the fixtures the test harness asserts against (arch §Standard Contracts binds to tests' E2E/integration legs; v2-18's `method: integration`).
- **Readiness-gate envelope ↔ security**: precondition strings are host-path-free and `data_dir` redacted — the same redaction discipline security owns for the obs sinks (arch §Standard Contracts Readiness gate ↔ obs-plan §3 processor-stage redaction).
- **Manifest load seam ↔ obs**: a harness-fault `CoreError` on absent/malformed manifest surfaces through the self-observation `tracing` JSON stream (`logs/agent-latest.jsonl`), which must carry no host path (arch §Occupied Resources — On-disk artifacts).
- **`contracts/` artifact ↔ arch amendment at wrap**: a fourth committed manifest is a new Occupied Resource that arch §Occupied Resources enumerates and must be registered at wrap (the `pulse-load-envelope.toml` precedent, amendment 2026-08-09-sut-load-envelope).
- **`UNBACKED_AUTO` pin ↔ scenario catalog**: `check_scenario_backing` couples the code-native pin to the committed scenario catalog at exact-set equality in both directions — the two halves must land in one commit (arch §Established Decisions [Accepted Capability Set]).

## Acceptance criteria contributions
- (arch) The run-contract manifest lives under `contracts/`, is read via a fixed `default_path()` → `resolve_under` with NO `CONDUCTOR_*` override handle, and carries a `provenance` field marking its terms as a transcribed SUT record (per architecture.md §Occupied Resources — On-disk artifacts).
- (arch) An absent / malformed / unparseable run-contract manifest is a `CoreError` harness fault (`Result::Err`) with a named reason — never `Blocked`, never a silent default (per architecture.md §Established Decisions [Accepted Capability Set]).
- (arch) Each unmet contract term yields a distinct, host-path-free `blocked_precondition` string returned as `Ok(Blocked)`; `ReportState` stays five variants, `Verdict` stays three, and `data_dir` stays redacted in the readiness result (per architecture.md §Standard Contracts — Readiness gate + run report envelope).
- (arch) Code lands in the existing seams — manifest load/bounds-check in `conductor-core`, gate assertion in `conductor-verify` — with no new workspace crate, no new `CONDUCTOR_*` env var, and no new external dependency (per architecture.md §Established Decisions [Module Boundaries] · §Occupied Resources).
