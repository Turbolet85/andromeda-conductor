# security extract

## Relevance
Relevant — the chunk adds a third committed SUT-facing manifest (a new external-input boundary), extends the preflight blocked-precondition set, touches the sidecar/data-dir env surface, and carries the seventh consecutive `cargo audit` deferral as a folded-in PREREQ.

## Constraints
- The new `contracts/` run-contract manifest is an external-input boundary of the same class as `pulse-capabilities.toml` / `pulse-load-envelope.toml`: serde deserialize + an explicit `validate()` in `conductor-core`, resolved from a fixed `default_path()` through `resolve_under`, with deliberately **no `CONDUCTOR_*` override handle** (unlike `CONDUCTOR_CONTRACT_MANIFEST`) so the path is not operator-steerable; absent/malformed is a hard harness fault, never defaulted and never silently widened; read faults carry `e.kind()` only, never the path (per security-plan §Input Validation, committed SUT-facing manifests row).
- Every new unmet-term precondition MUST surface as its own distinct named `blocked` string — never the generic corpus-empty string, never a silent downgrade to pass/fail/manual-check; the gate's currently-four named preconditions grow, they do not merge (per security-plan §Security Anti-Patterns → Universal, never-silently-downgrade bullet).
- Precondition strings, the readiness envelope, the journal, and any `runs.db`/report row must stay free of absolute host paths (canonicalized `CONDUCTOR_*` dirs, `ANDROMEDA_PULSE_DATA_DIR`) and internal seam-crate struct/field names; a `blocked` row populates identity fields plus the named precondition, measurement fields `null` (per security-plan §Error Handling, run-report artifact sanitization; §Security Anti-Patterns → Logging).
- Term B (shared data dir) must not change the spawn contract: `andromeda-pulse-mcp` stays a fixed hard-coded program path, `ANDROMEDA_PULSE_DATA_DIR` passes strictly via the `.env(...)` builder after injection-metacharacter rejection, and no contract-derived value (including `ANDROMEDA_PULSE_L4_DETERMINISTIC`) may be interpolated into argv or a shell (per security-plan §Input Validation, `ANDROMEDA_PULSE_DATA_DIR` row; §Security Anti-Patterns → Input + Code Patterns).
- If a term is observed via the MCP read-back surface, decoding stays bounded and non-panicking through the verdict/error wall (`VerifyError::{JsonRpc,Decode,Transport}`); an empty/error round-trip becomes `blocked`, never a false pass-as-empty, and the client keeps negotiating **down** to `2024-11-05` rather than pinning a strict newer default (per security-plan §Input Validation, MCP read-back child-stdout row; §Security Anti-Patterns → Input + Code Patterns).
- The PREREQ `cargo audit` re-check is an advisory-**DATABASE** fault, not a tool fault: run it, record the result, and verify `cargo deny check advisories bans licenses sources` actually ran green as the overlapping signal. Never raise the floor, never add a `deny.toml` ignore, never edit CI, never a silent accept (per security-plan §Dependency Security, two-fault split).
- Scope-law bans hold: no scenario without a Pulse P-ID (bears on the P-073 / `UNBACKED_AUTO` open question), and Conductor introduces no inbound listener of its own — the run contract is a recorded operator expectation that preflight checks, never Conductor launching or configuring `pulse-app` (per security-plan §Security Anti-Patterns → Universal, scope-law/trust-boundary bullet).

## Patterns to follow
- The two existing committed-manifest loaders are the template for the new one: `D:/dev/projects/conductor/crates/conductor-core/src/capability_manifest.rs` and `D:/dev/projects/conductor/crates/conductor-core/src/load_envelope.rs` — `default_path()` + `load()` + `e.kind()`-only `CoreError::Config`, with the traversal guard in `D:/dev/projects/conductor/crates/conductor-core/src/config_path.rs`.
- The named-precondition shape already in place at `D:/dev/projects/conductor/crates/conductor-verify/src/preflight.rs` (`blocked_precondition: Option<String>`, one `const` per precondition, host-path-free prose naming the condition and its candidate causes) — extend it, do not reshape it.
- Hardened-spawn discipline as shipped in `D:/dev/projects/conductor/crates/conductor-verify/src/spawn.rs` (fixed program path, `DATA_DIR_ENV` via `.env(...)`, metacharacter rejection with a `reason:` that names the character, not the path) — consuming this shipped hardened infra requires no new validation boundary.
- Non-path/non-secret env handles (`ANDROMEDA_PULSE_L4_DETERMINISTIC` is a boolean term, not a path) follow the established no-validation note rather than gaining a boundary row (per security-plan §Input Validation, non-path env-handle paragraph).

## Anti-patterns to avoid
- Never dress up Conductor's own inherited env as a measurement of a term set on a process Conductor does not launch — when Conductor cannot measure a thing the deliverable is a named precondition stating the condition and its candidate causes, never a claimed measurement (per security-plan §Security Anti-Patterns → Universal + §Error Handling verdict/error wall).
- Never let a malformed/absent contract file, or a malformed child/transport response on the assertion path, panic or default — hard `Err` for harness faults, `Ok(Blocked)` for unmet terms (per security-plan §Security Anti-Patterns → Universal).
- Never suppress the `cargo audit` red with a `deny.toml` ignore or a CI edit to make the gate look green (per security-plan §Dependency Security).

## Acceptance criteria contributions
- (security) The new run-contract manifest loader resolves only via `default_path()` → `resolve_under` with no `CONDUCTOR_*` override handle, validates on load, treats absent/malformed as a hard fault (never defaulted, never silently widened), and its read errors carry `e.kind()` only — never the path (per security-plan §Input Validation, committed SUT-facing manifests row).
- (security) Each unmet contract term yields its own distinct, host-path-free named `blocked` precondition string returned as `Ok(Blocked)`, with no downgrade to pass/fail/manual-check and no reuse of the generic corpus-empty string; grep the new strings for absolute-path fragments and internal struct names (per security-plan §Security Anti-Patterns → Universal + §Error Handling).
- (security) `cargo audit` re-run and its result recorded verbatim; `cargo deny check advisories bans licenses sources` verified green as the overlapping signal; no floor raise, no `deny.toml` ignore, no CI edit; `Cargo.lock` committed and un-drifted (per security-plan §Dependency Security, two-fault split + §Security Anti-Patterns → Universal).
- (security) Sidecar spawn remains a fixed hard-coded program path with the data dir passed only via `.env(...)` after metacharacter rejection; no contract term is interpolated into argv or a shell, and the existing "only the data-dir env is set" assertion is either preserved or changed only by an explicit `.env(...)` addition (per security-plan §Input Validation, `ANDROMEDA_PULSE_DATA_DIR` row; §Security Anti-Patterns → Code Patterns).
