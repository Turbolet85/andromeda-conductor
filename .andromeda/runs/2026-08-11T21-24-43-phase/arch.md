# arch extract

## Relevance
Relevant — the dispatcher lands inside locked workspace seams (`conductor-run` → `conductor-emit`, possibly `conductor-core`), and its fork touches two arch-registered contracts (determinism discipline, `contracts/pulse-load-envelope.toml`).

## Constraints
- Dispatcher code lives in `conductor-run` (the run composition root library, 9th workspace member — above the seams, below both bins) and consumes `conductor-emit` through its public API only; any model change lands in `conductor-core`. Crate-per-seam dependency edges are compiler-enforced — a forbidden cross-seam edge must not be introduced (per architecture.md §Established Decisions [Module Boundaries] · §Occupied Resources Crate names).
- All stream-shaping non-determinism must come from the timeline's seeded `ChaCha8Rng` (`seed_from_u64`); no clock reads, no unordered iteration, no `StdRng`. The `current_thread` runtime flavor is what makes emission ordering a deterministic function of the seed (per architecture.md §Established Decisions [Determinism RNG] · [Async Runtime Flavor] · §Cross-cutting Patterns Determinism discipline).
- Emission stays on raw `opentelemetry-proto` 0.32.0 message structs over tonic 0.14.6 to `127.0.0.1:4317`; the SDK exporter is banned and no new emit primitive or transport is introduced by this chunk (per architecture.md §Established Decisions [OTLP Emission Strategy] · §Conventions Outbound emission).
- If the fork extends the model, validation is declarative garde 0.22.1 co-located with the serde structs in the owning seam crate; garde 0.22.1's `custom` is field-level only, so cross-field invariants (rate/fraction/mix ordering, severity-mix sums) need the `Context` pattern. Durations non-negative, error fractions ∈ [0,1], ramps sane (per architecture.md §Established Decisions [Validation Library] · §Conventions Config conventions).
- Scenario shape stays declarative TOML under `scenarios/` deserialized via `Scenario::from_toml_str{,_with}` — no scenario DSL, and any migration keeps the existing load sites' contract (parse failure → `CoreError::Config`, garde failure → `CoreError::Validation`) (per architecture.md §Established Decisions [Scenario Config Format] · §Cross-cutting Patterns Config management).
- Verdict/error wall: a dispatch shortfall (unsupported declared shape, primitive gap) is either a typed value or a harness `Result::Err` (`CoreError`/`EmitError` via thiserror 2.0.18) — never a panic, and never a silently-downgraded verdict; anyhow stays at binary edges only (per architecture.md §Established Decisions [Error Handling] · §Cross-cutting Patterns Verdict/error wall).
- The load envelope's rate terms are recorded *declared-not-derivable* precisely because the scenario model carries no rate/occurrence-count field; adding one invalidates that stated justification, so `check_load_envelope`'s assertion surface and the exemption ledger's exact-set-equality property must be re-stated deliberately, never widened silently (per architecture.md §Occupied Resources `contracts/pulse-load-envelope.toml`).

## Patterns to follow
- Crate-seam placement precedent for emission-shaping code: the fingerprint/exception primitive was placed in `conductor-emit` co-located with the content it derives from, with composition of it deferred to the caller seam (per architecture.md §Infrastructure Patterns directory tree; amendment 2026-06-18) — the dispatcher is that caller, composing rather than re-implementing.
- Data-vs-code split precedent: the accepted capability set is manifest data while the coverage classification stays code-native, with an integrity gate holding the two to set-equality (per architecture.md §Established Decisions [Accepted Capability Set]). The chunk's TOML-vs-phase-name fork is the same class of decision; a hybrid resolution should carry an equivalent integrity check rather than an implicit convention.
- Journal-relative ground truth: emission stamps written into the per-run JSONL journal come from `std::time::SystemTime`/`Instant`, never tokio's (virtual) clock, so the SLO math downstream stays valid regardless of how many signals a phase now emits (per architecture.md §Design Philosophy Journal-relative ground truth · §Conventions Data model conventions).
- Public-API stability at the composition root: `conductor-run`'s exported entry points are shared by both bins (`conductor-cli` + `conductor-tauri`), so replacing an internal helper must not move the shared signature (per architecture.md §Occupied Resources Crate names · §Established Decisions [Workspace / Core Structure]).
- Self-observation stays `tracing` 0.1.44 structured JSON — never an OTel SDK, since OTLP is the product emission under test (per architecture.md §Stack and Technologies Self-observation).

## Anti-patterns to avoid
- Do not reach for `opentelemetry-otlp`'s exporter, its batch tasks, or any new transport/broker to fan out per-phase signals — in-process Rust calls / `tokio::sync::mpsc` at most (per architecture.md §Established Decisions [OTLP Emission Strategy] · [Message Broker]).
- Do not introduce a new `CONDUCTOR_*` env handle, port, or on-disk artifact to configure dispatch shape; configuration is scenario files + the existing reserved namespace, and `contracts/*` manifests deliberately carry no override handle (per architecture.md §Occupied Resources Environment variables · §Cross-cutting Patterns Config management).
- Do not add a new dependency to satisfy shape realization without re-stating the audit-surface basis — arch's registry pattern is that every new dep lands a §Stack row and passes audit/deny (per architecture.md §Stack and Technologies · §Infrastructure Patterns Build system).

## Contract bindings
- **arch ↔ obs:** `timeline.execute`'s `emission_count` field (obs-plan §4 CP1) is produced by this dispatcher; the self-observation stack is arch-pinned (`tracing`/`tracing-subscriber`, JSON, not OTel) and its sinks/artifacts (`logs/agent-latest.jsonl`, `logs/conductor-tauri.jsonl`) are arch-registered resources — obs owns the span/field semantics, arch owns the sink and the no-OTel-SDK rule (architecture.md §Stack Self-observation · §Occupied Resources On-disk artifacts).
- **arch ↔ tests:** determinism goldens (next chunk) run under the arch-pinned zero-retry nextest `ci` profile; no retries may mask a flaky stream shape (architecture.md §Infrastructure Patterns Build system).
- **arch ↔ SUT contracts:** if the fork adds a rate/occurrence field, `contracts/pulse-load-envelope.toml`'s provenance and `check_load_envelope`'s exact-set-equality exemption ledger become live surfaces (architecture.md §Occupied Resources).
- **arch ↔ config/validation:** scenario-TOML migration binds to garde 0.22.1's field-level-`custom` limitation and the three binary-edge load sites `from_toml_str_with` already threads (architecture.md §Established Decisions [Accepted Capability Set] · [Validation Library]).

## Acceptance criteria contributions
- (arch) Dispatcher code lives in `conductor-run` consuming `conductor-emit`'s public API, with any model change confined to `conductor-core`; no new workspace crate and no new cross-seam dependency edge (per architecture.md §Established Decisions [Module Boundaries] · §Occupied Resources Crate names).
- (arch) Every non-deterministic choice in the emitted stream derives from the seeded `ChaCha8Rng`; no clock read, no unordered-map iteration, no non-`current_thread` execution introduced (per architecture.md §Established Decisions [Determinism RNG] · §Cross-cutting Patterns Determinism discipline).
- (arch) No new `CONDUCTOR_*` env var, port, contracts-manifest override handle, or on-disk artifact; scenario shape stays declarative TOML bounds-checked by garde 0.22.1 co-located with its serde struct (per architecture.md §Occupied Resources · §Conventions Config conventions).
- (arch) If a rate/occurrence-count field lands, the load envelope's `declared-not-derivable` justification is explicitly re-stated and `check_load_envelope`'s assertion surface is changed deliberately, not widened by omission (per architecture.md §Occupied Resources `contracts/pulse-load-envelope.toml`).

- **2026-08-08-sut-capability-manifest** / **2026-08-09-current-sut-coverage-classification** — precedent for resolving a "convention vs. declaration" fork: move the set to data, keep the classification code-native, and add an integrity gate holding the two to set-equality rather than trusting a convention.
