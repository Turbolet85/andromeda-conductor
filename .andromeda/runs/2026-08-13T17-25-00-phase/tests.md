## Relevance
Relevant — this chunk is a pure tests-domain deliverable (determinism/replay golden extension + seed-space property generalization) plus a unit-tier re-scope of `check_load_envelope` and the standing supply-chain gate re-check.

## Constraints
- Determinism-replay is a mandated coverage trigger, not optional: a fixed scenario+seed must reproduce an identical emission stream across runs, with `conductor-timeline` as the named target — so the dispatcher's emission stream must be frozen by property **and** golden, not one or the other (per test-plan §1 Coverage triggers · property-test (determinism discipline)).
- Virtual clock only: every new timeline test runs `#[tokio::test(flavor = "current_thread", start_paused = true)]` + `tokio::time::advance`; scheduled ordering/shape is the assertion, never real elapsed time (per test-plan §2 Agent-runnable invariants; §4 conductor-timeline bullet).
- Goldens are committed under `<crate>/tests/snapshots/` (insta default) and run fail-don't-write in CI/assert mode; proptest counterexamples persist to `proptest-regressions/` per crate (per test-plan §2 Test directory + naming conventions; §7 Golden artifacts / Randomized data rows).
- No non-deterministic input without seed control, and no golden may capture a wall-clock value — `run_id` / `journal_emitted_at` / `read_back_observed_at` are the redaction set; virtual-clock leakage into a ground-truth artifact is itself a defect a golden must catch (per test-plan §7 Golden artifacts; §11 Test Data).
- Zero-flakiness budget is binding: nextest `retries` stays 0, and a flake here is by definition a real determinism break, not a test-stability nuisance (per test-plan §10 Quality Gates · Zero-flakiness budget).
- Test placement/naming: crate-local `tests/` for this tier, snake_case `fn`, per-seam grouping via `cargo nextest run -p conductor-timeline` / `-p conductor-core`; the `conductor-core` re-scope stays in its in-file `#[cfg(test)] mod tests` (per test-plan §2 Test directory + naming conventions; §4 Conventions).
- Supply-chain green is a build-failure condition, not a nice-to-have: `cargo audit --deny warnings` + `cargo deny check` + an un-drifted committed `Cargo.lock`; external-CLI tool versions are floors, never exact pins (per test-plan §9 Build failure conditions; §11 CI; §4 Tool-version policy).

- For the CARRY: extend the existing in-file unit block in `D:\dev\projects\conductor\crates\conductor-core\src\load_envelope.rs` (local `envelope()` / `scenario()` builders; assertions already name `unpinned` / `rotted` / `lost_subject`). The exact-set-in-both-directions ledger assertion has an established precedent to copy — the coverage gate's scenario-backing leg fails on a new unpinned entry, on pin rot, and on a lost subject (per test-plan §6 Scenario: Coverage-matrix completeness gate · Scenario-backing leg).
- Golden mechanism by altitude: exact-string `assert_eq!` for canonical serialization at unit level; insta for stream/E2E goldens with redaction (per test-plan §4 conductor-report bullet).

## Anti-patterns to avoid
- Never assert a real wall-clock duration in a `conductor-timeline` test, and never let a `std::time` stamp into a golden — that is the paused-clock-leak class a golden exists to catch (per test-plan §11 · Unit + Test Data).
- Never accept a regenerated snapshot through `cargo insta review` or any interactive accept UI — insta runs headless CI/assert (fail-don't-write) only; this is the mechanical enforcement of the scope's "a regenerated golden is a finding, not a rubber-stamp" (per test-plan §11 · Universal).
- Never add a retry, quarantine, or loosened bound to stabilize a determinism test, and never lower `--fail-under-lines 60` to land the chunk (per test-plan §11 · Quality; §10).

## Contract bindings
- **tests ↔ obs (log format):** test-plan §3 is the source of truth for the JSONL format and obs-plan §3 derives from it. The emission-stream golden must capture the dispatcher's emission sequence only — not self-obs `tracing` lines (event or span-lifecycle variants) and not emission-journal wall-clock stamps; the two record shapes must stay unconflated (per test-plan §3 Log format · "Self-obs stream is a distinct artifact").
- **tests ↔ security (dependency gate):** the `cargo audit --deny warnings` + `cargo deny check` CI stage is shared with security §Dependency Security; the PREREQ's remedy (re-run, record, verify deny green — no floor raise, no `deny.toml` ignore, no CI edit) is consistent with the floors policy (per test-plan §9 Supply-chain audit stage; §4 Tool-version policy).
- **tests ↔ arch/contracts (load-envelope CARRY):** tests owns only the assertion side (`check_load_envelope` coverage of the emitting-phase gap sum and the exact-set ledger); the `[envelope]` terms and `[[exempt]]` retirement live in `contracts/pulse-load-envelope.toml` + arch §Occupied Resources and must land in the same commit or the gate fails as ledger rot.

## Acceptance criteria contributions
- `cargo nextest run -p conductor-timeline` passes with the new emission-stream golden committed under `crates/conductor-timeline/tests/snapshots/`, reproducing byte-identical under insta CI/assert mode, with every new test under `start_paused = true` and no wall-clock/`std::time` value inside any golden (per test-plan §7 Test Data & Fixtures · Golden artifacts).
