# a11y extract

## Relevance
Partial — no UI, component, token, or harness work in this chunk, but it is the producer of the `verdict` / `state` / `latency_ms` values that the accessible six-state lamp, the operator-checklist, and the a11y-reproduced run-report envelope all render from.

## Constraints
- `verdict` / `state` are producer-assigned enums that the webview lamp renders; the extraction may emit only values present in the state-naming crosswalk (`Pass` / `CalibrationRegion` / `Fail` verdicts; `Pass` / `Fail` / `ManualCheck` / `KnownResidual` / `Blocked` states) — an out-of-crosswalk value produces an unlabeled seventh lamp (per a11y-plan §6 State color tokens (not-color-alone)).
- Lamp identity is **verdict-first**: `verdict == CalibrationRegion` ⇒ HOLD lamp regardless of `state`; a `ManualCheck` state with no verdict is the `Manual` lamp; `KnownResidual` (this chunk's `degraded_mode` target) is the `Residual` lamp, dashed-ring glyph (per a11y-plan §6 State-naming crosswalk).
- The envelope this chunk writes real values into is the obs §6 11-field log format, which a11y §3 reproduces **verbatim** and narrows (a11y violations fold into `fingerprints[]`, no new top-level fields) — a field add/rename/semantic change here obligates an a11y-plan §3 amendment (per a11y-plan §3 Structured violation JSON schema).
- If `fingerprints[]` is populated by this chunk, entries must stay selector/ID-shaped: no absolute host paths, no internal seam-crate struct names — a11y inherits tests' Status JSON constraint on this same array (per a11y-plan §3 Structured violation JSON schema, §9 CI-specific resource attributes).
- Absent / malformed / errored read-back must surface as the typed `Blocked` state (hollow-ring glyph + `Blocked` label), never as an in-progress result downgraded to `Fail` and never as a blank/absent lamp value (per a11y-plan §11 Visual).
- A not-color-alone failure — any of the six state tokens reaching the lamp without its text label + glyph pair — is a hard build/gate failure, not a warning (per a11y-plan §10 Build / deploy failure conditions).
- The six-label assertion keys on **lamp display labels only**; `--status-residual` also tints the coverage-matrix out-of-scope Mode cell as a coverage-mode classification, not a seventh state, so `KnownResidual` routing must not be conflated with that cell (per a11y-plan §6 State color tokens (not-color-alone)).

## Patterns to follow
- The state-naming crosswalk table is the single join from a journal row's `verdict`/`state` enum back to its lamp display label — any new state routing must land in an existing crosswalk row rather than inventing a display label (per a11y-plan §6 State color tokens).
- Envelope discipline: obs fixed the schema, a11y narrows it — extra per-check detail rides existing fields (`fingerprints[]` tuple style) instead of new top-level keys (per a11y-plan §3 Structured violation JSON schema).
- `ManualCheck` renders as the operator-checklist (checkbox-per-item, each item exposing induced-state + expected-observation text, unticked-count roll-up announced) — a `ManualCheck` this chunk produces must carry the per-item text that render depends on (per a11y-plan §4 Per-component pattern catalog; §1 Critical paths → Operator-checklist).
- Verdict lamp announces state changes via `status` / `aria-live` and the `Fail` lamp resolves in place, motionless — terminal, non-flapping state assignment keeps announcements from double-firing (per a11y-plan §4 Per-component pattern catalog).

## Anti-patterns to avoid
- NEVER convey state by color alone — no emitted state value may lack its `Pass`/`HOLD`/`Fail`/`Blocked`/`Manual`/`Residual` text label + glyph pairing (per a11y-plan §11 Visual).
- NEVER downgrade in-progress / empty / unavailable read-back to a `Fail` rendering — real prose and the typed `Blocked` value carry those cases (per a11y-plan §11 Visual).
- NEVER let absolute host paths or internal seam-crate struct names reach the obs §6 envelope that a11y artifacts share (per a11y-plan §11 SLO).

## Contract bindings
- **a11y §3 Structured violation JSON schema ↔ obs §6 Log Format JSON Schema** — a11y reproduces the 11-field envelope verbatim; this chunk makes `verdict` / `state` / `latency_ms` / `read_back_observed_at` measured rather than placeholder-derived, so envelope stability is a shared contract (amend a11y §3 if fields move).
- **a11y §6 State-naming crosswalk ↔ this chunk's `Verdict` / `ReportState` producer assignment** — the crosswalk is the documented join from a failing lamp back to its `runs.db` / JSONL journal row.
- **a11y §3/§9 redaction constraint ↔ tests' Status JSON constraint** — inherited, and identical to this chunk's stated redaction boundary inside `classify`.
- **a11y §6 state color tokens ↔ design §Color Palette** — the six state tokens are bound to exactly the enum set this chunk produces; no token/label pair exists for a new state.
- **a11y §9 CI integration ↔ tests' 5-command `logs`** — not engaged by this chunk (a11y gate is operator/local, and this chunk adds no CI gate).

## Acceptance criteria contributions
- (a11y) Every `state` / `verdict` value the extraction can emit resolves to exactly one of the six lamp display labels via the crosswalk; no value outside `Pass|Fail|ManualCheck|KnownResidual|Blocked` × `Pass|Fail|CalibrationRegion` is reachable (per a11y-plan §6 State color tokens (not-color-alone)).
- (a11y) `degraded_mode` read-back maps to `KnownResidual` and therefore to the `Residual` lamp (dashed-ring glyph + `Residual` text label), not to a `Fail` lamp and not to a seventh unlabeled state (per a11y-plan §6 State-naming crosswalk + §11 Visual).
- (a11y) A malformed / absent / errored read-back yields the typed `Blocked` state (hollow-ring + `Blocked` label) rather than a `Fail` or an empty lamp, preserving the "in-progress is never a Fail" rule downstream (per a11y-plan §11 Visual).
- (a11y) The run-report envelope keeps its 11 fields with unchanged names/semantics, or the change is landed as an a11y-plan §3 amendment before merge (per a11y-plan §3 Structured violation JSON schema).
