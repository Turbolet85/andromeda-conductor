# arch extract

## Relevance
Relevant — this chunk lands library code inside two locked workspace crates and writes into the pinned run-report envelope, so arch's crate boundaries, verdict/error wall, and envelope contract all bind.

## Constraints
- Code lands in `conductor-verify` (the extraction seam — it owns the read-back client) and `conductor-run` (the composition root); both are existing locked workspace members, and the seam dependency edge `conductor-run → conductor-verify` is the compiler-enforced direction. No new crate; a forbidden cross-seam edge simply will not compile (per architecture.md §Established Decisions [Module Boundaries] · §Occupied Resources Crate names).
- The verdict/error wall is absolute in every seam: a malformed / absent / degraded / errored read-back is an `Ok(...)` value (`Verdict` / `ReportState`), and `Result::Err` is reserved for harness faults (transport down, MCP unreachable). MCP error responses and `tonic::Status` codes are first-class verification inputs, never panics (per architecture.md §Established Decisions [Error Handling] · §Cross-cutting Patterns Verdict/error wall).
- Typed errors stay `thiserror` per seam — new read-back extraction failures fan into the existing `VerifyError` variants (`Transport`/`Protocol`/`Decode`/`JsonRpc`, mapping blocked/fail/harness-error); `anyhow` appears only at the `conductor-cli` / `#[tauri::command]` edges, so `execute_scenario`'s `anyhow::Result<RunRecord>` signature is exactly the permitted edge shape (per architecture.md §Conventions Error handling).
- `ReportState` stays the closed five-variant set `{Pass, Fail, ManualCheck, KnownResidual, Blocked}` and `Verdict` the closed three; `KnownResidual` is already arch's defined state for "a `retrieve_report` result returned under `degraded_mode`", so the degraded routing realizes an existing definition rather than widening the enum (per architecture.md §Established Decisions [Read-Back Dependency Posture] · §Standard Contracts).
- `verdict` and `state` remain independent — the `Verdict → ReportState` default mapping is `Pass→Pass`/`Fail→Fail`/`CalibrationRegion→ManualCheck`, and a producer may assign a context-specific state (which is what the degraded_mode → `KnownResidual` routing is). The run-report lamp is chosen verdict-first (per architecture.md §Established Decisions [Probabilistic-Assertion Policy]).
- The run-report envelope's field set and encodings are fixed: the eleven-field shape, `latency_ms` as INTEGER ms (NULL for unmeasured), `journal_emitted_at`/`read_back_observed_at` as TEXT RFC-3339, `fingerprints` as a JSON1 TEXT array of fingerprint strings, `slo_tier` a closed TEXT enum over `<5s`/`<20s`/`<90s`. `runs.db` has no migration framework — column types were fixed on first write (per architecture.md §Standard Contracts Run report envelope · §Conventions Data model conventions).
- Latency is always `read_back_observed_at − journal_emitted_at` against the on-disk JSONL journal, never wall-clock-from-test-start; journal stamps come from `std::time::SystemTime`/`Instant`, never tokio's virtual clock (per architecture.md §Design Philosophy Journal-relative ground truth · §Cross-cutting Patterns Determinism discipline).
- Consume the four shipped corpus-tool wrappers only; the MCP tool set (`query_incident_list` · `retrieve_report` · `retrieve_telemetry_slice` · `mark_incident_resolved`) is the complete route-equivalent surface, and no new env var may be added outside the reserved `CONDUCTOR_*` namespace (per architecture.md §Occupied Resources Interface routes · Environment variables).

## Patterns to follow
- Raw `serde_json::Value` in, typed value out: the hand-rolled JSON-RPC client deliberately returns the unenveloped raw tool payload because Pulse's server is non-MCP-compliant for `tools/call`. The extraction seam is the layer that turns that `Value` into a typed observation — it must not assume a `{content:[…]}` envelope (per architecture.md §Established Decisions [MCP Read-Back Client]).
- Blocked-row shape as the precedent for unmeasured checks: a blocked row populates only `run_id`/`seed`/`scenario`/`p_ids`/`slo_tier` and emits `verdict`, both instants, `latency_ms`, and `fingerprints` as JSON `null` / SQL NULL; cross-run latency, percentile and P-036 fingerprint queries MUST exclude NULL-measurement rows (per architecture.md §Standard Contracts Readiness gate).
- Fingerprint as the fidelity carrier: `retrieve_telemetry_slice.fingerprint_refs` is arch's proven read-back carrier (Pulse scrubs incident titles), so it is the sanctioned source if `fingerprints` gets populated — matching Pulse's derivation, stored as the JSON1 TEXT array (per architecture.md §Standard Contracts Readiness gate · §Conventions Data model conventions).
- Degraded/absence semantics distinguish accepted residual from real `Fail`: arch already separates "blocked precondition" (never measured), "known residual" (pre-accepted deviation), and `Fail` (wrong reaction). Route on which of the three actually happened, not on convenience (per architecture.md §Established Decisions [Read-Back Dependency Posture]).
- Corpus data is SUT-owned: `corpus.db` is plaintext SQLite that Conductor reads through the sidecar only and never persists or exfiltrates — extracted observed values are derived signals, not copied corpus content (per architecture.md §Standard Contracts corpus access).

## Anti-patterns to avoid
- Do not turn a read-back miss, a shape mismatch, a JSON-RPC error result, or a degraded response into `Result::Err` or a panic — that collapses the verdict/error wall and makes the report unable to classify the SUT (per architecture.md §Cross-cutting Patterns Verdict/error wall).
- Do not add a `ReportState`/`Verdict` variant, a `runs.db` column, or an envelope field to carry extraction detail; `state` stays the closed five-variant set and the run-level qualifier precedent is a separate additive table, not a widened `runs` row (per architecture.md §Occupied Resources On-disk artifacts `runs.db` · §Standard Contracts).
- Do not introduce a new dependency, a new MCP tool name, a new spawn path, or a `CONDUCTOR_*` env handle for tool/field selection — the manifest/`resolve_under` precedent is fixed-path with deliberately no override handle (per architecture.md §Occupied Resources · §Stack and Technologies).

## Contract bindings
- **Run-report envelope ↔ report/storage seam:** the extraction's output populates the eleven-field envelope shared by the Markdown report, the JSONL journal, and the `runs.db` `runs` row — `conductor-report` owns the writer; the extraction must produce values already in the envelope's encodings (INTEGER `latency_ms`, TEXT RFC-3339 instants, JSON1 fingerprint array) (architecture.md §Standard Contracts · §Conventions Data model conventions).
- **Verdict/error wall ↔ tests:** the stub-provable requirement means the deterministic test surface must exercise malformed / degraded / absent read-back shapes and assert typed `Blocked`/`Fail`/`KnownResidual` values, not error propagation (architecture.md §Cross-cutting Patterns Verdict/error wall; test tier detail is test-plan's).
- **Redaction ↔ obs/security:** observed values reach `runs.db` / journal / report through the existing redaction discipline — precondition and observed strings are host-path-free and carry no internal struct names or corpus content (architecture.md §Standard Contracts Readiness gate host-path-free clause; processor-stage redaction is obs-plan §3's).
- **CI posture ↔ live Pulse:** dynamic end-to-end proof requires a live Pulse with `mcp-server` + `ANDROMEDA_PULSE_MCP_ENABLED` and is an operator/local gate, never a CI gate — matching the chunk's "provable against the stub" boundary (architecture.md §Established Decisions [CI/CD]).

## Acceptance criteria contributions
- (arch) The extraction seam lives in `conductor-verify` and its consumer in `conductor-run`, with no new workspace crate and no new cross-seam dependency edge (per architecture.md §Established Decisions [Module Boundaries] · §Occupied Resources Crate names).
- (arch) Every read-back failure mode — absent tool result, malformed/unexpected `Value` shape, JSON-RPC error result, degraded response — yields an `Ok(...)` `Verdict`/`ReportState` value; only harness faults (transport down, MCP unreachable) yield `Result::Err`, and nothing panics (per architecture.md §Established Decisions [Error Handling] · §Cross-cutting Patterns Verdict/error wall).
- (arch) The written envelope keeps its eleven fields and encodings unchanged — `latency_ms` INTEGER ms (NULL when unmeasured), instants TEXT RFC-3339, `slo_tier` in `{<5s,<20s,<90s}`, `fingerprints` a JSON1 TEXT array — with no `runs.db` column added and no `ReportState`/`Verdict` variant added (per architecture.md §Standard Contracts · §Conventions Data model conventions).
- (arch) `latency_ms` is computed as `read_back_observed_at − journal_emitted_at` from journal stamps taken via `std::time::SystemTime`/`Instant`, never a wall-clock-from-start or tokio virtual-clock read (per architecture.md §Established Decisions [Timing-Tolerance Model] · §Cross-cutting Patterns Determinism discipline).
- (arch) No new dependency, MCP tool name, spawn path, or `CONDUCTOR_*` env handle is introduced (per architecture.md §Occupied Resources · §Stack and Technologies).
