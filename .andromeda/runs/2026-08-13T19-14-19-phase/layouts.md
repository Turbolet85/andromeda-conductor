## Constraints
- The per-P-ID lamp set is **closed at six** (`Pass` / `CalibrationRegion` / `Fail` / `Blocked` / `ManualCheck` / `KnownResidual`); `degraded_mode` must route into the existing `KnownResidual` state, never a seventh lamp or a sixth `ReportState` (per layout-templates §Surface: cli — Component — Primary content block 2 (verdict / report-state lines)).
- `KnownResidual` is a measured, **pre-accepted** gap rendered muted (webview dashed-ring `status-residual` dot / cli `[RESIDUAL]` ANSI 246) and is **never red, never downgraded to Fail**; it carries an "expected until {named fix}" detail line (the P-032 `recent_commits` precedent) (per layout-templates §Surface: desktop-webview — Component — Primary content block 2 (run-report view + verdict lamp)).
- A malformed / absent / errored read-back surfacing as a typed `Blocked` renders hollow ring / `[BLOCKED]` ANSI 60 with its **named precondition string** below and measurement columns as `—` / null — **never a red error** (`Blocked` ≠ red — it was never measured) (per layout-templates §Surface: cli — Component — Primary content block 1 (results / SLO table)).
- State is **never color-alone**: every state cell pairs its color with the ASCII bracket prefix / verdict text so it survives `NO_COLOR`, piping and screen readers — whatever the extraction emits must be text-bearing, not a color-only signal (per layout-templates §Surface: cli — Signature placement + IA notes — Pipe discipline).
- Output shape is a **stability contract**: the results/SLO table is exactly **6 columns** (P-ID · scenario · state · slo_tier · latency_ms · fingerprints) and the coverage matrix a separate **4 columns**; measured `verdict` / `state` / `latency_ms` (and `fingerprints`, if the open question resolves to populating it) fill *existing* columns — adding one without a `--format` flag is a breaking change for downstream agents (per layout-templates §Surface: cli — Component — Primary content block 1 + §Surface: cli — IA notes — Command model).
- The footer / summary roll-up tallies **each state token in its own color paired with its label**, and the per-state counts must sum to the step denominator over the manifest's accepted set — newly-measured Residual/Blocked/Fail states must land in that tally, not outside it (per layout-templates §Surface: desktop-webview — Component — Footer (status strip); §Surface: cli — Output structure `conductor suite`).
- The run-report view shows **distinct non-result states** ("No run yet" / "Run in progress") and never a partial or failed verdict for an unfinished run — real measured values must not turn an in-flight run into a rendered Fail (per layout-templates §Surface: desktop-webview — Component — Primary content block 2).

## Patterns to follow
- **Verdict-line anatomy is fixed**: lamp/ASCII prefix + scenario label + P-ID (Data / `color-id-cyan` ↔ ANSI 117) + verdict text + latency_ms + slo_tier. Extraction fills these existing fields; no new field is rendered (per layout-templates §Surface: cli — Output structure `conductor run <scenario>`; §Surface: desktop-webview — Wireframe — Run report (terminal)).
- **Indented detail line under a non-measured row**: `precondition: …` under `Blocked`, `residual: … until {named fix}` under `KnownResidual`, in Body / `text-tertiary` (webview) ↔ dim ANSI 246 (cli). A degraded-mode residual should reuse that shape (per layout-templates §Surface: desktop-webview — Wireframe — Run report; §Surface: cli — Output structure `conductor run`).
- **Run-level qualifiers ride OUTSIDE the lamp column** — the `[ENVIRONMENT-SUSPECT]` caption and the `not-conductors` Mode-cell precedent. If the degraded signal turns out to be run-wide rather than per-check, that precedent (a qualifier that alters no per-check state) is the established shape, not a new lamp (per layout-templates §Surface: cli — Component — Primary content block 2).
- **Adapted, not forked, across surfaces**: the same states/tokens by name on desktop CSS vars ↔ cli ANSI ↔ Markdown artifact; one extraction result must read identically on all three (per layout-templates §Surface: cli — IA notes — Multi-surface coordination; §Surface: desktop-webview — IA notes — Multi-surface coordination).
- **Webview receives values over the single Tauri `Channel` / the deny-by-default command set, never re-derived in TypeScript** (the `unbacked` prop precedent) — measured verdict/state/latency flow through the existing backend→frontend seam (per layout-templates §Surface: desktop-webview — IA notes — Live channel).

## Anti-patterns to avoid
- Do **not** invent a new lamp state, bracket label, status color or table column for degraded-mode / extraction-failure outcomes — the lamp set is closed and column count is a parse contract (per layout-templates §Surface: cli — Component — Primary content block 2 + IA notes — Command model).
- Do **not** render `Blocked` or `KnownResidual` in `status-fail` / ANSI 203, and never flash/blink a `Fail` — lamps resolve motionless (per layout-templates §Surface: desktop-webview — Component — Primary content block 2).
- Do **not** widen the rendered line body with raw read-back payload — verdict lines carry only the mono identifiers (P-ID, `run_id`, slo_tier, latency_ms, fingerprints) plus terse prose (per layout-templates §Surface: cli — Component — Primary content block 2).
