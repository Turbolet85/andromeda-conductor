# arch extract

## Relevance
Relevant — the chunk exercises arch-owned contracts live (readiness gate, run-contract artifact, MCP read-back client, runs/ artifacts, env-var namespace), all within already-locked crates and surfaces.

## Constraints
- The preflight readiness gate's shape is fixed and its named preconditions are exactly FIVE (protocol version-mismatch · required-tool absence · fingerprint absent from an existing incident · app/sidecar workspace-key agreement · unmet run-contract terms), with the run-contract arm ordered after the tool checks and BEFORE the canary arms, skipping the canary poll rather than paying it (per architecture.md §Standard Contracts — Readiness gate). A live run surfacing one of these is the gate working; no sixth arm.
- `ready:false` ⇒ every dependent auto scenario is emitted `state: "blocked"` with the named precondition — never silently pass/fail/manual-check — and a blocked row populates only `run_id`/`seed`/`scenario`/`p_ids`/`slo_tier`, with `verdict`/`journal_emitted_at`/`read_back_observed_at`/`latency_ms`/`fingerprints` as JSON `null` (NULL in `runs.db`) (per architecture.md §Standard Contracts — Readiness gate + Run report envelope).
- Verdict/error wall: `Blocked` is a returned VALUE (`Ok(ReportState::Blocked)`); `Result::Err` is reserved for harness faults (transport down, MCP unreachable, config parse). Live transport failure must not become a verdict, and neither becomes a panic (per architecture.md §Established Decisions [Error Handling] + §Cross-cutting Patterns — Verdict/error wall).
- Every precondition string is host-path-free and `data_dir` is REDACTED in the readiness result; `corpus.db` is SUT-owned data Conductor never persists or exfiltrates (per architecture.md §Standard Contracts — Readiness gate + Corpus access).
- Only the four PERSISTENT-CORPUS MCP tools work cross-process from a Conductor-spawned sidecar (the in-memory-buffer tools return empty), and incidents are filtered by the `workspace` column while the sidecar keys on raw `ANDROMEDA_PULSE_DATA_DIR` — a key divergence returns zero rows forever, byte-identical on the wire to "no incident" (per architecture.md §Standard Contracts — Readiness gate NOTE + §Occupied Resources `ANDROMEDA_PULSE_DATA_DIR`).
- No new env handle: the live recipe composes existing registry entries only — `CONDUCTOR_PREFLIGHT_TIMEOUT` (default 30, with the run contract's `min_canary_poll_seconds` as an effective FLOOR it cannot sit below; env overrides upward only), plus the Pulse-side `ANDROMEDA_PULSE_MCP_ENABLED` / `ANDROMEDA_PULSE_L4_DETERMINISTIC` / `ANDROMEDA_PULSE_DATA_DIR`, all asserted NOT set by Conductor and only READ in Conductor's own environment as the `shell-declaration` proxy (per architecture.md §Occupied Resources — Environment variables).
- Dynamic live proof is an operator/local gate, never a CI gate — CI has no Pulse; `scripts/agent-run.{sh,ps1}` `boot` wrapping `conductor preflight` is the documented headless entrypoint and source of truth (per architecture.md §Established Decisions [CI/CD] + [Deployment] + §Infrastructure Patterns — CI/CD approach).

## Patterns to follow
- Run-contract term semantics as an honesty statement: `shell-declaration` is the ONLY kind that can block (observable in Conductor's own environment); `declared-not-observable` is recorded and never blocks, because blocking would claim a measurement Conductor cannot make (per architecture.md §Occupied Resources — `contracts/pulse-run-contract.toml`). The three-arm probe's recorded reasons must respect this.
- Contract-manifest loading pattern: `RunContract::default_path()` resolved through `resolve_under`, runtime-read and bounds-checked at load, with deliberately NO `CONDUCTOR_*` override handle (the `pulse-capabilities` / `pulse-load-envelope` precedent); a malformed/absent manifest is a `CoreError` harness fault, never `Blocked` (per architecture.md §Occupied Resources + §Established Decisions [Accepted Capability Set]).
- Hand-rolled line-delimited JSON-RPC over the sidecar's stdio returning RAW `serde_json::Value` — Pulse's `tools/call` is non-MCP-compliant (no `{content:[…]}` envelope), which is exactly why `extract.rs`'s readers are hand-written key lookups and why a live key-diff is the only witness (per architecture.md §Established Decisions [MCP Read-Back Client] + §Conventions — Inbound verification).
- Hardened sidecar spawn: fixed program path resolved from PATH + `.env(ANDROMEDA_PULSE_DATA_DIR, …)` propagating the LIVE Pulse's data dir + injection-reject; when unset, resolve the identical platform default (`%APPDATA%\andromeda-pulse` on Windows) (per architecture.md §Occupied Resources — Service/process names + `ANDROMEDA_PULSE_DATA_DIR`).
- Artifact placement and naming: per-run `<run_id>.jsonl` journal + `<run_id>.md` report + `runs.db` under `runs/` (moves with `CONDUCTOR_RUNS_DIR`, never overwritten); `run_id` uses the filesystem-safe hyphen stamp while in-payload instants (`checked_at`) use colon-delimited RFC-3339; on-disk Markdown evidence files are kebab-case (per architecture.md §Standard Contracts — Timestamp formats + §Conventions — Naming patterns + §Occupied Resources — On-disk artifacts).

## Anti-patterns to avoid
- Do NOT add a sixth precondition, widen the `state` set beyond the closed five variants, or downgrade a blocked result to pass/fail/manual-check (per architecture.md §Standard Contracts).
- Do NOT introduce a `CONDUCTOR_*` override handle for the run contract, a new env var, an inbound listener, or any HTTP/network surface of Conductor's own — the only deliberate port-binding exception is the port-occupier fault scenario (per architecture.md §Occupied Resources + §Cross-cutting Patterns — Trust boundary).
- Do NOT perform Pulse process management or edit Pulse source from this repo, and do NOT let any live-Pulse dependency become a required CI step (per architecture.md §Cross-cutting Patterns — Scope law + §Established Decisions [CI/CD]).

## Contract bindings
- **Readiness-gate envelope ↔ report/storage seam:** the readiness result and the run-report envelope are one shape shared by the Markdown report and the `runs.db` row; NULL-measurement (blocked) rows MUST be excluded from cross-run latency/percentile and P-036 fingerprint queries (per architecture.md §Standard Contracts).
- **Readiness gate ↔ tests harness:** the live leg is an operator/local gate; any fixture or golden that pins a live response's key shape must not require a running Pulse in CI (per architecture.md §Infrastructure Patterns — CI/CD approach). Coordinates with the tests-plan owner on tier placement.
- **Precondition strings ↔ security/obs redaction:** host-path-free strings + redacted `data_dir` bind arch's gate contract to the obs processor-stage redaction applied to `logs/agent-latest.jsonl` (per architecture.md §Standard Contracts + §Occupied Resources — On-disk artifacts).
- **`ANDROMEDA_PULSE_DATA_DIR` propagation ↔ sidecar spawn hardening:** arch mandates propagation; the spawn hardening (fixed program, injection-reject) is security's (per architecture.md §Occupied Resources — Service/process names).
- **Deterministic-L4 deferral ↔ residual ledger:** "Conductor green" under deterministic L4 means the pipeline carried a canned answer end to end, not that interpretation is trustworthy; the gap is owned by a conductor-0.3.0 entry pinned in `.andromeda/residuals.md` and asserted via the `UNBACKED_AUTO` ledger (per architecture.md §Established Decisions [Read-Back Dependency Posture]).

## Acceptance criteria contributions
- (arch) The live preflight returns a readiness result whose `blocked_precondition` (when `ready:false`) is one of the FIVE named preconditions, host-path-free with `data_dir` redacted, and is returned as `Ok(...)` — no panic, no `Err` for a blocked outcome (per architecture.md §Standard Contracts — Readiness gate).
- (arch) No new `CONDUCTOR_*` env var, no override handle on `contracts/pulse-run-contract.toml`, no new workspace crate, and no inbound listener are introduced; the live recipe uses only registered handles and `CONDUCTOR_PREFLIGHT_TIMEOUT` is set at or above the contract's `min_canary_poll_seconds` floor (per architecture.md §Occupied Resources).
- (arch) Code changes (if any) stay inside `crates/conductor-verify` (preflight/client/spawn/extract) and `crates/conductor-run`, with no Pulse source edited and no cross-seam dependency added (per architecture.md §Established Decisions [Module Boundaries] + §Cross-cutting Patterns — Scope law).
- (arch) No live-Pulse dependency is added to any CI job or existing gate; the live leg remains an operator/local gate driven through `scripts/agent-run.{sh,ps1}` `boot` (per architecture.md §Infrastructure Patterns — CI/CD approach).
