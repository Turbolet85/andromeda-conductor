# obs extract

## Relevance
Partial — the chunk ships no new telemetry surface, but the live read-back leg, its `runs/` + `runs.db` evidence, and every recorded arm pass through obs's redaction, record-shape, and `verify.readback*` span/log-field contracts.

## Constraints
- **Two record shapes stay distinct.** `logs/agent-latest.jsonl` (and stderr) carry the self-obs base line (`timestamp_ms`, `level`, `target`, `service.name`/`.version`, `deployment.environment`, `run_id`); `runs/<run_id>.jsonl` + the `runs.db` row carry the 11-field Run-report envelope. Live evidence must be filed under the right shape (per obs-plan.md §3 Log format JSON schema — two record shapes).
- **Artifact hygiene is the redaction layer, not a convention.** Absolute host-FILE paths (drive-letter, `/home`, `/Users`, `%APPDATA%`, `~/.cargo`, `.rustup`, backtrace paths) mask to `<redacted>` at the processor stage in `conductor-core::redact`; non-allowlisted field names are dropped; the allowlisted `target` module path is preserved. The scope's "`data_dir` stays redacted / arms named by role" is this layer, single-location-owned (per obs-plan.md §11 PII Scrubbing + §11 Logs).
- **A span attribute must be a name in `conductor-core::redact::ALLOWLISTED_FIELDS` or it emits nothing.** Any new attribute for the live leg (an arm label, a cwd role, a warm-up counter) is silently dropped unless allowlisted — a failure mode indistinguishable from "no live signal" (per obs-plan.md §4 Required span attributes).
- **Bounded span-name set.** `verify.readback*` already covers the shipped `verify.readback.preflight` / `.preflight_boot`; never a per-arm, per-cwd, or per-data-dir span name (per obs-plan.md §11 Spans / Traces).
- **Zero unlogged panics + the verdict/error wall.** Unreachable sidecar, live transport failure, or malformed/unexpected read-back ⇒ a structured `warn`/`error` line and `Ok(Blocked)` with its named precondition; panic hook → one-line JSON backtrace → `Display`-not-`Debug` at the `anyhow` edge (per obs-plan.md §10 Always-required SLO invariant + §11 Error Reporting).
- **Wall-clock only for the timing evidence.** `journal_emitted_at` / `read_back_observed_at` / `latency_ms` come from `std::time::SystemTime`, never tokio's virtual clock — load-bearing here because the raised poll floor (`min_canary_poll_seconds`) and the warm-up window are measured journal-relative (per obs-plan.md §5 + §11 project-specific bans).
- **The MCP read-back is a must-log boundary call.** Each read-back logs tool name (`mcp_tool`), `latency_ms`, error (if any), and the canary-check result — the key-diff dump's provenance belongs on these structured lines, not on ad-hoc stdout (per obs-plan.md §6 Boundary-call wrappers).

## Patterns to follow
- The shipped preflight instrumentation at `D:\dev\projects\conductor\crates\conductor-verify\src\preflight.rs:134` / `:234` — `#[tracing::instrument(name = "verify.readback.preflight", skip_all)]`, i.e. manual client spans on the MCP seam with `skip_all` plus explicitly named allowlisted fields (per obs-plan.md §4 auto-instrumentation table: rmcp is a seam, never auto-instrumented).
- `redact_value` applied at the value boundary before anything enters an artifact — preflight already does this for `data_dir` and for error strings (`preflight.rs:144`, `:171`, `:249`, `:260`); the three-arm recording follows the same "role, never path" shape (per obs-plan.md §11 PII Scrubbing — scrub at the processor stage, not the sink).
- The blocked-state boundary line `tracing::info!(state = …Blocked.label(), "preflight blocked: {precondition}")` (`preflight.rs:215`) — `state` is an allowlisted envelope field, so the per-arm `blocked_precondition` evidence reads directly off these lines (per obs-plan.md §6 log-level mapping: `info` = state transitions, `warn` = degraded/recoverable).
- Degraded read-back is **observed, not requested** — it rides a `warn`-level line on the allowlisted `message` field rather than a request-side attribute (per obs-plan.md §4 Known-residual classification path).
- Agent-mode capture is a read-only trigger (`--agent-mode` flag `||` `CONDUCTOR_AGENT_MODE` env, never written by Conductor) that routes the self-obs stream to `logs/agent-latest.jsonl`. Note `D:\dev\projects\conductor\scripts\agent-run.sh` passes it on `run` (line 70) but not on `boot` (line 48) — the live leg's lines are only agent-readable/pasteable if the operator exports the env term (per obs-plan.md §3 Logging stack — agent-mode flag).

## Anti-patterns to avoid
- NEVER make the raw `retrieve_report` / `retrieve_telemetry_slice` key-diff dump an unstructured stderr/stdout blob — every signal needs an agent-parseable, redacted consumption path (per obs-plan.md §11 Logs + §11 Universal).
- NEVER let an obs CI gate (§9 log-conformance, zero-unlogged-panics) acquire a live-Pulse dependency; those gates read CI artifacts only, and the live leg is operator-gated (per obs-plan.md §9).
- NEVER pass `ANDROMEDA_PULSE_DATA_DIR` via argv to the sidecar spawn (`.env(...)` builder only), and never let a malformed read-back panic — bounded decode + empty canary ⇒ `blocked`, never a false pass (per obs-plan.md §11 project-specific bans).

## Contract bindings
- **obs ↔ tests harness (test-plan §3 owns the envelope):** the 11-field Run-report envelope schema is owned by test-plan §3; obs-plan §3/§6 reproduce it and can drift. Any evidence row this chunk writes is checked against the owner, not the reproduction (per obs-plan.md §3 + §6 binding-contract notes).
- **obs ↔ CI (§9):** the shipped conformance gate asserts the §3 self-obs base schema over `logs/agent-latest.jsonl`; the envelope (`runs/<run_id>.jsonl`) gate is explicitly not built — so a live-run journal is not covered by the existing gate, and nothing here should change that (per obs-plan.md §9 Log conformance check).
- **obs ↔ security (Logging & Monitoring):** security's "no absolute host paths in run-report artifacts" ban is enforced by the same single-location `conductor-core::redact` allowlist + host-path scrub that redacts `data_dir` in the readiness envelope (per obs-plan.md §11 PII Scrubbing).

## Acceptance criteria contributions
- The live preflight's self-obs lines carry the §3 base set (`timestamp_ms`, `level`, `target`, `service.name`, `service.version`, `deployment.environment`, `run_id`), and the `verify.readback.preflight*` span materializes as real `span_event: new` / `close` lines (per obs-plan.md §3 Log format JSON schema).
- No absolute host path appears in any artifact this chunk writes — readiness envelope (`data_dir`), journal/`runs.db` row, and the appended `two-launch-verdict.md` arms (roles, not paths) — checked against the §9 host-path anchors (drive-letter, `/home`, `/Users`, `%APPDATA%`, `~/.cargo`, `.rustup`) (per obs-plan.md §9 Log conformance check).
- Every span attribute added for the live leg is a member of `conductor-core::redact::ALLOWLISTED_FIELDS`, and no span name outside the bounded set is introduced (per obs-plan.md §4 Required span attributes / §11 Spans / Traces).
- Zero unlogged panics across the live leg: unreachable sidecar, transport failure, or an unexpected live response yields a structured `warn`/`error` line plus `Ok(Blocked)` with its named precondition, and no `^thread.*panicked` line reaches stderr or `logs/agent-latest.jsonl` (per obs-plan.md §10 SLO Invariants).
