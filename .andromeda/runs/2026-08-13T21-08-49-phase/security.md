# security extract

## Relevance
Partial — no new attack surface is added, but this chunk exercises three shipped security boundaries live for the first time (sidecar spawn, trusted-child stdout read-back, preflight never-downgrade) and writes new operator-visible evidence artifacts that fall under artifact hygiene.

## Constraints
- The MCP sidecar must stay spawned as the fixed hard-coded program name resolved from PATH, with `ANDROMEDA_PULSE_DATA_DIR` passed strictly via the `.env(...)` builder and metacharacter-rejected before spawn — the live recipe's "export both env terms in the launching shell" must not become argv/shell interpolation or an operator-chosen command (per security-plan.md §Input Validation, `ANDROMEDA_PULSE_DATA_DIR` row; §Security Anti-Patterns → Input & Code Patterns).
- First live responses on the read-back path must stay inside the bounded-decode contract: recursion-limited/soft-size-bounded line-delimited JSON-RPC, faults mapped to `VerifyError::{JsonRpc,Decode,Transport}`, and an empty canary round-trip becoming `blocked` rather than a false pass-as-empty (per security-plan.md §Input Validation, MCP read-back child-stdout row; §Security Anti-Patterns → Input).
- Every arm that fails must surface as its own distinct named `blocked` precondition string among the FIVE (version mismatch / missing tool / canary fingerprint absent / app-sidecar workspace-key agreement / unmet run-contract terms) — never the generic corpus-empty string, never a silent downgrade to pass/fail/manual-check; SUT-side-truth terms record `declared-not-observable` and never block (per security-plan.md §Security Anti-Patterns → Universal).
- The `initialize` handshake must keep negotiating DOWN by reading the result's `protocolVersion` against the pinned `2024-11-05` manifest expectation; a live mismatch is `blocked`, never a silent downgrade and never a strict-newer client default (per security-plan.md §Input Validation, pinned MCP contract manifest row; §Security Anti-Patterns → Code Patterns).
- Live transport/child faults route through the verdict/error wall as `Result::Err` (harness fault) or `Ok(Blocked)`, never a panic — `tonic::Status` codes and JSON-RPC errors are typed verification inputs (per security-plan.md §Error Handling; §Security Anti-Patterns → Universal).
- New evidence surfaces (the appended `two-launch-verdict.md` arms, matrix `notes`, `<run_id>.md`, `runs.db` rows, JSONL journal, any dumped raw read-back result) must carry verdict/state/identity fields only — no absolute host paths (the real `ANDROMEDA_PULSE_DATA_DIR`, canonicalized `CONDUCTOR_*` dirs), no internal seam-crate struct/field names, no stack traces (per security-plan.md §Error Handling, Run-report artifact sanitization; §Security Anti-Patterns → Logging).
- The warm-up / `[incident_formation]` observable must be captured through MCP read-back only — Conductor production code (and any diagnostic step whose output lands in a committed artifact) must never open, copy, or persist Pulse's plaintext `corpus.db` content (per security-plan.md §Data Protection; §Security Anti-Patterns → Data Protection). This directly bounds the P4 open question "how it is captured without reading `corpus.db`".
- `cargo audit` is the thirteenth consecutive advisory-**DATABASE** fault (`duplicate advisory ID: RUSTSEC-2026-0244`, reproduced on the latest published 0.22.2): remedy is the bounded wait alone — re-run, record, and verify `cargo deny check advisories bans licenses sources` actually ran green against THIS chunk's lockfile state; never raise the floor, never add a `deny.toml` ignore, never edit CI (per security-plan.md §Dependency Security, two-fault split).

## Anti-patterns to avoid
- NEVER adjust `extract.rs`'s readers to match whatever the live response returned without recording the finding — and never let a degraded-to-empty read-back present as a measured green (per security-plan.md §Security Anti-Patterns → Input, empty canary ⇒ `blocked`, never false pass).
- NEVER paper over the audit fault: no floor raise, no `deny.toml` ignore, no CI edit, no silent accept for an advisory-DATABASE fault (per security-plan.md §Dependency Security; §Security Anti-Patterns → Universal).
- NEVER let a raw live-response dump, a probe arm record, or a hand-off note carry the absolute data-dir/host paths or corpus content into a committed file (per security-plan.md §Security Anti-Patterns → Logging & Data Protection).

- **Artifact hygiene ↔ obs**: the journal/`<run_id>.md`/`runs.db` field set and the readiness envelope's `data_dir` redaction are shared with obs's emission schema — the new live-run rows must not introduce host-path fields (security-plan.md §Error Handling ↔ obs journal/report schema).
- **Key-diff fixture ↔ tests**: if the live key agreement is frozen as a golden/fixture (P4 open question), the fixture must be a sanitized synthetic response — no real host paths, no corpus-derived content (security-plan.md §Data Protection + §Anti-Patterns → Logging ↔ tests fixtures).
- **Dependency gate ↔ tests §CI Integration**: the audit/deny re-run is a local pre-merge gate this chunk records; the chunk's own "Not a CI gate" boundary and the plan's "never a CI edit" remedy agree — no workflow change (security-plan.md §Dependency Security ↔ tests CI gate).
- **Pulse-side hand-off ↔ arch scope law**: a recorded defect hand-off may name the divergence and the observable, but must not carry Pulse source, corpus content, or host paths across the boundary (security-plan.md §Data Protection, corpus out-of-scope).
