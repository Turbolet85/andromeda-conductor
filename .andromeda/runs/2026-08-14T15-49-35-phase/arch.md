## Relevance
Relevant — the chunk sits squarely inside arch-owned surfaces (`conductor-emit`, OTLP egress to `127.0.0.1:4317`, the self-observation artifact, and the read-back contract's cross-process limits), and it surfaces one arch decision (`spawn.rs` setting a Pulse-side flag) without pre-empting it.

## Constraints
- The capture's subject — the exception-event + fingerprint primitive — lives in `conductor-emit`; the fingerprint PRIMITIVE is arch-placed there (not `conductor-faults`, which owns only the fingerprint-STORM fault), so any Conductor-side fix from this chunk lands in `conductor-emit` and crosses no new seam edge (per architecture.md §Infrastructure Patterns directory tree + §Established Decisions [Module Boundaries]; amendment 2026-06-18).
- Byte-level control of the OTLP payload is the whole reason raw `opentelemetry-proto` message structs were chosen over the SDK exporter — a capture of "what Conductor actually sent" must read those raw structs / the tonic wire, not re-derive intent from an SDK abstraction (per architecture.md §Established Decisions [OTLP Emission Strategy] + §Stack and Technologies).
- Read-back is NOT an available capture channel for in-flight spans: only the four persistent-corpus MCP tools work cross-process from a Conductor-spawned sidecar; `query_traces`/`query_metrics`/`query_logs`/`generate_snapshot` return empty because the sidecar shares no memory with `pulse-app` (per architecture.md §Standard Contracts, corrected-live note; §Established Decisions [Read-Back Dependency Posture]).
- Any capture that lands in the self-observation stream uses `tracing` 0.1.44 / `tracing-subscriber` 0.3.23 through the existing `init_observability` redaction layer and the existing artifacts (`logs/agent-latest.jsonl` in agent mode, sibling of the runs dir, moving with `CONDUCTOR_RUNS_DIR`) — this is NOT an OTel SDK surface, and OTLP stays the PRODUCT emission (per architecture.md §Stack and Technologies Self-observation row + §Occupied Resources On-disk artifacts).
- Trust boundary: Conductor opens no inbound listener — it is a gRPC/MCP client only, with the single deliberate exception of the port-occupier fault scenario. A capture channel must not become a listener, a second port, or an `:4318`/HTTP surface (per architecture.md §Cross-cutting Patterns Trust boundary + §Occupied Resources Ports).
- Any new configuration handle for the capture must sit inside the reserved `CONDUCTOR_*` namespace; the `ANDROMEDA_PULSE_*` vars are Pulse-side and asserted **not set by Conductor** — `ANDROMEDA_PULSE_DATA_DIR` is the sole exception (propagated to the spawned sidecar), which is exactly why the chunk's `spawn.rs` / `ANDROMEDA_PULSE_MCP_ENABLED` question is a live arch decision and not a free implementation choice (per architecture.md §Occupied Resources Environment variables + §Cross-cutting Patterns Config management).
- Outcome-vs-fault wall: a settled "spans arrived intact" / "did not arrive" answer is an outcome recorded as a value; `Result::Err` stays reserved for Conductor's own harness faults (transport refused, config parse), so a capture failure must not be reported as a verification verdict and vice-versa (per architecture.md §Design Philosophy + §Cross-cutting Patterns Verdict/error wall).

## Patterns to follow
- **Journal-relative, file-artifact ground truth** — the settling artifact should be an on-disk, agent-parseable file (JSONL / kebab-case Markdown under the chunk or runs dir), consistent with "file artifacts are the agent-parseable ground truth and the SQLite index is a thin convenience layer over them" (architecture.md §Design Philosophy, §Occupied Resources On-disk artifacts).
- **Host-path-free artifacts** — the readiness gate's precondition strings are already host-path-free with `data_dir` redacted; the capture artifact inherits that same hygiene (architecture.md §Standard Contracts Readiness gate).
- **Transcribed-SUT-record vs Conductor-measurement labeling** — the `contracts/*.toml` manifests each carry a `provenance` field stating whether a term is a transcribed SUT record or a Conductor measurement. A capture that includes any Pulse-side observation should mark it the same way, so the hand-off (if the answer lands Pulse-side) says how far a reader can trust each line (architecture.md §Occupied Resources `pulse-load-envelope.toml` / `pulse-run-contract.toml`).
- **Check-kind honesty (`shell-declaration` / `asserted` / `declared-not-observable`)** — the run contract's precedent for "what Conductor can honestly know" applies directly to the fork: a claim about Pulse's appender is only `declared-not-observable` unless the capture actually observes it, and never a claimed measurement (architecture.md §Occupied Resources `contracts/pulse-run-contract.toml`).
- **Headless-first, agent-driven** — the settling run goes through the headless `scripts/agent-run.{sh,ps1}` path (the source of truth and release gate); the Tauri GUI is not a proof surface (architecture.md §Design Philosophy, §Cross-cutting Patterns Development Style).
- **New audit-green dep → §Stack row** — if a capture tool needs a new crate, the established flow is a `[workspace.dependencies]` addition with `cargo audit` + `cargo deny` green plus a §Stack registration at wrap (architecture.md §Infrastructure Patterns Build system; the serde_json / toml / clap / owo-colors precedent chain in the amendment history).

## Anti-patterns to avoid
- Do NOT add an inbound listener, a proxy port, `:4318`, or any HTTP surface to observe the wire — Conductor exposes no network service of its own and binds a port only in the port-occupier fault scenario (architecture.md §Established Decisions [Backend Framework], §Occupied Resources Ports).
- Do NOT have Conductor set `ANDROMEDA_PULSE_MCP_ENABLED` (or any other Pulse-side flag) inside `spawn.rs` as an unrecorded implementation convenience — §Occupied Resources currently asserts Conductor does not set it; only `ANDROMEDA_PULSE_DATA_DIR` is propagated. Changing that is an amendable arch decision requiring an explicit operator ratification, not a code-local choice.
- Do NOT route the capture around the self-observation redaction layer / field allowlist, and do NOT persist or copy Pulse's `corpus.db` — it is SUT-owned data Conductor never persists or exfiltrates (architecture.md §Standard Contracts corpus access; §Cross-cutting Patterns Trust boundary).
- Do NOT introduce an OTel SDK or `opentelemetry-otlp` exporter to gain span visibility — self-observation is `tracing`-only and OTLP stays hand-built raw types (architecture.md §Stack and Technologies Self-observation row + §Established Decisions [OTLP Emission Strategy]).

## Contract bindings
- **Standard Contracts readiness gate ↔ verify/security/obs** — the gate's FIVE named preconditions and the host-path-free / `data_dir`-redacted rule bound any preflight-adjacent capture output; obs owns the redaction processor stage, security owns the input/spawn boundary (architecture.md §Standard Contracts; §Occupied Resources).
- **`logs/agent-latest.jsonl` artifact ↔ obs-plan §3** — arch registers the artifact, path-resolution (sibling of runs dir, moves with `CONDUCTOR_RUNS_DIR`), and per-invocation truncation; the field allowlist and redaction stage are obs-plan's (architecture.md §Occupied Resources On-disk artifacts).
- **Crate-name registry ↔ all domains** — `conductor-emit` / `conductor-verify` / `conductor-run` are the LOCKED names any other plan's content must use (architecture.md §Occupied Resources Crate names).
- **`ANDROMEDA_PULSE_MCP_ENABLED` spawn question ↔ security-plan (subprocess hardening) + the operator recipe** — the open design question the scope surfaces touches arch's env-var assertion AND the hardened `.env(...)` spawn pattern security owns (architecture.md §Occupied Resources Environment variables + Service/process names).
- **`cargo audit` / `cargo deny` re-check (carried PREREQ) ↔ security-plan §Dependency Security** — arch §Infrastructure Patterns names the gates and the justified `deny.toml` exceptions; the advisory-database policy and floor decisions are security's (architecture.md §Infrastructure Patterns Build system).

## Acceptance criteria contributions
- (arch) Any Conductor-side fix lands in `conductor-emit` (the exception-event + fingerprint primitive's owning seam) and adds no forbidden cross-seam `Cargo.toml` edge — a violation must fail to compile (per architecture.md §Established Decisions [Module Boundaries] + §Infrastructure Patterns directory tree).
- (arch) The capture opens no inbound listener, binds no port, and adds no HTTP/`:4318` surface; Conductor's only outbound surfaces stay OTLP/gRPC egress to `127.0.0.1:4317` and the MCP stdio session (per architecture.md §Cross-cutting Patterns Trust boundary + §Occupied Resources Ports).
- (arch) The capture artifact is host-path-free (no `data_dir`, no host paths), carries no `corpus.db` content, and — if written into the self-obs stream — flows through the existing `tracing` sink and redaction layer rather than a bypass (per architecture.md §Standard Contracts Readiness gate + §Occupied Resources On-disk artifacts).
- (arch) No new env var outside the reserved `CONDUCTOR_*` namespace, and `ANDROMEDA_PULSE_MCP_ENABLED` remains unset-by-Conductor unless the surfaced decision is explicitly ratified and amended (per architecture.md §Occupied Resources Environment variables).
