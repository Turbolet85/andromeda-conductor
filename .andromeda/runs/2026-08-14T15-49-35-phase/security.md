# security extract

## Relevance
Relevant — the chunk adds a new capture/observation path on the OTLP egress wire, writes a new evidence artifact, and carries the standing dependency-audit deferral; all four are live security surfaces even though no auth/PII/secret is involved.

## Constraints
- The capture channel MUST NOT open an inbound listener of Conductor's own; the `:4317` port-occupier bind in `conductor-faults` is the *single* deliberate exception and must not be generalized into a capture proxy or tap that accepts input (per security-plan §Security Anti-Patterns → Universal + § API; §Threat Model Summary "Vector (single deliberate exception)"). Scope.md's own scope-law line is the same rule.
- The capture artifact is agent-parseable ground truth shared across hosts: it may carry verdict/state/identity fields but MUST NOT leak absolute host paths (canonicalized `CONDUCTOR_RUNS_DIR`/`CONDUCTOR_SCENARIOS_DIR`, `ANDROMEDA_PULSE_DATA_DIR`) or internal seam-crate struct/field names (per security-plan §Error Handling "Run-report artifact sanitization"; §Security Anti-Patterns → Logging).
- Any new decode of the emitted payload (OTLP protobuf on the wire, or JSON-RPC read-back lines) MUST be recursion- and size-bounded and MUST NOT panic — malformed input becomes a typed value through the verdict/error wall (`VerifyError::{JsonRpc,Decode,Transport}` / `tonic::Status` as first-class inputs), never an abort (per security-plan §Input Validation, MCP-read-back-child-stdout row; §Security Anti-Patterns → Input, protobuf-decode DoS lineage; §Universal "NEVER let a malformed child/transport input panic").
- If the capture writes anywhere under the runs tree, the path MUST derive from the canonicalized + bounds-checked `CONDUCTOR_RUNS_DIR` through the shipped `resolve_under` traversal guard — no new operator-steerable path handle, and no new `CONDUCTOR_*` override for fixed-path contract artifacts (per security-plan §Input Validation, env-var-path-handles row + committed-SUT-facing-manifests row).
- The sidecar spawn discipline is untouched by this chunk and must stay that way: fixed hard-coded `andromeda-pulse-mcp` program path, `ANDROMEDA_PULSE_DATA_DIR` passed only via the `.env(...)` builder with metacharacters rejected, never interpolated into argv/shell (per security-plan §Security Anti-Patterns → Input + Code Patterns; §Security Decisions Log key decision). The scope's "open design question" (should `spawn.rs` set `ANDROMEDA_PULSE_MCP_ENABLED` itself) is an arch/ownership decision, not a security relaxation — inheritance-from-Conductor's-own-environment is the recorded channel (per §Threat Model Summary → Auth model, Reason).
- Conductor's production code MUST NOT open, copy, or read Pulse's `corpus.db` directly to answer the discriminator — corpus access is MCP read-back only, and no corpus content is persisted into Conductor artifacts (per security-plan §Data Protection; §Security Anti-Patterns → Data Protection). Scope.md's observation that the corpus has no span table must not become a reason to reach into it.
- The `cargo audit` PREREQ re-check is governed as an advisory-DATABASE fault, not a tool fault: bounded wait — re-run literally, record the result, and verify `cargo deny check advisories bans licenses sources` actually ran green as the overlapping signal. Never raise the floor, never add a `deny.toml` ignore, never edit CI (per security-plan §Dependency Security, two-fault split).

## Patterns to follow
- Artifact-path derivation via `resolve_under` from `CONDUCTOR_RUNS_DIR` — the same guard the agent-mode `logs/agent-latest.jsonl` sink already uses (per security-plan §Input Validation, non-path env-handle paragraph).
- Read/IO faults surfaced with `e.kind()` only, never the path — the established pattern for the committed contract manifests (per security-plan §Input Validation, committed-SUT-facing-manifests row).
- Module-internal `thiserror` typed enums collapsing to `anyhow` only at the `conductor-cli` edge; verification outcomes stay `Ok(value)` and `Result::Err` is reserved for harness faults (per security-plan §Error Handling).
- Bounded line-delimited JSON-RPC decoding in `conductor-verify/src/jsonrpc.rs` as the model for any new bounded parse on the capture path (per security-plan §Input Validation, MCP-read-back row).
- Wall-clock stamps on any capture record come from `std::time::SystemTime`/`Instant`, never tokio's virtual clock (per security-plan §Security Anti-Patterns → Logging).

## Anti-patterns to avoid
- Never turn the capture into an inbound listener / interception proxy on `127.0.0.1:4317`, and never promote the fault-scenario bind into a general-purpose listener (per security-plan §Security Anti-Patterns → Universal + API).
- Never emit absolute host paths, stack traces, or internal struct names into the capture artifact or operator stderr — sanitize at the `anyhow`/artifact edge (per security-plan §Security Anti-Patterns → Logging).
- Never silently downgrade a failed preflight: the canary-fingerprint-absent arm is one of the FIVE named `blocked` preconditions and must carry its own distinct precondition string, never a false pass and never the generic corpus-empty string (per security-plan §Security Anti-Patterns → Universal).

## Contract bindings
- **obs** — the capture rides the existing self-observation `tracing` JSON surface (`logs/agent-latest.jsonl`); security's artifact-hygiene rule (no host paths, no internal struct names) is the artifact-edge expression of obs's redaction boundary + field allowlist. Any new capture field must go through the obs allowlist rather than around it (scope.md "Self-observation" surface; security-plan §Error Handling).
- **tests** — the `cargo audit` + `cargo deny` gate belongs in the one existing GitHub Actions workflow as a job, not a separate pipeline; the PREREQ re-check result must be recorded as a gate outcome (security-plan §Dependency Security → CI integration).
- **arch** — the capture-channel choice is arch/P3-P4's call, but it is bounded by the trust-boundary/scope-law constraint above and by the recorded fact that the four live-buffer MCP tools cannot serve as the channel (scope.md `conductor-verify` read-back bullet).

## Acceptance criteria contributions
- (security) `cargo audit` re-run **literally** this chunk with its result recorded, and `cargo deny check advisories bans licenses sources` verified green as the overlapping signal — with no floor raise, no `deny.toml` ignore, and no CI edit; deferral closes the moment the advisory DB parses (per security-plan §Dependency Security).
- (security) the capture artifact and any new operator-visible output contain no absolute host paths (repo root, `CONDUCTOR_*` canonicalized dirs, `ANDROMEDA_PULSE_DATA_DIR`) and no internal seam-crate struct/field names — grep-verifiable on the produced artifact (per security-plan §Error Handling, run-report artifact sanitization + §Security Anti-Patterns → Logging).
- (security) no new bind/listen socket is introduced: the diff adds no `TcpListener`/`UdpSocket` bind outside the existing `conductor-faults` port-occupier (per security-plan §Security Anti-Patterns → Universal).
- (security) any new decode path on the capture is size/recursion-bounded and non-panicking, routing malformed input through a typed error to the verdict/error wall; if a new crate is added, `Cargo.lock` is committed and un-drifted (per security-plan §Security Anti-Patterns → Input + §Universal).
