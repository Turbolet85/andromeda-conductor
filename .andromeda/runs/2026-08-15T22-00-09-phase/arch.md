## Constraints
- The changed constant lives in `conductor-run`, the run composition-root library (preflight + `execute_scenario` + `persist` + `drive_run`) sitting above the seams and below both bins — a LOCKED workspace member name; the change must not move logic across a seam boundary or add a cross-seam dependency edge, since crate edges *are* the architecture and a forbidden edge will not compile (per architecture.md §Occupied Resources — Crate names, §Established Decisions [Module Boundaries]).
- The preflight readiness gate is a Standard Contract with a fixed conceptual result shape (`ready` · `negotiated_protocol_version` · `expected_protocol_version` · `required_tools` · `data_dir` · `canary_round_trip` · `blocked_precondition` · `checked_at`) and exactly FIVE named preconditions, ordered with the run-contract arm after tool checks and before the canary arms; raising the canary count must not add, remove, or reorder a precondition (per architecture.md §Standard Contracts — Readiness gate; the scope's own boundary "no new preflight preconditions" agrees).
- Every precondition string is host-path-free (`data_dir` redacted) and a blocked row populates only identity fields (`run_id`, `seed`, `scenario`, `p_ids`, `slo_tier`) with `verdict`/timestamps/`latency_ms`/`fingerprints` as JSON `null` — a raised-count leg that still blocks must preserve that shape (per architecture.md §Standard Contracts — Readiness gate).
- The verdict/error wall applies: a canary that does not form an incident is a report *state* (`Blocked`) carried as a value, never a `Result::Err`; `Err` stays reserved for harness faults (transport down, MCP unreachable, config parse) (per architecture.md §Established Decisions [Error Handling], §Cross-cutting Patterns — Verdict/error wall).
- Determinism discipline binds the storm's timing basis: journal/wall-clock stamps come from `std::time::SystemTime`/`Instant`, never tokio's virtual clock, and the engine runs `current_thread` with zero work-stealing — so whether the raised occurrence count lands inside Pulse's single 30s detection sub-window is a property of the emit path's actual pacing, not an assumed one (per architecture.md §Cross-cutting Patterns — Determinism discipline, §Established Decisions [Async Runtime Flavor]).
- The live leg is an operator/local gate, never a CI gate — CI has no Pulse instance, so dynamic end-to-end scenario proof stays outside `cargo build`/nextest/clippy gating (per architecture.md §Established Decisions [CI/CD], §Infrastructure Patterns — CI/CD approach).
- No new `CONDUCTOR_*` env handle is warranted for the margin: the constant is code, and the run contract's `[incident_formation]` poll floor already governs the canary budget through `CONDUCTOR_PREFLIGHT_TIMEOUT` (which may only override upward) (per architecture.md §Occupied Resources — Environment variables).
- The load envelope's asserted terms (`max_sustained_storm_ms` + `max_sustained_rate_spans_per_s`) are judged **per emitting phase** with `check_load_envelope` and `LoadEnvelope::classify` reading ONE shared basis, and the `[[exempt]]` ledger is held at exact-set equality in both directions while EMPTY — whether the preflight canary is inside or outside that basis is research's question, not something this extract can attest (per architecture.md §Occupied Resources — `contracts/pulse-load-envelope.toml`).

## Patterns to follow
- Emission goes out via `conductor-emit`'s raw opentelemetry-proto types over tonic to `127.0.0.1:4317` — the canary storm reuses the existing fingerprint primitive + exception-event builder rather than introducing a new emit path (per architecture.md §Conventions — Outbound emission, §Infrastructure Patterns directory tree).
- The fidelity carrier for the canary round-trip is `retrieve_telemetry_slice.fingerprint_refs` (Pulse scrubs incident titles), read back over the hand-rolled line-delimited JSON-RPC client in `conductor-verify` returning raw `serde_json::Value` (per architecture.md §Standard Contracts — Readiness gate, §Established Decisions [MCP Read-Back Client]).
- SUT-side facts that Conductor must respect but cannot measure belong in a `contracts/*.toml` pinned manifest with a `provenance` field stating they are a transcribed SUT record — the precedent for how a Pulse-side threshold like `DEFAULT_AUTONOMOUS_THRESHOLD` would be recorded if it were data rather than a constant (per architecture.md §Occupied Resources — `contracts/pulse-run-contract.toml`, `pulse-load-envelope.toml`).
- Conductor is a client with no inbound listener; the only deliberate exception is the port-occupier fault scenario. The canary raise adds no listener and no new outbound surface (per architecture.md §Cross-cutting Patterns — Trust boundary).
- Headless `scripts/agent-run.{sh,ps1}` is the source of truth and the release gate; the GUI is convenience. The live leg's evidence path is the headless `boot`/`preflight` invocation (per architecture.md §Design Philosophy — Headless-drivable core, §Cross-cutting Patterns — Development Style).

## Anti-patterns to avoid
- Do not encode the raised count as a new `CONDUCTOR_*` env var, CLI flag, or scenario-config field — configuration handles are reserved for artifacts and concepts arch already defines, and the canary is not a scenario (per architecture.md §Occupied Resources — Environment variables, §Cross-cutting Patterns — Config management).
- Do not let a live leg that fails to reach `ready:true` be downgraded to pass/fail/manual-check or surfaced as `Result::Err` — dependent scenarios report `blocked` with the named precondition, a distinct state (per architecture.md §Established Decisions [Read-Back Dependency Posture]).
- Do not make the live leg a CI gate or add retries to mask a flaky canary — the nextest `ci` profile is zero-retry precisely because retries mask flakes against the determinism invariant (per architecture.md §Infrastructure Patterns — Build system).
