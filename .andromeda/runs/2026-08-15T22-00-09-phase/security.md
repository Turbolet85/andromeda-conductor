## Constraints
- The PREREQ audit re-check must be resolved under the **two-fault split**: a byte-identical `duplicate advisory ID: RUSTSEC-2026-0244` on a tool at/above the floor is an **advisory-DATABASE fault**, whose only sanctioned remedy is a bounded wait plus keeping coverage via the audit↔deny overlap **verified** green (`cargo deny check advisories bans licenses sources` actually run, not assumed) — never a floor raise, never a `deny.toml` ignore, never a CI edit (per security-plan §Dependency Security).
- `Cargo.lock` must stay committed and drift-free, and the release gate must not run/merge without the dependency audit control satisfied — the audit gate IS the Minimal-tier residual-risk control for the `bundled`-SQLite-from-C + OTLP/gRPC tree (per security-plan §Security Anti-Patterns → Universal).
- The live leg must never silently downgrade a failed preflight: each of the gate's **five named preconditions** (version mismatch / missing tool / canary fingerprint absent / app-sidecar workspace-key agreement / unmet run-contract terms) must surface as the distinct `blocked` state with its own named precondition string — never a false pass, never the generic corpus-empty string. A leg that does not reach `ready:true` is a `blocked` result, which is exactly the operator directive's "recorded, never stretched" (per security-plan §Security Anti-Patterns → Universal).
- The leg's **fresh data dir** flows through the sidecar-spawn boundary: `ANDROMEDA_PULSE_DATA_DIR` must be validated for argument-injection metacharacters before spawn and passed strictly via the `.env(...)` builder, never interpolated into argv or a shell; the sidecar must be spawned as a fixed hard-coded program, not an operator-chosen command (per security-plan §Input Validation, env-propagation row; §Security Anti-Patterns → Input + Code Patterns). Whether `spawn.rs` already performs the metacharacter rejection and uses a fixed program path (vs. bare PATH lookup of an operator-placed binary, which host-precondition 1 implies) is research's question.
- The raised canary storm is read back over the trusted-child stdout boundary, which requires bounded line-delimited JSON-RPC decoding (recursion-limited + soft per-line size bound), JSON-RPC/decode/transport faults mapped to typed `VerifyError` variants and never panics, and an **empty canary round-trip ⇒ `blocked`, never a false pass-as-empty** (per security-plan §Input Validation, MCP read-back child-stdout row; §Security Anti-Patterns → Input + Universal).
- Evidence produced by the leg — the run report `<run_id>.md`, `runs.db` rows, JSONL journals, and the two verdict-doc closure appends — must carry verdict/state/identity fields only, with **no absolute host paths** (the fresh `ANDROMEDA_PULSE_DATA_DIR`, canonicalized `CONDUCTOR_*` dirs) and no internal seam-crate struct/field names (per security-plan §Error Handling, run-report artifact sanitization; §Security Anti-Patterns → Logging).
- Host precondition 4 (poll budget) sits on the committed-manifest input boundary: `contracts/pulse-run-contract.toml` terms are never defaulted and never silently widened, and a lowered `CONDUCTOR_PREFLIGHT_TIMEOUT` must clamp **up** to the contract floor, not down — the budget comes from the validated fixed-path contract, not an operator-steerable env handle (per security-plan §Input Validation, committed SUT-facing manifests row).

## Patterns to follow
- Fault-class discrimination before remedy on the audit gate: name whether the red is a TOOL fault or an advisory-DATABASE fault, then apply that class's remedy only; the deliberate audit↔deny **overlap** is the standing coverage mechanism while the DB fault persists (per security-plan §Dependency Security).
- Env-handle classification: *path* handles canonicalize + bounds-check through `resolve_under` at the CLI edge; *declaration-only* / non-path handles (`ANDROMEDA_PULSE_L4_DETERMINISTIC`, `CONDUCTOR_SERVICE_NAME`/`CONDUCTOR_ENV`/`CONDUCTOR_AGENT_MODE`) require no validation because their values never become a path, argv element, or log value — the leg's recipe exports both classes, so treat them differently (per security-plan §Input Validation).
- The verdict/error wall: `Result::Err` strictly for harness faults (transport down, MCP unreachable, config parse); verification outcomes stay typed values returned as `Ok(Verdict/ReportState)`; `tonic::Status` codes and MCP error responses are first-class typed inputs, never panics (per security-plan §Error Handling).
- The `blocked` row shape: identity fields plus the named precondition string, measurement fields JSON `null` — this is the shape a non-`ready:true` leg must produce (per security-plan §Error Handling, run-report artifact sanitization).
- The `deny.toml` accepted-exceptions mechanism (RUSTSEC-2025-0119 `number_prefix` ignore; `Zlib` license allow) is the documented home for *non-actionable* advisories and must be left untouched here — it is not the remedy for a DB parse fault (per security-plan §Dependency Security, Accepted exceptions).

## Anti-patterns to avoid
- Papering over the audit red: no floor raise, no new `deny.toml` ignore for RUSTSEC-2026-0244, no CI workflow edit, no silent accept (per security-plan §Dependency Security; §Security Anti-Patterns → Universal).
- Leaking absolute host paths, stack traces, or internal struct names into the leg's stderr, run-report artifacts, or the appended verdict-doc closures — including the fresh data-dir path and the Pulse repo root (per security-plan §Security Anti-Patterns → Logging).
- Building the sidecar invocation from operator-supplied strings — no shell/`eval` spawn, no config-into-argv, no operator-chosen program (per security-plan §Security Anti-Patterns → Code Patterns).

## Contract bindings
- **Dependency gate ↔ tests §CI Integration:** the audit/deny gate is a job in the single CI workflow; this chunk's remedy explicitly excludes touching that workflow, so the binding is "record the result, leave the gate definition alone" (per security-plan §Dependency Security, CI integration).
- **Artifact sanitization ↔ obs (journal/report emission) + tests (fixtures):** the no-absolute-paths / no-internal-struct-names rule is enforced where obs writes the journal and report; test fixtures and the verdict-doc closures must carry no real host paths (per security-plan §Error Handling; §Security Anti-Patterns → Logging).
- **`blocked` precondition strings ↔ arch Standard Contracts readiness gate:** the five named preconditions are the arch's gate; security only bans downgrading them. The chunk states it adds no new preconditions, so this binding is a no-widening check (per security-plan §Security Anti-Patterns → Universal).
