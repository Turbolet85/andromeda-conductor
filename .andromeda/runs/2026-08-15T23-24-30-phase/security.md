# security extract

## Relevance
Partial — no new external-input boundary, dependency, secret, or auth surface; the security stake is the standing `cargo audit` deferral (20th pin), the preflight never-downgrade ban, and artifact/error sanitization on the re-run leg.

## Constraints
- The `cargo audit` deferral carried by this chunk is an **advisory-DATABASE fault**, not a tool fault: the remedy is a bounded re-check each chunk with the audit↔deny overlap **verified** green (`cargo deny check advisories bans licenses sources`, true exit 0 across all four classes, never assumed) — never a floor raise, never a `deny.toml` ignore, never a CI edit, never a silent accept (per security-plan §Dependency Security, two-fault split). Whether the DB now parses is research's question; close the deferral the moment it does.
- Any change to the canary emit path must keep `Cargo.lock` committed and un-drifted; a red or skipped audit/deny gate blocks the release-gate path (per security-plan §Security Anti-Patterns → Universal, "NEVER run `cargo build --release` … without cargo-audit green" + "NEVER let `Cargo.lock` drift").
- If the canary's span shape change alters what the preflight gate asserts (`crates/conductor-verify/`), each of the gate's FIVE named preconditions (version mismatch / missing tool / canary fingerprint absent / app-sidecar workspace-key agreement / unmet run-contract terms) must still surface as the distinct `blocked` state with its own named precondition string — never a false pass, never the generic corpus-empty string (per security-plan §Security Anti-Patterns → Universal, never-downgrade ban). An empty canary round-trip MUST become `blocked`, never a false pass-as-empty (per §Security Anti-Patterns → Input).
- The read-back path must not panic on malformed child/transport input: JSON-RPC errors, decode faults, and `tonic::Status` codes stay first-class typed inputs through the verdict/error wall (`VerifyError::{JsonRpc,Decode,Transport}`), with `Result::Err` reserved for harness faults (per security-plan §Error Handling; §Input Validation, MCP read-back child stdout row; §Security Anti-Patterns → Universal).
- Live-leg evidence and run artifacts (`<run_id>.md`, `runs.db` rows, JSONL journals) must record verdict/state/identity fields without leaking absolute host paths (canonicalized `CONDUCTOR_*` dirs, `ANDROMEDA_PULSE_DATA_DIR`) or internal seam-crate struct names — including any new diagnostic output added to discriminate the two leads (per security-plan §Error Handling, run-report artifact sanitization; §Security Anti-Patterns → Logging).
- The sidecar spawn contract is unchanged and must stay so: fixed hard-coded program path, `ANDROMEDA_PULSE_DATA_DIR` strictly via the `.env(...)` builder with metacharacters rejected first, never interpolated into argv or a shell (per security-plan §Input Validation, `ANDROMEDA_PULSE_DATA_DIR` row; §Security Anti-Patterns → Input/Code Patterns).
- Pulse's repo and `corpus.db` stay read-only/out-of-scope: Conductor's production code must reach corpus content via MCP read-back only, never directly open/copy/exfiltrate it, and never persist its content into Conductor artifacts (per security-plan §Data Protection; §Security Anti-Patterns → Data Protection). This aligns with the chunk's own Pulse-READ-ONLY boundary.
- Journal/report wall-clock stamps on the re-run leg must come from `std::time::SystemTime`/`Instant`, not tokio's virtual clock (per security-plan §Security Anti-Patterns → Logging).

## Patterns to follow
- The verdict/error wall: typed `thiserror` enums inside seam crates, collapsed to `anyhow` only at the `conductor-cli` / `#[tauri::command]` edges; verification outcomes returned as `Ok(Verdict/ReportState)` values (per security-plan §Error Handling).
- `e.kind()`-only read faults for fixed-path committed manifests (`contracts/pulse-*.toml`), resolved via `default_path()` → `resolve_under` with deliberately no `CONDUCTOR_*` override — the pattern to reuse if the canary path gains any contract-derived term (per security-plan §Input Validation, committed SUT-facing manifests row).
- Bounded decoding on the trusted-child stdout boundary (recursion-limited serde_json + soft per-line size bound, no unbounded read) — the shipped pattern any canary read-back assertion should ride on (per security-plan §Input Validation, MCP read-back child stdout row).
- garde `dive`, never `skip`, on nested spec structs if any scenario/emission struct is touched while chasing shape differences (per security-plan §Input Validation, scenario-config row).
- The deny.toml accepted-exceptions mechanism (justifying comment per entry) as the only sanctioned suppression channel — and it does **not** apply to the current DB-parse fault (per security-plan §Dependency Security, Accepted exceptions).

## Anti-patterns to avoid
- Never silently downgrade a failed preflight to pass / fail / manual-check, and never claim `ready:true` on an argument rather than a measured leg (per security-plan §Security Anti-Patterns → Universal).
- Never suppress the red `cargo audit` with a `deny.toml` ignore, a CI edit, or an unexecutable floor raise for the advisory-DB fault (per security-plan §Dependency Security + §Security Anti-Patterns → Universal).
- Never let malformed canary/read-back input panic, and never leak absolute paths or internal struct names into stderr or the run-report artifacts while adding diagnostics (per security-plan §Security Anti-Patterns → Universal + Logging).
