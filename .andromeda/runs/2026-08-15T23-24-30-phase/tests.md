# tests extract

## Relevance
Relevant — the chunk edits a test file directly (`crates/conductor-run/tests/canary_wire.rs`), changes the OTLP wire shape the wire/golden tier locks, and re-runs the `boot` preflight live leg that test-plan §3 owns.

## Constraints
- Test tier is **Minimal (0)** (per test-plan §1) — expected breadth is the per-seam unit bulk plus the already-registered integration mechanisms; this chunk adds no new tier escalation.
- `conductor-emit` is classified **partially-testable**: OTLP struct construction + byte-level encoding are unit-assertable in isolation, while the actual gRPC egress to a live Pulse ingest listener is **local-gate-only, not CI** (per test-plan §1 Testable entities, `conductor-emit`). The Conductor-side correction must therefore be provable at the wire/struct tier, with Pulse's enumeration proven only on the local leg.
- `boot` = preflight readiness gate; readiness signal is stdout `{"ready": true}`, and `ready:false` must make every dependent scenario report `state="Blocked"` with the named precondition string — **never a silent downgrade** to pass/fail/manual-check (per test-plan §3 5-command implementation → `boot`). This is the gate the chunk's step 5 (`v2-10`) hinges on.
- The `boot` timeout is **two derived budgets, never a literal**: the in-process canary poll (`CONDUCTOR_PREFLIGHT_TIMEOUT`, clamped up to `contracts/pulse-run-contract.toml` `[incident_formation].min_canary_poll_seconds`) and the `scripts/agent-run.{sh,ps1}` wall-clock wrapper derived per invocation as `warmup_ms/1000 + poll + margin`; a missing contract term is a hard exit 2 (per test-plan §3 → `boot` Timeout). Any re-run of the live leg must honour both.
- An **empty or malformed canary round-trip must become `blocked`, never a false pass-as-empty** (per test-plan §1 Coverage triggers, security-vector Vector 4(c); reasserted in §5 `query_incident_list` boundary). The chunk's measured zero-enumeration outcome is exactly this class.
- The **live-Pulse leg is an operator/local gate** via `workflow_dispatch` or `scripts/agent-run.sh`, explicitly **NOT a CI gate**; CI runs the rmcp-stub / loopback-stub legs only (per test-plan §9 Live-Pulse scenarios).
- Quality gates are binding and unlowerable: `--fail-under-lines 60`, zero-flakiness (nextest `retries` must stay 0 — a flake is a determinism break, not a retry budget), clippy `-D warnings`, and `cargo audit --deny warnings` + `cargo deny check` green with un-drifted `Cargo.lock` (per test-plan §10 Quality Gates). The chunk's carried 20th `cargo audit` pin lands against this gate; whether the advisory-DB fault still blocks it is research's question.

## Patterns to follow
- **Loopback OTLP-egress gRPC stub** — a tonic `TraceService` server over `tokio-stream::wrappers::TcpListenerStream` on an ephemeral `127.0.0.1:0`, registered as the integration-row mechanism for byte-level egress assertions and explicitly never binding the real `:4317` (per test-plan §2 test-pyramid Integration row; §8 Mocking table). Whether `canary_wire.rs` today uses this stub or a different in-crate collector is research's question.
- **Seeded stream goldens** — committed per-crate under `<crate>/tests/snapshots/`, one file per test-file family × seed, with the `dispatch_wire__*` family covering the dispatched-wire projection; stream goldens have no wall-clock field to redact because the projection **excludes** every `*_time_unix_nano` rather than masking it, and CI is fail-don't-write (never `cargo insta review`) (per test-plan §7 Seed strategies → Golden artifacts).
- **Per-seam crate-local layout** — `#[cfg(test)] mod tests` inside each `conductor-<seam>` source file plus crate-local `tests/` for in-crate integration, run per-seam via `cargo nextest run -p conductor-<seam>` (per test-plan §2 Test directory conventions; §4 Conventions).
- **rmcp stub for the preflight/verdict leg** — in-process duplex transport for verdict logic, `TokioChildProcess` test-binary for the spawn/`.env()` path; the pinned-manifest tool-set + `2024-11-05` negotiation contract assertions live here (per test-plan §5 Cross-module patterns; §8 Mocking table).
- **cli E2E driver** — `assert_cmd` `Command::cargo_bin("conductor")` under an `assert_fs::TempDir` sandbox wired via `CONDUCTOR_RUNS_DIR`, asserting exit code + the closed bracket-label set + `runs.db` row + JSONL journal, stdin closed (per test-plan §6 Drivers per surface, cli row).

## Anti-patterns to avoid
- **NEVER fake Pulse's reaction as a CI verdict** — the stub/own-collector canary proves wiring and emission shape only; Pulse's actual behaviour is a live/local-gate assertion (per test-plan §11 Test Strategy). A green `canary_wire.rs` against Conductor's own collector therefore cannot substitute for the chunk's live-leg proof, which is precisely the LEAD-B failure mode the scope names.
- **NEVER treat `Blocked`/`ManualCheck`/`KnownResidual`/`CalibrationRegion` as a non-zero process exit** — those are reported envelope states, not hard `Fail` exits (per test-plan §11 E2E). An un-`ready:true` preflight must record `Blocked`, not be re-coded as a failure or a pass.
- **NEVER introduce an inbound listener of Conductor's own** (the `:4317` port-occupier is the sole deliberate bind, and it must release on cleanup) and **never use real network in tests** beyond loopback stubs (per test-plan §11 Universal, project-specific + CI bans).

## Contract bindings
- **tests §3 Log format ↔ obs-plan §3** — test-plan §3 is the declared SOURCE OF TRUTH for the JSONL format and obs derives from it; the self-obs stream (`logs/agent-latest.jsonl`, `logs/conductor-tauri.jsonl`) is a **distinct artifact** from the per-run emission journal (`runs/<run_id>.jsonl`, the SLO ground truth + Run-report envelope) and the two schemas must not be conflated (per test-plan §3 "Self-obs stream is a distinct artifact"). If this chunk adds or changes a wire-shape witness line (the `emit.batch`-class `debug` event line), §3 and obs-plan §3 move in lockstep; the field allowlist / redaction layer is obs's half, asserted here by a negative test.
- **tests §3 `boot` ↔ arch Standard Contracts / `contracts/pulse-run-contract.toml`** — the preflight handshake assertions (protocol `2024-11-05`, required-tool set vs. the pinned `contracts/` manifest, canary round-trip) and both derived timeout budgets read from the run contract; a missing term is exit 2, not a default.
- **tests §1 trigger / §5 ↔ security Vector 4(c)** — empty/malformed canary round-trip ⇒ `blocked`; the negative test for that mapping is the tests-side obligation of the security vector.
- **tests §9/§10 supply-chain stage ↔ security §Dependency Security** — the same `cargo audit --deny warnings` + `cargo deny check` gate the chunk's carried 20th pin defers against.

- `cargo nextest run -p conductor-run -p conductor-emit -p conductor-verify` passes for the changed canary emit path including the updated wire assertion, and the workspace legs stay green (`cargo nextest run --workspace --profile ci`, `cargo test --workspace --doc`, `cargo clippy --workspace --all-targets -- -D warnings`) (per test-plan §3 `run` / §4 / §9).

- The live re-run executes as an operator/local gate (`scripts/agent-run.sh boot` under `ANDROMEDA_PULSE_MCP_ENABLED`) and never as a CI gate; if it does not reach `ready:true`, the run records `state="Blocked"` with the named precondition and exits per the reported-state semantics — no silent downgrade and no non-zero-exit reinterpretation (per test-plan §3 `boot` + §9 Live-Pulse scenarios + §11 E2E/CI).
