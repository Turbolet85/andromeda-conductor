## Relevance
Partial (narrow) — no DOM/UI surface is touched by this chunk; a11y's only ties are the shared obs §6 envelope that a11y reproduces verbatim (`fingerprints[]`) and the run-report display of fingerprint text.

## Constraints
- A11y's structured violation JSON is a **verbatim reproduction of the obs §6 log-format envelope** — a11y narrows, obs fixed the schema, and a11y must never diverge from it (per a11y-plan §3 Structured violation JSON schema). `fingerprints[]` is the field this chunk's derivation writes; a11y folds axe rule-id + WCAG-SC tag + selector into that same array. Any obs-side envelope wording change caused by this chunk propagates to a11y §3's **two** reproductions at wrap, not as a phase edit.
- Artifacts riding that envelope **MUST NOT leak absolute host paths or internal seam-crate struct names** (per a11y-plan §3 Structured violation JSON schema + §11 SLO). Live consequence for this chunk: the fingerprint's input moves to the rendered stacktrace, which carries `{file}:{line}` — the hash output is safe, but emitting the pre-hash or normalized stacktrace into an envelope-shaped artifact for debugging would breach this.
- Fingerprint values shown on the desktop-webview run-report are **monospace status-tier text** bound to `--color-id-cyan`/`--color-base` at SC 1.4.3 4.5:1 and `--font-mono` (per a11y-plan §6 Color contrast pairs + §6 Typography tokens). A rendered-width change (16 hex → 8-char prefix) must not introduce a new token pair or a non-mono rendering. Whether the webview renders fingerprints today at all is research's question.
- The **cli surface is not-assertable** — `conductor-run` / `conductor-report` terminal output has no DOM/widget tree and no a11y verification path; its ASCII/NO_COLOR pairing is output-stream discipline, not an a11y gate (per a11y-plan §1 A11y scope + §11 Universal).
- Tier stays **Minimal** and this chunk triggers **no new WCAG criterion** — it adds no interactive control, state token, motion, form input, or live region, so the baseline SC 2.1.1 / SC 1.4.3 / SC 2.4.3 and token-driven SC 1.4.1 / SC 1.4.11 / SC 2.3.3 set is unchanged (per a11y-plan §1 WCAG criteria mapping + §3 WCAG criteria mapping).
- The **zero-WCAG-AA-violations SLO on the four must-be-accessible paths is unconditional**, including "View run report" — a derivation change surfacing there must not regress that path's gate, and no retry-once policy may mask it (per a11y-plan §10).

## Patterns to follow
- **Envelope reproduction, never redefinition:** a11y copies the obs §6 envelope verbatim and folds its own data into existing fields rather than adding top-level fields; schema changes flow obs → a11y at wrap (per a11y-plan §3 Structured violation JSON schema).
- **Token-name-bound assertion, not value-bound:** the `colorjs.io` checker resolves *named* token pairs from compiled CSS, so changing the *content/width* of a monospace field needs no a11y harness change (per a11y-plan §3 Contrast verification harness + §6).
- **One artifact surface:** a11y results emit through the tests' 5-command `logs` command on the single tauri-driver/WebdriverIO webview stack — no parallel emission lane is stood up for a derivation change (per a11y-plan §3 CI integration + §9).
- **State-naming crosswalk as the join key:** lamp display label ↔ obs `verdict` / `state` enums is the binding join (per a11y-plan §6 State color tokens); this chunk alters `fingerprints[]` only, so verdict/state join keys are untouched.

## Anti-patterns to avoid
- NEVER let an artifact aligned to the obs §6 envelope leak absolute host paths or internal seam-crate struct names (per a11y-plan §11 SLO) — acutely relevant now that the hash input is a path-bearing rendered stacktrace.
- NEVER treat the cli surface as accessibility-assertable (per a11y-plan §11 Universal) — the canary/preflight console output is not an a11y verification path.
- NEVER claim any a11y/WCAG conformance from a non-machine-verifiable basis such as a live-leg narrative (per a11y-plan §11 Strategy) — relevant only if the `v2-10` leg record touches a11y state.
