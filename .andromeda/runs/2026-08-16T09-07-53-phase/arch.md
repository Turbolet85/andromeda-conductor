## Relevance
Relevant — the chunk changes a primitive owned by a locked workspace crate, lands a new normal dependency (a §Stack registry event), and touches two arch sections that currently record the mismatch as current truth.

## Constraints
- The fingerprint primitive is seam-placed in `conductor-emit` (co-located with the exception content it derives from), and `conductor-faults` owns only the fingerprint-STORM fault that composes it; the crate-per-seam workspace makes a forbidden cross-seam edge a compile error, so `conductor-run` consumes the primitive and must not re-derive it at the gate (per architecture.md §Established Decisions [Module Boundaries] + §Occupied Resources Crate names + §Infrastructure Patterns directory tree).
- A hashing crate backing a shipped signature is a new **layer** in the technology registry — arch §Stack and Technologies currently carries no hashing/digest row at all. The workspace convention requires the pin in `[workspace.dependencies]` plus the member dep, and the registry row is owed at wrap (per architecture.md §Stack and Technologies). It must build on Rust 2024 / MSRV 1.94.1 (per architecture.md §Inherited Defaults Language/runtime).
- The tree gate: `Cargo.lock` is committed and CI runs build + nextest + clippy on the changed tree; exact dev-test tool versions stay test-plan's, so a hasher used by shipped code cannot sit in the dev-test stack (per architecture.md §Infrastructure Patterns Build system + §CI/CD approach).
- No new occupied resource may land. `CONDUCTOR_*` is a closed enumerated namespace over concepts arch already defines, and the `contracts/` artifacts deliberately carry NO `CONDUCTOR_*` override handle — so neither the algorithm nor the comparison width (prefix vs full) may become a tunable env handle or manifest term (per architecture.md §Occupied Resources Environment variables + On-disk artifacts).
- The verdict/error wall applies at the gate: a fingerprint that does not read back is a `Blocked` **value** carrying its named precondition string, never a `Result::Err`, and never silently downgraded to pass/fail/manual-check (per architecture.md §Cross-cutting Patterns Verdict/error wall + §Established Decisions [Read-Back Dependency Posture]).
- The readiness-gate contract is fixed at FIVE named preconditions with host-path-free strings (`data_dir` redacted) and a blocked row that nulls `verdict`/`journal_emitted_at`/`read_back_observed_at`/`latency_ms`/`fingerprints`; this chunk changes what the canary arm *compares*, not the gate's precondition set or result shape (per architecture.md §Standard Contracts Readiness gate).
- The hashed input must be the same string the wire carries. Raw `opentelemetry-proto` types were chosen precisely because the SDK exporter "offers no control over fingerprint identity", and the OTel-semconv exception span event is the shared vocabulary (`exception.type` / `message` / `stacktrace`) — so the derivation's input is the emitted `exception.stacktrace`, not a parallel construction (per architecture.md §Established Decisions [OTLP Emission Strategy] + §Conventions Interface surfaces / Outbound emission). Whether `render_stacktrace`'s output is byte-identical to what actually lands in the wire attribute is research's question.
- Determinism discipline: the derivation must remain a pure function of exception content — no clock read, no RNG, no host-dependent input — so "same scenario + seed ⇒ same stream shape" survives (per architecture.md §Design Philosophy Determinism under a seed + §Cross-cutting Patterns Determinism discipline).

## Patterns to follow
- **New-dep registration flow** (serde_json / toml / rand_chacha / clap / owo-colors / inquire precedent): pin in `[workspace.dependencies]` → member dep → audit + deny green with `Cargo.lock` committed → §Stack row amended at wrap → cascade to `.claude/docs/stack.md`. A standard utility crate earns a §Stack row, not a §Established Decisions entry; only a consequential fork earns the latter (per architecture.md §Stack and Technologies).
- **SUT-contradicts-Conductor → Conductor adopts the SUT's shape.** The [MCP Read-Back Client] reversal is the governing precedent: a locked Conductor-side choice was replaced wholesale when the live SUT's actual wire behavior contradicted it, and the superseded rationale was preserved in the amendments sidecar rather than deleted (per architecture.md §Established Decisions [MCP Read-Back Client]).
- **Typed per-seam error enums** (`EmitError` in `conductor-emit`, `VerifyError` at the read-back seam); `anyhow` only at `conductor-cli` / `#[tauri::command]` edges (per architecture.md §Conventions Error handling).
- **Provenance labeling for transcribed SUT facts.** The `contracts/` manifests state their `provenance` so a reader can tell a transcribed SUT record from a Conductor measurement; a doc comment asserting "matches Pulse's derivation" is exactly the unlabeled-claim class this discipline exists to prevent (per architecture.md §Occupied Resources On-disk artifacts).
- **Gate-arm ordering + one-string-per-precondition composition** is already fixed (run-contract arm before the canary arms, canary poll skipped rather than paid) — the canary arm's placement is not this chunk's to move (per architecture.md §Standard Contracts Readiness gate).

## Anti-patterns to avoid
- Do not introduce a `CONDUCTOR_*` handle, a `contracts/` term, or a cargo feature to select the algorithm, the normalization, or the comparison width — arch's manifest artifacts deliberately expose no override handle, and the env namespace is enumerated (per architecture.md §Occupied Resources).
- Do not duplicate the derivation outside `conductor-emit` (a second copy in `conductor-run` at the comparison site, or a re-home into `conductor-faults`) — the seam placement was ratified for this primitive and the storm fault is the only composer (per architecture.md §Established Decisions [Module Boundaries]).
- Do not turn a fingerprint absence into a harness fault or a silent pass; the mismatch class must stay a named `Blocked` precondition (per architecture.md §Cross-cutting Patterns Verdict/error wall).

## Contract bindings
- **§Stack and Technologies new-dep row ↔ security (Dependency Security).** The hashing dep moves `Cargo.toml` + `Cargo.lock`, so the audit/deny overlap re-runs against a tree that is no longer zero-delta and any new advisory/license needs the `deny.toml` justified-exception ledger — and the standing `cargo audit` deferral's stated basis ("no dependency delta") no longer holds. The 2026-08-08 remediation is the precedent that `cargo audit` exit-0 can hide what `cargo deny` denies, so audit-only is not sufficient evidence.
- **§Standard Contracts readiness-gate envelope ↔ tests.** The precondition strings and the blocked-row null-field shape are what `conductor-run`'s canary/preflight fixtures pin; changing the compared value must not perturb the envelope those fixtures assert.
- **§Standard Contracts host-path-free precondition strings ↔ obs.** Whatever the gate logs about the fingerprint comparison inherits the `data_dir`-redaction rule.
- **§Occupied Resources Crate names ↔ all domains** — every domain's content for this chunk lands in `conductor-emit` / `conductor-run` as locked here.
- **Expected wrap amendment (not a phase edit):** §Established Decisions [Read-Back Dependency Posture] and §Standard Contracts Readiness gate BOTH currently state the mismatch as by-construction and instruct readers to read a `canary fingerprint not found` block as a derivation mismatch. Landing the alignment makes both stale, and the 2026-08-15 duplicate-occurrence entry is the standing lesson that a single-site apply leaves the second restatement teaching the disproved reading.
