## Relevance

## Constraints
- The `run`/`suite` results/SLO table is fixed at **exactly 6 columns**, `fingerprints` last, in the ANSI 117 (`color-id-cyan`) mapping, width terminal-detected and never hardcoded (per layout-templates §Surface: cli — Component — Primary content block 1 (results / SLO table)). A derivation change may change the *value* rendered in that cell, never the column set.
- Output structure is a **stability contract** — downstream agents parse it, so adding a `comfy-table` column without a `--format` flag is a breaking change (per layout-templates §Surface: cli — IA notes → Command model). Exposing an expected-vs-actual fingerprint pair therefore cannot be done by widening the table.
- The preflight readiness line (`protocol … tools … canary …`) is printed once per command after the header, with identifiers in ANSI 117 and an **`[OK]` / `[BLOCKED]` ASCII prefix so the gate reads without color**; `conductor preflight [--json]` emits the `ReadyState` JSON or a `[PASS]`/`[BLOCKED]` line and exits 0 **iff** `ready:true` (per layout-templates §Surface: cli — Component — Header / banner + §Surface: cli — Primary screens). Whether the shipped preflight output already carries the bracket prefix and the iff-exit rule is research's question.
- The per-P-ID bracket-label set is **closed at six** (`[PASS]`/`[HOLD]`/`[FAIL]`/`[MANUAL]`/`[RESIDUAL]`/`[BLOCKED]`), with the only permitted addition being a **run-level, non-lamp qualifier riding outside the lamp column** (per layout-templates §Surface: cli — Component — Primary content block 2). A fingerprint mismatch must route through the existing set, not a new label.
- A precondition that was **never measured** renders `[BLOCKED]` (ANSI 60) with its **named precondition string** and `—`/null measurement cells — **never a red error**, since `Blocked` ≠ red (per layout-templates §Surface: cli — Component — Primary content block 2; mirrored at §desktop-webview Component — Primary content block 2).
- Pipe discipline: raw artifact data (the fingerprint among it) stays on stdout, human messages on stderr, ANSI auto-stripped when `!isatty(1)` / `NO_COLOR` / `TERM=dumb`, and **no emoji in machine-parseable output** (per layout-templates §Surface: cli — IA notes → Pipe discipline).
- Tokens are **adapted, not forked** across surfaces: identifiers render ANSI 117 in cli ↔ `color-id-cyan` Data role on desktop (per layout-templates §Surface: cli — IA notes → Multi-surface coordination; §Surface: desktop-webview — IA notes → Multi-surface coordination).

## Patterns to follow
- **Identifier-rendering pattern:** P-ID, `run_id`, slo_tier, latency_ms and fingerprints all take the same Data-role / ID-cyan treatment; a recomputed fingerprint keeps that treatment regardless of the width the prefix-vs-full-width decision lands on (per layout-templates §Surface: cli — Component — Primary content block 2).
- **Elided-identifier sample pattern:** the templated table sample shows the fingerprint truncated with an ellipsis (`a3f9c1b…`) rather than at full width, so display width and comparison width are independent decisions (per layout-templates §Surface: cli — Output structure `conductor suite`).
- **Named-precondition pattern:** when a gate cannot pass, the `[BLOCKED]` row/line carries the human-readable precondition string beneath it (the `P-022` shape) rather than an error (per layout-templates §Surface: cli — Component — Primary content block 2).
- **Header-once pattern:** the readiness gate prints as part of the once-per-command header block, never an always-on banner (per layout-templates §Surface: cli — Component — Header / banner).
- **Two-table split:** the 6-column results/SLO table and the 4-column `conductor coverage` matrix must not be conflated; only the former has a state column and a fingerprints column (per layout-templates §Surface: cli — Component — Primary content block 1).

## Anti-patterns to avoid
- Do **not** add, rename, split or reorder a results/SLO column (e.g. an "expected fingerprint" column beside "actual") to surface the alignment — the 6-column shape is a parse contract (per layout-templates §Surface: cli — Component — Primary content block 1 + §IA notes → Command model).
- Do **not** render a fingerprint mismatch as a red `[FAIL]`/`status-fail` on a precondition that was never measured, and do **not** mint a seventh lamp/bracket label for it (per layout-templates §Surface: cli — Component — Primary content block 2).
- Do **not** introduce fingerprints into the desktop-webview run-report verdict line — the templated desktop identifier set is P-ID / `run_id` / slo_tier / latency_ms only; a fingerprint there would be a new, untemplated surface element (per layout-templates §Surface: desktop-webview — Component — Primary content block 2).

## Contract bindings
- **cli color mappings ↔ design:** ANSI 117 / 114 / 179 / 203 / 60 / 246 are the ANSI half of the design tokens (`color-id-cyan`, `count-nominal`, `count-hold`, `status-fail`, `count-blocked`, journal-text) — the fingerprint cell's tint is design's token, layouts only fixes its position (layout-templates §Surface: cli — IA notes → Multi-surface coordination).
- **ASCII bracket prefix ↔ a11y / NO_COLOR:** the `[OK]`/`[BLOCKED]` and `[PASS]`/`[FAIL]` prefixes are the layout-level mechanism a11y's "never color-alone" conformance derives from (layout-templates §Surface: cli — Signature placement + §Notes).
- **Preflight exit contract ↔ tests/harness:** the readiness gate is the `agent-run boot` entrypoint (exit 0 iff `ready:true`); the headless path must never block on an `inquire` prompt, so the gate's render and exit code are the harness's observable surface (layout-templates §Surface: cli — Primary screens + §IA notes → Headless invariant).

## Acceptance criteria contributions
- (layouts) After the derivation change, `conductor run`/`suite` still render exactly 6 results/SLO columns with `fingerprints` last in the ID-cyan mapping — no column added, removed, renamed or reordered, and no conflation with the 4-column coverage table (per layout-templates §Surface: cli — Component — Primary content block 1).
- (layouts) `conductor preflight` renders the canary result on the readiness line with its `[OK]`/`[BLOCKED]` ASCII prefix (legible under `NO_COLOR`/piping) and exits 0 iff `ready:true`, non-zero on a Blocked precondition (per layout-templates §Surface: cli — Primary screens + §Component — Header / banner).
- (layouts) If the fingerprint still does not match, the outcome renders through the closed six-label set as `[BLOCKED]` (ANSI 60) with a named precondition string and `—`/null measurement cells — never a red Fail and never a seventh label (per layout-templates §Surface: cli — Component — Primary content block 2).
- (layouts) Fingerprint values print as parseable stdout data with ANSI stripped when piped and no emoji; any human-facing mismatch explanation goes to stderr (per layout-templates §Surface: cli — IA notes → Pipe discipline + §Component — Footer / terminator + error output).
