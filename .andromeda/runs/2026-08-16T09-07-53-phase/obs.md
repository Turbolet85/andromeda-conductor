# obs extract

## Relevance
Partial — the derivation change itself is emit-domain, but it lands on two instrumented boundaries (`emit.batch` egress, `verify.readback` of `retrieve_telemetry_slice`), touches the field-allowlist/redaction layer, and moves the CI supply-chain artifact.

## Constraints
- Obs tier is Minimal (0); self-observation is `tracing` JSON lines only — no OTel SDK, no metrics instrument, no exporter may be introduced alongside the new hashing dep (per obs-plan §1 Obs Scope Summary + §3 OTel SDK init + §11 Telemetry Strategy). The chunk adds a normal dependency to the emit path; §3's dormant-transitive note governs only opentelemetry-proto, so a hashing crate must not arrive with an SDK/exporter feature enabled.
- Span names are a bounded set (`scenario.run`, `timeline.execute*`, `emit.batch`, `emit.logs_batch`, `verify.readback*`, `report.generate`, `db.insert_run`, `fault.*`, `tauri.command.*`) — the realigned derivation must reuse existing spans, not add one (per obs-plan §11 Spans / Traces).
- §11 Telemetry Strategy names **fingerprint generation** explicitly as a hot path that must be profiled before it gains a span — instrumenting the new blake3-over-normalized-stacktrace derivation per-exception is banned absent that profiling (per obs-plan §11 Telemetry Strategy).
- Any span attribute or log field the plan adds must be a name in `conductor-core::redact::ALLOWLISTED_FIELDS`, or the processor stage drops it and it emits nothing; diagnostics that do not have an allowlisted name ride the allowlisted `message` field (per obs-plan §4 Required-span-attributes constraint + §11 PII Scrubbing).
- The fingerprint's new input is the rendered stacktrace, whose frames carry `({file}:{line})` — logging that input or its normalization at any level is subject to the host-file-path value scrub (drive-letter, `/home`, `/Users`, `%APPDATA%`, `~/.cargo`, `.rustup`) → `<redacted>` (per obs-plan §11 Logs + §9 Log conformance check). Whether the canary's synthetic frames carry host-shaped paths is research's question.
- The preflight canary comparison must not turn a malformed or unrecognized read-back into a verdict: an empty canary ⇒ `blocked`, never a false pass, and never a panic (per obs-plan §11 Error Reporting + §11 Project-specific bans). Zero-unlogged-panics is the always-required SLO invariant, so any slicing/truncation panic in the new derivation must be captured by `std::panic::set_hook()` + `tracing::error!` (per obs-plan §10 SLO Invariants).
- Pulse is Boundary-only — Conductor instruments its own outbound emission and its observation of the read-back response, never Pulse-side state; harvesting Pulse's `agent-latest.jsonl.<date>` for the live leg is evidence collection, not instrumentation Conductor owns (per obs-plan §1 Instrumentation scope, Pulse MCP server row).

## Patterns to follow
- The `verify.readback` boundary-log wrapper: tool name (`retrieve_telemetry_slice` is in the enumerated set), `latency_ms`, error, **canary-check result**, and the observed KEY SET of the raw tool result — names only, never values, on `message` (per obs-plan §6 Boundary-call wrappers). This is the existing pattern for making an empty-vs-diverged `fingerprint_refs` extraction distinguishable.
- The emitting-side twin: `emit.batch`'s wire-shape witness (span count, skip count, distinct event/event-attribute key names, ordered, at `debug` inside the existing `#[instrument]` span, on `message`) — the canary's outbound shape is already this pattern's subject (per obs-plan §6 Boundary-call wrappers).
- `{module}.{operation}` span naming with `verify.readback_fingerprints` carrying `mcp_tool` / `latency_ms` / `fingerprints_matched_count`, and `emit.batch` carrying `batch_index` / `fingerprints_in_batch` — the fingerprint-storm path's existing attribute vocabulary (per obs-plan §4 Fingerprint-storm scenario).
- The Run-report envelope's `fingerprints` array is a reserved envelope field written by the report seam; the self-obs line carries the smaller base set — the two record shapes are governed differently (per obs-plan §3 Log format JSON schema, two record shapes).
- Opt-in verbosity uses the ADDITIVE form `RUST_LOG=info,conductor_emit=debug`; a bare per-target directive replaces the default and blacks out the rest of the stream (per obs-plan §3 Per-module log levels).

## Anti-patterns to avoid
- Never emit a fingerprint diagnostic at `info` on the emission hot path, and never wrap the derivation in its own span (per obs-plan §11 Telemetry Strategy + §11 Logs).
- Never introduce an OTel SDK, meter, or any self-observation OTLP export as a side effect of the dependency change — `:4317` is the PRODUCT stream only, `:4318` is dead (per obs-plan §11 Metrics + §11 Universal).
- Never let the changed comparison path leak the raw stacktrace, a host file path, or an internal struct name into logs / run-report / `runs.db` (per obs-plan §11 Logs + §11 PII Scrubbing).

## Contract bindings
- **obs ↔ tests (harness):** test-plan §3 OWNS the JSONL envelope schema including the `fingerprints` array; obs derives and does not re-author it (per obs-plan §3 Log format JSON schema + §1 creator-explicit-telemetry trigger). Any test surface pinning a literal fingerprint value is the tests domain's; obs binds only to the field's presence/shape.
- **obs ↔ security:** the host-file-path value scrub + field-name allowlist in `conductor-core::redact` is the single-location redaction owner for anything the new derivation logs (per obs-plan §11 PII Scrubbing).
- **obs ↔ CI/supply-chain:** the `cargo-audit` / `cargo-deny` output is a §9 telemetry artifact (inline in CI logs) and an audit red flag is a §10 build-failure condition — the chunk's `Cargo.toml`/`Cargo.lock` move re-arms that gate (per obs-plan §9 Telemetry artifact handling + §10 Build / deploy failure conditions).

## Acceptance criteria contributions
- (obs) The preflight canary read-back emits a boundary line carrying the tool name, `latency_ms`, the canary-check result, and the observed key set of the raw `retrieve_telemetry_slice` result (key names only, on `message`) so an empty corpus is distinguishable from a `fingerprint_refs` shape divergence (per obs-plan §6 Boundary-call wrappers).
- (obs) No new span name is introduced and no span wraps fingerprint derivation; all self-obs for this path stays within the bounded span set (per obs-plan §11 Spans / Traces + §11 Telemetry Strategy).
- (obs) Every field the change emits is either an allowlisted field name or rides `message`; no rendered stacktrace, host file path, or internal struct name appears in `logs/agent-latest.jsonl`, the journal, or `runs.db` (per obs-plan §11 PII Scrubbing + §9 Log conformance check).
- (obs) An empty, malformed, or unrecognized read-back slice yields `blocked` with a structured line — never a false pass and never an unlogged panic from the new hashing/truncation code (per obs-plan §11 Error Reporting + §10 SLO Invariants).
