# security extract

## Relevance
Relevant — this chunk adds a NORMAL (shipped) hashing dependency, moves `Cargo.toml`/`Cargo.lock`, changes a hash written into run artifacts, and touches the preflight `blocked` precondition set.

## Constraints
- A new **normal** dep on the emit path enters the shipped `conductor-cli` tree, so the release/merge gate applies unchanged: `cargo-audit` ≥ 0.22 (+ recommended `cargo-deny` ≥ 0.19) must run green against the changed tree, with `Cargo.lock` committed and drift-free — versions are minimum floors, not lockable pins (per security-plan §Dependency Security; §Security Anti-Patterns → Universal).
- The standing `cargo audit` deferral is governed by the **two-fault split**: an advisory-DATABASE fault is remedied only by a bounded re-check plus the audit↔deny **overlap verified** (`cargo deny check advisories bans licenses sources` true exit 0 across all four classes) — never a floor raise, never a `deny.toml` ignore, never a CI edit, never a silent accept (per security-plan §Dependency Security). The scope itself records that the "no dependency delta" leg of the deferral basis dies once the dep lands; whether the duplicate-ID DB fault still reproduces at this chunk is research's question.
- If the new dep introduces a license or source outside the current `deny.toml` policy, §Dependency Security requires the **documented accepted-exception mechanism** — a specific entry with a justifying comment — never a blanket widening of the license/bans/sources classes. Whether the existing allow-set already covers it is research's question.
- Any fingerprint/hash persisted to `runs.db` or the journal must be a **modern hash**; MD5/SHA-1/DES/RC4/ECB are banned outright (per security-plan §Security Anti-Patterns → Data Protection).
- The preflight gate's FIVE named preconditions — including **canary fingerprint absent** — must each surface as their own distinct `blocked` state with its own named precondition string; a derivation change must never convert a genuine absence into a pass, a generic corpus-empty string, or a silent downgrade (per security-plan §Security Anti-Patterns → Universal).
- The read-back side of the comparison crosses the **trusted-child stdout boundary**: `retrieve_telemetry_slice.fingerprint_refs` arrive through bounded line-delimited JSON-RPC decoding, faults routed as typed `VerifyError::{JsonRpc,Decode,Transport}` through the verdict/error wall, never a panic; an empty canary round-trip must become `blocked`, never a false pass-as-empty (per security-plan §Input Validation, MCP read-back child-stdout row; §Security Anti-Patterns → Input).
- Moving the hash INPUT from `frames[].function` to the **rendered stacktrace** puts `file` values on the wire and into anything derived from them: run-report artifacts (`<run_id>.md`, `runs.db` rows, JSONL journals) must carry verdict/state/identity fields without leaking absolute host paths or internal seam-crate struct names (per security-plan §Error Handling, run-report artifact sanitization; §Security Anti-Patterns → Logging). Whether the frames' `file` values are synthetic scenario literals rather than host-derived paths is research's question.

## Patterns to follow
- The established dep-addition pattern for this workspace: land the dep, commit the lock, and record `cargo audit` + `cargo deny` outcomes for the chunk — the precedent used for `rusqlite`/`bundled` SQLite and the presentation deps (per security-plan §Dependency Security; amendments 2026-06-21, 2026-06-23).
- `runs.db` fingerprint writes use **rusqlite bound parameters** with fingerprint arrays as a JSON1 TEXT array — never `format!`/concatenated SQL, even for self-generated synthetic content (per security-plan §Input Validation, `runs.db` row). Whether this chunk touches that write path at all is research's question.
- The verdict/error wall: typed `thiserror` enums stay inside the seam crates and collapse to `anyhow` only at the `conductor-cli` / `#[tauri::command]` edges; verification outcomes (`Verdict` / `ReportState::Blocked`) are returned as `Ok(...)` values, `Result::Err` is reserved for harness faults (per security-plan §Error Handling).
- `cargo-geiger` ad-hoc mapping of `unsafe` is the named tool when a dependency's implementation carries unsafe/SIMD surface the compiler cannot check (per security-plan §Security Anti-Patterns → Universal).

## Anti-patterns to avoid
- NEVER silently downgrade a failed preflight — the canary-fingerprint precondition keeps its own distinct `blocked` string; aligning the derivation must not make a real mismatch or empty read-back indistinguishable from a pass (per security-plan §Security Anti-Patterns → Universal).
- NEVER resolve the audit red with a `deny.toml` ignore, a CI edit, a floor raise that changes nothing, or a silent accept — the remedy for an advisory-DB fault is a bounded wait with the overlap verified (per security-plan §Dependency Security; §Security Anti-Patterns → Universal).
- NEVER let `Cargo.lock` drift or go uncommitted, and never run the release gate / merge without audit (+deny) green — the lock is what makes the scan deterministic (per security-plan §Security Anti-Patterns → Universal).

## Contract bindings
- **CI security gate ↔ tests plan (§CI Integration):** the audit/deny re-run against the no-longer-zero-delta tree is the same single-workflow security job the tests domain owns; the gate's pass/fail belongs to both (per security-plan §Dependency Security, CI integration).
- **`blocked` precondition string ↔ architecture §Standard Contracts readiness gate + obs run-report/journal fields:** the canary-fingerprint precondition's string is agent-parseable ground truth shared across the report artifact and the gate contract; security constrains only that it stay distinct and sanitized (per security-plan §Security Anti-Patterns → Universal; §Error Handling).
- **Fixture/golden fingerprint literals ↔ tests plan:** the "no real PII in fixtures" rule is satisfied by construction here — all fingerprint inputs are self-generated synthetic telemetry, no PII/credential class exists (per security-plan §Threat Model Summary, data classification).

## Acceptance criteria contributions
- `cargo audit` re-run against the changed lock, and while the RustSec DB fault persists the overlap `cargo deny check advisories bans licenses sources` is verified true exit 0 across all four classes — not assumed (per security-plan §Dependency Security).
- `Cargo.lock` committed and drift-free with the hashing dep declared as a normal (not dev) dependency of the emit path (per security-plan §Security Anti-Patterns → Universal).
- The adopted fingerprint algorithm is a modern hash, with no MD5/SHA-1/DES/RC4/ECB anywhere on the fingerprint path (per security-plan §Security Anti-Patterns → Data Protection).
- A fingerprint mismatch or an empty/erroring read-back still yields the distinct `canary fingerprint absent` `blocked` precondition string rather than a pass, and no read-back decode fault panics (per security-plan §Security Anti-Patterns → Universal; §Input Validation, MCP read-back child-stdout row).
