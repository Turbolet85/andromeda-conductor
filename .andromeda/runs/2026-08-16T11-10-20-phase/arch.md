# arch extract

## Relevance
Relevant — the chunk places code in locked workspace crates, may add a cross-seam dependency edge, and uses arch's pinned self-observation stack, clock discipline and registered artifact.

## Constraints
- Crate-per-seam is compiler-enforced: `Cargo.toml` dependency edges *are* the architecture, and the workspace-member set (`conductor-core` / `-timeline` / `-emit` / `-faults` / `-verify` / `-report` / `-run` / `-cli` / `-tauri`) is locked — this chunk lands in existing crates, adds no member (per architecture.md §Established Decisions [Module Boundaries] + §Occupied Resources — Crate names). The scope's `[inferred]` "run → faults edge?" question is exactly a seam decision this rule governs: if the edge is taken it must be an explicit manifest edge, and §Project Intent requires new seams be expressed as explicit `Cargo.toml` dependency edges, never routed around.
- Self-observation is `tracing` 0.1.44 + `tracing-subscriber` 0.3.23, pinned in `[workspace.dependencies]` and explicitly **NOT an OTel SDK** — OTLP is the PRODUCT emission (per architecture.md §Stack and Technologies — Self-observation row). Adding `tracing` to `conductor-faults` must consume the existing workspace pin, not a fresh version or a new crate.
- Journal-relative values take their basis from `std::time::SystemTime`/`Instant`, never tokio's virtual clock, because the virtual clock breaks journal-relative SLO math (per architecture.md §Cross-cutting Patterns — Determinism discipline; §Conventions — Data model conventions). `fault_start_offset_ms` is a journal offset and inherits this.
- Determinism discipline requires "same scenario + seed ⇒ same emission-stream shape" under the seeded `ChaCha8Rng` + `current_thread` runtime (per architecture.md §Established Decisions [Determinism RNG] + [Async Runtime Flavor]). Instrumentation must be observation-only and must not perturb phase timing, gap jitter or emission ordering — consistent with the scope's "no new fault behavior" boundary.
- `logs/agent-latest.jsonl` is a registered on-disk artifact with its own schema, distinct from the per-run emission journal, written as a sibling of the runs dir (moves with `CONDUCTOR_RUNS_DIR`) and truncated per invocation; the Tauri sibling `logs/conductor-tauri.jsonl` inherits the same processor-stage redaction (per architecture.md §Occupied Resources — On-disk artifacts). No new artifact path is available to this chunk.
- Agent mode is triggered by `CONDUCTOR_AGENT_MODE`, which Conductor **reads** and main never writes (avoiding edition-2024 `unsafe std::env::set_var`); the `CONDUCTOR_*` namespace is the only reserved config surface (per architecture.md §Occupied Resources — Environment variables). This chunk adds no env var.
- The port-occupier fault is the single deliberate exception to the trust boundary — the one case where Conductor *binds* `:4317` rather than acting as a client (per architecture.md §Cross-cutting Patterns — Trust boundary; §Occupied Resources — Ports). The `port` span attribute names an already-registered occupied resource, so it introduces no new one.

## Patterns to follow
- Downward seam composition: `conductor-run` is the run composition root sitting **above** the seams and **below** both bins, shared by `conductor-cli` and `conductor-tauri` (per architecture.md §Occupied Resources — Crate names). Instrumenting on that path is the shape that reaches both bins with one edge; a run → faults edge is directionally consistent with the composition-root role, unlike a faults → run edge.
- Seam crates composing lower seams: `conductor-faults` is recorded as depending on `conductor-emit` for the fingerprint-storm fault (per architecture.md §Infrastructure Patterns — directory tree; amendment 2026-06-18). Precedent that a fault helper may take a downward dependency when the behavior genuinely lives there.
- Shared-dependency declaration: every new library enters `[workspace.dependencies]` first and is referenced per-crate (the serde_json / toml / clap / blake3 precedent across §Stack and Technologies + the amendment log). Enabling `tracing` in `conductor-faults` follows this, not a crate-local version.
- Typed per-seam errors with `thiserror`; `anyhow` only at `conductor-cli` / `#[tauri::command]` edges, and the verdict/error wall keeps `Result::Err` for harness faults only (per architecture.md §Conventions — Error handling). Instrumentation must not manufacture a new error path through the fault helpers.
- Naming: snake_case Rust identifiers and module paths, kebab-case `conductor-<seam>` crates (per architecture.md §Conventions — Naming patterns). Span-name/attribute vocabulary itself is obs-plan's bounded set, not arch's.

## Anti-patterns to avoid
- Do not reach for an OTel SDK / `opentelemetry-otlp` exporter (or any OTLP path) for these self-obs spans — the raw-types-over-SDK decision covers the product emission only, and the exporter spawns its own batch tasks on the deterministic runtime (per architecture.md §Established Decisions [OTLP Emission Strategy] + §Stack — Self-observation).
- Do not dodge the compiler seam with a bin-local or duplicated shim to avoid declaring a cross-crate edge — the point of crate-per-seam is that a forbidden edge fails to compile, so a hidden one defeats the enforcement (per architecture.md §Established Decisions [Module Boundaries]).
- Do not add a `CONDUCTOR_*` env var, a new on-disk artifact, or a new port to carry the fault spans (per architecture.md §Occupied Resources).

## Contract bindings
- **arch ↔ obs:** arch owns the self-obs *stack* and the artifact registration; the span names, attribute set and span-tree placement are obs-plan §3/§4's (arch's §Stack row explicitly defers detail to obs-plan §3). The five new attribute names must clear `conductor-core/src/redact.rs`, whose redaction arch records as shared by BOTH sinks — so a change there affects `logs/conductor-tauri.jsonl` as well as `logs/agent-latest.jsonl` (per architecture.md §Occupied Resources — On-disk artifacts).
- **arch ↔ tests:** CI is GitHub Actions build + test only, run through the zero-retry nextest `ci` profile (no retries mask flakes — the determinism invariant) plus `cargo test --doc` (per architecture.md §Infrastructure Patterns — Build system; §Established Decisions [CI/CD]). Any obs-conformance gate for these spans must be headless and Pulse-free, matching the scope's "not a live-Pulse leg".
- **arch ↔ build order:** any workspace-wide `cargo build`/`nextest`/`clippy` that compiles `conductor-tauri` requires the webview bundle built first, because `generate_context!` resolves `build.frontendDist` at COMPILE time (per architecture.md §Infrastructure Patterns — Build system). Relevant only if the chunk runs full-workspace gates.
- **arch ↔ security (PREREQ in scope):** `cargo deny check advisories bans licenses sources` is the gate arch records as green while `cargo audit` is red on an external advisory-DB fault; the accepted-license set is no longer Tauri-only (`BSD-2-Clause` via `conductor-emit`→`blake3`) (per architecture.md §Infrastructure Patterns — Build system). Whether adding `tracing` to `conductor-faults` moves `Cargo.lock` at all is research's question — the pin already exists at workspace level.

## Acceptance criteria contributions
- (arch) All fault-span code lands in existing locked workspace members (`conductor-faults` / `conductor-run` / `conductor-timeline` / `conductor-core`); no new workspace crate is introduced (per architecture.md §Occupied Resources — Crate names).
- (arch) Any new cross-crate dependency is an explicit `Cargo.toml` edge that compiles under crate-per-seam, with no bin-local shim bypassing the seam; whether a `conductor-run` → `conductor-faults` edge is even needed is research's question (per architecture.md §Established Decisions [Module Boundaries] + §Project Intent — How new functionality is added).
- (arch) `tracing` in `conductor-faults` resolves from the pinned `[workspace.dependencies]` self-obs stack (tracing 0.1.44 / tracing-subscriber 0.3.23) and no OTel SDK or OTLP path is added for self-observation (per architecture.md §Stack and Technologies — Self-observation).
- (arch) `fault_start_offset_ms` / `fault_duration_ms` derive from `std::time::SystemTime`/`Instant` (never tokio's virtual clock), and the chunk adds no new `CONDUCTOR_*` env var, port, or artifact path beyond the registered `logs/agent-latest.jsonl` (per architecture.md §Cross-cutting Patterns — Determinism discipline + §Occupied Resources).
