# arch extract

## Relevance
**Relevant** — arch governs crate placement for the new log-harvest capability, the scenario-config/ledger/load-envelope gates the re-shaped storm must cross, and the report envelope its assertions serialize into.

## Constraints
- **Workspace placement is compiler-enforced and the member list is closed.** The log-harvest reader (a read of a SUT-owned log artifact) has no registered home: architecture.md §Occupied Resources (Crate names) enumerates exactly nine workspace members, and §Established Decisions [Module Boundaries] requires each seam to be a crate whose `Cargo.toml` edges *are* the architecture. Placing it in an existing seam (emit/verify/report/run) or landing a tenth member are architecturally different acts; the latter is a new occupied resource requiring registration at wrap.
- **Do not conflate Conductor's `logs/agent-latest.jsonl` with Pulse's.** architecture.md §Occupied Resources (On-disk artifacts) registers `logs/agent-latest.jsonl` as **Conductor's own** self-observation stream (sibling of the runs dir, moves with `CONDUCTOR_RUNS_DIR`, truncated per invocation). The chunk's harvest target under `{data_dir}/logs/…` is a SUT-owned file with a colliding base name and a different owner, namespace and lifecycle.
- **Scenario edits stay declarative + validated at load.** `scenarios/fingerprint-storm.toml` is serde-deserialized and garde-bounds-checked, nested spec fields must `dive` and never `skip`, and a phase's shape is declared data (`EmissionSpec { signal, occurrences, shape }`) per architecture.md §Conventions (Config conventions). Adding `P-074` to `p_ids` requires membership in the manifest's accepted set, asserted by `check_capabilities` at the binary-edge load sites, per §Established Decisions [Accepted Capability Set] — "no scenario without a P-ID" (§Cross-cutting Patterns Scope law).
- **The `UNBACKED_AUTO` pin is exact-set in both directions.** architecture.md §Established Decisions [Accepted Capability Set] requires `check_scenario_backing` to fail (`CoreError::UnbackedCoverage`) on a new unbacked claim, a stale pin a scenario now covers, or a pin that lost its `Auto` classification — so naming P-074 and retiring its pin are one atomic change, and `check_sut_drift`'s classification-row requirement still applies.
- **Re-shaped occurrence counts must clear the load envelope.** architecture.md §Occupied Resources (`contracts/pulse-load-envelope.toml`) requires the two sustained terms — `max_sustained_storm_ms` and `max_sustained_rate_spans_per_s` — asserted **per emitting phase**, with the `[[exempt]]` ledger held empty at exact-set equality in both directions, and `check_load_envelope` / `LoadEnvelope::classify` reading ONE shared basis. Whether the re-derived variant mix and counts still clear both terms is research's question.
- **Verdict/error wall.** architecture.md §Cross-cutting Patterns (Verdict/error wall) + §Established Decisions [Error Handling] require identity/tier/coalescing outcomes to be typed values (`Verdict`/`ReportState`), with `Result::Err` reserved for harness faults. An unreadable/absent SUT log is a harness fault or a named `Blocked` precondition — never a `Fail` verdict smuggled through `Err`, and never a silent downgrade.
- **Report envelope + timing model are fixed.** Each family check serializes into the canonical per-check envelope with `verdict ∈ {Pass, Fail, CalibrationRegion}` / `state ∈ {Pass, Fail, ManualCheck, KnownResidual, Blocked}` and a `slo_tier` from the closed `<5s`/`<20s`/`<90s` set (architecture.md §Standard Contracts + §Conventions Data model conventions). Any `<20s` re-calibration must land inside that closed enum, and latency stays `read_back_observed_at − journal_emitted_at` stamped from `std::time`, never wall-clock-from-test-start (§Established Decisions [Timing-Tolerance Model], §Cross-cutting Determinism discipline).

## Patterns to follow
- **Pinned SUT-record artifact pattern** (`contracts/pulse-capabilities.toml` · `pulse-load-envelope.toml` · `pulse-run-contract.toml`, architecture.md §Occupied Resources): `sut_version` · `captured_at` · `provenance`, runtime-read and bounds-checked at load, resolved from a fixed `default_path()` through `resolve_under` with deliberately **no** `CONDUCTOR_*` override handle. If the log-harvest surface needs any pinned path/shape knowledge, this is the established precedent rather than a new env handle.
- **Fingerprint primitive lives in `conductor-emit`**, co-located with the exception content it derives from, while `conductor-faults` composes it for the storm fault (architecture.md §Infrastructure Patterns directory tree; recorded by the 2026-06-18 amendment). The doc-comment and variant-arithmetic work belongs on the emit side by this seam split.
- **Named-precondition + null-measurement blocked row** (architecture.md §Standard Contracts, Readiness gate): a blocked check populates only `run_id`/`seed`/`scenario`/`p_ids`/`slo_tier` with the rest JSON `null`, every precondition string is host-path-free with `data_dir` redacted, and cross-run queries exclude NULL-measurement rows. The family inherits this shape when the gate or the leg cannot measure.
- **Hand-rolled JSON-RPC read-back returning raw `serde_json::Value`** (architecture.md §Established Decisions [MCP Read-Back Client], §Conventions Inbound verification) — the key-diff baseline work in `conductor-verify` sits inside this decision; readers degrade on unrecognized shapes, so any divergence is landed as a finding plus a test, not a silent reader fix.
- **Self-observation is `tracing` JSON, not an OTel SDK** (architecture.md §Stack and Technologies, Self-observation row) — OTLP is the PRODUCT emission. Witness spans for the leg ride the tracing stream; field/redaction detail is obs-plan's, not arch's.

## Anti-patterns to avoid
- **No new network/inbound surface.** architecture.md §Established Decisions [Backend Framework] + §Cross-cutting Patterns (Trust boundary) bar any HTTP/server surface of Conductor's own; the only deliberate bind is the port-occupier fault. A log-harvest capability is a local filesystem read, never a listener, watcher service, or new egress path.
- **Never persist or exfiltrate SUT-owned data or host paths into Conductor artifacts.** architecture.md §Standard Contracts states `corpus.db` is out-of-scope SUT-owned data Conductor never persists, and requires host-path-free precondition strings with `data_dir` redacted — the same posture governs harvested Pulse log content.
- **No new env-var handle outside the reserved namespace, and no `CONDUCTOR_*` override for SUT-artifact path resolution** (architecture.md §Occupied Resources, Environment variables + the capability-manifest/load-envelope/run-contract precedent); `ANDROMEDA_PULSE_L4_DETERMINISTIC` and `ANDROMEDA_PULSE_MCP_ENABLED` are asserted **not** set by Conductor.

## Contract bindings
- **Run-report envelope ↔ tests + obs + report seam** — the family's P-017/P-018/P-074 checks must serialize into the canonical envelope (architecture.md §Standard Contracts); tests own fixtures for it, obs owns the field-level redaction of any harvested evidence.
- **Readiness gate ↔ verify + the live leg** — the family runs only behind `ready:true`; a staleness block reads "corpus reachable, this run raised nothing", not "wiring broken" (architecture.md §Standard Contracts, Readiness gate).
- **Capability manifest / `UNBACKED_AUTO` ↔ tests + the verification matrix** — the exact-set gates are compile/test-time and must be green without a live Pulse (architecture.md §Established Decisions [Accepted Capability Set], §Established Decisions [CI/CD]).
- **Log-harvest placement ↔ security + obs** — arch fixes only the crate/namespace/artifact-hygiene boundary; path handling, SUT-artifact read posture and content redaction rules are security-plan's and obs-plan's to state.
- **Workspace crate names ↔ all domains** — every domain's content for this chunk lands under the locked `conductor-*` names (architecture.md §Occupied Resources, Crate names).

## Acceptance criteria contributions
- (arch) All chunk code lands in one of the registered `conductor-*` workspace members with no forbidden cross-seam dependency edge, and any tenth member or new `CONDUCTOR_*` env handle is registered rather than introduced silently (per architecture.md §Occupied Resources / §Established Decisions [Module Boundaries]).
- (arch) The re-shaped `fingerprint-storm` phases pass `check_load_envelope` against both asserted per-emitting-phase sustained terms with the `[[exempt]]` ledger still empty in both directions (per architecture.md §Occupied Resources `contracts/pulse-load-envelope.toml`).
- (arch) Every family check emits into the run-report envelope with `verdict`/`state` drawn from the closed sets and `slo_tier` from `<5s`/`<20s`/`<90s`, latency measured journal-relative from `std::time` (per architecture.md §Standard Contracts + §Established Decisions [Timing-Tolerance Model]).
- (arch) The live leg stays an operator/local gate — whatever lands in nextest/clippy is green with no live Pulse, and no CI workflow is made to depend on one (per architecture.md §Established Decisions [CI/CD] / §Infrastructure Patterns CI/CD).
