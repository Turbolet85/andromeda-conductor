# design extract

## Relevance
Partial — the chunk is predominantly emit/core/verify backend work, but its live leg and any new log-harvest reader surface through the `cli` design surface (verdict lines, results/SLO table, `error:`/`hint:` stderr), so only design-system §Surface: cli applies.

## Constraints
- Any per-P-ID outcome this leg produces (P-017 / P-018 / P-074) must render through the closed status set with an ASCII prefix, never color alone: `[PASS]`/`[HOLD]`/`[FAIL]`/`[MANUAL]`/`[RESIDUAL]`/`[BLOCKED]` plus the `✓`/`✗`/`?`/`~`/`•` TTY glyphs (per design-system.md §Surface: cli → Tokens and §Surface: cli → Component Patterns #4). No new lamp state may be introduced for a log-harvested assertion.
- If a P-017/P-018 assertion has no programmatic read-back and depends on the operator's eyes, it is `ManualCheck` (ANSI 146 lavender, `?` glyph, `[MANUAL]`); if it is a measured-but-pre-accepted gap it is `KnownResidual` (ANSI 246, `~`, carrying "expected until {named fix}") — neither may collapse into `Fail` red, and `Blocked` (ANSI 60) with its named precondition string must render measurement columns as `—`/null, never as a red error (per design-system.md §Color Palette → Verdict vs ReportState note and §Surface: cli → Component Patterns #3/#4).
- New failure paths from the log-harvest reader (missing `agent-latest.jsonl.<date>`, zero-byte tee, unparseable line) must go to **stderr** as `error: <short>` + detail + `hint: <fix>`, **sanitized of absolute host paths, internal struct names and stack traces**, reusing only Fail red (ANSI 203) for `error:` and Residual mute (ANSI 246) for `hint:` — no new colors (per design-system.md §Surface: cli → Component Patterns #5 and §Anti-Patterns → Per-Surface Bans / cli). This is the design-side mirror of the scope's artifact-hygiene rule about never persisting host paths or SUT log content.
- Raw artifact data belongs on stdout, human messages on stderr; ANSI must be stripped when piped and `NO_COLOR`/`TERM=dumb` honored via `anstream` — emoji is banned in machine-parseable piped output (per design-system.md §Surface: cli → Platform-Specific Notes and §Anti-Patterns → Per-Surface Bans / cli).
- Identity-bearing values this chunk asserts on — fingerprints, P-IDs (`P-017`/`P-018`/`P-074`), `run_id`, SLO tiers (`<20s`) and `latency_ms` — belong to the reserved mono status tier and must render in mono ID cyan / ANSI 117, right-aligned for `latency_ms`, never in the prose tier (per design-system.md §Typography Data row and §Surface: cli → Tokens).
- If the live leg blocks on an interactive prompt, the headless `agent-run.sh` path must not be gated: every `inquire` prompt is `isatty`-checked and the non-interactive policy decision is recorded to the artifact instead (per design-system.md §Surface: cli → Component Patterns #2 and §Anti-Patterns → Per-Surface Bans / cli). Whether the existing run path already satisfies this on the fingerprint-storm leg is research's question.
- If the leg's profile breaches the SUT load envelope, that renders as the run-level `[ENVIRONMENT-SUSPECT]` caption (ANSI 246, printed once above the per-P-ID lines, outside the lamp column) — a qualifier on the run, never a seventh lamp or a sixth `ReportState` (per design-system.md §Surface: cli → Component Patterns #4).

## Patterns to follow
- **Results / SLO table** (design-system.md §Surface: cli → Component Patterns #3): the 6-column `comfy-table` — P-ID · scenario · `state` · `slo_tier` · `latency_ms` · fingerprints — is the existing home for this family's measured verdicts, including any re-calibrated `<20s` tier; terminal width is detected dynamically, never hardcoded. Note the plan's explicit disambiguation: `conductor coverage` is a **separate** 4-column table with no verdict/state column, so a v2-11 coverage roll-up must not grow a state column.
- **Verdict / report-state lines** (design-system.md §Surface: cli → Component Patterns #4): the in-place `✓/✗/?/~/•` + prefix + P-ID + tier + latency line format is where P-017/P-018/P-074 outcomes print; reuse it rather than inventing a storm-specific output shape.
- **Error output** (design-system.md §Surface: cli → Component Patterns #5): the `error:`/`hint:` pair with its stderr-specific `IsTerminal` gate is the existing shape for the log-harvest reader's failure modes.
- **Paused-count hold-point, CLI mirror** (design-system.md §Surface: cli → Component Patterns #1 and §Motion → High-impact moments): if the leg surfaces an operator-pause, the `indicatif` spinner **stops in place at the exact value** with a bold ANSI 179 `HOLD — operator pause` line above the `inquire` prompt — it must never hide or animate to 100%.
- **Existing token-by-name pair discipline** (design-system.md §Surface: cli → Tokens, Residual-mute entry): any new recessive/de-emphasized caption reuses the shipped ANSI 246 ↔ `var(--status-residual)` pair with the text label carrying the signal, rather than adding a palette row.

## Anti-patterns to avoid
- NEVER let a `ManualCheck`, `KnownResidual` or `Blocked` outcome from this family read as `Fail` red, and never flash/blink/pulse a `Fail` — the storm verdict resolves motionless (design-system.md §Anti-Patterns → Rejected Defaults: flashing/pulsing alert; conflating "no result yet" with "failed").
- NEVER emit color-only signal or emoji in the machine-parseable path, and never colorize without the pipe/`NO_COLOR`/`TERM` check (design-system.md §Anti-Patterns → Per-Surface Bans / cli).
- NEVER print stack traces or absolute host paths in normal mode — only under `--debug`/`-v`, sanitized (design-system.md §Anti-Patterns → Per-Surface Bans / cli).

## Contract bindings
- **State color + text prefix** binds to a11y §Use of Color (SC 1.4.1): every `[PASS]`/`[FAIL]`/`[MANUAL]`/`[RESIDUAL]`/`[BLOCKED]` this leg emits carries the ASCII label so NO_COLOR and screen-reader paths lose nothing (design-system.md §Surface: cli → Component Patterns #4).
- **ANSI 117 / 114 contrast choice** binds to a11y §Contrast: the ID-cyan and nominal-green codes were chosen for legibility on dark terminals; dark-blue-on-black / dark-red-on-black is banned (design-system.md §Surface: cli → Platform-Specific Notes).
- **Artifact hygiene ↔ error rendering**: the scope's "never persist host paths or SUT log content into Conductor artifacts" rule is enforced at the render seam by design-system.md §Surface: cli → Component Patterns #5 (sanitized stderr); the security/obs plans own the redaction mechanism, design owns the output shape.
- **`ReportState` set ↔ core/report crates**: the six-treatment set and the run-level `[ENVIRONMENT-SUSPECT]` caption are a shared vocabulary with architecture's run-report envelope — a new assertion surface must map into the existing set, not extend it (design-system.md §Color Palette → Verdict vs ReportState note).

## Acceptance criteria contributions
- (design) Every P-017 / P-018 / P-074 outcome the leg prints carries its ASCII bracket prefix and glyph from the closed set (`[PASS]`/`[HOLD]`/`[FAIL]`/`[MANUAL]`/`[RESIDUAL]`/`[BLOCKED]`), with no color-only signal and no new lamp state added (per design-system.md §Surface: cli → Component Patterns #4).
- (design) Any new log-harvest failure path writes `error: <short>` + `hint: <fix>` to stderr, sanitized of absolute host paths / internal struct names / stack traces, reusing only ANSI 203 and ANSI 246 — zero new color tokens (per design-system.md §Surface: cli → Component Patterns #5).
- (design) P-IDs, fingerprints, `run_id`, `slo_tier` and `latency_ms` render in the reserved mono status tier (ANSI 117 ID-cyan), with table widths detected from the terminal rather than hardcoded (per design-system.md §Typography Data row + §Surface: cli → Component Patterns #3).
- (design) Piped output of the leg is ANSI-free and emoji-free, and the headless `agent-run.sh` path completes without blocking on an `inquire` prompt (per design-system.md §Anti-Patterns → Per-Surface Bans / cli and §Surface: cli → Component Patterns #2).
