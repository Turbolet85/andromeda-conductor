# a11y extract

## Relevance
Partial (narrow) — the chunk has no UI surface, but a11y's violation artifact reproduces the obs §6 envelope whose `fingerprints[]` field this chunk's semantics feed, and rendered fingerprint text carries a bound contrast/type token pair.

## Constraints
- a11y-plan.md §3 (Structured violation JSON schema) requires a11y violation artifacts to align **verbatim** to the obs §6 run-report envelope, with axe rule-id + `impact` + WCAG tags + node selector riding inside `fingerprints[]` and **no new top-level fields**. If this chunk alters that envelope's `fingerprints[]` field (name/type/arity), a11y's two verbatim reproductions must be amended in lockstep; whether the chunk touches the envelope at all — versus only exception-fp derivation inside `conductor-emit` — is research's question.
- a11y-plan.md §3 / §9 / §11 (SLO) require that artifacts folded into the obs envelope MUST NOT leak absolute host paths or internal seam-crate struct names (inherited from tests' Status JSON constraint). This is the same artifact-hygiene family as the chunk's `stacktrace_carries_no_absolute_host_path` invariant, but a11y's ban binds the a11y-side artifact and is not discharged by the emit-side invariant.
- a11y-plan.md §6 (Color contrast pairs) requires `--color-id-cyan`/`--color-base` at 4.5:1 (SC 1.4.3) for the monospace status-tier text that carries count / P-IDs / run_id / SLO timings / **fingerprints** — any fingerprint value surfaced in the desktop-webview run-report inherits that assertion.
- a11y-plan.md §6 (Typography tokens) requires fingerprints render under `--font-mono` as status/code text; the plan names no truncation/wrapping allowance for a changed fingerprint shape.
- a11y-plan.md §1 (A11y scope — cli entity, not-assertable) and §11 (Universal) require the chunk's Rust-tier surfaces (`conductor-emit`, `conductor-run` tests, scenario TOML, CLI render) be treated as **not-assertable**: no DOM/widget tree, no axe/Lighthouse reach, so no a11y gate attaches to them.
- a11y-plan.md §10 requires zero WCAG AA violations on the four must-be-accessible paths including the run-report view; a change in how many distinct fingerprints a storm yields does not relax that gate if it reaches the report render.

## Patterns to follow
- Envelope-tracking pattern (§3 + amendment 2026-06-16): a11y **reproduces** the obs §6 envelope and never re-shapes it — when obs's field set changes, a11y's reproduction follows in the same wrap; a11y proposes no envelope field of its own.
- Shared-field overload pattern (§3): `fingerprints[]` is one field with per-producer payload semantics — exception fingerprints on emission rows, (axe rule-id + WCAG-SC tag + DOM-relative selector) tuples on a11y rows. Redesigning exception-fp membership must not narrow the field's declared type in a way that excludes the a11y tuple payload.
- Selector/path hygiene pattern (§3): a11y node `target` values are stored as DOM-relative selectors / `data-testid`, never filesystem paths — the a11y-side analogue of the chunk's no-absolute-host-path invariant.
- Journal-row join pattern (§6 State-naming crosswalk): correlating a rendered lamp back to a journal row is keyed **verdict-first** on the display-label ↔ `verdict` / `state` crosswalk; any change to journal-row identity semantics must leave that join intact.

## Anti-patterns to avoid
- NEVER let a11y artifacts leak absolute host paths or internal seam-crate struct names into the obs §6 envelope (a11y-plan.md §11 § SLO).
- NEVER introduce a new top-level field into the violation envelope to carry richer fingerprint identity — it rides `fingerprints[]` (a11y-plan.md §3 Structured violation JSON schema).
- NEVER treat the cli / Rust-tier surfaces this chunk edits as accessibility-assertable; ASCII status prefixes + NO_COLOR text-pairing are output-stream discipline, not an ARIA verification path (a11y-plan.md §11 § Universal).

## Contract bindings
- **a11y ↔ obs §6 Log Format:** a11y-plan.md §3 reproduces the obs run-report envelope verbatim (twice — §1 harness spec and §3); `fingerprints[]` is the shared carrier. Any envelope-level change from this chunk binds both plans (precedent: 2026-06-16 amendment).
- **a11y ↔ tests Status JSON constraint:** artifact hygiene (no absolute host paths / no internal seam-crate struct names) is inherited into a11y artifacts per §3 / §9 / §11 SLO — parallel to, but independent of, this chunk's `stacktrace_carries_no_absolute_host_path`.
- **a11y ↔ design tokens:** `--color-id-cyan`/`--color-base` (SC 1.4.3 4.5:1) + `--font-mono` are the binding tokens for any fingerprint text rendered in the run-report (§6).
