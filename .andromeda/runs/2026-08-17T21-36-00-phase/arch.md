## Constraints
- **The derivation is the SUT's choice, not Conductor's.** architecture.md §Stack and Technologies (Hashing / digest row) + §Established Decisions [Read-Back Dependency Posture] require Conductor to *recompute Pulse's* derivation — blake3 over `exception_type` + `\0` + `normalize_stacktrace(render_stacktrace(spec))`, truncated to `FINGERPRINT_BYTES = 16`, rendered as 32 lowercase hex — under the Pulse-consistency mandate (blake3 pinned to the SUT's own pin). A token-leading re-alignment must be a transcription against a recorded Pulse HEAD, never a Conductor-side reinterpretation.
- **The plan's current P-017 narrowing is a TARGET-state mandate this chunk supersedes.** §Established Decisions [Read-Back Dependency Posture] presently requires the two identity narrowings — first `NORMALIZED_FRAMES = 3` lines, and of a frame's `file` only the **leading path segment** — byte-verified against `andromeda-pulse crates/buffer/src/fingerprint.rs:139-218` at HEAD `d090314` and pinned by a named unit test. Whether the shipped `exception.rs` still encodes that (vs. the `efabe8e` token-boundary guard) is research's question; the doc mandate is what changes here.
- **Crate-per-seam placement is compiler-enforced.** Per §Established Decisions [Module Boundaries] + §Infrastructure Patterns (directory tree) the fingerprint PRIMITIVE and the exception-event builder live in `conductor-emit`; `conductor-faults` owns only the fingerprint-STORM fault composed over it; `conductor-run` is the composition root above the seams. No new cross-seam edge and no new workspace member.
- **The load envelope's two sustained terms are asserted PER EMITTING PHASE, and the exemption ledger is empty.** Per §Occupied Resources (`contracts/pulse-load-envelope.toml`), a re-shaped variant mix must keep every emitting phase inside `max_sustained_storm_ms` and `max_sustained_rate_spans_per_s` unaided; `[[exempt]]` is held at exact-set equality in both directions, so it can only shrink under compulsion.
- **Scenario changes are declarative data, garde-validated at load.** Per §Conventions (Config conventions) + §Established Decisions [Scenario Config Format] / [Validation Library]: TOML under `scenarios/`, a phase's shape is `EmissionSpec { signal, occurrences, shape }` (`occurrences: 0` = a deliberate silence window), nested spec fields must `dive` and never `skip`.
- **Scope law + capability gates bound any coverage claim.** Per §Cross-cutting Patterns (Scope law) + §Established Decisions [Accepted Capability Set]: "no scenario without a P-ID" drawn from `contracts/pulse-capabilities.toml`'s accepted set; `check_sut_drift` (accepted ↔ code-native classification) and `check_scenario_backing` (the `UNBACKED_AUTO` pin, exact-set) must stay green — the chunk's "no new capability claimed" boundary is exactly what those gates enforce.

## Patterns to follow
- **Transcribe-and-pin.** §Established Decisions [Read-Back Dependency Posture] records the derivation with its source file, line range and SUT HEAD, plus a named unit test that pins the narrowing (`exception.rs::only_the_leading_path_segment_reaches_the_preimage`). The re-alignment should follow the same shape: new HEAD recorded, new pinning test replacing the retired one.
- **Duplicate-occurrence sweep for retired doc claims.** The amendment history shows this project twice landing a supersession at §Established Decisions and having to re-apply it at §Standard Contracts; the path-narrowing claim currently sits in §Read-Back Dependency Posture — check whether the same rule is restated elsewhere before treating one edit as complete.
- **Composition-root test placement.** Storm grading lives in `conductor-run/tests/` (§Occupied Resources Crate names — `conductor-run` is the run composition root shared by both bins), above the seams; unit-tier variant tests stay in `conductor-emit`.
- **Pinned test runner.** §Infrastructure Patterns (Build system): `cargo nextest` on the zero-retry `ci` profile (`.config/nextest.toml` — no retries mask flakes, the determinism invariant) plus `cargo test --doc`; clippy in the same gate.

## Anti-patterns to avoid
- **Inventing or "fixing" the fingerprint semantics on Conductor's side** — algorithm, preimage, truncation and hex width are the SUT's per the Pulse-consistency mandate (§Stack and Technologies · §Established Decisions [Read-Back Dependency Posture]).
- **Adding a `[[exempt]]` entry or raising a load-envelope term to make a re-shaped storm fit** — the ledger is empty and exact-set in both directions (§Occupied Resources `contracts/pulse-load-envelope.toml`).
- **Introducing a new `CONDUCTOR_*` env handle, contracts artifact, or on-disk artifact for variant/fingerprint semantics** — the env namespace is enumerated and the contracts manifests deliberately carry NO `CONDUCTOR_*` override handles (§Occupied Resources).
