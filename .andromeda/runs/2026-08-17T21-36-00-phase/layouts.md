## Constraints
- The cli results/SLO table is exactly **6 columns** — P-ID · scenario · state · slo_tier · latency_ms · **fingerprints** — with terminal-detected width; layout-templates.md §cli Component — Primary content block 1 requires that shape, and §cli IA notes (Command model) requires output structure stay stable across versions because downstream agents parse it (adding a column without a `--format` flag is a breaking change). A fingerprint-semantics redraw must not add, rename, split or drop that column.
- The `fingerprints` cell is a **Data-role identifier** rendered in the ID-cyan mapping (ANSI 117 ↔ `color-id-cyan`), alongside P-ID / `run_id` / latency_ms (per layout-templates.md §cli Component — Primary content block 1 and §cli Component — Primary content block 2). If the redesign yields more than one fingerprint per check, whatever is surfaced still occupies that one cell in that one mapping — a fingerprint is data, never a color-coded state.
- The per-P-ID bracket/lamp set is **closed at six** (`[PASS]` / `[HOLD]` / `[FAIL]` / `[MANUAL]` / `[RESIDUAL]` / `[BLOCKED]`), with exactly one run-level non-lamp qualifier (`[ENVIRONMENT-SUSPECT]`) riding outside the lamp column (per layout-templates.md §cli Component — Primary content block 2). Retiring the `PathVariant` / `RelativePathVariant` same-fp distinction must not mint a seventh lamp, a new bracket label, or a new webview lamp glyph for "different-fp variant".
- Phase names from `scenarios/fingerprint-storm.toml` are **operator-facing on both surfaces**: layout-templates.md §desktop-webview Component — Header requires the titlebar phase line to name the current operational segment (`fingerprint-storm` is one of its named examples), and §cli Output structure (`conductor run <scenario>`) requires the `→ phase <name>` line. Any per-phase rename in the storm scenario changes what both surfaces render verbatim.
- Every status must be **paired with an ASCII text prefix** so signal is never color-alone and survives `NO_COLOR` / piping / screen readers (per layout-templates.md §cli Signature placement and §cli IA notes → Pipe discipline). Raw artifact data stays on stdout, human messages on stderr.
- If this chunk names a new P-ID in `scenarios/fingerprint-storm.toml`, layout-templates.md §cli Primary screens (`conductor coverage [--write]`) requires the roll-up caption's `(N unbacked)` qualifier to be **manifest-derived, never a literal**, to qualify the auto term only (never a fifth summand), to be omitted at zero, and to render identically on all three surfaces via the coverage matrix's `unbacked` prop sourced from the `unbacked_auto` command (never mirrored in TypeScript). The chunk's §Boundaries says no new capability is claimed, so whether this fires at all is P5's call.

## Patterns to follow
- **Run-level qualifier outside the lamp column** — `[ENVIRONMENT-SUSPECT]` (layout-templates.md §cli Output structure `conductor run` + §cli Primary content block 2): printed once per run above the verdict lines, ASCII bracket always printed, ANSI 246 reuse with no new token entry, omitted entirely when inapplicable. This is the sanctioned shape if the chunk ever needs to surface a run-level fingerprint statement — not a new lamp.
- **Recessive treatment for a non-outcome classification** — the Mode cell's out-of-scope value (layout-templates.md §desktop Component — Primary content block 1): `--status-residual` ↔ ANSI 246 ↔ Markdown emphasis, label always rendered, deliberately NOT `--status-fail` / `--count-blocked`, and never a seventh lamp state.
- **Absent measurement renders `—` / null, never a red error** — the `Blocked` / `Residual` row convention (layout-templates.md §cli Component — Primary content block 1; §desktop Component — Primary content block 2). Applies to a fingerprint cell that has no value for a given check.
- **Placeholder form for derived values in samples** — layout-templates.md §cli Primary screens elides fingerprint hexes (`a3f9c1b…`) and, since the 2026-08-16 amendment, writes the unbacked count as `(N unbacked)` rather than a baked number. Any doc sample this chunk touches follows the same de-literalized form.
- **Same tokens by name, adapted not forked** across desktop CSS vars ↔ cli ANSI ↔ Markdown artifact (layout-templates.md §cli IA notes → Multi-surface coordination; §desktop IA notes → Multi-surface coordination).

## Anti-patterns to avoid
- Adding a seventh lamp state, a new bracket label, or a fingerprint-variant status glyph — the per-P-ID set is closed at six (layout-templates.md §cli Component — Primary content block 2).
- Conflating the 6-column results/SLO table with the 4-column `conductor coverage` matrix (P-ID · Title · Category · Mode, no state column, no bracket prefix) — the `fingerprints` column exists only on the results/SLO shape (layout-templates.md §cli Component — Primary content block 1).
- Baking a fresh derived literal (fingerprint hex, unbacked count, phase duration) into a wireframe sample — layout-templates.md §cli Primary screens states every number is manifest-derived, never a literal.
