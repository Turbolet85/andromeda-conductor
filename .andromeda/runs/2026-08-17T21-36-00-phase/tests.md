This matches the chunk's "no live leg is required to land this" boundary.
- Live-Pulse legs are an **operator/local `workflow_dispatch` gate, never a CI gate**; CI runs the stub legs only (per test-plan.md §9 Live-Pulse scenarios + §11 CI). The chunk's "live re-proof of the storm family is a separate question" is therefore the plan's own posture, not a concession — but whether `crates/conductor-run/tests/storm_harvest.rs` is actually gated so the workspace CI leg stays green is research's question.
- §6 requires the fingerprint-storm verification signal to be: envelope `fingerprints` **present but expected `[]`** under deterministic L4, read-back token checks **DECLARE-ONLY** (`retrieve_report` is permanently `degraded_mode` in this mode), and the live proof carried by the test-only harvest of Pulse's `triage.pattern.storm.detected` line (`cue_kind = "retry_storm"` · `severity_hint` · `occurrence_count` · `fingerprint_hex`) at the `conductor-run` unit tier (per test-plan.md §6 Scenario: Fingerprint-storm). The storm-grading restoration must not revive a populated-`fingerprints` claim or a read-back token check.
- Scenario config files under `scenarios/` are **committed declarative serde+garde fixtures**, one per P-ID, carried as a valid + invalid matrix (per test-plan.md §7 Seed strategies → Fixture files). §1's config-validation trigger requires garde to reject out-of-range values *at load* including bounded per-phase occurrences and the per-shape emission rules — and requires the negative-test suite to catch a nested spec field annotated `skip` rather than `dive`. Whether the chunk's revised variant-mix in `fingerprint-storm.toml` stays inside executing garde rules is research's question.
- Seeded **stream goldens** are committed per-crate under `<crate>/tests/snapshots/`, one file per test-file family × seed (`replay__*` · `pacing__*` · `dispatch_wire__*`), with no wall-clock field to redact (the dispatch-tier projection excludes every `*_time_unix_nano`); CI is fail-don't-write (per test-plan.md §7 Golden artifacts). Whether redrawing the variant set shifts `dispatch_wire__storm_stream_seed_*` / `pacing__*` content is research's question.
- Zero-flakiness budget: no `retries`, no quarantine-by-retry; determinism is enforced upstream via the seeded generator, so a shifted stream is a real semantic change to be re-golden-ed, not a flake (per test-plan.md §10 Zero-flakiness budget).
- Artifact-sanitization is a **required-field rule on the journal/envelope** — no absolute host paths, no internal struct names, asserted by a negative test (per test-plan.md §3 Log format Required fields + §11 Test Data). This is the plan-side anchor under the chunk's `stacktrace_carries_no_absolute_host_path` invariant, which must keep holding through the redesign.

## Patterns to follow
- Table-driven variant matrices as rstest `#[rstest]` + `#[case]` rows (the plan's grouping mechanism for P-ID and garde valid/invalid matrices), with crate-local `#[cfg(test)] mod tests` inside the seam source file and per-seam isolation via `cargo nextest run -p conductor-<seam>` (per test-plan.md §4 Conventions + Fixture pattern; §2 Test directory conventions). Whether `exception.rs`'s existing variant tests already use `#[case]` rows is research's question.
- Unit-tier canonical goldens via **exact-string `assert_eq!`** (the `verdict.rs`/`report_state.rs`/`scenario.rs` serialization-golden pattern), with insta reserved as the E2E journal-golden mechanism (per test-plan.md §4 conductor-report bullet).
- Seeded-fixture bootstrap: the `#[fixture]` seeded `conductor-timeline` generator, no developer-seeded DB; `#[tokio::test(flavor="current_thread", start_paused=true)]` + `tokio::time::advance` where scheduling is involved (per test-plan.md §3 Test data bootstrap + §4).
- Name the SET, not a literal, when an assertion tracks SUT-derived facts — the plan's standing de-hardcode discipline for manifest-relative and label-set assertions (per test-plan.md §1 Critical paths Path 6 + §6 Selector strategy).

## Anti-patterns to avoid
- NEVER test implementation details (private fns / internal struct fields) or write brittle assertions against fixture-internal values — assert the public seam API and observable output (per test-plan.md §11 Unit). The redrawn variant model must be asserted through the recomputed derivation, not through the variant enum's internals.
- NEVER refresh a golden through `cargo insta review`'s interactive accept UI — insta runs CI/assert (fail-don't-write) mode only (per test-plan.md §11 Universal + §7 Golden artifacts).
- NEVER fake Pulse's *reaction* as a CI verdict — the stub proves wiring only; Pulse's actual storm behavior stays a live/local-gate assertion (per test-plan.md §11 Test Strategy).
