# arch extract

## Relevance
Relevant — arch owns the envelope/tier/verdict contracts the leg grades against, the crate-seam placement of any edit, and the operator-gate-not-CI rule for live legs.

## Constraints
- **The live leg is an operator/local gate, never a CI gate.** Dynamic end-to-end scenario proof requires a live Pulse (`mcp-server` feature + `ANDROMEDA_PULSE_MCP_ENABLED`) and is explicitly excluded from CI; `error-baseline-spike` is named by name as one of these dynamic proofs. Any unit/golden addition riding along must pass deterministically under the pinned zero-retry `ci` nextest profile — retries are banned because they mask the determinism invariant (per architecture.md §Infrastructure Patterns — CI/CD approach + Build system; §Established Decisions [CI/CD]).
- **Latency is journal-relative and tier-banded.** Every SLO measurement is required to be `read_back_observed_at − journal_emitted_at`, never wall-clock-from-test-start; hard/deterministic SLOs get tolerance scaled to the `<5s` / `<20s` / `<90s` tiers, while the sample-count floors this chunk names (50-sample latency, 10-span error-rate) and model-interpretive timings are required to route to the calibration-region bucket instead of hard-failing (per architecture.md §Established Decisions [Timing-Tolerance Model]; §Design Philosophy — Journal-relative ground truth).
- **The verdict/error wall governs every grading outcome.** A measurement disagreement must surface as a `Verdict`/`ReportState` VALUE; `Result::Err` is reserved for harness faults (transport down, MCP unreachable, config/manifest parse). `state` is a closed five-variant set (`Pass`/`Fail`/`ManualCheck`/`KnownResidual`/`Blocked`); a blocked row must populate identity fields only (`run_id`/`seed`/`scenario`/`p_ids`/`slo_tier`) with `verdict`/instants/`latency_ms`/`fingerprints` NULL, and cross-run queries must exclude those NULL-measurement rows (per architecture.md §Cross-cutting Patterns — Verdict/error wall; §Standard Contracts — Readiness gate; §Established Decisions [Error Handling]).
- **The deterministic/interpretive split decides which check shape is legal.** Baseline math, error-rate and lifecycle-timing claims are hard pass/fail; model-interpretive claims (severity choice, hypothesis quality) are calibration-region and must never be hard-failed on exact values, mapping `CalibrationRegion→ManualCheck` by default with the run-report lamp chosen verdict-first (per architecture.md §Established Decisions [Probabilistic-Assertion Policy]). This is the rule the §1 token-gradeability settlement and the §4 retire-to-declare-only disposition must land inside.
- **The run-report envelope and `runs.db` column types are fixed contracts.** The per-check envelope's field set is pinned, `slo_tier` is a closed TEXT enum over exactly `<5s`/`<20s`/`<90s`, `latency_ms` is INTEGER milliseconds (NULL for blocked), and the two instant columns are TEXT RFC-3339 — no migration framework exists to coerce a type later, so a re-calibration may move a tier VALUE but never the enum or the shapes (per architecture.md §Standard Contracts — Run report envelope + Timestamp formats; §Conventions — Data model conventions).
- **Scenario TOML edits stay inside the declarative-config contract.** Scenario config is serde-deserialized + garde-bounds-checked at load; a nested spec field must `dive` and never `skip`; `EmissionShape::Error { error_percent: u32 }` is an integer percent ∈ 0..=100 (so `PhaseSpec`/`Scenario` keep `Eq`); `occurrences: 0` is a deliberate silence window; and every named P-ID must be in `contracts/pulse-capabilities.toml`'s accepted set with a matching code-native classification row (per architecture.md §Conventions — Config conventions; §Established Decisions [Validation Library] + [Accepted Capability Set]).
- **Re-shaping phases is bounded by the SUT load envelope.** The two asserted terms are judged PER EMITTING PHASE (`max_sustained_storm_ms`, `max_sustained_rate_spans_per_s`); `check_load_envelope` (static catalog gate) and `LoadEnvelope::classify` (the `[ENVIRONMENT-SUSPECT]` caption) read ONE shared basis, and the `[[exempt]]` ledger is held to exact-set equality in both directions and is currently recorded EMPTY — so if the sample floors force more emission, adding an exemption is a gate-level change, not a scenario edit (per architecture.md §Occupied Resources — `contracts/pulse-load-envelope.toml`).

## Patterns to follow
- **Crate-per-seam placement.** Grading/read-back extraction belongs in `conductor-verify`, journal + report + `runs.db` in `conductor-report`, preflight/execute/persist composition in `conductor-run`, the fingerprint + exception-event primitive in `conductor-emit`, scenario configs under `scenarios/` (one per P-ID), pinned SUT records under `contracts/` (per architecture.md §Occupied Resources — Crate names; §Infrastructure Patterns — directory structure). Whether the shipped per-check extraction and dispatcher already suffice for grading this family without a seam change is research's question.
- **Preflight-gate-before-trust.** The MCP `initialize` + tool-presence + run-contract-terms + canary-freshness gate runs once at suite start and its five named preconditions are ordered so an unmet launch condition is surfaced BEFORE the canary symptom; on `ready:false` dependent auto scenarios are emitted `blocked` with the named precondition, never downgraded (per architecture.md §Standard Contracts — Readiness gate).
- **Sidecar/env wiring the operator recipe rides on.** `ANDROMEDA_PULSE_DATA_DIR` is propagated by Conductor to the spawned `andromeda-pulse-mcp` sidecar (the read-back tools filter incidents by the `workspace` column, so a divergence returns zero rows forever); `ANDROMEDA_PULSE_L4_DETERMINISTIC` and `ANDROMEDA_PULSE_MCP_ENABLED` are Pulse-side and asserted NOT set by Conductor — L4-deterministic is only READ in Conductor's own shell as the run contract's `shell-declaration` proxy; `CONDUCTOR_PREFLIGHT_TIMEOUT` carries a run-contract-derived effective FLOOR (`[incident_formation].min_canary_poll_seconds`) and overrides only upward (per architecture.md §Occupied Resources — Environment variables).
- **Reading Pulse's harvest telemetry.** Arch pins the reading discipline for the surface premise 6 asks about: windowed gauges (`tracked_fingerprints_count` — 60s window over DISTINCT fingerprints, sampled after eviction) must never be read as evidence of absence; the window-immune discriminators are the cumulative counters beside them (`storms_detected_total`, `fingerprints_evicted_total`) (per architecture.md §Occupied Resources — `contracts/pulse-run-contract.toml`).
- **Artifact naming/stamping.** `run_id` is the filesystem-safe hyphen stamp (it is the `runs.db` PK and the stem of `<run_id>.jsonl` / the report), in-payload instants are colon-delimited RFC-3339, evidence markdown is kebab-case; journal wall-clock stamps come from `std::time`, never tokio's clock (per architecture.md §Standard Contracts — Timestamp formats; §Conventions — Naming patterns; §Cross-cutting Patterns — Determinism discipline).

## Anti-patterns to avoid
- **No new inbound surface.** Conductor exposes no HTTP/network service and no listener of its own — loopback OTLP/gRPC egress to `127.0.0.1:4317` plus an MCP stdio client are the whole outbound set; the port-occupier fault scenario is the single deliberate bind exception and is not this family (per architecture.md §Cross-cutting Patterns — Trust boundary; §Established Decisions [Backend Framework]).
- **No silent downgrade or vacuous pass.** A check whose surface cannot carry its assertion must not be left as a passing `Absent`, and an unmeasurable scenario must be `Blocked` with a named precondition rather than pass/fail/manual-check (per architecture.md §Standard Contracts — Readiness gate; §Established Decisions [Read-Back Dependency Posture]).
- **No un-registered resource creep.** New env vars must stay inside the reserved `CONDUCTOR_*` namespace and be registered; the `contracts/` manifests are deliberately given NO `CONDUCTOR_*` override handle (the capability-manifest precedent) — do not add one (per architecture.md §Occupied Resources — Environment variables + On-disk artifacts).

## Contract bindings
- **Run report envelope ↔ tests/obs:** the envelope field set + `runs.db` row shape are arch's; the leg's evidence pointers (`runs/<run_id>.jsonl`, `runs.db` rows) and the `verify.readback.observe` key-set witness in `conductor-verify/tests/readback.rs` are the tests/obs harness reading arch's contract — a key-set diff against the pinned baseline is a contract-drift signal, not a scenario failure (arch §Standard Contracts ↔ test-plan/obs-plan §3).
- **Timing-tolerance tiers ↔ tests:** which `[[expected]]` checks hard-fail vs route to calibration-region is decided by arch's deterministic/interpretive split; test-plan owns how they are exercised (arch §Established Decisions [Timing-Tolerance Model] + [Probabilistic-Assertion Policy]).
- **Load envelope ↔ tests:** if phases are re-shaped for the sample floors, the static catalog gate `check_load_envelope` and the exact-set `[[exempt]]` ledger are the binding assertion surface (arch §Occupied Resources ↔ test catalog gates).
- **Dependency admission ↔ security:** the PREREQ `cargo audit` re-check binds arch's §Stack registry + `deny.toml` accepted-exception prose to security-plan §Dependency Security; arch records `cargo deny` green as a state SEPARATE from `cargo audit`'s external advisory-DB fault, so the two must be verified independently (arch §Infrastructure Patterns — Build system).
- **Fingerprint derivation ↔ emit seam:** the transcription-equality ride-along compares Conductor's `conductor-emit` derivation against Pulse's own; arch mandates the derivation IS Pulse's (blake3, 32 lowercase hex, first `NORMALIZED_FRAMES = 3`, token-leading normalization) — a live disagreement is a transcription defect against that mandate, not a scenario verdict (arch §Established Decisions [Read-Back Dependency Posture]).

## Acceptance criteria contributions
- (arch) Every change lands inside the crate-per-seam boundary — scenario configs under `scenarios/`, grading in `conductor-verify`, persistence in `conductor-report`, composition in `conductor-run` — with no new workspace member and no new `contracts/` manifest (per architecture.md §Occupied Resources — Crate names; §Infrastructure Patterns — directory structure).
- (arch) Measured `latency_ms` is journal-relative (`read_back_observed_at − journal_emitted_at`) and any re-calibrated `slo_tier` is one of exactly `<5s` / `<20s` / `<90s`, with `latency_ms` INTEGER-ms and the two instants TEXT RFC-3339 in `runs.db` (per architecture.md §Established Decisions [Timing-Tolerance Model]; §Conventions — Data model conventions).
- (arch) The leg stays an operator/local gate: no CI job gains a live-Pulse dependency, no new `CONDUCTOR_*` env var / port / listener is introduced, and any added deterministic test passes under the zero-retry `ci` nextest profile (per architecture.md §Infrastructure Patterns — CI/CD approach + Build system; §Occupied Resources — Environment variables).
- (arch) Sample-floor shortfalls and interpretive claims resolve to `CalibrationRegion`/`ManualCheck` or a named `Blocked` precondition — never a hard-fail on an interpretive value and never a vacuously-passing check (per architecture.md §Established Decisions [Probabilistic-Assertion Policy] + [Read-Back Dependency Posture]).
