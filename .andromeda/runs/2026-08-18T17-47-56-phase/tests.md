## Relevance
Relevant — this chunk is the live/operator-gate leg of Critical Path 1, which test-plan §6 names verbatim as `Scenario: Headless deterministic scenario run with MCP read-back (error-baseline-spike)`.

## Constraints
- The live-Pulse leg is an **operator/local gate via `workflow_dispatch` or `scripts/agent-run.sh`, NOT a CI gate**; CI runs the rmcp-stub legs only (per test-plan §9 CI Integration → Live-Pulse scenarios, restated as a ban in §11 CI). Any unit/golden additions this chunk lands must therefore be CI-deterministic under the zero-retry bar — flakes are quarantined, `retries` must stay 0 (per test-plan §10 Zero-flakiness budget).
- test-plan §6 (`error-baseline-spike` scenario) requires the leg's verification signal to be: exit 0 with `[PASS]` on stdout; a `runs.db` row with `verdict="Pass"` / `state="Pass"` and `latency_ms` within `slo_tier` read by **bound-parameter `SELECT`**; `runs/<run_id>.jsonl` present and parsing to the envelope; MCP read-back confirming Pulse's reaction on the live leg; and a same-seed re-run yielding an identical stream shape. Whether the shipped scenario TOMLs' `[[expected]]` checks already produce that signal is research's question (scope premise 5).
- `Blocked` / `ManualCheck` / `KnownResidual` / `CalibrationRegion` are reported envelope states and must NOT become non-zero process exits; only a hard `Fail` exits non-zero (per test-plan §3 `run` exit-code semantics + §11 E2E stack-specific ban). A failed preflight must surface as `state="Blocked"` with the named precondition, never a silent downgrade (per test-plan §3 `boot` readiness signal).
- `boot` carries **two derived budgets, never a literal**: the in-process canary poll (`CONDUCTOR_PREFLIGHT_TIMEOUT`, raised to `contracts/pulse-run-contract.toml` `[incident_formation].min_canary_poll_seconds`) and the `agent-run.{sh,ps1}` wall-clock wrapper derived per invocation as `warmup_ms/1000 + poll + margin`; a missing contract term is a hard exit 2 (per test-plan §3 `boot` → Timeout). This is the operator-recipe item "poll budget ≥ the contract floor" in the chunk scope.
- The Run-report envelope is fixed at the 11 named fields and is serialized identically into the `runs.db` row, the JSONL journal, and the Markdown report; journal lines are one JSON object per line with `journal_emitted_at` from `std::time::SystemTime` (never tokio's virtual clock) and must leak no absolute host paths or internal struct names (per test-plan §3 Status endpoint shape + Log format; §11 Test Data stack-specific ban).
- Golden artifacts are committed per-crate under `<crate>/tests/snapshots/`, one file per test-file family × seed, in the two families (envelope/journal, redacting `run_id`/timestamps; and seeded stream — `replay__*` · `pacing__*` · `dispatch_wire__*`, which exclude every `*_time_unix_nano` rather than masking it), CI fail-don't-write, **never** `cargo insta review` (per test-plan §7 Seed strategies → Golden artifacts). This governs the folded Plain-path stream-golden ride-along candidate if the plan takes it.
- `cargo audit --deny warnings` and `cargo deny check` (advisories/licenses/bans/sources) green plus an un-drifted committed `Cargo.lock` are binding build-failure conditions and may not be skipped "just this once" (per test-plan §9 Build failure conditions, §10 Build failure conditions, §11 CI + Quality) — the frame for this chunk's standing `cargo audit` PREREQ.

## Patterns to follow
- **Harvest-surface substitution** (per test-plan §6 Scenario: Fingerprint-storm, as amended 2026-08-16): when a read-back surface provably cannot carry a scenario token, the token check retires to **declare-only** and the live proof relocates to a test-only harvest of Pulse's own telemetry line, asserted at the `conductor-run` unit tier on the operator/live gate. Scope premise 6 (which Pulse line carries the error-rate/latency verdict) is the direct analogue of `triage.pattern.storm.detected`.
- **CLI E2E driver shape** (per test-plan §6 driver table + §6 Scenario 1 steps): `assert_cmd` `Command::cargo_bin("conductor")` with `CONDUCTOR_RUNS_DIR` → `assert_fs::TempDir` and **stdin closed** to prove the headless path is never blocked on an interactive prompt; assertions on NO_COLOR-stable bracket labels — the closed six-label lamp set plus the run-level non-lamp `[ENVIRONMENT-SUSPECT]` qualifier (per test-plan §1 Surfaces → cli Signal, §6 Selector strategy).
- **`status` is a disk read, not an endpoint** (per test-plan §3 `status`): bound-parameter `rusqlite` `SELECT` on the `runs.db` row for typed assertions, or `jq -e '<predicate>'` on `runs/<run_id>.jsonl` for the shell-level gate. This is the shape the chunk's evidence pointers (`runs/<run_id>.jsonl` + `runs.db` rows) should be read and cited in.
- **Per-check read-back extraction is a separate tier from the canary** (per test-plan §5 Cross-module patterns, as amended 2026-08-16): `query_incident_list` carries the canary freshness round-trip; `retrieve_telemetry_slice` / `retrieve_report` are per-check readers the canary no longer calls, and malformed responses must degrade to empty rather than panic. The chunk's `verify.readback.observe` key-set witness / pinned baseline diff belongs at this tier.
- **Fixtures and determinism** (per test-plan §7 Seed strategies + §3 Test data bootstrap): seeded `conductor-timeline` generator via rstest `#[fixture]`, in-memory `runs.db` per unit test, `assert_fs::TempDir` file DB for cross-process legs; no developer-seeded DB.

## Anti-patterns to avoid
- NEVER fake Pulse's *reaction* as a CI verdict — the rmcp stub canary proves MCP wiring only; Pulse's actual behavior is a live/local-gate assertion (per test-plan §11 Test Strategy, stack-specific), and the live-Pulse scenarios must never be wired as a CI gate (per test-plan §11 CI, stack-specific).
- NEVER leave a check that can only pass vacuously — the `Absent` that passed against text which cannot carry the token is the recorded failure mode; the disposition is declare-only plus a harvest assertion, not a green `Absent` (per test-plan §6 Scenario: Fingerprint-storm, amended 2026-08-16).
- NEVER use `sleep(N)` for synchronization on the live leg — wait on an explicit signal (envelope `state`, a JSONL journal line, exit code) (per test-plan §11 E2E).

- **tests §3 ↔ obs §3 (log format):** test-plan §3 is the SOURCE OF TRUTH for the JSONL journal format; obs derives its product-side envelope from it, and the field-allowlist/redaction layer is the one obs-owned piece, asserted here by a negative test (per test-plan §3 → Bootstrap phases → log-format-bind-with-obs).
