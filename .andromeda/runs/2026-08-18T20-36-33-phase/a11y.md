## Constraints
- The cli / `agent-run` / harness surface is **not-assertable**: no ARIA, axe, Lighthouse or WCAG obligation attaches to `scenarios/*.toml`, `crates/conductor-run`, or `scripts/agent-run.sh`; ASCII status prefixes / NO_COLOR text-pairing are output-stream discipline, **not** an a11y verification path (per a11y-plan §1 A11y Scope Summary + §11 A11y Anti-Patterns → Universal).
- a11y §3 requires the a11y violation artifact to reproduce the obs §6 run-report envelope **verbatim** (a11y narrows; obs fixed the schema). If this chunk changes that envelope's field set, a11y-plan §3's reproduction must be amended in lockstep (per a11y-plan §3 Structured violation JSON schema). Whether this chunk touches any envelope field at all is research's question.
- `slo_tier` is reproduced in a11y §3 as the closed enum `<5s | <20s | <90s`; the chunk's expected `<20s` → `<90s` re-declaration stays inside it, but a *new* tier string would put a11y's reproduction out of sync with obs (per a11y-plan §3 Structured violation JSON schema).
- Any `state` / `verdict` the leg row records must resolve through the state-naming crosswalk to exactly one of the six lamp display labels (`Pass`/`HOLD`/`Fail`/`Blocked`/`Manual`/`Residual`), **verdict-first**: `verdict == CalibrationRegion` ⇒ HOLD lamp regardless of `state` (per a11y-plan §6 Visual Design Verification → State color tokens, State-naming crosswalk). The chunk's "read-back honestly Blocks" path maps to the `Blocked` lamp (state-only, no verdict).
- Artifacts riding the envelope MUST NOT leak absolute host paths or internal seam-crate struct names — a11y inherits this from tests' Status JSON constraint and it applies to any leg capture / harvest predicate recorded under the envelope (per a11y-plan §3 Structured violation JSON schema + §11 SLO).
- No a11y gate is added by this chunk: the webview axe/contrast/keyboard step is operator/local-gated on the `ubuntu-latest`+`xvfb` `wdio run` job, and this chunk's gates (nextest `ci` / doctests / clippy / `cargo deny` / `cargo audit`) carry no a11y lane (per a11y-plan §9 CI Integration).

## Patterns to follow
- **Envelope-reproduction tracking**: when the obs §6 envelope gained a field, a11y amended its verbatim reproduction in the *same* chunk rather than drifting (see amendment history below) — same discipline applies if this chunk moves the envelope (per a11y-plan §3).
- **No new top-level fields**: a11y folds rule-id / WCAG-SC tag / selector tuples into the existing `fingerprints[]` array instead of extending the envelope; any new witness this chunk wants recorded should follow the same "ride an existing field" discipline (per a11y-plan §3 Structured violation JSON schema).
- **Verdict-first lamp precedence** when a `CalibrationRegion` verdict co-occurs with a `ManualCheck` state — join/identify HOLD on `verdict`, never on `state` (per a11y-plan §6 State-naming crosswalk).
- **Selector/identifier hygiene**: DOM-relative selectors or `data-testid`, never filesystem paths, in anything folded into the envelope (per a11y-plan §3).

## Anti-patterns to avoid
- NEVER treat the cli surface as accessibility-assertable — do not let this chunk's acceptance claim an a11y property from ASCII prefixes / NO_COLOR output (per a11y-plan §11 Universal).
- NEVER claim WCAG conformance without machine-verifiable axe-core / colorjs.io / Lighthouse JSON — no leg-verdict written here may assert a11y conformance (per a11y-plan §11 Strategy).
- NEVER let artifacts leak absolute host paths or internal seam-crate struct names into the obs §6 envelope (per a11y-plan §11 SLO).
