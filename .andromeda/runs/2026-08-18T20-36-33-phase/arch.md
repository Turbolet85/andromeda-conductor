## Relevance
Relevant (partial) — arch governs crate placement, scenario-config/envelope contracts, `slo_tier` + journal-relative measurement, the seed/env precedence rule, and the operator-gate boundary; the SUT-behavior premises (restart cue gating, P-016/P-057 thresholds) are research's to measure, not arch's to assert.

## Constraints
- The live restart-suppression leg is an **operator/local gate, never a CI gate** — architecture.md §Infrastructure Patterns (CI/CD approach) names `restart-suppression` explicitly as one of the three dynamic end-to-end proofs requiring a live Pulse with the `mcp-server` feature + `ANDROMEDA_PULSE_MCP_ENABLED`, while CI stays `cargo build` / nextest / clippy only (also architecture.md §Established Decisions [CI/CD]). No leg artifact may become a CI dependency.
- Scenario content stays **declarative data validated at load**: TOML deserialized + garde bounds-checked via `Scenario::from_toml_str_with(&str, &CapabilityManifest)`, "no scenario without a P-ID", and P-015/P-016/P-057 must be members of `contracts/pulse-capabilities.toml`'s accepted set — shape (garde `pid_format`) and membership (`check_capabilities`) are separate layers (per architecture.md §Established Decisions [Scenario Config Format] + [Accepted Capability Set], §Conventions Naming patterns). A phase's emission is declared data (`EmissionSpec { signal, occurrences, shape }`, `occurrences: 0` = a deliberate silence window; `EmissionShape::Error { error_percent: u32 }` ∈ 0..=100) per architecture.md §Conventions (Config conventions) — the gap phase and the error phases are config, not new dispatch code.
- Any TOML re-shape must clear the **two asserted per-emitting-phase load-envelope terms** (`max_sustained_storm_ms`, `max_sustained_rate_spans_per_s`; `max_scenario_duration_ms` is recorded-not-asserted), and `check_load_envelope` (static catalog gate) and `LoadEnvelope::classify` (the per-run `[ENVIRONMENT-SUSPECT]` caption) MUST read one shared basis. The `[[exempt]]` ledger is held at exact-set equality in both directions and is currently EMPTY — it can only shrink under compulsion (per architecture.md §Occupied Resources `contracts/pulse-load-envelope.toml`).
- `slo_tier` is a **closed TEXT enum over exactly `<5s`/`<20s`/`<90s`** and latency is always `read_back_observed_at − journal_emitted_at`, never wall-clock-from-test-start; wall-clock journal stamps come from `std::time::SystemTime`/`Instant`, never tokio's virtual clock (per architecture.md §Conventions Data model conventions, §Established Decisions [Timing-Tolerance Model], §Cross-cutting Patterns Determinism discipline). A `<20s` → `<90s` re-declaration must be justified on that journal-relative basis, not on the ~177s scenario window.
- Config precedence is **files over env defaults, and CLI flags over env** (architecture.md §Cross-cutting Patterns Config management); `CONDUCTOR_SEED` is documented as an override where "the equivalent CLI flag takes precedence; env supports `scripts/agent-run.sh` parameterization" (§Occupied Resources Environment variables). Under that rule a harness-injected `SEED` env default outranking a TOML-declared seed inverts the stated precedence — so the conforming disposition is "stop overriding TOML-declared seeds"; recording the override as intended would require amending arch's precedence rule. Whether `agent-run.sh` currently forces it is research's question to confirm at source.
- Suppression/bypass logic is classified a **deterministic claim → hard pass/fail**, while model-interpretive claims are calibration-region → `ManualCheck` via `Verdict::default_report_state` (`Pass→Pass`/`Fail→Fail`/`CalibrationRegion→ManualCheck`), with `verdict` and `state` independent and the report lamp chosen verdict-first (per architecture.md §Established Decisions [Probabilistic-Assertion Policy]). If measurement shows no surface can carry the restart/suppression tokens, the honest landing is a narrowed claim + harvest-tier grading — not a re-labelling of a deterministic claim as interpretive.
- Verdict/error wall: `Blocked` is a **value, never a `Result::Err`**, and dependent auto scenarios on an unmet precondition report blocked with the named precondition, never silently downgraded; a blocked row populates only `run_id`/`seed`/`scenario`/`p_ids`/`slo_tier` with `verdict`/`journal_emitted_at`/`read_back_observed_at`/`latency_ms`/`fingerprints` as JSON `null` (NULL in `runs.db`), and cross-run latency/percentile/P-036 queries MUST exclude NULL-measurement rows (per architecture.md §Established Decisions [Error Handling] + [Read-Back Dependency Posture], §Standard Contracts Readiness gate). The auto-resolve-window CARRY therefore has a mandated outcome shape: an honest Block, budgeted for in the row's expected state.

## Patterns to follow
- **Composition-root placement**: `conductor-run` is the registered 9th workspace member — preflight + scenario execution + `persist` + the live-counter run driver — sitting above the seams and below both bins (architecture.md §Occupied Resources Crate names, §Infrastructure Patterns directory tree). Leg plumbing and the harvest parser/predicates belong there; crate-per-seam edges are compiler-enforced, so no new cross-seam dependency may be introduced (§Established Decisions [Module Boundaries]).
- **Harvest surface is the self-observation artifact, not the emission journal**: `logs/agent-latest.jsonl` is a SEPARATE artifact + schema from the per-run JSONL journal, a sibling of the runs dir (moves with `CONDUCTOR_RUNS_DIR`), truncated per invocation, gated by `CONDUCTOR_AGENT_MODE` which Conductor READS (`flag || env-set`) and main never writes (architecture.md §Occupied Resources On-disk artifacts + Environment variables).
- **Transcribed-SUT-record posture** for any P-016/P-057 threshold facts that get pinned: contract artifacts carry `sut_version` · `captured_at` · `provenance` stating they are a transcribed SUT record and never a Conductor measurement, are runtime-read + bounds-checked at load, and resolve from a fixed `default_path()` through `resolve_under` with deliberately NO `CONDUCTOR_*` override handle (the capabilities → load-envelope → run-contract precedent, architecture.md §Occupied Resources).
- **Preflight budget**: `CONDUCTOR_PREFLIGHT_TIMEOUT` defaults to 30s but carries a run-contract-derived effective FLOOR (`[incident_formation].min_canary_poll_seconds`) it cannot sit below, overridable only upward (architecture.md §Occupied Resources Environment variables) — the chunk's "poll budget ≥ the contract floor" is this handle.
- **Two-source integrity gates stay exact**: `check_sut_drift` (manifest ↔ code-native `coverage_matrix()`) and `check_scenario_backing` (`Auto`-classified capabilities ↔ the `UNBACKED_AUTO` pin, exact-set both directions) fail as `CoreError::SutDrift` / `CoreError::UnbackedCoverage` (architecture.md §Established Decisions [Accepted Capability Set]). Any claim/classification movement at P5 must land as a matching row, never a silent widening.
- **Fingerprint identity is Pulse's derivation**: blake3 over `exception_type` + `\0` + normalized stacktrace, 16 bytes → 32 lowercase hex, first `NORMALIZED_FRAMES = 3` frames, TOKEN-LEADING normalization (relative paths significant at every depth; token-leading absolute paths stripped; insensitive axes are line/col and hex addresses) — architecture.md §Established Decisions [Read-Back Dependency Posture]. This governs whether the error phases actually re-raise the SAME identity to keep the corpus alive.

## Anti-patterns to avoid
- No new inbound listener or port (Conductor is a gRPC/MCP client; the port-occupier fault is the single deliberate `:4317` bind and is out of this chunk's scope), no new env var outside the reserved `CONDUCTOR_*` namespace, and no `CONDUCTOR_*` override handle for a `contracts/` artifact (architecture.md §Cross-cutting Patterns Trust boundary + Scope law, §Occupied Resources).
- No scenario DSL and no compile-time widening of the accepted P-ID set; a nested spec field must `dive`, never `#[garde(skip)]` — a skipped nested struct deserializes unvalidated (architecture.md §Established Decisions [Validation Library], §Conventions Config conventions).
- Never widen the load envelope by adding an `[[exempt]]` entry to make a re-shape pass, and never express a verification outcome as `Result::Err` — `Err` is reserved for harness faults (config parse, transport down, MCP unreachable) (architecture.md §Occupied Resources `contracts/pulse-load-envelope.toml`, §Cross-cutting Patterns Verdict/error wall).

## Contract bindings
- **Run-report envelope + `runs.db`** (arch ↔ report/tests): the per-check row shape and the `runs` table's eleven columns keyed `(run_id, scenario)` with `state` a closed five-variant set; run-level envelope classification goes to the separate `run_envelope` table (`classification` · `cause`), not a new `runs` column (architecture.md §Standard Contracts Run report envelope, §Occupied Resources runs.db).
- **Harvest surface** (arch ↔ obs ↔ tests): `logs/agent-latest.jsonl` inherits the processor-stage redaction of `init_observability` (obs-plan §3 per architecture.md §Occupied Resources); harvest predicates pinned to verbatim leg captures are the tests-domain half of the same surface.
- **Determinism discipline** (arch ↔ tests): seeded `ChaCha8Rng` + `current_thread` + the zero-retry nextest `ci` profile (no retries mask flakes) are one invariant; a seed disposition change re-shapes emission timing and therefore any frozen replay/stream goldens (architecture.md §Infrastructure Patterns Build system, §Established Decisions [Determinism RNG]).
- **Precondition/report strings** (arch ↔ security/obs): every readiness precondition string is host-path-free with `data_dir` redacted (architecture.md §Standard Contracts Readiness gate) — leg evidence and any new blocked-reason string inherit that.
- **Verdict-first lamp** (arch ↔ design/a11y): a calibration row renders HOLD, not Manual (architecture.md §Established Decisions [Probabilistic-Assertion Policy]).

## Acceptance criteria contributions
- (arch) Leg plumbing + harvest parser/predicates land in `conductor-run` with no new workspace member and no new cross-seam dependency edge (per architecture.md §Occupied Resources Crate names + §Established Decisions [Module Boundaries]).
- (arch) Any `restart-suppression.toml` re-shape re-runs `check_load_envelope` green on the two asserted per-emitting-phase terms with the `[[exempt]]` ledger still empty and exact-set in both directions (per architecture.md §Occupied Resources `contracts/pulse-load-envelope.toml`).
- (arch) The recorded `slo_tier` is one of exactly `<5s`/`<20s`/`<90s`, and any re-declaration is justified against measured `latency_ms` computed as `read_back_observed_at − journal_emitted_at` — never a wall-clock-from-test-start or scenario-window figure (per architecture.md §Conventions Data model conventions + §Established Decisions [Timing-Tolerance Model]).
- (arch) The SEED disposition conforms to the files-over-env-defaults precedence (a TOML-declared seed is not overridden by a harness-injected env default), with `.sh`/`.ps1` parity; recording the override as intended instead requires an arch amendment to that precedence rule (per architecture.md §Cross-cutting Patterns Config management + §Occupied Resources `CONDUCTOR_SEED`).
