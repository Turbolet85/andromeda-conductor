# obs extract

## Relevance
Relevant — this chunk drives obs-plan's Critical Path 3 (restart-suppression incl. bypass) end-to-end on a live surface, and touches the envelope's `slo_tier`/`bypass_triggered` fields, the gap-phase fault span, and the read-back boundary log.

## Constraints
- The family's must-trace span chain and attributes are mandated: `scenario.run` → `timeline.execute_restart_suppression` → `emit.batch` (canonical) → `emit.batch` (bypass, distinct, `path_type` = "canonical"/"bypass") → `verify.readback_suppression_bypass` (`bypass_verdict_received`) → `report.generate`, with `canonical_path_taken`/`bypass_path_taken` on the timeline span (per obs-plan §4 "Restart-suppression scenario incl. bypass case"); §11 "Spans / Traces" additionally bans skipping spans on Critical Paths 1-7. Whether the code already emits this chain and these attributes is research's question.
- Any span attribute must be a name in `conductor-core::redact::ALLOWLISTED_FIELDS` or the processor stage drops it and the attribute emits nothing; non-allowlisted witnesses (key sets, shape observations, realized-state notes) must ride the allowlisted `message` field (per obs-plan §4 Required-span-attributes constraint + §6 Boundary-call wrappers). Whether `path_type` / `bypass_verdict_received` / `canonical_path_taken` are allowlisted today is research's question.
- Span names must stay inside the bounded set — `timeline.execute*` and `verify.readback*` wildcards admit this family's two names; no per-run/per-path high-cardinality name may be introduced (per obs-plan §11 "Spans / Traces").
- The Run-report envelope is the 11-field schema plus this family's scenario extra `bypass_triggered` (boolean); `latency_ms` and `read_back_observed_at` are null for blocked rows (per obs-plan §6 Log Coverage + §3 Log format JSON schema). The envelope is a binding contract obs *derives* from the tests plan, not re-authors (per obs-plan §3 Log format JSON schema preamble).
- `slo_tier` is a closed enum (`<5s` | `<20s` | `<90s`) and `latency_ms` = `read_back_observed_at − journal_emitted_at` in wall-clock `std::time` — never tokio's virtual clock; the SLO verdict is a JSON field assertion at report-generation time, and soft/unenforced budgets are banned (per obs-plan §5 Metric Coverage, §10 Performance budgets, §11 project-specific bans). A `<20s` → `<90s` re-declaration must land inside that enum and keep the same measurement basis.
- The scenario's gap phase (`occurrences = 0`) is the declarative silence fault, so `fault.silence` is required from the caller-supplied per-phase hook (`run_timeline_observed` / `PhaseWindow`, `conductor-run` supplying fault semantics + the `std::time` journal basis) with `fault_type`="silence", `fault_duration_ms`, `fault_start_offset_ms`; created but NOT entered (entering re-parents `emit.batch`), child of `timeline.execute`, lifecycle at `info` so it survives the default INFO filter (per obs-plan §4 Fault-injection spans + §6 log-levels table and its why-note). Whether this scenario's gap phase already raises `fault.silence` is research's question.
- Pulse is Boundary-only: Conductor instruments the read-back boundary and observes responses/SLO timing, never Pulse's internals (per obs-plan §1 instrumentation-scope table, Pulse MCP server row). Pulse's own tracing lines (e.g. the `triage.cue.emit` `suppression_bypassed` witness) are therefore not a contract obs owns — harvest predicates over them must be pinned to verbatim leg captures, not treated as a stable obs surface.

## Patterns to follow
- Read-back boundary must-log set as the gradeability measuring instrument: tool name (`query_incident_list` / `retrieve_report` / `retrieve_telemetry_slice` / `mark_incident_resolved`) + `latency_ms` + error + canary result + the **observed key set** of each raw tool result — key NAMES only, never values, on the `message` field, because the extraction readers degrade to empty on an unrecognized shape rather than erroring (per obs-plan §6 Boundary-call wrappers). This is the existing pattern for settling "can this surface carry the token" by measurement.
- `emit.batch` wire-shape witness at `debug` inside the existing `#[instrument]` span, on `message` (per obs-plan §6 Boundary-call wrappers) — the emitting-side twin, reached with the **additive** `RUST_LOG=info,{crate}=debug` form; a bare per-target directive replaces the default and darkens every other target, and RUST_LOG must never be set for a run that also executes the test suite (per obs-plan §3 Per-module log levels note).
- Reading a leg capture: `report.generate` and `db.insert_run` are run-scoped SIBLINGS of `scenario.run`, correlated by `run_id`, not descendants — under a suite one `persist` serves N already-closed scenario roots (per obs-plan §4 Critical Path 1 Cleanup).
- Two record shapes when writing harvest predicates: the self-obs line (`timestamp_ms`/`level`/`target`/service identity/`run_id`, plus the span-lifecycle variant carrying `span`/`span_event`/optional `parent`/allowlisted attributes on `new`) vs the Run-report envelope (`runs/<run_id>.jsonl` + `runs.db` row, written by the report seam) — per obs-plan §3 "Two record shapes". Harvest parses the former; `[[expected]]` gradeability concerns what the read-back/envelope surface can carry.

## Anti-patterns to avoid
- Never log per-record/per-emission detail at `info` — hot-path witnesses go to `debug`/`trace`; the one deliberate exception is fault-span lifecycle, which is `info` by design (per obs-plan §11 "Logs" + §6 why-note).
- Never leak absolute host paths or internal struct names into logs, the run report, `runs.db`, or the artifacts derived from them; redaction is single-location in `conductor-core::redact` (field-name allowlist + host-file-path value scrub + `Display`-not-`Debug` at the `anyhow` edge), applied at the processor stage, not the sink (per obs-plan §11 "Logs" and "PII Scrubbing").
- Never introduce an OTel SDK, `tracing-opentelemetry`, or W3C `traceparent` to correlate the live leg, and never export self-observation OTLP to `:4317` or `:4318` — correlation across the leg is the `run_id` field only (per obs-plan §11 "Spans / Traces" + "Universal").

## Contract bindings
- **obs ↔ tests harness:** test-plan §3 OWNS the JSONL Run-report envelope; obs-plan §3/§6 reproduce it and realign to the owner (per obs-plan §3 Log format JSON schema; amendment 2026-06-16-emission-journal-writer). Any envelope change this chunk makes — a re-declared `slo_tier`, the `bypass_triggered` extra, a blocked-row shape — is a joint obs+tests change, not an obs-local edit.
- **obs ↔ verification-matrix (v2-13):** the acceptance's "within SLO" concretizes to obs's report-time assertion `latency_ms <= threshold(slo_tier)` over the wall-clock journal basis (per obs-plan §10 Performance budgets); if the measured window forces `<90s`, the claim's SLO wording must concretize against that same basis.
- **obs ↔ security:** the "no absolute host paths / no internal struct names" guarantee is realized by the shared `conductor-core::redact` allowlist + host-path scrub, so leg captures and evidence files inherit it rather than defining their own rule (per obs-plan §11 "PII Scrubbing").
- **obs ↔ CI:** `logs/agent-latest.jsonl` is gated on the §3 self-obs BASE schema (not the envelope) plus the zero-unlogged-panics grep (per obs-plan §9 Log conformance check + Zero-unlogged-panics gate).

## Acceptance criteria contributions
- Leg captures show the family's full must-trace chain with its distinguishing attributes — two `emit.batch` spans separated by `path_type`, `timeline.execute_restart_suppression` carrying `canonical_path_taken`/`bypass_path_taken`, `verify.readback_suppression_bypass` carrying `bypass_verdict_received` — with any attribute that is not allowlisted either added to the allowlist or moved onto `message` (per obs-plan §4 Restart-suppression scenario).
- The journal row and `runs.db` row carry the 11-field envelope plus `bypass_triggered` (boolean), with `latency_ms`/`read_back_observed_at` null on a Blocked row and no absolute host paths in any field (per obs-plan §6 Log Coverage + §11 Logs).
- Any `slo_tier` re-declaration stays within the closed enum and its pass/fail is evidenced as the report-time assertion `latency_ms <= threshold` computed from `read_back_observed_at − journal_emitted_at` wall-clock, never a tokio virtual-clock value (per obs-plan §5 Metric Coverage + §10 Performance budgets).
- The live leg's gap phase materializes a `fault.silence` line at `info` (`fault_type`, `fault_duration_ms`, `fault_start_offset_ms`) that does not re-parent that phase's `emit.batch` spans, and the leg produces zero unstructured `^thread.*panicked` lines in the capture (per obs-plan §4 Fault-injection spans + §9 Zero-unlogged-panics gate).
