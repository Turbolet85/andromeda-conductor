# a11y extract

## Relevance
Partial — no assertable UI surface changes here (the leg is CLI/backend/scenario/artifact work), but the chunk writes verdict/state rows and artifacts into the envelope a11y binds to, and the a11y-plan §6 lamp crosswalk governs how those values must render.

## Constraints
- Every verdict/state value this leg records must resolve to exactly one row of the six-lamp crosswalk (verdicts `Pass`/`CalibrationRegion`/`Fail`; states `Pass`/`Fail`/`ManualCheck`/`KnownResidual`/`Blocked`) — a11y-plan §6 "State color tokens (not-color-alone)" makes that table binding for the DOM-text assertion + obs join, so a seventh state value would leave a lamp uncovered.
- If a graded check retires to declare-only, the recorded `state` selects the lamp (`KnownResidual` ⇒ `Residual`, `ManualCheck` ⇒ `Manual`) and any `CalibrationRegion` verdict takes HOLD **verdict-first** regardless of `state` (per a11y-plan §6 crosswalk) — the retire path must choose deliberately, not incidentally.
- a11y violation/assertion artifacts share the obs §6 envelope verbatim and MUST NOT leak absolute host paths or internal seam-crate struct names (per a11y-plan §3 "Structured violation JSON schema" + §9 CI resource attributes + §11 SLO ban); this chunk's no-excerpt-content rule extends the same constraint to raw PII payloads. Whether this leg emits any a11y artifact at all (the a11y gate is operator/local per §9) is research's question.
- The CLI and Markdown report are declared not-assertable — a11y-plan §1 A11y scope excludes them (no DOM/widget tree) and §11 Universal forbids treating the cli surface as accessibility-assertable; ASCII status prefixes / NO_COLOR text pairing are output-stream discipline, never an ARIA verification path.
- If a new coverage-mode classification (analogous to the out-of-scope Mode cell) is introduced for retired checks, a11y-plan §6 requires its own always-rendered text label as the not-color-alone signal, and the six-label lamp assertion must key on the LAMP labels — a token-tinted Mode cell is not a lamp state.
- If P-035/P-047/P-048 rows change the coverage matrix rendering, a11y-plan §4 pattern catalog requires `list`/`listitem` (or table) semantics with every P-ID row reachable/announceable including virtual-scrolled off-screen rows (§11 Screen Reader).

## Patterns to follow
- The §6 State-naming crosswalk table as the single join from a recorded row back to its lamp (display label ↔ `verdict` enum ↔ `state` enum) — use it rather than re-deriving a mapping in the harvest test.
- a11y §3 envelope discipline: a11y narrows, obs fixed the schema — no new top-level fields; rule-id / SC tag / selector tuples ride inside `fingerprints[]`. Any new witness this chunk needs should follow the same fold-into-existing-fields shape.
- a11y §11 Universal + §1: keep CLI-side scrub evidence as text-paired output-stream discipline (ASCII prefix / NO_COLOR), explicitly not framed as an a11y assertion.
- a11y §6 not-color-alone pairing (text label + glyph supplement) for any state surfaced by the new rows in the webview lamp/matrix.

## Anti-patterns to avoid
- NEVER treat the cli or Markdown report surface as accessibility-assertable, or claim WCAG conformance for it (a11y-plan §11 Universal).
- NEVER let artifacts sharing the obs §6 envelope leak absolute host paths or internal seam-crate struct names (a11y-plan §11 SLO) — with this chunk's raw-excerpt content in the same prohibited class.
- NEVER convey a state by color alone — each of the six lamps requires its text label + glyph supplement (a11y-plan §11 Visual).

## Contract bindings
- a11y §3 / §9 ↔ obs §6 log-format envelope: a11y reproduces it verbatim (11 fields incl. `read_back_observed_at`) and inherits its no-leak constraint; this chunk writes into the same envelope.
- a11y §6 crosswalk ↔ obs `verdict` / `state` enums and design's six state color tokens (`--count-nominal` / `--count-hold` / `--status-fail` / `--count-blocked` / `--status-manual` / `--status-residual`).
- a11y §9 ↔ tests' 5-command harness (`logs` as the artifact-emitting command) on the tauri-driver/WebdriverIO webview job — engaged only if a webview lane runs for this leg; otherwise dormant for this chunk.

## Acceptance criteria contributions
- Every verdict/state recorded by the pii-scrub leg maps to exactly one of the six crosswalk rows; no seventh state value is introduced (per a11y-plan §6 State color tokens — State-naming crosswalk).
- Any check retired to declare-only records a deliberate `state` (`KnownResidual` vs `ManualCheck`), and a `CalibrationRegion` verdict is joined HOLD verdict-first, never on `state` (per a11y-plan §6 State-naming crosswalk).
- No artifact this leg writes into the obs §6 envelope contains absolute host paths, internal seam-crate struct names, or raw excerpt content (per a11y-plan §3 Structured violation JSON schema + §11 SLO).
- No a11y/WCAG conformance claim is attached to the CLI or Markdown report surface for this family (per a11y-plan §1 A11y scope + §11 Universal).
