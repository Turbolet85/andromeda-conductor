# arch extract

## Relevance
Relevant — the chunk lands code in three existing seam crates, drives the pinned read-back + preflight contracts, and writes the run-report envelope, so arch's workspace, contract-envelope and occupied-resource rules all bind.

## Constraints
- **Crate-per-seam placement is compiler-enforced, and this chunk adds no new seam.** PII corpus primitives belong in `conductor-emit` (the emission/exception-content seam), leg execution + any new harvest test module in `conductor-run` (the composition root above the seams, below both bins), read-back in `conductor-verify`, artifacts in `conductor-report`; a forbidden cross-seam edge must fail to compile, not be caught in review (per architecture.md §Established Decisions [Module Boundaries] · §Occupied Resources "Crate names" · §Infrastructure Patterns directory tree).
- **The verdict/error wall governs every scrub outcome.** `Verdict {Pass, Fail, CalibrationRegion}` / `ReportState {Pass, Fail, ManualCheck, KnownResidual, Blocked}` are returned as `Ok`; `Result::Err` is reserved for harness faults (manifest parse, transport down, MCP unreachable). A structurally ungradeable check must land in a named state — never a silent downgrade to pass (per architecture.md §Conventions "Error handling" · §Cross-cutting Patterns "Verdict/error wall" · §Established Decisions [Read-Back Dependency Posture]).
- **The read-back surface is narrow and payload-invariant by architecture's own measurement.** Only the four persistent-corpus MCP tools (`query_incident_list` · `retrieve_report` · `retrieve_telemetry_slice` · `mark_incident_resolved`) function cross-process from a Conductor-spawned sidecar — the four live-buffer tools return empty — and §RBDP records that NO read-back field varies with the emitted payload under deterministic L4 (titles are scrubbed; `fingerprint_refs` carries a constant `det-*` triple; Pulse's own fingerprint lands in a `span_events` column no MCP tool reads). Whether any surface carries scrub evidence for THIS family is research's question, not something arch can attest (per architecture.md §Standard Contracts "Readiness gate" · §Established Decisions [Read-Back Dependency Posture]).
- **Scrub is a deterministic claim, so it is hard pass/fail — not calibration-region.** The two-state split reserves calibration/`ManualCheck` for model-interpretive claims (severity choice, hypothesis quality); a scrub pipeline is suppression/bypass logic, i.e. a hard signal. `verdict` and `state` stay independent and the report lamp is chosen verdict-first (per architecture.md §Established Decisions [Probabilistic-Assertion Policy]).
- **The run-report envelope and `runs.db` schema are closed.** `runs` keeps its eleven columns keyed `(run_id, scenario)`; `state` is the closed five-variant set; column types are fixed on first write with no migration framework; `fingerprints` is a JSON1 TEXT array. "Verdicts recorded without persisting excerpt content" must therefore fit the existing envelope — no excerpt column, no sixth state (per architecture.md §Standard Contracts "Run report envelope" · §Conventions "Data model conventions" · §Established Decisions [ORM]).
- **Scenario TOML is declarative + manifest-bounded + envelope-bounded.** `pii-scrub.toml`'s P-IDs must be members of `contracts/pulse-capabilities.toml`'s accepted set ("no scenario without a P-ID"), garde `dive`s into nested spec structs rather than skipping them, and any re-shaped phase must satisfy the two ASSERTED sustained terms judged PER EMITTING PHASE (`max_sustained_storm_ms`, `max_sustained_rate_spans_per_s`), with `check_load_envelope` and the `[[exempt]]` ledger held at exact-set equality in both directions — the ledger is currently recorded EMPTY (per architecture.md §Established Decisions [Accepted Capability Set] · [Scenario Config Format] · §Occupied Resources `contracts/pulse-load-envelope.toml`).
- **Pulse's `corpus.db` is plaintext SQLite and SUT-owned, out of Conductor's scope to persist or exfiltrate**, and Conductor's trust boundary is loopback-only with no inbound listener of its own (the port-occupier fault is the single deliberate bind). This is the arch-side floor under the chunk's no-excerpt-content invariant (per architecture.md §Standard Contracts "Corpus access" · §Cross-cutting Patterns "Trust boundary").

## Patterns to follow
- **Declare-only retirement with the measurement recorded** — the precedent architecture already carries: the `error-baseline-spike` family ships declare-only (zero `[[expected]]` checks) with live rows landing `verdict: null` / `state: "KnownResidual"` under degraded read-back and the live claim graded at the harvest tier (per architecture.md §Standard Contracts "Run report envelope" note).
- **Blocked/unmeasured row shape** — populate only identity fields (`run_id`, `seed`, `scenario`, `p_ids`, `slo_tier`); emit `verdict`, `journal_emitted_at`, `read_back_observed_at`, `latency_ms`, `fingerprints` as JSON `null` (NULL in `runs.db`), and cross-run latency/percentile/P-036 queries MUST exclude NULL-measurement rows (per architecture.md §Standard Contracts "Readiness gate").
- **Contract manifests resolve from a fixed `default_path()` through `resolve_under` with deliberately NO `CONDUCTOR_*` override handle** (the capability-manifest / load-envelope / run-contract precedent); a malformed or absent manifest is a `CoreError` harness fault carrying a named reason, never `Blocked` (per architecture.md §Occupied Resources on-disk artifacts · §Established Decisions [Accepted Capability Set]).
- **Per-call seeded span identity on every emitted span.** Pulse's `spans` table is `PRIMARY KEY (trace_id, span_id)`; a constant identity makes every span after the first logged-and-skipped — the defect that ran through the shared builder into `dispatch.rs` and cost two legs. A PII corpus emitting many spans across categories is exactly the shape that trips it (per architecture.md §Occupied Resources `contracts/pulse-run-contract.toml`).
- **Two service identities, kept split.** Preflight runs inside every scenario leg emitting as `conductor-canary` (`CANARY_SERVICE_NAME`); the dispatcher emits as `conductor` (`DEFAULT_SERVICE_NAME`) — Pulse keys per-service sample counts and error-rate EWMAs, so merging them would age the PII leg's suppression window and inflate its baseline denominator before phase 1 emits (per architecture.md §Occupied Resources "Service / process names").
- **Artifact naming split:** `run_id` uses the filesystem-safe hyphen stamp (it is the `runs.db` PK and the stem of `<run_id>.jsonl` / the report); in-payload instants use colon-delimited RFC-3339; on-disk Markdown artifacts are kebab-case (per architecture.md §Standard Contracts "Timestamp formats" · §Conventions "Naming patterns").

## Anti-patterns to avoid
- **Do not widen an occupied-resource namespace for this chunk** — no new `CONDUCTOR_*` env var, no override handle on a `contracts/` manifest, no new workspace crate, no inbound port, no new `runs` column or sixth `ReportState` to carry excerpt data (per architecture.md §Occupied Resources · §Standard Contracts "Run report envelope").
- **Never assert a measurement Conductor cannot make.** Arch's precondition-string discipline names candidate causes instead of claiming SUT-side facts read-back does not expose, and every precondition string is host-path-free (`data_dir` redacted) — the same discipline applies to a scrub witness whose provenance is Pulse-side (per architecture.md §Standard Contracts "Readiness gate" · §Occupied Resources `pulse-run-contract.toml` `declared-not-observable`).
- **Do not make a live leg a CI gate, and do not mask flakiness.** Dynamic end-to-end proof against a live Pulse is an explicit operator/local gate; CI runs `cargo build` / nextest (zero-retry `ci` profile — no retries mask flakes) / clippy (per architecture.md §Established Decisions [CI/CD] · §Infrastructure Patterns "Build system" + "CI/CD approach").

## Contract bindings
- **arch ↔ obs:** arch registers the self-obs artifacts `logs/agent-latest.jsonl` and `logs/conductor-tauri.jsonl` (siblings of the runs dir, moving with `CONDUCTOR_RUNS_DIR`, truncated per invocation) and records that both inherit the same processor-stage redaction; the redaction rules that keep PII excerpts out of those streams are obs-plan §3's domain, not arch's.
- **arch ↔ security:** the trust boundary + "`corpus.db` is SUT-owned, never persisted/exfiltrated" rule is arch's; PII-payload handling, excerpt hygiene in test pins, and the `cargo audit` / `cargo deny` posture (arch records deny GREEN and audit RED on an external advisory-DB fault, the PREREQ's surface) bind to security-plan §Dependency Security.
- **arch ↔ tests:** the harvest-tier pin is what carries the live claim into CI; it runs under the pinned nextest zero-retry `ci` profile plus `cargo test --doc`, and the envelope shape (verdict/state/null-measurement fields) is the fixture contract those tests assert against.
- **arch ↔ design/layouts:** run-report lamp selection is verdict-first, so a calibration row renders HOLD rather than Manual — binding for how a retired-to-declare-only or `KnownResidual` PII row renders.

## Acceptance criteria contributions
- (arch) All chunk code lands in existing workspace members — PII corpus primitives in `conductor-emit`, leg/harvest execution in `conductor-run`, read-back in `conductor-verify`, artifacts in `conductor-report`; no new workspace crate and no new cross-seam dependency edge (per architecture.md §Established Decisions [Module Boundaries] · §Occupied Resources "Crate names").
- (arch) No new occupied resource: no new `CONDUCTOR_*` env var, no inbound port, no `runs.db` column beyond the existing eleven, and `state` stays the closed five-variant set — the "verdicts without excerpt content" record fits the shipped envelope (per architecture.md §Occupied Resources · §Standard Contracts "Run report envelope" · §Conventions "Data model conventions").
- (arch) If `pii-scrub.toml` phases re-shape, every emitting phase satisfies the two asserted sustained load-envelope terms with `check_load_envelope` green and the `[[exempt]]` ledger still exactly empty; all named P-IDs remain members of the capability manifest's accepted set (per architecture.md §Occupied Resources `contracts/pulse-load-envelope.toml` · §Established Decisions [Accepted Capability Set]).
- (arch) Any check that proves ungradeable lands in a named state — declare-only with the measurement recorded, or `KnownResidual`/`Blocked` with the named precondition and NULL measurement fields — never a pass, and unmeasured rows are excluded from cross-run latency/fingerprint queries (per architecture.md §Standard Contracts "Readiness gate" · §Cross-cutting Patterns "Verdict/error wall").
