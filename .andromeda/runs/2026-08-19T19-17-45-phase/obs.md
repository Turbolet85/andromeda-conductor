# obs extract

## Relevance
Relevant — the chunk's "verdicts recorded without persisting excerpt content" clause is squarely obs's redaction/artifact-hygiene domain, and the leg's evidence surface (self-obs lines, envelope, harvest pins) is obs-governed.

## Constraints
- Redaction must be **processor-stage and single-location** in `conductor-core::redact`, applied on all three paths — subscriber field filter, JSONL write at report generation, and runs.db insert validation — never at sink stage only (per obs-plan §11 PII Scrubbing). The chunk's four hygiene surfaces (`runs.db` / journal / Markdown report / self-obs streams) map onto exactly these paths plus the agent-mode file sink.
- A span attribute must be a name in `conductor-core::redact::ALLOWLISTED_FIELDS` or the processor stage drops it and the attribute emits nothing (per obs-plan §4 Span/Trace Coverage, Required-span-attributes constraint). Any new PII-scrub evidence field must therefore be allowlisted or ride the allowlisted `message` field.
- The value scrub that §11 mandates is anchored on **absolute host-FILE paths** → `<redacted>`, with internal struct names excluded by the field-name allowlist + `Display`-not-`Debug` at the `anyhow` edge — not by `::`-token redaction (per obs-plan §11 Logs + §11 PII Scrubbing). It is not specified as a PII-category value scrubber; whether the shipped redact layer masks any of the seven category values (email / JWT / bearer / API key / card / SSN / secret k=v), or whether hygiene rests solely on the allowlist dropping non-allowlisted fields, is research's question.
- Span names must stay inside §11's bounded set (`scenario.run`, `timeline.execute*`, `emit.batch`, `emit.logs_batch`, `verify.readback*`, `report.generate`, `db.insert_run`, `fault.*`, `tauri.command.*`) — no per-category or per-excerpt name (per obs-plan §11 Spans/Traces). Note the tension: §1's `creator-explicit-telemetry` trigger requires a `redaction.apply_field_allowlist()` span, a name the §11 bounded set does not enumerate; whether that span exists in code is research's question.
- The scenario-result record must carry the fixed eleven-field envelope (`journal_emitted_at` … `fingerprints`), with scenario extras only as named additions; the schema is **owned by test-plan §3 and obs aligns to it, not vice versa** (per obs-plan §3 Log format JSON schema + §6 Log Coverage). No PII-family extra is currently defined — adding one is a cross-plan change, not an obs-local one.
- Every self-obs line must carry the §3 base set — `timestamp_ms`, `level`, `target`, `service.{name,version}`, `deployment.environment`, `run_id` — distinct from the envelope (two record shapes), with `run_id` as the only correlation key (per obs-plan §3 two record shapes + §11 Logs).
- Per-record emission detail must not log at `info`; witnesses belong at `debug` and require the **additive** form `RUST_LOG=info,{crate}=debug` (a bare per-target directive replaces the default), and RUST_LOG must never be set for a run that also executes the test suite (per obs-plan §3 Per-module log levels + §11 Logs).

## Patterns to follow
- **Key-names-only witness on `message`**: the `verify.readback` observed-key-set witness and the `emit.batch` wire-shape witness both record NAMES and COUNTS, never values, on the already-allowlisted `message` field (per obs-plan §6 Boundary-call wrappers). This is the established carrier for "prove the corpus reached the wire without persisting the excerpt."
- **Harvest-tier grading over the SUT's own tracing lines**: the restart-suppression path records suppression evidence at the harvest tier over Pulse's lines rather than in Conductor's envelope (per obs-plan §4 Restart-suppression scenario) — the precedent the chunk cites for a `pii_harvest.rs`.
- **Retire-with-measurement**: when a mandated attribute or graded check proves non-computable under deterministic L4, the plan records the measurement and narrows the spec instead of leaving it standing (`fingerprints_read_back_count`, the declare-only restart-suppression landing) (per obs-plan §4 Fingerprint-storm + §4 Restart-suppression).
- **Boundary-call must-log set**: `verify.readback` (tool name + latency + key set), `emit.batch`, `db.insert_run`, `report.generate`, and `redaction.apply_field_allowlist` (redaction warnings when anything was scrubbed) at `info` (per obs-plan §6 Boundary-call wrappers + §6 log-levels table).
- **Spans materialize as real lines**: the custom layer emits a span-lifecycle variant adding `span` / `span_event` (`new`|`close`) / optional `parent` plus allowlisted attributes on `new` only (per obs-plan §3 two record shapes).

## Anti-patterns to avoid
- NEVER let a raw excerpt value ride a span attribute, log field, envelope extra, or test pin — PII in span attributes is banned outright and the plan's premise is that Conductor's telemetry is synthetic-only (per obs-plan §11 Spans/Traces + §11 PII Scrubbing; §1 `logging-sensitive` trigger row).
- NEVER hardcode scrubbing in one place or scrub only at the sink — the three-path processor-stage application is the mandate (per obs-plan §11 PII Scrubbing).
- NEVER add a high-cardinality or off-set span name (per-category, per-finding, per-excerpt) for the new evidence (per obs-plan §11 Spans/Traces).

## Contract bindings
- **obs ↔ tests**: the envelope schema and the self-obs line format are owned by test-plan §3; obs §3/§6 reproduce and align to it. A new PII-family envelope extra or line-shape change is a two-sided change (per obs-plan §3 Log format JSON schema).
- **obs ↔ tests (harvest)**: a `pii_harvest.rs` consuming pinned verbatim leg lines is a tests-tier artifact grading obs-shaped output; witness predicates must read the allowlisted fields obs guarantees, not dropped ones (per obs-plan §4 Restart-suppression scenario).
- **obs ↔ security**: the no-absolute-host-paths / no-internal-struct-names artifact rule cites security plan §2's "leaking absolute host paths in run-report artifacts" anti-pattern; the redact layer is the shared enforcement point (per obs-plan §1 Log format JSON schema note + §11 PII Scrubbing).
- **obs ↔ CI**: the §9 log conformance gate reads `logs/agent-latest.jsonl` and validates the base schema + absence of absolute host-file paths; the envelope-side gate is recorded as not-yet-built (per obs-plan §9 Log conformance check).

## Acceptance criteria contributions
- No raw excerpt value from any of the seven PII categories appears in a self-obs line, the `runs/<run_id>.jsonl` envelope, a `runs.db` row, the Markdown report, or a harvest test pin — evidence is category label + count + a non-content witness only (per obs-plan §11 PII Scrubbing + §6 Boundary-call wrappers).
- Every new evidence field is either present in `conductor-core::redact::ALLOWLISTED_FIELDS` or carried on `message`, and every span name used stays inside the bounded set (per obs-plan §4 Required-span-attributes constraint + §11 Spans/Traces).
- The leg's self-obs lines carry the §3 base set with `run_id` on every line, the scenario-result record carries the eleven-field envelope including `latency_ms` (wall-clock `std::time`) + `slo_tier`, and the §9 conformance gate stays green on `logs/agent-latest.jsonl` (per obs-plan §3 two record shapes + §9 Log conformance check + §10 Performance budgets).
- Zero unlogged panics across the live leg, including on malformed or degraded read-back, which must yield a typed `blocked` value rather than a panic (per obs-plan §10 Always-required SLO invariant + §11 Error Reporting).
