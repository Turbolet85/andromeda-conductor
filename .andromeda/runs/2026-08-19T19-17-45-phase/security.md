## Constraints
- The PII corpus is **synthetic self-generated test data, not user PII** — security-plan §Threat Model Summary (Data classification: PII "none"; "the only identities are synthetic incident/fingerprint data Conductor itself emits"). This chunk must not change that classification: the seven categories are fabricated payloads, and treating them as real PII would contradict the Minimal-tier basis. Whether the shipped `conductor-emit` corpus values are in fact synthetic is research's question.
- Run-report artifacts (`<run_id>.md`, `runs.db` rows, JSONL journals) MUST carry verdict/state/identity fields only and MUST NOT leak absolute host paths or internal seam-crate struct names — security-plan §Error Handling (Run-report artifact sanitization) + §Security Anti-Patterns → Logging. The chunk's "verdicts recorded without persisting excerpt content" is this invariant applied to the excerpt surface; whether the current recording path already withholds excerpt content is research's question.
- `runs.db` MUST NOT hold real secrets or credentials and is to be treated as a **world-readable local file** — security-plan §Security Anti-Patterns → Data Protection. Since the PII corpus deliberately shapes payloads that *look* like JWTs / bearer tokens / API keys / secret `key=value`, persisting an excerpt verbatim would land secret-shaped strings in an unencrypted artifact and would also collide with the no-secret-shaped-string invariant of §Secret Management.
- Conductor's production code MUST reach Pulse's `corpus.db` via MCP read-back ONLY — never directly open, copy, or exfiltrate it, and never persist its content into Conductor artifacts — security-plan §Security Anti-Patterns → Data Protection + §Data Protection ("Conductor only reads the corpus via MCP read-back to prove wiring"). `corpus.db` is plaintext SQLite (the P-049 encryption assumption was disproved live 2026-06-27), so a corpus-row read used as scrub evidence is unencrypted SUT-owned data that must not be copied into `runs.db`/journal/report.
- `runs.db` writes MUST use rusqlite **bound parameters**, never `format!`/concatenated SQL — security-plan §Input Validation (`runs.db` writes row) + §Security Anti-Patterns → Input. Any new scrub-verdict column added this chunk inherits this.
- MCP read-back child stdout stays a **bounded, non-panicking** boundary: bounded line-delimited JSON-RPC decoding with a soft per-line size bound, faults routed to `VerifyError::{JsonRpc,Decode,Transport}` through the verdict/error wall — security-plan §Input Validation (MCP read-back child stdout row) + §Security Anti-Patterns → Universal. A scrub read-back that pulls excerpt-bearing lines must not raise or remove that bound.
- Any re-shaped `scenarios/pii-scrub.toml` phases re-enter the garde boundary: `[phases.emission]` `kind` REQUIRED whenever the table exists, `occurrences` bounded by `MAX_OCCURRENCES`, per-shape cross-field rules, and **every nested spec field `dive`, never `skip`** — security-plan §Input Validation (scenario-config row) + §Security Anti-Patterns → Input.
- The PREREQ deferral's remedy is the **bounded wait alone** under the advisory-DATABASE-fault branch: re-check each chunk, keep coverage via the audit↔deny overlap VERIFIED green (not assumed), never raise a floor, never add a `deny.toml` ignore, never edit CI — security-plan §Dependency Security (two-fault split). If a dependency lands this chunk, the admission condition tightens to a `cargo deny check advisories bans licenses sources` verified green over the NEW `Cargo.lock`, and "no dependency delta" stops being available as the deferral's basis.

## Patterns to follow
- **Non-content witness recording** — the plan's artifact-sanitization pattern (record `run_id`/`seed`/`scenario`/`p_ids`/verdict/state, withhold host paths and internal struct names) is the same shape the chunk's "category + count + a non-content witness, never the raw excerpt value" boundary needs; per security-plan §Error Handling.
- **Read-back-fed vs. locally-derived field separation** — security-plan §Security Anti-Patterns → Data Protection records that the report `fingerprints[]` column is fed from read-back `Observation#fingerprints` and never from the local blake3 derivation ("the two never meet"). A scrub verdict fed from a read-back surface should keep the same one-way discipline rather than mixing an emitted-payload copy into the artifact.
- **`blocked` rows populate identity fields only, measurement fields JSON `null`** — security-plan §Error Handling. If the scrub surface proves ungradeable under det-L4, this is the recording shape already sanctioned rather than an ad-hoc empty string.
- **Fixed-path, no-`CONDUCTOR_*`-override manifest loading with `e.kind()`-only read faults** — security-plan §Input Validation (committed SUT-facing manifests row) governs `contracts/pulse-run-contract.toml` / `pulse-load-envelope.toml`, both named in the chunk's touched surfaces; a re-shaped envelope or new run-contract term inherits never-defaulted, never-silently-widened validation.
- **Blake3 for any hashing** — if a scrub check needs to compare payload identity without storing the payload, security-plan §Security Anti-Patterns → Data Protection bans MD5/SHA-1/DES/RC4/ECB and points at the shipped blake3 derivation as the live precedent.

## Anti-patterns to avoid
- NEVER let the report/`runs.db`/JSONL/self-obs streams carry a raw excerpt, an absolute host path, or an internal struct name — security-plan §Security Anti-Patterns → Logging. A secret-shaped excerpt (JWT / bearer / API key / `key=value`) in a committed-or-shared artifact also trips §Secret Management's "no secret-shaped string in the workspace" invariant, including in **test pins** (harvest-test verbatim leg lines are files in the tree).
- NEVER have Conductor open, copy, or exfiltrate Pulse's plaintext `corpus.db` directly to obtain scrub evidence — MCP read-back only, per security-plan §Security Anti-Patterns → Data Protection. (Direct `sqlite3` reads of the corpus have precedent only as one-off operator-sanctioned diagnosis, never as production code.)
- NEVER silently downgrade a failed preflight — the preflight runs inside this leg under `conductor-canary`, and each of the five named preconditions must surface as its own distinct `blocked` precondition string, never a false pass and never the generic corpus-empty string — security-plan §Security Anti-Patterns → Universal.

## Contract bindings
- **PII scrubbing ↔ obs §PII Scrubbing**: the "no excerpt content in the self-obs streams" half of the chunk's hygiene invariant is jointly owned — security's artifact-sanitization ban (§Security Anti-Patterns → Logging) covers `runs.db`/report/journal; the self-obs log stream is obs's scrubbing surface. Whether the shipped self-obs pipeline already scrubs emitted-payload values is research's question.
- **PII scrubbing ↔ tests**: no real PII in fixtures, and the harvest-test verbatim leg pins must carry non-content witnesses only (chunk Boundaries: "in test pins as well as in run artifacts"), which is security's secret-shaped-string invariant applied to the tests domain.
- **PREREQ audit deferral ↔ tests §CI Integration**: the audit/deny gate is one CI workflow job; the bounded-wait remedy explicitly forbids a CI edit (security-plan §Dependency Security), so the deferral must not reach the tests domain as a workflow change.
- **Env-handle discipline ↔ arch**: `ANDROMEDA_PULSE_L4_DETERMINISTIC` is a declaration-only read with nothing to validate — never a path, argv element, or log value — and an absent declaration is an unmet run-contract term, never a claimed measurement of `pulse-app` (security-plan §Input Validation).
