## Relevance
Relevant — this is an E2E live-proof chunk for a named catalog scenario the test plan already claims coverage of, plus a harvest-tier test module and an artifact-hygiene negative test.

## Constraints
- `pii-scrub` is covered as an additional auto-scenario instance of Critical Path 1's pattern, not as its own 8th critical path — the path count is capped at 7 (per test-plan §6 Scenario: Headless deterministic scenario run, Cleanup note; §1 Critical paths closing note). Its E2E signal set is Path 1's: exit code, `runs.db` row via bound-parameter `SELECT`, `runs/<run_id>.jsonl` present and parsing to the envelope, MCP read-back (live leg) / stub canary (CI leg).
- `blocked` / `ManualCheck` / `KnownResidual` / `CalibrationRegion` are reported envelope states, never non-zero process exits; only a hard `Fail` exits non-zero (per test-plan §3 `run` exit-code semantics; §11 E2E stack-specific ban). Whatever state the pii family measures to, the row must not be wired into a hard-fail exit.
- The live-Pulse leg is an operator/local gate via `workflow_dispatch` or `scripts/agent-run.sh` and MUST NOT become a CI gate; CI runs the rmcp-stub legs only (per test-plan §9 Live-Pulse scenarios; §11 CI stack-specific ban). A new pii harvest module must therefore assert over pinned verbatim captures at the `conductor-run` unit tier so it stays CI-runnable.
- Artifacts MUST NOT leak absolute host paths or internal seam-crate struct names, enforced by the insta golden plus a tracing field-allowlist redaction layer, with a negative test asserting that boundary (per test-plan §3 Status endpoint shape; §3 Bootstrap → log-format-bind-with-obs; §5 Run report envelope bullet). The chunk's "no excerpt content persisted" claim is the same invariant class extended to payload content — test-plan §3 requires the negative test on the journal; whether the current redaction allowlist already withholds excerpt content from journal / report / `runs.db` / self-obs is research's question.
- Zero-flakiness budget: nextest `retries` stays 0, and synchronization is on an explicit signal (envelope `state`, a JSONL journal line, exit code) — never `sleep(N)` (per test-plan §10 Zero-flakiness budget; §11 E2E ban).
- Test data stays self-generated synthetic OTLP from the seeded `conductor-timeline` generator; the PII corpus is synthetic by data classification, never production data (per test-plan §11 Test Data; §1 Coverage scope, `runs.db` entity).
- The binding coverage gate is `cargo llvm-cov ... --fail-under-lines 60` over the workspace (Minimal tier) and may not be lowered to pass the build (per test-plan §10 Coverage thresholds; §11 Quality).

## Patterns to follow
- Harvest-tier grading: parsers + witness predicates + pinned verbatim leg lines asserted at the `conductor-run` unit tier — `crates/conductor-run/tests/storm_harvest.rs` → `baseline_harvest.rs` → `restart_harvest.rs` (per test-plan §6 Scenarios: Fingerprint-storm / error-baseline-spike / Restart-suppression). A new pii harvest module is the same shape.
- Harness scenario invocation `SCENARIO=<name|P-ID> [SEED=<n>] scripts/agent-run.{sh,ps1} run`, where `--seed` is appended ONLY when `SEED` is explicitly set — otherwise the TOML-declared seed governs and the envelope records the effective seed (per test-plan §3 `run` scenario invocation).
- Envelope assertions: bound-parameter `SELECT` on the `runs.db` row and/or `serde_json::from_str::<RunReportEnvelope>(line)` / `jq -e` on the JSONL journal; `assert_cmd` + `assert_fs::TempDir` with `CONDUCTOR_RUNS_DIR` for the CLI subprocess leg, stdin closed (per test-plan §3 `status` + `logs`; §6 cli driver row).
- Golden discipline: insta in CI/assert mode, fail-don't-write, never `cargo insta review`; envelope/journal goldens redact `run_id` / `journal_emitted_at` / `read_back_observed_at`, and seeded stream goldens are one file per test-file family × seed under `<crate>/tests/snapshots/` (per test-plan §7 Golden artifacts; §11 Universal).
- Preflight inside the leg runs against two derived budgets — the in-process canary poll clamped up to `contracts/pulse-run-contract.toml` `[incident_formation].min_canary_poll_seconds`, and the `agent-run.{sh,ps1}` wall-clock wrapper derived as `warmup_ms/1000 + poll + margin`; a missing contract term is a hard exit 2, never a silent default (per test-plan §3 `boot` Timeout).

## Anti-patterns to avoid
- Never leave a check standing that passes vacuously against a surface which cannot carry its token — the storm/baseline precedent requires retiring such a check to declare-only WITH the measurement recorded (per test-plan §6 Scenario: Fingerprint-storm; §6 Scenario: error-baseline-spike).
- Never fake Pulse's reaction as a CI verdict — the rmcp stub canary proves MCP wiring only; Pulse's actual behavior is a live/local-gate assertion (per test-plan §11 Test Strategy, stack-specific ban).
- Never write an assertion, golden, or harvest pin that embeds excerpt/payload content or a host path — the artifact-sanitization negative test governs test pins as much as run artifacts (per test-plan §3 Status endpoint shape; §11 Unit "no brittle assertions against fixture-internal values").

## Contract bindings
- tests §3 Log format ↔ obs §3: this plan is the SOURCE OF TRUTH for the JSONL journal format and obs derives its envelope from it; the field-allowlist / redaction layer (no host paths, no struct names — the layer that would also have to withhold excerpt content) is the one piece OWNED by obs, and test-plan §3 asserts that boundary via a negative test. Any change either side is a lockstep two-site amendment (per test-plan §3 Bootstrap → log-format-bind-with-obs).
- tests §3 "Self-obs stream is a distinct artifact" ↔ obs §3 / §11: the self-obs stream (`logs/agent-latest.jsonl`, `logs/conductor-tauri.jsonl`) is a SEPARATE schema from the per-run emission journal; the chunk's hygiene claim spans both, but the two must not be conflated in assertions, and a span attribute is gated by the same `conductor-core::redact` allowlist as any event field.
- tests §1 coverage triggers ↔ security: the `runs.db` verdict write path is bound by the bound-parameter-SQL negative/static assertion, and artifact sanitization folds into the envelope golden tests.
- tests §3 `boot` ↔ arch/contracts: `contracts/pulse-run-contract.toml` supplies the derived preflight floors the leg's `boot` must honour; `contracts/pulse-load-envelope.toml` supplies the `[ENVIRONMENT-SUSPECT]` run-level non-lamp qualifier cli selectors must expect if phases re-shape (per test-plan §1 Surfaces under test → cli Signal; §6 Selector strategy).
