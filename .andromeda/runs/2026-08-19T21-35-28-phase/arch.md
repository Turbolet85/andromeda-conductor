# arch extract

## Relevance
Relevant — arch governs the new `conductor-run` → `conductor-faults` crate edge, the `:4317` inbound-bind exception, determinism, and the run-report envelope the live legs must emit.

## Constraints
- The run→faults wiring MUST be an explicit `Cargo.toml` dependency edge between two already-registered workspace members — dependency edges *are* the architecture and a forbidden cross-seam dep must fail to compile; a bin-local shim or a vendored copy of the occupier bypasses the compiler-enforced seam (per architecture.md §Established Decisions [Module Boundaries] · §Project Intent "new module seams … explicit `Cargo.toml` dependency edges" · §Inherited Defaults Module boundaries). No new crate is needed: `conductor-faults` (fault helpers incl. port-occupier) and `conductor-run` (composition root above the seams, below both bins) are both registered (§Occupied Resources Crate names · §Infrastructure Patterns directory tree).
- The `:4317` port-occupier is the SINGLE deliberate exception to "no inbound listener of Conductor's own"; `:4318` is declared unused and Conductor is otherwise a gRPC/MCP *client* only (per architecture.md §Cross-cutting Patterns Trust boundary · §Occupied Resources Ports). The scope's RAII bind→hold→release restatement is this rule, not a new one.
- The verdict/error wall applies to every occupier outcome: verification results are typed VALUES (`Verdict`/`ReportState`), `Result::Err` is reserved for harness faults (per architecture.md §Cross-cutting Patterns Verdict/error wall · §Established Decisions [Error Handling] · §Conventions Error handling). A tension the chunk must resolve: §Standard Contracts "Liveness equivalent (OTLP egress check)" requires the timeline engine to confirm `127.0.0.1:4317` is connectable before emission and to treat a refused transport as `Result::Err` — the occupier deliberately makes that same port unconnectable. Whether the shipped egress/preflight path already distinguishes "occupier-held by design" from "transport down" is research's question, and per the wall the answer must be a typed classification, never a bare error.
- Determinism holds across the driver: the timeline runs on seeded `ChaCha8Rng` + `current_thread` tokio so scenario+seed ⇒ same stream shape, and journal stamps come from `std::time::SystemTime`/`Instant`, never tokio's virtual clock (per architecture.md §Cross-cutting Patterns Determinism discipline · §Established Decisions [Async Runtime Flavor] · [Determinism RNG]).
- SLO grading is journal-relative (`read_back_observed_at − journal_emitted_at`, never wall-clock-from-test-start) against the CLOSED tier set `<5s`/`<20s`/`<90s`; any tier re-calibration must land inside that set (per architecture.md §Established Decisions [Timing-Tolerance Model] · §Conventions Data model conventions — `slo_tier` is a closed TEXT enum).
- Scenario identity stays manifest-driven: "no scenario without a P-ID", membership asserted by `Scenario::check_capabilities` against `contracts/pulse-capabilities.toml`, with two integrity gates held at exact-set equality — `check_sut_drift` (accepted ⇔ classified) and `check_scenario_backing` (`UNBACKED_AUTO`, `Auto`-classified capabilities no scenario names). Re-basing or retiring checks in the family TOMLs must not silently move either ledger (per architecture.md §Established Decisions [Accepted Capability Set] · §Cross-cutting Patterns Scope law). Whether P-001..P-004 are currently classified `Auto` and whether any sits in `UNBACKED_AUTO` is research's question.
- Live dynamic proof against a live Pulse is an OPERATOR/LOCAL gate, never a CI gate — CI has no Pulse instance and runs `cargo build`/nextest/clippy only, on a zero-retry `ci` nextest profile (no retries mask flakes — the determinism invariant) (per architecture.md §Established Decisions [CI/CD] · §Infrastructure Patterns Build system + CI/CD approach). A harvest/live-leg test must therefore be gated, not a default CI-run test.

## Patterns to follow
- Composition-root placement: `conductor-run` holds preflight + `execute_scenario` + `persist` + the live-counter run driver and is shared by `conductor-cli` and `conductor-tauri`; a driver hook wired there is reachable from both bins without duplication (per architecture.md §Occupied Resources Crate names · §Infrastructure Patterns directory tree).
- Declare-only re-basing precedent: a family whose read-back checks are structurally ungradeable ships zero `[[expected]]` checks, and its live rows land `verdict: null` / `state: "KnownResidual"` under the degraded read-back with the claims graded elsewhere — the shape both the error-baseline-spike (2026-08-18) and pii-scrub (2026-08-19) retirements took (per architecture.md §Standard Contracts Run report envelope).
- Emitted OTLP service identity is a registered, deliberately split resource — `conductor` (`DEFAULT_SERVICE_NAME`, scenario dispatcher) vs `conductor-canary` (`CANARY_SERVICE_NAME`, preflight warm-up + storm), because Pulse keys per-service sample counts and error-rate EWMAs. A new emitting path picks one of the registered identities rather than minting an unregistered third (per architecture.md §Occupied Resources Service/process names).
- Typed per-seam `thiserror` enums in library crates, `anyhow` only at the `conductor-cli` / `#[tauri::command]` edges (per architecture.md §Conventions Error handling · §Established Decisions [Error Handling]) — the occupier's failure modes belong in a `conductor-faults` typed enum, not an `anyhow` bubble.
- Contracts artifacts are runtime-read from a fixed `default_path()` through `resolve_under` with deliberately NO `CONDUCTOR_*` override handle (`pulse-capabilities` / `pulse-load-envelope` / `pulse-run-contract`); only `contracts/mcp-contract.toml` has an override (per architecture.md §Occupied Resources On-disk artifacts).

## Anti-patterns to avoid
- No bin-local shim, no duplicated occupier helper, and no re-implementation of `PortOccupier` outside `conductor-faults` to dodge declaring the crate edge (arch §Established Decisions [Module Boundaries]).
- No listener widening: no second inbound port, no `:4318`, no non-loopback bind, and no occupier that outlives its scenario — the exception is exactly one loopback port held under RAII (arch §Cross-cutting Patterns Trust boundary · §Occupied Resources Ports).
- No new `CONDUCTOR_*` env handle for the leg-dir convention (`%TEMP%/pulse-legs/` is an operator convention, not a Conductor resource); the reserved namespace is enumerated and the runs dir already moves with `CONDUCTOR_RUNS_DIR` (arch §Occupied Resources Environment variables).

## Contract bindings
- **Run report envelope ↔ tests + report seam:** the closed `verdict ∈ {Pass, Fail, CalibrationRegion}` / `state ∈ {Pass, Fail, ManualCheck, KnownResidual, Blocked}` shape, `slo_tier` closed enum, and the blocked-row rule (identity fields only; `verdict`/`journal_emitted_at`/`read_back_observed_at`/`latency_ms`/`fingerprints` emitted JSON `null`, stored NULL, excluded from cross-run latency/percentile queries) are what a live-leg or harvest test asserts against (arch §Standard Contracts · §Conventions Data model conventions).
- **Crate edge ↔ obs-plan §4:** the scope's own note — obs records `fault.port_occupier`'s `timeline.execute` parentage as CONDITIONAL because nothing runs it beneath the timeline; the arch-side act that makes it real is the `Cargo.toml` edge + the driver hook. The §4 rewording is obs's wrap-owned amendment, not arch's.
- **Load envelope + capability manifest ↔ tests:** `check_load_envelope`, `check_sut_drift` and `check_scenario_backing` are static catalog gates that run over the committed scenario set, so any TOML re-basing is judged by them rather than by the live leg (arch §Established Decisions [Accepted Capability Set] · §Occupied Resources `contracts/pulse-load-envelope.toml`).
- **Readiness gate ↔ obs + security:** the five named preconditions and the host-path-free / `data_dir`-redacted precondition strings govern how a blocked live leg is reported; the preflight runs inside every scenario leg (arch §Standard Contracts Readiness gate).
- **No arch resource expected to land:** no new crate, no new port beyond the already-registered `:4317` occupier exception, no new env var, and (given the PREREQ's zero-dependency-delta basis) no new §Stack row — so this chunk is not expected to owe arch a §Occupied Resources amendment at wrap.

## Acceptance criteria contributions
- (arch) The driver reaches `conductor-faults` through a declared `Cargo.toml` dependency edge from `conductor-run`, with no bin-local shim and no duplicated occupier implementation (per architecture.md §Established Decisions [Module Boundaries] · §Project Intent).
- (arch) `127.0.0.1:4317` remains the SOLE inbound bind, loopback-only and released on cleanup; no `:4318`, no additional listener, and Conductor's remaining surfaces stay client-side (per architecture.md §Cross-cutting Patterns Trust boundary · §Occupied Resources Ports).
- (arch) Every row the live legs emit conforms to the run-report envelope: `state` from the closed five-variant set, `slo_tier` from the closed `<5s`/`<20s`/`<90s` set, latency measured journal-relative, and any blocked row carrying identity fields only with NULL measurements (per architecture.md §Standard Contracts Run report envelope · §Established Decisions [Timing-Tolerance Model]).
- (arch) Re-based family TOMLs keep every emitting phase inside the two asserted load-envelope terms (`max_sustained_storm_ms`, `max_sustained_rate_spans_per_s`) with the `[[exempt]]` ledger still EMPTY, and leave `check_sut_drift` / `check_scenario_backing` set-equality intact (per architecture.md §Occupied Resources `contracts/pulse-load-envelope.toml` · §Established Decisions [Accepted Capability Set]).

## Relevant amendment history
- **2026-06-26-live-counter-channel-stream** — registered `conductor-run` as the 9th workspace member (the composition root shared by both bins). This is the crate the chunk adds its new outbound edge from; the precedent establishes that a new workspace MEMBER is a registrable arch resource, while a new edge between two already-registered members is not.
- **2026-08-13-dispatcher-determinism-goldens** — inverted the load envelope's asserted terms to the two SUSTAINED per-emitting-phase bounds (`max_scenario_duration_ms` became recorded-but-not-asserted) and retired the `[[exempt]]` ledger to EMPTY, held at exact-set equality in both directions. Any SLO/phase re-shaping of the four family TOMLs is judged against these terms, and re-adding an exemption is a compelled, visible change.
- **2026-08-11-faithful-emission-dispatcher** — landed the declarative `EmissionSpec { signal, occurrences, shape }` model (`occurrences: 0` = deliberate silence window), the integer `error_percent` encoding, and the rule that a nested spec field must `dive`, never `skip` (a skipped nested struct deserializes unvalidated). Directly bears on re-basing the Idle/Stalled phases, which are silence windows.
- **2026-08-09-interpretation-correctness-posture** — added `check_scenario_backing` / the `UNBACKED_AUTO` exact-set gate (only `Auto`-classified capabilities participate) and closed the deterministic-L4 posture as a RECORDED DEFERRAL: "Conductor green" under deterministic L4 means the pipeline carried a canned answer, not that interpretation is trustworthy. This is the standing frame for what a P-001..P-004 live green can honestly claim.
- **2026-08-18-error-baseline-spike-live-proof** and **2026-08-19-pii-scrub-live-proof** — the two immediate precedents for the scope's declare-only-vs-harvest fork: checks measured structurally ungradeable were retired, the families ship zero `[[expected]]` checks, and the arch envelope note names both by name with live rows at `verdict: null` / `state: KnownResidual`.
- **2026-08-18-restart-suppression-live-proof** — registered the `conductor` / `conductor-canary` service-identity split, because preflight runs inside every scenario leg and a shared identity would age the young-sample suppression window and inflate the baseline denominator before phase 1 emits. Relevant to any connection-lifecycle leg whose expected transitions depend on per-service state.
- **2026-08-10-workspace-key-divergence-probe** and **2026-08-10-pulse-run-contract** — grew the readiness gate to FIVE named preconditions and put the unmet-run-contract-terms arm BEFORE the canary arms (an unmet launch condition explains a failed canary). This governs how a blocked live leg on fresh data dirs must read.
- **No prior amendment touches the port-occupier path.** Its only arch registrations are the §Cross-cutting Patterns Trust boundary exception sentence and the §Occupied Resources Ports bullet — both target-state, neither attesting that a driver exists.
