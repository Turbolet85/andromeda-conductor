## Constraints
- The per-P-ID verdict / report-state label set is **closed at six** (`[PASS]`/`[HOLD]`/`[FAIL]`/`[MANUAL]`/`[RESIDUAL]`/`[BLOCKED]`, mirroring the six-state lamp); the typed classification the chunk pins for occupier-bind vs. transport-fault outcomes must map into those six — anything that qualifies the *run* rather than reporting a check rides outside the lamp column as a run-level qualifier (the `[ENVIRONMENT-SUSPECT]` / `not-conductors` Mode-cell precedent), never a seventh lamp (per layout-templates §Surface: cli — Component — Primary content block 2, §Surface: desktop-webview — Component — Primary content block 2).
- `Blocked` is **never red and never a measured verdict**: it must carry its named precondition string and render its measurement columns as `—` / null. A failed `:4317` bind (the expected live condition when Pulse holds the port) classifying `Blocked` must not surface as a red error (per layout-templates §cli Component — Primary content block 1, §desktop Component — Primary content block 2).
- **Headless invariant**: `inquire` operator-pause prompts are `isatty`-gated and the agent-driven `scripts/agent-run.sh` path is *never* blocked on a prompt. Live-proof legs driven through the 5-command harness must not introduce an interactive gate (per layout-templates §cli IA notes — Headless invariant, §cli Component — Hero / signature output).
- **Pipe discipline + color-never-alone**: raw artifact data on stdout, human messages on stderr; ANSI auto-stripped when piped and under `NO_COLOR`/`TERM=dumb`; every status color paired with its always-printed ASCII bracket prefix (per layout-templates §cli IA notes — Pipe discipline, §Surface: cli signature-placement preamble).
- **Output structure is a parsed contract**: downstream agents parse cli stdout, so adding a `comfy-table` column (e.g. an occupier port/bind field) without a `--format` flag is a breaking change; the results/SLO table is 6-column and must not be conflated with the 4-column `conductor coverage` matrix (per layout-templates §cli IA notes — Command model, §cli Component — Primary content block 1).
- **slo_tier renders the scenario's TOML-declared value from the closed set** `<5s` / `<20s` / `<90s`; the chunk's inferred tier re-calibration must land inside that closed set, not widen it (per layout-templates §cli Component — Primary content block 2, §Wireframe — Run console (HOLD)).
- **Derived counts are manifest-sourced, never literals**: the `conductor coverage` roll-up (`82 capabilities · 66 in scope (43 auto (N unbacked) · …)`) is manifest-derived on all three surfaces, the `(N unbacked)` parenthetical qualifies the auto term only and is never a fifth summand — if this chunk names new P-IDs in the family's TOMLs, `UNBACKED_AUTO` moves and the surfaces must re-derive rather than re-pin (per layout-templates §cli Primary screens — `conductor coverage [--write]`).

## Patterns to follow
- **Adapted-not-forked cross-surface rendering**: the same token names carry across desktop CSS vars ↔ cli ANSI (`count-blocked` ↔ ANSI 60, `status-fail` ↔ ANSI 203, `color-id-cyan` ↔ ANSI 117, journal-text ↔ ANSI 146); a new driven leg's output must reuse the existing mapping, not introduce a new code (per layout-templates §cli IA notes — Multi-surface coordination, §desktop IA notes).
- **The Blocked-row shape already templated for the port-occupier**: `• P-0xx  <scenario>  Blocked  <named precondition>` on cli with the precondition on its own detail line, and the hollow-ring `count-blocked` lamp + precondition line on desktop. Whether the code already emits that shape for the receiver-failed / port-conflict leg is research's question (per layout-templates §cli Component — Primary content block 2, §Wireframe — Run report (terminal)).
- **Run-level qualifier precedent** for anything the occupier leg needs to say about the run rather than about a check: printed once, ASCII bracket always rendered, ANSI 246 reuse with no new token, omitted entirely when not applicable (per layout-templates §cli Output structure — `conductor run <scenario>`).
- **Sample-cell de-literalization** when a scenario re-declares its tier: replace the pinned literal with the set-named `<slo_tier>` placeholder rather than substituting a fresh literal (per layout-templates §Wireframe — Run console (HOLD) + §cli Component — Primary content block 2, established by the two 2026-08-18 amendments).
- **Operator-pause signature still applies if the family's timeline holds**: cli spinner STOPS in place at the exact value with the hold-amber `HOLD — operator pause` line above the confirm carrying the frozen count as text (per layout-templates §cli Component — Hero / signature output).

## Anti-patterns to avoid
- Do not introduce a seventh lamp / sixth `ReportState` bracket label for an occupier-bind outcome — classify into the closed six or make it a non-lamp run-level qualifier (per layout-templates §cli Component — Primary content block 2).
- Do not render an unbound / never-measured occupier leg in `status-fail` red, and do not blank its measurement cells into a gray placeholder — `—` / null plus the named precondition (per layout-templates §cli Component — Primary content block 1, §desktop Component — Primary content block 2).
- Do not bake a fresh count or tier literal into any wireframe / caption sample this chunk touches (per layout-templates §cli Primary screens — `conductor coverage`; amendment 2026-08-16-fingerprint-storm-live-proof).

## Contract bindings
- **layouts ↔ verdict/error wall (typed outcomes)**: the six bracket labels / lamp states map 1:1 to the typed run outcomes; the wall owns which type the occupier-bind failure gets, layouts owns that the set stays closed and that `Blocked` never collapses into `Fail`.
- **layouts ↔ obs**: layouts requires the driven leg's state to be legible in the run report + journal-backed artifact (`run report → runs/<run_id>.md`); obs-plan §4 owns the span/parentage side of the same driver wiring.
- **layouts ↔ a11y**: layouts states the behavioral requirement (status never color-alone; verdict/state change announced); a11y derives live-region attributes and conformance.
- **layouts ↔ design**: token *names* only here (`count-blocked`, `status-fail`, `status-residual`, `color-id-cyan`); hex / ANSI values are design's.
- **layouts ↔ backend command surface**: the coverage roll-up's `unbacked` prop is sourced from the `unbacked_auto` command and never mirrored in TypeScript — if TOML P-ID naming moves `UNBACKED_AUTO`, that path is the single source.
