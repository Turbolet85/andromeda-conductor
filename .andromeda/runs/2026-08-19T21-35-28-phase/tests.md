## Constraints
- Live-Pulse legs are an **operator/local gate**, never a CI gate — CI runs the rmcp-stub legs only; the live leg is `workflow_dispatch` / `scripts/agent-run.sh` gated on `ANDROMEDA_PULSE_MCP_ENABLED` (per test-plan §9 Live-Pulse scenarios; §11 CI stack-specific ban). Any P-001..P-004 live evidence must therefore land in a gate-excluded test, not the CI aggregate.
- Reported states are **not** process failures: `blocked` / `ManualCheck` / `KnownResidual` / `CalibrationRegion` are envelope states; only a hard `Fail` exits non-zero (per test-plan §3 `run` exit-code semantics; §11 E2E stack-specific ban). If P-001..P-004 read-back checks retire declare-only, the row must land `verdict` null / `state=KnownResidual` with exit 0.
- The `:4317` port-occupier is the **sole deliberate inbound bind**, must RAII-release on cleanup, and must never become a general-purpose listener; `cleanup` must be idempotent and is verified by file-absence + `SELECT count(*) FROM runs WHERE run_id = ?1` returning 0 + `TcpListener::bind("127.0.0.1:4317")` succeeding (per test-plan §3 5-command → `cleanup` Verification; §11 Universal project-specific ban). Its bind/release is a **chaos/integration** concern, not a unit concern (per §4 conductor-faults bullet; §2 pyramid Chaos row — bounded "typical/high" P-060 profiles only, never saturation).
- Determinism discipline: seeded `conductor-timeline` under `#[tokio::test(flavor="current_thread", start_paused=true)]` + `tokio::time::advance`; journal/report stamps from `std::time::SystemTime`/`Instant`, never tokio's virtual clock (per test-plan §7 Seed strategies; §11 Test Data stack-specific ban). Stream goldens are committed one file per test-file family × seed under `<crate>/tests/snapshots/`, CI fail-don't-write, never `cargo insta review` (per §7 Golden artifacts).
- Harness seed precedence: the scenario leg appends `--seed` **only** when `SEED` is explicitly set — otherwise the TOML-declared seed governs, with identical `.sh`/`.ps1` semantics and the envelope recording the effective seed (per test-plan §3 `run` scenario invocation). Whether the shipped harness already honours this is research's question.
- `boot` on the live leg carries two derived budgets, never literals: the in-process canary poll (`CONDUCTOR_PREFLIGHT_TIMEOUT`, clamped up to `contracts/pulse-run-contract.toml` `[incident_formation].min_canary_poll_seconds`) and the wall-clock wrapper derived as `warmup_ms/1000 + poll + margin`; a missing contract term is a hard exit 2 (per test-plan §3 `boot` Timeout).
- No scenario without a P-ID, and the accepted set stays manifest-driven (per test-plan §11 Universal project-specific; §1 Scenario-catalog entity). Quality gates stay binding: `--fail-under-lines 60`, zero nextest `retries`, audit-green (per §10).

## Patterns to follow
- **Harvest-tier live proof** — when a read-back surface is structurally ungradeable under deterministic L4, the family goes declare-only and the live claim grades as hard predicates over verbatim SUT log lines in a `conductor-run`-unit-tier harvest test (`storm_harvest.rs` → `baseline_harvest.rs` → `restart_harvest.rs` → `pii_harvest.rs` chain, per test-plan §6 Scenarios: Fingerprint-storm / error-baseline-spike / Restart-suppression). This is the named precedent the scope's `pii_harvest.rs` mold points at.
- **Path-1 cli E2E shape** — `assert_cmd` `Command::cargo_bin("conductor")` with `CONDUCTOR_RUNS_DIR` → `assert_fs::TempDir` and stdin closed; assert exit code + the closed six-label bracket set (plus the run-level non-lamp `[ENVIRONMENT-SUSPECT]` qualifier) NO_COLOR-stable + bound-parameter `runs.db` `SELECT` + `runs/<run_id>.jsonl` parsing to the envelope; `TempDir` drop is cleanup (per test-plan §6 cli driver row + Scenario: Headless deterministic scenario run; §3 `status`).
- **Committed declarative scenario fixtures** — serde+garde config one-per-P-ID under `scenarios/`, valid + invalid matrices, driven table-wise by rstest `#[rstest]`/`#[case]`; `#[once]` for the in-memory `runs.db` schema; no developer-seeded DB (per test-plan §7 Seed strategies + Self-bootstrapping requirement; §4 Fixture pattern).
- **Chaos leg mechanics** — `conductor-faults` seeded generators + a loopback `TcpListener` reachability probe (turmoil optional, not load-bearing) for the port-occupier fault; integration DBs are real rusqlite `open_in_memory()` / `TempDir`, never fakes (per test-plan §8 Mocking libraries + What NOT to mock; §2 pyramid Chaos row).
- **Two-site restatement** — the connection-lifecycle verification signal is stated in two places (§1 Critical-paths closing note and §6 Scenario: Headless deterministic scenario run, Cleanup parenthetical); a re-base that touches one and not the other leaves the retired shape standing (per test-plan §1 closing note + §6 Cleanup parenthetical; established at the error-baseline re-base).

## Anti-patterns to avoid
- NEVER fake Pulse's *reaction* as a CI verdict — the rmcp stub canary proves MCP wiring only; Pulse's actual behavior is a live/local-gate assertion (per test-plan §11 Test Strategy stack-specific).
- NEVER treat `blocked`/`ManualCheck`/`KnownResidual`/`CalibrationRegion` as a non-zero exit, and NEVER `sleep(N)` for synchronization — wait on an explicit signal (envelope `state`, a journal line, exit code) (per test-plan §11 E2E).
- NEVER widen the `:4317` bind into a general listener, skip its release-on-cleanup, or make a real (non-loopback) network call from a test (per test-plan §11 Universal project-specific + "NEVER use real network calls in tests").
