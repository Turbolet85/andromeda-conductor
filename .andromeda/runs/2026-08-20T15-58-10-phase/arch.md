## Relevance
Relevant — the chunk edits declarative scenario config, a `contracts/` manifest gate, and a workspace-crate test, all under arch-locked conventions.

## Constraints
- Scenario re-shape MUST stay declarative TOML data (no scenario DSL), serde-deserialized and garde-bounds-checked at load via `Scenario::from_toml_str_with(&str, &CapabilityManifest)`; phase emission stays `EmissionSpec { signal, occurrences, shape }` with `occurrences: 0` reserved as a deliberate silence window, and latency targets MUST satisfy p50≤p95≤p99 ordering — per architecture.md §Conventions (Config conventions) + §Established Decisions [Scenario Config Format].
- The load envelope asserts exactly two terms, judged PER EMITTING PHASE: `max_sustained_storm_ms` and `max_sustained_rate_spans_per_s`; `max_scenario_duration_ms` is recorded but not asserted. The `[[exempt]]` ledger is empty and held to exact-set equality in BOTH directions, so a denser/longer baseline that needs an exemption is a gate failure, not a ledger edit — per architecture.md §Occupied Resources (`contracts/pulse-load-envelope.toml`). `check_load_envelope` (static catalog gate) and `LoadEnvelope::classify` (per-run `[ENVIRONMENT-SUSPECT]` caption) MUST keep reading ONE shared basis.
- Latency is ALWAYS journal-relative (`read_back_observed_at − journal_emitted_at`), never wall-clock-from-test-start; tolerance is tier-scaled over the closed `<5s`/`<20s`/`<90s` set, and sample-count floors (the 50-sample latency floor) plus model-interpretive timings route to the calibration-region bucket instead of hard-failing — per architecture.md §Established Decisions [Timing-Tolerance Model]. `slo_tier` is a closed TEXT enum over exactly those three values and `latency_ms` is INTEGER ms (NULL for blocked rows) — per §Conventions (Data model conventions).
- P-011/P-012 MUST be members of the manifest's accepted set (`contracts/pulse-capabilities.toml`) with matching code-native `coverage_matrix()` rows; `check_sut_drift` holds the two to set-equality and `check_scenario_backing` holds the `UNBACKED_AUTO` pin to exact-set equality — a pin a scenario newly covers is a `CoreError::UnbackedCoverage`, not a silent pass. "No scenario without a P-ID" — per architecture.md §Established Decisions [Accepted Capability Set] + §Conventions (Naming patterns) + §Cross-cutting Patterns (Scope law).
- Grading outcomes are VALUES on the verdict/error wall: `Verdict ∈ {Pass, Fail, CalibrationRegion}` / `ReportState ∈ {Pass, Fail, ManualCheck, KnownResidual, Blocked}` returned as `Ok(...)`; `Result::Err` is reserved for harness faults only (config parse, transport down, MCP unreachable) — per architecture.md §Established Decisions [Error Handling] + §Cross-cutting Patterns (Verdict/error wall). architecture.md §Standard Contracts (Run report envelope) records `latency-regression` as one of SIX declare-only families (zero `[[expected]]`, live rows `verdict: null` / `state: "KnownResidual"`); whether the shipped TOML still declares zero checks, and whether the chunk's read-back design re-adds any, is research's/P4's question.
- Determinism discipline holds over the re-shape: seeded `ChaCha8Rng` + `current_thread` runtime give "same scenario + seed ⇒ same stream shape", and journal wall-clock stamps come from `std::time::SystemTime`/`Instant`, never tokio's virtual clock — per architecture.md §Cross-cutting Patterns (Determinism discipline) + §Established Decisions [Determinism RNG].
- The live leg is an operator/local gate, never a CI gate (CI has no Pulse); nextest runs the zero-retry `ci` profile because retries mask flakes — per architecture.md §Established Decisions [CI/CD] + §Infrastructure Patterns (Build system).

## Patterns to follow
- Workspace placement is settled and additive-only: scenario data in `scenarios/`, pinned manifests in `contracts/`, the harvest predicates in `crates/conductor-run/tests/` (conductor-run is the composition root above the seams and below both bins), latency-shaping emit primitives in `conductor-emit` — per architecture.md §Infrastructure Patterns (Directory structure) + §Occupied Resources (Crate names).
- Contract-manifest access pattern: `contracts/pulse-load-envelope.toml` resolves from a fixed `LoadEnvelope::default_path()` through `resolve_under` with deliberately NO `CONDUCTOR_*` override handle (the capability-manifest precedent); its terms are a transcribed SUT record, never a Conductor measurement, which `provenance` states — per architecture.md §Occupied Resources.
- Nested-spec validation pattern: a nested spec field must `dive`, never `skip` (a `skip`ped nested struct deserializes unvalidated); cross-field invariants spanning distinct fields sit field-level one altitude up (the `no_duplicate_pids` / `fault_phases_are_silent` shape), since garde 0.22.1 has no container-level custom — per architecture.md §Established Decisions [Validation Library].
- Live-leg environment pattern: `CONDUCTOR_RUNS_DIR` / `CONDUCTOR_SCENARIOS_DIR` / `CONDUCTOR_SEED` / `CONDUCTOR_AGENT_MODE` / `CONDUCTOR_PREFLIGHT_TIMEOUT` (floored by `[incident_formation].min_canary_poll_seconds`) are the reserved handles; `ANDROMEDA_PULSE_DATA_DIR` MUST be propagated to the spawned sidecar, and `ANDROMEDA_PULSE_L4_DETERMINISTIC` is READ as the run contract's shell-declaration proxy, never set by Conductor — per architecture.md §Occupied Resources (Environment variables).
- Per-service accumulation is wire-visible identity: the emitted `service.name` split (`conductor` = `DEFAULT_SERVICE_NAME` dispatcher vs `conductor-canary` = `CANARY_SERVICE_NAME` preflight) exists precisely because Pulse keys per-service sample counts and error-rate EWMAs — the "accumulated history" a latency re-shape must reason about is per-service — per architecture.md §Occupied Resources (Service / process names).

## Anti-patterns to avoid
- Do NOT add an imperative scenario DSL, a new external crate, a new workspace member, a new `CONDUCTOR_*` env var, or a `CONDUCTOR_*` override handle for the load-envelope path — the re-shape is declarative data over shipped primitives (architecture.md §Conventions Config conventions · §Occupied Resources).
- Do NOT widen `slo_tier` beyond the closed `<5s`/`<20s`/`<90s` set, and do NOT compute latency from wall-clock-from-test-start or from tokio's virtual clock (architecture.md §Conventions Data model conventions · §Established Decisions [Timing-Tolerance Model]).
- Do NOT relax the load-envelope gate to admit the re-shape — no `[[exempt]]` entry, no term edit, no `deny.toml` ignore or advisory-floor raise for the PREREQ; `cargo deny` stays green and the `cargo audit` advisory-DB fault is a bounded wait (architecture.md §Occupied Resources `pulse-load-envelope.toml` · §Infrastructure Patterns Build system).

## Contract bindings
- **Load-envelope gate ↔ tests:** `check_load_envelope` (static catalog) and `LoadEnvelope::classify` (run-level caption) share one basis, so a re-shape that moves one moves both — a catalog test and a live-run caption cannot disagree (arch §Occupied Resources).
- **Run-report envelope ↔ obs/tests harness:** the harvest predicates in `crates/conductor-run/tests/baseline_harvest.rs` grade witnesses from the self-observation `tracing` JSON stream (`logs/agent-latest.jsonl`, a SEPARATE artifact + schema from the per-run emission journal, moving with `CONDUCTOR_RUNS_DIR`) — line shape is obs-plan §3's domain; arch fixes only the artifact identity and the envelope fields (`latency_ms` INTEGER, `journal_emitted_at`/`read_back_observed_at` TEXT RFC-3339, `run_id` hyphen-delimited) (arch §Occupied Resources On-disk artifacts · §Standard Contracts Timestamp formats).
- **Capability manifest ↔ coverage classification:** any change to which scenario backs P-011/P-012 crosses `check_sut_drift` + `check_scenario_backing`/`UNBACKED_AUTO` (arch §Established Decisions [Accepted Capability Set]).
- **Readiness gate ↔ the read-back design:** the preflight canary's incident is freshness-carried and the gate has FIVE named preconditions; arch does not license keying a scenario's grading on the canary incident persisting — the row's non-Blocked clause must not assume it (arch §Standard Contracts Readiness gate).

## Acceptance criteria contributions
- (arch) Every re-shaped emitting phase passes `check_load_envelope` unaided against `max_sustained_storm_ms` and `max_sustained_rate_spans_per_s`, with the `[[exempt]]` ledger still exactly empty in both directions (per architecture.md §Occupied Resources — `contracts/pulse-load-envelope.toml`).
- (arch) The re-shape lands as declarative TOML phase data that garde validates at load — nested specs `dive` (never `skip`), latency targets hold p50≤p95≤p99, and any fault/silence phase keeps `occurrences = 0` (per architecture.md §Conventions Config conventions + §Established Decisions [Validation Library]).
- (arch) Any `slo_tier` change stays inside the closed `<5s`/`<20s`/`<90s` set and all latency figures remain journal-relative (`read_back_observed_at − journal_emitted_at`) with `latency_ms` as INTEGER ms (per architecture.md §Conventions Data model conventions + §Established Decisions [Timing-Tolerance Model]).
- (arch) No new workspace crate, port, external dependency, or `CONDUCTOR_*` env var; changes land only in `scenarios/`, `contracts/`, `crates/conductor-run/tests/`, and `evidence/` (per architecture.md §Occupied Resources + §Infrastructure Patterns Directory structure).
