# obs extract

## Relevance
Partial — obs governs the latency/SLO envelope fields, the fault-span surface raised by re-shaped ramp/silence phases, and the self-obs line shape the harvest predicates grade; the cue mechanism and scenario semantics are arch/domain.

## Constraints
- Latency is a **JSON field assertion, not an instrument**: `latency_ms = read_back_observed_at − journal_emitted_at` in wall-clock (`std::time::SystemTime`/`Instant`), asserted against the closed `slo_tier` enum (`<5s` / `<20s` / `<90s`) at report-generation time — obs-plan §5 Metric Coverage + §10 Performance budgets require this; a longer/denser baseline that pushes wall-clock latency past the declared tier flips the report-time assertion, so an SLO-tier change on `scenarios/latency-regression.toml` is an obs-governed edit, not a free knob (per obs-plan §10).
- **Never tokio's virtual clock** for journal timestamps or the fault-span journal offsets the re-shape produces — wall-clock only, to preserve journal-relative SLO math (per obs-plan §11 Project-specific bans).
- A re-shaped **ramp phase** must raise `fault.ramp` with exactly `fault_type` / `fault_duration_ms` / `fault_start_offset_ms` / `ramp_factor`, where `ramp_factor` is the normalized **signed** slope `(to_rate − from_rate) / max(from_rate, to_rate)` over `EmissionShape::Ramp`'s integer rates, range −1.0..1.0; a silence gap raises `fault.silence` with the first three. Both open from the caller-supplied per-phase hook, are **created-not-entered**, are children of `timeline.execute`, and close at the phase boundary (per obs-plan §4 Fault-injection spans / "Where each span opens"). Whether the shipped latency-regression phases already raise these spans is research's question.
- Any attribute the harvest predicates grade must be a name in `conductor-core::redact::ALLOWLISTED_FIELDS` — the processor stage drops anything else, so a non-allowlisted attribute emits nothing; unbounded witness detail rides the allowlisted `message` field instead (per obs-plan §4 Required-span-attributes constraint + §11 PII Scrubbing).
- The predicates grade the **self-obs line** (base set: `timestamp_ms` / `level` / `target` / service identity / `run_id`, plus the span-lifecycle variant's `span` / `span_event` (`new`|`close`) / optional `parent` / allowlisted attributes on `new`) — NOT the eleven-field Run-report envelope, which is the scenario-result record written by the report seam (per obs-plan §3 Log format JSON schema, "two record shapes").
- Fault-span **lifecycle is `info`**, so fault phases are visible under the default INFO filter without a `RUST_LOG` opt-in; a debug-level witness needs the **additive** form `RUST_LOG=info,{crate}=debug` (a bare per-target directive replaces the default and blacks out every other crate), and neither form may be set for a run that also executes the test suite (per obs-plan §6 Log levels + §3 Per-module log levels).
- A denser baseline raises per-record volume: per-record processing stays at `trace`/`debug`; never `info` in the inner loop (per obs-plan §11 Logs).

## Patterns to follow
- **Harvest-tier grading over the SUT's own tracing lines** with the standard eleven-field envelope and no bespoke envelope extra — the declare-only landing shape recorded for restart-suppression (`verdict` null, `state` "KnownResidual" under a degraded read-back, evidence graded in `restart_harvest.rs`) is the in-plan precedent for scope item 2's harvest route (per obs-plan §4 Restart-suppression scenario + §1 critical-paths table).
- **Shape witness on the `message` field**: the `verify.readback` observed-key-set witness and the `emit.batch` wire-shape witness exist because readers degrade to empty on an unrecognized shape, making a field-name divergence indistinguishable from an empty corpus — the same construction answers the scope's open premise "whether the shipped fixtures' shape matches the live line shape" (per obs-plan §6 Boundary-call wrappers).
- **Measured offsets recorded verbatim from the leg**: restart-suppression's `fault.silence` offsets (7006ms / 76436ms) were pinned from a live leg into §4 — the same treatment applies to this chunk's witness offsets (per obs-plan §4 Restart-suppression scenario).
- **Span-lifecycle lines as the machine-readable witness**: a §4 span materializes as real `new`/`close` lines carrying `parent` and its allowlisted attributes, which is what makes a span assertable by a test predicate rather than implicit (per obs-plan §3 two record shapes).
- Boundary read-back logging already mandates tool name + `latency_ms` + error + canary result on `verify.readback` — the latency witness for a read-back-tier design comes from there (per obs-plan §6 Boundary-call wrappers).

## Anti-patterns to avoid
- NEVER add an OTel histogram / meter provider to "measure" the latency regression — Minimal tier has no metrics backend and a meter re-introduces the banned SDK plus background tasks that break `current_thread` determinism; the budget is the `latency_ms`/`slo_tier` field assertion (per obs-plan §11 Metrics + §11 Telemetry Strategy).
- NEVER mint a high-cardinality or unbuildable span name for the re-shape — the bounded set is `scenario.run`, `timeline.execute*`, `emit.batch`, `emit.logs_batch`, `verify.readback*`, `report.generate`, `db.insert_run`, `fault.silence`/`ramp`/`port_occupier`, `tauri.command.*`; a family-specific chain mandated but never built is the exact failure the restart-suppression retirement corrected (per obs-plan §11 Spans / Traces).
- NEVER let leg evidence or pinned predicate fixtures carry absolute host paths or Debug-dumped struct fields — redaction is at the processor stage via the field-name allowlist + host-file-path value scrub (per obs-plan §11 PII Scrubbing + §9 Log conformance check).

## Contract bindings
- **obs ↔ tests harness (test-plan §3)**: test-plan §3 OWNS the JSONL self-obs line format and the eleven-field envelope; obs-plan §3 derives from it. `baseline_harvest.rs`'s latency predicates consume that line shape, so a re-pin that changes what a line must carry is a two-sided change (the D-tests-obs-harness one-sided-change guard), per obs-plan §3 Log format JSON schema.
- **obs ↔ tests (SLO gate)**: `slo_tier`/`latency_ms` assertion at report-generation time is obs-specified but test-asserted (per obs-plan §10 Performance budgets).
- **obs ↔ CI/supply-chain**: a `cargo-audit` red flag is an obs-listed build/deploy failure condition and the audit report is a §9 CI artifact — the chunk's 32nd `cargo audit` re-check PREREQ closes against that gate (per obs-plan §10 Build / deploy failure conditions + §9).

## Acceptance criteria contributions
- Each re-shaped ramp/silence phase materializes span-lifecycle lines (`span_event` `new` + `close`, `parent: "timeline.execute"`) carrying exactly the §4 attribute set for that fault kind — `ramp_factor` a signed value in −1.0..1.0 — quoted verbatim from the leg into evidence (per obs-plan §4 Fault-injection spans).
- The re-shaped run's envelope row carries the eleven-field Run-report envelope with `latency_ms` computed wall-clock from `read_back_observed_at − journal_emitted_at` and a `slo_tier` from the closed enum, and the report-time assertion `latency_ms <= threshold(slo_tier)` governs the row's state (per obs-plan §5 + §10).
- Every field the pinned latency predicates grade is either an `ALLOWLISTED_FIELDS` name or carried on `message`; no predicate depends on an attribute the processor stage drops (per obs-plan §4 Required-span-attributes constraint).
- Live legs produce zero unstructured panic lines (`^thread.*panicked`) and no absolute host paths in `logs/agent-latest.jsonl` or the evidence excerpts (per obs-plan §9 Zero-unlogged-panics gate + §10 SLO invariant).
