## Constraints
- The re-shaped `scenarios/latency-regression.toml` phases remain an external-input boundary: `[phases.emission]` `kind` is REQUIRED whenever the table exists (no inferred default), `occurrences` is bounded by `MAX_OCCURRENCES` (`0` = a declared silence window), and the per-shape cross-field rules — notably percentile ordering p50≤p95≤p99, which the sharper/shorter spike directly moves — must hold at load, with a failed garde `Report` becoming `ConfigError` (harness fault, never a verdict) (per security-plan §Input Validation, scenario-config row).
- Every nested spec field reachable from `PhaseSpec` must be annotated `dive`, never `skip` — a skipped nested struct deserializes entirely unvalidated because garde never descends into it, so its rules never execute even though they exist (per security-plan §Input Validation; §Security Anti-Patterns → Input). Whether the fields the re-shape touches already carry `dive` is research's question.
- `contracts/pulse-load-envelope.toml` is a committed SUT-facing manifest validated by an explicit `validate()` in `conductor-core`, resolved from a fixed `default_path()` through `resolve_under` with deliberately **no** `CONDUCTOR_*` override handle; absent/malformed is a hard harness fault, **never defaulted and never silently widened**, and read faults carry `e.kind()` only, never the path (per security-plan §Input Validation, committed-SUT-facing-manifests row). The chunk's exempt-ledger-can-only-shrink rule is the same never-widen mandate on the security side.
- The 32nd re-check is governed by the two-fault split: an advisory-DATABASE fault (RustSec DB unparseable) admits **only** a bounded wait with the audit↔deny overlap VERIFIED green — never a floor raise, never a `deny.toml` ignore, never a CI edit, never a silent accept (per security-plan §Dependency Security). If any dependency delta lands (the scope calls no new external crates [inferred]), it may land under a red audit **only** on `cargo deny check advisories bans licenses sources` verified green over the NEW `Cargo.lock`, with the deferral's basis restated (per security-plan §Dependency Security, advisory-DATABASE fault bullet).
- Live-leg artifacts (`<run_id>.md`, `runs.db` rows, JSONL journals) must carry verdict/state/identity fields only and must not leak absolute host paths — canonicalized `CONDUCTOR_*` directories or the fresh `%TEMP%` `ANDROMEDA_PULSE_DATA_DIR` — nor internal seam-crate struct names (per security-plan §Error Handling, run-report artifact sanitization; §Security Anti-Patterns → Logging). Whether the shipped emitters already satisfy this on the paths this leg exercises is research's question.
- Journal/report wall-clock stamps must come from `std::time::SystemTime`/`Instant`, never tokio's virtual clock, so journal-relative SLO math stays correct — a wrong clock source corrupts the ground-truth artifact (per security-plan §Security Anti-Patterns → Logging). This binds tightly to a chunk whose deliverable is witness offsets and spike timing.
- The live leg's read-back grading may not silently downgrade a failed precondition: each of the five named preconditions must surface as the distinct `blocked` state with its own precondition string, never a false pass and never the generic corpus-empty string (per security-plan §Security Anti-Patterns → Universal). The scope's "re-thought non-Blocked clause" must not convert an unmet precondition into a pass.

## Patterns to follow
- garde `#[derive(Validate)]` `range` + `#[garde(custom)]` cross-field rules co-located with the serde structs in their owning seam crate, failing to `ConfigError` via `#[from]` (per security-plan §Input Validation).
- Fixed-path manifest loading — `default_path()` → `resolve_under`, explicit `validate()` in `conductor-core`, `e.kind()`-only read faults — as the shape any envelope/contract read follows (per security-plan §Input Validation).
- The verdict/error wall: verification outcomes as typed VALUES returned `Ok(...)`, `Result::Err` reserved for harness faults; MCP/`tonic::Status` errors are first-class typed inputs, never panics (per security-plan §Error Handling).
- The `deny.toml` justified-exception mechanism (per-advisory ignore / license allow, each with a comment) as the ONLY documented widening path, with `deny.toml` itself the authority on the full set (per security-plan §Dependency Security, Accepted exceptions).
- Hardened sidecar spawn for the live legs: fixed hard-coded `andromeda-pulse-mcp` program path, `ANDROMEDA_PULSE_DATA_DIR` passed strictly through the `.env(...)` builder with argument-injection metacharacters rejected first, never interpolated into argv or a shell (per security-plan §Security Anti-Patterns → Input, Code Patterns).

## Anti-patterns to avoid
- NEVER mark a nested spec field `#[garde(skip)]` while re-shaping phase structs — the rules exist but never run, silently bypassing the boundary (per security-plan §Security Anti-Patterns → Input).
- NEVER resolve the red audit with a floor raise, a `deny.toml` ignore, or a CI edit — the fault is in the advisory database, so each of those looks like compliance while changing nothing (per security-plan §Dependency Security; §Security Anti-Patterns → Universal).
- NEVER let `Cargo.lock` drift or go uncommitted, and never run the release gate green-less — the committed lock is what makes the deny overlap deterministic while audit is red (per security-plan §Security Anti-Patterns → Universal).

## Contract bindings
- **Artifact path hygiene ↔ tests:** scope item 4 re-pins the `crates/conductor-run/tests/baseline_harvest.rs` latency predicates **VERBATIM** from this chunk's live leg — verbatim transcription from a fresh-`%TEMP%`-dir run is exactly where an absolute host path or internal struct name can enter a committed file, so the §Error Handling / §Anti-Patterns → Logging sanitization mandate binds to the tests plan's fixture rules.
- **Dependency gate ↔ tests §CI Integration:** the audit/deny gate is one job in the single existing workflow; the PREREQ is a recorded re-check, and §Dependency Security forbids a CI edit as its remedy.
- **Load-envelope never-widen ↔ arch/tests:** the `[[exempt]]` exact-set-equality guard is the tests-side expression of the §Input Validation "never defaulted, never silently widened" manifest rule.
