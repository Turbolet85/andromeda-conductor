## Relevance
Relevant — the chunk is predominantly test-domain: harvest-tier predicates, a live operator-gate leg, seeded-stream determinism, and two CI quality gates (load envelope, supply-chain audit).

## Constraints
- Live-Pulse legs are an **operator/local gate** (`workflow_dispatch` or `scripts/agent-run.sh`), never a CI gate; CI runs the rmcp-stub legs only — so the fresh-dir live leg in scope item 3 must not become a CI-gating test (per test-plan §9 Live-Pulse scenarios).
- The harness scenario leg is `SCENARIO=<name|P-ID> [SEED=<n>] scripts/agent-run.{sh,ps1} run`, and §3 requires `--seed` be appended ONLY when `SEED` is explicitly set — with it unset the TOML-declared seed governs, with identical `.sh`/`.ps1` semantics, and the envelope records the effective seed (per test-plan §3 `run`). Whether the shipped wrappers already honour this is research's question.
- Determinism is a hard bar: same scenario+seed ⇒ same stream shape, asserted by committed seeded-stream goldens (one file per test-file family × seed: `replay__*` · `pacing__*` · `dispatch_wire__*`), CI fail-don't-write — a phase re-shape changes the input to those goldens (per test-plan §7 Golden artifacts + §1 property-test trigger).
- Any scenario-TOML edit must survive garde at load: non-negative durations, bounded per-phase occurrences, **p50 ≤ p95 ≤ p99 ordering**, severity-mix sums, and the per-shape emission rules — with the negative-test matrix required to catch a nested spec field annotated `skip` rather than `dive` (per test-plan §1 Trigger *security-vector-coverage / property-test* + §4 Scenario-config validation surface). The latency re-shape edits exactly the p50/p95/p99 + duration terms these rules govern.
- Fault/chaos coverage is **bounded "typical/high" profiles (P-060) only**; perf budgets are N/A at this tier — a denser/longer baseline may not become a saturation regime (per test-plan §1 chaos-test trigger + §10 Performance budgets).
- The per-run `runs/<run_id>.jsonl` journal is the SLO ground truth and "the left side of every SLO check": wall-clock stamps from `std::time::SystemTime` (never tokio's virtual clock), one JSON object per line, envelope identity fields incl. `latency_ms` + `slo_tier`, no absolute host paths or internal struct names (per test-plan §3 `logs` + Log format + Status endpoint shape).
- Quality gates bind: line coverage ≥ 60% via `--fail-under-lines 60`, zero-retry flakiness budget (a flake is quarantined + root-caused, never retried), and build-failure on `cargo audit --deny warnings` / `cargo deny check` non-green or `Cargo.lock` drift (per test-plan §10).

## Patterns to follow
- **Harvest-tier grading with a declare-only row** — the established shape across five siblings (`storm_harvest.rs` → `baseline_harvest.rs` → `restart_harvest.rs` → `pii_harvest.rs` → `connection_harvest.rs`): the scenario row lands `verdict` null / `state=KnownResidual`, non-Blocked, `latency_ms` against the declared `slo_tier`, while the live claim grades as hard predicates at the `conductor-run` unit tier over test-only harvested Pulse lines (per test-plan §6 Scenarios 1–3 + §1 Critical Paths 1–3).
- **Verbatim leg pinning with recorded-not-asserted arms** — the restart precedent pins predicates from the leg's captured lines, records structurally unreachable arms rather than asserting them, and treats redacted counters as carrying no evidence (per test-plan §6 Restart-suppression).
- **Two-site restatement** — a re-based verification signal must be restated at BOTH §6 E2E scenario and §1 Critical paths; a single-site apply leaves the twin asserting the retired shape (per test-plan §6/§1, the error-baseline two-site rule).
- **cli E2E driver shape** — assert_cmd `Command::cargo_bin("conductor")` + `CONDUCTOR_RUNS_DIR` → `assert_fs::TempDir`, stdin closed, NO_COLOR-stable assertions over the closed six-label lamp set plus the run-level non-lamp `[ENVIRONMENT-SUSPECT]` caption; `runs.db` read via bound-parameter `SELECT` (per test-plan §6 driver table + Selector strategy).
- **Fixture/layout conventions** — crate-local `tests/` for the harvest files, rstest `#[fixture]` seeded generators + `#[rstest]`/`#[case]` table rows, snake_case test fns, committed declarative scenario config under `scenarios/` (per test-plan §2 directory/naming + §4 fixture pattern + §7).

## Anti-patterns to avoid
- NEVER let the denser/longer baseline escalate into load/saturation testing — 50k+ spans/sec regimes are Pulse's `perf_load_profiles.rs`, explicitly out of Conductor scope (per test-plan §11 Test Strategy, stack-specific).
- NEVER treat `KnownResidual` / `Blocked` / `CalibrationRegion` as a non-zero process exit — only a hard `Fail` exits non-zero (per test-plan §11 E2E, stack-specific).
- NEVER fake Pulse's *reaction* as a CI verdict, and NEVER accept re-shaped goldens through `cargo insta review` or synchronize a leg with `sleep(N)` — stubs prove wiring only; goldens are CI fail-don't-write; waits key on an explicit signal (per test-plan §11 Test Strategy / E2E / Universal).

## Contract bindings
- **tests §3 ↔ obs §3/§11 (log format):** test-plan §3 is the declared SOURCE OF TRUTH for the JSONL format and for the self-obs stream's two line variants (event line at whatever level obs-plan §11 assigns; span-lifecycle line with `span`/`span_event`/`parent`); obs derives from it and owns only the field-allowlist/redaction layer. The chunk's witness-offset harvest and the verification-harness self-obs choreography cues read that stream, so a format change here is a harness break and requires the lockstep §3↔§3 amendment (per test-plan §3 log-format-bind-with-obs).
- **tests §9 ↔ security §Dependency Security:** the supply-chain stage (`cargo audit --deny warnings` + `cargo deny check` advisories/licenses/bans/sources, committed un-drifted `Cargo.lock`) runs in the same workflow as the test gates — this is the binding the chunk's 32nd-re-check PREREQ closes against (per test-plan §9 pipeline + §10 Build failure conditions).
- **cli label set ↔ load-envelope contract:** `[ENVIRONMENT-SUSPECT]` is a run-level, non-lamp caption printed outside the lamp column when a run breaches the load envelope; cli selectors must assert the named six-label set PLUS that qualifier rather than assuming stdout carries only six — relevant to the `check_load_envelope` re-run over re-shaped phases (per test-plan §1 cli Signal + §6 Selector strategy).
