# a11y extract

## Relevance
Partial (narrow) — no UI/webview surface is touched; the only a11y stake is the typed `Verdict`/`ReportState` vocabulary the killing tests pin, the journal-stamp fields a11y reproduces from obs, and the not-assertable-cli / zero-retry / artifact-hygiene guardrails.

## Constraints
- a11y-plan §1 (A11y Scope Summary) fixes tier **Minimal (0)** with exactly ONE assertable surface (Tauri desktop-webview); the `conductor-cli` / headless `conductor run` paths this chunk hardens are declared **not-assertable** (no DOM/widget tree, no axe/Lighthouse reach), so no WCAG assertion is required or permitted for them.
- a11y-plan §6 (State color tokens → State-naming crosswalk) makes the display-label ↔ obs `verdict` ↔ obs `state` join **binding**: `Pass|HOLD|Fail|Blocked|Manual|Residual` ↔ `Pass|Fail|CalibrationRegion` ↔ `Pass|Fail|ManualCheck|KnownResidual|Blocked`. Killing tests that assert typed values must pin those exact variant spellings, since the six-lamp join keys on them. Whether the crates' current enums already match the crosswalk is research's question.
- a11y-plan §6 further requires **verdict-first lamp precedence** (`verdict == CalibrationRegion` ⇒ HOLD lamp regardless of `state`; identify/join HOLD on `verdict`, never on `state`) — a `declares`-family assertion that encodes a state-first mapping would contradict it.
- a11y-plan §3 (Structured violation JSON schema) requires a11y emissions to align **verbatim** with the obs §6 envelope, whose time fields (`journal_emitted_at`, `read_back_observed_at`, `latency_ms`) derive from the `SystemTime` stamp helpers this chunk hardens — stamp semantics/field names must stay compatible or a11y's reproduction drifts.
- a11y-plan §9 (CI Integration, Unit row) records **no UI a11y tests at the unit layer**, and places the axe/contrast/keyboard gate on the tests' `wdio run` webview-E2E job as an operator/local gate — so this chunk adds no a11y gate and must not pull a11y work into the Rust unit/integration lane.
- a11y-plan §10 (SLO Invariants) requires a **zero-retry** stance explicitly paralleling tests' "do NOT set cargo-nextest `retries` > 0"; the runner-portability fix must remove the cause, not add retries/reruns.
- a11y-plan §9 (CI-specific resource attributes) requires artifacts to carry no absolute host paths and no internal seam-crate struct names — the same constraint the chunk states for artifacts its tests write/read back.

## Patterns to follow
- **Reuse the one existing harness, never stand a parallel one** (§3 A11y testing tool pick; §11 CI): a11y injects axe into the tests' already-installed `@crabnebula/tauri-driver`/WebdriverIO session rather than a second automation stack — the same "one runner, fixed at the cause" discipline this chunk's §B3 work applies.
- **Machine-verifiable evidence only** (§2 Agent-runnable invariants): every criterion needs a JSON/typed verification path; manual or narrative attestation is supplemental, never sole — parallels the chunk's typed-value assertion wall (never panics-as-assertions).
- **Fold results into the obs envelope, add no top-level fields** (§3 Structured violation JSON schema): axe rule-id + WCAG tag + selector ride inside `fingerprints[]`; any new run-level signal follows the same fold rather than widening the schema.
- **Crosswalk as the join** (§6): the enum value is the join key and the display label is the assertion target — keep them separable when tests pin outcomes.

## Anti-patterns to avoid
- §11 Universal: NEVER treat the cli surface as accessibility-assertable — its ASCII status prefixes / NO_COLOR text-pairing are output-stream discipline, not an ARIA verification path; no a11y check may be attached to the CLI-side survivors.
- §11 SLO: NEVER a retry-once policy to make a failing lane green — masks real failures (the explicit parallel to nextest `retries = 0`).
- §11 SLO: NEVER let artifacts leak absolute host paths or internal seam-crate struct names into the obs §6 envelope.

## Contract bindings
- **a11y ↔ obs** (a11y §3 Structured violation JSON schema → obs §6 Log Format): a11y reproduces the obs envelope verbatim; the `now_ms` / `now_unix_nanos` stamp helpers in this chunk's survivor family feed its time fields, so a rename or semantic change cascades into a11y §3's reproduction (cascade precedent recorded in the 2026-06-16 amendment).
- **a11y ↔ tests** (a11y §3 + §9): a11y's gate rides tests' binding 5-command harness (results surfaced via `logs`) on the same Linux+xvfb `wdio run` webview-E2E job — any runner/profile change tests own is inherited by the a11y gate.
- **a11y ↔ design** (§6 token pairs / motion / focus ring): not engaged — this chunk renders nothing.

## Acceptance criteria contributions
- (a11y) No a11y assertion or gate is attached to the cli / headless paths hardened here; the cli stays not-assertable (per a11y-plan §1 A11y Scope Summary + §11 Universal).
- (a11y) Any killing test that pins typed outcomes uses the crosswalk variant spellings — `Verdict::{Pass, Fail, CalibrationRegion}` and state `{Pass, Fail, ManualCheck, KnownResidual, Blocked}` — with HOLD identified verdict-first, so the six-lamp join stays valid (per a11y-plan §6 State color tokens — State-naming crosswalk).
- (a11y) Journal-stamp work preserves the obs §6 field semantics a11y reproduces verbatim (`journal_emitted_at` / `read_back_observed_at` / `latency_ms`): no field renamed, dropped, or re-typed (per a11y-plan §3 Structured violation JSON schema).
- (a11y) The runner-portability fix leaves the zero-retry stance intact (no `retries > 0` in any profile) and any artifact written or read back carries no host paths or internal struct names (per a11y-plan §10 SLO Invariants + §9 CI-specific resource attributes).
