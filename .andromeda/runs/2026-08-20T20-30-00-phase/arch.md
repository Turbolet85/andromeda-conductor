# arch extract

## Relevance
Relevant — arch governs crate placement, the readiness-gate/run-contract contract shapes the survivor assertions must pin, the verdict/error wall the killing tests must use, the determinism/`std::time` stamp rule, and the dependency/resource registry the rider touches.

## Constraints
- **Crate-per-seam placement is compiler-enforced; the four touched units are all registered workspace members** (`conductor-core`, `conductor-verify`, `conductor-run`, `conductor-cli`) — per architecture.md §Occupied Resources (Crate names) and §Established Decisions [Module Boundaries]. New tests and any test-support code must stay inside the crate that owns the seam; no new workspace member, no new cross-seam dependency edge (`conductor-run → conductor-faults` is the only recently added edge, §Occupied Resources).
- **Verdict/error wall: verification outcomes are typed values, `Result::Err` is reserved for harness faults** — per §Established Decisions [Error Handling], §Conventions (Error handling), §Cross-cutting Patterns (Verdict/error wall). Read-back transport/decode/JSON-RPC failures must fan out into `VerifyError` variants (`Transport`/`Protocol`/`Decode`/`JsonRpc`); a breached read-back line bound is therefore required to surface as a typed error, never a panic and never a verdict. Whether `jsonrpc.rs`'s current guard already lands in that fan-out is research's question.
- **Journal stamps must come from `std::time::SystemTime`/`Instant`, never tokio's virtual clock** — per §Cross-cutting Patterns (Determinism discipline) and §Conventions (Data model conventions), which make the journal-relative SLO math (`latency_ms` INTEGER) depend on real-clock stamps. The engine runs on the `current_thread` flavor precisely so timing is deterministic (§Established Decisions [Async Runtime Flavor]), so a paused-clock advance assertion is admissible only on the scheduling path, not on the stamp helpers.
- **The readiness gate's contract is FIVE named preconditions in a fixed ORDER, with the run-contract-terms arm after tool checks and BEFORE the canary arms (skipping the canary poll rather than paying it)** — per §Standard Contracts (Readiness gate). The freshness carrier is required to be "an incident opened AFTER the storm's emission instant" (`opened_at_unix_nano` vs Conductor's `std::time`-stamped emission instant), per §Established Decisions [Read-Back Dependency Posture]. Whether `preflight.rs:385` implements that as a strict after-comparison and whether any test pins the boundary is research's question.
- **`shell-declaration` is the only run-contract check kind that may block, and an unmet term must compose ONE string naming each unmet term individually with its candidate causes — never a claimed measurement of `pulse-app`** — per §Occupied Resources (`contracts/pulse-run-contract.toml`) and §Standard Contracts. `ANDROMEDA_PULSE_L4_DETERMINISTIC` is read in Conductor's OWN environment as that proxy (§Occupied Resources — Environment variables), which is exactly the predicate the `declares` survivor family covers.
- **`Blocked` is a distinct terminal state, never silently downgraded to pass/fail/manual-check; a blocked row populates only `run_id`/`seed`/`scenario`/`p_ids`/`slo_tier` with the rest JSON `null`** — per §Standard Contracts (Readiness gate) and §Established Decisions [Read-Back Dependency Posture]. A stuck-`true` declaration predicate defeats this state, so the killing assertion must be against the `Blocked` outcome shape, not against a boolean alone.
- **No new occupied resource may be introduced to make behavior observable** — the `CONDUCTOR_*` namespace, the four `contracts/` manifests, and the on-disk artifact list (`logs/agent-latest.jsonl`, `logs/conductor-tauri.jsonl`, per-run JSONL/Markdown, `runs.db`) are the enumerated set, per §Occupied Resources. Every artifact/precondition string must be host-path-free (`data_dir` redacted, §Standard Contracts) — which also binds anything a test writes or reads back.
- **cargo-nextest is the pinned runner under a zero-retry `ci` profile in `.config/nextest.toml` ("no retries mask flakes — the determinism invariant"), with `cargo test --doc` beside it and CI running both `cargo nextest`/`cargo test`** — per §Infrastructure Patterns (Build system) and (CI/CD approach). Arch does not forbid a second runner; it forbids retry-masked non-determinism, so any fix must make the test deterministic under both rather than pin it to one.

## Patterns to follow
- Typed per-seam `thiserror` enums with the read-back fan-out already established in `conductor-verify` (`VerifyError` / `ContractMismatch`), `anyhow` only at the `conductor-cli` / `#[tauri::command]` edges — §Conventions (Error handling), §Inherited Defaults.
- The composition-root pattern: `conductor-run` sits above the seams and below both bins (preflight + `execute_scenario` + `persist` + `drive_run` + the fault-phase guard), so contract-predicate and journal-stamp assertions belong there rather than in a bin — §Occupied Resources (Crate names).
- The `current_thread` runtime pattern — `#[tokio::main(flavor = "current_thread")]` on the CLI path, hand-built `Builder::new_current_thread()` owned by the core — is the flavor any scheduling/paused-clock test must ride to preserve determinism-under-seed — §Established Decisions [Async Runtime Flavor].
- Self-observation artifacts are written by the production `init_observability` path in `conductor-core` and land as siblings of the runs dir, truncated per invocation, inheriting the processor-stage redaction — §Occupied Resources (On-disk artifacts), §Stack (Self-observation row). Arch registers the artifacts; the install-once subscriber semantics are obs-plan §3's.
- Named-precondition composition: one string per unmet term naming condition + candidate causes, host-path-free, ordered so an upstream launch condition explains a downstream canary symptom — §Standard Contracts (Readiness gate).

## Anti-patterns to avoid
- Relocating crate-private logic across a seam, or widening visibility beyond its owning crate, to make it testable — dependency edges *are* the architecture and a forbidden edge must not compile (§Established Decisions [Module Boundaries]); this covers the contract predicate, the jsonrpc line reader, the stamp helpers, and the crate-private `route_read_back` in the same file.
- Introducing a new env var, config handle, `contracts/` manifest, or on-disk artifact path as a test seam — the reserved namespaces and artifact list are closed (§Occupied Resources); likewise no host paths or internal struct names in anything a test writes or reads back (§Standard Contracts).
- Asserting by panic, or letting a harness fault be reported as a verdict / a verdict be raised as `Err` — the verdict/error wall applies in every seam crate (§Cross-cutting Patterns).

## Contract bindings
- **arch ↔ security:** the read-back per-line size bound is security's requirement (`.claude/rules/security.md`); arch binds only *where its breach lands* — a typed `VerifyError` variant on the hand-rolled JSON-RPC decode path, never a panic (§Conventions — Error handling; §Cross-cutting Patterns — Trust boundary, which makes the spawned sidecar's stdout an untrusted read-back source).
- **arch ↔ tests:** the §Standard Contracts readiness-gate shape (five preconditions, their order, freshness semantics, blocked-row nulls) is the fixture contract any killing preflight assertion must pin; the pinned nextest zero-retry `ci` profile (§Infrastructure Patterns) is arch's determinism constraint on the tests harness.
- **arch ↔ obs:** `init_observability`'s global-subscriber install semantics and the redaction layer are obs-plan §3's; arch registers the sink artifacts and requires them host-path-free. The runner-portability fix must preserve the "real artifact from the real production init path" premise without adding a new artifact path.
- **arch ↔ all domains:** the locked workspace crate names (`conductor-core`/`-timeline`/`-emit`/`-faults`/`-verify`/`-report`/`-run`/`-cli` + the `conductor-tauri` bin) are where every domain's content lives (§Occupied Resources).

## Acceptance criteria contributions
- (arch) All changes land inside the already-registered crates `conductor-core` / `conductor-verify` / `conductor-run` / `conductor-cli`, with no new workspace member and no new cross-seam dependency edge (per architecture.md §Occupied Resources — Crate names, §Established Decisions [Module Boundaries]).
- (arch) Killing tests assert typed values (`Verdict` / `ReportState` / `VerifyError`), and a breached read-back line bound surfaces as a `VerifyError` variant rather than a panic, a `Verdict`, or a silent accept (per architecture.md §Conventions — Error handling, §Cross-cutting Patterns — Verdict/error wall).
- (arch) The stamp-helper assertions read real `std::time` magnitudes with no tokio virtual clock on the journal path; any paused-clock advance assertion is confined to the poll loop and runs on the `current_thread` flavor (per architecture.md §Cross-cutting Patterns — Determinism discipline, §Established Decisions [Async Runtime Flavor]).
- (arch) No new `CONDUCTOR_*` / `ANDROMEDA_PULSE_*` env var, no fifth `contracts/` manifest, no new on-disk artifact path, and every string a test writes or reads back stays host-path-free; the `conductor-cli` `tracing` removal touches only that crate's manifest and leaves the workspace-pinned self-observation stack (`tracing 0.1.44` + `tracing-subscriber 0.3.23`) intact (per architecture.md §Occupied Resources, §Standard Contracts, §Stack and Technologies).
