# obs extract

## Relevance
Relevant — §B3 (global subscriber / `RUST_LOG` env write / self-obs artifact read-back), the `tracing` rider on `conductor-cli`, the journal-stamp helpers, and the Blocked/typed-value wall all land in obs's domain.

## Constraints
- Self-obs init is a single process-wide bootstrap: obs-plan §3 (Observability Harness Contract → "Logging init instead") requires the `tracing-subscriber` JSON layer be initialized at CLI bootstrap (`main`) / Tauri startup **before any scenario logic**. A runner-portability fix must keep the witness test reading an artifact produced by that production init path; it may not substitute a test-only subscriber to gain isolation.
- `RUST_LOG` discipline is a measured plan rule, not a convention: obs-plan §3 (Per-module log levels) requires the **additive** form `info,{crate}=debug` (a bare per-target directive replaces the default and darkens every other target, failing the CLI's own agent-mode self-obs test) and states "never set either form for a run that also executes the test suite — the environment reaches the runner's child processes." The scope's `:220` `unsafe set_var` of `RUST_LOG` sits directly against this rule.
- Journal stamps are wall-clock only: obs-plan §11 (Project-specific bans) forbids tokio's virtual clock for journal timestamps — `std::time::SystemTime` only, "preserves journal-relative SLO math"; obs-plan §10 (Performance budgets) defines `latency_ms = read_back_observed_at − journal_emitted_at` in wall-clock ms. A `now_ms` / `now_unix_nanos` killing test must assert a wall-clock magnitude; the paused-clock technique is confined to the poll loop (scheduling), never the stamp helpers.
- A `Blocked` outcome has a fixed envelope shape: obs-plan §6 (Log Coverage — required fields) fixes `state` ∈ {Pass, Fail, ManualCheck, KnownResidual, **Blocked**} with `latency_ms` **null for blocked rows** and `read_back_observed_at` **null until read-back / null for blocked rows**. A `declares`-family killing test that drives an unmet term to `Blocked` must hold the record to that shape rather than inventing an extra field.
- Transport-bound failures return typed values, never panics: obs-plan §11 (Error Reporting) requires that a panic on the MCP read-back / transport path never go uncaptured, and that malformed child/transport input yield `blocked` as a typed `Ok(...)` verification value. This governs the `MAX_LINE_BYTES` (`jsonrpc.rs`) family's killing assertions and matches the chunk's own verdict/error-wall boundary.
- Any artifact a test writes or reads back is subject to redaction: obs-plan §11 (Logs · PII Scrubbing) requires absolute host-**file** paths (drive-letter, `/home`, `/Users`, `%APPDATA%`, `~/.cargo`, `.rustup`, backtrace paths) be masked → `<redacted>` at the **processor** stage, with the field-name allowlist (`conductor-core::redact::ALLOWLISTED_FIELDS`, cited in §4's required-span-attributes heading) dropping any non-allowlisted field and the allowlisted `target` module path preserved. A temp-dir-hosted `obs.jsonl` is such an artifact.
- The `conductor-cli` `tracing` rider crosses two mandates: obs-plan §4 (Auto-instrumentation per surface — `cli` row) requires manual `#[tracing::instrument]` on `fn main()` and core scenario handlers, and §3 requires the CLI bootstrap logger init; obs-plan §9 requires the conformance gate read the CLI-produced `logs/agent-latest.jsonl`. Whether the shipped CLI already satisfies §4's `fn main()` instrumentation mandate — and whether the `agent-latest.jsonl` production path survives dropping the dep declaration — is research's question.

## Patterns to follow
- Two record shapes (obs-plan §3, "Two record shapes"): the self-obs line carries the base set `timestamp_ms` / `level` / `target` / `service.{name,version,environment}` / `run_id`; the Run-report envelope is the separate scenario-result record. Assertions over `obs.jsonl` key off the base set, not envelope fields.
- Span-lifecycle line variant (obs-plan §3): a §4 span materializes as real lines adding `span`, `span_event` (`new` | `close`), optional `parent`, and the span's allowlisted attributes on `new`. A line/span-count assertion should key off these documented fields rather than free text.
- Shape witnesses ride the allowlisted `message` field (obs-plan §6, Boundary-call wrappers): both the `verify.readback` key-set witness and the `emit.batch` wire-shape witness carry **key names only, never values, ordered** so the same batch renders identically — the property a deterministic count assertion depends on.
- Additive per-target opt-in (obs-plan §3 Per-module log levels): `conductor-emit` is `info` with `debug` reserved for the wire-shape witness, reached via `RUST_LOG=info,conductor_emit=debug`.
- Agent-parseable JSONL (obs-plan §3 Log format): every line parseable by `jq` / `serde_json` — assertions read parsed fields rather than substring matches.

## Anti-patterns to avoid
- Never promote a hot-path witness line from `debug` to `info` to make it visible (obs-plan §11 Logs, "NEVER log in hot path at `info`"; §6's why-note scopes the `info` exemption to once-per-phase fault spans only).
- Never write process env to steer telemetry: a bare per-target `RUST_LOG`, or setting `RUST_LOG` for a run that also executes the suite, is banned by obs-plan §3 (Per-module log levels) — the plan's agent-mode precedent is a **read-only** env trigger Conductor never writes.
- Never swap in an OTel SDK, exporter, or an alternative test-only telemetry stack to obtain isolation (obs-plan §11 Telemetry Strategy + Universal — self-obs is stdout/file/console JSON only).

## Contract bindings
- **obs ↔ tests harness:** obs-plan §3 states the JSONL log format is a *binding contract owned by test-plan §3* (obs aligns to tests). The `canary_wire` witness consumes that line schema, so any change to line shape or emission level is a two-sided change requiring the tests-side owner.
- **obs ↔ CI:** obs-plan §9 (Log conformance check) requires the gate validate the §3 self-obs base schema on `logs/agent-latest.jsonl` plus no absolute host-file paths; the `conductor-cli` dep removal must not break the artifact that gate reads. §9's zero-unlogged-panics gate likewise reads the same stream.
- **obs ↔ security:** the `MAX_LINE_BYTES` bound is security's (`.claude/rules/security.md`); obs's side of the seam is obs-plan §11 (Error Reporting) — the bound's breach must surface as a typed `blocked`/`VerifyError`, logged, never a panic or an unsanitized backtrace.

## Acceptance criteria contributions
- (obs) The runner-portability fix preserves the witness test's premise — it reads a real artifact produced by the production `tracing-subscriber` init path, with no test-only subscriber or alternative telemetry stack substituted (per obs-plan §3 Observability Harness Contract / Logging init + §11 Telemetry Strategy).
- (obs) Every self-obs line the affected test reads back carries the base set (`timestamp_ms`, `level`, `target`, `service.name`, `service.version`, `deployment.environment`, `run_id`) and contains no absolute host-file path — including the test's own temp-dir path, which must render `<redacted>` (per obs-plan §3 two record shapes + §9 Log conformance check + §11 Logs).
- (obs) The `emit.batch` wire-shape witness stays at `debug` and is reached via the additive `RUST_LOG=info,conductor_emit=debug` form, with no env write from test code and no bare per-target directive (per obs-plan §3 Per-module log levels + §6 Boundary-call wrappers).
- (obs) Journal-stamp killing tests assert a plausible wall-clock `std::time::SystemTime` magnitude and never read tokio's virtual clock (per obs-plan §11 Project-specific bans + §10 Performance budgets).
