## Constraints
- The read-back per-line size bound on the MCP child-stdout boundary is a required control, not an optional one — security-plan §Input Validation (MCP read-back child stdout row) requires "a soft per-line size bound on the child's stdout — no unbounded read" alongside serde_json's recursion limit. `MAX_LINE_BYTES` at `crates/conductor-verify/src/jsonrpc.rs:18` is the implementation of that mandate; a mutant that disables the guard and survives means the mandate has no enforcing test. Killing tests must pin BOTH sides of the boundary (at-limit accepted / over-limit rejected), because §Input Validation names the bound itself, not merely its presence.
- Decode/size-bound failures must route through the typed verdict/error wall, never a panic — security-plan §Input Validation requires the boundary map JSON-RPC errors and decode faults to `VerifyError::{JsonRpc,Decode,Transport}`, and §Security Anti-Patterns → Universal bans letting a malformed child/transport input panic. Any new assertion on `MAX_LINE_BYTES` must assert the typed `VerifyError` value, which coincides with the chunk's own verdict/error-wall invariant.
- The canary freshness comparison is a security control against a false pass — security-plan §Input Validation (MCP read-back child stdout row) requires the canary assert an incident opened AFTER the storm's emission stamp, with an absent or unparseable stamp contributing nothing and reading as NOT-fresh ⇒ `blocked`, never a false pass. §Security Anti-Patterns → Universal (never-silently-downgrade, five named preconditions) makes that arm one of the five. A killing test for the `preflight.rs:385` boundary must therefore cover the degrade DIRECTION (equal/older/absent stamp ⇒ not fresh ⇒ `blocked`), not only the happy path.
- The `shell-declaration` predicate is a `blocked`-precondition input — security-plan §Input Validation (`ANDROMEDA_PULSE_L4_DETERMINISTIC` row) requires an absent declaration surface as an unmet contract term naming both candidate causes, never a claimed measurement of `pulse-app`; §Security Anti-Patterns → Universal requires the run-contract arm compose one string naming each unmet term with its causes. A `declares`-stuck-at-`true` mutant defeats exactly that requirement, so the killing tests owe the false/absent/garbage-value cases, not just `"true"`.
- No artifact a test writes or reads back may carry absolute host paths or internal seam-crate struct names — security-plan §Security Anti-Patterns → Logging and §Error Handling (Run-report artifact sanitization). This binds the §2 runner-portability work directly: the fix touches `obs.jsonl` production via the REAL `init_observability` path, and any new fixture, temp-dir path, or assertion text must not embed the resolved temp path into an artifact.
- The declaration-only env read must stay declaration-only — security-plan §Input Validation requires `ANDROMEDA_PULSE_L4_DETERMINISTIC`'s value never become a path, an argv element, or a log value. Tests that manipulate env to drive the `declares` predicate must not widen that (and the `unsafe set_var` of `RUST_LOG` at `canary_wire.rs:220` is a test-side env write whose soundness the chunk is already re-opening).
- The standing dependency-audit deferral is governed by §Dependency Security (advisory-DATABASE fault bullet): the remedy is a bounded wait with `cargo deny check advisories bans licenses sources` VERIFIED green, never a floor raise, never a `deny.toml` ignore, never a CI edit. §3's `tracing` removal from `conductor-cli` is a dependency-tree DELTA, which per the 2026-08-16 amendment changes the deferral's stated basis.

## Patterns to follow
- Typed-error assertion at the read-back boundary — security-plan §Error Handling keeps `thiserror` enums (`VerifyError`, `ContractMismatch`, `ConfigError`) inside the seam crates and collapses to `anyhow` only at the `conductor-cli` / `#[tauri::command]` edges. Killing tests for `jsonrpc.rs` live inside the seam crate and should match on the typed variant.
- Distinct-`blocked`-precondition-string discipline — security-plan §Security Anti-Patterns → Universal requires each of the five preconditions surface its own named string, never the generic corpus-empty string. Assertions for both the `declares` and freshness families should key off the specific precondition string, which makes them killing rather than merely covering.
- Fixed-path, non-operator-steerable contract resolution — security-plan §Input Validation (committed SUT-facing manifests row) requires `pulse-run-contract.toml` resolve through `default_path()`/`resolve_under` with deliberately no `CONDUCTOR_*` override, and read faults carry `e.kind()` only, never the path. Test fixtures for the run-contract terms should exercise the validated-contract path rather than introducing a new operator-steerable handle.
- `resolve_under` traversal guard for any test-written artifact path — per §Input Validation's non-path env-handle note, artifact paths derive from `CONDUCTOR_RUNS_DIR` through `resolve_under`; the runner-portability fix should not bypass that to reach a per-test sink.
- Audit↔deny overlap as the coverage of record while the advisory DB is unparseable — §Dependency Security requires verifying `cargo deny check advisories bans licenses sources` actually ran green rather than assuming it.

## Anti-patterns to avoid
- NEVER weaken or delete the per-line size bound to make a test pass — §Security Anti-Patterns → Input bans unbounded decoding on the read-back path and requires an empty/failed canary round-trip become `blocked`, never a false pass-as-empty. The chunk's job is to assert the guard, not relax it.
- NEVER let the runner-portability fix or any new test leak absolute host paths or internal struct names into `<run_id>.md`, `runs.db`, JSONL journals, or `obs.jsonl` — §Security Anti-Patterns → Logging.
- NEVER resolve the audit gate obligation by raising a floor, adding a `deny.toml` ignore, or editing CI — §Dependency Security (advisory-DATABASE fault); the remedy is the bounded wait, and §3's dependency delta means the deferral's basis must be restated (a `tracing` REMOVAL shrinks the tree rather than admitting packages, but whether that still discharges the "no dependency delta" basis or requires the verified-green deny run over the new `Cargo.lock` is research's question).

## Contract bindings
- **CI security gate ↔ tests §CI Integration** — the chunk changes the test runner story (`--test-tool=nextest`, plus making the affected binary pass under `cargo test`). §Dependency Security (CI integration) places the audit/deny steps in the same single `.github/workflows/` pipeline as build + nextest + clippy; the anti-pattern bans a CI edit as the audit remedy, so any runner-related workflow touch must be justified independently of the audit gate.
- **Journal-stamp clock source ↔ obs/tests determinism** — §Security Anti-Patterns → Logging requires journal/report wall-clock stamps come from `std::time::SystemTime`/`Instant`, never tokio's virtual clock, "a wrong clock source corrupts the ground-truth artifact." This is the same rule the chunk states as its own invariant; the `lib.rs:516-518` / `lib.rs:630-632` killing tests and the paused-`tokio::time` technique for `preflight.rs:335` must stay on opposite sides of that line.
- **Artifact sanitization ↔ obs self-observation sink** — the §2 fix operates on `init_observability`'s process-global subscriber; §Error Handling's artifact-sanitization rule and obs's own PII/redaction posture both bind whatever sink shape P4 chooses.
