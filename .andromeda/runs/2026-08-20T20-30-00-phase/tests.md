# tests extract

## Relevance
Relevant — fully in-domain: this is a test-and-harness-integrity chunk (killing assertions + runner-portability + a dev-dep rider), touching no product contract.

## Constraints
- **Zero-flakiness / determinism is binding, and a runner-dependent result is a determinism break, not a tolerable quirk.** test-plan §10 (Zero-flakiness budget) requires flakes be root-caused, never retried (`retries` must stay 0), on the stated grounds that "agent-driven dev cannot distinguish flake from real bug"; §11 CI repeats the ban. The §2 runner-portability defect falls in this class.
- **Per-test isolation must hold with no shared mutable state across parallel tests** — test-plan §3 (Test data bootstrap → Per-test isolation), §7 (Test data lifecycle → Per-test) and §11 Test Data require per-test isolated state and ban sharing mutable state across parallel tests. Note the plan's isolation *rationale* is stated as nextest's per-test process model (§3, §7, §11 Integration/CI), and §4 names cargo-nextest the primary runner with `cargo test --doc` only as the doctest leg — so the chunk's "passes under `cargo test` too" bar is operator-set and goes beyond what §4 mandates, while §11 Test Data's shared-state ban is what actually governs the fix.
- **Clock discipline is split, and the split is a hard ban on both sides.** test-plan §7 (Seed strategies → Time-sensitive data) + §8 (Mocking → Time) require `start_paused = true` + `tokio::time::advance` for *scheduling only*; §11 Test Data bans stamping the journal/report from the virtual clock (and requires a golden test catch it), §11 Unit bans asserting a real wall-clock duration in scheduling tests. This maps exactly onto the chunk's poll-loop vs. journal-stamp families.
- **Assertions target the public seam API and typed observable output, never implementation details or fixture internals** — test-plan §11 Unit ("test the public seam API + observable behavior (envelope/verdict/state output)"). This is the plan-side of the chunk's verdict/error wall.
- **A failed precondition must surface as a named `Blocked`, never a silent downgrade** — test-plan §3 (`boot` readiness signal): `ready:false` ⇒ dependent scenarios report `state="Blocked"` with the named precondition string; §1 (5-command `boot`) restates "never silently downgraded". §11 E2E further requires `Blocked` be a reported envelope state, not a non-zero exit. This is the assertion target the `declares` family requires; whether the existing tests already pin per-term `Blocked` naming is research's question.
- **The canary round-trip is required to be covered by fresh / stale / stamp-absent stub legs** — test-plan §5 (Cross-module patterns → `query_incident_list`): an incident opened AFTER the emission stamp ⇒ proceed; empty corpus, only-older incidents, or a missing/unparseable stamp ⇒ `blocked`, never false-pass-as-empty; §4 (conductor-verify) mandates the same widened mapping. Whether those legs already pin the *strict* `>` boundary (so `>=`/`==` mutants die) is research's question.
- **Vector-4 negative-tests are a mandated coverage trigger for the read-back path** — test-plan §1 (Coverage triggers, security-vector-coverage Vector 4) requires negative tests that an empty/malformed canary round-trip becomes `blocked` and that bounded decoding does not panic on malformed child stdout. The read-back per-line size bound sits in this family; whether a bound-boundary case already exists there is research's question.
- **The supply-chain gate binds any dependency edit** — test-plan §9 (Supply-chain audit stage), §10 (Build failure conditions) and §11 CI require `cargo audit --deny warnings` + `cargo deny check` green with a committed, un-drifted `Cargo.lock`; the rider's `tracing` removal moves the lockfile, and the carried 33rd-consecutive audit obligation lands on this same gate.

## Patterns to follow
- **Paused-clock scheduling assertion** — `#[tokio::test(flavor = "current_thread", start_paused = true)]` + `tokio::time::advance`, asserting scheduled ordering/shape (test-plan §4 conductor-timeline bullet, §7 Time-sensitive row, §8 Time-mocking row). This is the established shape the chunk's `[inferred]` "cheapest killing shape" for the loop-guard family should be checked against.
- **rstest table-driven boundary matrices** — `#[fixture]` / `#[rstest]` + `#[case]` rows for valid/invalid matrices (test-plan §4 Fixture pattern, §7 Fixture library). The natural carrier for the `true`/`1`/other predicate matrix and for `<` vs `<=` vs `>` boundary rows.
- **rmcp stub tiers for verify-side work** — in-process duplex transport for verdict/preflight logic, `TokioChildProcess` test-binary for the spawn path (test-plan §5 Drivers, §8 Mocking table). Relevant to the acceptance's `stub_pulse_mcp` exclusion ruling.
- **Canonical-serialization goldens by exact-string `assert_eq!` at unit tier; insta reserved for E2E with redaction, CI fail-don't-write, never `cargo insta review`** (test-plan §7 Golden artifacts row, §11 Universal).
- **Test placement/naming** — crate-local `#[cfg(test)] mod tests` for unit, crate-local `tests/` for in-crate integration, snake_case `fn` (test-plan §2 Test directory + naming conventions).

## Anti-patterns to avoid
- **No implementation-detail or fixture-internal assertions, and no brittle value pins** — assert the envelope/verdict/state contract instead (test-plan §11 Unit). Combined with §11 E2E, a reported state (`Blocked`/`KnownResidual`/`ManualCheck`/`CalibrationRegion`) must never be asserted as a process-failure exit.
- **No virtual-clock stamping and no real-wall-clock duration assertions** — journal/report stamps from `std::time` only; scheduling asserted via `advance`, never elapsed real time (test-plan §11 Test Data + §11 Unit, both stack-specific).
- **No shared mutable state across parallel tests, no retries, no threshold-lowering to get green** (test-plan §11 Test Data, §11 CI, §11 Quality, §10).

## Contract bindings
- **tests §3 ↔ obs-plan §3 (log format).** test-plan §3 is the declared source of truth for the JSONL format and states the self-obs stream (per-line base fields; event-line and span-lifecycle-line variants, allowlist-gated) is a *distinct artifact* from the per-run emission journal — the two schemas must not be conflated. The wire-shape witness reads a self-obs artifact, so any fix that changes what the production init path installs or emits crosses into obs §3/§11 (level policy, redaction allowlist) and would require lockstep amendment of both §3s (the 2026-08-10 and 2026-08-14 precedent).
- **tests §1 Vector-4 trigger ↔ security plan / `.claude/rules/security.md`.** The read-back per-line bound is a security-mandated bound; the *negative test* proving it is the tests domain's obligation under §1's Vector-4 trigger.
- **tests §3 `boot` ↔ arch Standard Contracts.** The named-`Blocked`-per-unmet-precondition mapping the `declares` family must assert is arch's contract, asserted here.
- **tests §9/§10 supply-chain gate ↔ the carried `cargo audit` (33rd consecutive) obligation** and the `Cargo.lock`-no-drift rule that the dep-removal rider triggers.
- **Unbound tool: cargo-mutants.** The acceptance tool appears in none of test-plan §4 (tool inventory / floors policy), §9 (pipeline stages), §10 (gates) or §12 (decisions log) — so the scoped re-run is currently an out-of-plan instrument. If it is to become a standing gate (or if the `--test-tool=nextest` + `stub_pulse_mcp`-exclusion ruling is to be durable), that is a plan-amendment question for wrap, not something this extract can assume.

## Acceptance criteria contributions
- `cargo nextest run --workspace --profile ci` is zero-retry green with no `retries` setting introduced and no test quarantined-out, and the §9/§10 gate set stays green after the dep removal — `--fail-under-lines 60` coverage, `cargo audit --deny warnings` + `cargo deny check`, committed un-drifted `Cargo.lock` (per test-plan §10 Quality Gates & §9 CI Integration)
- Each new killing test asserts typed public-seam output (`Verdict` / `ReportState` / `VerifyError` / envelope `state`) rather than private fields, panics, or fixture-internal values — with the unmet-declaration case asserting a `Blocked` state naming the specific unmet precondition, never a silent pass (per test-plan §11 Unit & §3 Test Harness Contract → `boot`)
- The clock split holds in the new tests: the poll-loop family is killed by a `start_paused = true` + `tokio::time::advance` scheduling-shape/sleep-count assertion (no real elapsed-time assertion), and the journal-stamp family is killed by a `std::time`-magnitude assertion that never reaches for the virtual clock (per test-plan §7 Test Data & Fixtures → Time-sensitive data, with §11 Test Data / §11 Unit)
- The affected test binary's result does not depend on shared process state — no cross-test mutable sharing (process-global subscriber install, process-wide env write) that only one runner's isolation model masks — and the canary round-trip retains fresh / stale / stamp-absent leg coverage with the freshness boundary itself asserted (per test-plan §11 Test Data & §5 Integration Test Strategy)
