# arch extract

## Relevance
**Partial** — arch governs workspace placement, the read-back wire shape a stub must be faithful to, and the dep/artifact/env-var registration posture; it introduces no new external surface for this test-integrity chunk.

## Constraints
- Code must land in the registered workspace member `conductor-verify` (the MCP read-back client / preflight gate / verdict-logic seam) — its `tests/` and its `[dev-dependencies]`. Crate names are a tracked occupied resource; arch §Occupied Resources (Crate names) + §Infrastructure Patterns (directory tree) require a new seam to be a new workspace crate, which this chunk's boundaries exclude (per architecture.md §Occupied Resources).
- Crate-per-seam boundaries are compiler-enforced: a forbidden cross-seam dependency must not compile, so test-support must not create a new cross-crate edge beyond `conductor-core` (arch names it "the runtime-agnostic engine library every other crate depends on"). Whether `conductor-verify` already carries the dev-edges the ShapeWitness/self-obs witness needs is research's question (per architecture.md §Established Decisions [Module Boundaries] + §Occupied Resources Crate names).
- A stub standing in for the sidecar must speak the shape arch locks: hand-rolled **line-delimited JSON-RPC over stdio**, `initialize` (whose result carries `protocolVersion`) → `tools/list` → `tools/call` returning a **raw `serde_json::Value`** (no `{content:[…]}` envelope). A stub that normalizes to MCP-compliant shapes would pin a fiction rather than Pulse's actual wire format (per architecture.md §Established Decisions [MCP Read-Back Client] + §Conventions Interface surfaces).
- The verdict/error wall is a cross-cutting rule in every seam crate: `Verdict`/`ReportState` are values, `Result::Err` is harness-fault only, and read-back transport/decode/JSON-RPC failures fan into `VerifyError` variants (`Transport`/`Protocol`/`Decode`/`JsonRpc`). Assertions added here must read existing classifications, never reclassify one (per architecture.md §Cross-cutting Patterns Verdict/error wall + §Conventions Error handling).
- Determinism discipline: `current_thread` runtime, no retries masking flakes (the zero-retry `ci` nextest profile in `.config/nextest.toml` is arch-pinned), and wall-clock stamps from `std::time`, never tokio's virtual clock. A multi-attempt poll harness must not introduce a real-clock or work-stealing dependency (per architecture.md §Cross-cutting Patterns Determinism discipline + §Infrastructure Patterns Build system).
- No new occupied resource may land unregistered: no new `CONDUCTOR_*` env var, no new on-disk artifact path outside the registered set (`logs/agent-latest.jsonl`, `logs/conductor-tauri.jsonl`, per-run journal/report, `runs.db`, `contracts/*`). If a self-obs witness writes a file, whether it reuses a registered path is research's question — a new path requires an arch §Occupied Resources amendment at wrap (per architecture.md §Occupied Resources Environment variables + On-disk artifacts).
- Any added dev-dependency must keep `cargo deny check` green with each new advisory/license exception justified inline in `deny.toml` naming its crate and dependency path (per architecture.md §Infrastructure Patterns Build system).

## Patterns to follow
- **The arch-registered dev-test stack first** — nextest (pinned runner, zero-retry `ci` profile) + `cargo test --doc`, over rstest / proptest / insta / assert_cmd / assert_fs / predicates, with exact versions deferred to test-plan §4. Preferring a stack member already in the workspace is the path that adds no package (per arch §Infrastructure Patterns Build system).
- **The in-process transport seam, not a socket.** Arch pins the read-back transport as a spawned sidecar's stdio and pins Conductor as having no inbound listener of its own; the scope's `ReadbackClient::connect_transport` duplex is the arch-consistent injection point (per arch §Cross-cutting Patterns Trust boundary + §Conventions Interface surfaces).
- **Self-obs is `tracing`, not an OTel SDK** — the `ShapeWitness` line rides the structured-JSON self-observation stream, a deliberately separate artifact/schema from the PRODUCT OTLP emission and from the per-run JSONL journal; a witness must read the self-obs surface, not the emission journal (per arch §Stack and Technologies Self-observation + §Occupied Resources On-disk artifacts).
- **New-dep registration precedent** — blake3 (2026-08-16) is the shipped pattern: a genuinely-new dep gets a §Stack row plus its deny.toml exception; library symbols, test helpers and stub types are explicitly *not* arch-registered resources. This chunk should expect **no arch amendment** unless a dep, artifact path, or env var lands (per arch §Stack and Technologies + §Occupied Resources).
- **CI-gateable by construction** — arch splits build+test CI gating from the live-Pulse operator gate; a chunk claiming no capability and driving no live Pulse belongs wholly on the CI side (per arch §Established Decisions [CI/CD]).

## Anti-patterns to avoid
- **Do not open a listening socket in a test stub.** Arch permits exactly one deliberate port bind (the port-occupier fault scenario binding `:4317`); a loopback listener standing in for the sidecar would contradict the trust boundary (per arch §Cross-cutting Patterns Trust boundary + §Occupied Resources Ports).
- **Do not widen a seam's visibility to make a mutant observable.** Crates are the compiler-enforced visibility boundary; promoting `pub(crate)` to `pub` converts an internal into workspace API surface — arch's module-boundary decision is the reason the scope already rules this out (per arch §Established Decisions [Module Boundaries]).
- **Do not introduce a second async runtime or a `tokio::time` virtual clock into the verify seam.** The runtime is `current_thread` and core-owned; `Duration::ZERO` intervals, not clock manipulation, are the determinism-preserving lever (per arch §Established Decisions [Async Runtime Flavor] + §Cross-cutting Patterns Determinism discipline).

## Contract bindings
- **arch ↔ tests:** the locked read-back wire shape (§Established Decisions [MCP Read-Back Client]) is the fidelity bar for any stub the tests domain builds; a stub diverging from line-delimited JSON-RPC / raw-`Value` results makes the kill assertion meaningless.
- **arch ↔ obs:** the `ShapeWitness` observation surface is the `tracing` self-obs stream arch registers (§Stack Self-observation, §Occupied Resources On-disk artifacts); the artifact's schema, redaction layer and sink selection are obs-plan §3's, and arch only constrains that no *new* artifact path lands unregistered.
- **arch ↔ security:** a new dev-dependency crosses arch §Infrastructure Patterns (Build system, deny.toml inline justification) into security-plan §Dependency Security — the same seam the chunk's carried `cargo audit` PROBE-AUTO-SATISFY prereq sits on.
- **arch ↔ tests (runner):** the zero-retry `ci` nextest profile is arch-pinned in §Infrastructure Patterns; the test-plan §11 process-global-singleton ban the scope cites operates on top of it (a self-obs-capturing test alone in its own test binary).

## Acceptance criteria contributions
- (arch) All changes live under `crates/conductor-verify/` — its `tests/` and, if required, its `[dev-dependencies]`; no new workspace member and no new cross-seam dependency edge (per architecture.md §Occupied Resources Crate names + §Established Decisions [Module Boundaries]).
- (arch) No new `CONDUCTOR_*` env var and no new on-disk artifact path beyond the registered set; a witness that writes a file must reuse a registered path or be recorded as an amendment at wrap (per architecture.md §Occupied Resources Environment variables + On-disk artifacts).
- (arch) `cargo deny check` stays green over any dev-dep added, with each new advisory/license exception justified inline in `deny.toml` naming its crate and dependency path (per architecture.md §Infrastructure Patterns Build system).
- (arch) The test stub opens no listening socket and adds no second async runtime; the scoped re-run is executed under the zero-retry `ci` nextest profile (per architecture.md §Cross-cutting Patterns Trust boundary + Determinism discipline, §Infrastructure Patterns Build system).
