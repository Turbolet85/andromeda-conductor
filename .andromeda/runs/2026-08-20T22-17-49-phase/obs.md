# obs extract

## Relevance
Partial — the ShapeWitness pair (`preflight.rs:357`) sits squarely on an obs surface (the §6 read-back key-set witness line + self-obs artifact capture); the id-counter x2 and `notify` survivors are JSON-RPC wire concerns outside obs.

## Constraints
- The MCP read-back boundary-call must-log set is mandated to carry the **observed key set** of each raw tool result — key NAMES only, never values, carried on the allowlisted `message` field, because a field name outside the allowlist is dropped at the processor stage (per obs-plan §6 Boundary-call wrappers). A killing assertion for `ShapeWitness::list` must therefore target `message` text, not a bespoke structured field. Whether the shipped `extract::log_observed_keys` line already conforms to that form (level, target, key-names-only) is research's question.
- A span/log **attribute name must be a member of `conductor-core::redact::ALLOWLISTED_FIELDS`** or the processor stage drops it, emitting nothing (per obs-plan §4 Required-span-attributes constraint; §11 PII Scrubbing). Any new observation surface the chunk adds inherits this — no new field name may be introduced to make a mutant observable.
- The self-obs record shape a capture asserts against is the **§3 self-obs base line** (`timestamp_ms`, `level`, `target`, `service.name`/`service.version`/`deployment.environment`, `run_id`), in two variants (event line; span-lifecycle line adding `span` / `span_event` / optional `parent`) — **not** the §6 eleven-field run-report envelope (per obs-plan §3 Log format JSON schema, "two record shapes"; §9 Log conformance check).
- `info` is the mandated level for boundary-call summaries including verify read-back completion, and §3's per-module table sets `conductor-verify` base level `info` under `RUST_LOG=info` (per obs-plan §6 Log levels mapping; §3 Per-module log levels) — so the witness line is required to be visible under the default filter without a `RUST_LOG` opt-in. Whether the shipped line is emitted at `info` is research's question.
- A per-target `RUST_LOG` directive **replaces** the default rather than adding to it; the additive form `RUST_LOG=info,{crate}=debug` is required, and neither form may be set for a run that also executes the test suite, since the environment reaches the runner's child processes (per obs-plan §3 Per-module log levels, measured note). This binds the chunk's scoped `cargo mutants … --test-tool=nextest` re-run.
- Self-observation is **structured `tracing` logs only** — no OTel SDK is ever initialized/used for self-obs, and no self-obs OTLP is exported on any port (per obs-plan §3 OTel SDK init; §11 Telemetry Strategy / Universal). Test support that captures self-obs must be a `tracing-subscriber` layer, never an SDK/exporter.
- The read-back / transport path must never panic on malformed input — bounded decode ⇒ typed `blocked`, never a panic or false pass (per obs-plan §11 Error Reporting; Project-specific bans). A stub driving degenerate id sequences (`1,0,-1…` or a pinned `1`) must not be allowed to convert into an uncaptured panic.

## Patterns to follow
- **Key-set shape witness** (per obs-plan §6 Boundary-call wrappers): the read-back witness renders as key names on `message` (recorded live form: `query_incident_list returned keys [items, next_cursor, total]`); the `emit.batch` wire-shape witness is its emitting-side twin at `debug`. An assertion distinguishing "emitted once, on the first answering attempt" from "on every attempt except the first" is a count-of-matching-`message`-lines assertion over the captured stream.
- **Self-obs line capture shape** (per obs-plan §3 two record shapes / span-lifecycle variant): captured lines carry the base set on every line, with `span` + `span_event` (`new` | `close`) + allowlisted attributes only on span-lifecycle records — so a capture-based assertion should key on `target` + `message`, which are the allowlisted identity/content fields present on the event-line variant.
- **Bounded span-name set** (per obs-plan §11 Spans): `verify.readback*` is already a member; test support must not coin a new span name to make behaviour observable.
- **Redaction is processor-stage, single-owner** (per obs-plan §11 PII Scrubbing; §6): capture harnesses read the post-redaction stream — asserting on a value the allowlist drops, or on a path the value scrub masks to `<redacted>`, will never match.

## Anti-patterns to avoid
- NEVER introduce an OTel SDK / exporter / any self-obs OTLP export to make a mutant observable (per obs-plan §11 Telemetry Strategy + Universal).
- NEVER leak absolute host paths or non-allowlisted (Debug-dumped) field names into anything the new test support writes or prints; the allowlisted `target` module path is the one `module::`-shaped field that is preserved by design (per obs-plan §11 Logs + PII Scrubbing).
- NEVER add a bespoke log/span field or a new span name as the observation hook — a non-allowlisted field emits nothing and a new name breaks the bounded set (per obs-plan §4 attribute constraint; §11 Spans).

## Contract bindings
- **obs ↔ tests harness:** obs-plan §3 mandates the subscriber be installed once at bootstrap (`…init()`), i.e. process-global; test-plan §11's process-global-singleton ban is the tests-side face of the same fact — a test capturing the self-obs artifact must be alone in its own test binary (chunk scope names `conductor-run/tests/canary_obs_witness.rs` as precedent). The JSONL line format is OWNED by test-plan §3; obs §3 aligns to it (per obs-plan §3 Log format JSON schema).
- **obs ↔ security:** the redaction/field-allowlist layer is single-owner in `conductor-core::redact` (per obs-plan §11 PII Scrubbing) — a capture harness must consume it, not bypass it.
- **obs ↔ CI:** the `logs/agent-latest.jsonl` conformance gate asserts the §3 base schema (per obs-plan §9 Log conformance check) — any artifact the new test support emits must not pollute or reshape that stream.

## Acceptance criteria contributions
- (obs) The ShapeWitness killing assertion matches the witness line's key NAMES on the allowlisted `message` field (never values, no new field name), and distinguishes emit-count across ≥3 answering attempts (per obs-plan §6 Boundary-call wrappers + §4 ALLOWLISTED_FIELDS constraint).
- (obs) Captured self-obs lines are asserted against the §3 self-obs base-line shape (`timestamp_ms` / `level` / `target` / service identity / `run_id`), not the §6 run-report envelope (per obs-plan §3 Log format JSON schema "two record shapes").
- (obs) The witness line is observable at the default `info` filter for `conductor-verify` with no `RUST_LOG` opt-in, and the scoped mutants/nextest re-run sets no bare per-target `RUST_LOG` (per obs-plan §6 Log levels mapping + §3 Per-module log levels).
- (obs) The new test support introduces no OTel SDK/exporter, no self-obs OTLP, no new span name, and leaks no absolute host paths or non-allowlisted field names (per obs-plan §11 Telemetry Strategy / Spans / Logs / PII Scrubbing).
