# tests extract

## Relevance
**Relevant (primary domain)** — this is a test-integrity chunk: it adds killing assertions + test-support harness in `crates/conductor-verify/` tests, with mutation-audit acceptance; no production behaviour changes.

## Constraints
- **Mutation-instrument run discipline is mandatory, not advisory** — per test-plan §4 (Mutation instrument): `-f` resolves from the **workspace root** so full crate paths are required (a package-relative path under `-p` silently matches nothing); `--test-tool=nextest` is REQUIRED (the default `cargo test` aborts in an unmutated tree wherever a test is not runner-portable); **`Found 0 mutants to test` exits 0 with only a WARN and is a NO-OP, never a pass** — the tallies must be read; output lands in a gitignored `mutants.out/`.
- **Every named survivor must end killed OR classified accepted-deliberate against a cited standing rule** — per test-plan §10 (Mutation-survivor disposition): this is an audit-tier, non-blocking rule and deliberately **not** a numeric `--fail-under` threshold; a moved score is a consequence, never the acceptance. The scoped run is an operator/local instrument, **never a blocking CI stage**, and §9's stage table is CI's complete inventory, not a chunk's (per test-plan §9 Scoped mutation audit).
- **Runner portability is a standing gate** — per test-plan §4 (Framework): the suite must be green under BOTH `cargo nextest run -p <crate>` and `cargo test -p <crate>` (full, non-doc). Only the shared-process runner can produce that evidence; a runner-dependent result is a **determinism break under §10**, not a runner quirk.
- **A test capturing the self-obs artifact must own its test binary** — per test-plan §11 (Integration): `conductor_core::init_observability` installs a process-global, first-install-wins subscriber; a per-test `TempDir` sink does NOT isolate it, and serializing (`--test-threads=1` / a profile knob) is banned as hiding the shared-state defect. One `tests/*.rs` per such test holds under both runners. This binds the ShapeWitness observation-gap witness specifically.
- **Zero-retry, zero real-clock** — per test-plan §10 (Zero-flakiness budget): nextest `retries` must stay 0; determinism is enforced upstream (virtual clock / seeds), so a flake indicates a real determinism break to fix at the cause. Per test-plan §11 (Universal): never use real time without injection.
- **The MCP sidecar is exercised through an injected rmcp stub transport, never a monkey-patch** — per test-plan §8 (Mocking table + Anti-monkey-patching) and §5 (boundary table, Module ↔ external): in-process duplex transport for verdict/preflight logic, `TokioChildProcess` test-binary only for the spawn/`.env()` path; DI of transport, no runtime patching of production code.
- **The self-obs stream is a DISTINCT artifact from the per-run emission journal** — per test-plan §3 (Log format, "Self-obs stream is a distinct artifact"): a `tracing` witness asserts against the self-obs **event-line** variant (`message` plus its allowlisted fields, at whatever level obs-plan §11's policy assigns that call site), never against the Run-report envelope. §3 also requires the two schemas not be conflated.

## Patterns to follow
- **rmcp in-process duplex stub as the CI-runnable conductor-verify leg** (test-plan §5 Drivers + §8 Mocking table) — verdict logic and preflight state mapping are asserted against a stub over an injected transport; this is the same seam the chunk pins at the public `connect_transport`.
- **Own-test-binary self-obs witness** (test-plan §11 Integration remedy) — one `tests/*.rs` file per subscriber-capturing test; the scope names `conductor-run`'s `tests/canary_obs_witness.rs` as the worked precedent.
- **Per-seam fast-iteration selection** (test-plan §3 `run` → Test selection): `cargo nextest run -p conductor-verify` for the crate, `cargo nextest run -E 'test(<name>)'` for a single test.
- **rstest fixtures + `#[tokio::test(flavor="current_thread")]` for async legs** (test-plan §4 Fixture pattern — `#[future]` + `#[awt]` named explicitly for `conductor-verify`; §2 agent-runnable invariants) — crate-local `tests/` for in-crate integration, snake_case `fn` naming (§2 Test directory + naming conventions, §4 Conventions).
- **Exact-string `assert_eq!` for canonical unit-level goldens; insta reserved for E2E with redaction and never `cargo insta review`** (test-plan §4 conductor-report bullet + §7 Golden artifacts) — applies if a wire/line witness locks a shape.

## Anti-patterns to avoid
- **Never rely on nextest's per-test process to isolate from a process-global singleton, and never serialize the file instead** (test-plan §11 Integration) — the remedy is a dedicated test binary.
- **Never test implementation details — private fns / internal struct fields** (test-plan §11 Unit); assert the public seam API + observable behaviour. This is the plan-side reason the chunk's "no `pub(crate)` widening" boundary holds, and why the `notify` and ShapeWitness kills must be witnessed on the **wire / self-obs artifact** rather than by exposing internals.
- **Never add retries or lower a gate to pass** (test-plan §11 Quality + §11 CI) — no nextest `retries`, no coverage-threshold relief (`--fail-under-lines 60` stays binding per §10).

## Contract bindings
- **tests ↔ obs (log format / self-obs schema):** test-plan §3 (Log format) is the SOURCE OF TRUTH for the JSONL format and obs-plan §3 derives from it; the self-obs line's field set is gated by the obs-owned `conductor-core::redact` allowlist, and its level is assigned by obs-plan §11 policy (amended 2026-08-14 to name the event-line variant by SET, not by level literals). A ShapeWitness witness that asserts on a `tracing` line therefore binds to both plans — **whether the existing `log_observed_keys` line's fields already survive that allowlist, and at what level, is research's question**; the witness must not assume `info!` from the call-site literal.
- **tests ↔ security (supply chain):** test-plan §9 (Build failure conditions) + §10 require `cargo audit --deny warnings` and `cargo deny check` green with a committed, un-drifted `Cargo.lock`. The scope's possible `[dev-dependencies]` addition touches that gate and the carried PROBE-AUTO-SATISFY pin.
- **tests ↔ arch (seam under test):** the assertion surface is the public `conductor-verify` client seam, not internal state — per test-plan §11 Unit; no production-visibility change is authorized by any tests mandate.

## Acceptance criteria contributions
- `cargo nextest run -p conductor-verify` **and** `cargo test -p conductor-verify` both green — runner portability is a standing gate, and a runner-dependent result is a determinism break to fix at the cause (per test-plan §4 Framework + §10 Zero-flakiness).
- The scoped `cargo mutants -p conductor-verify --test-tool=nextest -f crates/conductor-verify/src/jsonrpc.rs -f crates/conductor-verify/src/preflight.rs` run reports a **non-zero mutant count** (a `Found 0 mutants to test` exit-0 result is recorded as a NO-OP, never as acceptance) with the five named survivors killed and the previously-killed set still dead (per test-plan §4 Mutation instrument + §10 Mutation-survivor disposition).
- Each of the five named survivors ends **killed or classified accepted-deliberate against a cited standing rule**; no numeric mutation score substitutes for the disposition (per test-plan §10 Mutation-survivor disposition).
- nextest stays zero-retry, no `--test-threads=1` serialization is introduced, and any new test that captures the `init_observability` self-obs artifact lives in its own test binary (per test-plan §10 Zero-flakiness budget + §11 Integration).
