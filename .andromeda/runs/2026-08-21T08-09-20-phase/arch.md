# arch extract

## Relevance
Relevant — the chunk edits scenario config, the `conductor-run`/`conductor-verify`/`conductor-report` seams, and lands rows on the locked run-report envelope; arch governs placement, envelope shape, state routing, and occupied resources.

## Constraints
- Code must land in the existing crate-per-seam members: per-check read-back extraction in `conductor-verify`, drive/routing in `conductor-run` (composition root above the seams, below both bins), journal/report/`runs.db` writes in `conductor-report`; a cross-seam dependency not declared in `Cargo.toml` must fail to compile, so no new edge appears silently (per architecture.md §Established Decisions [Module Boundaries] · §Occupied Resources — Crate names).
- Lifecycle outcomes are typed VALUES, not errors: an unobserved auto-resolve, an empty active list, or a missing resolution summary must be a `Verdict`/`ReportState`, while `Result::Err` stays reserved for harness faults (transport down, MCP unreachable, config/manifest parse) (per architecture.md §Established Decisions [Error Handling] · §Cross-cutting Patterns — Verdict/error wall).
- Every row must conform to the run-report envelope with `verdict ∈ {Pass, Fail, CalibrationRegion}` and `state` within the closed five `{Pass, Fail, ManualCheck, KnownResidual, Blocked}`; arch requires the two routes to `KnownResidual` (degraded read-back, or the post-green-preflight empty-active-list auto-resolve residual for a zero-`[[expected]]` scenario) and requires that a scenario carrying ANY `[[expected]]` check and every read-back call failure still land `Blocked` with a named precondition — that confinement is a mandate, and whether the shipped code already honors it on this family is research's question (per architecture.md §Standard Contracts — Run report envelope · §Established Decisions [Read-Back Dependency Posture]).
- The v2-16 assertion split is arch-mandated, not chunk-local: lifecycle timing is a deterministic hard pass/fail claim, severity choice is model-interpretive → `CalibrationRegion`, mapped to `ManualCheck` by `Verdict::default_report_state`, never hard-failed on exact values; `verdict` and `state` stay independent and the report lamp is chosen verdict-first (per architecture.md §Established Decisions [Probabilistic-Assertion Policy]).
- Read-back must go through the hand-rolled line-delimited JSON-RPC client returning a RAW `serde_json::Value` result — Pulse's `tools/call` is non-MCP-compliant (no `{content:[…]}` envelope), so no typed-SDK envelope may be assumed when extracting from `query_incident_list` / `retrieve_report` / `mark_incident_resolved`; only the four persistent-corpus tools work cross-process from a Conductor-spawned sidecar (the in-memory-buffer tools return empty) (per architecture.md §Established Decisions [MCP Read-Back Client] · §Standard Contracts — Readiness gate NOTE).
- Scenario TOML edits stay inside the declared-config model: P-IDs validated two-layered (garde `pid_format` shape + `Scenario::check_capabilities` membership against `contracts/pulse-capabilities.toml`), nested spec structs must `dive` not `skip`, and the coverage-integrity gates (`check_sut_drift`, `check_scenario_backing`/`UNBACKED_AUTO` exact-set equality) treat a lost `Auto` backing as `CoreError::UnbackedCoverage` — whether retiring this family's checks to declare-only disturbs either gate is research's question (per architecture.md §Established Decisions [Accepted Capability Set] · §Conventions — Config conventions).
- Timing must be journal-relative (`read_back_observed_at − journal_emitted_at`), stamped from `std::time` and never tokio's virtual clock; `latency_ms` is INTEGER ms (NULL for blocked rows), the instant columns TEXT RFC-3339, `slo_tier` the closed `<5s`/`<20s`/`<90s` enum, and cross-run latency/fingerprint queries must exclude NULL-measurement rows — this governs any 120s-idle/30s-tick auto-resolve wait the leg measures (per architecture.md §Established Decisions [Timing-Tolerance Model] · §Conventions — Data model conventions).

## Patterns to follow
- The composition-root routing pattern already named in arch: `route_read_back` / `ReadBack {Graded, AutoResolved, Blocked}`, crate-private in `conductor-run`, with the `AutoResolved` arm recorded as unit-pinned and NOT fired on the 2026-08-20 live leg — arch describes it as target state; whether it now fires under this family is research's question (per architecture.md §Established Decisions [Read-Back Dependency Posture]).
- Sidecar spawn shape: fixed program path + `.env(ANDROMEDA_PULSE_DATA_DIR = the live Pulse's data-dir)` + injection-reject, so the sidecar reads the same `{data_dir}/corpus/corpus.db`; the preflight canary is what verifies that wiring before any scenario trusts read-back (per architecture.md §Occupied Resources — Service/process names · §Standard Contracts — Readiness gate).
- Split emission identities: `conductor` (`DEFAULT_SERVICE_NAME`, dispatcher) vs `conductor-canary` (`CANARY_SERVICE_NAME`, preflight warm-up + storm), because Pulse keys per-service sample counts and error-rate EWMAs — directly load-bearing for the scope's premise that canary residue kept refreshing an incident past its idle timeout (per architecture.md §Occupied Resources — Service/process names).
- Pinned-SUT-fact pattern, if the chunk needs to record resolver cadence or tier bands as data: a `contracts/*.toml` manifest carrying `sut_version` · `captured_at` · `provenance` (stated as a transcribed SUT record, never a Conductor measurement), runtime-read, bounds-checked at load, resolved from a fixed `default_path()` through `resolve_under` with deliberately NO `CONDUCTOR_*` override handle (per architecture.md §Occupied Resources — `contracts/pulse-capabilities.toml` / `pulse-load-envelope.toml` / `pulse-run-contract.toml`).
- Artifact naming/format split: `run_id` is the filesystem-safe hyphen stamp and the stem of `<run_id>.jsonl` + `<run_id>.md` under the runs dir (moves with `CONDUCTOR_RUNS_DIR`), while in-payload instants are colon-delimited RFC-3339; evidence Markdown is kebab-case (per architecture.md §Standard Contracts — Timestamp formats · §Occupied Resources — On-disk artifacts).

## Anti-patterns to avoid
- No new inbound listener and no HTTP surface of Conductor's own; the only sanctioned bind is the port-occupier fault on `:4317`, which this family does not declare (per architecture.md §Cross-cutting Patterns — Trust boundary · §Occupied Resources — Ports).
- No new env var outside the reserved `CONDUCTOR_*` namespace, no `CONDUCTOR_*` override handle for a `contracts/` manifest, and Conductor must never SET `ANDROMEDA_PULSE_MCP_ENABLED` / `_L4_DETERMINISTIC` — it reads them (as shell-declaration proxies) and propagates `ANDROMEDA_PULSE_DATA_DIR` only (per architecture.md §Occupied Resources — Environment variables).
- Never read `tracked_fingerprints_count` as evidence of absence — it is a 60s-windowed gauge over DISTINCT fingerprints sampled after eviction, so a healthy storm reads `1` or `0`; the window-immune discriminators are the cumulative `storms_detected_total` / `fingerprints_evicted_total` (per architecture.md §Occupied Resources — `contracts/pulse-run-contract.toml`).

## Contract bindings
- Run-report envelope + `runs.db` schema (11-column `runs` keyed `(run_id, scenario)` plus the run-scoped `run_envelope` table) bind arch → tests (row/golden fixtures) and → obs (report/journal field emission); a run-scoped qualifier must not become a `runs` column (arch §Occupied Resources — On-disk artifacts).
- Readiness gate's five named preconditions bind arch → security: every precondition string must be host-path-free with `data_dir` redacted (arch §Standard Contracts — Readiness gate).
- Self-observation stream (`logs/agent-latest.jsonl`) is a SEPARATE artifact and schema from the per-run emission journal — binds arch → obs-plan §3 for anything the live leg logs (arch §Occupied Resources — On-disk artifacts).
- Build-gate state binds arch → security-plan §Dependency Security: arch records `cargo deny` green while `cargo audit` is separately red on an external advisory-DB fault, which is the standing basis the chunk's folded 35th-consecutive audit prereq re-checks (arch §Infrastructure Patterns — Build system).

## Acceptance criteria contributions
- (arch) All chunk code lands in existing workspace members (`conductor-verify` read-back, `conductor-run` routing/drive, `conductor-report` artifacts) with no new crate and no new cross-seam `Cargo.toml` edge (per architecture.md §Established Decisions [Module Boundaries] / §Occupied Resources — Crate names).
- (arch) Every live row conforms to the envelope: `state` within the closed five, `verdict` within the three or `null` for declare-only, blocked rows null-measurement on `verdict`/instants/`latency_ms`/`fingerprints`, `slo_tier` from the closed tier enum, latency computed journal-relative (per architecture.md §Standard Contracts — Run report envelope / §Established Decisions [Timing-Tolerance Model]).
- (arch) Severity-choice claims resolve `CalibrationRegion → ManualCheck` and are never hard-failed on exact values, while lifecycle-timing claims are hard pass/fail (per architecture.md §Established Decisions [Probabilistic-Assertion Policy]).
- (arch) No new occupied resource: consumed MCP tools stay within the registered four, no env var outside `CONDUCTOR_*`, no inbound listener; any newly pinned SUT fact ships as a `contracts/` manifest with `provenance` and no override handle (per architecture.md §Occupied Resources).
