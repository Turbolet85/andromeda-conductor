- A never-measured or pre-accepted state must never render red or be downgraded to `Fail`: `Blocked` = hollow ring + named precondition string with measurement columns as `—`/null; `KnownResidual` = muted dashed dot + "expected until {named fix}" note (per layout-templates §Component — Primary content block 2, both surfaces).
- Every status must be paired with its ASCII bracket prefix (`[PASS]`/`[HOLD]`/`[FAIL]`/`[MANUAL]`/`[RESIDUAL]`/`[BLOCKED]`) so the signal survives `NO_COLOR`, piping and screen readers — never color-alone (per layout-templates §Surface: cli signature-placement paragraph + §cli IA notes → Pipe discipline).

- The coverage roll-up caption requires every number manifest-derived, never a literal; `(N unbacked)` qualifies the auto term only, is never a fifth summand, is omitted at zero, and renders identically on all three surfaces via the coverage matrix's `unbacked` prop sourced from the `unbacked_auto` command (per layout-templates §Surface: cli — Primary screens, `conductor coverage [--write]`).

## Patterns to follow
- **De-literalize, never re-pin** — when a scenario re-declares its tier, sample cells move to the `<slo_tier>` placeholder rather than a fresh literal; the same rule already applied to the unbacked count (per layout-templates §cli Primary screens, and the 2026-08-16/18/19 amendment line).
- **Run-level qualifier outside the lamp column** — the `[ENVIRONMENT-SUSPECT]` caption and the `not-conductors` Mode cell are the established shape for an annotation that qualifies a run/row without being a state: ASCII label always printed, ANSI 246 recessive tint, alters no per-check state, omitted entirely when not applicable (per layout-templates §cli Component — Primary content block 2 and §Component — Primary content block 1). This is the precedent for surfacing "measurement recorded, check declare-only" without inventing a lamp.
- **Detail line beneath the row** — `Blocked` carries its named precondition string and `KnownResidual` its residual note, both Body/`text-tertiary`, indented under the verdict line on cli and under the report line on desktop (per layout-templates §Wireframe — Run report (terminal) and §cli Output structure `conductor run <scenario>`).
- **Six-column results/SLO table vs four-column coverage table** — the two must not be conflated; a declare-only or retirement outcome that reaches `conductor coverage` touches the 4-column shape and its roll-up caption, not the results table (per layout-templates §cli Component — Primary content block 1).

## Anti-patterns to avoid
- Adding a seventh lamp state / new bracket label for the declare-only or "measured-but-ungradeable" outcome (per layout-templates §cli Component — Primary content block 2).
- Rendering a structurally-ungradeable or never-measured severity check as `Fail`/red, or as a silent green — both are banned; `CalibrationRegion` is amber-`[HOLD]`, `KnownResidual` is muted-dashed and never red (per layout-templates §Component — Primary content block 2, "Distinct non-result states (never downgraded to Fail)").
- Substituting a fresh count/tier literal into any sample row or caption (per layout-templates §cli Primary screens `conductor coverage` — "every number manifest-derived (never a literal)").
