# security extract

## Relevance
Relevant — the chunk carries a security-owned PREREQ (35th `cargo audit` re-check), edits the scenario-config trust boundary (five family TOMLs), drives the MCP read-back child-stdout boundary (incl. `mark_incident_resolved`, no live exercise on record), and lands agent-parseable evidence artifacts subject to artifact sanitization.

## Constraints
- The folded PREREQ is a security-plan mandate, not a formality: security-plan.md §Dependency Security requires the advisory-DATABASE fault be carried as a **bounded wait** with the audit↔deny overlap **verified** green (`cargo deny check advisories bans licenses sources` actually run, never assumed) — explicitly never a floor raise, never a `deny.toml` ignore, never a CI edit, never a silent accept. §Dependency Security also requires that if any dependency delta lands, the deferral's basis be re-stated ("no dependency delta" stops being available) and deny be verified green over the NEW `Cargo.lock` (per security-plan.md §Dependency Security).
- Any edit to the five family TOMLs (including retiring `expected` blocks to declare-only) must keep the garde trust boundary intact: `#[derive(Validate)]` `range` + `#[garde(custom)]` cross-field rules at load, **every nested spec field `dive`, never `skip`** — a `skip`ped nested struct deserializes entirely unvalidated because garde never descends into it. The severity shape's own rules (severity numbers ∈ 1..=24, `kind` REQUIRED whenever `[phases.emission]` exists, `occurrences` bounded by `MAX_OCCURRENCES` with `0` = declared silence) are the boundary for this family (per security-plan.md §Input Validation, scenario-config row).
- The read-back path for `query_incident_list` / `retrieve_report` / `mark_incident_resolved` must stay bounded and non-panicking: line-delimited JSON-RPC decoded with recursion limits + a soft per-line size bound, faults typed as `VerifyError::{JsonRpc,Decode,Transport}` through the verdict/error wall — a JSON-RPC error or empty round-trip reads as `blocked`, never a false pass-as-empty (per security-plan.md §Input Validation, MCP read-back child-stdout row; §Security Anti-Patterns → Universal). Whether the shipped extractors for a *resolved*-incident shape already degrade in the safe direction is research's question.
- An empty/emptied active list is the chunk's headline observable AND the plan's canonical false-pass hazard: §Security Anti-Patterns → Universal requires each of the gate's FIVE named preconditions surface as the **distinct** `blocked` state with its own named precondition string, never a false pass and **never the generic corpus-empty string**. A term whose truth lives on the SUT's side is recorded `declared-not-observable` and never blocks (per security-plan.md §Security Anti-Patterns → Universal) — this is the mechanism the chunk's "retire to declare-only WITH the measurement recorded" must land on.
- Lifecycle timing asserted hard pass/fail (120s idle / 30s resolver ticks) must be stamped from `std::time::SystemTime`/`Instant`, never tokio's virtual clock — a wrong clock source corrupts the ground-truth artifact and the journal-relative SLO math (per security-plan.md §Security Anti-Patterns → Logging).
- The evidence trail (per-leg journal, `runs.db` rows, `leg-verdict.md`) must carry verdict/state/identity fields only, with no absolute host paths (canonicalized `CONDUCTOR_*` directories, `ANDROMEDA_PULSE_DATA_DIR`) and no internal seam-crate struct/field names; a `blocked` row populates only identity fields with the named precondition string, measurement fields JSON `null` (per security-plan.md §Error Handling, run-report artifact sanitization; §Security Anti-Patterns → Logging).
- New `runs.db` rows must be written with rusqlite **bound parameters**, never `format!`/concatenated SQL, fingerprint arrays as a JSON1 TEXT array (per security-plan.md §Input Validation, `runs.db` row; §Security Anti-Patterns → Input).

## Patterns to follow
- Corpus access via **MCP read-back ONLY** — the sanctioned channel for observing auto-resolve and any resolution summary is the tool call, including `mark_incident_resolved` as a P-023 ack stimulus (it is already in the manifest's required-tool name set per §Input Validation, contract-manifest row). `corpus.db` is plaintext SQLite and SUT-owned; reading it directly to close a read-back gap is out of bounds (per security-plan.md §Data Protection; §Security Anti-Patterns → Data Protection).
- The named-precondition `blocked` pattern (§Security Anti-Patterns → Universal) is the existing shape for "structurally ungradeable, measurement recorded": a distinct precondition string carrying the condition AND its candidate causes, versus `declared-not-observable` for SUT-side truths — the same discipline the run-contract arm already uses.
- Sidecar spawn stays a fixed hard-coded program NAME (`andromeda-pulse-mcp`) resolved through the inherited `PATH`, with `ANDROMEDA_PULSE_DATA_DIR` passed strictly via the `.env(...)` builder after metacharacter rejection — never interpolated into argv or a shell (per security-plan.md §Security Anti-Patterns → Input and → Code Patterns).
- Live-leg environment discipline: `ANDROMEDA_PULSE_MCP_ENABLED` must be present in **Conductor's own** process environment (operator-exported, inherited by the sidecar — `spawn.rs` passes only the data dir via `.env(...)`); absent it the sidecar exits immediately and every read-back measures the unreachable path (per security-plan.md §Threat Model Summary → Auth model, Reason).
- Typed-error containment: `thiserror` enums stay inside the seam crates, collapsing to `anyhow` only at the `conductor-cli` edge; `tonic::Status` codes and MCP error responses are first-class typed verification inputs, not panics (per security-plan.md §Error Handling).

## Anti-patterns to avoid
- NEVER open, copy, or exfiltrate Pulse's `corpus.db` from production code — even if read-back turns out not to expose resolved rows or a resolution summary, the answer is a recorded measurement/`declared-not-observable`, not a direct corpus read (per security-plan.md §Security Anti-Patterns → Data Protection).
- NEVER silently downgrade a failed preflight, and never let an emptied active list read as either a false pass or the generic corpus-empty `blocked` string (per security-plan.md §Security Anti-Patterns → Universal).
- NEVER resolve the red audit by raising a tool floor, adding a `deny.toml` ignore, or editing CI — the fault is the advisory DB, so those remedies are unexecutable and would look like compliance while changing nothing (per security-plan.md §Dependency Security).

## Contract bindings
- **CI security gate ↔ tests §CI Integration** — the audit/deny probe is operator/local for this chunk (live legs are never CI); the gate itself stays one workflow job and must not be edited as a remedy (per security-plan.md §Dependency Security, CI integration).

- **Wall-clock stamp source ↔ arch determinism discipline** — the `SystemTime`/`Instant` mandate binds the lifecycle-timing hard pass/fail check this chunk grades (per security-plan.md §Security Anti-Patterns → Logging).
