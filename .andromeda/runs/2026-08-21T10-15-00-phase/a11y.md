# a11y extract

## Relevance
**Partial** — no UI surface, focus, keyboard or contrast work is added by this chunk, but it mutates the run-report envelope that a11y reproduces verbatim as its violation-artifact schema, and open fork 1 (row-per-check vs. sub-structure) collides with the coverage-matrix row identity a11y pins.

## Constraints
- The a11y violation artifact is **not its own schema** — it aligns verbatim to the obs §6 run-report envelope (11 fields incl. `latency_ms` and `slo_tier: "<5s | <20s | <90s"`), with a11y narrowing only; obs fixed the shape (per a11y-plan §1 A11y assertion harness specification → Structured violation JSON schema, and §3 Structured violation JSON schema). If this chunk changes the envelope (a sub-5s budget field, a per-check latency sub-structure, or altered `latency_ms` semantics), a11y's **two** verbatim reproductions (§1 and §3) must be amended in lockstep or the binding contract goes stale.
- **No new top-level fields may be introduced by a11y** — axe rule-id, `impact`, WCAG tags and node `target` selectors ride inside `fingerprints[]` precisely so the envelope stays the obs-fixed shape (per a11y-plan §3 Structured violation JSON schema). Whatever per-check latency shape P4 picks must remain populatable (or explicitly null-able) by an a11y artifact that has no per-check semantics; whether a11y emission code exists yet is research's question (§3 Bootstrap phases lists `violation-json-emission-wire` as a *pending* bootstrap item).
- The **lamp → journal-row join is defined by a11y**, not by the renderer: the display-label ↔ `verdict` ↔ `state` crosswalk is binding for joining a failing lamp back to its journal row, verdict-first (`verdict == CalibrationRegion` ⇒ HOLD lamp regardless of `state`) (per a11y-plan §6 State color tokens → State-naming crosswalk). If one journal row becomes several per-check rows, the join key gains a check dimension and the crosswalk's "its journal row" phrasing needs an amendment; open fork 2 ("the chosen row's latency must be attributable to a named check") is the same question from the a11y side.
- The coverage matrix is specified as a **single-row-per-P-ID `list`/`listitem`** with `aria-selected`/`aria-current` on the selected row (per a11y-plan §4 Per-component pattern catalog; §1 A11y scope → Coverage matrix entity). Open fork 1's row-per-check option changes what a matrix row *is*; a per-check sub-structure inside one row does not. Whichever P4 picks, the rendered list must keep one accessible row identity per listitem.
- **Any new envelope field name must survive the artifact-leak ban**: a11y artifacts MUST NOT leak absolute host paths or internal seam-crate struct names into the obs §6 envelope (per a11y-plan §3 Structured violation JSON schema, §9 CI-specific resource attributes, §11 SLO). A per-check field named after an internal seam-crate struct would put the a11y artifact in violation the moment it inherits the envelope; the chunk's redaction-allowlist touch (`conductor-core/src/redact.rs`) is where that lands.
- The **cli surface is not-assertable** — no DOM/widget tree, no axe/Lighthouse/pa11y reach; its ASCII status prefixes and NO_COLOR text-pairing are output-stream discipline, **not** an a11y verification path (per a11y-plan §1 A11y scope → conductor-cli entity; §11 Universal). Latency display in `conductor-cli/src/render.rs` and the Markdown `conductor-report/src/report.rs` therefore carries **no** a11y acceptance obligation.

## Patterns to follow
- **Envelope-reproduction tracking:** when the upstream envelope gains a field, a11y's reproduction tracks it verbatim without behavior change — the established mechanism is a sidecar amendment to §1 + §3, exactly as done for `read_back_observed_at` (per a11y-plan §3 Structured violation JSON schema; amendment 2026-06-16).
- **Fold-into-`fingerprints[]`:** all a11y sub-detail (rule id, SC tag, selector tuple, colorjs.io `{ token_fg, token_bg, ratio, required, pass }`, keyboard PASS/FAIL) is expressed inside existing fields rather than by widening the envelope (per a11y-plan §3 Structured violation JSON schema, § Contrast verification harness).
- **Monospace status-tier typography for timings:** SLO timings, counts, P-IDs, `run_id` and fingerprints render with `--font-mono` and are contrast-asserted on the `--color-id-cyan`/`--color-base` pair at 4.5:1 (per a11y-plan §6 Color contrast pairs; §6 Typography tokens). This is the pattern any *webview* per-check latency display would follow — whether a desktop-webview render surface exists today, and whether this chunk touches it, is research's question (the scope's surface table names only Rust crates).
- **Envelope-derived resource tagging:** a11y artifacts tag `service.name` (`"conductor-tauri"` / `"conductor-ui"`) + `deployment.environment` for cross-correlation with the `runs.db` row and JSONL journal (per a11y-plan §2 Naming conventions; §9 CI-specific resource attributes) — the storage-key decision in open fork 1 is what that correlation resolves against.

## Anti-patterns to avoid
- NEVER treat the cli surface as accessibility-assertable — its status prefixes / NO_COLOR pairing are output discipline, not an ARIA verification path (per a11y-plan §11 Universal). Do not attach a11y checks to the CLI/Markdown latency renderers.
- NEVER let a11y artifacts leak absolute host paths or internal seam-crate struct names into the obs §6 envelope (per a11y-plan §11 SLO) — constrains the naming of any new per-check field the envelope gains.
- NEVER drop virtual-scrolled coverage-matrix rows from the accessibility tree — every P-ID `listitem` must stay reachable/announceable (per a11y-plan §11 Screen Reader). A row-per-check envelope multiplies matrix rows and raises the virtualization exposure this ban targets.

## Contract bindings
- **a11y ↔ obs (D-a11y-obs-schema):** a11y's violation artifact reproduces the obs §6 run-report envelope verbatim; obs owns the shape, a11y narrows (per a11y-plan §1 A11y assertion harness specification, §3 Structured violation JSON schema). Any envelope delta from this chunk propagates to a11y as a reproduction amendment.
- **a11y ↔ tests:** the a11y gate rides the tests §6 `@crabnebula/tauri-driver` + WebdriverIO `wdio run` webview job and surfaces results through tests' `logs` command of the 5-command contract (per a11y-plan §3 CI integration, §9 Pipeline integration) — unchanged by this chunk, noted so no parallel a11y lane is invented for a Rust-side change.
- **a11y ↔ design:** `--color-id-cyan`/`--color-base` (SLO-timings monospace text, 4.5:1) and `--font-mono` are the token anchors any webview latency display binds to (per a11y-plan §6 Color contrast pairs, §6 Typography tokens).
- **a11y ↔ storage/render (open fork 1):** the §6 crosswalk's lamp→journal-row join and §4's single-row-per-P-ID matrix both assume one row per scenario/P-ID; P4's PK decision is the deciding input.

## Acceptance criteria contributions
- (a11y) If the run-report envelope's field set or `latency_ms` semantics change, a11y-plan's **two** verbatim envelope reproductions (§1 harness spec + §3) are amended in the same wrap, per the D-a11y-obs-schema bind (per a11y-plan §3 Structured violation JSON schema).
- (a11y) Any new envelope field name admitted to `conductor-core/src/redact.rs` is not an internal seam-crate struct name and exposes no absolute host path, so an a11y artifact inheriting the envelope cannot leak (per a11y-plan §11 SLO).
- (a11y) If open fork 1 lands row-per-check, the §6 lamp→journal-row join and §4's single-row-per-P-ID `list`/`listitem` matrix contract are restated for the new row identity (amendment), not left implicitly broken (per a11y-plan §6 State color tokens → State-naming crosswalk; §4 Per-component pattern catalog).
- (a11y) No a11y assertion, gate, or acceptance check is attached to the CLI or Markdown latency renderers — the cli surface is not-assertable (per a11y-plan §11 Universal).
