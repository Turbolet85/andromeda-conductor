# arch extract

## Relevance
Relevant — the chunk edits a Standard Contract (the run-report envelope), the `runs.db` schema, and the scenario config model, all of which arch governs directly.

## Constraints
- Latency is journal-relative by mandate: every SLO value is `read_back_observed_at − journal_emitted_at`, never wall-clock-from-test-start, and the stamps must come from `std::time::SystemTime`/`Instant` and never tokio's virtual clock (per architecture.md §Design Philosophy "Journal-relative ground truth" + §Cross-cutting Patterns "Determinism discipline"). A per-check latency must be derived the same way per check, not from a new clock source.
- `slo_tier` is required to stay a closed TEXT enum over exactly `<5s`/`<20s`/`<90s`, and `runs` column types are "fixed on first write (no migration framework to coerce later)" with `latency_ms` INTEGER milliseconds, NULL for blocked rows (per architecture.md §Conventions "Data model conventions"). This is the arch basis for the scope's `[inferred]` lean to add a budget *beneath* the tier rather than widen the enum.
- The run-report envelope is a Standard Contract: the Markdown report and the `runs.db` row must share ONE documented shape, and a blocked row populates only identity fields (`run_id`/`seed`/`scenario`/`p_ids`/`slo_tier`) with `verdict`/`journal_emitted_at`/`read_back_observed_at`/`latency_ms`/`fingerprints` emitted as JSON `null` and stored NULL; cross-run latency/percentile and P-036 fingerprint queries MUST exclude NULL-measurement rows (per architecture.md §Standard Contracts "Run report envelope"). Any per-check latency representation must preserve all three properties — whether the shipped code already honors the NULL-exclusion rule is research's question.
- The nearest arch precedent for open fork 1 is the `run_envelope` split: arch requires `runs.db` tables be added additively under `CREATE TABLE IF NOT EXISTS` with raw SQL and no ORM/migrations, and records that `run_envelope` was made a separate table rather than a column on `runs` *because its qualifier is run-scoped*, so `runs` keeps its eleven columns and `state` stays the closed five-variant set (per architecture.md §Occupied Resources "On-disk artifacts" + §Established Decisions [ORM]). By that reasoning a per-CHECK qualifier is not run-scoped; P4 must pick and cite.
- Budget declaration is config, validated at load: declarative TOML → serde → garde in the owning seam crate, `CoreError::Config` on parse failure and `CoreError::Validation` on a garde failure (per architecture.md §Established Decisions [Scenario Config Format] + §Conventions "Config conventions"). A budget-exceeds-its-tier incoherence is therefore a harness fault at load, never a `Fail` verdict — the verdict/error wall (§Design Philosophy, §Conventions "Error handling").
- garde 0.22.1's `#[garde(custom)]` is field-level only (no container-level custom), so the "budget ≤ its tier's `deadline_ms()`" cross-field invariant must use the `Context` pattern or a field-level `custom` one altitude up (the `no_duplicate_pids` / `fault_phases_are_silent` shape), and any nested spec field must `dive`, never `skip` (per architecture.md §Established Decisions [Validation Library] + §Conventions "Config conventions").
- Deadline comparison stays inside the tier-scaled tolerance model: hard/deterministic SLOs hard-fail against a tolerance band, while sample-count floors and model-interpretive timings route to the calibration region, mapping `CalibrationRegion→ManualCheck` by default with `verdict`/`state` independent (per architecture.md §Established Decisions [Timing-Tolerance Model] + [Probabilistic-Assertion Policy]).

## Patterns to follow
- Optional nested declared-data field on the scenario model: `PhaseSpec.fault: Option<FaultSpec>` (serde default absent, garde `dive`, closed kind enum, invariant asserted one altitude up) is the shipped precedent for adding an optional sub-5s budget declaration (per architecture.md §Conventions "Config conventions").
- Value-type preservation in the config model: `EmissionShape::Error { error_percent: u32 }` was chosen as an integer specifically so `PhaseSpec`/`Scenario` keep `Eq` — a new budget field should follow the same integer-milliseconds discipline (per architecture.md §Established Decisions [Validation Library]).
- Additive second-table registration in `runs.db` (`run_envelope` beside `runs`, raw SQL, `CREATE TABLE IF NOT EXISTS`) is the shipped shape if per-check latency needs its own row grain (per architecture.md §Occupied Resources + §Established Decisions [ORM]).
- Instant/duration encoding split already in force: RFC-3339 TEXT for the two instant columns, a separate INTEGER `latency_ms` for the value the SLO math consumes — the same split should carry per check (per architecture.md §Conventions "Data model conventions" + §Standard Contracts "Timestamp formats").
- Crate-per-seam placement: the scope's touched files sit in already-locked members (`conductor-core`, `conductor-verify`, `conductor-run`, `conductor-report`, `conductor-cli`); cross-seam edges are compiler-enforced, so no new edge should be introduced (per architecture.md §Established Decisions [Module Boundaries] + §Occupied Resources "Crate names").

## Anti-patterns to avoid
- Do not widen `SloTier` beyond its three variants, and do not widen the closed `state`/`verdict` sets, to express a finer budget — arch pins both as closed enums (per architecture.md §Conventions "Data model conventions" + §Standard Contracts).
- Do not introduce a migration framework, an ORM, or a column-type coercion to reshape `runs`; and do not add a new `CONDUCTOR_*` env var or a new workspace crate for this representation change (per architecture.md §Established Decisions [ORM] + §Occupied Resources).
- Do not let a per-check latency be a synthesized or inherited value on a row that was never measured (Blocked, or the `KnownResidual` declare-only routes) — the envelope requires JSON `null` there (per architecture.md §Standard Contracts "Run report envelope" + §Established Decisions [Read-Back Dependency Posture]).

## Contract bindings
- **Envelope ↔ security/obs redaction:** the scope names `conductor-core/src/redact.rs` — arch requires every precondition string be host-path-free and `data_dir` redacted, so any NEW envelope field name must be admitted to the allowlist deliberately, which is security's and obs's surface, not arch's alone (per architecture.md §Standard Contracts).
- **Envelope ↔ tests:** the run-report envelope is the shape golden/E2E fixtures assert, so a shape change is a fixture change (per architecture.md §Standard Contracts; test-plan owns the fixtures).
- **`slo_tier` ↔ scenario catalog:** the scope forbids re-tiering; arch's envelope sample was itself re-tiered `<5s`→`<90s` at 2026-08-18, so the catalog's tier values are live doc content that must stay consistent with whatever lands.
- **Dependency delta ↔ security:** arch §Stack and Technologies is the registry any new crate must enter; the scope's PREREQ auto-satisfy basis holds only on a zero-dependency-delta chunk, which is P3/P4's to confirm.

- (arch) The run-report envelope documented in arch and the `runs.db` row still share ONE shape, and blocked rows still emit `verdict`/`journal_emitted_at`/`read_back_observed_at`/`latency_ms`/`fingerprints` as `null`/NULL with cross-run latency and P-036 queries excluding NULL-measurement rows (per architecture.md §Standard Contracts "Run report envelope").
