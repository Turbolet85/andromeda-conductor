# security extract

## Relevance
Partial — the chunk touches two of security's live surfaces (the scenario-config garde boundary and the run-report/`runs.db` artifact-hygiene surface) but crosses no new trust boundary: no auth, no secrets, no network surface, no sidecar-spawn change, no new external input source.

## Constraints
- A new scenario-declared sub-5s budget field is an addition to the scenario-config trust boundary, so security-plan §Input Validation (scenario-config row) requires it to be garde-validated at load in its owning seam crate — `range` bounds plus a `#[garde(custom)]` cross-field rule for the budget-vs-tier relation — with the failed `Report` becoming `ConfigError` via `#[from]` (a harness fault, never a verdict). The scope's `[inferred]` "budget ≤ its tier's `deadline_ms()`" invariant is exactly the cross-field class this row mandates.
- If the budget lands as (or inside) a nested spec struct, security-plan §Input Validation and §Security Anti-Patterns → Input require the field be annotated `dive` and never `#[garde(skip)]` — a skipped nested struct deserializes entirely unvalidated because garde never descends into it.
- Any write of a per-check latency value into `runs.db` must use rusqlite bound parameters; §Input Validation (`runs.db` row) and §Security Anti-Patterns → Input ban string-concatenated / `format!`-built SQL regardless of the data being self-generated synthetic telemetry.
- security-plan §Security Anti-Patterns → Logging requires journal/report wall-clock stamps to come from `std::time::SystemTime`/`Instant` and never from tokio's virtual clock, because a wrong clock source corrupts the ground-truth artifact. This chunk is entirely about which instants a latency is measured between, so it sits directly on that ban; whether the current `emitted_ms`/`observed_ms` pair already uses the std clock is research's question.
- security-plan §Error Handling (run-report artifact sanitization) requires `<run_id>.md` and `runs.db` rows to carry verdict/state/identity/measurement fields — it names `latency_ms` in that set — without leaking absolute host paths or internal seam-crate struct names, and requires a `blocked` row to populate identity fields only with measurement fields JSON `null`. Whatever shape per-check latency takes (row-per-check or per-check sub-structure, the scope's open fork 1), that null-on-blocked rule and the field-naming discipline must survive it; the scope's redaction-allowlist touch (`conductor-core/src/redact.rs`) is the enforcement point, and whether the allowlist already admits only sanitized names is research's question.
- Operator-visible failures from the new budget validation must stay sanitized: §Error Handling requires typed `thiserror` enums (`ConfigError`) internal to the seam crate, collapsing to type-erased `anyhow` only at the `conductor-cli` / `#[tauri::command]` edges, with no stack traces, absolute paths, or internal struct names surfacing there.
- The chunk expects zero dependency delta. security-plan §Dependency Security holds the audit deferral open only as a bounded wait with the `cargo deny check advisories bans licenses sources` overlap **verified** green, and requires that any admitted package land only on a deny run verified green over the NEW `Cargo.lock` — "no dependency delta" ceases to be an available basis the moment one lands. §Security Anti-Patterns → Universal additionally forbids the release gate without audit/deny green.

## Patterns to follow
- garde `#[derive(Validate)]` with `range` rules plus `#[garde(custom)]` cross-field validators, co-located with the serde structs in their owning seam crate (per security-plan §Input Validation) — the same shape the `[phases.emission]` and `[phases.fault]` surfaces are held to.
- Closed serde-renamed enum discriminators where an unknown value is a deserialize error rather than an inferred default (per security-plan §Input Validation, the `FaultKindSpec` closed-enum rule) — this is the precedent supporting the scope's lean to keep `SloTier` closed at three variants and add a separate optional budget beneath it.
- rusqlite 0.38.0 parameterized statements in the `conductor-report` storage seam, with array-valued fields written as JSON1 TEXT (per security-plan §Input Validation, `runs.db` row) — the JSON1 precedent is directly usable for the scope's open fork 1 if per-check latency lands as a sub-structure in one row.
- Typed `thiserror` enums per seam crate collapsed to `anyhow` only at the binary/IPC edge, with verification outcomes staying typed `Ok(...)` values and `Result::Err` reserved for harness faults (per security-plan §Error Handling).
- For the folded PREREQ: reproduce the audit probe and verify the deny overlap actually ran green rather than assuming it; remedy stays the bounded wait — never a floor raise, never a `deny.toml` ignore, never a CI edit (per security-plan §Dependency Security, advisory-DATABASE fault bullet).

## Anti-patterns to avoid
- Never deserialize the new budget declaration without garde validation, and never mark a nested spec field `#[garde(skip)]` — the rules exist but never run, silently bypassing the boundary (per security-plan §Security Anti-Patterns → Input).
- Never build the per-check latency SQL by string concatenation / `format!` (per security-plan §Security Anti-Patterns → Input).
- Never let the new envelope field carry an absolute host path or an internal seam-crate struct/field name into `<run_id>.md`, `runs.db`, or the JSONL journal, and never source its stamps from the virtual clock (per security-plan §Security Anti-Patterns → Logging).

## Contract bindings
- **Artifact field allowlist** (`conductor-core/src/redact.rs` per the scope) binds security's artifact-hygiene ban (security-plan §Security Anti-Patterns → Logging; §Error Handling) to obs's envelope/field schema and to tests' golden-envelope assertions: the new per-check latency field name must be admitted deliberately, and security's ban, obs's schema, and the golden fixtures must name the same field set.
- **Blocked-row nulling** binds §Error Handling to the run-report envelope contract (`conductor-core/src/run_record.rs` + architecture §Standard Contracts) — whichever shape open fork 1 picks must keep measurement fields JSON `null` on `blocked`.
- **CI security gate** (cargo-audit + cargo-deny per security-plan §Dependency Security, CI integration) binds to tests §CI Integration — one workflow, security gate as a job.
- No PII/secret binding: security-plan §Threat Model Summary classifies PII/payment/health/credential as "none", so no scrubbing contract attaches to this chunk.

- (security) grep verifies no `#[garde(skip)]` on any new or nested scenario-spec field introduced by this chunk, and no `format!`/concatenated SQL on the per-check latency write path in `conductor-report` (per security-plan §Security Anti-Patterns → Input).
