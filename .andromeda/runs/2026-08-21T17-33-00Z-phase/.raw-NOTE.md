## The modification: HTML entity decode (5 of 7 extracts)

The subagent return transport HTML-escaped `<`, `>` and `&`. On save each affected file had exactly this
uniform transformation applied, and nothing else:

- `&lt;` → `<`
- `&gt;` → `>`
- `&amp;` → `&`

| extract | affected | load-bearing tokens that were mangled |
|---|---|---|
| `arch.md` | no | — (returned clean) |
| `a11y.md` | no | — (returned clean) |
| `design.md` | yes | `&lt;5s`/`&lt;20s`/`&lt;90s` (the closed `slo_tier` set), `&lt;slo_tier&gt;` |
| `security.md` | yes | `&amp;field`, `&amp;()` (the garde 0.22.1 `(&field, &())` signature), `&lt;run_id&gt;` |

## Why this matters beyond bookkeeping

This is a REPEAT of a defect already recorded in CLAUDE.md §Session Learnings (2026-08-21): "the subagent
transport HTML-escaped `<`/`>` in all seven returned extracts, mangling exactly the `<5s`/`<20s`/`<90s`
tokens the work turned on." It recurred in this run, on the same token class, and was caught the same way
— by reading the returned text rather than trusting it.

The decode is uniform and mechanically invertible, so the extracts as saved are the faithful content. No
raw twin was persisted because a re-encoded file would be a RECONSTRUCTION wearing the name of a raw
record; this note states the exact delta instead. Recorded as a deliberate deviation from `fan-out.md`'s
raw-twin clause in the phase evolve step record (`problem` block), not as a silent omission.
