# a11y extract

## Relevance
Partial — no desktop-webview code is in the chunk's surface list, but the chunk writes the `verdict`/`state` values and coverage-matrix classifications that a11y binds to the six-state lamp and Mode cell, and one live outcome shape (DriveObserve operator-checklist) is itself a must-be-accessible path; whether the webview lamp/coverage-matrix/checklist surfaces already exist in code is research's question.

## Constraints
- Every `verdict`/`state` value this chunk writes into the run-report envelope or per-check `CheckRecord` must resolve through the display-label ↔ `verdict` ↔ `state` crosswalk, chosen **verdict-first** (`verdict == CalibrationRegion` ⇒ HOLD lamp regardless of `state`); a value outside that closed set would leave a rendered state with no lamp row (per a11y-plan §6 State color tokens → State-naming crosswalk).
- If the four P-IDs land as `KnownResidual` (harvest tier) or `ManualCheck` (DriveObserve), a11y-plan §6 requires the corresponding lamp carry its text label plus glyph supplement (`Residual`+dashed-ring / `Manual`+checkbox-glyph) — state may never be color-alone (SC 1.4.1) (per a11y-plan §6 + §11 Visual).
- If a coverage-mode reclassification lands for any of the four P-IDs, the Mode cell is a **coverage-mode classification, not a seventh lamp state**: the six-label not-color-alone assertion keys on the LAMP display labels, and the Mode cell's own always-rendered label is its signal (no glyph supplement), while its token pair is still contrast-asserted (per a11y-plan §1 A11y triggers → non-lamp reuse of a state token).
- If the chunk's outcome is a DriveObserve operator-checklist, that is one of the four must-be-accessible paths and requires `checkbox` per item inside a group/region container, `aria-checked` per row, Space toggling a focused row, each item exposing induced-state + expected-observation text, and a reachable/announced unticked-count roll-up (per a11y-plan §1 Critical paths → Operator-checklist + §4 pattern catalog).
- Any evidence/basis strings this chunk records into the envelope must not leak absolute host paths or internal seam-crate struct names — a11y violation artifacts ride the same obs §6 envelope and inherit tests' Status-JSON constraint (per a11y-plan §3 Structured violation JSON schema + §11 SLO).
- New or re-classified coverage-matrix rows must remain keyboard-reachable and announceable, including off-screen virtual-scrolled rows (per a11y-plan §4 Coverage matrix + §5 run-report-terminal + §11 Screen Reader).
- The `conductor-run` / `conductor-report` CLI output of these gradings carries **no** a11y verification path — the cli surface is not-assertable; ASCII prefixes / NO_COLOR text-pairing are output-stream discipline, not ARIA conformance (per a11y-plan §1 A11y scope + §11 Universal).

## Patterns to follow
- The §6 State-naming crosswalk as the join table: pick an existing display-label row rather than inventing a grading-outcome state; downstream joins a failing lamp back to its journal row through it (a11y-plan §6).
- Envelope-narrowing pattern: a11y reproduces the obs §6 envelope verbatim and folds its own detail into `fingerprints[]` with **no new top-level fields** — the same discipline any new grading evidence should follow (a11y-plan §3 Structured violation JSON schema).
- Operator-checklist rendering pattern already catalogued for `ManualCheck`: native checkbox rows in a group/region, `aria-checked`, Space toggle, unticked-count roll-up (a11y-plan §4).
- Coverage-matrix pattern: `list`/`listitem` (or table semantics) with `aria-selected`/`aria-current` + `--border-emphasis` on the selected row, real-prose empty state (a11y-plan §4 + §6 Focus ring tokens).
- Operator/local gate posture: a11y's webview gate is explicitly operator/local (live-Pulse dependent), riding tests' `wdio run` job and the 5-command `logs` surface — matching this chunk's own live-Pulse proof posture (a11y-plan §3 CI integration + §9).

## Anti-patterns to avoid
- NEVER convey a grading outcome by color alone — any state token applied to a new/reclassified cell without an always-rendered text label fails the not-color-alone gate (a11y-plan §11 Visual).
- NEVER treat the cli grading output as an accessibility-assertable surface or claim a11y coverage from it (a11y-plan §11 Universal).
- NEVER let report/`CheckRecord` evidence fields carry absolute host paths or internal seam-crate struct names into the shared envelope (a11y-plan §11 SLO).

## Contract bindings
- **a11y ↔ obs:** a11y's violation JSON is the obs §6 run-report envelope reproduced verbatim; if this chunk changes the envelope or `CheckRecord` field set, a11y-plan §3's two reproductions must be amended in step (a11y-plan §3; precedent in amendment history below).
- **a11y ↔ design:** state-color token pairs (`--status-residual`, `--status-manual`, `--count-nominal`, `--count-hold`, `--status-fail` over `--color-base`) bind to design's Color Palette for the SC 1.4.11 3:1 assertion (a11y-plan §6 Color contrast pairs).
- **a11y ↔ tests:** the a11y axe/contrast/keyboard step rides tests' `@crabnebula/tauri-driver` + WebdriverIO webview job and emits through the 5-command `logs` command (a11y-plan §3 CI integration + §9).
