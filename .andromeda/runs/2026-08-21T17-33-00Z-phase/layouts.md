## Relevance
Partial — the chunk is engine/verdict work, but its graded outcomes render into layouts-owned surfaces: the `runs/<run_id>.md` per-check detail region, the closed six-lamp report-state set (cli + webview run-report card), and the coverage-matrix Mode cell / roll-up caption if the four P-IDs' modes move.

## Constraints
- The per-P-ID verdict/report-state label set is **closed at six** (`[PASS]`/`[HOLD]`/`[FAIL]`/`[MANUAL]`/`[RESIDUAL]`/`[BLOCKED]`); whatever grading tier this chunk lands must render through that set — a new tier is not a seventh lamp or a sixth `ReportState` (per layout-templates §cli Component — Primary content block 2).
- A capability whose value was never measured must render `Blocked` (hollow ring, named precondition string, measurement columns `—`/null) and a pre-accepted gap must render `KnownResidual` (muted dashed dot + "expected until {named fix}" note) — **never red, never downgraded to `Fail`** (per §Component — Primary content block 2, both surfaces).
- Per-check budget grading belongs in the **indented per-check detail region of `runs/<run_id>.md`** — one line per expected check carrying ordinal, comparison kind, verdict, its own `latency_ms`, and the deadline it was judged against (declared budget, or the scenario tier when inherited) — with no new column, no new bracket label, no new ANSI/token entry; cli stdout and the 6-column results/SLO table stay unchanged (per §cli Component — Primary content block 2, per-check detail region).
- The `slo_tier` cell renders the scenario's TOML-declared value from the **closed `<5s`/`<20s`/`<90s` set**. Sub-tier budgets (≤1s / ≤2s) have no tier cell to occupy — they are per-check deadlines, not a fourth tier value and not a new column (per §Wireframe — Run report (terminal) · §cli Component — Primary content block 1).
- If any of the four P-IDs' classification moves, the **Mode cell** must render exactly one of four text values (`auto` · `drive+observe` · `static-only` · `not-Conductor's`), never color-only, and the header-strip / cli tallies must still sum to the row count (per §Component — Primary content block 1, coverage matrix).
- The `conductor coverage` roll-up caption's numbers are **manifest-derived, never literals**; `(N unbacked)` qualifies the `auto` term only, is never a fifth summand, is plain text with no new token/ANSI/colour, is omitted at zero, and renders identically on all three surfaces via the coverage matrix's `unbacked` prop from the `unbacked_auto` command — never mirrored in TypeScript (per §cli Primary screens, `conductor coverage [--write]`). Naming these four P-IDs in scenarios would move `UNBACKED_AUTO`; whether it does is research's question.
- Every status is paired with its ASCII/text label so it survives `NO_COLOR`, piping and screen readers; adding a `comfy-table` column without a `--format` flag is a breaking change for downstream agents (per §cli IA notes · §Component — Primary content block 2).

## Patterns to follow
- **Run-level non-lamp qualifier riding outside the lamp column** — `[ENVIRONMENT-SUSPECT]` (ANSI 246, always-printed ASCII bracket, printed once per run above the verdict lines, omitted when not applicable) is the precedent for any run-scoped caveat this chunk needs about basis/reachability; it alters no per-check state (per §cli Output structure `conductor run` · §Primary content block 2).
- **Indented-detail-line precedent** — the `Blocked` precondition string and the `KnownResidual` note already establish that extra per-P-ID prose goes on an indented line beneath the verdict line, not in a new column (per §Component — Primary content block 2, both surfaces).
- **Operator-checklist render for `ManualCheck`** — induced state (what Conductor drove) left, expected observation as a ticked y/n right; Space toggles; the footer roll-up surfaces the unticked count so an incomplete manual pass never reads as a finished run. This is the shape if a human-operated Pulse window turns out to be a precondition for the three webview-sourced observables (per §Component — Operator-checklist).
- **Adapted-not-forked across surfaces** — the same report-state reads identically on the webview run-report card, cli stdout and the Markdown artifact; a change to one must land on all three by name (per §desktop-webview IA notes, Multi-surface coordination · §cli IA notes).
- **De-literalize rather than re-pin** — sample tier cells and derived counts in the doc use `<slo_tier>` / `(N unbacked)` placeholder form instead of a fresh literal (established across the 2026-08-16 / -18 / -19 amendments below).

## Anti-patterns to avoid
- Adding a seventh lamp state, a new bracket label, or a new results-table column to express "measured but unreachable" / "graded from a live leg's harvest" (per §cli Component — Primary content block 2).
- Rendering an unreachable or never-measured budget as a red `Fail` — `Blocked`/`KnownResidual` exist exactly so nothing silently collapses into `Fail` (per §Component — Primary content block 2, Distinct non-result states).
- Any layout that implies Conductor drives Pulse's GUI: the operator-checklist is where a Pulse-window observation is **checked**, never performed (per §Component — Operator-checklist).

## Contract bindings
- **Per-check detail region ↔ report data contract** — the rendered deadline field is the layout surface of `ExpectedCheck::budget_ms` → `effective_deadline_ms` on `CheckRecord` (`conductor-report`); the region must render whichever deadline the record carries (declared vs. inherited tier). Whether that region already renders `budget_ms`-declared deadlines is research's question.
- **Mode cell + roll-up caption ↔ coverage classification** — bound to `conductor_core::coverage_matrix` / `UNBACKED_AUTO` and, on the webview, to the `unbacked_auto` command feeding the `unbacked` prop (never a TypeScript mirror).
- **Lamp/state rendering ↔ a11y** — status never color-alone (webview: lamp always paired with verdict text; cli: ANSI always paired with the ASCII bracket prefix); verdict/state changes are announced, with the concrete attributes derived by a11y (per §Notes).
- **ManualCheck footer roll-up ↔ verdict path** — the unticked-ManualCheck count in the footer strip depends on the report exposing per-item confirmation state (per §Component — Footer).
