# obs extract

## Relevance
Relevant — this chunk grades measured timing values and records their basis, which lands squarely on obs-plan's journal record shapes (§3), SLO/latency semantics (§5, §10), harvest-tier evidence precedent (§4), and the redaction/bounded-span bans (§11).

## Constraints
- The run-report envelope must stay the eleven fields; per-check grading rides the **`CheckRecord` grain** (`run_id` · `scenario` · `check_index` · `kind` · `verdict` · `state` · `latency_ms` · `deadline_ms` · `budget_ms`) as a finer grain beneath the envelope, never an extension of it, and a declare-only/blocked scenario emits no check line at all (per obs-plan §3 Log format JSON schema — two record shapes). Neither report-seam shape passes through the span-attribute allowlist. Format ownership is test-plan §3; obs derives.
- `latency_ms` is defined as `read_back_observed_at − journal_emitted_at` in wall-clock milliseconds (per obs-plan §5 Metric Coverage and §10 Performance budgets). The chunk's open premise about `budget_ms` being a category error is exactly this constraint: the plan binds the instrument to Conductor's read-back round trip, not to a duration measured inside Pulse. Whether the shipped `budget_ms`/`effective_deadline_ms` path measures anything other than that difference is research's question.
- `slo_tier` is a closed enum (`<5s` / `<20s` / `<90s`) on the envelope (per obs-plan §3 Log format JSON schema and §6 Log Coverage), so three of the four budgets (≤1s, ≤2s, ≤2s) have no tier of their own — any grading must come from the check-grain budget field, not from widening the envelope enum.
- No metrics instrument may be introduced to carry these values: Minimal tier has no metrics backend and the performance budget is a JSON field assertion (per obs-plan §5), with the no-SDK invariant stated as behavioral — no OTel SDK is ever initialized for self-observation (per obs-plan §3 OTel SDK init). Pulse's four `metric.*` leaves are Pulse's own tracing events; naming does not make them Conductor metrics.
- Any span the measurement path adds must use the `{module}.{operation}` convention and fall inside the bounded span-name set (per obs-plan §4 Span naming convention and §11 Spans / Traces); its attributes must be names in `conductor-core::redact::ALLOWLISTED_FIELDS` or the processor stage drops them, emitting nothing (per obs-plan §4 Required-span-attributes constraint).
- Timestamps and durations must come from wall clock (`std::time::SystemTime`/`Instant`), never tokio's virtual clock (per obs-plan §11 Project-specific bans and §1 conductor-timeline instrumentability row).
- Nothing harvested from Pulse may reintroduce absolute host paths or internal struct names into Conductor's logs / run report / `runs.db` (per obs-plan §11 PII Scrubbing and §9 Log conformance check).

## Patterns to follow
- **Harvest-tier grading with a declare-only envelope** — obs-plan §4 (Restart-suppression scenario; Severity-lifecycle full pass) records the shipped shape for capability claims Conductor cannot grade from its own read-back: the standard eleven-field envelope with `verdict` null and `state` "KnownResidual", with the capability evidence graded over Pulse's own tracing lines at the harvest tier. This is the plan-side precedent for the scope's option (a).
- **Shape witness on the `message` field** — obs-plan §6 Boundary-call wrappers requires the observed key set / key names (names only, never values) to be logged because the extraction readers degrade to empty on an unrecognized shape, making a field-name divergence indistinguishable from an empty corpus. This applies directly to the scope's `value`-vs-`duration_ms` divergence on P-037. The witness rides `message` precisely because a dedicated attribute outside the allowlist would emit nothing.
- **Redaction-blindness check before trusting a Pulse field** — obs-plan §4 (Restart-suppression, Severity-lifecycle) records that Pulse's tick counters read `"<redacted>"` on the wire under Pulse's default-deny allowlist, so an evidence field must be one that is actually unredacted live. Whether the four observables' allowlist leaves (`duration_ms`, `severity_tier`, `discovered_count`, `value`, `section_count`, `degraded_mode`) survive Pulse's allowlist on a real leg is research's question.
- **Span-lifecycle line variant** — obs-plan §3 (two record shapes) requires the self-obs layer to materialize a §4 span as real lines (`span`, `span_event` `new`|`close`, optional `parent`, allowlisted attributes on `new` only). Attributes not computable at span open cannot be recorded as attributes.
- **Additive `RUST_LOG` form** — obs-plan §6 Per-module log levels requires `info,{crate}=debug`; a bare per-target directive replaces the default rather than adding to it, and neither form may be set for a run that also executes the test suite.

## Anti-patterns to avoid
- Never define a soft SLO budget with no enforcement — formal SLO assertion must be evaluated at report-generation time (per obs-plan §11 SLO). Recording the four measured values without grading them against their budgets is the banned shape.
- Never add an OTel metrics backend / meter provider (or any self-obs OTel SDK) to consume or express these `metric.*` values (per obs-plan §11 Metrics and §11 Telemetry Strategy).
- Never emit a high-cardinality or off-set span name, and never drop `run_id` from a log line — it is the sole correlation key (per obs-plan §11 Spans / Traces and §11 Logs).

## Contract bindings
- **obs ↔ tests (D-tests-obs-harness, two-sided):** test-plan §3 owns the journal format including the `CheckRecord` fields (`latency_ms` / `deadline_ms` / `budget_ms`); obs-plan §3 reproduces it. Any change to the check-record shape or to what `budget_ms` grades must land on both sides.
- **obs ↔ security / arch:** the scope's option (b) — a programmatic reader of Pulse's tracing stream — would be a new ingestion surface (trust-boundary / scope-law question owned there); obs's binding is that anything re-emitted from it must pass `conductor-core::redact` at the processor stage, not only at the sink (per obs-plan §11 PII Scrubbing).
- **obs ↔ CI:** the log conformance gate reads `logs/agent-latest.jsonl` against the §3 self-obs base-line schema (not the §6 envelope), and the zero-unlogged-panics gate greps the same artifact (per obs-plan §9).

## Acceptance criteria contributions
- (obs) Each of the four budgets produces a graded outcome asserted at report-generation time — not a recorded-but-ungraded number — with its measured basis present in an agent-readable artifact (JSONL journal / run report), no human-only surface (per obs-plan §11 SLO + §2 Agent-readable invariants).
- (obs) Per-check grading uses the `CheckRecord` grain (`latency_ms` / `deadline_ms` / `budget_ms`) and adds no field to the eleven-field run-report envelope; a declare-only scenario emits no check line (per obs-plan §3 Log format JSON schema — two record shapes).
- (obs) Every value harvested from Pulse that enters a Conductor log line rides an allowlisted field name (the `message` field where no dedicated allowlist entry exists) and carries no absolute host path or internal struct name (per obs-plan §11 PII Scrubbing + §9 Log conformance check).
- (obs) Any span added by the measurement path carries a `{module}.{operation}` name inside the bounded span-name set, with attributes drawn from `ALLOWLISTED_FIELDS` and recorded at span open (per obs-plan §11 Spans / Traces + §4 Span naming convention).
