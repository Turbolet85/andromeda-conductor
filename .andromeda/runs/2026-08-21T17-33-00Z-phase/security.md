- Any new or changed key in `scenarios/{halo-hue-encoding,service-constellation-discovery,report-render-surface,findings-counter-refresh}.toml` (notably `[[expected]].budget_ms`) must be validated at load — garde `range` + `dive` on the owning struct, with any rule that reads a SIBLING field shipped as a load-path `Scenario::check_*()` invoked from `from_toml_str` raising `CoreError::Config`, never as `#[garde(custom)]` (per security-plan §Input Validation, scenario-config row + §Security Anti-Patterns → Input). Whether the four TOMLs' current keys already reach that validation path is research's question.
- If P3 selects the open premise's option (b) — a Conductor-side reader for Pulse's tracing stream — that is a NEW external-input boundary and §Input Validation requires it be enumerated with bounded decoding (a soft per-line/size bound, no unbounded read, recursion-limited parse), faults routed as typed values through the verdict/error wall and never a panic (per §Input Validation, MCP read-back child-stdout row + §Security Anti-Patterns → Universal). It must not become an inbound listener of Conductor's own (per §Security Anti-Patterns → Universal, trust-boundary/scope-law ban).
- Any path handle introduced to reach Pulse's log stream or data dir must take one of the two sanctioned shapes: an operator-facing `CONDUCTOR_*` handle canonicalized + bounds-checked at the `conductor-cli` edge, or a committed artifact at a fixed `default_path()` resolved through `resolve_under` with deliberately no `CONDUCTOR_*` override and `e.kind()`-only read faults (per §Input Validation, env-var path handles + committed SUT-facing manifests rows; §Security Anti-Patterns → Input).
- Additions to the run-report envelope and per-check `CheckRecord` that record the measured basis must carry verdict/state/identity/measurement fields only — no absolute host paths (canonicalized `CONDUCTOR_*` dirs, `ANDROMEDA_PULSE_DATA_DIR`) and no internal seam-crate struct/field names, since these artifacts are agent-parseable ground truth shared across hosts (per §Error Handling, run-report artifact sanitization; §Security Anti-Patterns → Logging).
- Wall-clock and duration values written into the journal/report must come from `std::time::SystemTime`/`Instant`, never tokio's virtual clock — load-bearing here because the deliverable IS a measured duration graded against a budget (per §Security Anti-Patterns → Logging, clock-source ban).
- A budget the run cannot honestly measure must surface as its own distinct state with its own named precondition string (or the declare-only/`KnownResidual` harvest shape), never a false pass, never a generic string, and never a claimed measurement Conductor cannot make (per §Security Anti-Patterns → Universal, never-silently-downgrade + `declared-not-observable`; §Error Handling, verdict/error wall).
- The PREREQ audit re-check: the remedy for the advisory-DATABASE fault stays the bounded wait with the audit↔deny overlap VERIFIED green — never a floor raise, never a `deny.toml` ignore, never a CI edit; and if any dependency lands in this chunk, "no dependency delta" stops being an available basis and `cargo deny check advisories bans licenses sources` must be verified green over the NEW `Cargo.lock` (per §Dependency Security, two-fault split + 2026-08-16 admission condition).

## Patterns to follow
- The co-equal load-path arm: garde for field-local rules, `Scenario::check_*()` (`check_capabilities`, `check_budgets`) called from `from_toml_str` for sibling-spanning rules, with a test pinning that the load path actually invokes it (per §Input Validation, How cell; §Bootstrap phases, input-validation-library-install).
- The verdict/error wall: `Result::Err` reserved for harness faults (config parse, transport down, MCP unreachable); verification outcomes returned as typed `Ok` values (`Verdict`, `ReportState`), with `tonic::Status` codes and JSON-RPC/MCP errors as first-class typed inputs (per §Error Handling).
- The `blocked`-with-named-precondition pattern, and the `declared-not-observable` recording for a term whose truth lives on the SUT's side — directly applicable to the three webview-sourced observables Conductor cannot drive (per §Security Anti-Patterns → Universal).
- The committed SUT-facing manifest boundary shape (explicit `validate()` in `conductor-core`, fixed path via `resolve_under`, absent/malformed a hard harness fault never defaulted and never silently widened) as the template if any new committed artifact carries the four budgets (per §Input Validation, committed manifests row).

## Anti-patterns to avoid
- NEVER mark a nested spec field `#[garde(skip)]`, and NEVER express a sibling-reading invariant as `#[garde(custom)]` — in garde 0.22.1 it receives `(&field, &())` and would look enforced while never testing the invariant (per §Security Anti-Patterns → Input).
- NEVER silently downgrade an unmeasurable or failed precondition into pass/fail/manual-check, and never assert a measurement Conductor cannot make (per §Security Anti-Patterns → Universal).
- NEVER let the report, `runs.db` rows, JSONL journal, or CLI stderr leak absolute host paths, stack traces, or internal struct/field names (per §Security Anti-Patterns → Logging; §Error Handling).

## Contract bindings
- Run-report/`CheckRecord` sanitization binds to obs (journal/report field schema for the recorded measurement basis) and to tests (golden report fixtures must not embed absolute host paths or struct names).
- The dependency-audit prereq binds to tests §CI Integration — one workflow, the security gate as a job; the bounded-wait deferral must be recorded rather than resolved by a CI edit (per §Dependency Security, CI integration).
- If option (b) lands, the capability/scope-law decision itself is arch's call; security binds only the boundary discipline (enumeration in §Input Validation, bounded decoding, no inbound listener).
