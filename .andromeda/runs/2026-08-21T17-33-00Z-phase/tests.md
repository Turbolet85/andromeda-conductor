## Relevance
Relevant — the chunk's core open question (which grading tier the four budgets can honestly reach) is a test-strategy decision this plan already governs via its declare-only/harvest-tier precedent.

## Constraints
- Test tier is **Minimal (0)**, augmented only by the §1 coverage triggers — no Comprehensive escalation (per test-plan §1 Scope Summary). §10 states **Performance budgets: N/A** (no perf-budget trigger; the bounded fault-injection path is a *chaos correctness* check, not a budget), so a "timing budget" here must be graded as a scenario/harvest predicate, never introduced as a new perf-gate tier.
- The assertion-policy split is binding: `Blocked` / `ManualCheck` / `KnownResidual` / `CalibrationRegion` are **reported envelope states, not process-failure exits**; only a hard `Fail` exits non-zero (per test-plan §3 `run` exit-code semantics, restated as a ban in §11 E2E). A model-interpretive or unmeasurable budget outcome grades `CalibrationRegion` — report-for-human, never hard-failed.
- Where a claim reaches no MCP read-back surface, §6 requires the **declare-only + harvest-tier** shape: the scenario row lands `verdict` null / `state="KnownResidual"` (non-Blocked) with `latency_ms` against its declared `slo_tier`, the retired read-back checks' measurement is recorded in the scenario TOML header, and the live claim is graded **hard** at the harvest tier as a `conductor-run` unit-tier test over verbatim live-leg captures (per test-plan §6 Scenarios: fingerprint-storm / error-baseline-spike / restart-suppression / pii-scrub / connection-lifecycle / severity-lifecycle). The chunk's structural finding (none of the four observables reaches MCP read-back) is exactly the precondition that precedent covers.
- Pulse's reaction may not be manufactured in CI: §9 requires the live-Pulse leg stay an **operator/local `workflow_dispatch` gate, never a CI gate**, and §11 Test Strategy bans faking Pulse's reaction as a CI verdict (the rmcp stub canary proves wiring only). Any graded outcome for these four budgets must come from a live leg while CI keeps stub-only `--unit`/`--integration`/`--e2e` stages (per test-plan §3 CI stage selectors, §9 pipeline table).
- The per-run journal's two report-seam shapes are §3-owned: the **envelope line (eleven fields, byte-unchanged)** and the **per-check `CheckRecord` line** (`run_id`·`scenario`·`check_index`·`kind`·`verdict`·`state`·`latency_ms`·`deadline_ms`·`budget_ms`), with `budget_ms` null when the check inherits its tier and **a blocked or declare-only scenario emitting none** (per test-plan §3 Log format / Status endpoint shape). §3 also scopes `budget_ms` to that per-check grain, so carrying a *Pulse-internal* duration would be a spec change to §3, not a free implementation choice — which is precisely the chunk's `budget_ms`-category-error premise. Whether the code already wires a check kind these budgets could use is research's question.
- §1 flags `drive+observe` visual/UX confirmation as **untestable by agent** — the checklist rendering and induced-state context are agent-assertable, the human go/no-go is not — and §11 Universal bans manual smoke steps except that explicitly-flagged operator checklist. If the three webview-sourced observables require a human-driven Pulse window, §1 requires that shape be declared as the operator-checklist mode, not dressed as an `auto` assertion.
- Determinism is a hard gate: zero-flakiness budget, no nextest `retries`, root-cause fixes only, and a **runner-dependent result counts as a determinism break** (per test-plan §10); §11 E2E bans `sleep(N)` for synchronization (wait on an explicit signal: envelope `state`, a journal line, an exit code) and §11 Test Data bans stamping the journal/report from tokio's virtual clock — `std::time::SystemTime`/`Instant` only, since the journal is the left side of every SLO check.

## Patterns to follow
- **Harvest-tier test file** — a test-only harvest of Pulse's own tracing lines, asserted at the `conductor-run` unit tier as `crates/conductor-run/tests/<family>_harvest.rs`, pinning verbatim leg-captured lines as fixtures (per test-plan §6; the storm → baseline → restart → pii → connection → severity precedent chain).
- **Recorded-not-asserted witnesses + a pinned negative test** — witnesses that provably cannot carry evidence (redacted counters, unreachable digest kinds) are *recorded*, and a plausible mis-pairing is pinned as a negative test rather than left implicit (per test-plan §6 Severity-lifecycle).
- **Two-site restatement** — a scenario's verification signal lives in both §6 E2E and §1 Critical paths; a re-base must land at both sites in one pass (per test-plan §1 critical-paths closing note; the two-site rule established across the 2026-08-18/19 re-bases).
- **Harness invocation + seed precedence** — `SCENARIO=<name> scripts/agent-run.{sh,ps1} run`, with `--seed` appended ONLY when `SEED` is explicitly set (the TOML-declared seed governs otherwise; identical `.sh`/`.ps1` semantics), and `boot` timeouts derived from `contracts/pulse-run-contract.toml`, never literals (per test-plan §3 `run` / `boot`).
- **Fixture + isolation discipline** — committed declarative scenario TOMLs one-per-P-ID under `scenarios/` as the fixtures; `assert_fs::TempDir` + `CONDUCTOR_RUNS_DIR` per cross-process test; in-memory `runs.db` per unit test; goldens committed and run fail-don't-write (never `cargo insta review`) (per test-plan §7).

## Anti-patterns to avoid
- NEVER fake Pulse's reaction as a CI verdict — the stub canary proves MCP wiring only; Pulse's actual behavior is a live/local-gate assertion (per test-plan §11 Test Strategy, stack-specific).
- NEVER treat a `Blocked`/`ManualCheck`/`KnownResidual`/`CalibrationRegion` state as a non-zero process exit (per test-plan §11 E2E, stack-specific).
- NEVER synchronize with `sleep(N)` on a timing leg, and NEVER assert a real wall-clock duration in a `conductor-timeline` unit test (advance the paused virtual clock and assert shape/ordering) — while journal/report stamps must still come from `std::time`, never the virtual clock (per test-plan §11 E2E · §11 Unit · §11 Test Data).

## Contract bindings
- **tests §3 ↔ obs-plan §3 (log format).** test-plan §3 is the SOURCE OF TRUTH for the JSONL journal/envelope/`CheckRecord` shape and obs derives from it; any field or grain change this chunk needs must move both in lockstep or it is one-sided (precedent: the 2026-08-21 per-check-latency amendments; the redaction/field-allowlist half is obs-owned and asserted here by a negative test).
- **tests harvest tier ↔ Pulse's self-obs stream (foreign artifact) ↔ arch/security trust boundary.** The harvest tier reads Pulse's own tracing lines from a live leg. The chunk's alternative premise — Conductor gaining a *programmatic reader* for that stream — is a new ingestion surface, so it is an arch/security scope-law question, not a test-strategy choice this plan can settle alone.
- **tests §6 coverage gate ↔ the SUT capability manifest + `UNBACKED_AUTO` pin.** §6 requires exact-set equality in both directions over `UNBACKED_AUTO` (only `Auto` participates), so a coverage-mode change for any of P-025/P-027/P-037/P-045 must move the pin in the same change or the gate fails on pin rot.
- **tests §9/§10 supply-chain gate ↔ security-plan §Dependency Security.** §10 lists `cargo audit --deny warnings` + `cargo deny check` green and an un-drifted `Cargo.lock` as binding build-failure conditions; the chunk's PREREQ probe is the disposition path for that gate (security-owned rationale, tests-owned gate).

## Acceptance criteria contributions
- (tests) `cargo nextest run -p conductor-run` passes for any new/changed harvest-tier test, AND the same suite is green under `cargo test -p conductor-run` — the standing runner-portability gate (per test-plan §4 Framework).
- (tests) All four scenarios exit 0 with their rows carrying a reported (non-`Fail`) state and `latency_ms` recorded against each declared `slo_tier`; a `KnownResidual`/`CalibrationRegion` outcome must not produce a non-zero exit (per test-plan §3 `run` exit-code semantics).
- (tests) `cargo llvm-cov nextest --lcov --fail-under-lines 60` passes and no nextest `retries` are introduced; any flake is root-caused, not retried (per test-plan §10).
- (tests) If any of the four P-IDs' coverage mode changes, the coverage-matrix completeness gate and `check_scenario_backing` exact-set equality both stay green in both directions (per test-plan §6 Scenario: Coverage-matrix completeness gate).
