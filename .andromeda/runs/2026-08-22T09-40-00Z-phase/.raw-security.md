# security extract

## Relevance
partial — the chunk is lifecycle/UX proof, but crosses three security surfaces: the folded `cargo audit` PREREQ (dependency gate), a possible NEW scenario-config input boundary if checklist `induced`/`observation` becomes data, and the CLI-stderr / `#[tauri::command]` output boundaries the hold path renders to.

## Constraints
- The folded PREREQ is governed by the two-fault split: an advisory-**DATABASE** fault (RustSec DB unparseable) is remedied by a **bounded wait** with the audit↔deny overlap **verified** green — never a floor raise, never a `deny.toml` ignore, never a CI edit, never a silent accept (per security-plan §Dependency Security, advisory-DATABASE fault bullet). The scope's PROBE-AUTO-SATISFY signature is the plan's "verified, not assumed" discipline in operational form.
- Scope says "no new external crates expected"; if a dependency delta nonetheless lands, it MAY only land on a `cargo deny check advisories bans licenses sources` **verified green over the NEW `Cargo.lock`**, and the deferral basis must be re-stated because "no dependency delta" stops being available as a reason (per security-plan §Dependency Security, admitting-a-NEW-dependency clause). `Cargo.lock` must stay committed and un-drifted (per §Security Anti-Patterns → Universal).
- If part (3) makes a scenario's induced state + expected observation into **data** (scenario TOML or a committed artifact), that is a new external-input boundary and §Input Validation is an exhaustive enumeration: it requires garde `#[derive(Validate)]` co-located with the serde struct in its owning seam crate, `dive` (never `skip`) on every nested spec field, and any SIBLING-reading rule shipped as a load-path `Scenario::check_*()` from `from_toml_str` raising `CoreError::Config` — never `#[garde(custom)]`, which sees no sibling (per security-plan §Input Validation, scenario-config row + §Anti-Patterns → Input). If instead the data lands as a committed fixed-path artifact, the committed-manifest row's rules apply (explicit `validate()`, `default_path()` through `resolve_under`, deliberately no `CONDUCTOR_*` override, `e.kind()`-only read faults, absent/malformed = hard fault never defaulted).
- The hold prompt rendered to `conductor-cli` stderr, the recorded resolution, and any checklist wording that reaches `&lt;run_id&gt;.md` / `runs.db` rows must carry verdict/state/identity fields only — no absolute host paths, no internal seam-crate struct/field names, no stack traces (per security-plan §Error Handling, run-report artifact sanitization + §Anti-Patterns → Logging). The plan states this as a requirement on the artifact surface; whether the existing `prompt_is_redacted_in_the_resolution` behaviour already satisfies it for a real (non-placeholder) checklist item is research's question.
- Any `#[tauri::command]` touched or added on the hold path (`resolve_operator_hold`) requires a deny-by-default capabilities file allowing ONLY the actual commands (start/stop, picker, run-report, operator-pause) plus the one live-counter `Channel`; a permissive default exposes unintended IPC (per security-plan §Anti-Patterns → Code Patterns). Whether such a capabilities file already enumerates exactly these commands is research's question.
- The attended interactive prompt must not become reachable from the headless `scripts/agent-run.sh` source-of-truth path — the plan bans introducing an interactive prompt there because it would silently break the release gate (per security-plan §Anti-Patterns → Authentication, agent-run bullet). Scope records `agent_mode` forcing Headless; whether every NEW surface this chunk adds (checklist rendering, corrected tracing wording) preserves that gate is research's question.
- The live legs run against a real Pulse, so the never-downgrade rule stands: each of the gate's FIVE named preconditions must surface as its own distinct `blocked` precondition string, never a false pass and never the generic corpus-empty string; a hold resolution must not mask or overwrite one (per security-plan §Anti-Patterns → Universal). `ANDROMEDA_PULSE_L4_DETERMINISTIC=true` in the runbook is a declaration-only read with nothing to validate — the value must never become a path, an argv element, or a log value (per security-plan §Input Validation, L4 row).

## Patterns to follow
- garde `range` + `#[garde(custom)]` co-located with the serde struct in its owning seam crate, failed `Report` → `ConfigError` via `#[from]` (harness fault, not a verdict) — the shipped shape for every scenario-config boundary (per security-plan §Input Validation).
- The load-path `check_*()` arm as a second, co-equal mechanism for sibling-spanning rules, with a test pinning that `from_toml_str` actually invokes it (per security-plan §Bootstrap phases, input-validation-library-install) — the `check_budgets` precedent, which sits on the very `[[expected]]` block whose absence routes a scenario to the checklist HoldPoint.
- `thiserror` typed enums stay inside the seam crates and collapse to type-erased `anyhow` only at the `conductor-cli` / `#[tauri::command]` edges; the verdict/error wall keeps outcomes as typed `Ok(...)` values and `Result::Err` strictly for harness faults (per security-plan §Error Handling).
- Journal/report wall-clock stamps come from `std::time::SystemTime`/`Instant`, never tokio's virtual clock — relevant because the hold freezes and resumes under a paused clock in the existing tests (per security-plan §Anti-Patterns → Logging).
- The `deny.toml` justified-exception mechanism with a per-entry comment, if any license/advisory surfaces — `deny.toml` itself is the authority on the full set (per security-plan §Dependency Security, Accepted exceptions).

## Anti-patterns to avoid
- NEVER mark a nested spec field `#[garde(skip)]`, and NEVER write a sibling-reading invariant as `#[garde(custom)]` — both look enforced while the boundary is silently bypassed (per security-plan §Anti-Patterns → Input).
- NEVER ship Tauri commands without a minimal deny-by-default capabilities file; NEVER use the `shell-open` plugin with config-derived strings or embed remote-origin iframes in the bundled webview (per security-plan §Anti-Patterns → Code Patterns).
- NEVER remedy the red audit with a floor raise, a `deny.toml` ignore, or a CI edit — the DB fault admits none of them (per security-plan §Dependency Security).

## Contract bindings
- **Dependency gate ↔ tests §CI Integration:** the security gate is a job in the one workflow; the PREREQ's remedy explicitly forbids a CI edit, so this chunk's probe is a local operator-run verification, not a workflow change (per security-plan §Dependency Security + §Bootstrap phases, dep-security-ci-gate).
- **Artifact sanitization ↔ obs (report/journal fields) + tests (fixtures):** any checklist `induced`/`observation` string that lands in `&lt;run_id&gt;.md` / `runs.db` / the JSONL journal is bound by the artifact-hygiene rule; fixtures carry only self-generated synthetic content (per security-plan §Error Handling + §Data Protection).
- **Tauri IPC capabilities ↔ arch (capability decisions) + design (hold prompt surface):** the capabilities file enumerates the commands the design surfaces; the security mandate is deny-by-default coverage, the surface choice is arch/design's (per security-plan §Anti-Patterns → Code Patterns).
- **Frontend delta ↔ npm gate:** if `OperatorChecklist.tsx` / `Gallery.tsx` wiring changes the `crates/conductor-tauri/ui/` tree, `npm audit --omit=dev` clean (0 production vulns) with `package-lock.json` committed is the gate (per security-plan §Dependency Security, Frontend (npm) supply chain).
