# a11y extract

## Relevance
Partial — the chunk's live vehicles (CLI `suite` spinner + `inquire::Confirm`) sit on the plan's **not-assertable** surface, but two of the four must-be-accessible paths (operator-pause go/no-go, operator-checklist) and the ManualCheck/Residual lamp crosswalk are squarely a11y-owned if any part of the wiring lands on the desktop-webview.

## Constraints
- The cli surface is **not-assertable** — no DOM/widget tree, no axe/Lighthouse reach, excluded from the strategy + critical-path sections; a live hold answered through `PromptResolver`/`inquire` on stderr yields **no WCAG conformance evidence** and its ASCII/`NO_COLOR` text-pairing is output-stream discipline, not an a11y verification path (per a11y-plan §1 A11y Scope Summary, §11 Anti-Patterns → Universal).
- Operator-pause go/no-go is a must-be-accessible path: on the webview it requires `alertdialog` + `aria-modal`, focus trap entry over the dimmed/inert console, Tab/Shift+Tab cycle across Proceed/Abort, Escape-escapable (SC 2.1.2), focus restoration to the triggering control, and `aria-live="assertive"` on the HOLD phase-line flip (per a11y-plan §1 Critical paths, §4 ARIA Patterns & Roles, §5 Keyboard Navigation). Whether `conductor-tauri/src/pause.rs` / the webview HOLD surface already satisfies these is research's question.
- Operator-checklist is a must-be-accessible path whose required shape **names acceptance part (3) verbatim**: `checkbox` per item inside a group/region container, `aria-checked` per row, Space toggles a focused row, and **"each item exposes induced-state + expected-observation text"**, plus an unticked-count roll-up announced so an incomplete pass is not mistaken for a finished run (per a11y-plan §1 Critical paths, §4 per-component catalog). Whether `ui/src/components/OperatorChecklist.tsx` already meets this (vs. only rendering hardcoded Gallery placeholders) is research's question.
- The hold-point state must not rest on motion: the plan requires the paused-count freeze **plus** the phase-line text swap ("HOLD — operator pause") **plus** `aria-live="assertive"` to carry the state independently of the count-tint transition, and requires the frozen count value to be announced as frozen (neither blanked nor still running) (per a11y-plan §11 Anti-Patterns → Motion, §3 Screen reader test pattern).
- Lamp identity is **verdict-first**: `verdict == CalibrationRegion` ⇒ HOLD lamp regardless of `state`; a `ManualCheck` state with no verdict ⇒ `Manual` lamp; a `KnownResidual` state with no verdict ⇒ `Residual` lamp (per a11y-plan §6 State color tokens → State-naming crosswalk). This is the binding contract behind `conductor-core/src/lamp.rs:44` and behind the deterministic-L4 `verdict: null` / `KnownResidual` row shape the legs expect.
- Every lamp state must carry its text label **and** glyph supplement, never color alone — `Manual`+checkbox-glyph, `HOLD`+amber-filled-lamp+phase-line-swap, `Residual`+dashed-ring (per a11y-plan §6 State color tokens, §11 Anti-Patterns → Visual).
- Any a11y evidence produced must be machine-verifiable JSON folded into the obs §6 envelope (violations ride `fingerprints[]`; no new top-level fields) and must not leak absolute host paths or internal seam-crate struct names (per a11y-plan §3 Structured violation JSON schema, §11 Anti-Patterns → SLO).

## Patterns to follow
- Reuse the tests §6 `@crabnebula/tauri-driver` + WebdriverIO session for any webview a11y assertion (axe via `@axe-core/webdriverio`, keyboard via `browser.keys()`, focus via `document.activeElement`) — one webview-automation stack, no parallel puppeteer/CDP attach (per a11y-plan §3 Focus/Keyboard test harness, §3 A11y testing tool pick).
- Semantic HTML first, ARIA second — native `<button>` for Proceed/Abort, native checkbox for checklist rows, shadcn AlertDialog over Radix for the hold dialog (which supplies the trap + Escape + restoration with no extra focus library) (per a11y-plan §4 Naming convention, §3 Bootstrap phases → focus-management-library-install / aria-component-library-install).
- A11y checks land as an **operator/local gate, not a CI gate**, riding the tests' 5-command harness and surfacing through the `logs` command — the same operator-driven shape this chunk's live legs already use (per a11y-plan §3 CI integration, §9 CI Integration).
- Real-prose status text, never decorative skeletons, and in-progress never downgraded to Fail — the must-announce set includes the HOLD phase-line flip, the frozen count value, and the checklist unticked-count roll-up (per a11y-plan §3 Screen reader test pattern, §11 Anti-Patterns → Visual).

## Anti-patterns to avoid
- Never treat the cli surface as accessibility-assertable, and never let a manual attended keyboard/terminal pass stand as sole verification of any WCAG criterion (per a11y-plan §11 Anti-Patterns → Universal).
- Never make the hold-point legible only through the count tint, and never let the count tint / dialog fade / status-light transition survive `prefers-reduced-motion: reduce` (per a11y-plan §11 Anti-Patterns → Motion, §6 Motion tokens).
- Never introduce a keyboard trap or drop focus styles on the hold dialog — Escape must exit and the `--color-focus` ring must be visible on the active control (per a11y-plan §11 Anti-Patterns → Keyboard).

## Contract bindings
- **a11y ↔ obs (§6 log-format envelope):** the lamp display-label ↔ obs `verdict`/`state` crosswalk is the join contract for this chunk's `ManualCheck` / `KnownResidual` / `verdict: null` rows; a11y violation artifacts reproduce the obs §6 envelope verbatim and fold rule-id + WCAG-SC tag + selector into `fingerprints[]` (a11y-plan §3, §6).
- **a11y ↔ tests (§6 webview driver + 5-command harness):** any webview a11y assertion for the checklist/hold surface rides tests' `wdio run` tauri-driver session and emits through the `logs` command (a11y-plan §3 CI integration, §9).
- **a11y ↔ design (tokens):** `--count-hold`/`--color-base` and `--status-manual` / `--status-residual` lamp pairs at SC 1.4.11 3:1, `--motion-micro`/`--ease-quiet` for the reduced-motion drop of the hold count tint and dialog fade (a11y-plan §6 Color contrast pairs, §6 Motion tokens).

## Acceptance criteria contributions
- (a11y) If a scenario's induced state + expected observation reaches the webview checklist surface, each item renders as a native `checkbox` inside a group/region container with `aria-checked`, Space-toggle on a focused row, its induced-state + expected-observation text exposed as accessible content, and an announced unticked-count roll-up — whether the current `OperatorChecklist.tsx` already does this is research's question (per a11y-plan §1 Critical paths → Operator-checklist, §4 ARIA Patterns & Roles).
- (a11y) The HOLD state is carried by three independent signals — frozen count value (announced as frozen, not blanked and not still running), phase-line text swap, and `aria-live="assertive"` — with the count tint as decoration only (per a11y-plan §11 Anti-Patterns → Motion, §3 Screen reader test pattern).
- (a11y) Lamp selection for the legs' rows follows verdict-first: `ManualCheck` + no verdict ⇒ `Manual`; `KnownResidual` + no verdict ⇒ `Residual`; either state carrying `verdict == CalibrationRegion` ⇒ HOLD lamp; each rendered with its text label + glyph supplement (per a11y-plan §6 State color tokens → State-naming crosswalk).
- (a11y) No WCAG conformance is claimed from the attended CLI leg — the cli surface is not-assertable and any a11y claim requires machine-verifiable JSON from the webview harness aligned to the obs §6 envelope (per a11y-plan §1 A11y Scope Summary, §11 Anti-Patterns → Strategy/Universal).
