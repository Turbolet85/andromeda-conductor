# arch extract

## Relevance
Relevant — arch governs crate placement of any new checklist-item data, the closed report-state/envelope contracts the ManualCheck row rides, and the headless-core-vs-thin-shell rule that decides part (3)'s rendering surface.

## Constraints
- **Crate-per-seam placement is compiler-enforced, and the shells are thin.** arch §Established Decisions [Module Boundaries] + [Workspace / Core Structure] require engine logic in the runtime-agnostic core that both `agent-run` and the Tauri commands call identically; §Occupied Resources (Crate names) fixes `conductor-run` as the composition root above the seams and below both bins. So a checklist-item data model is core-shaped by mandate, with the CLI/webview as rendering surfaces only — a design where the item wording lives in a shell (webview state, bin-local constant) inverts §Design Philosophy "Headless-drivable core, thin shells", where the CLI/headless path is the release gate and the GUI is convenience.
- **New scenario-declared data must be declarative TOML, serde-deserialized and garde-bounds-checked at load, with nested specs `dive`d and never `skip`ped; an unknown closed-enum kind is a parse error, never an inferred default** (arch §Conventions — Config conventions). If a scenario's induced state + expected observation becomes scenario data, this is the mandated route, and validation co-locates with the serde structs in the owning seam crate.
- **A sibling-spanning invariant cannot be a garde validator under 0.22.1** — it ships as a load-path `Scenario::check_*()` invoked from `from_toml_str`, and the load-error mapping is three-way (`CoreError::Config` on parse or non-garde check failure; `CoreError::Validation` only on a garde `Report`) — arch §Established Decisions [Validation Library] + [Scenario Config Format]. Relevant if a checklist item must be cross-checked against a sibling field (e.g. against `expected` emptiness or `p_ids`).
- **The verdict/error wall applies in every seam crate** (arch §Cross-cutting Patterns — Verdict/error wall; §Conventions — Error handling): an operator NoGo/Abort is an outcome VALUE, never a `Result::Err`, which stays reserved for harness faults. `ReportState` is a closed five-variant set and `ManualCheck` is the terminal awaits-a-human state whose FIRST route is exactly the operator-checklist claim with no programmatic read-back (arch §Established Decisions [Read-Back Dependency Posture]).
- **The lamp is chosen verdict-first, and the `Verdict → ReportState` default mapping is fixed** (arch §Established Decisions [Probabilistic-Assertion Policy]); `verdict` and `state` stay independent. Whether the shipped `lamp.rs` mapping already satisfies verdict-first for a `(ManualCheck, None)` checklist row is research's question.
- **The run-report envelope is byte-unchanged and a declare-only scenario emits ZERO `CheckRecord`/`run_check` rows** (arch §Standard Contracts — Run report envelope + Per-check record; §Occupied Resources — runs.db). Since every live vehicle here is declare-only, the per-check surface structurally cannot carry a checklist item — the carrier must be a report-seam surface arch already registers, or a new shared shape registered as one.
- **Internal core↔UI is `#[tauri::command]` request/response plus one `Channel` for live counters; no HTTP/REST/GraphQL surface exists or may be added** (arch §Conventions — Interface surfaces; §Occupied Resources — Interface routes). The operator-pause prompt is already an enumerated Tauri command surface; `Channel` is scoped to live counters/target status.

## Patterns to follow
- **The declared-data precedent for a new scenario-config surface**: the per-phase `[phases.fault]` table — optional field, `#[serde(default)]` absent, garde `dive`, closed kind enum, scenario-level invariant at load (arch §Conventions — Config conventions). A checklist-item declaration should follow this exact shape rather than inventing a new config idiom.
- **The already-registered terminal-rendering stack** — owo-colors + indicatif + comfy-table + inquire, with the role explicitly including "isatty-gated interactive operator-pause prompts (inquire confirm; headless never blocks)" (arch §Stack and Technologies). Parts (1) and (2) are mandated to ride this row; no new crate is expected.
- **`CONDUCTOR_AGENT_MODE` is READ-only** — `agent_mode = flag || env-set`, main never WRITES it, deliberately avoiding edition-2024 `unsafe std::env::set_var` (arch §Occupied Resources — Environment variables). Any attended-leg mechanism must respect the read-only direction; the flag/env pair is the existing handle, not a new one.
- **Dynamic proof is an operator/local gate, never a CI gate** (arch §Established Decisions [CI/CD]; §Infrastructure Patterns — CI/CD approach; §Cross-cutting Patterns — Development Style). An attended live leg is arch-consistent by construction and must not be wired into the GitHub Actions job.
- **Webview build-order coupling if the rendering surface stays the GUI**: `tauri-build`'s `generate_context!` resolves `ui/dist` at COMPILE time, so the webview bundle must be built before any workspace cargo compile of `conductor-tauri` (arch §Infrastructure Patterns — Build system). This is a real cost input to the "which surface" design question.

## Anti-patterns to avoid
- **No native OS toasts and no new network surface.** arch §Established Decisions [Real-time Strategy] states Conductor must NOT emit native OS toasts precisely because those are Pulse behavior it observes *via the operator checklist* — so the checklist may describe a toast, never raise one; §[Backend Framework] bars any HTTP/service surface for rendering items.
- **No widening of the closed `state` set and no silent downgrade** — `Blocked` is never downgraded to pass/fail/manual-check, and a new state for "attended hold" is banned (arch §Standard Contracts; §Established Decisions [Read-Back Dependency Posture]).
- **No new occupied resource smuggled in without registration** — a new workspace crate, `CONDUCTOR_*` env var, port, on-disk artifact, or `contracts/` manifest is a §Occupied Resources entry requiring a wrap amendment; a new external crate is a §Stack row.

## Contract bindings
- **§Standard Contracts (envelope + `CheckRecord`) ↔ tests + obs + report seam** — declare-only scenarios emit zero check records, so a checklist item's persistence path binds to whatever report-seam artifact the report/obs plans own; if it becomes a third shared shape, arch §Standard Contracts is its registry.
- **§Established Decisions [Probabilistic-Assertion Policy] verdict-first lamp ↔ design + a11y** — the verdict-first precedence was the resolution of the a11y six-lamp conflict, so any change to how a ManualCheck checklist row renders its lamp is a joint arch/design/a11y surface (color never alone).
- **§Occupied Resources Tauri command surface + CLI flags ↔ layout-templates** — the `[HOLD]` line and the inquire confirm are layouts' §cli wireframe content, and CLI verbs/flags are layouts' registry, not arch's; arch governs only the crate the code lives in and the IPC command-name namespace.
- **§Infrastructure Patterns Build system (`cargo deny` green / `cargo audit` separately red on an external advisory-DB fault) ↔ security-plan §Dependency Security** — the folded audit PREREQ's audit↔deny split is recorded on both sides; arch expects this chunk to admit zero packages and therefore produce no §Stack delta.

## Acceptance criteria contributions
- (arch) Any new checklist-item / hold data type lives in a workspace crate consistent with crate-per-seam boundaries — runtime-agnostic engine data in the core, composition wiring in `conductor-run`, presentation confined to the bins/webview — with no new workspace member (per arch §Established Decisions [Module Boundaries] + §Occupied Resources Crate names).
- (arch) The operator decision and the resulting checklist row are typed VALUES inside the closed five-variant `ReportState` set — a NoGo/Abort is never a `Result::Err` and no sixth state is introduced (per arch §Cross-cutting Patterns Verdict/error wall + §Standard Contracts).
- (arch) Zero new external crates and zero new occupied resources: parts (1)+(2) ride the already-registered indicatif/inquire row, `CONDUCTOR_AGENT_MODE` stays read-only, and no new `CONDUCTOR_*` handle, port, or artifact is added (per arch §Stack and Technologies + §Occupied Resources Environment variables).
- (arch) If induced/observation lands as scenario TOML, it is serde-declared + garde-validated at load with nested `dive` (never `skip`), an unknown kind a parse error, sibling-spanning rules routed to a load-path `check_*()`, and the new key registered in §Conventions Config conventions at wrap (per arch §Conventions Config conventions + §Established Decisions [Validation Library]).
