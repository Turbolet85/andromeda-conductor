# design extract

## Relevance
Relevant — this chunk fires the design system's **signature element** (the Paused-count hold-point) live, plus the `ManualCheck` operator-checklist treatment; both surfaces (cli primary, desktop-webview if part (3) wiring lands there) are governed.

## Constraints
- The frozen count is the signature and is defined by the **absence** of motion: at the operator-pause the count halts at its exact hold value and resumes on decision; the CLI mirror is the `indicatif` spinner that **STOPS in place — not hides, not animates to 100%** (per design-system.md §Brand Identity "Signature element" + §Motion "High-impact moments"). The scope's part (2) vehicle (`suite`'s `{spinner} {pos}/{len} scenarios` bar suspended around the prompt) is the surface this mandate binds to; **whether the shipped `bar.suspend(...)` behaviour reads as stop-in-place rather than a temporary hide is research's question.**
- The HOLD state must use the existing hold-amber token, no new color: `--count-hold` `#E3B341` → **ANSI 179** in cli, printed as a bold phase line **above** the prompt (per §Color Palette / Semantic Colors "Warning (`CalibrationRegion` / HOLD)" + §Surface: cli / Tokens + §Surface: cli / Component Patterns 1).
- Color alone is never the signal: every status carries its ASCII text from the closed set `[PASS]`/`[HOLD]`/`[FAIL]`/`[MANUAL]`/`[RESIDUAL]`/`[BLOCKED]` (glyphs `✓`/`✗`/`?`/`~`/`•`/`→`, never emoji in piped output), and colorization is gated on `NO_COLOR`/`TERM`/pipe status (per §Surface: cli / Tokens + §Anti-Patterns / Per-Surface Bans / cli).
- `ManualCheck` is deliberately **outside** the green/amber/red verdict triad — neutral lavender `--status-manual` `#A9B1D6` → ANSI 146, checkbox glyph (`☐`→`☑`) in webview, `?` + `[MANUAL]` in cli — because there is no machine verdict; it must never read as `Fail` (per §Color Palette "Verdict (3) vs ReportState (5)" note + §Iconography).
- A checklist item's rendered content is a contract, not free prose: per P-ID it must carry the **induced state** (what Conductor drove) *and* the **expected observation** as a yes/no the operator ticks; the roll-up must surface the unticked count so an incomplete manual pass is never mistaken for a finished run (per §Surface: desktop-webview / Component Patterns 7; cli counterpart §Surface: cli / Component Patterns 4).
- The interactive prompt must be `isatty`-gated on **both** streams and the headless agent-driven path must never block on it — the decision is recorded to the artifact instead (per §Surface: cli / Component Patterns 2 + §Platform-Specific Notes). The scope's `agent_mode`-overrides-TTY behaviour is the mechanism this rule rides on.
- A declare-only leg landing `verdict: null` / `KnownResidual` must render as the muted dashed `~ [RESIDUAL]` tier (ANSI 246 / `--status-residual`) carrying its "expected until {fix}" note — never red, and "no result yet" must never collapse into "failed" (per §Anti-Patterns / Rejected Defaults, "Conflating 'no result yet' with 'failed'").
- Expression level `0.3` caps everything here: in-place CSS/ANSI color transitions only, no animation library, **no pulse / blink / glow on any status**, no flashing red on `Fail` (per §Brand Identity "Expression level" + §Motion "Hard limits").

## Patterns to follow
- §Surface: cli / Component Patterns 1 — Paused-count hold-point CLI mirror: nominal-green (ANSI 114) phase-line prefix during the run, spinner appears only after ~200ms (honest progress), TTY-gated so agent-captured artifacts stay clean.
- §Surface: cli / Component Patterns 4 — Verdict / report-state lines; the sanctioned `ManualCheck` line shape already carries an observation question (`? P-0xx  Manual  <observation>? · <observation>?`, ANSI 146), which is the existing precedent for part (3) if the checklist surface lands in cli.
- §Surface: cli / Component Patterns 5 + §Anti-Patterns cli — the hold line renders to **stderr**, which has its own `IsTerminal` gate distinct from the stdout gate; stdout stays raw artifact data.
- §Surface: desktop-webview / Component Patterns 7 (Operator-checklist card: `--color-raised-1`, `1px --border-subtle`, `--radius-md`, `--status-manual` checkbox glyphs, Space toggles a row, footer unticked roll-up) reached from Component Patterns 6 (run-report `ManualCheck` rows expand into it) — the target shape if the webview is chosen as part (3)'s rendering surface.
- §Typography (Data row) + §Surface: cli / Tokens — P-IDs, run_id, SLO timings and latency stay in the reserved mono status tier (`--color-id-cyan` / ANSI 117), never a generic accent.

## Anti-patterns to avoid
- No progress bar that hides or animates-to-100% at the operator-pause — it must freeze in place; hiding/animating destroys the signature (per §Anti-Patterns / Rejected Defaults + Per-Surface Bans / cli).
- No new palette or ANSI entries for the hold/manual/residual surfaces — reuse the shipped token pairs by name; the amendment record shows the standing correction is "reuse the existing tier, don't add a color row" (per §Anti-Patterns / Universal Bans "color purely for decoration").
- No flashing/pulsing/toast-style alarm on any outcome, and Conductor must never emit a native OS toast (that is Pulse behaviour it *observes* — the checklist is where "no OS toast appeared?" is *checked*, never performed) (per §Anti-Patterns / Rejected Defaults + §Surface: desktop-webview / Platform-Specific Notes).

## Contract bindings
- **a11y §Contrast** — ANSI 179 (hold amber) / 146 (manual lavender) / 246 (residual) on dark terminals must clear the contrast bar; the plan already avoids dark-blue/dark-red-on-black for this reason (§Surface: cli / Platform-Specific Notes).
- **a11y §Use of Color (SC 1.4.1)** — the `[HOLD]` / `[MANUAL]` / `[RESIDUAL]` ASCII prefixes are the not-color-alone mechanism; webview lamps additionally require paired text + `aria-live` (§Iconography "Rule").
- **a11y §Animation (SC 2.3.3)** — if any webview count-tint / dialog fade is touched, all transitions drop under `@media (prefers-reduced-motion: reduce)`, including on a held count (§Motion "Hard limits").
- **testing / release-gate harness** — the design rule "never block the headless source-of-truth path on a prompt" is the same guardrail `scripts/agent-run.sh` (`CONDUCTOR_AGENT_MODE`) relies on; the attended live leg is therefore an operator-driven invocation *outside* the harness, and its artifacts must still be gradeable (§Surface: cli / Component Patterns 2).
- **architecture (run-report envelope)** — design's six lamp treatments are a 1:1 rendering of the `Verdict` (3) × `ReportState` (5) contract; any new checklist-item data type must map into that closed set rather than introducing a seventh state (§Color Palette "Verdict (3) vs ReportState (5)").

## Acceptance criteria contributions
- (design) At the live hold, the suite count **stops in place at its exact value** — not blanked, not hidden, not animated to 100% — and resumes from that value on the decision (per design-system.md §Motion "High-impact moments" + §Surface: cli / Component Patterns 1).
- (design) The HOLD phase line prints above the prompt in bold hold-amber (ANSI 179 / `--count-hold`) and its ASCII text survives `NO_COLOR` / piped stderr — no new color introduced (per design-system.md §Surface: cli / Tokens + §Anti-Patterns / Per-Surface Bans / cli).
- (design) Any rendered `ManualCheck` checklist item carries **both** the induced state and the expected observation, in the neutral `--status-manual` / ANSI 146 tier with the `?` / `[MANUAL]` prefix — never the green/amber/red verdict triad and never red (per design-system.md §Surface: desktop-webview / Component Patterns 7 + §Surface: cli / Component Patterns 4 + §Iconography).
- (design) A declare-only leg's `verdict: null` / `KnownResidual` row renders as the muted dashed `~ [RESIDUAL]` tier with its "expected until {fix}" note, never as a `Fail` (per design-system.md §Anti-Patterns / Rejected Defaults, "Conflating 'no result yet' with 'failed'").
