# obs extract

## Relevance
Partial — no new critical path or span family, but the attended live leg's self-obs stream, the `lib.rs:403` resolution log line, the `tauri.command.resolve_operator_hold` span, and any checklist-item data reaching a log/journal record all fall under obs-plan mandates.

## Constraints
- Agent mode is a **read-only** trigger (`flag || CONDUCTOR_AGENT_MODE` env-set) per obs-plan §3 (Logging stack — agent-mode flag). Because the attended leg must run with `agent_mode` false (the scope's `resolve_kind` gate), it runs OUTSIDE the `logs/agent-latest.jsonl` file sink that §3/§6 (Sink configuration) assign to agent mode — the graded artifact must come from the dev-mode sink. §3/§6 word that sink "stderr pretty-print in dev"; the 2026-06-24 amendment flags that wording as possibly-stale vs. shipped JSON-to-stderr. **Whether the attended (non-agent) leg actually emits parseable JSON lines is research's question**, and it decides whether this leg produces gradeable self-obs evidence at all.
- Any span attribute must be a name in `conductor-core::redact::ALLOWLISTED_FIELDS` or the processor stage drops it, per obs-plan §4 (Required-span-attributes constraint, Known-residual path). A new hold/resolver/decision attribute therefore requires either an allowlist admission or the `message`-field route; it cannot simply be added.
- Span attributes are recorded on the `new` record ALONE, per obs-plan §3 (Log format JSON schema — span-lifecycle line variant). Anything unknown at span open — including the operator's Proceed/Abort outcome — cannot be a span attribute of the hold span; §4's `fault.port_occupier` release-witness is the sanctioned shape for a late-known value.
- New span names must come from the bounded set in obs-plan §11 (Spans / Traces), whose only member covering this chunk is the `tauri.command.*` wildcard. No `pause.*` / `hold.*` name is sanctioned; minting one is a §11 amendment, not an implementation choice.
- Two record shapes are governed differently per obs-plan §3 (Log format JSON schema — two record shapes): a journal ENVELOPE extra is written by the report seam and bypasses the field allowlist, whereas a self-obs SPAN attribute is allowlist-governed. §3 also requires the eleven envelope fields stay unchanged and that a declare-only scenario emit no `CheckRecord` line — which is exactly the declare-only class the scope names as the live vehicles.
- Performance budget is `latency_ms = read_back_observed_at − journal_emitted_at` in wall-clock time, asserted against `slo_tier` at report-generation time per obs-plan §5 / §10 (Performance budgets), with tokio's virtual clock banned for journal stamps (§11 project-specific bans). An attended hold inserts unbounded human wait inside the run; **whether the `lib.rs:394` checklist hold sits inside the `journal_emitted_at → read_back_observed_at` window (and so inflates `latency_ms` past its tier) is research's question**.
- obs-plan §9 (Telemetry artifact handling) treats the supply-chain audit report as an inline-CI-log telemetry artifact consumed by agent parse of stderr — the folded `cargo audit` / `cargo deny` PREREQ's true exit code and first diagnostic line are that agent-readable evidence, which is why the scope's before-any-pipe capture matters.

## Patterns to follow
- **Witness on the allowlisted `message` field** — obs-plan §6 (Boundary-call wrappers) establishes this for the `verify.readback` key-set witness and the `emit.batch` wire-shape witness: when a needed signal has no allowlisted field name, carry names/values as ordered text on `message` rather than minting an attribute that would emit nothing. This is the ready-made route for a resolver-kind / decision witness on the hold path.
- **Tauri command instrumentation** — obs-plan §4 (Auto-instrumentation per surface, Both-surface parity) requires `#[tracing::instrument]` on the `#[tauri::command]` handler as parent of the core spans, with `run_id` as the correlation key (never a `traceparent`); the shipped handler name `resolve_operator_hold` is the one obs-plan §1 (desktop-webview row) names for the operator-pause action.
- **Declare-only envelope shape** — obs-plan §4 (Restart-suppression and Severity-lifecycle scenarios) requires the standard eleven-field envelope with `verdict` null under a degraded read-back and no per-scenario extra minted for a quantity graded elsewhere; obs-plan §6 (Log format) keeps `state` a closed enum whose members include `ManualCheck`.
- **Harvest-tier grading for evidence Conductor does not compute** — obs-plan §4 (Known-residual path, Delegated-timing family) is the precedent for grading a claim over artifacts Conductor observes rather than inventing an envelope field for it; relevant to how a live attended activation is evidenced.
- **Level placement** — obs-plan §6 (Log levels mapping) puts state transitions and boundary summaries at `info` and internal control flow at `debug`; the §6 note on fault-span lifecycle records why an `info`-invisible signal cannot serve as a chunk's own acceptance evidence without a `RUST_LOG` opt-in.

## Anti-patterns to avoid
- obs-plan §11 (Logs) bans unstructured stderr text — every emitted signal must be structured JSON-per-line or sanitized machine-parseable stderr. A resolution line whose label is interpolated prose fixed at "resolved headless" is not an agent-readable statement of the resolver actually used (obs-plan preamble agent-driven invariant, §2 Agent-readable invariants).
- obs-plan §11 (PII Scrubbing) bans skipping the field-allowlist / redaction layer and bans scrubbing only at sink stage — operator-authored prompt or checklist wording entering the log path is governed at the processor stage, and a non-allowlisted checklist field must not be worked around by writing straight to the sink.
- obs-plan §11 (Spans / Traces, Universal) bans high-cardinality span names outside the bounded set and bans any W3C trace context / OTel SDK for self-observation — a CLI hold and a GUI hold are correlated by `run_id`, never by trace continuity; and if part (3) lands in the webview, obs-plan §1 (desktop-webview row) restricts frontend telemetry to console JSON with no OTel JS SDK and no OTLP export.

## Contract bindings
- **obs ↔ tests harness** — obs-plan §3 reproduces a journal format OWNED by test-plan §3; if a checklist item's induced state / expected observation becomes journal data, the shape change must land on both sides (the two-sided D-tests-obs-harness bind; precedent: the 2026-08-21 `CheckRecord` amendment).
- **obs ↔ security** — obs-plan §11 (PII Scrubbing) binds to security's logging/monitoring rules via `conductor-core::redact` (host-file-path value scrub + field-name allowlist + `Display`-not-`Debug` at the anyhow edge); the hold prompt and any checklist wording are the new text entering that path.
- **obs ↔ design/CLI surface** — obs-plan §3/§6 (Sink configuration) put the dev-mode self-obs sink on stderr, the same stream the indicatif suite spinner and `inquire` prompt occupy. Whether the log stream and the frozen count contend on stderr under an attended leg is research's question.
- **obs ↔ a11y** — a11y emits violations into obs's structured log format; only engaged if part (3) lands a rendered webview checklist surface.

## Acceptance criteria contributions
- (obs) Every self-obs line on the attended live leg carries the base set `timestamp_ms` / `level` / `target` / `service.name` / `service.version` / `deployment.environment` / `run_id` (per obs-plan §3 Log format JSON schema — two record shapes, enforced by §9 Log conformance check).
- (obs) The live hold's resolution is recorded by a signal that stays TRUE under an attended resolver — resolver kind and Proceed/Abort outcome distinguishable in the emitted line, carried on an allowlisted field name or on `message` (per obs-plan §4 Required-span-attributes allowlist constraint + §6 Boundary-call wrappers).
- (obs) Zero unlogged panics across the leg: no `^thread.*panicked` text in stderr or the journal, only formatted `tracing::error!` JSON events (per obs-plan §10 Always-required SLO invariant + §9 Zero-unlogged-panics gate).
- (obs) No absolute host paths and no internal struct names in the leg's journal or self-obs lines, including the rendered hold prompt and any checklist wording; the allowlisted `target` module path is preserved (per obs-plan §11 PII Scrubbing + §9 Log conformance check).
