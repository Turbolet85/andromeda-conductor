## Constraints
- The attended live activation is a **sanctioned operator step, not a test step**: test-plan §1 (Untestable zones) flags `drive+observe` visual/UX confirmation as untestable-by-agent while requiring that the *checklist rendering* and induced-state context ARE agent-assertable, and §11 (Universal) carves the operator checklist out as "a product feature, not a test step". Parts (1)+(2) of `v2-29` are therefore graded from operator-driven this-run artifacts, never from a CI assertion (per test-plan §1, §11).
- test-plan §1 (Surfaces under test → cli Notes) requires the headless path be "never blocked on an interactive prompt" — TTY-gated interactive `inquire` prompts (operator-pause) **must** be agent-bypassable — and §6 (cli driver row) requires the cli E2E leg run with stdin closed to prove it. Whether the code already satisfies this mandate (the `agent_mode`-overrides-TTY gate and its pinning test) is research's question.
- `ManualCheck` / `HOLD` are **reported envelope states, never non-zero process exits** (per test-plan §11 §E2E, Creator-Brief assertion-policy split); and the per-P-ID lamp label set is CLOSED at six (`[PASS]`/`[FAIL]`/`[HOLD]`/`[BLOCKED]`/`[MANUAL]`/`[RESIDUAL]`) plus the run-level non-lamp `[ENVIRONMENT-SUSPECT]` qualifier, NO_COLOR-stable (per test-plan §1 cli Signal, §6 Selector strategy). Any new checklist output on stdout must not widen that set silently.
- test-plan §3 (Log format) is the **source of truth for the JSONL/self-obs format**, and its "Self-obs stream is a distinct artifact" bullet requires the `tracing` stream (event line + span-lifecycle line variants) stay separate from the per-run emission journal envelope. Correcting the `lib.rs:403` "resolved headless" wording is an event-line `message` change: it stays inside §3's owned format, must keep §3 ↔ obs-plan §3 from going one-sided, and any new field is gated by the `conductor-core::redact` allowlist (per test-plan §3).
- If a scenario's induced state / expected observation becomes **scenario-config data**, test-plan §1 (Scenario-config validation entity) + §7 (Fixture files row) require it be a committed declarative serde+garde fixture under `scenarios/`, load-time-validated, with the negative-test suite catching a nested spec field annotated `skip` rather than `dive` — rules that exist but never execute (per test-plan §1 trigger "security-vector-coverage / property-test").
- Supply-chain gate (folded PREREQ): test-plan §9 (Build failure conditions) + §11 §CI require `cargo audit --deny warnings` and `cargo deny check` green with a committed un-drifted `Cargo.lock` and toolchain ≥ 1.94.1; §4 (Tool-version policy) frames the external CLI tools as reference **floors**, not pins. The chunk's ratified advisory-DB deviation must be recorded against that requirement, not treated as satisfying it (per test-plan §9, §10, §11 §CI).
- Zero-flakiness is binding — no `retries`, no serialize-to-hide; a runner-dependent or timing-dependent result is a determinism break to fix at the cause (per test-plan §10 Zero-flakiness budget), and live/attended legs are **operator/local gates, never blocking CI stages** (per test-plan §9 Live-Pulse scenarios + Scoped mutation audit).

## Patterns to follow
- **Harvest-tier live proof** — the six-precedent pattern (`storm` / `baseline` / `restart` / `pii` / `connection` / `severity_harvest.rs`): the operator drives the live leg by runbook, and this-run artifacts are pinned as hard predicates at the `conductor-run` unit tier so the claim stays CI-replayable (per test-plan §6 scenario rows + §1 Critical paths 1-4).
- **Declare-only row shape under deterministic L4** — exit 0, `verdict` null, `state="KnownResidual"`, non-Blocked, `latency_ms` against the declared `slo_tier`; this is the expected shape for these legs, not a defect (per test-plan §6 Scenario 1 Cleanup parenthetical + §1 critical-paths closing note).
- **Selector strategy for the HOLD/checklist render surface** — role/text/`aria-live` + brand anchors only: `role="alertdialog"` on the operator-pause dialog, the signature heading text "HOLD — operator pause", text-paired lamp labels, mono P-ID tokens (per test-plan §6 Selector strategy).
- **Fixture + golden discipline** — rstest `#[fixture]`/`#[rstest]`+`#[case]` table rows over the catalog; canonical serialization goldens locked by exact-string `assert_eq!` at unit tier with insta reserved for E2E goldens in CI fail-don't-write mode (per test-plan §4 Fixture pattern, §7 Seed strategies, §11 §Universal).
- **5-command harness parity** — `scripts/agent-run.{sh,ps1}` must expose identical semantics across both shells, with `--seed` riding only an explicitly set `SEED` (per test-plan §3 5-command implementation + Bootstrap phases). The scope's note that the harness exports `CONDUCTOR_AGENT_MODE` (forcing Headless) means the live attended leg runs outside this harness — whether that is already true of the shipped scripts is research's question.

## Anti-patterns to avoid
- NEVER encode a human-in-the-loop step as a test: no "developer verifies before deploy", no Percy/Chromatic/Applitools, no "human reviews screenshots" — the flagged `drive+observe` operator checklist is the sole carve-out and is a product feature (per test-plan §11 §Universal).
- NEVER use xpath or hashed-CSS selectors, and NEVER use `sleep(N)` for synchronization — wait on an explicit signal (envelope `state`, a JSONL journal line, element role/`aria-live`, exit code) (per test-plan §11 §E2E).
- NEVER let a `ManualCheck`/`KnownResidual`/`Blocked`/`CalibrationRegion` state become a non-zero process exit, and NEVER promote the live/attended leg into a blocking CI gate or add nextest `retries` to stabilize it (per test-plan §11 §E2E + §CI, §10).

- **tests §1/§6 cli label set ↔ design-system brand anchors** — the closed six-label set + `[ENVIRONMENT-SUSPECT]` qualifier, NO_COLOR-stable (per test-plan §1 cli Signal).
