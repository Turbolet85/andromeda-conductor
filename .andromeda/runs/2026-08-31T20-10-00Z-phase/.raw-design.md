# design extract

## Relevance
Partial — no webview surface is touched; design applies only to the status **vocabulary and rendering** of this chunk's outcomes (the declined arm, the un-inducible arm, the `incident_events` disproof) wherever they surface as `Verdict`/`ReportState` in cli output or a run-report row. If the leg lands as a harvest-tier test with no operator-facing print (scope §`[inferred]` premises), coverage narrows to vocabulary-only — which of the two it is, is research's question.

## Constraints
- The report row carries **both** a 3-valued `Verdict` and a 5-valued `ReportState`, and the three non-pass/fail states (`Blocked` / `ManualCheck` / `KnownResidual`) must never collapse into `Fail` — so the DECLINED arm's JSON-RPC error must map to a state chosen from this closed vocabulary, not invent a sixth (per design-system §Color Palette, the Verdict-vs-ReportState note).
- An arm that cannot be measured (scope's `[inferred]` "declined may not be inducible live") is `Blocked` — slate-violet, carrying the **named precondition string**, with measurement columns rendered `—`/null, never a red error (per design-system §Surface: cli / Component Patterns 3 + §Anti-Patterns → Rejected Defaults "conflating no-result-yet with failed").
- A measured-but-pre-accepted gap — the `incident_events` disproof recorded as a Pulse 0.4.0 residual candidate — is `KnownResidual`: ANSI 246 muted, `~` glyph, `[RESIDUAL]` label, carrying an "expected until {named fix}" note, visually NOT red (per design-system §Surface: cli / Component Patterns 4 + §Color Palette Residual row).
- Color is never the signal: every status requires its ASCII bracket label from the closed set `[PASS]`/`[HOLD]`/`[FAIL]`/`[MANUAL]`/`[RESIDUAL]`/`[BLOCKED]` plus the `✓`/`✗`/`?`/`~`/`•` glyph (TTY only, never emoji in piped output), TTY-gated through `anstream` honoring `NO_COLOR`/`TERM=dumb` (per design-system §Surface: cli / Tokens + §Per-Surface Bans → cli).
- No new color may be minted for this chunk's outcomes — the ANSI map and its `var(--…)` webview counterparts are the closed token set; a new outcome either reuses a shipped pair or, if it is a run-level qualifier rather than a per-P-ID lamp, becomes a non-lamp caption outside the lamp column (the `[ENVIRONMENT-SUSPECT]` precedent) (per design-system §Surface: cli / Tokens; §Anti-Patterns → Universal Bans).
- Mono ID-cyan (ANSI 117 / `--color-id-cyan`) is reserved strictly for P-IDs, `run_id`, SLO timings, `latency_ms`, and fingerprints — the P-075 id and any incident/run identifiers this leg prints belong to that tier, and nothing else may borrow it (per design-system §Typography Data row + §Surface: cli / Tokens).
- The declined-arm error, if it reaches operator output via the `VerifyError` fan-out, must render as sanitized stderr `error: &lt;short&gt;` + `hint: &lt;fix&gt;` — no absolute host paths, no internal struct names, no stack traces outside `--debug`/`-v` — reusing Fail red (203) and Residual mute (246), never new colors (per design-system §Surface: cli / Component Patterns 5).

## Patterns to follow
- **cli Verdict / report-state lines** (design-system §Surface: cli / Component Patterns 4) — the per-P-ID line shape any new result must match, including the `?`/`~`/`•` non-triad arms and the rule that `slo_tier` renders the scenario's **declared** value from the closed `&lt;5s`/`&lt;20s`/`&lt;90s` set, never a baked literal.
- **Results / SLO table** (design-system §Surface: cli / Component Patterns 3) — the 6-column `comfy-table` (P-ID · scenario · state · slo_tier · latency_ms · fingerprints), dynamic terminal width; note this is explicitly **separate** from the 4-column `conductor coverage` table, which carries no state column and therefore no bracket prefix — relevant to the scope's "at most a `notes` narrative" in `verification-matrix.json`.
- **Operator-pause prompt / headless discipline** (design-system §Surface: cli / Component Patterns 2 + §Per-Surface Bans → cli) — if the declined arm ends up needing operator confirmation, the headless `agent-run.sh` path must never block on an `inquire` prompt; the headless recording is "unconfirmed", the interactive path gets the confirm.
- **Reuse-over-add token precedent** (design-system §Color Palette Residual row, as amended twice) — the Residual-mute tier is the shared recessive tier for non-lamp uses; the correct move for a new de-emphasized caption is to join that set, not to add a palette row.

## Anti-patterns to avoid
- Rendering the DECLINED arm, an un-inducible arm, or the `incident_events` disproof as a red `Fail` — the "no surprise failure" discipline forbids silently downgrading not-measured / pre-accepted outcomes into the alarm state (per design-system §Anti-Patterns → Rejected Defaults).
- Any flashing, pulsing, blinking, or animate-to-100% treatment on a failing or held result; verdicts resolve motionless (per design-system §Motion hard limits + §Anti-Patterns → Rejected Defaults).
- Color-only status, emoji in machine-parseable piped output, hardcoded table widths, or colorizing without the TTY/`NO_COLOR` gate (per design-system §Per-Surface Bans → cli).

## Contract bindings
- **ReportState/Verdict vocabulary ↔ architecture §Standard Contracts / run-report envelope** — design's six lamp treatments are the render of arch's enums; the scope's "typed `Verdict`/`ReportState`, never a panic and never a harness `Err`" means the state word chosen for DECLINED must exist in both the arch enum and this closed render set. Whether the shipped enums already carry a state that fits the declined arm is research's question.
- **Bracket labels ↔ a11y §Use of Color (SC 1.4.1)** — the always-rendered ASCII label is the not-color-alone mechanism; it also carries the signal under `NO_COLOR` and when piped.
- **`[RESIDUAL]` "expected until {named fix}" ↔ docs/residuals.md pin** — the design-mandated note text needs a named fix to point at; scope names the Pulse 0.4.0 `incident_events` read path as the candidate, so the residual entry and the rendered note must agree on that name.
- **No webview binding expected** — motion, spacing, radius, and Lucide/lamp-glyph tokens are out of play unless a run-report row for this leg reaches the desktop surface (design-system §Surface: desktop-webview / Component Patterns 6).

## Acceptance criteria contributions
- (design) Every status this chunk emits carries its closed-set ASCII bracket label + glyph and is never signalled by color alone; output is TTY-gated and strips ANSI when piped (per design-system §Surface: cli / Tokens).
- (design) The DECLINED arm and any arm not provable live render as their own distinct state (`[BLOCKED]` with the named precondition, or `[MANUAL]`/`[RESIDUAL]`), never as `[FAIL]` (per design-system §Color Palette, Verdict-vs-ReportState note).
- (design) The `incident_events` disproof renders as `[RESIDUAL]` in the Residual-mute tier with an "expected until {named fix}" note and is never red (per design-system §Surface: cli / Component Patterns 4).
- (design) No new color, ANSI entry, or lamp state is introduced — any new de-emphasized output reuses the shipped Residual-mute / Fail-red pairs by name (per design-system §Anti-Patterns → Universal Bans; §Surface: cli / Tokens).
