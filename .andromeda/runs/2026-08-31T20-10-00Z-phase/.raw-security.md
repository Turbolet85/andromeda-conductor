# security extract

## Relevance
Relevant — the chunk fires the first production write across the MCP trusted-child boundary (`mark_incident_resolved`), maps a JSON-RPC error arm through the verdict/error wall, and carries a dependency-audit probe PREREQ; all three are security-plan surfaces.

## Constraints
- The MCP read-back child-stdout boundary is a named trust boundary requiring bounded line-delimited JSON-RPC decoding (serde_json recursion limit + soft per-line size bound, no unbounded read), with JSON-RPC errors and decode faults becoming typed inputs (`VerifyError::{JsonRpc,Decode,Transport}`), never panics (per security-plan §Input Validation, MCP read-back child stdout row). The DECLINED arm arrives as a JSON-RPC error, so it lands squarely in this mandate; whether the existing `conductor-verify/src/jsonrpc.rs` path already applies these bounds to a `tools/call` **write** response (as opposed to the read paths it serves today) is research's question.
- A malformed child/transport input MUST NOT panic — `tonic::Status` codes and MCP error responses are first-class typed verification inputs routed through the verdict/error wall (`Ok(Verdict/ReportState)` for outcomes, `Result::Err` reserved for harness faults only) (per security-plan §Security Anti-Patterns → Universal; §Error Handling). This governs the declined-arm handling the chunk builds.
- An empty canary round-trip MUST become `blocked`, never a false pass-as-empty (per security-plan §Input Validation, MCP read-back child stdout row). The chunk's `[inferred]` premise that resolving the canary's incident mid-run may perturb later read-backs is exactly this hazard: an ACTIVE set emptied by Conductor's own write must not read as a genuine measurement.
- A failed preflight MUST NOT silently downgrade to pass/fail/manual-check — each of the FIVE named preconditions surfaces as the distinct `blocked` state with its own named precondition string, and a term whose truth lives on the SUT's side is recorded `declared-not-observable` rather than blocking, because blocking on it would assert a measurement Conductor cannot make (per security-plan §Security Anti-Patterns → Universal). This is the sanctioned shape for recording the `incident_events` disproof and for the applied-arm-live / declined-arm-by-stub honest split.
- Conductor's production code MUST NOT directly open, copy, or exfiltrate Pulse's `corpus.db` (plaintext SQLite; corpus access is via MCP read-back ONLY), and MUST NOT persist its content into Conductor artifacts (per security-plan §Security Anti-Patterns → Data Protection). This constrains how the `DeclinedStale` concurrent-modification race may be staged — a direct corpus row mutation to induce it is the banned route on the production side; whether a test-only stager would fall outside "production code" is a question the plan does not answer and P3 should close.
- Run-report artifacts (`&lt;run_id&gt;.md`, `runs.db` rows, JSONL journals) MUST carry verdict/state/identity fields only — no absolute host paths (canonicalized `CONDUCTOR_*` dirs, `ANDROMEDA_PULSE_DATA_DIR`), no internal seam-crate struct/field names — and a `blocked` row populates only identity fields with the named precondition string, measurement fields JSON `null` (per security-plan §Error Handling, Run-report artifact sanitization; §Security Anti-Patterns → Logging). New lifecycle-leg fields (incident id, resolved status) inherit this.
- The dependency gate is not waivable by the standing deferral: a `cargo deny check advisories bans licenses sources` VERIFIED green is the sole coverage while the advisory-DATABASE fault persists, never assumed; and a dependency delta MAY land under a red audit only on a deny run verified green over the NEW `Cargo.lock`, restating the changed basis ("no dependency delta" stops being available as a reason) (per security-plan §Dependency Security, advisory-DATABASE fault bullet). `Cargo.lock` must not drift or go uncommitted (per §Security Anti-Patterns → Universal).
- If the leg needs a scenario TOML, it must carry a Pulse P-ID (per security-plan §Security Anti-Patterns → Universal) and every nested spec field must `dive`, never `skip`, with sibling-reading rules shipped as a load-path `Scenario::check_*()` from `from_toml_str` rather than `#[garde(custom)]` (per security-plan §Input Validation, scenario-config row).

## Patterns to follow
- The hand-rolled line-delimited JSON-RPC client's existing error fan-out (`VerifyError::{JsonRpc,Decode,Transport}`) is the sanctioned landing zone for the declined arm — the plan requires MCP error responses to become typed inputs on the existing wall, not a new ad-hoc parse (per security-plan §Input Validation; §Error Handling).
- The verdict/error wall split — verification outcomes as typed VALUES returned `Ok(...)`, `Result::Err` strictly for harness faults (config parse, transport down, MCP unreachable) (per security-plan §Error Handling).
- The `blocked`-with-a-named-precondition-string pattern, including the `declared-not-observable` recording for SUT-side truths, as the template for stating what the round could not measure (per security-plan §Security Anti-Patterns → Universal).
- The pinned contract-manifest preflight assert: negotiated `protocolVersion` pinned at `2024-11-05` and the required-tool name set (`query_incident_list` · `retrieve_report` · `retrieve_telemetry_slice` · `mark_incident_resolved`) checked against the `initialize` result — mismatch ⇒ `blocked`, never a silent downgrade (per security-plan §Input Validation, pinned MCP contract manifest row). The chunk's `[inferred]` premise about `mark_incident_resolved` being a required preflight tool resolves against this row.
- The PROBE-AUTO-SATISFY bounded wait with the deliberate audit↔deny overlap re-checked each chunk rather than a `deny.toml` ignore, a CI edit, or a silent accept (per security-plan §Dependency Security).

## Anti-patterns to avoid
- NEVER open, copy, or exfiltrate `corpus.db` directly, and never persist corpus content into Conductor artifacts — including as a means of staging the `DeclinedStale` race (per security-plan §Security Anti-Patterns → Data Protection).
- NEVER let a malformed child/transport input panic, and NEVER silently downgrade a failed preflight or an empty read-back into a pass (per security-plan §Security Anti-Patterns → Universal).
- NEVER write journal/report wall-clock stamps from tokio's virtual clock — use `std::time::SystemTime`/`Instant`, since the lifecycle leg's ordering and any freshness math ride those stamps (per security-plan §Security Anti-Patterns → Logging).

## Contract bindings
- Verdict/error wall + `blocked` precondition strings bind to architecture §Standard Contracts (readiness gate) and §Read-Back Dependency Posture — security restates the ban but arch owns the contract text the chunk amends.
- Run-report/journal field hygiene binds to the obs plan's journal + report schema (identity/verdict fields only; no path leakage) and to the tests domain's harvest-tier assertions that read those rows.
- The `cargo audit` / `cargo deny` probe binds to tests §CI Integration — security-plan §Dependency Security places the dependency gate in the existing GitHub Actions pipeline, one workflow with the security gate as a job.

## Acceptance criteria contributions
- (security) The DECLINED arm is handled as a typed `VerifyError` / typed `Verdict`/`ReportState` — no panic on the read-back path, no harness `Err` standing in for a verification outcome, no false pass (per security-plan §Security Anti-Patterns → Universal; §Error Handling).
- (security) No production code path opens Pulse's `corpus.db` directly to induce or observe the lifecycle write — the applied and declined arms are exercised through the MCP tool (or an explicit stub) only, and no corpus content is persisted into Conductor artifacts (per security-plan §Security Anti-Patterns → Data Protection).
- (security) The 40th probe records `cargo audit` and `cargo deny check advisories bans licenses sources` with the exit code captured before any pipe, the deny run VERIFIED green (not assumed); if any dependency delta lands, the deny overlap is verified green over the NEW `Cargo.lock` and the changed deferral basis is stated (per security-plan §Dependency Security, advisory-DATABASE fault bullet).
- (security) Any new run-report / `runs.db` / journal fields emitted by the lifecycle leg carry verdict/state/identity values only — no absolute host paths, no internal seam-crate struct names — and any `blocked` outcome carries its own named precondition string with measurement fields `null` (per security-plan §Error Handling, Run-report artifact sanitization).
