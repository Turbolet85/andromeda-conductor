## Constraints
- The six lamp display labels ↔ obs `verdict` ↔ obs `state` mapping is binding: any `Verdict`/`ReportState` this chunk emits (notably the DECLINED-arm typing) must land on an existing crosswalk row, and lamp identity is chosen **verdict-first** (`verdict == CalibrationRegion` ⇒ HOLD lamp regardless of `state`) (per a11y-plan §6 State color tokens — state-naming crosswalk). Whether the declined arm's chosen verdict/state pair already lands on an existing row, or creates a new co-occurrence needing a crosswalk amendment, is research's question.
- The set of lamp states is fixed at six (`Pass`/`HOLD`/`Fail`/`Blocked`/`Manual`/`Residual`), each requiring a text label + glyph supplement; a new classification introduced by this chunk must not become an unlabeled seventh state (per a11y-plan §11 Visual + §1 A11y triggers, visual-discrimination).
- a11y's violation artifacts reproduce the obs §6 Run-report envelope **verbatim** (11 fields incl. `read_back_observed_at`); if this chunk's read-back lifecycle work alters that envelope's field set or field semantics, a11y §3's reproduction must be amended in lockstep (per a11y-plan §3 Structured violation JSON schema).
- The CLI / harvest-tier surface is **not-assertable** — no DOM or widget tree, no axe/Lighthouse/pa11y reach; this chunk's live leg therefore carries no a11y verification path and can claim none (per a11y-plan §1 A11y scope, cli entity + §11 Universal).
- Artifacts folded into the obs §6 envelope MUST NOT leak absolute host paths or internal seam-crate struct names — relevant because the DECLINED arm's JSON-RPC error text / `VerifyError` fan-out variant names flow toward `fingerprints[]`/notes (per a11y-plan §3 Structured violation JSON schema + §11 SLO).
- No WCAG conformance may be claimed without machine-verifiable evidence; nothing in this chunk generates such evidence, so its wrap must not assert any WCAG SC coverage (per a11y-plan §11 Strategy + §2 Agent-runnable invariants).
- Tier stays Minimal (0) — this chunk adds no UI surface and no new must-be-accessible path, so no tier reassessment and no new axe/keyboard/contrast gate (per a11y-plan §1 A11y Scope Summary).

## Patterns to follow
- Crosswalk-row amendment over new-lamp invention: when a chunk produced a previously-denied verdict/state co-occurrence, the established response was to disambiguate the existing crosswalk row (per a11y-plan §6 crosswalk; precedent in the 2026-06-21 and 2026-08-21 amendments), not to add a lamp.
- Verdict-first lamp precedence when reasoning about which display label a journal row joins back to (per a11y-plan §6 crosswalk).
- Non-lamp reuse of a state token is a *classification*, carrying its own always-rendered text label rather than a glyph, and is explicitly excluded from the six-label assertion (per a11y-plan §1 A11y triggers, "Non-lamp reuse of a state token" + §6).
- Envelope-reproduction lockstep with obs: a11y narrows, obs fixes the schema — a11y tracks obs field additions rather than diverging (per a11y-plan §3 Structured violation JSON schema).

## Anti-patterns to avoid
- Treating the cli/headless leg as accessibility-assertable — its ASCII status prefixes / NO_COLOR text pairing are output-stream discipline, not an ARIA verification path (per a11y-plan §11 Universal).
- Conveying a new outcome state by color/token alone with no always-rendered text label (per a11y-plan §11 Visual).
- Leaking absolute host paths or internal seam-crate struct names into the shared obs §6 envelope (per a11y-plan §11 SLO).
