## Relevance
Relevant — the chunk lands code in two registered workspace crates, fires an already-registered consumed MCP tool, and turns a JSON-RPC error arm into a typed outcome, all of which arch governs directly.

## Constraints
- **Verdict/error wall.** The DECLINED arm arrives as a JSON-RPC error but is SUT behavior, not a Conductor fault: arch §Design Philosophy ("Outcomes are values, errors are harness faults"), §Established Decisions [Error Handling] and §Cross-cutting Patterns (Verdict/error wall) require it to land as an `Ok`-side `Verdict`/`ReportState`, with `Result::Err` reserved for config parse / transport down / MCP unreachable. §Conventions (Error handling) requires MCP error responses be treated as first-class verification inputs, never panics, and that read-back transport/decode/JSON-RPC failures fan out into `VerifyError` variants (`Transport`/`Protocol`/`Decode`/`JsonRpc`). Whether the shipped fan-out already distinguishes a tool-level application error from a transport fault is research's question.
- **Read-back client shape is locked.** Per arch §Established Decisions [MCP Read-Back Client], the call must go over the hand-rolled line-delimited JSON-RPC client (`initialize`/`tools/list`/`tools/call`) returning a RAW `serde_json::Value` — no rmcp, and no `{content:[…]}` envelope assumption, because Pulse's `tools/call` is non-MCP-compliant. The applied-path `Ok` payload must therefore be read as a raw value.
- **Crate placement / module boundary.** arch §Occupied Resources (Crate names) + §Established Decisions [Module Boundaries] and [Workspace / Core Structure] place the MCP client + preflight + verdict logic in `conductor-verify` and the run composition root (preflight + `execute_scenario` + persist + drive) in `conductor-run`, which sits above the seams and below both bins; new cross-seam edges are `Cargo.toml` facts arch registers, so the leg must not introduce an unregistered one nor a new workspace member.
- **No new occupied resource.** arch §Occupied Resources registers `mark_incident_resolved` as one of exactly four consumed MCP tools and pins the reserved `CONDUCTOR_*` env namespace; contracts artifacts deliberately carry NO `CONDUCTOR_*` override handle. The chunk adds no MCP tool (the scope's own `incident_events` boundary agrees), no env var, and no inbound surface (§Cross-cutting Trust boundary: Conductor is a client, never a server).
- **Readiness-gate contract is a shared shape.** arch §Standard Contracts requires the gate's FIVE named preconditions, tool-presence assertion against `contracts/mcp-contract.toml`, canary attribution to THIS run, and host-path-free precondition strings; §Occupied Resources notes `query_incident_list` takes no arguments. The scope's `[inferred]` risk — resolving the canary's incident perturbing later preflight/scenario reads — sits squarely against this contract; whether the current run seam already isolates them is research's question.
- **Report shapes are pinned.** If the leg grades anything, arch §Standard Contracts requires the eleven-field run envelope plus the nine-key `CheckRecord` across all three surfaces (JSONL journal, `run_check`, Markdown detail line), with `run_check.latency_ms`/`deadline_ms` NOT NULL and blocked/declare-only scenarios emitting ZERO check records and zero rows.
- **Scenario law, if a scenario TOML lands.** arch §Cross-cutting (Scope law) requires "no scenario without a P-ID" and §Established Decisions [Accepted Capability Set] requires membership in `contracts/pulse-capabilities.toml` via `check_capabilities`, plus exact-set satisfaction of `check_sut_drift` and `check_scenario_backing`/`UNBACKED_AUTO` — a pin a new scenario now covers is a `CoreError::UnbackedCoverage`, so adding a scenario naming an `Auto` capability is a two-artifact change, not a file drop.

## Patterns to follow
- The harvest-tier live-leg shape the eight declare-only families ship (arch §Standard Contracts, run-report envelope declare-only registry) — the scope's `[inferred]` "home is a harvest test, not a new scenario TOML" matches this precedent; the delegated-timing family is the nearest analogue.
- `route_read_back` / `ReadBack {Graded, AutoResolved, Blocked}` (crate-private in `conductor-run`, arch §Established Decisions [Read-Back Dependency Posture]) — the existing seam deciding how a read-back observation lands, including the `KnownResidual` routes; an active-set assertion after a resolve interacts with the auto-resolve arm.
- Live-leg preconditions arch already models: `ANDROMEDA_PULSE_L4_DETERMINISTIC` read in Conductor's own shell as the run contract's `shell-declaration` proxy, `ANDROMEDA_PULSE_DATA_DIR` propagated to the spawned sidecar, and `CONDUCTOR_PREFLIGHT_TIMEOUT`'s run-contract-derived floor (arch §Occupied Resources, Environment variables).
- Duplicate-occurrence discipline for the recorded disproof: arch states the payload-fidelity/freshness-carrier posture at BOTH §Established Decisions [Read-Back Dependency Posture] and §Standard Contracts (readiness gate), so a second-axis disproof recorded at one site alone leaves the other teaching the retired reading — the wrap's amendment surface, not a phase edit (the scope already routes it to wrap).
- Two-source integrity-gate pattern (`check_sut_drift` + `check_scenario_backing`, arch §Established Decisions [Accepted Capability Set]) if the P5 matrix step decides to claim a capability.

## Anti-patterns to avoid
- Returning `Result::Err` (or panicking) for the DECLINED/`ToolDispatchFailed` arm — arch's verdict/error wall bans classifying SUT behavior as a harness fault (§Established Decisions [Error Handling]).
- Making the live leg a CI gate, or adding a network/HTTP surface, a new `CONDUCTOR_*` env var, or a `CONDUCTOR_*` override for a `contracts/` artifact — arch §Infrastructure Patterns (CI/CD: live Pulse proof is an operator/local gate) + §Occupied Resources.
- Asserting payload-level content fidelity or re-deriving a claim from a weaker basis — arch §Established Decisions [Read-Back Dependency Posture] fixes freshness as the carrier because every L4-authored field is payload-invariant under deterministic L4.

## Contract bindings
- **Verdict/error wall ↔ tests + report:** the typed DECLINED outcome must be assertable by `match`, so the tests harness fixture shape and `conductor-report`'s `ReportState` mapping (`Verdict::default_report_state`, arch §Probabilistic-Assertion Policy) are the downstream consumers.
- **`CheckRecord` / run envelope ↔ report + tests + `runs.db`:** one shape crossing three surfaces (arch §Standard Contracts, Per-check record) — any graded check the leg adds binds all three.
- **Readiness gate ↔ tests + obs:** the five named preconditions and the canary incident are the fixtures a live leg runs against; resolving that incident touches the gate's own attribution basis.
- **Capability manifest / `UNBACKED_AUTO` ↔ tests + the P5 verification-matrix step:** the scope's "claims no capability by default" boundary is exactly arch's exact-set pin discipline.
