# layouts extract

## Relevance
Partial — no webview surface and no new cli verb; layouts applies only where this chunk's typed declined-arm outcome, the recorded disproof, and any new scenario row reach rendered output (cli stdout, the `runs/<run_id>.md` report, the coverage roll-up).

## Constraints
- The per-P-ID lamp set is **closed at six** (`[PASS]`/`[HOLD]`/`[FAIL]`/`[MANUAL]`/`[RESIDUAL]`/`[BLOCKED]`) and `ReportState` stays five; the DECLINED arm must land inside that closed set — no seventh lamp, no new bracket label, no new ANSI/token entry (per layout-templates §Surface: cli — Component — Primary content block 2).
- The status tier maps **1:1 to the typed run outcomes** on both surfaces — the machine-verdict triad (`Pass`/`CalibrationRegion`/`Fail`) plus the three non-verdict ReportStates (`ManualCheck`/`KnownResidual`/`Blocked`) — and none may silently collapse into `Fail` (per layout-templates §Decisions Log — Cross-surface IA decisions).
- If the declined arm resolves `Blocked`, the row must carry its **named precondition string** and render `—`/null in the measurement columns, **never a red error** (`Blocked` ≠ red — it was never measured) (per layout-templates §Component — Primary content block 2 and §cli Component — Primary content block 1).
- If the `incident_events` disproof surfaces as a pre-accepted gap it renders `KnownResidual`: muted dashed lamp / `~ [RESIDUAL]` ANSI 246 plus an "expected until {named fix}" note — **never a red Fail** (per layout-templates §Component — Primary content block 2 and §cli Component — Primary content block 2).
- Every state must be **paired with its ASCII bracket prefix / status text** so it survives `NO_COLOR`, piping and screen readers; stdout stays reserved for parseable artifact data, human messages to stderr (per layout-templates §Surface: cli signature placement + §cli IA notes — Pipe discipline).
- Output structure is a **parsed contract**: adding a `comfy-table` column without a `--format` flag is a breaking change; the 6-column results/SLO table and the 4-column coverage table must not be conflated (per layout-templates §cli IA notes — Command model and §cli Component — Primary content block 1).
- The headless invariant holds for any live leg: `inquire` prompts are `isatty`-gated and the agent-driven source-of-truth path is **never** blocked on a prompt (per layout-templates §cli IA notes — Headless invariant).

## Patterns to follow
- **Indented-detail-line precedent** — the `Blocked` precondition string, the `KnownResidual` note, and the per-check detail region under a P-ID verdict line: one indented plain-text line carrying kind / verdict / `latency_ms` / the deadline judged against, with no new column and no new label (per layout-templates §cli Component — Primary content block 2).
- **Run-level non-lamp qualifier** — the `[ENVIRONMENT-SUSPECT]` caption + the `not-conductors` Mode-cell treatment: a fact that qualifies the run rather than reporting a check rides **outside** the lamp column and alters no per-check state; that is the shape to reuse if the second-axis disproof needs any stdout presence (per layout-templates §cli Component — Primary content block 2 and §Component — Primary content block 1, Mode cell).
- **De-literalized derived counts** — sample captions and tier cells use placeholder form (`(N unbacked)`, `<slo_tier>`) because every number is manifest-derived, never a literal; if this chunk names a P-ID in a scenario the roll-up shifts without owing a doc re-pin (per layout-templates §cli Primary screens — `conductor coverage [--write]`).
- **Mirror, not fork** — the same state reads identically across webview CSS vars, cli ANSI and the Markdown artifact (`count-nominal` ↔ 114, `count-hold` ↔ 179, `status-fail` ↔ 203, `count-blocked` ↔ 60, residual ↔ 246); a state introduced on one surface must be expressible on all three (per layout-templates §cli IA notes — Multi-surface coordination).
- **P-ID sample labels track the authoritative coverage classification** (`conductor_core::coverage_matrix` + the committed scenario catalog) — any sample row this chunk adds or touches must pair the right P-ID with the right scenario name (per layout-templates §Wireframe — Run report (terminal) + §cli Output structure).

## Anti-patterns to avoid
- Introducing a seventh lamp, a sixth `ReportState`, a new bracket label, or a new ANSI/token entry to express the DECLINED arm or the `incident_events` disproof (per layout-templates §cli Component — Primary content block 2).
- Rendering a never-measured or pre-accepted state as red / as `Fail` — `Blocked`, `KnownResidual` and a declined write are not failures (per layout-templates §Component — Primary content block 2 and §Decisions Log — Cross-surface IA decisions).
- Widening the results/SLO table (a 7th column) or otherwise changing parseable stdout shape to carry the new measurement without a `--format` flag (per layout-templates §cli IA notes — Command model).

## Contract bindings
- **layouts ↔ verify/run typed outcomes** — layout-templates §Decisions Log binds the rendered status tier 1:1 to the typed `Verdict`/`ReportState`; the chunk's declined-arm mapping in the `VerifyError` fan-out (scope §Surfaces and contracts touched) must therefore terminate in one of the six existing labels, so a harness `Err` or panic has no legal render.
- **layouts ↔ obs/tests harness (verdict/error wall)** — a JSON-RPC error arm must reach a rendered typed state; the honest applied-live + declined-by-stub split (scope §`[inferred]` premises) has to pick which of the existing states carries the un-fired arm (`Blocked` with a named precondition being the plan's shape for "never measured").
- **layouts ↔ design (tokens/ANSI)** — token and ANSI authority is design's; layouts requires the state reuse an existing mapping and forbids a new entry (per layout-templates §cli IA notes — Multi-surface coordination).
- **layouts ↔ a11y** — no binding fires: this chunk adds no focusable element, no dialog and no focus-order position.
