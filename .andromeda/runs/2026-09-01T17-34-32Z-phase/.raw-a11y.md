## Relevance
Relevant — harness-platform, not WCAG-assertion: the chunk's probe decides whether the plan's only agent-runnable a11y verification path exists on this host, and the scope names `a11y-plan.md` §3 as a wrap-amendment target.

## Constraints
- One webview-automation stack only: a11y-plan.md §3 (A11y testing tool pick) requires axe to inject via `@axe-core/webdriverio` into the SAME `@crabnebula/tauri-driver` + WebdriverIO session tests §6 stands up — the probe's driver path must be that session, not a parallel attach. §3 (Configuration) already names `msedgedriver` as tauri-driver's Windows backend, so a Windows driver is contract-consistent at the driver layer; it is the *target* ("CI aligns on the Linux+xvfb runner") that a Windows result diverges from.
- The Linux+xvfb framing is restated across at least six plan sites — §3 (Configuration), §3 (CI integration), §3 (Bootstrap phases → `a11y-ci-gate-wire`), §9 (Platform + pipeline bullets), §11 (CI bans), §12 (Decisions Log). a11y-plan.md §9 requires the a11y path run on the runner tests' webview E2E uses; a measured Windows path makes every one of those sites stale at once, so the wrap amendment must sweep all sites, not just §3.
- Agent-runnable invariant (plan preamble + §2 Agent-runnable invariants): every WCAG criterion requires at least one machine-verifiable path; manual NVDA/keyboard/contrast is never sole. A probe FAIL therefore has to be recorded as "the desktop-webview SCs have no agent-runnable path on this host", not absorbed by the manual SR spec.
- Reduced-motion emulation is the plan's single platform-dependent assertion: a11y-plan.md §6 (Motion tokens) + §12 (Decisions Log open caveat) require `browser.emulate('prefers-reduced-motion','reduce')` over the driver session where Bidi/CDP-backed, with an OS-level / `CONDUCTOR_TEST_REDUCED_MOTION` fallback otherwise. A WebView2/msedgedriver session is exactly the Chromium-backed case the caveat was hedging; whether the probed session actually supports `emulate` is research's question.
- Emission channel is fixed: a11y-plan.md §3 (CI integration) + §9 require a11y results surface through the `logs` command of tests' binding 5-command harness contract, as an operator/local gate rather than a CI gate. If this chunk promotes ui-smoke to a Test Commands gate, that channel constraint still binds the a11y step.
- Artifact hygiene: a11y-plan.md §3 (Structured violation JSON schema) + §11 (SLO bans) require a11y artifacts carry no absolute host paths and no internal seam-crate struct names, with node targets as DOM-relative selectors / `data-testid`. Windows-host probe records (`target/release/conductor-tauri.exe`, `node_modules/.bin`, `D:\…`) are the live leak risk if any probe output is folded into an a11y artifact.

## Patterns to follow
- Driver-reuse construction per a11y-plan.md §3 (Focus management test harness): one WebdriverIO session, `new AxeBuilder({ client: browser }).analyze()`; assertions read state via `browser.execute(() =&gt; document.activeElement?.getAttribute('data-testid'))`.
- Affordance-proof shape per a11y-plan.md §3 (Keyboard test harness) + §5 (Test harness pattern): scripted `browser.keys(['Tab'|'Shift+Tab'|'ArrowDown'|'Enter'|'Space'|'Escape'])` against named controls, PASS/FAIL emitted structurally — this is the plan's existing template for the chunk's "real click / keypress on a named affordance" legs.
- Bootstrap discipline per a11y-plan.md §3 (Bootstrap phases → `a11y-tooling-install`): reuse the already-installed `webdriverio` + `@crabnebula/tauri-driver` devDeps; puppeteer-core / `@axe-core/puppeteer` / pa11y were explicitly dropped for implying a parallel CDP/Windows-only stack. Any driver-binary acquisition the probe needs sits under that "reuse, don't add a stack" rule.
- Envelope folding per a11y-plan.md §3 (Structured violation JSON schema): results ride the obs §6 envelope with axe rule-id + WCAG-SC tag + selector inside `fingerprints[]`, tagged `service.name` = `"conductor-tauri"` / `deployment.environment`.
- Multi-site amendment precedent (see amendment history below): the 2026-08-22 entry changed six sites in one pass because each restated a retired composition — the platform framing is restated at least as widely.

## Anti-patterns to avoid
- a11y-plan.md §11 (CI) bans standing up a second browser-automation stack (puppeteer/CDP) for a11y — a Windows CDP attach that bypasses tauri-driver/wdio would violate this even if it makes the probe pass.
- a11y-plan.md §11 (Strategy, Universal) bans any WCAG conformance claim without machine-verifiable evidence — a green driver attach proves session availability, not zero violations; the conformance claim belongs to the separate sweep entry (v2-22).
- a11y-plan.md §11 (Universal, CI) bans manual NVDA/VoiceOver/Orca or manual keyboard as the ONLY method — on a probe FAIL, manual passes must not be re-labelled as the verification path.
