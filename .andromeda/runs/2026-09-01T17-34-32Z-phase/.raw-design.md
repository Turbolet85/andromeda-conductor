# design extract

## Relevance
**Partial** — the chunk's deliverable is driver/test infrastructure (out of design's domain), but design owns three things it touches: how the probe's outcome is *reported* (Blocked vs Fail vs ManualCheck), the named-affordance contract a driver must select on, and cli/agent-harness output discipline if a self-verify stage lands in `agent-run.{sh,ps1}`.

## Constraints
- A driver that cannot attach — or a leg never executed — is `ReportState::Blocked` carrying its named precondition string (`--count-blocked` slate-violet / ANSI 60 `[BLOCKED]`, measurement columns `—`/null), **never** a red `Fail`; the Verdict triad and the 5-valued ReportState are separate axes and a report row carries both (per design-system.md §Color Palette / Verdict-vs-ReportState note; §Surface: cli Component Patterns 3).
- The chunk's "operator legs reserved for judgment items" must land in the **existing** `ManualCheck` class — `--status-manual` / ANSI 146, `[MANUAL]` + `?` glyph, neutral-lavender checkbox, deliberately outside the green/amber/red triad because there is no machine verdict — and renders as the operator-checklist, not a new state (per design-system.md §Component Patterns 7; §Surface: cli Component Patterns 4).
- Affordance proof presumes affordances are *named*: every icon-only titlebar/lamp control must carry an `aria-label` and every status lamp must be paired with a text label. This is the accessible-name surface a WebDriver session selects on. Whether the shipped controls already carry those names is research's question (per design-system.md §Iconography, "Rule").
- If a self-verify stage becomes an agent-harness command, cli discipline binds: `isatty`-gated, the headless agent-driven source-of-truth path **never** blocked on a prompt, `NO_COLOR`/`TERM=dumb`/pipe stripping honored, ASCII bracket prefixes never color-alone (per design-system.md §Surface: cli Platform-Specific Notes; §Anti-Patterns / Per-Surface Bans / cli).
- Probe-failure diagnostics take the shipped stderr shape: `error: &lt;short&gt;` + contextual detail + `hint: &lt;fix&gt;`, sanitized (no absolute host paths, no internal struct names, stack traces only under `--debug`/`-v`), reusing Fail red 203 / Residual mute 246 — no new colors (per design-system.md §Surface: cli Component Patterns 5).
- The webview under drive is a **frameless** Tauri window (`decorations: false`, `data-tauri-drag-region` titlebar) with no native chrome — driving happens against in-page controls, and `alert()`/`confirm()`/`prompt()` are banned in favor of the styled `AlertDialog`, so a real DOM dialog exists to drive (per design-system.md §Surface: desktop-webview Toolkit/Framework + Component Patterns 2).
- Timing under drive is CSS-only: zero animation library, `--motion-micro` 150ms transitions, `--motion-heartbeat` 1600ms breath, and a global `@media (prefers-reduced-motion: reduce)` block that drops every animation/transition — waits should bind to these token names, never magic sleeps or spring/library timing (per design-system.md §Motion, Hard limits; §Surface: desktop-webview Tokens).

## Patterns to follow
- **Frameless titlebar + Paused-count heartbeat** (design-system.md §Component Patterns 1) — the primary driveable surface: phase line, mono count, `aria-label`-ed min/close Lucide controls at 16px; drag-region must not leak pointer state into controls.
- **Operator-pause go/no-go dialog** (§Component Patterns 2) — Radix `AlertDialog`, `role="alertdialog"`, focus trapped, Proceed disables in-flight; the canonical click/keypress affordance an agent can honestly drive.
- **Verdict / report-state lamp** (§Component Patterns 4) — six visually distinct treatments, always paired with text (`Pass`/`CalibrationRegion`/`Fail`/`Blocked`/`Manual`/`Residual`) + `aria-live`; this is the read-back an affordance assertion reads.
- **Results / SLO table + verdict lines** (§Surface: cli Component Patterns 3 and 4) — the shape any probe-result reporting takes: P-ID (ANSI 117) · state prefix · `slo_tier` from the closed set · `latency_ms`; a `Blocked` row carries the precondition, never a red error.
- **Keyboard-first navigation** (§Surface: desktop-webview Navigation Pattern) — no router/URL/back-forward; an agent drives by keybindings and named controls, so keyboard alternatives to every hover interaction are load-bearing here.

## Anti-patterns to avoid
- Recording the probe's negative outcome as a `Fail`, or inventing a seventh lamp / sixth `ReportState` for "driver unavailable" — the sanctioned form for a run-level qualifier is a caption in the recessive Residual-mute tier (the `[ENVIRONMENT-SUSPECT]` precedent), never a new lamp state (per §Anti-Patterns / Rejected Defaults "Conflating 'no result yet' with 'failed'"; §Surface: cli Tokens).
- Relaxing a shipped webview ban to make the window driveable — no visible Chromium/WebView2 artifacts (context menu, devtools, text-selection on non-text elements), no remote-origin iframes, no Tauri commands without the deny-by-default capabilities file (per §Anti-Patterns / Per-Surface Bans / desktop-webview).
- Adding an interactive prompt, or an un-`isatty`-gated colored spinner, to the agent-driven self-verify path (per §Anti-Patterns / Per-Surface Bans / cli).

## Contract bindings
- **design ↔ a11y:** the accessible-name mandate (§Iconography Rule: `aria-label` on icon-only controls, text label beside every lamp) is simultaneously a11y's not-color-alone/SC 1.4.1 requirement and the *selector surface* the driver uses — one contract, two consumers. Motion tokens bind to a11y SC 2.3.3 via the mandatory `prefers-reduced-motion: reduce` override (§Motion).
- **design ↔ tests harness:** `--motion-micro` (150ms) and `--motion-heartbeat` (1600ms) are the only sanctioned timing constants for driver waits; there is no animation library whose completion could be awaited (§Motion, Motion tokens).
- **design ↔ cli / agent harness:** the closed status-prefix set `[PASS]`/`[HOLD]`/`[FAIL]`/`[MANUAL]`/`[RESIDUAL]`/`[BLOCKED]` plus the `error:`/`hint:` stderr structure govern any self-verify stage added to `agent-run.{sh,ps1}` (§Surface: cli Tokens + Component Patterns 5).

## Acceptance criteria contributions
- (design) A driver-unavailable or unexecuted leg is reported as `Blocked` with its named precondition string, distinct from a red `Fail`, with measurement columns rendered `—`/null (per design-system.md §Color Palette / Verdict-vs-ReportState + §Surface: cli Component Patterns 3).
- (design) Operator-reserved judgment legs render in the existing `ManualCheck` class (`--status-manual` / ANSI 146, `[MANUAL]` + `?`, paired text, outside the verdict triad) — no new report state or lamp is introduced (per design-system.md §Component Patterns 7 + §Iconography).
- (design) Every affordance the probe drives is reachable by accessible name — icon-only controls carry `aria-label`, status lamps carry text labels; no color-only or icon-only affordance is relied on as the target (per design-system.md §Iconography, "Rule").
- (design) Any self-verify stage added to the agent harness stays TTY-gated and non-blocking, emits sanitized `error:` / `hint:` stderr on driver failure, and introduces no new color, token, or raw ms/hex literal (per design-system.md §Surface: cli Component Patterns 5 + §Anti-Patterns / Per-Surface Bans).
