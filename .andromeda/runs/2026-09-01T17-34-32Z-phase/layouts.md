# layouts extract

## Relevance
Partial — the chunk creates no surface and authors no wireframe, but it drives the shipped desktop-webview surface through a WebDriver session (affordance targets, focus behaviour, dialog structure are layout-owned) and may extend the agent-harness command/stage surface that layout-templates.md enumerates.

## Constraints
- **Run state, not routes.** layout-templates.md §Surface: desktop-webview / Primary screens + §IA notes require the frameless window BE the surface — idle / live / HOLD / report are one window in different run states, with no router, no breakpoints, no deep links, no back/forward. A self-verify leg must reach a state by driving run state (pick → Start → hold → report), never by navigating a URL or route. Whether the shipped `wdio.conf.ts` assumes a URL/route entry point is research's question.
- **Titlebar drag-region vs. window controls.** §Component — Header requires the full-width titlebar to carry `data-tauri-drag-region`, requires the drag-region pointer cursor not to leak onto the min/close glyphs, and specifies standard (not traffic-light) buttons on Windows. A driver click landing on the band is a window drag, not an activation, so a titlebar affordance leg must target the control glyph itself. Whether the shipped markup separates the two is research's question.
- **The styled `AlertDialog` is the only modal.** §IA notes require `alert()` / `confirm()` / `prompt()` are never used, and §Component — Hero / signature section requires focus trapped inside the dialog with a visible `color-focus` ring. Modal proof therefore runs entirely through DOM interaction; a native-alert driver path has nothing to attach to.
- **Every affordance has a keyboard equivalent.** §Component — Primary navigation requires start / stop / proceed / abort each bound to a keybinding, a visible focus ring on every interactive control, and a `border-emphasis` edge on the active picker item so focus is never color-only. A keypress leg is a first-class form of affordance proof here, not a fallback for a failed click.
- **The affordance inventory is closed by the wireframes.** §Wireframe — Run console (idle) / (HOLD) plus §Component — Primary content block 1 name the interactive set: scenario/suite picker (shadcn `Command`/`Select`), Start, Stop, minimize/close, virtual-scrolled coverage-matrix rows (selected → `border-emphasis` left edge), HOLD dialog Proceed / Abort, and checklist checkbox rows (Space toggles). A leg claiming "affordance proof" must land on one of these.
- **Webview guardrails constrain what a driver may assume.** §IA notes require Chromium context menu / devtools / text-selection on non-text elements to be suppressed, deny-by-default Tauri capabilities (only start/stop · picker · run-report · operator-pause commands plus the one live-counter `Channel`), and no remote-origin iframes. Enabling a suppressed Chromium affordance or opening a new capability purely to let a driver attach would violate the layout-level guardrail set.
- **The agent-harness command surface is enumerated here.** §Surface: cli — Primary screens fixes `scripts/agent-run.sh` as the 5-command `boot`/`run`/`status`/`cleanup`/`logs` harness with `run` taking `--unit`/`--integration`/`--e2e` (default = the full bundled gate), and names no `.ps1` variant. A self-verify stage or Windows script path landing in that harness is a layout-surface registration owed at wrap.

## Patterns to follow
- **Fixed operator path as the drive script.** §Component — Primary navigation states the operator's path is fixed: pick scenario/suite → Start → heartbeat + phase line + live counters over the Tauri `Channel` → answer operator-pause holds → read the run report. An agent drive that mirrors this path exercises the surface as designed rather than inventing a traversal.
- **Status is never color-only — assert text, not pixels.** §Component — Primary content block 1 and block 2 require every lamp to be paired with its verdict/state text (`Pass` / `CalibrationRegion` / `Fail` / `Blocked` / `ManualCheck` / `KnownResidual`), and require Blocked rows to render `—` / null rather than a red error. That pairing is the text anchor an agent-driven assertion should key on.
- **ManualCheck is the already-named reserved-operator class.** §Component — Operator-checklist defines `ManualCheck` as the past visual observation Conductor cannot read back over MCP (halo→burgundy, no OS toast), ticked by the operator. This is the plan's existing expression of the chunk's "operator legs reserved for judgment items" boundary — the class exists in the layout, so the chunk need not invent one.
- **HOLD dialog structure as amended.** §Component — Hero / signature section requires checklist rows to render BETWEEN Body and Actions as a **sibling** of the dialog's `Description`, never nested inside it, and requires Proceed to disable into an in-flight state on commit. Any real-webview structural assertion must expect that shape.
- **The freeze is assertable as absence of change.** §Component — Header and §Wireframe — Run console (HOLD) require the count to halt at the exact hold value — it does not advance and does not blank — with the tint transition dropped under reduced-motion preference. "Value identical across the hold" is the layout-legible proof of the signature moment.

## Anti-patterns to avoid
- **No breakpoint or viewport-resize assertions.** §Decisions Log — Responsive breakpoints records N/A for this surface (desktop-bound single-station console); a driver leg resizing to probe per-breakpoint behaviour would assert a rule the plan says does not exist.
- **Do not treat the four screens as routes/pages.** §Surface: desktop-webview / Primary screens explicitly rejects that framing ("one surface in different run states, not four routes"); a page-object model built on routes encodes a layout the plan forbids.
- **No test-only operator-visible chrome.** §Component — Footer restricts the status strip to operational state (no links, no brand chrome), and §Surface: cli — Component Header / banner forbids an always-on banner. A self-verify mode indicator added to the console or harness output would be new chrome the layout does not sanction.

## Contract bindings
- **layouts ↔ a11y** — §Component — Header requires accessible names on the icon-only window controls and §Component — Primary navigation / §Component — Hero require the visible focus ring and focus trap, but §Notes states a11y derives the concrete attributes. Layouts owns the affordance's position and existence; a11y owns the name/role/live-region the shipped specs and any axe run assert. The chunk's `a11y-plan.md` §3 amendment sits on that seam.
- **layouts ↔ tests/harness** — §Surface: cli — Primary screens owns the `agent-run` command/stage-flag enumeration; `test-plan.md` §2/§9 owns the gate semantics (the entry's "Test Commands gate" clause). A new self-verify stage moves both, in their own docs, at wrap.
- **layouts ↔ design** — §Notes restricts this plan to role and token names (`count-hold`, `color-focus`, `border-emphasis`, `status-residual`); any color/contrast value a driver-side assertion needs comes from design-system, not here.

## Acceptance criteria contributions
- (layouts) Every driven affordance is one named in the run-console wireframes — scenario/suite picker · Start · Stop · minimize/close · coverage-matrix row · Proceed · Abort · checklist row — and is reached by driving run state, never by a route or URL (per layout-templates.md §Wireframe — Run console (idle) / §Component — Primary navigation).
- (layouts) A click leg aimed at a window control lands on the control glyph and not the `data-tauri-drag-region` band, so activation is not consumed as a window drag (per layout-templates.md §Component — Header).
- (layouts) Any affordance proved by click has a keypress equivalent available and its focus position is visible via the `color-focus` ring, since keybindings are first-class on this surface (per layout-templates.md §Component — Primary navigation).
- (layouts) If a self-verify stage or Windows harness path lands, §cli Primary screens' `agent-run` 5-command + `--unit`/`--integration`/`--e2e` enumeration is amended at wrap to name it — never left implicit (per layout-templates.md §Surface: cli — Primary screens).
