# obs extract

## Relevance
**Partial** — the chunk's deliverable (a Windows WebDriver probe + agent-driven spec execution) is tests/a11y-owned, but it drives the **desktop-webview** surface, which obs-plan governs: the Tauri backend/frontend self-obs sinks, the `tauri.command.*` handler spans, `run_id` correlation, and the no-host-path redaction that a Windows host stresses hardest.

## Constraints
- **Frontend self-obs during any driven session is console JSON only** — obs-plan §1 (desktop-webview surface row) + §11 Universal require NO OTel JS SDK, NO `auto-instrumentations-web`, NO browser OTLP exporter, and explicitly no `:4318` (dead port + recursion trap). A driver/wdio path must not add a network telemetry exporter to harvest evidence (per obs-plan.md §1, §11 Universal).
- **Tauri backend self-obs is `logs/conductor-tauri.jsonl` unconditionally**, stderr only as an open-failure fallback; nothing in the self-obs stack writes stdout and there is no pretty layer — so log evidence from a driven window must be read from that file, not from captured stdout (per obs-plan.md §3 Logging stack / §6 Sink configuration).
- **If the probe drives an affordance that starts/stops a run**, obs-plan §4 (desktop-webview auto-instrumentation row + Both-surface parity scenario) requires the `#[tracing::instrument]` command-handler span over `#[tauri::command]` with `run_id` as the correlation key — never a W3C `traceparent`. *Whether the shipped handlers already carry those spans is research's question.*
- **Both-surface parity is a `runs.db` envelope comparison** (same seed ⇒ same verdict/state, matched by `(scenario, seed)`), never trace correlation — a GUI-driven run compared to a CLI run must be graded that way (per obs-plan.md §3 Correlation + §4 Both-surface parity).
- **No absolute host-file paths in any log/artifact** — the redaction anchor names drive-letter `X:\`, `%APPDATA%`, `~/.cargo`, `.rustup` and backtrace file paths; the allowlisted `target` module path is preserved; redaction applies at the **processor** stage, never sink-only (per obs-plan.md §9 Log conformance check + §11 Logs / PII Scrubbing). This is the live hazard on a Windows host whose driver/bundle paths are all `C:\…`.
- **If a self-verify stage enters `scripts/agent-run.{sh,ps1}`, agent mode stays a READ-ONLY trigger** — `agent_mode = flag || env-set`; Conductor never WRITES `CONDUCTOR_AGENT_MODE`, the harness/operator exports it, and the flag is a WRITER switch, not a format switch (per obs-plan.md §3 Logging stack — agent-mode flag).
- **Zero unlogged panics** — a panic in the driver-attached binary must be captured by the panic hook and rendered as a `tracing::error!` JSON event; unstructured `^thread.*panicked` text fails the gate (per obs-plan.md §10 + §9 Zero-unlogged-panics gate).

## Patterns to follow
- **Desktop-webview command instrumentation:** plain `#[tracing::instrument]` on the `#[tauri::command]` handlers (`start_run` / `stop_run` / `run_report` / `resolve_operator_hold`), rendered as JSON log events — no OTel SDK, no framework auto-instrumentation (obs-plan.md §1 desktop-webview row, §4 auto-instrumentation table).
- **Self-obs line shape to assert against:** the §3 base set (`timestamp_ms`, `level`, `target`, `service.name` / `service.version` / `deployment.environment`, `run_id`) plus the span-lifecycle variant (`span`, `span_event` = `new` | `close`, optional `parent`, allowlisted attributes on `new`) — a §4 span materializes as real lines, which is what a driven-session assertion should read (obs-plan.md §3 two record shapes).
- **Service identity resolution:** `conductor-tauri` (backend) / `conductor-ui` (browser frontend), `$CONDUCTOR_SERVICE_NAME` override, `deployment.environment` from `$CONDUCTOR_ENV` (default `local`); CI adds `ci.run.id` + `git.commit.sha` (obs-plan.md §3 Service identity, §9 CI-specific resource attributes).
- **Witness-on-`message` pattern:** any new shape/identity witness (e.g. driver session, tool result key set) carries **names only, never values**, on the allowlisted `message` field — a field name outside `conductor-core::redact::ALLOWLISTED_FIELDS` is dropped at the processor stage and emits nothing (obs-plan.md §6 Boundary-call wrappers).
- **Live-counter `Channel` is UI state, not telemetry** — the `conductor.tick` / emission-counter stream is unstructured data for rendering; a spec asserting on it is asserting UI state, not a telemetry signal (obs-plan.md §3 Heartbeat ticks).

## Anti-patterns to avoid
- NEVER introduce an OTel JS SDK, browser OTLP exporter, or any `:4318`/`:4317` self-observation export into the webview or the wdio/driver path to capture drive evidence — recursion guard; self-obs is stderr/file/console JSON on every surface including the frontend (obs-plan.md §11 Universal).
- NEVER let Windows host paths (driver binary path, `node_modules/.bin` shim path, bundle path, backtrace paths) reach a log line, run-report artifact, or `runs.db` row unredacted (obs-plan.md §11 Logs).
- NEVER add a span name outside the bounded set (`tauri.command.*` wildcard covers new command handlers; `{module}.{operation}` convention, no per-session/per-path-with-input names) if the probe adds instrumentation (obs-plan.md §11 Spans / Traces).

## Contract bindings
- **obs ↔ tests harness** — test-plan §3 OWNS the JSONL/log format and obs §3 reproduces it (D-tests-obs-harness is two-sided). The chunk's wrap amendment touches `.andromeda/test-plan.md` §2/§9 platform framing; if "headful self-verify available" makes ui-smoke a Test Commands gate, obs-plan §9 artifact rules (upload `logs/agent-latest.jsonl`, log-conformance gate on the §3 base schema, zero-unlogged-panics gate) bind to that stage and any one-sided edit must be flagged.
- **obs ↔ a11y** — a11y-plan §3 reproduces the obs §6 envelope verbatim for its structured violation JSON, tags artifacts with obs §3 service identity, and inherits the no-host-path/no-struct-name constraint. This chunk *enables* those specs to run (running the sweep is v2-22's scope), so the binding is inherited unchanged, not re-authored here.
- **obs ↔ security** — redaction lives single-location in `conductor-core::redact` at the processor stage (obs-plan.md §11 PII Scrubbing); a Windows-path leak in a new artifact is a security-plan §2 anti-pattern as well as an obs one.

## Acceptance criteria contributions
- (obs) No OTel JS SDK, `auto-instrumentations-web`, browser OTLP exporter, or `:4318`/`:4317` self-observation endpoint is introduced into the webview, wdio config, or driver path; frontend evidence stays `console.log` JSON (per obs-plan.md §1 desktop-webview surface + §11 Universal).
- (obs) Every log line / artifact produced by the probe or the driven session is free of absolute host-file paths (drive-letter `X:\`, `%APPDATA%`, `~/.cargo`, `.rustup`, backtrace file paths); the allowlisted `target` module path is preserved (per obs-plan.md §9 Log conformance check + §11 Logs).
- (obs) If a run is started through the driven window, its lines carry `run_id` and a `tauri.command.*` handler span from the bounded span-name set, with correlation by `run_id` and parity judged by the `runs.db` envelope — never a `traceparent` (per obs-plan.md §4 Both-surface parity + §11 Spans / Traces); whether the shipped handlers already emit those spans is research's question.
- (obs) No unstructured panic line (`^thread.*panicked`) appears in `logs/conductor-tauri.jsonl`, `logs/agent-latest.jsonl`, or stderr from the driver-attached binary (per obs-plan.md §10 + §9 Zero-unlogged-panics gate).

## Relevant amendment history
- **2026-08-10-scenario-run-root-span-tree — Tauri command-span names reconciled to the shipped handlers** (§1 desktop-webview row · §4 Both-surface parity): `start_scenario`/`stop_scenario`/`get_run_report`/`operator_pause_go_no_go` → `start_run`/`stop_run`/`run_report`/`resolve_operator_hold`, and `tauri.command.start_scenario` → `tauri.command.start_run`. **Why it matters here:** this chunk drives those exact handlers through real controls; the pre-2026-08-10 names match no shipped handler, so any spec or assertion citing the old names is citing retired text.
- **2026-08-10-scenario-run-root-span-tree — self-obs span-lifecycle line variant recorded** (§3): before that chunk the layer implemented only `on_event`, so spans emitted nothing at all. **Why:** it is the reason a driven-session assertion can expect `span` / `span_event` lines rather than only event lines.
- **2026-08-22-operator-pause-and-checklist-live-firing — self-obs sink corrected: stderr never stdout, JSON never pretty** (21 sites, incl. §1 desktop-webview row + §3 sinks): the Tauri backend file sink is UNCONDITIONAL with stderr as an open-failure fallback; the earlier "stderr (dev only)" dual-sink and "pretty-print in dev" framings are retired. **Why:** a probe harvesting a driven window's logs from stdout, or expecting pretty output, would be reading against a premise measured false at source.
- **2026-06-24-sanitized-stderr-agent-mode-logging — `CONDUCTOR_AGENT_MODE` reworded to a read-only trigger** (§3): Conductor reads `flag || env-set` and never writes the env (avoids edition-2024 `unsafe set_var`). **Why:** directly governs the chunk's "only if a self-verify stage becomes an agent-harness command" surface in `scripts/agent-run.{sh,ps1}`.
- **2026-06-15-log-error-boundary-redaction — redaction model reconciled to `conductor-core::redact`** (§6 CI gate · §11): the value scrub anchors on absolute host-**file** paths (drive-letter included) rather than `::` tokens; struct names are excluded by the field-name allowlist + `Display`-not-`Debug`; the `module::`-shaped `target` is preserved. **Why:** this is the amendment that makes the Windows drive-letter form an explicit redaction target — the failure mode most likely to be provoked by a Windows-host driver probe.
- **2026-06-27-obs-ci-conformance-gate — §9 gate asserts the §3 self-obs base schema, not the §6 envelope** (§9): `agent-latest.jsonl` is the per-line self-obs stream; the run-report envelope has its own, not-yet-built gate. **Why:** if this chunk's measurement feeds a new CI/agent-harness stage, the applicable field list is the §3 base set, not the eleven-field envelope.
