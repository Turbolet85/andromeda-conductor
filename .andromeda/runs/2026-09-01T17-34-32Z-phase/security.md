# security extract

## Relevance
Partial — relevant on three axes: dependency/supply-chain (a driver package or host binary acquisition + the carried `cargo audit` PREREQ), the Tauri bundled-webview/IPC trust boundary the driver attaches to, and spawn-through-PATH discipline in `wdio.conf.ts`. No auth/PII/secret surface is touched.

## Constraints
- Any npm dependency delta under `crates/conductor-tauri/ui/` (a Windows driver package, a new script's dep) MUST keep `npm audit --omit=dev` at **0 PRODUCTION** vulnerabilities with `package-lock.json` committed; dev-only transitive advisories in the non-shipping harness are accepted at dev-tree grain (per security-plan.md §Dependency Security, Frontend (npm) supply chain).
- A **host-installed** driver binary (`msedgedriver`, or a `tauri-driver` outside `node_modules`) sits in NEITHER audited tree — `cargo-audit`/`cargo-deny` cover only `Cargo.lock` and `npm audit` only the npm tree (per security-plan.md §Dependency Security). Minimal tier explicitly SKIPs signed-artifact/SBOM controls, so recording **provenance + version** for any acquired binary is the only available control, matching the scope's "explicit, recorded step" rule.
- The carried 41st `cargo audit` deferral discharges ONLY under the advisory-DATABASE-fault remedy: a **bounded wait** with `cargo deny check advisories bans licenses sources` VERIFIED green (never assumed) — never a floor raise, never a `deny.toml` ignore, never a CI edit (per security-plan.md §Dependency Security, two-fault split). If this chunk admits a package node (cargo or otherwise), the deferral's basis must be re-stated on the NEW lock rather than reusing "no dependency delta" (per security-plan.md §Dependency Security, 2026-08-16 admission condition).
- Any driver/child spawn (the `onPrepare` `tauri-driver` launch, an `msedgedriver` hand-off) MUST use a fixed hard-coded program NAME resolved through the inherited `PATH` or a repo-derived path constant — never a config-derived or operator-supplied command string, never a shell/`eval` with operator input; `PATH` is itself a spawn-resolution input and a mis-resolution surfaces as a false blocked/failed result indistinguishable from a genuine one (per security-plan.md §Security Anti-Patterns → Input and → Code Patterns).
- The WebDriver server a driver opens is a **dev-only loopback** harness listener; the shipped `conductor-tauri` / `conductor-cli` binaries must gain no inbound listener of Conductor's own, and no test-harness bind may be promoted into a general-purpose listener — the sole sanctioned bind remains the `:4317` port-occupier fault (per security-plan.md §Security Anti-Patterns → Universal and → API; §Threat Model Summary, Attack surface).
- Driving the real window exercises the Tauri IPC trust boundary (per security-plan.md §Threat Model Summary, Attack surface — Tauri IPC). The bundle under drive MUST carry a deny-by-default capabilities file allowing only the actual commands plus the one live-counter `Channel`, and MUST embed no remote-origin iframe (per security-plan.md §Security Anti-Patterns → Code Patterns). Whether the shipped bundle already satisfies both is research's question.
- `tauri` ≥ 2.10.3 is a required bump against origin-confusion CVE-2026-42184, which is specifically a **Windows** exposure — exactly this chunk's premise of running the real bundle on this host (per security-plan.md §Dependency Security, Update policy; §Security Anti-Patterns → Universal, "never skip bumping a pinned dependency flagged by research"). Whether the locked version is already ≥ 2.10.3 is research's question; the 2026-06-15 amendment deferred that remit to the Tauri GUI work.

## Patterns to follow
- The dev-tree accept: gate production deps strictly (`npm audit --omit=dev` = 0) and accept dev-only transitives at dev-tree grain — the npm analogue of the `deny.toml` justified-exception mechanism (per security-plan.md §Dependency Security). The a11y/GUI harness tooling (`@crabnebula/tauri-driver`, `webdriverio`, `axe-core`, `lighthouse`, `tsx`) is already the registered dev tree.
- The `deny.toml` justified-exception shape: one entry per accepted advisory/license with a justifying comment, `deny.toml` itself as the authority on the full set (per security-plan.md §Dependency Security, Accepted exceptions).
- The sanctioned spawn shape already used for the MCP sidecar — a compile-time program-name constant resolved through the inherited environment, config never reaching argv (per security-plan.md §Security Anti-Patterns → Input).
- Artifact hygiene for anything the probe records: read/spawn faults carry the error KIND only, never the path; artifacts carry verdict/state/identity fields without absolute host paths (per security-plan.md §Error Handling, run-report artifact sanitization; §Input Validation, committed-manifest row). If a self-verify stage lands in `scripts/agent-run.{sh,ps1}`, the agent-mode log path derives from `CONDUCTOR_RUNS_DIR` through the existing `resolve_under` traversal guard (per security-plan.md §Input Validation, non-path env-handle note).
- The deferral discharge form the scope carries: capture the audit exit code BEFORE any pipe, verify the deny overlap actually ran green, and state the changed basis when re-pinning (per security-plan.md §Dependency Security).

## Anti-patterns to avoid
- NEVER interpolate an operator- or config-supplied string (a driver location, an Edge/WebView2 install path, a bundle path) into a spawn argv or shell string to make the probe work (per security-plan.md §Security Anti-Patterns → Input, → Code Patterns).
- NEVER paper over the red `cargo audit` with a `deny.toml` ignore, an unexecutable floor raise, or a CI edit — the fault is the advisory DB, and suppression would look like compliance while changing nothing (per security-plan.md §Dependency Security).
- NEVER add a remote-origin iframe or an unscoped `shell-open` plugin to the bundled webview to make it drivable — both re-expose the IPC surface the threat model assumes is in-process-only (per security-plan.md §Security Anti-Patterns → Code Patterns).

## Contract bindings
- **CI security gate ↔ tests §CI Integration:** `.github/workflows/ci.yml` already carries `Supply-chain — cargo audit` / `cargo deny check` (:74-78) and `Frontend gate (npm audit · build)` → `npm audit --omit=dev` (:163, :184). If a self-verify stage becomes a Test Commands gate, it must not restructure or weaken those jobs, and the carried deferral's "no CI edit" term binds here.
- **Tauri capabilities ↔ arch:** which commands the drivable bundle exposes is an arch capability decision; security only bans the permissive default (per security-plan.md §Security Anti-Patterns → Code Patterns).
- **Artifact path redaction ↔ obs:** PII scrubbing is N/A (no PII owned), but the absolute-host-path ban cross-cuts any journal/log the self-verify stage emits (per security-plan.md §Security Anti-Patterns → Logging).

## Acceptance criteria contributions
- (security) If any npm dependency lands under `crates/conductor-tauri/ui/`, `npm audit --omit=dev` reports 0 production vulnerabilities and `package-lock.json` is committed (per security-plan.md §Dependency Security).
- (security) `cargo deny check advisories bans licenses sources` VERIFIED green over the committed `Cargo.lock`, and the `cargo audit` exit code captured BEFORE any pipe, with the deferral re-pinned stating its basis — no floor raise, no `deny.toml` ignore, no CI edit (per security-plan.md §Dependency Security).
- (security) Every driver/binary spawn added or touched in `wdio.conf.ts` / any Windows script resolves a fixed program name or repo-derived constant — grep shows no operator- or config-supplied command string and no shell interpolation (per security-plan.md §Security Anti-Patterns → Code Patterns).
- (security) The bundle under drive adds no inbound listener beyond the dev-only loopback driver port, no remote-origin iframe, and no unscoped `shell-open`; the locked `tauri` version is checked against the ≥ 2.10.3 Windows origin-confusion floor and any gap recorded (per security-plan.md §Security Anti-Patterns → Universal, → Code Patterns; §Dependency Security).
