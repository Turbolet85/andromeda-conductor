## Constraints
- The plan's standing agent-driven invariant requires every test layer to be runnable end-to-end by an agent reading exit codes + structured output, and requires a surface that CANNOT be agent-driven to be **flagged untestable** rather than given an invented driver (per test-plan.md §preamble "Agent-driven invariant" + §1 Untestable zones). This is the mandated disposition for a failed probe: flag + record, never a relaxed claim.
- test-plan.md §6 (drivers-per-surface, desktop-webview row) mandates @crabnebula/tauri-driver via `wdio run` **headless** with mode recorded as "Linux + `xvfb`", justified only by "no WKWebView WebDriver on macOS" — Windows is never named. Changing that mode field is a wrap amendment to the plan, not a phase edit (per test-plan.md §6 + §9 Matrix builds).
- The "Linux-only" claim is duplicated at **six** plan sites — §3 Bootstrap phases (5-command-discipline-wire, :207), §6 drivers row (:304), §6 Both-surface-parity GUI leg (:369), §9 stage table (:456), §9 Matrix builds (:465), §12 Decisions Log E2E-driver bullet (:594). The plan's own two-site rule (established 2026-08-18, applied through 2026-08-22) requires every site stating the claim to move in one pass (per test-plan.md §6/§9/§12 + amendment history below).
- If a self-verify stage becomes a harness command, test-plan.md §3 (Bootstrap phases → 5-command-discipline-wire) requires `scripts/agent-run.sh` and `.ps1` to expose **identical semantics**, and §3 (`run` → CI stage selectors) requires the webview leg to attach under the mutually-exclusive `--e2e` selector, matching §9's stage table. Whether the shipped `agent-run.{sh,ps1}` already implements `--e2e` at all is research's question.
- test-plan.md §6 Selector strategy + §11 E2E require the executed specs to assert role / text / `data-testid` / `aria-live` and brand anchors only — the closed six-label lamp set plus the run-level `[ENVIRONMENT-SUSPECT]` qualifier, `role="alertdialog"`, the "HOLD — operator pause" heading, mono P-ID tokens — never xpath, never hashed CSS classes, never visual-pixel comparison.
- test-plan.md §10 (Zero-flakiness budget) forbids any retry policy: a driver leg that flakes once is quarantined and fixed at the cause, and a result that depends on the runner/environment is a determinism break, not a knob to pin. §10 build-failure conditions also bind `tauri` ≥ 2.10.3 and an un-drifted committed `Cargo.lock` to any dependency the probe adds.
- The webview surface stays **secondary to the cli release gate** (per test-plan.md §1 Surfaces under test + §6 drivers row); a successful probe promotes the leg's runnability, it does not make the GUI the gate.

## Patterns to follow
- **Measured-reality re-basing** (per test-plan.md §6 scenario blocks + the harvest-tier precedent recorded across §1/§5/§6): when a mandated witness is measured not to work, the shipped pattern is to re-base the claim at the tier that CAN prove it, record the measurement verbatim in the artifact, and amend both/all sites — never to soften the wording. This is the template for either probe outcome.
- **Gated-leg discipline** (per test-plan.md §9 Live-Pulse scenarios, as widened 2026-08-31): a leg deliberately kept out of default runs (cargo-feature gate; by extension a display/driver-availability gate) is a sanctioned path, but it is invisible to the default lint/test pass and therefore OWES its own explicit invocation command. Re-expressing the display gate as a driver-availability gate should follow this precedent's shape.
- **Stage-selector mapping** (per test-plan.md §3 `run` → CI stage selectors + §9 stage table): `--e2e` ⇒ the tauri-driver `wdio run` leg; `--unit`/`--integration` unchanged. A new self-verify command must map into this existing three-selector split rather than becoming a sixth harness verb.
- **Frontend build gate for `conductor-tauri/ui`** (per test-plan.md §4, conductor-tauri/ui bullet): the ui package carries no Rust/nextest unit tests and is build-gated by `tsc --noEmit` + `vite build` + `npm audit` + a `vite preview` render smoke. Any `package.json` change this chunk makes re-enters that gate (and `npm audit` is the security edge of it).
- **Runner-portability + the standing suite gates** (per test-plan.md §4 Framework): workspace green under BOTH `cargo nextest run` and `cargo test -p <crate>` remains the baseline any chunk must not regress, independent of the webview work.

## Anti-patterns to avoid
- Never author or run the webview leg through an interactive/recorder tool — no WebdriverIO codegen-recorder or inspector, no Percy / Chromatic / Applitools, no "human reviews screenshots" step; headless `wdio run` only (per test-plan.md §11 Universal + §2 Agent-runnable invariants). The `drive+observe` operator visual judgment is the ONE flagged exception (§1 Untestable zones).
- Never synchronize a webview leg with `sleep(N)` and never select by xpath or hashed Tailwind/CSS class — wait on an explicit signal (element role / `aria-live` / envelope `state` / exit code) (per test-plan.md §11 E2E).
- Never let a process-proxy stand in for the affordance claim, and never treat a reported state (`Blocked`/`ManualCheck`/`KnownResidual`/`CalibrationRegion`) as a non-zero process exit (per test-plan.md §11 Mocking "NEVER over-stub" + §11 E2E stack-specific ban).

## Contract bindings
- **tests ↔ a11y:** test-plan.md §6 Selector strategy depends on the a11y Color-Only rule (every lamp text/role-paired) to guarantee reliable selectors; the driver this chunk probes is the mechanism the a11y sweep (v2-22) and any a11y CI gate (v2-24) would run on. Per the focus guide, wiring a11y assertions into the 5-command discipline is tests-owned (§3), while the WCAG criteria themselves are a11y-plan's.
- **tests ↔ obs:** test-plan.md §3 Log format is the SOURCE OF TRUTH that obs-plan §3 derives from; the per-run emission journal (`runs/<run_id>.jsonl`) and the self-obs stream (`logs/conductor-tauri.jsonl` for the Tauri backend) are distinct artifacts that must not be conflated. A self-verify stage that writes anything to either binds here.
- **tests ↔ security:** §4's ui gate includes `npm audit`, and §10/§9 build-failure conditions bind `cargo audit --deny warnings` + `cargo deny check` green, un-drifted `Cargo.lock`, and `tauri` ≥ 2.10.3 — the gate any driver-binary/npm dependency acquisition passes through (and the chunk's PREREQ `cargo audit` re-check lands on the same surface).
