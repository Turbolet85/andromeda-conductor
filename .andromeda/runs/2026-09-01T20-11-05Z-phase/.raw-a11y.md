# a11y extract

## Relevance
Relevant — this chunk is entirely inside the a11y domain: it calibrates the `--e2e` axe/contrast/keyboard/motion leg that a11y-plan.md §3/§5/§6/§10 specify.

## Constraints
- Baseline tag scope is fixed at `withTags(['wcag2a','wcag2aa','wcag21aa'])` with `wcag22aa` unset; the `target-size` rule is `wcag22aa`-tagged and therefore must NOT run in this gate (per a11y-plan.md §3 A11y testing tool pick → Configuration, and §6 Target size tokens). The chunk's "Minimal tier stays the baseline" invariant is the same rule.
- The gate is fail-fast and absolute: zero WCAG AA violations across the four must-be-accessible paths, `violations.length &gt; 0` ⇒ non-zero exit, no retry-once policy, no soft/warning SLO (per a11y-plan.md §10 SLO Invariants). Build-failure conditions there also name not-color-alone failure and reduced-motion-not-dropped as gate failures in their own right, not just axe violations.
- The four must-be-accessible paths the leg has to actually assert are scenario pick/start, operator-pause go/no-go (HOLD), run-report view, and operator-checklist — each with its named roles and focus order (per a11y-plan.md §1 Critical paths and §4 per-component pattern catalog). Two of the five existing `it()` blocks target the HOLD dialog and checklist rows, i.e. paths 2 and 4.
- The HOLD `alertdialog` trap composition is the post-2026-08-22 shape: Tab/Shift+Tab cycles across the operator-checklist `checkbox` rows (when the hold declares `[[checklist]]` items) and then Proceed/Abort; Space toggles a focused row; `aria-checked` per row; Escape must escape the trap (SC 2.1.2); focus restores to the triggering control on close (SC 2.4.3) (per a11y-plan.md §3 Focus management test harness, §4 operator-pause row, §5 Focus trap / Focus restoration).
- One webview-automation stack only — axe injects via `@axe-core/webdriverio` into the tests-plan §6 `@crabnebula/tauri-driver` + WebdriverIO session; standing up a parallel puppeteer/CDP stack is banned (per a11y-plan.md §3 A11y testing tool pick and §11 CI). This matches the chunk's "no new automation stack" scope law.
- Contrast is asserted by token NAME, not by literal color: the nine foreground/background pairs in the §6 table (`--text-primary`/`--color-base` … `--color-focus`/`--color-base`) at 4.5:1 (SC 1.4.3) / 3:1 (SC 1.4.11), via axe `color-contrast` plus the colorjs.io token-name checker; raw values stay in design-system.md (per a11y-plan.md §6 Color contrast pairs and §3 Contrast verification harness).
- Not-color-alone keys on the six LAMP display labels (`Pass`/`HOLD`/`Fail`/`Blocked`/`Manual`/`Residual`) plus glyph supplement; the `--status-residual`-tinted coverage-matrix out-of-scope Mode cell is a coverage-mode classification, not a seventh lamp state, and must not be counted against the six-label assertion (per a11y-plan.md §6 State color tokens, and §1 A11y triggers → non-lamp reuse note).
- Artifacts must not leak absolute host paths or internal seam-crate struct names; node targets are stored as DOM-relative selectors / `data-testid` (per a11y-plan.md §3 Structured violation JSON schema and §11 SLO). This is the plan-side twin of the chunk's redaction invariant.

## Patterns to follow
- Focus assertion pattern: `browser.keys(['Tab'|'Shift+Tab'|...])` then `browser.execute(() =&gt; document.activeElement?.getAttribute('data-testid'))` after each key, asserting trap entry, in-trap cycle, Escape-escape, and restoration to the trigger (a11y-plan.md §3 Focus management test harness). Note the plan's identity handle here is `data-testid`, while the chunk's invariant says selectors stay role/text/aria-live — `data-testid` is explicitly sanctioned by §3 for both activeElement identity and violation `target` storage, so the two are reconcilable, but which handle the existing specs use is research's question.
- Per-pattern keyboard sequence catalog to extend the specs against: button Enter/Space; dialog Tab/Shift+Tab + Space-toggle + Escape + Enter/Space activate; combobox Arrow/Enter/Escape/type-ahead; checkbox Space; coverage-matrix row navigation incl. off-screen virtual rows (a11y-plan.md §3 Keyboard test harness, §5 Focus order per layout).
- Trap and restoration are expected to come from shadcn AlertDialog over Radix Primitives — the harness asserts Radix-default behaviour rather than installing `focus-trap-react` / `react-aria` (a11y-plan.md §3 Bootstrap → focus-management-library-install, §12 Decisions Log). Whether the shipped dialog is in fact the Radix AlertDialog is research's question.
- Contrast/motion assertion output shapes the plan already specifies: `{ token_fg, token_bg, ratio, required, pass }` per pair, and `{ element, prop, value, reduced_motion_respected }` for the motion check (a11y-plan.md §3 Contrast verification harness, §6 Motion tokens) — reuse these field names rather than inventing new ones, even though envelope emission itself is deferred to `v2-24`.
- Reduced-motion drive path: `browser.emulate('prefers-reduced-motion','reduce')` with the documented OS-level / `CONDUCTOR_TEST_REDUCED_MOTION` fallback; a single emulation set is expected to persist across the four in-place run-STATES (no routes) (a11y-plan.md §6 Motion tokens).

## Anti-patterns to avoid
- Never narrow axe to make it green: partial configuration (`runOnly` excluding default rules such as `color-contrast`) requires an explicit Decisions Log entry, and no WCAG conformance may be claimed without machine-verifiable evidence (a11y-plan.md §11 Strategy). Fixing the one genuine violation at the rule level instead of the defect is the banned move here.
- Never assert vacuously or downgrade the gate to a warning — no retry-once, no soft SLO, and manual SR/keyboard/contrast may never be the sole method for a criterion (a11y-plan.md §11 SLO and §11 Universal). The chunk's context-skip-with-reason shape is compatible only because a skip is not a pass.
- Never fix a markup-side axe violation by bolting ARIA onto non-semantic HTML or hand-rolling `alertdialog`/`combobox` over `&lt;div&gt;`s; never `:focus { outline: none }` without the `--color-focus` ring, and never `tabindex` &gt; 0 (a11y-plan.md §11 ARIA and §11 Keyboard).

## Contract bindings
- **a11y ↔ tests:** the leg must ride the tests-plan §6 `@crabnebula/tauri-driver` + WebdriverIO (`wdio run`) session and surface results through the 5-command harness `logs` command; it stays an operator/local gate, not a CI gate (a11y-plan.md §3 CI integration, §9 Pipeline integration) — consistent with the chunk's boundary that the CI gate is `v2-24`.
- **a11y ↔ obs:** any violation artifact must align to the obs §6 envelope with axe rule-id + WCAG-SC tag + selector folded into `fingerprints[]`, `state` = `Fail` when violations exist, and `service.name` / `deployment.environment` resource attributes (a11y-plan.md §3 Structured violation JSON schema). The chunk defers emission to `v2-24`, so this binding constrains any shape introduced now, rather than requiring emission.
- **a11y ↔ design:** contrast token pairs, `--color-focus` vs `--border-emphasis` (focus vs selection, so focus is never color-only), and the reduced-motion drop enforced CSS-natively via the Tailwind v4.1 `motion-reduce:` variant over `--motion-micro`/`--ease-quiet` (a11y-plan.md §6 Focus ring tokens, §6 Motion tokens).
- **a11y ↔ layouts:** focus anchors for run-console-idle / live / HOLD / report-terminal drive the expected tab sequence per run-STATE (a11y-plan.md §5 Focus order per layout).

## Acceptance criteria contributions
- (a11y) axe-core runs over the desktop-webview with exactly `withTags(['wcag2a','wcag2aa','wcag21aa'])` (no `wcag22aa`, no rule exclusions) and reports `violations.length == 0`, with the leg exiting non-zero otherwise (per a11y-plan.md §10 SLO Invariants + §3 A11y testing tool pick). The identity of the currently-measured single violation, and whether its fix belongs in markup/ARIA or a token, is research's question.
- (a11y) On a driven run where the HOLD subject IS present, the operator-pause `alertdialog` asserts trap entry on open, Tab/Shift+Tab cycling across the checklist `checkbox` rows then Proceed/Abort with Space toggling a focused row, Escape escaping the trap (SC 2.1.2), and focus restored to the triggering control on close (SC 2.4.3) — a skip-with-reason when the subject is absent does not satisfy this (per a11y-plan.md §3 Focus management test harness + §5 Focus trap / Focus restoration).
- (a11y) Perceivable pair: the nine named token pairs assert 4.5:1 (SC 1.4.3) / 3:1 (SC 1.4.11) by token name, and each of the six lamp display labels carries its text label + glyph with the `--status-residual` Mode cell excluded from the six-label count (per a11y-plan.md §6 Color contrast pairs + §6 State color tokens).
- (a11y) Under `prefers-reduced-motion: reduce`, the count tint, focus-ring fade-in, status-light transition, and operator-pause dialog fade all collapse to none/0s (SC 2.3.3) — via `browser.emulate` or the documented OS-level / `CONDUCTOR_TEST_REDUCED_MOTION` fallback (per a11y-plan.md §6 Motion tokens). Whether `browser.emulate` functions under `wdio:enforceWebDriverClassic` on WebView2 is recorded-not-established by the plan, so which of the two drive paths this host needs is research's question.
