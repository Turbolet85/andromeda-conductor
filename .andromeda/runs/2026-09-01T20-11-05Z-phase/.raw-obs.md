# obs extract

## Relevance
Partial — the chunk's core work is a11y/tests, but obs binds at four points: the redaction boundary over every artifact the leg produces, the recursion guard on the webview under test, and the command-span / sink / zero-panic mandates that a *driven* live-Pulse leg exercises.

## Constraints
- Frontend self-observation in the Tauri webview is **console JSON only** — no OTel JS SDK, no `auto-instrumentations-web`, no browser OTLP exporter, and never `:4318` (dead port per arch); applies to anything the sweep wires into `ui/src/**` or the axe/wdio in-page surface (per obs-plan.md §1 telemetry-surfaces desktop-webview row, §11 Universal).
- No absolute host-file path (drive-letter `X:\`, `/home`, `/Users`, `%APPDATA%`, `~/.cargo`, `.rustup`, backtrace file paths) and no internal struct name may appear in any log, run-report or artifact; scrubbing is single-location in `conductor-core::redact` at the **processor** stage, never only at the sink, and the allowlisted `target` module path is preserved (per obs-plan.md §11 PII Scrubbing, §11 Logs, §9 Log conformance check). The leg's TS-side artifacts do not pass through the Rust layer, so whether an equivalent host-path guard exists on the wdio/axe output is research's question.
- Every `#[tauri::command]` handler must open a manual `tracing::info_span!("tauri.command.&lt;name&gt;").entered()` guard — the `#[tracing::instrument]` attribute does **not** stack with `#[tauri::command]` — with the name inside the bounded `tauri.command.*` set (per obs-plan.md §4 auto-instrumentation table, §11 Spans/Traces bounded span-name set). The driven leg's hold-raising path runs through `start_run` / `resolve_operator_hold`, two of the seven enumerated handlers; whether the code already carries the guard at every site it touches is research's question.
- Tauri backend self-obs writes `logs/conductor-tauri.jsonl` **unconditionally** (stderr only as an open-failure fallback), one `JsonObsLayer` over every writer — JSON, never pretty, never stdout; every self-obs line carries the base set `timestamp_ms` / `level` / `target` / `service.{name,version}` / `deployment.environment` / `run_id` (per obs-plan.md §3 Logging stack, §3 Log format JSON schema).
- Zero unlogged panics is the always-required invariant: a panic on the driven leg must be captured by `std::panic::set_hook()` + `tracing::error!` with the backtrace serialized to a **single** field; an unstructured `^thread.*panicked` line in the log or stderr is a gate FAIL (per obs-plan.md §10, §9 Zero-unlogged-panics gate).
- `RUST_LOG` discipline for the leg's invocation: a bare per-target directive **replaces** the default rather than adding to it — always pair as `info,{crate}=debug` — and never set either form for a run that also executes the test suite, because the environment reaches the runner's child processes (per obs-plan.md §6 Per-module log levels). `agent-run.{sh,ps1} run --e2e` dispatches `npm run a11y` as exactly such a child.
- Agent mode is a **read-only** trigger — Conductor reads `--agent-mode || CONDUCTOR_AGENT_MODE` and never writes it; the harness/operator script exports it. Relevant only if the leg's invocation in `agent-run.{sh,ps1}` changes (per obs-plan.md §3 Logging stack, agent-mode flag).

## Patterns to follow
- The manual `.entered()` command-span guard already prescribed for all seven handlers (`list_scenarios` · `coverage_matrix` · `unbacked_auto` · `run_report` · `start_run` · `stop_run` · `resolve_operator_hold`) — obs-plan.md §1 desktop-webview row / §4 auto-instrumentation table.
- The **message-field witness** pattern: when the useful identifier is not a name in `conductor-core::redact::ALLOWLISTED_FIELDS`, it rides the allowlisted `message` field rather than a dedicated attribute, which the processor stage would drop and emit nothing (precedents: the `verify.readback` observed-key-set witness, the `emit.batch` wire-shape witness, the `mark_incident_resolved` incident id) — obs-plan.md §6 Boundary-call wrappers, §4 attribute-allowlist constraint. This is the shape for any Rust-side log of an axe rule id or a skip reason.
- The **observed-not-requested** signal pattern: a condition the code cannot request but only observes is recorded on a `warn`-level line over the allowlisted `message` field (`verify.readback.observe` / `degraded_mode`) — obs-plan.md §4 Known-residual classification path. This is the closest existing precedent for making a context-skip ("subject absent") machine-distinguishable from a pass.
- Service-identity tagging is never hardcoded: `service.name` = `"conductor-tauri"` (backend) / `"conductor-ui"` (webview) with `$CONDUCTOR_SERVICE_NAME` override, `service.version` from `env!("CARGO_PKG_VERSION")`, `deployment.environment` from `$CONDUCTOR_ENV` default `"local"` — obs-plan.md §3 Service identity.
- Redaction applies at three sites, not one: the tracing-subscriber field filter, report generation on JSONL write, and runs.db insert validation — obs-plan.md §11 PII Scrubbing.

## Anti-patterns to avoid
- NEVER introduce an OTel SDK/exporter (Rust or JS) or any network OTLP for self-observation while instrumenting the webview under test — recursion guard plus `current_thread` determinism (per obs-plan.md §11 Telemetry Strategy, §11 Universal).
- NEVER emit unstructured stderr text or a multi-line stack trace as the leg's evidence — structured JSON-per-line or machine-parseable hints only (per obs-plan.md §11 Logs).
- NEVER add a second scrubbing implementation or scrub only at the sink — single-location ownership in `conductor-core::redact` (per obs-plan.md §11 PII Scrubbing).

## Contract bindings
- **obs ↔ a11y**: a11y-plan §3/§5 reproduces obs §3 Service Identity and obs §6 log-format envelope for its structured violation JSON, and inherits obs's no-absolute-host-paths / no-struct-names constraint. This chunk explicitly excludes building that envelope (deferred to `v2-24`), so obs's role here is a boundary guard — nothing the sweep emits now may pre-commit a violation-JSON shape that diverges from obs §6 + §3 identity tagging.
- **obs ↔ tests harness**: the JSONL format is OWNED by test-plan §3 and obs §3 aligns to it, not vice versa; the §9 conformance gate reads the §3 **self-obs base line** (`agent-latest.jsonl`), while the run-report envelope (`runs/&lt;run_id&gt;.jsonl`) has its own not-yet-built gate. Relevant because the `--e2e` leg is dispatched from the same `agent-run.{sh,ps1}` entry as the suite (per obs-plan.md §3, §9).
- **obs ↔ security**: the redaction path list is configured at the logger/processor stage (per obs-plan.md §11 PII Scrubbing) — the chunk's own "no absolute host paths in any artifact" invariant and the skip-arm's "host-path-free precondition" both rest on this boundary.

## Acceptance criteria contributions
- (obs) No artifact the leg produces — spec output, skip reason, axe report, console line, backend log — contains an absolute host path (drive-letter / `/home` / `/Users` / `%APPDATA%` / `~/.cargo` / `.rustup` / backtrace file path) or an internal struct name (per obs-plan.md §11 PII Scrubbing / §9 Log conformance check).
- (obs) The webview under test gains no OTel JS SDK, no browser OTLP exporter and no `:4318` traffic; any frontend telemetry the sweep adds is `console.log(JSON…)` only (per obs-plan.md §1 telemetry-surfaces desktop-webview row / §11 Universal).
- (obs) A driven live leg leaves zero unstructured panic lines (`^thread.*panicked`) in `logs/conductor-tauri.jsonl` or stderr; any panic appears as a one-line-serialized `tracing::error!` JSON event (per obs-plan.md §10 / §9 Zero-unlogged-panics gate).
- (obs) Every Tauri command handler the driven leg exercises or the chunk adds opens a manual `tracing::info_span!("tauri.command.&lt;name&gt;").entered()` guard whose name is inside the bounded `tauri.command.*` set (per obs-plan.md §4 auto-instrumentation table / §11 Spans/Traces bounded span-name set) — whether the code already satisfies this at the sites this chunk touches is research's question.
