## Relevance
Partial — the a11y assertion work itself is out of domain, but four security surfaces are live: the standing `cargo audit` PREREQ, the frontend npm supply-chain gate, the `CONDUCTOR_MSEDGEDRIVER` / harness-spawn boundary, and the no-host-paths redaction invariant.

## Constraints
- The 42nd consecutive audit re-check is an **advisory-DATABASE fault**, not a tool fault: the only sanctioned remedy is the bounded wait re-checked each chunk, with coverage carried by the audit↔deny overlap **verified** green rather than assumed — never a floor raise, never a `deny.toml` ignore, never a CI edit (per security-plan.md §Dependency Security, two-fault split).
- If this chunk admits any dependency node (a devDep for an extended spec, a bump to clear the axe fix), the "no dependency delta" basis for the deferral is no longer available and the delta may land only on `cargo deny check advisories bans licenses sources` verified green over the **new** lockfile (per security-plan.md §Dependency Security, admitting-a-new-dependency-under-a-red-audit rule).
- Any change under `crates/conductor-tauri/ui/` must keep the frontend gate satisfied: `npm audit --omit=dev` clean at 0 **production** vulnerabilities with `package-lock.json` committed; dev-only transitive advisories in the non-shipping a11y/driver tooling are accepted at dev-tree grain, production advisories are not (per security-plan.md §Dependency Security, Frontend (npm) supply chain).
- `CONDUCTOR_MSEDGEDRIVER` is a dev-harness-only path boundary whose duty is discharged at the wdio edge — existence + `isFile` + shell-metacharacter rejection before the driver spawn, then passage as a **separate element of an array-form argv**; unset-or-not-a-file must skip at exit 0 with a host-path-free precondition. It is deliberately outside the Rust-side `canonicalize` rule because no Rust code reads it (per security-plan.md §Input Validation, boundary table; §Security Anti-Patterns → Input).
- The harness-spawn rule requires the driver **program** to be a repo-derived resolved constant, never a bare PATH name and never operator-chosen; an operator-supplied value may appear only as an argv array element after metacharacter rejection, never as the program nor inside a shell string. This binds if the skip shape forces a `wdio.conf.ts` edit (per security-plan.md §Security Anti-Patterns → Code Patterns (b)).
- Anything the leg surfaces to the operator or writes as an artifact must stay sanitized: no absolute host paths (canonicalized `CONDUCTOR_*` dirs, `ANDROMEDA_PULSE_DATA_DIR`), no internal seam-crate struct/field names, no stack traces — at the `anyhow` / `#[tauri::command]` edge and in `&lt;run_id&gt;.md` / `runs.db` rows alike (per security-plan.md §Error Handling; §Security Anti-Patterns → Logging).
- The chunk's `--features tauri/custom-protocol` release build on a Windows host is exactly the surface of the required `tauri` ≥ 2.10.3 bump (origin-confusion CVE-2026-42184); the plan states this as a required bump over the architecture's 2.10.1 pin. **Whether the workspace already resolves ≥ 2.10.3 is research's question** (per security-plan.md §Dependency Security, Update policy; §Security Anti-Patterns → Universal, last bullet).

## Patterns to follow
- The existing `UNSAFE_PATH` guard in `wdio.conf.ts` is the sanctioned shape for a harness-edge path boundary (validate → array-form argv → skip-with-precondition); extend around it rather than re-deriving a validation path (per security-plan.md §Input Validation, `CONDUCTOR_MSEDGEDRIVER` row).
- The `deny.toml` justified-exception mechanism (each entry carrying its comment; `deny.toml` itself is the authority on the full set) is the route for any non-actionable advisory or permissive-license addition surfaced by a dependency delta (per security-plan.md §Dependency Security, Accepted exceptions).
- Dev-tree-grain acceptance via `--omit=dev` is the npm analogue of that same mechanism for the non-shipping test tooling — reuse it, do not add an audit-suppression tool (per security-plan.md §Dependency Security, Frontend (npm) supply chain).
- Named, host-path-free precondition strings — the discipline the preflight's distinct `blocked` state already carries — is the shape the context-skip reason should follow: a specific named cause, never a generic string and never a path (per security-plan.md §Security Anti-Patterns → Universal, never-silently-downgrade; §Error Handling).

## Anti-patterns to avoid
- Never paper over the red audit: no `deny.toml` ignore for RUSTSEC-2026-0244, no unexecutable floor raise, no CI edit, no silent accept (per security-plan.md §Dependency Security).
- Never let an absolute host path or an internal struct name reach a spec assertion message, a skip reason, or any artifact the leg writes (per security-plan.md §Security Anti-Patterns → Logging).
- Never introduce a remote-origin iframe into the bundled webview, and never reach for an unscoped `shell-open` plugin, while fixing markup/ARIA for the axe violation — both re-expose the IPC surface the threat model assumes is in-process-only (per security-plan.md §Security Anti-Patterns → Code Patterns).

## Contract bindings
- **CI security gate ↔ tests §CI Integration:** the `npm audit --omit=dev` frontend gate lives in the existing workflow beside the cargo audit/deny steps. The scope keeps the a11y leg an operator/local gate (v2-24 owns the CI gate), and the advisory-DB remedy forbids CI edits — so the binding here is "leave the security gate job untouched," not "extend it."
- **Redaction ↔ a11y/obs:** the service-tagged violation-JSON envelope **and its redaction boundary** are explicitly deferred to v2-24, so security's only redaction claim on this chunk is the generic no-host-paths rule over whatever the leg emits today (skip precondition, spec failure text, run-report rows).
- **Dev-harness tooling ↔ tests:** any new devDep the extended specs need registers into the dev tree the `--omit=dev` gate is scoped over, and its advisories take the dev-tree-grain accept — not a production exception.

- (security) PREREQ discharged in COMPACT form: `cargo audit` true exit **1** with first diagnostic `duplicate advisory ID: RUSTSEC-2026-0244`, and `cargo deny check advisories bans licenses sources` true exit **0**, each exit code captured BEFORE any pipe; any deviation restores the full form (per security-plan.md §Dependency Security).
- (security) if any dependency node lands (npm or cargo), `npm audit --omit=dev` reports 0 production vulnerabilities with `package-lock.json` committed, and the deny check is verified green over the NEW lockfile with the deferral's changed basis restated (per security-plan.md §Dependency Security).
- (security) the `CONDUCTOR_MSEDGEDRIVER` unset/not-a-file arm still exits 0 with a host-path-free precondition, and existence + `isFile` + shell-metacharacter rejection + array-form argv with a repo-derived resolved program survive any `wdio.conf.ts` edit (per security-plan.md §Input Validation; §Security Anti-Patterns → Code Patterns).
- (security) no artifact or operator-visible string this chunk's leg produces — skip reason, spec assertion message, run-report row — contains an absolute host path or an internal seam-crate struct name (per security-plan.md §Error Handling; §Security Anti-Patterns → Logging).
