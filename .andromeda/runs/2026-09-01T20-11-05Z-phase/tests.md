## Relevance
**Relevant** — the chunk's whole surface is the `--e2e` desktop-webview leg, which test-plan.md owns end-to-end (§2 agent-runnable invariants, §3 harness `run --e2e`, §6 E2E drivers/selectors, §9 CI, §10 gates, §11 E2E/Universal bans).

## Constraints
- The desktop-webview driver is tauri-driver via WebdriverIO `wdio run`, **non-interactive only**, asserting **role/text/`aria-live` selectors ONLY** — no visual-pixel comparison; on the Windows host it runs headful via WebView2 with an operator-supplied `msedgedriver` gated on `CONDUCTOR_MSEDGEDRIVER`, and **unset or not-a-file must skip at exit 0** (per test-plan.md §6 Drivers per surface, desktop-webview row).
- The selector anchor set is **named, not invented**: `role="alertdialog"` on the operator-pause dialog, `aria-live` HOLD/verdict announcements, the signature heading text "HOLD — operator pause", the closed six-label lamp set `[PASS]/[FAIL]/[HOLD]/[MANUAL]/[RESIDUAL]/[BLOCKED]` plus the run-level non-lamp `[ENVIRONMENT-SUSPECT]` qualifier, and mono P-ID tokens (the manifest's accepted set) (per test-plan.md §6 Selector strategy).
- The `--e2e` stage selector has a mandated invocation chain — ensure-frontend → release build with `--features tauri/custom-protocol` (the *feature*, not `--release`, decides bundle embedding) → `wdio run` — and `scripts/agent-run.{sh,ps1}` must expose **identical semantics in both shells**, the webview leg included (per test-plan.md §3 CI stage selectors + §3 Bootstrap `5-command-discipline-wire`).
- A driven live-Pulse leg is an **operator/local gate, never a CI gate**, and must ride one of the three sanctioned invocation paths (`workflow_dispatch`, `scripts/agent-run.sh`, or a gated test file invoked directly) (per test-plan.md §9 Live-Pulse scenarios + §11 CI).
- Zero-retry flakiness budget: a flake is quarantined and fixed at the **root cause**, never absorbed by a retry knob; an environment-dependent green is a determinism break to remove at the cause, not a runner/host to pin to (per test-plan.md §10 Zero-flakiness budget).
- `blocked` / `ManualCheck` / `KnownResidual` / `CalibrationRegion` are **reported states, never non-zero exits** — a driven leg whose run lands declare-only or Blocked must not read that as a leg failure (per test-plan.md §11 E2E, stack-specific).
- The frontend carries **no JS/TS unit runner** (not adopted; GUI is convenience-only), and the build gate (`tsc --noEmit` + `vite build`) explicitly **does not prove ESM loadability** — e2e harness config and its members are proven only by EXECUTING the leg (per test-plan.md §4 conductor-tauri/ui + §12 Open questions).

## Patterns to follow
- **Precondition-absent ⇒ exit 0 with a reason** already exists at the harness level as the `CONDUCTOR_MSEDGEDRIVER` skip arm in both shells; the chunk's new spec-level context-skip shape should mirror that shape rather than introduce a second convention (per test-plan.md §6 desktop-webview row, §9 pipeline table).
- **Grade the unreachable claim in a separate, operator-gated leg** — the harvest-tier precedent (`*_harvest.rs` files driven by the feature-gated live leg) is the plan's established answer to "the routine leg cannot reach this subject; assert it hard, out of band, once" (per test-plan.md §6 scenario verification signals + §9 Live-Pulse scenarios).
- **Name the SET, never a fresh literal** — the selector strategy and the label enumerations were deliberately de-hardcoded to sets so they do not re-stale; any re-aimed assertion should follow (per test-plan.md §6 Selector strategy).
- **Text/role pairing is what makes selectors reliable** — §6 grounds the selector strategy in the Color-Only a11y rule, so the chunk's not-color-alone assertion and its selector discipline are the same invariant seen from two sides (per test-plan.md §6 Selector strategy + §11 E2E).
- **Measured, not assumed** — the plan repeatedly re-bases claims onto what a leg was observed to prove (the cli stdin-closed leg proving no-hang only; the platform verdict). Naming the axe rule by identity before designing its fix is the same discipline (per test-plan.md §6 Drivers per surface, cli row).

## Anti-patterns to avoid
- NEVER xpath, NEVER hashed Tailwind/CSS-class selectors, and NEVER `sleep(N)` for synchronization — wait on an explicit signal (element role / `aria-live` / envelope `state` / exit code) (per test-plan.md §11 E2E).
- NEVER Percy / Chromatic / Applitools, NEVER "human reviews screenshots" as a test step, and NEVER a WebdriverIO codegen-recorder or interactive inspector as a test author; the only sanctioned human step is the flagged `drive+observe` operator checklist, which is a **product feature, not a test step** (per test-plan.md §11 Universal + §1 Untestable zones).
- NEVER lower or skip a gate to obtain green, and never add a retry policy to mask it (per test-plan.md §11 Quality + §10) — this is the plan-side form of the chunk's "never weaken a gate" invariant.

- **tests §3 ↔ obs §3 (log format / redaction).** test-plan.md §3 is the source of truth for the JSONL journal format and obs derives from it; the field-allowlist/redaction layer (no absolute host paths, no internal struct names) is obs-owned with tests asserting the boundary via a negative test. This chunk emits **no** violation-JSON envelope (deferred to `v2-24`), so the binding must come out of the chunk **unchanged** — the "no absolute host paths in any artifact" invariant is the live edge of it (per test-plan.md §3 Log format + Bootstrap `log-format-bind-with-obs`).
- **tests §6 ↔ a11y-plan §3/§5/§6.** a11y owns the WCAG criteria (paths, keyboard, contrast pairs, motion); tests owns their wiring into the 5-command `--e2e` leg and the selector contract that makes them assertable. - **tests §9 ↔ a11y CI gate (`v2-24`).** §9's pipeline table is where a future a11y gate would attach; this chunk's leg stays operator/local per its own boundary, so the binding is named but not exercised.
- **tests §3 harness ↔ `scripts/agent-run.{sh,ps1}`.** Both shells are a binding contract with identical semantics; a change to the leg's invocation on one side requires the other.

## Acceptance criteria contributions
- (tests) The `--e2e` leg runs fully non-interactively and its verdict is readable from the process exit code alone — ensure-frontend → release build `--features tauri/custom-protocol` → `wdio run`, no inspector, no interactive accept UI (per test-plan.md §3 CI stage selectors + §2 Agent-runnable invariants).
- (tests) With `CONDUCTOR_MSEDGEDRIVER` unset or not pointing at a file, the leg still exits 0 with a host-path-free precondition message, and `.sh`/`.ps1` behave identically (per test-plan.md §6 Drivers per surface + §3 Bootstrap `5-command-discipline-wire`).
- (tests) Every assertion the sweep adds or repairs selects by role / text / `aria-live` / brand anchor and synchronizes on an explicit signal — zero xpath, zero hashed-class, zero `sleep(N)` (per test-plan.md §6 Selector strategy + §11 E2E).
- (tests) The leg is green on repeated runs with no retry knob, and no green is obtained by weakening, skipping, or vacuously asserting a check; any driven live-Pulse leg stays on an operator/local path and is never wired into CI (per test-plan.md §10 Zero-flakiness budget + §11 Quality/CI).
