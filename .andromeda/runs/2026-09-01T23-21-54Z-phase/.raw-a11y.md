# a11y extract

## Relevance
Relevant — both halves land on the run-report/coverage-matrix critical path and the six-state lamp surface that a11y-plan.md governs directly (§1 Critical paths → "View run report", §4 lamp + coverage-matrix rows, §6 state color tokens).

## Constraints
- **Not-color-alone, six lamp states.** a11y-plan.md §6 (State color tokens) + §1 (A11y triggers → visual-discrimination) require every rendered lamp state to carry its display label (`Pass`/`HOLD`/`Fail`/`Blocked`/`Manual`/`Residual`) **plus** its glyph supplement (`Pass`+filled-dot / `HOLD`+amber-filled-lamp / `Fail`+filled-lamp-motionless / `Blocked`+hollow-ring / `Manual`+checkbox-glyph / `Residual`+dashed-ring), machine-verified via DOM text-content + axe-core (SC 1.4.1). Whether `StatusLamp` already emits label+glyph for all six when rendered at `size="sm"` inside a matrix row is research's question.
- **Non-lamp token reuse must be labelled and must not be counted as a seventh state.** §1 (A11y triggers → "Non-lamp reuse of a state token") requires a `--status-residual`-tinted element outside the lamp column to carry its **own always-rendered text label** as its not-color-alone signal (no glyph supplement) and requires the six-label assertion to key on the **lamp** display labels only. Half 2's envelope banner is a second instance of exactly that rule; the "Not yet run" cell is a third treatment the plan does not yet enumerate (§6 crosswalk lists exactly six display labels) — extending the assertion's vocabulary is an amendment candidate, not something the plan already covers.
- **Lamp state change is a status message.** §4 (per-component catalog → Verdict/report-state lamp) requires `status`/`aria-live` announcement on state change with ONE accessible name per lamp (SC 4.1.3, SC 4.1.2); §11 §Screen Reader bans duplicated `&lt;label&gt;`+`title`+`aria-label` on a lamp, and §11 §Keyboard forbids live updates stealing focus. Populating a lamp into every P-ID row multiplies both risks — per-row announcement noise is the a11y cost of this wiring.
- **Coverage-matrix semantics + keyboard.** §4 requires `list`/`listitem` (or table semantics) with selected row `aria-selected`/`aria-current` + `--border-emphasis`; §5 (run-report-terminal / run-console-live) requires keyboard-first row navigation and that virtual-scrolled off-screen rows stay reachable/announceable (SC 1.3.1 / 2.1.1 / 2.4.3).
- **Contrast pairs must exist for every token the new surfaces render.** §6 (Color contrast pairs) enumerates only `--count-nominal` / `--count-hold` / `--status-fail` / `--color-focus` over `--color-base` at 3:1 (SC 1.4.11) plus the text pairs at 4.5:1 (SC 1.4.3). `--count-blocked`, `--status-manual` and `--status-residual` over `--color-base` are **not** in that table, yet §1 requires the residual pair be "asserted like any other in Section 3" — and the banner uses `--status-residual` behind *text*, which is SC 1.4.3 4.5:1 territory, not 3:1. Which ratio the banner owes is a plan gap this chunk exposes.
- **Empty / not-yet-run prose.** §11 §Visual bans rendering an empty or in-progress run-report as a gray decorative skeleton and bans downgrading in-progress to a Fail; §3 (Screen reader test pattern) names "No run yet" / "Run in progress" as must-announce real prose. The not-yet-run cell must therefore be announced prose distinct from `Fail`, not a dash or tint.
- **Harness reuse, one stack, honest skips.** §3 (A11y testing tool pick / Configuration) requires axe-core v4.12.0 injected via `@axe-core/webdriverio` into the existing `@crabnebula/tauri-driver` + WebdriverIO session with `withTags(['wcag2a','wcag2aa','wcag21aa'])` (no `wcag22aa`); §9 (E2E row) puts axe + colorjs.io + not-color-alone + the compiled reduced-motion rule on the unattended **routine** `--e2e` arm and requires subject-absent specs to **context-skip rather than pass green**.

## Patterns to follow
- The Mode-cell precedent for token reuse outside the lamp column — always-rendered own text label, no glyph, contrast still asserted, lamp column untouched (a11y-plan.md §1 A11y triggers → non-lamp reuse). The scope's Half 2 names this precedent by hand; the plan is its authority.
- The state-naming crosswalk with **verdict-first** lamp precedence — `verdict == CalibrationRegion` ⇒ HOLD lamp regardless of `state`; a `ManualCheck` or `KnownResidual` state carrying that verdict is HOLD, not Manual/Residual (a11y-plan.md §6 State-naming crosswalk). This is the binding shape for the chunk's `p_id → Lamp` join and constrains the P4 collision-rule decision.
- Routine/driven arm split — axe, colorjs.io token pairs in both declared themes, not-color-alone and the compiled `@media (prefers-reduced-motion: reduce)` rule ride the routine arm; keyboard/focus-trap/restoration assertions ride the operator-only `a11y:driven` suite (a11y-plan.md §9 E2E row, §3 CI integration).
- Violation-JSON emission — axe rule-id + WCAG-SC tag + node selector fold into `fingerprints[]` of the obs §6 envelope; selectors are DOM-relative / `data-testid`, never host paths or seam-crate struct names (a11y-plan.md §3 Structured violation JSON schema).
- Semantic HTML first, ARIA second — shadcn/Radix primitives, no hand-rolled roles on `&lt;div&gt;` (a11y-plan.md §4 Naming convention, §11 §ARIA).

## Anti-patterns to avoid
- NEVER convey state by color alone — a lamp, a not-yet-run cell, or an envelope banner distinguished only by tint fails SC 1.4.1 (a11y-plan.md §11 §Visual).
- NEVER drop virtual-scrolled off-screen coverage-matrix rows from the accessibility tree — every P-ID `listitem` stays reachable/announceable (a11y-plan.md §11 §Screen Reader).
- NEVER render the empty/not-yet-run state as a decorative skeleton, and never let an unrun row read as a failure (a11y-plan.md §11 §Visual).

- (a11y) Every lamp rendered in a coverage row carries its display label text **and** glyph supplement in the DOM — assertion keys on lamp display labels, and the envelope banner / not-yet-run cell are not counted as lamp states (per a11y-plan.md §6 State color tokens (not-color-alone) + §1 A11y triggers → non-lamp reuse).
