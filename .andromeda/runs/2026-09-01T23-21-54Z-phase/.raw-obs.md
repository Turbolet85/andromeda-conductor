# obs extract

## Relevance
Partial — the chunk is a UI/data-wiring chunk, but it adds a NEW `#[tauri::command]` (a §4-governed instrumentation site) and touches the desktop-webview frontend, both of which carry standing obs mandates.

## Constraints
- The new read-only `#[tauri::command]` handler must open a **manual** `tracing::info_span!("tauri.command.&lt;name&gt;").entered()` guard — the `#[tracing::instrument]` ATTRIBUTE does not stack with `#[tauri::command]` (the command macro rewrites the fn signature for IPC arg-extraction) (per obs-plan.md §4 Auto-instrumentation per surface → desktop-webview row; §1 Obs Scope Summary → desktop-webview + ipc-internal rows). Whether the code already carries such a guard on the new site is research's question; §1 records SEVEN handlers measured 2026-09-01 and this chunk's table names an eighth.
- The new span's name must stay inside the bounded span-name set — `tauri.command.*` wildcard, `{module}.{operation}` shape, no high-cardinality component (no run_id / p_id / path-with-input in the NAME) (per obs-plan.md §11 Anti-Patterns → Spans / Traces; §2 Naming conventions).
- Any span ATTRIBUTE the new command records must be a field name in `conductor-core::redact::ALLOWLISTED_FIELDS` — the processor stage drops anything else, so an attribute outside the allowlist emits nothing; non-allowlisted identifiers ride the allowlisted `message` field instead (per obs-plan.md §4 Known-residual classification path → Required span attributes constraint; §11 PII Scrubbing). An `envelope_status`-shaped attribute is exactly the failure mode this rule names.
- The command's rusqlite read (`RunsDb::get_envelope`) is a Client-kind boundary requiring a manual span — rusqlite is synchronous, off the async runtime, with no auto-instrumentation (per obs-plan.md §4 Auto-instrumentation per surface → conductor-report row; §4 Span kinds). Whether a span already wraps `get_envelope` is research's question.
- Frontend telemetry on this surface stays **console JSON only** — no OTel JS SDK, no `auto-instrumentations-web`, no browser OTLP exporter, and no export to `:4318` (dead port + recursion trap); the frontend produces NO spans at all (per obs-plan.md §1 Telemetry surfaces → desktop-webview; §3 Sink (Tauri frontend); §11 Universal). This binds `App.tsx` / `CoverageMatrix.tsx` / `RunReport.tsx`.
- The eleven-field Run-report envelope (`state` enum = exactly Pass | Fail | ManualCheck | KnownResidual | Blocked) is a binding contract obs DERIVES and does not re-author; the load-envelope banner must not become a sixth `state` value or a twelfth envelope field (per obs-plan.md §6 Log format JSON schema / Required fields; §1 creator-explicit-telemetry trigger "the emission-journal format is owned upstream").
- The new command must not panic on a missing row / DB error — malformed or absent input resolves to a typed `Result`, captured at the `anyhow` edge with a sanitized message (per obs-plan.md §10 Zero unlogged panics; §11 Error Reporting).

## Patterns to follow
- The seven existing `#[tauri::command]` handlers' manual `info_span!(…).entered()` guard (`commands.rs` ×6, `pause.rs` ×1 per the 2026-09-01 amendment) is the shape the new handler copies (per obs-plan.md §4 desktop-webview row).
- Boundary-call wrapper logging: a DB boundary logs its summary at `info` with the operation's identity fields (the `db.insert_run` precedent logs row count + `run_id` + verdict + state) (per obs-plan.md §6 Boundary-call wrappers; §6 Log levels mapping).
- Carrying a non-allowlisted identifier on the allowlisted `message` field rather than as a dedicated attribute — the `mark_incident_resolved` incident-id and the `verify.readback` key-set witness precedent (per obs-plan.md §6 Boundary-call wrappers; §11 PII Scrubbing).
- Self-obs lines from the Tauri backend go to `logs/conductor-tauri.jsonl` unconditionally, stderr only as an open-failure fallback; span lifecycle materializes as `span` / `span_event` (`new` | `close`) / optional `parent` lines over the §3 base set (per obs-plan.md §3 Logging stack sinks; §3 Log format JSON schema → two record shapes / span-lifecycle variant).
- Correlation within a run is the `run_id` field on the IPC envelope and on every line — never a W3C `traceparent` (per obs-plan.md §3 Correlation; §11 Spans / Traces).

## Anti-patterns to avoid
- NEVER add an OTel SDK, meter provider, `tracing-opentelemetry`, or any network OTLP exporter for self-observation on either the Rust or the browser side of this surface (per obs-plan.md §11 Telemetry Strategy / Metrics / Universal).
- NEVER emit a lamp-join or envelope-read metric/histogram instrument — Minimal tier has no metrics backend; perf budget is the `latency_ms` + `slo_tier` JSON field assertion only (per obs-plan.md §5 Metric Coverage; §11 Metrics).
- NEVER leak absolute host paths or internal struct names through the new command's projection into logs / run-report artifacts (per obs-plan.md §11 Logs; §9 Log conformance check).

## Contract bindings
- **obs ↔ tests harness (§3 log format / §9 CI gates):** the JSONL line format is OWNED by test-plan §3 and reproduced in obs §3/§6 — a change to what the new command emits is a two-sided change. The `--e2e` leg and the rust gates this chunk runs sit alongside the §9 `logs/agent-latest.jsonl` conformance gate (§3 self-obs base schema: `timestamp_ms`, `level`, `target`, `service.{name,version}`, `deployment.environment`, `run_id`) and the zero-unlogged-panics grep.
- **obs ↔ security (§11 PII Scrubbing / Logs):** host-file-path redaction is applied at the processor stage in `conductor-core::redact`, single-location ownership — the new command reuses it, never adds its own scrub.
- **obs ↔ a11y (violation JSON → structured log format):** NOT activated here — the chunk's boundaries exclude the A11y CI gate / violation JSON (`v2-24`), so no violation-schema emission is in scope.

## Acceptance criteria contributions
- (obs) The new read-only `#[tauri::command]` opens a manual `tracing::info_span!("tauri.command.&lt;name&gt;").entered()` guard whose name is inside the bounded `tauri.command.*` set — no `#[tracing::instrument]` attribute on a command handler (per obs-plan.md §4 Auto-instrumentation per surface + §11 Spans / Traces).
- (obs) Every span attribute recorded by the new command/DB-read spans is a name in `conductor-core::redact::ALLOWLISTED_FIELDS`; anything else (e.g. an envelope-status value) rides the allowlisted `message` field (per obs-plan.md §4 Known-residual classification path → Required span attributes).
- (obs) Backend lines produced by the new command carry the §3 self-obs base set including `run_id`, are one-JSON-object-per-line to `logs/conductor-tauri.jsonl`, and contain no absolute host paths (per obs-plan.md §3 Log format JSON schema + §9 Log conformance check).
- (obs) The webview half adds zero OTel JS SDK / zero browser OTLP export — frontend telemetry stays `console.log` JSON (per obs-plan.md §1 Telemetry surfaces desktop-webview row + §11 Universal).
