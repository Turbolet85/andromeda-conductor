## Relevance
Relevant — the chunk lands a new Tauri IPC surface plus webview wiring inside a locked workspace crate, so workspace placement, the internal core↔UI contract, and the two-stage Tauri build coupling all bind.

## Constraints
- Both halves land in locked workspace members: the Rust command in `conductor-tauri` (the GUI bin, per architecture.md §Occupied Resources — Crate names) and the React work under `crates/conductor-tauri/ui/`, which architecture.md §Occupied Resources — Frontend asset subtree requires to stay a non-Cargo-member npm subtree (React 19 / Vite ≥8.0.16 / Tailwind v4.1 / TS strict, `package-lock.json` committed, `npm audit --omit=dev` gate — architecture.md §Inherited Defaults — Frontend).
- The only permitted core↔UI surface is Tauri 2 `#[tauri::command]` request/response, with `Channel` reserved for streaming counters; architecture.md §Conventions — Interface surfaces and §Established Decisions [Backend Framework] forbid adding any HTTP/SSE/WebSocket/polling path for either the envelope or the lamp join. architecture.md §Occupied Resources — Interface routes treats Tauri command names as the route-equivalent set, so a new command is a new occupied resource to register at wrap.
- architecture.md §Design Philosophy (headless-drivable core, thin shells) plus §Established Decisions [Workspace / Core Structure] require the new command to be a thin read-only projection over an existing seam method — verdict/lamp truth stays in `conductor-core` and the envelope standing in `conductor-report`, never re-authored in the shell.
- architecture.md §Established Decisions [Error Handling] and §Conventions — Error handling put `anyhow` only at the `#[tauri::command]` edge and hold the verdict/error wall: `Verdict`/`ReportState` are values, `Result::Err` means a harness fault. A run with no persisted envelope row is an absence (`Option::None`), not an `Err`.
- The lamp shown for a record is governed by architecture.md §Established Decisions [Probabilistic-Assertion Policy]: default mapping `Pass→Pass` / `Fail→Fail` / `CalibrationRegion→ManualCheck`, `verdict` and `state` independent, and the report lamp chosen **verdict-first** (a calibration row renders HOLD, not Manual). Whether `lamp.ts`'s `lampForRecord` already mirrors that precedence byte-for-byte is research's question.
- architecture.md §Occupied Resources — On-disk artifacts fixes `runs.db` at three tables with the run-level envelope standing (`classification` · `cause`) in its own `run_envelope` table keyed `run_id`, deliberately separate so `runs` keeps eleven columns and `state` stays the closed five-variant set; architecture.md §Established Decisions [Database] keeps that storage seam synchronous and off the async runtime.
- architecture.md §Infrastructure Patterns — Build system requires `npm run build` before any workspace cargo compile touching `conductor-tauri` (`generate_context!` resolves `ui/dist` at compile time) AND `--features tauri/custom-protocol` for a binary that must serve the embedded bundle rather than `devUrl` (`http://localhost:5173`) — necessary and sufficient conditions are separate.

## Patterns to follow
- The existing six-command shape in `conductor-tauri` (`list_scenarios` / `coverage_matrix` / `unbacked_auto` / `run_report` / `start_run` / `stop_run`) is the precedent a seventh read-only reader follows — a thin projection over a seam method, per architecture.md §Conventions — Interface surfaces (Internal core↔UI).
- The shared-artifact shapes already crossing IPC are the eleven-field run envelope (`run_id` · `seed` · `scenario` · `p_ids` · `verdict` · `state` · instants · `latency_ms` · `slo_tier` · `fingerprints`) and the nine-key `CheckRecord`, per architecture.md §Standard Contracts — Run report envelope / Per-check record; the `p_id → Lamp` join is computed from the envelope shape rather than by widening it.
- Envelope classification has ONE shared basis: `check_load_envelope` (static catalog gate) and `LoadEnvelope::classify` (the per-run `[ENVIRONMENT-SUSPECT]` judgment) read the same terms, per architecture.md §Occupied Resources — `contracts/pulse-load-envelope.toml`. The GUI banner should surface the persisted classification, not re-derive one, or the third surface can diverge from the CLI caption and the Markdown banner.
- Dev-only webview driving rides ONE WebdriverIO + tauri-driver stack over two arms (unattended `--e2e`, operator-local `a11y:driven`), binding `4444`/`4445` for the harness's lifetime and gated by `CONDUCTOR_MSEDGEDRIVER` with skip-at-exit-0 when unset — per architecture.md §Occupied Resources — Ports / Environment variables and §Cross-cutting Patterns — Scope law. Adding specs to that stack is the sanctioned route.
- Design tokens are declared on `:root` in `tokens.css` with fonts self-hosted; the banner's `var(--status-residual)` reuse follows architecture.md §Inherited Defaults — Frontend rather than introducing a new color source.

## Anti-patterns to avoid
- Do not widen the closed enumerations or the schema: no sixth `ReportState`, no seventh lamp, no new column on `runs` — architecture.md §Standard Contracts (`state ∈ {Pass, Fail, ManualCheck, KnownResidual, Blocked}`) and §Occupied Resources — On-disk artifacts pin the qualifier at its own run-grained table precisely so status values stay closed.
- Do not open any non-Tauri surface (local HTTP endpoint, SSE, dev-server port, polling fetch) to move envelope or coverage data — architecture.md §Established Decisions [Backend Framework] + [Real-time Strategy] and §Cross-cutting Patterns — Trust boundary allow no inbound listener of Conductor's own in a shipped binary.
- Do not add a new `CONDUCTOR_*` env var, config handle, or workspace crate for this wiring — architecture.md §Occupied Resources reserves and enumerates that namespace; a new dependency (cargo or npm) would also break the compact `cargo audit` basis the scope's PREREQ 2 rests on and would owe a §Stack row.

## Contract bindings
- **Standard Contracts envelope ↔ tests/e2e + design/a11y:** the run-report envelope and `CheckRecord` shapes (architecture.md §Standard Contracts) are what the `--e2e` specs assert against and what the lamp join consumes; any shape change fans out to all three surfaces.
- **Verdict-first lamp precedence ↔ a11y/design six-lamp set:** architecture.md §Established Decisions [Probabilistic-Assertion Policy] is the arch-side ruling that resolved the a11y six-lamp conflict, so the webview join must agree with `conductor-core`'s `Lamp::for_record` rather than with `state` alone.
- **Build-system coupling ↔ tests harness:** the `npm run build` + `--features tauri/custom-protocol` pair (architecture.md §Infrastructure Patterns — Build system) is a precondition of the `--e2e` arm being able to observe the new UI at all; the harness shells own firing it.
- **Occupied-resource registration ↔ wrap:** the new command name joins the Tauri command route-equivalent set in architecture.md §Occupied Resources — Interface routes / surfaces (framework ACL capability perms remain security's domain, not arch's, per the 2026-06-24 precedent below).

## Acceptance criteria contributions
- (arch) The envelope reader ships as a `#[tauri::command]` in `crates/conductor-tauri`, with `anyhow` only at that edge and no HTTP/SSE/polling surface introduced (per architecture.md §Conventions — Interface surfaces + §Established Decisions [Backend Framework] / [Error Handling]).
- (arch) `ReportState` stays five and `runs` stays eleven columns — the banner reads the run-grained `run_envelope` standing and is never a status value or a new column (per architecture.md §Occupied Resources — On-disk artifacts (runs.db) + §Standard Contracts).
- (arch) No new workspace crate, port, or `CONDUCTOR_*` env var, and no new cargo/npm dependency (per architecture.md §Occupied Resources + §Inherited Defaults — Frontend).
- (arch) The `--e2e` binary under test is produced by `npm run build` followed by a `conductor-tauri` build carrying `--features tauri/custom-protocol`, so the webview serves the embedded bundle rather than `devUrl` (per architecture.md §Infrastructure Patterns — Build system).
