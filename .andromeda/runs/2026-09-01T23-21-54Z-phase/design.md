# design extract

## Relevance
Relevant — both halves land on `desktop-webview` surfaces the plan owns directly (verdict/report-state lamp, coverage matrix row, run-report card).

## Constraints
- The lamp is a **six-treatment** set that must remain visually distinct so none silently reads as another: filled dot for the machine-verdict triad (`Pass`/`CalibrationRegion`/`Fail`), hollow ring `Blocked`, checkbox glyph `ManualCheck`, dashed-ring dot `KnownResidual` — `ManualCheck`/`KnownResidual`/`Blocked` must never collapse into `Fail` (per design-system.md §Surface: desktop-webview / Component Patterns 4 + §Color Palette, Verdict-vs-ReportState note). This directly bounds the chunk's open P4 collision/aggregation rule: a "worst-wins" join must not downgrade a non-verdict report-state row into the red `Fail` treatment.
- A "no run record yet" row is the empty state, not an error state — design-system.md §Anti-Patterns / Rejected Defaults forbids conflating "no result yet" with "failed" (and forbids gray-skeleton placeholders); the run-report's own "no run yet" / "run in progress" states are prose in `--text-tertiary` / `--text-secondary`, never a partial or red verdict (per design-system.md §Surface: desktop-webview / Component Patterns 6).
- Colors bind **by token name only** — `--count-nominal`, `--count-hold`, `--status-fail`, `--count-blocked`, `--status-manual`, `--status-residual`, `--color-id-cyan`, `--border-subtle` — declared on plain `:root` (not `@theme`), with the light block mirrored; no raw hex, no magic px (per design-system.md §Surface: desktop-webview / Tokens).
- Every lamp is paired with a text label (`Pass`/`CalibrationRegion`/`Fail`/`Blocked`/`Manual`/`Residual`) plus an `aria-live` announcement, and every icon-only control carries an `aria-label` — color-alone is banned (per design-system.md §Component Patterns 4 + §Iconography Rule). Whether the shipped `StatusLamp` / `cov__unrun` cell already renders label text and announces is research's question.
- The lamp **resolves motionless**: a single in-place 150ms `--motion-micro` / `--ease-quiet` color transition, with no pulse, blink, glow, or flashing red on `Fail`, and all transitions dropped under `@media (prefers-reduced-motion: reduce)` (per design-system.md §Motion, "This project's values" + "Hard limits for this expression level"; expression level `0.3` per §Brand Identity).
- The envelope banner is a **run-level qualifier, never a seventh lamp**: it reuses the recessive `var(--status-residual)` tier with an always-rendered DOM text label, rendered outside the lamp column — the same by-name pair the CLI binds as ANSI 246 for the `[ENVIRONMENT-SUSPECT]` caption, `hint:` label, and out-of-scope Mode cell (per design-system.md §Surface: cli / Tokens, Residual-mute entry).
- Row and banner geometry come from the scale: `--space-md` (12px) coverage row padding, `--space-micro` (2px) lamp-glyph-to-label gap, `1px solid --border-subtle` seams, `--radius-md` on the run-report card, `--radius-full` + 16px on the lamp dot — **borders-only depth, zero `box-shadow` / `backdrop-filter`** (per design-system.md §Spacing, §Border Radius, §Depth Strategy).

## Patterns to follow
- **Verdict / report-state lamp (§Component Patterns 4)** — the supporting status convention already specified as an in-place per-P-ID light on the matrix row; the chunk composes this primitive, it does not author a new status visual.
- **Coverage matrix row anatomy (§Component Patterns 3)** — dense single-row-per-P-ID list (never a KPI-card grid): lamp glyph + label + P-ID + SLO tier + `latency_ms`, with hover → `--color-raised-1` lift and selected → `--border-emphasis` left edge.
- **Run-report view (§Component Patterns 6)** — `--color-raised-1` card, `1px --border-subtle`, `--radius-md`, IBM Plex Sans body in `--text-secondary` with mono identifiers in `--color-id-cyan`; the banner attaches to this card, above/outside the per-P-ID lines.
- **Residual-mute non-lamp reuse precedent (§Surface: cli / Tokens)** — three prior non-lamp uses bind the same tier by name in both surfaces; the webview envelope banner is the same treatment (tint de-emphasizes, the always-rendered label carries the signal), so it needs **zero new tokens and zero new palette rows**.
- **Mono status tier (§Typography, Data row)** — P-IDs / `run_id` / SLO timings / `latency_ms` render JetBrains Mono 500 / 13px / tabular-nums in `--color-id-cyan`; prose and labels stay IBM Plex Sans.

## Anti-patterns to avoid
- Never render `Blocked` (or an unrun row) as a red error, and never gray "no result yet" the same as "failed" (per design-system.md §Rejected Defaults).
- Never flash, pulse, blink, or glow any status — no animated alert banner or toast on `Fail`, and Conductor emits no native OS toast (per design-system.md §Rejected Defaults + §Motion hard limits).
- Never introduce a new color, a seventh lamp state, a drop shadow / `backdrop-filter`, or color used decoratively — every color must read as Verdict/ReportState (per design-system.md §Anti-Patterns / Universal Bans + §Depth Strategy).

## Contract bindings
- **Lamp/label color pairs ↔ a11y §Contrast (SC 1.4.3)** — lamp label text and banner text on `--color-raised-1` (rows) and `--color-raised-2` (thead) must clear 4.5:1; the 2026-09-01 sweep moved `--text-tertiary`/`--text-muted` for exactly these surfaces, so any newly-rendered text tier here must be computed, not assumed.
- **State color + text label ↔ a11y §Use of Color (SC 1.4.1)** — the always-rendered DOM text label on both the lamp and the envelope banner is the shared artifact; the chunk's `--e2e` specs assert its presence, which is the design↔tests-harness tie (scope: `ui/test/a11y/*.e2e.ts`).
- **Motion token ↔ a11y §Animation (SC 2.3.3)** — the 150ms lamp color transition must fall under the global `prefers-reduced-motion: reduce` override in the token bundle.
- **Six lamp treatments ↔ architecture's lamp truth** — design fixes the six *visual* treatments; `Lamp::for_record` / the `lampForRecord` mirror own the state→lamp mapping. Design mandates only that the mapping never yields a `Fail` treatment for a non-verdict report-state, and that `ReportState` stays five / `LAMP_META` stays six.

## Acceptance criteria contributions
- (design) Every coverage row with a run record renders one of the six distinct lamp treatments with an always-rendered text label plus glyph — never color alone (per design-system.md §Surface: desktop-webview / Component Patterns 4).
- (design) A capability with no run record renders a not-yet-run treatment visually distinct from both `Fail` and `Blocked`, and is not styled as an error or a gray skeleton (per design-system.md §Anti-Patterns / Rejected Defaults).
- (design) All lamp, banner, spacing, radius and motion values bind by token name (`--count-*` / `--status-*` / `--color-id-cyan` / `--space-*` / `--radius-*` / `--motion-micro` / `--ease-quiet`) with no raw hex, no magic px, and no `box-shadow` (per design-system.md §Surface: desktop-webview / Tokens + §Depth Strategy).
- (design) The load-envelope banner uses `var(--status-residual)` with an always-rendered DOM text label outside the lamp column, adds no seventh lamp and no new token, and any lamp state change is a motionless 150ms color transition dropped under `prefers-reduced-motion: reduce` (per design-system.md §Surface: cli / Tokens Residual-mute entry + §Motion).
