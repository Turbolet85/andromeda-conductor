## Relevance
Relevant — the chunk adds a Rust `#[tauri::command]`, frontend data-wiring, and new webview `*.e2e.ts` specs, all of which land on tiers test-plan.md owns (mock-runtime IPC, the `--e2e` routine arm, the 5-command harness gates).

## Constraints
- Every read-only `#[tauri::command]` owes a `tauri::test` mock-runtime IPC test asserting its payload against the source it single-sources — this is the standing (no longer deferred) tier, with only the `Channel`-frame-sequence and GUI-parity legs still deferred (per test-plan.md §5 Cross-module patterns → Tauri command bullet + GUI-leg deferral bullet). Whether the new envelope-reader command is added with such a test is the implementation's obligation; whether existing commands already carry theirs is research's question.
- `conductor-tauri/ui` has **no JS/TS unit runner** and is build-gated only (`tsc --noEmit` + `vite build` + `npm audit` + preview smoke), and §4 states explicitly that the build gate does **not** prove ESM loadability — a member reachable from neither `--e2e` nor `npm run a11y:driven` is as unproven as under the build gate (per test-plan.md §4 → conductor-tauri/ui; §12 Decisions Log open question "No JS/TS unit-test runner"). Consequence for this chunk: the `p_id → Lamp` collision rule has no unit tier available and is provable only through a spec the running suite actually loads.
- The `--e2e` leg is defined as ensure-frontend → release build with `--features tauri/custom-protocol` → `wdio run` (non-interactive), **routine suite only**, tauri-driver spawned at `cwd` = workspace root, 15-minute mocha ceiling; `CONDUCTOR_MSEDGEDRIVER` unset/not-a-file ⇒ skip at exit 0 (per test-plan.md §3 CI stage selectors; §6 Drivers per surface → desktop-webview; §9 pipeline table → E2E (webview)). §3 records the routine `specs` as narrowed to `accessibility.e2e.ts` on 2026-09-01, so whether a newly added spec file is reached by `--e2e` at HEAD is research's question — a spec the leg does not load cannot satisfy the DoD's "asserted by the `--e2e` leg".
- The routine arm runs with **no live Pulse**, and subject-absent specs must **context-skip rather than pass green** (per test-plan.md §6 → desktop-webview, ROUTINE arm). Both halves here depend on run records / an envelope row existing, so the new specs must distinguish "no run record present" from "assertion satisfied".
- The Run-report envelope's eleven fields are closed; per-run detail at any other grain is a separate record, never an extension of the envelope (per test-plan.md §3 Status endpoint shape). The load-envelope signal is already carried on cli as a **run-level non-lamp qualifier** alongside the closed six-label lamp set (per test-plan.md §1 Surfaces under test → cli Signal; §6 Selector strategy) — the webview banner must be modelled the same way, not as a seventh lamp.
- Zero-flakiness budget: no nextest `retries`, no `sleep(N)` synchronization in the wdio spec (wait on an explicit role/`aria-live`/text signal), and a runner-dependent result is a determinism break to fix at the cause, not a runner to pin to (per test-plan.md §10 Zero-flakiness budget; §11 E2E). The new Rust command additionally owes the standing runner-portability gate `cargo test -p <crate>` beside nextest (per test-plan.md §4 Framework).
- Supply-chain is a binding build-failure condition (`cargo audit --deny warnings` + `cargo deny check` green, committed un-drifted `Cargo.lock`) (per test-plan.md §9 Build failure conditions; §10; §11 CI). The chunk's PREREQ-2 "compact form" signature (audit true exit 1 on a duplicate-advisory-ID diagnostic) is a chunk-local discharge convention, not something test-plan.md sanctions; test-plan.md's own tool-version stance is floors-not-pins (§4 Tool-version policy).

## Patterns to follow
- The existing read-only mock-runtime IPC tests for `coverage_matrix` / `run_report` / `unbacked_auto`, which assert each command's payload against the `conductor-core` source it single-sources (per test-plan.md §5 GUI-leg deferral bullet) — the template for the new envelope-reader command.
- The routine a11y arm's spec shape: `wdio run` over the routine suite asserting axe, the §6 token pairs in both declared themes, not-color-alone, and the reduced-motion rule (per test-plan.md §6 → desktop-webview ROUTINE arm) — new assertions ride this file/suite rather than a new transport.
- Brand-anchor selector discipline: role / text / `data-testid`, text-paired status labels (the closed six-label set) plus the run-level non-lamp qualifier, and **mono P-ID tokens named as the manifest's accepted set** (never a hard-coded P-ID range) for coverage-matrix and report rows (per test-plan.md §6 Selector strategy).
- Rust-side isolation for the new command's tests: `rusqlite::Connection::open_in_memory()` per unit test, `assert_fs::TempDir` + `.env("CONDUCTOR_RUNS_DIR", …)` for any cross-process leg (per test-plan.md §3 Test data bootstrap → per-test isolation; §5 Setup/teardown; §7 Seed strategies).
- Cleanup is contractually defined to cover **every** table a run writes, `run_envelope` included, with bound-parameter SQL and count-zero verification (per test-plan.md §3 `cleanup`) — the table this chunk's new reader projects from is already inside that contract.

## Anti-patterns to avoid
- NEVER xpath, hashed Tailwind/CSS-class selectors, or `sleep(N)` synchronization in the new webview specs; never treat a reported envelope state as a non-zero process exit (per test-plan.md §11 → E2E).
- NEVER visual-pixel / Percy / Chromatic / screenshot-review assertions for the lamp or banner — role/text/`aria-live` only, non-interactive runners only (per test-plan.md §11 → Universal; §6 desktop-webview Notes).
- NEVER wire any live-Pulse leg (including the operator `a11y:driven` arm) as a CI gate; it stays the operator-local exception (per test-plan.md §9 Live-Pulse scenarios; §11 → CI).

## Contract bindings
- **tests ↔ a11y:** §6's selector strategy is only reliable *because* of the Color-Only rule's mandatory text/role pairing — the chunk's DoD ("text label + glyph, never color alone"; "always-rendered DOM text label") is simultaneously the a11y requirement and the precondition for a stable selector (per test-plan.md §6 Selector strategy; §1 desktop-webview Signal).
- **tests ↔ obs/report schema:** the new reader projects a `run_envelope`-grain value; test-plan.md §3 owns the envelope shape (eleven fields, unchanged) and the journal's two report-seam line shapes, so the projection must not widen the envelope or introduce a third journal record shape (per test-plan.md §3 Status endpoint shape + Log format).
- **tests ↔ arch/design closed sets:** the six-label lamp set and the run-level non-lamp qualifier are enumerated in three places test-plan.md keeps in sync (§1 cli Signal, §6 cli driver row, §6 Selector strategy); a webview banner introduced as a seventh lamp would contradict all three.
- **tests ↔ harness (5-command):** the `--e2e` selector is a harness command, so its preconditions and skip-at-exit-0 behavior are the harness contract, not spec-local choices (per test-plan.md §3 CI stage selectors; §3 Bootstrap → 5-command-discipline-wire, which binds `.sh`/`.ps1` to identical semantics).

## Acceptance criteria contributions
- (tests) The new read-only `#[tauri::command]` carries a `tauri::test` mock-runtime IPC test asserting its payload against the `RunsDb`/core source it single-sources, and the workspace is green under both runners (`cargo nextest run --workspace --profile ci` and `cargo test -p conductor-tauri`) (per test-plan.md §5 Cross-module patterns / GUI-leg deferral + §4 Framework).
- (tests) `--e2e` exits 0 with the new assertions residing in a spec the routine suite actually **loads** (routine `specs` narrowed to `accessibility.e2e.ts`), and with subject-absent cases context-skipping rather than passing green (per test-plan.md §3 CI stage selectors + §4 conductor-tauri/ui + §6 desktop-webview ROUTINE arm).
- (tests) Every new webview assertion selects by role / text / `data-testid` / P-ID token (the manifest's accepted set) with no xpath, no hashed-class selector, and no `sleep(N)` wait; the not-yet-run cell and the failed cell are distinguished by DOM **text**, not color (per test-plan.md §6 Selector strategy + §11 E2E).
- (tests) Workspace line coverage stays ≥ 60% under `cargo llvm-cov nextest --fail-under-lines 60`, clippy `-D warnings` clean, and the supply-chain gate (`cargo audit` + `cargo deny check`) satisfied with `Cargo.lock` un-drifted (per test-plan.md §10 Coverage thresholds + Build failure conditions; §9 pipeline table).
