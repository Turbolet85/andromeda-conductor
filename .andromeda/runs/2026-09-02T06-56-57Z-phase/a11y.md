# a11y extract

## Relevance
Relevant — this chunk IS the a11y plan's own `screen-reader-test-spec-setup` bootstrap phase (a11y-plan §3 Bootstrap phases); every artifact it builds is governed by a11y-plan §3 Screen reader test pattern.

## Constraints
- The manual SR pass is **supplemental, never sole verification**; the spec and its recorded pass carry no WCAG conformance claim — conformance evidence stays the axe-core / colorjs.io machine baseline (per a11y-plan §3 *Screen reader test pattern* → "Supplemental to automated"; §2 *Agent-runnable invariants*; §11 *Universal*).
- The pass-spec format is prescribed: **structured per-state text + expected SR output**, scaffolded per-state for NVDA (Windows) / VoiceOver (macOS) / Orca (Linux), **supplemental and not CI-gated** (per a11y-plan §3 *Screen reader test pattern* — "Manual pass spec format"; §3 Bootstrap `screen-reader-test-spec-setup`).
- §3 fixes the must-announce row set the spec must cover: empty-state real prose, in-progress announced as status **not** Fail, HOLD phase-line flip via `aria-live="assertive"`, frozen count value (does not blank or keep running), verdict-lamp `aria-live` status announcement on state change, operator-checklist unticked-count roll-up (per a11y-plan §3 *Screen reader test pattern*). These are TARGET-state mandates — **whether the shipped DOM renders each prose string and live region is research's question**, and where it does not, this domain's rule is to record the gap, not to claim the mandate satisfied.
- Node role/name expectations come from the §4 catalog, not from the DOM alone: lamp = `status` live-region with an always-present paired text label; operator-checklist = `checkbox` per row + `aria-checked` + announced unticked roll-up, at **two** render sites (report-terminal, and inside the HOLD `alertdialog` as a sibling of `Description`); dialog = `alertdialog` + `aria-modal` + `aria-labelledby` (frozen count + step index); icon-only controls carry `aria-label`; picker = `combobox`/`listbox` with `aria-expanded`/`aria-activedescendant` (per a11y-plan §4 *Per-component pattern catalog*).
- Landmarks are required, not optional: desktop-webview MUST expose `main` (console/report body) + `contentinfo` (footer status strip), with `banner` optional on the frameless titlebar; a window without landmarks is an SC 1.3.1 failure leaving NVDA with no navigation anchor (per a11y-plan §4 *Per-surface landmark roles inventory*; §11 *Screen Reader*). Whether `contentinfo` ships is research's question — the plan states the requirement, not the code's state.
- Expected-speech text for state lamps keys on the **display label** (`Pass`/`HOLD`/`Fail`/`Blocked`/`Manual`/`Residual`), and a `--status-residual`-tinted coverage-matrix Mode cell is a coverage-mode classification, **not a seventh lamp state** — its own `not-conductors` text is its signal (per a11y-plan §6 *State color tokens* state-naming crosswalk; §1 *non-lamp reuse*).
- Any committed a11y artifact MUST NOT leak absolute host paths or internal seam-crate struct names, and tags `service.name` / `deployment.environment` for obs cross-correlation (per a11y-plan §3 *Structured violation JSON schema*; §9 *CI-specific resource attributes*; §10 *SLO*).

## Patterns to follow
- The §4 catalog's column shape (Pattern | ARIA role | Key states | Keyboard contract | WCAG SCs | Tool reach) is the existing per-node description pattern the spec's node/role/name column should mirror (a11y-plan §4).
- Per-state framing already exists in §5 *Focus order per layout* (`run-console-idle` / `-live` / `-HOLD` / `run-report-terminal`) — the plan's own four-state decomposition, which the scope reports diverges from the shipped `RunState` set (a11y-plan §5; §1 entity, §3 pass-spec format).
- The two-arm split — unattended routine arm vs operator-only driven arm requiring a live Pulse plus its full firing form — is the existing precedent for a HOLD-state stimulus recipe (a11y-plan §9 *E2E* row; §3 *Command*).
- Bootstrap phases are enumerated as discrete, independently-materializable steps, with `screen-reader-test-spec-setup` sequenced after the harness phases and before `a11y-ci-gate-wire` — i.e. the spec is authored against an existing harness, not alongside a harness change (a11y-plan §3 *Bootstrap phases*).

## Anti-patterns to avoid
- NEVER let human-only NVDA/VoiceOver/Orca review stand without the machine axe-core/colorjs.io/WebdriverIO output, and NEVER claim WCAG conformance without machine-verifiable evidence (a11y-plan §11 *CI*, *Universal*).
- NEVER stand up a second browser-automation stack for a11y — one webview-automation stack only (a11y-plan §11 *CI*). This is the plan-side basis for the chunk's "no SR driver, no NVDA add-on" boundary.
- NEVER prescribe remedies that add ARIA noise or hide announcement sources — no redundant `<label>` + `title` + `aria-label` on a lamp (double-announce), no `aria-hidden` on lamp / counters / HOLD phase-line, no dropping virtual-scrolled coverage-matrix rows from the a11y tree (a11y-plan §11 *Screen Reader*).

## Contract bindings
- **a11y ↔ obs §6:** artifacts tag `service.name` = `"conductor-tauri"` / `deployment.environment` = `CONDUCTOR_ENV` and inherit the no-absolute-paths / no-seam-crate-struct-names constraint (a11y-plan §3 *Structured violation JSON schema*, §9). Note the boundary: §3 names only axe `violations[]`, colorjs.io ratio, and WebdriverIO keyboard PASS/FAIL as folding into the obs envelope — whether a **manual** pass record is an obs-enveloped artifact or a plain committed evidence file is not settled by the plan and is a design question for P4.
- **a11y ↔ tests:** the 5-command harness contract (boot / run / status / cleanup / logs) is the binding command surface for a11y results, but §3 Bootstrap marks the SR spec "supplemental, not CI-gated" — so this chunk's artifacts are not required to ride the `wdio run` job (a11y-plan §3 *CI integration*, §9). The HOLD stimulus depends on the driven-arm firing form registered in tests §6/§9.
- **a11y ↔ design:** lamp display labels + always-rendered text label per state, and the load-envelope banner's always-rendered `label` (+ optional `cause`) as a non-interactive `<p>`, deliberately not a lamp role (a11y-plan §4 catalog; §6 *State color tokens*).
- **a11y ↔ layouts:** §4's landmark inventory is *derived* by a11y because layouts assign no landmarks explicitly (Heading role on phase line, Label role on footer status strip) — the spec's landmark rows inherit that derivation, not a layouts mandate (a11y-plan §4).

## Acceptance criteria contributions
- (a11y) A per-state pass spec exists covering each run state, with a row per must-announce item naming the producing action/key sequence, the carrying node (role + accessible name + live-region mechanism where one exists), the expected NVDA speech, the WCAG SC evidenced, and a result cell — covering at minimum §3's six must-announce items (per a11y-plan §3 *Screen reader test pattern* + §3 Bootstrap `screen-reader-test-spec-setup`).
- (a11y) The spec and evidence record state explicitly that the SR pass is supplemental and claim no WCAG conformance; conformance evidence is attributed to the axe-core / colorjs.io machine baseline (per a11y-plan §3 *Supplemental to automated* + §11 *Universal*).
- (a11y) VoiceOver (macOS) and Orca (Linux) rows appear only as declared-not-runnable-on-this-host notes, never as claimed or green passes; macOS remains manual-pass-only (per a11y-plan §1 *A11y surfaces & assistive tech reach* + §11 *CI*).
- (a11y) Spec and evidence contain no absolute host paths and no internal seam-crate struct names, and the evidence carries the build/tool identity the artifact-tagging rule implies (per a11y-plan §3 *Structured violation JSON schema* + §9 *CI-specific resource attributes* + §10 *SLO*).
