## Relevance
Partial — the chunk's substance is a11y/docs, but arch governs artifact placement + naming, the closed state vocabularies the spec quotes, the build/launch form the stimulus recipe depends on, and the ban on a second automation stack.

## Constraints
- **Artifact placement adds no workspace member.** The candidate home `crates/conductor-tauri/ui/test/…` sits inside the frontend asset subtree, which architecture.md §Occupied Resources (Frontend asset subtree) records as NOT a Cargo workspace member (invisible to cargo), with `node_modules/`, `dist/` and `ui/logs/` git-ignored and `package-lock.json` committed. The spec + evidence must land on git-tracked paths there, and §Occupied Resources (Crate names) locks the nine members — no tenth. Whether `ui/test/` is currently git-tracked rather than caught by an ignore rule is research's question.
- **Artifact naming.** architecture.md §Conventions (Naming patterns) requires on-disk artifacts to use kebab-case Markdown filenames (`coverage-matrix.md`, the run report); snake_case is reserved for Rust source. Both new files inherit that form.
- **Closed state vocabularies the spec may quote.** `Verdict ∈ {Pass, Fail, CalibrationRegion}` and `ReportState ∈ {Pass, Fail, ManualCheck, KnownResidual, Blocked}` are closed sets (architecture.md §Standard Contracts; §Conventions Error handling), and §Established Decisions [Probabilistic-Assertion Policy] requires the run-report lamp be chosen **verdict-first** — a calibration row renders HOLD, not Manual. The webview's `RunState` (`idle`/`live`/`hold`/`aborted`) is a shell concept distinct from both sets and the spec must not conflate them. Whether the shipped `StatusLamp.tsx` label vocabulary already follows verdict-first is research's question.
- **Stimulus build form.** architecture.md §Infrastructure Patterns (Build system) requires `npm run build` before any cargo compile of `conductor-tauri` (`tauri::generate_context!` resolves `build.frontendDist` at COMPILE time; a bare `cargo build` does not run `beforeBuildCommand`), and records that the **`custom-protocol` FEATURE — not the profile** — decides whether the binary serves the embedded bundle or `devUrl` (`http://localhost:5173`). A recipe omitting `--features tauri/custom-protocol` launches a devUrl window.
- **`hold` stimulus preconditions.** A live preflight-ready Pulse requires `ANDROMEDA_PULSE_DATA_DIR` propagated to the spawned sidecar plus the Pulse-side `ANDROMEDA_PULSE_MCP_ENABLED` / `ANDROMEDA_PULSE_L4_DETERMINISTIC` declarations (architecture.md §Occupied Resources — Environment variables), and **`PATH` is a spawn-resolution input**: with the sidecar off `PATH`, preflight returns BLOCKED in ~2ms with all four tools `absent`, at row level indistinguishable from a genuine SUT-side gate failure (§Occupied Resources — Service/process names). The PATH prefix is part of the firing form, not an optional extra.
- **No new occupied resource beyond the two artifacts.** `CONDUCTOR_*` is the reserved namespace with an enumerated handle list, and the one handle naming a HOST dev-tool (`CONDUCTOR_MSEDGEDRIVER`) exists precisely so its value is **never committed** (architecture.md §Occupied Resources — Environment variables). Any NVDA install location the spec touches inherits that: version recorded, path never. Every precondition string is host-path-free (§Standard Contracts — Readiness gate).
- **The recorded pass is an operator/local gate, never CI.** architecture.md §Design Philosophy (Headless-drivable core, thin shells) makes the CLI/headless path the release gate and the GUI convenience only; §Established Decisions [CI/CD] keeps GitHub Actions to build + test, with anything needing a live SUT or a human as an explicit operator/local gate.

## Patterns to follow
- **Transcribed-record artifact with stated provenance** — `contracts/pulse-*.toml` are committed records whose `provenance` field states "a transcribed SUT record, never a Conductor measurement" so a reader knows how far to trust them (architecture.md §Occupied Resources — On-disk artifacts). The spec's EXPECTED-NVDA-speech column is the same species: a transcribed expectation, not a measurement — the artifact should say so on its face, with the "heard" column carrying the only measured half.
- **Two arms over ONE stack** — the operator-local `npm run a11y:driven` arm and the routine `--e2e` arm both ride one WebdriverIO + tauri-driver stack binding `4444`/`4445` for the harness's lifetime (architecture.md §Cross-cutting Patterns — Scope law; §Occupied Resources — Ports). Where a state's stimulus needs the window driven, it reuses the registered driven-arm firing form rather than standing anything up.
- **Skip-at-exit-0 precondition guard** — an unmet host-tool precondition makes the requesting arm SKIP at exit 0 with a host-path-free precondition plus a fetch recipe, never a hard failure (architecture.md §Occupied Resources — `CONDUCTOR_MSEDGEDRIVER`). NVDA-absent, and the VoiceOver/Orca no-surface-here rows, are the same shape: declared-not-runnable, never a claimed pass and never a failure.
- **Precondition strings name candidate causes, never a claimed measurement** — the readiness gate composes one string per unmet term naming its condition and its candidate causes rather than asserting something Conductor cannot observe (architecture.md §Standard Contracts — Readiness gate). The spec's `announced-differently` / `not-announced` cells inherit that discipline.
- **Self-obs evidence provenance is per-arm** — `logs/conductor-tauri.jsonl` resolves as `runs_dir.parent()/logs`, so the driven arm (handle unset) lands at the workspace root while the `--e2e` arm (`CONDUCTOR_RUNS_DIR=runs/e2e-fixture`) lands at `runs/logs/` (architecture.md §Occupied Resources — On-disk artifacts). Evidence citing a backend log must name which arm produced it.

## Anti-patterns to avoid
- **No second automation stack.** architecture.md §Cross-cutting Patterns (Scope law) permits driving Conductor's OWN webview only as the two suites over ONE WebdriverIO + tauri-driver stack — "never a second automation stack". An SR driver, NVDA add-on or speech-capture harness is exactly that; the chunk's own boundary agrees, and research records driver existence as a finding only.
- **No OS-level announcement surface.** architecture.md §Established Decisions [Real-time Strategy] bans Conductor emitting native OS toasts (those are Pulse behavior Conductor observes via the operator checklist). Every must-announce item is a webview DOM / live-region announcement over `Channel`-driven state, never an OS notification path.
- **Do not register SR/a11y test tooling into arch's stack.** The 2026-06-27 amendment dismissed precisely this as over-reach — arch §Stack and §Inherited Defaults summarize the frontend at React/Vite/Tailwind/npm grain and never enumerate test tooling, which lives in the a11y-plan + the stack.md distillation.

## Contract bindings
- **arch ↔ a11y:** the lamp's announced label follows arch's verdict-first precedence (§Established Decisions [Probabilistic-Assertion Policy]) — the 2026-06-21 amendment resolved the a11y §6 six-lamp conflict exactly this way, so the must-announce row for the verdict lamp must not re-open it. The four states the spec covers are the webview `RunState` set, NOT arch's five `ReportState` values.
- **arch ↔ tests:** the stimulus recipe consumes the same `wdio.conf.ts` + tauri-driver stack, the same `CONDUCTOR_MSEDGEDRIVER` handle and the same `npm run build` → `--features tauri/custom-protocol` build order the harness uses; F14 bans re-authoring any of it, so this chunk is a consumer of that contract only.
- **arch ↔ security/obs:** host-path-free artifact discipline (the readiness-gate `data_dir`-redaction precedent) governs both new files and the evidence record; the per-arm self-obs landing site governs how a cited log is attributed.

## Acceptance criteria contributions
- (arch) The spec and the evidence record land on git-tracked paths inside an already-registered artifact home (candidate `crates/conductor-tauri/ui/test/…`), add ZERO Cargo workspace members, and use kebab-case Markdown filenames (per architecture.md §Occupied Resources — Frontend asset subtree / Crate names · §Conventions Naming patterns).
- (arch) The stimulus recipe names `npm run build` before the cargo compile AND `--features tauri/custom-protocol` on the launched bundle; without the feature the window opens on `devUrl` and the recipe does not reproduce the shipped surface (per architecture.md §Infrastructure Patterns — Build system).
- (arch) The `hold` recipe's firing form carries the `PATH` prefix resolving the sidecar plus the Pulse-side `ANDROMEDA_PULSE_*` declarations, because `PATH` is a spawn-resolution input whose absence yields a BLOCKED-in-2ms preflight indistinguishable from a SUT-side gate failure (per architecture.md §Occupied Resources — Service/process names · Environment variables).
- (arch) No new `CONDUCTOR_*` handle, port, crate, MCP tool or automation stack is introduced, and every string in both artifacts is host-path-free — including the NVDA build's location, of which only the version is recorded (per architecture.md §Occupied Resources — Environment variables · §Standard Contracts — Readiness gate · §Cross-cutting Patterns Scope law).
