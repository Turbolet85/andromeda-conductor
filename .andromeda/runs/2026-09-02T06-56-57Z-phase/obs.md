# obs extract

## Relevance
Partial — the chunk ships documentation artifacts (pass spec + operator evidence record) rather than instrumented code, so obs applies to artifact redaction/agent-readability, to the not-instrumentable classification of the screen-reader surface, and as a guard-rail on the run-stimulus and any P5 pull-in touching the Tauri surface.

## Constraints
- **Host-path-free is an obs ban with concrete anchors, not a stylistic preference.** `{obs-plan} §11 Logs` and the `§9` log-conformance check enumerate the redaction anchors (drive-letter `X:\`, `/home`, `/Users`, `%APPDATA%`, `~/.cargo`, `.rustup`, backtrace file paths) and forbid internal struct names in logs / run-report / runs.db. On this Windows host the live risk is a pasted NVDA line, an installer path, or a WebView2/build path in the evidence record. Note the boundary: `§3` (two record shapes) scopes `conductor-core::redact`'s field allowlist to the **self-obs line only**, so a committed Markdown/JSON spec gets no automatic scrubbing — the discipline is authorial. Whether the chosen artifact home routes through any existing redaction path is research's question.
- **The screen-reader announcement surface is the plan's "not-instrumentable" class.** `{obs-plan} §preamble` (agent-driven invariant) requires every telemetry signal be readable by an agent from a snapshot or pasted excerpt, and mandates that a surface which cannot be is *flagged* not-instrumentable and handled by boundary instrumentation only. The operator's ears are exactly that. The requirement this imposes: the *record* of the pass must be agent-readable even though the *observation* is not.
- **No human-review-gated consumption path without machine-parseable export** (`{obs-plan} §11 Universal`; `§2` Agent-readable invariants). An evidence record that only a human can interpret does not satisfy the invariant; it must be parseable from a paste (`§1`/`§3` name `jq` / `serde_json` as the parse targets).
- **No new span names, no new exporter.** `{obs-plan} §11 Spans/Traces` fixes a bounded span-name set (`scenario.run`, `timeline.execute*`, `emit.batch`, `emit.logs_batch`, `verify.readback*`, `report.generate`, `db.insert_run`, `fault.silence/ramp/port_occupier`, `tauri.command.*`). If a P5-optional attribute-level remedy pulls a `#[tauri::command]` handler into scope, `§4` (auto-instrumentation table) requires the **manual** `tracing::info_span!("tauri.command.<name>").entered()` guard — never `#[tracing::instrument]`, which does not stack with the command macro. The plan records 8/8 sites measured 2026-09-02; re-confirming at HEAD is research's question.
- **Webview recursion guard applies to any diagnostic logging added while probing announcements.** `{obs-plan} §1` (desktop-webview row) and `§11 Universal` require frontend self-observation to be `console.log` JSON only — no OTel JS SDK, no `auto-instrumentations-web`, no browser OTLP exporter, not to `:4317` (the PRODUCT stream) and not to `:4318` (dead per arch).
- **Run identity vocabulary already exists — reuse it rather than minting fields.** `{obs-plan} §3` Correlation makes `run_id` the sole correlation key (no W3C `trace_id`/`traceparent` anywhere); `§3` Service identity fixes `service.name` (`conductor-tauri`, `$CONDUCTOR_SERVICE_NAME` override) / `service.version` (`env!("CARGO_PKG_VERSION")`) / `deployment.environment` (`$CONDUCTOR_ENV`, default `local`); `§9` names `git.commit.sha` for the commit identity the scope's evidence record requires.
- **A Tauri-surface run writes its own self-obs stream.** `{obs-plan} §3` Logging stack requires `logs/conductor-tauri.jsonl` unconditionally (stderr only as an open-failure fallback), each line carrying `timestamp_ms` / `level` / `target` / service identity / `run_id` per `§3`'s self-obs base set — the stimulus recipe's runs therefore leave a citable, already-specified trace independent of the manual pass. Whether the shipped code already writes it that way is research's question.

## Patterns to follow
- **Declare which record shape an artifact is.** `{obs-plan} §3` (two record shapes, per the 2026-06-15 and 2026-08-21 amendments) distinguishes the self-obs line, the eleven-field Run-report envelope, and the per-check `CheckRecord`. The SR evidence record is none of the three — it must not be described as a journal line nor presented as extending the envelope.
- **The a11y↔obs artifact binding is the house shape for machine-readable a11y output.** `a11y-plan §3` (Structured violation JSON schema) reproduces `{obs-plan} §6`'s envelope verbatim and inherits the no-absolute-host-paths / no-seam-struct-names constraint (a11y-plan :94-110, :282). If the evidence record is emitted as JSON, this is the existing shape to align to rather than a new schema.
- **Carry unschematized identifiers on the allowlisted `message` field.** `{obs-plan} §6` Boundary-call wrappers (key-set witness; incident id on the lifecycle write) establishes the convention for recording a string the schema has no field for — the precedent if the evidence record needs a free-text "heard" value inside a structured line.
- **Retire-on-measurement, don't silently diverge.** `{obs-plan}` amendment practice (2026-08-21 severity chain, 2026-09-01 command mechanism) is to record a plan-vs-shipped divergence as an amendment with the measurement attached — the frame the chunk's a11y-plan four-state naming finding should take for wrap.

## Anti-patterns to avoid
- Producing an evidence record with no machine-parseable form — `{obs-plan} §11 Logs` bans unstructured text an agent cannot parse fields from, and `§11 Universal` bans human-review-gated analysis without machine-parseable export.
- Leaking an absolute host path or internal struct name into a committed artifact (`{obs-plan} §11 Logs`; `§9` conformance anchors) — the NVDA install path, WebView2 path, and any pasted backtrace are the live vectors here.
- Adopting any candidate SR-driver / speech-capture tooling that ships its own OTel SDK, browser OTLP exporter, or W3C trace context (`{obs-plan} §11` Telemetry Strategy / Spans / Universal). Existence of such a driver is a research finding only per the chunk's Boundaries; the obs ban is why it could not simply be wired in even if found.

## Contract bindings
- **obs §6 log format ↔ a11y-plan §3 Structured violation JSON schema** — obs fixed the schema, a11y narrows it; a11y artifacts inherit obs's no-host-path constraint (a11y-plan :94-110). Whether this chunk's evidence record adopts that shape is a P4 decision, not an obs mandate.
- **obs §3 harness contract ↔ tests §3** — `{obs-plan} §3`/`§6` state that the JSONL format is a *binding contract owned by tests* ("obs aligns to tests, not vice versa"). If the artifacts land in the ui test tree, the format owner for anything journal-shaped is tests, not obs.
- **obs §4 `tauri.command.*` bounded set ↔ the Tauri command surface** — binds only if a P5 remedy touches a handler; the mechanism constraint above is obs's side of it.
- **obs §9 CI artifact handling ↔ v2-24 (A11y CI gate + violation JSON)** — that binding is explicitly pooled and out of this chunk's scope; flagged so the SR evidence record is not shaped as if it were the CI violation artifact.

## Acceptance criteria contributions
- The committed spec and evidence record contain no absolute host path (no `X:\` drive-letter, `%APPDATA%`, `~/.cargo`, `.rustup`, `/Users`, `/home` token) and no internal struct names — the same anchors the CI conformance gate enforces (per `{obs-plan} §11 Logs` / `§9 Log conformance check`).
- The evidence record is parseable by an agent from a paste with no human-only step (JSON via `jq`/`serde_json`, or a stable machine-readable table) (per `{obs-plan} §2 Agent-readable invariants` / `§11 Universal`).
- Each recorded state's stimulus is correlated to its run by `run_id`, and no W3C trace context / `traceparent` is introduced to tie the surfaces together (per `{obs-plan} §3 Correlation` / `§11 Spans`).
- No new span name and no self-observation exporter are added; any handler touched by a P5 pull-in keeps the manual `tracing::info_span!("tauri.command.<name>").entered()` guard inside the bounded `tauri.command.*` set (per `{obs-plan} §11 Spans/Traces` / `§4 auto-instrumentation table`).
