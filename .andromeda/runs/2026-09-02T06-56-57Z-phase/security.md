## Relevance
**partial** — no code, no dependency and no new boundary is expected, but the chunk commits two new cross-host artifacts and documents a sidecar-spawn stimulus recipe, both of which fall under existing mandates.

## Constraints
- Both new committed artifacts (the per-state pass spec and the evidence record) are agent-parseable ground truth shared across hosts, so they must carry **no absolute host path** (no expanded `CONDUCTOR_RUNS_DIR`, no expanded `ANDROMEDA_PULSE_DATA_DIR`) and **no internal seam-crate struct/field name** (per security-plan §Error Handling → Run-report artifact sanitization; §Security Anti-Patterns → Logging). The scope's own "host-path-free" requirement and this mandate are the same rule; the spec's stimulus recipe must name env **handles** and placeholders, never this host's resolved values.
- The stimulus recipe for `hold` must not weaken the sidecar-spawn controls it describes: the sidecar is a fixed hard-coded program **NAME** resolved through the inherited `PATH` (never a config-derived or operator-supplied command string), and `ANDROMEDA_PULSE_DATA_DIR` travels strictly via the `.env(...)` builder, never interpolated into argv or a shell string (per security-plan §Security Anti-Patterns → Input; §Input Validation → `ANDROMEDA_PULSE_DATA_DIR` row). The recipe documents an environment, not a new spawn path.
- `PATH` is itself a spawn-resolution input, and the plan records the measured failure mode: a mis-resolved sidecar reports `[BLOCKED]` in ~0s, **indistinguishable at row level from a genuine SUT-side gate failure** (per security-plan §Security Anti-Patterns → Input, 2026-08-20 diagnostic). The recipe must therefore let the operator distinguish a real `hold` from a fast `blocked`, or the state the spec claims to have exercised may not be the state that rendered.
- What NVDA speaks from the `role="alert"` error nodes IS the sanitized boundary text: §Error Handling requires the `#[tauri::command]` edge to expose no stack trace, absolute path, library version or internal seam-crate struct name to the webview. An announced absolute path or struct name is a **security** finding against the `sanitize_error` edge, not only an a11y one. Whether the shipped error prose already satisfies that mandate is research's question.
- The chunk's own boundary (no SR driver, no NVDA add-on, no second automation stack) keeps the tree static, which restores "no dependency delta" as an available basis when re-pinning the advisory-DB deferral (per security-plan §Dependency Security, advisory-DATABASE-fault bullet). If any package nonetheless lands, it may only do so on `cargo deny check advisories bans licenses sources` **VERIFIED** green over the new `Cargo.lock`; an npm addition additionally requires `npm audit --omit=dev` clean with `package-lock.json` committed (per §Dependency Security → Frontend (npm) supply chain).
- The new artifacts fall under the workspace-wide no-secrets invariant — no secret-shaped string, no `.env`, no credential may enter them; the operator-supplied "heard" text and version/commit identity fields are the only sanctioned content grain (per security-plan §Secret Management; §Security Anti-Patterns → Secrets).
- If `live`/`hold` is produced through the driven arm (`npm run a11y:driven`) rather than a hand-launched bundle, the `CONDUCTOR_MSEDGEDRIVER` guard governs (existence + `isFile` + shell-metacharacter rejection, then a separate element of an array-form spawn; unset-or-not-a-file ⇒ skip at exit 0) and the harness-lifetime `127.0.0.1:4444`/`:4445` listeners are the sanctioned dev-only carve-out from the inbound-listener ban (per security-plan §Input Validation → `CONDUCTOR_MSEDGEDRIVER` row; §Security Anti-Patterns → Code Patterns rule (b), → Universal).

## Patterns to follow
- **Identity-only rows for unmeasured outcomes** — §Error Handling specifies a `blocked` row populates only identity fields with a named precondition string while measurement fields stay `null`. The evidence record's not-announced / not-run-here rows should take the same shape: name the precondition, never fabricate a heard value.
- **`declared-not-observable`, never a claimed measurement** — §Security Anti-Patterns → Universal (never-downgrade ban) establishes that a term whose truth lives outside Conductor's reach is recorded as declared-not-observable and never asserted. VoiceOver/Orca rows follow exactly this precedent: declared-not-runnable-here notes, never claimed passes.
- **Fixed-path committed artifacts with deliberately no `CONDUCTOR_*` override handle**, resolved through `resolve_under` (per §Input Validation → committed SUT-facing manifests row). If the spec/evidence get a resolved home, follow that pattern rather than adding a new operator-steerable env handle.
- **`resolve_under` traversal guard + `sanitize_error` at the `#[tauri::command]` edge** (per §Input Validation → `#[tauri::command]` IPC arguments row) — the shipped pattern governing the `run_report` / `run_envelope` reads the terminal-state stimulus exercises; read-only for this chunk.
- **`e.kind()`-only read faults, never the path** (per §Input Validation → committed manifests row) — the established idiom if any new file read is introduced.

## Anti-patterns to avoid
- NEVER let the committed spec or evidence record leak absolute host paths or internal seam-crate struct/field names (per security-plan §Security Anti-Patterns → Logging) — they are cross-host ground truth, not local scratch notes.
- NEVER write the stimulus recipe as an operator-chosen command string or a shell interpolation of `ANDROMEDA_PULSE_DATA_DIR` / the `PATH` prefix; an operator value may appear only as a separate array-form argv element after metacharacter rejection (per §Security Anti-Patterns → Input, → Code Patterns).
- NEVER admit an SR driver / speech-capture package as an incidental convenience — it is a dependency delta under a persisting red-advisory-DB wait, admissible only on the verified-green deny condition (per §Dependency Security).

## Contract bindings
- **Artifact hygiene ↔ a11y-plan §3 pass-spec format + obs artifact conventions:** the spec's row format and the evidence record's identity fields are a11y/obs-owned; the host-path-free and no-struct-name bound on their CONTENT is security's (§Error Handling). No PII binding applies — §Threat Model Summary classifies PII as "none".
- **Error sanitization ↔ the must-announce list for `role="alert"`:** a11y owns whether the error is announced; security owns what the announced string may contain (§Error Handling → External responses). A finding here is dual-domain.
- **Dependency gate ↔ tests §CI Integration:** the existing `cargo audit` / `cargo deny` + `npm audit --omit=dev` jobs are the gate; a zero-delta chunk adds no job, only the un-drifted-lock check.

## Acceptance criteria contributions
- The new spec and evidence artifacts contain no absolute host path (no drive-letter path, no expanded `%APPDATA%`/`$HOME` value) and no internal seam-crate struct/field name — grep-verifiable (per security-plan §Error Handling, Run-report artifact sanitization + §Security Anti-Patterns → Logging).
- `Cargo.lock` and `package-lock.json` are un-drifted for this chunk; if any package lands, `cargo deny check advisories bans licenses sources` is recorded VERIFIED green over the new lock and `npm audit --omit=dev` reports 0 (per security-plan §Dependency Security, advisory-DATABASE-fault bullet + Frontend (npm) supply chain).
- The stimulus recipe expresses the sidecar environment as env handles only — no operator-supplied value appears as a spawn program or inside a shell string, and `ANDROMEDA_PULSE_DATA_DIR` is described as an `.env(...)`-passed value (per security-plan §Security Anti-Patterns → Input and → Code Patterns).
- Any absolute path, stack trace, library version or internal struct name heard aloud during the operator pass is recorded as a security finding against the `sanitize_error` edge, not filed as an a11y-only observation (per security-plan §Error Handling, External responses).
