# tests extract

## Relevance
Partial — the chunk delivers a manual (non-agent-driven) verification artifact, so tests owns the flagged-untestable discipline, the harness/CI non-entanglement rules, and the stimulus recipes that reuse harness mechanisms; the must-announce content itself is a11y's.

## Constraints
- A surface that cannot be agent-driven must be FLAGGED as untestable and handled as such — never given an invented driver (per test-plan §preamble agent-driven invariant + §1 Untestable zones). §1's untestable-by-agent list today names only the `drive+observe` visual/UX confirmation step, so a screen-reader manual pass has no flagged zone yet; whether the spec's home/flagging already exists in-repo is research's question, and adding the zone is a wrap-amendment question, not a phase edit.
- No manual step may enter an automated test path or a CI gate; the single sanctioned exception is the explicitly-flagged `drive+observe` operator checklist, which is a product feature rather than a test step (per test-plan §11 Universal). The NVDA pass must therefore sit outside the 5-command harness and outside every §9 stage.
- The desktop-webview stack is ONE non-interactive driver (@crabnebula/tauri-driver via `wdio run`) carrying exactly TWO arms — the unattended routine arm (`--e2e` → `accessibility.e2e.ts`) and the operator-only driven arm (`npm run a11y:driven`) — and interactive/recorder runners are banned (per test-plan §6 Drivers per surface, §11 Universal, §12 Decisions Log E2E driver choice). No third automation stack may be adopted here; recording whether an SR driver exists is a finding, not an adoption.
- Any live-Pulse stimulus (the `hold` state) is an operator/local gate ONLY, never a CI gate, and its FULL FIRING FORM is part of the leg: PATH-resolved sidecar program NAME, `ANDROMEDA_PULSE_MCP_ENABLED` + `ANDROMEDA_PULSE_L4_DETERMINISTIC`, `ANDROMEDA_PULSE_DATA_DIR` equal to the live Pulse's data dir, and a ≥120s quiet window + 30s resolver tick after any preflight canary (per test-plan §6 desktop-webview, §9 Live-Pulse scenarios, §11 CI).
- The spec's node/anchor vocabulary must be role / accessible-name / text / `aria-live` — never xpath, never hashed CSS classes — reusing the established anchors: the closed six-label lamp set plus the run-level `[ENVIRONMENT-SUSPECT]` qualifier, `role="alertdialog"`, and the signature heading text "HOLD — operator pause" (per test-plan §6 Selector strategy + §1 Surfaces under test / cli Signal).
- Committed artifacts must not leak absolute host paths or internal seam-crate struct names (per test-plan §3 Status endpoint shape + Log format) — the chunk's own host-path-free requirement for the spec and evidence record is the same rule.
- If any committed journal fixture is added or reused as a stimulus, it must come from the sanctioned provenance set AND carry its MEANING under test via a production-reader round-trip, so a persist-side change cannot leave it parseable-but-inert (per test-plan §7 Self-bootstrapping requirement).

## Patterns to follow
- Fixture-seeded subject: the routine arm copies a committed journal fixture into a gitignored runs dir and points the spawned app at it via a repo-relative `CONDUCTOR_RUNS_DIR` (`resolve_under` rejects absolute paths and `..`), which is how populated verdict lamps / report rows are produced with NO live Pulse (per test-plan §3 CI stage selectors + §7). This is the cheapest candidate stimulus for the report-populated terminal sub-state of `idle`; whether the launched app honours that handle outside the wdio spawn is research's question.
- Release-bundle precondition: ensure-frontend → release build with `--features tauri/custom-protocol` (a plain `--release` binary loads `devUrl`) → launch (per test-plan §3 CI stage selectors) — the same precondition the chunk's `idle` stimulus names.
- Declared-not-runnable-here expressed as an explicit gated skip at exit 0 rather than an assumed pass — the `CONDUCTOR_MSEDGEDRIVER` precedent (unset or not-a-file ⇒ skip at exit 0), and §1's coverage trigger split by who READS the handle (per test-plan §6 desktop-webview + §1 Coverage triggers). VoiceOver/Orca rows follow this shape.
- Measured-verdict discipline: a platform/capability verdict is recorded as MEASURED with its date and host, and a superseded verdict is corrected in place rather than silently carried (per test-plan §12 Decisions Log 2026-09-01 correction + §6 notes) — the model for the "no automated SR tool exists" claim the chunk records as a finding.
- Two-tier grading precedent: an unreachable or model-interpretive claim is reported (declare-only / CalibrationRegion / recorded-not-asserted), never hard-failed, while a hard claim is graded where evidence actually exists (per test-plan §6 scenario grading + §11 E2E assertion-policy split) — the model for "the acceptance is a recorded pass, not a green one".

## Anti-patterns to avoid
- NEVER add a manual smoke step ("developer verifies before deploy") to a test path, a `scripts/agent-run.{sh,ps1}` command, or a CI stage (per test-plan §11 Universal); §9's stage table is CI's complete gate inventory, so a new stage would be a plan amendment, not a phase action.
- NEVER include "human reviews screenshots" or Percy/Chromatic/Applitools-class visual regression — evidence is role/text/`aria-live`/heard-speech text, not images for review (per test-plan §11 Universal).
- NEVER let an unrun, skipped, or not-announced row read as a pass, and never convert a reported state into a non-zero process exit (per test-plan §6 desktop-webview "a context-skip is never a pass" + §11 E2E).

## Contract bindings
- tests ↔ a11y: the a11y-plan owns the must-announce content and the pass-spec format the chunk instantiates; test-plan §6/§11 own the selector/anchor vocabulary the spec's node column must use and the rule that this pass never wires into the 5-command discipline. The A11y CI gate (route `v2-24`) is where a11y assertions bind to test-plan §9's stage table — pooled, not this chunk.
- tests ↔ obs: test-plan §3 Log format is the SOURCE OF TRUTH obs-plan §3 derives from. The spec and evidence record must be standalone artifacts — adding a record shape to `runs/<run_id>.jsonl` or to the self-obs stream would break the §3 ↔ obs-plan §3 agreement (per test-plan §3 Log format / Agent parsing / Self-obs stream).
- tests ↔ harness (self): the 5-command surface, `status` disk read, and envelope/JSONL shapes must stay unchanged by this chunk (per test-plan §3) — F14's "do NOT re-author the harness" and §3 agree.

## Acceptance criteria contributions
- (tests) The harness is provably untouched: `wdio.conf.ts` and its spec inventory unchanged, and the routine arm still runs — `scripts/agent-run.{sh,ps1} run --e2e` (Windows leg `CONDUCTOR_MSEDGEDRIVER`-gated, skip at exit 0 when unset) exits 0 with the same spec set as before; new artifacts must not land where the wdio `specs` glob would pick them up (per test-plan §3 CI stage selectors + §6 Drivers per surface).
- (tests) The NVDA manual pass appears in NO CI stage and NO `agent-run.{sh,ps1}` command path, and the spec/evidence carry no instruction that a gate depends on the operator's pass (per test-plan §9 CI pipeline + §11 Universal/CI).
- (tests) Standing gates stay green with no new Rust: `cargo nextest run --workspace --profile ci`, the runner-portability leg `cargo test -p <crate>`, `cargo clippy --workspace --all-targets -- -D warnings`, and workspace line coverage ≥ 60% (per test-plan §4 + §9 + §10).
- (tests) Every spec row records an explicit outcome (announced-as-expected / announced-differently / not-announced) with the heard text; a not-announced or not-runnable-here row is recorded as such and never counted as a pass, and no row is graded as a hard failure exit (per test-plan §6 "a context-skip is never a pass" + §11 E2E assertion-policy split). Any committed fixture introduced as a stimulus additionally carries a production-reader round-trip pinning its meaning (per test-plan §7).
