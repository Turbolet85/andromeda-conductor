## Constraints
- **The run-report envelope is a locked shared shape, not a per-surface struct.** Per architecture.md §Standard Contracts (Run report envelope), the Markdown report and the `runs.db` row share the eleven-field envelope with closed sets `verdict ∈ {Pass, Fail, CalibrationRegion}` / `state ∈ {Pass, Fail, ManualCheck, KnownResidual, Blocked}`, and the envelope's shape is required to stay byte-unchanged; the per-check `CheckRecord` (nine keys) is registered as a SECOND shared shape riding the JSONL journal, the `run_check` table and the report. A parity proof must be field equality over those shapes — this chunk may not extend either.
- **`runs.db` is three tables with fixed keys, and `run_id` is both PK component and journal stem.** Per architecture.md §Occupied Resources (On-disk artifacts) the tables are `runs` (PK `(run_id, scenario)`), `run_envelope` (keyed `run_id`, `classification`/`cause`) and `run_check` (`(run_id, scenario, check_index)`); per §Standard Contracts (Timestamp formats) `run_id` is the filesystem-safe hyphen stamp that is also the `&lt;run_id&gt;.jsonl` / report stem. Two runs sharing one DB therefore co-exist as distinct rows and distinct journals BY CONSTRUCTION — which is why the scope's "field equality, never artifact identity" framing is the only one arch permits.
- **Workspace placement is fixed: one composition root, two thin shells.** Per architecture.md §Occupied Resources (Crate names) `conductor-run` sits above the seams and below both bins, shared by `conductor-cli` and `conductor-tauri`; §Established Decisions [Workspace / Core Structure] + [Module Boundaries] make the headless/CLI/GUI split compiler-enforced. Arch requires the divergence surface to be the shells only; whether the two shells today write the same envelope fields for one seed is research's question.
- **Same scenario + seed ⇒ same emission-stream shape is a runtime-flavor mandate, including under Tauri.** Per architecture.md §Design Philosophy and §Established Decisions [Async Runtime Flavor] the core owns a hand-built `Builder::new_current_thread()` under Tauri so Tauri's own multi_thread runtime stays the shell's concern, and §Established Decisions [Determinism RNG] pins `ChaCha8Rng`/`seed_from_u64` as the sole non-determinism source. Whether the shipped `#[tauri::command]` path actually builds the core-owned `current_thread` runtime (rather than borrowing Tauri's) is research's question — it is the premise the parity claim rests on.
- **The rust gate has a build-order precondition and a pinned runner profile.** Per architecture.md §Infrastructure Patterns (Build system), `tauri-build`'s `generate_context!` resolves `build.frontendDist` (`ui/dist`) at COMPILE time, so `npm run build` must precede any workspace `cargo build`/`nextest`/`clippy` that compiles `conductor-tauri` (the `ensure_frontend` step; a bare cargo build does NOT run `beforeBuildCommand`); nextest is the pinned runner driven through the zero-retry `ci` profile in `.config/nextest.toml` (no retries mask flakes — the determinism invariant), plus `cargo test --doc`. Separately, the `tauri/custom-protocol` FEATURE — not the profile — decides bundle-vs-`devUrl`.
- **The load-envelope terms and the empty exemption ledger are locked, and gate and caption share ONE basis.** Per architecture.md §Occupied Resources (`contracts/pulse-load-envelope.toml`), the two SUSTAINED terms are the asserted ones judged per emitting phase, `check_load_envelope` (static catalog gate) and `LoadEnvelope::classify` (the per-run `[ENVIRONMENT-SUSPECT]` caption) read one shared basis so they cannot mean different things, and `[[exempt]]` is EMPTY and held at exact-set equality in BOTH directions. Consequence for the CARRY-2 fork: a live `EnvironmentSuspect` classification cannot be manufactured by widening the ledger or re-tuning a term, and a catalog scenario that genuinely breaches a sustained term would by that shared basis also fail the static gate — whether any admissible run shape can classify over-envelope while the catalog gate stays green is research's question.
- **The read-back client's identity is a locked decision, and the pinned manifest is a registered resource.** Per architecture.md §Established Decisions [MCP Read-Back Client] (rmcp removed 2026-06-27) and §Conventions (Inbound verification), the current client is hand-rolled line-delimited JSON-RPC over the sidecar's stdio — `initialize`/`tools/list`/`tools/call` returning the RAW `serde_json::Value`, version negotiation read from the `initialize` result — while `contracts/mcp-contract.toml` (§Occupied Resources) stays pinned at protocol `2024-11-05`. Any v2-28 reconciliation must land on exactly that description; arch is the authority the three named docs and the `conductor-verify` doc comment must match.

## Patterns to follow
- **`CONDUCTOR_RUNS_DIR` as the single relocation handle.** Per architecture.md §Occupied Resources (Environment variables) it moves journals, reports and `runs.db` together — the existing mechanism for pointing two surfaces at one DB, needing no new handle.
- **Self-obs sinks follow that same handle as siblings.** Per architecture.md §Occupied Resources (`logs/agent-latest.jsonl`, `logs/conductor-tauri.jsonl`), the sink resolves as `runs_dir.parent()/logs`, and the landing site is per-suite because the ONE tauri-driver spawn site chooses `CONDUCTOR_RUNS_DIR` per invoked suite. A shared parity runs dir therefore co-locates both shells' self-obs streams — expected, not a defect.
- **Fixed-path contracts resolution through `resolve_under`.** Per architecture.md §Occupied Resources, the capability manifest, load envelope and run contract each resolve from a fixed `default_path()` with deliberately NO `CONDUCTOR_*` override — the precedent for reading a committed `contracts/` artifact.
- **Skip-at-exit-0 host-tool handles.** Per architecture.md §Occupied Resources (`CONDUCTOR_MSEDGEDRIVER`, `CONDUCTOR_NVDA`), each is validated at the harness edge (existence + `isFile` + shell-metacharacter rejection), passed as a separate argv element of an array-form spawn, never interpolated into a shell, and unset ⇒ SKIP at exit 0 with a host-path-free precondition. The banner DOM arm rides `CONDUCTOR_MSEDGEDRIVER`; the version confirmation is a read of that handle's target, never a committed value.
- **Never synthesize a value for something never measured.** Per architecture.md §Standard Contracts (Run report envelope + Per-check record) and §Occupied Resources, a blocked row populates identity fields only with the rest JSON `null`, and a blocked or declare-only scenario writes ZERO `run_check` rows. A seeded fixture `run_envelope` row is fixture data for a render proof, not a produced classification — the two must not be conflated in what the proof claims.

## Anti-patterns to avoid
- **No new inbound listener and no HTTP surface.** Per architecture.md §Established Decisions [Backend Framework] and §Cross-cutting Patterns (Trust boundary), the only bind in a SHIPPED binary is the `:4317` port-occupier fault; `4444`/`4445` are dev-only, harness-lifetime.
- **No second automation stack and no new `CONDUCTOR_*` handle for a `contracts/` manifest.** Per architecture.md §Cross-cutting Patterns (Scope law) — three suite families over ONE WebdriverIO + tauri-driver stack — and §Occupied Resources (the manifests' deliberate no-override rule).
- **Never widen `[[exempt]]` or re-tune a load-envelope term to manufacture the banner subject**, and do not "fix" the rate term here: per architecture.md §Occupied Resources (`contracts/pulse-load-envelope.toml`) the dispatch-vs-wire-span misnaming is SURFACED-not-authored, owned by a working-route entry.

## Contract bindings
- **Envelope + `CheckRecord` ↔ tests / obs:** the eleven-field envelope and the nine-key check record are the shapes the parity fixtures assert and the JSONL journal serializes (architecture.md §Standard Contracts) — tests owns the driver pair, arch owns the shape.
- **`CONDUCTOR_RUNS_DIR` ↔ obs:** sharing one runs dir also relocates both shells' `tracing` JSON sinks (`runs_dir.parent()/logs`), so obs' landing-site expectations move with the parity fixture.
- **`ensure_frontend` + `tauri/custom-protocol` ↔ tests build profiles:** the rust gate and any driver-backed webview arm inherit the compile-time frontend dependency and the feature-decided bundle (architecture.md §Infrastructure Patterns).
- **Read-back client identity ↔ tests harness docs:** architecture.md §Established Decisions [MCP Read-Back Client] is the authority `test-plan.md` / `tests-summary.md` / `verification-harness.md` must be reconciled against for v2-28.
- **Live leg ↔ security:** if the live fork is taken, architecture.md §Occupied Resources requires `ANDROMEDA_PULSE_DATA_DIR` propagation to the spawned sidecar, and §Standard Contracts requires every precondition string to be host-path-free with `data_dir` redacted; `PATH` is a spawn-resolution input for the fixed-NAME sidecar binary.
