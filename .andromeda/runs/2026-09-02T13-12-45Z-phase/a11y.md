## Constraints
- The load-envelope banner is a **non-interactive text qualifier, deliberately NOT a lamp role** — its always-rendered `label` (plus optional `cause`) carries the signal, the recessive `--status-residual` tint is never the sole signal, and the element is omitted entirely when the run stayed in-envelope; SCs in reach are 1.4.3 + 1.4.1 (per a11y-plan.md §4 per-component catalog, load-envelope banner row). Whether the shipped DOM already renders the label this way is research's question.
- The banner (like the out-of-scope Mode cell) must **not be treated as a seventh lamp state** — the not-color-alone assertion keys on the six LAMP display labels (`Pass`/`HOLD`/`Fail`/`Blocked`/`Manual`/`Residual`), so a token-tinted non-lamp element neither satisfies nor fails that assertion (per a11y-plan.md §1 "non-lamp reuse of a state token" + §6 State color tokens).
- Contrast for the banner is owed at **SC 1.4.3 4.5:1, not the 3:1 a non-text indicator owes**, on both pairs `--status-residual`/`--color-raised-1` and `--status-residual`/`--color-base`, asserted render-independently by token NAME in both declared themes — a11y-plan.md §6 records this pair as the banner's *only* asserting coverage until a rendered-DOM subject exists (per a11y-plan.md §6 Color contrast pairs).
- The run-report view is one of the four **must-be-accessible paths** carrying the zero-WCAG-AA-violations invariant: `violations.length > 0` ⇒ non-zero exit, no retry-once policy, no soft SLO (per a11y-plan.md §10 SLO Invariants). Whether the banner state currently produces zero violations is research's question — it has never been run.
- **One webview-automation stack only**: axe injects via `@axe-core/webdriverio` into the tests §6 `@crabnebula/tauri-driver` + WebdriverIO session; no parallel puppeteer/CDP attach, and the axe tag scope stays `withTags(['wcag2a','wcag2aa','wcag21aa'])` with `wcag22aa` unset (per a11y-plan.md §3 A11y testing tool pick + Configuration). This matches the chunk's own "No second automation stack" boundary.
- A11y result artifacts fold into the **obs §6 envelope** (axe rule-id + WCAG-SC tag + node selector inside `fingerprints[]`, envelope `state` = `Fail` iff violations exist) and **MUST NOT leak absolute host paths or internal seam-crate struct names** — selectors are DOM-relative / `data-testid` only (per a11y-plan.md §3 Structured violation JSON schema). Load-bearing here because the chunk introduces a fixture `TempDir` runs dir and, if the live leg is taken, an operator-printed fresh Pulse data dir.
- The **cli surface is not-assertable** — no DOM/widget tree, no axe/Lighthouse reach; the CLI half of the parity proof has no a11y verification path, and its ASCII/`NO_COLOR` discipline is output-stream discipline, not an ARIA path (per a11y-plan.md §1 A11y scope, cli entity).
- Arm placement follows the subject mechanism: the unattended ROUTINE `--e2e` arm seeds its own committed-journal fixture subject; the operator-only DRIVEN arm requires a live Pulse plus its full firing form and carries the 15-minute mocha ceiling with a quiet-window precondition costing two 12-minute runs when violated (per a11y-plan.md §9 E2E row + §10 performance budget). P4's seeded-vs-live fork therefore also decides which arm the banner assertion lands on.

## Patterns to follow
- Routine-arm subject seeding: the `--e2e` arm SEEDS its own fixture subject so DOM state is asserted for real, and a spec whose state the fixture cannot produce **context-skips, never passes green** (per a11y-plan.md §9 E2E row) — the pattern the banner spec currently sits on.
- Two-layer contrast verification: axe-core `color-contrast` on rendered-DOM ratios **plus** the `colorjs.io` v0.6.1 token-NAME checker emitting `{ token_fg, token_bg, ratio, required, pass }` per named pair — token names verbatim, raw values stay in design-system.md (per a11y-plan.md §3 Contrast verification harness + §6 Verification).
- not-color-alone assertion via DOM text-content + axe, keyed on display labels with the display-label ↔ obs-enum crosswalk used for any join back to a journal row (per a11y-plan.md §6 State color tokens).
- Results surface through the tests' binding 5-command harness via the **`logs`** command; the gate stays operator/local, not CI-wired (per a11y-plan.md §3 CI integration + §9 Pipeline integration).
- Platform handling for the driver: one stack running on Linux+`xvfb` and headfully on the Windows WebView2 host under `CONDUCTOR_MSEDGEDRIVER` (unset ⇒ skip at exit 0); macOS manual-pass-only (per a11y-plan.md §3 Bootstrap `a11y-ci-gate-wire` + §9 Platform) — the frame the chunk's msedgedriver `--version` confirmation lands in.

## Anti-patterns to avoid
- NEVER stand up a second browser-automation stack (puppeteer/CDP) for the banner proof (per a11y-plan.md §11 CI).
- NEVER treat the cli surface as accessibility-assertable, and never claim WCAG conformance without machine-verifiable JSON evidence (per a11y-plan.md §11 Universal + §11 Strategy).
- NEVER let a11y artifacts leak absolute host paths or internal seam-crate struct names into the obs §6 envelope — including the fixture temp dir and any operator-printed Pulse data dir (per a11y-plan.md §11 SLO).
