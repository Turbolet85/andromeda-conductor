## Patterns to follow
- The `not-conductors` Mode-cell precedent — a non-lamp classification riding outside the lamp column with an always-rendered text label and a recessive tint, adapted per surface, never forked (per layout-templates.md §Component — Primary content block 1). The envelope banner is explicitly modeled on it.
- Distinct non-result states are never downgraded to Fail, and are distinguished by TEXT rather than tint alone (per layout-templates.md §Component — Primary content block 2). An over-envelope run is a qualifier on a run whose per-check lamps are unchanged.
- The run-report card is the terminal render site: `color-raised-1` card, `border-subtle` seam, `radius-md`, banner directly beneath the card header (run_id / seed) and above the verdict lines (per layout-templates.md §Wireframe — Idle with a report).
- The single-station model has no routes, no breakpoints, no deep links — the frameless window IS the surface and the operator moves through run STATE (`idle` · `live` · `hold` · `aborted`, idle-with-report a sub-state of `idle`) (per layout-templates.md §Primary screens, §IA notes). The banner proof therefore has to drive the console into the idle-with-report state, not navigate to a report route.
- Live counters arrive over ONE Tauri `Channel`; there is no polling / SSE / URL surface (per layout-templates.md §IA notes). Parity between shells is about what each persists and renders, not about a shared transport.

## Anti-patterns to avoid

- Do not reuse `--status-fail` or `--count-blocked` (or any lamp-set token) for the envelope/out-of-scope recessive treatment — a lamp token reads as a verdict (per layout-templates.md §Component — Primary content block 1, Mode cell).
