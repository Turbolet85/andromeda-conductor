## Patterns to follow
- **Cross-process DB sharing**: §3 (Test data bootstrap → Per-test isolation) and §7 (Seed strategies) — `assert_fs::TempDir` + `.env("CONDUCTOR_RUNS_DIR", temp.path())` so the CLI subprocess and the Tauri mock runtime write the same file `runs.db`; `rusqlite::open_in_memory()` for unit/golden tiers.
- **Mock-runtime IPC test shape**: §5 (Driver(s) + deferral bullet) — `tauri::test::mock_builder()` + `mock_context(noop_assets())` + `get_ipc_response()` behind the `test` feature, with each read-only command asserted against whichever seam source it single-sources (`run_envelope` ← `conductor-report`'s `RunsDb::get_envelope` via `conductor_run::read_envelope`). This is the standing tier the banner's data path already rides.
- **The routine `--e2e` leg's firing form**: §3 (CI stage selectors) + §6 (desktop-webview) + §9 (E2E row) — ensure-frontend → release build with `--features tauri/custom-protocol` → seed the fixture runs dir (repo-relative `CONDUCTOR_RUNS_DIR`, since `resolve_under` rejects absolute paths and `..`) → `wdio run` non-interactively with the tauri-driver child spawned at workspace-root cwd, 15-min mocha ceiling, clean re-seed per session.
- **Selector discipline for the banner assertion**: §6 (Selector strategy) — role/text/data-testid + brand anchors; `[ENVIRONMENT-SUSPECT]` is the named run-level **non-lamp** qualifier outside the closed six-label lamp set; no xpath, no hashed CSS classes, no visual-pixel comparison.
- **Envelope golden discipline**: §7 (Golden artifacts) — insta in CI/assert mode redacting `run_id`/`journal_emitted_at`/`read_back_observed_at`; never `cargo insta review`.

## Anti-patterns to avoid
- §11 (Test Data) + §7 — never hand-populate `runs.db` or share mutable state across parallel tests; a directly-INSERTed `run_envelope` row to create the banner subject is the developer-seeded-DB class the plan bans.
- §11 (Integration) — never rely on nextest's per-test process to isolate from a process-global, first-install-wins singleton (`init_observability`); such a test gets its own test binary, never `--test-threads=1`. A parity test that drives two shells inside one binary sits squarely in this hazard.
- §11 (E2E) — never `sleep(N)` for synchronization (wait on envelope `state`, a journal line, a role/`aria-live` signal, or the exit code), and never treat `Blocked`/`KnownResidual`/`ManualCheck`/`CalibrationRegion` as a non-zero exit — which is the likely shape of both parity rows absent a live Pulse.
