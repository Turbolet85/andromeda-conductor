## Constraints
- Both-surface parity must remain an envelope comparison: obs-plan §4 (Both-surface parity scenario) and §3 (Correlation) require parity be asserted by the `runs.db` eleven-field envelope (same seed ⇒ same `verdict`/`state`), matched by `(scenario, seed)` — never by trace continuity. Wherever the test relocates, that is the assertion it must keep.
- obs-plan §4 (auto-instrumentation table, desktop-webview row) requires each `#[tauri::command]` handler to open a MANUAL `tracing::info_span!("tauri.command.&lt;name&gt;").entered()` guard, because `#[tracing::instrument]` does not stack with the command macro; §1 (telemetry-surfaces desktop-webview row) states the requirement over all EIGHT handlers. Mutation-driven edits to `commands.rs` may not convert or drop those guards.
- obs-plan §11 (Spans / Traces) fixes a bounded span-name set whose Tauri member is the `tauri.command.*` wildcard; a relocation/rename must stay inside it, and §6 (Boundary-call wrappers, DB READ bullet) forbids minting a `db.*` read span for the envelope read the parity path performs.
- obs-plan §3 (Log file location) requires the Tauri backend sink's file NAME to be fixed while the DIRECTORY rides `CONDUCTOR_RUNS_DIR` (`&lt;runs_dir.parent()&gt;/logs/conductor-tauri.jsonl`); a fresh-target-dir or temp-dir leg must carry that handle or the sink lands in the project root. Whether the existing parity test already sets `CONDUCTOR_RUNS_DIR` for its arms is research's question.
- obs-plan §3 (Logging stack, agent-mode flag) requires `CONDUCTOR_AGENT_MODE` to be a READ-ONLY trigger (`flag || env-set`) that Conductor never writes; a relocated harness must hand env to the child through the command builder, never a process-wide `set_var` (edition-2024 `unsafe`, and mutants/nextest run tests in parallel processes).
- obs-plan §6 (per-module log levels, "a per-target directive REPLACES the default") bans setting `RUST_LOG` in any form for a leg that also executes the test suite — the environment reaches the runner's child processes; the additive `info,{crate}=debug` form is the only permitted shape if a level opt-in is ever needed.
- obs-plan §9 (Log conformance check) + §11 (Logs) require no absolute host-file path (drive-letter, `/home`, `/Users`, `%APPDATA%`, `~/.cargo`, `.rustup`) in any emitted line, run-report artifact or `runs.db` row; the gate asserts the §3 self-obs BASE schema on `logs/agent-latest.jsonl`, not the §6 run-report envelope.

## Patterns to follow
- Sink/stream split (obs-plan §1 telemetry-surfaces rows + §3 Logging stack): the CLI's self-obs JSON goes to **stderr** (file only under agent mode), while the CLI PRODUCT render goes to stdout; the Tauri backend file sink is unconditional with stderr only as an open-failure fallback. An `assert_cmd` arm asserting on command output must target the stream the plan assigns.
- Span materialization (obs-plan §3, Log format — two self-obs line variants): a §4 span emits real lines carrying `span`, `span_event` (`new` | `close`), an optional `parent`, and its allowlisted attributes on `new` — this is the assertable surface for command-span coverage, not an implicit-only construct.
- Read-path boundary convention (obs-plan §6 Boundary-call wrappers, DB READ bullet): a rusqlite read inside a `tauri.command.*` span emits an `info!` carrying `run_id` plus the outcome on the allowlisted `message` field and mints no span — the shape the parity path's envelope read must follow.
- Span-attribute allowlist gate (obs-plan §4 Required-span-attributes heading): a span attribute must be a name in `conductor-core::redact::ALLOWLISTED_FIELDS` or the processor stage drops it; incidental ids ride the allowlisted `message` field instead (the §6 `incident_id` precedent).
- If the chosen binding form spawns a built binary, obs-plan §11 (Project-specific bans) is the governing spawn pattern: fixed hard-coded program NAME resolved through the inherited `PATH` + `.env(...)` only, never a shell with operator-supplied input, and never with a visible console window (the 2026-09-02 measured host-path channel).

## Anti-patterns to avoid
- Never add W3C trace context (`traceparent` / `tracing-opentelemetry` / an OTel SDK) to make the two surfaces correlate — obs-plan §11 (Spans / Traces) bans it; correlation is `run_id` and parity is the envelope comparison.
- Never widen the bounded span-name set or introduce a high-cardinality span name while reshaping `commands.rs` for mutation coverage (obs-plan §11 Spans / Traces).
- Never let the fresh-tree / mutation leg's artifacts or logs carry absolute host paths or Debug-dumped internal struct names (obs-plan §11 Logs + PII Scrubbing; the redaction layer is single-location in `conductor-core::redact`).
