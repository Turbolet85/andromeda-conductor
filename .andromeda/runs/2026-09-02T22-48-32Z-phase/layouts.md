# layouts extract

## Relevance
**Partial** — no surface, region, component, focus order or breakpoint is created or modified; layouts is engaged only because the mutated unit (`crates/conductor-tauri/src/commands.rs`) is the IPC boundary that feeds layouts-mandated per-surface payloads (envelope qualifier, coverage roll-up, run-report lines), and because the test being re-bound guards a layouts cross-surface invariant.

## Constraints
- The run-level load-envelope qualifier is **one SET adapted per surface, never forked** — cli `[ENVIRONMENT-SUSPECT]` bracket label / Markdown banner / desktop-webview run-report banner binding the same pair by name (per layout-templates §cli Component — Primary content block 2). This is the invariant the relocated `path7_…equal_envelope…` test exists to guard; the re-binding must not narrow or drop the assertion.
- The envelope qualifier is **neither a seventh lamp nor a sixth `ReportState`** — it rides outside the lamp column, its label ALWAYS renders (tint is never the only signal), and it is **omitted entirely** when the run stayed in-envelope (per layout-templates §desktop-webview Component — Primary content block 2). Any surviving mutant that would let the qualifier collapse into the lamp set, drop its label, or emit when in-envelope is a layouts-relevant defect, not an accepted-deliberate survivor.
- The lamp set is **closed at six** per-P-ID verdict/report-state labels on both surfaces (per layout-templates §cli Component — Primary content block 2). Mutation disposition must not widen or narrow it.
- The coverage roll-up (incl. the `(N unbacked)` qualifier) is **rendered identically on all three surfaces**, the webview receiving it as the coverage matrix's `unbacked` prop **sourced from the `unbacked_auto` command — never mirrored in TypeScript**; `(N unbacked)` **qualifies the auto term only, never a fifth summand**, and is omitted at zero (per layout-templates §cli Primary screens — `conductor coverage [--write]`). Whether the shipped webview already sources it this way (so a survivor here is load-bearing) is research's question.
- Desktop capability surface is **deny-by-default**: only start/stop · picker · run-report · operator-pause commands plus the one live-counter `Channel` (per layout-templates §desktop-webview IA notes). A test-binding or `[[test]]`-target change must not enlarge the command/IPC surface to make the test reachable.
- If the fresh-target-dir portability gate lands in the agent harness: `scripts/agent-run.{sh,ps1}` ship at **identical semantics**, and the headless path is **never gated on an interactive prompt** (per layout-templates §cli Primary screens — `agent-run.{sh,ps1}` and §cli IA notes — Headless invariant).

## Patterns to follow
- **Backend-as-single-source for derived display values** — counts/roll-ups reach the webview as command-sourced props rather than being recomputed frontend-side (per layout-templates §cli Primary screens — `conductor coverage`); the same commands (`coverage_matrix`, `unbacked_auto`, `run_report`, `run_envelope`) are the mutation target, so survivor triage should treat their payload shape as contract, not incidental.
- **The `not-conductors` Mode-cell precedent** — a state that is not an outcome gets a recessive treatment outside the lamp column and reuses no lamp-set token (per layout-templates §desktop-webview Component — Primary content block 1); this is the precedent the envelope qualifier already rides on.
- **Coverage-matrix row anatomy is four cells with the lamp LAST**, `slo_tier`/`latency_ms` deliberately absent (a per-run measurement belongs to the run-report table), worst-lamp-wins on P-ID collision, and the absence state reads "Not yet run" as TEXT (per layout-templates §desktop-webview Component — Primary content block 1).
- **Indented-detail-line precedent** for finer grain in the Markdown run report — no new column, no new bracket label, no new token (per layout-templates §cli Component — Primary content block 2, Per-check detail region); applies if any survivor disposition tempts an added report field.

## Anti-patterns to avoid
- Forking the envelope qualifier per surface (surface-specific label/threshold/shape) rather than adapting one SET (per layout-templates §cli Component — Primary content block 2).
- Mirroring the unbacked/roll-up derivation in TypeScript instead of consuming the command payload (per layout-templates §cli Primary screens — `conductor coverage`).
- Adding an interactive prompt or a TTY-only dependency anywhere on the headless/agent-driven path in service of the new gate (per layout-templates §cli IA notes — Headless invariant).
