# security extract

## Relevance
**Partial** — no shipped-binary attack surface, auth, secret, or scenario-config boundary is touched; security binds through (a) the supply-chain gate over any `Cargo.lock` delta the new binding creates, (b) harness-spawn / test-only-handle discipline for the binary binding, (c) the `#[tauri::command]` boundary guard whose mutants this chunk makes measurable, and (d) hygiene of committed artifacts.

## Constraints
- The chunk's standing supply-chain probe (the 45th) must run the audit↔deny **overlap**: `cargo audit` with its exit captured **before any pipe**, and `cargo deny check advisories bans licenses sources` **unconditionally** (never gated on whether the lock moved). The advisory-DATABASE fault is remedied by a *bounded wait* only while the signature reproduces byte-identically — a different error or a parsing audit **ENDS** the deferral and is reported, never re-pinned (per security-plan §Dependency Security, two-fault split; §Security Anti-Patterns → Universal).
- If the winning form admits a package (the escargot candidate), §Dependency Security requires the delta land **only on a `cargo deny check advisories bans licenses sources` VERIFIED green over the NEW `Cargo.lock`** — verified, never assumed, because the deny overlap is then the sole coverage for the added packages; "no dependency delta" stops being available as the deferral's basis (per §Dependency Security, "Admitting a NEW dependency while the fault persists"). Whether the chosen form actually adds a package is research's question.
- Any new license or advisory the added package surfaces takes the **justified-exception mechanism** — a `deny.toml` entry with a justifying comment, `deny.toml` itself being the authority on the full set — and `Cargo.lock` must stay committed and non-drifting (per §Dependency Security, Accepted exceptions; §Security Anti-Patterns → Universal).
- The artifact-dependency candidate (`-Z bindeps`) is nightly-only: §Dependency Security (Pinning) and §Security Anti-Patterns → Code Patterns require `rust-toolchain.toml` hold **≥ 1.94.1** to keep the tar-rs symlink-chmod clearance (CVE-2026-33056 / RUSTSEC-2026-0033); any toolchain move made to reach that form must not drop below the floor.
- The test's launch of the `conductor` binary is a **HARNESS spawn** under §Security Anti-Patterns → Code Patterns rule (b): the program must be a fixed OS/toolchain program or a repo-derived resolved constant (never operator-chosen), argv must be **array-form**, any value must ride the child's **env map** — never argv, never a shell string. The rule currently enumerates **FOUR governed forms** as an exhaustive set; a build-at-test-time or artifact-binding launch would be a FIFTH and owes wrap's amendment flow. Whether the existing `assert_cmd` call already satisfies this is research's question.
- §Input Validation (`#[tauri::command]` IPC arguments row) requires the `run_id`-class argument be `resolve_under`-guarded against the resolved runs dir **before any read** (absolute / `..` REJECTED, never clamped) and every returned `Err` cross the edge through `sanitize_error` — **proven at the mock-runtime IPC tier (`tauri::test`)**, because app-defined commands are NOT capability-ACL-gated and this row, not the capabilities file, is the boundary that governs them. The guard wiring sits in `crates/conductor-tauri/src/commands.rs` (call sites at `:38-40`, `:59-62`, `:102`, `:173`; the `:163` doc comment cites this plan section directly) while the guard functions live in `conductor-core` — so a relocation that moves the IPC-tier proofs out of `conductor-tauri` would leave that boundary's mutants unkillable by `-p conductor-tauri`. Whether the winning form keeps those proofs in-crate is research's question.
- §Input Validation is an **exhaustive enumeration** of external-input surfaces: if the fix introduces any new env handle (a `CARGO_BIN_EXE_*`-class or `CONDUCTOR_*` handle read by the test), it must be registered with its control model. Toolchain-set and harness-owned-constant values are not operator input, but the registration duty stands.
- Committed evidence records must not leak absolute host paths or internal seam-crate struct names (§Security Anti-Patterns → Logging) — `cargo mutants` output (`mutants.out`, per-mutant logs, the workspace-root `--output`) is host-path-bearing by construction.

## Patterns to follow
- The **`CONDUCTOR_E2E_SEED_DIR` third control class** (§Input Validation, added 2026-09-02): a handle read only by a TEST binary, whose value is a harness-owned repo-relative CONSTANT carried through the spawn's env map, with a no-op when unset — the nearest precedent if the winning form must hand a binary/path to a test.
- The **fixture-seed spawn form** in §Security Anti-Patterns → Code Patterns rule (b): fixed `cargo` program + fixed argv + handle in the child's env map + a non-zero exit **throwing** rather than proceeding silently — the closest governed shape to a build-the-binary-at-test-time binding.
- The **deny-overlap probe form** (§Dependency Security): capture the audit exit before any pipe, run deny unconditionally, and state a dependency delta's basis as the **package COUNT** or an explicit new-package diff — never lockfile byte-identity (that form was measured wrong 2026-09-02 and is recorded in the security distillation `.claude/rules/security.md`).
- The **`deny.toml` justified-exception** pattern (§Dependency Security, Accepted exceptions): a permissive-license addition lands as an allow entry carrying its justification, keeping the gate green without suppressing a real signal class.
- **`resolve_under` + `sanitize_error` at the IPC edge, proven at the mock-runtime IPC tier** (§Input Validation, Tauri IPC row) — the pattern the restored mutation tally is measuring the test-quality of.

## Anti-patterns to avoid
- NEVER paper over the red advisory gate to unblock this chunk — no `deny.toml` ignore for the RustSec duplicate-ID fault, no floor raise (unexecutable for a DB fault), no CI edit, no silent accept (§Dependency Security two-fault split; §Security Anti-Patterns → Universal).
- NEVER spawn the binary through a shell / `eval`-equivalent, an operator-chosen program, or an operator value interpolated into argv — array-form argv with a fixed or repo-derived program only (§Security Anti-Patterns → Code Patterns, rule (b)).
- NEVER let `Cargo.lock` drift or go uncommitted (it makes the scan non-deterministic), and NEVER let a committed artifact from the mutation run carry an absolute host path or internal seam-crate struct name (§Security Anti-Patterns → Universal; → Logging).

## Contract bindings
- **Supply-chain gate ↔ tests §CI Integration** — `.github/workflows/ci.yml` already carries the cargo audit/deny + npm gates as the security job; this chunk must leave that gate passing over the final lock while explicitly NOT promoting mutation to a CI stage (scope boundary; test-plan §9).
- **Mutation-survivor disposition ↔ tests §10** — security owns only one disposition rule here: survivors located in the `#[tauri::command]` guard wiring are not eligible for accepted-deliberate; all other dispositions are the tests domain's.
- **Evidence-record hygiene ↔ obs (host-path scrubbing) + the per-chunk `evidence/` tree** — the same `<host-path>` scrub discipline the screen-reader speech-log ingest established.
- **New spawn form / new test-read handle ↔ wrap's amendment flow** — both §Input Validation's boundary table and rule (b)'s form enumeration are stated as exhaustive sets, so an addition is an amendment, not a silent landing.

## Acceptance criteria contributions
- (security) `cargo audit` run with its exit captured **before any pipe** and its signature either reproduced byte-identically (deferral re-pinned as the 45th probe) or reported as ENDING the deferral; `cargo deny check advisories bans licenses sources` run **unconditionally** and green (per security-plan §Dependency Security).
- (security) If any package is admitted, the delta is stated as a **package COUNT / explicit new-package diff** with `cargo deny check advisories bans licenses sources` VERIFIED green over the **NEW** `Cargo.lock` (committed, non-drifting), and any new license lands as a `deny.toml` allow with a justifying comment (per §Dependency Security, dependency-delta-under-a-red-audit).
- (security) The restored `conductor-tauri` mutant tally shows **no survivor in the `#[tauri::command]` boundary-guard wiring** (`resolve_under` traversal guard / `sanitize_error` edge in `commands.rs`) dispositioned accepted-deliberate — such a survivor must be killed, since that wiring is the sole boundary governing app-defined commands (per §Input Validation, `#[tauri::command]` IPC arguments row).
- (security) The new binary binding launches through a fixed/repo-derived program with **array-form argv and no shell string**, and no artifact committed by this chunk (mutation tally, evidence record, new test target) carries an absolute host path or an internal seam-crate struct name (per §Security Anti-Patterns → Code Patterns rule (b); → Logging).
