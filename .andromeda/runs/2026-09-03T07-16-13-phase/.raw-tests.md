## Constraints
- **The two-outcome rule is the plan's own, and it is not a threshold.** test-plan §10 (Mutation-survivor disposition, `:500`) requires every NAMED survivor end either killed or classified accepted-deliberate **against a cited standing rule**, and states the second is a real disposition only where a standing rule *prescribes* the untested shape — never a deferral. It also forbids a numeric `--fail-under` beside the coverage gate; the score moves as a consequence (per test-plan §10 Mutation-survivor disposition). The scope's acceptance is a verbatim restatement of this §, so it inherits it exactly.
- **Run discipline is mandated, and the exit code is not the signal.** test-plan §4 (Mutation instrument) requires `-f` be given full workspace-root paths (`-f crates/conductor-tauri/src/&lt;file&gt;.rs` — a package-relative path under `-p` silently matches nothing), `--test-tool=nextest` REQUIRED, `Found 0 mutants to test` treated as a NO-OP never a pass, and the gate read from the `mutants.out/` tallies (`missed.txt` / `caught.txt`) because a non-zero exit reflects surviving/timeout *classes* rather than run failure (per test-plan §4 Mutation instrument).
- **The tier must stay non-blocking and per-crate.** test-plan §9 (Scoped mutation audit) puts cargo-mutants on the live-Pulse leg's footing — operator/local, never a blocking CI stage, run per-chunk against the crates the chunk touched. This is the plan-side basis for the scope's "no CI gate on the mutation score" boundary (per test-plan §9 Scoped mutation audit).
- **Runner portability is a standing gate on any test added here.** test-plan §4 (Framework) requires `conductor-tauri` be green under BOTH `cargo nextest run -p conductor-tauri` and `cargo test -p conductor-tauri`; §10 (Zero-flakiness budget) classes a runner-dependent result as a determinism break to fix at the cause, not a runner to pin to (per test-plan §4 Framework, §10 Zero-flakiness budget).
- **Killing the read-only command survivors has a named standing tier.** test-plan §5 (Cross-module patterns → mock-runtime command-dispatch) requires each read-only Tauri command carry a mock-runtime IPC test asserting its payload against whichever seam source it single-sources — naming `run_envelope` → `conductor-report`'s `RunsDb::get_envelope` via `conductor_run::read_envelope`, and stating the command list is not closed. That is the mandated shape for `run_report:168` / `run_envelope:224` / `list_scenarios:113`; whether the shipped tests already exercise those commands at a non-empty subject is research's question (per test-plan §5 Cross-module patterns).
- **Any seeded subject must come from the sanctioned provenance set and carry a meaning-pinner.** test-plan §7 (Self-bootstrapping requirement) admits the committed fixture family read through the production reader or written through the production writer, keeps the "no developer-seeded `runs.db`" ban standing, and requires a committed fixture's MEANING be pinned by a Rust round-trip so a persist-side change fails at `cargo nextest` rather than silently inerting a green assertion (per test-plan §7 Self-bootstrapping requirement). This governs the scope's "staged repo root + populated runs dir" hypothesis directly.
- **The path-guard survivors sit under a mandated negative-test class.** test-plan §1 (Coverage triggers → Vector-1, security-vector-coverage) requires the Rust-read `CONDUCTOR_*` path handles keep a negative test asserting canonicalization + type/existence rejects traversal BEFORE any `runs.db`/journal write or manifest read (per test-plan §1 Coverage triggers). Whether `conductor-tauri`'s `resolve_handle`/`resolve_under` path already carries such a test — as opposed to `conductor-core`'s — is research's question, and it decides whether the six forbidden-domain must-kills are a gap or a re-aim.

## Patterns to follow
- **Extract the DI-free core, unit-test it synchronously.** The `HoldGate::{arm,deliver}` precedent (`D:/dev/projects/conductor/.claude/rules/testing.md` `:64`, referenced by test-plan §5's deferral bullet) is the shipped pattern for exactly the `pause.rs` survivors: pure decision logic on the managed state tested under `#[tokio::test(flavor="current_thread")]` — round-trip, no-pending no-op, abort-safe default — with only the `Channel.send` line deferred.
- **Mock-runtime command dispatch.** `tauri::test::mock_builder()` + `mock_context(noop_assets())` + `get_ipc_response()` behind the `test` feature (test-plan §5 Driver(s); §8 mocking table) is the named driver for `#[tauri::command]` payload assertions inside `conductor-tauri`.
- **Committed fixture + production-reader/writer round-trip pinner.** `D:/dev/projects/conductor/crates/conductor-run/tests/fixtures/lamps-journal.jsonl` + `lamps_fixture.rs`, and `fixtures/over-envelope.toml` + `envelope_fixture.rs`, are the plan's named proof SET (test-plan §7 Self-bootstrapping requirement). Whether these are reusable across the package boundary or a `conductor-tauri`-local sibling is needed is the scope's stated P4 fork.
- **Per-test isolation for anything touching disk or DB.** `assert_fs::TempDir` with `CONDUCTOR_RUNS_DIR` for cross-process/staged-root tests; `rusqlite::Connection::open_in_memory()` per unit test (test-plan §3 Test data bootstrap; §7 Seed strategies).
- **Crate-local conventions.** snake_case `#[test]` / `#[tokio::test]` / rstest `#[rstest]` fns inside the source file's `#[cfg(test)] mod tests`, with rstest `#[fixture]` / `#[case]` for table-driven rows (test-plan §4 Conventions, Fixture pattern at unit level).

## Anti-patterns to avoid
- **Never rely on nextest's per-test process to isolate from a process-global, first-install-wins singleton** — `conductor_core::init_observability` is the named shipped case; the remedy is a test binary of its own, never `--test-threads=1` (per test-plan §11 Integration). This bites directly on `main.rs:tauri_log_path:44`, since `main.rs` carries no test module today and its survivor is an obs-sink return.
- **Never force a thread-timing-dependent assertion to satisfy the plan literally** — the `Channel`-frame-sequence leg is deferred precisely because it would flake against the zero-retry bar, and no retry policy may be added to rescue it (per test-plan §5 deferred-leg bullet; §10 Zero-flakiness budget; §11 Quality). Relevant to `start_run:260` / `run_thread:296`.
- **Never test implementation details or assert on fixture-internal values** — assert the public seam API and the envelope contract (per test-plan §11 Unit). A killing test that reaches into a private helper's internals to observe a mutant would violate this; the observable-behavior route is the mandated one.
