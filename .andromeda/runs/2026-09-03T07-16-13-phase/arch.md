# arch extract

## Relevance
Partial — test-side work inside an arch-registered crate; arch governs crate/module placement, the build-order coupling the tier re-run pays, and the registered resources three of the survivors (`tauri_log_path`, `run_envelope`, the three path helpers) resolve.

## Constraints
- **Test/fixture code stays inside its crate's boundary; edges are the architecture.** Per arch §Established Decisions [Module Boundaries] a forbidden cross-seam dep must fail to compile, and per §Occupied Resources (Crate names) `conductor-run` sits *above the seams and below both bins*, shared by them — so the P4 fixture fork may add no bin→bin edge and no `conductor-run → conductor-tauri` inversion. Whether the existing `conductor-tauri → conductor-run` edge can even reach that crate's `tests/` fixture modules (integration-test modules are not a crate's dependable surface) is research's question.
- **The tier re-run compiles `conductor-tauri` once per mutant, and that compile has a prerequisite.** arch §Infrastructure Patterns — Build system requires the webview bundle (`ui/dist`) to exist before ANY workspace `cargo build`/`nextest`/`clippy` that compiles `conductor-tauri`, because `tauri::generate_context!` resolves `build.frontendDist` at COMPILE time and a bare cargo build does not run `beforeBuildCommand`; it further requires `--features tauri/custom-protocol` wherever the binary must serve the bundle rather than `devUrl`. Whether the mutation harness already performs the `ensure_frontend` step is research's question.
- **`tauri_log_path` resolves a REGISTERED occupied resource, not an incidental path.** arch §Occupied Resources (On-disk artifacts — `logs/conductor-tauri.jsonl`) requires the Tauri backend self-obs stream to resolve as `runs_dir.parent()/logs`, move with `CONDUCTOR_RUNS_DIR`, and be truncated per invocation — so a `None`/`Some(Default::default())` mutant drops or relocates a registered artifact, which is the arch-side reading of that survivor.
- **The three path helpers resolve arch-defined handles, and the namespace is closed.** `CONDUCTOR_RUNS_DIR` / `CONDUCTOR_SCENARIOS_DIR` / `CONDUCTOR_CONTRACT_MANIFEST` are enumerated in arch §Occupied Resources — Environment variables (eleven entries); the `contracts/` manifests additionally mandate a fixed `default_path()` through `resolve_under` with deliberately NO `CONDUCTOR_*` override. Killing tests must not introduce a twelfth handle — a new one is a wrap amendment, per the registry's own precedent.
- **Fixture staging must not write into the repository on an ordinary test run.** arch §Occupied Resources (`CONDUCTOR_E2E_SEED_DIR`) pins that shape explicitly: unset, the seeding test is a no-op, "so an ordinary `cargo nextest` / `cargo test` run never writes into the repository". A staged repo root / populated runs dir for the catalog + run-data survivors is bound by that rule.
- **`run_report` / `run_envelope` return arch-locked shared shapes.** Per arch §Standard Contracts — Run report envelope (eleven fields, closed `verdict`/`state` sets) and Per-check record (nine-key `CheckRecord`); `run_envelope` corresponds to the run-grained `run_envelope` table of the three-table `runs.db` (§Occupied Resources), whose classification is produced by `LoadEnvelope::classify` reading ONE shared basis with the static `check_load_envelope` gate (§Occupied Resources — `contracts/pulse-load-envelope.toml`). Any committed fixture backing a killing test must be a valid instance of those shapes.
- **The GUI bin is a thin shell; the headless path is the release gate.** arch §Design Philosophy (Headless-drivable core, thin shells) + §Established Decisions [Workspace / Core Structure] require engine logic to live in a runtime-agnostic library both bins call. If a survivor is killable only by extracting a DI-free core, arch requires the extraction land in a library crate — never as new engine logic added to the bin (which the chunk also bans as production-behavior change).

## Patterns to follow
- **Fixed `default_path()` through `resolve_under`** — the shape `CapabilityManifest`/`LoadEnvelope`/`RunContract` already use for the `contracts/` manifests (arch §Occupied Resources — On-disk artifacts); the `commands.rs` guard + its three callers are the Tauri-side instance of it.
- **Env-handle-driven redirection as the staging lever** — `CONDUCTOR_RUNS_DIR` moves the runs dir AND (via `runs_dir.parent()/logs`) the self-obs sink together (arch §Occupied Resources); the a11y suites' per-suite landing sites are the worked precedent for staging without touching the repo.
- **Core-owned `Builder::new_current_thread()` under Tauri** — arch §Established Decisions [Async Runtime Flavor] keeps Tauri's own multi_thread runtime the shell's concern; `start_run` / `run_thread` and the three `pause.rs` timeouts sit on that seam, and §Cross-cutting Patterns (Determinism discipline) bans wall-clock stamps from tokio's virtual clock.
- **Lift bin-local logic into a shared library crate when it must be testable** — the sanctioned route, precedent being `conductor-cli`'s bin-local pipeline becoming the `conductor-run` workspace member (arch §Occupied Resources — Crate names).
- **Verdict/error wall at the command edge** — anyhow only at `#[tauri::command]` edges over typed seam errors (arch §Conventions — Error handling); mutants flipping a `Result`/`Option` arm are judged against that wall, not against a panic.

## Anti-patterns to avoid
- Landing a new `CONDUCTOR_*` env handle, port, or on-disk artifact via test scaffolding without registration (arch §Occupied Resources enumerates each individually).
- Adding any inbound listener or network surface from the harness — arch §Cross-cutting Patterns (Trust boundary) permits no listener in a shipped Conductor binary except the port-occupier fault, and confines `4444`/`4445` to the dev-only, harness-lifetime driver stack.
- Making a mutant observable by moving behavior into the Tauri bin (arch §Design Philosophy — thin shells; §Established Decisions [Workspace / Core Structure]).

## Contract bindings
- **arch ↔ obs:** `logs/conductor-tauri.jsonl` is arch's registered artifact (§Occupied Resources — On-disk artifacts: `runs_dir.parent()/logs`, moves with `CONDUCTOR_RUNS_DIR`, truncated per invocation); obs-plan `:103-105` supplies the unconditional-write mandate. `tauri_log_path:44`'s disposition sits exactly on that seam.
- **arch ↔ security:** the `CONDUCTOR_*` path handles and fixed manifest paths arch defines are the inputs security-plan §Input Validation's `resolve_under` guard covers — arch names the resources, security mandates the validation. The six must-kill survivors are the intersection.
- **arch ↔ layouts:** the `run_envelope` banner qualifier (layout-templates `:144`) renders the run-level standing arch registers as the `run_envelope` table plus the `[ENVIRONMENT-SUSPECT]` caption from `LoadEnvelope::classify` — which arch requires to share ONE basis with the static gate (§Occupied Resources — `contracts/pulse-load-envelope.toml`). That shared-basis rule is the arch input to P3's "omission-correct-in-envelope vs over-envelope-renders-nothing" fork.
- **arch ↔ tests:** the eleven-field envelope and nine-key `CheckRecord` (§Standard Contracts) are the shapes any committed fixture + production-reader round-trip pinner must instantiate.

## Acceptance criteria contributions
- (arch) All new test/fixture code lands inside `crates/conductor-tauri/`, and any cross-package fixture reuse rides an explicit Cargo.toml edge introducing no bin→bin edge and no `conductor-run → conductor-tauri` inversion (per architecture.md §Established Decisions [Module Boundaries] + §Occupied Resources — Crate names).
- (arch) The tier re-run builds the webview bundle (`ui/dist`) before any cargo compile of `conductor-tauri`, since `generate_context!` resolves `build.frontendDist` at compile time (per architecture.md §Infrastructure Patterns — Build system).
- (arch) No new `CONDUCTOR_*` env handle, port, or on-disk artifact is landed unregistered, and a plain `cargo nextest` / `cargo test` writes nothing into the repository (per architecture.md §Occupied Resources — Environment variables, incl. the `CONDUCTOR_E2E_SEED_DIR` no-op-when-unset rule).
- (arch) Any committed fixture backing a `run_report` / `run_envelope` killing test is a valid instance of the eleven-field run-report envelope and the nine-key `CheckRecord`, with the `run_envelope` row at run grain (per architecture.md §Standard Contracts — Run report envelope + Per-check record).
