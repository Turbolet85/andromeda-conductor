## Constraints
- The run-level `[ENVIRONMENT-SUSPECT]` load-envelope caption is required to print **once, above the per-P-ID lines, only for a run whose profile breaches the SUT load envelope** — a qualifier on the run, never a seventh lamp and never a sixth `ReportState` (per design-system §Surface: cli / Component Patterns 4). This is the design half of the scope's open `run_envelope:224` fork: my plan's wording supports the *conditional* reading (omission is correct in-envelope; the defect is an over-envelope run rendering nothing), not the "label vanishes unconditionally" reading. P3 must still confirm against layout-templates `:144`, which owns placement.
- That caption renders in the existing Residual-mute recessive tier (ANSI 246 ↔ webview `var(--status-residual)`, bound **by name** across both surfaces), and my plan requires the always-rendered ASCII bracket label to carry the signal while the tint only de-emphasizes (per design-system §Surface: cli / Tokens — Residual-mute entry).
- Never color-alone: every status in asserted output must carry its ASCII prefix from the closed `[PASS]`/`[HOLD]`/`[FAIL]`/`[MANUAL]`/`[RESIDUAL]`/`[BLOCKED]` set plus the non-lamp `[ENVIRONMENT-SUSPECT]` (per design-system §Surface: cli / Platform-Specific Notes; §Anti-Patterns / Per-Surface Bans → cli).
- An empty / `None` / no-result return is a **legitimate distinct state**, not an error: `Blocked` and "no result yet" must never collapse into `Fail` (per design-system §Anti-Patterns / Rejected Defaults — "Conflating 'no result yet' with 'failed'"). This bears directly on the survivors the scope says are "tested at exactly their empty case — which IS the mutants' return value".
- My plan pins the shipped empty-state strings as the design contract (`No scenarios found.` for the matrix; `No run yet` for the report; no report-area prose at all while a run is in progress) — per design-system §Surface: desktop-webview / Component Patterns 3 and 6. A killing test must not require these strings to change; whether the code already emits exactly them is research's question (my plan states the target, amended 2026-09-02 to record the shipped forms).
- Because production-render change is out of scope for this chunk, any survivor killable only by altering caption text, lamp treatment, or empty-state prose is a design-system amendment candidate to surface as a finding, not an in-chunk edit (per design-system §Surface: cli / Component Patterns 4 + §desktop-webview / Component Patterns 3, 6).

## Patterns to follow
- **Reuse-not-new-token**: the Residual-mute tier absorbed each new non-lamp use (`hint:` label, out-of-scope Mode cell, `[ENVIRONMENT-SUSPECT]` caption) with zero new palette rows or ANSI entries (per design-system §Surface: cli / Tokens). Any fixture-driven output added here follows the same routine.
- **Label-first assertion shape**: status is asserted through the ASCII bracket prefix, which is the surface that survives `NO_COLOR`, `TERM=dumb`, and piped stdout — ANSI is stripped by `anstream` in exactly the headless path a mutation test runs in (per design-system §Surface: cli / Tokens + Platform-Specific Notes).
- **Cross-surface by-name pairing**: a Tauri command feeding both the webview and the cli view of the same state must not let the two diverge — the pair is bound by token name, not by duplicated literals (per design-system §Surface: cli / Tokens; §Surface: desktop-webview / Tokens, the 34-token binding contract).
- **Six-treatment lamp separation**: `ManualCheck`, `KnownResidual` and `Blocked` each have a visually distinct non-red treatment precisely so none silently reads as `Fail` (per design-system §Color Palette → Verdict-vs-ReportState note; §desktop-webview / Component Patterns 4). Any report-shaped fixture must preserve the six-way distinction rather than flattening to pass/fail.

## Anti-patterns to avoid
- Do NOT introduce a new color, ANSI entry, lamp state, or `ReportState` value to make a survivor observable — `[ENVIRONMENT-SUSPECT]` stays a run-level caption outside the lamp column (per design-system §Surface: cli / Component Patterns 4; §Anti-Patterns / Universal Bans).
- Do NOT let a killing assertion encode an absent/`None`/empty return as an error, a red `Fail`, or a gray placeholder (per design-system §Anti-Patterns / Rejected Defaults).
- Do NOT assert on color/ANSI alone in any output-shaped test (per design-system §Anti-Patterns / Per-Surface Bans → cli).

## Contract bindings
- **design ↔ layouts**: `[ENVIRONMENT-SUSPECT]` conditionality. Design owns the token tier, the bracket label, and "prints once when the profile breaches the envelope"; layout-templates `:144` owns the banner's placement/qualifier semantics. The scope's `run_envelope:224` `[inferred]` fork must be closed against both, and design's §cli Pattern 4 wording favours the conditional reading.
- **design ↔ a11y**: never-color-alone (SC 1.4.1) — the ASCII bracket label is the a11y-carrying half of every status token; assertions that pin the label satisfy both domains at once.
- **design ↔ tests**: any committed fixture that stages an over-envelope run (the `fixtures/over-envelope.toml` precedent named in scope) inherits the §cli Pattern 4 caption contract as its expected output shape.

## Acceptance criteria contributions
- (design) No new color token, ANSI entry, lamp treatment, or `ReportState` value is introduced to make a survivor observable; `[ENVIRONMENT-SUSPECT]` remains a run-level caption in the existing Residual-mute tier (per design-system §Surface: cli / Tokens + Component Patterns 4).
- (design) Every killing assertion touching status or envelope output keys on the ASCII bracket label, never on color/ANSI alone (per design-system §Surface: cli / Platform-Specific Notes).
- (design) No killing test encodes an empty, `None`, or no-result-yet return as an error or `Fail` state (per design-system §Anti-Patterns / Rejected Defaults — "Conflating 'no result yet' with 'failed'").
- (design) No shipped render string or empty-state prose (`No scenarios found.`, `No run yet`, the absent in-progress prose) is changed to kill a survivor; a survivor requiring such a change is recorded as a finding (per design-system §Surface: desktop-webview / Component Patterns 3 and 6).
