# layouts extract

## Relevance
**Partial** — layouts governs one survivor directly (`run_envelope:224`, double-governed at layout-templates `:144`) and constrains what a *killing assertion* may treat as an observable render for the run-report / catalog / operator-pause commands; the path-helper (`resolve_handle` + callers), `resolve_selection`, `load_all` and `tauri_log_path` survivors sit outside this domain.

## Constraints
- The run-level load-envelope banner is required to print **once per run, above the per-P-ID verdict lines and outside the lamp column, with its label always rendered**, and to be **omitted entirely when the run stayed in-envelope** (per layout-templates §Component — Primary content block 2, run-level load-envelope banner — the scope's `:144`). This settles the scope's `[inferred]` fork toward the plan's own reading: absence-when-in-envelope is the *specified* render, so the defect a `Ok(None)` mutant introduces is an **over-envelope run rendering nothing**, not "the label vanishing". Whether the shipped `run_envelope`/`LoadEnvelope::classify` path already produces that in-envelope-`None` shape is research's question.
- The lamp set is **closed at six** and the envelope banner is **neither a seventh lamp nor a sixth `ReportState`** (per layout-templates §Component — Primary content block 2 and §Surface: cli — Component — Primary content block 2). No disposition may make a survivor observable by adding a state label, bracket label, column or token.
- The envelope qualifier is **one SET adapted per surface, never forked** — cli `[ENVIRONMENT-SUSPECT]` bracket label, the Markdown report banner, and the webview banner binding the same pair by name (per layout-templates §Surface: cli — Component — Primary content block 2). Any committed envelope fixture must hold the three legs at one shape; per-surface divergence is a finding, not a licence.
- **Empty is a named, specified render, not an absence of render** — the run-report card's `No run yet`, the matrix/picker's `No scenarios found.`, and the per-row "Not yet run" prose, each distinguished by **TEXT, never tint alone** (per layout-templates §Component — Primary content block 2 "Distinct non-result states" and §Component — Primary content block 1 States/Status). Consequence for this chunk: a test that exercises only the empty case cannot distinguish a returns-empty mutant from correct behaviour, which is exactly the scope's LIKELY-SHAPE hypothesis for the run-data and catalog commands.
- The operator-pause hold admits **exactly two operator outcomes — Proceed and Abort** — and on commit **Proceed disables and shows an in-flight state to prevent a double-commit**; the styled `AlertDialog` is the only modal (`alert()`/`confirm()`/`prompt()` never used) (per layout-templates §Component — Hero / signature section and §IA notes). A `HoldGate::deliver -> true`/`false` disposition is bound to that two-outcome decision, not merely to "a decision was delivered".
- **HOLD is defined by the ABSENCE of motion** — the count freezes at the exact hold value, does **not advance and does not blank**, the phase line flips to the fixed `Conductor · HOLD — operator pause` label (per layout-templates §Signature placement, §Wireframe — Run console (HOLD), §Component — Header). A hold that never resolves and a legitimate held run therefore render identically on this surface: the three `pause.rs` **timeout** survivors have **no distinguishing layout observable**, which is a real input to P3/P4's open question about whether a timeout admits a killing test.
- Live-run evidence lives in the **titlebar count + phase line + coverage matrix over the single Tauri `Channel`**; **no in-progress prose ships in the report area** and the report never shows a partial verdict for an unfinished run (per layout-templates §Component — Primary content block 2 non-result states, §IA notes Live channel). `start_run` / `run_thread` survivors have no report-region render to assert against.

## Patterns to follow
- **Omitted-at-zero with an always-rendered label** — the cli coverage roll-up's `(N unbacked)` parenthetical is plain text, never a fifth summand, and omitted entirely at zero (per layout-templates §Surface: cli — Primary screens, `conductor coverage`). The same shape governs the envelope banner: conditional omission is specified behaviour, and the label carries the signal whenever it renders.
- **Per-surface adaptation, never a fork** — desktop CSS vars ↔ cli ANSI ↔ Markdown, same tokens by name (per layout-templates §IA notes Multi-surface coordination, §Decisions Log Cross-surface IA decisions). A fixture pinned on one surface is expected to describe the other two's rendering of the same fact.
- **De-literalize derived values in pinned samples** — name the SET / term, never a baked count or duration (per layout-templates §Surface: cli — Primary screens, "every number manifest-derived (never a literal)"; reinforced by four amendments below). Applies directly to committed fixture content and its round-trip pinner.
- **Distinct non-result states never downgrade to a failure render** — `Blocked` renders `—`/null measurement cells and its named precondition, `KnownResidual` renders a muted dashed lamp plus its note, never red (per layout-templates §Component — Primary content block 2). Assertions must key on the state's text, not on colour or on presence/absence alone.
- **The shipped `RunState` vocabulary is `idle` · `live` · `hold` · `aborted`**, with idle-with-report a sub-state and the phase line rendering one of four fixed labels, never a segment name (per layout-templates §Surface: desktop-webview — Primary screens, §Component — Header).

## Anti-patterns to avoid
- Do **not** add a seventh lamp, a sixth `ReportState`, a new bracket label, a new column or a new token to make any survivor observable (per layout-templates §Component — Primary content block 2 and §Surface: cli — Component — Primary content block 2; the per-check detail region set this precedent explicitly — "no new column, no new bracket label").
- Do **not** assert the envelope banner as unconditionally present — an always-rendered banner contradicts the omitted-when-in-envelope rule (per layout-templates §Component — Primary content block 2, `:144`).
- Do **not** treat an empty/absent render as a defect or a placeholder — the empty renders are shipped prose strings and a designed state (per layout-templates §Component — Primary content block 1 Empty, §Component — Primary content block 2 Empty).

## Contract bindings
- **layouts ↔ tests** — layouts owns *which render* a killing fixture must produce (over-envelope banner present with label; populated report/catalog rather than the empty state); the tests domain owns fixture mechanics, the committed-fixture + production-reader round-trip pinner, and the tier re-run. The scope's `run_envelope:224` double-governance is precisely this seam.
- **layouts ↔ security** — layout-templates §IA notes ("Security guardrails honored at the layout level") enumerates the deny-by-default command surface as *start/stop · picker · run-report · operator-pause + the one live-counter `Channel`*; the chunk's command-level survivors map onto that enumeration, but `resolve_handle` and its three path-helper callers are security-plan §Input Validation's, not layouts'.
- **layouts ↔ obs** — `tauri_log_path:44` has **no layout surface**: layouts requires all live state to be carried in-window by titlebar + matrix + footer and forbids a native OS toast (per layout-templates §Component — Footer). Its disposition is obs-plan's alone.
- **layouts ↔ a11y** — the Channel-opened hold dialog's focus restoration is contract-borne (`restoreFocusTo` / `onCloseAutoFocus`; Start conveys unavailability with `aria-disabled`, never native `disabled`) per layout-templates §Component — Hero / signature section; flagged only, not a test surface this chunk touches.

## Acceptance criteria contributions
- (layouts) The `run_envelope:224` killing test drives an **over-envelope** run and asserts the banner's presence with its always-rendered label; an in-envelope run returning no banner is asserted as the *correct* render, not a defect (per layout-templates §Component — Primary content block 2, run-level load-envelope banner).
- (layouts) No survivor disposition introduces a seventh lamp, a sixth `ReportState`, a new bracket label, column or token — the lamp set stays closed at six (per layout-templates §Component — Primary content block 2 / §Surface: cli — Component — Primary content block 2).
- (layouts) Killing tests for the run-data and catalog commands exercise a **populated** render, because the empty renders (`No run yet` / `No scenarios found.`) are themselves specified states a returns-empty mutant reproduces (per layout-templates §Component — Primary content block 2 non-result states, §Component — Primary content block 1 Empty).
- (layouts) Any committed envelope fixture keeps the qualifier at one shape across its three surfaces (cli bracket label · Markdown banner · webview banner) and pins the term SET rather than a baked duration/count literal (per layout-templates §Surface: cli — Component — Primary content block 2, §Surface: cli — Primary screens).
