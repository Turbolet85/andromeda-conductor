This is the mandate the scope's `tauri_log_path:44` question (`None` / `Some(Default::default())`) must be settled against: obs-plan states no conditional-sink escape, so "the file sink is optional" is not an available accepted-deliberate rationale. - Every `#[tauri::command]` handler is required to open a **manual** `tracing::info_span!("tauri.command.<name>").entered()` guard; the `#[tracing::instrument]` ATTRIBUTE is prohibited on command handlers because it does not stack with `#[tauri::command]` (per obs-plan §4 auto-instrumentation table, desktop-webview row + §1 desktop-webview/ipc-internal rows). The plan records 8/8 sites measured 2026-09-02; whether that still holds at HEAD is research's question. Five survivors sit on these handlers: `list_scenarios:113`, `run_report:168`, `run_envelope:224`, `start_run:260`, `resolve_operator_hold:105`.
- Span names must stay inside the bounded set (`scenario.run`, `timeline.execute*`, `emit.batch`, `emit.logs_batch`, `verify.readback*`, `report.generate`, `db.insert_run`, `fault.*`, `tauri.command.*`) — no high-cardinality names, and explicitly **no `db.*` read span** (per obs-plan §11 Spans/Traces + §6 Boundary-call wrappers, DB READ bullet). The read path's required witness is instead a boundary `info!` carrying `run_id` plus the outcome on the allowlisted `message` field, inside the caller's `tauri.command.*` span — which is exactly the `run_envelope:224` seam (`conductor_run::read_envelope` over `RunsDb::get_envelope`).

- No absolute host paths and no internal struct names may appear in logs, run-report artifacts, or `runs.db`; the value scrub masks drive-letter / `/home` / `/Users` / `%APPDATA%` / `~/.cargo` / `.rustup` / backtrace file paths → `<redacted>`, and struct names are kept out by the field-name allowlist + `Display`-not-`Debug` at the `anyhow` edge (per obs-plan §11 PII Scrubbing + §11 Logs + §9 Log conformance check). This binds the chunk's staged-repo-root fixtures and its committed per-survivor disposition ledger, which will otherwise carry temp-dir host paths.
- A **span attribute** must be a name in `conductor-core::redact::ALLOWLISTED_FIELDS` or the processor stage drops it; report-seam records (the eleven-field Run-report envelope and the per-check `CheckRecord`) do **not** pass through that allowlist (per obs-plan §4 Known-residual required-span-attributes note + §3 Log format, two record shapes). - Critical-path spans may not be skipped (obs-plan §11 Telemetry Strategy, "NEVER skip spans on critical paths (Scenarios 1-7)"); `tauri.command.start_run` is the root of the both-surface-parity path (per obs-plan §4 Both-surface parity), so a `start_run:260` killing test may not require bypassing that root — consistent with the scope's own ban on production-behavior change.

## Patterns to follow
- Manual command-span guard at each handler (`tracing::info_span!("tauri.command.<name>").entered()`), names inside the `tauri.command.*` wildcard — the shape any test exercising a handler will observe (per obs-plan §4 desktop-webview row).
- Read-path witness as a boundary `info!` on the allowlisted `message` field rather than a new span/attribute — the established alternative when a needed field is outside the allowlist (per obs-plan §6 Boundary-call wrappers: DB READ, MCP key-set witness, lifecycle-WRITE incident id).
- Sink-derivation-by-handle: the log directory is derived from the runs dir, so a test can drive the sink location by setting `CONDUCTOR_RUNS_DIR` rather than by patching the path fn (per obs-plan §3 Log file location, with per-suite landing sites recorded).
- Three line shapes discriminated by a typed parse: self-obs base line (`timestamp_ms`, `level`, `target`, `service.name`/`service.version`/`deployment.environment`, `run_id`; span-lifecycle variant adds `span`/`span_event`/`parent`), the eleven-field Run-report envelope, and the per-check `CheckRecord` grain (per obs-plan §3 Log format JSON schema).
- Service identity on every self-obs line: `service.name` = `conductor-tauri` (override `$CONDUCTOR_SERVICE_NAME`), version from `env!("CARGO_PKG_VERSION")`, `deployment.environment` from `$CONDUCTOR_ENV` default `local` (per obs-plan §3 Service identity) — a fixture or assertion over a Tauri log line must accommodate these constant fields.

## Anti-patterns to avoid
- Never add `#[tracing::instrument]` to a `#[tauri::command]` handler while reshaping it for testability (per obs-plan §4 desktop-webview row / §1 Notes) — the attribute cannot stack with the command macro.
- Never widen the bounded span-name set to make a survivor observable — no `db.*` read span, no per-input/high-cardinality span name (per obs-plan §11 Spans/Traces + §6 DB READ, recorded as a deliberate operator ruling).
- Never let an absolute host path or internal struct name reach a log line, run-report artifact, `runs.db` row, or a committed evidence file (per obs-plan §11 PII Scrubbing + §11 Logs); §11's 2026-09-02 bullet records that the three application sites do not bound every host-path channel.
