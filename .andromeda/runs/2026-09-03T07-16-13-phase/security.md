# security extract

## Relevance
Relevant — six of the chunk's named survivors sit directly on the `#[tauri::command]` / `resolve_under` boundary this plan governs, and the chunk's committed-evidence deliverable falls under artifact-hygiene bans.

## Constraints
- The six named must-kills (`resolve_handle:38`, `scenarios_dir:44`, `runs_dir:48`, `manifest_path:52`, `run_report:168`, `run_envelope:224`) sit on the boundary security-plan §Input Validation (`#[tauri::command]` IPC-arguments row, `:123`) governs; that row prescribes a control, never an untested shape, so it supplies no standing rule an accepted-deliberate classification could cite. Killed is the only disposition my plan's text supports for them.
- §Input Validation `:123` requires the caller-supplied `run_id`-class id be resolved through `resolve_under` against the resolved runs dir **before any read**, with an absolute candidate or a `..` escape **REJECTED, never clamped**. A killing assertion for `resolve_handle` must therefore pin rejection (Err), not a clamped-but-safe path — a mutant returning `Ok(Default::default())` is exactly the guard-bypass shape the row exists to forbid. Whether the shipped `resolve_handle` already rejects rather than clamps is research's question; if it clamps, that is a finding against this row, not a test-shape problem.
- §Input Validation `:123` + §Error Handling require every returned `Err` from these commands to cross the edge through `sanitize_error` (no absolute host path, no internal seam-crate struct name, no stack trace), and an unknown/absent id to be an **absence** (`Ok(None)` / empty list) — never a panic, never a fabricated value. The `run_report` / `run_envelope` mutants return precisely that absence shape, so a killing test must distinguish *earned* absence from *fabricated* absence. Whether the shipped commands already route Err through `sanitize_error` is research's question.
- The chunk's committed fixture content and the per-survivor disposition ledger under `evidence/` are committed evidence records: security-plan §Security Anti-Patterns → Logging (`:349`) forbids absolute host paths in them (canonicalized `CONDUCTOR_*` dirs, `ANDROMEDA_PULSE_DATA_DIR`). The same bullet also names internal seam-crate struct names; whether that half reaches a mutation ledger whose *subject* is `conductor-tauri`'s own symbols is a reading P3 should settle — the host-path half binds unconditionally.
- If staging a repo root / populated runs dir adds any dependency (incl. a dev-dependency), §Dependency Security requires it land only on `cargo deny check advisories bans licenses sources` **VERIFIED green over the NEW `Cargo.lock`**, with the red-audit deferral's basis restated — "no dependency delta" stops being an available reason.
- The standing PREREQ re-check is governed by §Dependency Security (advisory-DATABASE-fault bullet, `:176-178`): a DB fault is remedied by a bounded wait with the audit↔deny overlap verified green — never a floor raise, never a `deny.toml` ignore, never a CI edit. Any deviation from the expected signature restores the full form.
- §Security Anti-Patterns → Code Patterns (`:357`) requires a minimal deny-by-default capabilities file allowing only the actual commands; §Input Validation `:123` records that app-defined commands are *not* capability-ACL-gated, so observability for a killing test must not be bought by adding a command or widening capabilities.

## Patterns to follow
- The proving tier my plan already names for this boundary: the `resolve_under` guard + `sanitize_error` edge in `conductor-tauri/src/commands.rs` "proven at the mock-runtime IPC tier (`tauri::test`)" (§Input Validation `:123`) — the sanctioned home for the six killing tests, and evidence the tier need not be a live-app leg.
- Committed-fixture + production-reader round-trip precedent, with its security model recorded at §Input Validation's `CONDUCTOR_E2E_SEED_DIR` row (`:118`): harness-owned repo-relative constant, carried through a spawn's **env map** (never argv, never a shell), no-op when unset. The row records an explicit residual — the seeding test applies no `resolve_under`/canonicalize guard of its own, sound only while no shipped binary reads the handle. If this chunk reuses that machinery inside `conductor-tauri`, the residual travels with it and must stay test-only.
- Directory handles vs. IPC arguments are two different rows: `CONDUCTOR_RUNS_DIR` / `CONDUCTOR_SCENARIOS_DIR` / `CONDUCTOR_CONTRACT_MANIFEST` are governed by the canonicalize + bounds-check row (§Input Validation `:115`), the caller-supplied id by `:123`. A fixture that sets those handles is exercising the *first* boundary — it must point at a real existing directory of the expected type, not a synthetic string.
- Typed errors stay inside the seam crates (`thiserror`) and collapse to type-erased `anyhow` only at the `#[tauri::command]` edge (§Error Handling) — a killing assertion should read the sanitized edge value, not reach for internal error detail that the edge is required to strip.

## Anti-patterns to avoid
- NEVER kill a guard mutant by relaxing the guard: clamping an absolute or `..` candidate instead of rejecting it would satisfy a weaker test while violating §Input Validation `:123` and the traversal ban in §Security Anti-Patterns → Input (`:312`).
- NEVER let a committed fixture, a staged-runs-dir artifact, or the disposition ledger carry an absolute host path (§Security Anti-Patterns → Logging, `:349`).
- NEVER add a `#[tauri::command]` or widen the capabilities file to make a survivor observable (§Security Anti-Patterns → Code Patterns, `:357`).

## Contract bindings
- **security ↔ tests:** the six must-kills are my domain's input to the tests domain's disposition ledger; the ledger itself is a committed evidence record subject to the host-path hygiene gate shape my plan already applies to `evidence/nvda-pass.json` (§Input Validation speech-log row, `:119` — "gate-1 hygiene grep (no host path / seam-crate struct name in the committed record)").
- **security ↔ obs on `tauri_log_path:44`:** obs-plan owns the unconditional-sink mandate. The security-side hook is conditional: §Input Validation `:128` records that the *agent-mode* log path derives from `CONDUCTOR_RUNS_DIR` through the same `resolve_under` traversal guard. Whether the Tauri backend sink path likewise derives from a `CONDUCTOR_*` handle — and therefore inherits that guard, making a `Some(Default::default())` mutant a traversal-guard evasion and not merely a dropped stream — is research's question.
- **security ↔ layout-templates on `run_envelope:224`:** whichever banner reading `:144` supports, the security half of the assertion is fixed by §Input Validation `:123` + §Error Handling (guarded resolve, sanitized Err, absence never fabricated); the two halves can be pinned by the same test without waiting on the banner fork.
- **security ↔ CI/tests §CI Integration:** the audit/deny probe is the standing PREREQ and is independent of the mutation tier, which stays audit-tier and non-blocking (no `--fail-under`) — the dependency gate must not be conflated with the mutation score.
