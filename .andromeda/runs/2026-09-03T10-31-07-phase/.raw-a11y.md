## Relevance
Partial — the chunk's surface (`conductor-run`, headless/composition root) is not-assertable for a11y, but `crates/conductor-run/tests/` hosts the fixture seeds the a11y routine arm depends on, so a11y contributes do-not-break constraints only.

## Constraints
- No a11y assertion, ARIA role, or WCAG claim attaches to `conductor-run` code: the headless `conductor run` / cli entity is declared not-assertable (no DOM / widget tree) and its paths are excluded from the must-be-accessible set (per a11y-plan §1, conductor-cli entity + Critical-paths preface).
- The Rust unit/test layer this chunk works in produces no a11y artifact — the pipeline table's Unit row is `cargo-nextest / cargo test / golden (no UI a11y tests at unit layer)`, artifact `n/a` (per a11y-plan §9, per-pipeline-stage table).
- a11y-plan §4 requires the load-envelope banner's rendered-DOM axe subject to be seeded through the **production writer** via `cargo test -p conductor-run --test envelope_fixture` under `CONDUCTOR_E2E_SEED_DIR`; any killing test or admitted production edit in this chunk must leave that seeding contract intact. Whether this chunk's survivors actually sit in that path — or whether `tests/envelope_fixture.rs` / `tests/lamps_fixture.rs` are touched at all — is research's question (per a11y-plan §4, load-envelope banner row).
- a11y-plan §4 names `conductor_run::read_envelope`'s round-trip plus the Tauri mock-runtime IPC test as the banner's **non-DOM** verification path; a mutation remedy that alters envelope read/write semantics would move an a11y-cited contract and require an amendment rather than a silent change (per a11y-plan §4, load-envelope banner row).
- a11y-plan §9 requires the routine arm to seed its own committed fixture subject so that **both** the per-P-ID verdict lamps and the load-envelope banner are asserted for real, with the standing rule that a spec whose DOM state the subject cannot produce context-skips (never passing green) and that no routine-arm spec does so today (per a11y-plan §9, E2E row).
- a11y violation artifacts align to the obs §6 run-report envelope reproduced verbatim in the plan; `conductor-run` is the emitting crate for that envelope, so a survivor remedy that changes field semantics would force a re-check of a11y's reproduction (per a11y-plan §3, Structured violation JSON schema).
- No WCAG conformance may be claimed without machine-verifiable axe-core / colorjs.io / Lighthouse JSON — cargo-mutants tallies are not a11y evidence (per a11y-plan §11 § Strategy).

## Patterns to follow
- Seed-through-the-production-writer fixtures (the existing `tests/envelope_fixture.rs` + `over-envelope.toml` shape) rather than hand-authored JSON/DOM state — this is how the a11y routine arm gets a real subject (per a11y-plan §4 + §9).
- Two-part coverage split: a render-independent half (token/schema assertion) plus a rendered-DOM half, so a Rust-side change is checkable without the webview (per a11y-plan §6 note, as revised by the 2026-09-02 cross-surface amendment).
- Zero-flakiness / no-retry discipline, mirrored from tests' "Do NOT set cargo-nextest `retries` &gt; 0" — killing tests must be deterministic (per a11y-plan §10, Cross-input parallel).
- Artifacts must not leak absolute host paths or internal seam-crate struct names, inherited from tests' Status JSON constraint — applies to anything this chunk's tests emit downstream (per a11y-plan §3 + §11 § SLO).

## Anti-patterns to avoid
- NEVER treat the cli / headless surface as accessibility-assertable — its ASCII status prefixes and `NO_COLOR` text-pairing are output-stream discipline, not an a11y verification path (per a11y-plan §11 § Universal).
- NEVER claim WCAG conformance (or a11y regression-freedom) from this chunk without machine-verifiable evidence (per a11y-plan §11 § Strategy).
- NEVER let an a11y spec pass green on a subject the fixture cannot produce — a lost seed must surface as a context-skip or failure, not silence (per a11y-plan §9, E2E row).

## Contract bindings
- **a11y ↔ tests:** `crates/conductor-run/tests/` is shared ground — `envelope_fixture` (and the lamps fixture) are tests-owned files that a11y's routine arm consumes as its DOM-state seed; a11y otherwise rides tests' 5-command harness (`logs`) and the single `@crabnebula/tauri-driver` + WebdriverIO stack (per a11y-plan §3 + §9).
- **a11y ↔ obs:** a11y violation JSON folds into the obs §6 run-report envelope, the same envelope `conductor-run` emits — the survivor cluster around `observe_run_contract` / `declares` sits adjacent to that emitter (per a11y-plan §3, Structured violation JSON schema).
