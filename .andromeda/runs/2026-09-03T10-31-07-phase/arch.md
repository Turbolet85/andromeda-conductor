## Constraints
- All work stays inside the `conductor-run` workspace member — the run composition root library (preflight + `execute_scenario` + `persist` + live-counter `drive_run` + the fault-phase occupier guard), sitting above the seams and below both bins, carrying the `conductor-run → conductor-faults` edge. Adding a workspace member or a new cross-seam dependency edge to make a mutant convenient is barred; the crate-name registry is a locked, individually-enumerated resource (per architecture.md §Occupied Resources — Crate names, §Established Decisions [Module Boundaries], §Established Decisions [Workspace / Core Structure]).
- The verdict/error wall is a cross-cutting rule that applies in every seam crate: `Verdict`/`ReportState` are returned as `Ok(...)` values and `Result::Err` is reserved for harness faults (config parse, transport down, MCP unreachable). Any killing test for a survivor in the run/route arms (`route_read_back` → `ReadBack {Graded, AutoResolved, Blocked}` is crate-private to `conductor-run`) must assert on the typed value, and any admitted bounding edit must surface a timeout as a harness fault, never as a verdict (per architecture.md §Cross-cutting Patterns — Verdict/error wall, §Established Decisions [Error Handling]).
- The `declares` acceptance rests on an arch-level requirement, not only a testing rule: arch requires Conductor to READ `ANDROMEDA_PULSE_L4_DETERMINISTIC` in its own environment as the run contract's `shell-declaration` proxy and asserts Conductor never SETS it, with the sibling `CONDUCTOR_AGENT_MODE` precedent explicitly stating main never writes it "avoiding edition-2024 `unsafe std::env::set_var`". Whether the six `declares` survivors at HEAD are still exactly the branch that requirement forecloses is research's question (per architecture.md §Occupied Resources — Environment variables, §Occupied Resources — `contracts/pulse-run-contract.toml`).
- The pinned runner is `cargo nextest` driven through a **zero-retry** `ci` profile (`.config/nextest.toml`) because retries would mask flakes against the determinism invariant, plus `cargo test --doc` for the doctests nextest skips. A killing test must be deterministic under that profile — a retry-dependent kill is not available as a remedy (per architecture.md §Infrastructure Patterns — Build system).
- A workspace-wide cargo compile that includes `conductor-tauri` requires `ui/dist` to exist first (`tauri-build`'s `generate_context!` resolves `build.frontendDist` at COMPILE time; a bare `cargo build` does not run `beforeBuildCommand`). Whether the crate-scoped mutation tier's build graph pulls `conductor-tauri` in — and therefore whether the scope's "no tier restoration needed" premise holds — is research's question (per architecture.md §Infrastructure Patterns — Build system).
- Artifact writes are handle-governed: `CONDUCTOR_RUNS_DIR` overrides the default `runs/` artifact directory, and `crates/conductor-run/tests/envelope_fixture.rs` is required to be a **no-op when `CONDUCTOR_E2E_SEED_DIR` is unset** precisely so an ordinary `cargo nextest` / `cargo test` run never writes into the repository. New tests in this crate's `tests/` inherit that obligation — a mutation tier re-runs the suite many times (per architecture.md §Occupied Resources — Environment variables, §Occupied Resources — On-disk artifacts).
- Any dev-dependency addition moves `Cargo.lock` and lands in a `deny.toml`-gated tree whose accepted exception set is enumerated inline per crate and dependency path; `cargo deny` must stay green (`cargo audit` is separately red on the external advisory-DB fault this chunk's PREREQ re-checks) (per architecture.md §Infrastructure Patterns — Build system).

## Patterns to follow
- Crate-private mechanism + unit-pinned arms: `route_read_back` / `ReadBack {Graded, AutoResolved, Blocked}` is the shipped shape for a run-seam decision that is unit-pinned on all three arms without widening the public API — the model for reaching a composition-root branch from inside the crate rather than restructuring it (per architecture.md §Established Decisions [Read-Back Dependency Posture]).
- Read env at the caller, pass it in as a typed value: the `CONDUCTOR_AGENT_MODE` `agent_mode = flag || env-set` shape (read, never written) is arch's registered precedent for keeping an env-reading edge thin (per architecture.md §Occupied Resources — Environment variables).
- Fixed-path-through-`resolve_under` contract loading with deliberately NO `CONDUCTOR_*` override handle (`RunContract::default_path()`, the capability-manifest precedent) — the shape `observe_run_contract`'s inputs arrive through, relevant to how a preflight/contract-cluster test supplies a contract without inventing a new handle (per architecture.md §Occupied Resources — `contracts/pulse-run-contract.toml`).
- RAII guard release at the scheduler's boundary drop for the fault-phase port occupier — the structural shape the `fault_span` / `FaultKind::label` cluster sits in (per architecture.md §Occupied Resources — Crate names, §Cross-cutting Patterns — Trust boundary).
- Wall-clock stamps come from `std::time::SystemTime`/`Instant`, never tokio's virtual clock, on the `current_thread` core-owned runtime — binding on any test that pauses or advances time to make a timing branch reachable (per architecture.md §Cross-cutting Patterns — Determinism discipline, §Established Decisions [Async Runtime Flavor]).

## Anti-patterns to avoid
- Do not introduce a new workspace crate or cross-seam dependency edge to split the composition root — that is a registered-resource change and a §Module Boundaries decision, out of this chunk's scope (per architecture.md §Established Decisions [Module Boundaries], §Occupied Resources — Crate names).
- Do not write or mutate process environment in a test to reach a branch (`unsafe std::env::set_var` in a shared-process test module), and do not make Conductor SET a Pulse-side `ANDROMEDA_PULSE_*` variable — arch asserts those are read-only in Conductor's environment (per architecture.md §Occupied Resources — Environment variables).
- Do not convert a harness fault into a verdict (or vice versa) to make an arm testable, and do not let a new test write artifacts into the repository default `runs/` without the `CONDUCTOR_RUNS_DIR` handle (per architecture.md §Cross-cutting Patterns — Verdict/error wall; §Occupied Resources — Environment variables).

## Contract bindings
- arch ↔ tests: the nextest runner + zero-retry `ci` profile and `cargo test --doc` are arch-pinned; the mutation instrument's invocation and the `caught.txt`/`missed.txt` read-out discipline are test-plan §4/§10/§12's.
- arch ↔ security: a dev-dependency addition moves `Cargo.lock` and enters the `deny.toml` exception ledger whose authoritative home is security-plan §Dependency Security (arch carries derived one-liners); the standing `cargo audit` advisory-DB fault the PREREQ re-checks is likewise security-plan's record.
- arch ↔ obs: any admitted bounding/tightening edit in the composition root must keep the `tracing` self-observation stack (NOT an OTel SDK — OTLP is the PRODUCT emission) and the `logs/agent-latest.jsonl` sink behaviour intact; detail is obs-plan §3's.
- arch ↔ tests (build graph): if the crate's tier compiles `conductor-tauri`, the `ui/dist`-before-cargo coupling becomes a precondition of running the tier at all.
