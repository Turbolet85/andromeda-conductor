# obs extract

## Relevance
Partial — relevant: four of the named survivor sites (`fault_span`, `FaultKind::label`, `execute_scenario`, and `conductor-run`'s report-seam/read-back seams) are obs-instrumentation surfaces this plan governs, so obs supplies the contracts a killing test may assert against and bounds the admitted "observability gap" remedy class; the dispositioning discipline itself is tests-owned.

## Constraints
- The `scenario.run` root span is required to open per-scenario **at this very file's composition root** (`conductor-run::execute_scenario`) and close when that scenario returns, with `report.generate` / `db.insert_run` as run-scoped **siblings** correlated by `run_id`, never descendants (per obs-plan §4 Critical Path 1 → Cleanup). A killing test around `execute_scenario` must not re-assert the retired nesting. Whether the shipped code already places the root there is research's question.
- `conductor-run` is the mandated **owner of fault-span semantics**: `fault.silence` / `fault.ramp` are required to open from the caller-supplied per-phase hook (`run_timeline_observed` / `PhaseWindow`) with `conductor-run` supplying the fault semantics and the `std::time` journal basis, **created but NOT entered** (entering would re-parent `emit.batch`), and `conductor-run`'s `phase_guard`/`PhaseGuard` drives `fault.port_occupier` for a fault-declared phase's window (per obs-plan §4 → Fault-injection spans → "Where each span opens").
- Fault-span attribute sets are exact and closed (per obs-plan §4 → Fault-injection spans): `fault.silence` = `fault_type`("silence") + `fault_duration_ms` + `fault_start_offset_ms`; `fault.ramp` adds `ramp_factor` as a **signed −1.0..1.0** normalized slope `(to_rate − from_rate) / max(from_rate, to_rate)`; `fault.port_occupier` = `fault_type`("port_occupier") + `port` **only**, with the realized hold witnessed on the allowlisted `message` field at `debug` on RAII release. A `FaultKind::label` mutant is only distinguishable by an assertion pinning these literal `fault_type` values.
- Span names must stay inside the **bounded set** — `scenario.run`, `timeline.execute*`, `emit.batch`, `emit.logs_batch`, `verify.readback*`, `report.generate`, `db.insert_run`, `fault.silence/ramp/port_occupier`, `tauri.command.*` — and a span **attribute must be a name in `conductor-core::redact::ALLOWLISTED_FIELDS`** or the processor stage drops it, so it emits nothing (per obs-plan §11 Spans/Traces + §4 Known-residual → Required span attributes).
- The observable surface a killing test can read is the §3 **self-obs span-lifecycle line**: base set (`timestamp_ms`, `level`, `target`, service-identity, `run_id`) plus `span`, `span_event` (`new` | `close`), optional `parent`, and the span's allowlisted attributes **on the `new` line only** (per obs-plan §3 → Log format JSON schema, two record shapes). An attribute not computable at span-open is uninstrumentable by construction.
- Fault-span lifecycle is required at `info`, not `debug`, precisely so it is visible under the default INFO filter with no `RUST_LOG` opt-in (per obs-plan §6 → Log levels + "Why fault-span lifecycle is `info`"). §6 further states a per-target `RUST_LOG` directive **replaces** the default and must never be set for a run that also executes the test suite — the environment reaches the runner's child processes, which bears directly on a cargo-mutants/nextest tier.
- If a survivor is dispositioned by the admitted production-edit exception (bounding/tightening a construct, the sibling's unbounded-`rx.await` class), the bounded arm must emit a structured line and never an unlogged panic or unstructured stderr; panics are captured via `std::panic::set_hook()` + `tracing::error!` + the `anyhow` edge (per obs-plan §10 zero-unlogged-panics; §11 Logs / Error Reporting).
- `conductor-run`'s own seams carry named must-log obligations that a survivor at those sites would touch: the read-back/canary boundary (`verify.readback*` — tool name, `latency_ms`, canary-check result, observed key set on `message`), the lifecycle WRITE via `probe_resolve_lifecycle` (same `verify.readback.call_tool` span, `mcp_tool` attribute, incident id on `message`, declined arm stub-only and permanently so), and the DB **read** via `read_envelope` (an `info!` inside the caller's span, minting **no** `db.*` span) (per obs-plan §6 → Boundary-call wrappers).

## Patterns to follow
- Assert instrumentation through the emitted self-obs JSONL lines (`span` / `span_event` / `parent` / allowlisted attributes), not through internal structures — this is the mechanism that made `fault.port_occupier`'s `parent: "timeline.execute"` a *measured* fact rather than a spec claim (per obs-plan §3 Log format, §4 Fault-injection spans).
- Keep any evidence text on the already-allowlisted `message` field rather than minting a new attribute — the established pattern for the read-back key-set witness, the `emit.batch` wire-shape witness, the incident id, and the port-occupier release witness (per obs-plan §6 Boundary-call wrappers; §4 Fault-injection spans).
- Prefer a run-scoped `run_id` correlation over structural nesting when relating report-seam records to a scenario — the plan's own remedy when a nesting claim proved unachievable at this composition root (per obs-plan §4 Critical Path 1 Cleanup).
- Wall-clock only (`std::time::SystemTime`/`Instant`) for any journal-relative offset or duration a test constructs around `fault_start_offset_ms` / `latency_ms`; never tokio's virtual clock (per obs-plan §11 Project-specific bans; §5 Metric Coverage).
- Values that cannot be computed at the moment the layer reads attributes are recorded as a `message`-borne witness instead of a required attribute — the precedent set for `fault.port_occupier` and for the retired `fingerprints_matched_count` (per obs-plan §4).

## Anti-patterns to avoid
- NEVER delete, weaken, or bypass a critical-path span/attribute to make a mutant die — "NEVER skip spans on critical paths (Scenarios 1-7)" and "NEVER leave dangling spans" (per obs-plan §11 Telemetry Strategy + Spans/Traces).
- NEVER widen the bounded span-name set or add an attribute outside `ALLOWLISTED_FIELDS` to make a survivor observable; the set is a deliberate contract (the 2026-09-01 operator ruling declined even a `db.*` read-span wildcard) (per obs-plan §11 Spans/Traces; §6 DB READ bullet).
- NEVER introduce an OTel SDK, `tracing-opentelemetry`/W3C trace context, or a metrics instrument as a test-observation aid — it re-introduces the banned SDK and its background tasks break `current_thread` determinism (per obs-plan §11 Telemetry Strategy / Metrics / Universal; §3 OTel SDK init).

## Contract bindings
- **obs ↔ tests harness (two-sided, D-tests-obs-harness):** test-plan §3 OWNS the JSONL/self-obs line format; obs-plan §3 reproduces it and aligns to tests, not vice versa. Any killing test that asserts a span or field consumes that shared shape, and a one-sided change to either side is exactly what the bind guards (per obs-plan §3 Log format JSON schema; §6 Log Coverage preamble).
- **obs ↔ tests CI gates:** the §9 log-conformance gate (§3 self-obs base schema on `logs/agent-latest.jsonl`, no absolute host paths) and the zero-unlogged-panics gate (`^thread.*panicked` grep) must remain green across the mutation tier and any test the chunk adds (per obs-plan §9 CI Integration; §10 SLO Invariants).
- **obs ↔ security:** any artifact a new test writes is bound by the redaction contract — no absolute host-file paths, no internal struct names; allowlist + `Display`-not-`Debug` at the `anyhow` edge (per obs-plan §11 PII Scrubbing; §9 conformance check).

## Acceptance criteria contributions
- (obs) Any killing test that observes instrumentation asserts only bounded span names and allowlisted attributes — no new span name, no attribute outside `conductor-core::redact::ALLOWLISTED_FIELDS` (per obs-plan §11 Spans/Traces + §4 Known-residual → Required span attributes).
- (obs) A disposition of the `fault_span` / `FaultKind::label` survivors pins the exact §4 fault contract: literal `fault_type` values, `fault.silence`/`fault.ramp` created-not-entered as children of `timeline.execute`, `ramp_factor` signed in −1.0..1.0, and `fault.port_occupier` carrying `fault_type` + `port` only (per obs-plan §4 → Fault-injection spans).
- (obs) No production edit taken as a survivor remedy removes or downgrades a critical-path span, and any bounded-await/timeout arm emits a structured `warn`/`error` line rather than panicking or writing unstructured stderr — zero unlogged panics holds (per obs-plan §10 SLO Invariants + §11 Logs / Error Reporting).
- (obs) The mutation tier runs with no per-target `RUST_LOG` directive exported, so the `info`-level fault-span lifecycle stays visible and non-opted-in targets are not silenced in the runner's child processes (per obs-plan §6 → per-module log levels, additive-form note).
