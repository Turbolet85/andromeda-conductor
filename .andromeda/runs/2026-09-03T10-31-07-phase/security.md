## Constraints
- The standing PREREQ is an **advisory-DATABASE fault**, not a tool fault: the only sanctioned remedy is the bounded wait plus the audit↔deny overlap **verified** green — never a floor raise, never a `deny.toml` ignore, never a CI edit, never a silent accept (per security-plan §Dependency Security, two-fault split). "Verified, not assumed" is the plan's own wording and binds this 47th re-check.
- If any dev-dependency lands (the scope anticipates none, but permits one), the plan requires it land **only** on a `cargo deny check advisories bans licenses sources` verified green over the **new** `Cargo.lock`, and requires the deferral's stated basis to be re-pinned — "no dependency delta" stops being available as a reason (per security-plan §Dependency Security, admitting-a-new-dependency-under-a-red-audit clause). `Cargo.lock` must stay committed and un-drifted (per §Security Anti-Patterns → Universal).
- Any killing test targeting the resolve-lifecycle path (`conductor_run::probe_resolve_lifecycle`, the first production caller of `mark_incident_resolved`) must reach the corpus through the MCP tool surface only; **staging a corpus row directly to induce `DeclinedStale` is the banned route, which is why that arm is required to be stub-proven** (per security-plan §Security Anti-Patterns → Data Protection, corpus.db ban). Whether that arm's survivors are in this chunk's re-measured set is research's question.
- The `declares` accepted-deliberate class rests on a declaration-only read: the plan requires that Conductor test only whether its **own** environment declares the flag, and that a term whose truth lives SUT-side be recorded `declared-not-observable` and never block — **never a claimed measurement of `pulse-app`** (per security-plan §Input Validation, `ANDROMEDA_PULSE_L4_DETERMINISTIC` row; §Security Anti-Patterns → Universal, never-downgrade bullet). A killing test must not convert this into an asserted SUT measurement.
- Any production edit admitted under the chunk's observability-exception clause on the preflight/contract cluster must preserve the never-silently-downgrade rule: each of the gate's five named preconditions surfaces as the distinct `blocked` state with its own precondition string, the run-contract arm composing one string naming each unmet term with its causes (per security-plan §Security Anti-Patterns → Universal). Whether the shipped code already satisfies this is research's question — this extract states it as a requirement the edit must not regress.
- The port-occupier fault's bind target is required to stay a private builder parameter — **deliberately not a config field, no operator-steerable bind target** — and the `:4317` bind must never be promoted toward a general-purpose listener (per security-plan §Input Validation, `[phases.fault]` clause; §Security Anti-Patterns → API, 4th bullet). This binds any killing test for the `fault_span` / `FaultKind::label` cluster that reaches for a parameterizable port.
- Any record this chunk commits (mutation ledger, `caught.txt`/`missed.txt`, an `evidence/` row) must carry no absolute host path — the artifact-hygiene ban covers committed evidence records as agent-parseable ground truth shared across hosts (per security-plan §Security Anti-Patterns → Logging). Note the tension for research: mutation output names internal functions by construction, so only the host-path half is unambiguously binding.

## Patterns to follow
- Pinned-signature reproduction of the red audit with the deny overlap verified green each chunk — the pattern established at the 2026-08-09 chunk and re-run every chunk since (per security-plan §Dependency Security).
- The verdict/error wall: harness faults stay `Result::Err` (typed `thiserror` enums inside the seam crates), verification outcomes stay typed values returned as `Ok(...)`; killing tests should assert those typed values / error variants rather than panics or exit codes (per security-plan §Error Handling; §Security Anti-Patterns → Universal, never-panic bullet).
- Accepted-exception mechanism as the model for this chunk's accepted-deliberate roster shape: an entry with a justifying comment, with the machine-readable file (`deny.toml`) as the authority and prose as a known-incomplete record (per security-plan §Dependency Security, Accepted exceptions).
- The test-binary env-handle model already sanctioned for `crates/conductor-run/tests/` — `CONDUCTOR_E2E_SEED_DIR` as a harness-owned repo-relative constant carried through a spawn's env map, no-op when unset, with the missing-`resolve_under` residual recorded explicitly (per security-plan §Input Validation, `CONDUCTOR_E2E_SEED_DIR` row). If a killing test needs a handle, this is the governed shape.
- Fixed `default_path()` through `resolve_under` with deliberately no `CONDUCTOR_*` override for the committed SUT-facing manifests, absent/malformed never defaulted and never silently widened (per security-plan §Input Validation, committed-manifests row) — the shape any contract-cluster fixture must not undermine.

## Anti-patterns to avoid
- NEVER paper over the red audit with a `deny.toml` ignore, a floor raise, or a CI edit — a floor raise is unexecutable against a database fault and "would look like compliance while changing nothing" (per security-plan §Dependency Security).
- NEVER have production or test code directly open/copy/stage Pulse's `corpus.db` to make a survivor convenient to kill (per security-plan §Security Anti-Patterns → Data Protection).
- NEVER parameterize a survivor's guard through a new `CONDUCTOR_*`-style path handle read by a **shipped** binary without the `std::fs::canonicalize` + bounds-check duty at the `conductor-cli` edge — the three exempt handles are exempt only because no shipped binary reads them (per security-plan §Security Anti-Patterns → Input, canonicalize ban).

## Contract bindings
- **CI security gate ↔ tests §CI Integration:** the PREREQ's `cargo audit` / `cargo deny` gates run alongside the mutation tier read-out; the tier read-out discipline is tests' (test-plan §4/§10), the audit/deny gates and their exit-code reading are security's (per security-plan §Dependency Security, CI integration).
- **Dependency delta ↔ the chunk's own report contract:** the scope binds a `Cargo.lock` move to a package-count delta report rather than a "byte-unchanged" claim, citing `.claude/rules/security.md` (2026-09-02) — the distilled form of security-plan §Dependency Security.
- **No obs/PII binding:** Conductor owns no PII (per security-plan §Threat Model Summary, data classification all-"none"), so the obs §PII-scrubbing cross-cut does not attach to this chunk.
