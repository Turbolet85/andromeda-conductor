# tests extract

## Relevance
Relevant — this chunk is a pure tests-domain chunk (mutation instrument, survivor disposition, read-out gate, killing tests), governed end-to-end by test-plan §4 / §9 / §10 / §12.

## Constraints
- Mutation-instrument run discipline is mandated, each item measured not assumed: `-f` resolves from the **workspace root** so full crate paths are required (a package-relative path under `-p` matches nothing), `--test-tool=nextest` is REQUIRED, `Found 0 mutants to test` is a NO-OP and never a pass, output goes to a gitignored `mutants.out/` (per test-plan §4 Mutation instrument). Tool version is a floor, not a pin (per test-plan §4 Tool-version policy).
- The read-out gate is the tallies, never the exit code — a non-zero exit reflects surviving/timeout CLASSES, not run failure; `missed.txt` must hold EXACTLY this run's accepted-deliberate survivors (empty only when none is accepted) and every other named survivor must be present in `caught.txt` (per test-plan §4 Mutation instrument, as reconciled to §10 by the sibling chunk).
- Every NAMED survivor must end either killed or classified accepted-deliberate **against a cited rule**; the roster is the SET recorded in §12, so a new acceptance EXTENDS it rather than contradicting a single-case literal. Explicitly NOT a numeric `--fail-under` threshold — the score moves as a consequence of dispositioning and is never itself the acceptance (per test-plan §10 Mutation-survivor disposition).
- The mutation audit is an operator/local instrument on the same footing as the live-Pulse leg — never a blocking CI stage, run per-chunk against the crates the chunk touched, not workspace-wide (per test-plan §9 Scoped mutation audit). This is the plan-side ground for the scope's "workspace-wide mutation is out of scope".
- Any killing test must be green under BOTH runners: `cargo nextest run -p conductor-run` and the standing runner-portability gate `cargo test -p conductor-run`; a runner-dependent result is a determinism break to fix at the cause, not a runner to pin to (per test-plan §4 Framework; §10 Zero-flakiness budget).
- Killing tests must target the public seam API and observable behavior (envelope / verdict / state output), not private fns or internal struct fields, and must not assert against fixture-internal values (per test-plan §11 Unit). Time-shaped survivors must be driven by `tokio::time::advance` under `start_paused = true`, never a real wall-clock duration (per test-plan §11 Unit, stack-specific).
- If a killing test touches the process-global, first-install-wins `init_observability` subscriber, it OWES its own test binary — a per-test `TempDir` sink does not isolate it, and serializing with `--test-threads=1` is banned as hiding the defect (per test-plan §11 Integration, stack-specific).

## Patterns to follow
- Crate-local `#[cfg(test)] mod tests` inside the source file for unit-tier kills, plus crate-local `tests/` for slower in-crate integration; snake_case `#[test]` / `#[tokio::test]` / rstest `#[rstest]` naming; per-seam crate is the grouping (per test-plan §4 Conventions) — matching the scope's named homes (`crates/conductor-run/tests/` and the in-file modules).
- rstest as the fixture layer: `#[fixture]` for the seeded `conductor-timeline` generator, `#[rstest]` + `#[case]` for table-driven variant rows, `#[once]` for in-memory `runs.db` schema, `#[future]`+`#[awt]` for async fixtures under the `current_thread` flavor (per test-plan §4 Fixture pattern; §7 Seed strategies).
- The env-at-the-caller shape that grounds the standing `declares` acceptance: env is read at the caller and passed in as a typed value so the edge stays thin and both branches test with no `unsafe` env mutation (per test-plan §10 / §12 `2026-08-20` entry). Whether any `conductor-run` survivor is reachable by parameterising a default at the caller — the sibling's cheapest remedy — is research's question.
- Integration-tier drivers already sanctioned for this crate's preflight/contract cluster: the hand-rolled `stub_pulse_mcp` over sidecar stdio (in-process duplex or spawned child), rusqlite `Connection::open_in_memory()`, `assert_fs::TempDir` file DB (per test-plan §5 Driver(s) + boundary table; §8 What to mock).
- Where a new committed fixture is needed, it must come from the sanctioned provenance SET (crate-local `tests/fixtures/` trees) and must carry its MEANING via one production reader/writer round-trip per fixture, not merely parse (per test-plan §7 Self-bootstrapping requirement).

## Anti-patterns to avoid
- Never gate on cargo-mutants' exit code in either direction, and never read `Found 0 mutants to test` as a clean pass (per test-plan §4 Mutation instrument).
- Never substitute a numeric mutation threshold or lower/skip a standing gate to accept the run — the coverage line gate and audit-green/clippy remain binding (per test-plan §10; §11 Quality).
- Never kill a mutant by testing implementation details, by `unsafe` env mutation inside a shared-process test module (the exact hazard the 2026-08-20 chunk removed, per test-plan §12 `2026-08-20`), or by relying on nextest's per-test process for isolation from process-global state (per test-plan §11 Unit / §11 Integration).

## Contract bindings
- tests ↔ obs: if the scope's admitted exception class fires (a survivor that is a genuine observability gap remedied by bounding the shipped construct), test-plan §3 Log format / Status endpoint shape OWNS the journal + envelope schema and obs-plan §3 derives from it — any change to line shape, envelope fields, or `runs.db` columns is a two-site reconcile, not a one-sided edit (per test-plan §3; amendment precedent 2026-08-10 / 2026-08-21).
- tests ↔ security: a dev-dependency addition moves `Cargo.lock` and must be reported as a package-count delta; the supply-chain gate (`cargo audit --deny warnings` + `cargo deny check` green, un-drifted `Cargo.lock`) stays binding, which is also where the chunk's standing PREREQ (the 47th `cargo audit` re-check) lands (per test-plan §9 Build failure conditions; §11 CI, stack-specific).
- tests ↔ docs/wrap: an accepted-deliberate disposition binds to §10's roster and §12's mutation-instrument entry, each member against its own cited rule with a named evidence home under the chunk's `evidence/` (per test-plan §10; §12 `2026-08-20`).

## Acceptance criteria contributions
- (tests) The scoped mutation tier is re-measured at HEAD over the touched files with full workspace-root `-f` paths and `--test-tool=nextest`, and the verdict is read out of `mutants.out/`: `missed.txt` holds EXACTLY this run's accepted-deliberate survivors and every other named survivor is present in `caught.txt` — the exit code is not the signal, and a zero-mutants result is a NO-OP (per test-plan §4). Whether `conductor-run` already has a runnable mutation tier at HEAD, or needs the build-graph repair its sibling crate needed, is research's question.
- (tests) Every survivor the re-measurement names is dispositioned killed or accepted-deliberate against a cited standing rule, with the §12 roster EXTENDED rather than contradicted, and no numeric threshold used as the acceptance (per test-plan §10).
- (tests) `cargo nextest run -p conductor-run` AND `cargo test -p conductor-run` both green — the standing runner-portability gate — with zero retries configured and no runner-dependent result (per test-plan §4 Framework; §10 Zero-flakiness budget).
- (tests) New killing tests keep the workspace coverage gate at `--fail-under-lines 60` without lowering it, and add no wall-clock or shared-mutable-state dependence (`start_paused` clock, per-test in-memory/`TempDir` `runs.db`) (per test-plan §10; §11 Unit / Test Data).
