# design extract

## Relevance
Partial — the `cli` surface applies in full (probe output, status labels, error/hint edge, artifact tint); `desktop-webview` is out of scope (this chunk touches no UI surface).

## Constraints
- The probe's result must NOT render any of the six lamp brackets (`[PASS]`/`[HOLD]`/`[FAIL]`/`[MANUAL]`/`[RESIDUAL]`/`[BLOCKED]`) nor introduce a seventh lamp state or a sixth `ReportState` — per design-system.md §Surface: cli / Tokens, the closed lamp set is per-P-ID, and a run-scoped qualifier lives **outside the lamp column** (the `[ENVIRONMENT-SUSPECT]` precedent). This is the design-side expression of the scope's "Not a verdict" boundary.
- Any non-lamp probe caption must reuse the existing recessive tier — Residual-mute ANSI 246, bound by name to webview `var(--status-residual)` — and must NOT mint a new palette row or ANSI entry (per design-system.md §Surface: cli / Tokens, which names the non-lamp uses as a SET precisely so a fourth reuse needs no new token).
- Color must never carry the signal: an always-rendered ASCII text label accompanies every tint, and output must be TTY-gated through `anstream` with `NO_COLOR` and `TERM=dumb` honored, ANSI stripped when piped (per design-system.md §Surface: cli / Tokens + §Surface: cli / Platform-Specific Notes). Whether the probe's chosen emit path already routes through the shipped `anstream`/`owo-colors` gate is research's question.
- A probe that cannot answer must emit the stderr `error: &lt;short&gt;` + contextual detail + `hint: &lt;fix&gt;` shape, reusing Fail red (ANSI 203) for `error:` and Residual-mute (ANSI 246) for `hint:`, on stderr's own `IsTerminal` gate distinct from the stdout gate; sanitized — no absolute host paths, no internal struct names, no stack traces outside `--debug`/`-v` (per design-system.md §Surface: cli / Component Patterns 5). The scope's "a `PATH` miss must be named without echoing the `PATH`" is this rule applied to subject 2.
- The probe must not introduce an interactive prompt on the agent-driven path: `inquire` prompts are always `isatty`-gated and the headless source-of-truth path is never blocked on one (per design-system.md §Surface: cli / Component Patterns 2 + §Surface: cli / Platform-Specific Notes).
- No spinner for a sub-threshold probe: design-system.md §Surface: cli / Component Patterns 1 permits an `indicatif` spinner only after ~200ms ("honest progress, not instant churn"), so a ~2 ms connectability/resolution probe must print its result without live-progress chrome.
- The mono ID-cyan tier (ANSI 117 / `--color-id-cyan`) is a **closed reserved set** — P-IDs, `run_id`, SLO timings, `latency_ms`, fingerprints (per design-system.md §Typography Data row + §Surface: cli / Tokens). Endpoint literals (`127.0.0.1:4317`), a binary name, and `ANDROMEDA_PULSE_*` handle names are not in that set; tinting them ID-cyan would be an extension the plan does not authorize, so either keep them untinted or route them through the existing recessive tier.
- If the probe's artifact is Markdown (no color channel), the surface-adapted counterpart is required: emphasis or the bracket label in a blockquote, never a color-only distinction (per design-system.md §Surface: cli / Tokens, Residual-mute entry).

## Patterns to follow
- **Run-level `[ENVIRONMENT-SUSPECT]` caption** (design-system.md §Surface: cli / Tokens + §Component Patterns 4) — the existing precedent for a run-scoped qualifier printed **once**, above the per-P-ID lines, outside the lamp column, in the Residual-mute tier, explicitly "a qualifier on the run, never a seventh lamp." The scope's "absent SUT named once rather than absorbed per chunk" is the same shape; follow this rather than inventing a new status vocabulary.
- **`error:` / `hint:` stderr pair** (design-system.md §Surface: cli / Component Patterns 5) — the shipped two-token, always-ASCII-labelled, sanitized error edge for the "probe cannot answer" path.
- **`Blocked` row precondition string** (design-system.md §Surface: cli / Component Patterns 3) — where a precondition IS named against a run, it carries the named precondition string and renders measurement columns as `—`/null, never a red error. If probe results are ever tabulated, `comfy-table` width is detected dynamically from the terminal, never hardcoded.
- **Terse-callout tone** (design-system.md §Brand Identity) — "terse status callouts with no alarm in the tone"; an absent SUT is stated flatly, not escalated.
- **Stdout/stderr intent split** (design-system.md §Anti-Patterns / Per-Surface Bans, cli) — raw artifact data on stdout (agent-parseable), human messages on stderr.

## Anti-patterns to avoid
- Conflating "no result yet" with "failed", or rendering a precondition miss as a red error — a named Rejected Default in design-system.md §Anti-Patterns / Rejected Defaults; `Blocked` is a distinct slate-violet state carrying the precondition string, "never a silent downgrade to red Fail." A probe fact is even further from a verdict than `Blocked` is.
- Adding a new color, ANSI entry, or lamp glyph for the probe — design-system.md §Anti-Patterns / Universal Bans forbids color that does not communicate `Verdict`/`ReportState`; the amendment history records this correction twice already (an existing tier is reused, no palette row added).
- cli bans that apply verbatim (design-system.md §Anti-Patterns / Per-Surface Bans, cli): emoji in machine-parseable piped output, colorizing without the `NO_COLOR`/`TERM`/pipe check, color-alone status, stack traces in normal mode, hardcoded widths, an un-`isatty`-gated prompt.

## Contract bindings
- **Never-color-alone ↔ a11y SC 1.4.1** — design-system.md §Surface: cli / Tokens carries the ASCII-label rule as the terminal mirror of a11y's use-of-color criterion; a11y owns the criterion, design owns the label/prefix shape.
- **ANSI 246 ↔ `var(--status-residual)`** — design-system.md §Surface: cli / Tokens binds the CLI and webview halves of the recessive tier **by name**; a fourth non-lamp reuse here must keep the pair in sync (and, per the plan's own precedent, be recorded as a set member, not a new token).
- **Artifact sanitization ↔ security plan** — design-system.md §Surface: cli / Component Patterns 5 defers the sanitize rule ("no absolute host paths / internal struct names / stack traces") to the security plan; design owns only the `error:`/`hint:` label and tint shape, security owns the field allowlist.
- **stdout data channel ↔ tests/harness** — the `agent-run.{sh,ps1}` harness consumes the stdout half; design-system.md §Surface: cli / Navigation Pattern requires it stay pipe-friendly and ANSI-free on the headless path.

## Acceptance criteria contributions
- Probe output introduces zero new colors: every tint traces to an existing entry in the ANSI 256 map, and any non-lamp caption uses Residual-mute ANSI 246 / `var(--status-residual)` (per design-system.md §Surface: cli / Tokens).
- Probe output renders no per-P-ID lamp bracket for an unrun scenario and adds no seventh lamp / sixth `ReportState`; any run-scoped qualifier prints once, outside the lamp column (per design-system.md §Surface: cli / Component Patterns 4).
- Every probe status line carries an always-rendered ASCII label, and the same line is legible with color stripped — verified under a pipe, `NO_COLOR`, and `TERM=dumb` (per design-system.md §Surface: cli / Platform-Specific Notes).
- A probe that cannot answer emits `error: &lt;short&gt;` + `hint: &lt;fix&gt;` on stderr, sanitized — no absolute host path, no `PATH` echo, no internal struct name, no stack trace outside `--debug`/`-v` (per design-system.md §Surface: cli / Component Patterns 5).
