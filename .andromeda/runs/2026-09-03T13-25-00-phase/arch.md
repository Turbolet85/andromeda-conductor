# arch extract

## Relevance
Relevant — arch is foundational here: the chunk lands a new client-side surface, touches locked crate names, the `:4317` egress resource, the `ANDROMEDA_PULSE_*` env registry, and the verdict/error wall.

## Constraints
- **Workspace placement is locked.** Probe code must land in an existing workspace member (`conductor-emit` owns egress primitives; `conductor-run` is the composition root above the seams and below both bins; `conductor-cli` owns the clap verb surface); a new member is only justified as a new module seam with explicit `Cargo.toml` edges, and a forbidden cross-seam edge must fail to compile (per architecture.md §Occupied Resources — Crate names, §Established Decisions [Module Boundaries], §Project Intent).
- **Client-side only, never a bind.** `127.0.0.1:4317` is Pulse-owned egress target; `:4318` is unused; the shipped binaries carry no inbound listener of Conductor's own, and the port-occupier fault scenario is the single deliberate bind (per architecture.md §Occupied Resources — Ports, §Cross-cutting Patterns — Trust boundary). A connectability check must stay on the client side of that line.
- **Verdict/error wall applies to the probe.** Verification outcomes are typed values; `Result::Err` is reserved for harness faults, so a probe that cannot answer is an `Err`, not a verdict. Arch also requires that a `Blocked` row populate `run_id`/`seed`/`scenario`/`p_ids`/`slo_tier` — none of which exist before a scenario is scheduled — the same reasoning arch already applies to manifest-load failure ("never `Blocked`, never a silent widening") (per architecture.md §Cross-cutting Patterns — Verdict/error wall, §Standard Contracts, §Established Decisions [Accepted Capability Set]).
- **Env registry discipline.** `CONDUCTOR_*` is the reserved namespace and each handle is individually registered; the three `ANDROMEDA_PULSE_*` handles are Pulse-side and asserted **not set by Conductor**. Arch records `ANDROMEDA_PULSE_L4_DETERMINISTIC` as READ in Conductor's own environment as the run contract's `shell-declaration` proxy, and mandates read-never-write (the `CONDUCTOR_AGENT_MODE` precedent, avoiding edition-2024 `unsafe std::env::set_var`). Whether the shipped run-contract term list already enumerates all three handles as `shell-declaration` terms — i.e. whether subject 3 is already answered in code — is research's question (per architecture.md §Occupied Resources — Environment variables).
- **Error typing by altitude.** Typed `thiserror` enums per seam crate; `anyhow` only at `conductor-cli` / `#[tauri::command]` edges (per architecture.md §Conventions — Error handling, §Inherited Defaults).
- **Headless is the release gate.** `scripts/agent-run.{sh,ps1}` is the source of truth and the gate, development style is agent-driven, and the CLI verb surface is clap 4 `derive` — so a probe reachable only from the GUI would not satisfy the gate (per architecture.md §Design Philosophy, §Cross-cutting Patterns — Development Style, §Stack — CLI argument parsing).
- **Runtime + clock.** Core-owned tokio `current_thread` (`#[tokio::main(flavor = "current_thread")]` on the CLI path); any instant the probe stamps comes from `std::time::SystemTime`/`Instant`, never a virtual clock (per architecture.md §Established Decisions [Async Runtime Flavor], §Cross-cutting Patterns — Determinism discipline).

## Patterns to follow
- **The run contract's `check`-kind taxonomy is the honesty model a probe should reuse:** `shell-declaration` (observable in Conductor's OWN environment — the only kind arch permits to block), `asserted` (true by construction), `declared-not-observable` (recorded so an operator can satisfy it, never blocking, because a block would claim a measurement Conductor cannot make). All three probe subjects are Conductor-side observables, so they map to the first kind (per architecture.md §Occupied Resources — `contracts/pulse-run-contract.toml`).
- **The readiness-result shape, minus the canary:** a serialized result with per-subject states, a single named `blocked_precondition`-style string, and an RFC-3339 `checked_at`, with `data_dir` redacted. The probe can borrow that projection without borrowing the mutating round-trip (per architecture.md §Standard Contracts — Readiness gate, Timestamp formats).
- **Precondition strings name candidate causes rather than assert an unmeasurable fact** — the shape both the workspace-key arm and the unmet-run-contract-terms arm already use (per architecture.md §Standard Contracts — Readiness gate).
- **Manifest resolution precedent, if the probe reads `contracts/`:** fixed `default_path()` through `resolve_under`, deliberately NO `CONDUCTOR_*` override handle, and a malformed/absent/unparseable manifest is a harness fault carrying a named reason (per architecture.md §Occupied Resources — On-disk artifacts).
- **Seam reuse over duplication:** emission/egress primitives belong to `conductor-emit`; whether a non-mutating `:4317` connectability primitive already exists there (satisfying subject 1 by reuse) is research's question — arch only fixes the endpoint and the transport (per architecture.md §Occupied Resources — Ports, §Conventions — Outbound emission).

## Anti-patterns to avoid
- **Any OTLP write, under any `service.name`.** Arch records that Pulse keys per-service sample counts and error-rate EWMAs, which is why `conductor-canary` was split off `conductor` at all, and that Pulse dedupes a new incident against an open one on the `(kind, scope, scope_id)` tuple — so a probe that emits both ages a baseline and primes the state a later leg collides with (per architecture.md §Occupied Resources — Service/process names, §Established Decisions [Read-Back Dependency Posture]).
- **A second network surface.** No HTTP/gRPC server, no `:4318`, no inbound listener, no web framework (per architecture.md §Established Decisions [Backend Framework], §Occupied Resources — Ports).
- **Registry drift:** a new env handle outside `CONDUCTOR_*`, a `CONDUCTOR_*` override for a `contracts/` manifest path, or Conductor writing an `ANDROMEDA_PULSE_*` var (per architecture.md §Occupied Resources — Environment variables, On-disk artifacts).

## Contract bindings
- **arch ↔ security:** arch requires precondition strings be host-path-free with `data_dir` redacted (§Standard Contracts — Readiness gate); security owns the `anyhow`-edge sanitization + tracing field allowlist that enforces it. Arch names `PATH` a *spawn-resolution input* (§Occupied Resources — Service/process names), so a `PATH` miss is reportable while the `PATH` value itself is not.
- **arch ↔ obs:** the probe's structured output rides `tracing`/`tracing-subscriber` JSON (arch §Stack — Self-observation, detail delegated to obs-plan §3), landing at `logs/agent-latest.jsonl` in agent mode (§Occupied Resources — On-disk artifacts).
- **arch ↔ tests:** headless-as-release-gate plus `.sh`/`.ps1` harness parity (§Cross-cutting Patterns — Development Style) binds the test plan's harness legs; and because CI has no Pulse instance (§Established Decisions [CI/CD]), a probe reporting *absent* must not itself red a CI job.
- **arch ↔ the run contract artifact:** `contracts/pulse-run-contract.toml` is an arch-registered resource whose `[[term]]` shape (`{id, statement, check, env?, causes}`) is the existing declaration surface for launch preconditions — any new precondition vocabulary this chunk introduces has to reconcile with it (§Occupied Resources).

## Acceptance criteria contributions
- (arch) Probe code lives in an existing locked workspace member with no new cross-seam dependency edge; no new workspace crate unless declared as a module seam (per architecture.md §Occupied Resources — Crate names / §Established Decisions [Module Boundaries]).
- (arch) The probe binds no port and emits no OTLP: `:4317` is contacted as a client only, `:4318` untouched, and the shipped binaries gain no inbound listener (per architecture.md §Occupied Resources — Ports / §Cross-cutting Patterns — Trust boundary).
- (arch) The probe produces no `Verdict`/`ReportState` and no `Blocked` row; an unanswerable subject surfaces as a harness `Result::Err` (typed in its seam, `anyhow` only at the CLI edge) (per architecture.md §Cross-cutting Patterns — Verdict/error wall / §Conventions — Error handling).
- (arch) No env handle is added outside the reserved `CONDUCTOR_*` namespace, the `ANDROMEDA_PULSE_*` trio is read and never written, and probe output is host-path-free with instants in colon-delimited RFC-3339 (per architecture.md §Occupied Resources — Environment variables / §Standard Contracts — Timestamp formats).
