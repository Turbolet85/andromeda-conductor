## Relevance
Partial — cli surface only (a probe verb and/or `agent-run` harness output shape); no desktop-webview element falls in this chunk's scope.

## Constraints
- Any new probe surface must fit the cli verb structure: verb-noun via clap, flat one level deep, help verb-prefixed, and registered in the verb table alongside `run`/`suite`/`report`/`preflight`/`coverage` (per layout-templates.md §Surface: cli — Component — Primary navigation (verb structure) + §Surface: cli — Primary screens (commands)). Note the plan documents **five** verbs plus the harness while the scope's HEAD read of `cli.rs:20` names four — whether the shipped `Commands` enum already carries `Coverage` is research's question.
- cli output structure is a parsed contract: layout-templates.md §Surface: cli — IA notes (Command model) requires output shape stay stable across versions because downstream agents parse it, and treats adding a `comfy-table` column without a `--format` flag as a breaking change. A machine-readable probe result therefore owes the `[--json]` precedent shape documented for `conductor preflight` (§cli Primary screens): a typed JSON payload **or** a single bracket-prefixed line, with readiness encoded in the exit code.
- Every status signal must be paired with an always-printed ASCII prefix so it is never color-alone and survives `NO_COLOR` / piping / `TERM=dumb` / screen readers; ANSI routes through `anstream` and auto-strips when not a TTY; no emoji in machine-parseable output (per layout-templates.md §Surface: cli — Signature placement closing rule + §cli IA notes (Pipe discipline)).
- The per-P-ID bracket label set is **closed at six** (`[PASS]`/`[HOLD]`/`[FAIL]`/`[MANUAL]`/`[RESIDUAL]`/`[BLOCKED]`) and the lamp set is closed at six with `ReportState` unextended; a fact that qualifies the *run* rather than reporting a check rides **outside the lamp column** as a non-lamp qualifier (per layout-templates.md §Surface: cli — Component — Primary content block 2). A harness-side probe result is that class, so it must not become a seventh label/lamp. Correspondingly, on the webview a capability no run record names renders the "Not yet run" absence prose distinguished by TEXT, not tint (§desktop-webview Component — Primary content block 1) — the probe must not drive a lamp there.
- stdout is reserved for raw artifact data and stderr for human messages, never mixed without intention; errors take the form `error: <short>` + contextual detail + `hint: <fix>`, sanitized with no absolute host paths, no internal struct names, no stack traces (traces only under `--debug`/`-v`), paths un-colorized when piped (per layout-templates.md §Surface: cli — Component — Footer / terminator + error output). The scope's "name a `PATH` miss without echoing the `PATH`" sits inside this mandate.
- Headless invariant: interactive `inquire` prompts must check `isatty` first and the agent-driven source-of-truth path must **never** be gated on a prompt (per layout-templates.md §Surface: cli — IA notes (Headless invariant) + §cli Component — Hero / signature output). A probe placed on the harness path must add no interactive gate.
- If the probe rides `scripts/agent-run.{sh,ps1}`, both shells must ship at **identical semantics**, and an absent Conductor-owned handle is expected to skip at **exit 0** with a host-path-free `error:`/`hint:` precondition rather than hard-fail (per layout-templates.md §Surface: cli — Primary screens, the `agent-run` harness bullet).

## Patterns to follow
- The `--e2e` driver-handle guard shape (§cli Primary screens, harness bullet): a missing Conductor-owned handle → stage skipped at exit 0 + host-path-free `error:`/`hint:` precondition, never a hard failure. This is the closest existing precedent for "absent SUT named once."
- The `conductor preflight [--json]` output/exit shape (§cli Primary screens): `ReadyState` JSON or one bracketed line, exit 0 iff ready. Reuse the **shape**, not the mechanism — the chunk's boundary forbids being or invoking preflight.
- The run-level non-lamp qualifier (`[ENVIRONMENT-SUSPECT]`, §cli Output structure `conductor run <scenario>` + §cli Component — Primary content block 2): printed once per run, above/outside the verdict lines it qualifies, ASCII bracket always printed, reusing an existing recessive mapping rather than a new entry, and **omitted entirely** when not applicable.
- The `not-conductors` Mode-cell precedent (§desktop-webview Component — Primary content block 1; §cli Primary screens `coverage` roll-up): a remit/precondition fact takes a recessive treatment with an always-rendered label and no new token, ANSI entry, column or lamp — deliberately not `status-fail`/`count-blocked`.
- Header printed once per command, never an always-on banner: `CONDUCTOR` + verb + subject + metadata dimmed, followed by a gate line carrying an `[OK]`/`[BLOCKED]` prefix so it reads without color (§cli Component — Header / banner).

## Anti-patterns to avoid
- Minting a new bracket label, lamp state or `ReportState` for a probe fact — the per-P-ID set and the lamp set are closed (§cli Component — Primary content block 2; §desktop-webview Component — Primary content block 2). Explicitly banned corollary: no `[BLOCKED]` per-P-ID row for a scenario that was never run.
- Reusing any lamp-set token/ANSI (`status-fail` ↔ 203, `count-blocked` ↔ 60) for a non-outcome fact, or letting tint be the only signal — the ruling rests on the lamp-token SET, not on a hex coincidence (§desktop-webview Component — Primary content block 1, Mode-cell treatment).
- Baking derived counts or command literals into documented sample output, and adding a column to an existing table shape without a `--format` flag (§cli IA notes (Command model); the de-literalization rule established across the coverage roll-up amendments).

## Contract bindings
- **layouts ↔ security:** the sanitized `error:`/`hint:` stderr shape and host-path-free artifact output are stated here as layout invariants only; the threat model, tracing field allowlist and `anyhow`-edge sanitization belong to security-plan (§cli Component — Footer / terminator + error output; §desktop-webview IA notes "Security guardrails honored at the layout level").
- **layouts ↔ a11y / NO_COLOR:** "status never color-alone, ASCII prefix always printed" is stated here as a design requirement; a11y derives the concrete conformance (§cli Signature placement closing rule; §Decisions Log Notes).
- **layouts ↔ design-system:** status mappings are referenced by token name ↔ ANSI code only (`count-nominal` ↔ 114, `count-hold` ↔ 179, `status-fail` ↔ 203, `count-blocked` ↔ 60, `color-id-cyan` ↔ 117, journal-text ↔ 146); raw values live in design-system (§cli IA notes (Multi-surface coordination)).
- **layouts ↔ tests:** `.sh`/`.ps1` parity is mandated by test-plan §3 and surfaced here as a layout invariant of the harness bullet (§cli Primary screens).

## Acceptance criteria contributions
- (layouts) A probe surface, if it lands as a verb, appears in the flat verb-noun clap table with verb-prefixed help and does not nest below one level (per layout-templates.md §Surface: cli — Component — Primary navigation (verb structure)).
- (layouts) The probe emits no new per-P-ID bracket label, no seventh lamp and no `[BLOCKED]` row for an unrun scenario; any probe fact prints outside the lamp column with its ASCII label always rendered, and is omitted entirely when not applicable (per layout-templates.md §Surface: cli — Component — Primary content block 2).
- (layouts) Probe precondition messages go to stderr as `error: <short>` + detail + `hint: <fix>`, contain no absolute host path, no internal struct name and no stack trace, and never echo the `PATH`; stdout carries only parseable data with ANSI stripped when piped (per layout-templates.md §Surface: cli — Component — Footer / terminator + error output + §cli IA notes (Pipe discipline)).
- (layouts) On the harness path the probe adds no interactive prompt and, where it guards a leg, an absent handle skips at exit 0 with `.sh`/`.ps1` at identical semantics (per layout-templates.md §Surface: cli — Primary screens (agent-run bullet) + §cli IA notes (Headless invariant)). Whether the shipped harness already prints such a precondition for a missing `andromeda-pulse-mcp` is research's question.
