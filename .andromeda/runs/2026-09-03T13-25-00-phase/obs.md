# obs extract

## Relevance
Relevant — the chunk's deliverable is a Conductor-generated telemetry artifact plus new boundary instrumentation at the `:4317` / MCP-spawn / env-handle seams, all governed by the obs plan.

## Constraints
- Self-observation is structured `tracing` JSON only: the probe must not initialize an OTel SDK, must not export self-obs OTLP anywhere, and specifically not to `:4317` (the PRODUCT fault stream) or `:4318` (dead port) — subject 1's connectability check is a client-side connect, never an export or a bind (per obs-plan.md §3 OTel SDK init + §3 Correlation, §11 Universal bans).
- Probe output rides the existing self-obs stream in its existing shape: one JSON object per line, `jq`/`serde_json`-parseable, carrying the §3 self-obs base set (`timestamp_ms`, `level`, `target`, `service.name`/`service.version`/`deployment.environment`, `run_id`); sink is stderr in non-agent mode and `logs/agent-latest.jsonl` under `--agent-mode` — a WRITER switch, never a format switch (per obs-plan.md §3 Log format JSON schema + §3 Logging stack, §6 Sink configuration). Whether a scheduling-time probe can carry `run_id` at all, given §11's "never skip the `run_id` field" ban, is research's question.
- The probe must emit neither of the two report-seam record shapes — not the eleven-field Run-report envelope nor the per-check `CheckRecord` — since both are written by the report seam on scenario-result events; this is the obs-side reading of the scope's "Not a verdict" boundary (per obs-plan.md §3 Log format JSON schema, "two record shapes").
- Any span the probe opens must be `{module}.{operation}`, low-cardinality, and a member of §11's bounded span-name set (`scenario.run` · `timeline.execute*` · `emit.batch` · `emit.logs_batch` · `verify.readback*` · `report.generate` · `db.insert_run` · `fault.silence`/`ramp`/`port_occupier` · `tauri.command.*`) — no probe name exists in that set today, so either a conforming member is added by amendment or the §6 boundary-call `info!` route is taken; wildcard widening is banned (per obs-plan.md §11 Spans / Traces).
- A span attribute must be a name in `conductor-core::redact::ALLOWLISTED_FIELDS` or the processor stage drops it, emitting nothing; non-allowlisted facts (resolved program name, env-handle names, outcome text) ride the allowlisted `message` field (per obs-plan.md §4 Known-residual Required-span-attributes constraint + §6 Boundary-call wrappers). Whether `port` is allowlisted — it is `fault.port_occupier`'s attribute per §4 — is research's question.
- Artifact hygiene is processor-stage redaction, not sink-stage: absolute host FILE paths (drive-letter, `/home`, `/Users`, `%APPDATA%`, `~/.cargo`, `.rustup`, backtrace paths) mask to `<redacted>`; internal struct names are excluded by the field-name allowlist plus `Display`-not-`Debug` at the `anyhow` edge; the allowlisted `target` module path is preserved. The inherited `PATH` value is a host-path-bearing string and falls under this ban — the scope's "a `PATH` miss must be named without echoing the `PATH`" is the same requirement (per obs-plan.md §11 PII Scrubbing + §9 Log conformance check).
- Level discipline: an absent precondition is a `warn` (recoverable / degraded), boundary-call summaries and state transitions are `info`, and `error` is reserved for panic capture and unrecoverable harness faults; a probe that cannot answer must return a typed value with a structured line, never panic, with `std::panic::set_hook()` + one-line-serialized backtrace as the floor (per obs-plan.md §6 Log levels mapping, §10 Zero unlogged panics, §11 Error Reporting).

## Patterns to follow
- The §6 boundary-call wrapper shape for MCP-adjacent facts: the bounded `verify.readback.call_tool` span with the allowlisted `mcp_tool` attribute, plus tool name / `latency_ms` / error / observed result key-set (names only, never values) on `message` — and its off-run-path precedent, the first `mark_incident_resolved` caller which reuses that same span rather than minting a new one (per obs-plan.md §6 Boundary-call wrappers, MCP lifecycle WRITE bullet).
- The DB-READ convention as the "new boundary without a new span name" template: an `info!` carrying `run_id` plus the outcome on the allowlisted `message` field, inside the caller's existing span, minting no new `db.*` span (per obs-plan.md §6 Boundary-call wrappers, DB READ bullet).
- `fault.port_occupier`'s attribute discipline as the closest existing port-bearing shape: attributes exactly `fault_type` + `port`, with the realized outcome witnessed on `message` because the layer records attributes on the `new` record only (per obs-plan.md §4 Fault-injection spans). Note the occupier BINDS; the probe is a connect-only client per scope.
- Bootstrap order and mode trigger: the single `JsonObsLayer`-over-every-writer subscriber must be installed before any probe logic, and agent mode is the read-only `flag || env-set` trigger Conductor never writes — load-bearing if the probe rides `scripts/agent-run.{sh,ps1}` (per obs-plan.md §3 Logging init instead + §3 Agent-mode flag).
- Wall-clock only for any timing the probe records: `std::time::SystemTime`/`Instant`, never tokio's virtual clock (per obs-plan.md §11 Project-specific bans).

## Anti-patterns to avoid
- Never introduce an OTel SDK/exporter or any network OTLP for self-observation while instrumenting the `:4317` subject — recursion guard plus `current_thread` determinism (per obs-plan.md §11 Telemetry Strategy + §11 Universal).
- Never emit unstructured stderr text for the probe result, and never leak an absolute host path, the inherited `PATH`, or an internal struct name into the probe's artifact (per obs-plan.md §11 Logs + §11 PII Scrubbing).
- Never add a high-cardinality span name (e.g. per-endpoint, per-resolved-path) and never widen the bounded set with a wildcard to accommodate the probe (per obs-plan.md §11 Spans / Traces).

## Contract bindings
- **obs ↔ tests:** the JSONL log format is OWNED by test-plan §3 and obs derives from it (per obs-plan.md §3 Observability Harness Contract / Log format JSON schema). If the probe needs a record shape beyond the self-obs line, that is a lateral bind requiring the owner side, not an obs-local addition — the "two record shapes" split is the current contract.
- **obs ↔ security:** the sidecar-spawn ban (fixed hard-coded program NAME resolved through the inherited `PATH`, `.env(...)` never argv, and "never with a visible console window") is the same surface subject 2 probes; obs-plan.md §11 Project-specific bans + §11 PII Scrubbing record a MEASURED host-path channel outside the three redaction application sites, whose `CREATE_NO_WINDOW`-class fix is route-owned and not shipped (the scope puts that defect out of scope, so the probe must not itself open that channel).
- **obs ↔ CI:** probe lines land in `logs/agent-latest.jsonl`, which §9 uploads as a CI artifact and gates twice — the base-schema conformance check and the zero-unlogged-panics grep for `^thread.*panicked` (per obs-plan.md §9 CI Integration).

## Acceptance criteria contributions
- (obs) Every probe log line is a single-line JSON object carrying the self-obs base set (`timestamp_ms`, `level`, `target`, `service.name`, `service.version`, `deployment.environment`) and parses with `jq`/`serde_json`; no unstructured stderr text on any probe path (per obs-plan.md §3 Log format JSON schema)
- (obs) No probe output field contains an absolute host path or the inherited `PATH` value — drive-letter / `/home` / `/Users` / `%APPDATA%` / `~/.cargo` / `.rustup` anchors masked at the processor stage; an `andromeda-pulse-mcp` resolution miss is named without echoing `PATH` (per obs-plan.md §11 PII Scrubbing)
- (obs) Any span the probe opens is a member of the bounded span-name set (added by amendment if new, never by wildcard) with attributes restricted to `redact::ALLOWLISTED_FIELDS` names; every other fact rides the `message` field (per obs-plan.md §11 Spans / Traces)
- (obs) A probe that cannot answer yields a typed value plus a structured `warn`/`error` line — zero unlogged panics, no `^thread.*panicked` line in `logs/agent-latest.jsonl` or stderr, and no Run-report envelope or `CheckRecord` row minted for an unrun scenario (per obs-plan.md §10 SLO Invariants, Zero unlogged panics)
