# security extract

## Relevance
Relevant — the chunk touches four security surfaces the plan governs: the sidecar's `PATH` spawn-resolution input, the `ANDROMEDA_PULSE_*` handle set, the `:4317` trust-boundary bind claim, and artifact-hygiene/verdict-wall sanitization of a new operator-visible output.

## Constraints
- **Trust boundary unchanged — connect, never bind.** `security-plan.md` §Threat Model Summary (Attack surface: the `:4317` port-bind "single deliberate exception") and §Security Anti-Patterns → Universal require that no *shipped* Conductor binary gain an inbound listener of its own, with `conductor-faults`' occupier remaining the sole deliberate bind; subject 1 must therefore be a client-side connectability check. §Security Anti-Patterns → API separately bans promoting that occupier bind into a general-purpose listener.
- **Sidecar resolvability must probe the FIXED program name.** §Security Anti-Patterns → Input requires the sidecar be spawned as a fixed, hard-coded program NAME resolved through the inherited `PATH`, never a config-derived or operator-supplied command string, and names `PATH` itself as the spawn-resolution input. The same section records the measured failure this chunk repays: a `PATH` entry split on a drive-letter colon resolved the sidecar nowhere and the run reported `[BLOCKED]` in ~0 s, indistinguishable at row level from a genuine SUT-side gate failure.
- **Report the `ANDROMEDA_PULSE_*` handles' declared-ness, not their values.** Per §Input Validation: `ANDROMEDA_PULSE_L4_DETERMINISTIC` is a declaration-only read whose value must never become a path, an argv element, or a log value, and whose absence must surface as an unmet contract term naming both candidate causes and **never as a claimed measurement of `pulse-app`** (Conductor launches no Pulse process and cannot inspect one); `ANDROMEDA_PULSE_DATA_DIR` requires argument-injection-metacharacter rejection and must travel only through the `.env(...)` builder; `ANDROMEDA_PULSE_MCP_ENABLED` must be present in Conductor's own process environment (inheritance is the sole channel to the sidecar) and Conductor must never set it itself (§Threat Model Summary — Auth model Reason).
- **Artifact hygiene at the new output edge.** §Error Handling requires the `anyhow`/`conductor-cli`-stderr and `#[tauri::command]` edges to surface no absolute filesystem paths, internal seam-crate struct names, or stack traces, and §Error Handling (Run-report artifact sanitization) extends this to written artifacts. §Input Validation's committed-manifest row adds the specific form for read faults: carry `e.kind()` only, never the path. A `PATH` miss must therefore be named without echoing `PATH`.
- **Verdict/error wall — a probe result is not a verification outcome.** §Error Handling keeps `Result::Err` strictly for harness faults and verification outcomes as typed `Ok(...)` values; §Security Anti-Patterns → Universal reserves `blocked` for the preflight gate's FIVE named preconditions, each carrying its own distinct precondition string, and forbids blocking on a term whose truth lives on the SUT's side (recorded `declared-not-observable` instead, because blocking would assert a measurement Conductor cannot make). A probe must not mint a `blocked` row for a scenario that was never run.
- **Any new `CONDUCTOR_*` handle picks up its class's rule.** §Input Validation + §Security Anti-Patterns → Input require `std::fs::canonicalize` + type/existence bounds-check at the `conductor-cli` edge for every path handle a *shipped* binary reads (these sit outside garde); non-path string labels and boolean triggers require no validation. The committed-manifest precedent is deliberately **no** `CONDUCTOR_*` override handle, so a fixed path stays non-operator-steerable — the same discipline as the occupier port being a private builder parameter rather than a config field.
- **Dependency delta under the standing red audit.** §Dependency Security requires that a dependency added while the advisory-DATABASE fault persists land only on `cargo deny check advisories bans licenses sources` **verified** green over the NEW `Cargo.lock` (never assumed), and that "no dependency delta" stop being cited as the deferral basis once one lands. §Security Anti-Patterns → Universal bans the release gate without audit/deny green.

## Patterns to follow
- **Non-mutating egress probe as `Result::Err`, not a verdict** — §Threat Model Summary (OTLP/gRPC egress vector) states a refused transport surfaces as a harness fault, not a verdict; scope names `crates/conductor-emit/src/client.rs:42` (`probe_egress`) as the existing shape to reuse. Whether that helper's error path already withholds host/endpoint detail per §Error Handling is research's question.
- **Fixed-path, no-override resolution with `e.kind()`-only read faults** — the `default_path()` → `resolve_under` pattern of the committed SUT-facing manifests (§Input Validation) is the model for any fixed resource the probe reads.
- **`resolve_under` + `sanitize_error` edge** — §Input Validation's `#[tauri::command]` row is the pattern if the probe ever crosses the IPC edge (reject absolute/`..`, never clamp; every `Err` through `sanitize_error`; app-defined commands are not capability-ACL-gated, so this row is their boundary).
- **One composed precondition string naming each unmet condition AND its candidate causes**, with SUT-side truths recorded `declared-not-observable` (§Security Anti-Patterns → Universal) — the existing vocabulary for reporting a subject Conductor cannot measure, in place of inventing a new blocking state.
- **Host-path scrub + hygiene grep pair** — §Input Validation's speech-log ingest row establishes the scrub (drive-letter / `%APPDATA%` / `/Users` / `/home` → `<host-path>`, row gaining a `security_finding`) and the gate-1 hygiene grep over the committed record; reuse both if the probe writes a committed artifact.

## Anti-patterns to avoid
- **Never let the probe bind.** No inbound listener of Conductor's own in a shipped binary; no promotion of the `:4317` occupier bind into a general-purpose listener (per security-plan.md §Security Anti-Patterns → Universal, → API).
- **Never echo the environment into output.** No `PATH` contents, no absolute host path, no `ANDROMEDA_PULSE_DATA_DIR` value, no internal seam-crate struct name on `conductor-cli` stderr, in a `#[tauri::command]` return, or in any artifact (per §Security Anti-Patterns → Logging, §Error Handling).
- **Never test resolvability by spawning an operator-chosen command**, and never interpolate an operator-supplied value into the sidecar's argv or a shell string (per §Security Anti-Patterns → Input, → Code Patterns rule (a)). If any spawn occurs at all, rule (a)'s console-window-suppression duty applies — the plan records a flagless `Command::new(PULSE_MCP_PROGRAM)` as publishing the sidecar's absolute exe path as a foreground pane title, a host-path disclosure channel outside the `sanitize_error`/artifact-hygiene edges (measured 2026-09-02, recorded as a routed defect, **not** as a shipped control; whether HEAD carries the flag is research's question).

## Contract bindings
- **Artifact hygiene ↔ obs**: §Error Handling supplies the sanitization rule; the scope's "tracing field allowlist" is the obs-plan-owned mechanism that must carry it for any probe log/field emission.
- **Hygiene grep ↔ tests**: the gate-style grep asserting no host path / seam-crate struct name in the probe's output is a tests-harness gate consuming this domain's rule (precedent: the speech-log gate-1/gate-2 pair, §Input Validation).
- **CI security gate ↔ tests §CI Integration**: §Dependency Security requires `cargo audit` (+ `cargo deny check advisories bans licenses sources`) as a job in the single existing workflow — not a second pipeline.
- **Shell parity ↔ arch/harness scripts**: if the probe reads any contract-derived budget in `scripts/agent-run.{sh,ps1}`, §Input Validation's committed-manifest row binds the shell readers to the same never-defaulted rule (missing term ⇒ hard exit 2) and the clamp-**up**-to-the-contract-floor behaviour, in both shells.

## Acceptance criteria contributions
- (security) The probe's operator-visible output and any artifact it writes contain no absolute host path (no drive-letter / `%APPDATA%` / `/Users` / `/home` token), no `PATH` contents, no internal seam-crate struct name and no stack trace; a `PATH` miss and an absent `ANDROMEDA_PULSE_*` declaration are named by handle only (per security-plan.md §Error Handling · §Security Anti-Patterns → Logging).
- (security) No shipped binary gains a bind: the `:4317` subject is a client-side connect only, and `conductor-faults`' occupier remains the sole deliberate bind in `conductor-cli` / `conductor-tauri` (per security-plan.md §Threat Model Summary — Attack surface · §Security Anti-Patterns → Universal).
- (security) The sidecar-resolvability subject resolves the fixed compile-time program NAME through the inherited `PATH` — no operator-supplied or config-derived command string, no operator value in argv or a shell string, `.env(...)` the only channel for `ANDROMEDA_PULSE_DATA_DIR` (per security-plan.md §Security Anti-Patterns → Input · → Code Patterns rule (a)).
- (security) A probe that cannot answer yields a harness fault, never a `Verdict`/`ReportState` and never a `blocked` row; the preflight gate's five named preconditions remain the sole producers of `blocked` (per security-plan.md §Error Handling · §Security Anti-Patterns → Universal).
