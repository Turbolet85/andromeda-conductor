## Constraints
- Focus order must follow the visible top-to-bottom source order the console wireframe fixes — titlebar zones first (phase line · count · window controls), then the control row (picker / Start / Stop), then the coverage matrix, then the run report; every interactive control carries a visible `color-focus` ring and every hover affordance a keyboard equivalent (per layout-templates.md §Wireframe — Run console (idle), §Component — Primary navigation). Finding 1's fix must land inside that order rather than re-ordering regions. Whether initial focus currently lands in the picker ahead of the titlebar controls is research's question.
- The titlebar is three fixed zones with a **closed set of four** phase-line labels (`Conductor · idle` / `live` / `HOLD — operator pause` / `aborted`, never the segment name), the count centered in Display role with tabular figures as the signature freeze (per layout-templates.md §Component — Header, §Primary screens). Finding 7's labeling and finding 8's terminal-state correction must stay inside that zone layout and label set.
- The dialog's focus restoration is **contract-borne, not Radix-supplied**: layout-templates.md §Component — Hero / signature section requires a `restoreFocusTo` accessor restoring in `onCloseAutoFocus` (the Channel-opened dialog has no Radix `Trigger`), with the invoking control kept focusable via `aria-disabled` and never the native `disabled` attribute. Finding 3's fix is bound to this contract.
- The HOLD flip and every verdict / report-state change are required to be announced; layouts states *what* must be announced and defers politeness and attributes to a11y (per layout-templates.md §Component — Header, §Primary content block 2). Findings 3 and 4 sit exactly on that seam.
- The coverage matrix is a dense single-row-per-P-ID virtual-scroll list with a **four-cell** row (P-ID · Capability · Mode · Status, lamp last; `slo_tier`/`latency_ms` deliberately absent), and the run report is a `color-raised-1` card of per-P-ID verdict lines under an optional run-level envelope banner (per layout-templates.md §Component — Primary content block 1, §Component — Primary content block 2). Finding 2's scroll-region fix must not restructure either region.
- Empty and absence states are **prose, never placeholders**: the shipped `No scenarios found.` for the picker/matrix empty, `No run yet` for the report, and a never-run capability rendering "Not yet run" text distinguished by TEXT not tint (per layout-templates.md §Component — Primary content block 1 States, §Component — Primary content block 2). Finding 6's filter-miss prose must remain rendered text inside the picker's list region.
- Single-station surface: no router, no routes, no breakpoints, no deep links; `alert()`/`confirm()`/`prompt()` are never used and the styled `AlertDialog` is the only modal (per layout-templates.md §IA notes, §Decisions Log). No route-level focus reset or responsive work is available as a remedy path.

## Patterns to follow
- Signature-echo placement — the frozen count is named at three sites (titlebar center · dialog header · matrix header strip). Any labeling/announcement work on the count must preserve all three echoes (§Component — Header, §Component — Hero, §Component — Primary content block 1).
- `border-emphasis` selection edge — the active picker item and the selected matrix row both carry a visible edge so selection is never color-only; finding 5's `aria-current` / ` · selected` work rides this existing visible-plus-text pattern (§Component — Primary navigation, §Component — Primary content block 1).
- Sibling-not-nested projection inside the dialog — checklist rows render as a sibling of `Description`, never nested, because `Description` is the described-by target (§Component — Hero). Any content added to the dialog while fixing finding 3 follows the same placement rule.
- Status text always paired with its tint/glyph across surfaces, adapted never forked (§Component — Primary content block 2, §Decisions Log cross-surface IA) — the pattern any new terminal-state text for finding 8 must follow.
- Designed-not-shipped markers — the footer status strip is recorded as designed but **not** shipped (landmark set banner + main + two regions), so no `contentinfo` landmark exists to host a roll-up or status text (§Component — Footer).

## Anti-patterns to avoid
- Restructuring the coverage matrix into a KPI-card grid or re-adding measurement columns while making its scroll region readable — the card grid is an explicit Rejected Default (§Component — Primary content block 1).
- Minting a fifth titlebar phase-line label, a seventh lamp, or a sixth `ReportState` to express a "done/complete" run — the lamp set is closed at six and run-level qualifiers ride outside the lamp column (§Primary screens, §Component — Primary content block 2).
- Replacing an empty/absence state with a gray skeleton or placeholder, or reaching for `alert()`/`confirm()`/`prompt()` (§Component — Primary content block 1 States, §IA notes).

## Acceptance criteria contributions
- Focus order matches the wireframe's visible order — titlebar controls are reachable before the picker/Start/Stop control row, then matrix, then report; no region re-ordering (per layout-templates.md §Wireframe — Run console (idle) / §Component — Primary navigation).
