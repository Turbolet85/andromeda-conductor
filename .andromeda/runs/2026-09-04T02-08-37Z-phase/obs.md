## Relevance

## Constraints
- The self-obs line schema is fixed: every `tracing` line must carry `timestamp_ms` (epoch millis from `std::time::SystemTime`), `level`, `target`, `service.name`/`service.version`/`deployment.environment`, and `run_id` — and is a DIFFERENT record shape from the eleven-field Run-report envelope. A finding-8 fix in `conductor-run` may not add fields to the envelope, whose format is owned by test-plan §3 and reproduced (not authored) here (per obs-plan.md §3 Log format JSON schema, two record shapes).
- The Run-report envelope's `state` is a closed enum (`Pass | Fail | ManualCheck | KnownResidual | Blocked`) and `verdict` (`Pass | Fail | CalibrationRegion`); the UI's `aborted`/`idle`/`Done` phase vocabulary is not envelope vocabulary, so reconciling the finding-8 divergence must not introduce a new envelope state (per obs-plan.md §3 Log format JSON schema / §6 Log Coverage required fields).
- Any Tauri IPC surface the fix touches must open a MANUAL `tracing::info_span!("tauri.command.<name>").entered()` guard — the `#[tracing::instrument]` attribute does not stack with `#[tauri::command]` — and the name must fall inside the bounded `tauri.command.*` set; §1 enumerates EIGHT handlers as the measured target (`list_scenarios`, `coverage_matrix`, `unbacked_auto`, `run_report`, `run_envelope`, `start_run`, `stop_run`, `resolve_operator_hold`) (per obs-plan.md §4 auto-instrumentation table + §1 desktop-webview row + §11 Spans/Traces bounded set).
- Frontend changes (App.tsx, Titlebar live-region politeness, ScenarioPicker prose) may log ONLY `console.log(JSON…)` — no OTel JS SDK, no browser OTLP exporter, no `:4318` (per obs-plan.md §1 desktop-webview surface row + §11 Universal "NEVER export any self-observation OTLP").
- The `sr*` re-run's Tauri backend sink is `<runs_dir.parent()>/logs/conductor-tauri.jsonl` — file NAME fixed, DIRECTORY rides `CONDUCTOR_RUNS_DIR` (measured landing sites `runs/logs/`, `runs/sr-leg/logs/`, `runs/driven/logs/`); the file sink is unconditional with stderr only as an open-failure fallback (per obs-plan.md §3 Log file location + §3 Logging stack sinks).
- No log line, run-report artifact, or committed evidence JSON may carry an absolute host-file path (drive-letter, `/home`, `/Users`, `%APPDATA%`, `~/.cargo`, `.rustup`, backtrace file paths) or an internal struct name; redaction is single-location in `conductor-core::redact` and applies at the PROCESSOR stage, never only at the sink (per obs-plan.md §11 PII Scrubbing + §11 Logs).
- The abort path must not panic and must not go unlogged: panic capture is `std::panic::set_hook()` + `tracing::error!` + `anyhow` edge bridging, and a malformed/aborted transport outcome resolves to a typed value, never a panic (per obs-plan.md §10 Always-required SLO invariant + §11 Error Reporting).

## Patterns to follow
- Run-path state transitions (run start, verdict classification) log at `info`; internal control flow at `debug`; a recoverable/degraded condition at `warn` — the level table §6 is the mapping the finding-8 abort/settle transition should follow (per obs-plan.md §6 Log levels mapping).
- Boundary-call wrapper pattern: `db.insert_run` logs row count + `run_id` + `verdict` + `state` in its span; a rusqlite READ inside a `tauri.command.*` span logs an `info!` carrying `run_id` plus the outcome on the allowlisted `message` field and mints NO `db.*` read span (per obs-plan.md §6 Boundary-call wrappers).
- Detail that has no allowlisted field name rides the `message` field rather than a new span attribute — a span attribute must be a name in `conductor-core::redact::ALLOWLISTED_FIELDS` or the processor stage drops it silently (per obs-plan.md §4 Known-residual Required-span-attributes note + §6 Boundary-call wrappers).
- `report.generate` / `db.insert_run` are run-scoped SIBLINGS of the `scenario.run` root, correlated by `run_id`, because `persist` is called alongside `execute_scenario` at every production site including `drive_run` — relevant to reading finding 8's `Done`-vs-`aborted` divergence (per obs-plan.md §4 Critical Path 1 Cleanup).
- All obs artifacts are agent-parseable via `jq`/`serde_json`, paste-to-AI; no human-only dashboard is an acceptable consumption path for the leg's evidence (per obs-plan.md §2 Agent-readable invariants + §3 Snapshot / paste-to-AI integration).

## Anti-patterns to avoid
- NEVER widen the bounded span-name set or mint a high-cardinality span name (e.g. per-row, per-finding, per-scenario-name span) for the leg or the abort fix (per obs-plan.md §11 Spans / Traces).
- NEVER emit unstructured stderr text or a multi-line panic backtrace from the run driver or the leg harness — structured JSON-per-line only, backtrace serialized to a single field (per obs-plan.md §11 Logs).
- NEVER introduce an OTel SDK, `tracing-opentelemetry`, W3C `traceparent`, or any network OTLP for self-observation on either surface (per obs-plan.md §11 Telemetry Strategy + §11 Universal).
