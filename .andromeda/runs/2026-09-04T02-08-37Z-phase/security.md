## Constraints
- The screen-reader speech-log ingest is a registered **untrusted third-party text** boundary: spec-id cross-check, closed `outcome`/`arm`/`review_grade` sets, `heard` bounded at 400 chars, and a mandatory host-path scrub (drive-letter / `%APPDATA%` / `/Users` / `/home` → `<host-path>`, row gaining a `security_finding`), with the raw log staying under gitignored `runs/` (per security-plan.md §Input Validation, speech-log ingest row). The chunk's in-scope parser extension — surfacing `tabsToStart` into the committed record — must land **inside** `writeNvdaPass`'s scrub/bound path, not beside it. Whether the current parser applies the scrub per-field or only to `heard` (so that a new emitted field would bypass it) is research's question.
- Committed evidence records — `evidence/nvda-pass.json` is named explicitly — must not carry absolute host paths or internal seam-crate struct names; they are agent-parseable ground truth shared across hosts and carry verdict/state/identity fields only (per security-plan.md §Security Anti-Patterns → Logging).
- Any `#[tauri::command]` argument the webview fixes touch or add (the `run_id`-class strings behind `run_report` / `run_envelope`) must resolve through `resolve_under` against the resolved runs dir **before any read** — an absolute candidate or `..` escape REJECTED, never clamped — with every returned `Err` crossing the edge through `sanitize_error`, and an unknown id being an absence (`Ok(None)` / empty list), never a panic. App-defined commands are NOT capability-ACL-gated, so this row, not the capabilities file, governs them (per security-plan.md §Input Validation, Tauri IPC row).
- If CARRY 2b lands (`SendInput`/`SendKeys` from the leg's own process), it must take one of the four governed harness-spawn forms — none a shell string: a repo-derived resolved constant program, or a fixed OS program with a fixed argv (the PowerShell window-activation form is the closest template), or a guarded host-tool path as program. An operator-supplied value may appear only as a separate element of an **array-form** argv after existence + `isFile` + shell-metacharacter rejection, and never as the program except through that guarded form (per security-plan.md §Security Anti-Patterns → Code Patterns rule (b); §Input Validation `CONDUCTOR_NVDA` row).
- The standing `cargo audit` red is an **advisory-DATABASE fault, not a tool fault**: the remedy is a bounded wait re-checked each chunk with coverage kept by a `cargo deny check advisories bans licenses sources` **VERIFIED** green (verified, never assumed) — never a floor raise, never a `deny.toml` ignore, never a CI edit, never a silent accept (per security-plan.md §Dependency Security, two-fault split).
- If CARRY 2a lands a driver package (`@guidepup/guidepup` + `@guidepup/setup`), the npm tree is outside `cargo-audit`/`cargo-deny` remit: gate it with `npm audit --omit=dev` clean (0 PRODUCTION vulnerabilities) and a committed `package-lock.json`; dev-only transitive advisories in non-shipping test tooling are accepted at dev-tree grain (per security-plan.md §Dependency Security, Frontend (npm) supply chain). The cargo-side admission condition — a dependency delta may land under a red audit only on verified-green deny over the NEW lock — states the shape of the argument even where the delta is npm-only (per §Dependency Security, 2026-08-16 admission bullet).
- Finding 8's abort/`Done` reconciliation in `drive_run` must keep the verdict/error wall intact: verification outcomes stay typed values returned as `Ok(...)`, `Result::Err` stays reserved for harness faults, and `<run_id>.md` / `runs.db` rows record identity and verdict fields without absolute host paths or internal struct names (per security-plan.md §Error Handling, incl. run-report artifact sanitization).

## Patterns to follow
- The `UNSAFE_PATH` guard in `crates/conductor-tauri/ui/wdio.conf.ts` — existence + `isFile` + shell-metacharacter rejection before spawn, unset-or-not-a-file ⇒ the requesting leg SKIPS at exit 0 with a **host-path-free** precondition naming the handle, never its value (per security-plan.md §Input Validation, `CONDUCTOR_NVDA` / `CONDUCTOR_MSEDGEDRIVER` rows).
- `writeNvdaPass` in `test/a11y/screen-reader/parse-nvda-log.ts` as the single write point for the committed record — extend it for `tabsToStart` rather than emitting alongside it; its output is asserted by the leg's gate-1 hygiene grep (no host path / seam-crate struct name) and gate 2 (closed sets) (per security-plan.md §Input Validation, speech-log ingest row).
- The `resolve_under` + `sanitize_error` edge in `crates/conductor-tauri/src/commands.rs`, proven at the mock-runtime IPC tier (`tauri::test`) — the shape any command-surface change should preserve (per security-plan.md §Input Validation, Tauri IPC row).
- The fixed-program/fixed-argv activation spawn (`spawnSync('powershell.exe', ['-NoProfile', '-ExecutionPolicy', 'Bypass', '-File', <repo script>, '-Title', <constant>])`) — the template for a CARRY-2b key-injection step, with no operator input anywhere in the vector (per security-plan.md §Security Anti-Patterns → Code Patterns rule (b)).
- The justified-exception mechanisms (per-advisory `deny.toml` ignore / license allow on the cargo side; the `--omit=dev` dev-tree-grain accept on the npm side) as the documented route for a non-actionable advisory a new dev dependency drags in (per security-plan.md §Dependency Security).

## Anti-patterns to avoid
- NEVER let a committed evidence record (`nvda-pass.json` included) or a run-report artifact leak an absolute host path, a canonicalized `CONDUCTOR_*` directory, or an internal seam-crate struct name — this applies to every newly surfaced field, not only `heard` (per security-plan.md §Security Anti-Patterns → Logging).
- NEVER spawn a key-injection / activation / driver step through a shell string, an `eval` equivalent, or with an operator-supplied value as the program (per security-plan.md §Security Anti-Patterns → Code Patterns rule (b)).
- NEVER paper over the red `cargo audit` with a floor raise, a `deny.toml` ignore, or a CI edit — and NEVER treat the deny overlap as green without reading its exit directly (per security-plan.md §Dependency Security; §Security Anti-Patterns → Universal).

## Contract bindings
- **Speech-log scrub ↔ a11y + tests:** the security controls on the ingest are asserted by the leg's own gates — gate-1 hygiene grep and gate-2 closed sets — over rows whose `expected`/`tokens` this chunk tightens in `nvda-pass-spec.md` / `rows.ts`; a tightened row must not widen what the scrub permits into the committed record (security-plan.md §Input Validation, speech-log ingest row).
- **PREREQ probes ↔ the plan's `## Test Commands`:** both `cargo audit` and the `cargo deny check advisories bans licenses sources` overlap must appear there with their dispositions, or the deferral cannot be re-pinned at wrap (security-plan.md §Dependency Security).
- **CARRY-2a dependency fork ↔ test-plan §6:** the scope already binds the Guidepup weighing to both plans; the security side contributes only the npm gate + committed lockfile, not the adopt/decline decision (security-plan.md §Dependency Security, Frontend (npm) supply chain).
- **Sidecar console-window suppression (row S1-01) ↔ the NEXT route entry:** the plan records the flagless spawn's absolute-exe-path pane as a measured, route-owned defect; this chunk's scope excludes it, so the binding here is only that the scrub which caught it must not be weakened (security-plan.md §Security Anti-Patterns → Code Patterns rule (a)).

## Acceptance criteria contributions
- The committed `evidence/nvda-pass.json` re-generated by the `sr*` re-run — including any newly surfaced field such as `tabs_to_start` — contains no drive-letter / `%APPDATA%` / `/Users` / `/home` token and no seam-crate struct name; any scrubbed token appears as `<host-path>` with the row carrying `security_finding`, and `heard` stays within the 400-char bound with `outcome`/`arm`/`review_grade` inside their closed sets (per security-plan.md §Input Validation, speech-log ingest row; §Security Anti-Patterns → Logging).
- `cargo audit` and `cargo deny check advisories bans licenses sources` are both run with exits read DIRECTLY (never through a pipe) and recorded with dispositions; deny is green over the current lock, and any deviation from the pinned signature (`cargo audit` exit 1 / `duplicate advisory ID: RUSTSEC-2026-0244`; deny exit 0) restores the full form and is reported (per security-plan.md §Dependency Security).
- If any npm dependency lands (Guidepup or otherwise): `package-lock.json` is committed and `npm audit --omit=dev` reports 0 production vulnerabilities (per security-plan.md §Dependency Security, Frontend (npm) supply chain).
- Every spawn added or changed by the leg work is array-form with a fixed or repo-resolved program, no shell string, and any host-tool path used as a program passes the existence + `isFile` + shell-metacharacter guard first, skipping at exit 0 with a host-path-free message when unset (per security-plan.md §Security Anti-Patterns → Code Patterns rule (b); §Input Validation `CONDUCTOR_NVDA` row).
