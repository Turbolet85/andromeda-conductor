## Patterns to follow
- The **boolean-grade fact** pattern of `conductor_verify::sidecar_resolves_on_path()` — reads the environment, constructs no `Command`, returns a boolean, and never returns/logs/renders the resolved path (per security-plan.md §Security Anti-Patterns → Code Patterns (a) and §Input). This is the shape a presence check on a path-valued handle should take.
- `declares()` in `conductor-run` is the plan-named control for the READ SET, and `conductor_core::OBSERVED_HANDLES` is the plan-named enumeration (per security-plan.md §Input Validation, READ-SET row) — per-handle grading belongs at that observation site, with the enumeration unchanged.
- Read-fault hygiene precedent for fixed-path artifacts: faults carry `e.kind()` only, never the path (per security-plan.md §Input Validation, committed SUT-facing manifests row) — the same "identity, not value" discipline the finding text owes.
- The `sanitize_error` / artifact-hygiene edge: no absolute host path, no internal seam-crate struct name crossing to operator-visible surfaces or ground-truth artifacts (per security-plan.md §Error Handling; §Security Anti-Patterns → Logging).

## Anti-patterns to avoid
- NEVER let the data-dir **value** reach the probe's human output, `--json`, stderr, a log value, `&lt;run_id&gt;.md` / `runs.db` / JSONL, or a committed evidence record — absolute host paths are banned on all of those (per security-plan.md §Security Anti-Patterns → Logging; §Error Handling).
- NEVER loosen the predicate shared with `observe_run_contract` so a non-affirmative `ANDROMEDA_PULSE_L4_DETERMINISTIC` / `ANDROMEDA_PULSE_MCP_ENABLED` satisfies a `shell-declaration` term — that is a silent widening of a preflight gate (per security-plan.md §Security Anti-Patterns → Universal; §Input Validation).
- NEVER make the probe mutate state to become testable — no env write, no spawn on the observation path (per security-plan.md §Security Anti-Patterns → Universal).
