# obs extract

## Relevance
Partial — the chunk's logic is arch/tests-owned, but it newly makes a **PATH-valued** env handle load-bearing in a surfaced CLI finding and touches the `agent-run boot` arm that produces the agent-mode self-obs artifact, so §11 redaction, §11's bounded span-name set, §3's self-obs line schema and the §9 CI gate all apply.

## Constraints
- The `ANDROMEDA_PULSE_DATA_DIR` **value** is an absolute host path; obs-plan.md §11 (Logs · PII Scrubbing) requires that no absolute host-file path reach a log line, span attribute, run-report artifact or `runs.db` row — the redaction layer masks drive-letter / `/home` / `/Users` / `%APPDATA%` / `~/.cargo` / `.rustup` forms to `<redacted>`. A finding may carry the handle **name**; whether the shipped finding/`--json` shape already carries name-only (never the value) is research's question.
- obs-plan.md §11 (Spans / Traces) requires span names stay inside the bounded set (`scenario.run`, `timeline.execute*`, `emit.batch`, `emit.logs_batch`, `verify.readback*`, `report.generate`, `db.insert_run`, `fault.silence/ramp/port_occupier`, `tauri.command.*`). It contains **no** `preconditions.*` / `probe.*` / `boot.*` name — minting one requires a plan amendment, not an implementation decision.
- obs-plan.md §4 (Required span attributes heading) requires every span attribute name be a member of `conductor-core::redact::ALLOWLISTED_FIELDS`; the processor stage drops anything else, so a new attribute (`handle`, `declared_count`, …) would emit nothing. §6 (Boundary-call wrappers) establishes that such detail rides the allowlisted `message` field instead.
- obs-plan.md §3 (Log format JSON schema, two record shapes) requires every self-obs line carry the base set — `timestamp_ms`, `level`, `target`, `service.{name,version}`, `deployment.environment`, `run_id` — and §11 (Logs) bans skipping `run_id`. The probe runs **outside** a scenario, so whether the probe emits self-obs lines at all and what `run_id` they can carry is research's question.
- obs-plan.md §6 (Log levels mapping) reserves `error` for panics and unrecoverable harness faults; a subject graded unmet is a recoverable/expected outcome and belongs at `warn`-or-below, with boundary summaries and state transitions at `info`.
- obs-plan.md §10 (Zero unlogged panics) + §11 (Error Reporting) require the probe's env-read failure path exit through `std::panic::set_hook()` + `tracing::error!` + the sanitized `anyhow` binary edge (exit 1 + sanitized stderr), never a raw `thread … panicked` line or an unsanitized backtrace.
- obs-plan.md §2 (Agent-readable invariants) + §11 (Universal) require the probe's machine-consumed output stay agent-parseable (`jq` / `serde_json`); unstructured stderr text is not an acceptable carrier for any signal an agent or the `boot` arm reads.

## Patterns to follow
- **Read-only env trigger with presence semantics** — obs-plan.md §3 (Logging stack, agent-mode flag) specifies `agent_mode = flag || env-set`: a handle Conductor READS by presence and never WRITES, explicitly to avoid edition-2024 `unsafe std::env::set_var`. This is the plan's own precedent both for grading a handle by presence and for a test seam that does not mutate process env.
- **Boundary read logs, mints no span** — obs-plan.md §6 (Boundary-call wrappers, DB READ) records the convention that a read boundary emits an `info!` inside the **caller's** existing span carrying the outcome on `message`, deliberately without widening the bounded span-name set.
- **Detail on the allowlisted `message` field** — obs-plan.md §6 carries the MCP key-set witness, the `emit.batch` wire-shape witness and the incident id this way, precisely because a dedicated attribute outside `ALLOWLISTED_FIELDS` emits nothing.
- **Both-shell sink parity** — obs-plan.md §3 (Log file location) puts the CLI agent-mode sink at `logs/agent-latest.jsonl` relative to `CONDUCTOR_RUNS_DIR`; the `.sh`/`.ps1` `boot` arms must land on the same sink for the §9 gate to read one artifact.

## Anti-patterns to avoid
- NEVER leak an absolute host path — echoing the resolved `ANDROMEDA_PULSE_DATA_DIR` value into a log, span attribute, `--json` payload or test fixture output violates obs-plan.md §11 (Logs) and would trip the §9 conformance gate's own path patterns.
- NEVER use a span name outside the bounded set (obs-plan.md §11 Spans / Traces) — a `preconditions.observe`-shaped span is a plan amendment, not an implementation choice.
- NEVER emit unstructured stderr text as the probe's machine-read signal, and never drop `run_id` from a self-obs line (obs-plan.md §11 Logs).

## Contract bindings
- **obs ↔ tests (harness contract).** obs-plan.md §3 states the self-obs line format is owned by test-plan §3 (obs aligns to tests, not vice versa); any line this chunk's probe adds is a two-sided bind. The scope's `.sh`/`.ps1` parity requirement (test-plan §3) is obs-visible through the shared sink path in §3 Log file location.
- **obs ↔ CI (§9).** obs-plan.md §9 (Log conformance check + Zero-unlogged-panics gate) consumes `logs/agent-latest.jsonl` — the artifact `agent-run boot` produces in agent mode. A probe that short-circuits `exit 1` before the preflight starves that artifact of the preflight's lines; restoring reachability restores the gate's input.
- **obs ↔ security (logging & monitoring).** `ANDROMEDA_PULSE_DATA_DIR` already carries a security-owned treatment cited in obs-plan.md §11 (Project-specific bans): never via argv to the sidecar spawn, `.env(...)` builder only. Changing how the handle is **graded** must not change how it is **passed onward**.

## Acceptance criteria contributions
- No absolute host path appears in any log line, span attribute, `--json` payload or report artifact produced by the probe — the path handle is identified by NAME only; the §9 gate's patterns (`X:\`, `/home`, `/Users`, `%APPDATA%`, `~/.cargo`, `.rustup`) match nothing (per obs-plan.md §11 Logs / PII Scrubbing + §9 Log conformance check).
- The chunk mints no span name outside the bounded set and no span attribute outside `redact::ALLOWLISTED_FIELDS`; any probe observation is a §6 boundary-call log with detail on the `message` field (per obs-plan.md §11 Spans / Traces + §4 Required span attributes).
- Any self-obs line the probe emits carries the §3 base set (`timestamp_ms`, `level`, `target`, `service.name`, `service.version`, `deployment.environment`, `run_id`) (per obs-plan.md §3 Log format JSON schema).
- Zero unlogged panics on the env-read/grading path — a failure surfaces as a structured `tracing::error!` + sanitized anyhow edge (exit 1), with no `^thread.*panicked` line in `logs/agent-latest.jsonl` or stderr (per obs-plan.md §10 Zero unlogged panics + §9 Zero-unlogged-panics gate).
