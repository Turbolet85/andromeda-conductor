## Patterns to follow
- The graded-record pipeline: `parse-nvda-log.ts` grades the speech log against the per-state pass spec, operator review is transcribed per row into `evidence/nvda-pass.json` — one row per must-announce item carrying producing action, carrying node, expected NVDA output + required tokens, WCAG SC, result, arm, heard text (a11y-plan §3 Pass spec format).
- Host-tool handle guard: `CONDUCTOR_NVDA` unset ⇒ skip at exit 0, the same shape as `CONDUCTOR_MSEDGEDRIVER` on the driven arm (a11y-plan §3 Bootstrap phases).
- One webview-automation stack reused from tests §6, never a parallel one; the three suite families (routine `--e2e`, driven `a11y:driven`, `sr`/`sr-empty`/`sr-error`) all ride it (a11y-plan §3 tool pick + §9 E2E row).
- Measured-claim discipline for platform/mechanism verdicts: state only what the leg measured, label the untested half as recorded-not-established (a11y-plan §12 Decisions Log; the pattern the 2026-09-01 amendments established).
- Multi-site sweep when retiring a verdict: grep every site restating the retired claim before amending, not just the sites a report names (a11y-plan amendment precedent, 2026-09-02-cross-surface-envelope-parity).

## Anti-patterns to avoid
- NEVER let a11y artifacts leak absolute host paths or internal seam-crate struct names into the obs §6 envelope (a11y-plan §11 SLO) — applies to the re-run's `nvda-pass.json` and any committed speech-log excerpt.
- NEVER use human-only / SR-only review as the evidence for a claim, and never claim WCAG conformance without machine-verifiable JSON (a11y-plan §11 CI + §11 Strategy) — retiring `reactivateWindow()` on a prediction rather than a graded re-run is this ban.
- NEVER stand up a second browser-automation stack for a11y (a11y-plan §11 CI) — no new driver or harness to prove the console pane is gone.
