## Constraints
- The `conductor-verify` spawn is a seam with NO auto-instrumentation; any telemetry the fix adds at `build_command`/`connect` must be a manual `tracing` span or a boundary-call log, never an attribute-driven framework hook (per obs-plan §4 auto-instrumentation table, conductor-verify row).
- The bounded span-name set is a deliberate closed contract — `scenario.run`, `timeline.execute*`, `emit.batch`, `emit.logs_batch`, `verify.readback*`, `report.generate`, `db.insert_run`, `fault.silence/ramp/port_occupier`, `tauri.command.*`. A new `spawn.*` or `verify.connect` span name would widen it and requires an amendment, not a code decision (per obs-plan §11 Spans/Traces).
- Any field the fix logs must be a name in `conductor-core::redact::ALLOWLISTED_FIELDS`; a non-allowlisted attribute (e.g. `program`, `exe_path`, `creation_flags`) is DROPPED at the processor stage and emits nothing — such detail rides the allowlisted `message` field instead, key names only (per obs-plan §6 Boundary-call wrappers, §11 PII Scrubbing).
- Redaction is a processor-stage (tracing-subscriber layer) concern with single-location ownership in `conductor-core::redact`; the fix must not introduce a second, sink-stage or spawn-local scrubbing rule (per obs-plan §11 PII Scrubbing, "NEVER scrub only at sink stage" / "NEVER hardcode scrubbing rules in single location").
- No absolute host paths in logs / run-report / runs.db — the drive-letter, `/home`, `/Users`, `%APPDATA%`, `~/.cargo`, `.rustup` anchors are the value scrub; the resolved sidecar exe path is exactly the class this bans (per obs-plan §11 Logs + §9 Log conformance check).
- Whether the sidecar's exe path currently reaches any Conductor-owned log field (as opposed to only the OS window title, which sits outside every redaction edge per §11) is research's question — obs-plan §11 asserts only that the pane title is a channel OUTSIDE the three application sites, not that the path is or is not in-stream.
- The self-obs stream stays stderr/file JSON only on every surface; nothing about this spawn change may introduce an OTel SDK, exporter, or network egress for self-observation (per obs-plan §3 OTel SDK init, §11 Universal).

## Patterns to follow
- Boundary-call `info!` inside the caller's existing span, with detail on the allowlisted `message` field and NO new span name — the convention the plan records for the rusqlite READ path and for the MCP shape witness; the same shape fits a spawn-outcome witness if one is wanted (per obs-plan §6 Boundary-call wrappers, DB READ + MCP readback bullets).
- Existing `verify.readback` / `verify.readback.call_tool` manual span with the allowlisted `mcp_tool` attribute is the in-crate precedent for how `conductor-verify` instruments its seam (per obs-plan §4 must-trace Scenario 1, §6 Boundary-call wrappers).
- RAII-lifecycle instrumentation precedent: `fault.port_occupier` opens at bind and witnesses its realized hold on the allowlisted `message` field at `debug` on release, because attributes are recorded on the `new` record only — the model for any process-handle lifetime witness (per obs-plan §4 Fault-injection spans).
- Self-obs line variants: every `tracing` line carries `timestamp_ms`, `level`, `target`, service identity, `run_id`; span lines add `span`/`span_event`/`parent` — so a span materializes as real JSON lines the sr re-run can be graded from (per obs-plan §3 Log format JSON schema, two-record-shapes paragraph).
- For the live `sr` re-run leg, the Tauri backend self-obs sink is directory-derived: `&lt;runs_dir.parent()&gt;/logs/conductor-tauri.jsonl`, measured at `runs/sr-leg/logs/` for the `sr`/`sr-error` suites — evidence for "did the foreground move" should be read from that path, not the project-root `logs/` (per obs-plan §3 Log file location).

## Anti-patterns to avoid
- Do NOT widen the bounded span-name set with a `spawn.*` / `process.*` / `verify.connect` name to instrument the fix (per obs-plan §11 Spans/Traces).
- Do NOT log the resolved sidecar exe path, `Command` debug-dump, or a `Command`-shaped struct field anywhere in the fix's diagnostics — absolute host paths and Debug-dumped internal struct names are banned at source, not merely at sink (per obs-plan §11 Logs + PII Scrubbing).
- Do NOT add an `info`-level line on the connect path per attempt if connect is retried in a loop; hot-path chatter belongs at `debug`/`trace` behind `RUST_LOG=info,conductor_verify=debug`, and a bare per-target directive REPLACES the default (per obs-plan §11 Logs, §6 per-module log levels).
