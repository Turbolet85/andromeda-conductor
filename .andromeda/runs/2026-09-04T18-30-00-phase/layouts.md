# layouts extract

## Relevance
Partial — the fix itself is a Rust spawn-seam change (security/obs domain), but it targets a layout invariant of the desktop-webview surface (nothing but the frameless window may hold the foreground / overlay the console) and its CARRYs touch layouts-owned focus order and empty-state renders.

## Constraints
- The desktop surface is one frameless window and all live run state is carried in-window (titlebar + matrix + footer); Conductor performs no native OS window/toast of its own — it only *observes* Pulse's (per layout-templates §Component — Footer (status strip); §Component — Operator-checklist). A console pane raised by the app on `Start` would be state/chrome outside that surface. Whether the shipped spawn already raises one is research's question.
- The styled shadcn `AlertDialog` is the only modal over the console; `alert()`/`confirm()`/`prompt()` are never used and the Chromium context menu/devtools are suppressed (per layout-templates §IA notes — desktop, Global model). Any foreign top-level window arriving over the console during a run is an undesigned second overlay surface.
- The operator-pause dialog traps focus with a visible `color-focus` ring and restores focus **contract-borne** via a `restoreFocusTo` accessor in `onCloseAutoFocus`, because the hold arrives over a Tauri `Channel` with no Radix `Trigger` (per layout-templates §Component — Hero / signature section). An OS-foreground handoff mid-run defeats that trap and restoration; the plan requires the trap/restore to hold for the whole hold.
- Every interactive control carries a visible focus ring, hover affordances all have keyboard equivalents, keybindings (start/stop/proceed/abort) are first-class, and the focus position is communicated to assistive tech while OS shortcuts keep working (per layout-templates §Component — Primary navigation). This is the requirement CARRY 3's `tabs_to_start` (live 3 / empty 6 / error 5, `initial_focus` BODY) is measured against.
- The idle console's control region renders picker → **Start** → **Stop** inside the single `main` region beneath the frameless titlebar (per layout-templates §Wireframe — Run console (idle), control row). The visible order is the reference any tab-order measurement must match; the plan fixes no numeric focus index beyond that ordering.
- The run-report empty render is the shipped `No run yet` prose (Body, `text-tertiary`) — an ABSENCE state distinguished by TEXT, never a gray skeleton and never an error render (per layout-templates §Component — Primary content block 2, "Distinct non-result states"). CARRY 1's `run_report` / `run_envelope` comment corrections must keep describing exactly that render.
- The catalog-empty `No scenarios found.` (owned by `App.tsx`) and the picker's FILTER-MISS `No scenarios match.` (persistently-mounted announced region, SR row S0-16) are two states, two strings, two rows — neither is the other's (per layout-templates §Component — Primary content block 1, States). Relevant if CARRY 4's `role="alert"` region work re-touches that set.

## Patterns to follow
- **Security guardrails honored at the layout level** — the desktop surface already carries this class of rule (deny-by-default Tauri capabilities, no remote-origin iframes, no `shell-open` with scenario-derived strings, Tauri ≥ 2.10.3) per layout-templates §IA notes — desktop. A console-suppressing creation flag is the same class: a process-level guardrail expressed as "the window stays the surface", not a new UI element.
- **Adapt per surface, never fork** — one rule, expressed per surface (desktop CSS vars ↔ cli ANSI; the run-level qualifier SET) per layout-templates §IA notes — Multi-surface coordination / §cli IA notes. The spawn seam is shared by the cli legs and the webview leg; the layout expression differs (in-window invariant vs. linear stdout/stderr discipline) but there is one fix, not two.
- **Headless invariant / pipe discipline** — interactive prompts are `isatty`-gated and the agent-driven source-of-truth path is never blocked, with stdout reserved for artifact data (per layout-templates §cli IA notes — Headless invariant, Pipe discipline). The spawn change must leave the headless `agent-run` legs unblocked and their output shape untouched.
- **`aria-disabled`, never native `disabled`, on Start** so the invoking control stays focusable for dialog restoration (per layout-templates §Component — Hero). This is the layout-side reason a tabs-to-Start count may legitimately differ across run states, and it constrains any CARRY-3 focus fix.
- **OS window behavior is delegated, not templated** — window-control specifics (Windows/Linux standard buttons vs. macOS traffic-light, double-click-to-maximize) follow OS convention at implementation time (per layout-templates §Decisions Log — Notable surface-specific deferrals). Precedent for a Windows-only construction detail living in code with no doc-side layout entry.

## Anti-patterns to avoid
- Do not introduce or tolerate a second foreground/overlay surface over the console — no native dialogs, no un-styled OS window; the `AlertDialog` is the only modal (per layout-templates §IA notes — desktop).
- Do not let any run state or identity reach the operator through a channel outside the window — Conductor never emits a native OS toast/pane; that behavior is *checked*, never performed (per layout-templates §Component — Footer (status strip); §Component — Operator-checklist).
- Do not restructure the console for this fix: no routes, no deep links, no breakpoints — the frameless window is the surface and the operator navigates by run state (per layout-templates §IA notes — Global model; §Decisions Log — Responsive breakpoints N/A).

## Contract bindings
- **Focus order ↔ a11y §Focus Order (SC 2.4.3)** — layouts fixes the visible control-row order (picker → Start → Stop, §Wireframe — Run console (idle)); a11y owns the conformance claim that focus order matches it. CARRY 3's `tabs_to_start` divergence is measured against the layouts order.
- **Modal patterns ↔ a11y §Modal focus trap (Escape dismiss + restore focus)** — the operator-pause dialog's `restoreFocusTo` / `onCloseAutoFocus` restoration contract (§Component — Hero) is the layout-side requirement the a11y trap criterion binds to.
- **Layouts ↔ tests/SR harness** — `screen-reader.e2e.ts:121` `reactivateWindow()` compensates for a foreground handoff; layouts contributes only the invariant (nothing but the Conductor window takes the foreground) that a live re-run would prove. Retirement is the tests domain's call and is conditional per the chunk scope, not a layouts mandate.
- **Layouts ↔ security/obs** — the pane title's host-path disclosure belongs to security-plan §Anti-Patterns (a) and obs-plan §11; layouts owns only "no foreign window over the console", not path redaction.
- **Layouts ↔ cli surface** — the spawn fires on `ReadBackClient` connect, i.e. under the `preflight` / `run` / `suite` verbs documented in §cli Primary screens; their documented output shape (headers, `[PRECONDITION]` / `[OK]` lines, terminator) must be unchanged by the fix.
