## Patterns to follow
- The boolean-grade, path-never-returned resolution pattern of `sidecar_resolves_on_path` — it answers presence without constructing a `Command`, and the resolved path is never returned, logged, or rendered (per security-plan §Security Anti-Patterns → Code Patterns rule (a); §Security Anti-Patterns → Input).
- Env-map-only propagation of operator-supplied values to a child, with metacharacter rejection at the caller before the spawn (per security-plan §Input Validation, `ANDROMEDA_PULSE_DATA_DIR` SPAWN-propagation row).
- The `<host-path>` scrub + `security_finding` row written into `evidence/nvda-pass.json` by the leg's parser, asserted by the chunk's own hygiene grep (per security-plan §Input Validation, speech-log ingest row).
- Typed `thiserror` seam errors collapsing to `anyhow` only at the `conductor-cli` / `#[tauri::command]` edges, with `sanitize_error` on every returned `Err` — relevant to the CARRY-1 `commands.rs` doc-comment corrections, which describe behavior at that sanitized boundary (per security-plan §Error Handling; §Input Validation, `#[tauri::command]` IPC-arguments row).
- The justified, comment-carrying `deny.toml` entry as the sanctioned mechanism for a non-actionable advisory or a permissive-license addition, should a dependency delta surface one (per security-plan §Dependency Security, Accepted exceptions).

## Anti-patterns to avoid
- Never restructure the spawn toward a shell, an `eval`-equivalent, an operator-chosen command string, or an argv-carried data dir while adding the creation flag (per security-plan §Security Anti-Patterns → Code Patterns rule (a); §Security Anti-Patterns → Input).
- Never reach for a `deny.toml` ignore, a CI edit, or a silent accept to turn the red `cargo audit` green — it is an advisory-DATABASE fault, so a floor raise is unexecutable and the only remedy is the bounded wait with the deny overlap verified green (per security-plan §Dependency Security, two-fault split; §Security Anti-Patterns → Universal).
- Never add a fifth harness spawn form or reclassify the sidecar spawn under rule (b); rule (b)'s four governed harness forms are explicitly not this defect (per security-plan §Security Anti-Patterns → Code Patterns rule (b)).
