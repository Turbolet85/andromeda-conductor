## Constraints
- The spawn seam's negative-test mandate is unchanged by this chunk and must survive it: `andromeda-pulse-mcp` spawned as a fixed hard-coded program NAME resolved through the inherited `PATH`, `ANDROMEDA_PULSE_DATA_DIR` passed strictly via `.env(...)` after metacharacter rejection, never into argv — with a negative test asserting argv-injection rejection (per test-plan §11 Test Anti-Patterns → Mocking, stack-specific). Whether the existing `build_command` unit test already carries all three assertions, and can be extended rather than duplicated, is research's question.
- Unit tests assert the public seam API and observable behavior, never implementation details or private internals (per test-plan §11 → Unit). `build_command` is `pub(crate)` and returns a `tokio::process::Command`; whether a creation-flag assertion is reachable as observable behavior at all — or must instead be flagged in the §1 "Untestable zones" discipline (flag it, never invent a driver) — is research's question, not something this plan settles.
- Any new test must be green under BOTH runners: `cargo nextest run -p conductor-verify` and the standing runner-portability gate `cargo test -p conductor-verify` (per test-plan §4 Unit Test Strategy → Framework). A runner-dependent or otherwise flaky result is a determinism break to fix at the cause, never a retry or a `--test-threads=1` pin (per test-plan §10 Zero-flakiness budget).
- Because the chunk touches `conductor-verify`, the per-chunk scoped mutation audit applies as an operator/local instrument: full workspace-root `-f crates/conductor-verify/src/spawn.rs` paths, `--test-tool=nextest` required, gate on the `mutants.out/` tallies and never the exit code, `Found 0 mutants to test` is a NO-OP not a pass (per test-plan §4 → Mutation instrument; §9 Scoped mutation audit). Every named survivor ends killed or classified accepted-deliberate against a cited rule (per test-plan §10 Mutation-survivor disposition).
- Doc-comment edits ride their own gate: `cargo test --workspace --doc` is a SEPARATE Section 9 stage, never folded into `--unit` (per test-plan §3 → CI stage selectors; §9 pipeline Doctest row).
- The `sr*` screen-reader suites are operator-local-gate only — Windows + NVDA host, real wall clock, never a CI stage, never an `agent-run` verb; NVDA's speech log is the driver and the operator's role is REVIEW of the graded record (per test-plan §6 Drivers per surface → desktop-webview; §2 Agent-runnable invariants operator-local carve-out; §11 → CI stack-specific live-leg ban).
- If a webview arm is exercised, the routine `--e2e` leg's preconditions hold unchanged — ensure-frontend, release build `--features tauri/custom-protocol`, self-seeded fixture runs dir via `CONDUCTOR_RUNS_DIR=runs/e2e-fixture`, tauri-driver spawned at workspace-root cwd (per test-plan §3 → CI stage selectors).

## Patterns to follow
- Crate-local `#[cfg(test)] mod tests` inside the seam source file, snake_case `#[test]`/`#[tokio::test]` fn names, rstest `#[case]` rows for table-driven variants (per test-plan §4 Conventions).
- The sanctioned mechanism for exercising the spawn/`.env()` path is the hand-rolled `stub_pulse_mcp` spawned as a CHILD binary (as distinct from the in-process duplex transport used for verdict logic), with DI of transport and no monkey-patching of production code (per test-plan §5 boundary table "Module ↔ external (MCP sidecar)"; §8 mocking table).
- The in-repo precedent for a spawn leg that needs a host precondition is the `stub-server`-gated `preflight_spawn.rs`; a cargo-feature-gated file is invisible to the default lint pass and OWES its own `cargo clippy -p <crate> --features <feat> --all-targets -- -D warnings` (per test-plan §9 Live-Pulse scenarios).
- Live/host-dependent handles follow the measured skip-arm shape — unset / not-a-file / metacharacter ⇒ skip at exit 0 (`CONDUCTOR_MSEDGEDRIVER`, `CONDUCTOR_NVDA`), with the `sr` live subject additionally taking `CONDUCTOR_SCENARIOS_DIR=runs/sr-leg/scenarios`, repo-relative (per test-plan §6 Drivers per surface → desktop-webview; §1 Coverage triggers, Vector-1 per-reader split).
- Anything touched that reaches an artifact keeps the envelope/journal golden discipline: insta in CI/assert mode with `run_id`/timestamp redaction, plus the artifact-sanitization assertion that artifacts leak no host paths or internal struct names (per test-plan §5 Run report envelope; §7 Golden artifacts).

## Anti-patterns to avoid
- Never assert on private internals or fixture-internal values to "prove" the creation flag — assert the public seam contract / observable behavior, and where no agent-drivable signal exists, record it as a flagged zone rather than inventing a driver (per test-plan §11 → Unit; §1 Untestable zones).
- Never turn a real-clock, live-Pulse or NVDA-host leg into a CI gate, and never add nextest `retries` to stabilize one (per test-plan §11 → CI stack-specific; §10 Zero-flakiness budget).
- Never introduce a human-in-the-loop verification step for the console-window claim ("developer confirms no pane appears") — no manual smoke steps, no screenshot review; unresolved rows stay recorded findings, never passes and never a manual arm (per test-plan §11 → Universal; §1 Untestable zones, browse-mode entry).
