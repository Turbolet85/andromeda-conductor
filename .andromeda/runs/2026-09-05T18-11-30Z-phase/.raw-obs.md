# obs extract

## Relevance
Relevant — W2 edits the self-obs module itself (`conductor-core/src/obs.rs`), W5's stated acceptance is obs span identity, W4a/W4b touch obs-governed Tauri command spans and coverage-gate denominators, and W6 closes a §9/§10 CI gate.

## Constraints

1. **W2 sits inside the self-obs layer.** `crates/conductor-core/src/obs.rs` is the custom `tracing-subscriber` layer's home. obs-plan §11 Project-specific bans forbids tokio's virtual clock for journal timestamps — wall-clock `std::time::SystemTime` only — and §3 Log format JSON schema requires the two record shapes stay distinct: the self-obs base line's `timestamp_ms` (epoch millis) versus the Run-report envelope's ISO-8601 `journal_emitted_at` / `read_back_observed_at`, which carry the SLO math. A boundary-date test must pin the stamp on the shape that owns it. **Which of the two `civil_from_unix` renders is research's question** — the scope calls it "the self-obs timestamp's days-to-civil conversion", but the §3 base set names `timestamp_ms` as epoch millis, so the rendering site needs measuring.

2. **W5 must not disturb span identity.** obs-plan §11 (Spans / Traces) mandates a *bounded* span-name set (`scenario.run` · `timeline.execute*` · `emit.batch` · `emit.logs_batch` · `verify.readback*` · `report.generate` · `db.insert_run` · `fault.silence`/`ramp`/`port_occupier` · `tauri.command.*`), and §4 Critical Path 1 Cleanup requires the root `scenario.run` to open per-scenario at the composition root `conductor-run::execute_scenario`, closing when that scenario returns, with `report.generate` / `db.insert_run` as run-scoped **siblings** correlated by `run_id` — because `persist` is called alongside `execute_scenario` at every production site. W5 relocates `execute_scenario`, `persist` and `drive_run` (potentially into different modules); that sibling topology and the name set must survive the move.

3. **The split moves a field the gate reads: `target`.** obs-plan §3 (two record shapes) puts `target` on *every* self-obs line, and §9 Log conformance check plus §11 Logs both require it preserved as an allowlisted identity field (a `module::`-shaped path deliberately not redacted). Splitting `lib.rs` into siblings shifts `target` from `conductor_run` to `conductor_run::&lt;module&gt;` on lines emitted by moved code. Span names are function-derived and stay; `target` does not. **Whether any golden, test or gate pins `conductor_run` target values is research's question** — the scope's "spans byte-identical" acceptance does not cover the `target` field.

4. **W4a must preserve per-handler command spans.** obs-plan §1 (desktop-webview row) and §4 (auto-instrumentation table) require a **manual** `tracing::info_span!("tauri.command.&lt;name&gt;").entered()` guard on each `#[tauri::command]` handler across all eight — the `#[tracing::instrument]` attribute cannot stack with the command macro. A shared resolve-and-map-error prologue must not absorb the guard in a way that collapses eight distinct names into one shared name.

5. **W4a's error-mapping arm is a redaction site.** obs-plan §11 (Logs · PII Scrubbing · Error Reporting) requires that internal struct names be kept out by the field-name allowlist plus `Display`-not-`Debug` at the `anyhow` edge, and that absolute host-file paths be masked. A single shared error mapper is precisely where a `Debug` format or a raw path would re-enter; the scope's "error strings unchanged" is the same boundary stated from the product side.

6. **W4b's clone pair is the coverage gate's own two surfaces.** obs-plan §4 (Coverage-matrix completeness gate — denominator semantics) names `conductor_report::coverage::summary_line` and `conductor_cli::render::coverage_summary` explicitly and requires: `p_id_count_expected` = the FULL manifest capability count, `coverage_percent` computed over the **in-scope** count, both manifest-derived and never literals, plus the auto term's derived `(N unbacked)` qualifier (from `conductor_core::UNBACKED_AUTO`) qualifying the auto count rather than joining the breakdown. A shared formatter must carry this split or the two surfaces silently disagree with the not-yet-built gate.

7. **W3's transport must stay non-panicking and must keep its boundary log.** obs-plan §11 Error Reporting / Project-specific bans require that malformed child or transport input on the MCP read-back path yield `blocked` (a typed `Ok(...)`), never a panic or an uncaptured crash; §6 Boundary-call wrappers require the `verify.readback*` seam to log tool name + `latency_ms` + error + canary result + the observed key-set shape witness on the `message` field. A bounded await added at `jsonrpc.rs` must not drop or reshape that must-log set.

## Patterns to follow

- **Manual command-span guard at every `#[tauri::command]` site** (obs-plan §4 auto-instrumentation table; the 2026-09-01 amendments record 8/8 sites measured) — the pattern W4a's prologue extraction has to preserve rather than re-invent.
- **`message`-field carrier for anything outside `conductor-core::redact::ALLOWLISTED_FIELDS`** (obs-plan §6 Boundary-call wrappers): a dedicated attribute outside the allowlist is dropped at the processor stage and emits nothing, so incident ids, key sets and realized-hold witnesses all ride `message`. Any new detail added while dedup'ing or splitting follows this.
- **Read-path convention: no `db.*` read span** (obs-plan §6 DB READ bullet; §4 conductor-report row) — a rusqlite READ inside a `tauri.command.*` span logs a boundary `info!` with `run_id` + outcome on `message`; only WRITE queries carry `db.insert_run`. Directly relevant to W4a, whose prologue spans the `run_report` / `run_envelope` read handlers.
- **`{module}.{operation}` span naming** (obs-plan §4 Span naming convention) — if W4/W5 extraction produces an instrumented helper, it reuses an existing bounded name or follows this convention.
- **The §9 log conformance gate as proof instrument** (obs-plan §9 Log conformance check) — validates the §3 self-obs base schema over `logs/agent-latest.jsonl` and asserts no absolute host-file paths; this is the gate the chunk's own Harness list names, and the natural W5 proof.

## Anti-patterns to avoid

- **Never widen the bounded span-name set** (obs-plan §11 Spans / Traces) — no module path from the W5 split may leak into a span name or span field, and the deliberately-withheld `db.*` read wildcard (§6) stays withheld.
- **Never emit unstructured or stdout self-obs** (obs-plan §11 Logs; §3 Logging stack sinks) — W1's `render.rs` `stdout_color` / `stderr_color` survivors sit on the CLI **product** render; the self-obs stream is stderr/file JSONL only, never stdout, never pretty. Dispositioning the tty gates must not move a self-obs line onto stdout or introduce a non-JSON writer.
- **Never leak host paths or internal struct names through the `anyhow` edge** (obs-plan §11 PII Scrubbing) — W4a's shared error map and W5's moved `?`-chains are both sites where a `Debug` format would re-introduce them.

## Contract bindings

- **obs ↔ tests (§3 harness contract).** test-plan §3 OWNS the JSONL/self-obs line format; obs-plan §3 derives from it. W4c's shared `conductor-run/tests/common/` fixture serves `canary_obs_witness.rs`, an obs-witness test — the fixture must not alter what the witness asserts about the self-obs stream.
- **obs ↔ tests (§10/§12 disposition rules).** W2's survivors live in the obs module and W3's in the obs-logged MCP seam; obs contributes the field/shape constraints above, tests owns the kill-or-accept rule.
- **obs ↔ security (§11 PII Scrubbing ↔ security-plan §Input Validation).** W1's `paths.rs:73` / `paths.rs:130 env_seed` sit on the `CONDUCTOR_*` handle edge that obs also depends on: obs-plan §3 makes `CONDUCTOR_RUNS_DIR` the directory the Tauri log sink rides, `CONDUCTOR_AGENT_MODE` a **read-only** trigger Conductor never writes, and `CONDUCTOR_ENV` / `CONDUCTOR_SERVICE_NAME` the service-identity resolution. A change in how those handles resolve moves the log sink and the identity fields.
- **obs ↔ CI/supply-chain (W6).** obs-plan §9 lists the supply-chain audit report as a CI telemetry artifact (agent-readable, machine-parseable) and §10 Build/deploy failure conditions names a `cargo-audit` red flag as a gate. The scope's two-step probe (exit read directly, output into `target/`) satisfies the agent-readable requirement; §11 CI also bans losing telemetry artifacts.
- **obs ↔ conductor-run seam (W5).** `probe_resolve_lifecycle` — the §6 MCP lifecycle-WRITE bullet's named first production caller, carrying the `verify.readback.call_tool` span, the allowlisted `mcp_tool` attribute and the `message`-borne incident id — is inside W5's "lifecycle / harvest helpers" group being moved.

## Acceptance criteria contributions

- After the `conductor-run/src/lib.rs` split the span tree is unchanged: `scenario.run` opens at `execute_scenario` and closes when that scenario returns, `report.generate` and `db.insert_run` remain run-scoped siblings correlated by `run_id` (not descendants), and every emitted span name stays inside the bounded set (per obs-plan §4 Critical Path 1 Cleanup + §11 Spans / Traces).
- The obs conformance gate passes over `logs/agent-latest.jsonl` after the split: every line carries the self-obs base schema (`timestamp_ms` · `level` · `target` · `service.name` · `service.version` · `deployment.environment` · `run_id`) with no absolute host-file path in any field, and the post-split `target` values are recorded in evidence alongside the pre-split ones (per obs-plan §9 Log conformance check + §3 Log format JSON schema).
- W4a's shared prologue leaves a distinct `tauri.command.&lt;name&gt;` span per handler across all eight handlers, and its error-mapping arm renders `Display`, never `Debug`, so no internal struct name or host path enters a mapped error string (per obs-plan §4 auto-instrumentation table + §11 Logs / PII Scrubbing).
- W4b's shared coverage formatter renders the same denominator split on both surfaces — `p_id_count_expected` as the full manifest capability count against `coverage_percent` over the in-scope count, both manifest-derived, with the derived `(N unbacked)` qualifier attached to the auto term and not summing into the per-mode breakdown (per obs-plan §4 Coverage-matrix completeness gate — denominator semantics).
