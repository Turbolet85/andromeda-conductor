## Patterns to follow
- The `resolve_under` guard + `sanitize_error` edge pair as the shipped shape for `run_id`-class IPC arguments, proven at the mock-runtime IPC tier (`tauri::test`) — per §Input Validation, `#[tauri::command]` row. W4a should hoist exactly this pair; app-defined commands are NOT capability-ACL-gated, so this pattern (not the capabilities file) is what governs them.
- The verdict/error wall: module-internal `thiserror` typed enums per seam crate, collapsing to type-erased `anyhow` only at the `conductor-cli` / `#[tauri::command]` edges; `Result::Err` reserved for harness faults, verification outcomes returned as `Ok(typed value)` (per §Error Handling). W3's ownership and W5's split must leave the wall at those same two edges.
- `e.kind()`-only read faults, never the path, for fixed-path manifest reads resolved through `resolve_under` (per §Input Validation, committed SUT-facing manifests row) — the reference shape if any moved code re-renders a filesystem error.
- The deny.toml justified-exception mechanism: each entry carries a justifying comment, `deny.toml` itself is the authority on the full set (the plan's prose is known-incomplete), and reconciling the two is carried by the `Dependency polish` route entry (per §Dependency Security, Accepted exceptions). The expected 18-allowed-warning summary is the current shape of that set.
- The two-step probe form the scope names (porcelain check, then `cargo audit` with the exit read directly rather than through a pipe) is the audit↔deny overlap being VERIFIED rather than assumed (per §Dependency Security, advisory-DATABASE fault bullet).

## Anti-patterns to avoid
- NEVER classify a survivor accepted-deliberate at a site that implements a §Input Validation-mandated control (the `CONDUCTOR_*` handle edge, scenario-config validation, the bounded MCP decode) — the boundary would read as enforced while nothing tests it, the same failure mode §Security Anti-Patterns → Input names for a sibling-reading `#[garde(custom)]` and a `#[garde(skip)]` nested field.
- NEVER close the standing deferral by ignoring the advisory in `deny.toml`, editing CI, or silently accepting; and never re-pin a fresh RED as the retired signature (per §Dependency Security, advisory-DATABASE fault bullet).
- NEVER let a refactor widen what crosses the operator edge: the tauri prologue must keep every error string it maps today, and no committed evidence record may leak an absolute host path (per §Security Anti-Patterns → Logging; §Error Handling).
