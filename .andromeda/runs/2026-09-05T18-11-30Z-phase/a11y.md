# a11y extract

## Relevance
**Partial** — no rendered-UI/DOM surface is touched (all six work items are Rust: cli, core, verify, tauri-backend, report, run), but three seams carry a11y-owned contracts: the not-assertable cli verdict (W1/W4b), the coverage/lamp label text the webview assertions key on (W4b), and the conductor-run production-writer path the a11y routine arm seeds through (W5).

## Constraints
- The `conductor-cli` surface is **not-assertable** for a11y — per a11y-plan §1 (A11y scope, `conductor-cli` entity, scoped to the whole `conductor` verb SET since the 2026-09-03 amendment). W1's `render.rs` / `main.rs` / `paths.rs` / `pause.rs` / `commands/mod.rs` survivors therefore carry **no WCAG obligation** and produce **no a11y coverage**, whatever assertions kill them.
- The scope's "status-never-color-alone invariant" on the PLAIN cli path is **not** SC 1.4.1 — per a11y-plan §11 Universal, the cli's ASCII status prefixes + NO_COLOR text-pairing are *output-stream discipline, not an ARIA a11y verification path*; SC 1.4.1 is required only of the webview's six lamp **display labels** (§6 State color tokens). W1 must not conflate the two.
- Per a11y-plan §6 (State color tokens → state-naming crosswalk), the display-label ↔ obs-`verdict` ↔ obs-`state` crosswalk is **binding for the DOM-text assertion + obs join**, and lamp selection is **verdict-first**. Any new/sharpened assertion this chunk writes over `render.rs::lamp_code`'s mapping must not pin a state-first mapping that contradicts it. Whether `lamp_code` already implements verdict-first is research's question.
- Per a11y-plan §1 (non-lamp reuse of `--status-residual`, added 2026-08-09), the coverage-matrix out-of-scope Mode cell is a **coverage-mode classification, not a seventh lamp state**, and its not-color-alone signal is its **own always-rendered `not-conductors` label** (no glyph supplement). W4b's shared coverage formatter must keep that label always-rendered and byte-identical in every surface it feeds.
- Per a11y-plan §4 (load-envelope banner row) + §9 (E2E routine-arm row), the routine a11y arm's real-DOM coverage **requires** that its committed fixture subject be written *through the production writer* (`cargo test -p conductor-run --test envelope_fixture` under `CONDUCTOR_E2E_SEED_DIR`; the per-P-ID lamps likewise). W5's byte-stable-public-API / no-behaviour-change requirement must hold for that path, or the banner's rendered-DOM axe regresses to the UNRUNNABLE verdict the 2026-09-02 amendment retired.
- Per a11y-plan §11 SLO + §3 (Structured violation JSON schema), a11y artifacts must never carry absolute host paths or **internal seam-crate struct names** — W5's new sibling-module names must not become artifact or selector content.
- Per a11y-plan §11 Strategy, no WCAG conformance may be claimed without machine-verifiable axe-core / colorjs.io / Lighthouse JSON. This chunk runs no a11y gate, so it must claim none.

## Patterns to follow
- The production-writer seed pattern established by `2026-09-02-cross-surface-envelope-parity` (a11y-plan §4 banner row, §9 routine arm): the routine arm produces its DOM state by writing a real `run_envelope` row through `conductor-run`'s shipped writer. A refactor of that crate keeps the seed's shape rather than the seed adapting to the refactor. Existing seed binaries: `crates/conductor-run/tests/envelope_fixture.rs`, `crates/conductor-run/tests/lamps_fixture.rs`.
- Label-text-as-cross-skill-anchor (a11y-plan §2 Naming conventions, §6 crosswalk): display labels and token *names* are the anchors downstream skills join on. Dedup refactors preserve label strings verbatim instead of deriving/computing them.
- The "no WCAG conformance claimed from this chunk" recording precedent (a11y-plan §11 Strategy; applied at the 2026-08-22 amendment) for chunks touching a11y-adjacent surfaces without running the gate.
- The a11y harness is self-contained under `crates/conductor-tauri/ui/test/a11y/` (`accessibility.e2e.ts`, `operator-hold.e2e.ts`, `screen-reader.e2e.ts`, `screen-reader/nvda-pass-spec.md`) per a11y-plan §3/§9. No file there appears in this chunk's surfaces list, and none should be added by it.

## Anti-patterns to avoid
- Treating the cli kills as accessibility evidence — a11y-plan §11 Universal bans recording the cli surface as a11y-assertable; a `[PASS]`/`[FAIL]` prefix assertion is not an SC 1.4.1 datum.
- A dedup that makes a state/mode **label conditional** or reconstructs it from the color/mode token alone — a11y-plan §11 Visual (never convey state by color alone) and §1's Mode-cell note.
- Letting a new `conductor-run` module path or internal struct name reach an a11y artifact field or DOM selector — a11y-plan §11 SLO leak ban (inherited from tests' Status JSON constraint).

## Contract bindings
- **a11y ↔ obs §6**: a11y violation artifacts reproduce the obs Run-report envelope **verbatim** (a11y-plan §3 Structured violation JSON schema; the reproduction tracks obs field changes per the 2026-06-16 amendment). W2 edits `civil_from_unix` in `crates/conductor-core/src/obs.rs`, the self-obs timestamp's days-to-civil conversion — whether that function is on the path that renders the envelope's `journal_emitted_at` / `read_back_observed_at` ISO-8601 (and so whether a11y artifacts inherit the fix) is research's question. The requirement either way: the emitted timestamp *shape* a11y reproduces must not change.
- **a11y ↔ tests §6**: the a11y routine/driven/SR arms ride tests' `@crabnebula/tauri-driver` + WebdriverIO `wdio run` job and emit through the 5-command `logs` command (a11y-plan §3 CI integration, §9). W5's "17 test binaries compile unchanged" must cover the two a11y seed producers named above.
- **a11y ↔ design §Color Palette / §Motion**: not exercised — no CSS/token/TSX file appears in this chunk's surfaces.
