## Constraints
- The cli's output structure is a stable contract downstream agents parse — layout-templates §cli IA notes (Command model) states that adding a `comfy-table` column without a `--format` flag is a breaking change. This is the layout reading of the chunk's own "no behaviour change in the CLI's output text" boundary: kills and dedups must be shape-preserving, not merely test-preserving.
- Every status must be paired with an ASCII text prefix (`[PASS]`/`[FAIL]`/`[HOLD]`/`[BLOCKED]`, `✓`/`✗`/`→`/`•`) so the signal is never color-alone and survives `NO_COLOR`/piping (per layout-templates §cli Signature placement · §cli Component — Primary content block 2). The `lamp_code` / `paint` survivors sit on this rule; whether the existing tests already assert the label text on the plain path is research's question.
- Two distinct table shapes must stay distinct: the 6-column results/SLO table (`run`/`suite`) and the 4-column `conductor coverage` matrix with no verdict/state column and therefore no bracket prefix (per layout-templates §cli Component — Primary content block 1). W4b's shared formatter spans both artifacts and must not conflate them.
- ANSI styling routes through a TTY gate decided independently for stdout and stderr, auto-stripping when piped and honoring `NO_COLOR`/`TERM=dumb` (per layout-templates §cli Component — Header / banner). The `stdout_color` / `stderr_color` survivors sit on this rule: any seam introduced to make terminal-ness testable must preserve per-stream independence, not collapse the two into one decision.
- The roll-up caption's numbers are manifest-derived, never literals; `(N unbacked)` qualifies the auto term only, is never a fifth summand, is omitted at zero, and the same roll-up shape renders on all three surfaces — Markdown artifact · cli · webview header strip, the webview receiving it as the coverage matrix's `unbacked` prop from the `unbacked_auto` command and never mirrored in TypeScript (per layout-templates §cli Primary screens, `conductor coverage [--write]`). Whether the shipped `coverage_summary` / `coverage_summary_styled` already derive rather than bake is research's question.
- The `[ENVIRONMENT-SUSPECT]` line is a run-level, non-lamp qualifier printed once per run ABOVE the verdict lines and OUTSIDE the lamp column, its ASCII bracket label always printed, omitted entirely when the run is in-envelope or pinned exempt; the per-P-ID lamp set stays closed at six (per layout-templates §cli Component — Primary content block 2 · §cli Output structure `conductor run`). `envelope_caption` renders this.
- `hold_line` carries signature placement #2 — the `HOLD — operator pause` phase line printed above the `inquire` confirm with the frozen count as text — and the headless invariant requires the agent path never block on that prompt (per layout-templates §cli Component — Hero / signature output · §cli IA notes Headless invariant). It is signature-bearing structure, not incidental formatting.

## Patterns to follow
- Adapted per surface, never forked: the same roll-up / qualifier shape rendered by name across cli ANSI, webview CSS var and Markdown (per layout-templates §cli IA notes Multi-surface coordination). W4b's shared formatter is that stated principle expressed in code — the accept-and-record arm is only defensible if the two surfaces differ at the roll-up, not merely at the rendering (styled table vs Markdown is a rendering difference).
- The indented-detail-line precedent: extra grain is added as an indented plain-text line under its P-ID verdict line — no new column, no new bracket label, no new ANSI/token entry (per layout-templates §cli Component — Primary content block 2, per-check detail region). Any detail a kill assertion needs to pin should key on this existing shape.
- Run-level captions are placed once, above the verdict lines they qualify, with an always-printed ASCII bracket label and both arms of the label reachable (per layout-templates §cli Component — Primary content block 2, the non-lamp qualifier SET).
- Set-naming over literals in anything asserted about the caption — the plan states every number is manifest-derived (per layout-templates §cli Primary screens, `conductor coverage [--write]`).

## Anti-patterns to avoid
- Introducing a seventh lamp, a new bracket label, a new ANSI entry, or a new column as a side effect of the dedup or of a sharpened assertion — the lamp set is closed at six (per layout-templates §cli Component — Primary content block 2).
- Merging the 4-column coverage matrix into the 6-column results/SLO shape, or giving `conductor coverage` a verdict/state column and bracket prefix, in the course of extracting one shared formatter (per layout-templates §cli Component — Primary content block 1).
- Pinning a literal count (e.g. a baked unbacked number or per-mode tally) inside a new content assertion — the plan's own line declares these derived, and the amendment history records three consecutive re-stalings from substituting fresh literals (per layout-templates §cli Primary screens, `conductor coverage [--write]`).
