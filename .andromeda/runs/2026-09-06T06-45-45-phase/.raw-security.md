## Relevance
Relevant — the chunk composes env handles, harness spawns, a live preflight refusal path and a committed evidence artifact, all of which sit on named security boundaries.

## Constraints
- Every env handle the composed invocation carries is already a registered boundary with a control that differs BY HANDLE CLASS, and the invocation must not relax any: Rust-read `CONDUCTOR_RUNS_DIR`/`SCENARIOS_DIR`/`CONTRACT_MANIFEST` require `std::fs::canonicalize` + bounds-check at the `conductor-cli` edge; `CONDUCTOR_MSEDGEDRIVER`/`CONDUCTOR_NVDA` require the wdio-edge existence + `isFile` + shell-metacharacter guard (never the Rust rule); `CONDUCTOR_E2E_SEED_DIR` is a harness-owned repo-relative constant carried only in a spawn env map (per security-plan §Input Validation, boundary table). A composed entry point that re-exports or re-derives any of these must route through the same guard, not around it.
- `ANDROMEDA_PULSE_MCP_ENABLED` must be present in Conductor's OWN process environment and reach the sidecar by inheritance only — `spawn.rs` passes only `ANDROMEDA_PULSE_DATA_DIR` through `.env(...)`, and Conductor never SETS the flag itself (per §Threat Model Summary → Auth model Reason). The `ANDROMEDA_PULSE_*` declaration-only READ SET is presence/value graded by `conductor_core::{handle_declared, flag_declared}` and must render handle NAMES only — no value may become a path, an argv element or a log value (per §Input Validation, READ SET row). Whether the existing legs already satisfy this end-to-end is research's question.
- `ANDROMEDA_PULSE_DATA_DIR` on the SPAWN-propagation path must be passed strictly via the `.env(...)` builder with argument-injection metacharacters rejected first, never interpolated into argv or a shell (per §Input Validation, spawn-propagation row; §Anti-Patterns → Input).
- Any spawn the suite adds falls under the harness-spawn rule: the program is a repo-derived resolved constant or a fixed OS/toolchain program with a fixed argv; a guarded host-tool path may be the program only after the `isFile` + metacharacter guard; an operator-supplied VALUE appears only as a separate element of an array-form argv or in the child's env map, never inside a shell string (per §Anti-Patterns → Code Patterns rule (b), which currently enumerates FOUR governed forms). The MCP sidecar spawn keeps rule (a): fixed program NAME through inherited `PATH`, `.env(...)`-only, `CREATE_NO_WINDOW`-class console suppression.
- The evidence artifact and any persisted record the suite writes must carry verdict/state/identity fields only — no absolute host paths (canonicalized `CONDUCTOR_*` dirs, `ANDROMEDA_PULSE_DATA_DIR`) and no internal seam-crate struct names — because committed `evidence/` trees are agent-parseable ground truth shared across hosts (per §Anti-Patterns → Logging, third bullet; §Error Handling, Run-report artifact sanitization). If the suite ingests NVDA speech, the third-party-text scrub to `&lt;host-path&gt;` + `security_finding` applies (per §Input Validation, speech-log ingest row).
- A refusal on unmet preconditions must name its subject: a failed preflight may never be silently downgraded to pass/fail/manual-check; each of the FIVE named preconditions surfaces as a distinct `blocked` state with its own precondition string, never a generic one, and a term whose truth lives SUT-side is `declared-not-observable` and never blocks (per §Anti-Patterns → Universal, never-downgrade ban, as scoped to a preflight that IS invoked). This is exactly the scope's "refuses to run a partial env rather than degrading to a silent `[BLOCKED]`".
- Shipped binaries add no inbound listener; the whole deliberate-bind set is the `:4317` port-occupier plus the dev-only harness-lifetime `4444`/`4445` driver ports, and the plan's carve-outs enumerate the driver legs BY NAME (`agent-run … --e2e` routine arm, `a11y:driven`, `sr`/`sr-empty`/`sr-error`) at §Threat Model port-bind vector, §Input Validation `CONDUCTOR_MSEDGEDRIVER`/`CONDUCTOR_NVDA` rows and §Anti-Patterns → Universal. A new named invocation that fires the same wdio stack makes those name-lists incomplete — a boundary-inventory amendment is likely owed, not a control change.
- Dependency gates stay green over the committed lock: `cargo audit` + `cargo deny check advisories bans licenses sources`, and `npm audit --omit=dev` = 0 with `package-lock.json` committed if the suite adds any npm script/devDep (per §Dependency Security; the red-audit dependency-admission regime is recorded CLOSED as of 2026-09-05).

## Patterns to follow
- The capture/grade split already used by the harvest tier — a live leg PRINTS its observation, grading happens over committed frozen lines — is the existing evidence convention; §Error Handling's artifact-sanitization rule applies to the committed half of that split, so reuse it rather than minting a second evidence shape.
- `resolve_under` against a resolved base directory as the traversal guard for any caller-supplied id/path before a read, with `sanitize_error` on every `Err` crossing an operator-visible edge (per §Input Validation, `#[tauri::command]` row; the same `resolve_under` traversal discipline governs derived artifact paths under `CONDUCTOR_RUNS_DIR`).
- The `UNSAFE_PATH` guard in `crates/conductor-tauri/ui/wdio.conf.ts` plus skip-at-exit-0 with a host-path-free precondition naming the HANDLE, never its value — the established shape for a host-dev-tool handle the suite may re-fire (per §Input Validation, `CONDUCTOR_NVDA` row).
- The `[PRECONDITION]`-subject / run-contract-term shape: an unmet condition is named upstream with both candidate causes rather than surfacing only downstream as a ~0s `[BLOCKED]` row (per §Threat Model → Auth model Reason; §Anti-Patterns → Input, `PATH` bullet). This is the precedent for W1's refusal path.
- Contract-derived budgets over operator-steerable env: `pulse-run-contract.toml` terms are read from the fixed validated path and a lowered `CONDUCTOR_PREFLIGHT_TIMEOUT` clamps UP to the contract floor (per §Input Validation, committed SUT-facing manifests row) — the pattern for the quiet-window/pacing values the suite must honour.

## Anti-patterns to avoid
- NEVER open, copy, or stage a row in Pulse's `corpus.db` to induce a live state (e.g. a NOT-ready gate or a `DeclinedStale` arm) — corpus access is through the MCP tool surface only; direct FILE access is the banned route, which is why the declined arm is stub-proven (per §Anti-Patterns → Data Protection, corpus bullet).
- NEVER assemble the composed invocation as a shell/`eval`-equivalent string interpolating an operator-supplied env value or host-tool path (per §Anti-Patterns → Code Patterns rule (b)); and NEVER let a per-run canary identity change (the CARRY-1 `scope_id` salting fork) weaken the freshness assertion — an absent or unparseable `opened_at` stamp must still read NOT-fresh ⇒ `blocked`, never a false pass (per §Input Validation, MCP child stdout row). Any new derivation used for salting is bound by the active deprecated-crypto ban (per §Anti-Patterns → Data Protection).
- NEVER put a live leg on any default `nextest`/`clippy`/release path or wire it into CI — the Universal release gate remains `cargo-audit`/`cargo-deny` green, not a live proof (per §Anti-Patterns → Universal; §Dependency Security, CI integration).
