## Patterns to follow
- **The empty-feature gate:** `[features] live-pulse = []` declares no dependency, adds zero package nodes, leaves `Cargo.lock` byte-unchanged, and keeps the leg out of default `nextest`/`clippy`/release and out of BOTH runner-portability runs; the `stub-server`-gated `preflight_spawn.rs` is the in-repo precedent (§9).
- **Firing form as part of the leg, not an optional extra:** the driven arm's recorded form — a `PATH` prefix resolving `andromeda-pulse-mcp` (fixed program NAME through the inherited `PATH`), `ANDROMEDA_PULSE_MCP_ENABLED` + `ANDROMEDA_PULSE_L4_DETERMINISTIC`, `ANDROMEDA_PULSE_DATA_DIR` equal to the LIVE Pulse's data dir, and the ≥120s idle + 30s resolver-tick quiet window — each with a failure mode that misreads as something else (a bare invocation returns BLOCKED in ~2ms, indistinguishable at row level from a genuine SUT-side gate failure) (§6 desktop-webview row). This is precisely W1's "refuses a partial env rather than degrading to a silent `[BLOCKED]`".
- **Probe-then-gate refusal:** `boot` runs `conductor preconditions` first and SHORT-CIRCUITS on an actually-unmet subject — emitting no `ReadyState` JSON and skipping the two derived timeout budgets — with each `ANDROMEDA_PULSE_*` name graded by its own KIND via `conductor_core::handle_declared`, and identical `.sh`/`.ps1` semantics (§3 `boot`). The wrapper budget is DERIVED (`warmup_ms/1000 + poll + margin`); a missing contract term is a hard exit 2, never a silent default (§3 `boot` Timeout).
- **Per-family runs-dir isolation, repo-relative:** each suite family persists under its own `CONDUCTOR_RUNS_DIR` (`runs/driven/runs`, `runs/sr-leg/*`, `runs/e2e-fixture`) so no session's journal leaks into another's subject; the handle is repo-relative because `resolve_under` rejects absolute values at `Paths::resolve()` (§6 drivers row; §3 CI stage selectors; §3 Per-test isolation).
- **Committed-capture provenance:** a committed fixture is a reviewable declarative artifact read/written through production code, and it carries its MEANING under test via a round-trip test — one per committed fixture (§7 Self-bootstrapping requirement). Applies if this chunk's evidence capture becomes a graded subject.

## Anti-patterns to avoid
- NEVER run any live-Pulse leg as a CI gate, and never let one onto a default `nextest` / `clippy` / release path (per §11 CI stack-specific; §9).
- NEVER fake Pulse's *reaction* as a CI verdict — the stub canary proves MCP wiring only; Pulse's behaviour is a live/local-gate assertion (per §11 Test Strategy stack-specific).
- NEVER use `sleep(N)` for synchronization inside a test — wait for an explicit signal (envelope `state`, a journal line, an exit code). The quiet window is a PRECONDITION of the leg's firing form (§6), not an in-test sync sleep (per §11 E2E).
