# a11y extract

## Relevance
Partial — the chunk composes two a11y-owned operator-only suite families (`npm run a11y:driven`, `npm run a11y:sr` / `a11y:sr-empty` / `a11y:sr-error`, named in W1's firing-form inventory) into one gated invocation and lands its evidence; it adds no new UI surface, so no new WCAG criteria, ARIA roles or focus order enter scope.

## Constraints
- The three a11y suite families (routine `agent-run run --e2e`, operator-only driven, operator-only `sr*`) are operator/local gates and NONE is CI-wired; a11y-plan §9 (CI Integration, Pipeline integration) requires that any invocation composing them keeps them off every CI path — the same boundary the chunk states. Whether all three are in fact CI-free at HEAD is research's question.
- a11y-plan §3 (A11y testing tool pick / Focus management test harness) requires the driven and `sr*` legs run over the ONE `@crabnebula/tauri-driver` + WebdriverIO session the tests plan §6 stands up; a composing entry point must reuse that session, not spawn a parallel driver stack.
- a11y-plan §9 (E2E row) records the driven arm as REQUIRING a live Pulse plus its full firing form (tests §6) and the `sr*` leg as requiring `CONDUCTOR_NVDA` (unset ⇒ skip at exit 0); the composed invocation's "refuse a partial env" outcome (W1) must be reconciled with this skip-at-exit-0 handle semantics for absent HOST TOOLS — the plan mandates the skip for a missing NVDA/msedgedriver handle, not a silent block.
- a11y-plan §10 (Performance budget per a11y CI run) bounds the driven arm at a 15-minute mocha ceiling and records that a violated quiet-window precondition costs two 12-minute runs — the cost basis W1's quiet-window ordering and W4's per-run-canary fork are weighed against.
- Any a11y result folded into the chunk's evidence artifact must align to the obs §6 envelope (axe rule-id + WCAG-SC tag + node selector inside `fingerprints[]`, `state` = `Fail` when `violations.length > 0`) and must carry `service.name` / `deployment.environment` resource attributes, per a11y-plan §3 (Structured violation JSON schema) — a11y already has an evidence convention, so W2's "do not mint a second" applies to it too.
- a11y-plan §10 (Build / deploy failure conditions) + §11 (SLO) require a11y failures stay fail-fast and un-retried: a composing wrapper may not downgrade an a11y leg's non-zero exit to a warning, aggregate it into a soft verdict, or re-run it to green.
- a11y-plan §3 (Screen reader test pattern) requires the `sr*` leg stay agent-driven-and-graded (speech log → `parse-nvda-log.ts` → per-row record, operator REVIEW) and supplemental, never sole; the 14 browse-mode rows are recorded as findings, never passes, never a manual arm.

## Patterns to follow
- Tests' binding 5-command harness discipline (boot / run / status / cleanup / logs) with a11y results surfacing through the `logs` command — the existing integration seam a single invocation should keep rather than bypass (per a11y-plan §9 Pipeline integration / §3 CI integration).
- The measured arm split: routine arm is unattended and needs NO live Pulse (it seeds its own committed fixture through the production writer); only the driven and `sr*` families need the live/host preconditions (per a11y-plan §9 E2E row) — a live-gated invocation should compose the latter two, not drag the routine arm behind a live gate.
- The host-tool-handle pattern already recorded for both operator-only legs: `CONDUCTOR_NVDA` for the SR leg and `CONDUCTOR_MSEDGEDRIVER` for the Windows WebView2 arm, each "unset ⇒ skip at exit 0" (per a11y-plan §3 Bootstrap phases `screen-reader-test-spec-setup` / `a11y-ci-gate-wire`).
- The context-skip rule for a spec whose DOM state the arm's subject cannot produce: it context-skips, never passes green (per a11y-plan §9 E2E row) — the shape a composed suite's partial-leg reporting should follow.
- The measured platform SET framing rather than a platform bound: the one stack runs on Linux+`xvfb` AND headfully on the Windows WebView2 host; macOS alone stays manual-pass-only (per a11y-plan §9 Platform / §3 Focus management test harness Driver).

## Anti-patterns to avoid
- NEVER stand up a second browser-automation stack (puppeteer/CDP or a fresh driver session) for the composed invocation — axe/keyboard/SR all inject into the tests' tauri-driver/WebdriverIO session (per a11y-plan §11 → CI).
- NEVER let the composed suite's evidence artifact leak absolute host paths or internal seam-crate struct names into the obs §6 envelope; node targets stay DOM-relative selectors / `data-testid` (per a11y-plan §11 → SLO, §3 Structured violation JSON schema).
- NEVER present an NVDA/manual review row as the verification of record without the machine axe-core / colorjs.io / WebdriverIO output alongside it, and NEVER apply a retry-once to an a11y leg (per a11y-plan §11 → CI and → SLO).

## Contract bindings
- **a11y ↔ tests:** the driven arm's full firing form (incl. the quiet window) and the `sr*` families' preconditions are owned by tests §6, and the live-leg CI ban by tests §9; a11y-plan §9/§3 reuse them by reference — this chunk's basis artifacts are those same tests sections, so composition must not fork a11y's copy of the firing form from tests'.
- **a11y ↔ obs:** a11y violation/keyboard/contrast results fold into the obs §6 log envelope via `fingerprints[]` with obs §3 service identity (`service.name` = `conductor-tauri` / `conductor-ui`, `deployment.environment` = `CONDUCTOR_ENV`), per a11y-plan §3 — the shape W2's evidence record inherits for its a11y half.
- **a11y ↔ arch/CI:** a11y-plan §9's operator/local-gate-not-CI-gate rule derives from arch's "dynamic end-to-end scenario proof requires a live Pulse" note — the same rule the chunk's "never a CI gate" boundary asserts.

- (a11y) The composed invocation drives the a11y legs over the existing `@crabnebula/tauri-driver` + WebdriverIO session; no second browser-automation stack or parallel driver process is introduced (per a11y-plan §11 A11y Anti-Patterns → CI).
- (a11y) No CI workflow gains the `a11y:driven` or `a11y:sr*` legs — all three suite families remain operator/local-gated after the chunk (per a11y-plan §9 CI Integration, Pipeline integration).
