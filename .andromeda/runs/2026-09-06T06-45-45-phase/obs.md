# obs extract

## Relevance
Relevant — obs owns the record shapes, sinks, and env triggers this suite composes and the evidence it carries; the invocation's SHAPE (W1) and the CARRY-1 fork (W4) are not obs's call.

## Constraints
- The three CARRY-2 observables live on TWO different record shapes, governed differently: `Observation.degraded` and the persisted `latency_ms` are Run-report **envelope** fields (report seam → `runs/<run_id>.jsonl` + the `runs.db` row, eleven fields), while `preflight blocked: readiness gate not satisfied` is a **self-obs base line** (`timestamp_ms` / `level` / `target` / `service.{name,version,environment}` / `run_id`) in the CLI stream. "Asserted from persisted records" therefore means two different artifacts read two different ways (per obs-plan §3 Log format JSON schema, two record shapes).
- `latency_ms` is required to be `read_back_observed_at − journal_emitted_at` in wall-clock milliseconds from `std::time::SystemTime`, never tokio's virtual clock — the CARRY's "a subtraction, not a sum or quotient" restates the plan's own definition (per obs-plan §5 Per-surface metrics + §10 Performance budgets + §11 Project-specific bans).
- The degraded signal is **observed, not requested**: Pulse computes `degraded_mode` and returns it in the `retrieve_report` result; the read-back pass is `verify.readback.observe` and the signal rides a `warn` line on the allowlisted `message` field, with `degraded_mode_response` as the report-seam envelope extra. Any span attribute the suite wants must be a name in `conductor-core::redact::ALLOWLISTED_FIELDS` or the processor stage drops it silently (per obs-plan §4 Known-residual classification path).
- Agent mode is a **read-only trigger** — `agent_mode = --agent-mode flag || CONDUCTOR_AGENT_MODE env-set`, which Conductor never writes. A composed invocation that wants the `logs/agent-latest.jsonl` file sink must supply the flag or export the env itself; it is a WRITER switch, never a format switch (per obs-plan §3 Logging stack / agent-mode flag).
- `RUST_LOG` must use the additive form `info,{crate}=debug` — a bare per-target directive REPLACES the default and darkens every other crate — and neither form may be set for a leg that also executes the test suite, because the environment reaches the runner's child processes. W1 composes env blocks around `cargo test -p conductor-run --features live-pulse`, so this bears directly (per obs-plan §6 Per-module log levels).
- The Tauri backend sink's file NAME is fixed (`conductor-tauri.jsonl`) but its DIRECTORY rides `CONDUCTOR_RUNS_DIR` (`runs_dir.parent()/logs`) — recorded landing at `runs/logs/`, `runs/driven/logs/` and `runs/sr-leg/logs/` per a11y arm. An evidence collector spanning the driven / sr arms must resolve the path per leg, never read a project-root literal (per obs-plan §3 Log file location).
- The obs CI gates are exactly two — log conformance over `logs/agent-latest.jsonl` (§3 base schema, not the envelope) and zero-unlogged-panics — and they run on every CI job. Nothing in this chunk may add a live stage to them; the suite's evidence is a chunk `evidence/` artifact, not a CI artifact (per obs-plan §9 CI Integration + §11 CI bans).

## Patterns to follow
- The **capture/grade split at the harvest tier**: live claims are graded over committed frozen leg lines rather than asserted inline — the pattern the restart-suppression, severity-lifecycle and delegated-timing families all landed on, each reading its OWN exact allowlist leaf and never through `budget_ms`/`effective_deadline_ms` (which bound Conductor's MCP round-trip, not a Pulse-internal duration). W2 should reuse this rather than mint a second evidence convention (per obs-plan §4 restart-suppression / severity-lifecycle / Known-residual delegated-timing blocks).
- **Non-allowlisted identifiers ride the `message` field**: the precedent is the `verify.readback` observed-key-set witness, the `emit.batch` wire-shape witness, and the incident id on the lifecycle WRITE — names/ids only, never values, on the already-allowlisted `message` field so no new allowlist entry is needed. A leg name / arm name / SUT HEAD recorded in the self-obs stream should follow this (per obs-plan §6 Boundary-call wrappers).
- **Read boundaries log, they do not mint spans**: a rusqlite read inside a caller's span emits a boundary-call `info!` carrying `run_id` plus the outcome on `message`, with no `db.*` read span — the bounded set carries `db.insert_run` alone and is deliberately not widened (per obs-plan §6 Boundary-call wrappers, DB READ).
- **Span naming `{module}.{operation}` inside the bounded set** — `scenario.run`, `timeline.execute*`, `emit.batch`, `emit.logs_batch`, `verify.readback*`, `report.generate`, `db.insert_run`, `fault.silence/ramp/port_occupier`, `tauri.command.*` (per obs-plan §4 Span naming convention + §11 Spans / Traces).
- If the suite fires the connection-lifecycle conflict leg, `fault.port_occupier` carries `fault_type` + `port` **only** (neither duration nor journal offset is knowable at bind time), opens at the RAII bind site as a child of `timeline.execute`, and witnesses its realized hold on `message` at `debug` on release (per obs-plan §4 Fault-injection spans).

## Anti-patterns to avoid
- Never widen the bounded span-name set implicitly: a new suite verb that mints a span must fit `{module}.{operation}` within the existing set or take a plan amendment (the `emit.logs_batch` precedent), and never a high-cardinality name (per obs-plan §11 Spans / Traces).
- The "refuses to run a partial env rather than degrading to a silent `[BLOCKED]`" outcome must be a structured JSON line plus the sanitized `anyhow` edge — never unstructured stderr text, never an unlogged panic, never a multi-line backtrace (per obs-plan §11 Logs + §11 Error Reporting + §10 zero-unlogged-panics).
- Never leak an absolute host-file path or an internal struct name into the evidence artifact or any log line; the redaction layer's three application sites are a floor, not a bound on every channel (the standing warning) (per obs-plan §11 PII Scrubbing + §9 Log conformance check).

## Contract bindings
- **obs ↔ tests (harness contract):** the Run-report envelope schema is OWNED by test-plan §3 and obs §3/§6 reproduce it; the harvest targets consume obs's self-obs lines sliced from `agent-latest.jsonl`. The chunk's live-leg CI ban (test-plan §9) sits alongside obs §9's two CI gates — neither side may gain a live stage. A change to either side's record shape must land on both.
- **obs ↔ a11y:** the driven / sr arms move `CONDUCTOR_RUNS_DIR`, which moves the Tauri self-obs sink (obs §3 Log file location); the a11y leg's `<host-path>` scrub is a second line of defence for the host-path channel, not the only one (obs §11 PII Scrubbing).
- **obs ↔ security:** the sidecar spawn ban — fixed program NAME through inherited `PATH` + `.env(...)`, never a shell with operator-supplied input, and never with a visible console window — is a cross-master citation that moves on both sides together (obs §11 Project-specific bans).

## Acceptance criteria contributions
- The persisted `latency_ms` on the manual path equals `read_back_observed_at − journal_emitted_at` in wall-clock milliseconds — a subtraction, never a sum or quotient, and never read from tokio's virtual clock (per obs-plan §5 Per-surface metrics / §11 Project-specific bans). Whether `execute.rs:136` already computes it this way is research's question.
- The degraded observable is asserted from the report-seam envelope record (`state` = `KnownResidual` plus the `degraded_mode_response` extra) rather than from a request-side span attribute; any new field name outside `redact::ALLOWLISTED_FIELDS` emits nothing and must ride `message` instead (per obs-plan §4 Known-residual classification path).
- The `preflight blocked: readiness gate not satisfied` assertion reads the SELF-OBS base-line shape (`timestamp_ms` / `level` / `target` / `service.{name,version,environment}` / `run_id`) from the CLI stream, present on a not-ready gate and absent on a ready one (per obs-plan §3 Log format JSON schema / §9 Log conformance check). Whether that line currently carries the full base set, and which sink it lands in under each leg's env, is research's question.
- The chunk's `evidence/` artifact and every line it quotes carry no absolute host-file path (drive-letter, `/home`, `/Users`, `%APPDATA%`, `~/.cargo`, `.rustup`, backtrace file paths) in any field, with the allowlisted `target` module path preserved as an identity field rather than scrubbed (per obs-plan §9 Log conformance check / §11 PII Scrubbing).
