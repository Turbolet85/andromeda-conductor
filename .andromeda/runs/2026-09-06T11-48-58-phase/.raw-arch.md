# arch extract

## Relevance
Relevant — the gate's subject shapes, its artifact identity, its CI/test home, and the CARRY's `runs.db` grains are all arch-locked.

## Constraints
- The run-report envelope is a LOCKED shared shape: the eleven fields named at `architecture.md` §Standard Contracts — Run report envelope, with `verdict`/`state` as closed enums. That section further requires a Blocked row to populate identity fields only and emit the five measurement fields as JSON `null` — so "schema-complete" must mean *key present*, with explicit `null` conformant, never key-absent (per architecture.md §Standard Contracts — Run report envelope). The gate asserts this shape; §Standard Contracts is the registry, so a shape change is out of the chunk's authority.
- The journal carries a SECOND registered shape: the nine-key `CheckRecord` rides the per-run JSONL journal beside the envelope rows, on three surfaces, with the envelope byte-unchanged and a blocked/declare-only scenario emitting ZERO check records (per architecture.md §Standard Contracts — Per-check record). A gate that asserts envelope keys over every line contradicts this registered split. Whether the shipped writer emits both shapes discriminably today is research's question.
- Instant/stem forms are contract: `run_id` is the filesystem-safe hyphen-delimited stamp (also the journal's stem and the `runs.db` PK) while in-payload instants are colon-delimited RFC-3339, and `runs.db` TEXT instant columns take the JSONL envelope's wire form (per architecture.md §Standard Contracts — Timestamp formats; §Conventions — Data model conventions).
- `runs/&lt;run_id&gt;.jsonl` is registered as a SEPARATE artifact and schema from `logs/agent-latest.jsonl`, and the runs dir moves with `CONDUCTOR_RUNS_DIR` — the gate must resolve its subject through that handle, not a fixed path (per architecture.md §Occupied Resources — On-disk artifacts / database; — Environment variables).
- CI is build + test gating only; anything requiring a live Pulse (`mcp-server` feature + `ANDROMEDA_PULSE_MCP_ENABLED`) is an explicit operator/local gate and NOT a CI gate — so a build-failing gate must have a Pulse-free subject, run under the pinned `cargo nextest` zero-retry `ci` profile in `.config/nextest.toml` (no retries mask flakes), and clear the `ensure_frontend` build-order coupling if it runs in the workspace Rust job (per architecture.md §Infrastructure Patterns — CI/CD approach + Build system).
- Crate-per-seam module boundaries are compiler-enforced: `conductor-report` owns the JSONL journal + Markdown report + `runs.db` storage seam, `conductor-run` is the composition root, and `conductor-core` is the runtime-agnostic library every other crate depends on (the legitimate home of a shared host-path predicate). Gate code lands in an existing crate without minting a new cross-seam dependency edge (per architecture.md §Occupied Resources — Crate names; §Inherited Defaults — Module boundaries).
- `runs.db` is registered at THREE grains — `runs` keyed `(run_id, scenario)`, `run_check` keyed `(run_id, scenario, check_index)`, `run_envelope` keyed `run_id` — which is the grain set the CARRY's `cleanup` fix and its count-zero verification must match (per architecture.md §Occupied Resources — On-disk artifacts / database).

## Patterns to follow
- serde + serde_json is the canonical (de)serialization path for the envelope and the per-run journal — a typed parse discriminating the two line shapes needs no new dependency (per architecture.md §Stack — Serialization (JSON)).
- File artifacts are the agent-parseable ground truth and `runs.db` is a thin index over them — assert the gate over the journal, treating the DB as derived (per architecture.md §Design Philosophy — Journal-relative ground truth; §Established Decisions [Run-History Persistence]).
- Default-suite home precedent: pinned `cargo nextest` over the rstest/proptest/insta/assert_cmd/assert_fs/predicates dev-test stack, plus `cargo test --doc` for what nextest skips (per architecture.md §Infrastructure Patterns — Build system).
- Handle-less harness-owned artifact precedent: `runs/live-suite/{leg}.jsonl` is written by `scripts/agent-run.{sh,ps1}` with deliberately NO `CONDUCTOR_*` handle, deriving its path from the runs dir and clearing per invocation with a non-recursive delete — the model for any file the gate itself needs to produce (per architecture.md §Occupied Resources — On-disk artifacts / database).
- Storage-seam edits are raw SQL, no ORM/migrations, tables added additively — the CARRY's two added deletes belong in that idiom at the registered grains (per architecture.md §Established Decisions [ORM] None — raw SQL).

## Anti-patterns to avoid
- Minting a second definition of a shared notion — neither a second "host path" predicate outside `conductor-core` nor a second envelope/`CheckRecord` schema declaration outside §Standard Contracts, which declares itself the registry of shared shapes (per architecture.md §Standard Contracts; §Occupied Resources — Crate names).
- Adding a fourth `CONDUCTOR_*` handle class: the namespace is reserved for handles over artifacts this document already defines, and the settled classes are the defined-path handles, the two HOST dev-tool handles, and `CONDUCTOR_E2E_SEED_DIR` (per architecture.md §Occupied Resources — Environment variables).
- Routing a conformance violation through the verdict/error wall — it is a build/test failure, never a scenario verdict, a `Result::Err` from a seam, or a sixth `ReportState` variant (the state set stays closed at five) (per architecture.md §Cross-cutting Patterns — Verdict/error wall; §Conventions — Error handling).

## Contract bindings
- **arch ↔ obs:** the envelope + `CheckRecord` shapes are arch-owned (§Standard Contracts), while the host-path-freedom mechanism and the existing self-obs conformance gate the chunk must not duplicate are obs-plan's; arch's own host-path-freedom requirement appears only for readiness-gate precondition strings (§Standard Contracts — Readiness gate).
- **arch ↔ tests:** the gate's home binds to the pinned nextest `ci` profile and the `--e2e` fixture producer precedent (`CONDUCTOR_E2E_SEED_DIR`, read only by `crates/conductor-run/tests/envelope_fixture.rs`) (§Infrastructure Patterns — Build system; §Occupied Resources — Environment variables); the CARRY's `cleanup` contract half lives in test-plan + `.claude/rules/verification-harness.md`, arch owns only the three grains it must delete at.
- **arch ↔ security:** the CARRY adds two more interpolated `sqlite3` statements at the shells' `cleanup` verb; arch fixes the tables and keys, the injection posture is security-plan's call.

## Acceptance criteria contributions
- (arch) Every envelope line in `runs/&lt;run_id&gt;.jsonl` carries all eleven contract fields, with a Blocked row's five measurement fields present as JSON `null` rather than absent, and `verdict`/`state` within their closed enums (per architecture.md §Standard Contracts — Run report envelope).
- (arch) Every `CheckRecord` line carries all nine keys and is judged against the CheckRecord shape, not the envelope's — with `budget_ms: null` (inherited tier) accepted as conformant and zero such lines emitted for a blocked or declare-only scenario (per architecture.md §Standard Contracts — Per-check record; §Conventions — Data model conventions).
- (arch) The gate fails a build with no live Pulse in the loop and no new `CONDUCTOR_*` handle, running under the zero-retry `ci` nextest profile / the CI Rust job (per architecture.md §Infrastructure Patterns — CI/CD approach + Build system; §Occupied Resources — Environment variables).
- (arch) The `cleanup` verb deletes at all three registered `runs.db` grains — `runs` `(run_id, scenario)`, `run_check` `(run_id, scenario, check_index)`, `run_envelope` `run_id` — leaving no orphan at any grain (per architecture.md §Occupied Resources — On-disk artifacts / database).
