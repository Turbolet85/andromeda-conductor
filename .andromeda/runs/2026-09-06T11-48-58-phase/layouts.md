Whether the gate surfaces any cli line at all (vs. living only in CI/nextest) is research's question.
- Pipe discipline binds any new output: raw artifact data on stdout, human messages on stderr, ANSI auto-stripped when piped, `NO_COLOR`/`TERM=dumb` honored, no emoji in machine-parseable output (per layout-templates §Surface: cli — IA notes).
- The per-P-ID bracket-label set is **closed at six** (`[PASS]`/`[HOLD]`/`[FAIL]`/`[MANUAL]`/`[RESIDUAL]`/`[BLOCKED]`); run-level captions belong to the separate non-lamp qualifier SET (`[ENVIRONMENT-SUSPECT]`, `[PRECONDITION]`) printed outside the lamp column (per layout-templates §Surface: cli — Component — Primary content block 2). This reinforces the scope's "not a schema change" boundary: the journal's shapes back a rendered table, so a shape change is also a surface change.
- The eleven-field envelope record is the **render input** for the run-level load-envelope banner rendered on all three surfaces — cli `[ENVIRONMENT-SUSPECT]`, the Markdown report banner, the webview run-report banner — adapted per surface, never forked (per layout-templates §Surface: cli — Component — Primary content block 2 and §Surface: desktop-webview — Component — Primary content block 2). - The headless invariant: the agent-driven source-of-truth path is **never** gated on an interactive prompt (per layout-templates §Surface: cli — IA notes, Headless invariant). A build-failing gate must not introduce a prompt on that path.

## Patterns to follow
- The journal is already a documented render source: `conductor report <run_id>` re-prints a stored run as the colored 6-column results view **by reading the per-run JSONL journal**, while the on-disk `<run_id>.md` stays Markdown (per layout-templates §Surface: cli — Primary screens). Treat a row shape as a layout input, not just a storage detail.
- The per-check detail region in `runs/<run_id>.md` renders one indented plain-text line per expected check carrying its ordinal, comparison kind, verdict, `latency_ms` and the deadline judged against — the same grain as the nine-key `CheckRecord` (per layout-templates §Surface: cli — Component — Primary content block 2, per-check detail region). Its governing rule is the shape to reuse: **no new column, no new bracket label, no new ANSI or token entry**.
- The run-level qualifier form: printed **once per run**, above the verdict lines it qualifies, ASCII bracket label always printed so it survives `NO_COLOR`/piping, ANSI 246 reuse with no new entry, omitted entirely when not applicable (per layout-templates §Surface: cli — Output structure `conductor run <scenario>`).
- Surface entries name SETS and guard SHAPES rather than command literals (the de-literalization discipline running through the doc's verb/stage/count entries) — if this chunk moves the `cleanup` semantics, describe the table set by name, not by baked SQL.

## Anti-patterns to avoid
- Minting a seventh lamp / a new per-P-ID bracket label (or a sixth `ReportState`) for a conformance-gate outcome — the lamp set stays closed at six (per layout-templates §Surface: cli — Component — Primary content block 2).
- Emitting absolute host paths, internal struct names or stack traces in the gate's operator-facing output, or colorizing it when piped (per layout-templates §Surface: cli — Component — Footer / terminator + error output).
- Adding a column to either `comfy-table` shape — the 6-column results/SLO table or the 4-column coverage matrix — the two must not be conflated or widened (per layout-templates §Surface: cli — Component — Primary content block 1).
