# obs extract

## Relevance
Relevant — this chunk builds the run-report envelope conformance gate that obs-plan §9 explicitly reserves as "not-yet-built"; obs is the primary domain owner of the gate's schema, host-path and build-failure requirements.

## Constraints
- The gate's subject is the **scenario-RESULT record**, not the self-obs stream: obs-plan §9 (Log conformance check) requires the `logs/agent-latest.jsonl` gate to validate the §3 self-obs base-line schema and states the run-report envelope in `runs/<run_id>.jsonl` "gets its own (not-yet-built) conformance gate". The new gate must assert the envelope family only and must not re-assert or widen the existing self-obs gate (per obs-plan §9).
- The journal carries **two report-seam shapes**, so the gate must discriminate before asserting: obs-plan §3 (Log format JSON schema — two record shapes) requires the eleven-field envelope and the nine-key per-check `CheckRecord` to be separated by a typed parse, records the `CheckRecord` as a finer GRAIN beneath the envelope (never an extension of it), and states a blocked or declare-only scenario emits **no check line at all** — so a gate must tolerate envelope-only journals (per obs-plan §3).
- **Schema-completeness means key PRESENCE, not non-null values.** obs-plan §3/§6 define `read_back_observed_at` as null until read-back and null for blocked rows, and `latency_ms` as "integer or null (null for blocked rows)". A gate asserting non-null would false-fail every Blocked row — which is exactly the row a hermetic no-live-Pulse producer yields (per obs-plan §3 Log format JSON schema, §6 Log Coverage).
- **Field-count divergence inside obs-plan itself — load-bearing for the gate's field list.** §3 and §6's schema block both show **eleven** keys, but §6's "Required fields (every log line)" bullet list enumerates only **ten** (omits `read_back_observed_at`), and its "every log line" heading predates the two-record-shapes split. The 2026-06-16 amendment settled the count at eleven; the gate must assert eleven, and whether the shipped writer emits eleven is research's question (per obs-plan §3 + §6, amended 2026-06-16).
- **Obs derives the envelope, it does not re-author it.** obs-plan §6 reproduces the schema as a "binding contract from upstream-context §5 Test Plan Excerpt", §3 names test-plan §3 as the format owner for both shapes, and §1 (creator-explicit-telemetry trigger) states "the emission-journal format is owned upstream — obs DERIVES, does not re-author". A gate that would require a shape change is an escalation to the owner, matching the chunk's own "Not a schema change" boundary (per obs-plan §3, §6, §1).
- **Host-path freedom has exactly one definition.** obs-plan §11 (Logs) bans leaking absolute host paths or internal struct names in "logs / run-report / runs.db", and §11 (PII Scrubbing) pins single-location ownership in `conductor-core::redact`: the value scrub masks absolute host-FILE paths (drive-letter, `/home`, `/Users`, `%APPDATA%`, `~/.cargo`, `.rustup`, backtrace file paths) → `<redacted>`, and `::`-type/module tokens are explicitly NOT redaction targets. §9's existing gate mirrors that same anchor list. A second notion of "host path" is a violation (per obs-plan §11, §9).
- **Build-failing enforcement is already mandated, not merely implied by the entry.** obs-plan §10 (Build / deploy failure conditions) lists "CI log conformance gate: any runs.db / journal row with missing required fields or leaked absolute paths" as a build/deploy failure condition, and §9 requires the conformance gate to mark the CI check FAIL on schema violation (per obs-plan §10, §9).
- **The per-scenario extension point stands with no known instance.** obs-plan §3 (amended 2026-09-06) retires `degraded_mode_response` as never implemented and states nothing is known to exercise the extension point, while keeping the point open. The gate must therefore require no scenario extra, and must decide the extra-key policy without treating the open extension point as closed (per obs-plan §3, §6 Additional scenario-specific fields).

## Patterns to follow
- The three-step shape of the shipped obs CI gate (obs-plan §9 Log conformance check): read the artifact → assert every line carries its declared schema → assert no absolute host-file paths in any field → FAIL the CI check on violation. The chunk's "produce hermetically, then assert over it" precedent is the same shape.
- Mirror the redaction anchors from the single source rather than restating them — obs-plan §11 (PII Scrubbing) makes `conductor-core::redact` the owner, and §9's self-obs gate already mirrors that anchor list including the "preserve the allowlisted `target` module path" carve-out.
- Typed parse as the discriminator between the two report-seam shapes (obs-plan §3), rather than a key-union or one-shape-fits-all assertion.
- Redaction at the **report-generation / journal-write** site: obs-plan §11 (PII Scrubbing) enumerates three application sites — (a) tracing-subscriber field filter, (b) report generation when writing JSONL, (c) runs.db schema validation on insert. The run journal is site (b); whether the writer already applies it there is research's question. §6 (Boundary-call wrappers) additionally requires `redaction.apply_field_allowlist` to log a redaction warning when anything was scrubbed.
- Agent-parseable artifact handling if the gate lives in CI: obs-plan §9 (Telemetry artifact handling) uploads telemetry artifacts for agent download + `jq` parse, and §3 requires the journal be agent-parseable via `jq` / `serde_json`.

## Anti-patterns to avoid
- NEVER leak absolute host paths or internal struct names in logs / run-report / runs.db — but NEVER via blanket `::`-token redaction either; the allowlisted `target` module path is preserved and struct names are kept out by the field-name allowlist + `Display`-not-`Debug` at the anyhow edge (per obs-plan §11 Logs).
- NEVER hardcode scrubbing rules in a second location — a gate that mints its own host-path regex instead of mirroring `conductor-core::redact` violates the single-location ownership rule, and §11's standing warning is that the enumerated sites bound only the sites they name, never every channel (per obs-plan §11 PII Scrubbing).
- NEVER widen the bounded span-name set (`scenario.run`, `timeline.execute*`, `emit.batch`, `emit.logs_batch`, `verify.readback*`, `report.generate`, `db.insert_run`, `fault.*`, `tauri.command.*`) — relevant to the CARRY: §6 records that a `db.*` wildcard was deliberately NOT added, so a DELETE path (or the gate itself) mints no new `db.*` span name (per obs-plan §11 Spans / Traces, §6 DB READ convention).

## Contract bindings
- **obs ↔ tests (two-sided, D-tests-obs-harness):** test-plan §3 OWNS the journal format for BOTH shapes; obs-plan §3/§6 reproduce it as a binding contract ("obs aligns to tests, not vice versa"). Any field the gate asserts, and any divergence the gate's first run surfaces, moves on both sides together — the 2026-08-21 amendment set this precedent for the `CheckRecord`.
- **obs ↔ arch:** the Run report envelope is an arch §Standard Contract (obs-plan §1, conductor-report instrumentation-scope row) — the gate asserts the shipped contract, it does not extend it.
- **obs ↔ security:** the host-path/no-struct-name ban is a cross-master citation (obs-plan §11 Logs + Project-specific bans cite security-plan §2 "Leaking absolute host paths in run-report artifacts"); obs-plan §1 restates it for run-report artifacts. The CARRY's two added interpolated `sqlite3` DELETE statements are the security detector's surface, not obs's — obs's only claim there is that `runs` / `run_check` / `run_envelope` artifacts stay host-path-free (§11 Logs names `runs.db` explicitly).
- **obs ↔ the self-obs gate (intra-domain):** §9's existing `agent-latest.jsonl` gate and this envelope gate must stay disjoint by the §3 record-shape split; the redact field-allowlist governs the **self-obs line only** (per the 2026-08-21 amendment), so the envelope gate cannot lean on `ALLOWLISTED_FIELDS` for its field list.

## Acceptance criteria contributions
- (obs) Every envelope row in `runs/<run_id>.jsonl` carries all **eleven** envelope keys by PRESENCE, with `read_back_observed_at` and `latency_ms` permitted null on blocked rows (per obs-plan §3 Log format JSON schema + §6 Log Coverage).
- (obs) Each `CheckRecord` row is judged against its own nine keys and never against envelope keys — the gate discriminates the two report-seam shapes by typed parse, and an envelope-only journal (blocked / declare-only) passes (per obs-plan §3 two record shapes).
- (obs) No absolute host-FILE path (drive-letter, `/home`, `/Users`, `%APPDATA%`, `~/.cargo`, `.rustup`, backtrace file paths) appears in any journal field, with `::` module-path tokens NOT flagged, the notion sourced from `conductor-core::redact` rather than re-minted (per obs-plan §9 Log conformance check + §11 Logs / PII Scrubbing).
- (obs) A violation is RED — the gate fails the build rather than annotating it, and its first red run counts as a measurement finding about the shipped rows, not a gate defect (per obs-plan §10 Build / deploy failure conditions + §9 "On schema violation, agent marks CI check as FAIL (build gated)").
