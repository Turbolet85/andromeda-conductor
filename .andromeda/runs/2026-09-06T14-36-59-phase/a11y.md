# a11y extract

## Relevance
**Partial** — the gate's own surfaces (`conductor-core`/`-report`/`-cli`/`-emit`, CI YAML) are not-assertable a11y surfaces, but three touchpoints bind: the coverage-matrix out-of-scope Mode cell's token treatment, CARRY 4's `LoadEnvelope::classify` feeding the a11y-asserted load-envelope banner, and CI placement of a11y legs.

## Constraints
- The cli surface (the WHOLE `conductor` verb surface, `coverage` included) is **not-assertable** — a11y-plan §1 (A11y scope, `conductor-cli` entity) requires no ARIA/axe assertion on `conductor coverage`'s terminal output; its ASCII/NO_COLOR text-pairing is output-stream discipline, not an a11y verification path (per a11y-plan §11 Universal).
- A coverage-mode Mode cell tinted with `--status-residual` is a **coverage-mode classification, not a seventh lamp state** — a11y-plan §1 (Non-lamp reuse of a state token) requires the six-label not-color-alone assertion to key on the **lamp** display labels, and requires that Mode cell to carry its own always-rendered `not-conductors` text label (no glyph supplement) as its SC 1.4.1 signal. Whether the code already renders that label at every render site (webview `.cov__mode--out-of-scope` · cli ANSI 246 · Markdown emphasis) is research's question.
- a11y-plan §6 (Color contrast pairs) requires `--status-residual`/`--color-base` — the coverage-matrix out-of-scope Mode cell pair — asserted at **SC 1.4.3 AA 4.5:1**, not the 3:1 a non-text indicator owes, because the token colours TEXT there. Any mode-render change must leave that pair assertable.
- If CARRY 4 moves `check_load_envelope` / `LoadEnvelope::classify`, a11y-plan §4 (per-component catalog, run-level load-envelope banner row) requires the banner keep its non-lamp shape: `label` always rendered in the DOM plus optional `cause`, recessive `--status-residual` tint never the sole signal, **omitted entirely** when the run stayed in-envelope, and outside the lamp column.
- a11y-plan §9 (E2E row, routine-arm clause) requires the banner's label spec + rendered-DOM axe to assert against the arm's **seeded** over-envelope fixture written through the production writer; the rule stands that a spec whose DOM state the seeded subject cannot produce context-skips and **never passes green**. A classify change that invalidates the seed would therefore silently reduce coverage.
- a11y-plan §9 (Pipeline integration) + §3 (CI integration) require all three a11y suite families (routine `--e2e`, operator-only `a11y:driven`, screen-reader `a11y:sr*`) to stay **operator/local-gated, none CI-wired**. The chunk's added `rust`-job step must not fold any of them in, and "every existing CI gate green" cannot be read as an a11y CI obligation.
- a11y-plan §3 (Structured violation JSON schema) + §11 SLO require a11y-adjacent artifacts to carry no absolute host paths or internal seam-crate struct names, and to introduce **no new top-level fields** on the obs §6 envelope (rule-id / SC tag / selector ride `fingerprints[]`).

## Patterns to follow
- **Obs §6 envelope, narrowed not extended** — a11y-plan §3 (Structured violation JSON schema) folds every assertion result into the fixed obs envelope; the coverage gate's observable should follow the same "obs fixed the schema, the consumer narrows" discipline rather than inventing a parallel shape.
- **Seeded-fixture-through-the-production-writer** — a11y-plan §4 (banner row) / §9 record the routine arm seeding its own committed over-envelope subject via the production writer under `CONDUCTOR_E2E_SEED_DIR`, which is the established way to give a static, live-Pulse-free assertion a real subject; this chunk's gate is likewise static (scope §3 "needs no running SUT").
- **Token-name-bound contrast assertion** — a11y-plan §3 (Contrast verification harness) / §6 resolve named token pairs from compiled CSS via colorjs.io and emit `{ token_fg, token_bg, ratio, required, pass }`; any newly tinted classification cell follows that pattern, with raw values staying in design-system.
- **Display-label ↔ obs-enum crosswalk as the join** — a11y-plan §6 (State color tokens, State-naming crosswalk) is binding for joining a DOM label back to its journal row; a gate emitting per-mode counts must not introduce a competing label vocabulary.
- **One webview-automation stack** — a11y-plan §3 (tool pick) reuses the tests' `@crabnebula/tauri-driver` + WebdriverIO session; no parallel stack for anything this chunk adds.

## Anti-patterns to avoid
- NEVER treat the cli surface as accessibility-assertable — its ASCII prefixes / NO_COLOR pairing are not an ARIA verification path (a11y-plan §11 Universal).
- NEVER convey state by color alone — a state-token-tinted Mode cell or banner without its always-rendered text label is an SC 1.4.1 failure and, per §10, a build-failure condition (a11y-plan §11 Visual + §1 non-lamp reuse).
- NEVER CI-wire or lint-only-ize the a11y legs as a side effect of adding a CI step, and never stand up a second automation stack for them (a11y-plan §11 CI).

## Contract bindings
- **a11y ↔ obs** — a11y assertion/violation JSON aligns verbatim to the obs §6 log-format envelope (a11y-plan §3); the chunk's obs-plan §4 fields (`missing_p_ids` / `coverage_percent` / `p_id_count_expected` / `p_id_count_found`) are obs-owned, and a11y's stake is only that the DOM-label ↔ enum crosswalk (§6) still joins a rendered mode/lamp back to its journal row.
- **a11y ↔ design-system** — `--status-residual` over `--color-base` (Mode cell) and over `--color-raised-1` (banner) are the binding token pairs; names are the cross-skill anchor, raw values stay in design-system (a11y-plan §6).
- **a11y ↔ tests** — a11y rides the tests 5-command harness and emits through the `logs` command on the one `wdio run` webview job (a11y-plan §3 CI integration / §9); this chunk's CI step is in the Rust job and must not disturb that arrangement.
- **CARRY 4 ↔ a11y §4 banner row** — `LoadEnvelope::classify` is the producer of the DOM state the routine-arm banner label + axe specs assert; the classify/gate move and the seeded fixture must stay coherent or that a11y coverage degrades to a context-skip.

## Acceptance criteria contributions
- (a11y) Any state-token-tinted coverage-mode cell renders its own always-rendered text label (`not-conductors`) in DOM text-content, and the six-label lamp assertion does not treat it as a lamp state (per a11y-plan §1 Non-lamp reuse of a state token / §6 State color tokens).
- (a11y) The colorjs.io token-pair assertions `--status-residual`/`--color-base` (4.5:1, SC 1.4.3) and `--status-residual`/`--color-raised-1` (4.5:1, SC 1.4.3) still pass after any classification or Mode-cell render change (per a11y-plan §6 Color contrast pairs).
- (a11y) If CARRY 4 lands, the routine-arm load-envelope banner label spec and its rendered-DOM axe run (`wcag2a`/`wcag2aa`/`wcag21aa`, no reinstated `this.skip()` guard) against the seeded over-envelope fixture (per a11y-plan §4 per-component catalog, load-envelope banner row / §9 E2E routine arm).
- (a11y) The added CI step CI-wires none of the three a11y suite families; they remain operator/local-gated and no a11y assertion becomes a CI gate (per a11y-plan §9 Pipeline integration).
