## Constraints
- All code named in scope §5 lands in already-registered workspace members — `conductor-core`, `conductor-report`, `conductor-cli`, `conductor-emit` — with no new member and no new cross-seam dependency edge; crates are the compiler-enforced visibility boundary (per architecture.md §Occupied Resources → Crate names, §Established Decisions [Module Boundaries]). Note that [Module Boundaries] qualifies standalone per-seam BUILD as intent, not guarantee (it records `cargo check -p conductor-verify --lib` red at a 2026-09-04 measurement), so a new gate must not be premised on per-crate standalone compilation.
- The gate must preserve the **two-source** comparison: the accepted set is DATA (`contracts/pulse-capabilities.toml`) and the coverage classification is code-native (`coverage_matrix()`, a no-runtime-IO `static`); an accepted id with no row, or a classified id the manifest no longer accepts, is required to be a `CoreError::SutDrift` and "never a silent gap" (per architecture.md §Established Decisions [Accepted Capability Set]).
- A drift failure is a **harness fault on the `Result::Err` side**, never a `Verdict`/`ReportState` and never `Blocked` — the same rule the manifest-load path already carries ("a malformed / absent / unparseable manifest is a harness fault … never `Blocked` and never a silent widening") (per architecture.md §Cross-cutting Patterns → Verdict/error wall, §Established Decisions [Accepted Capability Set], [Error Handling]).
- Neither count may be a literal: `coverage_percent`'s in-scope denominator and `p_id_count_expected`'s full manifest count must both stay manifest-derived, per the de-hardcoding mandate that removed the compile-time `001..=060` bound and every "all 60 P-IDs" claim (per architecture.md §Established Decisions [Accepted Capability Set], §Conventions → Naming patterns).
- `contracts/pulse-capabilities.toml` must be resolved from the fixed `CapabilityManifest::default_path()` through `resolve_under` with **deliberately no `CONDUCTOR_*` override handle**; the reserved env namespace is enumerated and a gate adds nothing to it (per architecture.md §Occupied Resources → On-disk artifacts, Environment variables).
- `coverage-matrix.md` is a **registered occupied resource** at the repo root (§Occupied Resources on-disk artifacts) and its complete form is named "the definition of done" (§Cross-cutting Patterns → Scope law), with the directory tree placing it at the workspace root. CARRY 2's fork therefore cannot be settled silently: any resolution other than "the complete file is the artifact" moves an arch mandate and owes an amendment at wrap. Whether the file exists at HEAD is research's question (scope §1.1 records it absent).
- The added CI step must stay inside the **build + test only** gating model — GitHub Actions runs `cargo build` / `cargo nextest` (zero-retry `ci` profile, "no retries mask flakes") / `cargo clippy`; anything requiring a live Pulse is an operator/local gate, never CI (per architecture.md §Infrastructure Patterns → CI/CD approach, Build system; §Established Decisions [CI/CD]).

## Patterns to follow
- The **paired integrity-gate shape**: `check_sut_drift` (manifest ↔ classification set-equality) and `check_scenario_backing` (`UNBACKED_AUTO` held to exact-set equality against the committed catalog, "so the ledger can only shrink under compulsion") are two gates on distinct axes — a new gate surface follows that exact-set-both-directions idiom rather than inventing a tolerance (per architecture.md §Established Decisions [Accepted Capability Set]).
- **Contract-artifact resolution**: every `contracts/*.toml` manifest is runtime-read and bounds-checked at load, resolved from a fixed `*::default_path()` through `resolve_under`, with no env override — the shape `pulse-capabilities` / `pulse-load-envelope` / `pulse-run-contract` all share (per architecture.md §Occupied Resources → On-disk artifacts).
- **Shared-basis discipline** for CARRY 4: `check_load_envelope` (static catalog gate) and `LoadEnvelope::classify` (the per-run `[ENVIRONMENT-SUSPECT]` caption) read ONE basis "so the gate and the caption cannot mean different things", and the `[[exempt]]` ledger is held at exact-set equality in both directions (per architecture.md §Occupied Resources → `contracts/pulse-load-envelope.toml`).
- **Pulse-consistency transcription** for CARRY 5: where Conductor mirrors a SUT-owned definition, the definition is the SUT's choice, transcribed and version/HEAD-cited — the blake3 fingerprint precedent ("the algorithm is the SUT's choice, not Conductor's", byte-verified against a named Pulse HEAD) (per architecture.md §Stack and Technologies → Hashing/digest, §Established Decisions [Read-Back Dependency Posture]).
- **Self-observation stack**: obs-plan §4's spans/fields ride `tracing` 0.1.44 + `tracing-subscriber`, explicitly NOT an OTel SDK — OTLP is the PRODUCT emission only (per architecture.md §Stack and Technologies → Self-observation).

## Anti-patterns to avoid
- Do not source the coverage classification from the manifest to make the gate pass — architecture.md §Established Decisions [Accepted Capability Set] states that doing so "would collapse [the two-source comparison] into a self-check"; the deliberate two-source shape is the gate's whole value.
- Do not add a `CONDUCTOR_*` (or any) env handle, a new workspace crate, or a new `contracts/` artifact path for the gate — the capability manifest deliberately carries no override handle and the env namespace is a closed enumeration (per architecture.md §Occupied Resources → Environment variables, On-disk artifacts).
- Do not make the CI gate depend on a live Pulse, MCP read-back, or OTLP egress — dynamic proof is an explicit operator/local gate, and CI has no Pulse instance (per architecture.md §Established Decisions [CI/CD], §Infrastructure Patterns → CI/CD approach).
