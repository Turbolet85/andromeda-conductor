## Patterns to follow
- **Verb registration**: each cli verb's entry in §cli Primary screens carries its output shape plus its exit rule; `preflight`, `preconditions`, `coverage` and `cleanup` all set this precedent (per §cli Primary screens). A gate that changes `coverage`'s exit behaviour registers there, not in architecture.
- **SET-naming over literals**: name the derived source, never bake the count — §cli Primary screens states "every number manifest-derived (never a literal)" and §cli Primary navigation names the verb set as whatever `Commands` declares.
- **Run-level qualifier outside the lamp column**, adapted per surface never forked (the `not-conductors` Mode-cell and `[ENVIRONMENT-SUSPECT]` / `[PRECONDITION]` precedents, §cli Component — Primary content block 2) — the shape to reuse if the gate needs any user-facing signal.
- **Indented detail line, not a new column**, for extra per-row grain (the `Blocked` precondition string, the `KnownResidual` note, the per-check detail region in `runs/<run_id>.md`) — §cli Component — Primary content block 2.
- **Recessive treatment for non-outcome states**: `--status-residual` ↔ ANSI 246 ↔ Markdown emphasis, with the label always rendered so it survives `NO_COLOR` / piping (per §Component — Primary content block 1, Mode cell).

## Anti-patterns to avoid
- Adding a column (or a `--format`-less shape change) to either `comfy-table` — breaking for downstream agent parsers (per §cli IA notes — Command model).
- Reusing any lamp-set token / bracket label (`[FAIL]`, `[BLOCKED]`) for a gate result — out-of-scope and gate states are REMIT/qualifier, not a verdict; the lamp set stays closed at six (per §Component — Primary content block 1 Mode cell; §cli Component — Primary content block 2).
- Re-pinning a fresh literal count in the roll-up caption sample — the de-literalized `(N unbacked)` placeholder form is the standing resolution after three re-stales (per §cli Primary screens; amendment 2026-08-16).
