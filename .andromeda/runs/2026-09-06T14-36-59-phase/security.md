## Constraints
- The gate's subject manifest and CARRY 4's load envelope are registered input boundaries: `contracts/pulse-capabilities.toml` and `contracts/pulse-load-envelope.toml` must resolve from a fixed `default_path()` through `resolve_under` with **deliberately no `CONDUCTOR_*` override handle**, read faults carrying `e.kind()` only (never the path), and absent/malformed being a hard harness fault — never defaulted, never silently widened (per security-plan §Input Validation, committed SUT-facing manifests row). The gate must not add an override handle to reach either.
- CARRY 4 must not be absorbed by the `[[exempt]]` ledger: §Input Validation requires strictly positive `[envelope]` terms and **no duplicate or reason-less `[[exempt]]` entry**; a rate-term correction that keeps the gate green by adding an exemption without a stated reason violates the same row's never-silently-widened rule (per security-plan §Input Validation).
- The gate's failure output and any artifact it commits must carry verdict/state/identity fields only — **no absolute host paths, no internal seam-crate struct names, no stack traces** (per security-plan §Security Anti-Patterns → Logging, and §Error Handling run-report artifact sanitization). Whether `coverage-matrix.md` counts as one of the enumerated committed-record classes is a wording question that CARRY 2 option (a) would create; the ban's intent covers agent-parseable records shared across hosts.
- If the gate is placed as a non-zero exit on `conductor coverage` (P4 fork 2), the failure crosses the type-erased `anyhow` CLI edge, which §Error Handling requires to be sanitized (no paths / library versions / internal struct names) before reaching the operator (per security-plan §Error Handling, external responses).
- CARRY 5's eighth category is the provider-key/secret-token class (scope §CARRY 5 cites Pulse's `sk_live_…` · `sk-proj-…` · `ghp_…` · `AKIA…` matrix). §Security Anti-Patterns → Secrets bans committing **any secret-shaped string** to the `conductor-*` workspace, and §Secret Management names API keys and third-party tokens as the scanning gate's invariant subjects. Whether the shipped seven-category corpus already commits literal samples, and by what construction they are provably non-live, is research's question.
- The added CI step must leave the workspace's dependency-security controls green: `cargo audit` plus `cargo deny check advisories bans licenses sources` over a committed, un-drifted `Cargo.lock` (per security-plan §Dependency Security, CI integration; §Security Anti-Patterns → Universal, first two bullets). The 2026-09-05 re-adjudication means the audit is expected green with no standing deferral.
- If the gate's `db.query_all_p_ids` span (obs-plan §4) resolves to a `runs.db` query rather than a manifest read, rusqlite **bound parameters** are required — never `format!`/concatenated SQL (per security-plan §Input Validation `runs.db` row; §Security Anti-Patterns → Input). Which seam that span actually reads is research's question.

## Patterns to follow
- Read the manifests through the shipped fixed-path loader shape (`CapabilityManifest::load` / `LoadEnvelope::load` idiom: fixed `default_path()` → `resolve_under`, explicit `validate()` in `conductor-core`) rather than a fresh path read at the gate site (per security-plan §Input Validation, committed manifests row).
- The host-path-free failure-origin idiom from the immediately prior chunk's conformance gate — a failure names the handle and the file's own name, never a resolved path via `path.display()` (per security-plan-amendments `2026-09-06-run-report-envelope-conformance-gate`, family (a)).
- Typed `thiserror` enums internally, collapsing to `anyhow` only at the `conductor-cli` edge; `sanitize_error` on every `Err` crossing a `#[tauri::command]` boundary (per security-plan §Error Handling).
- `e.kind()`-only rendering for manifest read faults, so the artifact-hygiene rule holds even on the error path (per security-plan §Input Validation, committed manifests row).
- For CARRY 3's recurring create-inspect-delete cost: the operator precedent is the file's own **non-recursive** clear idiom (`rm -f …/*.ext` / `Remove-Item '…/*.ext'`), never a recursive delete on a path derived from an operator-supplied handle (per security-plan-amendments `2026-09-06-operator-gated-live-suite`).

## Anti-patterns to avoid
- NEVER introduce a `CONDUCTOR_*` override handle for the capability manifest, the load envelope, or a `coverage-matrix.md` write target — the SUT-facing manifests are deliberately non-operator-steerable; and any new env path handle read by a **shipped** binary carries the `std::fs::canonicalize` + bounds-check duty at the `conductor-cli` edge, with the duty binding per READER (per security-plan §Security Anti-Patterns → Input, canonicalize ban, as restated 2026-09-06).
- NEVER let the gate emit or commit an absolute host path or an internal seam-crate struct name — in the artifact, the CI step's log, or the assertion failure text (per security-plan §Security Anti-Patterns → Logging).
- NEVER commit a secret-shaped literal for CARRY 5's provider-key category; the corpus is synthetic fixture data and the no-secrets invariant must hold over time (per security-plan §Security Anti-Patterns → Secrets; §Secret Management).
