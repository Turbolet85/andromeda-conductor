## Constraints
- The gate's assertion must be **set-equality against the SUT capability manifest's accepted set** with every capability in exactly one of the four `CoverageMode`s and zero unclassified entries — explicitly **no literal count and no P-ID range** (per test-plan §1 Critical Path 6, and §4's unit-coverage line for the scenario-catalog + coverage-matrix entity). Whether the shipped classification already satisfies set-equality is research's question.
- A missing `P-XXX` must **fail the gate at a non-zero exit** — the gate is a hard-`Fail` class, not a reported envelope state (per test-plan §6 Coverage-matrix completeness gate). Whether any shipped surface (`conductor coverage`, a Rust test target) already produces that non-zero exit is research's question.
- The gate is **unit-tier, static, over committed artifacts — no live Pulse — so it runs in CI**, the footing §6 already assigns `check_sut_drift`'s sibling leg (per test-plan §6 Scenario-backing leg). The live-Pulse ban on CI gates is unchanged in force (per §11 CI).
- Whatever CI step lands must leave every §9/§10 **build-failure condition** green: nextest 100/101, `--fail-under-lines 60`, clippy `-D warnings` + fmt, bare `cargo audit` + `cargo deny check`, un-drifted `Cargo.lock`, toolchain ≥ 1.94.1 (per test-plan §9 Build failure conditions + §10 Build failure conditions).
- The suite must be green under **both runners** — `cargo nextest run -p <crate>` and `cargo test -p <crate>` — a runner-dependent result being a determinism break, not a runner quirk (per test-plan §4 Framework + §10 Zero-flakiness budget).
- If CARRY 2 resolves to committing `coverage-matrix.md`, §7 requires the committed artifact carry its **MEANING under test**: a round-trip through the production reader/writer (the `lamps_fixture.rs` / `envelope_fixture.rs` precedent), not mere parseability (per test-plan §7 Self-bootstrapping requirement).
- CARRY 4/CARRY 5 freight rides the same per-seam discipline: pure-function unit coverage per touched seam crate (`conductor-core` load-envelope, `conductor-emit` PII catalog), plus the per-chunk **scoped mutation audit** against the touched crates — operator-local, never a blocking CI stage, gated on the `mutants.out/` tallies and never on the exit code (per test-plan §4 Mutation instrument + §9 Scoped mutation audit).

## Patterns to follow
- **The sibling-gate shape** already specified for the second axis: exact-set equality in **both directions**, unit-tier, over committed artifacts, CI-runnable — §6 states it runs "like its `check_sut_drift` sibling", so the sibling's tier is the template for raising this one (per test-plan §6 Scenario-backing leg).
- **assert_cmd exit-code assertion at the cli edge**: `Command::cargo_bin("conductor")` inside the owning package (`CARGO_BIN_EXE_conductor` from any other package), asserting exit code + NO_COLOR-stable stdout labels (per test-plan §6 Drivers per surface, cli row; §5 Driver(s)).
- **A cli-edge test of a verb that writes no run artifacts sets `CONDUCTOR_RUNS_DIR` NOT AT ALL** — the handle is repo-relative and `resolve_under` rejects an absolute `temp.path()` at `Paths::resolve()`, before dispatch (measured on the `conductor preconditions` edge tests) (per test-plan §3 Per-test isolation). `conductor coverage` is in that class.
- **insta golden / static row-count check** for the rendered matrix, CI fail-don't-write mode, never `cargo insta review` (per test-plan §6 verification signal + §7 Golden artifacts + §11 Universal).
- **rstest `#[rstest]` + `#[case]` table rows over the manifest's accepted set** (never a hand-listed id range) for per-capability classification matrices (per test-plan §3 Test data bootstrap Mechanism + §4 Fixture pattern).

## Anti-patterns to avoid
- NEVER reintroduce a literal capability count or `P-001..P-0NN` range into the gate, its fixtures, or its selectors — the manifest-derived SET is the anchor (per test-plan §1 Critical Path 6 + §6 Selector strategy).
- NEVER let a reported state (`Blocked`/`ManualCheck`/`KnownResidual`/`CalibrationRegion`) become the gate's non-zero exit, and NEVER assert on implementation details or fixture-internal values instead of the public seam contract (per test-plan §11 E2E + §11 Unit).
- NEVER make the new gate green by adding nextest `retries`, lowering `--fail-under-lines 60`, or skipping a quality gate "just this once" (per test-plan §10 Zero-flakiness + §11 Quality).
