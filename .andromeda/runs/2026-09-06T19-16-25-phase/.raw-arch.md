# arch extract

## Relevance
**Relevant** — the chunk edits declarative scenario config, is judged by the load-envelope gate, changes a scenario's report-state routing class, and rides the live-leg firing form: all four are arch-locked surfaces.

## Constraints
- **Workspace placement is fixed and the chunk should need no new crate.** The scenario model + its load-path validation live in `conductor-core`; the read-back routing (`route_read_back` / `ReadBack {Graded, AutoResolved, Blocked}`) is crate-private to `conductor-run`, the run composition root above the seams and below both bins; `crates/conductor-run/tests/` is where the harvest assertion sits (per architecture.md §Occupied Resources — Crate names · §Established Decisions [Module Boundaries]). Scope §4's "`conductor-core` scenario model — only if needed" is exactly the right crate if a model change is required.
- **The re-driven emission shape must clear BOTH asserted load-envelope terms per EMITTING PHASE, unaided.** No phase declaring occurrences may run longer than `max_sustained_storm_ms` nor emit faster than `max_sustained_rate_spans_per_s`, the rate judged as **wire records** — `occurrences × EmissionSpec::max_spans_per_dispatch() × 1000 &gt; max_rate × gap_ms`, exact integer math, an upper BOUND because the rate curves carry seeded jitter and the static gate has no seed. `max_scenario_duration_ms` is recorded but NOT asserted, so a long *elapsed* scenario is not itself a breach (per architecture.md §Occupied Resources → `contracts/pulse-load-envelope.toml`).
- **`slo_tier` is a closed three-value set (`&lt;5s` / `&lt;20s` / `&lt;90s`) and the tier deadline is a CEILING, not the deadline itself.** Latency is always journal-relative (`read_back_observed_at − journal_emitted_at`), never wall-clock-from-test-start; a check may declare sub-tier `budget_ms` and is graded against `ExpectedCheck::effective_deadline_ms(tier)` (per architecture.md §Established Decisions [Timing-Tolerance Model] · §Conventions — Data model conventions). The re-tier is therefore sized against the MCP round-trip, not against the scenario's own 6000 ms of gaps.
- **A `[[checklist]]`-beside-`[[expected]]` conflict is a LOAD-PATH fault, not a verdict.** Sibling-spanning invariants cannot be garde validators under 0.22.1 (a field-level `custom` sees no sibling), so the rule ships as `Scenario::check_checklist()` invoked from `from_toml_str`, raising `CoreError::Config` — an `Err`, on the harness-fault side of the verdict/error wall (per architecture.md §Established Decisions [Validation Library] · [Scenario Config Format] · §Design Philosophy "Outcomes are values, errors are harness faults").
- **Gaining an `[[expected]]` check changes the scenario's report-state class.** The auto-resolve/empty-active-list route to `KnownResidual` is confined to declare-only scenarios; a checks-bearing scenario hitting an empty active list lands `Blocked` with the named precondition, while the degraded read-back route to `KnownResidual` is NOT so gated and `state_for` returns `KnownResidual` iff `observation.degraded` (per architecture.md §Established Decisions [Read-Back Dependency Posture] · §Standard Contracts — Run report envelope, which lists `halo-hue-encoding` in the eight declare-only families).
- **A graded check newly emits per-check artifacts on three surfaces.** A blocked or declare-only scenario emits ZERO `CheckRecord`s; the nine-key record rides the per-run JSONL journal, the `run_check` table (`latency_ms`/`deadline_ms` **NOT NULL**, `budget_ms` NULL on inherit) and an indented Markdown detail line (per architecture.md §Standard Contracts — Per-check record · §Conventions — Data model conventions).
- **`CONDUCTOR_*` is the only namespace Conductor reserves; `ANDROMEDA_PULSE_*` handles are Pulse-side and asserted NOT set by Conductor** — they are READ (contract `shell-declaration` terms / `conductor preconditions` subjects). Config precedence is files over env defaults, CLI flags over env, and live legs are operator/local gates, never CI (per architecture.md §Occupied Resources — Environment variables · §Cross-cutting Patterns — Config management · §Established Decisions [CI/CD]). This governs how any `ANDROMEDA_PULSE_BASELINE_BOOTSTRAP_SECONDS` posture may reach a leg — arch registers no such handle today, so whether it must be registered (or stays purely operator-side firing form) is a P3/P5 question.

## Patterns to follow
- **Emission is declared data, validated in place.** A phase's shape is `EmissionSpec { signal, occurrences, shape }` where `occurrences: 0` is a deliberate silence window and the shape selects its emit-primitive family; nested spec fields must `dive`, never `skip`, or garde never descends (architecture.md §Conventions — Config conventions · §Established Decisions [Validation Library]). Whether the shipped `EmissionShape` arms already carry a shape that sustains through formation — and whether `max_spans_per_dispatch()` already has an arm for it — is research's question.
- **Sibling-spanning rules go to the load path, not garde.** `Scenario::check_capabilities` / `check_budgets` / `check_checklist` are the shipped precedent, all called from `from_toml_str` and all mapping to `CoreError::Config` (architecture.md §Established Decisions [Validation Library]).
- **One shared basis for the load judgment.** `phase_rate_exceeds` has exactly one caller, `phase_breach`, whose only callers are `check_load_envelope` (static catalog gate) and `LoadEnvelope::classify` (the per-run `[ENVIRONMENT-SUSPECT]` caption), so gate and caption cannot diverge — any sizing change must go through that chain rather than around it (architecture.md §Occupied Resources → `contracts/pulse-load-envelope.toml`).
- **Attribution rides the emitted service identity.** `conductor` (`DEFAULT_SERVICE_NAME`, dispatcher) vs `conductor-canary` (`CANARY_SERVICE_NAME`, preflight warm-up + storm), split deliberately because Pulse keys per-service sample counts and error-rate EWMAs (architecture.md §Occupied Resources — Service/process names). This is the discriminator DoD 1's "attribution provable, not assumed" leans on.
- **Live-leg self-observation is captured per leg.** `runs/live-suite/{leg}.jsonl`, harness-owned by `scripts/agent-run.{sh,ps1}`, deliberately with NO `CONDUCTOR_*` handle of its own, leg-stemmed and cleared at suite start — the durable read for a multi-leg proof, since `logs/agent-latest.jsonl` truncates per invocation (architecture.md §Occupied Resources — On-disk artifacts).

## Anti-patterns to avoid
- **Do not reach for an `[[exempt]]` entry to make the sustained window fit.** The ledger is EMPTY and held at exact-set equality in both directions so it can only shrink under compulsion (architecture.md §Occupied Resources → `contracts/pulse-load-envelope.toml`); scope §4 already calls it a last resort, and arch makes that a domain ban, not a preference.
- **Do not bind a Pulse-internal duration to `budget_ms` / `effective_deadline_ms`, and do not measure from wall-clock-at-test-start.** Those grade Conductor's own journal-relative MCP round-trip only (architecture.md §Established Decisions [Timing-Tolerance Model] · §Design Philosophy "Journal-relative ground truth").
- **Conductor must not SET any `ANDROMEDA_PULSE_*` variable, manage the Pulse process, or add a handle outside `CONDUCTOR_*`.** Arch asserts the Pulse-side flags are not set by Conductor and the scope law bans Pulse process management (architecture.md §Occupied Resources — Environment variables · §Cross-cutting Patterns — Scope law).

## Contract bindings
- **Run report envelope + `CheckRecord` → tests + obs:** the eleven-field envelope is byte-unchanged, but a scenario leaving the declare-only set starts writing `run_check` rows and Markdown per-check lines for the first time — test fixtures/goldens and the JSONL journal schema both consume those shapes (architecture.md §Standard Contracts).
- **Declare-only family enumeration → report/tests:** `halo-hue-encoding` is named in the eight-family list; if it gains an `[[expected]]` check the enumeration and its `verdict: null` claim move, which is wrap-amendment territory for arch and a golden/expectation change for tests.
- **Load-envelope asserted terms → tests:** `check_load_envelope` is the static gate over the committed scenario catalog, so any re-shaped phase is gated by an existing test surface, not only at runtime.
- **Firing form (`scripts/agent-run.{sh,ps1}` `run --live` + operator launch) → obs + tests harness:** the bootstrap posture, the `PATH` prefix resolving the sidecar, and the `CONDUCTOR_PREFLIGHT_TIMEOUT` floor all ride the same firing form; the per-leg capture site is arch-registered (architecture.md §Occupied Resources — Service/process names · Environment variables · On-disk artifacts).
- **`slo_tier` closed enum → storage seam:** the `runs` TEXT column accepts exactly `&lt;5s`/`&lt;20s`/`&lt;90s`, so the re-tier is constrained by a persisted column type fixed on first write (architecture.md §Conventions — Data model conventions).

## Acceptance criteria contributions
- (arch) Every emitting phase of the re-driven scenario passes both asserted load-envelope terms **unaided**, with the rate judged as wire records (`occurrences × max_spans_per_dispatch() × 1000 &gt; max_rate × gap_ms`), and `contracts/pulse-load-envelope.toml`'s `[[exempt]]` ledger stays empty (per architecture.md §Occupied Resources → `contracts/pulse-load-envelope.toml`).
- (arch) The scenario's `slo_tier` is one of the closed three values and is chosen against journal-relative latency (`read_back_observed_at − journal_emitted_at`), never against the scenario's own elapsed duration (per architecture.md §Established Decisions [Timing-Tolerance Model] · §Conventions — Data model conventions).
- (arch) The `[[checklist]]` / `[[expected]]` resolution is enforced on the load path — a scenario declaring both fails `Scenario::from_toml_str` with `CoreError::Config` (a harness fault on the `Err` side of the verdict/error wall), never as a verdict or a silent acceptance (per architecture.md §Established Decisions [Validation Library] · [Scenario Config Format]).
- (arch) Any bootstrap-window posture reaches the leg through the operator's firing form; no shipped Conductor code sets an `ANDROMEDA_PULSE_*` variable and no new configuration handle is added outside the reserved `CONDUCTOR_*` namespace (per architecture.md §Occupied Resources — Environment variables · §Cross-cutting Patterns — Config management).
