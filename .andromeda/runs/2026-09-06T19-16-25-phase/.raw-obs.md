## Relevance
Relevant (partial) — obs owns the grading surface (harvest tier, `slo_tier` enum, envelope/check-record shapes) and the instrumentation discipline for the sustained window; it does not own the scenario's phase design or the load-envelope sizing.

## Constraints
- `slo_tier` is a CLOSED enum (`&lt;5s` | `&lt;20s` | `&lt;90s`) with fixed thresholds 5000/20000/90000 ms, and the SLO is a JSON field assertion evaluated at report-generation time over `latency_ms = read_back_observed_at − journal_emitted_at` (wall-clock) — so the re-tier must be sized against Conductor's own MCP round-trip, never against a Pulse-internal hue duration (per obs-plan §5 Per-surface/per-path metrics, §10 Performance budgets, §11 SLO).
- The delegated hue budget must grade at the HARVEST tier over Pulse's own tracing lines, read from its OWN exact allowlist leaf, and NEVER through `budget_ms`/`effective_deadline_ms`; obs-plan records the field as `duration_ms` on `metric.constellation.hue_update_ms` (non-uniform across the family — `value` on `metric.report.render_ms`) (per obs-plan §4 Known-residual classification path → Delegated-timing family).
- `halo-hue-encoding` must add NO critical path of its own — it reaches the Known-residual classification path and rides the standard chain (`scenario.run` → `timeline.execute` → `emit.batch` → `verify.readback*` → `report.generate`) plus the eleven-field envelope alone; the fixed 7-path count is a tier-justification input, so an eighth row is not to be added incidentally (per obs-plan §1 Critical paths (must-trace), §4 Known-residual classification path).
- No new span name may be minted for the sustained emission window — the span-name set is bounded and closed (per obs-plan §11 Spans / Traces). If the re-driven phase data declares `occurrences: 0` or `EmissionShape::Ramp`, the existing `fault.silence`/`fault.ramp` spans govern (created-not-entered children of `timeline.execute`, `info` lifecycle, `ramp_factor` as the signed −1.0..1.0 slope) (per obs-plan §4 Fault-injection spans). Whether the code already opens those spans for the phase kinds this chunk adds is research's question.
- Adding an `[[expected]]` check changes the emitted record set: the report seam then writes per-check `CheckRecord` lines (nine keys incl. `deadline_ms`/`budget_ms`) as a finer grain beneath the envelope, whereas a declare-only scenario emits no check line at all; the envelope's eleven fields are unchanged and neither report-seam shape passes the span-attribute allowlist (per obs-plan §3 Log format JSON schema — two record shapes).
- The scenario TOML gains nested emission spec fields, which must remain garde-validated — a nested spec field must `dive`, never `skip`, and the shipped error encoding is `error_percent` ∈ 0..=100 (per obs-plan §11 Project-specific bans).
- Any `RUST_LOG` carried by the live-leg firing form must use the ADDITIVE form `info,{crate}=debug` — a bare per-target directive replaces the default and blanks the rest of the self-obs stream — and must never be set for a run that also executes the test suite (per obs-plan §6 Per-module log levels).

## Patterns to follow
- Harvest-tier grading over Pulse's own structured lines in a per-family harvest test (`conductor-run/tests/delegated_timing_harvest.rs`), each budget read from its own exact leaf — the established shape for the restart-suppression and severity-lifecycle families (per obs-plan §4 Known-residual → Delegated-timing family; §4 Severity-lifecycle Required log fields).
- Redacted-counter workaround for the `AutoResolved` re-proof: obs-plan records `triage.incident.auto_resolve.tick`'s `resolved_count`/`evaluated_count`/`duration_ms` as reading `"&lt;redacted&gt;"` live under Pulse's default-deny allowlist, so the auto-resolve witness is the UNREDACTED `incidents.list_active.request` `item_count` transition to empty, corroborated by read-back only where the list actually empties (per obs-plan §4 Severity-lifecycle Required log fields).
- Attribution where the Pulse line carries no service identity: the severity family attributes by `persistence_seconds` precisely because `triage.cue.emit` carries no service field. The chunk's canary-vs-dispatcher discriminator (`conductor-canary` vs `conductor`) therefore depends on whether the hue leaf carries a service identity at all — that is research's question, not something the plan attests (per obs-plan §4 Severity-lifecycle Required log fields; §3 Service identity).
- Message-field escape hatch for any new witness detail (counts, key sets, ids): a span-attribute name absent from `conductor-core::redact::ALLOWLISTED_FIELDS` is dropped at the processor stage, so new detail rides the already-allowlisted `message` field rather than a new attribute (per obs-plan §4 Required span attributes heading; §6 Boundary-call wrappers).
- Service identity is env-resolved, never hardcoded (`$CONDUCTOR_SERVICE_NAME` override; version from the manifest; `deployment.environment` from `CONDUCTOR_ENV`) — the identity split the chunk leans on rides this mechanism (per obs-plan §3 Service identity; §11 Universal).

## Anti-patterns to avoid
- NEVER mint an OTel metrics instrument / histogram for the hue budget — Minimal tier has no metrics backend and the SDK is banned for self-observation; the budget is a field assertion plus the harvest read of Pulse's line (per obs-plan §11 Metrics, §11 Telemetry Strategy).
- NEVER log at `info` inside the sustained emission's per-record loop — hot-path detail stays `debug`/`trace` (the `emit.batch` wire-shape witness is explicitly `debug`), and a longer window must not turn one-per-phase spans into per-record spans (per obs-plan §11 Logs, §11 Telemetry Strategy; §6 Boundary-call wrappers).
- NEVER let absolute host paths reach logs, run-report artifacts or committed evidence — the leg dirs this chunk cites resolve under `%TEMP%/pulse-legs/`, and the plan's standing warning is that the enumerated application sites bound the sites they name, never every channel (per obs-plan §11 PII Scrubbing; §9 Log conformance check).
