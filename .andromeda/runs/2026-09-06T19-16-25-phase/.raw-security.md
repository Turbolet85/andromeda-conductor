## Constraints
- Every `[phases.emission]` block the re-drive adds is an enumerated external-input surface: `kind` REQUIRED whenever the table exists (no inferred default), `occurrences` bounded by `MAX_OCCURRENCES` (`0` = a declared silence window), and the per-shape cross-field rules (percentile ordering, severity ∈ 1..=24, ≥2 distinct topology services, non-empty variant/category sets), validated at load by garde `range`/`custom` co-located with the serde structs in their owning seam crate (per security-plan §Input Validation, scenario-config row).
- The re-tier and the checklist/expected resolution both land on SIBLING-reading rules, which the plan requires to ship as load-path `Scenario::check_*()` invoked from `from_toml_str` raising `CoreError::Config` — `check_budgets` (`[[expected]].budget_ms` ∈ `1..=MAX_BUDGET_MS` AND ≤ the scenario's own `slo_tier` deadline) and `check_checklist` (a `[[checklist]]` beside a non-empty `expected` is REJECTED) — never `#[garde(custom)]`, which in garde 0.22.1 receives `(&amp;field, &amp;())` and structurally cannot see a sibling (per §Input Validation; §Security Anti-Patterns → Input). Whether the shipped load path already invokes both is research's question.
- If the sustained shape needs a scenario-model field the model lacks (scope §4 leaves this open), the new nested spec field must `dive`, never `#[garde(skip)]` — a skipped nested struct deserializes entirely unvalidated because garde never descends into it (per §Input Validation; §Security Anti-Patterns → Input).
- `contracts/pulse-load-envelope.toml` is a committed SUT-facing manifest boundary: strictly positive `[envelope]` terms, no duplicate or reason-less `[[exempt]]` entry, absent/malformed a hard harness fault **never defaulted and never silently widened**, resolved by every shipped reader from a fixed `default_path()` through `resolve_under` with deliberately no `CONDUCTOR_*` override handle, and read faults carrying `e.kind()` only, never the path (per §Input Validation, committed SUT-facing manifests row).
- Live-leg output is agent-parseable ground truth shared across hosts: the `&lt;run_id&gt;.md` report, `runs.db` rows, JSONL journals and this chunk's committed `evidence/` must carry verdict/state/identity fields only — no absolute host path (the canonicalized `CONDUCTOR_*` dirs, `ANDROMEDA_PULSE_DATA_DIR`, the `%TEMP%/pulse-legs/…` leg dir the scope cites) and no internal seam-crate struct name (per §Error Handling, run-report artifact sanitization; §Security Anti-Patterns → Logging).
- The verdict/error wall must hold through the re-graded bound: a second disproof is a typed VALUE (`Ok(Verdict/ReportState)`), `Result::Err` stays reserved for harness faults (config parse, transport down, MCP unreachable), and no malformed child/transport input may panic on the read-back path (per §Error Handling; §Security Anti-Patterns → Universal).
- The bootstrap posture (`ANDROMEDA_PULSE_BASELINE_BOOTSTRAP_SECONDS`, scope §3.4) sits under the plan's Pulse-side-flag model: Conductor never SETS a Pulse-side flag itself, `spawn::build_command` passes only `ANDROMEDA_PULSE_DATA_DIR` through `.env(...)`, inheritance is the sole channel to the child, and no operator-supplied value may be interpolated into argv or a shell string (per §Threat Model Summary, Auth model + MCP child-process vector; §Security Anti-Patterns → Input / Code Patterns). If the chunk gives Conductor a READER of the new knob, §Input Validation's `ANDROMEDA_PULSE_*` declaration-only READ SET row governs (handle NAMES only; no value ever becoming a path, argv element or log value) — whether the firing form merely exports it or Conductor reads it is research's question.
- `cargo-audit` (+ `cargo deny check advisories bans licenses sources`) green over an un-drifted committed `Cargo.lock` remains the merge gate even at zero dependency delta, and the plan's Minimal-tier residual-risk control (per §Dependency Security; §Security Anti-Patterns → Universal).

## Patterns to follow
- garde `#[derive(Validate)]` co-located with the serde structs in the owning seam crate, nested fields `dive`, failed `Report` → `ConfigError` via `#[from]` as a harness fault at load, never a verdict (per §Input Validation).
- The load-path `Scenario::check_*()` arm as the sanctioned co-equal mechanism for sibling-spanning rules, with a test pinning that `from_toml_str` actually invokes it (per §Bootstrap phases, input-validation-library-install).
- Fixed-path manifest load: `LoadEnvelope::load` + explicit `validate()` through `resolve_under`, no `CONDUCTOR_*` override, `e.kind()`-only read faults (per §Input Validation, committed SUT-facing manifests row).
- Typed `thiserror` detail stays inside the seam crates and collapses to type-erased `anyhow` only at the `conductor-cli` edge (`sanitize_error` at the `#[tauri::command]` edge) (per §Error Handling).
- `conductor preconditions` as the leading arm of the path SET `{boot, run --live}`: on `run --live` an unmet subject is a REFUSAL at exit 1 naming each unsatisfied subject with no leg fired — never a degraded ~0s `[BLOCKED]` row and never a silent downgrade (per §Security Anti-Patterns → Universal).

## Anti-patterns to avoid
- Never `#[garde(skip)]` a nested spec field, and never write a sibling-reading invariant as `#[garde(custom)]` — it would look enforced while never testing the invariant (per §Security Anti-Patterns → Input).
- Never let a run report, `runs.db` row, JSONL journal or committed evidence record leak an absolute host path or an internal seam-crate struct name (per §Security Anti-Patterns → Logging).
- Never silently widen or downgrade: no defaulted/assumed load-envelope term standing in for a validated one, and no unmet preflight precondition resolving to a pass/fail/manual-check instead of a distinct `blocked`/refusal (per §Input Validation, committed manifests row; §Security Anti-Patterns → Universal).

## Contract bindings
- **Artifact hygiene ↔ obs + tests** — the host-path/struct-name scrub on journals, reports and committed `evidence/` is shared with obs's journal/report field schema and with tests (evidence fixtures and the re-aimed harvest assertion must not embed a leg dir or data dir).
- **Load-envelope sizing ↔ tests/arch envelope conformance gate** — the asserted rate term counts wire records via `EmissionSpec::max_spans_per_dispatch()` (scope §1.1), so the validated manifest is the shared authority for the new shape's bounds; `[[exempt]]` is set-equality-held in both directions.
- **Live-leg firing form ↔ tests harness + the run contract** — the `shell-declaration` terms (`mcp-enabled`, `l4-deterministic`) and the `sidecar-resolvable` / `handles-declared` subjects are graded by the leading `conductor preconditions` arm before any leg fires (per §Input Validation, declaration-only READ SET row; §Security Anti-Patterns → Universal).
