## Constraints
- The only assertable surface is the desktop-webview; the whole `conductor` verb surface and scenario-driving/CLI paths are declared not-assertable, so nothing this chunk builds is an axe/Lighthouse/contrast subject and the correct disposition for those surfaces is a cited `a11y n/a`, not a claim (per a11y-plan §1 A11y Scope Summary → A11y scope entities, `conductor-cli` entity; §11 Anti-Patterns → Universal).
- Whatever `verdict` / `state` pair the re-driven grading produces must be joinable through the display-label ↔ obs-enum crosswalk, which is verdict-first (`verdict == CalibrationRegion` ⇒ HOLD lamp regardless of `state`); a co-occurrence the crosswalk does not already name is an amendment trigger, not an undocumented state (per a11y-plan §6 Visual Design Verification → State color tokens → State-naming crosswalk).
- The re-tiered `slo_tier` value is inside an envelope a11y reproduces verbatim in two places (§1 harness spec and §3), whose declared tier set is `<5s | <20s | <90s`; a value outside that set obliges both reproductions to track obs rather than diverge (per a11y-plan §3 A11y Assertion Harness Contract → Structured violation JSON schema; the a11y↔obs bind is "a11y narrows; obs fixed the schema").
- If the `[[checklist]]` row survives the `[[checklist]]`-vs-`[[expected]]` resolution and reaches a render site, the operator-checklist is one of the four must-be-accessible paths and its rows carry a fixed contract (native `checkbox`, `aria-checked` per row, Space toggles, unticked-count roll-up announced, dialog-site rows inside the HOLD trap as a sibling of `Description`) — a11y-plan §4 records the dialog site as the only shipped mount and the report-site render as unbuilt; whether this scenario's checklist row renders anywhere today is research's question (per a11y-plan §1 Critical paths → Operator-checklist; §4 ARIA Patterns & Roles → per-component catalog, operator-checklist row).
- Any bootstrap posture (e.g. `ANDROMEDA_PULSE_BASELINE_BOOTSTRAP_SECONDS`) placed into the live-leg firing form lands in the same firing form the operator-only `a11y:driven` arm and the `a11y:sr*` legs require — both are declared live-Pulse-dependent and neither is CI-wired (per a11y-plan §9 CI Integration → E2E row; §3 CI integration).
- The driven arm carries a quiet-window precondition whose violation is budgeted at two 12-minute runs, and a 15-minute mocha ceiling; a chunk that deliberately sustains an error stream through incident formation on a shared live Pulse is a live constraint on that budget — whether the two legs can share a Pulse instance/data dir is research's question (per a11y-plan §10 SLO Invariants & A11y Budgets → Performance budget per a11y CI run).
- No WCAG conformance may be claimed from this chunk: it runs no axe-core / colorjs.io / WebdriverIO-keyboard leg, and conformance requires machine-verifiable evidence (per a11y-plan §11 Anti-Patterns → Strategy; §10 zero-WCAG-AA-violations invariant is scoped to the four webview paths).

## Patterns to follow
- Evidence/result artifacts fold into the obs §6 envelope with tuple data riding `fingerprints[]` and no new top-level fields — the same envelope discipline this chunk's harvest/leg records inherit (per a11y-plan §3 Structured violation JSON schema).
- Artifacts never carry absolute host paths or internal seam-crate struct names — directly relevant since the chunk's own basis cites a transient `%TEMP%/pulse-legs/...` leg dir; the committed-evidence-is-the-durable-basis move the scope already takes is the pattern (per a11y-plan §3 Structured violation JSON schema; §9 CI-specific resource attributes; §11 → SLO).
- Not-assertable surfaces get a cited exclusion, set-scoped rather than enumerated, so new verbs/scenarios do not restale the verdict (per a11y-plan §1 `conductor-cli` entity).
- Operator/local-gated legs ride the tests' 5-command harness and surface results through `logs` — one stack, no parallel harness path for a new live posture (per a11y-plan §3 CI integration; §9 Pipeline integration).

## Anti-patterns to avoid
- Do not treat the cli / scenario-driving surface as accessibility-assertable — its ASCII status prefixes and NO_COLOR text pairing are output-stream discipline, not an ARIA verification path (per a11y-plan §11 → Universal).
- Do not introduce a lamp-adjacent state or coverage-mode tint that is read as a seventh lamp state; the six-label not-color-alone assertion keys on the LAMP display labels only (per a11y-plan §11 → Visual; §1 non-lamp reuse of a state token).
- Do not stand up a second automation stack or fork the live-leg firing form for a11y-adjacent runs (per a11y-plan §11 → CI).
