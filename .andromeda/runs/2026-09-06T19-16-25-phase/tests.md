## Constraints
- **Live-Pulse legs are operator/local-gate only, never a CI gate.** The sanctioned invocation SET is `workflow_dispatch` · `scripts/agent-run.{sh,ps1}` (including its composed `run --live` stage) · a `[features] live-pulse = []`-gated test file invoked directly · an npm-script wdio suite; a gated file is invisible to the default lint pass and therefore OWES its own `cargo clippy -p <crate> --features <feat> --all-targets -- -D warnings` (per test-plan §9 Live-Pulse scenarios; ban restated at §11 CI).
- **The `--live` auto-resolve leg is not run-stable and must not be read as one.** §9 records a SUT-uptime precondition: an EMPTY active set at read-back holds only inside the emitting service's one-hour bootstrap window; past it `service_went_silent` cues raise new autonomous incidents so no window length reaches the arm, and inside it the window must still clear 150 s measured from the LAST incident the leg's own preflight formed (which can be more than one) — explicitly NOT a source-delta fact (per test-plan §9). This is the governing rule for CARRY §3.3, and it is the plan's own record of the two causes the scope names (a)/(b).
- **A claim that reaches no MCP read-back surface grades DECLARE-ONLY plus a HARVEST tier, not an `[[expected]]` check.** The standing shape across six families is: row lands exit 0 / `verdict` null / `state="KnownResidual"` (non-Blocked) with `latency_ms` recorded against the declared `slo_tier`, while the live claim is asserted HARD over verbatim leg-line captures at the `conductor-run` unit tier in `crates/conductor-run/tests/<family>_harvest.rs` (per test-plan §6 scenarios error-baseline-spike / fingerprint-storm / restart-suppression / severity-lifecycle). Whether `delegated_timing_harvest.rs` already conforms to that capture discipline is research's question.
- **Assertion-policy split binds the "record whichever way it lands" requirement.** `blocked` / `ManualCheck` / `KnownResidual` / `CalibrationRegion` are reported envelope states, never process-failure exits; only a hard `Fail` exits non-zero, and model-interpretive claims are calibration-region + report-for-human (per test-plan §3 `run` exit-code semantics; §11 E2E stack-specific ban).
- **The scenario TOML is a committed declarative fixture inside the garde-validated set.** Scenario configs one-per-P-ID under `scenarios/` are load-validated (bounded per-phase occurrences, non-negative durations, the per-shape emission rules, the `error_percent ∈ 0..=100` encoding), with a negative-test suite mandated to catch a nested spec annotated `skip` rather than `dive` — rules that exist but never execute (per test-plan §1 coverage trigger *security-vector-coverage / property-test*; §4 Scenario-config validation surface; §7 Seed strategies). Whether the new `[phases.emission]` blocks are already reached by that matrix is research's question.
- **Real-wall-clock non-determinism is admissible ONLY as an enumerated operator-local exception.** §2 closes the exception set at the driven a11y arm, the three `sr*` suites and the composed `run --live` suite; a new non-deterministic leg outside that set reads as a §10 zero-flakiness break, and retries stay banned (per test-plan §2 Agent-runnable invariants; §10 Zero-flakiness budget).
- **The `sleep(N)` ban's subject is synchronisation INSIDE a test.** A harness-level wait BETWEEN legs reproducing a SUT-side dedupe window (the 150 s quiet window) is part of the firing form, because the transition being waited out is the ABSENCE of a Pulse-side event; nothing inside a test may sleep to synchronise (per test-plan §11 E2E).

## Patterns to follow
- **Harvest-tier grading over verbatim leg captures**, with witnesses that do not work RECORDED rather than asserted — the restart harvest records the relative-magnitude arm unreachable at shipped SUT constants and the redacted `triage.cue.tick` counters; the severity harvest records the `"<redacted>"` auto-resolve tick and the unreachable resolution summary (per test-plan §6 Restart-suppression, Severity-lifecycle).
- **Pin the mis-pairing as a NEGATIVE test.** §6's severity-lifecycle scenario pins that pairing a creation with the FIRST active-count drop measures the preflight canary's own resolution. The scope's attribution problem (`conductor-canary` vs `conductor` service identity, §1.1) is the same class, and this is the plan's sanctioned shape for closing it (per test-plan §6 Severity-lifecycle).
- **The `--live` composition and per-leg journal freeze**: leading non-priming `conductor preconditions` probe (unmet subject ⇒ exit 1 with `[PRECONDITION]` lines, no leg fires) → B1 → B2 → 150 s quiet window → A → the driven a11y arm, each leg's `logs/agent-latest.jsonl` frozen to `runs/live-suite/{leg}.jsonl` because that sink truncates per invocation (per test-plan §3 CI stage selectors).
- **A live leg's FULL FIRING FORM is part of the leg, not an optional extra** — PATH resolving `andromeda-pulse-mcp`, `ANDROMEDA_PULSE_MCP_ENABLED` + `_L4_DETERMINISTIC`, `ANDROMEDA_PULSE_DATA_DIR` equal to the live Pulse's data dir, and the quiet window; a bare invocation returns BLOCKED in ~2 ms indistinguishable from a genuine SUT-side gate failure (per test-plan §6 desktop-webview driven arm). Any bootstrap posture the plan states rides here.
- **Seed precedence and envelope read**: `--seed` is appended ONLY when `SEED` is explicitly set, otherwise the TOML-declared seed governs and the envelope records the effective seed; `status` reads the NEWEST ENVELOPE line selected by the envelope-only `seed` key, never the file's last line (a graded run ends on a `CheckRecord`) (per test-plan §3 `run` scenario invocation, §3 `status`).

## Anti-patterns to avoid
- NEVER fake Pulse's *reaction* as a CI verdict, and NEVER run a live-Pulse leg as a CI gate — the stub canary proves MCP wiring only (per test-plan §11 Test Strategy stack-specific; §11 CI stack-specific).
- NEVER let a "sustained emission window" become a load/saturation test — bounded P-060 "typical/high" profiles only; 50k+ spans/sec is Pulse's own suite and perf budgets are N/A at this tier (per test-plan §11 Test Strategy stack-specific; §10 Performance budgets).
- NEVER treat a `KnownResidual` / `CalibrationRegion` / `Blocked` state as a non-zero process exit (per test-plan §11 E2E stack-specific).
