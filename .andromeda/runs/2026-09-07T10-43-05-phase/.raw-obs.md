## Patterns to follow
- **`message`-field escape hatch** — when a needed field name is absent from `conductor-core::redact::ALLOWLISTED_FIELDS`, carry the datum on the allowlisted `message` value rather than minting a new attribute (a non-allowlisted attribute emits nothing at the processor stage). Precedents: the MCP key-set witness, the lifecycle-write incident id, the coverage roll-up counts (obs-plan.md §6 Boundary-call wrappers).
- **Bounded span-name set is closed by design** — a new span must be an existing member; the set was deliberately not widened with a `db.*` wildcard. No dependency-polish work should mint a new name (obs-plan.md §11 Spans/Traces · §4 conductor-report row).
- **Additive `RUST_LOG` form** — `RUST_LOG=info,{crate}=debug`; a bare per-target directive **replaces** the default rather than adding to it. The `emit.batch` wire-shape witness is `debug`-gated on `conductor_emit`, so any before/after comparison across the A2 trim needs the paired form (obs-plan.md §6 Per-module log levels).
- **Instrumentation mechanism per surface** — `#[tracing::instrument]` on the core library handlers the CLI drives; a manual `tracing::info_span!("tauri.command.&lt;name&gt;").entered()` guard on each `#[tauri::command]` (the attribute does not stack with the command macro). B6's doc-comment re-paths in `conductor-run` sit beside these attributes and must leave them untouched (obs-plan.md §4 Auto-instrumentation per surface).
- **Enumerate every dep site before declaring a footprint dropped** — §1's instrumentation-scope table binds each crate to its stack pins; B3's two-site finding follows that discipline for `opentelemetry-proto` (obs-plan.md §1 Obs Scope Summary).

## Anti-patterns to avoid
- NEVER introduce or initialize an OTel SDK / `opentelemetry_sdk` meter provider for self-observation — the dormant-crate footprint must be reduced by feature trimming, never "resolved" by wiring an SDK-based exporter, and defaults must not be re-enabled at any dep site (obs-plan.md §11 Telemetry Strategy · §11 Metrics).
- NEVER export self-observation OTLP — not to `:4317` (the PRODUCT fault stream) and not to `:4318` (dead per arch); the conductor-emit dep change must not open a self-obs export path (obs-plan.md §11 Universal).
- NEVER emit unstructured stderr text — a spinner/progress render that breaks one-JSON-object-per-line parseability of the self-obs stream violates this ban (obs-plan.md §11 Logs).
