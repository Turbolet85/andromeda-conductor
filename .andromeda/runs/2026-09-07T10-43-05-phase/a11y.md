## Constraints
- The a11y harness's dependency set is mandated by name and pin: `axe-core@4.12.0` + `@axe-core/webdriverio` + `lighthouse@13.0.3` (per a11y-plan.md §3 Bootstrap phases → `a11y-tooling-install`) and `colorjs.io@0.6.1` (per §3 → `contrast-verification-harness-setup`), reusing tests' already-installed `webdriverio` + `@crabnebula/tauri-driver`. These live in the same `crates/conductor-tauri/ui/package.json` that B5 edits, so a devDep/lock move must leave them declared and resolvable at those versions. Whether the package currently declares all of them (notably `lighthouse`, whose §3 role is a *secondary coarse gate* and which may therefore have no importing spec) is research's question.
- A static dead-code report is not authority over the a11y engine: a11y-plan.md §11 Anti-Patterns → CI requires the runtime axe-core step and bans lint-only a11y, and §11 → Strategy bans partial axe-core configuration without an explicit §12 Decisions Log entry. A `knip` "unused dependency" hit on any of the above requires a written disposition, not a removal.
- One webview-automation stack only (per a11y-plan.md §11 → CI and §3 A11y testing tool pick): nothing added to this package may introduce a parallel puppeteer/CDP/pa11y automation path, and `webdriverio` + `@crabnebula/tauri-driver` are shared property with tests §6 — not a11y-private deps a consolidation pass may drop.
- The a11y legs are addressed by npm script *name* (`a11y:driven`, `a11y:sr`, `a11y:sr-empty`, `a11y:sr-error`; the routine arm rides `agent-run run --e2e`) per a11y-plan.md §9 CI Integration → E2E row. Adding a `knip` script must not rename, reorder-away, or displace those names.
- The cli surface is not-assertable — a11y-plan.md §1 (cli entity) and §11 → Universal ban treating it as accessibility-assertable. A1's indicatif hold spinner therefore carries no ARIA/keyboard/contrast verification path and no a11y claim may be attached to it; its ASCII/`NO_COLOR` text pairing is output-stream discipline, not an a11y path.
- a11y violation artifacts must align field-for-field with the obs §6 envelope, reproduced verbatim at two sites (a11y-plan.md §1 A11y assertion harness specification → Structured violation JSON schema, and §3 → Structured violation JSON schema). If A2/B3's `opentelemetry-proto` default-features trim changes that envelope's shape, both reproductions track it; whether the trim touches the envelope at all is research's question.
- The gate stays hard: zero WCAG AA violations, no retry-once, no soft SLO (per a11y-plan.md §10 SLO Invariants and §11 → SLO). A dependency/lock move that makes an a11y leg unstable may not be absorbed by a retry.

## Patterns to follow
- Host-tool handle with skip-at-exit-0: `CONDUCTOR_NVDA` for the SR leg and `CONDUCTOR_MSEDGEDRIVER` for the Windows arm (per a11y-plan.md §3 Bootstrap → `screen-reader-test-spec-setup` / `a11y-ci-gate-wire`) — the established shape for a script in this package that is not universally runnable.
- Three-arm separation in this package (per a11y-plan.md §9 E2E row): unattended routine arm, operator-only driven arm, operator-only SR leg — none CI-wired. A new tool script lands beside them, not folded into one.
- Results surface through tests' `logs` command of the binding 5-command harness contract (per a11y-plan.md §3 CI integration and §9 Pipeline integration) — a new tool does not become a second artifact channel.
- Reuse-over-install: §3 A11y testing tool pick and §12 Decisions Log record puppeteer-core / `@axe-core/puppeteer` / pa11y / `focus-trap-react` / `react-aria` as deliberately *dropped* installs. Any package-level cleanup must read those as decisions, not as accidental omissions to "fix".

## Anti-patterns to avoid
- Removing or swapping an a11y harness dependency on the strength of a static unused-code report (a11y-plan.md §11 → CI: lint-only a11y ban; §11 → Strategy: no partial axe configuration without a Decisions Log entry).
- Adding any second browser-automation dependency to `crates/conductor-tauri/ui` (a11y-plan.md §11 → CI: "NEVER stand up a second browser-automation stack").
- Attaching an a11y assertion or WCAG claim to the cli/indicatif spinner (a11y-plan.md §11 → Universal: cli is not accessibility-assertable).
