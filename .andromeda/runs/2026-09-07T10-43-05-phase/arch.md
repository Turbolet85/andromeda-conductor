## Patterns to follow
- **Bump → registry row refresh, produced here, written at wrap.** The anyhow `1.0.102 → 1.0.104` amendment moved only the version value across §Stack / §Established Decisions / §Inherited Defaults with the decision's invariants untouched; the same three-surface shape applies to a tokio or Tauri correction (arch sites for tokio: §Stack, §Established Decisions [Language / Runtime], §Inherited Defaults; for Tauri: §Stack, §Infrastructure Patterns — Deployment model, §Inherited Defaults).
- **Resolved lock is the reconciliation source of truth.** Precedent shape: rusqlite's transitive `libsqlite3-sys 0.38.0 → 0.36.0` / SQLite `3.51.1 → 3.50.4` correction, and the `indicatif 0.18 → 0.17` stack.md cascade — both moved the doc to the lock, never the reverse.
- **arch already attests one of the two version corrections internally.** architecture.md §Infrastructure Patterns — Build system states `tauri` **2.11.3** in a measured build claim while §Stack / §Deployment model / §Inherited Defaults still read `v2.10.x` — an intra-document inconsistency, so the corrected Tauri value needs no external warrant. No arch site states a tokio value other than `1.48.x`, so that one rests on the lock alone.
- **Feature declaration belongs in the consuming member's own `[dependencies]`** (workspace pin + `workspace = true` at the member), which is precisely the shape §Established Decisions [Module Boundaries] records as broken for `conductor-verify`.
- **`deny.toml` growth pattern:** an inline-justified entry naming crate + dependency path, with the arch Build-system prose updated when the accepted set changes class (the `BSD-2-Clause`/`arrayref` entry).
