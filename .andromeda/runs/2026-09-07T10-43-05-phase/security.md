## Patterns to follow
- Accepted-exception mechanism: a `deny.toml` `[advisories] ignore` / `[licenses] allow` entry plus an inline justifying comment, gate staying green, no unresolved CVE — the shape used for `number_prefix`/RUSTSEC-2025-0119, `Zlib` (`foldhash`), `BSD-2-Clause` (`arrayref`) (per security-plan.md §Dependency Security).
- Dev-tree-grain acceptance for npm: gate production strictly (`--omit=dev` = 0), accept dev-only transitives categorically rather than adding a suppression tool — the precedent knip follows (per security-plan.md §Dependency Security, Frontend (npm) supply chain).
- External CLI scanners are **floors, not lockable pins** (`cargo-audit` ≥ 0.22 · `cargo-deny` ≥ 0.19); record the actual installed version rather than over-pinning (per security-plan.md §Dependency Security, Audit tool).
- Version bumps flagged by an audit drive a floor raise, not a suppression — the Vite 6→8.0.16 esbuild precedent on the npm side, the same discipline on cargo (per security-plan.md §Dependency Security, Update policy).

## Anti-patterns to avoid
- NEVER let `Cargo.lock` drift or go uncommitted, and never run the release gate / merge without `cargo-audit` (+ recommended `cargo-deny`) green (per security-plan.md §Security Anti-Patterns → Universal).
- NEVER answer a red audit with a `deny.toml` ignore, a CI edit, or a silent accept for a transient external fault — and never leave an ignore standing whose subject the bump removed (per security-plan.md §Dependency Security; §Security Anti-Patterns → Universal).
- NEVER commit a secret-shaped string to the `conductor-*` workspace — this binds the B7 `provider_key` corpus and any golden/expected fixture it regenerates (per security-plan.md §Security Anti-Patterns → Secrets).
