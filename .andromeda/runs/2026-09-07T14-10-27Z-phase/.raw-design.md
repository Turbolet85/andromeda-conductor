# design extract

## Relevance
**Partial** — the chunk ships no UI, but the assertions it gates (token contrast, reduce-motion, color-not-alone) are design-token-bound, and CARRY 2 / CARRY 5 touch design-owned roles and the contrast toolchain.

## Constraints
- The gated contrast assertions read **token pairs, not literals**: the 34-token `:root` contract (dark block + `@media (prefers-color-scheme: light)` override) is the binding contract, and every text/surface pair the gate checks must resolve through `var(--…)` names (per design-system.md §Surface: desktop-webview / Tokens). Whether the harness currently reads tokens vs. computed hexes is research's question.
- `--text-tertiary` / `--text-muted` carry an explicit contrast rationale in the plan (dark `--text-tertiary` lifted so it clears 4.5:1 on `--color-raised-2` and `--color-raised-1`, not only `--color-base`; `--text-muted` moved in opposite directions per theme to clear `--color-inset`). A gate that fails on any violation makes these values CI-load-bearing — regressing either token re-opens the measured 2026-09-01 axe finding (per design-system.md §Color Palette / Text Hierarchy).
- design-system.md §Motion requires **all** transitions dropped under `@media (prefers-reduced-motion: reduce)` (`* { animation: none !important; transition: none !important; }`), including the count-tint on a held count. This mandate is stated unconditionally — it is **not** platform-conditional, so a runner that cannot emulate reduced motion is a gate-arrangement problem, never grounds to drop the assertion (per design-system.md §Motion, Hard limits).
- The operator-pause dialog is required to carry `role="alertdialog"` (§Component Patterns 2) while the operator-checklist's unticked roll-up is required to be **its own** `role=status` line (§Component Patterns 7). The two roles are distinct **by design**, which is exactly why CARRY 2's `[role="status"]` guard is loose — `role=status` is a shared, growing population; `role="alertdialog"` is the singular hold marker (per design-system.md §Component Patterns 2 + 7).
- Status must never be signalled by color alone: every verdict lamp is required to be paired with its text label (`Pass`/`CalibrationRegion`/`Fail`/`Blocked`/`Manual`/`Residual`) plus an `aria-live` announcement, and every icon-only control with an `aria-label` (per design-system.md §Component Patterns 4 and §Iconography). These are the design-side preconditions for the axe/SR assertions the gate will enforce.
- Any human-readable output the gate emits from the cli surface must be ANSI-stripped when piped (per-stream `IsTerminal` + `NO_COLOR` + `TERM != dumb`), must carry no emoji in machine-parseable output, and must keep raw data on stdout / messages on stderr (per design-system.md §Surface: cli / Tokens and §Anti-Patterns / Per-Surface Bans: cli). Whether the gate's emitter is the cli surface at all, or purely the wdio/JS plane, is research's question.
- CARRY 5's knip config must not be allowed to prune the contrast toolchain: `colorjs.io` and `axe-core` are the mechanism by which the token pairs above are measured at all, and §Anti-Patterns forbids reasoning about design tokens from anything but the declared contract (per design-system.md §Surface: desktop-webview / Tokens).

## Patterns to follow
- **Token block as the fixture** (§Surface: desktop-webview / Tokens) — the dark/light `:root` pair is a single enumerable contract; contrast checks should iterate it by name rather than restate hexes in test code.
- **Role separation of hold vs. roll-up** (§Component Patterns 2 / 7) — `role="alertdialog"` marks a raised hold; `role=status` is a general announced region. CARRY 2's corrected shape follows the existing in-file precedent at `accessibility.e2e.ts:294`.
- **TTY-gating "so agent-captured artifacts stay clean"** (§Surface: cli / Component Patterns 1) — the shipped precedent for making CI-captured output ANSI-free; the violation JSON should inherit this discipline rather than invent a new one.
- **Sanitized error shape** (§Surface: cli / Component Patterns 5) — `error: &lt;short&gt;` + detail + `hint: &lt;fix&gt;`, no absolute host paths, no internal struct names, no stack traces outside `--debug`. This is the design-side twin of the obs-owned redaction contract the gate's JSON must satisfy.
- **Lamp + label + `aria-live` pairing** (§Component Patterns 4, §Iconography) — the render-side invariant the SR rows in CARRY 3 are measuring.

## Anti-patterns to avoid
- Introducing any raw hex, raw ms, or hardcoded pixel value into gate config, fixtures, or expected-violation snapshots — tokens are bound by `var(--…)` name only, and no new palette row is warranted by a CI chunk (per §Anti-Patterns / Universal Bans + §Surface: desktop-webview / Tokens).
- Relaxing or conditionally skipping the `prefers-reduced-motion: reduce` override to make a runner green — §Motion states the drop as a hard limit, not a best-effort.
- Emitting emoji or unconditional ANSI into the gate's machine-parseable output, or letting a status appear as color/glyph without its ASCII label (per §Anti-Patterns / Per-Surface Bans: cli).

## Contract bindings
- **Token contrast ↔ a11y §Contrast (SC 1.4.3)** — the plan's Text-Hierarchy values were solved against a11y-plan's nine token pairs in both themes; a11y owns the criterion, design owns the values. The gate enforces the intersection.
- **Motion tokens ↔ a11y SC 2.3.3** — §Motion's reduce-motion override is explicitly declared as "binding with a11y SC 2.3.3"; CARRY 4's stale `a11y-plan.md:565` clause ("reduced-motion emulation is the one platform-dependent assertion") sits on the a11y side of this binding, and a11y-plan is read-only for phase.
- **Lamp color + text label ↔ a11y SC 1.4.1 (use of color)** — §Component Patterns 4 and §Iconography mandate the pairing the SR/axe assertions verify.
- **Violation JSON redaction ↔ obs-owned format** — design's §cli Error-output sanitization (no absolute host paths, no internal struct names) is the same discipline; obs owns the field-level shape, design owns the human-message shape if the gate emits one.
- **knip config ↔ a11y-plan §3 pinned devDeps** — `colorjs.io` / `axe-core` are the contrast measurement mechanism for design's token contract; their retention is a design stake in an a11y/tooling decision.

## Acceptance criteria contributions
- The gating (without-Pulse) arm actually executes the token-contrast assertions over the declared token pairs — a run in which those assertions skipped is not a pass (per design-system.md §Color Palette / Text Hierarchy + §Surface: desktop-webview / Tokens).
- The gating arm actually executes the `prefers-reduced-motion: reduce` assertion; if the runner cannot emulate it, the gate reports that as a failure or a named non-green outcome, never a silent skip (per design-system.md §Motion, Hard limits).
- The chunk introduces no new design token, hex, raw duration, or hardcoded pixel — the token contract is unchanged in name, count, and value by this chunk (per design-system.md §Surface: desktop-webview / Tokens and §Anti-Patterns / Universal Bans).
- Gate output captured in CI (non-TTY) carries no ANSI and no emoji, keeps data on stdout and human messages on stderr, and never signals a status by color alone (per design-system.md §Surface: cli / Tokens and §Anti-Patterns / Per-Surface Bans: cli).
