## Constraints
- The desktop-webview is ONE frameless window in four run states (`idle` · `live` · `hold` · `aborted`) with no router, no routes, no deep links and no breakpoints — a gate's specs may only reach a state by driving run flow, never by navigating or resizing (per layout-templates.md §Surface: desktop-webview → IA notes, and §Decisions Log → Responsive breakpoints, which records N/A for this surface).
- §Component — Footer (status strip) records the status strip as DESIGNED, NOT SHIPPED with the landmark set stated as `banner` + `main` + two `region`s and no `contentinfo`, a route-owned gap; §Component — Operator-checklist likewise records the run-report checklist site as unbuilt with only the dialog context mounting. A gate that fails on any violation must not draw assertions from these two regions, since a red there would report an unbuilt region, not a defect.
- The hold is an `AlertDialog` over the console (per layout-templates.md §Component — Hero / signature section), while the checklist roll-up is a `role=status` region (per §Component — Operator-checklist). Layouts therefore requires the alert-dialog role — not `role="status"` — as the token standing for "a hold is raised", which is exactly CARRY 2's tightening.
- §Component — Primary content block 1 requires two distinct empty states with two distinct strings — the catalog-empty prose owned by `App.tsx` and the picker's separate FILTER-MISS prose from a persistently-mounted announced region — "two states, two strings, two rows; neither is the other's". Spec subjects in the gate must keep them apart.
- §Surface: cli → Primary screens (the `scripts/agent-run.{sh,ps1}` bullet) requires the `--live` stage to be reachable from no default or CI path, and fixes two exit classes apart: an unmet live-Pulse precondition REFUSES at exit 1, an absent host-tool handle (`CONDUCTOR_MSEDGEDRIVER` / `CONDUCTOR_NVDA`) SKIPS its own leg at exit 0 with a fetch recipe. The chunk's open questions 1–2 must be answered inside that two-class frame, not by inventing a third.
- §Surface: cli → IA notes (Headless invariant) requires the agent-driven source-of-truth path never to be gated on an interactive prompt — "an interactive gate there would silently break the release gate". Any CI arrangement the chunk adds inherits this.
- §Surface: cli → Component — Footer / terminator + error output and §IA notes (Pipe discipline) require stdout reserved for raw artifact data a downstream agent parses cleanly, human messages on stderr in `error:` / `hint:` shape, sanitized of absolute host paths, internal struct names and stack traces. The violation JSON's stream and redaction posture is bound by this even though its field set is obs-owned.

## Patterns to follow
- The refuse-vs-skip precedent already documented at §Surface: cli → Primary screens: a `[PRECONDITION]`-style refusal at exit 1 with one host-path-free line per unmet subject, versus a driver-handle skip at exit 0. Whether the a11y job should take the refusal arm on a runner lacking `CONDUCTOR_MSEDGEDRIVER` is the chunk's decision; the two shapes it must choose between are already minted.
- The `--e2e` stage's documented guard shape (§Surface: cli → Primary screens): builds the release bundle, drives the desktop-webview console through the tauri-driver webview leg, gated on a Conductor-owned driver handle whose absence emits a host-path-free `error:` / `hint:` precondition. This is the without-Pulse arm the scope names, described by target and guard rather than by command literal.
- ASCII-prefix pairing (`[PASS]`/`[FAIL]`/`[BLOCKED]`, never emoji in machine-parseable output) per §Surface: cli → Signature placement and §IA notes — if the gate prints a human status line beside its JSON, this is the shape.
- Titlebar right-zone ordering (§Component — Header): minimize then close, left to right, each carrying an accessible name. CARRY 3(2)'s measured "first Tab landed on Close window, not Minimize window" is a divergence from this documented order; whether the shipped DOM order matches §Component — Header is research's question.

## Anti-patterns to avoid
- Asserting against the `contentinfo` footer strip or the run-report checklist render as if they were live regions — layout-templates.md §Component — Footer and §Component — Operator-checklist record both as route-owned gaps, so such an assertion converts a known gap into a permanent red gate.
- Reaching a surface state by route, URL, deep link or viewport/breakpoint change — banned by §IA notes and §Decisions Log → Responsive breakpoints (no router, no breakpoints; the frameless window IS the surface).
- Wiring `--live`, or any prompt-bearing path, into the CI job — §Surface: cli → Primary screens bars `--live` from every CI path, and §IA notes (Headless invariant) bars an interactive gate on the agent-driven path.
