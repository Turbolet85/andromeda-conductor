# security extract

## Relevance
Relevant — the chunk edits the one workflow that carries Conductor's dependency-audit security gates, emits a new committed artifact class (violation JSON), and touches the wdio edge that owns the two host-tool path-handle guards; it adds no auth, network, or IPC surface.

## Constraints
- The a11y job joins `.github/workflows/ci.yml`, which security-plan.md §Dependency Security (CI integration) + §Bootstrap phases (dep-security-ci-gate) require to carry `cargo audit` (+ `cargo deny check advisories bans licenses sources`) and `Cargo.lock` drift verification, and §Dependency Security (Frontend npm supply chain) requires to carry `npm audit --omit=dev` = 0 PRODUCTION vulns. Adding a job must not remove, reorder-around, or soften those; whether those steps are present in the two current jobs today is research's question.
- The gate's "redacted, service-tagged JSON" must carry no absolute host path (canonicalized `CONDUCTOR_*` dirs, `ANDROMEDA_PULSE_DATA_DIR`, drive-letter / `%APPDATA%` / `/Users` / `/home` tokens) and no internal seam-crate struct name — per security-plan.md §Security Anti-Patterns → Logging, which binds committed `evidence/` records explicitly, and §Error Handling (Run-report artifact sanitization). Whether current axe/lighthouse output (node HTML snippets, page URL of the bundled webview) already leaks such tokens is research's question.
- `CONDUCTOR_MSEDGEDRIVER` and `CONDUCTOR_NVDA` must keep the wdio-edge duty: existence + `isFile` + shell-metacharacter rejection before the spawn, the value used only as a separate array-form argv element (or the guarded program for NVDA), and an unset/not-a-file arm that emits a host-path-free precondition naming the handle, never its value — per security-plan.md §Input Validation (`CONDUCTOR_MSEDGEDRIVER` row, `CONDUCTOR_NVDA` row). Their exemption from the Rust `std::fs::canonicalize` rule holds *only because no Rust code reads them* (§Security Anti-Patterns → Input); making the gate red on a missing handle must come from a gate-level assertion outside the guard, not from relaxing it.
- Any NEW `CONDUCTOR_*` path handle introduced for the gate (e.g. a violation-JSON output dir) binds the canonicalize + bounds-check duty **per READER** — a shipped reader discharges it at the `conductor-cli` edge; a test-binary-only reader carries the explicit recorded residual plus a host-path-free failure origin naming the handle and the file, never a resolved path — per security-plan.md §Input Validation (env-var path handles row) and §Security Anti-Patterns → Input (per-READER restatement, 2026-09-06).
- Any dependency delta (a knip wdio plugin for CARRY 5, or a CI-side npm addition) lands only under `npm audit --omit=dev` = 0 production vulns with `package-lock.json` committed; dev-only transitive advisories in the non-shipping harness tree are accepted at dev-tree grain — per security-plan.md §Dependency Security (Frontend npm supply chain). Cargo side: `cargo audit` / `cargo deny` green over the committed lock per §Security Anti-Patterns → Universal.
- The scope's "driver ports live and die with the harness" is the security-plan mandate, not a chunk convention: security-plan.md §Security Anti-Patterns → Universal bans an inbound listener in Conductor's SHIPPED binaries and carves out `4444`/`4445` only for the *named* dev-only arms (`--e2e` routine, `a11y:driven`, `sr*`). A CI arm firing the same `wdio.conf.ts` stays inside the ban's intent but falsifies the carve-out's enumeration — a wrap amendment, never a phase edit to the plan.

## Patterns to follow
- The `UNSAFE_PATH` guard in `crates/conductor-tauri/ui/wdio.conf.ts` — the shipped shape for host-tool handles (three checks, array-form spawn, skip-at-exit-0 with a host-path-free precondition), which security-plan.md §Input Validation states is proven by both guard arms in both harness shells.
- The speech-log ingest sanitizer (`crates/conductor-tauri/ui/test/a11y/screen-reader/parse-nvda-log.ts`, `writeNvdaPass`) is the existing template for a committed machine-readable a11y record: closed enum sets, bounded text (`heard` ≤ 400), host-path token → `&lt;host-path&gt;` with the row gaining a `security_finding`, raw log staying under gitignored `runs/` — per security-plan.md §Input Validation (speech-log ingest row). The violation JSON is the same class of artifact.
- Harness spawn discipline: five governed forms, none a shell string; operator values appear only as separate array-form argv elements after metacharacter rejection, handles ride in the child's **env map** — per security-plan.md §Security Anti-Patterns → Code Patterns rule (b). Any spawn the CI job introduces must be one of these forms.
- The existing dep-security CI gate shape — build fails on advisory hit, gates run over committed lockfiles — per security-plan.md §Dependency Security (CI integration) and §Bootstrap phases (dep-security-ci-gate); the a11y job should fail the build the same way rather than reporting green-with-warnings.
- Precedent for a CI step that sets a `CONDUCTOR_*` handle consumed by a test binary, with its residual recorded and its failure origin naming handle + filename only — per security-plan.md §Input Validation (env-var path handles row, the journal-conformance reader).

## Anti-patterns to avoid
- NEVER weaken, bypass, or delete the `isFile` / shell-metacharacter guard (or route a handle value into a shell string or spawn program) in order to make the gate red on a bare runner — security-plan.md §Security Anti-Patterns → Input and → Code Patterns rule (b) bind regardless of which arm invokes the config.
- NEVER let the violation JSON, or any committed evidence record this chunk adds, carry absolute host paths or internal seam-crate struct names — security-plan.md §Security Anti-Patterns → Logging; a real host path has already arrived through this test tree's third-party text once (row S1-01).
- NEVER edit CI to make a red dependency gate go green: security-plan.md §Dependency Security states the remedy set explicitly — never a `deny.toml` ignore, never a CI edit, never a silent accept — and requires the local advisory-DB porcelain check before classifying any audit failure as external.

## Contract bindings
- CI security gate ↔ tests §CI Integration: one workflow; the a11y job lands beside the audit/npm-audit gates in the same `ci.yml`, and their fail-the-build semantics are security's, their job/step arrangement tests'.
- Violation JSON ↔ obs: obs owns the service-tagged JSON *schema and fields*; the redaction predicate (no absolute host path, no internal struct name, per security-plan.md §Security Anti-Patterns → Logging) is security's and must be asserted, not assumed, once obs pins the fields.
- Committed a11y evidence records ↔ a11y/tests fixtures: a11y owns the assertions and pass-spec, security owns the scrub-to-`&lt;host-path&gt;` + `security_finding` discipline on the committed derivative (security-plan.md §Input Validation, speech-log ingest row).

## Acceptance criteria contributions
- `cargo audit` and `cargo deny check advisories bans licenses sources` exit 0 over an un-drifted committed `Cargo.lock`, and `npm audit --omit=dev` reports 0 production vulnerabilities over a committed `package-lock.json`, after any dependency or lockfile delta this chunk lands (per security-plan.md §Dependency Security)
- The post-edit `ci.yml` still runs the dependency-audit and `npm audit --omit=dev` gates with build-fails-on-hit semantics — the a11y job is additive, and no existing security step is removed, downgraded to warn, or made conditional (per security-plan.md §Dependency Security, CI integration)
- A grep of every artifact this chunk commits (violation JSON + any `evidence/` record) returns 0 absolute host paths (drive letter / `%APPDATA%` / `/Users` / `/home`) and 0 internal seam-crate struct names, and any unset-handle skip message names the handle without its value (per security-plan.md §Security Anti-Patterns → Logging)
- The wdio-edge guard for `CONDUCTOR_MSEDGEDRIVER` / `CONDUCTOR_NVDA` retains existence + `isFile` + shell-metacharacter rejection with both arms still exercised, and no new `CONDUCTOR_*` handle reaches a shipped Rust reader without the canonicalize + bounds-check duty (per security-plan.md §Input Validation)
