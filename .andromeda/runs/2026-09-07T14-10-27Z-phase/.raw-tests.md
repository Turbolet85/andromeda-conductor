## Relevance
Relevant — the chunk extends CI (§9), wires a webview/a11y leg into a gate (§3 CI stage selectors, §6), and is constrained by the flakiness + skip-is-not-a-pass rules (§10, §6, §11).

## Constraints
- test-plan.md §9 (Matrix builds) names this chunk's route entry as the OWNER of the CI arrangement: the three-OS matrix and a dedicated `ubuntu-latest`+`xvfb` webview-E2E job are recorded as TARGET arrangement "owned by the *A11y CI gate* route entry", with the shipped arrangement measured as two `windows-latest` jobs. The plan also requires the nextest `job_name` be set per matrix variant so `dorny/test-reporter` distinguishes per-OS results. Note the internal tension the chunk must resolve: §9's pipeline-table E2E row still states "the CI JOB is Linux + `xvfb`" while §9 Matrix builds classifies that as target, not shipped — whether a runner-agnostic/Windows job contradicts that row is a wrap-amendment question, not a phase edit.
- test-plan.md §11 (CI, stack-specific) bans running any live-Pulse leg as a CI gate, and names the banned SET explicitly: `workflow_dispatch` / `scripts/agent-run.sh`, its composed `run --live` stage, a cargo-feature-gated test invoked directly, and an npm-script wdio suite "such as `a11y:driven`" (§9 Live-Pulse scenarios carries the same SET). This forecloses the `driven` arm as a CI gate at the rule level; scope Open Question 1's remaining half is which non-live suites qualify.
- test-plan.md §6 (Drivers per surface → routine arm) requires that a spec whose DOM state the subject cannot produce context-skips and that "a context-skip is never a pass"; §9 (Build failure conditions) requires any E2E test failure to fail the build. A gate satisfiable by a skipped-green suite violates both — the plan-level answer to scope Open Questions 1-2, though whether the shipped `CONDUCTOR_MSEDGEDRIVER` guard's skip-at-exit-0 arm can fire on the chosen runner is research's question.
- test-plan.md §10 (Zero-flakiness budget) forbids tolerating a flaky test: quarantine and fix at the root cause, never a retry budget, and `retries` must not be set on nextest. §11 (CI) repeats the no-retry ban. CARRY 3(3)'s recorded run-to-run announcement variance therefore cannot be absorbed by the gate — it must be removed at the cause or the varying suite must not be in the gate (scope Open Question 4).
- test-plan.md §3 (5-command implementation → `run`, CI stage selectors) requires CI stages to fire through `agent-run.{sh,ps1} run --{unit|integration|e2e}`, and §3 (Bootstrap → 5-command-discipline-wire) makes identical `.sh`/`.ps1` semantics a binding contract. The `--live` precedent recorded there is the sanctioned shape for a new selector: a sibling `case` branch that keeps the command count at five, adds no port/env/`CONDUCTOR_*` handle, and leaves the envelope / `status` read / JSONL shapes untouched.
- test-plan.md §3 (Log format; Status endpoint shape) requires artifacts to carry no absolute host paths and no internal seam-crate struct names, asserted by a negative test, and requires that the per-run emission journal, the self-obs stream, and the run-report envelope not be conflated. Any new violation-JSON artifact is bound by that separation (scope Open Question 3).
- test-plan.md §4 (conductor-tauri/ui) records that the frontend build gate does NOT prove ESM loadability — a `wdio.conf.ts` member is proven only by EXECUTING the wdio leg that loads it; §12 (Open questions) records that no JS/TS unit runner is adopted. Any edit to `wdio.conf.ts` guards is proven by running the leg, never by `tsc --noEmit`.

## Patterns to follow
- The §9 stage-table pattern: each CI stage invokes the harness verb (`agent-run.{sh,ps1} run --&lt;selector&gt;`) rather than a bespoke command, with `~/.cargo` + `target/` caching keyed on `Cargo.lock` and npm cache on the E2E row (per §9 pipeline table; §11 CI bans skipping dependency caching).
- The self-seeding-subject pattern for the routine arm (§3 CI stage selectors, §6 routine arm, §7 Self-bootstrapping requirement): `seedFixtureRuns()` clean-re-creates the gitignored runs dir and writes the subject through the production writer under `CONDUCTOR_E2E_SEED_DIR`, throwing on a non-zero exit or missing journal rather than seeding silently, with `CONDUCTOR_RUNS_DIR` repo-relative — so a clean CI tree has a subject and a dev box cannot pass off host-local run residue.
- The coverage-completeness-gate precedent (§6 Coverage-matrix completeness gate; amendment 2026-09-06): a crate-local test target enforced by a NAMED `ci.yml` step, loud on artifact absence and red on violation — and, by operator resolution at that wrap, such a step took no §9 stage-table row.
- Machine-parseable, non-interactive output (§2 Agent-runnable invariants; §9 Test report format): the gate must be exit-code-readable and non-interactive — `wdio run` only, headless where a display must be faked, headful on a real desktop host.
- Selector discipline for any new/edited assertion (§6 Selector strategy): role / text / `data-testid` / `aria-live` / brand anchors and the closed lamp-label set plus the non-lamp caption SET; never xpath, never hashed CSS classes.

## Anti-patterns to avoid
- Wiring a live-Pulse-dependent suite (`a11y:driven`, the `sr*` family, `run --live`, feature-gated live targets) as a CI gate (per §11 CI; §9 Live-Pulse scenarios; §6 records the `sr*` family as "never a CI stage, never an `agent-run` verb").
- Setting nextest/mocha retries, lowering or skipping a binding gate to make the new job green, or accepting a run-to-run-variant suite into the gate (per §10 Zero-flakiness budget; §11 Quality).
- `sleep(N)` for synchronization inside a test, and any human-in-the-loop step — no Percy/Chromatic/Applitools, no "human reviews screenshots", no interactive recorder/inspector (per §11 E2E; §11 Universal).

## Contract bindings
- tests ↔ obs: §3 (Bootstrap → log-format-bind-with-obs) makes test-plan §3 the SOURCE OF TRUTH for the JSONL format, from which obs derives its envelope; the field-allowlist / redaction layer is the one piece obs owns downstream, and test-plan asserts that boundary via a negative test. The chunk's "redacted, service-tagged JSON aligned to the obs-owned format" must be pinned against obs-plan §3's self-obs base fields (service identity, `run_id`, `timestamp_ms`, `level`, `target`) and must not be conflated with the eleven-field run-report envelope (§3 Log format, Status endpoint shape).
- tests ↔ a11y: §6 owns the driver / mode / firing-form record for all three suite families over the one WebdriverIO + tauri-driver stack and §11 owns the ban set; the WCAG assertions themselves are a11y's. §11 Universal notes the Color-Only a11y rule is what makes text/role selectors reliable.
- tests ↔ security: §9 and §10 (Build failure conditions) require `cargo audit` + `cargo deny check` green and an un-drifted committed `Cargo.lock`; any `ci.yml` edit must leave those steps intact (§11 CI). §1 (Vector-1 coverage trigger) splits the `CONDUCTOR_MSEDGEDRIVER` / `CONDUCTOR_NVDA` host dev-tool handles per READER — no Rust negative test is reachable for either; their mandated coverage is the skip arm asserted at the e2e tier.
- tests ↔ harness/shells: §3 Bootstrap 5-command-discipline-wire binds `.sh`/`.ps1` to identical semantics, explicitly including the webview E2E leg.

## Acceptance criteria contributions
- (tests) The a11y CI job fires through the harness verb with identical `.sh`/`.ps1` semantics and leaves the 5-command count unchanged; no new port, env var or `CONDUCTOR_*` handle, and the envelope / `status` read / JSONL shapes untouched (per test-plan.md §3 CI stage selectors + §3 Bootstrap 5-command-discipline-wire).
- (tests) No live-Pulse-dependent leg (`a11y:driven`, `sr*`, `run --live`, feature-gated live targets) is wired as a CI gate, and the gate cannot be satisfied by a suite that skipped itself green — a context-skip is never a pass (per test-plan.md §11 CI + §6 routine-arm rule + §9 Build failure conditions).
- (tests) Zero retries configured on the new job; any suite with recorded run-to-run variance is either fixed at the cause or excluded from the gate, with the decision stated (per test-plan.md §10 Zero-flakiness budget).
- (tests) The emitted violation JSON carries no absolute host paths and no internal seam-crate struct names, and is distinguishable from both the per-run emission journal envelope and the self-obs line (per test-plan.md §3 Log format + Status endpoint shape).
