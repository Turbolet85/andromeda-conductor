# arch extract

## Relevance
Relevant — the chunk lands a new CI job, touches the registered a11y driver stack/handles, and adds an emitted artifact, all of which architecture.md governs (assertion content itself is a11y-plan's).

## Constraints
- CI is **build + test gating only**, and live-Pulse dynamic proof is explicitly *not* a CI gate (CI has no Pulse instance) — so the gate's without-Pulse framing is an architecture mandate, not just this entry's preference; any suite needing `ANDROMEDA_PULSE_MCP_ENABLED` / a live corpus stays an operator/local gate (per architecture.md §Established Decisions [CI/CD] and §Infrastructure Patterns — CI/CD approach). This is the plan-level answer that constrains the chunk's open question 1.
- Test running is pinned to `cargo nextest` through a **zero-retry `ci` profile** in `.config/nextest.toml`, with the stated rationale "no retries mask flakes — the determinism invariant" (per architecture.md §Infrastructure Patterns — Build system). A gate over a suite with known run-to-run variance may therefore not be stabilized by retries; the discipline bears directly on the chunk's open question 4 / CARRY 3(3).
- The webview bundle must be built (`npm run build`) **before any workspace cargo compile of `conductor-tauri`** (`generate_context!` resolves `build.frontendDist` at compile time), and `npm run build` alone is **not sufficient** — a binary that must serve the embedded bundle requires `--features tauri/custom-protocol`, otherwise it loads `devUrl` (`http://localhost:5173`) (per architecture.md §Infrastructure Patterns — Build system). Whether the existing workflow's jobs already satisfy this ordering for a webview-driving job is research's question.
- `CONDUCTOR_MSEDGEDRIVER` and `CONDUCTOR_NVDA` are registered as **operator-owned host dev-tool handles, read only by `wdio.conf.ts`, never by a shipped binary**, validated at the harness edge (existence + `isFile` + shell-metacharacter rejection), passed as separate argv elements of an array-form spawn, and **skip-at-exit-0 when unset**, with the value never logged, echoed into an artifact, or committed (per architecture.md §Occupied Resources — Environment variables). The chunk's open question 2 asks to change that skip semantic; architecture.md states it as the current mandate, so any fail-closed CI arm is an arch amendment at wrap, not a silent behavior swap.
- Configuration handles live in the reserved `CONDUCTOR_*` namespace only; precedence is files over env defaults and CLI flags over env; there is no secrets manager and no cloud config (per architecture.md §Occupied Resources — Environment variables and §Cross-cutting Patterns — Config management). A new "CI strict" handle must be `CONDUCTOR_*`-named and registered.
- The a11y driver listeners `127.0.0.1:4444` / `:4445` are **dev-only and harness-lifetime**, and no shipped binary gains a listener — the sole shipped-binary bind is the port-occupier fault scenario on `:4317` (per architecture.md §Occupied Resources — Ports and §Cross-cutting Patterns — Trust boundary).
- `crates/conductor-tauri/ui/` is an npm subtree, **not a Cargo workspace member**; `package-lock.json` is committed while `node_modules/`, `dist/` and `ui/logs/` are git-ignored, and architecture.md deliberately summarizes the frontend at React/Vite/Tailwind/npm grain without enumerating a11y test tooling (that lives in a11y-plan/test-plan) (per architecture.md §Occupied Resources — Frontend asset subtree, and the 2026-06-27 amendment below). So a new committed harness config in that subtree (CARRY 5's `knip.json`) is an npm-tree file, not a workspace member, and its devDep pins defer to a11y-plan.
- Harness-emitted precondition/readiness strings are **host-path-free and redacted** (`data_dir` redacted; the skip messages name the handle, never its value) (per architecture.md §Standard Contracts — readiness gate, and §Occupied Resources — Environment variables). The violation JSON's exact field set is obs-plan's, but the host-path-free floor is architecture's.

## Patterns to follow
- The `ensure_frontend` precedent: the frontend-before-cargo build step is already wired into `scripts/agent-run.{sh,ps1}` (`run` verb) **and the CI Rust job** — a new a11y job follows that established ordering rather than inventing one (per architecture.md §Infrastructure Patterns — Build system).
- The registered skip-guard shape in `wdio.conf.ts`: host-path-free precondition + a fetch recipe naming the handle, never its value, at exit 0 (per architecture.md §Occupied Resources — Environment variables). Any CI-strict variant should be an added arm over this shape, not a rewrite of it.
- Per-suite `CONDUCTOR_RUNS_DIR` selection at the ONE tauri-driver spawn site, with the self-obs sink resolving as `runs_dir.parent()/logs` — the routine `--e2e` arm at `runs/e2e-fixture` → `runs/logs/conductor-tauri.jsonl` (per architecture.md §Occupied Resources — On-disk artifacts, `logs/conductor-tauri.jsonl`). A CI job collecting artifacts must read the per-suite site, not a single fixed one.
- `.gitattributes` as an explicit **gate-correctness control** (the coverage gate's LF byte-compare, added because both CI jobs run `windows-latest`) — the precedent for a CI gate declaring its checkout/normalization dependency rather than assuming it (per architecture.md §Infrastructure Patterns — Build system).
- New CI content lands under `.github/workflows/`, the registered home; no new top-level directory (per architecture.md §Infrastructure Patterns — Directory structure).

## Anti-patterns to avoid
- Standing up a second browser-automation stack — architecture.md pins THREE suite families (four `wdio` suites) over the ONE WebdriverIO + tauri-driver stack, "never a second automation stack" (per architecture.md §Cross-cutting Patterns — Scope law).
- Making CI depend on a live Pulse, its data dir, or its `mcp-server` feature (per architecture.md §Established Decisions [CI/CD]).
- Masking a flaky suite with retries, or committing/logging an operator-owned handle's value to make a runner green (per architecture.md §Infrastructure Patterns — Build system; §Occupied Resources — Environment variables).

## Contract bindings
- **arch ↔ obs:** the violation JSON's service tag and environment ride the registered `CONDUCTOR_SERVICE_NAME` / `CONDUCTOR_ENV` handles, which architecture.md registers and delegates to obs-plan §3; architecture.md contributes only the host-path-free/redacted floor (§Occupied Resources — Environment variables; §Standard Contracts).
- **arch ↔ tests:** build profile and feature selection for any binary the gate drives (`--features tauri/custom-protocol`, frontend-before-cargo), plus the zero-retry `ci` nextest profile (§Infrastructure Patterns — Build system).
- **arch ↔ security:** the harness-edge validation + array-form spawn contract for `CONDUCTOR_MSEDGEDRIVER` / `CONDUCTOR_NVDA` — a CI-supplied driver path must keep that path and never be committed (§Occupied Resources — Environment variables).
- **arch ↔ a11y-plan:** architecture.md deliberately does not enumerate a11y test tooling; the pinned devDeps and assertion coverage are a11y-plan's, so CARRY 5's knip entry-point decisions defer there (2026-06-27 amendment, below).
- **Known adjacent CI gap, not this chunk's to claim:** architecture.md §Established Decisions [Module Boundaries] records that no CI job builds a workspace member standalone, so that property is measured-at-a-chunk rather than gate-enforced. Adding an a11y job does not close it, and the chunk should not imply it does.

## Acceptance criteria contributions
- (arch) The a11y CI job requires no live Pulse — it declares neither `ANDROMEDA_PULSE_MCP_ENABLED` nor `ANDROMEDA_PULSE_DATA_DIR`, and no Pulse-dependent suite is in the gated set (per architecture.md §Established Decisions [CI/CD] + §Infrastructure Patterns — CI/CD approach).
- (arch) The job builds the webview bundle before any cargo compile of `conductor-tauri`, and any binary it drives is built with `--features tauri/custom-protocol` rather than a bare release profile (per architecture.md §Infrastructure Patterns — Build system).
- (arch) The gate adds no listener to a shipped binary, no second automation stack, and `4444`/`4445` remain harness-lifetime only (per architecture.md §Occupied Resources — Ports + §Cross-cutting Patterns — Scope law/Trust boundary).
- (arch) Any new configuration handle sits in the reserved `CONDUCTOR_*` namespace and is registered at wrap; no operator-owned handle's VALUE is committed, logged, or emitted into the violation JSON, and no emitted string carries an absolute host path (per architecture.md §Occupied Resources — Environment variables + §Standard Contracts).
