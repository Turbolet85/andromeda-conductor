## Patterns to follow
- The host-tool handle pattern (a11y-plan §3 bootstrap `a11y-ci-gate-wire` `:299`): `CONDUCTOR_MSEDGEDRIVER` unset ⇒ skip at exit 0, with strict mode flipping unresolved-handle to a gate failure. The path fix belongs on the resolution side (make the handle name a real file), not on the guard.
- Both-shell parity for the verdict assertion — a11y-plan §11 CI (`:564`) names "both harness shells" as asserting the printed verdict, matching the chunk's `agent-run.ps1` / `agent-run.sh` parity invariant.
- Results surface through the `logs` command of tests' binding 5-command harness contract (a11y-plan §3 CI integration `:281`, §9 Pipeline integration `:470`) — the a11y JSON step rides the `wdio run` webview leg rather than a new lane.
- Focus measurement pattern already specified by a11y-plan §3 Focus management test harness (`:253`) and §5 (`:372`): `browser.keys([...])` then `browser.execute(() =&gt; document.activeElement?.getAttribute('data-testid'))` after each key — the instrument for measuring which element holds the sequential-focus starting point.
- NVDA speech-log grading (a11y-plan §3 `:268-269`): `-l 12` log graded against the per-state pass spec at `crates/conductor-tauri/ui/test/a11y/screen-reader/nvda-pass-spec.md`, browse-mode rows recorded as findings and never as passes.

## Anti-patterns to avoid
- Never relax the strict guard, the expected-skip SET, or the printed-verdict assertion to obtain a green (or a red) — a11y-plan §11 CI (`:564`) requires a skipped-green run to stay distinguishable from a real pass.
- Never apply a retry, a runner pin, or a soft threshold to the announcement variance or to any a11y violation — a11y-plan §11 SLO (`:570-571`), §10 (`:489`).
- Never claim WCAG conformance from the SR leg alone — a11y-plan §11 Strategy (`:518`) and §11 Universal (`:577`) require machine output (axe / colorjs.io / WebdriverIO) as the baseline, with NVDA supplemental.
