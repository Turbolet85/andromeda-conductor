## Constraints
- **CI job identity is pinned, and the driver comes from the image.** architecture.md §Infrastructure Patterns — Build system requires the `a11y` job on the explicit `windows-2025` label ("pinned rather than floating so a `-latest` move cannot change the Edge driver the leg resolves from the image"); the fix must resolve the image's driver rather than add an install step or a `-latest` label. Whether `.github/workflows/ci.yml` currently satisfies the label/driver premise at HEAD is research's question.
- **The CI exclusion is the LIVE-PULSE dependency, not the end-to-end tier.** architecture.md §Established Decisions [CI/CD] + §Infrastructure Patterns — CI/CD approach require that only proof needing a live Pulse (`mcp-server` feature + `ANDROMEDA_PULSE_MCP_ENABLED`) stay operator-local; the routine `--e2e` arm is gateable *because* it seeds its own fixture. This is the rule that keeps `a11y:driven` and `sr*` out of CI.
- **Both harness shells are one surface, and `agent-run.sh` is the release gate.** architecture.md §Design Philosophy (headless-drivable core, thin shells) + §Cross-cutting Patterns — Development Style (agent-driven) require the headless path to be the source of truth; a change to `Assert-A11yVerdict` that is not mirrored in `assert_a11y_verdict` breaks that invariant.
- **`CONDUCTOR_*` is the reserved namespace, with four registered handle classes and per-class control models.** architecture.md §Occupied Resources — Environment variables requires: `CONDUCTOR_MSEDGEDRIVER`/`CONDUCTOR_NVDA` (operator-supplied host-tool paths — existence + `isFile` + shell-metacharacter rejection, array-form spawn, never shell-interpolated), `CONDUCTOR_E2E_SEED_DIR` (harness-set repo-relative path), `CONDUCTOR_A11Y_STRICT` (flag-valued, read by `wdio.conf.ts` AND both shells, never by a shipped binary). §Occupied Resources further requires that `CONDUCTOR_A11Y_STRICT` strictness be an ADDED arm, never a relaxation of the guard. `EDGEWEBDRIVER` is a runner-image variable, not a Conductor handle; if the fix introduces any *new* handle it must land in this namespace under one of these models.
- **Handle values are never logged, echoed into an artifact, or committed.** architecture.md §Occupied Resources — Environment variables requires precondition text to name the handle only; the scope's proposed printed `Test-Path` precondition line must report presence, not a path.
- **`npm run build` is necessary but not sufficient — the `custom-protocol` FEATURE decides bundle embedding.** architecture.md §Infrastructure Patterns — Build system requires `cargo build --release -p conductor-tauri --features tauri/custom-protocol` for a binary that serves the bundle (a bare release build loads `devUrl`), and requires the webview bundle built before any cargo compile of `conductor-tauri` (`generate_context!` resolves `build.frontendDist` at compile time). Whether the CI step's 6 m 10 s release build already uses the feature form is research's question.
- **The app-under-test fixes land outside the Cargo workspace.** architecture.md §Occupied Resources — Frontend asset subtree places `crates/conductor-tauri/ui/` as a non-Cargo-member npm subtree; §Inherited Defaults — Frontend pins React 19 / Vite ≥8.0.16 / Tailwind v4.1 / TypeScript strict / `npm audit --omit=dev` with a committed `package-lock.json`. The re-announce (1) and focus-start-point (2) fixes therefore add no workspace crate and no cross-seam dependency edge.

## Patterns to follow
- **One driver stack, one config, three suite families.** architecture.md §Cross-cutting Patterns — Scope law + §Occupied Resources — Ports establish `wdio.conf.ts` as the single config all four suites fire, binding harness-lifetime `127.0.0.1:4444`/`4445` and releasing them with the session.
- **Single-site routing for a shared decision.** §Occupied Resources — `CONDUCTOR_A11Y_STRICT` records both skip sites routed through one `exitUnresolvedHandle()`, so strictness flips in one place; a diagnostic-print fix should follow the same shape rather than duplicating the arm per suite.
- **Reuse the existing gate, never a second copy of the schema.** §Occupied Resources — On-disk artifacts records `runs/a11y/<run_id>.jsonl` asserted by `conductor-run`'s `journal_conformance` under `CONDUCTOR_RUNS_DIR=runs/a11y` — the same test the run journal uses.
- **Harness-owned capture sites take no handle of their own and move with `CONDUCTOR_RUNS_DIR`.** The `runs/live-suite/{leg}.jsonl` precedent (§Occupied Resources — On-disk artifacts): git-ignored, deterministically stemmed, cleared per invocation by a non-recursive `rm -f …/*.jsonl`. Applies if the diagnostic-output fix keeps a log file.
- **Per-suite `CONDUCTOR_RUNS_DIR` chosen at the ONE tauri-driver spawn site**, which is what moves the self-obs landing site per suite (§Occupied Resources — `logs/conductor-tauri.jsonl`).

## Anti-patterns to avoid
- **No second automation stack, and no `sr*` suite in CI** — architecture.md §Cross-cutting Patterns — Scope law admits driving Conductor's OWN webview only as three suite families over ONE WebdriverIO + tauri-driver stack; §Established Decisions [CI/CD] keeps live-Pulse-dependent arms operator-local.
- **No inbound listener of Conductor's own** — architecture.md §Cross-cutting Patterns — Trust boundary allows only the harness-lifetime `4444`/`4445` driver listeners and the deliberate port-occupier bind of `:4317`; a diagnostic or driver fix must add none.
- **Never commit, echo, or log a handle's value** (§Occupied Resources — Environment variables); host paths must not reach an artifact — `runs/a11y` fingerprint selectors are DOM-relative/`data-testid` precisely so the record can carry none.

## Contract bindings
- **arch ↔ obs:** the `runs/a11y/<run_id>.jsonl` envelope's extra resource tags (`service.name` `conductor-ui`, `deployment.environment`, plus `ci.run.id` + `git.commit.sha` under CI — 13 keys locally / 15 under CI) are admitted by obs-plan §3's extension point, which arch §Occupied Resources requires `journal_conformance` to honour by asserting key PRESENCE, not exclusivity.
- **arch ↔ tests:** that same artifact is gated by `conductor-run`'s `journal_conformance`, the run-journal test reused under a redirected `CONDUCTOR_RUNS_DIR` — arch registers the artifact and the reuse rule; test-plan owns the gate's zero-flake bar the scope's finding (3) cites.
- **arch ↔ security:** `CONDUCTOR_A11Y_STRICT` is an added arm over the wdio-edge guard (existence + `isFile` + shell-metacharacter rejection), never a relaxation — arch §Occupied Resources defers the guard itself to security-plan §Security Anti-Patterns → Input.
- **arch ↔ a11y:** arch fixes the placement (`crates/conductor-tauri/ui/`, non-Cargo-member) and the one-stack law; a11y-plan §11 owns the Operable carve-out and what closing finding (2) unblocks.
