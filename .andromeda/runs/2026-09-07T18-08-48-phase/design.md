## Constraints
- Any element that becomes the sequential-focus starting point, or that gains focus as a result of fix (2), must render the visible focus ring in `--color-focus` (`#7DCFFF` dark / `#0969DA` light — the same ID-cyan as the mono status tier), per design-system §Color Palette → Border Progression (Focus). §Depth Strategy permits `box-shadow` **only** as `0 0 0 2px var(--color-focus)` — a ring, never an elevation shadow; borders-only depth otherwise, no `backdrop-filter`.
- Every value the fix writes must bind by `var(--…)` name from the 34-token `:root` contract (colors / `--space-*` / `--radius-*` / `--motion-micro` / `--ease-quiet`), declared on plain `:root` with a `@media (prefers-color-scheme: light)` override, per design-system §Surface: desktop-webview → Tokens. No raw hex, px, or ms literal; no new palette row.
- If the re-announce or focus fix introduces any transition, it is `--motion-micro` (150ms) + `--ease-quiet`, CSS only (no animation library), per design-system §Motion. §Motion hard limits BAN pulse / blink / glow on any status and any flashing attention cue — a re-announce must be a text re-assertion, not a visual flash. All transitions drop under `@media (prefers-reduced-motion: reduce)`.
- Status and state signals are never color-alone: a lamp/state is always paired with its text label plus an `aria-live` announcement, per design-system §Component Patterns 4 and §Iconography (Rule). A re-announce mechanism must re-assert *text*, not re-tint.
- Icon-only controls (the titlebar min/close Lucide glyphs, 16px, hover lift 150ms) each carry an `aria-label`, per design-system §Iconography and §Component Patterns 1 — these labels are the accessible names the leg's tab-order measurement reads ("Minimize window" / "Close window"). Whether the shipped code already carries them is research's question.
- Keyboard-first is mandatory: design-system §Surface: desktop-webview → Per-Surface Bans forbids hover-only interactions without keyboard alternatives, and §Navigation Pattern makes keybindings first-class with no browser-style nav — so a focus-start-point fix may not trade keyboard reachability for a mount-time convenience.
- The axe/contrast arm of the a11y gate enforces design's Text Hierarchy values (`--text-tertiary` `#838EBA`, `--text-muted` `#727EB5` dark / `#636882` light), which design-system §Color Palette → Text Hierarchy records as solved against every surface pair in both themes. Those values may not be re-tuned to obtain a green run — mirroring the scope's own "strict-mode guard is not relaxed to obtain redness or greenness".

## Patterns to follow
- **§Component Patterns 1 (Frameless titlebar + Paused-count).** The drag-region bar hosting the phase line, count, and the right-side min/close Lucide controls — this is the surface the R0-02 first-Tab landing measurement falls on, and where §Component Patterns 1 requires `aria-live="assertive"` for the HOLD flip. Also its standing rule: no drag-region pointer cursor leaking into controls.
- **§Component Patterns 5 (Scenario/suite picker).** shadcn `Command`/`Select` over `--color-raised-2`, inputs `--color-inset` + `1px --border-standard` + `--color-focus` ring, keyboard-first. The leg attributes the focus start point to "the picker input at mount"; the plan mandates the focus ring and keyboard path, not an autofocus — whether anything focuses at mount is research's question.
- **§Component Patterns 5 (Filter miss).** The nearest shipped precedent for fix (1): a *persistently-mounted* announced region rendering `No scenarios match.` in the list's existing recessive tier (no new token), with the plan's recorded caveat that a region mounting together with its text announces nothing.
- **§Component Patterns 4 (Verdict / report-state lamp).** Resolves motionless via a 150ms color transition, always paired with text + `aria-live` — the shape the announcement-variance rows (S0-01/S0-02, E0-06/07/09) are graded against.
- **§Component Patterns 6 / 3 (Run-report + Coverage matrix empty states).** The shipped `No run yet` and `No coverage data.` prose are the exact announced strings the SR subjects read; per §Component Patterns 6 the in-progress state ships no report-area prose, and "no result yet" must never be downgraded to a red `Fail`.

## Anti-patterns to avoid
- No `alert()` / `confirm()` / `prompt()` and no native OS toast as a re-announce vehicle — design-system §Per-Surface Bans (desktop-webview) mandates the styled `AlertDialog`, and §Platform-Specific Notes states Conductor MUST NOT emit native OS toasts (that is Pulse behavior it observes).
- No flashing / pulsing / animated attention cue to force an announcement, and no flashing red on `Fail` — design-system §Motion (Hard limits) and §Rejected Defaults ("a flashing / pulsing red banner or animated alert toast on a Fail verdict").
- No new hex, px, ms, or font family introduced by the fix; Inter / Roboto / Arial / Helvetica / system-ui are banned as primary faces — design-system §Anti-Patterns → Universal Bans, and §Self-Validation Protocol (Token Test).

## Contract bindings
- **Token contrast ↔ a11y §Contrast (SC 1.4.3).** Design owns the hex values (§Color Palette → Text Hierarchy); a11y owns the 4.5:1 criterion; the gate's *contrast* arm is the enforcement point for both.
- **Motion tokens ↔ a11y §Animation (SC 2.3.3).** The `prefers-reduced-motion: reduce` override in the §Tokens block is mandatory for anything the fix animates.
- **State color + text label ↔ a11y §Use of Color (SC 1.4.1).** The text the SR leg grades as `announced` is the same text design requires alongside every state color (§Component Patterns 4, §Iconography Rule).
- **Icon-only control `aria-label`s ↔ a11y / tests harness.** Design mandates the labels (§Iconography); the SR leg's `tabs_to_start` and first-Tab-target assertions consume them as accessible names.
- **Focus ring ↔ layouts (focus order).** Design owns the ring token and its `0 0 0 2px` form; the per-screen focus *order* is layouts' domain, not extracted here.

## Acceptance criteria contributions
- (design) Every element the fix makes focusable or focuses renders the visible `0 0 0 2px var(--color-focus)` ring, and no `box-shadow` is used for elevation (per design-system §Depth Strategy / §Color Palette → Border Progression).
- (design) The re-announce and focus fixes introduce no hardcoded hex / px / ms — all values bind by `var(--…)` name from the 34-token `:root` contract, dark block + light `@media` override intact (per design-system §Surface: desktop-webview → Tokens).
- (design) The re-announce signal is carried by text (not color or motion alone), adds no pulse / blink / flash, and any transition it adds uses `--motion-micro` + `--ease-quiet` and is dropped under `prefers-reduced-motion: reduce` (per design-system §Motion).
- (design) Contrast-critical token values (`--text-tertiary`, `--text-muted`) are byte-unchanged by this chunk — a green axe run is obtained by fixing the driver path, never by re-tuning the palette (per design-system §Color Palette → Text Hierarchy).
