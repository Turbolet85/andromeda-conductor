## Constraints
- The frameless titlebar is a three-zone flex row — left phase line, center count, right window controls (minimize then close, Lucide, icon size grid) — so visible left→right order is minimize-before-close; layout-templates §Component — Header (frameless titlebar + Paused-count heartbeat) requires that ordering, and a sequential-focus fix must not reorder or re-nest the zones to obtain it. Whether the shipped DOM order already matches this visible order is research's question.
- Every interactive control must carry a visible `color-focus` ring and the focus position must be communicated to assistive tech; the active picker item additionally carries a `border-emphasis` edge so focus is never color-only (layout-templates §Component — Primary navigation (single-station run control)). Whatever element ends up holding Chromium's sequential-focus starting point must satisfy this.
- The console is one surface with no router, no routes, no deep links, no breakpoints, and `alert()`/`confirm()`/`prompt()` are never used — the styled `AlertDialog` is the only modal (layout-templates §IA notes; §Decisions Log → Responsive breakpoints: N/A). A re-announce mechanism or focus fix must stay in-window and mint no new surface.
- The empty-catalog state and the picker's filter-miss state are TWO states, two strings, two owners: `No scenarios found.` owned by `App.tsx`, and `No scenarios match.` rendered from a **persistently-mounted announced region** (layout-templates §Component — Primary content block 1 (coverage matrix) → States). Any change touching the SR `empty` subject rows must preserve that split and the persistent mount.
- Focus restoration for the operator-pause dialog is contract-borne, not Radix-supplied: the dialog takes a `restoreFocusTo` accessor and restores in `onCloseAutoFocus`, and the invoking control must stay focusable — `Start` conveys unavailability with `aria-disabled`, never the native `disabled` attribute (layout-templates §Component — Hero / signature section). A focus-start-point fix must not make a control unfocusable.
- cli/harness diagnostics stay on the documented error shape: messages to **stderr**, sanitized with no absolute host paths / internal struct names / stack traces, as `error: <short>` + detail + `hint: <fix>`, with stdout reserved for raw artifact data (layout-templates §Component — Footer / terminator + error output). The CI driver-path precondition line and any restored diagnostic print inherit this.
- The `--e2e` stage asserts the runner's **printed** verdict — the `Spec Files:` failed count, per-spec skip markers against the expected-skip set, and the `[webview2 … windows]` driven-session banner — because the exit code alone cannot distinguish a full pass from a total skip; and both shells ship at identical semantics (layout-templates §Surface: cli — Primary screens, `scripts/agent-run.{sh,ps1}`). A fix to the swallowed-output defect must keep that printed-verdict assertion reachable, in both shells.

## Patterns to follow
- Three-zone titlebar (`data-tauri-drag-region`, `space-xl` height, `space-xs` cluster gaps, `border-subtle` bottom seam, borders-only depth) with window controls last in the right zone — layout-templates §Component — Header.
- Keyboard-first register modelled on k9s/lazygit: start/stop/proceed/abort each bound to a shortcut through the Radix primitives, hover affordances always with a keyboard equivalent, hint row pinned for discoverability — layout-templates §Component — Primary navigation.
- Region-siting precedent for projected content: checklist rows render as a **sibling** of the dialog's `Description`, never nested inside it, because the Description is the described-by target — layout-templates §Component — Hero / signature section (checklist rows) and §Component — Operator-checklist. The same "sibling, not nested" siting discipline applies to any re-announce region added near a described-by target.
- Absence states are distinguished by TEXT, never by tint alone (`Not yet run` prose, `No run yet`, `No scenarios found.`) — layout-templates §Component — Primary content block 1 and §Component — Primary content block 2 (Distinct non-result states).
- Host-path-free `error:` / `hint:` precondition line as the shape a missing/unresolved host-tool handle prints — layout-templates §Surface: cli — Primary screens (`--e2e` gating clause) + §Component — Footer / terminator + error output.

## Anti-patterns to avoid
- No native `alert()`/`confirm()`/`prompt()` and no second modal primitive for announcing a load-time error (layout-templates §IA notes).
- No native `disabled` on an invoking control, and no color-only focus or status signal (layout-templates §Component — Hero / signature section; §Component — Primary navigation).
- No new route, breakpoint, or extra surface region to carry a focus or announcement fix — the frameless window IS the surface, and the footer `contentinfo` strip is recorded DESIGNED-NOT-SHIPPED, so it is not an available host for new state (layout-templates §IA notes; §Component — Footer (status strip)).

## Contract bindings
- **Focus order ↔ a11y §Focus Order (SC 2.4.3):** layouts fixes the visible left→right titlebar zone order; a11y owns the conformance claim that focus order matches it. The sequential-focus start-point holder is explicitly unmeasured per the chunk scope — layouts states the target order only.
- **Modal focus ↔ a11y §Modal focus trap:** Radix supplies trap + Escape; restoration is the `restoreFocusTo` contract this plan mandates (§Component — Hero), so the a11y spec and the component contract must agree.
- **Announcement mechanism ↔ a11y:** layout-templates repeatedly defers the live-region attribute to a11y ("a11y derives the live-region attribute", §Component — Header, §Primary content block 1/2). Layouts contributes only the region's SITING and persistence (persistently-mounted filter-miss region, §Primary content block 1 States); the re-announce mechanism itself is a11y's.
- **cli surface ↔ tests/harness:** layout-templates §cli Primary screens states the `--e2e` printed-verdict assertion shape and the strict-arm/lax-arm outcome set; the harness domain owns the implementation of that assertion under the CI error preference.
