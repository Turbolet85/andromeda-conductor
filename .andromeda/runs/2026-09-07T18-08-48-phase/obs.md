## Constraints
- The a11y violation record at `runs/a11y/<run_id>.jsonl` is a registered telemetry artifact: it must be produced by the `a11y` job, uploaded (`actions/upload-artifact@v4`, `if-no-files-found: warn`), and asserted in-job by `journal_conformance` under `CONDUCTOR_RUNS_DIR=runs/a11y` (per obs-plan §9 Telemetry artifact handling). A red arm that yields no record leaves this mandated artifact unproduced — so the green run this chunk owes is also this artifact's obligation.
- The record's shape: the eleven envelope keys PLUS the §9 resource tags `service.name` / `deployment.environment` (13 top-level keys locally, 15 under CI where `ci.run.id` + `git.commit.sha` join), and conformance asserts key PRESENCE, closed sets, and host-path freedom — never key exclusivity, which is what lets one gate serve both record shapes (per obs-plan §3 Log format JSON schema, extension-point paragraph). "Required" means the key is present, not that its value is non-null (per obs-plan §6 Required fields).
- Every telemetry signal must have an agent-readable consumption path, and human-review-gated analysis without machine-parseable export is banned (per obs-plan §2 Agent-readable invariants and §11 CI). The scope's second defect (CI swallowing wdio's output so only `node.exe ended with non-zero exit code: 1` survives) is squarely this class; whether the shipped `agent-run.ps1` capture-then-print already satisfies the invariant under `$PSNativeCommandUseErrorActionPreference` is research's question.
- No absolute host-file paths (drive-letter `X:\`, `/home`, `/Users`, `%APPDATA%`, `~/.cargo`, `.rustup`, backtrace file paths) in any emitted field of the conformance-gated artifacts (per obs-plan §9 Log conformance check; §11 Logs). Bears directly on a fix that resolves `$env:EDGEWEBDRIVER` and prints a `Test-Path` precondition line, and on any SR speech capture.
- §11 PII Scrubbing carries a standing, deliberately unretired warning: the three application sites (subscriber field filter / report-write / runs.db insert) bound the sites they name, never every host-path channel — the 2026-09-02 console-pane case is the precedent, and the a11y leg's own `<host-path>` scrub is a second line of defence, not the only one.
- The span-name set is bounded and closed (`scenario.run`, `timeline.execute*`, `emit.batch`, `emit.logs_batch`, `verify.readback*`, `report.generate`, `db.insert_run`, `fault.*`, `tauri.command.*`) — this chunk adds no span, and the browser frontend must produce NO spans at all (per obs-plan §11 Spans/Traces and §11 Universal).
- Frontend self-observation is console JSON only: no OTel JS SDK, no `auto-instrumentations-web`, no browser OTLP export to any port (per obs-plan §1 desktop-webview row, §3 Sink (Tauri frontend), §11 Universal). Frontend `service.name` is `conductor-ui`, environment inherited from the backend env var (per obs-plan §3 Service identity) — the same tag the a11y record is required to carry.

## Patterns to follow
- Diagnostic detail rides the already-allowlisted `message` field rather than a new span attribute or field name — the boundary-call witness pattern (`verify.readback` observed-key-set, `emit.batch` wire-shape witness, the lifecycle-write incident id). A field name outside `conductor-core::redact::ALLOWLISTED_FIELDS` is dropped at the processor stage, so a dedicated attribute would emit nothing (per obs-plan §6 Boundary-call wrappers).
- The report-seam/harness-artifact records (`runs/<run_id>.jsonl`, per-check `CheckRecord`, and the a11y violation record) do NOT pass through the span-attribute field allowlist — that allowlist governs the self-obs line only (per obs-plan §3 two record shapes). A new key on the a11y record is therefore an envelope-shape question, not an allowlist question.
- Conformance-gate targeting is record-shape-specific: `logs/agent-latest.jsonl` is checked against the §3 self-obs base schema (`timestamp_ms`/`level`/`target`/service identity/`run_id`), while the envelope-shaped records get the run-journal conformance gate (per obs-plan §9 Log conformance check).
- The Tauri backend sink's file NAME is fixed and its DIRECTORY rides `CONDUCTOR_RUNS_DIR` (`runs_dir.parent()/logs`) — measured landing sites include `runs/logs/` (routine `--e2e`), `runs/sr-leg/logs/` (`sr`/`sr-error`), `runs/driven/logs/` (per obs-plan §3 Log file location). Any suite this chunk moves or re-runs moves its own log sink with it.
- CI resource attributes are `deployment.environment: dev`, `ci.run.id` from `${{ github.run_id }}`, `git.commit.sha` from `${{ github.sha }}` (per obs-plan §9 CI-specific resource attributes).

## Anti-patterns to avoid
- NEVER lose telemetry artifacts, and NEVER gate log analysis behind human review without a machine-parseable export (per obs-plan §11 CI) — a fix that makes the gate green but leaves the next red run opaque still violates this.
- NEVER leak absolute host paths or internal struct names into logs, run-report artifacts, or the a11y record (per obs-plan §11 Logs and §11 PII Scrubbing).
- NEVER introduce an OTel SDK/exporter or any self-observation OTLP on any surface, including the browser frontend touched by the re-announce and focus fixes (per obs-plan §11 Universal and §11 Telemetry Strategy).

## Contract bindings
- **obs ↔ a11y** — the a11y surface emits its violation record into obs's structured-record format at `runs/a11y/<run_id>.jsonl` via `writeA11yEnvelope`; obs §9 owns its artifact row and obs §3 owns the shape it extends (eleven envelope keys + resource tags).
- **obs ↔ tests** — test-plan §3 OWNS the JSONL format; obs §3/§6 reproduce it and must not re-author it. `journal_conformance` is the shared gate; its presence-not-exclusivity semantics are the binding term. Finding 3 (run-to-run announcement variance) binds to the tests-side zero-flake bar the scope cites (`test-plan.md:500`) — obs's contribution is that the variance be RECORDED on an agent-readable artifact, not in prose.
- **obs ↔ security** — host-path freedom / PII scrubbing at the redaction layer, and the sidecar spawn ban ("never with a visible console window") is a shared cross-master citation that moves on both sides together (per obs-plan §11 PII Scrubbing and §11 Project-specific bans).

## Acceptance criteria contributions
- The a11y job produces `runs/a11y/<run_id>.jsonl`, uploads it as a CI artifact, and the in-job conformance step runs and passes under `CONDUCTOR_RUNS_DIR=runs/a11y` (per obs-plan §9 Telemetry artifact handling).
- That record carries the eleven envelope keys plus `service.name` = `conductor-ui` and `deployment.environment`, with `ci.run.id` + `git.commit.sha` joining under CI; asserted as key presence, never exclusivity (per obs-plan §3 Log format JSON schema).
- A RED a11y arm's own diagnostic (wdio output, including the strict-arm unresolved-handle message) reaches an agent-readable surface — job log or uploaded artifact — rather than being reduced to a single non-zero-exit line (per obs-plan §11 CI and §2 Agent-readable invariants).
- No absolute host-file path (drive-letter, `/home`, `/Users`, `%APPDATA%`, `~/.cargo`, `.rustup`) appears in the a11y record or in emitted self-obs fields, including anything introduced by the driver-path resolution or the SR speech capture (per obs-plan §9 Log conformance check and §11 PII Scrubbing).
