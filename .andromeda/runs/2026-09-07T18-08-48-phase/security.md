# security extract

## Relevance
**Partial** — the chunk is a11y/harness/CI work, but it touches three named security boundaries: the `CONDUCTOR_MSEDGEDRIVER` dev-harness path handle, the `CONDUCTOR_A11Y_STRICT` flag handle, and the screen-reader speech-log ingest into a committed evidence record; plus the CI workflow that carries the dependency-audit gates.

## Constraints
- The `CONDUCTOR_MSEDGEDRIVER` wdio-edge guard is the whole of this handle's validation duty — existence + `isFile` + shell-metacharacter rejection before the driver spawn, then the value as a separate argv element of an array-form spawn (per security-plan §Input Validation → `CONDUCTOR_MSEDGEDRIVER` row). The plan deliberately exempts this handle from the Rust `std::fs::canonicalize` rule *because* no Rust code reads it (per §Security Anti-Patterns → Input, canonicalize ban). The CI red must therefore be fixed by making the handle's **value** resolvable, never by loosening the guard that correctly rejected it.
- The unresolved-handle outcome must name the **handle**, never its value: §Input Validation requires a host-path-free precondition on the `CONDUCTOR_MSEDGEDRIVER` skip arm and a host-path-free fetch recipe on the `CONDUCTOR_NVDA` skip arm, and requires that `CONDUCTOR_A11Y_STRICT`'s value "never becomes a path, an argv element, a spawn program or a log value" (per §Input Validation → `CONDUCTOR_A11Y_STRICT` row). The fix shape the scope names — a printed `Test-Path` precondition line — inherits that duty: print the handle name and a boolean grade, not the resolved path. Whether the shipped precondition/skip text is already host-path-free is research's question.
- `CONDUCTOR_A11Y_STRICT` may only INVERT what an already-unresolved handle costs; §Input Validation requires that `nativeDriver()` / `nvdaExe()` and their `UNSAFE_PATH` checks stay **byte-unchanged** — "an ADDED arm over the existing guards, never a relaxation of them" (per §Input Validation → `CONDUCTOR_A11Y_STRICT` row). This is the plan-side statement of the scope's own "strict-mode guard is not relaxed" boundary.
- Re-graded SR rows for findings 1–3 must reach the committed record only through the mandated ingest controls: spec-id cross-check against `nvda-pass-spec.md`, closed `outcome` / `arm` / `review_grade` sets, `heard` bounded at 400 chars, and a **mandatory** host-path scrub (drive-letter / `%APPDATA%` / `/Users` / `/home` token → `<host-path>`, the row gaining a `security_finding`), with the raw log staying under gitignored `runs/` (per §Input Validation → speech-log ingest row). The plan classes the NVDA speech log as **untrusted third-party text** — it transcribes whatever took the OS foreground — so this binds every new grading run, not only the first. Whether `writeNvdaPass` currently applies all four controls is research's question.
- Committed evidence records and run artifacts must carry no absolute host path and no internal seam-crate struct name (per §Security Anti-Patterns → Logging, which names `evidence/nvda-pass.json` explicitly). §Security Anti-Patterns → Code Patterns rule (a) records the 2026-09-04 measurement — S1-01's `heard` losing `<host-path>` and the record carrying 0 `security_finding` rows — as the evidence the console-suppression duty is held; a re-graded record that reintroduces either would read against that, so P3 should establish the current record's state rather than assume it.
- Any new spawn the focus-holder measurement (finding 2) or a re-announce leg introduces must fit one of the **five** governed harness-spawn forms — array-form argv, fixed or repo-resolved program, operator value only as a separate argv element after metacharacter rejection, never a shell string, never as the program except through the guarded host-tool form (per §Security Anti-Patterns → Code Patterns rule (b)). A sixth form is a boundary widening the plan's own history marks never-routine and escalate-only.
- CI edits to `.github/workflows/ci.yml` must leave the supply-chain gates intact: §Security Anti-Patterns → Universal forbids the release gate without `cargo-audit` (+ recommended `cargo-deny`) green, and §Dependency Security → Frontend (npm) supply chain requires `npm audit --omit=dev` clean (0 PRODUCTION vulnerabilities) with `package-lock.json` committed for any change under `crates/conductor-tauri/ui/`.

## Patterns to follow
- **The host-dev-tool handle pattern** (`CONDUCTOR_MSEDGEDRIVER` · `CONDUCTOR_NVDA`): guard at the wdio edge, then array-form spawn with the guarded value as program or argv element; unset-or-not-a-file ⇒ SKIP at exit 0 (lax) with a handle-named, value-free precondition (per §Input Validation, both rows). The CI fix should make the value resolve *upstream* of this pattern rather than reshaping it.
- **Handle-name-only / `<redacted>` rendering for path-valued handles in operator-visible output** — §Input Validation → `ANDROMEDA_PULSE_*` declaration-only row records the probe rendering handle NAMES only and the readiness gate's `data_dir` as `<redacted>`. This is the existing precedent for how the restored diagnostic output and the new CI precondition line should render a path handle.
- **Env-map propagation, never argv, never a shell** — the `CONDUCTOR_E2E_SEED_DIR` model: a harness-owned constant carried to a child through the spawn's env map only (per §Input Validation → `CONDUCTOR_E2E_SEED_DIR` row; §Code Patterns rule (b), fourth form). The applicable shape if the CI fix computes a value in one step and hands it to another (`$env:GITHUB_ENV` is the workflow analogue).
- **Scrub-then-commit with two gates** — §Input Validation → speech-log ingest row names gate-1 (hygiene grep: no host path / seam-crate struct name in the committed record) and gate-2 (closed sets) as the assertions that hold the ingest boundary. Re-grading findings 1–3 re-runs both.
- **Per-READER scoping of the canonicalize duty** (restated 2026-09-06, per §Security Anti-Patterns → Input): a handle's duty attaches to each reader separately, and an unguarded test-only or harness-only reader is recorded as an explicit residual rather than silently absorbed. The template if this chunk adds a reader of any existing handle.

## Anti-patterns to avoid
- NEVER weaken the wdio-edge guard, the `isFile` check, or the strict arm to obtain a green (or a red) run — the guard behaved correctly and the wiring did not (per §Security Anti-Patterns → Input, canonicalize/guard ban; §Input Validation → `CONDUCTOR_A11Y_STRICT` row).
- NEVER let the restored diagnostic output, the new CI precondition line, or the re-graded `evidence/nvda-pass.json` carry an absolute host path or an internal seam-crate struct name (per §Security Anti-Patterns → Logging).
- NEVER assemble any new harness spawn from a shell string or an operator-chosen program; array-form argv with a fixed/repo-resolved program only (per §Security Anti-Patterns → Code Patterns rule (b)).

## Contract bindings
- **Speech-log ingest ↔ a11y + tests:** the committed `nvda-pass.json` is an a11y-owned record whose *hygiene* half (host-path scrub, `security_finding`, `heard` bound, closed sets) is security's; the two gates asserting it are the tests harness's (per §Input Validation → speech-log ingest row).
- **`CONDUCTOR_A11Y_STRICT` ↔ a11y-plan §11 Anti-Patterns → CI:** §Input Validation cites that clause as the reason the strict arm exists (a gate must not report success by skipping); security's contribution is only that the added arm never relaxes the existing guards.
- **CI security gate ↔ tests §CI Integration:** one workflow, the audit steps as jobs; this chunk edits `ci.yml`, so the cargo-audit / cargo-deny / `npm audit --omit=dev` steps must survive the edit unchanged (per §Dependency Security → CI integration).
- **No PII binding** — Conductor owns no PII (per §Threat Model Summary → Data classification); the speech-log scrub is host-path hygiene, not PII scrubbing, so no obs §PII Scrubbing contract attaches.

## Acceptance criteria contributions
- The wdio-edge guard spans (`nativeDriver()` / `nvdaExe()` / the `UNSAFE_PATH` check) are byte-unchanged by the CI fix, and both `CONDUCTOR_A11Y_STRICT` arms still hold — strict + unresolved ⇒ non-zero exit, lax + unresolved ⇒ exit 0 with the dev-host skip preserved (per security-plan §Input Validation → `CONDUCTOR_A11Y_STRICT` row).
- The committed `evidence/nvda-pass.json` produced by any re-grading run passes the ingest bounds: every spec-id present in `nvda-pass-spec.md`, `outcome`/`arm`/`review_grade` within the closed sets, every `heard` ≤ 400 chars, and 0 unscrubbed host-path tokens (drive-letter / `%APPDATA%` / `/Users` / `/home`) with a `security_finding` on any row that required a scrub (per security-plan §Input Validation → speech-log ingest row).
- No absolute host path or internal seam-crate struct name appears in the CI step's printed precondition line or in the restored wdio diagnostic output; the unresolved-handle text names the handle, never its value (per security-plan §Input Validation → `CONDUCTOR_MSEDGEDRIVER` / `CONDUCTOR_NVDA` rows; §Security Anti-Patterns → Logging).
- If any dependency lands (npm or cargo): `npm audit --omit=dev` reports 0 production vulnerabilities with `package-lock.json` committed, and `cargo audit` / `cargo deny check advisories bans licenses sources` exit 0 over the committed lock (per security-plan §Dependency Security → Frontend (npm) supply chain; §Security Anti-Patterns → Universal).
