## Constraints
- The `--e2e` leg's verdict must be asserted from the PRINTED output, never the exit code — the exit read from the BARE command (never through a pipe), with all four required terms: zero on the `Spec Files:` failed count (a term the line OMITS when nothing failed), a per-spec skip tally within the expected-skip SET (a third skip is a failure), and the `[webview2 … windows]` driven-session banner (per test-plan §3 `run` → CI stage selectors, `--e2e` clause). Whether the shipped shells' capture-then-print actually delivers those printed terms to the job log under the workflow's own error preference is research's question — the plan mandates the assertion, not a capture mechanism.
- `.sh` and `.ps1` must expose IDENTICAL semantics — a binding contract, not a convention; the command count stays five and no stage selector may be added (per test-plan §3 Bootstrap phases → 5-command-discipline-wire; §3 `--e2e` clause). A diagnostic/driver-path fix landing in one shell only violates it.
- The per-run violation record at `runs/a11y/<run_id>.jsonl` is required of the leg, in the §3 envelope's eleven fields PLUS the obs §9 resource tags, and deliberately OUTSIDE the harness's non-recursive `"$RUNS_DIR"/*.jsonl` glob so `status` cannot read it as a scenario run; the envelope / `status` disk read / JSONL shapes stay untouched so §3 ↔ obs-plan §3 agree (per test-plan §3 `--e2e` clause; §9 Pipeline E2E row).
- `CONDUCTOR_MSEDGEDRIVER` and `CONDUCTOR_A11Y_STRICT` are harness-read handles for which NO Rust negative test is reachable; their mandated coverage is entirely at the e2e tier — the driver handle's skip arm in BOTH shells, and the strict flag's two measured arms (strict + unresolved handle ⇒ exit 1; lax + unresolved ⇒ exit 0 with the dev-host skip preserved) (per test-plan §1 Coverage triggers, Vector-1 per-reader classes). A fix must leave both arms observable.
- The SR leg is the operator-local THIRD suite family with a named firing form (five env handles including `CONDUCTOR_NVDA` and `CONDUCTOR_SCENARIOS_DIR`; NVDA started before tauri-driver, ready on its `NVDA initialized` line; the stop form's `nvda -q` → census → `tauriDriver.kill()`). NVDA's own speech log IS the driver and the operator's role is REVIEW of the graded record; browse-mode rows stay findings — never passes, never hard fails, never a manual arm (per test-plan §6 Drivers per surface → desktop-webview; §1 Untestable zones).
- Flakes are not tolerated and are never absorbed: no cargo-nextest `retries`, quarantine-and-fix at root cause, and a runner-dependent result is explicitly in this class — a shared-state defect to remove at the cause, never a runner to pin to (per test-plan §10 Zero-flakiness budget). This is the bar finding (3) is measured against.
- No JS/TS unit runner is adopted, and the frontend build gate (`tsc --noEmit` + `vite build` + preview smoke) does NOT prove ESM loadability or leg membership — a `wdio.conf.ts` member reachable from no executed leg is as unproven as it was under the build gate (per test-plan §4 Unit Test Strategy → `conductor-tauri/ui`). Fixes to `ui/src/**` for re-announce (1) and focus start point (2) are provable only by EXECUTING the wdio leg that loads them.

## Patterns to follow
- The `--e2e` self-seeding precedent: `seedFixtureRuns()` invokes the `conductor-run` `envelope_fixture` target under `CONDUCTOR_E2E_SEED_DIR` and THROWS on a non-zero exit or missing journal rather than seeding silently (per test-plan §3 `--e2e` clause). The same "fail loudly at the precondition, never proceed on a silently-unresolved value" shape is the established model for a driver-path precondition line.
- Identify CI jobs BY NAME rather than by `ci.yml` line coordinates, which move as the workflow grows (per test-plan §9 Matrix builds) — applies directly to this chunk's `:258` / `:254-262` citations.
- Selector discipline for any new re-announce or focus assertion: role / text / `aria-live` selectors and brand anchors ONLY — the closed lamp-label set plus the non-lamp caption SET, `role="alertdialog"`, the "HOLD — operator pause" heading text; no xpath, no hashed CSS classes (per test-plan §6 Selector strategy; §11 E2E).
- The routine arm's skip rule: a spec whose DOM state the seeded subject cannot produce context-skips, and a context-skip is NEVER a pass (per test-plan §6 desktop-webview, routine-arm paragraph) — the reason the harness gates on a skip TALLY within an expected SET rather than on exit 0.
- Committed fixtures carry their MEANING under test via a production reader/writer round-trip, one per fixture, so a persist-side change that leaves a file parseable but semantically inert fails at `cargo nextest` rather than silently weakening a green webview assertion (per test-plan §7 Self-bootstrapping requirement) — applies if the focus/re-announce work moves the seeded subject.

## Anti-patterns to avoid
- NEVER `sleep(N)` to synchronise INSIDE a test — wait on an explicit signal (element role / `aria-live` / journal line / exit code). The one sanctioned wall-clock wait is a harness-level pause BETWEEN legs reproducing a documented SUT-side precondition; a carve-out for in-test waits was proposed and REJECTED (per test-plan §11 E2E). Lengthening an in-test settle window to mask finding (3)'s variance is barred by this.
- NEVER run an operator-local live leg as a CI gate — the `a11y:driven` arm and the `sr*` suites are `workflow_dispatch`/local only; and NEVER skip or relax a quality gate "just this once" (per test-plan §11 CI; §11 Quality). Both match the chunk's own boundaries (no `sr*` into CI; the strict guard is not relaxed to obtain a colour).
- NEVER add a manual smoke step, human-reviewed screenshots, or an interactive runner — `wdio run` non-interactive only, headful where a real desktop host is used (per test-plan §11 Universal). The green-run verification must be agent-readable output, not an operator eyeball.
