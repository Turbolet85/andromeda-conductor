## Relevance
Relevant — the chunk IS the a11y CI gate's own blocker; a11y-plan §11 Anti-Patterns → Strategy names the route entry *Hosted-runner WebView2 session* as the owner of the still-owed CI proof. Contribution is harness/gate discipline (driver stack, strictness, artifact), not new WCAG-criteria coverage (no UI surface is added).

## Constraints
- **One webview-automation stack.** Any remedy must keep axe injecting via `@axe-core/webdriverio` into the `@crabnebula/tauri-driver` + WebdriverIO session; standing up a parallel puppeteer/CDP stack for a11y is banned (per a11y-plan §11 Anti-Patterns → CI, §3 A11y testing tool pick). Hypothesis 1 (official `tauri-driver` crate) is a driver-implementation swap *inside* that one stack, admissible only if axe still injects through the same WebdriverIO session.
- **A green job must be a real pass, not a skipped-green.** §11 → CI requires the fail-fast mechanism: `CONDUCTOR_A11Y_STRICT` makes an unresolved host-tool handle exit non-zero instead of skipping at 0, AND both harness shells assert the runner's PRINTED verdict (`Spec Files:` failed count, per-spec skip tally against the expected-skip SET, driven-session banner) — "a skipped-green run and a real pass are otherwise indistinguishable." A remedy that greens the job by widening a skip guard violates this. Whether the `a11y` job already declares `CONDUCTOR_A11Y_STRICT` and already asserts the printed verdict is research's question.
- **The routine arm's assertion set is fixed and may not be thinned to reach green.** Per §9 CI Integration (E2E row) + §11 → Strategy carve-out, the CI-wired routine arm carries axe under `wcag2a`/`wcag2aa`/`wcag21aa`, colorjs.io token pairs in both declared themes, not-color-alone, the compiled reduced-motion rule, and the hold-free Operable pair (SC 2.1.1 reachability, SC 2.4.3 focus order asserting no `tabindex &gt; 0`). §11 → Strategy also bans partial axe config (`runOnly` excluding default rules such as `color-contrast`) without an explicit Decisions Log entry.
- **Zero-violations is a hard gate with no retry policy.** `violations.length &gt; 0` → non-zero exit; retry-once for a11y violations is banned as masking real failures (per §10 SLO Invariants + §11 → SLO). The baseline log's `(1 retries)` is a session-creation retry, not a violation retry — but a remedy must not extend retries over assertion outcomes.
- **Artifact hygiene.** A11y artifacts MUST NOT leak absolute host paths or internal seam-crate struct names; node `target` selectors stay DOM-relative / `data-testid` (per §3 Structured violation JSON schema, §9 CI-specific resource attributes, §11 → SLO). The chunk's probe-ref hygiene constraint is the same invariant applied to the pushed probe tree.
- **Platform is not a capability bound, but the arm split is binding.** The measured platform SET is Linux under `xvfb` and headfully on the Windows WebView2 host; macOS alone lacks a WebDriver; `ubuntu-latest`+`xvfb` is a CI *arrangement* (per §9 Platform, §3 Configuration). A runner/OS change is therefore not a domain violation — but the `driven` and `sr*` arms must stay operator/local (live Pulse / NVDA), and no assertion in the harness may become platform-dependent (§11 → CI second-stack ban).
- **No WCAG conformance claim without machine-verifiable evidence** (axe `AxeResults` JSON / colorjs.io ratio JSON / WebdriverIO keyboard PASS-FAIL, aligned to obs §6) — per §2 Agent-runnable invariants + §11 → Strategy/Universal. This bounds what a `v2-24` claim may assert.

## Patterns to follow
- **Host-tool-handle guard shape:** `CONDUCTOR_MSEDGEDRIVER` unset ⇒ skip at exit 0, with `CONDUCTOR_A11Y_STRICT` flipping that to non-zero under CI (per §3 Bootstrap `a11y-ci-gate-wire`, §11 → CI). Any new env handle a remedy introduces (e.g. hypothesis 2's `WEBVIEW2_USER_DATA_FOLDER`, hypothesis 3's driver-version pin) should follow this same resolve-or-declare shape rather than an unguarded assumption.
- **One config, three suite families:** the routine arm rides `agent-run run --e2e` through the single `wdio run` webview leg, and results surface through the tests' 5-command contract's `logs` command (per §3 CI integration → Command, §9 Pipeline integration).
- **Violation-record shape as shipped:** the eleven obs §6 envelope keys plus obs resource tags — 13 top-level keys locally, 15 under CI where `ci.run.id` + `git.commit.sha` join — with `fingerprints[]` carrying one tuple PER NODE, and `journal_conformance` asserting key PRESENCE rather than exclusivity (per §3 Structured violation JSON schema). This is the shape the chunk's `runs/a11y/&lt;run_id&gt;.jsonl` + conformance gate must produce once a session is created.
- **Reference verdict for "green":** the routine arm's known-good local verdict is 12 passing / 2 skipped with the expected-skip SET unchanged (per §11 → Strategy). A hosted green should be compared against that tally, not merely against exit 0.
- **Identify CI jobs BY NAME, not by `ci.yml` line coordinates** — the plan records that coordinates move as the workflow grows (per §3 Configuration). The scope cites `ci.yml:263/:314/:366`; those are session-local, not durable anchors.

## Anti-patterns to avoid
- Standing up a second browser-automation stack (puppeteer/CDP, a separate Windows-only CDP attach) to route around the WebView2 session failure (per §11 → CI).
- Reaching green by skipping: any widening of the skip guard, or accepting exit 0 without the printed-verdict assertion, is banned — the a11y step is fail-fast, not a warning (per §11 → CI).
- Claiming `v2-24` on a green job without the machine-verifiable artifact behind it (axe/colorjs JSON emitted, conformance gate run, record uploaded), or leaking host paths into the artifact or the public probe tree (per §11 → Strategy/Universal, §11 → SLO).

## Acceptance criteria contributions
- (a11y) If the job goes green, greenness is asserted from the PRINTED verdict under `CONDUCTOR_A11Y_STRICT` — zero failed spec files and a per-spec skip tally matching the expected-skip SET — never from exit code alone (per a11y-plan §11 Anti-Patterns → CI).
- (a11y) A green routine arm exercises the full routine set with no rule subset: axe under `wcag2a`/`wcag2aa`/`wcag21aa`, colorjs.io token pairs in both declared themes, not-color-alone, the compiled reduced-motion rule, and the hold-free Operable pair (SC 2.1.1, SC 2.4.3 with no `tabindex &gt; 0`) (per a11y-plan §9 CI Integration E2E row + §11 → Strategy carve-out).
- (a11y) Whatever remedy lands, axe still injects via `@axe-core/webdriverio` into a single tauri-driver/WebdriverIO session — no second browser-automation stack, and the `driven` / `sr*` arms remain operator-local (per a11y-plan §11 Anti-Patterns → CI + §3 A11y testing tool pick).
