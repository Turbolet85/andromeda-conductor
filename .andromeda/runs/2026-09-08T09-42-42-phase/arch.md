# arch extract

## Relevance
Relevant — the chunk edits CI wiring, the shared wdio config, a frontend devDependency and env handles, all of which arch governs; arch does not decide the WebView2 root cause itself.

## Constraints
- The `a11y` job must run on the **explicit `windows-2025` label, pinned rather than floating**, precisely so a `-latest` move cannot change the Edge driver the leg resolves from the image (per architecture.md §Infrastructure Patterns — Build system). Hypothesis 3 (steering the driver build) is bounded by this pin; whether ci.yml at HEAD still carries the explicit label is research's question.
- Conductor's own configuration handles live under the reserved `CONDUCTOR_*` namespace **over artifacts/concepts arch already defines**; a non-Conductor handle (the `EDGEWEBDRIVER` precedent) is registered only because a shipped artifact both NAMES and READS it (per architecture.md §Occupied Resources — Environment variables). A `WEBVIEW2_USER_DATA_FOLDER` (hypothesis 2) would land in the second class, not the reserved namespace.
- A host-dev-tool path handle must be **validated at the harness edge** (existence + `isFile` + shell-metacharacter rejection) and passed as a **separate argv element of an array-form spawn, never interpolated into a shell**; its VALUE is never logged, echoed into an artifact, or committed — precondition text names the handle only (per architecture.md §Occupied Resources — `CONDUCTOR_MSEDGEDRIVER` / `CONDUCTOR_NVDA` / `EDGEWEBDRIVER`).
- `CONDUCTOR_A11Y_STRICT` is an **ADDED arm over the existing guards, never a relaxation of them**: under an affirmative declaration an unresolved handle must exit NON-ZERO, because a CI gate that can pass by skipping is banned (per architecture.md §Occupied Resources — `CONDUCTOR_A11Y_STRICT`).
- Conductor's OWN webview automation ships as **three suite families (four wdio suites) over ONE WebdriverIO + tauri-driver stack — "never a second automation stack"**, and `wdio.conf.ts` is the ONE config all families fire, binding/releasing `127.0.0.1:4444` + `:4445` per session (per architecture.md §Cross-cutting Patterns — Scope law; §Occupied Resources — Ports). Hypothesis 1 must be a swap inside that one stack, and any config edit is judged against all four suites, not the routine arm alone.
- The webview bundle must be built before any cargo compile of `conductor-tauri` (`generate_context!` resolves `build.frontendDist` at COMPILE time), and **`npm run build` is necessary but not sufficient — the `tauri/custom-protocol` FEATURE, not the profile, decides whether the binary loads the embedded bundle or `devUrl` (`http://localhost:5173`)** (per architecture.md §Infrastructure Patterns — Build system). A session-creation diagnosis must account for which of the two the launched binary opens.
- The frontend default is **npm with `package-lock.json` committed and `npm audit --omit=dev` clean as the gate** (production-dep strict; dev-only test-tooling advisories accepted at dev-tree grain) (per architecture.md §Inherited Defaults — Frontend). A `@crabnebula/tauri-driver` swap is a lockfile-bearing change under that gate.

## Patterns to follow
- **Runner-image handle resolved in the step SHELL, not the expression context**: GitHub's `${{ env.* }}` holds only workflow/job/step declarations and never a runner-process variable, so `CONDUCTOR_MSEDGEDRIVER` is derived from `$env:EDGEWEBDRIVER` in the step shell, printing a handle-named `Test-Path` precondition (handle NAME + boolean, never the path) and exiting non-zero when it does not resolve (arch §Occupied Resources — `EDGEWEBDRIVER`). Any second image handle a probe adds follows this shape.
- **One skip/strict routing site**: both unresolved-handle skips route through a single `exitUnresolvedHandle()` so strictness inverts them together (arch §Occupied Resources — `CONDUCTOR_NVDA` / `CONDUCTOR_A11Y_STRICT`). A new precondition arm joins that site rather than adding a second exit path.
- **Harness-owned handle set per invoked suite**: the one tauri-driver spawn site chooses `CONDUCTOR_RUNS_DIR` per suite and the self-obs sink follows it (`runs/logs/`, `runs/driven/logs/`, `runs/sr-leg/logs/`) — arch §Occupied Resources — `logs/conductor-tauri.jsonl`. A probe that changes the spawn must keep the per-suite landing sites.
- **a11y test tooling is deliberately NOT enumerated in arch §Stack / §Inherited Defaults** (summarized at React/Vite/Tailwind/npm grain); the driver/axe/wdio tooling lives in a11y-plan §3.5 + the stack distillation. A tauri-driver dependency swap is therefore not an arch §Stack registration.
- **Diagnostic-then-upload staging**: the a11y job's three stages (routine arm → `journal_conformance` over `runs/a11y` → violation-record upload) are the job's WIRING; arch requires the record upload as a stage, not an optional extra (arch §Infrastructure Patterns — CI/CD approach).

## Anti-patterns to avoid
- Introducing a **second automation stack** (a parallel driver/runner path beside WebdriverIO + tauri-driver) to get a session (arch §Cross-cutting Patterns — Scope law).
- Reaching green by **weakening a guard** — loosening `CONDUCTOR_A11Y_STRICT`, the `isFile`/metacharacter validation, or letting an unresolved handle skip at exit 0 under CI (arch §Occupied Resources — `CONDUCTOR_A11Y_STRICT`; security-plan §Security Anti-Patterns → Input, cited there).
- Putting a **host path or handle VALUE** into a workflow log, a committed diagnostic, or the probe tree — arch requires precondition strings and driver-handle outputs to be host-path-free on both the dev-host and CI sides (arch §Occupied Resources — `CONDUCTOR_MSEDGEDRIVER` / `EDGEWEBDRIVER`).

## Contract bindings
- **arch ↔ tests/obs**: `runs/a11y/<run_id>.jsonl` is the eleven-field run-report envelope plus obs resource tags (`service.name` = `conductor-ui`, `deployment.environment`; under CI additionally `ci.run.id` + `git.commit.sha` — 13 keys locally / 15 under CI), asserted by `conductor-run`'s **reused** `journal_conformance` under `CONDUCTOR_RUNS_DIR=runs/a11y`, never a second copy of the schema (arch §Occupied Resources — On-disk artifacts). Arch requires this stage to execute once a session exists; whether it has ever executed in CI is research's question.
- **arch ↔ a11y/harness shells**: `CONDUCTOR_A11Y_STRICT` is read by `wdio.conf.ts` AND by both shells' verdict assertions (`assert_a11y_verdict` / `Assert-A11yVerdict`) — a reader set no other handle class has (arch §Occupied Resources — Environment variables).
- **arch ↔ security**: every handle-edge guard (validate, never interpolate, never log the value) and the host-path-free artifact rule are arch's restatement of security-plan's input/anti-pattern rules; a probe-tree edit is bound by the same rule.
- **`verification-matrix.json#v2-24` disposition**: no arch contract binds it — the matrix is not an arch-registered surface.

## Acceptance criteria contributions
- (arch) The `a11y` job remains on the explicit `windows-2025` label — no move to a floating `-latest` image as part of any remedy (per architecture.md §Infrastructure Patterns — Build system).
- (arch) Any remedy stays inside the ONE WebdriverIO + tauri-driver stack shared by all three suite families / four wdio suites; no second automation stack is introduced (per architecture.md §Cross-cutting Patterns — Scope law).
- (arch) Any env handle the remedy introduces is placed by the namespace rule (`CONDUCTOR_*` only for concepts arch defines; a runner-image handle only because a shipped artifact names AND reads it), validated at the wdio edge, passed array-form, and its value never logged, uploaded or committed (per architecture.md §Occupied Resources — Environment variables).
- (arch) The gate is not made green by skipping or by relaxing a guard: under `CONDUCTOR_A11Y_STRICT` an unresolved `CONDUCTOR_MSEDGEDRIVER` / `CONDUCTOR_NVDA` still exits non-zero, and strictness stays an added arm over the existing guards (per architecture.md §Occupied Resources — `CONDUCTOR_A11Y_STRICT`).
