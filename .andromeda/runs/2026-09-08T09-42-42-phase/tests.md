## Constraints
- **"Green" is a printed-verdict assertion, never exit 0.** test-plan §3 (`run` → CI stage selectors, `--e2e`) requires both shells assert the CAPTURED output — zero on the `Spec Files:` failed count, a per-spec skip tally within the expected-skip SET (the two live-hold subjects; a third skip is a failure, which is how a fixture-seeding failure surfaces), and the `[webview2 … windows]` driven-session banner — because the handle guard is designed to skip at exit 0 and the exit cannot separate a full pass from a total skip. Disposing `v2-24` as "claimed on a green job" must be premise-checked against those three.
- **The gate step may never carry `continue-on-error`.** §9 Pipeline structure (E2E webview row) requires the `a11y` job's gate step and the reused `journal_conformance` gate over `runs/a11y` stay unconditioned; only the two version/session diagnostics and the `if: always()` `a11y-session-diag` upload may be `continue-on-error`. Probe steps this chunk adds land in the diagnostic channel, not by loosening the gate.
- **A `wdio.conf.ts` edit is unproven until a leg that LOADS it executes.** §4 (`conductor-tauri/ui`) requires the harness config and its members be proven only by executing the wdio leg that loads them — `tsc --noEmit` / `vite build` / `npm audit` do not prove ESM loadability, and a member reachable from no leg is as unproven as under the build gate.
- **Loopback only, routine arm only.** §11 Universal (real-network ban) admits the harness-lifetime WebDriver pair `:4444`/`:4445`, distinct from `:4317`, with no off-host traffic; §6 records the routine `--e2e` arm as carrying no live Pulse and §11 CI bans any live-Pulse leg as a CI gate. Hypotheses 1/2 must not widen the loopback set, and hypothesis 4 (self-hosted runner) must still run the routine arm alone.
- **Runner-dependent results are in the flakiness class.** §10 (Zero-flakiness budget) requires a test green under one runner and red under the other be treated as a defect removed at the cause, "never a runner to pin to," and forbids retry policies. Whether that rule reaches hypothesis 4 (pinning to a self-hosted runner) or whether a hosted-runner capability gap sits outside it is a judgment the plan must state rather than assume.
- **The driver-handle guards are mandated coverage, not incidental wiring.** §1 (Coverage triggers, Vector-1, per-reader classes) requires `CONDUCTOR_MSEDGEDRIVER` keep its existence + `isFile` + shell-metacharacter guard ahead of an array-form spawn, asserted at the e2e tier by its skip arms, and requires `CONDUCTOR_A11Y_STRICT`'s coverage be the two measured arms — strict + unresolved handle ⇒ exit 1; lax + unresolved ⇒ exit 0 with the dev-host skip preserved. A hypothesis-3 remedy that changes how the driver is acquired must preserve both; whether the code already carries both arms is research's question.
- **A dependency swap owes the supply-chain and frontend gates.** §9 / §10 (Build failure conditions) require `cargo audit` + `cargo deny check` green with a committed un-drifted `Cargo.lock`; §4 (`conductor-tauri/ui`) puts `npm audit` on the frontend build gate. Hypothesis 1 (official `tauri-driver` crate vs `@crabnebula/tauri-driver`) touches both. External test CLIs are reference FLOORS outside `Cargo.lock` per §4 Tool-version policy, so a version choice is not itself a spec break.

## Patterns to follow
- **Diagnostic-step channel already shipped** (§9 E2E webview row): `continue-on-error` version + session-isolation probes plus an `if: always()` artifact upload is the established shape for measuring on the hosted runner without changing the gate's verdict — extend it rather than invent a new probe surface.
- **Name the measured SET, never a literal** (§6 desktop-webview row): the working msedgedriver × WebView2-Runtime pairing is recorded as a pair of runtimes, with a cross-major pairing measured green and driver refresh named an operator host task; a hypothesis-3 finding extends that SET rather than substituting a fresh version literal.
- **Skip-arm-as-coverage** (§1 Vector-1 trigger): the host dev-tool handles carry no reachable Rust negative test and are asserted at the e2e tier by their skip arms — the same probe-and-record shape this chunk's measurement should take for anything it cannot assert in-process.
- **Seed-before-session, fail loudly** (§3 `--e2e`): `seedFixtureRuns()` clean-re-creates the gitignored fixture runs dir and writes the subject through the production writer under `CONDUCTOR_E2E_SEED_DIR`, throwing on a non-zero exit — so a seeding failure is distinguishable from a session-creation failure (it surfaces as a third skip against the expected-skip SET).
- **Identify CI jobs and steps BY NAME** (§9 Matrix builds): line coordinates into `ci.yml` move as the workflow grows; the scope's `ci.yml:263/:314/:366` citations should be re-resolved by step name at P3.

## Anti-patterns to avoid
- **No `sleep(N)` to synchronise inside a test** (§11 E2E). The ban's subject is in-test synchronisation; a harness-level wait BETWEEN legs reproducing a documented SUT-side precondition is a firing-form item, not a synchronisation substitute. A session-creation remedy shaped as a fixed wait for the WebView2 loader is barred.
- **No retry to paper over the failure** (§11 CI + §10). The baseline's `FAILED in wry ... (1 retries)` is a wdio-level spec retry; whether it is configured and whether §10's zero-retry rule reaches the wdio layer as it reaches nextest is research's question, but adding or widening retries as the remedy is out.
- **No manual/visual verification step and no interactive runner** (§11 Universal): `wdio run` non-interactive only, no "operator checks the session" arm, and a `deferred` disposition must rest on the measured cause rather than on a human-observed one.

- **tests ↔ obs (§3 Log format / envelope).** §3 is the source of truth obs-plan §3 derives from, and §3 records the a11y violation record `runs/a11y/<run_id>.jsonl` as a SEPARATE shape — the eleven envelope fields plus obs §9 resource tags — deliberately outside the harness's non-recursive `"$RUNS_DIR"/*.jsonl` glob so `status` cannot read it as a scenario run. Any remedy must leave the five-command surface, the `status` disk read and the envelope/JSONL shapes untouched so §3 ↔ obs-plan §3 continue to agree.
- **tests ↔ a11y.** §9's E2E webview row binds the a11y assertions (axe, the token pairs in both declared themes, not-color-alone, reduced-motion) and the `journal_conformance` gate to this one job; a11y owns the assertions, tests owns the 5-command/CI wiring and the verdict contract.
- **tests ↔ security.** §1 Vector-1's handle guards and §9/§10's `cargo audit` + `cargo deny` + un-drifted `Cargo.lock` conditions bind any driver-acquisition or dependency change taken under hypotheses 1 or 3.
- **tests ↔ shells (§3 `5-command-discipline-wire`).** The identical-`.sh`/`.ps1` semantics contract is asserted of the SCRIPTS TOGETHER WITH the invoking environment — a caller setting `$PSNativeCommandUseErrorActionPreference = $true` diverges the `.ps1` leg with zero script delta. Workflow-level shell settings are in scope of that binding even though the scope marks `agent-run.ps1` read-only.
