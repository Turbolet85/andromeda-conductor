## Patterns to follow
- Host-tool handle pattern (a11y-plan §3 bootstrap `a11y-ci-gate-wire`, §11 → CI): a missing host tool skips at exit 0 while CI's `CONDUCTOR_A11Y_STRICT` flips that to non-zero — the shape any new runtime precondition should follow rather than a bare unconditional failure.
- Tests' binding 5-command harness discipline (boot / run / status / cleanup / logs), with `logs` as the artifact-emitting command, per a11y-plan §3 (CI integration → Command) and §9 (Pipeline integration) — probe results that become a11y evidence ride that surface.
- The routine arm seeds its own committed fixture through the production writer and needs no live Pulse (a11y-plan §9, E2E artifacts row) — consistent with the chunk's "no Pulse dependency" boundary; the driven and `sr*` arms stay operator-local and are untouched here.
- Per-arm budgeting (a11y-plan §10 Performance budget): axe-core &lt; 30s and the routine arm stays "fast and unattended". An in-job runtime download/install sits ahead of the budgeted assertion time but must not make the arm attended (no interactive installer, no elevation prompt).
- Recording a disproved premise with its mechanism, as §12 Decisions Log does for the retired reduced-motion-emulation claim — the template for the chunk's falsification branch.

## Anti-patterns to avoid
- Green-by-suppression on the `a11y` job — a11y-plan §11 → CI bans skipping a11y on CI failure and requires the strict-mode + printed-verdict mechanism precisely because exit 0 can mean "skipped".
- Any second browser-automation stack or CDP/Windows-only attach introduced to work around the session failure — a11y-plan §11 → CI.
- Retry-once, soft SLO, or dropped per-PR diff to get past a violation — a11y-plan §11 → SLO.
