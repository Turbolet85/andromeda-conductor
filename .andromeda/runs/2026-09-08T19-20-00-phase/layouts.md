Installing a 152+ runtime changes what that printed verdict can report, not the assertion shape. Whether the `a11y` job's step already reads the printed verdict rather than the exit code is research's question.
- The handle-absence outcome is an **ARM SET**, not one verdict: lax arm skips its own leg at exit 0 with a fetch recipe; under an affirmative `CONDUCTOR_A11Y_STRICT` the same unresolved handle exits non-zero instead (per layout-templates §cli Primary screens, agent-run bullet). A runtime-install step must add no fourth arm and must not convert a refusal into a skip.
- The per-P-ID bracket-label set is **closed at six** (`[PASS]`/`[HOLD]`/`[FAIL]`/`[MANUAL]`/`[RESIDUAL]`/`[BLOCKED]`) plus a run-level non-lamp qualifier SET (`[ENVIRONMENT-SUSPECT]`, `[PRECONDITION]`); nothing here may mint a new bracket label, ANSI entry or token on the cli surface (per layout-templates §cli Component — Primary content block 2). CI-step `[diag]`/`[precondition]` lines are workflow output, outside that governed set, and must not be conflated with it.
- **Headless invariant:** the agent-driven source-of-truth path is never gated on a prompt — an interactive gate there silently breaks the release gate (per layout-templates §cli IA notes — Headless invariant; §cli Component — Primary navigation). A runtime install placed in this job must be silent/non-interactive; the scope marks "installs without an interactive session or elevation prompt" as `[inferred]` for P3 to close.
- Error output is sanitized: `error: <short>` + detail + `hint: <fix>` on stderr, **no absolute host paths**, no stack traces (per layout-templates §cli Component — Footer / terminator + error output). A signature-gate refusal that surfaces through the harness inherits that shape; the `--e2e` guard's existing precondition text is already specified host-path-free on the same bullet.
- Desktop-webview has no routes, no breakpoints and no responsive behavior — the frameless window IS the surface (per layout-templates §IA notes; §Decisions Log — Responsive breakpoints: N/A). No wireframe, region, component-placement or focus-order edit is in scope for this chunk.

## Patterns to follow
- **Refuse-vs-skip two-class pattern** on the harness (per layout-templates §cli Primary screens, agent-run bullet): an incomplete environment REFUSES at non-zero with one host-path-free line per unmet subject naming its statement and candidate causes; an absent HOST TOOL skips its own leg. A failed/untrusted `Get-AuthenticodeSignature` result is the REFUSAL class by this pattern — a stop, never a warning that proceeds.
- **ASCII bracket-prefix + always-printed label** so a signal survives `NO_COLOR`, piping and screen readers, with color never the sole channel (per layout-templates §Surface: cli signature-placement note; §cli IA notes — Pipe discipline). The before/after runtime-version lines should follow the existing `[diag] WebView2 Evergreen Runtime: …` label shape rather than inventing a new prefix.
- **Diagnostic-vs-gate separation**: a diagnostic must never decide the gate, and correspondingly a gate step must never be demoted to advisory (per layout-templates §cli Primary screens, agent-run bullet — the strict arm exists so a gate cannot pass by skipping). The install + signature step is a gate step; the neighbouring versions/session-isolation steps are diagnostics.
- **Both-shells parity as an environment-conditioned property** (per layout-templates §cli Primary screens, agent-run bullet as conditioned): parity holds for the SCRIPTS together with the invoking environment, so a CI-only environment change (runtime major) may diverge the CI leg from a dev host with zero script delta — record such a divergence as an environment fact, never as a script defect.

## Anti-patterns to avoid
- **Green-by-skip / green-by-suppression on the gate** — the strict arm exists precisely so an unresolved handle cannot yield a passing gate (per layout-templates §cli Primary screens, agent-run bullet); no `continue-on-error` on the install/signature step, and no silent skip of the routine arm.
- **Minting a new cli-surface label or token** for install/version output — no seventh lamp, no new bracket label, no new ANSI/token entry (per layout-templates §cli Component — Primary content block 2; the `not-conductors` Mode-cell precedent in §Primary content block 1).
- **Leaking absolute host paths / internal detail** into the step's failure text (per layout-templates §cli Component — Footer / terminator + error output).
