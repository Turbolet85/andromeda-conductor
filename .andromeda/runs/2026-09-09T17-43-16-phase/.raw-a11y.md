# a11y extract

## Relevance
Partial — no UI surface, no WCAG criteria triggered; a11y contributes guard-rails only (CI-gate integrity, the obs §6-aligned violation artifact reused by `conductor-run`'s conformance gate, and the shared retry ban), since two of the four crates to be measured (`conductor-run`, `conductor-tauri`) host a11y-bound seams.

## Constraints
- The unit/integration test layer (`cargo-nextest` / `cargo test` / golden) carries **no** UI a11y tests — a11y coverage lives only in the `wdio run` webview E2E leg (per a11y-plan §9 Per-pipeline-stage a11y artifacts, Unit row). So this chunk owes no new a11y assertion, and may not relocate a11y coverage into a Rust test target.
- a11y-plan §10 SLO Invariants forbids retry-once policies for a11y violations, explicitly paralleling tests' "Do NOT set cargo-nextest `retries` &gt; 0" — the chunk's pre-banned retry/pin/sleep list is the same discipline, and the fix must not introduce a retry on any lane the a11y gate shares (per a11y-plan §10 + §11 SLO).
- a11y-plan §3 Structured violation JSON schema requires the a11y artifact to align to the obs §6 envelope and requires `conductor-run`'s `journal_conformance` to assert key **presence**, not exclusivity (11 envelope keys + obs resource tags = 13 local / 15 CI). `conductor-run` is one of the four crates measured here; whether its tests already encode that presence-not-exclusivity semantics, and whether a fix would perturb it, is research's question.
- a11y-plan §3 (schema) and §9 (CI-specific resource attributes) require that a11y artifacts MUST NOT leak absolute host paths or internal seam-crate struct names, inherited from tests' Status JSON constraint — relevant because this chunk touches `conductor_core::{init_observability, ObsSink}`, the emission path whose lines that envelope shares.
- a11y-plan §11 CI requires the a11y step be a fail-fast gate, with `CONDUCTOR_A11Y_STRICT` plus the printed-verdict assertion as the mechanism (exit code alone cannot enforce it, because the host-tool guard skips at exit 0). No delta may make a skipped-green run indistinguishable from a pass in pursuit of a workspace-green claim.
- a11y-plan §11 CI bans standing up a second browser/automation stack — one webview-automation stack (`@crabnebula/tauri-driver` + WebdriverIO, axe injected via `@axe-core/webdriverio`). A runner-race remedy must not fork a parallel stack for any crate.
- The `conductor-cli` verb surface and the fault crate's line-oriented output are declared **not-assertable** (a11y-plan §1 A11y scope entities, cli entity; §11 Universal) — no a11y verification path is owed by the fix itself.

## Patterns to follow
- Lane separation: a11y rides the tests' `wdio run` webview-E2E leg, never a `cargo test` lane (per a11y-plan §3 A11y testing tool pick + §9 Pipeline integration) — keep the crate-by-crate `cargo test -p` measurement in its own lane rather than folding results into the a11y job.
- Harness reuse: a11y results emit through the **`logs`** command of tests' binding 5-command harness contract (boot / run / status / cleanup / logs) (per a11y-plan §9 Pipeline integration) — any recorded artifact from this chunk should reuse an existing harness surface, not add one.
- Envelope shape: obs §6 eleven keys plus the obs resource tags `service.name` (`conductor-tauri` / `conductor-ui`) and `deployment.environment`, joined by `ci.run.id` / `git.commit.sha` under CI (per a11y-plan §3 Structured violation JSON schema + §9 CI-specific resource attributes).
- Zero-tolerance gate framing: `violations.length &gt; 0` → non-zero exit, no soft SLO, no per-arm exemption (per a11y-plan §10 Build / deploy failure conditions + §11 SLO) — congruent with this chunk's "exits 0, repeatably" bar.

## Anti-patterns to avoid
- Retry-once / rerun-on-red as a race remedy on any shared lane (per a11y-plan §11 SLO, "NEVER use a retry-once policy… masks real failures").
- Weakening or skipping the a11y gate — including anything that lets a skipped run read as green — to reach a workspace-wide green (per a11y-plan §11 CI, "NEVER skip a11y on CI/operator-gate failure").
- Introducing a second automation/browser stack or a parallel runner for a11y-adjacent crates (per a11y-plan §11 CI, second-stack ban).

## Contract bindings
- **a11y ↔ obs §6** (a11y-plan §3 Structured violation JSON schema): the a11y violation artifact reproduces the obs Run-report envelope verbatim; `conductor_core::{init_observability, ObsSink}` — the process-global subscriber this chunk reads and may change — is the emission path that envelope describes.
- **a11y ↔ `conductor-run` `journal_conformance`** (a11y-plan §3 schema + §3 CI integration → Command): the a11y routine arm reuses that gate; `conductor-run` is one of the four crates this chunk measures under `cargo test -p`.
- **a11y ↔ tests §4 / §11 / §12** (a11y-plan §10 Cross-input parallel + §9 Pipeline integration): a11y's zero-WCAG-AA-violations invariant is the declared parallel of tests' zero-flakiness budget, and a11y rides tests' 5-command harness and tests §6 webview driver — so the runner-portability contract this chunk satisfies is upstream of a11y's own gate discipline.
- **a11y ↔ CI workflow** (a11y-plan §9 Platform): the `a11y` job (`windows-2025`) shares the workflow whose gate set this chunk's green claims describe.

## Acceptance criteria contributions
- (a11y) No a11y spec, assertion, or gate is skipped, weakened, or deleted to reach `cargo test -p` green; the routine-arm a11y gate keeps its fail-fast non-zero-exit and `CONDUCTOR_A11Y_STRICT` printed-verdict semantics (per a11y-plan §11 CI + §10 Build / deploy failure conditions).
- (a11y) The delta introduces no retry, rerun, or soft-failure policy on any lane the a11y gate shares (per a11y-plan §10 SLO Invariants + §11 SLO).
- (a11y) If the fix alters `init_observability` / `ObsSink` emission, the obs §6-aligned a11y violation artifact still satisfies `journal_conformance` key-**presence** checking and leaks no absolute host paths or internal seam-crate struct names (per a11y-plan §3 Structured violation JSON schema + §9 CI-specific resource attributes). Whether the current code already satisfies this is research's question.
- (a11y) No second browser/automation stack is introduced for any measured crate; the one `tauri-driver` + WebdriverIO stack remains the sole webview-automation path (per a11y-plan §11 CI, second-stack ban).
