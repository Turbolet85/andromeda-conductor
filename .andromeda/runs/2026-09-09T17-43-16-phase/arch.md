## Constraints
- The subject crate is `conductor-faults` (fault helpers: ramps, silence, port-occupier, fingerprint-storm), one of the nine registered workspace members; the delta must stay inside the crate-per-seam boundaries and add no new cross-seam `Cargo.toml` dependency edge — a forbidden edge is required not to compile (per architecture.md §Established Decisions [Module Boundaries] · §Occupied Resources — Crate names · §Inherited Defaults — Module boundaries).
- Per-seam `cargo test -p` is a stated payoff of the crate-per-seam decision itself, not only a test-plan contract — architecture.md §Established Decisions [Module Boundaries] requires the workspace to give "per-seam `cargo test -p` (and, with the qualifier below, `cargo build -p`)". The chunk's premise therefore has an arch anchor as well as `test-plan` §4/§12.
- The same decision requires per-member properties to be measured on each member's OWN targets, and bans `--all-targets` as the sweep form because it re-unifies dev-dependencies — the exact masking that made `cargo check -p conductor-verify --lib` red at HEAD 2026-09-04 while the workspace form was green (per architecture.md §Established Decisions [Module Boundaries]). Whether `conductor-faults` carries the analogous manifest shape (a feature declared only under `[dev-dependencies]`) is research's question.
- `127.0.0.1:4317` is the registered OTLP egress target and the port-occupier fault is the single registered exception under which a shipped binary *binds* rather than connects; `:4318` is registered as not used (per architecture.md §Occupied Resources — Ports · §Cross-cutting Patterns — Trust boundary). A restructuring that changes what the test binds must not widen that registered set.
- `conductor_core::{init_observability, ObsSink}` sits in `conductor-core`, "the runtime-agnostic engine library every other crate depends on", and reads the reserved handles `CONDUCTOR_SERVICE_NAME` / `CONDUCTOR_ENV`; the self-observation stack is pinned to tracing 0.1.44 + tracing-subscriber 0.3.23 and is explicitly NOT an OTel SDK (per architecture.md §Occupied Resources — Crate names / Environment variables · §Stack and Technologies — Self-observation row). Any change to that surface is a change to every seam's shared dependency, and its behavioural detail is obs-plan's, not arch's.
- A new dependency requires a §Stack and Technologies row plus green `cargo deny check advisories bans licenses sources` and `cargo audit` over an un-drifted lock — the standing registration precedent for every dep added since serde_json (per architecture.md §Stack and Technologies · §Infrastructure Patterns — Build system).
- The pinned runner is cargo-nextest driven through a **zero-retry** `ci` profile in `.config/nextest.toml`, justified in arch's own words as "no retries mask flakes — the determinism invariant" (per architecture.md §Infrastructure Patterns — Build system). This reinforces `test-plan` §11's retry ban at arch level.

## Patterns to follow
- Per-member measurement on each member's own targets, recorded as a measurement rather than a gate — the nine-member standalone sweep shape (`--lib` for the seven libraries, `--bins` for `conductor-cli` / `conductor-tauri`, which have no lib target and false-red under a uniform `--lib`) is the precedent for how this chunk should record the four unmeasured crates (per architecture.md §Established Decisions [Module Boundaries]).
- Register-then-measure for anything crossing a seam: `conductor-run → conductor-faults` is the crate's only registered consumer (its first, registered 2026-08-19), so a change to `conductor-faults`' public surface has exactly one downstream (per architecture.md §Occupied Resources — Crate names).
- The dev-test stack is already fixed at rstest / proptest / insta / assert_cmd / assert_fs / predicates with exact versions deferred to `test-plan` §4 — a restructuring should reach for that registered set before proposing a new crate (per architecture.md §Infrastructure Patterns — Build system).
- The measured-not-gate-enforced disposition: arch already records a per-member property that holds by measurement because no CI job enforces it. CI's `rust` job runs `cargo fmt --all --check` / `cargo build` / nextest / clippy — plain per-crate libtest is not among them (per architecture.md §Established Decisions [CI/CD] · §Infrastructure Patterns — CI/CD approach). Whether the repo has since added such a job is research's question.

## Anti-patterns to avoid
- Introducing a retry, a runner pin, or a runner-config relaxation anywhere in the delta — the zero-retry `ci` profile is arch-level determinism discipline, not only a test-plan rule (per architecture.md §Infrastructure Patterns — Build system · §Cross-cutting Patterns — Determinism discipline).
- Landing an unregistered occupied resource: a new port beyond `:4317`, a new `CONDUCTOR_*` env handle, or a new on-disk artifact used to serialize the tests (per architecture.md §Occupied Resources — Ports / Environment variables / On-disk artifacts).
- Smuggling in a new dependency (e.g. a subscriber-capture or serialization crate) without the §Stack row and the supply-chain gates the registration precedent requires (per architecture.md §Stack and Technologies · §Infrastructure Patterns — Build system).

## Contract bindings
- **arch ↔ tests:** [Module Boundaries] is what MAKES per-seam `cargo test -p` a property at all; `test-plan` §4/§12's runner-portability contract rests on it, and arch supplies the nine-member roster that bounds "the four unmeasured crates" (`conductor-verify` · `-run` · `-cli` · `-tauri`, of which the last two have no lib target).
- **arch ↔ obs:** `init_observability` / `ObsSink` live in `conductor-core` per arch's crate registry and read the `CONDUCTOR_SERVICE_NAME` / `CONDUCTOR_ENV` handles arch reserves; the subscriber's field allowlist behaviour the assertion exists to prove is `obs-plan` §4's mandate, not arch's. If the fix changes `init_observability`'s contract rather than the test, it crosses into obs's domain and touches core, which every seam depends on.
- **arch ↔ CI:** changing what CI runs (e.g. adding a plain `cargo test -p` leg) would require a lockstep amendment at the five sites that enumerate the gate set — the §Stack CI/CD row, §Established Decisions [CI/CD], the `.github/workflows/` tree comment, §Infrastructure Patterns CI/CD approach and §Inherited Defaults CI/CD — which the chunk's own scope places out of bounds ("any spec amendment").
