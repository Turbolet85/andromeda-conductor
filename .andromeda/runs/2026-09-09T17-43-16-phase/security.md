# security extract

## Relevance
Partial — the chunk is test-hygiene work with no new external-input boundary, but it touches the one deliberate `:4317` port bind and the log-emission surface, so a bounded set of security rules constrains the fix shape.

## Constraints
- The `conductor-faults` port bind on `:4317` is the SINGLE deliberate exception in the threat model — loopback-only, an intentional in-host fault, the sole case a shipped Conductor binary opens a port. Any restructuring of the occupier or its test must leave it that and nothing more (per security-plan §Threat Model Summary → Attack surface, "Vector (single deliberate exception): port bind `:4317`"; §Security Anti-Patterns → API).
- The occupier's PORT must remain a private builder parameter — deliberately NOT a config field, and with no operator-steerable bind target. If the race fix parameterizes the bind (per-test or ephemeral port), that requirement binds the new shape too; whether HEAD already keeps the port private is research's question (per security-plan §Input Validation, scenario-config row `[phases.fault]`).
- The ban on an inbound listener of Conductor's own is scoped to SHIPPED binaries, with leg-lifetime dev-only ports carved out — so no delta may put a listener into `conductor-cli` / `conductor-tauri`, and any test-lifetime socket must stay outside them (per security-plan §Security Anti-Patterns → Universal).
- Any dependency delta (e.g. a test-support crate to isolate or capture the subscriber) lands only under `cargo audit` + `cargo deny check advisories bans licenses sources` green over the NEW committed `Cargo.lock`, with any added license carrying a justifying `deny.toml` comment; `Cargo.lock` must not drift or go uncommitted (per security-plan §Dependency Security; §Security Anti-Patterns → Universal).
- Lines the test emits or captures, and the four recorded crate measurements, must carry no absolute host paths and no internal seam-crate struct/field names — artifacts and evidence records are agent-parseable ground truth shared across hosts (per security-plan §Security Anti-Patterns → Logging; §Error Handling, run-report artifact sanitization).
- The canonicalize/residual duty binds per READER, and two of the four crates to be measured have test-binary env-handle readers: `CONDUCTOR_E2E_SEED_DIR` must stay a no-op when unset so an ordinary plain `cargo test` never writes into the repository, and `conductor-run/tests/journal_conformance.rs`'s `CONDUCTOR_RUNS_DIR` read must keep a host-path-free failure origin naming the handle and file, never a resolved path (per security-plan §Input Validation, env-var path handles row + `CONDUCTOR_E2E_SEED_DIR` row; §Security Anti-Patterns → Input).

## Patterns to follow
- "Added arm, never a relaxation" — the shape used when `CONDUCTOR_A11Y_STRICT` and the CI-side `CONDUCTOR_MSEDGEDRIVER` producer were introduced: a new gating arm is added while the existing guards stay byte-unchanged. A restructured probe should keep the failing power of the allowlist-survival assertion as a preserved/added arm rather than a softened one (per security-plan §Input Validation, `CONDUCTOR_A11Y_STRICT` row).
- The unset-no-op discipline for harness-owned handles: the control cited is the seeding test's own unset path, "which runs in every ordinary `cargo nextest` / `cargo test` execution" — exactly the runner this chunk measures (per security-plan §Input Validation, `CONDUCTOR_E2E_SEED_DIR` row).
- Per-reader recording rather than silent exemption: when a shipped-handle reader appears in a test binary, the plan records it with an explicit residual instead of widening or dropping the duty (per security-plan §Security Anti-Patterns → Input, per-READER restatement).
- Fault-spec validation shape, if the delta touches the fault structs: closed `FaultKindSpec` `kind` enum (unknown kind = deserialize error), `dive` never `skip` on nested spec fields, fault-declaring phase ⇒ `occurrences = 0` (per security-plan §Input Validation, scenario-config row; §Security Anti-Patterns → Input).

## Anti-patterns to avoid
- Never promote the `:4317` occupier bind into a general-purpose inbound listener accepting external input, and never widen it beyond loopback (per security-plan §Security Anti-Patterns → API; → Universal).
- Never introduce a config key or `CONDUCTOR_*` env handle that steers the occupier's bind target — that would create an operator-steerable path/value the canonicalize duty would then attach to (per security-plan §Input Validation `[phases.fault]`; §Security Anti-Patterns → Input).
- Never let a test-emitted line, captured buffer, or recorded measurement expose an absolute host path or an internal seam-crate struct name (per security-plan §Security Anti-Patterns → Logging).

## Contract bindings
- obs ↔ security: obs-plan §4's tracing field allowlist is the mechanism that enforces security-plan §Security Anti-Patterns → Logging (no host paths / internal field names reaching emitted lines). The assertion the chunk must preserve is that ban's proof-of-enforcement, so a fix that makes it unable to fail removes the only evidence the log-hygiene control still holds.
- tests ↔ security (CI): the dependency gate (`cargo audit` / `cargo deny`) lives as its own job in the same `.github/workflows/ci.yml` that runs build / nextest / clippy; adding `cargo test -p <crate>` steps must not disturb it, and per the 2026-09-09 amendment a fixed-toolchain-binary step with fixed argv mints no new governed harness-spawn form (per security-plan §Dependency Security, CI integration; §Security Anti-Patterns → Code Patterns rule (b)).
- arch ↔ security: `:4317` is Pulse-owned loopback ingest (architecture §Occupied Resources — Ports); the occupier's bind is registered against that ownership in the threat model's port-bind vector, so any change to what/where it binds is a cross-master fact, not a test-local one.

## Acceptance criteria contributions
- The delta introduces no operator-steerable bind target — no scenario-config key and no `CONDUCTOR_*` / env handle selects the occupier's port; it remains a private builder parameter (per security-plan §Input Validation, scenario-config `[phases.fault]` row).
- No shipped binary (`conductor-cli` / `conductor-tauri`) gains an inbound listener, and the fault bind stays loopback-only inside the `conductor-faults` seam (per security-plan §Security Anti-Patterns → Universal and → API).
- If the delta changes `Cargo.lock`: `cargo audit` exits 0 and `cargo deny check advisories bans licenses sources` exits 0 over the committed lock, any new license carrying a justifying `deny.toml` comment (per security-plan §Dependency Security; §Security Anti-Patterns → Universal).
- The four recorded `cargo test -p` measurements, and any lines the fixed test emits or captures, contain zero absolute host paths and zero internal seam-crate struct names (per security-plan §Security Anti-Patterns → Logging; §Error Handling).
