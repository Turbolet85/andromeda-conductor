# design extract

## Relevance
Partial — CLI surface only (verdict/report-state output, the `[MANUAL]` render, artifact cleanliness); no webview/token work is implied by this chunk's deliverable.

## Constraints
- The six lamp states are a closed set and `ManualCheck` must never collapse into `Fail` or `Blocked`: `?` glyph + `[MANUAL]` ASCII prefix in ANSI 146 lavender (webview pair `--status-manual`), deliberately outside the green/amber/red machine-verdict triad because there is no machine verdict (per design-system.md §Color Palette → the Verdict-vs-ReportState note; §Surface: cli / Component Patterns 4). P-067/P-072's expected `ManualCheck` outcome and P-079's graded Hard outcome are different lamp treatments by mandate, not by preference.
- A per-P-ID verdict line must render the scenario's **declared** `slo_tier` drawn from the closed `&lt;5s`/`&lt;20s`/`&lt;90s` set — never a baked per-scenario literal (per design-system.md §Surface: cli / Component Patterns 4, as amended 2026-08-18). These three scenarios' tiers (`&lt;20s` · `&lt;90s` · `&lt;20s`) are data, not sample text.
- Color is never the signal: every status carries its ASCII bracket label, and ANSI is applied via `owo-colors` behind a `std::io::IsTerminal` gate decided **independently for stdout and stderr**, each requiring a TTY **and** `NO_COLOR` unset **and** `TERM != dumb`, so piped/agent-captured output carries no ANSI (per design-system.md §Surface: cli / Tokens; §Anti-Patterns → Per-Surface Bans / cli). Whether the shipped run path already satisfies this for these legs' captured artifacts is research's question.
- Never emoji in machine-parseable (piped) output — the `✓`/`✗`/`?`/`~`/`•`/`→` glyphs are TTY-only; the bracket labels are what survive into the journal/report evidence (per design-system.md §Surface: cli / Tokens; §Anti-Patterns → cli).
- The headless agent-driven path must NEVER be gated on an interactive `inquire` prompt: when stdin is not a TTY the prompt is skipped per the configured non-interactive policy and the decision is **recorded to the artifact** (per design-system.md §Surface: cli / Component Patterns 2; §Platform-Specific Notes / cli). Any new leg wiring inherits this.
- Run-level captions are not lamp states: `[ENVIRONMENT-SUSPECT]` (load envelope) and `[PRECONDITION]` (the `preconditions` probe) are ANSI 246 Residual-mute, printed **outside** the lamp column, qualifying the run and never adding a seventh lamp or sixth `ReportState` (per design-system.md §Surface: cli / Tokens → status-prefix line). A live round against an operator-launched Pulse can plausibly emit both; they must not be mistaken for per-scenario verdicts.
- A `Blocked` row renders slate-violet with its **named precondition string**, and measurement columns render `—`/null — never a red error (per design-system.md §Surface: cli / Component Patterns 3). Relevant as the negative case this chunk must avoid producing.

## Patterns to follow
- §Surface: cli / Component Patterns 4 (Verdict / report-state lines) — the existing per-P-ID in-place line shape, including the `? P-035  Manual  halo→burgundy? · no OS toast?` form, where the manual line carries the expected-observation text and, headless, is "recorded unconfirmed." This is the mandated render for P-067/P-072; whether the shipped code generates that text absent a `[[checklist]]` block is research's question (scope Q3).
- §Surface: cli / Component Patterns 1 (Paused-count hold-point, CLI mirror) — if any new leg runs through the live harness spinner, the `indicatif` spinner STOPS in place at the hold value (never hides, never animates-to-100%), appears only after ~200ms, and is TTY-gated so agent-captured artifacts stay clean.
- §Surface: cli / Component Patterns 3 (Results / SLO table) — the `comfy-table` 6-column per-check table (P-ID · scenario · state · slo_tier · latency_ms · fingerprints), width detected dynamically; it is a **separate** table from `conductor coverage`'s 4-column matrix, which carries no verdict/state column and therefore no bracket prefix.
- §Surface: cli / Component Patterns 5 (Error output) — a finding recorded rather than built (per the chunk's "no new verification capability" boundary) surfaces on stderr as `error: &lt;short&gt;` + detail + `hint: &lt;fix&gt;`, sanitized (no absolute host paths, struct names, stack traces), reusing Fail red / Residual mute — no new colors.
- §Surface: cli / Tokens → Residual entry — Markdown, having no color channel, uses emphasis or the bracket label in a blockquote as the surface-adapted counterpart. The Markdown run report in this chunk's evidence set is bound by this, not by ANSI.

## Anti-patterns to avoid
- Conflating "no result yet" / "not machine-graded" with "failed" — `ManualCheck` and `KnownResidual` exist precisely so neither silently reads as `Fail`, and `Blocked` is never shown as a red error (per design-system.md §Anti-Patterns → Rejected Defaults).
- Colorizing without the `NO_COLOR` / `TERM` / pipe check, or relying on color alone; mixing raw artifact data on stdout with human messages on stderr (per design-system.md §Anti-Patterns → Per-Surface Bans / cli).
- Hiding or animating the progress spinner to 100% at an operator-pause — it must stop in place (per design-system.md §Anti-Patterns → Per-Surface Bans / cli; §Motion → high-impact moment).

## Contract bindings
- **a11y §Use of Color (SC 1.4.1)** — the closed ASCII prefix set (`[PASS]`/`[HOLD]`/`[FAIL]`/`[MANUAL]`/`[RESIDUAL]`/`[BLOCKED]`) is the not-color-alone carrier; it also governs NO_COLOR and screen-reader legibility of this chunk's output (design-system.md §Surface: cli / Tokens).
- **tests / harness (agent-run.sh)** — the per-stream `IsTerminal` gate is what keeps agent-captured evidence (journal, stdout capture, frozen self-obs) ANSI- and emoji-free; the harness's headless invariant and design's "never block the headless path on a prompt" are the same rule seen from two plans (design-system.md §Surface: cli / Component Patterns 2 + §Platform-Specific Notes).
- **architecture (run-report envelope)** — a report row carries BOTH `Verdict` (3) and `ReportState` (5); design mandates the two render as distinct treatments, arch owns the envelope shape (design-system.md §Color Palette → Verdict-vs-ReportState note).
- **layouts** — if any `ManualCheck` row must surface in the webview run-report route, placement/focus order is layouts' call; design only mandates the checklist's content pair (induced state + expected observation) and `--status-manual` treatment (design-system.md §Component Patterns 7).

## Acceptance criteria contributions
- (design) Each of P-067 / P-072 / P-079 prints a per-P-ID verdict line whose glyph + bracket label come from the closed six-state set and whose tier cell renders that scenario's **declared** `slo_tier`, not a baked literal (per design-system.md §Surface: cli / Component Patterns 4).
- (design) P-067 and P-072 render as `?` + `[MANUAL]` (ANSI 146) and never as `[FAIL]` or `[BLOCKED]`; P-079's graded outcome renders as its own machine-verdict lamp — no state collapses into another (per design-system.md §Color Palette → Verdict-vs-ReportState note).
- (design) Every captured artifact this chunk produces (journal, `runs.db` row, Markdown run report, self-obs capture) contains no ANSI escapes and no emoji; the ASCII bracket labels alone carry the status signal (per design-system.md §Surface: cli / Tokens and §Anti-Patterns → Per-Surface Bans / cli).
- (design) The headless leg run completes without blocking on an interactive `inquire` prompt, and any skipped operator decision is recorded to the artifact under the non-interactive policy (per design-system.md §Surface: cli / Component Patterns 2).
