## Constraints
- The live read-back is a validated trust boundary: bounded line-delimited JSON-RPC decode with a soft per-line size bound, JSON-RPC/decode/transport faults typed rather than panicking, and an empty canary round-trip becoming `blocked` — never a false pass-as-empty (per security-plan.md §Input Validation, MCP child stdout row). Whether the shipped read-back path already applies the per-line bound and the freshness comparison is research's question.
- A non-blocked verdict must be produced by the gate PASSING, not by the gate being weakened: each of the five named preconditions must still surface as its own distinct `blocked` string, and a term whose truth lives on the SUT's side must be recorded `declared-not-observable` rather than blocking (per security-plan.md §Security Anti-Patterns → Universal, never-silently-downgrade ban).
- Every live leg's sidecar spawn must keep the hardened form: fixed program NAME resolved through the inherited `PATH`, `ANDROMEDA_PULSE_DATA_DIR` carried only via the `.env(...)` builder after argument-injection metacharacter rejection, nothing operator-supplied in argv or a shell, plus the Windows console-suppressing creation flag (per security-plan.md §Security Anti-Patterns → Code Patterns rule (a); §Input Validation, `ANDROMEDA_PULSE_DATA_DIR` SPAWN-propagation row).
- The scope's "env posture handed per command and read back from Pulse's own witness line" is bounded by the declaration-only read discipline: handle NAMES only, no `ANDROMEDA_PULSE_*` value ever becoming a path, an argv element or a log value, and `data_dir` rendering `&lt;redacted&gt;` in the gate output (per security-plan.md §Input Validation, `ANDROMEDA_PULSE_*` declaration-only READ SET row). Whether the current witness-line read already satisfies this is research's question.
- Every artifact this chunk must produce — `runs/&lt;run_id&gt;.jsonl`, the `runs.db` row, `&lt;run_id&gt;.md`, and the frozen self-obs capture — must carry verdict/state/identity fields only, with no absolute host path (canonicalized `CONDUCTOR_*` dirs, the data-dir value) and no internal seam-crate struct name; a `blocked` row must populate identity fields plus the named precondition string and null its measurement fields (per security-plan.md §Error Handling, run-report artifact sanitization).
- Pulse's `corpus.db` is reachable through the MCP TOOL SURFACE only — read-back plus the `mark_incident_resolved` lifecycle write — never the file, and its content is never persisted into Conductor artifacts (per security-plan.md §Security Anti-Patterns → Data Protection). This binds P3 open question 2 (is `span_refs` populated at HEAD): it must be answered through read-back, not by opening the corpus.
- ManualCheck and graded outcomes alike must cross the verdict/error wall as `Ok(Verdict/ReportState)` values, with `Result::Err` reserved for harness faults, and no malformed child/transport input may panic (per security-plan.md §Error Handling; §Security Anti-Patterns → Universal).

## Patterns to follow
- The leading `conductor preconditions` arm on the path SET `{boot, run --live}`: a short-circuit REFUSAL at exit 1 naming each unsatisfied subject with no leg fired and no sidecar spawned, rather than a ~0s `[BLOCKED]` row indistinguishable from a real SUT-side gate failure (per security-plan.md §Security Anti-Patterns → Universal; §Security Anti-Patterns → Input, `PATH`-miss / `sidecar-resolvable` clause).
- The harness's non-recursive capture-dir clearing idiom, adopted when the recursive delete over a `CONDUCTOR_RUNS_DIR`-derived path was removed — new legs or gate entries must not reintroduce a recursive delete (per security-plan.md §Security Anti-Patterns → Input, canonicalize duty; amendment `2026-09-06-operator-gated-live-suite`).
- Host-path-free failure origins and precondition text: name the handle and the file's own name, never a resolved path (per security-plan.md §Input Validation, env-var path handles row).
- The committed-evidence hygiene grep already used for `evidence/nvda-pass.json` (zero host paths, zero seam-crate struct names in the committed record) is the shape this chunk's frozen self-obs capture should be gated with (per security-plan.md §Security Anti-Patterns → Logging).
- Harness-spawn rule (b)'s existing governed forms — array-form argv, fixed program, operator-supplied values only as separate argv words after rejection — are the template if the wiring fork adds any new invocation (per security-plan.md §Security Anti-Patterns → Code Patterns rule (b)).

## Anti-patterns to avoid
- Never reach "non-blocked" by relaxing the readiness gate: no downgrading a failed preflight to pass/fail/manual-check, no reading an absent or unparseable canary stamp as satisfied, no false pass-as-empty. A P-079 `CountAtLeast` Pass that cannot distinguish the storm's contribution from the preflight canary's is exactly the false-green this ban targets (per security-plan.md §Security Anti-Patterns → Universal and → Input).
- Never open, copy, read or stage rows in Pulse's plaintext `corpus.db` directly — not to diagnose `span_refs`, not to induce a SUT state (per security-plan.md §Security Anti-Patterns → Data Protection).
- Never leak an absolute host path, a seam-crate struct name, or an `ANDROMEDA_PULSE_*` handle VALUE into stderr, a run artifact, or the committed capture (per security-plan.md §Security Anti-Patterns → Logging).

## Contract bindings
- security ↔ obs: the frozen self-obs capture and the `ReadyState` line are obs-emitted artifacts subject to this plan's host-path / struct-name sanitization ban and the `data_dir: &lt;redacted&gt;` rendering (security-plan.md §Error Handling; §Input Validation declaration-only READ SET row).
- security ↔ tests: the committed-evidence hygiene grep is the tests-side check that proves the Logging ban; separately, per security-plan.md §Threat Model Summary → Infrastructure → CI/CD, dynamic live-Pulse proof is an explicit operator/local gate and must not be wired as a CI gate — the security CI gate (`cargo audit` / `cargo deny`, journal conformance) stays a distinct job.
- security ↔ arch/harness: the wiring fork (three legs inside `live_suite()` vs three `leg = 'live'` gate entries) touches harness-spawn rule (b)'s governed-form enumeration; whether either form constitutes a new subprocess crossing (a boundary widening that escalates, per security-plan.md §Security Anti-Patterns → Code Patterns rule (b)) is research's question.

## Acceptance criteria contributions
- No artifact produced by any of the three legs — `runs/&lt;run_id&gt;.jsonl`, the `runs.db` row, `&lt;run_id&gt;.md`, or the frozen self-obs capture — contains an absolute host path or an internal seam-crate struct name, and no `ANDROMEDA_PULSE_*` handle value appears in any of them (per security-plan.md §Error Handling, run-report artifact sanitization; §Security Anti-Patterns → Logging).
- Each non-blocked verdict is reached with the readiness gate intact: no preflight/preconditions arm is relaxed, skipped outside the sanctioned `{boot, run --live}` short-circuit, or re-graded, and an empty/NOT-fresh canary round-trip would still yield `blocked` with its own named precondition string (per security-plan.md §Security Anti-Patterns → Universal).
- Every leg's outcome (ManualCheck or graded) crosses the wall as an `Ok(...)` typed value with `Result::Err` reserved for harness faults, and no live sidecar response — including a JSON-RPC error or malformed line — panics any leg (per security-plan.md §Error Handling; §Security Anti-Patterns → Universal).
- `cargo audit` and `cargo deny check advisories bans licenses sources` are green over an un-drifted committed `Cargo.lock` before the round is banked (per security-plan.md §Security Anti-Patterns → Universal; §Dependency Security).
