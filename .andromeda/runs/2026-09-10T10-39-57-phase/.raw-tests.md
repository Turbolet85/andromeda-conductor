## Constraints
- The live-Pulse round is an **operator/local gate, never a CI gate**; the sanctioned invocation paths are a named SET — `workflow_dispatch`, `scripts/agent-run.{sh,ps1}` (including its composed `run --live` stage), a cargo-feature-gated test file invoked directly behind `[features] live-pulse = []`, or an npm-script wdio suite. A feature-gated target is invisible to the default lint pass and therefore **owes its own** `cargo clippy -p &lt;crate&gt; --features &lt;feat&gt; --all-targets -- -D warnings` (per test-plan.md §9 Live-Pulse scenarios, §11 CI). This governs the chunk's wiring fork (scope open question 4) from the tests side: either fork must land on a path in that SET.
- Any `--live` wiring must keep the harness at **five commands** (a sibling `case` branch under `run`), add **no port, env var or `CONDUCTOR_*` handle**, read leg ORDER from `live_leg_order` in the shells rather than restating a count, and freeze each leg's `logs/agent-latest.jsonl` to `runs/live-suite/{leg}.jsonl` because that sink truncates per invocation (per test-plan.md §3 `run` → CI stage selectors, `--live` paragraph).
- `Blocked` / `ManualCheck` / `KnownResidual` / `CalibrationRegion` are **reported envelope states, not process-failure exits**; only a hard `Fail` is non-zero. A leg must not grade by exit code where the state is the signal (per test-plan.md §11 E2E stack-specific ban; §3 `run` exit-code semantics).
- Evidence shape is fixed: the eleven-field envelope, serialized identically into the Markdown report, the `runs` row and the envelope JSONL line; the journal carries **two report-seam shapes** (envelope line + per-check `CheckRecord`), so a typed parse must DISCRIMINATE and a `status` read must target the **newest ENVELOPE line selected by the envelope-only `seed` key — never the file's last line** (per test-plan.md §3 Status endpoint shape + Log format + `status`). Load-bearing here because P-079 grades a check and will end its journal on a `CheckRecord`.
- Pulse's reaction may **never be faked as a verdict**, and where no read-back surface can carry a claim the plan's standing remedy is to retire the read-back check to declare-only and grade the live claim at the **harvest tier** over Pulse's own log lines — never to keep a check that can pass vacuously or on the wrong subject (per test-plan.md §11 Test Strategy stack-specific; §6 Fingerprint-storm, where `Contains` structurally failed and `Absent` passed VACUOUSLY). This is the plan-side handle on the scope's P-079 false-green risk.
- Live legs run on **real wall clock** and are carried only as the enumerated operator-local exceptions to the determinism invariant; a leg whose grading moves by SUT uptime or by when a preflight canary formed must be recorded **NOT run-stable with a conditional verdict**, explicitly not a source-delta fact. The `--live` suite's 150 s inter-leg quiet window is a firing-form precondition (a SUT-side dedupe window that emits no signal to wait on), not a permitted in-test sleep (per test-plan.md §2 Agent-runnable invariants; §9 Live-Pulse scenarios; §11 E2E `sleep(N)` ban scope).
- Scenario TOMLs are **committed declarative fixtures one-per-P-ID under `scenarios/`**, and seed precedence is `--seed` ONLY when `SEED` is explicitly set — unset ⇒ the TOML-declared seed governs, identical in both shells (per test-plan.md §7 Seed strategies; §3 `run` scenario invocation). Backs the scope's "no scenario re-authoring" boundary.

## Patterns to follow
- **Harvest-tier grading for a live claim the read-back cannot carry** — the `storm_harvest.rs` / `baseline_harvest.rs` / `restart_harvest.rs` / `pii_harvest.rs` / `connection_harvest.rs` / `severity_harvest.rs` / `lifecycle_harvest.rs` family at the `conductor-run` tier, asserting verbatim Pulse log lines from a pinned capture (test-plan.md §6 scenario entries).
- **Declare-only row shape** as the established non-blocked outcome: `verdict` null, `state="KnownResidual"` (non-Blocked), `latency_ms` recorded against the declared `slo_tier`, exit 0 (test-plan.md §6 + §1 Critical paths 1–4).
- **Evidence assertion mechanics**: bound-parameter `SELECT` against `runs.db` (never `format!`-built SQL) plus `serde_json::from_str::&lt;RunReportEnvelope&gt;` on the envelope line or `jq -e`; artifacts must leak no absolute host paths or internal struct names (test-plan.md §3 Status endpoint shape; §11 Integration).
- **Live-leg firing form** as part of the leg, not an optional extra: `andromeda-pulse-mcp` resolved by fixed NAME through the inherited `PATH`, `ANDROMEDA_PULSE_MCP_ENABLED` (+ `_L4_DETERMINISTIC` where the tier demands it), `ANDROMEDA_PULSE_DATA_DIR` **equal to the live Pulse's data dir**, and a quiet window after any preflight canary — a bare invocation returns BLOCKED in ~2 ms, at row level indistinguishable from a genuine SUT-side gate failure (test-plan.md §6 drivers-per-surface, driven-arm firing form). Relevant because `v2-04` requires a **non-blocked** verdict.
- **Boot as probe-then-gate**: a leading non-priming `conductor preconditions` short-circuits an actually-unmet subject before the preflight and its two derived timeout budgets are paid; budgets are derived from `contracts/pulse-run-contract.toml`, never a literal (test-plan.md §3 `boot`).

## Anti-patterns to avoid
- NEVER run the live-Pulse scenarios as a CI gate, in any of the three wiring forms (test-plan.md §11 CI).
- NEVER treat `Blocked`/`ManualCheck`/`KnownResidual`/`CalibrationRegion` as a non-zero process exit, and NEVER bank a check whose predicate cannot distinguish its intended subject from an incidental one (test-plan.md §11 E2E; §11 Test Strategy "never fake Pulse's reaction as a CI verdict").
- NEVER re-author a scenario or loosen a check to make a verdict greener; the plan's precedent is to RETIRE the ungradeable check and re-base the signal at both its §6 and §1 sites (test-plan.md §6 scenario re-bases; §11 Quality "never skip/lower a gate").
