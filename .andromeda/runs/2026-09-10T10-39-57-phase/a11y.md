## Constraints
- The `conductor` verb surface is **not-assertable** as a SET (not an enumeration of verbs) — no axe / Lighthouse / pa11y reach, no WCAG conformance claimable from any leg this chunk drives; ASCII status prefixes and `NO_COLOR` text-pairing are output-stream discipline, not an a11y verification path (per a11y-plan.md §1 A11y Scope Summary → `conductor-cli` entity; §11 Anti-Patterns → Universal).
- The journal rows this chunk emits ARE the envelope a11y's violation artifacts reproduce verbatim; a11y narrows, obs fixed the schema. Any change to the eleven-key envelope (or to which resource tags ride it) obligates a11y §3's reproduction to track it (per a11y-plan.md §3 Structured violation JSON schema).
- `verdict`/`state` must remain joinable **verdict-first**: a `ManualCheck` state with NO verdict is the `Manual` lamp; a `ManualCheck` state carrying `verdict == CalibrationRegion` is the HOLD lamp regardless of state. The scope's reading of P-067/P-072 ("empty `expected` → verdict None → `Lamp::Manual`") lands on the `Manual` row of that table only if the emitted verdict is genuinely absent (per a11y-plan.md §6 State color tokens → State-naming crosswalk).
- a11y-plan.md §1 Critical Paths (Operator-checklist) requires that a `ManualCheck` lamp **link to a checklist** whose rows are `checkbox`-per-item with an announced unticked-count roll-up (SC 4.1.3). Scope open question 3 notes none of the three scenarios declares `[[checklist]]`; whether the code already renders a `Manual` lamp with a reachable (or empty) checklist target is research's question (per a11y-plan.md §1 Critical Paths + §5 Focus order → `idle-with-report`, which records the report-site checklist render as unbuilt and route-owned).
- The **driven** a11y arm requires a live Pulse plus its full firing form and stays operator/local — it is barred from CI; only the Pulse-free routine arm is CI-wired. The wiring fork (three legs in `live_suite()` vs three `leg = 'live'` gate entries) must not migrate the driven arm into CI or strand it out of the live session (per a11y-plan.md §9 CI Integration → Platform + E2E artifacts row; §11 Anti-Patterns → Strategy CARVE-OUT).
- The operator/local a11y gate is budgeted so it does not dominate the live-Pulse operator session — driven arm at a 15-minute mocha ceiling, with a quiet-window precondition costing two 12-minute runs when violated. Three new live legs in the same session spend against that budget (per a11y-plan.md §10 SLO Invariants → Performance budget per a11y CI run).
- Artifacts must not leak absolute host paths or internal seam-crate struct names into the obs §6 envelope (inherited from tests' Status JSON constraint) — this binds the frozen self-obs capture and any violation record produced alongside it (per a11y-plan.md §9 CI-specific resource attributes; §11 Anti-Patterns → SLO).

## Patterns to follow
- **Arm-split registration**: a leg needing a live SUT registers in the operator-only driven family, never the routine CI arm; the routine arm seeds its own committed fixture through the production writer instead (a11y-plan.md §9 E2E artifacts row). The wiring fork should place the three live legs on the same side of this split as the existing driven arm.
- **One webview-automation stack**: everything webview-facing rides tests' `@crabnebula/tauri-driver` + WebdriverIO session (`wdio run`) — a11y injects into it rather than standing up a parallel stack (a11y-plan.md §3 A11y testing tool pick; §11 Anti-Patterns → CI).
- **Host-handle skip discipline plus a printed-verdict assertion**: legs whose host tool is unresolved skip at exit 0 by design, so `CONDUCTOR_A11Y_STRICT` plus assertions on the runner's printed verdict (`Spec Files:` failed count, per-spec skip tally against the expected-skip SET) are what distinguish a skipped-green run from a real pass (a11y-plan.md §11 Anti-Patterns → CI). Any light-gate re-run form for these three legs inherits the same failure mode.
- **Crosswalk join for lamp↔journal**: downstream joins a rendered lamp back to its journal row through the §6 crosswalk table, keyed verdict-first (a11y-plan.md §6 State color tokens).
- **5-command harness reuse**: a11y results surface through tests' binding `logs` command rather than a bespoke emission path (a11y-plan.md §3 CI integration → Command; §9 Pipeline integration).

## Anti-patterns to avoid
- Treating any part of the CLI round as accessibility-assertable, or claiming WCAG conformance from a leg with no DOM (a11y-plan.md §11 → Universal).
- Standing up a second browser-automation stack (puppeteer/CDP or otherwise) for any a11y-adjacent leg the wiring fork adds (a11y-plan.md §11 → CI).
- Letting the light-gate re-run form be satisfiable by a skipped-green run — a skip at exit 0 and a real pass are otherwise indistinguishable (a11y-plan.md §11 → CI).
