## Constraints
- The per-P-ID verdict / report-state bracket-label set is **closed at six** (`[PASS]`/`[HOLD]`/`[FAIL]`/`[MANUAL]`/`[RESIDUAL]`/`[BLOCKED]`); a live-round outcome must land in one of them — a "live"/"unconfirmed"/"canary-contaminated" state may not become a seventh lamp or a sixth `ReportState` (per layout-templates.md §Surface: cli — Component — Primary content block 2).
- Run-level qualifiers ride **outside** the lamp column as a separate non-lamp SET (`[ENVIRONMENT-SUSPECT]` once per run, `[PRECONDITION]` one line per unmet subject **or** the single satisfied line — both arms shipped), minting no `Verdict`, no `ReportState` and no per-P-ID row (per layout-templates.md §Surface: cli — Component — Primary content block 2; §Primary screens `conductor preconditions [--json]`).
- `--live` is a **stage flag** of `scripts/agent-run.{sh,ps1}`, never a sixth command, with a stated exit rule: an unmet live-Pulse subject **refuses** the suite at exit 1 printing one host-path-free `[PRECONDITION]` line per subject and firing no leg, while an absent host-tool handle **skips** its leg at exit 0 (lax arm) or exits non-zero under an affirmative `CONDUCTOR_A11Y_STRICT` (per layout-templates.md §Surface: cli — Primary screens, the `agent-run` bullet). Whichever wiring fork P3/P4 picks must leave that rule intact.
- **Headless invariant:** `inquire` prompts are always `isatty`-gated and the agent-driven source-of-truth path is *never* blocked on a prompt; a headless ManualCheck is **recorded unconfirmed**, not prompted (per layout-templates.md §Surface: cli — IA notes, Headless invariant; §Component — Hero / signature output).
- The `runs/<run_id>.md` **per-check detail region** requires one indented plain-text line per expected check under its P-ID verdict line (ordinal · comparison kind · verdict · `latency_ms` · the deadline judged against) with **no new column, no new bracket label, no new ANSI/token** — and a scenario that graded nothing (blocked or declare-only) contributes **no such line** (per layout-templates.md §Surface: cli — Component — Primary content block 2, per-check detail region). This bears directly on the P-067/P-072 (empty `expected`) vs P-079 (one `CountAtLeast` check) split.
- Non-result states are never downgraded: `ManualCheck` is not a machine verdict, `Blocked` is never red, and measurement columns render `—`/null rather than an error (per layout-templates.md §Surface: cli — Component — Primary content block 2; §desktop Primary content block 2, distinct non-result states).
- Output structure is a **stability contract** — downstream agents parse it, so adding a `comfy-table` column without a `--format` flag is a breaking change; the 6-column results/SLO table and the 4-column `coverage` table must not be conflated (per layout-templates.md §Surface: cli — IA notes, Command model; §Component — Primary content block 1).

## Anti-patterns to avoid
- Minting a new bracket label / lamp / `ReportState` to express a live-round nuance (canary-contaminated read-back, "live-unverified") — the six-member set is closed and run-level facts go to the non-lamp qualifier SET outside the lamp column (per layout-templates.md §Surface: cli — Component — Primary content block 2).
- Gating any `--live` leg on an interactive `inquire` prompt or an un-`isatty`-checked confirm — an interactive gate on the agent path silently breaks the release gate (per layout-templates.md §Surface: cli — IA notes, Headless invariant).
- Widening the 6-column results/SLO table (or leaking `slo_tier`/`latency_ms` cells into the 4-column coverage matrix) to carry live-round evidence (per layout-templates.md §Surface: cli — Component — Primary content block 1).
