# obs extract

## Relevance
Relevant — the chunk's whole deliverable is telemetry artifacts (run journal envelope, `runs.db` row, frozen self-obs capture) that this plan specifies.

## Constraints
- The run journal row per scenario must carry the eleven-field Run-report envelope, and "required" means KEY PRESENCE, not non-null — the five measurement fields are `Option` and serialize as `null` on a blocked row (per obs-plan.md §6 Required fields, §3 Log format JSON schema). `state` and `verdict` are closed enums; `ManualCheck` is a member of `state`, and `Blocked` is the value `v2-04`'s "non-blocked" clause must exclude.
- A blocked row is defined by `read_back_observed_at` and `latency_ms` being null (per obs-plan.md §3/§6 envelope schema) — so a non-blocked verdict is an obs-observable property of those two fields, not only of `state`. Whether the ManualCheck path (empty `expected`) populates them, i.e. whether it reaches read-back at all, is research's question (scope open question 1).
- Critical Path 1 — headless deterministic scenario run with MCP read-back verification — is the must-trace path all three legs drive: `scenario.run` → `timeline.execute` → `emit.batch` → `verify.readback` → `report.generate` → `db.insert_run`, with `report.generate`/`db.insert_run` as run-scoped SIBLINGS correlated by `run_id`, since under a suite one `persist` serves N scenarios whose roots already closed (per obs-plan.md §4 Critical Path 1 + Cleanup). §11 requires spans not be skipped on Scenarios 1-7; whether these already fire on these three scenarios is research's question.
- Any span attribute must be a name in `conductor-core::redact::ALLOWLISTED_FIELDS` or the processor stage drops it silently (per obs-plan.md §4 Required-span-attributes heading). Evidence with no allowlisted field name — an incident id, an observed key set, a per-incident distinction for P-079 — must ride the allowlisted `message` field.
- `latency_ms` is `read_back_observed_at − journal_emitted_at` in wall-clock (`std::time::SystemTime`), never tokio's virtual clock, and the SLO is a hard JSON field assertion at report-generation time against the closed `slo_tier` set `<5s | <20s | <90s` (per obs-plan.md §5, §10, §11 project-specific bans). P-072's `<90s` tier is therefore graded, not advisory — the scope's `ANDROMEDA_PULSE_L4_DETERMINISTIC` inference is load-bearing on this plan's side too.
- The frozen self-obs capture is the §3 self-obs base line (`timestamp_ms`, `level`, `target`, `service.{name,version}`, `deployment.environment`, `run_id`), a DIFFERENT record shape from the envelope, and the §9 conformance gate asserts that base schema plus zero absolute host-file paths in any field (per obs-plan.md §9 Log conformance check, §3 two record shapes).
- Malformed or failing MCP read-back must yield a typed `blocked` value, never a panic, and every panic must be captured structured (per obs-plan.md §11 Error Reporting, §10 zero-unlogged-panics). Against a live SUT this is the failure mode that turns a leg into exactly the `Blocked` row `v2-04` forbids.

## Patterns to follow
- The read-back boundary must-log: tool name (`query_incident_list` / `retrieve_report` / `retrieve_telemetry_slice` / `mark_incident_resolved`) + `latency_ms` + error + canary-check result + the observed KEY SET of each raw tool result, key names only, never values, on the `message` field (per obs-plan.md §6 Boundary-call wrappers). This witness exists precisely because the extraction readers degrade to empty on an unrecognized shape — it is the mechanism that separates "`span_refs` absent" from "`span_refs` empty", which is scope open question 2 and P-079's false-green risk.
- Prior live-proof landings record the shipped chain and the standard eleven-field envelope rather than a family-specific span chain, with Pulse-side quantities graded at the harvest tier over Pulse's own tracing lines (per obs-plan.md §4 Restart-suppression, Severity-lifecycle, Known-residual/Delegated-timing blocks). If P-079's storm-vs-canary distinction is not derivable from Conductor's own surfaces, that is the tier it belongs to.
- The `message`-field escape hatch as the sanctioned way to carry derived counts and identifiers without widening `ALLOWLISTED_FIELDS` (per obs-plan.md §6 Boundary-call wrappers, §4 Coverage-matrix gate).
- Sink discipline for the captures: one `JsonObsLayer` over every writer, stderr or file, JSON either way, never stdout and never pretty; `--agent-mode` is a WRITER switch and a read-only trigger (`flag || env-set`) Conductor never writes (per obs-plan.md §3 Logging stack, §6 Sink configuration).
- Envelope-extension precedent: a harness artifact may carry a superset of the eleven keys because `journal_conformance` asserts presence, closed sets and host-path freedom, never key exclusivity — the scenario record at `runs/<run_id>.jsonl` still carries the eleven alone (per obs-plan.md §3 extension-point paragraph).

## Anti-patterns to avoid
- Minting a span name outside the bounded set (`scenario.run`, `timeline.execute*`, `emit.batch`, `emit.logs_batch`, `verify.readback*`, `report.generate`, `db.insert_run`, `fault.*`, `tauri.command.*`) or a span attribute outside `ALLOWLISTED_FIELDS` — the latter emits nothing at all (per obs-plan.md §11 Spans/Traces, §4).
- Any absolute host path in the committed capture, run report or `runs.db` row — including the SUT boot-posture witness line, since §11's standing warning is explicit that the three redaction application sites do not bound every host-path channel (per obs-plan.md §11 Logs, §11 PII Scrubbing).
- Treating an SLO tier as advisory, or introducing any OTel SDK / network OTLP for self-observation while driving a live Pulse on `:4317` (per obs-plan.md §10 SLO, §11 Universal recursion guard).

## Contract bindings
- **obs ↔ tests:** test-plan §3 OWNS the JSONL envelope and log format; obs §3/§6 reproduce it and must not diverge one-sidedly. The grading instrument for this chunk's journal evidence is `conductor-run`'s `journal_conformance` (per obs-plan.md §3, §6).
- **obs ↔ tests (harvest tier):** Pulse-side quantities reach the record through the harvest-tier tests over Pulse's own tracing lines, not through Conductor spans (per obs-plan.md §4 Known-residual / Delegated-timing).
- **obs ↔ security:** the sidecar-spawn ban — fixed program NAME through inherited `PATH` + `.env(...)`, never a shell, never a visible console window — governs the live legs' MCP sidecar (per obs-plan.md §11 Project-specific bans).
- **obs ↔ a11y:** the driven a11y arm shares `live_suite()` with the wiring fork, and its violation record at `runs/a11y/<run_id>.jsonl` is the one known exerciser of the envelope extension point (per obs-plan.md §3, §9 artifact table).

## Acceptance criteria contributions
- Each of the three scenarios' journal row carries all eleven envelope keys, `state` and `verdict` inside their closed sets, `state` ≠ `Blocked`, and `read_back_observed_at` + `latency_ms` non-null (per obs-plan.md §6 Required fields / §3 Log format JSON schema)
- Each leg's `latency_ms` ≤ its `slo_tier` threshold, computed wall-clock as `read_back_observed_at − journal_emitted_at` and asserted at report-generation time (per obs-plan.md §10 Performance budgets / §5)
- The frozen self-obs capture per leg carries the §3 base set on every line, zero absolute host-file paths in any field, and zero unstructured `^thread.*panicked` lines (per obs-plan.md §9 Log conformance check + Zero-unlogged-panics gate)
- Each leg's read-back boundary log records tool name + latency + the observed KEY SET of each raw tool result on the allowlisted `message` field, so an empty corpus is distinguishable from a shape divergence — the check that makes P-079's `CountAtLeast >= 1` interpretable rather than a false green (per obs-plan.md §6 Boundary-call wrappers)
