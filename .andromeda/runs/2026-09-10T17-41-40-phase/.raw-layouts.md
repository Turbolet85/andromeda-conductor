## Constraints
- The operator-pause dialog's focus **restoration is contract-borne, not Radix-supplied**: layout-templates §Component — Hero / signature section requires a `restoreFocusTo` accessor restored explicitly in `onCloseAutoFocus`, with the invoking control kept focusable (`Start` conveys unavailability via `aria-disabled`, **never** the native `disabled` attribute) — because the hold arrives over a Tauri `Channel` and the dialog has no Radix `Trigger`. This is exactly the mandate `S3-04` exercises; **whether the code at HEAD already satisfies it (vs. focus landing on `&lt;body&gt;`) is research's question.**
- The release bundle must present **one surface in the four shipped run states** — `idle` · `live` · `hold` · `aborted` (idle-with-report a sub-state of `idle`) — with no router, no routes, no deep links, no breakpoints (per layout-templates §Surface: desktop-webview Primary screens and §IA notes Global model). Any e2e/SR driving navigates by run state, not by route.
- In the `aborted` state, layout-templates §Component — Header requires the titlebar phase line to render one of **four fixed labels** from the label map (`Conductor · aborted`), never the operational segment name, with the count stopped and dimmed to `count-blocked` (per §Primary screens, Run console (aborted)). §Primary screens records **no wireframe entry** for `aborted`, so the label map plus the count rule are the whole layout spec for CARRY C's state.
- The `--e2e` stage is the **cross-surface** leg: it builds the release Tauri bundle and drives the console through tauri-driver, gated on a Conductor-owned driver handle, and it must assert the runner's **printed verdict** — the `Spec Files:` failed count, the per-spec skip markers against the expected-skip set, and the `[webview2 … windows]` driven-session banner — because the exit code alone cannot separate a full pass from a total skip (per layout-templates §Surface: cli — Primary screens, `scripts/agent-run.{sh,ps1}` bullet). Handle absence **skips at exit 0 on the default arm and exits non-zero under an affirmative `CONDUCTOR_A11Y_STRICT`** (same anchor).
- The desktop-webview expression budget is **0.3** — in-place CSS color transitions, `motion-micro` at most, no animation library, no spring/stagger/parallax (per layout-templates §Surface: desktop-webview Expression level), and the signature moment is choreographed by the *absence* of motion (per §Component — Hero, expression rationale).
- Two layout regions are recorded as **DESIGNED, NOT SHIPPED** and remain route-owned gaps at version close: the footer `contentinfo` status strip (landmark set is `banner` + `main` + two `region`s) and the run-report-site operator-checklist render (only the dialog context mounts the primitive) — per layout-templates §Component — Footer and §Component — Operator-checklist. A final verification pass must not read either absence as a regression this chunk introduced.
- Status is **never color-alone** on either surface: every lamp pairs with its text, every cli state cell pairs with its ASCII bracket prefix, and absence states are distinguished by TEXT (per layout-templates §Primary content block 1 / §cli Primary content block 2).

## Patterns to follow
- **Announce-exactly-once siting** (the closest precedent to CARRY C's variance class): the catalog LOAD-ERROR render keeps its VISIBLE copy *outside* the announced `role="alert"` region while the region carries a visually-hidden re-assertion alone, inserted once on the first `focusin` — per layout-templates §Primary content block 1, States. The recorded reason is that keeping both inside made NVDA read the region whole and speak it twice.
- **Mount timing as the discriminator**: the three sibling error regions (action / coverage / report) keep the empty-mount-at-first-paint shape *because they fire at arbitrary times rather than before the screen reader binds* (same anchor). Any CARRY C theory should be reasoned against this bind-timing axis, which layout-templates already treats as causal.
- **Three distinct App.tsx-owned console states, three strings, three regions** — empty catalog `No scenarios found.`, picker filter-miss `No scenarios match.`, and the load-error render — never collapsed into one (per layout-templates §Primary content block 1, States). Relevant if the final pass asserts console prose over the shipped bundle.
- **Checklist rows are a sibling of the dialog's `Description`, never nested inside it** (the Description is the described-by target and interactive rows read as flat prose there) — per layout-templates §Component — Hero and §Component — Operator-checklist. Binding if any CARRY C remedy touches the dialog subtree.
- **Adapted per surface, never forked**: run-level qualifiers and tokens render by the same name across webview / cli / Markdown (per layout-templates §IA notes, Multi-surface coordination).

## Anti-patterns to avoid
- **No motion added to stabilize the SR/e2e leg** — no delay-to-settle, no fade-in lengthening, no animation-library entrance; the 0.3 budget and the "freeze is the event" rationale forbid it (per layout-templates §Expression level and §Component — Hero). This compounds the scope's own zero-flake bar (no retry, no pin, no in-test sleep).
- **No new route, router, second window or breakpoint** to accommodate the e2e/SR leg — the frameless window IS the surface and responsive breakpoints are N/A by decision (per layout-templates §IA notes Global model and §Decisions Log, Responsive breakpoints).
- **No new lamp, bracket label or `ReportState`** minted to record the release/SLO pass — the lamp set is closed at six and run-level qualifiers ride OUTSIDE the lamp column (per layout-templates §Primary content block 2, both surfaces).

## Contract bindings
- **layouts ↔ a11y** — layout-templates §Component — Hero owns the *structure* of restoration (`restoreFocusTo`, `onCloseAutoFocus`, focusable invoker via `aria-disabled`); a11y §Modal focus trap owns Escape-dismiss + restore-focus conformance and the announcement semantics. `S3-04` sits exactly on this seam, which is why its ownership is the operator fork raised at P4.
- **layouts ↔ a11y** — focus order / focus-ring visibility (`color-focus`, `border-emphasis` on the active picker item) binds to a11y §Focus Order SC 2.4.3 (per layout-templates §Component — Primary navigation).
- **layouts ↔ tests/harness** — layout-templates §cli Primary screens names the `--e2e` stage's SUBJECT (the release Tauri bundle) and its printed-verdict assertion set; the test plan owns shell parity (§3) and the zero-flake bar (§10). Shell parity is stated as a property of the scripts *together with the invoking environment*, not of the scripts alone.
- **layouts ↔ build artifact** — the surface this domain specifies is delivered by this chunk's Tauri 2 bundle; the `--e2e` leg is the only path that drives layout structure over the *shipped* artifact rather than a dev server.

- (layouts) The shipped bundle presents one surface in the four run states with no router, route entry, deep link or breakpoint added (per layout-templates §Surface: desktop-webview Primary screens and §IA notes Global model).
- (layouts) The `--e2e` leg over the shipped bundle asserts the runner's PRINTED verdict — `Spec Files:` failed count, per-spec skip markers against the expected-skip set, and the `[webview2 … windows]` driven-session banner — rather than the exit code alone (per layout-templates §Surface: cli — Primary screens, `scripts/agent-run.{sh,ps1}` bullet).
