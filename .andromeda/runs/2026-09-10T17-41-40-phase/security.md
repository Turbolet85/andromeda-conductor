## Relevance
Relevant — the release build IS the gated act security-plan.md names, and the bundle, the recorded pass artifacts and the CARRY items each touch a mandated control.

## Constraints
- The release build is gated, not merely accompanied: `cargo audit` and (recommended) `cargo deny check advisories bans licenses sources` must be green and `Cargo.lock` committed and un-drifted **before** `cargo build --release` runs — this is the Minimal-tier residual-risk control for the `bundled`-SQLite-from-C + OTLP/gRPC/MCP tree (per security-plan.md §Security Anti-Patterns → Universal; §Dependency Security). Whether the current tree measures green at HEAD is research's question.
- If either scan goes red, the remedy path is fixed: run the porcelain check on the local RustSec advisory-db checkout FIRST — a local untracked residue must be excluded before any failure is classed as an advisory-DATABASE fault; a TOOL fault is remedied by raising the floor, a DB fault by a bounded wait with the audit↔deny overlap VERIFIED green. Never a `deny.toml` ignore, never a CI edit, never a silent accept (per security-plan.md §Dependency Security, two-external-decay-faults block).
- Release **signing / SBOM / base-image scanning are SKIP** for artifacts Conductor produces — Minimal tier, no container/cloud deployment. `cargo auditable build --release` is named as low-priority, purely additive, and explicitly **not a gate**; this chunk must not promote it into one. The SKIP covers PRODUCED artifacts only and does not retract the consumption-side Authenticode control (per security-plan.md §Dependency Security, supply-chain-integrity subsection).
- The Tauri bundle must ship a deny-by-default capabilities file allowing ONLY the actual commands (start/stop, scenario/suite picker, run-report view, operator-pause) plus the one live-counter `Channel`; no `shell-open` plugin, no remote-origin iframes in the bundled webview (per security-plan.md §Security Anti-Patterns → Code Patterns). App-defined commands are NOT capability-ACL-gated, so the `resolve_under` + `sanitize_error` IPC row — not the capabilities file — governs their arguments (per §Input Validation, `#[tauri::command]` row). Whether the shipped `capabilities/` already satisfies the deny-by-default requirement is research's question, not something this extract can attest.
- CARRY A's remedy (serializing the two `obs.rs` hook tests or giving them a shared guard) must not weaken the invariant `panic_hook_redacts_host_path_in_payload` exists to hold: §Security Anti-Patterns → Logging bans exposing absolute file paths or internal seam-crate struct names to operator-facing surfaces, and a "fix" that merges, deletes or stubs that assertion would remove the only guard on the panic-payload redaction (per security-plan.md §Security Anti-Patterns → Logging; §Error Handling, external responses).
- The recorded final-pass artifacts are agent-parseable ground truth shared across hosts: `<run_id>.md`, `runs.db` rows and JSONL journals must carry verdict/state/identity fields WITHOUT absolute host paths (canonicalized `CONDUCTOR_*` dirs, `ANDROMEDA_PULSE_DATA_DIR`) or internal seam-crate struct names; a `blocked` row populates identity fields plus its named precondition string with measurement fields JSON `null` (per security-plan.md §Error Handling, run-report artifact sanitization).
- If the final pass runs live through `scripts/agent-run.{sh,ps1}`, the preflight rules bind unchanged: each of the FIVE named preconditions must surface as its own distinct `blocked` string — never a downgrade to pass/fail/manual-check — and the leading `conductor preconditions` short-circuit on `{boot, run --live}` is the sanctioned skip, minting no `ReadyState`/`Verdict`/`blocked` row. `ANDROMEDA_PULSE_MCP_ENABLED` must be present in Conductor's OWN process environment (operator-exported, inherited by the sidecar; Conductor never sets it) or every read-back measures the unreachable path (per security-plan.md §Security Anti-Patterns → Universal; §Threat Model Summary → Auth model).

## Patterns to follow
- Verify the audit↔deny overlap green rather than assuming it, over the **committed** lock — the deny run is what actually covers advisories, bans, licenses and sources together (security-plan.md §Dependency Security).
- Treat `deny.toml` as the authority on the accepted-exception set; the plan's counts (16 `[advisories] ignore` + 9 `[licenses] allow` as of 2026-09-07) are a reconciliation stamp, not a second source, and must not be re-derived into the plan by this chunk (§Dependency Security, Accepted exceptions).
- Distinguish **version floors** from the **version stamp** the scope raises as an open question: `tauri` ≥ 2.10.3 and toolchain ≥ 1.94.1 are standing security FLOORS recorded as met (tree resolves 2.11.3; toolchain pinned). A `0.1.0 → 0.2.0` product-version stamp bump is not a floor question and neither satisfies nor threatens them (§Dependency Security → Update policy; §Security Anti-Patterns → Universal).
- A plain build/CLI invocation of a fixed toolchain binary with fixed argv (`cargo build --release`, a bundler verb, `cargo audit`) is the class already outside rule (b)'s six governed harness-spawn forms — it is not a new subprocess crossing and owes no boundary-widening ratification (§Security Anti-Patterns → Code Patterns rule (b), as clarified by the 2026-09-09 amendment).
- Host-path scrubbing happens at the WRITER, not at review: `writeNvdaPass` in `crates/conductor-tauri/ui/test/a11y/screen-reader/parse-nvda-log.ts` maps any drive-letter / `%APPDATA%` / `/Users` / `/home` token to `<host-path>` and flags the row `security_finding`, with `heard` bounded at 400 and closed `outcome`/`arm`/`review_grade` sets; the raw log stays under gitignored `runs/` (§Input Validation, screen-reader speech-log ingest row). Any CARRY C work that re-runs the SR leg and commits evidence inherits this path.

## Anti-patterns to avoid
- NEVER produce the release binary or bundle under a red or unrun `cargo audit` / `cargo deny`, and NEVER let `Cargo.lock` drift or go uncommitted — drift makes the scan non-deterministic and lets the `bundled` SQLite C version float past advisory tracking (security-plan.md §Security Anti-Patterns → Universal).
- NEVER relax an existing harness guard to make the SR leg (CARRY C) or the release pass go green: the `UNSAFE_PATH` existence/`isFile`/shell-metacharacter checks on `CONDUCTOR_MSEDGEDRIVER` and `CONDUCTOR_NVDA`, and the `CONDUCTOR_A11Y_STRICT` strictness arm, are recorded as ADDED arms that are byte-unchanged — a remedy may add an arm, never subtract one (security-plan.md §Input Validation, host-tool handle rows).
- NEVER let the shipped bundle introduce an inbound listener of Conductor's own, and NEVER promote the `:4317` port-occupier bind into a general-purpose listener — the dev-only `4444`/`4445` driver ports remain outside the ban and must stay absent from `conductor-cli` / `conductor-tauri` (security-plan.md §Security Anti-Patterns → Universal; §API).

## Contract bindings
- **CARRY A ↔ obs + tests:** the two `obs.rs` hook tests are the holders of a security invariant (panic-payload host-path redaction) but the shared-state defect is owned by testing.md §Quality gates — the security duty is that the redaction assertion survives whatever serialization the tests domain chooses.
- **CI supply-chain gate ↔ tests §CI Integration:** the audit/deny gate is a job in the one existing workflow, not a second pipeline (security-plan.md §Dependency Security, CI integration).
- **Committed SR evidence ↔ a11y + tests:** the host-path scrub and closed-set rules on `nvda-pass.json` are asserted by the SR leg's own gate-1 hygiene grep and gate 2 — no real host path in any committed fixture (security-plan.md §Input Validation speech-log row; §Security Anti-Patterns → Logging).
- **Frontend tree ↔ dependency gate:** if CARRY C or the bundle changes `crates/conductor-tauri/ui/**`, the npm arm binds — `npm audit --omit=dev` clean with `package-lock.json` committed (security-plan.md §Dependency Security, Frontend (npm) supply chain).
- **WebView2 ↔ CI a11y job:** if this chunk touches that job, the CI-time-fetched bootstrapper is the third dependency class whose sole admitting control is the pre-execution Authenticode check (`Valid` + `O=Microsoft Corporation`), plus the in-step runtime major ≥ 152 floor (security-plan.md §Dependency Security, third dependency class).

- `cargo audit` exits 0 and `cargo deny check advisories bans licenses sources` exits 0 over the committed `Cargo.lock`, recorded as run BEFORE the release build, with `git status` showing no `Cargo.lock` drift (per security-plan.md §Security Anti-Patterns → Universal; §Dependency Security)
- The release binary, the Tauri bundle metadata and the recorded final-pass artifacts (`<run_id>.md`, `runs.db` rows, journals) contain zero absolute host paths and zero internal seam-crate struct names (per security-plan.md §Error Handling, run-report artifact sanitization; §Security Anti-Patterns → Logging)

- No release-signing or SBOM step is added as a gate, and any `cargo-auditable` use stays additive and non-blocking (per security-plan.md §Dependency Security, supply-chain-integrity subsection)
