# tests extract

## Relevance
Relevant — the chunk's release gate, the harness-driven final SLO pass, and both open CARRYs (a shared-state test race; a flaky operator-local suite) all sit inside the tests domain.

## Constraints
- The supply-chain gate is a precondition of `cargo build --release`, not a follow-up: `cargo audit` + `cargo deny check` green and a committed, un-drifted `Cargo.lock` are required before a release build or merge (test-plan §11 Test Anti-Patterns → CI; restated as build-failure conditions in §9 and §10). §12 requires the **bare** `cargo audit` form — `--deny warnings` was measured to exit 1 by construction against the `deny.toml`-adjudicated allowed set. Toolchain ≥ 1.94.1 and `tauri` ≥ 2.10.3 ride the same gate (§9 Matrix builds → Toolchain; §10 build-failure conditions).
- Zero-flakiness is a hard bar: a test that flakes once is fixed at the cause — no `retries`, no serialization knob, no runner pin — and a **runner-dependent** result is explicitly in this class as a shared-state defect (§10 Zero-flakiness budget). This is the rule CARRY A and CARRY C are both governed by.
- §11 Test Anti-Patterns → Integration requires that no test rely on nextest's per-test process to isolate it from a **process-global, first-install-wins singleton**; the mandated remedy is a test binary of its own (one file per such test, so it holds under both runners), never serializing the file. CARRY A's `take_hook`/`set_hook` pair is that shape; whether the shipped `conductor-core/src/obs.rs` tests already share a guard or their own binary is research's question.
- §4 Unit Test Strategy makes `cargo test -p <crate>` (full, non-doc) a standing runner-portability gate beside `cargo nextest run` — only the shared-process runner can expose a per-test-process dependency, so CARRY A's remedy owes evidence under both runners.
- §3 Test Harness Contract requires the five-command surface to stay five, with `.sh`/`.ps1` at identical semantics — a property §3 (`5-command-discipline-wire`) requires to be asserted of the SCRIPTS *together with the invoking environment*, since a caller setting `$PSNativeCommandUseErrorActionPreference = $true` diverges the `.ps1` leg with zero script delta. The chunk's boundary ("no change to the 5-command harness discipline") matches this requirement.
- Live-Pulse legs — `run --live`, the feature-gated targets, `npm run a11y:driven`, and the `sr*` suites — are operator/local only and must never become CI gates (§9 Live-Pulse scenarios; §11 → CI). §9 further requires the `--live` auto-resolve leg's verdict be recorded as **conditional**: it is not run-stable even under the stretched bootstrap posture, which removes cause (a) only.
- Coverage stays gated at the Minimal thresholds (`--fail-under-lines 60`; branch ≥ 50 informational, function ≥ 70) and §11 → Quality forbids lowering the bar to pass a build (§10 Coverage thresholds).

## Patterns to follow
- The `--e2e` printed-verdict contract (§3 `run` → CI stage selectors): capture wdio output to `$RUNS_DIR/a11y-e2e.log`, read the exit from the **bare** command never through a pipe, then assert zero on the `Spec Files:` failed count (a term the line omits when nothing failed), a per-spec skip tally within the expected-skip SET, and the `[webview2 … windows]` driven-session banner. This is exactly the format detail the scope preserves from discharged CARRY B.
- The `status` read (§3 `status`, and §3 Status endpoint shape): target the **newest ENVELOPE line**, selected by the envelope-only `seed` key — never the file's last line, which is a `CheckRecord` on any run that graded checks. The envelope's eleven fields, including `latency_ms` and `slo_tier`, are the shape any recorded SLO pass is read out of.
- The committed-artifact gate precedent for `v2-21` (§1 Critical Path 6; §6 Coverage-matrix completeness gate): a crate-local `--test` target, CI-enforced, asserting **set equality** against the authoritative source plus byte-equality to the renderer with LF pinned by `.gitattributes` — and §1's own signal forbids a literal-count assertion. `v2-21`'s "exactly one entry per capability, ids unique, no P-NNN in an id position" is the same enumeration shape.
- The scoped mutation audit (§4 Mutation instrument; §9 Scoped mutation audit; §10 disposition rule): per-chunk against touched crates, workspace-root `-f` paths, `--test-tool=nextest`, gate on the tallies read out of `mutants.out/` (never the exit code, which carries no verdict in either direction), every named survivor killed or classified accepted-deliberate against a cited rule in the §12 roster SET.
- The `--live` composition (§3 `run` → `--live`): read the leg order from `live_leg_order` in `scripts/agent-run.{sh,ps1}` rather than a restated count, and freeze each leg's `logs/agent-latest.jsonl` to `runs/live-suite/{leg}.jsonl` because that sink truncates per invocation.

## Anti-patterns to avoid
- No retry, no runner pin, no in-test `sleep(N)` as a remedy for CARRY C's announcement variance — §11 → E2E states the ban's subject is synchronisation inside a test and closes with "nothing inside a test may sleep to synchronise"; §10 requires the fix at the cause. (The scope records the same carve-out being proposed and rejected at `2026-09-06-operator-gated-live-suite`.)
- Do not serialize CARRY A's two panic-hook tests via `--test-threads=1` or a profile knob — §11 → Integration names that as hiding the shared-state defect rather than removing it.
- Do not certify the release artifact with a manual smoke step or a human-reviewed screenshot, and do not promote any live-Pulse or `sr*` leg into the CI gate to make the release pass "recorded" (§11 → Universal; §11 → CI).

## Contract bindings
- **tests §3 Log format ↔ obs-plan §3** — §3 (`log-format-bind-with-obs`) declares this plan the source of truth for the JSONL journal, with the harness grepping the file, so a format break is a harness break. Two edges for this chunk: (a) CARRY A's remedy is inside `conductor-core/src/obs.rs`, and §3 requires the envelope/JSONL/self-obs line shapes stay untouched by a test-side fix; (b) the self-obs base fields include `service.version` (§3 "Self-obs stream is a distinct artifact"), so the open version-stamp question touches an obs-bound field — whether any committed golden or exact-assert pins that value is research's question.
- **tests §9 pipeline E2E row ↔ a11y** — the `a11y` job's step set is `agent-run.ps1 run --e2e` → the reused `journal_conformance` gate over `runs/a11y` → artifact upload, with the rule that the GATE step never carries `continue-on-error`. §3 also requires the `runs/a11y/<run_id>.jsonl` violation record stay outside the harness's non-recursive `"$RUNS_DIR"/*.jsonl` glob so `status` cannot read it as a scenario run.
- **CARRY C ↔ a11y** — the SR leg's graded record is the a11y pass artifact; tests owns its wiring to the zero-flake bar and its operator-local, never-CI, never-an-`agent-run`-verb status (§6 drivers-per-surface, desktop-webview). §1 Untestable zones requires browse-mode rows stay recorded findings — never passes and never a manual arm.
