## Patterns to follow
- **The existing `WebView2 session isolation (diagnostic)` step's shape** — two sub-probes inside ONE `continue-on-error` step, (a) SETS `WEBVIEW2_USER_DATA_FOLDER` + `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`, (b) CLEARS both first so it observes unmodified behaviour; whole handle lifetime confined to that step (per `architecture.md` §Occupied Resources — Environment variables).
- **Read runner env in the STEP SHELL (`$env:NAME`), never via `${{ env.* }}`** — arch records the measured mechanism: the expression context "holds only workflow/job/step declarations and never a runner-process variable," which yielded an empty base and a literal `\msedgedriver.exe` reaching the guard (run 34148079506, 2026-09-07) (per `architecture.md` §Occupied Resources — Environment variables, `EDGEWEBDRIVER` / `RUNNER_TEMP`).
- **Report presence/shape, not content** — the `Test-Path` boolean + handle-name idiom is arch's registered CI reporting form and is the pattern the scope's "a policy value that is itself a path is reported by presence/shape, not verbatim" inherits (per `architecture.md` §Occupied Resources — Environment variables).
- **Evidence-by-reference** — arch cites CI findings as dated, run-id-bearing refs under `conductor-0.N.0/chunks/{marker}/evidence/…` and re-states the numbers in the body; the recorded reading should be authored to be citable in that form (per `architecture.md` §Established Decisions [CI/CD]; §Occupied Resources).

## Anti-patterns to avoid
- **A diagnostic that can decide the gate, or a gate quietly made skippable.** Do not omit `continue-on-error: true` on a new probe, and do not add `if:` / `continue-on-error` to, remove it from, or reorder any existing step — the install gate's bare posture is recorded as deliberate (per `architecture.md` §Established Decisions [CI/CD]).
- **A second boundary widening smuggled in as a diagnostic.** No new non-loopback fetch, no port bind, no third-party binary pulled in-job; arch routes this class to "always a human's call … never mint a routine rule" (per `architecture.md` §Cross-cutting Patterns — Trust boundary; §Occupied Resources — Ports).
- **Emitting an absolute host path, a handle VALUE, or a path-valued registry datum verbatim** into the job log or the evidence artifact (per `architecture.md` §Occupied Resources — Environment variables; §Standard Contracts).
