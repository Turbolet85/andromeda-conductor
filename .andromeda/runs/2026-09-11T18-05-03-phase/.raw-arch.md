## Patterns to follow
- **Registration-basis pattern for external handles:** a new handle is registered by naming which of the three existing bases it falls under, and explicitly stating which bar does NOT apply — the shape both `RUNNER_TEMP` and the `WEBVIEW2_*` pair use (per architecture.md §Occupied Resources — Environment variables).
- **Host-path-free diagnostic output:** precondition/diagnostic prints name the HANDLE plus a boolean, never the value or a host path — the `EDGEWEBDRIVER` `Test-Path` precondition and the redacted `data_dir` are the two shipped instances. Scope's "`ModuleName` + `FileVersion` only, never `FileName`" is this rule at probe grain (per architecture.md §Occupied Resources — Environment variables · §Standard Contracts).
- **Fixed-program, fixed array-form argv, never shell-interpolated** — the Evergreen install step's `'/silent','/install'`, the `CONDUCTOR_MSEDGEDRIVER`/`CONDUCTOR_NVDA` spawns, and the validated-at-the-edge handle discipline (per architecture.md §Established Decisions [CI/CD] · §Occupied Resources — Environment variables).
- **Measured-claim discipline:** a body claim carries its site, date and scope ("as measured at CI run `34586959536`"), and a falsified hypothesis is RETIRED by name with its replacement status stated rather than quietly dropped — the shape used for the 152-runtime and policy/session retirements (per architecture.md §Established Decisions [CI/CD]).
- **Artifact split:** raw captures live under git-ignored `runs/`; only graded records are committed, kebab-case Markdown (per architecture.md §Occupied Resources — On-disk artifacts · §Conventions Naming patterns).

## Anti-patterns to avoid
- Duplicating the probe body inline in `ci.yml` or as a second script — arch registers ONE probe file at per-file grain in the directory tree, and a duplicate silently forks the dev-host control from the CI reading.
- Minting a `CONDUCTOR_*` name for a runner/WebView2 handle, or reading/setting an env var in `ci.yml` or the probe script without registering it with a basis (per architecture.md §Occupied Resources — Environment variables).
- Widening the boundary to get a reading — a new outbound fetch, a new bind, a new spawned program, or a probe step that can fail the job (per architecture.md §Cross-cutting Patterns — Trust boundary · §Established Decisions [CI/CD]).
