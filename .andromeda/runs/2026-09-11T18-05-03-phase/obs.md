## Relevance
**Partial** — the chunk mints no runtime telemetry (a GitHub Actions step is Not-instrumentable per obs-plan.md §1), but its committed reading, its job-log output, and the a11y job it edits all sit under obs's host-path, artifact-handling and agent-readable rules.

## Constraints
- A CI workflow step produces no runtime telemetry: obs-plan.md §1 (instrumentation-scope table, `cargo build / CI/CD pipeline` row) classes the GitHub Actions pipeline **Not-instrumentable** — build-time verification that does not run at runtime. A probe step therefore requires no span, no self-obs line, and no change to that classification (per obs-plan.md §1).
- No absolute host path may appear in any log line or artifact the chunk produces: obs-plan.md §11 (Logs) bans leaking absolute host paths or internal struct names, and obs-plan.md §9 (Log conformance check) requires the gate to FAIL on drive-letter `X:\`, `/home`, `/Users`, `%APPDATA%`, `~/.cargo`, `.rustup` in any field. The scope's own `ModuleName` + `FileVersion`-only / never-`FileName` rule is this ban restated for a Windows module enumeration; whether the shipped `scripts/webview2-cause-probe.ps1` already holds that line is research's question (per obs-plan.md §9, §11 Logs).
- The redaction layer does not reach a PowerShell capture: obs-plan.md §11 (PII Scrubbing) requires redaction at the processor stage in `conductor-core::redact` and carries a standing warning that its three application sites "bound the sites they name, never every channel" — proven by a Windows process/console surface that leaked a host path outside them. A probe reading Windows process state is categorically outside that layer, so its host-path discipline must be in the probe's own output shape (per obs-plan.md §11 PII Scrubbing).
- The a11y job's telemetry artifact must survive the edit: obs-plan.md §9 (Telemetry artifact handling) registers `runs/a11y/<run_id>.jsonl` as uploaded via `actions/upload-artifact@v4` with conformance asserted in-job under `CONDUCTOR_RUNS_DIR=runs/a11y`, and obs-plan.md §11 (CI) bans losing telemetry artifacts. Whether a probe capture written under `runs/` collides with that path is research's question (per obs-plan.md §9, §11 CI).
- The live-app window arm A targets is also a self-obs emission window: obs-plan.md §3 (Log file location) and §1 (desktop-webview row) require the Tauri backend sink `conductor-tauri.jsonl` to sit under `<runs_dir.parent()>/logs/`, the directory riding `CONDUCTOR_RUNS_DIR` — so any change to that handle in the isolation step moves both the sink and the §9 conformance target (per obs-plan.md §3 Log file location).
- Any reading an agent must consume has to be machine-parseable: the plan's agent-driven invariant (obs-plan.md header) and §11 (Universal / Logs) require every signal readable from a snapshot or pasted excerpt, with no unstructured stderr text — structured JSON-per-line or sanitized output with machine-parseable hints (per obs-plan.md §2 Agent-readable invariants, §11 Universal).
- The folded PREREQ gate run falls under obs's CI telemetry rules: obs-plan.md §9 (Pipeline integration, Unit tests row) requires `cargo-nextest` JSON output plus `logs/agent-latest.jsonl` as uploaded artifacts, and §10 requires the zero-unlogged-panics invariant to hold over them (per obs-plan.md §9, §10).

## Patterns to follow
- **The fmt-gate disposition (obs-plan.md §9, Lint/typecheck row):** a build-time diagnostic whose output is agent-readable *from the job log* and deliberately **not** written into any telemetry artifact, stated with its reason — the lines carry absolute host paths that §9's own conformance check rejects. This is the closest existing template for where a probe's raw reading belongs.
- **Additive classification of a new build-time step (obs-plan.md §1, CI/CD row):** a new CI gate joins the build-time verification enumeration without changing the Not-instrumentable classification. A diagnose-only probe step should land the same way.
- **Job-produced record → §9 artifact row (obs-plan.md §9 artifact table, a11y row):** if the reading is to be retrieved from CI rather than read from the log, the established shape is `actions/upload-artifact@v4` with the record's conformance asserted in-job.
- **Runs-dir-relative sink resolution (obs-plan.md §3 Log file location):** the file NAME is fixed and the DIRECTORY rides `CONDUCTOR_RUNS_DIR`, with per-suite a11y landing sites recorded — the pattern any new file emitted inside the a11y job should respect rather than hardcoding a project-root path.

## Anti-patterns to avoid
- Never route a line carrying an absolute host path into a telemetry artifact or committed record — obs-plan.md §11 (Logs) and §9 (Log conformance check); the §9 fmt-diff precedent keeps such lines in the job log alone.
- Never assume `conductor-core::redact` covers this channel — obs-plan.md §11 (PII Scrubbing) states the enumeration bounds only the sites it names; a PowerShell probe is outside all three application sites.
- Never add an OTel SDK, exporter, W3C trace context, or a span name outside the bounded set to "instrument" a CI diagnostic — obs-plan.md §11 (Telemetry Strategy, Spans/Traces, Universal); self-obs never exports OTLP on any surface.

## Contract bindings
- **obs ↔ a11y:** obs-plan.md §9 (artifact table) owns the a11y job's violation record `runs/a11y/<run_id>.jsonl` and its in-job conformance under `CONDUCTOR_RUNS_DIR=runs/a11y`; the isolation step this chunk edits lives in that job.
- **obs ↔ tests harness:** obs-plan.md §9 (Pipeline integration, Unit tests) + §10 bind the folded PREREQ `cargo nextest run --workspace --profile ci` to nextest JSON + `logs/agent-latest.jsonl` and the zero-unlogged-panics gate.
- **obs ↔ security:** obs-plan.md §11 (PII Scrubbing / Project-specific bans) cites security-plan's host-path and sidecar-spawn bans; the 2026-09-02 → 2026-09-04 host-path channel moved on both sides together, so a host-path finding in this chunk's probe surface is a two-master concern.

## Acceptance criteria contributions
- (obs) No absolute host path appears in the committed reading or in any job-log line the chunk adds — no drive-letter `X:\`, `/home`, `/Users`, `%APPDATA%`, `~/.cargo`, `.rustup`; the module enumeration reports `ModuleName` + `FileVersion` and never `FileName` (per obs-plan.md §9 Log conformance check / §11 Logs).
- (obs) The chunk introduces no span, no metric instrument, no new self-obs log field, and no span name outside the bounded set; the CI/CD pipeline row's Not-instrumentable classification is unchanged (per obs-plan.md §1 / §11 Spans / §5).
- (obs) The a11y job still produces and uploads `runs/a11y/<run_id>.jsonl` with its in-job conformance assertion under `CONDUCTOR_RUNS_DIR=runs/a11y` intact, and no probe output displaces or overwrites it (per obs-plan.md §9 Telemetry artifact handling / §11 CI).
- (obs) The re-run PREREQ rust gate yields nextest JSON + `logs/agent-latest.jsonl` with zero unstructured panic lines (`^thread.*panicked`) in either that file or stderr (per obs-plan.md §9 Zero-unlogged-panics gate / §10).
