## Constraints
- The whole modify-set must stay inside the already-registered workspace member `conductor-report` (the journal/report/`runs.db` storage seam); architecture.md §Occupied Resources — Crate names locks the nine-member roster and §Infrastructure Patterns — Directory structure fixes that crate's role, so no new member, module seam, port, `CONDUCTOR_*` handle or on-disk artifact may be landed by this chunk.
- architecture.md §Established Decisions [Accepted Capability Set] locks the shape: an id space the project outgrows must be expressed as DATA or as a general predicate, never as a compile-time enumeration — it is the decision that retired the baked `001..=060` bound for exactly this failure mode. A replacement predicate that enumerates known version prefixes reinstates the class.
- The same anchor requires that a two-source integrity comparison stay two-source (`check_sut_drift` is deliberately not sourced from the artifact it checks). The required-id set must therefore keep being derived from `requirements.md` independently of `verification-matrix.json`, or the set-equality arm collapses into a self-check.
- architecture.md §Conventions — Naming patterns pins `P-NNN` as the Pulse capability id space (shape-checked by garde's `pid_format`, membership-checked against the SUT capability manifest per §Established Decisions [Accepted Capability Set]). The generalised predicate must keep the version id space and the P-ID space disjoint; the `no_pulse_p_id_occupies_an_id_position` arm is the in-repo expression of that separation.
- architecture.md §Established Decisions [CI/CD] requires `cargo fmt --all --check` as an unconditional early step of the `rust` job (no `continue-on-error`, no `if:`), so any edit to the gate file must be rustfmt-clean under the workspace `edition = "2024"` config (§Infrastructure Patterns — Directory structure).
- architecture.md §Infrastructure Patterns — Build system pins `cargo nextest` driven through a **zero-retry** `ci` profile — retries must not mask a flake, which is the determinism invariant of §Design Philosophy. A repaired gate must be deterministically green, not retry-green.
- Any dependency delta (none expected per scope) would fall under §Infrastructure Patterns — Build system's supply-chain gates (`cargo deny check advisories bans licenses sources` + `cargo audit` exit 0, `Cargo.lock` committed). §Established Decisions [Module Boundaries] additionally bans `--all-targets` as the standalone per-member build form, because it re-unifies dev-dependencies and masks a feature declared only in `[dev-dependencies]` — relevant if the repair touches `conductor-report`'s manifest.

## Patterns to follow
- **Shape-then-membership two-layer validation** (architecture.md §Established Decisions [Accepted Capability Set]): garde asserts the `P-NNN` SHAPE while a separate load-path check asserts MEMBERSHIP against data. The same split is the arch-native shape for an id-space predicate: a general lexical form (`v{N}-{NN}`) decided structurally, with any set-level claim kept as a separate assertion.
- **One shared basis so two consumers cannot diverge** (architecture.md §Occupied Resources — `contracts/pulse-load-envelope.toml`): `phase_rate_exceeds` → `phase_breach` → {static gate, per-run caption} is a single call chain so the gate and its companion cannot mean different things. Applies here: the anti-vacuity assertion and the set-equality arm should consult ONE predicate function, not two spellings of it. Whether the file already does so is research's question.
- **Reuse the one assertion rather than copy it** (architecture.md §Occupied Resources — On-disk artifacts, the `runs/a11y` record asserted by the same `journal_conformance` the run journal uses — "never a second copy of the schema").
- **Exact-set equality in both directions for a ledger-shaped gate** (architecture.md §Established Decisions [Accepted Capability Set], the `UNBACKED_AUTO` pin; §Occupied Resources — `pulse-load-envelope.toml`, the `[[exempt]]` ledger): a gate holds its ledger so it can only shrink under compulsion, rather than tolerating drift.
- **Gate-correctness controls over committed text** (architecture.md §Infrastructure Patterns — Build system): the sole `.gitattributes` rule exists because a gate compares a committed Markdown artifact and the comparison only holds where checkout preserves LF. That rule is recorded as scoped to `coverage-matrix.md`; whether a line-parsing gate over `requirements.md` is exposed to the same checkout sensitivity on this Windows-runner-only CI is research's question.

## Anti-patterns to avoid
- Baking a finite set of version prefixes (or any compile-time enumeration of an id space that grows with the project) — architecture.md §Established Decisions [Accepted Capability Set] retired exactly that bound.
- Relaxing the predicate until the arm cannot fail, or sourcing the required id set from the artifact being checked — architecture.md §Established Decisions [Accepted Capability Set] requires the comparison stay a genuine two-source one.
- Landing a new workspace member, `CONDUCTOR_*` env handle, on-disk artifact or dependency to repair a single test file — architecture.md §Occupied Resources enumerates each of those classes as registered resources.

## Contract bindings
- **arch ↔ tests:** architecture.md §Infrastructure Patterns — Build system pins the runner (`cargo nextest`, zero-retry `ci` profile in `.config/nextest.toml`) plus `cargo test --doc` for doctests nextest skips; exact tool/dep versions are deferred to test-plan §4, so the tests specialist owns the harness form and arch owns the profile/determinism constraint.
- **arch ↔ CI:** architecture.md §Established Decisions [CI/CD] scopes the workspace gate to the `rust` job (fmt → build → nextest → clippy). The separate `a11y` job's RED is attributed there to an established, unrelated cause (elevation suppressing the WebView2 endpoint) and owned by route entry `v3-02` — so "workspace gate green" for this chunk means the `rust` job's nextest leg, not a green `a11y` job.
- **arch ↔ security:** any package-set change routes to §Infrastructure Patterns — Build system's deny/audit gates and the committed-lockfile rule; with no dependency delta expected, this binding should stay inert.

## Acceptance criteria contributions
- The entire change lands inside the registered workspace member `conductor-report`, adding no new workspace member, `CONDUCTOR_*` env handle, port, on-disk artifact or dependency (per architecture.md §Occupied Resources).
- The replacement id-space predicate is not a compile-time enumeration of known version prefixes: a future `v{N}-{NN}` space is admitted with no edit to this file (per architecture.md §Established Decisions [Accepted Capability Set]).
- `P-NNN` stays excluded from the version id space and the required-id set stays derived from `requirements.md` independently of `verification-matrix.json`, so the set-equality arm remains a two-source comparison (per architecture.md §Conventions — Naming patterns + §Established Decisions [Accepted Capability Set]).
- `cargo fmt --all --check` exits 0 and `cargo nextest run --workspace --profile ci` is green on a zero-retry profile — green on the first run, never retry-green (per architecture.md §Established Decisions [CI/CD] + §Infrastructure Patterns — Build system).
