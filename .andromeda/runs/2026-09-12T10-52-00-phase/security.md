# security extract

## Relevance
Partial — the chunk adds no input boundary, spawn, secret, network or IPC surface; security touches it only through the dependency/lock gate, gate-output hygiene, and the not-operator-steerable fixed-path read discipline.

## Constraints
- **No-dependency-delta is the expected state, and it is the gate.** If P4's predicate choice pulls any new crate (a regex engine is the obvious temptation), security-plan §Dependency Security requires it land under a **verified**-green `cargo deny check advisories bans licenses sources` over the NEW `Cargo.lock`, with any new license taking the documented `deny.toml` accepted-exception mechanism (`deny.toml` is the authority, not the plan's reconciliation counts). `Cargo.lock` must stay committed and un-drifted (per security-plan §Security Anti-Patterns → Universal).
- **The workspace merge/release gate requires `cargo-audit` (+ recommended `cargo-deny`) green** — the Minimal-tier residual-risk control (per security-plan §Security Anti-Patterns → Universal). The standing advisory-DB deferral was closed 2026-09-05, so a red audit at this HEAD would be new information; whether both run green at this chunk's HEAD is research's question.
- **If the audit does go red, the local-first adjudication is mandatory:** §Dependency Security requires a `git status --porcelain` check on the host `advisory-db` checkout to PRECEDE classifying any parse/fetch failure as external — and forbids a `deny.toml` ignore, a CI edit, or a silent accept as the remedy (per security-plan §Dependency Security, two-external-decay-faults block).
- **The gate's inputs are committed files read at fixed repo paths, and that read must stay not-operator-steerable.** security-plan §Input Validation (committed SUT-facing manifests row) requires such readers resolve a fixed path with deliberately **no `CONDUCTOR_*` override handle**. Generalising the id-space predicate must not introduce an env-configurable prefix, version list or directory override; doing so would mint a new external-input boundary carrying the `std::fs::canonicalize` + bounds duty of §Input Validation's env-path-handles row and §Security Anti-Patterns → Input.
- **Never defaulted, never silently widened.** For committed artifacts read at a fixed path, §Input Validation requires absent/malformed input be a hard fault, never defaulted and never silently widened. Applied to this chunk: the anti-vacuity arm must keep failing an empty required set, and the replacement predicate must not widen the accepted set to admit non-capability content — a gate that passes by matching nothing is the false-pass class the plan's never-downgrade discipline exists to prevent (§Security Anti-Patterns → Universal, by analogy — that ban's own subject is the preflight, not this gate).
- **Gate output must be host-path-free and struct-name-free.** §Security Anti-Patterns → Logging bans absolute host paths and internal seam-crate struct names in operator-facing output and committed records; the per-READER precedent recorded at §Input Validation (env-path-handles row) bounds a test gate's failure origin to the handle and the file's own name, never a resolved path. This binds the re-worded `:153` / `:208` messages and any new message that names a scanned version directory. Whether the current messages already render host-path-free origins is research's question.
- **The `:208` id-space separation contract is load-bearing beyond hygiene.** §Input Validation mandates `P-NNN` shape validation per id for `contracts/pulse-capabilities.toml`; the generalised predicate must keep rejecting the Pulse P-ID space so the two id spaces stay visibly distinct rather than converging on one permissive pattern.

## Patterns to follow
- The sibling test-binary reader in the SAME crate: `conductor-report --test coverage_gate` loads a committed manifest through a bounds-checking loader and resolves the conventional repo path from `CARGO_MANIFEST_DIR` (a cargo test binary's CWD is its own package root), introducing no `CONDUCTOR_*` handle and reading nothing operator-supplied (per security-plan §Input Validation, committed-manifests row). Whether `matrix_ledger_gate.rs` resolves its version dirs by the same mechanism is research's question; the not-operator-steerable property is what must hold however it resolves.
- The host-path-free failure-origin pattern established for the other `tests/`-tier reader (failure names the handle + the file's own name, never a resolved path) — per security-plan §Input Validation (env-path-handles row) and §Security Anti-Patterns → Input.
- The shape-predicate discipline the plan already mandates for committed manifests — closed/validated id shape per entry, no duplicates, non-empty sets, absent-or-malformed a hard fault (per security-plan §Input Validation) — is the model for a generalised `v{N}-{NN}` predicate: a stated shape, not an absence of filtering.
- The `deny.toml` justified-exception mechanism, if any advisory or license surfaces from an unexpected dependency delta (per security-plan §Dependency Security, Accepted exceptions).

## Anti-patterns to avoid
- NEVER let `Cargo.lock` drift or go uncommitted — it makes the audit non-deterministic (per security-plan §Security Anti-Patterns → Universal). State the no-delta basis as the package set, per the standing rule the scope already cites, not as lockfile byte-identity.
- NEVER surface an absolute host path (e.g. `path.display()` of a scanned version directory) or an internal seam-crate struct name through the gate's assertion or failure output (per security-plan §Security Anti-Patterns → Logging; §Error Handling).
- NEVER add a `CONDUCTOR_*` (or any env) handle to steer the id space or the directory scan without discharging the canonicalize + bounds duty at the reader (per security-plan §Security Anti-Patterns → Input); the fixed-path, no-override property (§Input Validation) is the simpler compliance and the one the plan already records for this crate's committed-file readers.

## Contract bindings
- **CI security gate ↔ tests §CI Integration:** the `cargo audit` / `cargo deny` steps are jobs in the same single workflow whose `cargo nextest run --workspace --profile ci` is this chunk's headline gate (per security-plan §Dependency Security, CI integration). This chunk must leave those security steps unedited — a CI edit is explicitly barred as a remedy for a red audit (§Dependency Security).
- No obs binding (the chunk emits no log/telemetry), no design/a11y binding (no operator-visible surface).
