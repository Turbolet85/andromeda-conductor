# arch extract

## Relevance
Partial — arch owns three of this chunk's four items (the `conductor-emit → conductor-core` dependency edge, the eleven-key envelope array as a Standard Contract shape, and workspace placement of the new shared fixture); the mutation roster itself is tests' domain, with arch contributing pinned expected values for two of the five unowned survivors.

## Constraints
- **A `Cargo.toml` dependency edge IS the architecture** — dropping `conductor-emit → conductor-core` is a seam-graph change, not hygiene, and carries the same evidence burden as any seam change (per architecture.md §Established Decisions [Module Boundaries], §Design Philosophy "Compiler-enforced module seams").
- **The standalone per-seam build property has a pinned measurement form and is NOT gate-enforced.** Each member is checked on its OWN targets (`--lib` for the seven library crates, `--bins` for the two bins); `--all-targets` is deliberately banned because it re-unifies dev-dependencies — the exact masking the sweep exists to catch. No CI job builds a member standalone, so the property is measured-at-a-chunk and a chunk that edits a member's `[dependencies]` must re-measure rather than inherit the 2026-09-07 sweep (per architecture.md §Established Decisions [Module Boundaries]).
- **No new workspace member and no new cross-seam edge.** The nine crate names are the locked roster and `conductor-core` is registered as "the runtime-agnostic engine library every other crate depends on" — the only home for a shared const that adds no edge. A const placement that would make `conductor-report` and `conductor-verify` depend on each other is forbidden (per architecture.md §Occupied Resources — Crate names). Whether both clone sites already carry the `conductor-core` edge is research's question; arch requires only that the landing add none.
- **The eleven-key array is a Standard Contract, not an internal literal.** §Standard Contracts requires the run-report envelope's eleven-field shape stay byte-unchanged and pins it as the ONE shape shared by the Markdown report, the per-run JSONL journal and the `runs` table; single-sourcing may move where the key list is written, never what it contains (per architecture.md §Standard Contracts — Run report envelope).
- **Envelope conformance asserts key PRESENCE, never key exclusivity** — obs' extension point admits extra resource tags (the `runs/a11y` record measures 13 keys locally / 15 under CI against the same eleven-field base). A collapse onto one const must not convert a presence assertion into an exclusivity one (per architecture.md §Occupied Resources — On-disk artifacts, `runs/a11y/&lt;run_id&gt;.jsonl`).
- **Killing assertions must sit on the correct side of the verdict/error wall:** `anyhow` only at `conductor-cli` / `#[tauri::command]` edges, typed `thiserror` enums inside seam crates, verification outcomes returned as VALUES with `Result::Err` reserved for harness faults (per architecture.md §Conventions — Error handling, §Established Decisions [Error Handling]). This governs the `cleanup.rs` (cli edge, `anyhow::Result&lt;ExitCode&gt;`) and `client.rs` / `extract.rs` / `manifest.rs` (verify seam) kills alike.
- **Two of the five unowned survivors have arch-pinned expected values.** `ContractManifest::default_path` must resolve the pinned MCP contract manifest under `contracts/` through `resolve_under`, with `CONDUCTOR_CONTRACT_MANIFEST` as its only override handle (§Occupied Resources — On-disk artifacts + Environment variables); `cleanup` is registered as the SOLE caller of `RunsDb::delete_run` — three literal `DELETE … WHERE run_id = ?1` statements over `runs` / `run_check` / `run_envelope` in one transaction, idempotent (§Established Decisions [ORM]). An idempotent teardown returning a default success code is exactly the shape whose kill needs an observable-effect assertion rather than an exit-code one.

## Patterns to follow
- **Single-source-by-construction, already twice established in this workspace.** `journal_conformance` asserts the a11y violation record under `CONDUCTOR_RUNS_DIR=runs/a11y` — "the same test the run journal uses — never a second copy of the schema" (§Occupied Resources — On-disk artifacts); and `phase_rate_exceeds → phase_breach → {check_load_envelope, LoadEnvelope::classify}` makes the static gate and the per-run caption unable to diverge "BY CONSTRUCTION" through a single call chain (§Occupied Resources — `contracts/pulse-load-envelope.toml`). Both the envelope-array collapse and the fixture-family collapse are this shape.
- **Which dependency SECTION a dep is declared in is load-bearing, both directions.** blake3 landed as a NORMAL (non-dev) dep of `conductor-emit` because "a test-scoped dep cannot back a shipped signature" (§Stack — Hashing / digest); the converse repair moved tokio's `time` out of `[dev-dependencies]` into `[dependencies]` for `conductor-verify` (§Established Decisions [Module Boundaries]). So the emit dep question is "which section, if any," not only "keep or drop" — and a new `tests/common/mod.rs` is dev-dependency territory, where the unification masking lives.
- **A crate-seam placement is decided by co-location with the content it derives from**, and is ratified explicitly rather than inferred — the fingerprint primitive was placed in `conductor-emit` on that reasoning (§Infrastructure Patterns — directory tree, `conductor-emit` comment). "Beside the schema it describes" is the same rule applied to the envelope const.
- **A test fixture must never write into the repository on an ordinary run.** `CONDUCTOR_E2E_SEED_DIR` unset makes the seeding test a no-op precisely "so an ordinary `cargo nextest` / `cargo test` run never writes into the repository" (§Occupied Resources — Environment variables). A shared `conductor-emit/tests/common/mod.rs` inherits that discipline; gate output belongs under gitignored `target/` (§Infrastructure Patterns — Build system / Deployment model).
- **The MCP write path's declined arm is stub-territory by construction.** §Established Decisions [Read-Back Dependency Posture] records that `mark_incident_resolved`'s `DeclinedStale` arm is unreachable through MCP (Pulse's `updated_unix_nano &lt;= ?2` predicate fails only against a future-stamped row) and is "stub-proven and permanently so" — so a killing vehicle for `ReadbackClient::resolve_incident` rides the stub sidecar, not a live leg. This bears directly on the chunk's `[inferred]` reachability premise.

## Anti-patterns to avoid
- `--all-targets` as the standalone per-member check form — explicitly banned in the sweep because it re-unifies dev-dependencies and hides the defect the sweep exists to find (§Established Decisions [Module Boundaries]).
- A second copy of a schema or contract shape — named as a ban at the artifact that already collapsed one ("never a second copy of the schema", §Occupied Resources — On-disk artifacts). Collapsing two literal arrays into a const that is then re-literalized anywhere reintroduces exactly this.
- Minting a new workspace crate or a new `CONDUCTOR_*` handle to carry a shared fixture or a shared const. The crate roster is locked (§Occupied Resources — Crate names) and the namespace's own precedent is fixed-path resolution with "deliberately NO `CONDUCTOR_*` override handle" (the capability-manifest / load-envelope / run-contract bullets).

## Contract bindings
- **§Standard Contracts envelope ↔ tests harness** — `conductor-run`'s `journal_conformance` is the registered conformance vehicle for the eleven-field shape; any single-sourced key const must remain compatible with it rather than becoming a third assertion site.
- **§Standard Contracts envelope ↔ obs** — obs-plan §3's extension point is what makes the record 13/15 keys wide; the presence-not-exclusivity property is obs' to state and arch's to preserve.
- **[Module Boundaries] standalone-build property ↔ tests** — the per-crate build form and the per-unit `cargo mutants` firing form are both crate-scoped gates; tests owns the mutation gate's tallies-not-exit-code rule, arch owns the `--lib`/`--bins`/no-`--all-targets` form.
- **Dependency-edge change ↔ security (§Dependency Security)** — `deny.toml`'s first non-Tauri license exception (`BSD-2-Clause` for `arrayref`) entered via `conductor-emit`→`blake3` (§Infrastructure Patterns — Build system). If dropping the `conductor-core` edge moves the resolved tree, re-adjudicating the exception ledger is security's call, not arch's; whether it moves the tree at all is research's question.
- **Verdict/error wall ↔ tests** — a kill must assert a typed value or a typed error variant, not a panic; the wall is arch's rule, the assertion form is tests'.

## Acceptance criteria contributions
- (arch) All touched code stays inside the existing nine workspace members, with no new crate, no new `CONDUCTOR_*` env handle, and no new cross-seam dependency edge introduced by the const's placement (per architecture.md §Occupied Resources — Crate names / Environment variables).
- (arch) If the `conductor-emit → conductor-core` edge is dropped, the standalone per-seam property is RE-MEASURED in its pinned form — each affected member on its own targets (`cargo check -p conductor-emit --lib`), `--all-targets` not used — exit 0; the 2026-09-07 sweep may not be inherited, since the property is measured-at-a-chunk and not gate-enforced (per architecture.md §Established Decisions [Module Boundaries]).
- (arch) The single-sourced eleven-key const leaves the run-report envelope's eleven-field shape byte-unchanged, and both former clone sites continue to assert key PRESENCE rather than key exclusivity (per architecture.md §Standard Contracts — Run report envelope).
- (arch) Every killing assertion respects the verdict/error wall — `anyhow` confined to the `conductor-cli` edge, typed errors/values inside `conductor-verify` — and no kill is obtained by asserting a panic (per architecture.md §Conventions — Error handling).
