## Patterns to follow
- **Gate on the printed/structured verdict, not the exit code.** a11y-plan §11 CI records that an exit code alone cannot enforce a gate (a skipped-green run and a real pass are indistinguishable), so the harness declares `CONDUCTOR_A11Y_STRICT` and asserts the runner's printed verdict. This is the same discipline the chunk's mutation gates adopt (tallies, not exit code) — the a11y precedent is the in-repo model for it (per a11y-plan §11 CI).
- **Schema reproduced verbatim from one owner, consumers narrow it.** a11y §3 states the envelope as a verbatim reproduction of obs §6 with "a11y narrows; obs fixed the schema" — the same single-owner/verbatim-consumer shape the chunk's single-sourcing should take (per a11y-plan §3 Structured violation JSON schema).
- **Amend-the-reproduction cascade.** When the obs envelope gained `read_back_observed_at`, a11y's two reproductions were amended in lockstep. Any change to the key list's membership in this chunk owes the same cascade to a11y-plan §3's two reproduction sites (per a11y-plan §3; amendment `2026-06-16-emission-journal-writer`).
- **Shared test-harness reuse over parallel stacks.** a11y-plan §3 / §11 CI mandate reuse of the tests' one driver and the tests' 5-command harness surface rather than standing up a second stack — the same "one shared `common/mod.rs`, modelled on the existing one" instinct this chunk applies to `conductor-emit/tests/` (per a11y-plan §3 A11y testing tool pick, §11 CI).
