## Constraints
- The eleven-key envelope is a **binding contract obs DERIVES, never re-authors** (test-plan §3 owns the format) — a single-sourced const must carry exactly the eleven keys in the §3 order (`journal_emitted_at`, `read_back_observed_at`, `run_id`, `seed`, `scenario`, `p_ids`, `verdict`, `state`, `latency_ms`, `slo_tier`, `fingerprints`), and "required" means KEY PRESENCE, not non-null — five measurement fields are `Option` and serialize as JSON `null` (per obs-plan §6 Required fields, §3 Log format JSON schema).
- The consuming gate must assert presence, **never key exclusivity**: `conductor-run`'s `journal_conformance` asserts presence + closed sets + host-path freedom only, which is what lets one gate serve both the scenario record (eleven keys) and the a11y violation record (13 local / 15 CI keys). A single-sourced const hardened into an exact-set check would break that (per obs-plan §3 Log format JSON schema — extension-point paragraph).
- The run-teardown write (`RunsDb::delete_run`, sole caller the `conductor cleanup <run_id>` verb) is required to mint **NO span and NO boundary log** — deliberately off the must-trace paths, with §11's bounded span-name set held at `db.insert_run` with no `db.*` widening; the operator-facing signal is the CLI's printed row-count line (per obs-plan §4 Auto-instrumentation per surface — conductor-report row, §6 Boundary-call wrappers — DB DELETE).
- `conductor-cli` is specified as raising no spans of its own (no `tracing` dependency, no `tracing::` call site); a CLI-side boundary log would first require adding that dependency edge, which §4 defers to a later entry. A `cleanup` kill assertion must therefore not be built on a CLI-emitted log line (per obs-plan §4 cli row, §6 per-module log levels — conductor-cli row).
- Any span attribute must be a name in `conductor-core::redact::ALLOWLISTED_FIELDS` or the processor stage drops it — which is why `resolve_incident`'s incident id and the read-back key-set/shape witnesses ride the allowlisted `message` field rather than dedicated attributes (per obs-plan §4 Known-residual Required span attributes, §6 Boundary-call wrappers).
- §11's bounded span-name set is closed: `scenario.run`, `timeline.execute*`, `emit.batch`, `emit.logs_batch`, `verify.readback*`, `report.generate`, `db.insert_run`, `fault.*`, `tauri.command.*`. Fixture consolidation, dep removal, and kill work must add or rename no span (per obs-plan §11 Spans / Traces).
- `RUST_LOG` must not be set for a run that also executes the test suite — the environment reaches the runner's child processes — and a bare per-target directive REPLACES the default rather than adding to it (`info,{crate}=debug` is the only valid additive form). This applies directly to repeated `cargo mutants` / nextest re-runs (per obs-plan §6 per-module log levels).

- Emission-egress witness pattern: `emit.batch` logs batch index, emission count, result status and the wire-shape witness (span count, skippable-span count, ordered event/attribute KEY NAMES, never values) at `debug` inside the existing `#[instrument]` span, on the allowlisted `message` field (per obs-plan §6 Boundary-call wrappers). A shared `conductor-emit/tests/common/mod.rs` must preserve whatever any existing clone asserts about this surface.
- Boundary-call read convention as the model for "witness without a new span": a rusqlite READ logs an `info!` with `run_id` + outcome on `message` inside the caller's span and mints no `db.*` span (per obs-plan §6 Boundary-call wrappers — DB READ).
- No-SDK-for-self-obs is a BEHAVIORAL invariant; `opentelemetry-proto` in `conductor-emit` is the PRODUCT, and the `default-features = false` trim ships at the WORKSPACE entry (a member cannot disable defaults on an inherited dep) (per obs-plan §3 OTel SDK init). Any `conductor-emit/Cargo.toml` edit must leave both intact.

## Anti-patterns to avoid
- NEVER leak absolute host paths or internal struct names in logs / run-report / runs.db — relevant to `ContractManifest::default_path`: a killing assertion must not route a host path into a log line or committed artifact, and the redaction anchor is absolute host-FILE paths, not `::`-token redaction (per obs-plan §11 Logs, §11 PII Scrubbing).
- NEVER log in a hot path at `info`, and NEVER introduce an OTel SDK/exporter/`traceparent` for self-observation — a fixture-sharing refactor in `conductor-emit` must not promote the `debug` wire-shape witness or reach for SDK-level instrumentation to make a mutant observable (per obs-plan §11 Telemetry Strategy, §11 Logs, §11 Spans / Traces).
- NEVER widen the bounded span-name set with a `db.*` wildcard or a new name minted purely to give a mutant something to assert on (per obs-plan §11 Spans / Traces, §4 conductor-report row).

## Contract bindings
- **obs ↔ tests (harness contract):** test-plan §3 OWNS the JSONL envelope format; obs-plan §3/§6 reproduce it. Single-sourcing the eleven-key array is a two-sided surface — the const's content is the tests-owned schema, and obs's §6 Required-fields list is the derived reproduction (per obs-plan §3 Log format JSON schema, §6 Required fields). If the const's home or key list changes shape, the bind moves on both sides.
- **obs ↔ a11y:** the a11y CI gate's violation record (`runs/a11y/<run_id>.jsonl`) carries the eleven envelope keys PLUS `service.name` (`conductor-ui`) + `deployment.environment`; the shared const must stay compatible with that superset (per obs-plan §3 extension-point paragraph, §9 Telemetry artifact handling).
- **obs ↔ security:** redaction / no-host-path is single-owned in `conductor-core::redact`; `conductor-emit` losing its `conductor-core` dependency must not be read as licence to duplicate or bypass an allowlist/redaction path — whether `conductor-emit` reaches `redact` at all today is research's question (per obs-plan §11 PII Scrubbing).
- **obs ↔ Tauri surface (re-attempt work):** `commands.rs:273` `start_run` is one of the 8/8 handlers required to carry a MANUAL `tracing::info_span!("tauri.command.<name>").entered()` guard — the `#[tracing::instrument]` attribute does not stack with `#[tauri::command]`. A kill re-attempt must not disturb that guard (per obs-plan §4 desktop-webview row).

- (obs) The single-sourced envelope key list enumerates exactly the eleven §3 fields and is consumed as a KEY-PRESENCE assertion, never an exclusive key-set assertion (per obs-plan §6 Required fields + §3 Log format JSON schema).
- (obs) After the `cleanup` survivor is killed, the teardown path still mints no span and no boundary log, and §11's bounded span-name set is unchanged — no `db.*` widening, no new `tracing` call site added to `conductor-cli` (per obs-plan §4 conductor-report row + §6 Boundary-call wrappers — DB DELETE).
- (obs) Any assertion added on `resolve_incident` / `observe` reads only allowlisted carriers — the bounded `verify.readback.call_tool` / `verify.readback.observe` span names and the `mcp_tool` / `count` / `message` fields; no new non-allowlisted span attribute is introduced (per obs-plan §4 Known-residual Required span attributes + §6 Boundary-call wrappers).
- (obs) Mutation and nextest re-runs are executed with `RUST_LOG` unset (or, if a target level is genuinely needed, in the additive `info,{crate}=debug` form only) (per obs-plan §6 per-module log levels).
