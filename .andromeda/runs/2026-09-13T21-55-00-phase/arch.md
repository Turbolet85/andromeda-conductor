## Constraints
- **A fifth `contracts/` artifact is an occupied resource that must be registered individually.** architecture.md §Occupied Resources → On-disk artifacts enumerates each pinned manifest as its own bullet (`contracts/mcp-contract.toml` · `pulse-capabilities.toml` · `pulse-load-envelope.toml` · `pulse-run-contract.toml`), and §Infrastructure Patterns → Directory structure carries a `contracts/` comment naming FOUR manifests. If this chunk lands the artifact there, both sites require an amendment at wrap; whether the artifact ships under `contracts/` at all is the scope's `[inferred]` P4 decision (per architecture.md §Occupied Resources, §Infrastructure Patterns).
- **No new `CONDUCTOR_*` handle for the artifact's path.** §Occupied Resources states each of the three SUT-facing manifests resolves from a fixed `<Type>::default_path()` through `resolve_under` with *deliberately* NO `CONDUCTOR_*` override (only the MCP contract manifest carries `CONDUCTOR_CONTRACT_MANIFEST`). A path handle for a fifth artifact would contradict that precedent (per architecture.md §Occupied Resources — Environment variables).
- **If a Rust reader ships, a malformed/absent artifact is a harness fault, never a verdict.** §Established Decisions [Accepted Capability Set] requires runtime-read contract data be bounds-checked at load and that a malformed/absent/unparseable manifest be a `CoreError` (`Result::Err`) carrying a named reason — never `Blocked`, never a silent widening. Whether this chunk ships any reader at all is the scope's open form/location question (per architecture.md §Established Decisions [Accepted Capability Set], [Validation Library]).
- **The stated hard-grade predicate must be expressible as a typed VALUE.** §Cross-cutting Patterns — Verdict/error wall and §Established Decisions [Error Handling] reserve `Result::Err` for harness faults; a grade is `Verdict {Pass, Fail, CalibrationRegion}` → `ReportState`. A delegated *timing* claim is a deterministic claim under §Probabilistic-Assertion Policy, so hard pass/fail is the licensed disposition — model-interpretive routing to CalibrationRegion is not (per architecture.md §Cross-cutting Patterns, §Probabilistic-Assertion Policy).
- **The bound must not be restated in the journal-relative SLO vocabulary.** §Established Decisions [Timing-Tolerance Model] defines latency as `read_back_observed_at − journal_emitted_at` with tier deadlines (`<5s`/`<20s`/`<90s`) and an optional per-check `budget_ms`/`effective_deadline_ms(tier)`. That model owns Conductor's own emission-window grading; the scope's second qualifier (a value PULSE produces) requires the contract state its window as Pulse-internal events, so the contract must neither consume nor be read as amending that formula (per architecture.md §Established Decisions [Timing-Tolerance Model]).
- **Provenance must be stated on the artifact's face.** Both SUT-facing contracts carry `sut_version` · `captured_at` · `provenance`, and §Occupied Resources requires the artifact say whether its terms are a *transcribed SUT record* or a Conductor measurement "so a reader can tell how far to trust them". The scope's cited Pulse coordinates are pinned at HEAD `83d4060`, which the artifact must carry rather than assert undated (per architecture.md §Occupied Resources — `contracts/pulse-run-contract.toml`, `pulse-load-envelope.toml`).
- **Committed-text discipline.** §Infrastructure Patterns — Build system requires repo-wide LF at checkout (`* text=auto eol=lf`, added 2026-09-13), with the named `coverage-matrix.md` rule beneath it as the gate-correctness control — relevant if any in-tree assertion byte-compares the new artifact (per architecture.md §Infrastructure Patterns — Build system).

## Patterns to follow
- **The `contracts/` manifest pattern** — a committed, kebab-case, `pulse-*`-prefixed file with a header block (`sut_version` / `captured_at` / `provenance`) plus a typed body, resolved (if read) through `resolve_under` from a fixed default path (architecture.md §Occupied Resources; §Conventions — Naming patterns: kebab-case on-disk artifacts).
- **The run contract's `check` kinds as an honesty vocabulary** — `shell-declaration` (observable in Conductor's own environment; the only kind that can block) · `asserted` (satisfied by construction) · `declared-not-observable` (true on the SUT's side with no read-back surface; recorded, never blocking). A term addressed to Pulse today is `declared-not-observable` by construction, and stating that is how the contract avoids claiming a measurement Conductor cannot make (architecture.md §Occupied Resources — `contracts/pulse-run-contract.toml`).
- **The two-source integrity shape** — §Established Decisions [Accepted Capability Set] pairs manifest DATA with a code-native classification held to set-equality (`check_sut_drift`, `check_scenario_backing`/`UNBACKED_AUTO`) so a ledger can only shrink under compulsion. If the chunk wants anything in-tree to assert on the new contract, this is the established shape (and the `UNBACKED_AUTO` ledger is where an `Auto` claim no scenario backs is already asserted rather than remembered).
- **Load-path `check_*()` over garde for sibling-spanning rules** — §Established Decisions [Validation Library] fixes the boundary: garde `custom` is field-level only, so any invariant spanning a field and its sibling ships as a plain method called from `Scenario::from_toml_str` (`check_budgets` / `check_capabilities` / `check_checklist`), mapping to `CoreError::Config`.
- **Harvest-tier grading for the delegated-timing family** — §Standard Contracts → Run report envelope registers `halo-hue-encoding` as a member of the EIGHT declare-only families (zero `[[expected]]`, live rows `verdict: null` / `state: KnownResidual`, live claims graded at the harvest tier). §Conventions — Config conventions additionally requires that a `[[checklist]]`-declaring scenario carry an EMPTY `expected` (`Scenario::check_checklist`), and names `halo-hue-encoding` as one of exactly two committed scenarios declaring `[[checklist]]`. Whether the eventual `v3-08` grade can therefore ride an `[[expected]]` on that scenario without a load-path rejection is research's question.

## Anti-patterns to avoid
- **Introducing any delivery/network surface for the contract.** §Established Decisions [Backend Framework] and §Cross-cutting Patterns — Trust boundary hold that Conductor exposes no HTTP/network service of its own and its only non-loopback egress is one CI-job-scoped fetch; the contract ships as a committed file, never as a call into the SUT.
- **Reaching into the SUT.** §Cross-cutting Patterns — Scope law states the non-goals (no Pulse process management, no automation of Pulse's UI); §Standard Contracts holds `corpus.db` as out-of-scope SUT-owned data Conductor never persists or exfiltrates. The Pulse working copy is a READ-ONLY citation source for this chunk.
- **Claiming a measurement in the artifact's own voice.** §Occupied Resources records the shipped counter-example: `warmup_ms`'s `check = "asserted"` rationale was measured FALSE and "cannot catch its own falsity", and `sidecar-built` repeats the shape. A contract term that asserts a SUT-side property Conductor cannot observe must be marked as such, not asserted.

## Contract bindings
- **arch ↔ obs** — arch owns the artifact's placement and registration; the observable's identity, fields and emission surface belong to obs-plan §Delegated-timing family, which the scope names as the wrap-amendment surface for the unmeasurable finding.
- **arch ↔ tests** — the hard-grade predicate must land on an arch-defined shape if it is ever asserted: the nine-key `CheckRecord` (`run_check`, `latency_ms` and `deadline_ms` INTEGER **NOT NULL**, `budget_ms` NULL on tier inheritance) and the eleven-field run envelope (§Standard Contracts; §Conventions — Data model conventions). Whether a Pulse-produced duration can ride `run_check` without redefining `latency_ms`'s journal-relative meaning is a joint arch/tests/obs question for P3.
- **arch ↔ security** — every precondition/contract string arch ships is host-path-free with `data_dir` redacted (§Standard Contracts — Readiness gate); the new artifact inherits that, and its committed status means no operator-owned path value may appear in it.
