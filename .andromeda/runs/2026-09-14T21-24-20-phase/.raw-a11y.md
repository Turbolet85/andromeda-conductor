# a11y extract

## Relevance
Partial (narrow) — no UI/DOM surface is touched, so no WCAG/ARIA/focus/contrast/motion coverage is owed; the one live tie is the artifact-hygiene invariant that a11y violation artifacts inherit and the obs §6 envelope shape a11y reproduces.

## Constraints
- The emit crate and the `conductor` verb surface are not-assertable (no DOM/widget tree, no axe/Lighthouse reach), so this chunk owes zero WCAG SC coverage and may not claim any (per a11y-plan.md §1 A11y scope — entities needing assertions).
- a11y-plan.md §11 (SLO) requires that a11y artifacts NEVER carry absolute host paths or internal seam-crate struct names into the obs §6 envelope. `exception.rs`'s host-path scrubber trio is the class of enforcement point for that constraint; whether a11y's violation artifacts actually traverse this scrubber (vs. being scrubbed in the TS leg / `journal_conformance`) is research's question.
- a11y violation JSON is a narrowing of the obs §6 envelope reproduced verbatim, with axe rule-id + WCAG-SC tag + node selector folded into `fingerprints[]` — a11y-plan.md §3 (Structured violation JSON schema) requires the envelope's field set not diverge from the obs contract; any source edit here must leave that shape intact.
- The same §3 records the artifact's shipped shape as the 11 envelope keys plus obs resource tags (13 local / 15 CI), with `latency_ms` / `slo_tier` `&lt;90s` MAPPED rather than measured, and `fingerprints[]` carrying one tuple PER NODE. Whether `latency.rs`'s `quantile` / `LatencyProfile` accessors feed any field an a11y artifact carries is research's question — if they do, the accessor retire/assert fork (scope §Decisions deferred to P4) becomes an a11y-visible change.
- a11y-plan.md §9 (CI-specific resource attributes) restates the same no-host-path / no-struct-name rule for every uploaded a11y artifact, tagged with `service.name` / `deployment.environment` (+ `ci.run.id` / `git.commit.sha` in CI).
- a11y-plan.md §9 (Platform) and §11 (CI) require the routine-arm `a11y` job (`windows-2025`) to remain a fail-fast, non-skippable gate; any CI wiring this chunk's mutation gate acquires shares that workflow and must not displace, condition, or soft-gate it.

## Patterns to follow
- Selector/path hygiene as a positive assertion: a11y-plan.md §3 fixes node `target` as a DOM-relative selector / `data-testid`, "never filesystem paths" — the existing shape of "what a scrubbed field looks like" that scrubber tests can mirror rather than testing only that a mutant dies.
- Presence-not-exclusivity conformance gating: `journal_conformance` asserts key PRESENCE rather than key exclusivity (a11y-plan.md §3, as amended 2026-09-07) — the project's precedent for gating artifact shape without over-constraining extension points.
- Host-tool-handle skip discipline with a strict override: unset handle ⇒ skip at exit 0, with `CONDUCTOR_A11Y_STRICT` forcing non-zero instead, plus assertion of the runner's printed verdict because "a skipped-green run and a real pass are otherwise indistinguishable" (a11y-plan.md §11 CI). Directly applicable precedent for the chunk's `if not rows: FAIL` / empty-roster fork.
- Zero-retry, no-soft-threshold gate discipline (a11y-plan.md §10 + §11 SLO), explicitly parallel to tests' zero-flakiness rule — the design stance the mutation gate's pass condition should match.
- Identify CI jobs BY NAME, never by `ci.yml` line coordinates, which move as the workflow grows (a11y-plan.md §3 Configuration).

## Anti-patterns to avoid
- NEVER allow an artifact on a shared emission path to leak absolute host paths or internal seam-crate struct names — a11y artifacts inherit that ban (per a11y-plan.md §11 SLO); a test that pins scrubber output must not codify a leaking expectation.
- NEVER treat the cli/backend surface as accessibility-assertable or claim WCAG conformance from these tests (per a11y-plan.md §11 Universal + §1).
- NEVER make the existing `a11y` CI gate conditional, skippable, or cost-displaced by a long mutation run (per a11y-plan.md §11 CI); note a11y-plan.md §10 budgets a11y CI duration only, and states no budget for a mutation gate.

## Contract bindings
- a11y ↔ obs §6: a11y violation JSON aligns verbatim to the obs Run-report envelope (a11y narrows; obs fixed the schema) — a11y-plan.md §3. Any envelope-field change reachable from `latency.rs`'s percentile math (`latency_ms`, `slo_tier`) is a cross-domain change, not a local one.
- a11y ↔ tests (Status JSON constraint): the no-host-path / no-struct-name rule is inherited from tests and restated at a11y-plan.md §3, §9 and §11 SLO — the scrubber under test in this chunk is the same hygiene contract's enforcement class.
- a11y ↔ tests §9 / CI workflow: the routine-arm `a11y` job shares the GitHub Actions workflow any gate this chunk wires would join (a11y-plan.md §9 Platform + §3 Pipeline integration).

## Acceptance criteria contributions
- No artifact produced on any path shared with a11y violation artifacts contains an absolute host path or an internal seam-crate struct name; scrubber tests assert the hygiene outcome, not only mutant death (per a11y-plan.md §11 SLO + §9 CI-specific resource attributes).
- The obs §6 envelope shape a11y reproduces is unchanged by this chunk's source edits — the 11 envelope keys plus resource tags, `fingerprints[]` one tuple per node, `latency_ms` / `slo_tier` as mapped (per a11y-plan.md §3 Structured violation JSON schema).
- No WCAG conformance or a11y coverage claim is made from this chunk; the emit crate is a not-assertable surface (per a11y-plan.md §1 A11y scope + §11 Universal).
- If any gate lands in CI, the `a11y` job (routine arm, `windows-2025`) still runs and still exits non-zero on violations — no soft, conditional, or retried arm (per a11y-plan.md §11 CI + §10 Build/deploy failure conditions).
