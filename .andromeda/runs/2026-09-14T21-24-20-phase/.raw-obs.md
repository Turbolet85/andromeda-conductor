# obs extract

## Relevance
Partial — obs owns the host-path-freedom doctrine the `exception.rs` scrubber trio enforces and the latency/percentile semantics bounding `latency.rs`, but this chunk mints no new spans, logs, or metrics.

## Constraints
- The host-path redaction anchor is absolute host-**FILE** paths only — drive-letter `X:\`, `/home`, `/Users`, `%APPDATA%`, `~/.cargo`, `.rustup`, backtrace file paths → `&lt;redacted&gt;` — explicitly **NOT** `::`-token redaction, and the allowlisted `target` module path is preserved (per obs-plan.md §11 Obs Anti-Patterns — Logs + PII Scrubbing). Tests for `is_absolute_path_start` / `skip_absolute_path` / `skip_line_number_suffix` must discriminate against this anchor set, not a broader `::` rule.
- obs-plan.md §11 PII Scrubbing names `conductor-core::redact` as single-location owner with exactly three application sites (subscriber field filter, report-generation JSONL write, runs.db insert-validation); `conductor-emit::exception` is not among them, and the same section's standing warning requires that the enumeration be read as bounding only the sites it names. **Whether `exception.rs`'s scrubber delegates to `conductor-core::redact` or carries a duplicate/divergent rule set is research's question** — it decides whether the new tests pin one oracle or ratify two.
- obs-plan.md §11 Error Reporting requires that no unsanitized panic message or backtrace reach stderr or run-report artifacts, with absolute host paths and backtrace file paths stripped. The scrubber trio is that ban's mechanism on the emission side, so any arithmetic/comparison-boundary mutant that lets a path fragment survive must be killed by an assertion, not merely by unreachability.
- obs-plan.md §10 SLO Invariants states zero-unlogged-panics as the always-required Minimal-tier invariant, and §11 Error Reporting bans a panic on the emission/transport path. `quantile` / `lerp` / `sample_durations_nanos` boundary mutations (index math, `replace + with -`) are exactly the class that yields out-of-range or overflow panics, so the property test must carry a no-panic obligation alongside value correctness.
- obs-plan.md §5 Metric Coverage and §11 Metrics require that no metrics backend, meter provider, or histogram instrument exist at Minimal tier; `latency.rs`'s p50/p95/p99 are PRODUCT latency-profile synthesis, distinct from the §5/§10 self-obs `latency_ms` (`read_back_observed_at − journal_emitted_at`, wall-clock). The two must not be conflated in test naming or assertions.
- obs-plan.md §11 Project-specific bans requires garde cross-field validation carrying `p50 ≤ p95 ≤ p99` on scenario-config deserialization, with nested spec fields using `dive` and never `skip`. If the accessor fork resolves to *retire*, that ordering invariant still governs the fields; whether the retire path disturbs the garde derive or its test is research's question.
- obs-plan.md §3 OTel SDK init states the no-SDK invariant as **behavioral** — `opentelemetry` / `opentelemetry_sdk` sit dormant in `conductor-emit`'s tree and must never be initialized. New test targets under `crates/conductor-emit/tests/` must not init an SDK, exporter, or subscriber that exports (also §11 Universal: no self-obs OTLP to `:4317` or `:4318`).

## Patterns to follow
- §9 Log conformance check already encodes the host-path oracle as a concrete detector list (drive-letter / `/home` / `/Users` / `%APPDATA%` / `~/.cargo` / `.rustup`) with `target` explicitly exempt — reusable verbatim as the scrubber's discriminating corpus rather than inventing a new one.
- §3 Log format JSON schema records that `journal_conformance` asserts key presence, closed sets and **host-path freedom**, never key exclusivity — the artifact-tier twin of what the scrubber enforces at the unit tier; new unit tests should state the same property so the two tiers agree.
- §6 Boundary-call wrappers (`emit.batch`) establish the emit-path witness convention: key NAMES only, never values, on the already-allowlisted `message` field, at `debug` inside the existing `#[instrument]` span. Any assertion about emit-path logging must read `message`-borne text, since a non-allowlisted field name emits nothing.
- §4 Auto-instrumentation table, `conductor-emit` row: no auto-instrumentation, one manual span around the tonic client call, names bounded by §11's set (`emit.batch`, `emit.logs_batch`). A source edit under the accessor-retire fork must stay inside that set.

## Anti-patterns to avoid
- §11 Metrics bans an OTel meter provider / histogram instrument for self-observation; its "NEVER skip histogram quantile reporting — N/A (no histogram)" line must not be read as licensing one when `quantile` comes under test.
- §11 Logs / §11 PII Scrubbing ban blanket `::`-token redaction — a test asserting that `::`-shaped tokens are stripped would ratify the exact over-redaction the plan rejects (it would gut the allowlisted `target` field and mangle std type names such as `Option::unwrap`).
- §11 Telemetry Strategy bans over-instrumenting hot paths and §11 Logs bans `info`-level logging there — mutant discrimination must come from assertions, never from adding spans or log lines to the emission path to make behaviour observable.

## Contract bindings
- **obs ↔ security:** §11 PII Scrubbing and §11 Error Reporting cite security-plan §2 ("Leaking absolute host paths in run-report artifacts") as the upstream ban; the scope's own framing of these as security-surface tests (`security.md` §Artifact hygiene) makes the scrubber's contract two-sided — a change to its behaviour moves both masters.
- **obs ↔ tests:** §3 records the log-format schema as OWNED by test-plan §3 (obs aligns to tests, not vice versa), and §9's log-conformance + run-journal conformance gates are the harness-side consumers. The roster form and §12 test-decisions-log entries are test-plan-owned (wrap channel); obs contributes only the host-path-freedom criterion those artifacts must satisfy.
- **obs ↔ CI (§9):** §9's Lint row sets the precedent that `Diff in {file}` lines stay out of telemetry artifacts because they carry absolute host paths — the same rule governs any cargo-mutants `--output` run-dir content or `target/mutation-gate/` tally quoted into this chunk's committed report or roster `citation_home`.
