## Constraints
- Run-report artifacts, `runs.db` rows, JSONL journals and committed per-chunk `evidence/` must carry no absolute host path (canonicalized `CONDUCTOR_*` dirs, `ANDROMEDA_PULSE_DATA_DIR`) and no internal seam-crate struct name — they are agent-parseable ground truth shared across hosts (per security-plan.md §Security Anti-Patterns → Logging; restated at §Error Handling, Run-report artifact sanitization). `exception.rs`'s `is_absolute_path_start` / `skip_absolute_path` / `skip_line_number_suffix` are a mechanism of that mandate, so a surviving arithmetic-or-comparison-boundary mutant there is an unwitnessed security-control boundary, not only a coverage gap. **Whether the shipped trio already redacts every host-path shape the ban names is research's question** — the plan states the target, and 36 undiscriminated boundary mutants are exactly the evidence gap.
- Operator-visible surfaces must stay sanitized: no stack traces, file paths, internal hostnames, library versions or seam-crate struct names at the `conductor-cli` stderr / `#[tauri::command]` edge (per security-plan.md §Error Handling, External responses). Note the plan drops a standalone §Logging &amp; Monitoring at Minimal tier and folds redaction into the Logging anti-patterns + §Error Handling (per security-plan.md §Bootstrap phases, dropped-phases note) — so those two are the whole authority here.
- The deprecated-crypto ban is stated as ACTIVE and anchored to `conductor_emit::exception::fingerprint`'s blake3 derivation (first 16 bytes / 32 hex, replacing the retired FNV-1a), with the run-report `fingerprints[]` column read-back-fed and never fed from that derivation (per security-plan.md §Security Anti-Patterns → Data Protection). If the 96 never-measured `exception.rs` mutants reach that function, the gate reaches an active ban's implementation for the first time — **whether they do is research's question.**
- Any dependency added for the `quantile` property test (a property-test crate is named as the natural shape) must land under `cargo audit` green AND `cargo deny check advisories bans licenses sources` VERIFIED green over the NEW committed `Cargo.lock`; a new permissive license takes a `deny.toml` `[licenses] allow` entry with a justifying comment, `deny.toml` remaining the authority on the full set (per security-plan.md §Dependency Security, incl. Accepted exceptions). The 2026-08-16 "admit a delta under a red audit" regime is recorded CLOSED as of 2026-09-05, so the green-audit path is the only one available.
- `Cargo.lock` must not drift and must stay committed; the release gate / merge is barred without cargo-audit (and recommended cargo-deny) green (per security-plan.md §Security Anti-Patterns → Universal).
- Any extension of `scripts/mutation-gate.py` for file scoping must keep the cargo-mutants invocation array-form with a fixed toolchain program and repo-derived constant file arguments — never a shell string, never an operator-supplied value as the program (per security-plan.md §Security Anti-Patterns → Code Patterns, rule (b)). The plan records that rule (b)'s enumeration has been operator-ratified on every genuine new subprocess crossing with no routine rule minted, so a *new* crossing escalates; a fixed toolchain binary with fixed argv is recorded as not counted among the six governed forms (§Code Patterns; 2026-09-09 amendment).
- PII is classified "none" for Conductor — the only identities are self-generated synthetic data (per security-plan.md §Threat Model Summary, Data classification). The `tests/pii_payload_corpus.rs` ‖ `tests/common/mod.rs` clone-pair fold must keep the corpus synthetic and must not persist real secrets or credentials into any committed file (§Security Anti-Patterns → Data Protection, third bullet).

- The gate-1 hygiene grep asserted on the *committed* record (no host path, no seam-crate struct name) plus gate 2's closed-set assertion (same row) — a reusable acceptance shape for this chunk's new tests, fixtures and report.
- Handle-NAME-only / `&lt;redacted&gt;` rendering for anything path-valued: the readiness gate renders `data_dir: "&lt;redacted&gt;"`, and the journal-conformance residual is bounded by a failure origin naming the handle and the file's own name, never a resolved path (per security-plan.md §Input Validation, `ANDROMEDA_PULSE_*` declaration-only READ SET row and env-var path handles row). - The `deny.toml` justified-exception mechanism — every accepted advisory/license entry carries its own justifying comment — as the documented route for anything a new test dependency drags in (per security-plan.md §Dependency Security, Accepted exceptions).

## Anti-patterns to avoid
- NEVER let a committed file this chunk produces — test fixture, expected-output literal, roster row `citation_home`, chunk report or evidence — carry a real absolute host path from this dev host or an internal seam-crate struct name; use synthetic path literals for the scrubber's discriminating inputs (per security-plan.md §Security Anti-Patterns → Logging).
- NEVER resolve a surviving scrubber mutant by adjusting the trio's boundaries in the direction that admits *more* host-path text into the emitted/committed artifact — the chunk declares it changes tests, not emission behaviour, and a narrowing of the scrub would violate the Logging ban while the test turns green (per security-plan.md §Security Anti-Patterns → Logging; §Error Handling).
- NEVER build the extended mutation-gate command as a shell string / `eval`-equivalent, and never put an operator-supplied value in the program position (per security-plan.md §Security Anti-Patterns → Code Patterns, rule (b)).
