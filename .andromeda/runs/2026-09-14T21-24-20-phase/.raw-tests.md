# tests extract

## Relevance
Relevant — this is a test-authoring chunk squarely in the tests domain (mutation instrument, unit tier, fixtures, quality gates).

## Constraints
- **Mutation run discipline is measured, not assumed** (per test-plan.md §4 Mutation instrument): `-f` resolves from the **workspace root** so a full crate path is required (a package-relative path under `-p` silently matches nothing); `--test-tool=nextest` is REQUIRED; `Found 0 mutants to test` is a NO-OP, never a pass; **the exit code carries no verdict in either direction** (exit 3 measured on a fully-accepted run, exit 2 measured on two PASSING gate runs) — gate on the tallies read out of `mutants.out/`. §4 also states the committed executable form `python -X utf8 scripts/mutation-gate.py {unit}` into a fresh `target/mutation-gate/{unit}-{stamp}/`, comparing `missed.txt` against `scripts/mutation-roster.toml` as a **MULTISET over `(file, mutation)`**. Whether that instrument can express the chunk's two-file population is the scope's own blocking finding and P3/P4's question, not something this plan asserts.
- **Disposition, not a number** (per test-plan.md §10 Mutation-survivor disposition): every NAMED survivor must end **killed** or **classified accepted-deliberate against a cited rule**; the read-out condition is that `missed.txt` holds EXACTLY the run's accepted-deliberate survivors plus every other named survivor present in `caught.txt` (§4). This is deliberately NOT a `--fail-under` threshold beside the coverage gate — the score moves as a consequence of dispositioning, and is never itself the acceptance.
- **Roster identity and its two joined forms** (per test-plan.md §12, closing identity bullet, 2026-09-13): a member is keyed by cargo-mutants' own **mutation DESCRIPTION** joined to `scripts/mutation-roster.toml`'s `member` key — `file:line:col` is RETIRED and the executable roster carries no line/column. §12 is the CITATION HOME (cited rule + evidence pointer), the TOML the coordinate-free executable form; neither restates the other. The roster is populated **per gated unit**, so a unit with no rows today gains them only when a chunk touching that crate re-runs the tier.
- **Zero-flakiness bars a host-dependent kill** (per test-plan.md §10 Zero-flakiness + §12 members 4 and 5): a roster is an enumerated set that must mean the same thing on every host, so a kill reachable only via host state (or `unsafe { set_var }`, or binding a fixed port) is refused and the rejection is recorded as PART of the disposition. No nextest `retries`; a runner-dependent result is a determinism break in the same class.
- **Unit tier tests the public seam** (per test-plan.md §11 Unit): NEVER test implementation details (private fns / internal struct fields) and never write brittle assertions against fixture-internal values. §11 Integration adds that widening a crate's public API for tests alone is forbidden (architecture.md §Module Boundaries). Whether the scrubber trio and `lerp`/`quantile` are crate-private — and therefore must be discriminated through the public emission seam rather than by exposing them — is research's question.
- **Runner portability is a standing gate** (per test-plan.md §4 Framework + §12 runner-portability bullet): the suite must be green under BOTH `cargo nextest run -p &lt;crate&gt;` and `cargo test -p &lt;crate&gt;` (full, non-doc); only the shared-process runner exposes a test relying on per-test-process isolation.
- **Fixtures: sanctioned provenance and seeded randomness** (per test-plan.md §7): the committed fixture family is the SET of crate-local `tests/fixtures/` trees plus rstest-generated data; randomized data uses proptest 1.9.0 **with seed control and counterexamples persisted to `proptest-regressions/`** (§7 Seed strategies; §11 Test Data bans non-deterministic generators without seed control). Coverage exclusion is ONE generic regex `[\\/]tests[\\/]`, which already covers any crate-local `tests/` tree (§10 Coverage thresholds).
- **The mutation audit is operator/local, never a blocking CI stage** (per test-plan.md §9 Scoped mutation audit): it runs per-chunk against the crates that chunk touched, through the committed form since 2026-09-13, and adds no sixth `agent-run.{sh,ps1}` command (§4).

## Patterns to follow
- **Table-driven boundary matrices at the unit tier** — rstest `#[rstest]` + `#[case]` rows for valid/invalid matrices, `#[fixture]` for generators, `#[once]` for shared setup (per test-plan.md §4 Fixture pattern; §2 Test grouping). This is the plan's shape for the arithmetic/comparison-boundary discrimination the scrubber trio needs.
- **Property tests under the plan's proptest discipline** — proptest strategies with seed control, regressions persisted per crate for deterministic replay (per test-plan.md §7 Seed strategies; §2 pyramid Property-based row, which admits property tests "via trigger", not as a generic escalation). The `quantile` property test must carry that discipline whether or not it stands alone.
- **Shared crate-local test module as the fixture home** — `conductor-verify/tests/common/mod.rs` (the stub server) is the in-repo precedent for a crate-local `tests/common/mod.rs` shared module (per test-plan.md §4 conductor-verify bullet; §7 self-bootstrapping SET), and §10's single `tests/` coverage regex means such a module needs no coverage-exclusion entry.
- **Accepted-deliberate write-up shape** — name the SET (never a count), cite the member's own rule, record the REJECTED alternative as part of the disposition, and give a citation home in the chunk's own evidence (per test-plan.md §12 members 4 and 5). §10 requires the §12 citation home and the TOML row to join on `member`.
- **Flag an unassertable zone rather than invent a driver** — where a behaviour cannot be asserted at the unit tier, §1 records it as an untestable zone with the measurement that establishes it (per test-plan.md §1 Untestable zones; the 2026-09-04 creation-flag precedent), never a manual smoke step (§11 Universal).

## Anti-patterns to avoid
- Gating on `cargo mutants`' exit code, on a numeric mutation score, or treating an empty/zero-mutant run as a pass (per test-plan.md §4 + §10).
- Reaching a kill by widening the public API, mutating process env, binding a fixed port, or otherwise making the result host-dependent; and never stabilising with nextest `retries` or `--test-threads=1` (per test-plan.md §11 Unit/Integration + §10 Zero-flakiness).
- Lowering the coverage bar or skipping a binding gate "just this once" (per test-plan.md §11 Quality; `--fail-under-lines 60` stays).

## Contract bindings
- **tests ↔ security** — the host-path scrubber is the enforcement point for the artifact-sanitization invariant the plan already assigns to tests: artifacts must NOT leak absolute host paths or internal struct names (per test-plan.md §1 Status endpoint shape; §5 Run report envelope golden + sanitization assertion). Tests written here double as that negative-test surface; security.md §Artifact hygiene owns the rule's statement.
- **tests ↔ arch** — the accessor retire/assert fork edits production source; §11 Integration binds the "no `pub` widening for tests" rule to architecture.md §Established Decisions [Module Boundaries], so "make it public to test it" is not an available resolution of the fork.
- **tests ↔ harness/obs (5-command discipline)** — §3's `run` body is `cargo nextest run --workspace --profile ci` → `cargo test --workspace --doc` → `cargo clippy --workspace --all-targets -- -D warnings`; a source edit under the accessor fork must keep that body green, and §4 forbids the mutation gate becoming a sixth command. The scope's `cargo doc` warning-count pin is a chunk-gate concern, not a test-plan mandate; whether a source edit moves it is research's question.
- **tests ↔ wrap (amendment channel)** — §12 is the ratified-class citation home and the plan header forbids editing it during phase-loop runs; a new `conductor-emit` accepted-deliberate class therefore lands in §12 through wrap, while the chunk itself may only produce the evidence and the roster row.

## Acceptance criteria contributions
- (tests) `cargo nextest run -p conductor-emit` AND `cargo test -p conductor-emit` both green — the runner-portability standing gate, not nextest alone (per test-plan.md §4 / §12 runner-portability bullet).
- (tests) The mutation verdict is read from the run's tallies, never the exit code: every named survivor is in `caught.txt` and `missed.txt` holds EXACTLY the ratified accepted-deliberate set, matched as a MULTISET over `(file, mutation)` against `scripts/mutation-roster.toml`, with each member keyed by mutation DESCRIPTION and citing its own rule (per test-plan.md §4 + §10 + §12).
- (tests) Workspace line coverage stays ≥ 60% under `cargo llvm-cov nextest --fail-under-lines 60`; a new shared `tests/` module requires no new exclusion entry, since the shipped exclusion is the single `[\\/]tests[\\/]` regex (per test-plan.md §10 Coverage thresholds).
- (tests) Any new property test carries seed control with counterexamples persisted to `proptest-regressions/`, and no retry/serialisation knob is introduced to stabilise a result (per test-plan.md §7 Seed strategies + §10 Zero-flakiness + §11 Test Data).
