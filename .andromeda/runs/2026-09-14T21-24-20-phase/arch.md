## Relevance

## Constraints
- All of this chunk's code — the new `tests/`, the folded `tests/common/mod.rs`, and any accessor-retire source edit — lives in the seam crate `conductor-emit`, whose `Cargo.toml` dependency edges *are* the architecture. `conductor-emit` is EXCEPTED from the `conductor-core` edge since 2026-09-13; the dependent set is whatever members declare, never a universal (per architecture.md §Occupied Resources — Crate names; §Established Decisions [Module Boundaries]).
- Every member must build STANDALONE on its OWN target (`--lib` for a library crate), and `--all-targets` is banned as the sweep form because it re-unifies dev-dependencies — the exact masking class where a crate uses a feature it declares only in `[dev-dependencies]`. The property is measured-at-a-chunk, not gate-enforced. This chunk adds test-only deps, so whether `cargo check -p conductor-emit --lib` still exits 0 afterwards is a measurement the plan owes (per architecture.md §Established Decisions [Module Boundaries]).
- The scrubber trio is not Conductor's own invention: architecture.md §Established Decisions [Read-Back Dependency Posture] requires the fingerprint BE Pulse's derivation — blake3 over `exception_type` + `\0` + normalized stacktrace, `FINGERPRINT_BYTES = 16` rendered as 32 lowercase hex, only the first `NORMALIZED_FRAMES = 3` normalized lines contributing, normalization TOKEN-LEADING (relative paths significant at every depth; a token-leading absolute path stripped to nothing; line/col suffixes and hex addresses insensitive). A test that kills a boundary mutant must assert those semantics, because a Conductor-vs-Conductor assertion cannot see a derivation drift. Whether the shipped code still matches the SUT at its current HEAD is research's question.
- Determinism discipline binds the property test: nextest runs through a zero-retry `ci` profile precisely because "no retries mask flakes — the determinism invariant", and wall-clock stamps come from `std::time`, never a virtual clock (per architecture.md §Infrastructure Patterns — Build system; §Cross-cutting Patterns — Determinism discipline).
- Percentile math serves a locked config invariant: latency targets enforce p50≤p95≤p99 ordering, and a bounded-integer encoding is preferred over f64 where a type must keep `Eq` (per architecture.md §Conventions — Config conventions; §Established Decisions [Validation Library]).
- `scripts/mutation-gate.py` + `scripts/mutation-roster.toml` are registered as host-Python **operator instruments**: resolved by no lockfile, pinned by no toolchain file, invoked by NO CI step, and adding no sixth `agent-run.{sh,ps1}` command — the 5-command harness surface is unchanged. Any extension resolving the blocking finding must hold all three (per architecture.md §Stack and Technologies — Operator instruments row; §Established Decisions [CI/CD], whose CI enumeration is fmt / build / nextest / clippy + the a11y job).
- Any new dependency must land audit- and deny-green over an un-drifted lock, with each accepted advisory/license named inline in `deny.toml` — `conductor-emit` already minted the first non-Tauri cargo-side exception via its blake3 edge (per architecture.md §Infrastructure Patterns — Build system).

## Patterns to follow
- Semantics transcribed from the SUT are pinned by NAMED in-module tests beside the primitive (the two `exception.rs` pins arch cites by name), not by an external fixture — the shape established when the token-leading correction landed (per §Established Decisions [Read-Back Dependency Posture]).
- The dev-test stack is already pinned at arch grain — rstest / proptest / insta / assert_cmd / assert_fs / predicates under the zero-retry nextest `ci` profile, plus `cargo test --doc` for the doctests nextest skips — so a property test introduces no new dependency class; exact versions live in test-plan §4 (per §Infrastructure Patterns — Build system).
- Typed `thiserror` enums stay in the seam crate; `anyhow` lives only at the `conductor-cli` / `#[tauri::command]` edges (per §Conventions — Error handling).
- `scripts/mutation-roster.toml` is an already-registered instrument, so adding `conductor-emit` rows is per-item content in a registered resource — no arch registration is owed for rows. A genuinely NEW committed artifact would be (per §Occupied Resources — On-disk artifacts).
- snake_case Rust files/identifiers, kebab-case crate names, kebab-case on-disk Markdown artifacts (per §Conventions — Naming patterns).

## Anti-patterns to avoid
- Do not reintroduce a `conductor-emit → conductor-core` edge, including through `[dev-dependencies]` for the new tests (per §Occupied Resources — Crate names).
- Do not use `--all-targets` to demonstrate the crate builds — it re-unifies dev-dependencies and masks the exact defect the standalone sweep exists to catch (per §Established Decisions [Module Boundaries]).
- Do not wire the mutation gate into CI or into a sixth harness command, and do not let it acquire a lockfile-resolved runtime dependency (per §Stack — Operator instruments row; §Established Decisions [CI/CD]).

## Contract bindings
- **arch ↔ tests:** arch registers the runner, the zero-retry `ci` profile and the dev-test stack; test-plan §4 owns exact versions and §12 owns the ratified roster classes. Arch's only claim over the roster is that its instrument stays operator-local.
- **arch ↔ security:** the scrubber is the enforcement point for the host-path ban that arch also states on its own surfaces (precondition strings host-path-free, `data_dir` redacted, artifact records carrying no host path — §Standard Contracts, §Occupied Resources); security-plan §Artifact hygiene owns the rule itself.
- **arch ↔ SUT (Pulse-consistency mandate):** the blake3 pin is version-matched to the SUT's own, because the algorithm is the SUT's choice, not Conductor's (§Stack — Hashing / digest).
- **arch ↔ obs:** `conductor-emit` builds the PRODUCT OTLP stream; the `tracing` self-observation stack is a separate surface and is not an OTel SDK (§Stack — Self-observation).
