## Relevance
Partial — arch governs workspace placement, the declare-only shape and its registry, and the report/persistence consequences of removing `[[expected]]` blocks; it does not own the retirement judgement itself.

## Constraints
- Declare-only is an arch-registered shape, not an ad-hoc one: architecture.md §Standard Contracts (Run report envelope) enumerates the declare-only families and requires a zero-`[[expected]]` scenario's live row to land `verdict: null` / `state: KnownResidual` by one of the two named routes — never a silent pass. That enumeration is arch's own registry, so retiring four more members obliges an amendment at wrap; note the section currently excludes `findings-counter-refresh` from it *on the ground that it carries one `[[expected]]`*, which this chunk's member 2 would invalidate.
- Removing a scenario's last check moves it across a routing boundary arch pins: per architecture.md §Established Decisions [Read-Back Dependency Posture], the auto-resolve/empty-active-list residual route admits declare-only scenarios only, while a checks-bearing scenario is excluded from THAT route alone and every read-back call failure lands `Blocked` unconditionally. Retirement therefore changes which states these scenarios can reach, and the change must stay inside the closed `ReportState` set.
- The persistence consequence is mandated, not incidental: architecture.md §Standard Contracts (Per-check record) and §Occupied Resources (runs.db) require a declare-only scenario to emit ZERO `CheckRecord` lines and write ZERO `run_check` rows, with the eleven-field envelope byte-unchanged. Whether the shipped run seam already behaves that way for a newly-emptied scenario is research's question.
- No validation machinery is owed: architecture.md §Established Decisions [Scenario Config Format] + [Validation Library] fix the load path as serde + garde bounds with sibling-spanning rules as `Scenario::check_*` arms, and a three-way `CoreError::Config`/`Validation` mapping. The requirement is that an absent `expected` already loads; whether the committed loader satisfies it is research's question (the scope records it measured P1).
- One load-path invariant the edit interacts with: architecture.md §Conventions (Config conventions) requires `Scenario::check_checklist` to reject a `[[checklist]]` declared beside a non-empty `expected`. Emptying `expected` can only relax that rule, never violate it — but whether any member of the class enumeration declares `[[checklist]]` is research's question.
- Coverage identity is naming-based by mandate: architecture.md §Established Decisions [Accepted Capability Set] requires `check_sut_drift` (manifest ↔ code-native classification set-equality) and `check_scenario_backing` (`UNBACKED_AUTO` exact-set, keyed on whether a scenario NAMES an `Auto` id) — so a retired scenario must keep its `p_ids`, tier and drive intact, and no classification row may move as a side effect (`CoreError::SutDrift` / `UnbackedCoverage` are the guards).
- Placement is fixed: architecture.md §Infrastructure Patterns (directory tree) + §Established Decisions [Module Boundaries] put the scenario model and its tests in `conductor-core` and the declarative config under `scenarios/`; the crate-per-seam workspace forbids adding a dependency edge to reach anything else, and §Infrastructure Patterns (Build system) pins repo-wide LF at checkout, so edited `.toml`/`.rs` bytes stay LF.

## Patterns to follow
- The retirement precedent arch already carries: whole families retired to zero `[[expected]]` against a *measured* ground and re-registered in §Standard Contracts at wrap (eight families to date, most recently the severity-lifecycle and delegated-timing groups) — the same shape this chunk repeats for four single members.
- The verdict/error wall (architecture.md §Design Philosophy, §Cross-cutting Patterns): an ungradeable outcome is a VALUE, so a structurally-dead declaration is retired at the config layer rather than being handled as a `Result::Err` or special-cased in the grading path.
- Two-source integrity gates over a single edited artifact (architecture.md §Established Decisions [Accepted Capability Set]): manifest ↔ classification and classification ↔ scenario backing are held to exact-set equality, so the enumeration this chunk owes reads as data plus a committed catalog, never as a one-sided edit.
- Scope law "no scenario without a P-ID" (architecture.md §Cross-cutting Patterns, §Conventions Naming): the retired scenario keeps its P-ID identity and its drive; only the assertion half is removed.
- The `contracts/` artifacts are the home for SUT-side claims Conductor cannot measure (architecture.md §Occupied Resources) — including the one member no Rust code reads — which is the established place for a recorded SUT-side ground, if the class enumeration needs one.

## Anti-patterns to avoid
- Do not ship a new garde rule, `Scenario::check_*` arm, or `from_toml_str` signature change for the empty-`expected` shape (architecture.md §Established Decisions [Validation Library] — the boundary between garde and load-path checks is structural, and adding an arm for something the loader already enforces widens the surface for nothing).
- Do not edit the code-native coverage classification or the `UNBACKED_AUTO` pin as a convenience side effect of retirement (architecture.md §Established Decisions [Accepted Capability Set] — those are a separate two-source change and their gates exist to make a silent one impossible).
- Do not invent a report state, verdict value, or envelope key for "retired" (architecture.md §Standard Contracts — `verdict ∈ {Pass, Fail, CalibrationRegion}` and `state ∈ {Pass, Fail, ManualCheck, KnownResidual, Blocked}` are closed sets and the eleven-field envelope is byte-fixed).

## Contract bindings
- arch ↔ tests: the pinning tests sit inline in `conductor-core`'s `#[cfg(test)]` module, gated by the zero-retry `ci` nextest profile plus clippy/audit/deny (architecture.md §Infrastructure Patterns — Build system); the disposition of the two suite-shape tests is the tests domain's call, arch only fixes where they live and which gate must stay green.
- arch ↔ report/obs: the run-report envelope and the nine-key `CheckRecord` are shared shapes riding the JSONL journal, `runs.db` and the Markdown report (architecture.md §Standard Contracts) — retirement subtracts check records and `run_check` rows on all three surfaces at once.
- arch ↔ security: the scenario-config file is the governed input boundary, and its load-path error mapping is arch's [Scenario Config Format] three-way split — the declare-only shape must stay inside the existing boundary rather than adding one.
- arch ↔ wrap/docs: §Standard Contracts (Run report envelope) is the enumerating home for declare-only families and for the `findings-counter-refresh` exclusion clause; both are arch-body claims this chunk's outcome bears on.
