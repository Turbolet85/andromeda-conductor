## Constraints
- The per-P-ID verdict / report-state label set is **closed at six** on every surface; retiring a declaration must mint no seventh lamp, bracket label, `ReportState`, ANSI entry or token — "declare-only" / "retired" is not a renderable state (per layout-templates §Surface: cli — Component — Primary content block 2; §Surface: desktop-webview — Component — Primary content block 2).
- The Markdown run report's per-check detail region is **one indented line per expected check**, and the plan already rules that a scenario which graded nothing (blocked, or declare-only) contributes no such line — the region is absent, not rendered empty, and cli stdout plus the 6-column results/SLO table stay unchanged (per layout-templates §Surface: cli — Component — Primary content block 2, per-check detail region).
- Table shapes are fixed: **6 columns** for the results/SLO table (`run`/`suite`) and **4 columns** for `conductor coverage`; the two must not be conflated, and the plan states that adding a `comfy-table` column without a `--format` flag is a breaking change because downstream agents parse this output (per layout-templates §Surface: cli — Component — Primary content block 1; §Surface: cli — IA notes, Command model).
- Absence must be distinguished by **text, never by tint alone**: the webview matrix Status cell renders "Not yet run" prose when no run record names the capability, and `Blocked` measurement columns render `—` / null and are never red (per layout-templates §Surface: desktop-webview — Component — Primary content block 1; §Component — Primary content block 2).
- `CalibrationRegion` renders as the amber `[HOLD]` lamp and is **never silently a Fail** — which is exactly what the four dead floors render today per the scope's mechanism note; whether a retired scenario's P-ID row therefore moves from an amber cell to an absence/other cell is a rendering consequence research must establish (per layout-templates §Surface: cli — Component — Primary content block 2).
- Any change reaches all three surfaces **adapted, never forked** — Markdown artifact · cli stdout · webview — bound by token/label name (per layout-templates §Decisions Log, Cross-surface IA decisions; §Surface: cli — Primary screens, `conductor coverage [--write]`).
- The coverage roll-up caption's numbers are **manifest-derived, never literals**, and the `(N unbacked)` parenthetical qualifies the auto term only, is never a fifth summand, and renders identically on all three surfaces via the `unbacked` prop sourced from `unbacked_auto` (per layout-templates §Surface: cli — Primary screens, `conductor coverage [--write]`).

## Patterns to follow
- **Run-level qualifier outside the lamp column** — the `not-conductors` Mode-cell / `[ENVIRONMENT-SUSPECT]` / `[PRECONDITION]` precedent: a class-level fact is expressed as a non-lamp qualifier riding outside the lamp column with an always-printed ASCII label, never as a new lamp (per layout-templates §Surface: cli — Component — Primary content block 2). This is the shape to reuse if the chunk's class enumeration ever needs a rendered home.
- **Indented-detail-line precedent** — the `Blocked` precondition string and the `KnownResidual` note, extended to per-check grain; detail belongs beneath the verdict line, not in a new column (per layout-templates §Surface: cli — Component — Primary content block 2).
- **Worst-lamp-wins collision rule + the four-cell matrix row** (P-ID · Capability · Mode · Status, lamp LAST; `slo_tier`/`latency_ms` deliberately not on this surface) — the standing-vs-measurement split that keeps tier questions (v3-05) off the matrix entirely (per layout-templates §Surface: desktop-webview — Component — Primary content block 1).
- **De-literalize, never re-pin** — where a sample row or caption in this plan would go stale from a derived count moving, the established fix is to name the SET / placeholder form, not substitute a fresh literal (per layout-templates §Surface: cli — Primary screens, `conductor coverage [--write]`; amendment history below).

## Anti-patterns to avoid
- Minting a "retired" / "declare-only" bracket label, lamp glyph or `ReportState` to mark the four scenarios on any surface — the set is closed at six (per layout-templates §Surface: cli — Component — Primary content block 2).
- Adding or removing a column on either `comfy-table` shape to carry retirement status (per layout-templates §Surface: cli — Component — Primary content block 1; §IA notes).
- Signalling a retired/declare-only state by tint alone, or by reusing any lamp-set token to do it — reusing a lamp token reads as a verdict (the Mode-cell out-of-scope ruling, per layout-templates §Surface: desktop-webview — Component — Primary content block 1).

## Contract bindings
- **layouts ↔ coverage classification (architecture/obs):** the coverage roll-up's `(N unbacked)` is bound to `conductor_core::UNBACKED_AUTO` and reaches the webview as the matrix's `unbacked` prop, never mirrored in TypeScript (per layout-templates §Surface: cli — Primary screens). The chunk's scope keeps each scenario's `p_ids` and holds `coverage.rs`/`drift.rs` out of the modify-set, so this count is expected to be unmoved — whether that holds after the class enumeration is research's question.
- **layouts ↔ run-report writer:** the Markdown per-check detail region's row count is a direct function of a scenario's `[[expected]]` set; layouts mandates the region's shape, the writer owns emission. Whether the writer already omits the region cleanly for a zero-`[[expected]]` scenario (the five already-retired severity-lifecycle scenarios are the shipped precedent) is research's question.
- **layouts ↔ tests:** the pinning tests in `crates/conductor-core/src/scenario.rs` assert declaration triples, not rendered output; layouts adds no test-harness contract here.

- (layouts) Each retired scenario contributes **zero** indented per-check detail lines beneath its P-ID line in `runs/<run_id>.md` — the region is omitted, not rendered empty or as a placeholder row (per layout-templates §Surface: cli — Component — Primary content block 2, per-check detail region).
- (layouts) Column counts are unchanged: 6 for the results/SLO table, 4 for `conductor coverage` (per layout-templates §Surface: cli — Component — Primary content block 1).
