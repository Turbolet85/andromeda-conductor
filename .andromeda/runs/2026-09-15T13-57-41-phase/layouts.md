## Relevance
Partial — the chunk creates/modifies no surface, region or focus order, but it changes what two already-documented render regions emit (the Markdown per-check detail region and the per-P-ID verdict line) and is bounded by the closed-lamp-set rule.

## Constraints
- The per-P-ID verdict/report-state label set is **closed at six**; retiring a declaration must mint no seventh lamp, no new bracket label and no new `ReportState` on any surface — a "declare-only" standing is REMIT, not an outcome, and the `not-conductors` Mode-cell precedent is the only sanctioned recessive treatment for remit (per layout-templates §Surface: cli — Component — Primary content block 2, and §Surface: desktop-webview — Component — Primary content block 1).
- The Markdown per-check detail region (`runs/<run_id>.md`) carries one indented line per **expected check**; §cli Component — Primary content block 2 requires that a scenario which graded nothing (blocked, or declare-only) contributes no such line, with cli stdout and the 6-column results/SLO table unchanged. Whether the shipped renderer already honours that for a newly-declare-only scenario is research's question.
- Table shapes are frozen: the results/SLO table is exactly **6 columns** and the coverage matrix exactly **4 columns** (P-ID · Title · Category · Mode, no verdict column, no bracket prefix); §cli IA notes — Command model requires output structure stay stable because downstream agents parse it, so a column added without a `--format` flag is a breaking change (per layout-templates §cli Component — Primary content block 1 · §cli IA notes).
- Every number in the `conductor coverage` roll-up caption is manifest-derived, never a literal, and `(N unbacked)` qualifies the **auto term only** — never a fifth summand, omitted at zero, rendered identically on all three surfaces via the `unbacked` prop (per layout-templates §Surface: cli — Primary screens, `conductor coverage [--write]`). Scope states no `p_ids` change, so whether retirement moves this caption at all is research's question.
- Non-result states are never downgraded to Fail and never signalled by tint alone: measurement cells render `—`/null, `Blocked`/`KnownResidual`/`ManualCheck` each stay distinct, and every lamp is paired with its status text (per layout-templates §desktop-webview Component — Primary content block 2 · §cli Component — Primary content block 2).
- Any status signal on cli must carry its ASCII bracket prefix so it survives `NO_COLOR`/piping/screen readers, and the webview mirrors the same tokens **by name, adapted never forked** (per layout-templates §Surface: cli — Signature placement · §cli IA notes — Multi-surface coordination).

## Patterns to follow
- **Indented-detail-line precedent** — the `Blocked` precondition string and the `KnownResidual` note are the shape the per-check detail region extends; any per-scenario explanatory text belongs there rather than as a new column or label (per layout-templates §cli Component — Primary content block 2).
- **Run-level non-lamp qualifier SET** — `[ENVIRONMENT-SUSPECT]` / `[PRECONDITION]` show the sanctioned way to say something about a run *outside* the lamp column, if anything about the retirements ever needs surfacing (per layout-templates §cli Component — Primary content block 2).
- **Set-naming over literals in samples** — the standing de-literalization rule: a doc/sample value that can re-stale is stated as its derived set (`<slo_tier>`, `(N unbacked)`), never re-pinned as a fresh literal (per layout-templates §cli Primary screens `conductor coverage` · amendments 2026-08-16).
- **Cross-surface adapt-never-fork** — the same roll-up/qualifier shape renders on Markdown artifact, cli and webview header strip; a change landing on one surface must land by the same mechanism on the others, not be re-implemented (per layout-templates §cli Primary screens · §Decisions Log — Cross-surface IA decisions).
- No wireframe or sample row in the plan names `activity-floor`, `service-went-silent`, `high-severity-log-capture`, `exception-event-capture` or `threshold-hot-reload`, so the sample-row-staleness class that drove the 2026-08-18/19/21 sweeps does not apply to these five names.

## Anti-patterns to avoid
- Introducing a `[DECLARE-ONLY]` (or equivalent) bracket label, lamp glyph, ReportState or Mode value on any surface to mark the retired scenarios — the lamp set is closed at six and the Mode set closed at four (per layout-templates §cli Component — Primary content block 2 · §desktop Component — Primary content block 1).
- Letting a now-ungraded scenario render as a red `Fail`, or as tint/color alone without paired text — the "no surprise failure" rule extends to every never-measured or pre-accepted state (per layout-templates §desktop Component — Primary content block 2).
- Widening either `comfy-table` shape or the webview four-cell row to carry retirement metadata (per layout-templates §cli Component — Primary content block 1 · §cli IA notes — Command model).

- **layouts ↔ design-system** — lamp/bracket labels bind tokens by name (`count-nominal` ↔ ANSI 114, `status-residual` ↔ ANSI 246, etc.); no new token or ANSI entry may be minted by this chunk (per layout-templates §cli IA notes — Multi-surface coordination).
