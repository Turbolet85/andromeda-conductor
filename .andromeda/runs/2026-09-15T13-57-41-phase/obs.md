## Constraints
- A declare-only scenario's run-journal record is the **standard eleven-field envelope with `verdict` null and `state` "KnownResidual"** under the degraded read-back — the shape obs-plan §4 mandates at both the Restart-suppression and Severity-lifecycle blocks, and restates for the Delegated-timing family (per obs-plan §4 Span/Trace Coverage). Retiring a scenario's last live `[[expected]]` block moves it into that shape. *Whether the code already emits this for these five is research's question.*
- All **eleven envelope keys must remain PRESENT** after retirement — required means key presence, not non-null; the five measurement fields are `Option` and serialize as JSON `null`, and a typed parse cannot tell an absent `Option` key from a null one (per obs-plan §6 Log Coverage — Required fields, every ENVELOPE record).
- The report seam writes a **second line shape**, the per-check `CheckRecord` (mirrored into the `run_check` table), and **a blocked or declare-only scenario emits no check line at all** (per obs-plan §3 Harness Contract — Log format JSON schema, two record shapes). Removing six `[[expected]]` blocks therefore removes their check lines and `run_check` rows; the envelope's eleven fields are unchanged.
- The envelope's value sets are **closed**: `verdict` ∈ `Pass | Fail | CalibrationRegion`, `state` ∈ `Pass | Fail | ManualCheck | KnownResidual | Blocked` (per obs-plan §6 Log format JSON schema). A retirement removes any `CalibrationRegion` grade the retired floor produced and must introduce no new token.
- The **span-name set is bounded and closed** — `scenario.run`, `timeline.execute*`, `emit.batch`, `emit.logs_batch`, `verify.readback*`, `report.generate`, `db.insert_run`, `fault.silence/ramp/port_occupier`, `tauri.command.*` (per obs-plan §11 Obs Anti-Patterns — Spans / Traces). Pins and guards moved or minted here mint nothing outside it.
- A **span attribute must be a name in `conductor-core::redact::ALLOWLISTED_FIELDS`** or the processor stage drops it — anything else rides the allowlisted `message` field (per obs-plan §4 Required-span-attributes heading + §6 Boundary-call wrappers).

## Patterns to follow
- **Declare-only re-base:** when a family lands declare-only, the family-specific span chain and any envelope extra are retired and the scenario is recorded riding the generic chain `scenario.run` → `timeline.execute` → `emit.batch` → `verify.readback*` → `report.generate` with the standard eleven-field envelope (per obs-plan §4, Restart-suppression and Severity-lifecycle blocks).
- **Evidence that cannot grade in the envelope moves to the harvest tier** over Pulse's own tracing lines, each read from its OWN exact allowlist leaf, never through `budget_ms`/`effective_deadline_ms` (per obs-plan §4 Restart-suppression / Severity-lifecycle / Delegated-timing family). This is the destination precedent for retired evidence — note the chunk's own scope bans authoring new checks, so it bounds where a *later* entry would put it.
- **Retire only what is measured, never the generalizing universal** — the `degraded_mode_response` retirement applied text saying nothing is *known* to exercise the extension point, deliberately declining the detector's "no scenario extra is implemented" universal (per obs-plan §3 extension-point paragraph + §6 Additional scenario-specific fields). This is the same discipline the chunk's premises 1 and 2 need: state the ground that was actually measured, not the wider convenient one.
- **Uninstrumentable-as-written pre-check:** before a guard or witness carries a field, check the name against `ALLOWLISTED_FIELDS` first; the key-set and wire-shape witnesses show the `message`-field escape hatch as the sanctioned route (per obs-plan §6 Boundary-call wrappers).

## Anti-patterns to avoid
- **NEVER mint a span name outside the bounded set**, and never widen it with a `db.*`-class wildcard — the set is a deliberate contract (per obs-plan §11 — Spans / Traces, reinforced by the `conductor-report` row in §4).
- **NEVER leak absolute host paths or internal struct names** into logs / run-report / runs.db — if a DECLARE-ONLY header's `file:line` citations ever flow into a telemetry artifact they must be repo-relative (per obs-plan §11 — Logs, and §9 Log conformance check, which FAILs the build on a host-path hit).
- **NEVER skip spans on the §4 critical paths** — retirement is a scenario-corpus edit, not an instrumentation edit; the seven must-trace paths keep their instrumentation regardless of which `[[expected]]` blocks remain (per obs-plan §11 — Telemetry Strategy).

## Contract bindings
- **obs ↔ tests harness (two-sided, D-tests-obs-harness):** obs-plan §3/§6 *reproduce* test-plan §3's journal format, which OWNS it. Both report-seam shapes — the eleven-field envelope and the per-check `CheckRecord` — are test-plan-owned; a change in which line shapes a scenario emits must move on both sides together (precedent: the 2026-08-21 per-check amendment landed in obs because the owner amended).
- **obs ↔ CI gate:** `journal_conformance` asserts key PRESENCE, closed value sets and host-path freedom — never key exclusivity — which is what lets one gate serve both record shapes (per obs-plan §3 extension-point paragraph + §9 Log conformance check). It is the gate that will observe the retired scenarios' records.
- **obs ↔ arch:** architecture §Standard Contracts owns the declare-only family registry the scope flags as plausibly moving again; obs-plan §4's Delegated-timing declare-only roster is the obs-side twin (moved three→four at the prior chunk). Per scope, registry movement is wrap's amendment flow, never a phase edit.
