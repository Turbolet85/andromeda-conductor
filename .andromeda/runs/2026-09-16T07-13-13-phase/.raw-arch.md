## Constraints
- **Placement follows the crate-per-seam workspace.** If the check ships as Rust, arch's shipped home for static gates over committed catalog data is `conductor-core` — which already owns scenario loading (`Scenario::from_toml_str_with`, `list_scenarios(dir, &amp;manifest)`) and the code-native, no-runtime-IO `coverage_matrix()` — and forbidden cross-seam edges must not compile; no new workspace member is warranted for one check (per architecture.md §Established Decisions [Module Boundaries] · §Occupied Resources — Crate names · §Established Decisions [Accepted Capability Set]).
- **If the check ships as an operator instrument instead, its runtime is already registered.** §Stack and Technologies pins host Python 3 (resolved by no lockfile, pinned by no toolchain file) for `scripts/mutation-gate.py` + `scripts/mutation-roster.toml` and `scripts/code-graph.py`, and requires that such instruments add **no sixth `agent-run.{sh,ps1}` command** — the 5-command harness surface must stay unchanged (per architecture.md §Stack and Technologies [Operator instruments (host runtime)] · §Infrastructure Patterns — Directory structure, the `scripts/` tree comment).
- **If the registration is a CI gate, arch pins the step shape.** [CI/CD] requires a gate to be its own named step carrying no `continue-on-error` and no `if:` (the `cargo fmt --all --check` shape), running on the Windows runner set; and the a11y precedent holds that a gate which can report success by skipping is banned (per architecture.md §Established Decisions [CI/CD] · §Occupied Resources — Environment variables, `CONDUCTOR_A11Y_STRICT`).
- **A failure of a static catalog gate is a harness fault, never a verdict.** Arch's shipped shape for exactly this class is a named `CoreError` variant returned as `Result::Err` (`CoreError::SutDrift`, `CoreError::UnbackedCoverage`, the `check_load_envelope` gate); `Verdict`/`ReportState` are reserved for graded SUT behaviour (per architecture.md §Cross-cutting Patterns [Verdict/error wall] · §Established Decisions [Accepted Capability Set]).
- **Committed-data readers resolve from a fixed path with no new handle.** Every `contracts/` manifest resolves through a fixed `default_path()` + `resolve_under` with deliberately NO `CONDUCTOR_*` override; scenarios already have `CONDUCTOR_SCENARIOS_DIR`. Any env var, committed roster/ledger file, script or CI job this chunk lands is an occupied resource arch registers at wrap (per architecture.md §Occupied Resources — On-disk artifacts / Environment variables).
- **Byte-level comparisons over committed text are only correct under the LF pin.** `.gitattributes` pins `* text=auto eol=lf` repo-wide with `coverage-matrix.md text eol=lf` kept beneath it as the NAMED gate-correctness control, because `core.autocrlf=true` is the dev-host norm and every CI job runs a Windows runner — any probe of this chunk that compares file bytes or exact lines inherits that dependency (per architecture.md §Infrastructure Patterns — Build system).
- **Integrity gates stay two-source; ledgers stay exact-set in both directions.** Arch keeps the accepted set (data) and the classification (code) deliberately separate so `check_sut_drift` is a real comparison rather than a self-check, and holds `UNBACKED_AUTO` / the `[[exempt]]` ledger to exact-set equality so a ledger can only shrink under compulsion. The CARRY-1 obligation (grade every tally the claim rests on) is the same discipline — a check whose enumeration and whose expectation come from one source establishes nothing (per architecture.md §Established Decisions [Accepted Capability Set] · §Occupied Resources — `contracts/pulse-load-envelope.toml`).

## Patterns to follow
- **Static catalog gate over all committed scenarios, code-native, named error.** `check_load_envelope` judges every committed scenario per emitting phase against a committed contract and reports through `CoreError`; `check_sut_drift` / `check_scenario_backing` do the same on set-equality axes. Whether `conductor-core` already exposes a gate this chunk's check can join rather than duplicate is research's question (per architecture.md §Established Decisions [Accepted Capability Set] · §Occupied Resources — `contracts/pulse-load-envelope.toml`).
- **One shared basis, so a gate and any narrative cannot diverge.** The rate term's single call chain `phase_rate_exceeds` → `phase_breach` → {`check_load_envelope`, `LoadEnvelope::classify`} makes the static gate and the run-time caption agree *by construction* rather than by review — the model for a check that must establish an outcome a prose ledger currently holds (per architecture.md §Occupied Resources — `contracts/pulse-load-envelope.toml`).
- **Reuse the existing assertion over a re-pointed input, never a second copy of the schema.** The a11y violation record is asserted by `conductor-run`'s `journal_conformance` under a different `CONDUCTOR_RUNS_DIR` — "the same test the run journal uses — never a second copy" (per architecture.md §Occupied Resources — On-disk artifacts, `runs/a11y/&lt;run_id&gt;.jsonl`).
- **Script-plus-roster operator instrument.** `scripts/mutation-gate.py` + `scripts/mutation-roster.toml` is the registered shape for a committed check whose expectation lives in a data file beside it, not CI-invoked and not a harness verb (per architecture.md §Stack and Technologies [Operator instruments (host runtime)]).
- **Load-path checks for rules spanning sibling config fields.** `slo_tier` vs `[[expected]]`/`budget_ms` is already a sibling-spanning rule that ships as `Scenario::check_budgets()` at load rather than as a garde validator, because a field-level `custom` sees no sibling — the tier half of this chunk sits on that same structural boundary (per architecture.md §Established Decisions [Validation Library] · §Conventions — Config conventions).

## Anti-patterns to avoid
- **Do not mint a sixth `agent-run.{sh,ps1}` command** for this check, and do not add a new workspace crate for it (per architecture.md §Stack and Technologies [Operator instruments] · §Infrastructure Patterns — Directory structure).
- **Do not ship a gate that can pass by skipping** — an unresolved precondition or a missing input must not exit 0 in the gate arm (per architecture.md §Established Decisions [CI/CD] · §Occupied Resources — `CONDUCTOR_A11Y_STRICT`).
- **Do not open a listener, spawn the sidecar, or reach any non-loopback target.** Conductor exposes no HTTP/network surface of its own, and the only registered non-loopback egress is the CI-job-scoped WebView2 bootstrapper (per architecture.md §Cross-cutting Patterns [Trust boundary] · §Established Decisions [Backend Framework]).

## Contract bindings
- **arch ↔ tests:** the registration surface decides the runner — a Rust check runs under the pinned zero-retry nextest `ci` profile (`.config/nextest.toml`; no retries mask flakes), while a CI step is a workflow-level gate; exact tool/dep versions are test-plan §4's, not arch's (per architecture.md §Infrastructure Patterns — Build system).
- **arch ↔ security:** a `scripts/` instrument or CI step inherits the harness-edge discipline arch records for host-tool handles — validated at the edge, array-form argv, never interpolated into a shell; arch adds only "no new egress, no new env handle" (per architecture.md §Occupied Resources — `CONDUCTOR_MSEDGEDRIVER` · §Cross-cutting Patterns [Trust boundary]).
- **arch ↔ obs/report:** if the check emits any artifact under `runs/`, arch's placement rules bind — the harness's `status`/`report` readers glob `"$RUNS_DIR"/*.jsonl` non-recursively, which is why a non-scenario record gets its own directory (per architecture.md §Occupied Resources — On-disk artifacts).
- **arch ↔ wrap:** a new CI gate restates the gate-set enumeration at five arch sites (§Stack CI/CD row, §Established Decisions [CI/CD], the `.github/workflows/` tree comment, §Infrastructure Patterns CI/CD approach, §Inherited Defaults) — the 2026-09-09 fmt-gate fan-out.

## Acceptance criteria contributions
- (arch) The check lives in an existing workspace member (`conductor-core` for the catalog-gate shape) or under `scripts/` as a host-Python operator instrument; it adds no new workspace crate and no sixth `agent-run.{sh,ps1}` command — the 5-command harness surface is unchanged (per architecture.md §Stack and Technologies [Operator instruments (host runtime)] · §Established Decisions [Module Boundaries]).
- (arch) The check opens no listener, spawns no sidecar, and reaches no non-loopback target; it reads committed files only (per architecture.md §Cross-cutting Patterns [Trust boundary] · §Occupied Resources — Ports).
- (arch) A red result surfaces as a harness fault — a named `CoreError` variant / non-zero exit in the catalog-gate shape — never as a `Verdict` or `ReportState` value (per architecture.md §Cross-cutting Patterns [Verdict/error wall] · §Established Decisions [Accepted Capability Set]).
- (arch) Every new committed artifact (roster/ledger/fixture), script, CI job or env var this chunk lands is registered in §Occupied Resources / the directory tree at wrap, and any committed data the check reads resolves from a fixed path with no new `CONDUCTOR_*` override handle (per architecture.md §Occupied Resources — On-disk artifacts / Environment variables).
