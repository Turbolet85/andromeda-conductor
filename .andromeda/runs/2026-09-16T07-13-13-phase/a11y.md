## Patterns to follow
- **Routine vs driven arm split** (a11y-plan §9 CI Integration → E2E row; §11 → Strategy carve-out): checks needing no live SUT are the CI-gateable class; live-Pulse-requiring ones stay operator-local. The chunk's scope law ("no Pulse change, no live leg") puts it squarely in the CI-gateable class by that precedent — useful input to the "CI gate vs operator instrument" fork.
- **The skipped-green mechanism** (a11y-plan §11 → CI, shipped 2026-09-07): a gate whose guard is designed to skip at exit 0 needs a strict-mode env plus a printed-verdict assertion, because the verdict the caller keys off is not the only tally the claim rests on. This is the same failure shape CARRY 1 routes here and is the closest in-repo precedent for the chunk's "demonstrated able to fail" obligation.
- **Machine-verifiable-or-supplemental invariant** (a11y-plan §2 Agent-runnable invariants): every claim carries at least one machine-verifiable path; authored/manual records are supplemental, never sole. Directly parallels the chunk's job of replacing the authored `tier-ledger.md` enumeration with a mechanical separation.
- **Structured PASS/FAIL artifact shape** (a11y-plan §3 → Structured violation JSON schema): results fold into the obs §6 envelope, with per-node tuples in `fingerprints[]` and scenario-shaped keys recorded as *mapped, not measured*; resource tags ride alongside as an admitted extension. If this chunk emits a machine artifact, that is the house shape and the honesty convention for derived fields.

## Anti-patterns to avoid
- Never let a gate be green by not running — a skipped-green run and a real pass must be distinguishable by more than the exit code (a11y-plan §11 → CI).
- Never use retry-once or a soft threshold on a gate; it masks real failures (a11y-plan §11 → SLO, the zero-flakiness parallel).
- Never let an emitted artifact leak absolute host paths or internal seam-crate struct names (a11y-plan §11 → SLO, inherited from tests' Status JSON constraint).
