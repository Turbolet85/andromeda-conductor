## Constraints
- **The a11y job's ASSERTING steps must carry no `continue-on-error` and no `if:`; only diagnostic/upload steps may** — arch §Established Decisions [CI/CD] states this as the gate discipline for every named CI step, and pairs it with a presence guard on each gate's subject that emits `::error::` and exits 1 so an absent subject fails loudly rather than passing vacuously. Whichever outcome ships (A or B), the step that carries the verdict inherits this shape. Whether the current step set already satisfies it is research's question.
- **A CI gate that can report success by skipping is banned** — arch §Occupied Resources (`CONDUCTOR_A11Y_STRICT`) records that handle as existing precisely to invert the exit-0 skip arm under CI, and describes it as an ADDED arm over the existing guards, never a relaxation of them. Any launch-context change must not reintroduce a skip-shaped pass, and (B) must not become one.
- **Any new env handle the workflow or the wdio harness names must be registered under one of arch's four stated registration bases** — arch §Occupied Resources — Environment variables distinguishes: reserved `CONDUCTOR_*` (with a stated control model — path-valued + `isFile`/metacharacter-guarded, flag-valued, or harness-owned), an external handle a shipped artifact READS (`EDGEWEBDRIVER` · `RUNNER_TEMP` · `TEMP` · `LOCALAPPDATA`), and one a shipped artifact SETS but never reads (`WEBVIEW2_*`, diagnostic-scoped). A limited-token launch handle inherits whichever basis it fits; it does not get a new class silently.
- **A runner-process variable must be read in the step SHELL, never through `${{ env.* }}`** — arch §Occupied Resources (`EDGEWEBDRIVER`) records that the expression context holds only workflow/job/step declarations, and that reading it there yielded an empty base reaching the guard as a literal. This is the mechanism behind the scope's "observable only on the runner" method constraint.
- **The webview a11y legs are ONE WebdriverIO + tauri-driver stack across three suite families — never a second automation stack** — arch §Cross-cutting Patterns (Scope law). A limited-token launch must land as a change to the existing stack's launch context, not as a parallel driver/runner path.
- **The harness surface stays at five `agent-run.{sh,ps1}` commands, and a CI-only instrument adds none** — arch §Stack and Technologies (Operator instruments row) and §Infrastructure Patterns (Directory structure), which record `scripts/webview2-cause-probe.ps1` as CI-only, invoked solely by `ci.yml`'s a11y job and wired into neither harness shell. Any new launch script inherits that placement rule.
- **No shipped binary may gain an inbound listener, and a new CI-time fetched binary crosses a named boundary class** — arch §Cross-cutting Patterns (Trust boundary) + §Occupied Resources — Ports: `4444`/`4445` are dev-only, harness-lifetime, bound and released with the session; the single CI outbound target is admitted only through a pre-execution `Get-AuthenticodeSignature` gate (status `Valid` AND an `O=Microsoft Corporation` signer) and is operator-ratified boundary widening, in no lockfile and covered by no lockfile-scanning gate.

- **Conditional, floored provisioning with the assertion outside the conditional**: arch §Established Decisions [CI/CD] + §Infrastructure Patterns (Build system) describe the Evergreen install as taken only below runtime major 152, with the `&gt;= 152` assertion sitting OUTSIDE the conditional and running every job. Any added environment-shaping step should follow this shape (guard the fetching path; assert unconditionally).
- **The a11y record reuses the production schema, never a second copy**: arch §Occupied Resources — On-disk artifacts specifies `runs/a11y/&lt;run_id&gt;.jsonl` as the eleven-field run-report envelope plus obs resource tags (13 keys locally / 15 under CI), asserted by `conductor-run`'s `journal_conformance` under `CONDUCTOR_RUNS_DIR=runs/a11y` — the same test the run journal uses. - **Per-suite self-obs landing site**: arch §Occupied Resources (`logs/conductor-tauri.jsonl`) records the sink as `runs_dir.parent()/logs` with the ONE tauri-driver spawn site choosing `CONDUCTOR_RUNS_DIR` per invoked suite, and tauri-driver spawned with `cwd` = the workspace root. A token-dropped launch changes profile/CWD assumptions this depends on — research's question whether the record still lands.

## Anti-patterns to avoid
- **A gate that passes by asserting nothing** — arch §Established Decisions [CI/CD] requires presence-guarded, unconditional gate steps; the scope's own reading that step 13's conformance gate was SKIPPED on the failing run is exactly the shape arch bans as vacuous passing.
- **Minting a second automation stack, a sixth harness command, or an unregistered `CONDUCTOR_*` name** — arch §Cross-cutting Patterns (Scope law) · §Stack (Operator instruments) · §Occupied Resources (Environment variables).
- **Re-listing an assertion in shell** — arch §Established Decisions [CI/CD]: a second copy drifts from the production source, so the gate IS the Rust/harness test and the step is its presence-guarded invocation. A ratified exclusion (B) must not become a shell-side re-statement of what the routine arm asserted.
