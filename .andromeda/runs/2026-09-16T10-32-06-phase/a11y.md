# a11y extract

## Relevance
Relevant — this chunk IS the a11y capability's CI terminal; a11y-plan §3/§9/§10/§11 own the gate it must make honest.

## Constraints
- The a11y step is a **fail-fast gate, never a warning**, and a skipped-green run must be distinguishable from a real pass: `CONDUCTOR_A11Y_STRICT` makes an unresolved host-tool handle exit non-zero instead of skipping at 0, and both harness shells must additionally assert the runner's **printed verdict** (`Spec Files:` failed count, per-spec skip tally against the expected-skip SET, driven-session banner) — the exit code alone cannot enforce it (per a11y-plan §11 Anti-Patterns → CI). This is the plan-side definition of "honest terminal". Whether the shipped harness already declares the strict handle and asserts the printed verdict is research's question.
- **One webview-automation stack only** — axe injects via `@axe-core/webdriverio` into the tests §6 `@crabnebula/tauri-driver` + WebdriverIO session; standing up a parallel puppeteer/CDP attach for a11y is banned (per a11y-plan §3 A11y testing tool pick + §11 Anti-Patterns → CI). A launch-context change (scheduled task / limited-token principal) must keep the leg on that one stack rather than forking it.
- The routine arm's **asserted set** is the Perceivable half (axe under `wcag2a`/`wcag2aa`/`wcag21aa`, colorjs.io token-pair ratios in both declared themes, not-color-alone, the compiled `@media (prefers-reduced-motion: reduce)` rule) **plus the hold-free Operable pair** (SC 2.1.1 reachability, SC 2.4.3 focus order asserting no `tabindex > 0`); only the HOLD-dependent half (trap entry/containment, restoration) stays operator-local (per a11y-plan §11 Strategy CARVE-OUT, narrowed 2026-09-07, and §9 E2E row). Outcome (B) may not widen that carve-out beyond its hold-dependent half.
- The routine arm **needs no live Pulse** — it seeds its own committed fixture through the production writer — and the rule holds that a spec whose DOM state the seeded subject cannot produce **context-skips, never passing green** (per a11y-plan §9 per-pipeline-stage E2E row + §3 Pipeline integration). A green arm must therefore be green *with the assertions executed*, not green by skip.
- **Zero WCAG AA violations** on the four must-be-accessible paths is the always-required SLO, with `violations.length > 0` → non-zero exit; **no retry-once policy** for a11y violations, and no soft SLO (per a11y-plan §10 SLO Invariants + §11 Anti-Patterns → SLO). Whether the observed `(1 retries)` in the failing spec is a mocha spec-retry at session creation (outside the violation-retry ban) or inside it is research's question to settle before it becomes the green path.
- A11y violation artifacts align to the **obs §6 envelope** and carry the resource tags `service.name` / `deployment.environment` (plus `ci.run.id` / `git.commit.sha` under CI — 15 top-level keys), and MUST NOT leak absolute host paths or internal seam-crate struct names; node `target` selectors are DOM-relative / `data-testid` only (per a11y-plan §3 Structured violation JSON schema + §9 CI-specific resource attributes). The scope's host-path elision of the failure quote is the same discipline.
- **Per-PR diff against base** for new WCAG AA violations is required and may not be skipped (per a11y-plan §9 Pipeline integration + §11 Anti-Patterns → SLO). Whether the shipped `a11y` job implements the diff, or only the `actions/upload-artifact` half, is research's question.

## Patterns to follow
- **Identify CI jobs BY NAME, not `ci.yml` line coordinates** — a11y-plan §3 Configuration records that coordinates move as the workflow grows (the frontend job moved `:178` → `:188`), and job `a11y` on `windows-2025` is the named handle.
- **Host-tool handle discipline:** `CONDUCTOR_MSEDGEDRIVER` / `CONDUCTOR_NVDA` unset ⇒ skip at exit 0, with `CONDUCTOR_A11Y_STRICT` as the CI override (per a11y-plan §3 Bootstrap `a11y-ci-gate-wire` + §11 CI). Any new launch handle introduced by a limited-token arm inherits both halves of that contract.
- **Reuse the tests' 5-command harness surface** (boot / run / status / cleanup / logs) with a11y results surfacing through `logs`, the artifact-emitting command (per a11y-plan §3 CI integration + §9 Pipeline integration) — the gate rides `agent-run run --e2e`, not a bespoke lane.
- **Fixture seeding through the production writer** so DOM states the arm asserts against are really produced (e.g. the over-envelope `run_envelope` row under `CONDUCTOR_E2E_SEED_DIR`) rather than mocked (per a11y-plan §4 load-envelope banner row + §9 E2E row).
- **Epistemic-status labeling on platform/runner claims** — the plan's own convention is to state what a leg *measured* and mark the rest "recorded, not established" (per a11y-plan §6 Motion tokens + §12 Decisions Log; enforced by the `D-platform-claim` detector). Outcome (B)'s "measured cause" wording, and any (A) success claim, must be written to that standard.

## Anti-patterns to avoid
- NEVER ship an a11y gate that passes by asserting nothing — skipping on failure, warning-only exit, or a skipped-green run indistinguishable from a pass (per a11y-plan §11 Anti-Patterns → CI).
- NEVER stand up a second browser-automation stack (puppeteer / CDP / Windows-only attach) to get a session (per a11y-plan §11 Anti-Patterns → CI + §3 tool pick).
- NEVER define a soft a11y SLO or retry a11y violations away (per a11y-plan §11 Anti-Patterns → SLO + §10).
