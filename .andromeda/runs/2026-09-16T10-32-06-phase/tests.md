## Relevance
Relevant — this chunk changes a CI E2E-webview gate and its launch/handle edge, which test-plan §3 (harness contract), §6 (E2E drivers), §9 (CI integration) and §10/§11 (gates + bans) own directly.

## Constraints
- The asserting gate step must never carry `continue-on-error`; only the diagnostic/upload step SET may. test-plan §9 (Pipeline structure → E2E-webview row) requires this because "a gate that can report success by skipping or erroring is the thing the strict arm exists to forbid", and requires `CONDUCTOR_A11Y_STRICT` set on the job so an unresolved handle exits 1 instead of skipping green. Neither outcome (A) nor (B) may be reached by relaxing this (per test-plan §9; reinforced by §11 Quality "NEVER skip quality gates just this once").
- The routine arm's verdict must be read from the PRINTED wdio output, never the exit code — the leg's exit cannot separate a full pass from a total skip. §3 (`run` → `--e2e` CI stage selectors) requires: capture to `$RUNS_DIR/a11y-e2e.log`, read the exit from the BARE command (never through a pipe), then assert zero on the `Spec Files:` failed term, a per-spec skip tally within the expected-skip SET (the two live-hold subjects — a third skip is a failure), and the `[webview2 … windows]` session banner. §3 further conditions that contract on the INVOKING environment not preempting capture-then-print (the `$PSNativeCommandUseErrorActionPreference` case) — a limited-token wrapper (scheduled task / `runas`) is a new invoking environment and inherits that condition (per test-plan §3).
- Both shells must expose identical semantics and the command count must stay five. test-plan §3 Bootstrap (`5-command-discipline-wire`) states the binding contract is asserted of the SCRIPTS *together with the invoking environment*, so a launch-context change landing in `.ps1` alone diverges the pair with zero `.sh` delta (per test-plan §3 Bootstrap phases; §3 `--e2e`).
- Any change must leave the `status` disk read, the Run-report envelope and the per-run JSONL shapes untouched, adding no stage selector and no new `CONDUCTOR_*` semantics into the envelope — §3 repeatedly conditions each `--e2e` amendment on "§3 ↔ obs-plan §3 still agree" (per test-plan §3 `--e2e` / Log format).
- A new launch handle inherits the harness-edge guard duty: existence + `isFile` + shell-metacharacter rejection ahead of an ARRAY-FORM spawn, discharged in `wdio.conf.ts`, with e2e-tier skip arms as its mandated coverage — no Rust negative test is reachable for a harness-only host handle (per test-plan §1 Coverage triggers, security-vector-coverage Vector 1, the `CONDUCTOR_MSEDGEDRIVER` / `CONDUCTOR_NVDA` / `CONDUCTOR_E2E_SEED_DIR` / `CONDUCTOR_A11Y_STRICT` per-reader classes). `CONDUCTOR_A11Y_STRICT`'s own mandated coverage is its two arms: strict + unresolved handle ⇒ exit 1; lax + unresolved ⇒ exit 0 with the dev-host skip preserved.
- No retries and no runner-pinning: §10 (Zero-flakiness budget) forbids retry-once policies and states a runner-dependent result is a determinism break to fix at the cause; §11 CI restates "do NOT set nextest `retries`". Whether the wdio leg's own per-spec retry (the failing run shows `1 retries`) sits inside or outside that ban is research's question.
- If a wait on the endpoint's appearance is needed, it must key on an explicit signal, not a sleep: §11 E2E bans `sleep(N)` for synchronisation INSIDE a test, permitting only a harness-level between-legs wait that reproduces a documented SUT-side precondition (per test-plan §11 E2E).

## Patterns to follow
- The `continue-on-error` split already specified for this job: diagnostic + upload steps carry it (and `if: always()`), the gate step never does — §9 records the step set as an open SET precisely so a fourth probe cannot re-stale the spec.
- The repo-relative handle discipline for anything the app resolves: `CONDUCTOR_RUNS_DIR=runs/e2e-fixture` / `CONDUCTOR_SCENARIOS_DIR` are repo-relative because `resolve_under` rejects absolute paths and `..`, and the tauri-driver child is spawned at `cwd` = workspace root as the only lever (§3, §6). A token-dropped launch changes working directory and profile reachability, so this is the pattern any new launch mechanism must preserve.
- Self-seeding through the production writer: `wdio.conf.ts`'s `seedFixtureRuns()` clean-re-creates `runs/e2e-fixture/` and invokes `cargo test -q -p conductor-run --test envelope_fixture` with `CONDUCTOR_E2E_SEED_DIR`, throwing rather than seeding silently (§3, §7 Self-bootstrapping requirement). A relaunched-under-a-different-principal leg must still reach that subject.
- The separate a11y violation artifact: `runs/a11y/<run_id>.jsonl` = this §3 envelope's eleven fields PLUS obs §9 resource tags, deliberately outside the harness's non-recursive `"$RUNS_DIR"/*.jsonl` glob so `status` cannot read it as a scenario run, gated by the reused `journal_conformance` gate over `runs/a11y` (§3, §9).
- The flagged-untestable-zone form, if (B) ships: §1 records a non-covered surface with its Source, its Reason, and the explicit note that it is "flagged here rather than given an invented driver" — the `sr*` browse-mode precedent is the shape (recorded findings, never passes, never a manual arm).

## Anti-patterns to avoid
- Never discharge the terminal with a manual smoke step or human screenshot/visual review — §11 Universal bans both, with the `drive+observe` operator checklist as the only carve-out (a product feature, not a test step).
- Never pull a live-Pulse arm into CI to make the job green: the `driven` and `sr*` families and `run --live` are operator/local only (§9 Live-Pulse scenarios; §11 CI), and §11 Test Strategy bans faking Pulse's reaction as a CI verdict.
- Never assert via xpath / hashed-CSS selectors or visual regression when re-wiring the arm — role/text/`aria-live` + brand anchors only (§6 Selector strategy; §11 E2E; §11 Universal).
