## Relevance
**Relevant** — the chunk's subject is a new/replacement governed harness-spawn form on the CI locus plus the disposition of the WebView2 Evergreen float, both of which security-plan.md mandates directly.

## Constraints
- The launcher is governed by the harness-spawn rule: no shell / `eval`-equivalent, no operator-supplied value in argv, and — for the composing form that cannot array its arguments — whitespace + shell-metacharacter rejection on EVERY element before composition, with a named precondition on rejection (per security-plan.md §Security Anti-Patterns → Code Patterns rule (b)). Whether this chunk's `CreateRestrictedToken`/`SetTokenInformation`/`CreateProcessAsUser` launcher REPLACES the registered seventh form or constitutes an EIGHTH crossing decides which registry text the plan owes, but it is an operator-ratified boundary-widening escalation either way — never routine, and no playbook rule may be minted for the class (per §Security Anti-Patterns → Code Patterns rule (b); amendment record 2026-09-16 under playbook `:124`).
- If the API triple is not reachable from PowerShell and a different host lands (a Rust/Win32 P-Invoke shim, a vendored tool, an npm package), the dependency gates bind before merge: `cargo audit` + `cargo deny check advisories bans licenses sources` green over the committed `Cargo.lock`, `npm audit --omit=dev` = 0 for the `crates/conductor-tauri/ui/` tree, lock committed (per §Dependency Security; §Security Anti-Patterns → Universal). A new host that is neither repo-derived, repo-vendored, nor a fixed OS/toolchain binary additionally requires a pre-execution admitting control of the sixth form's class (per §Dependency Security third dependency class).
- §Dependency Security's third-class disposition is a requirement this chunk triggers, matching CARRY 4 and matrix obligation 1: the stated exit condition is that once the `a11y` job actually GATES (endpoint opens, routine arm runs to completion) the runtime is PINNED and the versioned Standalone Installer replaces the bootstrapper. Until then the `≥ 152` floor assertion must sit OUTSIDE the fetch conditional and run every job, the `Get-AuthenticodeSignature` gate must guard the only fetching path, and neither step may carry `continue-on-error`.
- Existing handle guards may be widened by an ADDED arm but never relaxed: `wdio.conf.ts` remains the sole READER and sole site of the `isFile` + shell-metacharacter guard for `CONDUCTOR_MSEDGEDRIVER` / `CONDUCTOR_NVDA`, and `CONDUCTOR_A11Y_STRICT` remains flag-valued with nothing to canonicalize (per §Input Validation, the `CONDUCTOR_MSEDGEDRIVER` / `CONDUCTOR_NVDA` / `CONDUCTOR_A11Y_STRICT` rows). A launcher that changes which process reads these must be recorded as a new READER, since the duty binds per READER.
- Precondition strings, CI step output, and any committed `evidence/` record must carry handle NAMES, booleans and verdict/identity fields only — no absolute host path, no internal seam-crate struct name, no stack trace (per §Error Handling; §Security Anti-Patterns → Logging). This binds CARRY 2's `WindowStation` / `UserInteractive` / `SessionName` witness output and any token/integrity-SID witness the new launcher emits.
- The inbound-listener ban binds Conductor's SHIPPED binaries; the harness-lifetime `4444`/`4445` driver ports are an explicit carve-out for the dev-only driver stack legs (per §Security Anti-Patterns → Universal). The scope states the trust boundary is unchanged — the requirement is that the medium-integrity launcher introduce no listener into a shipped binary and add no port beyond that carve-out.
- If the launch host is Rust FFI into Win32 token APIs, §Security Anti-Patterns → Universal requires review for `unsafe` across an FFI boundary; the ban names the OTLP/gRPC/SQLite surface explicitly, so whether it extends to a new Win32 surface is a classification P3/P4 must settle rather than assume.

## Patterns to follow
- The sixth form's admitting-control pattern: verify a non-repo-derived program BEFORE executing it (`Get-AuthenticodeSignature` status `Valid` + `O=Microsoft Corporation`), non-zero exit on either failing arm, both arms validated before the form ships (§Security Anti-Patterns → Code Patterns rule (b)).
- The seventh form's composition guard, which is the nearest precedent for a launcher whose API forces a command string: reject whitespace and metacharacters on every element first, surface rejection as a distinct named precondition at a distinct exit code, keep the form `-File`-only and never `-Command` (§Security Anti-Patterns → Code Patterns rule (b)).
- The CI-arm producer pattern for host-tool values: derive in the step shell behind a printed handle-NAMED boolean precondition and exit non-zero in CI where the dev host skips at exit 0 — handle name + boolean, never the resolved path (§Input Validation, `CONDUCTOR_MSEDGEDRIVER` row).
- The scrub/redact pattern for any witness value that can carry a host path: `&lt;host-path&gt;` substitution at write time with a `security_finding` marker, `&lt;redacted&gt;` rendering for path-valued gate fields (§Input Validation speech-log ingest row; §Security Anti-Patterns → Logging).
- The plain-step discriminator: a `run:` step invoking a fixed toolchain binary with fixed argv is NOT a governed form (established at amendment 2026-09-09); use it to classify whether the new launcher is a crossing or an ordinary step.

## Anti-patterns to avoid
- NEVER compose the launch through a shell / `eval`-equivalent with operator-supplied input — `Invoke-Expression` or a `-Command`-shaped vector is the banned shape (§Security Anti-Patterns → Code Patterns rule (b)).
- NEVER treat the registry move as routine or restate the rule more strictly than the master does — the 2026-09-16 operator ruling corrected an over-strict "array-form argv" restatement; registration is an enumeration amendment, never a relaxation and never a self-imposed stricter rule that manufactures a false violation (§Security Anti-Patterns → Code Patterns rule (b)).
- NEVER let CI logs, precondition text, or committed evidence leak absolute host paths or internal struct names (§Security Anti-Patterns → Logging).
