- The printed-verdict contract holds only where the INVOKING environment does not preempt the capture-then-print, and §3's binding contract requires identical `.sh`/`.ps1` semantics asserted of the SCRIPTS TOGETHER WITH the invoking environment — a caller diverges the `.ps1` leg with zero script delta (per test-plan §3 `--e2e` + §3 Bootstrap phases → `5-command-discipline-wire`). - The GATE step must never carry `continue-on-error` — a gate that can report success by skipping or erroring is exactly what the strict arm exists to forbid — while the diagnostic step SET around it is `continue-on-error`/`if: always()` and is named as a SET, not a count (per test-plan §9 Pipeline structure, E2E (webview) row).

## Patterns to follow
- Self-seeding before the session: `seedFixtureRuns()` clean-re-creates the gitignored fixture dir and invokes the `conductor-run` `envelope_fixture` target under `CONDUCTOR_E2E_SEED_DIR`, writing through the production writer and THROWING on a non-zero exit or missing journal; the driver spawn carries `CONDUCTOR_RUNS_DIR=runs/e2e-fixture` repo-relative (`resolve_under` rejects absolute) with cwd = workspace root (per test-plan §3 `--e2e`, §7 Self-bootstrapping requirement).
- Capture-then-assert: wdio output captured to `$RUNS_DIR/a11y-e2e.log`, exit read from the bare command, then the printed terms asserted (per test-plan §3 `--e2e`).
- Diagnostic-probe placement: `continue-on-error` + `if: always()` probe steps in the recorded order {driver+runtime versions · session isolation · cause probes · remote-debugging-pipe route} ahead of the `if: always()` `a11y-session-diag` upload, with the gate step outside that set (per test-plan §9 Pipeline structure, E2E (webview) row).
- Claim hygiene for the platform record: identify CI jobs BY NAME (`a11y` on `windows-2025`), never by `ci.yml` line coordinates, and state platform findings as measured SETs rather than fresh literals that re-stale (per test-plan §9 Matrix builds).
- Any touched routine spec keeps role/text/`aria-live` selectors and brand-anchor text — no xpath, no hashed CSS class (per test-plan §6 Selector strategy).

## Anti-patterns to avoid
- Never treat the leg's exit 0 as a pass, and never let the gate step carry `continue-on-error` or gain a retry policy (per test-plan §3 `--e2e`, §9 E2E row, §11 CI/Quality).
- Never substitute a manual/operator arm for the CI assertion — no manual smoke step, no human screenshot review; the ratified-exclusion outcome must be a recorded exclusion, not a human verification step (per test-plan §11 Universal).
- Never run a live-Pulse leg as a CI gate and never open a non-loopback network path; the routine arm carries no live Pulse and the WebDriver pair `:4444`/`:4445` is harness-lifetime only (per test-plan §11 CI + §11 Universal, §9 Live-Pulse scenarios).
