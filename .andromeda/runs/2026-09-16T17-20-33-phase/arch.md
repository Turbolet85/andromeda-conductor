## Constraints
- The `a11y` job's shape is locked: a third job on the explicit `windows-2025` label (pinned, not `-latest`, so the image cannot shift the Edge driver under the leg), running the routine leg under `CONDUCTOR_A11Y_STRICT` **launched through** `scripts/a11y-limited-token-launch.ps1` (leg entry point `scripts/a11y-token-witness.ps1`), then the reused `journal_conformance` gate over `runs/a11y`, then the violation-record upload — the asserting step carrying no `continue-on-error` and no `if:` (per architecture.md §Established Decisions [CI/CD] · §Infrastructure Patterns — Build system). A replacement or successor launcher must preserve every one of those properties.
- A new launcher belongs under `scripts/` at per-FILE grain in the directory tree, carrying the CI-only qualifier the two existing a11y scripts and `webview2-cause-probe.ps1` carry: invoked solely by `ci.yml`'s `a11y` job, wired into NEITHER harness shell, and adding **no sixth `agent-run.{sh,ps1}` command** — the 5-command harness surface is stated unchanged (per §Infrastructure Patterns — Directory structure · §Stack and Technologies, Operator instruments row).

- Environment handles are a registered namespace with typed classes: `CONDUCTOR_*` is reserved and each handle declares its class (path-valued operator handle · flag-valued · harness-owned path · strictness flag), while external names are registered on a reads-basis or a sets-but-never-reads basis; runner-process variables MUST be read in the step SHELL (`$env:X`), never through a `${{ env.* }}` expression, whose context holds only workflow/job/step declarations (per §Occupied Resources — Environment variables, `EDGEWEBDRIVER` · `RUNNER_TEMP` · `WEBVIEW2_*` entries). Any new handle this chunk's launcher sets or reads requires registration under one of those bases.
- The `--e2e` leg's build preconditions are structural, not incidental: `npm run build` must precede any workspace cargo compile of `conductor-tauri` (`generate_context!` resolves `ui/dist` at COMPILE time), and serving the embedded bundle turns on `--features tauri/custom-protocol`, not on the profile (per §Infrastructure Patterns — Build system). ## Anti-patterns to avoid
- A CI gate that can report success by skipping — the entire reason `CONDUCTOR_A11Y_STRICT` exists, and the strictness is an ADDED arm over the existing guards, never a relaxation of them (per §Occupied Resources — `CONDUCTOR_A11Y_STRICT`). Equally banned by the same logic: `continue-on-error` or an `if:` on the asserting step, and retry-to-green (the `ci` nextest profile is zero-retry because retries mask flakes, §Infrastructure Patterns — Build system).
- Widening the boundary silently. A new CI-time third-party binary/host dependency, a new egress, or a new listener is a boundary widening that is always the operator's call and never routine (per §Cross-cutting Patterns — Trust boundary · §Occupied Resources — Ports, the 2026-09-08 Evergreen precedent).
- Adding a sixth harness command, a new workspace member, or a shipped-binary reader for a CI-only mechanism — the nine-member crate roster and the 5-command surface are both stated as unchanged (per §Occupied Resources — Crate names · §Stack, Operator instruments row).
