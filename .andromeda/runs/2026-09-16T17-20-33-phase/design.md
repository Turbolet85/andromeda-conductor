## Constraints
- Any console-side change made to turn the routine arm green must bind tokens **by name** from the 34-token `:root` contract (colors / space / radius / motion), never a raw hex or px literal; the block is declared on plain `:root` with a `@media (prefers-color-scheme: light)` override, not `@theme` (per design-system §Surface: desktop-webview → Tokens).
- The text-tier values are contrast-solved artifacts, not free parameters: `--text-tertiary` and `--text-muted` carry the stated dark/light values specifically so they clear 4.5:1 on `--color-base` / `--color-raised-1` / `--color-raised-2` / `--color-inset`. An axe `color-contrast` finding from the routine arm must resolve to a token *pair*, not an ad-hoc hex at the use site (per design-system §Color Palette → Text Hierarchy). Whether the shipped `tokens.css` already carries these post-2026-09-01 values is research's question.
- Focus rendering is token-bound and is the only sanctioned `box-shadow`: `--color-focus` (`#7DCFFF` dark / `#0969DA` light) as a `0 0 0 2px` ring, never an elevation shadow — this is the visual substrate the `:384` (SC 2.1.1 reachability) and `:397` (SC 2.4.3 focus order) assertions read against (per design-system §Color Palette → Border Progression *Focus* and §Depth Strategy).
- The `@media (prefers-reduced-motion: reduce)` blanket override (`animation/transition: none !important`) is a mandated part of the token bundle, and ALL transitions must drop under it including the count-tint on a held count (per design-system §Motion → Hard limits, and §Tokens). If the routine arm ever asserts motion suppression, this is the required target state.
- If the console footer `contentinfo` strip is built (explicitly **not in scope** here), design requires flat borders-only elevation: `1px solid --border-subtle`, a surface-scale fill step, no shadow, no `backdrop-filter` (per design-system §Depth Strategy and §Anti-Patterns → Per-Surface Bans, desktop-webview). Design-system §Component Patterns 7 itself records the window footer strip as unbuilt, which is the same gap matrix-obligation 2 names.
- Any new CLI/harness output this launcher emits must reuse the closed label set and the existing recessive tier (Residual-mute ANSI 246 ↔ `var(--status-residual)`) rather than introducing a palette row or a new bracket prefix, and must be TTY-gated per-stream with `NO_COLOR`/`TERM` respected (per design-system §Surface: cli → Tokens and §Per-Surface Bans, cli).
- No status may be signalled by color alone; every state color pairs with a text label or glyph (per design-system §Anti-Patterns → Universal Bans and §Iconography → Rule).

## Patterns to follow
- **Reuse the recessive tier, don't add a row.** Three prior non-lamp captions (`hint:`, the out-of-scope Mode cell, `[ENVIRONMENT-SUSPECT]`/`[PRECONDITION]`) were all absorbed into ANSI 246 / `--status-residual` with zero new tokens — the precedent for any launcher/CI caption this chunk emits (per design-system §Surface: cli → Tokens).
- **Distinct states for "never measured" vs "failed".** `Blocked` (slate-violet hollow ring, carries a named precondition string) and `KnownResidual` (muted dashed dot, carries "expected until {named fix}") are the existing treatments for outcomes the machine did not fail — the direct analogue for a ratified exclusion or a leg that never reached its assertions (per design-system §Color Palette → Verdict vs ReportState note, and §Component Patterns 4).
- **"No result yet" is its own shipped state.** The report area ships no partial/failed prose while a run is unfinished; empty is the shipped `No run yet` / `No coverage data.` prose, never a gray skeleton and never a red downgrade (per design-system §Component Patterns 3 and 6).
- **Motionless verdict resolution.** The lamp resolves in place over a single 150ms `--motion-micro` color transition, always paired with text (per design-system §Component Patterns 4).

## Anti-patterns to avoid
- Never patch a routine-arm contrast failure with a new or inline hex — the fix is a token-pair correction in the `:root` contract (per design-system §Anti-Patterns → Universal Bans "NEVER use color purely for decoration" + §Tokens binding contract).
- Never render a CI/verdict failure as a flashing, pulsing, or animated alert, and never emit a native OS toast from Conductor (per design-system §Anti-Patterns → Rejected Defaults).
- Never collapse an excluded/unmeasured arm into red `Fail`, nor gray "no result yet" and "failed" identically (per design-system §Anti-Patterns → Rejected Defaults, "Conflating 'no result yet' with 'failed'").

## Contract bindings
- **Token contrast ↔ a11y §Contrast (SC 1.4.3):** the routine arm's axe `color-contrast` run is the enforcement point for the design token values; design owns the hexes, a11y owns the threshold. If the arm starts gating, a token regression becomes a CI red.
- **Motion tokens ↔ a11y SC 2.3.3:** the `prefers-reduced-motion` override in the token bundle is jointly owned (design-system §Motion hard limits explicitly names the binding).
- **State color + label ↔ a11y SC 1.4.1 (Use of Color):** the `[PASS]`/`[HOLD]`/`[FAIL]`/`[MANUAL]`/`[RESIDUAL]`/`[BLOCKED]` prefixes and the lamp+text pairing satisfy it on both surfaces.
- **Footer `contentinfo` ↔ a11y landmark rule + layouts:** design-system §Component Patterns 7 records the footer strip as unbuilt and the checklist's own `role=status` line as the substitute roll-up; the landmark ban itself is a11y's, the surface is layouts/route-owned, and the strip is out of this chunk's scope. Whether the console as shipped already satisfies the landmark requirement without it is research's question (matrix-obligation 2 demands a measurement, not an argument).

## Acceptance criteria contributions
- (design) Any console/token change introduced to clear a routine-arm finding uses only named tokens from the `:root` bundle — zero raw hex or px literals at use sites (per design-system §Surface: desktop-webview → Tokens).
- (design) If an axe `color-contrast` failure surfaces, the resolution moves a token value in both theme blocks and is re-checked against every pair that token renders on, not only the failing node's surface (per design-system §Color Palette → Text Hierarchy).
- (design) Any new launcher/CI status output reuses the closed prefix set and existing ANSI tiers — no new palette entry, no color-alone signal, per-stream TTY gating with `NO_COLOR`/`TERM` honored (per design-system §Surface: cli → Tokens and §Per-Surface Bans, cli).
- (design) An excluded or never-reached arm renders as `Blocked`/`KnownResidual` with its named precondition or "expected until {fix}" note — never as red `Fail`, never as an empty gray placeholder (per design-system §Color Palette → Verdict vs ReportState, §Anti-Patterns → Rejected Defaults).
