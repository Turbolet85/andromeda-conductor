An assertion whose pass/fail turns on how many times one environment's focus cycle wraps is the case that rule bars; restoring environment-independence is a §11 requirement, not a nicety.

- a11y-plan §10 → SLO Invariants and §11 → SLO ban any **retry-once policy** and any **soft SLO** for a11y results; green may not be obtained by tolerance, retry, or downgrading a failure to a warning.
- a11y-plan §9 (E2E artifacts row) permits a routine-arm spec to context-skip **only** when the seeded fixture cannot produce its DOM state, "never passing green," and records that **no routine-arm spec does so today**. Converting `:384` into a skip is therefore not an available route to a green verdict.

## Patterns to follow
- The §3 focus-management harness pattern: scripted `browser.keys(['Tab'])` traversal reading `document.activeElement` via `browser.execute(() =&gt; document.activeElement?.getAttribute('data-testid'))` after each key, over the one `@crabnebula/tauri-driver` + WebdriverIO session — the pattern `tabCycleNames()` (scope: `:185`) sits in.
- The measurement vocabulary a11y-plan §11 → Strategy already uses for this exact pair: `initialFocus` BODY, first Tab → "Minimize window" at **focusable index 0/5**, `tabsToStart` **5 over 5 focusables = a full cycle**. That is index/set/cycle language rather than a visit count, and it is the plan's own precedent for stating this property.
- §3 (Structured violation JSON schema): WebdriverIO-keyboard PASS/FAIL emits the same way as axe results — folded into the obs §6 envelope, `fingerprints[]` carrying the tuple, with artifacts barred from leaking absolute host paths or internal seam-crate struct names.
- §3 (CI integration → Command) and §9 (Pipeline integration): the routine arm rides `agent-run run --e2e` on the one `wdio run` webview leg and surfaces results through the **`logs`** command of tests' binding 5-command contract (boot / run / status / cleanup / logs).

## Anti-patterns to avoid
- **NEVER skip a11y on CI/operator-gate failure** (§11 → CI) — reaching green by letting the spec skip, or by weakening the expectation into something that cannot fail, is the indistinguishable-skipped-green case that ban exists for.
- **NEVER set `tabindex &gt; 0`** (§11 → Keyboard) — the §5 idle order relies on natural DOM/Radix order; the corrected assertion must keep that check live rather than absorb it.
- **NEVER use a retry-once policy or a soft SLO for a11y results** (§10, §11 → SLO) — masking is treated as equivalent to tests' zero-flakiness ban.
