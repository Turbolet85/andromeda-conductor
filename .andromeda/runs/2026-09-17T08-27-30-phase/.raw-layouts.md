## Constraints
- The idle console's interactive set is fixed by the wireframe: control row (scenario/suite picker, Start, Stop) plus the titlebar's minimize/close; the status strip is recorded DESIGNED, NOT SHIPPED with no `contentinfo` landmark, so no focusable chrome is mandated there (per layout-templates §Wireframe — Run console (idle), §Component — Footer (status strip)). Any counting basis must derive from that set; whether the shipped DOM's focusable set equals it is research's question.
- The invoking control must stay focusable — Start conveys unavailability with `aria-disabled`, never the native `disabled` attribute (per layout-templates §Component — Hero / signature section). A focusable query filtering `button:not([disabled])` must therefore still enumerate Start in every run state; whether the shipped DOM already satisfies this is research's question.
- Every interactive control must carry a visible `color-focus` ring, every hover affordance a keyboard equivalent, and the active picker item a `border-emphasis` edge so focus is never color-only (per layout-templates §Component — Primary navigation). "Reachable by Tab" is a layout property of the single window, not of a traversal tally.
- The frameless window IS the surface — no router, no routes, no deep links; the styled `AlertDialog` is the only modal and `alert()`/`confirm()`/`prompt()` are never used (per layout-templates §IA notes, desktop-webview). One document, one focus cycle: wrapping back to `BODY` is the expected shape of a single-station console, so the basis must tolerate ≥1 wrap.
- The titlebar's third zone is OS-conventional — standard Windows/Linux buttons vs macOS traffic-light style, each carrying an accessible name, with the drag region not leaking onto the controls (per layout-templates §Component — Header). The titlebar's contribution to the focusable set is platform-conditional by design, which makes any count-shaped expectation environment-sensitive at the layout level.
- The catalog LOAD-ERROR region's visually-hidden re-assertion is inserted once on the first `focusin`, while the three sibling error regions keep the mounted-empty shape (per layout-templates §Component — Primary content block 1, States). The DOM mutates during the first Tab, so a Tab-walk basis must be stable across that one-time insertion — whether it perturbs the cycle is research's question.
- The `--e2e` / a11y arm must assert the runner's PRINTED verdict — the `Spec Files:` failed count, the per-spec skip markers against the expected-skip set, and the `[webview2 … windows]` driven-session banner — because exit code alone cannot tell a full pass from a total skip; and an unresolved host-tool handle SKIPS at exit 0 on the default arm but exits non-zero under an affirmative `CONDUCTOR_A11Y_STRICT` (per layout-templates §Surface: cli — Primary screens, the `scripts/agent-run.{sh,ps1}` bullet).

## Patterns to follow
- Set-naming over baked literals: the plan's standing practice is to name the SET/mechanism and never a derived count ("every number manifest-derived, never a literal"; the de-literalized roll-up caption and `&lt;slo_tier&gt;` placeholders) — per layout-templates §Surface: cli — Primary screens (`conductor coverage [--write]`). The analogue is asserting the reachability property, not a visit tally.
- Signal always paired, never bare: lamps always paired with status text, mode labels always rendered so the classification survives `NO_COLOR`/piping — per layout-templates §Component — Primary content block 1 and §cli Component — Primary content block 2. The analogue is recording "12 visits / 6 distinct" rather than a bare count.
- Adapted per surface, never forked: the same contract is expressed per surface (CSS vars ↔ ANSI, the run-level qualifier SET) rather than branched — per layout-templates §IA notes (Multi-surface coordination). One basis must hold on both dev host and runner rather than forking per environment.
- Assert the printed artifact, not the process result: the cross-surface stage's assertion shape already exists on this surface — per layout-templates §Surface: cli — Primary screens (the `agent-run` bullet).

## Anti-patterns to avoid
- Do not adjust the console's focusable composition — adding/removing controls, shipping the unbuilt footer strip, or adding `tabindex` — to make a count reconcile (per layout-templates §Wireframe — Run console (idle), §Component — Footer).
- Do not shrink the focusable set with the native `disabled` attribute (per layout-templates §Component — Hero / signature section).
- Do not explain the runner/dev-host divergence with a route, breakpoint or second surface: the console has no router and no responsive breakpoints (per layout-templates §IA notes, §Decisions Log — Responsive breakpoints).
