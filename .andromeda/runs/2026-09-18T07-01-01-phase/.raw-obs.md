# obs extract

## Relevance
Partial — the chunk ships a committed posture/grading statement and a clippy discharge, not instrumentation; obs owns the verdict-record vocabulary, the latency/SLO arithmetic and the CI-gate boundary that the statement must be written against.

## Constraints
- The grading rule's verdict vocabulary is bounded by the eleven-field run-report envelope's closed sets (`verdict`: Pass | Fail | CalibrationRegion; `state`: Pass | Fail | ManualCheck | KnownResidual | Blocked), and per-scenario envelope EXTRAS are an extension point with no known scenario instance — the one ever named was retired as never implemented, and the only exercising artifact carries resource TAGS, not scenario fields (per obs-plan §3 Log format JSON schema, §6 Required fields). A rule that mints a new grade word or a new envelope key is outside the schema; whether a real-model leg's record already conforms is research's question.
- Per-leg quiet-window and budget arithmetic must be stated against obs-plan's measurement definition: `latency_ms = read_back_observed_at − journal_emitted_at`, wall-clock, covering the scenario's WHOLE emission window rather than the MCP round-trip, asserted at report-generation time against exactly three tiers `&lt;5s | &lt;20s | &lt;90s` (per obs-plan §10 Performance budgets; §4 Known-residual → Delegated-timing latency note). The scope's `[inferred]` ~110s real-model formation sits above the largest tier — obs-plan §10 requires the assertion, so the posture must say which tier (or what non-tier disposition) a real-model leg carries; whether the shipped enum admits anything above `&lt;90s` is research's question.
- A miss, a non-determination or a malformed/absent model output must resolve to a RECORDED verdict, never an uncaptured panic and never a retry: obs-plan §10 requires the zero-unlogged-panics invariant with `std::panic::set_hook()` + `tracing::error!` + the anyhow edge; §11 Error Reporting requires malformed child/transport input to become `blocked` (typed `Ok`), never a panic; §11 SLO bans retry-once policies because they mask real failures. The scope's "a failing leg grades as a failure rather than being re-driven" is the same requirement on the posture side.
- With deterministic L4 off, the degraded signal stays OBSERVED, not requested — Pulse computes `degraded_mode` as `parsed_l4.is_none()` and returns it in the `retrieve_report` result, riding a `warn`-level line on the allowlisted `message` field (per obs-plan §4 Known-residual classification path). A grading rule with a "model produced nothing usable" arm must define it over that observed result, not over a request-side flag.
- No new span name and no new span attribute may be introduced for grading: §11 Spans/Traces fixes a bounded span-name set (`scenario.run`, `timeline.execute*`, `emit.batch`, `emit.logs_batch`, `verify.readback*`, `report.generate`, `db.insert_run`, `fault.*`, `tauri.command.*`), and §4's Required-span-attributes heading requires every attribute name to be in `conductor-core::redact::ALLOWLISTED_FIELDS` or the processor stage drops it (per obs-plan §4, §11).
- "Never a CI gate" is an obs-side statement as well: obs-plan §9 enumerates the pipeline stages, the telemetry-artifact table and the two obs CI gates (log conformance over the §3 self-obs base schema + host-path freedom; zero-unlogged-panics), and §10 enumerates the build/deploy failure conditions. If a real-model leg ever routes an artifact into CI, those gates bind it — so the posture must state the leg's exclusion rather than leave it to the invocation path (per obs-plan §9, §10).
- The PREREQ clippy run carries no telemetry obligation: obs-plan §1 classifies the `cargo build / CI/CD` row (fmt, build, nextest, clippy) Not-instrumentable — build-time, no runtime signal — and §9 routes clippy warnings to stderr as CI annotations, non-blocking at Minimal per §10 (per obs-plan §1, §9, §10).

## Patterns to follow
- The SUT-facing committed contract precedent named inside obs-plan itself: `contracts/pulse-p025-measurement-contract.md`, which states the quantity to be exposed, its exhaustive case split, and an explicit ban on expressing a Pulse-side quantity through journal-relative terms (`latency_ms` / `budget_ms` / `effective_deadline_ms`) — per obs-plan §4 Known-residual → Delegated-timing family. Same form fits a posture/grading statement the drive chunk is bound by.
- Harvest-tier grading over Pulse's own tracing lines when the graded quantity is not Conductor's: each claim read from its OWN exact allowlist leaf, never through the journal-relative budget fields, with the caution that the duration field name is not uniform across leaves (`duration_ms` vs `value`) — per obs-plan §4 Known-residual → Delegated-timing family.
- Live legs reuse the standard chain `scenario.run` → `timeline.execute` → `emit.batch` → `verify.readback*` → `report.generate` plus the standard eleven-field envelope; family-specific chains and per-family envelope extras are recorded as never-built and retired — per obs-plan §4 Restart-suppression and Severity-lifecycle scenarios.
- The declare-only landing shape for a claim that is structurally ungradeable: `verdict` null, `state` KnownResidual, no extra field — per obs-plan §4 Restart-suppression / Severity-lifecycle. Available as the "not assertable" arm of a grading rule.
- Evidence that has no allowlisted field name rides the already-allowlisted `message` value (the MCP key-set witness, the `emit.batch` wire-shape witness, the incident id) — per obs-plan §6 Boundary-call wrappers.

## Anti-patterns to avoid
- Never widen the bounded span-name set or attach a non-allowlisted span attribute to carry grading evidence — it emits nothing at the processor stage (per obs-plan §11 Spans/Traces; §4 Required span attributes).
- Never define a soft SLO budget with no enforcement, and never add a retry-once policy around a failing leg — SLO assertions are evaluated at report-generation time as JSON field assertions (per obs-plan §11 SLO).
- Never leak absolute host paths or internal struct names into logs, the run-report artifacts or committed leg evidence; §11's own standing warning is that the three enumerated application sites bound only the sites they name, never every channel (per obs-plan §11 Logs, §11 PII Scrubbing).

## Contract bindings
- obs ↔ tests harness: the eleven-field JSONL envelope obs-plan §3/§6 reproduce is OWNED by test-plan §3 (obs aligns to tests, not vice versa) — any grading-rule change to the record's fields or closed sets must land on both sides.
- obs ↔ CI (§9): the log-conformance gate (§3 self-obs base schema + host-path freedom) and the zero-unlogged-panics gate attach to any artifact the leg routes into CI; the posture's "never a CI gate" property is the statement that keeps it out of §9's pipeline and artifact tables.
- obs ↔ SUT/Pulse contract: obs-plan §4 names `contracts/pulse-p025-measurement-contract.md` as the committed form for a Pulse-side measurement ask, with the journal-relative-term ban — the natural home the scope's `contracts/` `[inferred]` points at.

## Acceptance criteria contributions
- The committed grading rule maps every outcome (hit, miss, no-usable-model-output) onto the envelope's closed `verdict`/`state` sets and adds no scenario-specific envelope field (per obs-plan §3 Log format JSON schema / §6 Required fields).
- The per-leg quiet window and budget arithmetic are stated against `latency_ms = read_back_observed_at − journal_emitted_at` as a whole-emission-window wall-clock span and against §10's three tiers, naming the disposition when a real-model formation exceeds `&lt;90s` (per obs-plan §10 Performance budgets).
- The miss arm resolves to a recorded verdict — no uncaptured panic, no retry/re-drive path (per obs-plan §10 zero-unlogged-panics / §11 SLO no-retry-once).
- The posture introduces no new span name and no non-allowlisted span attribute; any grading evidence lacking an allowlisted field rides the `message` field (per obs-plan §11 Spans/Traces / §6 Boundary-call wrappers).
