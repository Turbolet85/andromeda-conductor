# a11y extract

## Relevance
**partial** — no UI surface, component, or WCAG criterion is added, but the chunk edits the operator-gated `--live` suite and its `preconditions` short-circuit in `scripts/agent-run.{sh,ps1}`, which is the declared carrier of a11y's operator-only `driven` arm (`driven-a11y`) and the home of the per-arm quiet-window/timing budget a11y-plan states.

## Constraints
- The `--live` suite's `driven-a11y` leg is a11y's operator-only DRIVEN arm, owner of the hold-dependent Operable claims (trap entry, containment, restoration); a11y-plan §9 (E2E artifacts row) and §11 *Strategy* (the 2026-09-07 carve-out as narrowed/extended 2026-09-17) require that arm to keep its stated owner and posture — a real-model posture added beside it must not re-scope or re-grade it (the scope's own boundary says the same).
- a11y-plan §11 *Strategy* requires the hold-dependent half to stay barred from CI because the hold fires only behind a preflight-ready live Pulse (citing test-plan §11 + architecture §Established Decisions [CI/CD]); a "never a CI gate" posture for a real-model leg must be stated compatibly, and must not re-route any live-Pulse-requiring a11y assertion into CI.
- a11y-plan §11 *CI* requires that the fail-fast gate not be defeated by a skip: the leg's host-tool guard is designed to skip at exit 0, so `CONDUCTOR_A11Y_STRICT` must make an unresolved handle exit non-zero and both harness shells must assert the runner's PRINTED verdict (failed count, per-spec skip tally against the expected-skip SET, driven-session banner). Any change to the `preconditions` short-circuit is in this mandate's blast radius.
- a11y-plan §11 *Strategy* fixes the substitute gate CI runs in place of the driven arm: the expected-skip SET held at exactly two under `CONDUCTOR_A11Y_STRICT`, the committed claim→owner enumeration, and its checker. A posture change that alters the routine arm's skip tally or leaves a claim unowned breaks that gate.
- a11y-plan §10 (per-arm performance budget) states the driven arm's timing envelope — a 15-minute mocha ceiling and a quiet-window precondition costing two 12-minute runs when violated. Whether the quiet-window arithmetic this chunk fixes still matches that stated envelope is research's question; if it diverges, §10 is owed an amendment.
- a11y-plan §10 + §11 *SLO* forbid retry-once policies and soft SLOs for a11y outcomes; the chunk's grading rule ("a leg that fails grades as a failure rather than being re-driven until it passes") must hold for any a11y-carrying leg in the same suite, not only the real-model one.
- a11y-plan §1 (the `conductor-cli` entity, set-scoped so added verbs stay covered) and §11 *Universal* require the cli/contracts surface to be treated as not-assertable — a committed posture document and any new `agent-run` flag or verb owe no WCAG assertion.

## Patterns to follow
- **Claim → owner → substitute-gate statement** (a11y-plan §11 *Strategy*, §5 focus-order bullets as amended 2026-09-17): each claim names the arm that asserts it, states what CI structurally cannot run and why, and enumerates what gates in its place *stated as not a substitute*. The posture's "operator-gated, never a CI gate" property should be written in this same form.
- **Verdict stated with its configuration** (a11y-plan §1 CI integration, §11 *Strategy* as amended 2026-09-17): green/red endpoints are recorded bound to runner label, runtime, driver and coherence rather than as bare verdicts — the discipline a dated, committed posture statement should inherit.
- **Host-tool handle with skip-at-exit-0 plus a STRICT override** (a11y-plan §9 E2E row: `CONDUCTOR_NVDA` unset ⇒ skip at exit 0; §11 *CI*: `CONDUCTOR_A11Y_STRICT` flips that to non-zero) — the existing precedent for expressing an environment-dependent leg's disposition without producing skipped-green runs.
- **Attribution-rot checker** (a11y-plan §11 *Strategy*): a committed claim→owner enumeration plus a checker that fails when the named owner's spec is missing or asserts nothing — the precedent for making a stated posture mechanically checkable rather than prose-only.
- **5-command harness discipline** (a11y-plan §3 CI integration / §9 Pipeline integration): boot / run / status / cleanup / logs, with `logs` the artifact-emitting command a11y results surface through — any new arm should ride the same command surface rather than a parallel one.

## Anti-patterns to avoid
- **Never let a gate failure become a skip** (a11y-plan §11 *CI*): a `preconditions` short-circuit that exits 0 makes a skipped-green run indistinguishable from a real pass — the exact failure mode `CONDUCTOR_A11Y_STRICT` + the printed-verdict assertion exist to prevent.
- **Never a retry-once policy or a soft SLO** (a11y-plan §11 *SLO*, §10): no re-drive-until-pass path, and no downgrade of a failing leg to a warning.
- **Never stand up a second automation stack or a second gate lane for a11y-carrying legs** (a11y-plan §11 *CI*, second-stack ban): a real-model arm must ride the one webview-automation stack / existing harness surface, not a parallel one.

- **a11y ↔ obs:** any artifact this chunk's posture causes to be emitted inherits a11y-plan §3's obs §6 envelope alignment and §9/§11's constraint that artifacts must not leak absolute host paths or internal seam-crate struct names.

## Acceptance criteria contributions
- The existing `driven-a11y` leg keeps its stated owner, its posture and its results unchanged; the real-model posture is additive and re-grades nothing (per a11y-plan §9 E2E artifacts row + §11 Strategy).
- Changes to `agent-run.{sh,ps1}` leave the anti-skip mechanism intact: `CONDUCTOR_A11Y_STRICT` still forces non-zero on an unresolved handle, and the printed-verdict assertion (failed count + expected-skip SET of exactly two) still holds (per a11y-plan §11 CI + §11 Strategy).
- The grading rule introduces no retry-until-pass or soft-verdict path for any leg in the suite that carries a11y assertions (per a11y-plan §10 SLO Invariants + §11 SLO).
- The stated per-leg quiet window and serialization rule remain consistent with the driven arm's recorded per-arm budget, or the divergence is recorded as an owed a11y-plan amendment (per a11y-plan §10 Performance budget per a11y CI run).
