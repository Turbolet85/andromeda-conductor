## Constraints
- **The verdict/error wall governs the grading rule.** Verification outcomes are VALUES — `Verdict {Pass, Fail, CalibrationRegion}` / `ReportState {Pass, Fail, ManualCheck, KnownResidual, Blocked}` returned as `Ok(...)`; `Result::Err` is reserved for harness faults (transport down, MCP unreachable, config parse). Any rule this chunk writes for "top hypothesis misses the injected root cause" must land on that closed value set, never on an `Err` (per architecture.md §Established Decisions [Error Handling] · §Cross-cutting Patterns — Verdict/error wall).
- **Which state a miss maps to is constrained by the Probabilistic-Assertion Policy, not free choice.** Model-interpretive claims (severity choice, **hypothesis quality**, root-vs-deep weighting) are calibration-region + report-for-human and are "never hard-failed on exact values"; the default mapping is `Pass→Pass` / `Fail→Fail` / `CalibrationRegion→ManualCheck` via `Verdict::default_report_state`, with `verdict`/`state` independent and the report lamp chosen verdict-first. A grading rule that hard-fails a top-hypothesis identity claim must reconcile with this policy explicitly rather than silently (per architecture.md §Established Decisions [Probabilistic-Assertion Policy]).
- **The live-Pulse exclusion from CI is an architectural boundary, already stated in the form this chunk needs.** "Dynamic end-to-end scenario proof requiring a live Pulse … is an explicit operator/local gate, not a CI gate — **the exclusion is the live-Pulse dependency, not the end-to-end tier**"; and Pulse-freedom is NECESSARY, not sufficient, for CI candidacy (per architecture.md §Infrastructure Patterns — CI/CD approach · §Stack CI/CD row). Whether the current `run --live` invocation path already realizes an operator-only gate for a real-model arm is research's question.
- **The two Pulse-side levers this chunk's posture names are registered handles with fixed semantics.** `ANDROMEDA_PULSE_L4_DETERMINISTIC` is asserted **not set by Conductor** and is READ as one of two run-contract `shell-declaration` proxies (with `ANDROMEDA_PULSE_MCP_ENABLED`), an absent declaration surfacing as an unmet term naming both candidate causes, never a claimed measurement of `pulse-app`. `ANDROMEDA_PULSE_BASELINE_BOOTSTRAP_SECONDS` is the ONE registered handle Conductor neither sets nor reads, is a **BOOT-TIME** posture (`Thresholds::from_env()`), hence **boot-wide rather than per-leg**, and is registered only because a shipped artifact names it in its own output (per architecture.md §Occupied Resources — Environment variables). A posture that needs it per-leg conflicts with its boot-wide resolution; whether the shipped shells already state its disposition is research's question.
- **A committed posture/measurement artifact under `contracts/` inherits one of two regimes, and the split is structural.** The four runtime-read manifests resolve from a fixed `default_path()` through `resolve_under` with deliberately **no `CONDUCTOR_*` override handle** and are bounds-checked at load (absent/malformed = harness fault, never a verdict); `contracts/pulse-p025-measurement-contract.md` is the precedent for a member with **no Rust reader** — no `default_path()`, no `resolve_under`, no bounds check, no override handle — and its `provenance` must state whether it is a Conductor measurement or a transcribed SUT record (per architecture.md §Occupied Resources — On-disk artifacts).
- **The harness command surface is fixed at five.** Arch records twice that added scripts "add no 6th command" and that "the 5-command harness surface is unchanged" — a real-model arm must ride an existing verb/flag, not a sixth `agent-run.{sh,ps1}` command (per architecture.md §Stack — Operator instruments · §Infrastructure Patterns — Directory structure).
- **Scope law and the trust boundary are unchanged by a live leg.** No inbound listener, loopback-only, the single deliberate port-bind exception being the port-occupier fault; "no scenario without a P-ID" (per architecture.md §Cross-cutting Patterns — Trust boundary · Scope law).

## Patterns to follow
- **The run contract's three `check` kinds are the vocabulary for stating posture terms honestly** — `shell-declaration` (observable in Conductor's OWN environment; the only kind that can block), `asserted` (satisfied by construction), `declared-not-observable` (true on the SUT's side with no read-back surface; recorded, never blocking, because blocking would claim a measurement Conductor cannot make). Arch also records two `asserted` rationales measured FALSE (`warmup_ms`, `sidecar-built`) — the failure shape to avoid when classifying a new term (architecture.md §Occupied Resources — `contracts/pulse-run-contract.toml`).
- **Committed-artifact-plus-static-gate**: each CI static gate asserts a committed artifact against the production source it derives from, is its own named step with no `continue-on-error`/`if:`, and opens with a presence guard on its subject so an absent subject fails loudly rather than passing vacuously; the gate IS the Rust test, never a re-listed shell copy (architecture.md §Established Decisions [CI/CD] · §Infrastructure Patterns — CI/CD approach).
- **Per-leg self-obs capture for a live suite already has a registered site**: `runs/live-suite/{leg}.jsonl`, harness-owned by `scripts/agent-run.{sh,ps1}`, no `CONDUCTOR_*` handle of its own, moving with `CONDUCTOR_RUNS_DIR`, git-ignored, LEG-stemmed, cleared per suite invocation by a non-recursive `rm -f …/*.jsonl` — because `logs/agent-latest.jsonl` truncates per invocation (architecture.md §Occupied Resources — On-disk artifacts).
- **Serialization/quiet-window arithmetic has stated SUT mechanics to anchor on**: the dedupe tuple `(kind, scope, scope_id)` within a workspace-scoped candidate set (at most one active incident per tuple), Pulse's 120s idle + 30s resolver tick, the L3 digest cadence floor already expressed as `[incident_formation].min_canary_poll_seconds` raising `CONDUCTOR_PREFLIGHT_TIMEOUT`'s effective floor, and the bootstrap-window mechanism that makes the auto-resolve arm REACHABLE rather than RELIABLE (architecture.md §Established Decisions [Read-Back Dependency Posture] · §Occupied Resources — `CONDUCTOR_PREFLIGHT_TIMEOUT`).
- **Report-state routing already shipped as `route_read_back` / `ReadBack {Graded, AutoResolved, Blocked}`** (crate-private, `conductor-run`), with `degraded` a PER-read-back property and every read-back CALL failure landing `Blocked` unconditionally — the existing router a real-model grading rule must compose with rather than duplicate (architecture.md §Established Decisions [Read-Back Dependency Posture]).

## Anti-patterns to avoid
- **Do not express a failed real-model leg as `Result::Err`, nor invent a sixth report state** — the five-variant `ReportState` and three-variant `Verdict` sets are closed (architecture.md §Conventions — Error handling · §Standard Contracts — Run report envelope).
- **Do not classify a posture term as `asserted` when a non-Conductor-observable condition decides it** — the `warmup_ms` / `sidecar-built` shape, where the term is satisfied-by-construction exactly when it is false and cannot catch its own falsity (architecture.md §Occupied Resources — `contracts/pulse-run-contract.toml`).
- **Do not add a `CONDUCTOR_*` override handle for a new `contracts/` artifact, and do not make a live-Pulse-dependent arm a CI gate** — both are standing bans (architecture.md §Occupied Resources — On-disk artifacts · §Infrastructure Patterns — CI/CD approach).

## Contract bindings
- **Grading rule ↔ tests/obs**: the run report envelope (eleven fields) and the nine-key `CheckRecord` are the shapes any graded real-model outcome must serialize into across the JSONL journal, the `run_check` table and the Markdown report; a blocked or declare-only scenario emits ZERO check records, and `run_check`'s `latency_ms`/`deadline_ms` are NOT NULL (architecture.md §Standard Contracts — Run report envelope · Per-check record · §Occupied Resources — `runs.db`).
- **Posture terms ↔ security/obs redaction**: every precondition string is host-path-free (`data_dir` redacted), and the `ANDROMEDA_PULSE_*` probe reporting is name-only — a finding names handles, never values (architecture.md §Standard Contracts — Readiness gate / Liveness equivalent · §Occupied Resources — Environment variables).
- **Operator gate ↔ CI**: the `rust`/`a11y` job gate-set enumeration in §Established Decisions [CI/CD] is the place a "never a CI gate" property is asserted-by-absence; the enumeration is amended at wrap when the gate set moves.
- **Quiet-window arithmetic ↔ timing model**: latency is always `read_back_observed_at − journal_emitted_at`, never wall-clock-from-test-start, and a per-check `budget_ms` yields an effective deadline via `ExpectedCheck::effective_deadline_ms(tier)` (architecture.md §Established Decisions [Timing-Tolerance Model]).

## Acceptance criteria contributions
- (arch) A miss of the top-hypothesis claim maps onto the closed `Verdict`/`ReportState` sets as an `Ok` value, never a `Result::Err`, and the mapping is reconciled explicitly against the `CalibrationRegion→ManualCheck` default rather than silently overriding it (per architecture.md §Established Decisions [Probabilistic-Assertion Policy] · [Error Handling]).
- (arch) The real-model leg is stated as an operator/local gate and appears in no CI job's gate set; if anything lands in `.github/workflows/ci.yml`, it is Pulse-free and carries no live-Pulse dependency (per architecture.md §Infrastructure Patterns — CI/CD approach).
- (arch) Any new `contracts/` member declares which regime it takes — runtime-read (fixed `default_path()` + `resolve_under`, bounds-checked at load, no `CONDUCTOR_*` override, absent/malformed = harness fault) or reader-less (the `pulse-p025-measurement-contract.md` precedent) — and carries `sut_version` / `captured_at` / `provenance` stating whether its terms are a Conductor measurement or a transcribed SUT record (per architecture.md §Occupied Resources — On-disk artifacts).
- (arch) No sixth `agent-run.{sh,ps1}` command, no new `CONDUCTOR_*` env var beyond the registered namespace, and no new inbound listener or non-loopback egress (per architecture.md §Stack — Operator instruments · §Occupied Resources — Environment variables/Ports · §Cross-cutting Patterns — Trust boundary).
