## Constraints
- The `ANDROMEDA_PULSE_L4_DETERMINISTIC` disposition the posture fixes is a **declaration-only read** of Conductor's OWN environment (`conductor_core::OBSERVED_HANDLES`, value-only `flag_declared`): nothing to validate, no value may become a path, an argv element or a log value, and an absent declaration must surface as an unmet run-contract term and/or a named `[PRECONDITION]` subject — **never as a claimed measurement of `pulse-app`**, because Conductor launches no Pulse process and cannot inspect one (per security-plan §Input Validation, declaration-only READ SET row). The posture must state the flag's disposition in that voice; whether the current code already grades it this way is research's question.
- `ANDROMEDA_PULSE_BASELINE_BOOTSTRAP_SECONDS` appears in **no** boundary row, no handle enumeration and no non-secret handle inventory of the plan. §Input Validation is an exhaustive enumeration of external-input surfaces (per security-plan §Input Validation; the enumeration duty restated across the 2026-08-10 / 2026-09-02 / 2026-09-07 handle-class amendments), so whichever reader the posture assigns it — a Conductor binary, a harness shell, or neither (operator export only, consumed SUT-side) — determines whether a row is owed. **Which reader exists is research's question**; the duty binds per READER, not per handle (per security-plan §Security Anti-Patterns → Input).
- If the committed posture/grading statement is ever **parsed at runtime** (by a shipped binary OR a test binary), §Input Validation's committed-manifest row attaches: serde typed parse + explicit `validate()`, a fixed non-operator-steerable path with deliberately no `CONDUCTOR_*` override handle, absent/malformed a hard fault **never defaulted and never silently widened**, and read faults carrying `e.kind()` only, never the path (per security-plan §Input Validation, committed SUT-facing manifests row). A code-**unread** prose statement (the `pulse-p025-measurement-contract.md` precedent the scope cites) attaches no such row — the chunk must settle which it is.
- The quiet-window / per-leg budget arithmetic must be derived from the **validated** `contracts/pulse-run-contract.toml` terms (`warmup_ms`, `min_canary_poll_seconds`), which the harness shells parse under the never-defaulted rule: a missing term is a hard exit 2, and a lowered `CONDUCTOR_PREFLIGHT_TIMEOUT` **clamps up to the contract floor rather than down** (per security-plan §Input Validation, committed-manifests row). A real-model window may lengthen a budget; it may not derive one that lowers the preflight floor.
- The grading rule must route through the **verdict/error wall**: verification outcomes stay typed VALUES (`Verdict` / `ReportState`) returned as `Ok(...)`, `Result::Err` stays reserved for harness faults, and a failed preflight must **never be silently downgraded** to pass/fail/manual-check — each of the FIVE named preconditions surfaces as the distinct `blocked` state with its own precondition string, and a term whose truth lives SUT-side is recorded `declared-not-observable` and never blocks (per security-plan §Error Handling; §Security Anti-Patterns → Universal). A real-model miss must therefore map to a graded `Verdict`/`ReportState`, distinguishable from `blocked`.
- The committed posture statement is an agent-parseable artifact shared across hosts: it must carry **no absolute host paths** (canonicalized `CONDUCTOR_*` directories, `ANDROMEDA_PULSE_DATA_DIR` values), no internal seam-crate struct names, and no secret-shaped string (per security-plan §Security Anti-Patterns → Logging; §Error Handling, run-report artifact sanitization; §Security Anti-Patterns → Secrets). Stating an operator launch recipe is the exact shape that leaks a data-dir value.
- Merging still requires the supply-chain gate green — `cargo audit` (+ recommended `cargo deny check advisories bans licenses sources`) with `Cargo.lock` committed and un-drifted (per security-plan §Security Anti-Patterns → Universal; §Dependency Security). If the audit reads red, the **porcelain check on the local advisory-DB checkout PRECEDES** classifying the fault as external (per security-plan §Dependency Security, two-external-decay-faults block). The chunk's PREREQ (clippy) is a lint, not this gate.

## Patterns to follow
- **Declaration-only observation, not measurement** — `conductor_core::{flag_declared, handle_declared}` called per handle by `conductor_run::observe_preconditions`, rendering handle NAMES only, with `declares()` in `conductor-run` retained as the thin wrapper serving the run contract's `shell-declaration` terms (per security-plan §Input Validation, READ SET row). A real-model posture term for the L4 flag should be authored in this shape.
- **The leading `conductor preconditions` short-circuit on the path SET `{boot, run --live}`** — on `run --live` it is a REFUSAL at exit 1 naming each unsatisfied subject with **no leg fired and no sidecar spawned**, rather than a degraded ~0s `[BLOCKED]` row (per security-plan §Security Anti-Patterns → Universal). A real-model arm added beside the `--live` suite should inherit this arm, not bypass it.
- **Run-contract term shape** — every `[[term]]` carries a unique id, a statement AND its candidate causes, and every `shell-declaration` term names the env var it observes (per security-plan §Input Validation, committed-manifests row). Any new posture term follows this shape.
- **Harness-spawn rule (b) forms** — fixed/repo-derived program, array-form argv, operator-supplied values only as separate argv elements after shell-metacharacter rejection, never a shell string and never as the program except through a guarded host-tool path (per security-plan §Security Anti-Patterns → Code Patterns). The existing `conductor cleanup <run_id>` form on the routine `agent-run.{sh,ps1}` path is the nearest precedent.
- **Sidecar spawn rule (a) is untouched by this chunk** and must stay so — fixed program NAME through inherited `PATH`, `ANDROMEDA_PULSE_DATA_DIR` via `.env(...)` only with metacharacter rejection, `CREATE_NO_WINDOW`-class console suppression (per security-plan §Security Anti-Patterns → Code Patterns rule (a)).

## Anti-patterns to avoid
- **Never make the real-model leg a CI gate or otherwise put a live-Pulse scenario proof on the CI path** — dynamic end-to-end scenario proof is an explicit operator/local gate (per security-plan §Threat Model Summary → Infrastructure → CI/CD); and never add an interactive prompt to the headless `scripts/agent-run.sh` source-of-truth path (per security-plan §Security Anti-Patterns → Authentication).
- **Never introduce a new harness spawn form, inbound listener or network reach in the real-model arm** — a new governed spawn crossing is a boundary widening that escalates to the operator every time and may never be routinised (per security-plan §Security Anti-Patterns → Code Patterns rule (b); §Security Anti-Patterns → Universal, inbound-listener ban).
- **Never let the grading rule read an absent/unparseable signal as satisfied** — the degrade DIRECTION is the security-relevant half: a missing stamp or empty round-trip reads as NOT-fresh ⇒ `blocked`, never a false pass (per security-plan §Input Validation, MCP child-stdout row; §Security Anti-Patterns → Universal).

## Contract bindings
- **obs ↔ security:** the grading rule's verdict lands in the run-report/`runs.db`/journal artifacts, which security mandates be sanitized (identity + verdict/state fields only; a `blocked` row populates identity fields with the named precondition string and JSON `null` measurement fields) — obs owns the field schema, security owns the redaction rule (per security-plan §Error Handling, run-report artifact sanitization).
- **tests ↔ security:** the "never a CI gate" property binds to the tests plan's CI-integration section — the supply-chain/security gate stays a CI job while the real-model leg stays operator-local; both live in one workflow.
- **arch ↔ security:** the run-contract term set and the `declared-not-observable` disposition are arch/contract decisions that security constrains but does not own.
