# tests extract

## Relevance
Relevant — the chunk fixes a live-leg launch posture, a grading rule and a quiet-window/serialization rule, all of which test-plan §3/§6/§9/§10/§11 own; it ships no new test code but its PREREQ is the lint-gate discharge §9's stage table requires.

## Constraints
- A real-model live leg must be **operator/local-gated and never a CI gate**, and its invocation must fall inside the sanctioned live-leg SET (`workflow_dispatch` · `scripts/agent-run.{sh,ps1}` incl. the composed `run --live` · a cargo-feature-gated test target invoked directly · an npm-script wdio suite) — extending that SET is an amendment, and the SET is stated by membership, never by a count (per test-plan §9 Live-Pulse scenarios, §11 CI).
- The grading rule must land inside the closed envelope vocabulary: `verdict ∈ {Pass, Fail, CalibrationRegion}` and `state ∈ {Pass, Fail, ManualCheck, KnownResidual, Blocked}`, over the eleven-field envelope, with the assertion-policy split enforced — only a hard `Fail` is a non-zero process exit (per test-plan §3 Status endpoint shape, §3 `run` exit-code semantics).
- A model-interpretive claim is the `CalibrationRegion` class — "report-for-human, never hard-failed" — which is how severity *choice* is already mandated to grade; the rule must state explicitly which side of that line a top-hypothesis identification falls on rather than leaving it implied (per test-plan §6 Scenario: Severity-lifecycle, §11 E2E stack-specific).
- A new non-deterministic real-wall-clock leg is admissible only as a member of the enumerated operator-local exceptions to the determinism invariant; outside that enumeration it reads as a §10 zero-flakiness break, so the posture must state its membership (per test-plan §2 Agent-runnable invariants, §10 Zero-flakiness budget).
- Retry-to-green is banned at every tier — no nextest `retries`, no retry-once policy, a flake is quarantined and fixed at the cause; v3-09's "a failing leg grades as a failure rather than being re-driven until it passes" is that same rule at leg grain (per test-plan §10 Zero-flakiness budget, §11 Quality).
- The per-leg quiet window must be a **harness-level wait BETWEEN legs** whose arithmetic reproduces a documented SUT-side precondition (the dedupe window: idle interval + resolver tick) — it is a firing-form precondition, not a synchronisation device, and nothing inside a test may sleep to synchronise (per test-plan §11 E2E `sleep(N)` ban scope).
- Timing terms must be **derived, never literal**: the preflight floor and the wall-clock wrapper both derive from `contracts/pulse-run-contract.toml` (`min_canary_poll_seconds`; `warmup_ms/1000 + poll + margin`), a missing term being a hard exit 2 — a real-model leg's budgets must respect that floor rather than restate a number (per test-plan §3 `boot` Timeout).

## Patterns to follow
- **Full-firing-form recording** (per test-plan §6 drivers-per-surface, driven arm): a live arm's complete precondition set is part of the leg, not an optional extra — `PATH`-resolved `andromeda-pulse-mcp`, `ANDROMEDA_PULSE_MCP_ENABLED`, `ANDROMEDA_PULSE_L4_DETERMINISTIC`, `ANDROMEDA_PULSE_DATA_DIR` equal to the live Pulse's data dir, and the quiet window — because each unmet precondition misreads as something else (a bare invocation returns BLOCKED in ~2ms, indistinguishable from a genuine gate failure). A real-model posture is the same list with the deterministic term inverted plus an explicit disposition for the boot-wide bootstrap-window lever.
- **Composed-suite shape** (per test-plan §3 CI stage selectors): `--live` is a sibling `case` branch on `run` so the 5-command count stays five; the leg order is read from `live_leg_order` in both shells rather than restated, each leg carries a `live_leg_budget_sec`, a fixed quiet window sits between legs, and each leg's sink is frozen to `runs/live-suite/{leg}.jsonl`. Whether a real-model arm can reuse this composition or needs its own is research's question.
- **Harvest-tier grading** (per test-plan §6 scenarios, §1 Critical paths 1-4): where a live claim reaches no MCP read-back surface, the scenario row lands declare-only (`verdict` null / `state=KnownResidual`, non-Blocked) and the live claim grades hard in a `crates/conductor-run/tests/*_harvest.rs` target over verbatim leg captures. This is the established mechanism a grading rule for a non-deterministic assertion should be written against.
- **Feature-gated live target** (per test-plan §9 Live-Pulse scenarios): `[features] live-pulse = []` — an empty feature adding zero package nodes and keeping the leg out of default nextest/clippy/release — gating a SET of targets; each such target **owes its own** `cargo clippy -p <crate> --features <feat> --all-targets -- -D warnings`, since a gated file is invisible to the default lint pass.
- **Conditional-verdict recording** (per test-plan §9): where a leg's outcome moves by SUT state alone rather than source delta, the plan requires it be recorded as not-run-stable and its verdict as conditional — a posture stating a grading rule for a non-deterministic leg must say what it does with that class.

## Anti-patterns to avoid
- NEVER wire a live-Pulse leg (including a real-model arm) as a CI gate, and never let the CI-ban enumeration and §9's sanctioned SET drift apart — they are a two-site pair (per test-plan §11 CI, stack-specific).
- NEVER map a reported state (`blocked` / `ManualCheck` / `KnownResidual` / `CalibrationRegion`) onto a non-zero process exit, and never fake Pulse's *reaction* as a CI verdict (per test-plan §11 E2E + §11 Test Strategy, stack-specific).
- NEVER introduce a wall-clock sleep inside a test to synchronise, and never weaken the ban to accommodate a harness-level wait — the 2026-09-06 carve-out proposal was rejected precisely because the between-legs window was never inside the ban's subject (per test-plan §11 E2E).

## Contract bindings
- **tests §3 ↔ obs §3** — the Run-report envelope's eleven fields, the two journal record shapes (envelope line + `CheckRecord` line) and the disk-read `status` mechanism are the bound surface; a posture/grading statement must leave all three untouched, or both sides amend in lockstep (test-plan §3 Log format / Status endpoint shape).
- **tests §3 ↔ harness shells** — `scripts/agent-run.sh` and `.ps1` must expose identical semantics and add no sixth command; the property binds the scripts *together with the invoking environment* (a caller setting `$PSNativeCommandUseErrorActionPreference` diverges the `.ps1` leg at zero script delta).
- **tests §3 ↔ `contracts/pulse-run-contract.toml`** — `warmup_ms` / `min_canary_poll_seconds` are the derivation source for both boot budgets; a real-model leg's timing statement binds here rather than to a literal.
- **tests §9 Lint stage ↔ the chunk's PREREQ** — the workspace clippy gate is a CI stage; a feature-gated live target adds a second, per-feature clippy command beyond it.

## Acceptance criteria contributions
- `cargo clippy --workspace --all-targets -- -D warnings` is run locally and green (the PREREQ discharge), and any feature-gated live target additionally passes `cargo clippy -p <crate> --features <feat> --all-targets -- -D warnings` (per test-plan §9 Live-Pulse scenarios).
- The committed posture states the leg's operator-invoked, never-a-CI-gate footing and names its invocation path as a member of §9's sanctioned live-leg SET (per test-plan §9 / §11 CI).
- The grading rule assigns a miss to a `Verdict`/`ReportState` from the closed sets, and no reported state it names produces a non-zero process exit; re-driving a failed leg to obtain a pass is excluded (per test-plan §3 Status endpoint shape / §10 Zero-flakiness budget).
- The per-leg quiet window is stated with its arithmetic derived from the SUT-side dedupe precondition, placed in the harness between legs, with no in-test sleep introduced (per test-plan §11 E2E `sleep(N)` ban scope).
