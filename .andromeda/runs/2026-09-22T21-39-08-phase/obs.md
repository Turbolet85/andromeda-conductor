## Relevance
Partial. The posture forbids new span names, non-allowlisted attributes and envelope fields, so this chunk adds no instrumentation. It is still in obs scope because the live leg runs the existing must-trace chain, and obs rules cover its envelope shape, SLO handling, emission and read-back witnesses, host-path hygiene in committed evidence, and the coverage roll-up if the scenario names a cluster P-ID.

## Constraints
1. **The planted cause travels only on the PRODUCT stream.** obs-plan §1 (Minimal tier), §3 OTel SDK init and §3 Correlation require that self-observation never starts an OTel SDK and never exports OTLP, on `:4317` or `:4318`. The only OTLP Conductor may send is `conductor-emit`'s product stream to Pulse. So the known root cause must be product telemetry on that stream. It must not be self-obs pointed at Pulse, and it must not use a side channel. No metrics instrument is added (per obs-plan §5 · §11 Metrics).
2. **The scenario record stays the eleven-key envelope.** obs-plan §3 Log format JSON schema (including its two-record-shapes paragraph) and §6 Required fields require all eleven keys to be PRESENT on every envelope record. Null values are allowed. `verdict`, `state` and `slo_tier` must come from their closed sets. A declare-only scenario emits NO per-check `CheckRecord` line. §3's extension point does not permit extra fields here: the posture forbids a new envelope field, and §4's earlier live families put family-specific evidence at the harvest tier instead. §4's Known-residual classification depends on an observed `degraded_mode`. Research must answer whether a declare-only row still reaches `KnownResidual` when `retrieve_report` is NOT degraded, which is this leg's success case.
3. **Instrumentation limits: existing chain, bounded names, allowlisted attributes.**
   - obs-plan §4 Critical Path 1 requires `scenario.run` → `timeline.execute` → `emit.batch` → `verify.readback*`. `report.generate` and `db.insert_run` are siblings correlated by `run_id`, not descendants.
   - §11 Spans / Traces limits span names to its enumerated set.
   - §4 Known-residual path requires every span attribute to be a name in `conductor-core::redact::ALLOWLISTED_FIELDS`; any other attribute emits nothing.
   - The plan contradicts itself here: §4 CP5 names a `report.classify_known_residual` span that §11's bounded set does not list. Whether that span exists in code is research's question. The chunk must not mint it, or any other new name, without reconciling §11 first.
4. **Read-back boundary logging.**
   - obs-plan §6 Boundary-call wrappers requires every MCP call, `retrieve_report` included, to log: tool name, `latency_ms`, error, canary result, and the observed result KEY SET. The key set is names only, never values, carried on `message`.
   - §4 Known-residual path and §6 Log levels require a degraded `retrieve_report` to appear as a `warn` on `message`. An MCP timeout is also a `warn`.
   - Consequence: no required self-obs line carries the hypothesis TEXT. Whether an existing Conductor surface keeps the ranked `## Hypotheses` verbatim for the harvest capture is research's question.
5. **Latency and the SLO ladder.**
   - obs-plan §5 and §10 define `latency_ms` as wall-clock `read_back_observed_at − journal_emitted_at`, graded against the closed `<5s`/`<20s`/`<90s` ladder (top threshold 90 000 ms).
   - §4's Delegated-timing note says this difference covers the WHOLE emission window.
   - §11 Project-specific bans require wall-clock `std::time` for these timestamps, never tokio's virtual clock.
   - A ~110 s leg would fail §10's post-run check (`latency_ms` ≤ tier threshold, applied to each verdict row). Research must answer whether a null-verdict declare-only row falls outside that check, and which tier the scenario declares.
6. **Self-obs capture for each serialized leg.**
   - obs-plan §1 Logging stack and §3 Logging stack / Log file location require the CLI self-obs stream to be written as JSON to `logs/agent-latest.jsonl` (relative to `CONDUCTOR_RUNS_DIR`) in agent mode. Agent mode is set by the flag, or by `CONDUCTOR_AGENT_MODE`, which Conductor only reads.
   - Only one writer at a time. Every line carries the §3 base set: `timestamp_ms`, `level`, `target`, service identity, `run_id`.
   - Research must answer whether the file is truncated per run, which would mean each leg's capture has to be taken before the next leg starts.
   - Per §4 Auto-instrumentation (cli row), `conductor-cli` has no `tracing` dependency. If the posture's "leg records that it observed its own environment" is written from the CLI, a self-obs line there first needs that dependency edge.
7. **Harness faults vs graded outcomes.** obs-plan §11 Error Reporting requires malformed or unexpected read-back input to produce a typed `blocked` value, never a panic. This matters here because real-model markdown is free-form. §10 requires zero unlogged panics: the panic hook logs a structured `tracing::error!`, sanitized at the `anyhow` edge.

## Patterns to follow
- **Declare-only landing, with the hard assertion in a harvest test on an UNREDACTED field** (per obs-plan §4 Restart-suppression · Severity-lifecycle · Known-residual Delegated-timing family). Earlier live families graded their claim in `conductor-run/tests/*_harvest.rs` over verbatim captures, never through envelope extras or `budget_ms`. The plan records that some Pulse counters read `"<redacted>"` live because of Pulse's default-deny allowlist, while `incidents.list_active.request` `item_count` came through unredacted. Before the harvest test grades any field, show that the field arrives unredacted.
- **Shape witnesses at both boundaries** (per obs-plan §6 Boundary-call wrappers).
  - The `emit.batch` wire-shape witness (`debug` level, key names, on `message`) is Conductor's own evidence that the cause left through the normal emission path. It is what the posture's "Emission witness" term refers to.
  - The read-back key-set witness tells a real-model `retrieve_report` shape change apart from an empty result.
  - An unresolvable sidecar produces a blocked row in about 0 s. That case is told apart on the self-obs boundary line (`timestamp_ms`, `latency_ms`, error), because the blocked envelope row has `latency_ms` null (per obs-plan §3 schema).
- **Values that are not allowlisted go on `message`** (per obs-plan §6 MCP lifecycle WRITE, which carries the incident ID; §4 Coverage-matrix gate, which carries counts). To confirm the second digest re-generated the same incident instead of forming a new one, the plan allows two Conductor-side carriers: the `count` attribute on `verify.readback.observe` (per obs-plan §4 Known-residual path) and an incident ID on `message`. Whether `count` separates the leg's own incident from its preflight-canary incidents is research's question.
- **Record the family; don't re-tier the plan** (per obs-plan §4 Delegated-timing family, §1 Justification, §12).
  - An earlier declare-only family was recorded in an existing path's detail block, not as an eighth critical path, because the fixed set of 7 paths is part of the Minimal-tier justification.
  - SUT facts measured live carry their Pulse HEAD, a measurement pointer and an expiry, in the §4 SCOPE-clause form. The confirmed formation figure should use that form if it lands in obs-plan.
- **If the emission profile separates the two digests with a silence or ramp phase** (per obs-plan §4 Fault-injection spans · §6 Log levels why-note): `fault.silence` and `fault.ramp` open from the per-phase hook, are created but not entered, log at `info`, and carry only their allowlisted fault attributes.

## Anti-patterns to avoid
- **A bare per-target `RUST_LOG`** (for example `conductor_emit=debug` on its own). It replaces the default and silences every other target. Always use `info,{crate}=debug`, and never set either form in a shell that also runs the test suite (per obs-plan §6 Per-module log levels · §11 Logs).
- **Absolute host paths in committed captures.** The redaction layer's three application sites do not cover every channel. Verbatim Pulse logs, report markdown and script output committed as harvest fixtures are outside those sites, and the operator's `ANDROMEDA_PULSE_DATA_DIR` value is one of the things they can leak. They need their own scrub (per obs-plan §11 Logs · §11 PII Scrubbing).
- **A soft or newly invented timing budget.** Do not add an unenforced "formation budget" or a tier outside the closed ladder. The ~110 s figure is recorded as a measurement, not as a budget (per obs-plan §11 SLO · §5).

## Contract bindings
- **obs §3 ↔ tests §3.** test-plan §3 owns the envelope, `CheckRecord` and self-obs line formats that obs §3 reproduces. The leg's scenario record must pass `journal_conformance`, which checks key presence, closed sets and absence of host paths, but not that no other keys exist. The harvest test consumes the verbatim captures.
- **obs §4 allowlist ↔ core (`conductor-core::redact::ALLOWLISTED_FIELDS`).** Any new span attribute means a core allowlist change; otherwise the value goes on `message`.
- **obs §5/§10 ↔ core `SloTier` ↔ posture §Disposition instead of an SLO tier.** The closed ladder, topping out at 90 000 ms, is why the leg lands declare-only. Any exemption from the SLO check belongs at this point.
- **obs §4 Coverage-matrix gate ↔ core `UNBACKED_AUTO` / `check_scenario_backing` ↔ tests `coverage_gate`.** If the scenario names a diagnostic-quality cluster P-ID (P-033), the roll-up's derived `(N unbacked)` qualifier and the committed `coverage-matrix.md` both change. Both counts must be derived from the manifest, never hard-coded, and the qualifier must never be treated as a fifth mode.
- **obs §11 PII Scrubbing ↔ security §2** (no absolute host paths in run-report artifacts). This also covers committed live-leg evidence.
- **obs §6 ↔ posture §The launch posture "Emission witness".** The posture holds the leg to obs's additive `RUST_LOG` form.

## Acceptance criteria contributions
- The leg's record in `runs/<run_id>.jsonl` has all eleven envelope keys (present even when null), takes `verdict`, `state` and `slo_tier` only from their closed sets, has no twelfth key, has no `CheckRecord` line with it, and passes `journal_conformance` (per obs-plan §3 Log format JSON schema · §6 Required fields)
- The leg's self-obs capture has span-lifecycle lines for `scenario.run`, `timeline.execute`, `emit.batch` and `verify.readback*`, with `retrieve_report` among the `mcp_tool` values. Every line carries `run_id` and the service-identity base set, and no span name falls outside §11's bounded set (per obs-plan §4 Critical Path 1 · §3 two record shapes · §11 Spans / Traces)
- The capture is taken with the additive `RUST_LOG=info,conductor_emit=debug` and contains both the `emit.batch` wire-shape witness at `debug` and the other targets' `info` lines. Each MCP call's boundary line carries the tool name, latency and observed result key set (per obs-plan §6 Boundary-call wrappers · §6 Per-module log levels)
- Every committed capture or evidence file has 0 matches for absolute host-file paths: drive-letter, `/home`, `/Users`, `%APPDATA%`, `~/.cargo`, `.rustup`, and the operator's data-dir value. The leg's stderr and `agent-latest.jsonl` have 0 matches for `^thread.*panicked` (per obs-plan §11 Logs · §11 PII Scrubbing · §10 Always-required SLO invariant)
