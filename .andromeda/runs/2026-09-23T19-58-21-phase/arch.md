## Constraints
- `CONDUCTOR_RUNS_DIR` is a registered `CONDUCTOR_*` handle with one defined meaning: it overrides the default `runs/` artifact directory. The chunk must not mint a new `CONDUCTOR_*` handle or change what this one names (per architecture §Occupied Resources — Environment variables). The plan does not say whether an absolute value is legal at the shipped edges. Research should check whether the cli and tauri edges already reject it through `resolve_under`, so the test-binary guard matches the shipped behaviour and does not invent a stricter meaning.
- `ANDROMEDA_PULSE_DATA_DIR` is the live Pulse's data directory. It is legitimately host-absolute. When unset, it falls back to a platform default (`%APPDATA%\andromeda-pulse` on Windows, `$XDG_CONFIG_HOME` or `~/.andromeda-pulse` on Linux). Conductor only reads it and passes it to the sidecar. So the `pulse_log()` guard has to accept an absolute path (canonicalize, check it exists and is a directory) rather than root it under the workspace (per architecture §Occupied Resources — Environment variables; §Cross-cutting Patterns — Config management).
- If the guard comes from `conductor_core::config_path::resolve_under`, the new `conductor-run` test edge must follow the crate-per-seam boundary. Any feature the test binaries need must be declared where the crate actually uses it, not only in `[dev-dependencies]`, because workspace feature unification can hide the gap. The standalone-build property is measured, not enforced by a gate (per architecture §Established Decisions [Module Boundaries]). Research should confirm whether `conductor-run` already depends on `conductor-core`.
- Part B, text 1 (`preflight.rs` comment): the canary's carrier is freshness, by choice. The gate asserts that Pulse opened an incident after the storm's emission instant, comparing `opened_at_unix_nano` against a `std::time` stamp. The fingerprint is not the gate's carrier (per architecture §Established Decisions [Read-Back Dependency Posture]).
- Part B, text 2 (`storm_harvest.rs` header): at `83d4060`, an incident's `fingerprint_refs` are the model's `evidence_refs` together with the triggering cue's full-hex fingerprint (`grounded_fingerprint_hashes`). The fixture-pinned `[]` or `det-*` description was true only at `efabe8e` (per architecture §Established Decisions [Read-Back Dependency Posture]).
- Part B, text 3 (posture doc): the run contract has seven terms, and `shell-absence` is a distinct check kind. `l4-real-model` is `check = "shell-absence"` on `ANDROMEDA_PULSE_L4_DETERMINISTIC`, `posture = "real-model"`. `mcp-enabled` is `shell-declaration` on `ANDROMEDA_PULSE_MCP_ENABLED` (per architecture §Occupied Resources — `contracts/pulse-run-contract.toml`). Watch the ordinal: the `ANDROMEDA_PULSE_MCP_ENABLED` registry entry calls `mcp-enabled` the run contract's "SECOND `shell-declaration` term". That counts across the whole term list, where the deterministic-posture `l4-deterministic` is the first. The posture doc's claim is about the real-model posture's own terms. The fix must not make the two contradict each other, and must not edit the arch row.
- `contracts/pulse-real-model-leg-posture.md` is a `contracts/` member with no Rust reader. It has no `default_path()`, no `resolve_under`, no bounds check and no override handle. It names only handles that are already registered and mints none. A prose fix must keep all of that (per architecture §Occupied Resources — posture-doc row).

## Patterns to follow
- Test-binary workspace-root resolution with path-free failures: the scenario-audit ledger's gate test resolves the workspace root from `CARGO_MANIFEST_DIR`, and its read faults carry only `e.kind()`, never the path (per architecture §Occupied Resources — `contracts/scenario-audit-ledger.toml`). This is the closest precedent for guarded `runs_dir()` joins and non-printing panics.
- `resolve_under` is the traversal guard for workspace-relative artifact paths. It is how `CapabilityManifest`, `LoadEnvelope` and `RunContract` resolve their `default_path()` (per architecture §Occupied Resources — On-disk artifacts).
- Report a path-valued handle by name and a boolean, never by value: the `EDGEWEBDRIVER` step prints the handle name and a `Test-Path` boolean, never the path. The preconditions probe keeps name-only reporting (per architecture §Occupied Resources — `EDGEWEBDRIVER`; amendment 2026-09-04-preconditions-probe-reads-path-handles-by-presence).
- Derived locations move with `CONDUCTOR_RUNS_DIR`: `runs/live-suite/`, `logs/agent-latest.jsonl` and the Tauri self-obs sink all resolve relative to the runs dir. A guard must resolve the runs dir once and must not break those sibling locations (per architecture §Occupied Resources — On-disk artifacts).

## Anti-patterns to avoid
- Adding a new `CONDUCTOR_*` handle or override for the Pulse log dir or for a test-only runs dir (per architecture §Occupied Resources — Environment variables; §Cross-cutting Patterns — Config management).
- Declaring a feature that a test guard needs only in `[dev-dependencies]` of a crate whose library uses it. This is the masking shape measured on 2026-09-04 (per architecture §Established Decisions [Module Boundaries]).
- Rewriting the Part B texts in terms the plan retired: "NO read-back field varies with the emitted payload", or the fingerprint as the canary's carrier (per architecture §Established Decisions [Read-Back Dependency Posture]).
