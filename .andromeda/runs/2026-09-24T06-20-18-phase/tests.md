## Constraints
- If the measurement ships as a test, it belongs at the crate-local `tests/` tier as a static gate over a committed artifact. It runs as `cargo nextest run -p <crate> --test <name> --profile ci`, and it resolves the file through `CARGO_MANIFEST_DIR`, never a CWD-relative path (per test-plan §6 "Coverage-matrix completeness gate (static)" Verification signal; §2 Directory pattern). Which crate could own a gate over `.andromeda/architecture.md`, a planning doc rather than a SUT artifact, is P3's question. No precedent in the plan covers it.
- If the measurement ships as a committed script instead, the precedent is the operator/local instrument footing: `python -X utf8 scripts/mutation-gate.py`, with no CI step invoking it (per test-plan §9 "Scoped mutation audit"). §9 says its stage table is "the complete inventory of gates CI enforces". However, the two shipped static CI gate steps took no stage-table row (see amendment history below). A new CI step must pick one of these precedents explicitly.
- The measurement must be agent-driven: an exit-code-readable byte count against a stated cap. "Readable whole" checked by eyeballing a Read is a manual verification step (per test-plan header "Agent-driven invariant"; §11 Universal "NEVER include a manual smoke step").
- No literal-count predicate. The cap is a threshold, like `--fail-under-lines 60`. Today's byte counts (49 133 B / 48 858 B), or counts of entries or rows, must not be pinned as literals that the check asserts. The value is measured, never restated (per test-plan §6 "Coverage-matrix completeness gate" ("a row count is the literal-count form this same path's Verification signal forbids"); D-tests-derived-count in amendments 2026-09-13).
- The result must be deterministic across hosts. A result that differs by runner is a defect to fix at the cause (per test-plan §10 "Zero-flakiness budget"). A byte count depends on line endings. Whether the repo's `.gitattributes` `* text=auto eol=lf` makes the measured bytes identical on the Windows runner and the dev host is research's question.
- Minimal tier. A doc-only chunk does not move the coverage gate, and new tests add no coverage obligation beyond `--fail-under-lines 60` (per test-plan §1 / §10 "Coverage thresholds").

## Patterns to follow
- A static gate over committed data proves it can fail inside the suite. Negative arms mutate the REAL committed artifact and assert that the error names the offender, here the section that exceeds the cap (per test-plan §6 "Scenario-assertion audit leg").
- A static gate is presence-guarded and CI-enforced as its own named `ci.yml` step with `continue-on-error: false`, recorded as a sibling leg rather than a new `#### Scenario`. Adding a scenario would break the "7 scenarios" maximum (per test-plan §6 "Scenario-assertion audit leg"; amendment 2026-09-16-scenario-assertion-audit-gate).
- Wrap-time sweep discipline: grep every changed or retired phrase across the seven masters, CLAUDE.md, the rule files, `playbook.md` and `drift-base.md`. Include a known-positive control so that 0-hit results can be trusted. Write the amendment entry only after the sweep. This is the mechanism for proving "no registered fact lost" (per amendments 2026-09-14 and 2026-09-16 Sweep blocks).
- Cite by stable identity, not by coordinate. The plan retired `file:line:col` identity because coordinates kept going stale. It identifies CI jobs "BY NAME rather than by `ci.yml` line coordinates" (per test-plan §9 "Matrix builds"; §12 "Roster member IDENTITY — `file:line:col` RETIRED"). The test-plan body cites architecture by section name ("arch CI/CD", "arch Standard Contracts"), not by `architecture.md:NNN`.

## Anti-patterns to avoid
- Never raise the cap figure to make the check pass, the same way the coverage threshold is never lowered to pass the build (per test-plan §11 Quality).
- Never use a literal-count predicate: a pinned byte count, entry count or row count (per test-plan §6 Coverage-matrix Verification signal; amendment 2026-09-13 D-tests-derived-count).
- Never add a manual or human-review verification step, such as "operator confirms Read returns whole" (per test-plan §11 Universal).
