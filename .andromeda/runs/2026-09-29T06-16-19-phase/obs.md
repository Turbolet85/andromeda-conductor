## Relevance
partial — the chunk mints no new instrumented surface, but it drives the real-model posture chain, the preflight canary read-back boundary, the harvest tier and the coverage roll-up's `(N unbacked)` qualifier, all of which obs-plan governs.

## Constraints
- A real-model-posture scenario adds NO critical path, span name or span attribute. It rides the Critical Path 1 chain with the standard eleven-field envelope and `verdict` null, and a non-degraded read-back lands `ManualCheck`. Its interpretation (here P-031 / P-033 / P-034 / P-044) is graded at the harvest tier over the scrubbed capture and never through the envelope (per obs-plan §4 Scenario: Headless deterministic scenario run… → Real-model posture). The plan records that the only drive (2026-09-23) was blocked at preflight, so this chain has never been observed live under the real-model posture. Whether a drive that gets past the canary emits the chain as specified is research's and the live leg's question, not a given.
- The canary's MCP read-back boundary must log four things: the tool name + `latency_ms` + error (if any) + the **canary-check result**. It must also log the **observed key set** of each raw tool result, as key NAMES only and never values, on the allowlisted `message` field (per obs-plan §6 Boundary-call wrappers). Research must answer two questions: whether the shipped self-obs stream already records the canary-check result at a grain that separates the three candidate causes, and what a drive's own lines can and cannot distinguish.
- A span attribute must be a name in `conductor-core::redact::ALLOWLISTED_FIELDS`. The processor stage drops any other field, so an attribute outside the allowlist emits nothing. Any new canary/diagnostic detail therefore rides the allowlisted `message` field or requires an explicit allowlist addition (per obs-plan §4 Scenario: Known-residual classification path → Required span attributes; §6 Boundary-call wrappers).
- Span names stay inside the bounded set `scenario.run`, `timeline.execute*`, `emit.batch`, `emit.logs_batch`, `verify.readback*`, `report.generate`, `db.insert_run`, `fault.*`, `tauri.command.*`. A canary-diagnosis or harvest step mints no new family (e.g. no `canary.*` / `harvest.*`) (per obs-plan §11 Spans / Traces).
- The coverage-matrix gate mints NO span. Its observable is ONE boundary `info!` from `conductor_report::coverage_rollup`, with derived counts in the `message` value. The auto term carries a derived `(N unbacked)` qualifier read from `conductor_core::UNBACKED_AUTO`, which qualifies the auto count and is not a fifth mode. The completeness assertion is the `conductor-report --test coverage_gate` target over the committed `coverage-matrix.md`, not a log field (per obs-plan §4 Scenario: Coverage-matrix completeness gate). Moving `UNBACKED_AUTO` 8 → 4 therefore changes a rendered qualifier and needs no allowlist or span change.
- No absolute host paths or internal struct names may appear in logs, the run report, `runs.db` or any committed artifact. The redaction layer is `conductor-core::redact`, applied at the processor stage, and the three enumerated application sites never bound every host-path channel (per obs-plan §11 Logs; §11 PII Scrubbing). A real-model capture or canary-diagnosis evidence file is a new channel and must be treated as one.
- Log timing uses the wall clock only (`std::time::SystemTime`/`Instant`), never tokio's virtual clock (per obs-plan §11 Project-specific bans). A per-target `RUST_LOG` directive REPLACES the default, so any opt-in debug for a diagnostic drive must pair the global level (`info,{crate}=debug`) and must never be set for a run that also executes the test suite (per obs-plan §6 Per-module log levels).

## Patterns to follow
- The **shape witness**: record the key NAMES a boundary actually saw, on `message`, because a reader that degrades to empty makes divergence indistinguishable from emptiness (per obs-plan §6 Boundary-call wrappers: the `verify.readback` key-set witness and its `emit.batch` wire-shape twin at `debug`). This is the precedent for turning an "absence" into evidence, which matters because the prior canary diagnosis rested on an absence (no `interpretation.incident.created` line).
- **Harvest-tier grading over PULSE's own tracing lines**, each quantity read from its own exact leaf. Pulse's default-deny allowlist can render a field `"<redacted>"` live, so a leaf's presence is not its readability (per obs-plan §4 Scenario: Restart-suppression… and Scenario: Severity-lifecycle… → Required log fields; §4 Known-residual → Delegated-timing family). This applies directly to what Pulse's log at `f15536b` can show about a Dismiss / severity-None decision.
- **Scenario-level `Blocked` on posture mismatch**, recorded inside `scenario.run` before the ready check with one `info` line on `message`. It is never a sixth gate precondition (per obs-plan §4 Real-model posture).
- The **two record shapes**: the envelope in `runs/<run_id>.jsonl` and the `runs.db` row versus the self-obs line. They are governed differently, since an envelope field is written by the report seam while a span attribute must be allowlisted (per obs-plan §3 Log format JSON schema → Two record shapes).

## Anti-patterns to avoid
- NEVER introduce a span name outside the bounded set, or a dedicated span attribute outside `ALLOWLISTED_FIELDS`. The attribute would be dropped silently and look instrumented while emitting nothing (per obs-plan §11 Spans / Traces; §4 Known-residual → Required span attributes).
- NEVER leak absolute host paths into committed evidence, `logs/agent-latest.jsonl` or `runs/**`, and never forward unsanitized model or transport text past the `anyhow` edge (per obs-plan §11 Logs; §11 Error Reporting; §11 PII Scrubbing).
- NEVER let malformed or empty canary / read-back input panic or false-pass. An empty canary is `Blocked` (per obs-plan §11 Project-specific bans; §11 Error Reporting).

## Contract bindings
- obs ↔ tests: the real-model interpretation is graded at the harvest tier (`conductor-run/tests/real_model_harvest.rs`, over the scrubbed capture) rather than through the envelope (per obs-plan §4 Real-model posture). The unbacked count's completeness is asserted by `conductor-report --test coverage_gate` over `coverage-matrix.md` (per obs-plan §4 Coverage-matrix completeness gate). Envelope key presence is asserted by `journal_conformance` (per obs-plan §6 Required fields; §3 Log format JSON schema).
- obs ↔ security: the redaction layer (`conductor-core::redact`) binds to the security plan's capture-scrubbing rules for untrusted SUT/model text (per obs-plan §11 PII Scrubbing). The capture-specific mechanism is security's to state, so verify it in security-plan and do not take it from this extract.
- obs ↔ arch: the `(N unbacked)` qualifier is derived from `UNBACKED_AUTO`, which `check_scenario_backing` holds to the catalog (per obs-plan §4 Coverage-matrix completeness gate → Denominator semantics).
- obs ↔ CI: a real-model leg adds no CI step. The `logs/agent-latest.jsonl` conformance and zero-unlogged-panics gates keep applying to the `rust` job the drift pin and coverage gate run in (per obs-plan §9 Log conformance check; §9 Zero-unlogged-panics gate).
