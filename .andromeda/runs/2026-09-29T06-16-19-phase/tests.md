relevant — the chunk moves a CI-enforced static gate (`UNBACKED_AUTO` pin + byte-compared `coverage-matrix.md`), extends a default-suite harvest target, and drives the operator-gated real-model leg whose firing discipline the test plan owns.

## Constraints
- The scenario-backing leg asserts `check_scenario_backing` against `UNBACKED_AUTO` by exact-set equality in BOTH directions (a new unbacked `Auto`, a pinned id a scenario now covers = pin rot, a pinned id that lost `Auto`), so dropping P-031/P-033/P-034/P-044 from the pin requires a committed scenario naming each id in the same change (per test-plan §6 Scenario: Coverage-matrix completeness gate → Scenario-backing leg).
- The coverage gate (`conductor-report --test coverage_gate`) requires the committed `coverage-matrix.md` to be byte-equal to `CoverageMatrix::render()` and forbids any literal row-count/id-range predicate; the pin and the artifact therefore move together, asserted set-wise, never by a count (per test-plan §6 Scenario: Coverage-matrix completeness gate; §1 Critical paths "Coverage-matrix completeness gate").
- The real-model leg (`agent-run run --live real-model`) is operator-gated and never a CI gate, and test-plan §9 states it is "fired once and never re-driven (only a Conductor-side environment fault may be re-fired)", its grading rule recorded into the capture BEFORE the leg; the chunk's bounded multi-drive canary measurement conflicts with that master text as written, so the plan must either fit the re-fire exception or surface a test-plan amendment — whether the shells enforce once-only mechanically is research's question (per test-plan §9 Live-Pulse scenarios; §3 `run` CI stage selectors; §11 CI).
- Real-model interpretation claims grade at the HARVEST tier in the default-suite `crates/conductor-run/tests/real_model_harvest.rs` over the scrubbed committed capture, against the pre-stated rule (`Identified → (Pass, Pass)`, `NotIdentified → (CalibrationRegion, ManualCheck)`, nothing to grade → `(null, Blocked)`), with synthetic arms for every outcome and the committed capture pinned byte-equal to its section; grading P-031/P-034/P-044 extends this tier, and whether the existing harness can already extract those surfaces is research's question (per test-plan §6 Scenario: Fingerprint-storm → Real-model interpretation leg).
- A real-model-posture scenario is excluded from cross-surface parity by design; only headless `conductor run` evaluates its declared posture, so no parity arm may be added for a new real-model scenario (per test-plan §1 Critical paths "Both-surface parity" Scope; §5 Cross-surface parity).
- A feature-gated live target (`live-pulse`, e.g. `real_model_live.rs`) is invisible to default nextest/clippy and OWES its own lint command `cargo clippy -p conductor-run --features live-pulse --all-targets -- -D warnings`; the suite must also stay green under BOTH `cargo nextest` and `cargo test -p <crate>` (runner-portability gate) (per test-plan §9 Live-Pulse scenarios; §4 Framework; §10 Zero-flakiness budget).
- A new or changed scenario TOML is subject to the scenario-assertion audit gate (`conductor-core --test scenario_audit_gate`): a live `[[expected]]` block or summed `gap_ms` over its tier's `deadline_ms()` must be pinned in `contracts/scenario-audit-ledger.toml` by exact-set equality (per test-plan §6 Scenario: Coverage-matrix completeness gate → Scenario-assertion audit leg).

## Patterns to follow
- Static gates over committed data reach the production source through the crate root and resolve the workspace root from `CARGO_MANIFEST_DIR`, never a CWD-relative `default_path()`; negative arms mutate the REAL committed artifact and assert the error names the offending id (per test-plan §6 Scenario: Coverage-matrix completeness gate).
- Harvest-tier grading over a verbatim, scrubbed leg capture in a default-suite test, the `storm/baseline/restart/pii/connection/severity_harvest.rs` precedent — the live claim never becomes a CI verdict (per test-plan §6 Scenario: Fingerprint-storm; §8 What NOT to mock).
- The read-only Tauri `unbacked_auto` command carries a mock-runtime IPC test asserting its payload against `conductor_core::UNBACKED_AUTO`; whether that test single-sources the constant or pins a literal set (and so moves with the pin) is research's question (per test-plan §5 Deferred to the GUI test-harness leg — command-dispatch half).
- Per-chunk scoped mutation audit on touched crates via `python -X utf8 scripts/mutation-gate.py {unit}`, graded on tallies vs `scripts/mutation-roster.toml`, never on cargo-mutants' exit code (per test-plan §4 Mutation instrument; §9 Scoped mutation audit; §10 Mutation-survivor disposition).

## Anti-patterns to avoid
- NEVER fake Pulse's reaction as a CI verdict or run the live/real-model leg as a CI gate — the stub proves wiring only (per test-plan §11 Test Strategy; §11 CI).
- NEVER assert the matrix or pin by a literal count (e.g. "4 unbacked", "43 auto") — set equality and render byte-equality only (per test-plan §6 Scenario: Coverage-matrix completeness gate).
- NEVER treat `Blocked`/`ManualCheck`/`CalibrationRegion` as a non-zero exit, and never add nextest `retries` to absorb real-model non-determinism (per test-plan §11 E2E; §10 Zero-flakiness budget).
