# a11y extract

## Relevance
partial — the chunk adds no UI surface, no rendered text, no interactive control and no motion; its only contact with this domain is the `crates/conductor-tauri/ui/package.json` edit plus the `package-lock.json` regeneration, since that tree carries the a11y harness's pinned tooling.

## Constraints
- a11y-plan §3 A11y testing tool pick and §3 Contrast verification harness pin the harness to specific tool versions: axe-core v4.12.0 via `@axe-core/webdriverio`, colorjs.io v0.6.1 and Lighthouse v13.0.3, all running over the `@crabnebula/tauri-driver` + WebdriverIO session. A lockfile regeneration made only to mirror a `license` field must not move any of these resolved versions. Whether a real `npm install` regeneration leaves them byte-stable is research's question.
- a11y-plan §9 CI Integration and §3 CI integration require job `a11y` (`windows-2022`, the routine `agent-run.ps1 run --e2e` arm) to stay a CI gate. A change to the npm manifest or lockfile is an input to that job, so its verdict on this chunk's own CI run is in scope.
- a11y-plan §11 CI requires the a11y step to be fail-fast (`violations.length > 0` → non-zero exit), with `CONDUCTOR_A11Y_STRICT` asserting the expected-skip SET. The chunk must not weaken the strict declaration or the printed-verdict assertions in either harness shell.
- a11y-plan §11 Strategy records the routine arm's green as tied to its configuration (the runtime/driver pair), not a standing verdict. A green reading from this chunk therefore cites its run and configuration, and is never carried forward from the 2026-09-17 run.
- a11y-plan §1 A11y Scope Summary / §3 WCAG criteria mapping set the tier at Minimal with no compliance trigger. License metadata introduces no WCAG criterion and no new surface to classify.

## Patterns to follow
- One webview-automation stack (per a11y-plan §3 A11y testing tool pick; §11 CI): if the regeneration touches the dev tree at all, the a11y harness dependencies remain the single tauri-driver/WebdriverIO stack, with no second driver introduced.
- Configuration-bound verdicts (per a11y-plan §11 Strategy; §9 CI Integration): any a11y-job reading cited as evidence names its run id and configuration.
- The frontend lockfile stays committed and un-drifted, regenerated by npm rather than hand-edited (this binds per the chunk scope and the security rule, not per a11y-plan). The a11y interest is limited to the harness pins above.

## Anti-patterns to avoid
- Never skip the a11y gate or accept a skipped-green run as a pass (per a11y-plan §11 CI). Skipping the leg because "only a license field changed" requires evidence that the lockfile delta leaves the harness tree unchanged.
- Never claim WCAG conformance without machine-verifiable evidence (per a11y-plan §11 Strategy; §11 Universal). The chunk makes no a11y claim and must not restate one.

## Contract bindings
- a11y ↔ tests: the a11y CI job rides the tests harness's webview leg and 5-command contract (per a11y-plan §3 CI integration; §9 CI Integration). A dev-dependency shift from the lockfile regeneration would surface in both.
- a11y ↔ security: security owns the `package-lock.json` committed/un-drifted discipline and `npm audit --omit=dev`. a11y owns only the harness tool-version pins inside that tree (per a11y-plan §3 A11y testing tool pick).

## Acceptance criteria contributions
- The `package-lock.json` diff limits a11y-harness packages to zero version changes: axe-core, `@axe-core/webdriverio`, colorjs.io, lighthouse, webdriverio and `@crabnebula/tauri-driver` each resolve to the same version before and after. Research decides whether the diff is confined to the root package's `license` mirror (per a11y-plan §3 A11y testing tool pick; §3 Contrast verification harness).
- Job `a11y` on this chunk's own CI run is read and cited with its run id and configuration. It is not red on a spec failure, and the expected-skip SET is unchanged under `CONDUCTOR_A11Y_STRICT` (per a11y-plan §9 CI Integration; §11 CI).
