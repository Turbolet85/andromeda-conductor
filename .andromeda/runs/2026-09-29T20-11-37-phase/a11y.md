## Constraints

The item renders as a checkbox row in two places: inside the run-console-HOLD `alertdialog` and on the report site (per a11y-plan §1 A11y Scope Summary → Operator-checklist path; §4 ARIA Patterns & Roles → Operator-checklist row). Whether the text changes is research's question. The scope currently puts it outside the correction.
- The lamp for a hold is chosen verdict-first (`CalibrationRegion` ⇒ HOLD). A `ManualCheck` state with no verdict is the `Manual` lamp (per a11y-plan §6 Visual Design Verification → State color tokens crosswalk). The chunk puts its hard grade in a harvest test, not in a `Verdict`. So the scenario's rendered lamp is not expected to move. Whether the chunk touches the `Verdict`/`ReportState` a GUI run of this scenario produces is research's question. If it does, the not-color-alone six-label assertion is back in scope.
- The cli surface does not count as assertable for a11y (per a11y-plan §11 A11y Anti-Patterns → Universal). A harvest-test `Fail` is a test assertion, not an a11y-verifiable status render.
