# security extract

## Relevance
partial. The chunk adds no shipped surface, no dependency and no new handle class. Its security touchpoints are (a) a live leg whose capture of Pulse's own log output becomes a COMMITTED fixture/evidence record, (b) test-binary readers of path-valued env handles, (c) a possible scenario-config edit, and (d) the zero-delta supply-chain gate.

## Constraints
- Any committed artifact this chunk writes must carry verdict/state/identity fields only, with no absolute host path (canonicalized `CONDUCTOR_*` dirs, `ANDROMEDA_PULSE_DATA_DIR`) and no internal seam-crate struct name. This covers the harvest's capture fixture, the `evidence/` tree, the corrected `contracts/pulse-p025-measurement-contract.md` and the scenario header. The reason is that they are agent-parseable ground truth shared across hosts (per security-plan §Security Anti-Patterns → Logging; §Error Handling → Run-report artifact sanitization).
- Pulse's emitted `metric.constellation.hue_update_ms` lines are untrusted SUT output at an ingest boundary. The per-READER precedent is the real-model capture row: fields-only witnesses, bounded reads, and each printed line scrubbed (`redact_value` → `mask_host_paths` → `elide_fingerprints`) before a single buffered write into committed evidence. Research should settle whether the delegated-timing leg's existing capture path already does this or needs it (per security-plan §Input Validation → Real-model capture ingest row).
- A test-binary reader that turns `ANDROMEDA_PULSE_DATA_DIR`'s VALUE into a path (joining `logs/` to reach Pulse's log) must canonicalize it and require a directory first. The shared `conductor-run/tests/capture_paths::pulse_logs_dir_from` guard does this, and every rejection is a path-free reason. A `CONDUCTOR_RUNS_DIR` test reader must resolve through `capture_paths::runs_dir_from` → `resolve_under`, so absolute and `..` values are rejected. The duty binds per READER, not per handle. Whether the leg and harvest this chunk touches already use those guards is research's question (per security-plan §Input Validation → env-var path-handle row and `ANDROMEDA_PULSE_DATA_DIR` spawn-propagation row; §Security Anti-Patterns → Input).
- The harvest test should read its committed capture from `CARGO_MANIFEST_DIR` plus a hard-coded path. No `CONDUCTOR_*` override should apply, so the fixture location is not operator-steerable. An absent or malformed fixture should be a hard failure, never defaulted and never a silent pass (per security-plan §Input Validation → Real-model capture ingest row, reader `real_model_harvest`; §Input Validation → committed fixed-path manifests row, "never defaulted, never silently widened").
- If `halo-hue-encoding.toml`'s phase data moves, the scenario must still clear load-time validation: garde `range`/`custom`/`dive` plus the load-path `Scenario::check_*()` arm. In particular `check_checklist` rejects a `[[checklist]]` beside a non-empty `expected`, so the hard grade can never be expressed as an `[[expected]]`/`budget_ms` entry (per security-plan §Input Validation → Scenario config files row).
- The leg reads Pulse through its emitted log and MCP tool surface only. It must never open, copy or persist `corpus.db` content. The ratified corpus-text exception is scoped to the real-model capture, and it does not cover this leg. No corpus-derived text may land in test source (the recorded `v3-09` BREACH shape) (per security-plan §Security Anti-Patterns → Data Protection).
- The dependency delta is expected to be zero. Even so, `cargo audit` and `cargo deny check advisories bans licenses sources` must both be green over the committed `Cargo.lock`. Before either is classified as external, check that the local advisory-db checkout is clean with a porcelain check, and read its `HEAD` against `FETCH_HEAD` (per security-plan §Dependency Security; §Security Anti-Patterns → Universal).

## Patterns to follow
- Use the shared `crates/conductor-run/tests/capture_paths` module for every env-derived path in a live-leg or harvest test. `capture_paths_guard` is the proving target, and rejection texts stay path-free (per security-plan §Input Validation → env-var path-handle row).
- Follow the real-model capture shape: read witness lines fields-only, apply a scrub chain, then write once into the per-chunk `evidence/` tree. The harvest loads the committed copy from `CARGO_MANIFEST_DIR` and asserts against it (per security-plan §Input Validation → Real-model capture ingest row).
- Keep the leg operator-gated (`live-pulse`), never a CI stage. The CI egress/spawn registry then stays unchanged (per security-plan §Threat Model Summary → Infrastructure, CI/CD, "Dynamic end-to-end scenario proof requires a live Pulse and is an explicit operator/local gate").
- Enforce Pulse-binary provenance by reading the field name from the binary, not by launching through a new committed spawn form. Launching `pulse-app` by the agent as a directed act adds no governed harness spawn (per security-plan §Security Anti-Patterns → Code Patterns, rule (b)).

## Anti-patterns to avoid
- Never let a committed capture or evidence line carry a raw host path, the data dir's workspace basename, or an un-elided fingerprint-shaped token copied verbatim from Pulse's log (per security-plan §Security Anti-Patterns → Logging; §Data Protection).
- Never add a new committed harness spawn to `scripts/agent-run.{sh,ps1}` or `ci.yml` to launch or probe `pulse-app`. That would be an EIGHTH governed form under rule (b), which always escalates. Never bind a listener to drive the leg either (per security-plan §Security Anti-Patterns → Code Patterns; §Universal, scope law).
- Never join an env-handle value under the workspace root unguarded in a new or modified test reader (per security-plan §Security Anti-Patterns → Input).

## Contract bindings
- security ↔ obs: the hue leaf `metric.constellation.hue_update_ms {duration_ms, severity_tier}` is Pulse's emission, and the field-allowlist question the contract raised is obs-plan §4's to settle. Security owns only the requirement that its captured copy is host-path-free and fields-only (security-plan §Security Anti-Patterns → Logging).
- security ↔ tests: the host-path hygiene gate and the supply-chain gate belong in the chunk's Test Commands. The live leg stays an operator-gated tier, never a CI job (security-plan §Threat Model Summary → Infrastructure, CI/CD).
- security ↔ arch: any new committed contract document or fixture read at a fixed path takes the per-READER record discipline (security-plan §Input Validation → committed fixed-path manifests row). Per the project's own framing, `pulse-p025-measurement-contract.md` has no Rust reader, so no loader row attaches unless this chunk adds one.
