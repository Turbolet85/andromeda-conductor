## Patterns to follow
- **Test-time committed-file reader.** A crate-local test binary resolves the workspace root from `CARGO_MANIFEST_DIR`, because a cargo test binary's CWD is its package root. Read faults carry `e.kind()` only and never the path, and an absent or malformed file is a hard fault that is never defaulted. This is the shape for reading committed evidence files after their digest matches. Whether the harvest already reads files this way is research's question. (per architecture §Occupied Resources — On-disk artifacts, `contracts/scenario-audit-ledger.toml` entry)
- **Real-model arm run-side artifacts.** The arm writes exactly `rm.jsonl`, `rm-capture.txt` and `rm-capture.err` under `runs/live-suite/`. They are leg-stemmed, git-ignored, and cleared per invocation by a non-recursive pattern delete. Any capture-side change (the key mask) writes into these same files and adds no new run-side artifact. (per architecture §Occupied Resources — On-disk artifacts, `runs/live-suite/{leg}.jsonl` entry)
- **`RUST_LOG` removal.** The `run --live real-model` arm removes `RUST_LOG` for the capture's two test invocations, and the `.ps1` restores the caller's value in a `finally`. A new series inherits this unchanged. (per architecture §Occupied Resources — Environment variables, `RUST_LOG`)
- **Add-only contract records.** Pre-registration means the rule is committed before the drive, "because a leg driven first and graded afterwards lets the grading be chosen to fit what happened". The new series sits beside the 2026-09-29 series record and never rewrites it. (per architecture §Occupied Resources — the posture-doc entry)

## Anti-patterns to avoid
- **Minting surface for the series.** Do not add a new `CONDUCTOR_*` handle, `agent-run` verb, flag or arm, or a Rust reader of the posture contract. The namespace is reserved for handles over concepts this plan already defines, and the posture doc mints none. (per architecture §Occupied Resources — Environment variables; the posture-doc entry)
- **A retry or masking arm for the a11y race.** Do not add `continue-on-error`, an `if:` gate, or a retry that turns one lucky green into a pass. The determinism discipline bans retries that mask flakes: the zero-retry nextest `ci` profile is the stated instance. Whether a wdio-level retry falls under the same ban is the a11y/tests extract's call. (per architecture §Infrastructure Patterns — Build system; §Cross-cutting Patterns — Determinism discipline; §Established Decisions [CI/CD])
- **A new hashing dependency added silently for the sha256 pin.** The stack table registers blake3 as the one hashing dependency. Whether a sha256 implementation is already in `Cargo.lock` is research's question. If one must be added, even as a dev-dependency, it is a dependency delta that needs `cargo deny` and `cargo audit` green over the new lock. (per architecture §Stack and Technologies — Hashing / digest; §Infrastructure Patterns — Build system)
