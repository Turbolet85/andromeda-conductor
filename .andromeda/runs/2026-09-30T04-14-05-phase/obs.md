# obs extract

## Relevance
partial — the chunk mints no new runtime instrumentation. Obs binds at four points: the real-model leg's envelope shape (item 5), host-path/redaction hygiene over the committed capture and evidence (items 2 and 3), the a11y violation-record artifact the CI red touches (item 4), and the must-log canary/read-back lines a drive produces.

## Constraints
- Obs tier is Minimal. No OTel SDK, exporter or meter may be introduced for self-observation by any item here, including a digest-pin helper or a capture-side mask (per obs-plan §1 Obs Scope Summary; §3 OTel SDK init; §11 Telemetry Strategy / Metrics).
- The real-model posture adds NO critical path, span name or span attribute. The `real-model-interpretation` scenario rides the standard `scenario.run` chain with the eleven-field envelope and `verdict` null; a non-degraded read-back lands `ManualCheck`; a canary-blocked drive lands `Blocked`. Interpretation is graded at the harvest tier (`real_model_harvest.rs`, over the scrubbed capture), never through the envelope. The new series must keep this shape, and moving the harvest's pins to digests must not route grading into the envelope (per obs-plan §4 Must-trace path scenarios, Critical Path 1 "Real-model posture (2026-09-22)").
- The posture-mismatch `Blocked` is recorded at scenario level inside `scenario.run`, before the ready check, as one `info` line on the allowlisted `message` field. It is never a sixth gate precondition. Any series pre-registration rule that re-fires a pipeline fault must classify against that shape (per obs-plan §4 Critical Path 1 "Real-model posture").
- The span-name set is bounded (`scenario.run`, `timeline.execute*`, `emit.batch`, `emit.logs_batch`, `verify.readback*`, `report.generate`, `db.insert_run`, `fault.*`, `tauri.command.*`). Any new capture/mask/digest step is test-binary code and must not widen that set (per obs-plan §11 Spans / Traces).
- No absolute host paths or internal struct names may enter logs, the run report, `runs.db` or the journal. The three redaction application sites do NOT bound every host-path channel, so a NEW channel carrying host-derived text must be closed on its own terms. The data dir's workspace key rendered in Pulse's verbatim report body is exactly that kind of out-of-enumeration channel: the §11 standing warning applies to it, not the field allowlist (per obs-plan §11 Logs; §11 PII Scrubbing "NEVER assume the three application sites above bound every host-path channel").
- The a11y CI job's violation record `runs/a11y/<run_id>.jsonl` is the one exercised instance of the envelope's extension point. It carries the eleven keys plus resource tags (13 keys locally, 15 under CI), is uploaded as a CI artifact, and is conformance-asserted in-job by `journal_conformance` under `CONDUCTOR_RUNS_DIR=runs/a11y`. A fix for the axe `Page/Frame is not ready` race must keep this record produced and conformant (per obs-plan §3 Log format JSON schema; §9 CI Integration Telemetry artifact handling).
- Repository-hygiene gate output (a hit names `path:line` and the rule, never the matched text) stays in the job log and is never written into a telemetry artifact (`logs/agent-latest.jsonl`, `runs/**`). A digest pin's mismatch diagnostic should follow the same discipline and never echo corpus text (per obs-plan §9 Pipeline integration, Repository-hygiene gates row).

## Patterns to follow
- Harvest-tier grading over SUT or capture text, kept out of the envelope. `delegated_timing_harvest.rs` and `real_model_harvest.rs` grade from committed evidence, and the envelope stays the eleven keys (per obs-plan §4 Critical Path 1 "Real-model posture"; §4 Critical Path 5 "Delegated-timing family").
- Key-names-only witnesses on the allowlisted `message` field. `verify.readback` logs the observed key SET, never values, because a non-allowlisted field name is dropped at the processor stage. Any new diagnostic the capture or digest path emits into self-obs should carry names or digests only, on `message` (per obs-plan §6 Boundary-call wrappers).
- The a11y leg's own scrub (`<host-path>` plus a `security_finding` flag before commit) is the precedent for a harness-side mask over untrusted third-party text entering committed evidence. It is the model for masking the workspace key in the capture body as a second line of defence (per obs-plan §11 PII Scrubbing, standing-warning bullet).
- The real-model canary's three storms each log only the existing message-borne `canary fingerprint computed` line and add no span or field. The new series inherits that and adds nothing (per obs-plan §4 Critical Path 1 "Real-model posture").

## Anti-patterns to avoid
- NEVER assume the named redaction sites cover a new host-derived channel. Masking the workspace key RAW only, while missing its scrubber-rendered form, repeats the class the standing warning names (per obs-plan §11 PII Scrubbing).
- NEVER add a retry-once policy or a soft budget to make a flaky gate green. The a11y race fix must remove the race, not retry past it, in keeping with zero-flakiness (per obs-plan §11 SLO; §10 SLO Invariants "NO retry-once policies").
- NEVER lose the telemetry artifacts: the a11y fix must not drop the violation-record upload or the `agent-latest.jsonl` upload (per obs-plan §11 CI; §9 Telemetry artifact handling).

## Contract bindings
- obs ↔ tests: test-plan §3 owns the eleven-field envelope and the `CheckRecord` line. `journal_conformance` asserts key presence, closed sets and host-path freedom, never key exclusivity. The real-model drive's envelope and the a11y violation record are both judged by it (per obs-plan §3 Log format JSON schema, "Two record shapes").
- obs ↔ security: the capture's `redact_value` + `mask_host_paths` + `elide_fingerprints` pipeline and the new workspace-key mask are security-plan-owned. Obs contributes only the §11 rule that redaction sites are enumerated, not exhaustive, and the ban on host paths in committed artifacts (per obs-plan §11 PII Scrubbing; §11 Logs).
- obs ↔ a11y: the a11y job emits its violation JSON into obs's envelope extension point (`runs/a11y/<run_id>.jsonl`, `service.name` = `conductor-ui`). Item 4's fix sits on that binding (per obs-plan §3 Log format JSON schema; §9 Telemetry artifact handling).
- Whether the capture writer already masks the workspace key, and whether the harvest already reads evidence files at test time, is research's question. obs-plan states neither.
