The scoped exception must not widen, because a widening waits for the founder's live word. After this chunk, no report-body text may sit in `crates/conductor-run/tests/real_model_series/mod.rs` or in any other test source. Whether the harvest's grading, row, route and witness assertions can instead read the committed file at test time is research's question.
- Every fingerprint-shaped token is elided. That includes the 2026-09-22 capture's un-elided storm `fingerprint_hex` prefix and the `PINNED_CAPTURE` literal (per security-plan §Security Anti-Patterns → Data Protection, "every fingerprint-shaped token elided"). Frozen chunks' `evidence/` stays untouched (scope Boundaries). So the elision has to happen on this chunk's side: either the literal leaves test source, or an elided copy is committed under this chunk.
- The real-model capture must never print the data dir's workspace basename. Per security-plan §Input Validation (Real-model capture ingest row), the verbatim report body's Project Context currently leaks it "however Pulse's scrubber renders it", and masking it is owned by this entry. The mask must cover the RAW key and every scrubber-rendered form of it. Whether the key is available to the capture at write time is research's question.
- The capture ingest keeps its bounds and its single write. Per security-plan §Input Validation (Real-model capture ingest row), the source is untrusted SUT output with a bounded poll and a bounded id sweep. Witnesses are read fields-only. Output is buffered and written ONCE. `ANDROMEDA_PULSE_DATA_DIR`'s value reaches `logs/` only through `capture_paths::pulse_logs_dir_from`, which canonicalizes it and requires a directory, and `CONDUCTOR_RUNS_DIR` goes through `runs_dir_from` → `resolve_under` (per security-plan §Input Validation, env-var path-handle row). - A digest pin must use a non-deprecated algorithm: sha256, never MD5 or SHA-1 (per security-plan §Security Anti-Patterns → Data Protection, the crypto ban). If a hashing crate enters the tree, the dependency delta must land under `cargo audit` + `cargo deny check advisories bans licenses sources` green over the NEW `Cargo.lock`, with the package count as the basis, never lockfile byte-identity (per security-plan §Dependency Security; §Security Anti-Patterns → Universal). Whether a sha256 implementation is already in the lock is research's question.
- The CI a11y fix (item 4) must not move the boundary. It keeps ONE non-loopback CI egress, the version-pinned msedgedriver fetch. The pre-execution Authenticode gate stays, with no `continue-on-error`. The governed spawn-form count stays seven, and an eighth form escalates (per security-plan §Dependency Security, third dependency class; §Security Anti-Patterns → Code Patterns rule (b); §Threat Model Summary → Infrastructure/Networking).
- The drive series (item 5) enters only through the closed `run --live real-model` allowlist, led by `conductor preconditions --for real-model-interpretation` under the real-model posture. Under that posture the L4 handle must be absent or falsy, and an unmet subject refuses at exit 1 with no leg fired. The preflight is never silently downgraded (per security-plan §Input Validation, CLI-arguments row and `ANDROMEDA_PULSE_*` read-set row; §Security Anti-Patterns → Universal).

## Patterns to follow
- A test-binary read of a committed artifact resolves from `CARGO_MANIFEST_DIR` plus a hard-coded path, with no `CONDUCTOR_*` handle. Read faults carry `e.kind()` only, never the path. This is the harvest's existing reader shape per security-plan §Input Validation (Real-model capture ingest row; fixed-path manifests row), and a digest-then-read harvest should keep it.
- The scrub pipeline runs in order: `redact_value` → `mask_host_paths` → `elide_fingerprints`, and a masked token renders as a fixed placeholder (as `<fingerprint>` and `<host-path>` do). Per security-plan §Input Validation (Real-model capture ingest row; Screen-reader speech-log ingest row), a workspace-key mask fits the same placeholder idiom.
- Path-free rejection reasons (`{HANDLE} rejected: {fixed reason}`) per security-plan §Input Validation (env-var path-handle row), for any new failure text the capture or the harvest emits.
- For the CI a11y fix, change the OUTPUT or the step shell and never loosen a guard. Per security-plan §Input Validation (`CONDUCTOR_A11Y_STRICT` row), strictness is an ADDED arm and never a relaxation, and `wdio.conf.ts`'s `UNSAFE_PATH` guards stay byte-unchanged.

## Anti-patterns to avoid
- Remedying the BREACH by writing a widening into the plan, or by moving corpus text into another test-source form: a differently shaped literal, an `include_str!` of evidence into source, or a fixture copy outside `evidence/`. Per security-plan §Security Anti-Patterns → Data Protection, the ban binds everywhere outside the scoped exception. Per security.md 2026-09-29, a widening is ratified only by the founder's live word.
- Letting absolute host paths, the workspace basename or internal seam-crate struct names reach committed `evidence/`, the attempt ledger, the report or test-failure text (per security-plan §Security Anti-Patterns → Logging).
- Staging a corpus row, or opening `corpus.db`, to induce a SUT state for the series. Per security-plan §Security Anti-Patterns → Data Protection, corpus access is through the MCP tool surface only.
