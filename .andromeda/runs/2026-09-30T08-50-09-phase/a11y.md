## Constraints
- Every claim this chunk closes needs an agent-runnable, machine-verifiable path. Manual keyboard review is supplemental only. The driver is WebdriverIO `browser.keys()` over the one `@crabnebula/tauri-driver` session, reading `document.activeElement` via `browser.execute` after each key (per a11y-plan header *Agent-driven invariant*; §2 *Agent-runnable invariants*; §3 *Keyboard test harness* / *Focus management test harness*; §5 *Test harness pattern*).
- SC 2.4.7 requires a check that the visible `--color-focus` ring is PRESENT on `document.activeElement`. That check is distinct from, and additional to, the `--color-focus`/`--color-base` 3:1 ratio row (per a11y-plan §6 *Focus ring tokens* → Verification; §3 *Focus management test harness*; §6 *Color contrast pairs*). Whether the routine arm already probes ring presence anywhere is research's question. The scope's take-up grep found only the contrast row.
- The coverage matrix's contract is `list`/`listitem` (or table semantics) with keyboard-first row navigation. A selected row carries `aria-selected`/`aria-current` plus `--border-emphasis`, and it maps to SC 1.3.1 / SC 2.1.1 / SC 2.4.3. The `--border-emphasis` selection marking must stay distinct from the `--color-focus` ring, so focus is never colour-only (per a11y-plan §4 *Per-component pattern catalog* → Coverage matrix; §5 *run-console-live* / *idle-with-report*; §6 *Focus ring tokens*). Research must answer two questions: do row focus, row selection and virtualization exist in the shipped matrix at all, and does the "off-screen virtual-scrolled rows" clause have a referent?
- The first-class start / stop / proceed / abort shortcuts are specified "via Radix primitives" and must not conflict with assistive-tech shortcuts (per a11y-plan §5 *Per-surface keyboard shortcuts*). Whether any shortcut handler ships is research's question.
- The HOLD-dependent Operable half belongs to the operator-only driven arm (`npm run a11y:driven` → `operator-hold.e2e.ts`), which CI cannot run. The routine CI arm carries only the hold-free keyboard half (per a11y-plan §5 *run-console-HOLD*; §9 *Pipeline integration*; §11 *Strategy* carve-out). Proceed/Abort shortcuts therefore sit on the hold-dependent side unless research shows a hold-free subject.
- Live emission-counter `aria-live` updates must not steal focus. Any run-console-live row-navigation assertion has to coexist with the counter (per a11y-plan §5 *run-console-live*; §11 *Keyboard*).
- Three rules from §11 *Strategy* and §10 *Always-required SLO invariant* bind:
  - Under `CONDUCTOR_A11Y_STRICT` the routine arm's expected-skip SET is held at exactly two.
  - `claim-ownership.ts` names a single owner per claim.
  - `npm run a11y:ownership` fails when an owner's spec is missing or asserts nothing.
  - Zero WCAG AA violations, SC 2.4.7 included, with no retry-once.

## Patterns to follow
- **The idle-console Tab walk.** Follow the routine arm's hold-free walk: SC 2.1.1 reachability plus SC 2.4.3 order, first Tab → "Minimize window" → "Close window", with no `tabindex > 0`. It was fixed on 2026-09-17 to be environment-independent: it no longer waits on a `BODY` sentinel that the webview's focus cycle need not contain. Use it as the template for new row-navigation and ring-presence walks (per a11y-plan §5 *run-console-idle*; §11 *Strategy*).
- **The picker as precedent for row selection.** Its active item already carries `aria-selected`/`aria-current` plus `--border-emphasis` as the selection indicator, separate from the `--color-focus` ring. Reuse the same token split for coverage-matrix row selection rather than inventing a treatment (per a11y-plan §4 → Scenario / suite picker; §5 *run-console-idle*; §6 *Focus ring tokens*).
- **Readiness before axe.** Any new spec that calls `axeFindings()` inherits the bounded readiness wait, which requires the probe to answer in under `RESPONSIVE_MS` before a single `analyze()` (per a11y-plan §9 *Pipeline integration* → Readiness before every axe analysis).
- **Keyboard PASS/FAIL into the obs envelope.** Keyboard PASS/FAIL results fold into the obs §6 envelope through the routine arm's record, with DOM-relative selectors / `data-testid` and never host paths (per a11y-plan §3 *Structured violation JSON schema*).
- **Semantic HTML first.** Row semantics come from native `<table>`/list elements. Shortcut wiring rides Radix primitives rather than hand-rolled ARIA (per a11y-plan §4 *Naming convention*; §11 *ARIA*).

## Anti-patterns to avoid
- **Focus-order and focus-style bans.** No `tabindex > 0`: coverage-matrix row order relies on natural DOM order. No `:focus { outline: none }` without the `--color-focus` replacement (per a11y-plan §11 *Keyboard*). No ARIA roles or selection states hand-rolled over non-semantic elements (per a11y-plan §11 *ARIA*).
- **No green through a skip or a paper owner.** Never close a claim with a skip, a `retries`, a soft gate or a relabelled `claim-ownership.ts` row whose spec asserts nothing. A third routine-arm skip fails under strict mode, and a spec whose DOM state the seeded subject cannot produce must context-skip, never pass green (per a11y-plan §9 *Per-pipeline-stage* E2E row; §10 *Always-required SLO invariant*; §11 *Strategy*; §11 *CI*; §11 *SLO*).
- **Virtualization.** If row virtualization is ever introduced to satisfy §5's "off-screen rows" wording, it must not drop off-screen `listitem`s from the accessibility tree (per a11y-plan §11 *Screen Reader*).

## Contract bindings
- **a11y ↔ tests.** New assertions ride the routine `agent-run run --e2e` arm in the 5-command harness and surface through `logs`. CI job `a11y` runs it under `CONDUCTOR_A11Y_STRICT`, and both harness shells assert the printed verdict: the failed count, the skip tally against the expected-skip SET, and the session banner (per a11y-plan §9 *Pipeline integration*; §11 *CI*).
- **a11y ↔ obs.** Keyboard and ring PASS/FAIL results fold into the obs §6 envelope with the `service.name`/`deployment.environment` resource tags and no host paths (per a11y-plan §3 *Structured violation JSON schema*; §9 *CI-specific resource attributes*).
- **a11y ↔ design.** The ring and selection tokens are `--color-focus` / `--border-emphasis`. The ring's fade-in rides `--motion-micro`, so whether a ring-presence probe read right after a key sees an in-transition value is research's question. The reduced-motion rule must still drop that fade (per a11y-plan §6 *Focus ring tokens*; §6 *Motion tokens*).
- **a11y ↔ layouts.** Focus order per surface and the first-class shortcut set derive from layouts' Focus Management Anchors (per a11y-plan §5 *Focus order per layout*; §5 *Per-surface keyboard shortcuts*).
- **Spec-amendment fork.** If P4 re-states a claim to what ships rather than building it, the change lands in a11y-plan §5 (and §4's coverage-matrix row) through the wrap's amendment flow, not in this chunk's code (per a11y-plan §5 *run-console-live* / *idle-with-report* / *Per-surface keyboard shortcuts*, each naming this route entry as owner).

## Acceptance criteria contributions
- **Ownership.** Each of the four claims is asserted in exactly one suite, preferring the routine `--e2e` arm. Each has its `claim-ownership.ts` row at `owned`, with SC 2.4.7 entering as a row of its own, and `npm run a11y:ownership` exits 0. The routine arm under `CONDUCTOR_A11Y_STRICT` reports 0 failing, 0 axe violations and an unchanged expected-skip SET of two (per a11y-plan §11 *Strategy*; §10 *Always-required SLO invariant*).
- **SC 2.4.7.** For each routine-reachable interactive control, once it is focused via `browser.keys`, a `browser.execute` probe on `document.activeElement` reads a rendered focus ring (non-`none` outline or ring) resolving to `--color-focus`. The assertion fails when the ring is absent (per a11y-plan §6 *Focus ring tokens*; §3 *Focus management test harness*).
- **Coverage-matrix row navigation.** Where the behaviour ships, keyboard input moves `document.activeElement` across coverage-matrix rows in DOM order. The selected row exposes `aria-selected` or `aria-current` plus `--border-emphasis`, distinct from the `--color-focus` ring, and axe `list`/`listitem`/`aria-*` rules stay clean on that DOM state. If P4 takes the re-state fork instead, the §5 claim text is amended to what ships (per a11y-plan §4 → Coverage matrix; §5 *run-console-live* / *idle-with-report*).
- **Shortcuts.** Each first-class start/stop shortcut, driven by `browser.keys` from a non-focused position, invokes its control's action without colliding with an assistive-tech key. Proceed/Abort shortcuts are asserted on the driven arm, or on a hold-free subject if research finds one, and never skipped green (per a11y-plan §5 *Per-surface keyboard shortcuts*; §5 *run-console-HOLD*; §11 *Strategy*).
