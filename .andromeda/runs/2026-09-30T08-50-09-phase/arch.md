## Relevance
partial — the chunk is mostly a11y and webview-test work; arch contributes where the code lives, the fixed Tauri command surface the shortcuts must reach, the single automation stack, the dev-only driver resources, and the build ordering the Rust-gate PREREQ runs under.

## Constraints
- The UI work (row navigation, selection marking, shortcut handlers, the focus ring) belongs in the frontend asset subtree `crates/conductor-tauri/ui/`, an npm SPA that is NOT a Cargo workspace member. That subtree requires TypeScript strict and design tokens declared on `:root` in `src/styles/tokens.css` (per architecture §Occupied Resources → Frontend asset subtree; §Inherited Defaults → Frontend). Research must answer whether `--color-focus` and `--border-emphasis` already exist there as tokens.
- The internal core↔UI surface is Tauri 2 `#[tauri::command]` request/response for start/stop, the picker, the run-report view and the operator-pause prompt, plus the one live-counter `Channel`. Those command names are declared the complete route-equivalent set (per architecture §Conventions → Interface surfaces; §Occupied Resources → Interface routes / surfaces). The start/stop/proceed/abort shortcuts therefore need to dispatch through those existing commands. Research must answer whether the existing commands cover all four actions without adding a new one.
- Headless-drivable core, thin shells: engine logic stays in the library crates, and the GUI is a thin shell over the same core commands. A keyboard handler is presentation only and must not duplicate run logic in the webview (per architecture §Design Philosophy → Headless-drivable core, thin shells; §Cross-cutting Patterns → Development Style).
- Scope law: driving Conductor's own webview ships as THREE suite families (four `wdio` suites) over ONE WebdriverIO + tauri-driver stack. New assertions go into an existing suite. The routine `--e2e` arm is the one CI runs, and there must never be a second automation stack (per architecture §Cross-cutting Patterns → Scope law).
- `127.0.0.1:4444`/`4445` are dev-only listeners that live only as long as the harness. No shipped binary gains a listener (per architecture §Occupied Resources → Ports; §Cross-cutting Patterns → Trust boundary). `CONDUCTOR_MSEDGEDRIVER` and `CONDUCTOR_A11Y_STRICT` are read only by `wdio.conf.ts` and, for the strict flag, by the harness shells' verdict assertions. `CONDUCTOR_E2E_SEED_DIR` is the routine arm's seeded-fixture handle, which may be what the idle-with-report state depends on (per architecture §Occupied Resources → Environment variables).
- Build ordering for the PREREQ: `generate_context!` resolves `ui/dist` at compile time. So `npm run build` must come before any workspace `cargo nextest`/`clippy` that compiles `conductor-tauri`. An `--e2e` binary must be built with `--features tauri/custom-protocol` so it serves the bundle rather than `devUrl` (per architecture §Infrastructure Patterns → Build system).
- The `a11y` CI job runs the routine arm on `windows-2022` under `CONDUCTOR_A11Y_STRICT`, with a driver pinned to the image's WebView2 runtime. The chunk's no-CI-change boundary rests on that job already running the routine spec (per architecture §Established Decisions → [CI/CD]; §Infrastructure Patterns → CI/CD approach).

## Patterns to follow
- Reach the shortcut actions through the existing `#[tauri::command]`s from the React shell. For the hold dialog, use the existing operator-pause prompt surface (per architecture §Conventions → Interface surfaces).
- `scripts/agent-run.{sh,ps1}` wire in an `ensure_frontend` step (the `run` verb), and the CI Rust job does the same. Rely on it, or run `npm run build` explicitly, before the PREREQ's workspace nextest/clippy (per architecture §Infrastructure Patterns → Build system).
- The routine arm seeds its subject through `CONDUCTOR_E2E_SEED_DIR` (set by `wdio.conf.ts` `onPrepare`, read by `conductor-run/tests/envelope_fixture.rs`). Use that as the way a report-bearing idle state reaches the routine arm without a live Pulse (per architecture §Occupied Resources → Environment variables).
- The routine arm's self-obs lands at `runs/logs/conductor-tauri.jsonl`, and its violation record at `runs/a11y/<run_id>.jsonl` (per architecture §Occupied Resources → On-disk artifacts).

## Anti-patterns to avoid
- Standing up a second automation stack or a new suite family for these claims (per architecture §Cross-cutting Patterns → Scope law).
- Adding a `#[tauri::command]`, a `CONDUCTOR_*` handle or a listener without registering it. Each extends a registry the plan calls complete: an unregistered addition is drift, and a listener in a shipped binary breaks the trust boundary (per architecture §Occupied Resources → Interface routes / surfaces · Environment variables; §Cross-cutting Patterns → Trust boundary).
- Putting run or engine logic into the webview's key handlers instead of calling the core through the existing commands (per architecture §Design Philosophy → Headless-drivable core, thin shells).
