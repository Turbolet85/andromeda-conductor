# security extract

## Relevance
partial. The chunk is webview keyboard/focus behaviour plus routine `--e2e` assertions. Its security surface is the Tauri IPC boundary the shortcuts may reach, the frontend supply chain if a key-handling dependency is added, the dev-only driver-leg harness guards, and committed-evidence hygiene. No config, MCP, OTLP or secret boundary is touched.

## Constraints
- If the start / stop / proceed / abort shortcuts (a11y-plan §5 `:370`) dispatch to the backend, they must reach only the existing app-defined commands (start/stop, picker, run-report view, operator-pause) and the one live-counter `Channel`. The capabilities file stays deny-by-default and gains no new `core:`/plugin permission unless a genuinely new plugin requires one (per security-plan §Security Anti-Patterns → Code Patterns, the minimal-capabilities ban). Research must answer two questions: do the shortcuts need any new `#[tauri::command]`, or can they reuse the existing handlers the buttons already call?
- Row selection or row activation in the coverage matrix or run report may end up loading a run by id (`run_report` / `run_envelope`). If so, the id must still go through the `resolve_under` guard against the resolved runs dir before any read, and every `Err` must cross through `sanitize_error`. An unknown id is an absence, never a panic (per security-plan §Input Validation, the `#[tauri::command]` IPC-arguments row). Research must check whether row navigation reaches IPC at all.
- The routine `--e2e` arm is a dev-only driver leg. Its loopback ports `127.0.0.1:4444`/`4445` exist only while the leg runs and are absent from `conductor-cli` / `conductor-tauri`. No shipped binary gains an inbound listener (per security-plan §Threat Model Summary, the single-deliberate-exception attack-surface row; §Security Anti-Patterns → Universal).
- `CONDUCTOR_MSEDGEDRIVER` stays validated only at the wdio edge: existence + `isFile` + shell-metacharacter rejection (`UNSAFE_PATH`), then an array-form spawn. `CONDUCTOR_A11Y_STRICT` stays an added arm that inverts the skip cost and never relaxes a guard. New assertions must leave `nativeDriver()` and its guard byte-unchanged (per security-plan §Input Validation, the `CONDUCTOR_MSEDGEDRIVER` and `CONDUCTOR_A11Y_STRICT` rows).
- Any spawn the new assertions add must be one of the seven governed harness forms under rule (b): array-form argv, no shell string, no `eval`-equivalent, and no operator value as the program except through the guarded host-tool form. An eighth crossing escalates and is never routine (per security-plan §Security Anti-Patterns → Code Patterns, rule (b)).
- A frontend dependency added for key handling (for example a hotkey library) needs `npm audit --omit=dev` clean (0 production vulnerabilities) and a committed `package-lock.json`. A Tauri plugin (for example a global-shortcut plugin) would be both a Rust dependency delta and a capabilities widening (per security-plan §Dependency Security, Frontend (npm) supply chain; §Security Anti-Patterns → Code Patterns).
- The PREREQ Rust gates (workspace nextest + clippy) run beside the standing supply-chain invariant. `Cargo.lock` stays committed and un-drifted. Any Rust dependency delta lands only with `cargo audit` + `cargo deny check advisories bans licenses sources` green over the new lock (per security-plan §Security Anti-Patterns → Universal; §Dependency Security).

## Patterns to follow
- The Tauri command edge pattern: validate the input first with `resolve_under` (reject, never clamp), then return errors through `sanitize_error`. The mock-runtime IPC tier (`tauri::test`) is the proof tier for any command the shortcuts newly exercise (per security-plan §Input Validation, the `#[tauri::command]` row).
- App-defined commands are not capability-ACL-gated. The input-validation row is the boundary, and the capabilities file changes only for a new core/plugin permission (per security-plan §Input Validation, the `#[tauri::command]` row).
- The wdio edge guard pattern for host-tool handles: `UNSAFE_PATH` + `isFile` + array-form spawn. Under `CONDUCTOR_A11Y_STRICT` it skips at exit 0 when lax and exits non-zero when strict, and its precondition text names the handle, never its value (per security-plan §Input Validation, the `CONDUCTOR_MSEDGEDRIVER` / `CONDUCTOR_A11Y_STRICT` rows).
- The committed-evidence hygiene pattern: evidence records carry verdict/state/identity fields only, with host paths scrubbed or absent (per security-plan §Security Anti-Patterns → Logging).

## Anti-patterns to avoid
- NEVER widen the capabilities file beyond deny-by-default (no permissive default, no unscoped `shell-open`, no remote-origin iframe) to make a shortcut or focus behaviour work (per security-plan §Security Anti-Patterns → Code Patterns).
- NEVER spawn a helper from the new e2e assertions through a shell string or with an operator value in argv outside the seven governed forms (per security-plan §Security Anti-Patterns → Code Patterns, rule (b)).
- NEVER let a committed evidence record or test output from the leg carry an absolute host path (for example the resolved driver path) or a seam-crate struct name (per security-plan §Security Anti-Patterns → Logging).

## Contract bindings
- security ↔ tests/a11y (CI gate): the routine `--e2e` arm runs in the CI `a11y` job under `CONDUCTOR_A11Y_STRICT`. The strictness is what stops a skipped leg from reading as success, so new routine-arm assertions inherit a hard fail in CI (security-plan §Input Validation `CONDUCTOR_A11Y_STRICT` row ↔ the a11y-plan §11 CI anti-pattern it cites). Scope states no CI workflow change, and the third-dependency-class msedgedriver fetch and its Authenticode gate are untouched.
- security ↔ frontend: the frontend npm supply-chain gate (`npm audit --omit=dev`, committed lockfile) binds any `crates/conductor-tauri/ui` dependency change (security-plan §Dependency Security).
- security ↔ arch (IPC surface): any new or rewired `#[tauri::command]` enters the Tauri IPC trust boundary (security-plan §Threat Model Summary, the Tauri IPC vector).
