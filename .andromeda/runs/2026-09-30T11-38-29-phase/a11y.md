# a11y extract

## Relevance
relevant. The chunk re-runs and regrades the agent-driven NVDA screen-reader leg, which is a11y-plan §3's *Screen reader test pattern*. The remedy may also touch the webview's accessibility-tree exposure (§4, §5).

## Constraints
- a11y-plan §3 *Screen reader test pattern* requires the NVDA pass to be AGENT-DRIVEN from NVDA's own speech log (`-l 12`). It runs over the SAME `@crabnebula/tauri-driver` + WebdriverIO session, adds zero new dependencies, and leaves the operator the role of REVIEWING the graded record. Rows are graded per state over the shipped `RunState` set (`idle` incl. idle-with-report / `live` / `hold` / `aborted`). Each row carries its producing action, carrying node, expected output and required tokens, SC, result, ARM and heard text. `parse-nvda-log.ts` grades them against `nvda-pass-spec.md`, and `operator_review` is transcribed into `evidence/nvda-pass.json`. The regrade's fresh record must take that shape. Whether the current grader still emits every one of those fields is research's question.
- a11y-plan §3 *Screen reader test pattern* requires browse-mode rows to stay pending OS-level key injection, because WebDriver-injected keys never reach NVDA browse mode. They are recorded as findings: never passes, and never a manual arm. This bounds the E0-09 regrade, which cannot be closed by a pass the leg cannot produce.
- a11y-plan §3 *Screen reader test pattern* (Supplemental to automated) and §2 *Agent-runnable invariants* make the SR pass supplemental and never the sole verification of anything. It verifies runtime announcement quality only. SC 4.1.2 / SC 4.1.3 stay covered programmatically by axe. A regrade therefore reopens no axe/SC claim, which is consistent with the scope's "v3-03 not reopened".
- a11y-plan §9 *Per-pipeline-stage a11y artifacts* (E2E row) and §3 *Bootstrap phases* (`screen-reader-test-spec-setup`) fix the SR leg's posture. It is operator-only (`npm run a11y:sr` / `a11y:sr-empty` / `a11y:sr-error`), runs on a Windows + NVDA host only, and uses `CONDUCTOR_NVDA` as the host-tool handle (unset ⇒ skip at exit 0). It is supplemental and NOT CI-gated. The chunk must not move it into CI or change the handle.
- a11y-plan §1 *A11y surfaces & assistive tech reach* declares VoiceOver (macOS) and Orca (Linux) not-runnable-on-this-host, and no pass is claimed for them. The regrade is scoped to NVDA on this host.
- a11y-plan §10 *Always-required SLO invariant* and §11 *SLO* ban retry-once policies because they mask real failures. A silent focus row must not be regraded by re-running until it happens to announce. The regrade rests on the discriminating cause, not on a lucky run.
- If the remedy lives in the webview's accessibility-tree exposure, three things bind it. a11y-plan §4 *Per-component pattern catalog* (coverage matrix: table semantics, `aria-current="true"` + `--border-emphasis` edge, roving row focus with one tab stop) and §5 *Focus order per layout* (idle-with-report / run-console-live roving focus) keep that contract. §4 *Naming convention* keeps semantic HTML first. Whether the silence originates in the webview layer at all is research's question.

## Patterns to follow
- Use the existing one-stack SR harness per a11y-plan §3 *Bootstrap phases* (`screen-reader-test-spec-setup`): the `sr` / `sr-empty` / `sr-error` wdio suites, `CONDUCTOR_NVDA` guarded at the wdio edge, and the graded record reviewed by the operator. Any control experiment rides this stack rather than a new one.
- Record which ARM produced every row (agent vs operator) and the heard text beside the result, per a11y-plan §3 *Screen reader test pattern* (Pass spec format), so the regraded record is never read as wholly automated or wholly manual.
- State a verdict with the configuration that produced it, as the plan does for the CI proof: "stated with its configuration, because the next image bump can move any of those terms" (a11y-plan §3 *CI integration*; §11 *Strategy*). For this chunk the terms are the WebView2 runtime, the msedgedriver version and the NVDA version.
- Use a two-sided witness: the same arm fails with the mechanism bypassed and passes with it restored. a11y-plan §9 *Pipeline integration* ("Readiness before every axe analysis") uses this form as the model for a discriminating control. It also warns that a control scheduled so that it absorbs its own effect measures nothing.

## Anti-patterns to avoid
- Per a11y-plan §11 *CI* and §11 *Universal*, human-only NVDA review without the machine output is banned. A regrade must come from the graded speech log, never from an operator's listening alone.
- Per a11y-plan §11 *CI*, never stand up a second browser-automation stack (puppeteer/CDP) for a11y. A remedy or control that attaches outside the one tauri-driver/WebdriverIO session is out.
- Per a11y-plan §11 *Screen Reader* and §11 *Keyboard*, three webview-side remedies are banned: adding redundant labels or ARIA noise to "make NVDA speak" (it makes NVDA double-announce), `aria-hidden` on announced nodes, and `tabindex` > 0.

## Contract bindings
- a11y ↔ tests: the SR leg is one of the three suite families over the tests §6 tauri-driver/WebdriverIO stack. It is operator-only and not CI-gated (a11y-plan §9 E2E row; §3 *CI integration*).
- a11y ↔ security: SR artifacts must not leak absolute host paths (a11y-plan §11 *SLO*; §3 *Structured violation JSON schema*, "MUST NOT leak absolute host paths"). The speech-log scrub to `<host-path>` and the `CONDUCTOR_NVDA` wdio-edge guard are security-owned. They are flagged here, not restated.
- a11y ↔ layouts: if the remedy touches coverage-matrix row focus, it binds to layouts §Focus management, which a11y-plan §5 cross-references for the roving row focus.

## Acceptance criteria contributions

Every row carries its arm and heard text, and `operator_review` is recorded. S0-09 and E0-05 grade `announced-as-expected` from the speech log, or the record names the non-removable cause with its evidence and no row is graded a pass it did not earn (per a11y-plan §3 *Screen reader test pattern*).
- (a11y) E0-09 and every other browse-mode row remain recorded findings (`not-run-here`), never graded a pass and never moved to a manual arm (per a11y-plan §3 *Screen reader test pattern*).
- (a11y) The regrade rests on a single graded run per subject after the cause is removed, never on a rerun-until-announced policy (per a11y-plan §10 *Always-required SLO invariant*; §11 *SLO*).
- (a11y) If the remedy touches webview code, the routine arm stays green with zero new axe violations and no `tabindex` > 0 introduced (per a11y-plan §10 *Always-required SLO invariant*; §11 *Keyboard*).
