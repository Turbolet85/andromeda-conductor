# layouts extract

## Relevance
partial — the chunk regrades focus rows on the desktop-webview surface and may touch the webview's accessibility-tree exposure. It builds no new surface, region or component, and its primary causes (runtime, NVDA configuration, the harness's launch and foreground path) sit outside layout.

## Constraints
- The surface is ONE frameless window (`decorations: false`) whose run states are `idle` · `live` · `hold` · `aborted`, with idle-with-report as a sub-state of `idle`. There is no router, no route and no breakpoint. So a regrade drives run STATE, never navigation, and any rerun focus row lands on one of those four states (per layout-templates §Surface: desktop-webview → Primary screens; §Decisions Log → Key layout choices).
- The coverage matrix is a dense single-row-per-P-ID list with no virtualization. Its region has exactly ONE tab stop, the current row, and the bounded scroll container is not a tab stop itself. Roving focus moves with ArrowUp/ArrowDown (±1, clamped) and Home/End, focusing an off-screen row scrolls it into view, and the keyboard-current row carries `aria-current="true"` plus a 2px `border-emphasis` left edge distinct from the focus ring. This is the DOM half the prior chunk measured passing (`expectActiveCoverageRow()`). Any remedy placed at the webview's accessibility-tree layer must keep this anatomy (per layout-templates §Component — Primary content block 1).
- Keybindings live on a MODIFIER map: Ctrl+Enter starts and proceeds, Ctrl+. stops, Escape aborts a hold. One in-webview `window` keydown listener handles them and stands down while a hold is raised. Single letters stay free for the picker's type-ahead and the screen reader's browse mode, and OS shortcuts are never bound. A regrade of browse-class rows such as E0-09 depends on single letters staying unbound (per layout-templates §Component — Primary navigation).
- The three App.tsx-owned empty and error states are DISTINCT. They are the empty-catalog `No scenarios found.` (SR row E0-01), the picker's filter-miss `No scenarios match.` from a persistently-mounted region (SR row S0-16), and the catalog LOAD-ERROR render. For the load error, the visible copy sits OUTSIDE the `role="alert"` region, and the region carries only a visually-hidden re-assertion inserted once on the first `focusin` (SR row R0-01). A regrade must not collapse these states or move that siting (per layout-templates §Component — Primary content block 1 → States).
- On close, the operator-pause dialog restores focus through the contract: a `restoreFocusTo` accessor and an explicit restore in `onCloseAutoFocus`, with Start kept focusable through `aria-disabled` rather than native `disabled`. The dialog has no Radix `Trigger`, so focus fell to `<body>` before this contract (per layout-templates §Component — Hero / signature section).
- The titlebar is a `data-tauri-drag-region` flex row whose phase line shows one of four fixed state labels. The drag-region cursor must not leak onto the window controls. Research must establish whether the frameless window's activation or drag-region path takes part in the foreground and focus-event path NVDA listens on, since this plan fixes the window shape (per layout-templates §Component — Header).
- The footer status strip is DESIGNED, NOT SHIPPED: the release DOM has no `contentinfo`, and its landmark set is `banner` + `main` + two `region`s. So a regrade must not expect a footer landmark or footer announcements (per layout-templates §Component — Footer).

## Patterns to follow
- Cite the SR row that measured a layout fact beside it, as the plan already does for E0-01, S0-16, R0-01 and S2-08, and write "as shipped, measured {date}" apart from the design intent. A regraded row that changes what the plan says renders gets the same measured-date annotation (per layout-templates §Component — Primary content block 1 → States; §Component — Operator-checklist).
- Correct the plan to what actually renders, not to what it predicted. The four-cell coverage row replaced the documented six-cell one, and "DESIGNED, NOT SHIPPED" marks target-only anatomy (per layout-templates §Component — Primary content block 1; §Component — Footer).
- Record accessibility behavior here as a design requirement ("a11y derives the focus semantics") and leave the concrete attributes to the a11y plan (per layout-templates §Decisions Log → Notes; §Component — Primary navigation).

## Anti-patterns to avoid
- Adding a second tab stop to the matrix region, such as a focusable scroll container or per-cell stops, or adding virtualization. Either one breaks the one-tab-stop roving model and the full-wall render (per layout-templates §Component — Primary content block 1).
- Binding single-letter keys or OS shortcuts to fix an announcement. That takes away the screen reader's browse-mode keys and the picker's type-ahead (per layout-templates §Component — Primary navigation).
- Replacing the styled `AlertDialog` with `alert()`, `confirm()` or `prompt()`, or adding a second modal (per layout-templates §IA notes → Global model).
