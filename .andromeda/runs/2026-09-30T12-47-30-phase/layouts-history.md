## Relevant amendment history
- **2026-09-30-unasserted-keyboard-and-focus-visible-claims-closed** — the most recent amendment, one chunk back. It set the focus topology the SR focus rows walk: a modifier-only key map (Ctrl+Enter start and proceed, Ctrl+. stop, Escape abort, with single letters, Ctrl+W and Alt+F4 left unbound), `aria-keyshortcuts` on each control, and a non-focusable hint line. It also made the coverage matrix ONE roving tab stop: every row rendered, a scroll container that is not a tab stop, and the keyboard-current row shown by `aria-current` plus a `border-emphasis` edge that is distinct from the `color-focus` ring. This is the "shipped surface unaltered" baseline that the `git diff --numstat 4460307` no-topology-change criterion protects. The same amendment is the source of the extract's rule to keep visible focus apart from announced focus, and of its rule that control (1) and any re-run are driven by Tab, arrow and modifier keys, never by single letters.
- **2026-09-07-sr-findings-fixed** — added the catalog LOAD-ERROR state as a third App.tsx-owned state. Its visible copy sits OUTSIDE the `role="alert"` region, which carries only a visually-hidden re-assertion inserted once on the FIRST `focusin`. The three sibling error regions keep the empty-mount shape because they fire at arbitrary times rather than before the screen reader binds. This is the timing-sensitive first-focus mechanism the extract flags as a possible bearing on the "heard only in the first burst" reading. It was fixed after an SR pass on the 152 runtime, where every focus row was heard, so it predates the 154 silence. The amendment also conditioned the harness's shell-parity claim: parity is a property of the scripts together with the invoking environment. That matters for any control arm run from a different shell.
- **2026-09-02-screen-reader-manual-spec** — named the run-state set as shipped (`idle` · `live` · `hold` · `aborted`, with idle-with-report a sub-state). Every focus-row re-grade or routing record must name one of these states, and must not invent a screen. It also recorded the measured landmark set (banner + main + two regions, no `contentinfo`), and marked the footer strip and the report-site checklist DESIGNED, NOT SHIPPED. That is the designed-vs-shipped separation the extract asks the routing record to keep. Every item was measured by an SR pass against the release bundle, which is the precedent for the "SR row id + date + configuration" evidence convention.
- **2026-09-01-desktop-a11y-sweep** — recorded that Radix supplies the dialog's focus trap and Escape but NOT focus restoration for this Channel-opened dialog. Focus was measured landing on `<body>` on close, which is why `restoreFocusTo` exists. Any dialog-held focus row the chunk routes forward rests on this explicit restore, and restructuring it would confound the isolation. The amendment also moved the dialog fade to `motion-micro`.
- **2026-08-22-operator-pause-and-checklist-live-firing** — put the checklist rows inside the HOLD dialog, between Body and Actions, as a SIBLING of the dialog's `Description`. So the dialog's focusable content within the trap depends on whether the hold point declares `[[checklist]]` items. A `hold`-state focus row should name which dialog shape it was driven in.
- **2026-09-04-sr-findings-remediation** — split the empty state in two, both measured by an SR pass: `No scenarios found.` belongs to App.tsx's empty catalog, and `No scenarios match.` belongs to the picker's filter-miss. It is a precedent that an SR-pass finding is reconciled into this plan only as shipped wording, never as a topology change. The control row's picker states that focus rows traverse are the ones recorded here.
- **2026-09-01-webview-self-verify-windows-host** — defined `--e2e` as the CROSS-SURFACE stage: it builds the release Tauri bundle and drives the desktop-webview console through the tauri-driver leg. It is gated on a Conductor-owned driver handle whose absence skips the stage at exit 0 with a host-path-free precondition. This is the harness any agent-driven control (1) would extend or re-point. Pointing it at Edge instead of `conductor-tauri` departs from this documented target.
- **2026-09-06-operator-gated-live-suite** — fixed the refuse-vs-skip split: an incomplete live-Pulse environment REFUSES, while an absent host-tool handle (`CONDUCTOR_MSEDGEDRIVER` / `CONDUCTOR_NVDA`) SKIPS its own leg at exit 0. The NVDA legs this chunk runs depend on `CONDUCTOR_NVDA`, which the handoff says is set per command, so a missing handle reads as a skip and not as a result.
- **2026-09-07-a11y-ci-gate** — made the `--e2e` handle-absence outcome an ARM SET: the lax arm skips at exit 0, and an affirmative `CONDUCTOR_A11Y_STRICT` exits non-zero. It also added the printed-verdict assertion: the `Spec Files:` failed count, the per-spec skip markers checked against the expected set, and the `[webview2 … windows]` banner, because the exit code cannot tell a full pass from a total skip. The chunk's "strict `--e2e` green" reading is this printed verdict. The banner is also where the WebView2 runtime version each leg ran on shows up.
