# security extract

## Relevance
partial — no shipped-code or dependency delta is expected, but the chunk puts new NVDA speech into committed evidence, may change the dev-only wdio harness's spawn surface, and plans runtime/driver controls that sit on registered boundaries.

## Constraints
- NVDA's speech log is untrusted third-party text. Any record the control commits goes through the ingest controls in security-plan §Input Validation (screen-reader speech-log ingest row): spec-id cross-check, closed `outcome`/`arm`/`review_grade` sets, `heard` capped at 400 characters, and a required host-path scrub to `<host-path>` that adds a `security_finding`. The raw log stays under gitignored `runs/`. A no-boundary control over Edge 154 or another WebView2 app adds foreign window titles and content to that log, which is the case the row was written for. Whether `parse-nvda-log.ts` accepts subjects and spec ids that are not Conductor's is a research question.
- The chunk's committed `evidence/` tree must not leak absolute host paths or seam-crate struct names (per security-plan §Security Anti-Patterns → Logging, the committed-evidence clause). This covers the control's configuration record: runtime, driver, NVDA, OS build, desktop and `allowInChromium`. Record the WebView2 runtime and driver by VERSION, never by install directory, and never write the NVDA or driver path a handle resolves to.
- Every harness spawn must be one of the seven governed forms in rule (b) (per security-plan §Security Anti-Patterns → Code Patterns, rule (b)). The plan records each crossing as an operator-ratified, deliberate boundary widening under playbook `:124`. Any new form would be a new crossing that needs that ratification before it runs, for example the wdio/msedgedriver stack launching Edge instead of `conductor-tauri`, or a harness-spawned third-party WebView2 app. The plan itself states no "eighth crossing escalates" rule: that wording lives in the leaf `.claude/rules/security.md`, so read the escalation trigger from the leaf and playbook `:124`.
- Host-tool handles keep their wdio-edge guard: `CONDUCTOR_NVDA` and `CONDUCTOR_MSEDGEDRIVER` need existence + `isFile` + shell-metacharacter rejection before an array-form spawn, and skip at exit 0 when unset (per security-plan §Input Validation, the `CONDUCTOR_MSEDGEDRIVER` and `CONDUCTOR_NVDA` rows). This applies unchanged to an operator-supplied 153 msedgedriver if the runtime control ever becomes runnable.
- A new env handle is a new trust boundary, and the duty binds per READER (per security-plan §Input Validation, the path-handle rows, and §Threat Model Summary → Attack surface, CLI-input vector enumeration). The runtime control's WebView2 loader executable-folder variable, and the product lever's browser-arguments variable, would each be an unregistered handle carrying a path or arguments into a spawned host. Neither may be set by the harness without its own registered row and guard.
- Dev-host harness legs do no public networking, and the only harness-lifetime listeners are `4444`/`4445` (per security-plan §Threat Model Summary → Infrastructure: Networking, and → Attack surface: the single deliberate exception vector). The control's plain focus page must be local content that needs no new listener, such as a local file. It must never be a page fetched from the network, and never a page served by an ad-hoc local HTTP server, which would be an unregistered listener.
- Frontend dependency hygiene applies if the harness gains a package: `npm audit --omit=dev` clean and `package-lock.json` committed (per security-plan §Dependency Security, Frontend (npm) supply chain). With a zero delta, state the basis as the package count, not as lockfile byte-identity.

## Patterns to follow
- The existing `writeNvdaPass` scrub path in `parse-nvda-log.ts` is the one route from NVDA's log into committed evidence (per security-plan §Input Validation, SR ingest row). Route the control's rows through it, never through a hand-written record.
- Array-form spawn with a fixed argv, and an operator value only as a separate, guarded argv element (per security-plan §Security Anti-Patterns → Code Patterns, rule (b)). The existing NVDA detached spawn `nvdaExe()` and the `nativeDriver()` shape are the in-tree forms.
- Record a boundary crossing as an operator-ratified widening, with the measured narrowing or net effect stated (per security-plan §Security Anti-Patterns → Code Patterns, rule (b), the fifth and seventh forms' registration shape; §Dependency Security, third dependency class).

## Anti-patterns to avoid
- NEVER spawn a child through a shell or an `eval`-equivalent with operator-supplied input (per security-plan §Security Anti-Patterns → Code Patterns). This covers any Edge, WebView2-app or NVDA launch the control adds.
- NEVER let committed evidence records leak absolute host paths, including paths spoken in foreign window titles that NVDA transcribes (per security-plan §Security Anti-Patterns → Logging).
- NEVER introduce an inbound listener or non-loopback egress for the control page (per security-plan §Security Anti-Patterns → Universal, and §Threat Model Summary → Infrastructure: Networking).

## Contract bindings
- a11y ↔ security: a11y-plan §3's screen-reader test pattern and `nvda-pass-spec.md` supply the spec ids and closed sets that the security ingest row cross-checks. A new control subject needs its rows in that spec before the scrubbed record can validate.
- arch ↔ security: any new env handle (the loader folder or browser-args variable) or port must be registered in architecture.md §Occupied Resources and in a matching security-plan §Input Validation row. The registries are paired.
- tests ↔ security: if `wdio.conf.ts` or the specs change, the routine strict `--e2e` leg (test-plan §3) must still pass, as proof the guarded spawn forms are unchanged. The plan's host-path hygiene grep over committed evidence is the gate that binds the two.

Every drive-letter-anchored hit is enumerated and shown to be a non-path, such as a URL scheme or a registry key, before the gate is called green (per security-plan §Security Anti-Patterns → Logging).
- Every committed NVDA-derived row from the control comes from the `parse-nvda-log.ts` scrub. Closed sets hold, `heard` is ≤ 400 characters, and every host-path token is `<host-path>` with a `security_finding`. No raw `nvda-speech.*.log` is committed (per security-plan §Input Validation, SR ingest row).
- `git diff 4460307` over `crates/conductor-tauri/ui/wdio.conf.ts`, the SR specs and `scripts/` adds no spawn form outside rule (b)'s seven. If it does add one, a recorded operator ratification under playbook `:124` exists before the arm runs (per security-plan §Security Anti-Patterns → Code Patterns, rule (b)).
- The control leg binds no listener beyond `4444`/`4445` and makes no non-loopback request. Its focus page is local content (per security-plan §Threat Model Summary → Infrastructure: Networking; §Security Anti-Patterns → Universal).
