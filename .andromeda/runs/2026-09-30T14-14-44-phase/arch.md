## Constraints
- The `sr*` screen-reader suites (`sr` / `sr-empty` / `sr-error`) are one of THREE suite families over ONE WebdriverIO + tauri-driver stack, and the scope law puts driving Conductor's OWN webview in scope and PULSE's UI out of it. Step 1's "Conductor launched UNDER tauri-driver + msedgedriver" control and any OS-level key path must stay inside that one stack, aimed at Conductor's webview only (per architecture §Cross-cutting Patterns → Scope law).
- Trust boundary: the SR suites may spawn, beyond the driver pair, only the host NVDA named by `CONDUCTOR_NVDA` and "a fixed-argv PowerShell window-activation script", and neither may open a listener. If the leg's key path moves to OS-level `SendInput`, that one sentence describes what the leg spawns and must stay true. Whether a committed `SendInput` form still fits "fixed-argv window-activation script" or is a new spawned thing is research's question, with the ruling going to security rule (b) and P4 (per architecture §Cross-cutting Patterns → Trust boundary).
- Ports: `127.0.0.1:4444` (tauri-driver) and `:4445` (native WebDriver) are dev-only listeners that live and die with the harness. Each suite binds and releases the pair within its own session, with the tauri-driver child spawned at `cwd` = the workspace root. The confound control must reuse this pair and add no other listener. The shipped `conductor-cli` / `conductor-tauri` binaries keep no listener of their own (per architecture §Occupied Resources → Ports).
- `CONDUCTOR_NVDA` and `CONDUCTOR_MSEDGEDRIVER` each have one COMMITTED reader, `crates/conductor-tauri/ui/wdio.conf.ts`. Each is validated at the harness edge (existence + `isFile` + shell-metacharacter rejection) and used only as an array-form spawn element: the NVDA path is a detached spawn with a fixed argv. Neither value is ever logged, echoed into an artifact or committed. An unset or unresolved handle skips at exit 0, and exits non-zero under `CONDUCTOR_A11Y_STRICT`. A step-1 or step-2 run through a new entry point must keep this handling (per architecture §Occupied Resources → Environment variables, `CONDUCTOR_NVDA` / `CONDUCTOR_MSEDGEDRIVER` / `CONDUCTOR_A11Y_STRICT`).
- Registration grain: every env-handle row in §Occupied Resources names its COMMITTED reader or binder. Per the scope's registration rule (operator ruling E1 at the prior wrap), a reader or binder this chunk COMMITS, such as `WEBVIEW2_BROWSER_EXECUTABLE_FOLDER` or a `:4445` binder, gets registered at wrap. A per-command, uncommitted use gets no row. Caveat: my grep of architecture.md found no sentence stating the "STANDING committed readers only" rule itself. Its basis here is the scope and the ruling, not arch text, and the plan must cite it that way (per architecture §Occupied Resources → Environment variables; scope §The CARRY → Registration rule).
- The `sr*` arms need a live Pulse and stay operator-local, never CI. Only the routine `--e2e` arm is the CI a11y gate, so no change in this chunk may move an `sr*` suite into `.github/workflows/ci.yml` (per architecture §Established Decisions → [CI/CD]).
- The a11y self-obs landing site is per suite: the one tauri-driver spawn site picks `CONDUCTOR_RUNS_DIR` for each suite (`sr` / `sr-error` → `runs/sr-leg/logs/…`, `sr-empty` → `runs/logs/…`). A new launch path for step 1 must choose it the same way and never leave the handle unset (per architecture §Occupied Resources → On-disk artifacts, `logs/conductor-tauri.jsonl`).

## Patterns to follow
- A verdict stated with its configuration: the a11y CI verdict names runtime, driver, coherence, integrity and run id because "the next image bump can move any of them". Step 2's rule that every verdict names runtime × driver × NVDA × OS build × input path follows this precedent (per architecture §Established Decisions → [CI/CD]).
- A mechanism is recorded, not established: the plan marks the elevated-token mechanism "recorded, not established — no probe measured it". The scope's `[inferred]` focus-event mechanism takes the same wording (per architecture §Established Decisions → [CI/CD]).
- A harness script is placed with an explicit qualifier: every non-harness `scripts/` row states who invokes it and that it "adds no 6th command". Any committed key-injection or activation helper gets a tree row in that form at wrap (per architecture §Infrastructure Patterns → directory tree).
- Handles are passed by env map and array-form spawn, never through a shell, as in the existing `startNvda` / `stopNvda` and `--native-driver` handling in `wdio.conf.ts` (per architecture §Occupied Resources → Environment variables, `CONDUCTOR_NVDA`).

## Anti-patterns to avoid
- A second automation stack, such as a standalone input-automation harness beside WebdriverIO + tauri-driver, or any key injection aimed at Pulse's UI (per architecture §Cross-cutting Patterns → Scope law).
- A new listener, or a new `agent-run` verb or arm, added to host the confound control. The harness stays five commands, and the only permitted listeners are the harness-lifetime `4444` / `4445` (per architecture §Occupied Resources → Ports; §Infrastructure Patterns → directory tree "no 6th command").
- A §Occupied Resources row for an uncommitted, per-command handle or binder, or a missing row for one this chunk does commit (per architecture §Occupied Resources → Environment variables; scope Registration rule E1).
