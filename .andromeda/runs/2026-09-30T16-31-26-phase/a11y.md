# a11y extract

## Relevance
relevant — the chunk changes the desktop-webview's accessible structure (coverage-row name, report/matrix cells, heading and landmark set) and regrades the `sr*` screen-reader leg; it touches the run-report-view must-be-accessible path (per a11y-plan §1 Critical paths).

## Constraints
- Landmarks: a11y-plan §4 (Per-surface landmark roles inventory) requires `main` + `contentinfo` (the footer status strip), with `banner` optional. It records `contentinfo` as designed but absent from the shipped DOM, "a recorded finding, route-owned". §11 Screen Reader bans a window without those landmarks. So S0-14's "or a recorded reason for none" branch conflicts with a standing plan ban. Taking that branch is a master amendment for the drift pass to raise, not an in-chunk record. Whether the shipped DOM still lacks `contentinfo` is research's question.
- Headings: the §4 note under the landmark table derives, for SC 1.3.1 and SC 2.4.6, a single `h1`-equivalent on the phase-line Heading role per run-state. S0-13's "no `h1`" is therefore measured against a plan requirement. Research must confirm whether the phase line carries heading semantics in each run-state the leg visits.
- Coverage-matrix row: a11y-plan §4 (the per-component catalog's Coverage matrix row) and §5 (run-console-live / idle-with-report) set these requirements:
  - table semantics, `table aria-label="Coverage rows"`, one `tr.cov__row` per P-ID;
  - roving focus through ONE tab stop: the current row alone has `tabindex="0"` and carries `aria-current="true"`, never `aria-selected`;
  - ArrowUp/ArrowDown ±1 (clamped), Home/End;
  - every row rendered.

  §11 Screen Reader requires every P-ID row to stay "reachable / announceable" (SC 1.3.1, SC 4.1.2). The plan does not spell out the row's accessible-name composition. Whether the rendered row name omits its P-ID (product fix) or the row's token/action is mis-aimed (re-token) is research's question, per the scope's DOM-first directive.
- Semantic HTML first: per a11y-plan §2 Agent-runnable invariants and §4 Naming convention, `aria-label` is reserved for icon-only controls with no feasible visible label (§11 ARIA, "NEVER overuse `aria-label`"). §11 Screen Reader bans redundant labels that double-announce. So a row-name or cell-content fix should reach for native table semantics before an `aria-label` on a `tr`/`td`.
- Screen-reader pattern: a11y-plan §3 (Screen reader test pattern) makes the NVDA leg agent-driven over the one tauri-driver/WebdriverIO stack, graded from NVDA's speech log.
  - Tab, Shift+Tab and the browse keys `h`/`d`/ArrowDown go through `send-keys.ps1`'s closed `-Key` set on the OS input path.
  - The reset cycle, Enter, Space, Escape and the picker keys stay WebDriver-injected.
  - Every row records its input path (`os`/`webdriver`/`mixed`/`none`).
  - A browse row with no OS key in its window stays a recorded finding. It is never a pass and never a manual arm.
  - Verdicts are configuration- and input-path-bound: runtime × driver × NVDA × Windows build × input path, stated beside the grade.
- Physical keyboard: per a11y-plan §3 (Screen reader test pattern), the physical-keyboard arm is "not run — founder ruling, the cause being already isolated by C1; retired, not pending". The chunk must not plan, run or simulate it.
- Supplemental, never sole: per a11y-plan §2, §3 (Screen reader test pattern, "Supplemental to automated") and §11 Universal, the SR pass verifies announcement quality only. Any product change to row names, cells, headings or landmarks must also sit under the automated baseline: axe `withTags(['wcag2a','wcag2aa','wcag21aa'])` on the routine arm, per §3 Configuration. §10 holds zero WCAG AA violations on the four paths, with no retry-once.

## Patterns to follow
- The SR pass spec format per a11y-plan §3 (Screen reader test pattern → Pass spec format):
  - one row per must-announce item, carrying its producing action, carrying node, expected NVDA output + required tokens, WCAG SC, result, arm and heard text;
  - the spec lives in `nvda-pass-spec.md` (51 rows) and is graded by `parse-nvda-log.ts`;
  - `operator_review` is transcribed into the chunk's `evidence/nvda-pass.json`.

  A re-token edits the row's token, node or action in that spec, with its reason.
- The OS input path per a11y-plan §3 (Screen reader test pattern) already admits `h`, `d` and ArrowDown. Driving the 7 `not-run-here` browse rows rides the existing closed key set.
- Routine-arm ownership per a11y-plan §5 (idle-with-report) and §9: the routine arm owns row navigation, the `aria-current` edge distinct from the `--color-focus` ring, and axe clean on the navigated state. A product change to the row or table is proven there, CI-gated by job `a11y`.
- Real-prose states per a11y-plan §3 (Screen reader test pattern, must-announce list) and §11 Visual. Status and fixture text (`Blocked`, `Not yet run`, `Manual`, the fixture name) is DOM text an SR can reach. Lamp display labels follow the §6 State-naming crosswalk: `Manual`/`Blocked` are display labels, not obs enums.
- Readiness before axe per a11y-plan §9 (Readiness before every axe analysis): any new or moved routine-arm axe call goes through `axeFindings()`'s bounded readiness wait, never a retry or a sleep.

## Anti-patterns to avoid
- The ARIA-on-non-semantic-HTML and ARIA-noise bans per a11y-plan §11 ARIA and §11 Screen Reader:
  - no `role` or `aria-label` layered onto non-semantic nodes to force an announcement;
  - no duplicated `<label>` + `title` + `aria-label`;
  - no `aria-hidden`/`display:none` on lamp, count or phase-line nodes;
  - no `role="presentation"` on `main`/`contentinfo`.
- Keyboard-order bans per a11y-plan §11 Keyboard: no `tabindex > 0`, and a row-name fix must not break the one-tab-stop roving focus. Per §5, the routine arm's focus-order spec asserts no `tabindex > 0`.
- Human-only SR bans per a11y-plan §11 CI and §11 SLO:
  - no human-only SR review standing in for machine output;
  - no retry-once or soft SLO for an a11y regression;
  - no leaking absolute host paths into the committed record (§11 SLO, inherited from tests' Status JSON constraint).

## Contract bindings
- a11y ↔ tests: the `sr*` suites (`a11y:sr` / `a11y:sr-empty` / `a11y:sr-error`) and the routine `--e2e` arm ride tests §6's one tauri-driver/WebdriverIO stack. The routine arm's expected-skip SET is held at exactly two under `CONDUCTOR_A11Y_STRICT`, per a11y-plan §9 and §11 CI. A product change must leave that SET and every existing routine/driven spec green, and `npm run a11y:ownership` must stay green (§11 Strategy).
- a11y ↔ security: the `sr*` legs' per-key OS input is `send-keys.ps1`, cited in a11y-plan §3 (Screen reader test pattern). Its registration and closed key set belong to the security plan (rule (b), eighth form). Widening the key set, or adding a spawn for a second, un-stopped live session (T-01), crosses that boundary.
- a11y ↔ obs: routine-arm results fold into the obs §6 envelope per a11y-plan §3 (Structured violation JSON schema): axe rule-id + SC tag + node selector per node in `fingerprints[]`. Selectors stay DOM-relative, never host paths.
- a11y ↔ design / layouts: the current-row `--border-emphasis` edge is distinct from the `--color-focus` ring, and lamp labels follow §6 State color tokens (not-color-alone). The heading and footer-strip semantics come from layouts' Heading Hierarchy Anchors, as a11y-plan §4's note derives them. Whether layouts itself states the `h1`/`contentinfo` placement is the layouts extractor's question.

## Acceptance criteria contributions
- The regrade record (`evidence/nvda-pass.json`) passes if:
  - every row carries an agent-arm grade with its input path recorded;
  - no browse row that had an OS key in its window is left `not-run-here`;
  - each re-tokened row states its reason;
  - the verdict is stated with its full configuration (runtime × driver × NVDA × Windows build × input path).

  It fails if any of those is missing, and if any row is graded by a physical-keyboard or manual arm (per a11y-plan §3 Screen reader test pattern).
- Focus rows S0-09 and E0-05 pass when NVDA's heard text on the OS path carries `P-001`, closing the focus-row red count from 2 to 0. The roving row focus must be unchanged: one tab stop, current row `tabindex="0"` + `aria-current="true"`, no `tabindex > 0` (per a11y-plan §5 run-console-live / idle-with-report and §4 Coverage matrix).
- The rendered DOM passes if it exposes `main` + `contentinfo` and a single `h1`-equivalent on the phase line. It fails if either is absent without a ratified a11y-plan amendment superseding the requirement (per a11y-plan §4 landmark inventory and its note, and §11 Screen Reader).
- The routine `--e2e` arm passes if, on the changed DOM, it is green with axe clean under `wcag2a`/`wcag2aa`/`wcag21aa`, the expected-skip SET is unchanged at two under `CONDUCTOR_A11Y_STRICT`, and `npm run a11y:ownership` is green (per a11y-plan §9, §10 and §11 Strategy).
