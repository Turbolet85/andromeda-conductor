The a11y semantics themselves (row names, headings, landmarks) are the a11y/design plans' domain.

## Constraints
- Product code for the row-name / heading / landmark fixes belongs in `crates/conductor-tauri/ui/` — the Vite + React 19 SPA, which is NOT a Cargo workspace member and is invisible to cargo; architecture §Occupied Resources → Frontend asset subtree and §Inherited Defaults → Frontend require TypeScript strict, npm with a committed `package-lock.json`, and an `npm audit --omit=dev` clean production tree. The scope expects no new dependency; any npm addition would be a production-tree delta that gate must re-read (per architecture §Inherited Defaults).
- Driving Conductor's OWN webview is in-scope, but only as the THREE suite families (four `wdio` suites) over ONE WebdriverIO + tauri-driver stack — the `sr` / `sr-empty` / `sr-error` legs with NVDA's speech log as the driver — never a second automation stack (per architecture §Cross-cutting Patterns → Scope law). Driving the 7 browse `not-run-here` rows and any T-01 second session must stay inside that stack.
- The trust boundary enumerates exactly what the `sr*` suites may spawn — tauri-driver / native WebDriver on dev-only harness-lifetime loopback `4444`/`4445`, the host NVDA named by `CONDUCTOR_NVDA`, the fixed-argv window-activation script, and per key the foreground-guarded `send-keys.ps1` with its closed `-Key` set (the eighth governed form) — none opening a listener (per architecture §Cross-cutting Patterns → Trust boundary; §Occupied Resources → Ports). Any spawn, listener or egress outside that list is a boundary widening; whether a second live session for T-01 fits within it is research's question, and a widening routes to the founder's live word, not a delegate.
- The `sr*` arms need a live Pulse and remain operator-local, never CI; the Pulse-free routine `--e2e` arm is the only a11y leg the CI `a11y` job asserts, and it must stay green (per architecture §Established Decisions → [CI/CD]). A product change that moves the coverage-row name or the heading structure therefore has a CI-gated consequence through the routine arm, separate from the operator-local regrade.
- The internal core↔UI surface is fixed: Tauri `#[tauri::command]` request/response for start/stop/picker/run-report view/operator-pause plus ONE `Channel` for live counters (per architecture §Conventions → Interface surfaces; §Occupied Resources → Interface routes / surfaces). If a row's missing content (e.g. a P-ID or a status/fixture value) is not already delivered to the webview by the existing commands, adding a command or a second Channel is an architecture change; whether the needed data already reaches the DOM is research's question (the scope's per-row DOM confirmation).
- No new env var: the `CONDUCTOR_*` namespace is reserved for handles over artifacts/concepts the architecture defines, and the SR leg's handles are the existing `CONDUCTOR_NVDA`, `CONDUCTOR_MSEDGEDRIVER`, `CONDUCTOR_SCENARIOS_DIR` (set by `wdio.conf.ts` for `sr-empty`/`sr-error`) and `CONDUCTOR_A11Y_STRICT` (per architecture §Occupied Resources → Environment variables).
- The PREREQ's Rust gates compile `conductor-tauri`, whose `tauri::generate_context!` resolves `ui/dist` at compile time, so the webview bundle must be built (`npm run build`, the `ensure_frontend` step) before any workspace clippy/nextest; a bundle-serving binary for the webview legs requires `--features tauri/custom-protocol` (per architecture §Infrastructure Patterns → CI/CD approach / build notes). A React change therefore reaches the Rust gates through the bundle even at zero Rust delta.

## Patterns to follow
- Harness handles are validated at the wdio harness edge (existence + `isFile` + shell-metacharacter rejection) and spawned array-form with fixed argv, never interpolated into a shell; an unresolved handle SKIPs at exit 0 unless `CONDUCTOR_A11Y_STRICT` is affirmative (per architecture §Occupied Resources → Environment variables, `CONDUCTOR_NVDA` / `CONDUCTOR_MSEDGEDRIVER` / `CONDUCTOR_A11Y_STRICT`). Any leg change in `wdio.conf.ts` or the SR spec keeps this shape.
- The a11y violation record's `fingerprints[]` carry DOM-relative / `data-testid` selectors so the record holds no host path (per architecture §Occupied Resources → On-disk artifacts, `runs/a11y/<run_id>.jsonl`). A product change to the coverage table or heading/landmark structure should keep selectors DOM-relative / `data-testid`-anchored.
- The routine arm seeds its own committed fixture through the production writer (`CONDUCTOR_E2E_SEED_DIR`, read only by `conductor-run/tests/envelope_fixture.rs`) (per architecture §Established Decisions → [CI/CD]; §Occupied Resources → Environment variables). Fixture values the SR rows expect (e.g. `lamps-fixture`, `Blocked`) originate there; if a regrade needs different fixture content, change it through that writer path rather than hand-editing a seeded artifact.
- Status labels rendered in the webview map from the closed `state ∈ {Pass, Fail, ManualCheck, KnownResidual, Blocked}` set (per architecture §Standard Contracts → Run report envelope); a cell conveying status (E0-08 `Blocked`, S3-06 `Manual`) conveys a member of that set, and no new state variant is introduced to satisfy a row.

## Anti-patterns to avoid
- No new inbound listener, no new spawn form, no new egress for the regrade or a T-01 second session without a founder-ratified widening (per architecture §Cross-cutting Patterns → Trust boundary; §Occupied Resources → Ports).
- No second UI automation stack and no automation of PULSE's UI — T-01's live session drives Conductor's own webview only (per architecture §Cross-cutting Patterns → Scope law).
- No new Tauri command, `Channel`, `Verdict`/`ReportState` variant or envelope key added merely to make a heard line carry content (per architecture §Conventions → Interface surfaces; §Standard Contracts → Run report envelope).
