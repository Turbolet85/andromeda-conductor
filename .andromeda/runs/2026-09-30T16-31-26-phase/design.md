# design extract

## Relevance
partial. The chunk mostly changes accessible structure: row names, status-cell conveyance, and an h1 plus a `contentinfo` landmark or a recorded reason for none. Design binds only where a fix changes a visible node or its text, or adds one: the coverage-matrix row, the lamp and text pair, the run-report cell, a new heading, or a footer strip. The sr leg's row table, its key actions and the PREREQ gates are outside this domain.

## Constraints
- The coverage-matrix row's visible anatomy is fixed: lamp glyph + label + P-ID in JetBrains Mono `--color-id-cyan` + SLO tier + latency_ms. The keyboard-current row is marked by `aria-current` plus a 2px `--border-emphasis` left edge on its P-ID cell, and that marker is distinct from the `--color-focus` ring. Every P-ID cell reserves a transparent 2px edge, so columns never shift. A fix that puts the P-ID into the row's accessible name must leave this visible anatomy and the reserved edge unchanged (per design-system §Surface: desktop-webview → Component Patterns 3). Whether the shipped row already exposes the P-ID in its name is research's question.
- Every lamp and every report-state cell carries its text label: `Pass`/`CalibrationRegion`/`Fail`/`Blocked`/`Manual`/`Residual`. The text is always rendered and is what carries the signal. Color and glyph only de-emphasize or reinforce it (per design-system §Iconography and §Surface: desktop-webview → Component Patterns 4 and 6). The status findings (E0-08 `Blocked`, S3-06 `Manual`) name exactly these labels. Whether the DOM already renders them as text, or only as a glyph or color, decides product fix versus re-token, and that is research's question.
- The empty and not-yet-run states are distinct strings with fixed tiers. `No run yet` is in `--text-tertiary`. `No coverage data.`, `No scenarios found.` and `No scenarios match.` are three states with three strings. A not-yet-run state must never collapse into a `Fail` or `Blocked` render (per design-system §Surface: desktop-webview → Component Patterns 3, 5 and 6; §Anti-Patterns → Rejected Defaults "Conflating no result yet with failed"). The S0-15 finding's `Not yet run` must be checked against which of these shipped strings and states the node carries. That check belongs to research, and the plan does not name `Not yet run` as a shipped string.
- Any new or visibly promoted heading uses the typography roles: Heading is IBM Plex Sans 600 18px/1.3, used for the phase line and panel titles. The mono status tier is reserved for count, P-IDs, run_id, SLO timings and fingerprints. It is never a heading face (per design-system §Typography; §Anti-Patterns → Rejected Defaults "A monospace font used everywhere").
- A `contentinfo` footer is not specified by the design plan. Pattern 7 records "the window footer strip is unbuilt as of 2026-09-02". If a footer is built, it must take its tokens from the surface, border and spacing scales: `--color-raised-1` or `--color-base`, a `1px --border-subtle` seam and `--space-*` steps. Depth is borders-only, with no shadow (per design-system §Surface: desktop-webview → Component Patterns 7; §Depth Strategy; §Spacing). Whether to add a visible footer or record a reason for none is a layouts and P4 question, not a design mandate.
- Every color, spacing, radius and motion value binds a `:root` token by `var(--…)` name, never a raw hex or px value. Any transition must drop under `prefers-reduced-motion: reduce` (per design-system §Surface: desktop-webview → Tokens; §Motion).

## Patterns to follow
- The coverage matrix is one tab stop: a roving current row moved by ArrowUp/ArrowDown/Home/End that scrolls into view, with no virtualization. A name change must preserve this model (per design-system §Surface: desktop-webview → Component Patterns 3).
- The run-report P-ID line is IBM Plex Sans body in `--text-secondary`, with mono ID-cyan P-IDs, run_id and timings, and the lamp plus its text label. Follow this when making a status or fixture cell convey its value (per design-system §Surface: desktop-webview → Component Patterns 6).
- The hint line is `text-tertiary`, not focusable and not a live region. S3-06 heard this line, so its non-focusable, non-live character is by design and must be kept (per design-system §Surface: desktop-webview → Component Patterns 5).
- An announced region that must speak is persistently mounted. A region that mounts together with its text announces nothing. Reuse this pattern if a fix adds or moves an announced status (per design-system §Surface: desktop-webview → Component Patterns 5).

## Anti-patterns to avoid
- Do not signal status by color alone, and do not drop the text label to shorten an accessible name. The glyph and color must always accompany the text (per design-system §Anti-Patterns → Universal Bans "NEVER use color purely for decoration"; §Iconography Rule).
- Do not add drop shadows, `backdrop-filter`, or a new decorative color for a new heading or footer. Depth is borders-only and every color means a status (per design-system §Anti-Patterns → Per-Surface Bans, desktop-webview; §Depth Strategy).
- Do not restyle the coverage wall into cards or tiles while restructuring rows (per design-system §Anti-Patterns → Universal Bans "cookie-cutter card grids"; Rejected Defaults "KPI metric cards").

## Contract bindings
- Design ↔ a11y: the lamp plus text-label pairing binds to a11y's SC 1.4.1 use-of-color rule. The row and cell accessible names are a11y's to specify, and design governs only the visible text they must stay consistent with.
- Design ↔ layouts: heading hierarchy (h1) and landmark structure (`contentinfo`) are layouts' domain. Design supplies only the typography and tokens of any visible node added.
- Design ↔ tests: the routine a11y arm asserts the focus ring through computed `outlineStyle`/`outlineColor` (per design-system §Depth Strategy), and the axe/contrast job asserts token contrast (per design-system §Color Palette → Text Hierarchy). A change to the row DOM or the heading structure must keep both green.

## Acceptance criteria contributions
- (design) Any changed or added visible node uses only `:root` tokens, with no hardcoded hex, px or ms values (per design-system §Surface: desktop-webview → Tokens; §Self-Validation Protocol 4 Token Test).
- (design) The coverage row still renders the P-ID in `--font-mono` / `--color-id-cyan`, and still marks the current row with the 2px `--border-emphasis` P-ID-cell edge distinct from the `--color-focus` ring, with no column shift (per design-system §Surface: desktop-webview → Component Patterns 3).
- (design) Every status and report-state cell the findings name (`Blocked`, `Manual`, and the not-yet-run state) renders its text label beside its lamp glyph, never color or glyph alone (per design-system §Surface: desktop-webview → Component Patterns 4).
- (design) A new h1 or footer adds no shadow or blur, and no transition that survives `prefers-reduced-motion: reduce` (per design-system §Depth Strategy; §Motion).
