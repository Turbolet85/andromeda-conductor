# layouts extract

## Relevance
partial — the chunk touches the desktop-webview's accessible structure (coverage-matrix row, report/matrix status cells, heading and landmark set, the designed-not-shipped footer), but every attribute-level remedy (accessible name, `h1`, `contentinfo` role) is a11y's to derive; layouts owns only the anatomy, the region order and the focus model those remedies must not break.

## Constraints
- Surface and regions: every row in groups 1-4 sits on the ONE desktop-webview surface — a single frameless window with no router, no routes and no breakpoints; its "screens" are run states (`idle` · `live` · `hold` · `aborted`, idle-with-report a sub-state of `idle`). A fix is placed in an existing region (titlebar · run-controls group · coverage matrix · run-report card · footer strip) and never adds a page or view (per layout-templates §Surface: desktop-webview → §Primary screens; §IA notes).
- The coverage-matrix row is FOUR cells in fixed order: P-ID (leftmost) → Capability (title above category) → Mode → Status (last). `slo_tier`/`latency_ms` are deliberately not in it. A fix that gives the row a P-ID-bearing name (E0-05 / S0-09 / E0-09 / S3-07) must keep that cell set and order, so the visual reading order still starts at the P-ID (per layout-templates §Component — Primary content block 1).
- The matrix region has exactly ONE tab stop: the current row, with roving focus (ArrowUp/ArrowDown ±1 clamped, Home/End; a row focused by any means becomes current). The bounded scroll container is NOT itself a tab stop, and the current row is marked `aria-current="true"` plus a 2px `border-emphasis` edge on its P-ID cell. A row-name fix must not add a second tab stop inside the row or the region (per layout-templates §Component — Primary content block 1, States).
- The Status cell carries the 6-state lamp paired with its status text, or the "Not yet run" ABSENCE prose (Body, `text-tertiary`) when no run record names the P-ID. That text is the distinguishing signal, and tint is never the only one. S0-15 (`Not yet run`) and S3-06 (`Manual`) name this cell's required text (per layout-templates §Component — Primary content block 1; §Component — Primary content block 2).
- Run-report verdict lines are lamp + verdict/state text + mono identifiers (P-ID, run_id, slo_tier, latency_ms). Blocked rows carry the named precondition string, and their measurement columns render `—`/null, never red. E0-07 (the `lamps-fixture` value) and E0-08 (`Blocked`) name this card's content (per layout-templates §Component — Primary content block 2; §Wireframe — Idle with a report).
- The footer status strip is DESIGNED, NOT SHIPPED: the plan records the release DOM's landmark set as `banner` + `main` + two `region`s, with no `contentinfo`. If the strip ships for S0-14, its anatomy is fixed: a single line pinned to the window bottom showing `conductor` · `seed <n>` · the run phase, plus the verdict roll-up and the unticked-ManualCheck count on the report. It has no links, no legal text and no brand chrome, and every count token is paired with its label. If it does not ship, the "recorded reason for none" must agree with the plan's route-owned-gap wording (per layout-templates §Component — Footer (status strip); §Wireframe — Run console (idle)).
- The heading structure is described only as typography ROLES. The phase line is the Heading role and takes one of four fixed state labels. The section headers `COVERAGE` and `RUN REPORT` are Label-role strips. The plan names no document heading level, so which node carries an `h1` for S0-13 is a11y's derivation, not a layout mandate. Whether the rendered DOM's three `h2`s map to these strips is research's question (per layout-templates §Component — Header; §Wireframe — Run console (idle); §Decisions Log → Notes).

## Patterns to follow
- A designed-vs-shipped annotation sits beside the anatomy: the plan marks unbuilt elements inline ("DESIGNED, NOT SHIPPED … measured 2026-09-02") and cites the SR row that measured them (E0-01, S0-16, R0-01, S2-08). A disposition this chunk records (product fix vs re-token) follows the same shape, with the row ID and the measurement date next to the structural claim (per layout-templates §Component — Primary content block 1, States; §Component — Footer (status strip)).
- Adapt, don't fork: one component serves several contexts. Examples are the operator-checklist primitive, and the out-of-scope Mode treatment carried per surface. A status or name fix lands in the shared primitive (the matrix row, the lamp-plus-text pairing) and is not duplicated per SR row (per layout-templates §Component — Operator-checklist; §Component — Primary content block 1, Mode).
- Announced-once siting is the precedent for fixing a double or misplaced announcement: the catalog load-error's visible copy sits OUTSIDE its `role="alert"` region, which carries a visually-hidden re-assertion inserted once. Where a group-2 row's heard text comes from the wrong node, prefer re-siting over duplicating content (per layout-templates §Component — Primary content block 1, States).
- The key-map hint line is a fixed element inside the run-controls group: Data role, `text-tertiary`, not focusable, no live region. S3-07 heard this line at the ArrowDown step, so its position between the controls row and the matrix is the neighbour the virtual cursor can land on. It stays where it is and is not made focusable (per layout-templates §Component — Primary navigation; §Wireframe — Run console (idle)).

## Anti-patterns to avoid
- Don't let a Status or Mode fix introduce a color-only state, a seventh lamp state or a flashing lamp. The lamp set stays closed at six, and every lamp is paired with its text (per layout-templates §Component — Primary content block 1; §Component — Primary content block 2).
- Don't add a KPI-card grid, a new route or view, or a per-row focusable child while restructuring the matrix row for its accessible name. The matrix is a dense single-row-per-P-ID list with one roving tab stop (per layout-templates §Component — Primary content block 1; §Decisions Log → Key layout choices).
- Don't bind a single-letter console key. Single letters stay free for the picker's type-ahead and the screen reader's browse mode, and the group-3/4 rows drive `h`/`d`/ArrowDown in browse mode. Console keys stay on the modifier map (Ctrl+Enter / Ctrl+. / Escape) (per layout-templates §Component — Primary navigation).

## Contract bindings
- layouts ↔ a11y: the plan defers every concrete attribute to a11y ("a11y derives the label / live-region attribute / focus semantics"). The row's accessible name, the `h1` choice and the `contentinfo` role are a11y-plan derivations over this anatomy. Visual reading order (P-ID first) must match focus and reading order, per a11y's Focus Order (SC 2.4.3) (per layout-templates §Decisions Log → Notes; §Component — Primary navigation).
- layouts ↔ tests (the `sr*` row table and the routine `--e2e` arm): the SR row IDs the plan cites (E0-01, S0-16, R0-01, S2-08) tie this plan's anatomy claims to the screen-reader spec. A product change to the row name, heading structure or footer can move existing `--e2e` selectors and assertions, and re-tokened rows must name nodes this anatomy actually renders (per layout-templates §Component — Primary content block 1, States; §Component — Operator-checklist).
- layouts ↔ design: shipping the footer uses only existing tokens (`space-sm` height, the `border-subtle` top seam, `text-tertiary`, the status-color count tokens), and design owns their values (per layout-templates §Component — Footer (status strip); §Decisions Log → Notes).
- layouts ↔ the plan itself: shipping the footer or a heading changes the facts behind the plan's "DESIGNED, NOT SHIPPED" annotations (three wireframes plus §Component — Footer) and §Component — Footer's landmark-set sentence. That is master drift, which wrap's amendment flow owns (per layout-templates §Wireframe — Run console (idle) / (HOLD) / Idle with a report; §Component — Footer (status strip)).

## Acceptance criteria contributions
- (layouts) The coverage-matrix row keeps its four cells in the order P-ID → Capability → Mode → Status, and the region keeps exactly one tab stop (the `aria-current="true"` row) after the P-ID-name fix; a count of tabbable descendants of the matrix region equals 1 (per layout-templates §Component — Primary content block 1).
- (layouts) Every Status cell renders its status text (`Pass` / `CalibrationRegion` / `Fail` / `Blocked` / `Manual` / `Residual`) or the `Not yet run` prose as DOM text beside the lamp. A row with a lamp and no text fails (per layout-templates §Component — Primary content block 1; §Component — Primary content block 2).
- (layouts) S0-14 is dispositioned one of two ways. (a) A footer strip ships at the window bottom in the anatomy §Component — Footer states: one line, seed plus phase plus roll-up, no links. (b) No strip ships, and the recorded reason is consistent with the plan's designed-not-shipped annotation. Either way, the plan's DESIGNED-NOT-SHIPPED markers are raised for amendment at wrap if (a) holds (per layout-templates §Component — Footer (status strip)).
- (layouts) No new route, view, modal or single-letter console key is introduced. The surface stays one frameless window whose states are the four shipped `RunState`s (per layout-templates §Primary screens; §Component — Primary navigation).
