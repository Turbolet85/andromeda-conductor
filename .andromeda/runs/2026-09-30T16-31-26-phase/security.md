## Constraints
- Harness-spawn rule (b) holds exactly EIGHT governed forms; the `sr*` legs' OS key path is the eighth (`send-keys.ps1`, `-File` only, closed `-Key` `ValidateSet` of `Tab` · `ShiftTab` · `h` · `d` · `ArrowDown`, foreground-guarded, a non-zero exit throws with no injected fallback). Driving the 7 browse `not-run-here` rows must stay inside that closed set; any key outside it, any new spawn, or any change to the script's key set is a ninth crossing that needs the founder's live word at P4, never a delegate's (per security-plan §Security Anti-Patterns → Code Patterns, rule (b) EIGHTH form; the ratification scope rule is in `rules/security.md` Session Additions 2026-09-29, not in the plan). Whether every row's intended action maps onto the five admitted keys is research's question.
- The regraded `evidence/nvda-pass.json` is an ingest of untrusted third-party text. security-plan §Input Validation (Screen-reader speech-log ingest row) requires the spec-id cross-check against `nvda-pass-spec.md`, closed `outcome` / `arm` / `review_grade` / `input` sets (`input` ∈ `os` · `webdriver` · `mixed` · `none`), `heard` bounded at 400 chars, and the mandatory host-path scrub to `<host-path>` with a `security_finding` on the row. The raw logs stay under gitignored `runs/`.
- Committed evidence records must carry no absolute host path and no internal seam-crate struct name (per security-plan §Security Anti-Patterns → Logging, the committed-evidence clause naming `nvda-pass.json`). This also covers any new or re-tokened row text in the SR spec tables.
- Dev-host-tool handles `CONDUCTOR_NVDA` and `CONDUCTOR_MSEDGEDRIVER` are read only at the wdio edge: existence + `isFile` + shell-metacharacter rejection, then an array-form spawn; an unset handle skips at exit 0 (per security-plan §Input Validation, the `CONDUCTOR_MSEDGEDRIVER` / `CONDUCTOR_NVDA` rows; §Security Anti-Patterns → Input). The chunk must not relax these guards.
- The driver ports `4444`/`4445` stay harness-lifetime loopback only, and no shipped binary may gain an inbound listener. A second live session for T-01 may use only the `:4317` client egress (with the operator's grant) plus the MCP sidecar spawn under rule (a): a fixed program name, `.env(...)` for `ANDROMEDA_PULSE_DATA_DIR`, and console suppression (per security-plan §Security Anti-Patterns → Universal; → Code Patterns rule (a); §Threat Model Summary → Attack surface). Whether a second, un-stopped live session fits inside the registered forms is research's question. If it does not, it goes to P4 as an escalation.
- If a product fix touches the Tauri surface: the text reaching the webview (row names, status cells) must stay sanitized, with no host path, no struct name and no stack trace. Any `run_id`-class IPC argument must go through `resolve_under` and `sanitize_error` (per security-plan §Error Handling; §Input Validation, the `#[tauri::command]` row). The capabilities file must stay deny-by-default (per §Security Anti-Patterns → Code Patterns). Whether the fix needs any backend or IPC change at all is research's question. The scope expects a React-only delta.
- Supply chain: the scope expects no new dependency. If a frontend dependency does land anyway, `npm audit --omit=dev` must be clean and `package-lock.json` committed. If a Rust dependency lands, `cargo audit` and `cargo deny` must be green over a committed `Cargo.lock` (per security-plan §Dependency Security; §Security Anti-Patterns → Universal).

## Patterns to follow
- The OS-key spawn shape: `spawnSync('powershell.exe', ['-NoProfile','-ExecutionPolicy','Bypass','-File', <repo script>, '-Key', <closed-set constant>])`, with `windowsHide` and a bounded timeout. There is no operator value anywhere in the vector (per security-plan §Security Anti-Patterns → Code Patterns, rule (b) fifth-through-eighth form descriptions).
- The ingest scrub path: `writeNvdaPass` in `parse-nvda-log.ts` is the single site that bounds, closes and scrubs before the committed record is written (per security-plan §Input Validation, Screen-reader speech-log ingest row).
- Escalate, never self-ratify: a boundary crossing is recorded as a BREACH with a route-owned remedy until the founder speaks live (per `rules/security.md` Session Additions 2026-09-29; the plan records each form's ratification the same way in §Security Anti-Patterns → Code Patterns).
- Any synthetic leak control that a hygiene gate needs as its known positive lives in the gitignored `.andromeda/cache/`, never in the committed evidence tree (per `rules/security.md` Session Additions 2026-09-30; this is a rule-file entry, not a plan clause).

## Anti-patterns to avoid
- Never add an eval-equivalent or shell-string spawn, and never widen `send-keys.ps1`'s `ValidateSet`, to reach a row's key. Never fall back to an injected key when the OS path refuses (per security-plan §Security Anti-Patterns → Code Patterns, rule (b)).
- Never commit raw NVDA logs, or `heard` text that has not been scrubbed, into `evidence/` (per security-plan §Security Anti-Patterns → Logging).
- Never use `shell-open` with scenario-derived strings, and never embed a remote-origin iframe, if the product fix adds links or anchors to the webview (per security-plan §Security Anti-Patterns → Code Patterns).
