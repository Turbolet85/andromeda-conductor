## Relevance
relevant — the PREREQ closes on two test-plan gates (Lint + `--unit`), the product fix lands in a surface the routine `--e2e` arm asserts, and the regrade runs on the operator-local `sr*` screen-reader leg that test-plan §6 specifies.

## Constraints
- PREREQ gate shapes: test-plan §9 Pipeline structure and §3 `run` (CI stage selectors) require `agent-run.{sh,ps1} run --unit` to be the `cargo nextest run --workspace --profile ci` leg ONLY. Doctest (`cargo test --workspace --doc`) and Lint (`cargo clippy --workspace --all-targets -- -D warnings`) are separate stages and are never folded into `--unit`. So "close the deferral" means running clippy as its own command beside `--unit`, and recording each verdict from its own bare exit. §11 Quality ("NEVER skip quality gates 'just this once'") makes both gates binding even when the chunk's Rust delta is zero.
- The frontend has no unit tier: per test-plan §4 (`conductor-tauri/ui`), the React webview is build-gated (`tsc --noEmit` + `vite build` + `npm audit` + a `vite preview` render smoke). That gate does NOT prove ESM loadability. A TS member (a spec, `wdio.conf.ts`, the screen-reader helpers) counts as proven only by EXECUTING an npm leg that loads it: `--e2e` for the routine suite, `a11y:sr` / `a11y:sr-empty` / `a11y:sr-error` for the screen-reader members, and `a11y:ownership` for `claim-ownership.ts`. §4 and §12 hold that no JS/TS unit runner is adopted.
- The routine arm must stay green through any row-name or heading change. Per test-plan §3 `run` (`--e2e`), both shells assert the PRINTED verdict, never the exit code. That means zero on the `Spec Files:` failed count, a per-spec skip tally within the expected-skip SET (the two live-hold subjects, where a third skip is a failure), and the `[webview2 … windows]` banner. The arm seeds its own subject through `envelope_fixture` into `runs/e2e-fixture/`, and asserts the lamp collision rule plus the not-yet-run cell told apart from a failure BY DOM TEXT (§6 desktop-webview row). Which existing assertions and selectors key on the coverage-row name or the heading structure is research's question.
- The screen-reader leg's footing: per test-plan §6 (desktop-webview row, third family) and §2 (Agent-runnable invariants), the `sr*` suites run operator-local, on Windows + NVDA only. They are never a CI stage and never an `agent-run` verb, and they run on real wall clock. NVDA's speech log is the driver, and the operator's role is REVIEW of the graded record. Browse rows driven by an OS key are graded on the agent arm, and every row records its input path.
- The firing form is part of the leg (test-plan §6): `CONDUCTOR_NVDA` + `CONDUCTOR_MSEDGEDRIVER`, the per-suite runs/scenarios dirs chosen at the one spawn site, and `send-keys.ps1` with its closed `-Key` constant, sending only while `conductor-tauri` holds the foreground (a refusal THROWS, never falls back to injection). The live `sr` subject also needs `CONDUCTOR_SCENARIOS_DIR=runs/sr-leg/scenarios` plus the three `ANDROMEDA_PULSE_*` handles. Without that handle the walk dies at S0-04 on option order.
- The `not-run-here` zone is defined per test-plan §1 (Untestable zones, the screen-reader browse-mode bullet): it holds only browse rows with NO OS key in their window. Those rows are findings, never passes and never a manual arm. Driving group 4's seven rows with OS-path `h` / `d` / ArrowDown is what moves them out of the zone. Whether the spec's row table already assigns an OS key to those windows is research's question. T-01 is live-class, so browse keys cannot reach it (§6 `sr` subject; §2).
- Zero-flakiness (test-plan §10): a row that grades differently across two runs of an unchanged tree is a defect to diagnose, never a retry. §11 E2E bans `sleep(N)` for synchronisation INSIDE a test. The NVDA readiness, settle and utterance windows are the leg's declared real-clock firing form (§2), not a sync substitute.

## Patterns to follow
- Selector strategy (test-plan §6 Selector strategy): role / text / `aria-live` / data-testid plus mono P-ID tokens for coverage-matrix and report rows. If the coverage row's accessible name comes to carry its P-ID, the routine arm's P-ID-keyed row selectors are the existing precedent. The driven arm already compares focus restoration "by P-ID" (§6 driven arm).
- Verdict capture (test-plan §3 `run`, `--e2e`): capture wdio output to a log file, read the exit from the BARE command (never through a pipe), then assert on the printed counts. Apply the same discipline when recording the PREREQ clippy / `--unit` verdicts and each `sr*` leg's `Spec Files:` line.
- The committed fixture carries meaning (test-plan §7 Self-bootstrapping requirement): the lamps fixture is round-tripped through the production writer (`lamps_fixture.rs`, `envelope_fixture.rs`). If E0-07's `lamps-fixture` content turns out to need a product change, it stays sourced from that committed tree, never from hand-built DOM.
- The static ownership checker (test-plan §4): `npm run a11y:ownership` is asserted on its printed last line (`ownership: every claim resolved`) beside its exit. Re-run it if the chunk touches the claim table or the screen-reader row set.

## Anti-patterns to avoid
- No xpath, no hashed Tailwind/CSS-class selectors, and no in-test `sleep(N)` synchronisation (test-plan §11 E2E). A re-tokened row keys on role/text/P-ID, never on DOM position.
- No manual smoke step and no "human reviews" test step (test-plan §11 Universal). A row the agent arm cannot reach is a recorded finding (§1 Untestable zones), never re-labelled as an operator pass.
- No retry or pinning to hide a row that grades inconsistently, and no skipping the PREREQ gates because the Rust delta is small (test-plan §10 Zero-flakiness; §11 Quality / CI).

## Contract bindings
- tests ↔ a11y: the routine `--e2e` arm and the `sr*` legs are a11y-plan §3's harness. Tests owns their wiring: `--e2e` inside the 5-command discipline and the CI `a11y` job (test-plan §9 E2E (webview) row); `sr*` as npm-script legs outside it (test-plan §6).
- tests ↔ security: `send-keys.ps1`'s closed `-Key` set is rule (b)'s eighth form. The harness-only handles `CONDUCTOR_NVDA` / `CONDUCTOR_MSEDGEDRIVER` get their mandated coverage from the e2e skip-at-exit-0 arms (test-plan §1 Coverage triggers, Vector 1). Any new key, spawn or live-session form is outside the tests domain and escalates.
- tests ↔ obs: the `--e2e` leg writes one violation record at `runs/a11y/<run_id>.jsonl` (the eleven envelope fields plus obs §9 tags), and CI's reused `journal_conformance` gate reads it (test-plan §3 `run`; §9). A DOM-only change should leave §3 ↔ obs-plan §3 agreement untouched.
- tests ↔ design/layout: the selectors key on the text-paired status labels and the mono P-ID tokens (test-plan §6 Selector strategy). A change to the row name or the heading structure moves the selector surface.
