# layouts extract

## Relevance
partial — the chunk builds no new surface; it regresses the desktop-webview regions Epoch 5 moved (titlebar `h1`, coverage row, `contentinfo` footer), touches the run-report banner via C5 (E0-10), the cli refusal/error shape via C3, and must keep the knip dispositions (C2) layout-neutral.

## Constraints
- The titlebar phase line is required to render as the window's SINGLE `h1` carrying one of the four fixed state labels (`Conductor · idle` / `live` / `HOLD — operator pause` / `aborted`), never the segment name, while keeping the drag region; the three section headings stay `h2` (per layout-templates §Component — Header (frameless titlebar + Paused-count heartbeat)). Whether the shipped titlebar still satisfies this at chunk HEAD is research's question.
- The coverage matrix row is required to be exactly FOUR cells — P-ID · Capability · Mode · Status (last) — with `slo_tier`/`latency_ms` deliberately absent, one roving tab stop for the whole region (ArrowUp/Down, Home/End), and "Not yet run" as a text absence state (per layout-templates §Component — Primary content block 1 (coverage matrix — dense single-row-per-P-ID)). The "count named by visually-hidden text" moved surface is not stated in this plan's coverage-matrix section; its layout requirement, if any, is the a11y plan's to state.
- The status footer is required to be a top-level `footer` after `main` (the window's one `contentinfo`), ONE non-focusable, non-live text line with ` · ` separators as plain text, carrying `conductor` · `seed <n>` (`—` when no report) · the `RunState` word (no step index) · one `{n}` + `StatusLamp` per non-zero lamp in `LAMP_ORDER`; the HOLD accent rides an `aria-hidden` glyph, never a tint on the word; the unticked-ManualCheck count stays a DESIGNED-NOT-SHIPPED gap (per layout-templates §Component — Footer (status strip)). The measured landmark set is `banner` + `main` + the `region`s + `contentinfo` (same §).
- The run-level load-envelope banner (C5 / SR row E0-10's subject) is required to be a single qualifier row ABOVE the per-P-ID verdict lines and OUTSIDE the lamp column, whose label text ALWAYS renders (the tint is never the only signal), which is neither a seventh lamp nor a sixth `ReportState`, and which is omitted entirely when the run stayed in-envelope (per layout-templates §Component — Primary content block 2 (run-report view + verdict lamp); drawn in §Wireframe — Idle with a report). So E0-10 grades against the banner's label as text; whether `runs/e2e-fixture` carries an out-of-envelope record that makes the banner present is research's question.
- The empty/filter-miss/load-error states are three distinct App.tsx-owned states with three strings (`No scenarios found.` · `No scenarios match.` · the sanitized load-error render with its visible copy outside the `role="alert"` region) and the report empty state is `No run yet` (per layout-templates §Component — Primary content block 1 (States) and §Component — Primary content block 2 (Distinct non-result states)). A regression over the moved surfaces must not collapse them.
- cli: a `P-NNN`-shaped value passed to `preconditions --for` is refused at argument parsing (clap usage error, exit 2) because a P-ID can name several scenarios, and error output goes to stderr as `error: <short>` + detail + `hint: <fix>`, host-path-free, never colorized when piped (per layout-templates §Primary screens (commands) `conductor preconditions` and §Component — Footer / terminator + error output). This is the precedent C3's ambiguous-P-ID refusal would mirror; this plan does not itself state how `conductor run <P-ID>` must resolve.
- cli output structure is stable because downstream agents parse it — adding a column or a new bracket label without a `--format` flag is a breaking change; the per-P-ID lamp set is closed at six and the run-level non-lamp qualifier set is `[ENVIRONMENT-SUSPECT]` + `[PRECONDITION]` (per layout-templates §cli IA notes and §Component — Primary content block 2 (verdict / report-state lines)).

## Patterns to follow
- Refuse-an-ambiguous-P-ID shape: `preconditions --for` refuses a `P-NNN` value at parsing with a usage error rather than picking one (per layout-templates §Primary screens (commands)) — the layout-level precedent for C3's refusal arm.
- Run-level qualifier adapted per surface, never forked: cli `[ENVIRONMENT-SUSPECT]` (ANSI 246) ↔ Markdown banner ↔ webview banner on `var(--status-residual)` (per layout-templates §Component — Primary content block 2 (verdict / report-state lines)) — E0-10's expected content is the webview arm of this one qualifier.
- Harness printed-verdict discipline: the `--e2e` stage asserts the runner's PRINTED verdict (`Spec Files:` failed count, per-spec skip markers vs the expected-skip set, the `[webview2 … windows]` banner), not its exit code (per layout-templates §Primary screens (commands) `scripts/agent-run.{sh,ps1}`).
- `--live` leads with the non-priming `conductor preconditions` probe and refuses at exit 1 with one host-path-free `[PRECONDITION]` line per unmet subject; a missing host-tool handle is a SKIP at exit 0 on the lax arm and non-zero under `CONDUCTOR_A11Y_STRICT` (per layout-templates §Primary screens (commands) `scripts/agent-run.{sh,ps1}`) — the live-drive path's layout-level contract.

## Anti-patterns to avoid
- Removing or renaming an export as a knip (C2) disposition in a way that changes a rendered region — e.g. re-introducing the retired six-cell coverage row, or letting a matrix tab stop multiply — is banned; the row stays four cells with one roving stop (per layout-templates §Component — Primary content block 1).
- Grading or rendering the envelope banner by colour alone, or folding it into the lamp column as a seventh state (per layout-templates §Component — Primary content block 2 (run-report view + verdict lamp)).
- Making the footer focusable, a live region, or tinting the HOLD word (per layout-templates §Component — Footer (status strip)).

## Contract bindings
- layouts ↔ a11y: the single `h1`, the landmark set (`banner`/`main`/`region`s/`contentinfo`), the coverage matrix's roving focus and the footer's non-focusable/non-live status bind to a11y-plan's heading, landmark, focus-order (SC 2.4.3) and live-region rules; the SR rows (S0-14 landmark set, E0-01 empty catalog, S0-16 filter miss, R0-01 load error, E0-10 envelope banner) are the measurement surface (per layout-templates §Component — Footer (status strip) and §Component — Primary content block 1 (States)).
- layouts ↔ tests: the routine `a11y` arm's landmark spec and the `--e2e` printed-verdict assertions (per layout-templates §Component — Footer (status strip); §Primary screens (commands) `scripts/agent-run.{sh,ps1}`) bind to test-plan's harness and the both-runners gate.
- layouts ↔ security: cli error output host-path-free and sanitized at stderr (per layout-templates §Component — Footer / terminator + error output) binds to security-plan §Error Handling — applies to any new C3 refusal string.
