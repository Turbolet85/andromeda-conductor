- The regression's supply-chain arm must run BOTH `cargo audit` and `cargo deny check advisories bans licenses sources`, with the advisory-db checkout's porcelain check PRECEDING any classification of an audit failure as external; a red result verified local is cleaned, never deferred, and a verified-external one takes the bounded wait with the deny overlap verified green, never assumed (per security-plan §Dependency Security, "Two distinct external-decay faults"; §Security Anti-Patterns → Universal). The scope bars new dependencies, so `Cargo.lock` must stay committed and un-drifted (per security-plan §Security Anti-Patterns → Universal).
- The frontend gate set must include `npm audit --omit=dev` at 0 production vulnerabilities over a committed `package-lock.json`; dev-only advisories are accepted at dev-tree grain only (per security-plan §Dependency Security, "Frontend (npm) supply chain"). If C2's knip disposition removes an export, no dependency may be removed or added as a side effect without this gate re-run.
- C3 sits on the CLI-argument boundary: security-plan §Input Validation (CLI arguments row) requires the scenario key to map to a known P-ID and already records that `preconditions --for` refuses a `P-NNN`-shaped value at argument parsing (clap usage error, exit 2) "because a P-ID can name several scenarios". Any fix for `conductor run <P-ID>` / the harness's `SCENARIO=<P-ID>` must stay inside that boundary — the P-ID never becomes a path join, argv element of a spawn, or shell string — and its refusal text must be host-path-free and struct-name-free at the `anyhow` edge (per security-plan §Error Handling). Whether `find_by_pid`'s current error path already sanitizes is research's question.
- C4 edits a comment in the `a11y` job that hosts the THIRD dependency class: the pin gate's pre-execution `Get-AuthenticodeSignature` control (`Valid` AND `O=Microsoft Corporation`, non-zero exit, no `continue-on-error` on fetch or verification) and the `EDGEWEBDRIVER`→`CONDUCTOR_MSEDGEDRIVER` producer arm (handle-name + boolean `Test-Path` precondition, non-zero on miss) must remain byte-unchanged in behaviour (per security-plan §Dependency Security, third dependency class; §Input Validation, `CONDUCTOR_MSEDGEDRIVER` row). The plan's row already describes the job WRITING `EDGEWEBDRIVER` through `GITHUB_ENV`, consistent with C4's measured mechanism.
- Every driver/SR leg the regression fires (the `--e2e` routine arm, `a11y:driven`, `sr*` incl. C5's NVDA run) must use only the eight registered harness-spawn forms; `send-keys.ps1`'s closed `ValidateSet` and foreground guard are a governed form, and a NINTH crossing escalates rather than landing on the agent's word (per security-plan §Security Anti-Patterns → Code Patterns, rule (b)). `CONDUCTOR_NVDA` is honoured only through the wdio `UNSAFE_PATH` guard and array-form detached spawn (per security-plan §Input Validation, `CONDUCTOR_NVDA` row).

## Patterns to follow
- The porcelain-first advisory probe: `git -C <advisory-db> status --porcelain` empty before `cargo audit`, with a fresh clone under `--db` as the second witness (per security-plan §Dependency Security, 2026-09-05 re-adjudication).
- The `preconditions --for` refusal of a `P-NNN`-shaped value at argument parsing as the in-tree model for refusing an ambiguous P-ID (per security-plan §Input Validation, CLI arguments row).
- The harness shells' upstream rejection before spawn (`valid_run_id` / `Test-RunId`) and the closed `case` allowlist for `run --live` — the shape for any shell-side `SCENARIO=<P-ID>` handling (per security-plan §Input Validation, CLI arguments row).
- `writeNvdaPass`'s scrub-then-commit path for any regraded SR record (per security-plan §Input Validation, screen-reader speech-log ingest row).

## Anti-patterns to avoid
- Reaching for a `deny.toml` `[advisories] ignore`, a CI edit or a silent accept to turn a red supply-chain gate green when the fault is transient/external (per security-plan §Dependency Security, advisory-DATABASE fault remedy).
- Leaking an absolute host path or seam-crate struct name into cli stderr, a committed evidence record or a run-report artifact — including from a new ambiguous-P-ID error or an SR regrade (per security-plan §Security Anti-Patterns → Logging).
- Adding `continue-on-error`, an `if:` gate or any relaxation to the `a11y` job's Authenticode fetch/verify steps while rewording C4's comment (per security-plan §Dependency Security, third dependency class).
