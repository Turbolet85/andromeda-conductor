## Patterns to follow
- `--e2e` is graded on the PRINTED verdict, never the exit code: capture wdio output to `$RUNS_DIR/a11y-e2e.log`, read the exit from the bare command, require zero on the `Spec Files:` failed count, a per-spec skip tally within the expected-skip SET (the two live-hold subjects), and the `[webview2 … windows]` banner; identical `.sh`/`.ps1` semantics, and the invoking PowerShell must not set `$PSNativeCommandUseErrorActionPreference = $true` (per test-plan §3 `run`; §3 Bootstrap phases 5-command-discipline-wire).
- CLI-edge tests via assert_cmd `Command::cargo_bin("conductor")`; a test of a verb that writes NOTHING (e.g. a C3 ambiguous-P-ID refusal) sets `CONDUCTOR_RUNS_DIR` NOT AT ALL, since `resolve_under` rejects an absolute `TempDir` before dispatch and every verb then fails with empty stdout (per test-plan §3 Per-test isolation; §6 Drivers per surface, cli row).
- A committed fixture carries its MEANING under test: a round-trip through the production reader/writer (`envelope_fixture.rs` seeds `runs/e2e-fixture/` through `conductor_run::persist`, including an over-envelope `run_envelope` row). For C5, which subject dir sr-empty actually reads ("the fixture dir + `runs/sr-leg/empty`") and whether that dir's `runs.db` carries the envelope row is research's question (per test-plan §3 `run` e2e seeding; §6 desktop-webview row, SR firing form; §7 Self-bootstrapping requirement).
- SR grading: NVDA's speech log is the driver, graded against the action timeline with the per-session log-clock calibration; a row the agent arm cannot reach is a recorded finding, never a pass and never a manual arm; every NVDA / window leg is operator-local, never CI, never an `agent-run` verb (per test-plan §6 desktop-webview row, third family; §1 Untestable zones, browse-mode bullet).
- Static gates over committed data (coverage_gate, scenario_audit_gate) and hygiene gates (secret_scan_gate, workflow_env_gate) run inside the Unit stage's `nextest run --workspace --profile ci` and as their own named `rust`-job steps with presence guards — no literal-count predicate (per test-plan §6 Coverage-matrix completeness gate, Scenario-assertion audit leg, Repository-hygiene legs).

## Anti-patterns to avoid
- NEVER fix a runner-dependent or flaky result with nextest `retries` > 0 or a runner knob (`--test-threads=1` / profile setting); a process-global singleton is isolated by its own test binary or an in-code guard, green under BOTH runners (per test-plan §11 Integration; §11 CI; §10 Zero-flakiness budget).
- NEVER run a live-Pulse leg, the `a11y:driven` arm or an `sr*` suite as a CI gate, and never `sleep(N)` to synchronise inside a test — the 150 s inter-leg window and the SR leg's 170 s `SECOND_RUN_QUIET_MS` are the only sanctioned SUT-precondition waits (per test-plan §11 CI; §11 E2E).
- NEVER lower `--fail-under-lines 60` or skip a gate "just this once" to reach "every gate green" (per test-plan §11 Quality).
