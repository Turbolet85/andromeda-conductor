That row's "whatever it holds" clause for `workspace=` lines is the requirement; a prior measurement does not discharge it.
- Corpus-rendered model text may enter the chunk's committed `evidence/` tree and nowhere else. Each capture must be held by a sha256 digest pin over LF-normalized content and graded from its file only after the digest matches. No capture text may sit in test source, including `real_model_series/mod.rs` (per security-plan §Security Anti-Patterns → Data Protection; the 2026-09-29 BREACH remedy). The scope's "no widening" boundary binds this: a new line kind the capture prints is not covered by the exception unless it comes from one of the row's two named sources and goes through the scrub chain.
- The workspace-key mask must take the key from the data dir's basename through the guarded `capture_paths::pulse_logs_dir_from` path, never from a raw read of the handle. The plan records that the leaf matches only when Pulse's workspace detection falls back to the data dir, measured at `fcc31b2` (per security-plan §Input Validation, real-model capture ingest row). Re-confirming that premise at `a2addb3` is the scope's CARRY 3. Whether `contract.rs` `workspace_key` or the `app.boot.workspace_key` stamp changed between those shas is research's question.
- Test-binary readers must resolve `CONDUCTOR_RUNS_DIR` through `runs_dir_from` → `resolve_under`. They must canonicalize `ANDROMEDA_PULSE_DATA_DIR` and require it to be a directory before joining `logs/`. Every rejection must give a path-free reason (per security-plan §Input Validation, env-var path-handle row; §Security Anti-Patterns → Input).
- Committed evidence must not leak absolute host paths, and that includes the new captures and `evidence/attempt-ledger.md` (per security-plan §Security Anti-Patterns → Logging). The fresh `%TEMP%/pulse-legs/<leaf>` data dir and its "absent before creation" record therefore name the leaf only, never the expanded temp path.
- The sidecar the capture re-reads through must be spawned by `ReadbackClient::connect` under rule (a): a fixed program name resolved through the inherited `PATH`, with the data dir passed only via `.env(...)` after metacharacter rejection (per security-plan §Security Anti-Patterns → Input and → Code Patterns). The plan rules out pointing Conductor at the freshly built sidecar through an operator-chosen command path; it must resolve by name. How the sidecar reaches `PATH` is research's question.
- Conductor may reach Pulse's corpus only through the MCP tool surface, never by opening `corpus.db` (per security-plan §Threat Model Summary, the `corpus.db` note; §Security Anti-Patterns → Data Protection). That applies to the binaries' content probes and to reading Pulse's "no-incident L4 outcome … with its reason". Pulse's own log via the guarded `logs/` join is a sanctioned source; the corpus file is not, and neither is staging a corpus row.

## Patterns to follow
- The shared `crates/conductor-run/tests/capture_paths` module guards both handles. Its failures surface as `pulse-log: none ({reason})` and go through the scrub chain (per security-plan §Input Validation).
- A digest pin per evidence file, graded from the file by `real_model_harvest`, which loads from `CARGO_MANIFEST_DIR` plus a hard-coded path with no `CONDUCTOR_*` handle. The harvest's `no_committed_capture_text_sits_in_test_source` arm holds the result, as already proven by its inverse control (per security-plan §Security Anti-Patterns → Data Protection).
- Pulse's witnesses are read fields-only. The workspace rendering gets a class-only witness line (`pulse-report workspace rendering: {verbatim|scrubbed|absent|unknown-key}`) and never the value (per security-plan §Input Validation, real-model capture ingest row).
- Bounded MCP re-read: a fixed poll budget and a capped id sweep, through the hardened client (per security-plan §Input Validation, real-model capture ingest row).

## Anti-patterns to avoid
- Pinning capture content as string literals in test source. That is the 2026-09-29 BREACH shape: remedied, never ratified (per security-plan §Security Anti-Patterns → Data Protection).
- Opening, copying or staging Pulse's `corpus.db` directly to induce or read a SUT state, including to obtain the no-incident reason (per security-plan §Security Anti-Patterns → Data Protection).
- Joining a path handle unguarded, or deriving the mask key from a raw handle read (per security-plan §Security Anti-Patterns → Input; §Input Validation).

## Contract bindings
- obs ↔ security: the capture reads Pulse's own JSONL log fields-only, and any new log line it reads (Pulse's no-incident reason, `app.boot.workspace_key`) goes through the same scrub chain. The obs redaction allowlist governs Conductor-generated artifacts. The capture's scrub chain governs this SUT-output ingest, and the two are separate mechanisms.
- tests ↔ security: digest pins and the source-text arm sit in `real_model_harvest.rs` / `real_model_series/mod.rs`, and the chunk's host-path hygiene gates cover the captures and the harvest. The `rust` job's Secret-scan gate covers the committed `evidence/` files (per security-plan §Bootstrap phases, secret-scanning-ci-gate).
- arch ↔ security: the preflight's app-sidecar workspace-key agreement precondition. Its `Blocked` string must stay distinct and host-path-free if the moved Pulse changes the key's form (per security-plan §Security Anti-Patterns → Universal).
- Dependency Security: no dependency is expected. If one lands, "no dependency delta" stops being an available basis, and `cargo audit` plus `cargo deny` must be re-run green over the new lock (per security-plan §Dependency Security).
