## Constraints
- **Workspace placement and surface freeze.** Round code belongs in the existing members. Arch §Occupied Resources → Crate names names `conductor-run` as the run composition root, and the existing live harvests/witnesses live at its test tier. The round adds no new crate. It consumes only the four registered MCP tools (`query_incident_list` · `retrieve_report` · `retrieve_telemetry_slice` · `mark_incident_resolved`) per §Occupied Resources → Interface routes / surfaces. It adds no sixth `agent-run` command: `--live` is a selector, not a verb (per architecture §Established Decisions [Read-Back Dependency Posture]; §Stack and Technologies → Operator instruments).
- **Hard grading at the measured value, nothing synthesized.** P-025/027/037/045 are lifecycle-timing claims, so the Two-state split requires them to be graded hard pass/fail and never routed to `CalibrationRegion` (per architecture §Established Decisions [Probabilistic-Assertion Policy]). Latency is journal-relative. A declared `budget_ms` is a per-check effective deadline under the tier ceiling (per architecture §Established Decisions [Timing-Tolerance Model]). A never-measured row carries JSON `null` measurement fields and emits zero `run_check` rows, so an absent sample can never read as met (per architecture §Standard Contracts → Readiness gate, blocked-row clause; §Occupied Resources → `runs.db`).
- **Content fidelity is defined by arch's fingerprint and freshness model.** The read-back value that varies with the payload is the grounded cue fingerprint in `retrieve_telemetry_slice.fingerprint_refs`. Conductor's derivation is blake3 over `exception_type` + `\0` + the normalized stacktrace, truncated to `FINGERPRINT_BYTES = 16` and rendered as 32 lowercase hex chars. Pulse's 8-char prefix is a logging convenience, not an identity. Attribution compares a `std::time` emission instant against `opened_at_unix_nano` (per architecture §Established Decisions [Read-Back Dependency Posture], the "Freshness is the canary's carrier" and "Conductor's fingerprint now IS Pulse's derivation" paragraphs). Every Pulse coordinate there was read at `83d4060`/`efabe8e`, so whether the derivation and the `grounded_fingerprint_hashes` union still hold at S is research's question.
- **`degraded_mode` is an output, not an argument.** `retrieve_report` RETURNS `degraded_mode`, and `degraded` is a per-read-back property. `state_for` returns `KnownResidual` iff `observation.degraded`, so assertion 1's `degraded_mode: false` corresponds to the non-degraded route (per architecture §Established Decisions [Read-Back Dependency Posture]; §Standard Contracts → Run report envelope).
- **Runtime-state fidelity mechanics.** Assertion 2 rides the `mark_incident_resolved` write plus `query_incident_list` active-set membership. Pulse allows at most one active incident per `(kind, scope, scope_id)` dedupe tuple. The declined-write arm is unreachable through MCP. Liveness, not a spared control, carries the attribution (per architecture §Established Decisions [Read-Back Dependency Posture], the "Two mechanisms measured the same day" paragraph). Whether `lifecycle_harvest.rs` already grades this against an arbitrary binary is research's question.
- **Sidecar resolution and data-dir wiring.** `andromeda-pulse-mcp` is a fixed NAME resolved through the inherited `PATH`. `PATH` is a spawn-resolution input: a miss is `[BLOCKED]` in ~2 ms, indistinguishable from a SUT-side gate failure at row level. So any operator-driven live leg must carry a `PATH` prefix resolving S's sidecar as part of its firing form (per architecture §Occupied Resources → Service / process names). `ANDROMEDA_PULSE_DATA_DIR` must be propagated to the sidecar, and the preflight canary verifies the wiring (per architecture §Occupied Resources → Environment variables). The deterministic canary stays one storm, under the deterministic posture's run-contract terms (per architecture §Standard Contracts → Readiness gate).
- **Live-Pulse proof is an operator/local gate.** No CI job can drive the round. Dynamic proof requiring a live Pulse stays an operator/local gate, so the graded test ids must be operator-gated, not default-suite (per architecture §Infrastructure Patterns → CI/CD approach; §Established Decisions [CI/CD]).

## Patterns to follow
- **Test-tier graders over a live capture.** These graders sit in `conductor-run/tests/`, add no `Verdict`/`ReportState` variant or envelope key, and leave `conductor-verify`'s `classify()` unchanged. Exemplars are the pre-committed-rule `row()` in `real_model_harvest.rs` and the `lifecycle_harvest.rs` lifecycle harvest (per architecture §Established Decisions [Probabilistic-Assertion Policy]; [Read-Back Dependency Posture]).
- **State the grading rule before the drive.** `contracts/pulse-p025-measurement-contract.md` §The grading rule fixes the P-025 hard grade before any drive. It is a no-Rust-reader `contracts/` member with per-clause provenance, and its Pulse coordinates (HEAD `226554a`) expire when that HEAD moves (per architecture §Occupied Resources → On-disk artifacts, the P-025 contract entry). Re-pinning its coordinates at S follows the same add-only, per-clause discipline as the real-model posture doc.
- **Harness-owned, leg-stemmed captures cleared by pattern.** `runs/live-suite/` holds no `CONDUCTOR_*` handle of its own. It lives at `$RUNS_DIR/live-suite`, so it moves with `CONDUCTOR_RUNS_DIR`. It is git-ignored and cleared non-recursively by pattern (`rm -f …/*.jsonl`, the `cleanup` verb's idiom) before its arm runs. The real-model arm clears exactly its own named files (per architecture §Occupied Resources → On-disk artifacts, the `runs/live-suite/{leg}.jsonl` entry). The CARRY's new subdir should take that shape.
- **Verdicts carry their configuration.** Live verdicts are cited as "as measured at `{chunk}/evidence/{file}`" with the SUT HEAD, posture and run conditions stated (per architecture §Established Decisions [Read-Back Dependency Posture]; §Cross-cutting Patterns → Determinism discipline, the witness-ledger citation). The round's committed evidence path should name S and both artifact sha256 values.
- **Per-execution span identity.** The production path salts span identity per execution through `Dispatcher::connect(…, Some(_))`. Content stays seed-pure, and journal stamps come from `std::time` (per architecture §Cross-cutting Patterns → Determinism discipline).

## Anti-patterns to avoid
- **Hiding a FAIL.** Never relax a budget, re-route a hard timing claim to `CalibrationRegion`/`ManualCheck`, or turn an absent sample into a pass. `KnownResidual` is reserved for the degraded read-back or the declare-only auto-resolve route, never for a missed budget (per architecture §Established Decisions [Probabilistic-Assertion Policy]; §Standard Contracts → Run report envelope).
- **Growing the harness surface.** No sixth `agent-run` command, no new `CONDUCTOR_*` handle for the span-landing subdir, and no recursive delete in the harness shells. The live-suite set "ships no recursive delete" (per architecture §Occupied Resources → On-disk artifacts, the live-suite entry; §Cross-cutting Patterns → Config management).
- **Pulse process management in shipped code.** "No Pulse process management" is a stated non-goal. Launching and stopping `pulse-app` for the round stays an operator-pass act, never harness or binary code (per architecture §Cross-cutting Patterns → Scope law).
