# security extract

## Relevance
partial. The round is a live verification over existing trust boundaries: the sidecar spawn, the MCP read-back and lifecycle write, the preflight gate and committed evidence. The span-landing CARRY touches a `CONDUCTOR_RUNS_DIR` test-binary reader and a harness-shell clear. No new boundary, dependency or listener is in scope.

## Constraints
- The sidecar is spawned only as the fixed hard-coded program NAME resolved through the inherited `PATH`. Pointing the round at S's `andromeda-pulse-mcp` is therefore a `PATH`-ordering act in the round's environment. It must never become an absolute or operator-chosen program path, a config-derived command, or a change to the spawn const (per security-plan §Security Anti-Patterns → Input, the fixed-NAME bullet; §Security Anti-Patterns → Code Patterns, rule (a)). `sidecar_resolves_on_path` returns a boolean-grade fact and never the resolved path. So "which copy resolved" cannot be answered by rendering a path through it. Research must settle how the round attests that S's copy resolved without a host path reaching an artifact (e.g. by sha256).
- `ANDROMEDA_PULSE_DATA_DIR` (the fresh data dir) reaches the sidecar only through the `.env(...)` builder, after the metacharacter rejection. It is never put in argv or a shell (per security-plan §Input Validation, the `ANDROMEDA_PULSE_DATA_DIR` spawn-propagation row; §Security Anti-Patterns → Input). `ANDROMEDA_PULSE_L4_DETERMINISTIC` and `ANDROMEDA_PULSE_MCP_ENABLED` stay declaration-only reads. Conductor never sets them, and neither one's value becomes a path, an argv element or a log value (per security-plan §Input Validation, the `ANDROMEDA_PULSE_*` declaration-only row; §Threat Model Summary → Auth model).
- Assertion 2's `mark_incident_resolved` goes through the MCP TOOL SURFACE only. It takes the same bounded line-delimited JSON-RPC path as read-back. Both the applied response and the `DeclinedStale` declined arm arrive as typed inputs, never as a panic. The round must never open, copy or stage `corpus.db` to induce a SUT state (per security-plan §Input Validation, the MCP child stdout row; §Data Protection; §Security Anti-Patterns → Data Protection).
- On a live round the preflight gate's FIVE named preconditions each surface as their own distinct `Blocked` string, never downgraded. The `run --live` preconditions short-circuit refuses before any sidecar spawn. A Blocked or UNGRADED outcome is a typed value, never a false PASS (per security-plan §Security Anti-Patterns → Universal, the preflight-downgrade and invoked-preflight bullets).
- Committed evidence and run-report artifacts carry verdict, state, identity and measured-value fields only. They must hold no absolute host paths (canonicalized `CONDUCTOR_*` dirs, `ANDROMEDA_PULSE_DATA_DIR`), no workspace key and no seam-crate struct names (per security-plan §Error Handling → Run-report artifact sanitization; §Security Anti-Patterns → Logging). The corpus-content ban has ONE exception, and it is scoped to the real-model capture's scrubbed report text. So quoting read-back corpus content (report bodies, `fingerprint_refs` payloads beyond the graded identity) into this deterministic round's evidence is not covered by it (per security-plan §Security Anti-Patterns → Data Protection). Whether a fingerprint value may sit in the committed evidence or should be graded and recorded as a match boolean is research's question.
- The span-landing witness's runs-dir input is resolved through `conductor-run/tests/capture_paths` → `resolve_under`. Absolute or `..` values are rejected with a path-free reason. The witness prints one integers-only line and commits nothing from the ingest. A moved subdir must keep all three properties (per security-plan §Input Validation, the path-handle row and the span-landing witness ingest row; §Security Anti-Patterns → Input, the by-READER clause).
- The live leg runs only in the operator's slot, operator-gated under the `live-pulse` feature and never in CI. No Conductor inbound listener is introduced, and `:4317` stays Pulse's (per security-plan §Threat Model Summary → Attack surface; §Security Anti-Patterns → Universal, the scope-law bullet). Any scenario the round authors names a Pulse P-ID and passes garde plus the `check_*` load path (per security-plan §Input Validation, the scenario config row).

## Patterns to follow
- Use the span-landing witness's output shape for any new live grader: one bounded `serde_json` decode per line, undecodable lines skipped, and one integers-only `PASS|FAIL` summary line with no path, key or fingerprint (per security-plan §Input Validation, the span-landing witness ingest row).
- Every `CONDUCTOR_RUNS_DIR` / `ANDROMEDA_PULSE_DATA_DIR` test-binary read goes through the shared `capture_paths` guards (`runs_dir_from`, and `pulse_logs_dir_from` for canonicalize plus is-dir). Read failures report `e.kind()` only (per security-plan §Input Validation, the path-handle row and the span-landing row).
- For the operator's "re-measure both sha256 before launch" directive, an analogous registered pattern exists: a binary is never executed before its integrity verdict is read, as with arm 153's pre-execution Authenticode + SHA-256 + version check (per security-plan §Security Anti-Patterns → Code Patterns, the 2026-09-30 controls). This is an analogy only. The plan does not mandate a hash check on Pulse's binaries.
- The harness-side clear of the new span subdir follows the non-recursive, by-pattern delete idiom inside a known directory: `rm -f "$DIR"/*.jsonl`, and in pwsh `Remove-Item (Join-Path $Dir '*.jsonl')`. Cite this to `.claude/rules/security.md` Session Additions 2026-09-06. **security-plan.md states no such rule**: a grep for `recursiv`, `rm -f`, `Remove-Item` and `wipe` returns 0. The scope's "per security rules 2026-09-06" therefore resolves to the rule file, not the master.

## Anti-patterns to avoid
- Never let a `CONDUCTOR_*`-derived path reach a recursive delete in `scripts/agent-run.{sh,ps1}`. The shell runs before any Rust `resolve_under` guard, so a `:-` default closes only the empty case (`.claude/rules/security.md` Session Additions 2026-09-06; the plan carries the by-READER duty at §Security Anti-Patterns → Input).
- Never spawn the sidecar from an operator-chosen command or absolute path to "make sure it's S's build" (per security-plan §Security Anti-Patterns → Code Patterns, rule (a)).
- Never persist Pulse corpus content into Conductor artifacts outside the one ratified real-model-capture exception, and never touch `corpus.db` as a file (per security-plan §Security Anti-Patterns → Data Protection).

## Contract bindings

Moving the inputs to their own subdir makes both masters stale and owes paired amendments at wrap. The plan's §Bootstrap phases and §Security Anti-Patterns → Input reader lists name the reader file, not the subdir, so whether they need a change is research's question.

- security ↔ obs: `span-{a,b}.jsonl` are Conductor self-obs journals under the tracing field allowlist. Committed evidence is held to the same host-path and struct-name redaction as run reports (per security-plan §Security Anti-Patterns → Logging).
