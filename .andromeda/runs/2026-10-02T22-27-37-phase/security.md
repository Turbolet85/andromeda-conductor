## Relevance
partial — no new trust boundary or dependency. The chunk does three things in this domain: it widens the pinned MCP required-tool set (a preflight-gate input), adds a new MCP response shape on the trusted-child stdout boundary, and commits fresh live-round evidence under the artifact-hygiene and corpus-content bans.

## Constraints
- The pinned MCP contract manifest is a validated boundary input. Its required-tool name set is asserted against the server in the preflight gate, and a mismatch is `blocked`, never a silent downgrade (per security-plan §Input Validation, pinned-MCP-contract-manifest row). That row enumerates exactly four names today (`query_incident_list` · `retrieve_report` · `retrieve_telemetry_slice` · `mark_incident_resolved`), so pinning `retrieve_incident_events` makes that enumeration stale. Research must answer whether the code reads the set only from `contracts/mcp-contract.toml` or also holds a four-name constant or test.
- A Pulse lacking a required tool must surface the distinct missing-tool `Blocked` precondition with its own host-path-free string. It must never be read as a pass and never as the generic corpus-empty string (per security-plan §Security Anti-Patterns → Universal, the FIVE-named-preconditions ban). Pinning the fifth name therefore makes every preflight against a pre-S Pulse `Blocked` by design, never relaxed.
- The `retrieve_incident_events` response and its unknown-id JSON-RPC error (`-32603`) arrive over the MCP child-stdout boundary. Security-plan §Input Validation (MCP-child-stdout row) requires bounded line-delimited decoding, with a soft per-line size bound and recursion-limited serde_json. It also requires JSON-RPC errors and decode faults to map to typed `VerifyError::{JsonRpc,Decode,Transport}` inputs, never panics. Research must answer whether a maximum 256-event response fits the existing per-line bound.
- The sidecar must stay a fixed hard-coded program NAME resolved through the inherited `PATH`. Pointing the round at S's `target/release` must happen through `PATH` alone, never through an operator- or config-chosen command string or path (per security-plan §Security Anti-Patterns → Input, the sidecar-spawn ban; §Security Anti-Patterns → Code Patterns rule (a)). `ANDROMEDA_PULSE_DATA_DIR` reaches the child only through `.env(...)` after metacharacter rejection (per security-plan §Security Anti-Patterns → Input).
- Corpus access is through the MCP tool surface only: read-back plus the `mark_incident_resolved` lifecycle write. Corpus content must never be persisted into Conductor artifacts. The single ratified exception is scoped to the real-model capture's scrubbed `evidence/` text, and this deterministic round is outside it (per security-plan §Security Anti-Patterns → Data Protection; §Data Protection). Research must answer whether the prior round's evidence shape commits any `retrieve_report` body or other corpus-rendered text.
- Committed evidence under this chunk's `evidence/` must carry verdict, state, identity and measurement fields only. It must hold no absolute host path (the canonicalized `CONDUCTOR_*` directories, `ANDROMEDA_PULSE_DATA_DIR`, S's binary location) and no internal seam-crate struct name (per security-plan §Security Anti-Patterns → Logging; §Error Handling, run-report artifact sanitization).
- Any live-leg test-binary reader of `CONDUCTOR_RUNS_DIR` or of `ANDROMEDA_PULSE_DATA_DIR`'s value must resolve through the shared `conductor-run/tests/capture_paths` guards (`runs_dir_from` → `resolve_under`; `pulse_logs_dir_from`, which canonicalizes and requires a directory) before any read. Every rejection must carry a path-free reason. The duty binds per READER (per security-plan §Input Validation, env-var path-handle row and the `ANDROMEDA_PULSE_DATA_DIR` spawn-propagation row).

## Patterns to follow
- The `mark_incident_resolved` lifecycle write shares the read-back `call_tool` path and its controls. Its applied response and its declined arm are both typed inputs at the child-stdout boundary (per security-plan §Input Validation, MCP-child-stdout row). The new read-back tool should take the same route.
- The capture ingests read Pulse's log through `capture_paths::pulse_logs_dir_from` and `CONDUCTOR_RUNS_DIR` through `runs_dir_from`. `capture_paths_guard` proves them, and `span_landing_live` is the from-birth exemplar (per security-plan §Input Validation, span-landing witness row).
- Committed evidence is graded from its file after a sha256 digest pin matches, never from text in test source (per security-plan §Security Anti-Patterns → Data Protection, the 2026-09-29 breach remedy). Research must answer whether the prior round's `evidence_pin` module is that mechanism.
- Journal and report stamps come from `std::time::SystemTime`/`Instant`, never tokio's virtual clock (per security-plan §Security Anti-Patterns → Logging). This bears on the resolve call's wall-clock window that assertion 7 compares `occurred_unix_nano` against.

## Anti-patterns to avoid
- Do not add a sidecar-path override, config key or explicit program path to aim the round at S's build. The fixed NAME plus the inherited `PATH` is the only sanctioned selection (per security-plan §Security Anti-Patterns → Input; §Security Anti-Patterns → Code Patterns rule (a)).
- Do not commit corpus-rendered text (a `retrieve_report` body, incident titles) into this deterministic round's evidence, and do not stage a corpus row to induce a lifecycle state (per security-plan §Security Anti-Patterns → Data Protection).
- Do not panic or `unwrap` on the new tool's response or its `incident not found` error. A malformed or errored child input is a typed value through the verdict/error wall (per security-plan §Security Anti-Patterns → Universal).
