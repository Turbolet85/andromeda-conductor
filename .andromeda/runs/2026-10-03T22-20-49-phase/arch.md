## Constraints
- The MCP read-back client stays the hand-rolled line-delimited JSON-RPC client returning RAW `serde_json::Value` results (Pulse's `tools/call` is non-MCP-compliant); a `retrieve_incident_events` call goes through that same client, with no SDK and no typed-envelope assumption (per architecture §Established Decisions [MCP Read-Back Client]; §Inherited Defaults → Interface style).
- Required-tool presence is gated against the pinned contract manifest. Arch states the gate's named preconditions are FIVE, required-tool absence among them. So pinning a fifth tool must reuse that existing precondition and must not mint a sixth. Whether `preflight.rs` already derives the tool check purely from the manifest/`READBACK_TOOLS` set is research's question (per architecture §Standard Contracts → Readiness gate; §Established Decisions [Read-Back Dependency Posture]).
- Verdict/error wall: each of the seven assertions is a typed VALUE (`Verdict`/`ReportState`, or the test-tier `RoundGrade`). A JSON-RPC error (the `-32603` `incident not found` arm), a malformed `events` payload or an absent sample maps to a typed `Blocked`/ungraded outcome, never a panic. `Result::Err` stays harness-fault only (per architecture §Established Decisions [Error Handling]; §Cross-cutting Patterns → Verdict/error wall).
- The resolve call's request→response window for assertion 7 is a wall-clock stamp, so it must come from `std::time` (`SystemTime`/`Instant`) and never from tokio's virtual clock (per architecture §Cross-cutting Patterns → Determinism discipline; §Conventions → Data model conventions).
- Lifecycle timing is a deterministic claim, so assertion 7 grades hard PASS/FAIL. The calibration-region routing applies only to model-interpretive claims and does not apply here (per architecture §Established Decisions [Probabilistic-Assertion Policy]).
- The sidecar is spawned as a fixed NAME through the inherited `PATH`, and `PATH` is a spawn-resolution input. A live leg's firing form therefore carries a `PATH` prefix that resolves S2's `andromeda-pulse-mcp`, and `ANDROMEDA_PULSE_DATA_DIR` is propagated via `.env(...)`. Arch records a Linux platform default for the data dir (`$XDG_CONFIG_HOME`/`~/.andromeda-pulse`) beside the Windows one, and marks the `CREATE_NO_WINDOW` flag `#[cfg(windows)]` (per architecture §Occupied Resources → Service / process names; §Occupied Resources → Environment variables `ANDROMEDA_PULSE_DATA_DIR`).
- Dynamic proof that REQUIRES A LIVE PULSE is a local operator gate, because CI has no Pulse instance and every CI job runs on a Windows runner. Arch does not decide whether the round runs on this host or a CI runner: per scope §Host that fork is the founder's at P4 (per architecture §Established Decisions [CI/CD]; §Inherited Defaults → CI/CD; §Infrastructure Patterns → Build system).

## Patterns to follow
- Crate-per-seam placement. The required-tool set (`READBACK_TOOLS`, the manifest validation) lives in `conductor-verify`, the MCP read-back client and preflight seam. The timed sibling of `probe_resolve_lifecycle` lives in `conductor-run`, the run composition root shared by both bins. Round grading stays at the `conductor-run` test tier, as the pre-committed-rule arm and the harvest graders do. Whether a typed `retrieve_incident_events` wrapper belongs in `conductor-verify` or only at the test tier is research's question (per architecture §Established Decisions [Module Boundaries]; §Occupied Resources → Crate names).
- Runtime-state fidelity (the `mark_incident_resolved` write observed through `query_incident_list`) is the live-proven axis assertions 2 and 7 extend. Attribution rides LIVENESS and freshness: an incident opened AFTER the storm's `std::time` emission instant. A spared-control design within one dedupe tuple is unattainable (per architecture §Established Decisions [Read-Back Dependency Posture]).
- Assertion 1's content fidelity rides the grounded cue fingerprint, a 32-hex blake3 value in `fingerprint_refs` beside the `det-*` triple under deterministic L4. Conductor's derivation in `conductor-emit/src/exception.rs` is the expected value (per architecture §Established Decisions [Read-Back Dependency Posture], the "Freshness is the canary's carrier" and "Conductor's fingerprint now IS Pulse's derivation" paragraphs).
- The production path salts span identity per execution, so a fresh round never replays a `(trace_id, span_id)` Pulse still holds. The unsalted tier stays seed-pure (per architecture §Cross-cutting Patterns → Determinism discipline).
- The P-025 grade reads `contracts/pulse-p025-measurement-contract.md`, a `contracts/` member with NO Rust reader. It is cited outward and never loaded through `resolve_under`. Its Pulse coordinates expire when the SUT HEAD moves (per architecture §Occupied Resources → On-disk artifacts, the P-025 contract entry).

## Anti-patterns to avoid
- Pin the fifth tool in all three places: the committed manifest, `READBACK_TOOLS` and the in-process stub's default list. Never widen only one site, and never let the tool's absence surface as a new named precondition or as the generic corpus-empty string (per architecture §Standard Contracts → Readiness gate).
- No new `CONDUCTOR_*` handle, `contracts/` reader, `agent-run` verb or sixth harness command for this round. The live leg rides the existing `live-pulse`-gated test and the registered handles (per architecture §Occupied Resources → Environment variables; §Stack and Technologies → Operator instruments, "the 5-command harness surface is unchanged").
- No Pulse process management and no automation of Pulse's UI (the P-037 hands-off posture), and no inbound listener (per architecture §Cross-cutting Patterns → Scope law; §Cross-cutting Patterns → Trust boundary).
