## Relevance
relevant — the chunk adds a fifth required MCP tool, which is a new input class on the trusted-child (sidecar-stdout) boundary. It re-aims the sidecar's `PATH` resolution and data-dir handle at a Linux S2 build, writes committed evidence, and puts the CI-vs-host fork in front of the founder.

## Constraints
- The pinned MCP contract manifest's required-tool set is a validated boundary. A tool absent from the server's `tools/list` must surface as the distinct missing-tool `Blocked` precondition, never a silent downgrade. The gate keeps FIVE named preconditions, so pinning `retrieve_incident_events` adds a name to an existing precondition and never adds a sixth (per security-plan §Input Validation, the pinned-MCP-contract-manifest row; §Security Anti-Patterns → Universal, the failed-preflight ban). That row today enumerates the four names `query_incident_list` · `retrieve_report` · `retrieve_telemetry_slice` · `mark_incident_resolved`. After the pin the master states a stale set, and its re-derivation is a wrap amendment, never a hand edit here. Whether `READBACK_TOOLS`, the committed manifest and the in-process stub's default list all move together is research's question.
- `retrieve_incident_events` responses arrive through the MCP-child-stdout boundary. That boundary requires bounded line-delimited JSON-RPC decoding (recursion-limited serde_json plus a soft per-line size bound), and requires a JSON-RPC error to become a typed input (`VerifyError::{JsonRpc,Decode,Transport}`) rather than a panic. Examples are Pulse's `-32603` `incident not found`, an unknown or undecodable `event_kind` shape, or a truncated response. An absent read-back stays UNGRADED or `Blocked`, never a false pass (per security-plan §Input Validation, the MCP-child-stdout row; §Security Anti-Patterns → Universal, the malformed-child-input-panic ban; §Error Handling). The row as written names read-back plus the `mark_incident_resolved` lifecycle write on the shared `call_tool` path. Whether the new tool rides that same path and its controls is research's question.
- The sidecar must stay a FIXED hard-coded program NAME resolved through the inherited `PATH`. Aiming the round at S2's `target/release` is therefore a `PATH` (environment) act, never a config-derived or operator-supplied program path. `PATH` is an explicit spawn-resolution input, and a miss should surface upstream as the `sidecar-resolvable` `[PRECONDITION]` subject on `run --live` (per security-plan §Security Anti-Patterns → Input, the fixed-name sidecar ban; → Code Patterns rule (a)). The non-spawning sibling `sidecar_resolves_on_path` is specified as a `split_paths(PATH)` + `PATHEXT` walk. Whether that walk resolves an extensionless Linux binary is research's question.
- `ANDROMEDA_PULSE_DATA_DIR` (the round's fresh data dir) is passed only via the `.env(...)` builder, after injection-metacharacter rejection, and never into argv or a shell. The spec names the Linux platform default (`$XDG_CONFIG_HOME` / `~/.andromeda-pulse`) for when it is unset (per security-plan §Input Validation, the `ANDROMEDA_PULSE_DATA_DIR` spawn-propagation row; §Security Anti-Patterns → Input).
- Pulse's corpus is reached through the MCP TOOL SURFACE only: read-back, the new read tool and the sanctioned `mark_incident_resolved` write. Never through the `corpus.db` file. Reading or staging the `incident_events` table directly to verify or induce assertion 7 is the banned route. The ratified corpus-content exception is scoped to the real-model capture only and does not extend to this deterministic round's evidence (per security-plan §Data Protection; §Security Anti-Patterns → Data Protection).
- The resolve call's request-to-response window stamp (Q3's timed sibling of `probe_resolve_lifecycle`) and every journal and report stamp come from `std::time`, never tokio's virtual clock (per security-plan §Security Anti-Patterns → Logging, the wall-clock ban).
- Supply chain: `Cargo.lock` stays committed and un-drifted. `cargo audit` and `cargo deny check` must both be green before any merge or `cargo build --release`. Before a red audit is classified as external, run the advisory-db porcelain check. The toolchain floor is ≥ 1.94.1, including for this host's first cold Linux build (per security-plan §Dependency Security; §Security Anti-Patterns → Universal). Pulse's S2 `wasmtime` advisories are Pulse's tree, not this lockfile's.

## Patterns to follow
- Pin a required tool as DATA in the committed manifest and assert presence in the preflight, rather than as a compile-time assumption at the call site (per security-plan §Input Validation, the pinned-MCP-contract-manifest row).
- Route every read-back and write through the hardened `ReadbackClient::connect` spawn: fixed name, `.env` data dir, bounded decode. This is the pattern the real-model capture rows cite for their own MCP re-read (per security-plan §Input Validation, the real-model capture ingest row).
- Make the verdict/error wall explicit. A graded outcome, including a FAIL that is a Pulse finding, is an `Ok(Verdict/ReportState)`. `Result::Err` is kept for harness faults only (per security-plan §Error Handling).
- Committed evidence carries verdict, state, identity and measured fields only, with no absolute host paths or data-dir values (per security-plan §Security Anti-Patterns → Logging; §Error Handling, run-report artifact sanitization).
- Any operator-supplied path handle a new leg reads is resolved per READER through the shared `capture_paths` guards, with path-free rejection reasons. The scope infers that the leg reaches the data dir only via `ReadbackClient::connect`, so it would not be a `capture_paths` reader. Research confirms that (per security-plan §Input Validation, the env-var path-handle row).

## Anti-patterns to avoid
- NEVER open, query or stage Pulse's `corpus.db` / `incident_events` table directly to cross-check or induce lifecycle events. Use only the MCP tool surface (per security-plan §Security Anti-Patterns → Data Protection).
- NEVER point the round at S2 by making the sidecar program a configured or absolute path, or by interpolating the data dir into argv or a shell string. The sidecar program is the fixed name plus `PATH`, and the data dir goes through `.env` (per security-plan §Security Anti-Patterns → Input; → Code Patterns rule (a)).
- NEVER let a missing fifth tool, an errored `retrieve_incident_events` call or an absent sample degrade into a pass or a panic (per security-plan §Security Anti-Patterns → Universal).

The committed-evidence host-path hygiene gate (drive-letter, `/home/`, `/Users`, `%APPDATA%` anchors) binds to this round's new evidence (per security-plan §Security Anti-Patterns → Logging).
- security ↔ CI (the founder's P4 host fork): the plan places live-Pulse end-to-end proof at the operator/local gate, never in CI. The plan also counts exactly ONE CI non-loopback egress. A CI-runner leg that builds or fetches Pulse at S2 would add a second egress and a network-arriving program, and would be a NINTH rule-(b) spawn crossing in `ci.yml`. Each of those escalates and is never routine (per security-plan §Threat Model Summary, Infrastructure → Networking and CI/CD; §Security Anti-Patterns → Code Patterns rule (b)).
- security ↔ obs: the `std::time` source for the resolve window and stamps; no data-dir value or host path in self-obs lines (per security-plan §Security Anti-Patterns → Logging).
