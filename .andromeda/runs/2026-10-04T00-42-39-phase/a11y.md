## Constraints

- a11y-plan §9 CI Integration (the stage table's Unit row) requires that the unit layer (cargo-nextest / cargo test / golden) carries no UI a11y tests. This chunk's fix stays at that layer and must not grow a DOM or a11y assertion into the mock-runtime tests.
- a11y-plan §10 SLO Invariants & A11y Budgets ties zero-flakiness to tests' no-`retries` rule. Getting the six tests green must not use a nextest `retries`, a skip or a host `cfg`-exclusion, which matches the scope's own Boundaries.
- a11y-plan §11 A11y Anti-Patterns → CI states that no assertion in the a11y harness is platform-dependent. The mock-origin fix should hold that same posture, with one source passing on both the Linux dev host and Windows. A host-derived origin is a correctness input, not a platform-conditional assertion.
- a11y-plan §9 CI Integration requires the routine a11y webview arm (CI job `a11y`) to stay green. The scope's Boundaries forbid any frontend, capability or `tauri.conf.json` change, so the arm's inputs should not move. Confirming that the job stays green on the push is the operator pass's CI read, not a new a11y assertion.

## Patterns to follow
- Keep the IPC test as the non-DOM sibling of the DOM-level routine-arm spec, per a11y-plan §4 ARIA Patterns & Roles (load-envelope banner row). The two prove the banner's data path and its rendered DOM separately, so changing one must not stand in for the other.
- Use ONE stack and host-agnostic assertions, per a11y-plan §11 A11y Anti-Patterns → CI. Make the origin correct for each host from a single source, never with a per-host test fork.

## Anti-patterns to avoid
- Do not mask a failure with a retry, skip, `#[ignore]` or `continue-on-error`, per a11y-plan §10 SLO Invariants & A11y Budgets and §11 A11y Anti-Patterns → SLO / CI. The ban on retry-once and skip for a11y violations applies equally to the IPC path that backs an a11y surface.
- Do not widen a Tauri capability to admit any origin, per a11y-plan §1 A11y Scope Summary's reliance on deny-by-default capabilities. That would also break the scope's "never made irrelevant" boundary.
