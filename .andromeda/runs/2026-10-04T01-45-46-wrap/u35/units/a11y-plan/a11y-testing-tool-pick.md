### A11y testing tool pick

- **Primary tool per surface:** desktop-webview → **axe-core v4.12.0** injected via **`@axe-core/webdriverio`** into the **same `@crabnebula/tauri-driver` + WebdriverIO (`wdio run`) session the tests plan §6 already stands up for webview E2E** (`new AxeBuilder({ client: browser }).analyze()` → `AxeResults` JSON). This **reuses the tests' webview driver** rather than a parallel stack — tauri-driver wraps the platform WebDriver (WebKitWebDriver on Linux / msedgedriver on Windows, the latter measured working 2026-09-01), so the gate runs on the **same target tests' webview E2E uses**, not a separate Windows-only CDP attach. Secondary coarse gate: **Lighthouse v13.0.3** a11y category, run against the WebdriverIO-launched webview where a Chromium-backed driver is available (skipped on WebKitGTK). The cli surface is not-assertable (no axe/Lighthouse reach) — no tool pick.
- **Configuration:** axe-core tag scope for Minimal baseline — `withTags(['wcag2a','wcag2aa','wcag21aa'])`; this lights `color-contrast` (SC 1.4.3 / SC 1.4.11), `button-name`/`aria-*`/`label` (SC 4.1.2), `aria-live`/status (SC 4.1.3), `list`/`listitem`/`aria-required-children` (SC 1.3.1). WCAG 2.2 rules ship off-by-default and are NOT added (no AA/AAA escalation trigger — Section 5 = None, so `wcag22aa` stays unset). **Binding (reuse the tests' driver):** axe injects via `@axe-core/webdriverio` into the tests' `@crabnebula/tauri-driver`/WebdriverIO session — no separate puppeteer/CDP stack. tauri-driver is cross-platform (WebKitWebDriver/Linux, msedgedriver/Windows); CI is TARGETED at a **Linux+xvfb** runner alongside tests' webview E2E; a CI a11y job EXISTS since 2026-09-07 — job `a11y` on `windows-2022` (moved 2026-09-17 from `windows-2025`), running `agent-run.ps1 run --e2e` for the ROUTINE arm — while tests' own webview-E2E job remains absent and operator/local; identify CI jobs BY NAME, not by `ci.yml` line coordinates, which move as the workflow grows (the frontend job sat at `:178` when that measurement was taken and is now at `:188`). macOS (WKWebView, no WebDriver) stays manual NVDA/VoiceOver only. Reduced-motion has NO emulation path on any driver — `browser.emulate` in webdriverio 9.x declares exactly six scopes (`clock` / `geolocation` / `userAgent` / `device` / `colorScheme` / `onLine`) and reduced-motion is not among them — so it is asserted from the compiled `@media (prefers-reduced-motion: reduce)` rule instead, and no assertion in this harness is platform-dependent (as measured 2026-09-01; see § Contrast verification harness / Section 6 Motion + Decisions Log).
