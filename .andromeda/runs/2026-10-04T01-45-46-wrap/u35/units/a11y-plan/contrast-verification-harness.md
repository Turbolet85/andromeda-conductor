### Contrast verification harness

- **Source-of-truth tokens:** design token names from upstream-context Section 3 A11y-Relevant Design Tokens, reproduced verbatim — `--text-primary` / `--text-secondary` / `--text-tertiary` / `--text-muted` / `--color-id-cyan` / `--count-nominal` / `--count-hold` / `--status-fail` / `--color-focus` / `--status-residual` (foregrounds) over `--color-base` / `--color-raised-1` / `--color-inset` (backgrounds), plus `--border-emphasis` for the selection-vs-focus distinction. Never invent tokens; raw values stay in design-system.md (`[NO_RAW_DESIGN_VALUES]`).
- **Verification tool:** axe-core v4.12.0 `color-contrast` rule (rendered-DOM ratios after Tailwind compiles tokens) + **`colorjs.io` v0.6.1** token-name-bound assertion (`new Color(fg).contrast(bg, "WCAG21")`) that resolves each named token pair from the compiled CSS custom properties and emits machine-readable `{ token_fg, token_bg, ratio, required, pass }` JSON folded into the obs Section 6 envelope. (`chroma-js` v3.2.0 is an accepted alternative — either one, not both; `wcag-contrast` rejected as stale, last publish 2019.) axe measures rendered color only; colorjs.io supplies the token-NAME-level assertion the binding contract requires.
- **WCAG SC mapping:** **SC 1.4.3 Contrast (Minimum)** (AA 4.5:1 normal / 3:1 large — `--text-primary`/`--color-base` etc.) + **SC 1.4.11 Non-text Contrast** (AA 3:1 — `--count-nominal`/`--color-base` status lamps + `--color-focus`/`--color-base` focus ring). SC 1.4.6 Enhanced (7:1) NOT in Minimal baseline.
