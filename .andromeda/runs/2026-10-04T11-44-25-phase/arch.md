## Constraints
- Module boundaries: per architecture §Inherited Defaults → Module boundaries and §Infrastructure Patterns → Directory structure, the chunk works inside a crate-per-seam workspace. The split targets and the lifted grading stay test-tier inside `crates/conductor-run/tests/`, reusing the existing `real_model_common/` module. They add no crate and no new cross-crate dependency edge. The secret-scan change stays inside `crates/conductor-core/tests/`.
- Dependency edges: per architecture §Infrastructure Patterns → Build system, `sha2` is a TEST-only `conductor-run` dev-dependency serving the real-model harvest's sha256 digest pins. `regex` is a `conductor-core` dev-dependency for the secret-scan gate. Both are "already locked transitively — no new package". The split and the lift must reuse those edges and add no package. Whether a split target needs any dev-dependency the crate does not already declare is research's question.
- Test runner: per architecture §Infrastructure Patterns → Build system, tests run under `cargo nextest` with the zero-retry `ci` profile in `.config/nextest.toml`, plus `cargo test --doc`. Every split target has to be picked up by that same runner with its pass/skip/ignore posture unchanged. No per-target retry and no profile carve-out is allowed.
- Static-gate shape: per architecture §Established Decisions → [CI/CD], each static gate (the `Secret-scan gate` is one of them) is its own named `rust`-job step with no `continue-on-error` and no `if:`. Its `run` opens with a presence guard on its subject that emits `::error::` and exits 1, then invokes the specific nextest target (`-p conductor-core --test secret_scan_gate`). "The gate IS the Rust test", so a no-`.git` skip in the test must leave that step able to fail loudly in a checkout. Whether the existing step's presence guard already tests for a git repository, or only for the target, is research's question.
- Harness surface: per architecture §Stack and Technologies (the Operator instruments row) and §Established Decisions (the real-model leg's "a `--live` selector, not a sixth command"), the 5-command `agent-run.{sh,ps1}` surface is fixed. If the CARRY's `stub-server` `cargo check --tests` gate lands in the harness shells, it rides an existing verb. It never becomes a sixth command. If it lands in CI, it takes the named-step shape above (§Established Decisions → [CI/CD]; §Infrastructure Patterns → CI/CD approach).
- Grading tier: per architecture §Established Decisions → Probabilistic-Assertion Policy (the 2026-09-22 pre-committed-rule arm), the Identified / NotIdentified / nothing-to-grade mapping "ships at test tier, in `conductor-run/tests/real_model_harvest.rs`'s `row()`". `conductor-verify`'s `classify()` stays unchanged, and the policy adds no `Verdict`/`ReportState` variant and no envelope key. Lifting the grading into `real_model_common` keeps it test-tier. That plan sentence names the file the split retires, so it becomes stale the moment the split lands.
- Determinism: per architecture §Cross-cutting Patterns → Determinism discipline, the bar is zero flakiness. Splitting by series must not create cross-target ordering or shared-state dependence between the new test binaries. Committed captures stay graded from their files under unchanged digest pins.

## Patterns to follow
- A gate is a presence-guarded invocation of one named nextest target, and its assertion is never re-listed in shell (§Established Decisions → [CI/CD]). A CI `stub-server` compile gate should copy this shape: its own named step that invokes the cargo command directly.
- Shared test-tier helpers live in a `tests/<name>/mod.rs` module inside the owning crate. The real-model harvest already has `real_model_common/` (scope §What it builds 2). The architecture's capture-path guards follow the same pattern through `conductor-run/tests/capture_paths`, per §Occupied Resources.
- Operator-local instruments stay out of CI and the harness shells (§Stack and Technologies, the Operator instruments row: `mutation-gate.py` "invoked by no CI step, wired into neither harness shell"). The `.git`-less copy that motivates the secret-scan skip belongs to that operator-local mutation path. The fix belongs in the test, not in a new CI or harness hook.
- New CI/harness-visible facts are recorded in the keyed contracts. The CI/CD approach key, §Established Decisions → [CI/CD] and §Inherited Defaults → CI/CD all enumerate the static gates. A new `stub-server` gate is an amendment to all three at wrap.

## Anti-patterns to avoid
- A gate that passes vacuously on an absent subject (§Established Decisions → [CI/CD]: "an absent subject fails loudly rather than passing vacuously"). The no-`.git` skip must never cover a `git ls-files` failure inside a repository.
- A sixth `agent-run` command or a shell-side copy of a Rust gate's assertion (§Stack and Technologies, the Operator instruments row; §Established Decisions → [CI/CD]).
- Moving harvest grading out of test tier, for example into `conductor-verify`'s `classify()`, or adding a `Verdict`/`ReportState` variant or envelope key while lifting it (§Established Decisions → Probabilistic-Assertion Policy).
