# arch extract

## Relevance
partial — no new surface, crate, resource or contract; arch governs workspace placement of the split and the kill tests, the span-identity and canary invariants the mutants touch, and the operator-instrument and build-system context. The obs §10 CARRY is obs's to amend.

## Constraints
- Every addition stays inside the crate that owns the code under test: the harvest split stays in `conductor-run`'s test tree, the `xor_in_place` kill goes in `conductor-emit`, and the `emit_canary_storms` kills go in `conductor-run`. No `Cargo.toml` dependency edge is added or moved. In particular `conductor-emit` is the one member that does NOT depend on `conductor-core`, and a test must not wire one in (per architecture §Established Decisions [Module Boundaries]; §Occupied Resources → Crate names).
- A dev-dependency added for a kill test can hide a feature that one crate uses but declares only in `[dev-dependencies]`, because of workspace feature unification. The standalone per-seam build (`--lib`/`--bins`, never `--all-targets`) is measured at a chunk, not gate-enforced. So any new dev-dep needs that sweep, and its basis is the package count, not lockfile byte-identity (per architecture §Established Decisions [Module Boundaries]; §Infrastructure Patterns → Build system).
- Span identity is the one emitted value that a wall-clock read reaches. `rekey_trace_identity` must stay an XOR re-key: a bijection per salt that preserves linkage and moves no content byte. The unsalted dispatcher tier (`None`) must stay seed-pure, pinned by the `dispatch_wire__*` goldens. The `^=`→`|=`/`&=` mutants violate exactly this bijection. Whether any test already asserts the bijection or involution property is research's question (per architecture §Cross-cutting Patterns → Determinism discipline).
- The canary has two shapes. The deterministic canary (`boot` and every deterministic leg) must stay ONE storm, byte-identical. The real-model canary is `REAL_MODEL_CANARY_STORMS = 3` distinct storms of `CANARY_STORM_COUNT` 12, 90 s apart, with the freshness stamp taken before the first storm (per architecture §Standard Contracts → Readiness gate). Every `ok_span` carries a seeded per-call identity with disjoint warm-up and storm seed ranges, because Pulse rejects a replayed `(trace_id, span_id)` batch (per architecture §Occupied Resources → `contracts/pulse-run-contract.toml`). The `n > 0` and `n * CANARY_STORM_COUNT` survivors sit on these per-storm properties. Which property each mutant actually breaks (the gap before storms after the first, or seed-range disjointness across storms) is research's question.
- Kills are test-tier only. The verdict/error wall and the envelope stay untouched. Production code changes only if a survivor is proven equivalent-mutant-shaped (per architecture §Cross-cutting Patterns → Verdict/error wall; §Standard Contracts → Run report envelope).
- `delegated_timing_harvest.rs` is the harvest tier for the declare-only delegated-timing family: `halo-hue-encoding` · `service-constellation-discovery` · `report-render-surface` · `findings-counter-refresh`. These scenarios land `verdict: null` in the envelope, and their live claims are graded at the harvest tier. The split must leave every harvest-tier grade intact (per architecture §Standard Contracts → Run report envelope).
- Tests run under nextest's zero-retry `ci` profile, and no retry may mask a flake, because determinism is the invariant (per architecture §Infrastructure Patterns → Build system).

## Patterns to follow
- One target, child modules: the precedent is the prior corrective's real-model harvest split. Architecture still cites `conductor-run/tests/real_model_harvest.rs`'s `row()` and `conductor-run/tests/lifecycle_harvest.rs` by path, so both files keep their paths (per architecture §Established Decisions [Probabilistic-Assertion Policy]; [Read-Back Dependency Posture]).
- A natural partition axis for the split is the scenario family, since architecture already enumerates the delegated-timing family's four scenarios. Whether the file's items actually group that way is research's question (per architecture §Standard Contracts → Run report envelope).
- Mutation work stays on the operator-local instrument, `scripts/mutation-gate.py` + `scripts/mutation-roster.toml`. Every roster row carries a required `tally` of `missed` or `timeout`, and `selftest` grades `scripts/fixtures/mutation-gate/`. Whether the roster lists the five survivors, and so must shrink when they are killed, is research's question (per architecture §Stack and Technologies → Operator instruments; §Infrastructure Patterns → Directory structure).
- Measure an architecture draft before writing it, with `scripts/arch-registry-check.py`. It sizes §Established Decisions and §Occupied Resources against 60 % of the Read cap (per architecture §Stack and Technologies → Operator instruments).

## Anti-patterns to avoid
- Wiring the mutation gate into CI or into `agent-run.{sh,ps1}`. It is invoked by no CI step and adds no sixth command; the 5-command harness surface is unchanged (per architecture §Stack and Technologies → Operator instruments; §Infrastructure Patterns → Directory structure).
- A "kill" that changes emitted bytes: a production edit that moves the `dispatch_wire__*` goldens, the deterministic one-storm canary, or the canary's seed-range disjointness (per architecture §Cross-cutting Patterns → Determinism discipline; §Standard Contracts → Readiness gate).
- A cross-seam test dependency added only to reach a mutated function from another crate (per architecture §Established Decisions [Module Boundaries]).

## Contract bindings
- arch ↔ obs (the CARRY): architecture states that clippy runs (`Lint with cargo clippy`; clippy in the `rust` job), and states no blocking or non-blocking posture. So the obs-plan §10 amendment needs no architecture counterpart, as long as it stays within that statement (per architecture §Infrastructure Patterns → Build system; → CI/CD approach).
- arch ↔ tests: the nextest `ci` profile and the dev-test stack (rstest/proptest/insta/assert_cmd/assert_fs/predicates/regex/sha2) bound which tools a kill test may use without a new package (per architecture §Infrastructure Patterns → Build system).
- arch ↔ security: a kill test or split module must not add a new reader of a `CONDUCTOR_*` handle or of a committed contract file without taking that reader's guard duty (per architecture §Occupied Resources → Environment variables).

No member's `[dependencies]` or `[dev-dependencies]` edge set changes, and the locked package count holds (per architecture §Established Decisions [Module Boundaries]; §Infrastructure Patterns → Build system).
