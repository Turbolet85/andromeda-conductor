# security extract

## Relevance
partial — the chunk is a test-surface corrective (a test-target split, mutation-kill tests, an obs §10 wording measurement) that adds no new trust boundary, but it touches test-binary readers, committed evidence, the canary path behind the preflight gate, the secret-scan gate under cargo-mutants, and the supply-chain gate at merge.

## Constraints
- The duty to guard a path handle binds per READER. If `delegated_timing_harvest.rs` (or a child module split out of it) reads `CONDUCTOR_RUNS_DIR` or `ANDROMEDA_PULSE_DATA_DIR`, security-plan requires that read to resolve through the shared `conductor-run/tests/capture_paths` guards (`runs_dir_from` → `resolve_under`; `pulse_logs_dir_from` canonicalize + is-dir), with path-free rejection reasons. A split must move the guarded call along with the reader and must never re-open a raw join. Whether this file reads any handle at all is research's question (per security-plan §Input Validation, path-handle row; §Security Anti-Patterns → Input).
- A committed artifact that a test target reads should be resolved from `CARGO_MANIFEST_DIR` plus a hard-coded path, with no `CONDUCTOR_*` override handle. Read faults should carry `e.kind()` only, never the path. If a split child module reads committed evidence, it inherits this resolution. Whether the file pins any evidence bytes is open in scope and is research's question (per security-plan §Input Validation, committed-manifests row and real-model capture-ingest row).
- Corpus-rendered SUT text may never sit in test source. The 2026-09-29 breach was remedied by having each committed capture graded from its file behind a sha256 digest pin. A behaviour-preserving split must not inline or relocate any quoted SUT output into a test literal. Whether `delegated_timing_harvest.rs` holds any SUT-output literal today is research's question (per security-plan §Security Anti-Patterns → Data Protection).
- Mutation kills against `emit_canary_storms` must not change what the canary's freshness proves. "No incident opened after the canary storm" stays a distinct named `Blocked` precondition, never a silent downgrade or a false pass. Any production edit the plan admits as equivalent-mutant-shaped must keep that precondition intact (per security-plan §Security Anti-Patterns → Universal, failed-preflight ban; §Input Validation, MCP child stdout row).
- Under cargo-mutants' default VCS-less copy, the secret-scan gate is specified to skip with one path-free line, decided by `Path::exists` before any spawn. Inside a repository, a `git ls-files` failure still fails the gate. The targeted mutation runs should therefore read a skip line from that copy as expected, not as a defect. New test files created by the split enter the gate's cached + untracked-not-ignored listing and must carry no secret-shaped string (per security-plan §Secret Management, Secret-scan gate shape; §Security Anti-Patterns → Secrets).
- The supply-chain gate binds the merge. `cargo audit` and `cargo deny check advisories bans licenses sources` must both be green over a committed, un-drifted `Cargo.lock`. Before any red audit is classified as external, the porcelain check on the local advisory-db checkout runs first. cargo-mutants is an external host CLI tool: like the tools named in that section, it is never added to `Cargo.lock` (per security-plan §Dependency Security; §Security Anti-Patterns → Universal).

## Patterns to follow
- Test-binary handle readers go through `conductor-run/tests/capture_paths`, which is proven by the default-suite target `capture_paths_guard`. A split child module reuses that module and never re-implements the guard (per security-plan §Input Validation, path-handle row).
- Committed evidence is read by a harvest from a `CARGO_MANIFEST_DIR`-anchored hard-coded path, behind a sha256 digest pin over LF-normalized content, and graded only after the digest matches. This is the `real_model_harvest` shape and is the model if this file's evidence reads need re-homing (per security-plan §Input Validation, real-model capture-ingest row).
- A test spawn of a fixed program with fixed argv and no operator value sits outside rule (b) and adds no governed form (per security-plan §Security Anti-Patterns → Code Patterns, the `secret_scan_gate` test-binary note). Mutation-kill tests should stay within that shape.

## Anti-patterns to avoid
- Inlining SUT/corpus output, or a capture's bytes, as string literals in test source while restructuring the file (per security-plan §Security Anti-Patterns → Data Protection).
- Letting the chunk's report, its committed evidence, or a quoted cargo-mutants/clippy measurement leak absolute host paths. Examples are the mutants copy's scratch directory and the canonicalized `CONDUCTOR_*` dirs. Internal seam-crate struct names in error/report text are banned too (per security-plan §Security Anti-Patterns → Logging; §Error Handling, run-report artifact sanitization).
- Loosening a guard or a gate to make a split or a kill land. That covers widening `resolve_under` acceptance, adding a `deny.toml` ignore, or dropping a CI step such as the secret-scan gate (per security-plan §Security Anti-Patterns → Secrets; §Dependency Security, two external-decay faults).

## Contract bindings
- security ↔ tests: the secret-scan gate is a test target run by `agent-run run`'s workspace nextest and by the CI `rust` job. Its VCS-less skip arm is what lets cargo-mutants' copy run the suite (security-plan §Secret Management, Secret-scan gate shape ↔ test-plan CI integration).
- security ↔ obs: the §10 clippy amendment rides the obs-plan. Security's stake is only that the measurement carried in the report is host-path-free (security-plan §Security Anti-Patterns → Logging ↔ obs-plan §10).
