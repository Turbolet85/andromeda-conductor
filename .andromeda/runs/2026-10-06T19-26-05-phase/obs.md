## Constraints
- The `real-model-interpretation` drives ride Critical Path 1 unchanged: obs-plan requires that the real-model posture add NO critical path, span name or span attribute, and that the three-storm real-model canary add no span or field (per obs-plan §4 Scenario: Headless deterministic scenario run with MCP read-back verification → Real-model posture). A fourth series is therefore not a licence to mint instrumentation; whether the code at chunk base already rides the chain with nothing added is research's question.
- Interpretation is graded at the harvest tier over the scrubbed capture, never through the envelope: the envelope requires `verdict` null, and a non-degraded read-back lands `ManualCheck` (per obs-plan §4 Real-model posture). The series verdict (`Identified` / `NotIdentified`) must not be carried on, or derived from, an envelope field. The plan names the harvest target as `conductor-run/tests/real_model_harvest.rs`; whether that path still names the target after the 2026-10-04 split into child modules is research's question.
- Every drive's scenario-result record must carry the eleven envelope keys PRESENT (null-valued measurement fields are legal on a blocked row), asserted by key presence rather than a typed parse (per obs-plan §6 Required fields; §3 Log format JSON schema — two record shapes). A declare-only or blocked scenario emits no `CheckRecord` line (per obs-plan §3 Log format JSON schema).
- Any span attribute must be a name in the field allowlist or it emits nothing; non-allowlisted facts ride the allowlisted `message` field as key NAMES / counts, never values (per obs-plan §4 Scenario: Known-residual classification path → Required span attributes; §6 Boundary-call wrappers). Applies only if the chunk touches a run-path log site — the scope names none.
- No absolute host path or internal struct name in any Conductor-generated artifact of the drives — journal, `runs.db`, run report, `logs/agent-latest.jsonl` (per obs-plan §11 Logs; §9 Log conformance check). The enumerated host-path forms the plan lists were written against the Windows host; whether the redaction layer masks the Linux parent chosen for the new data dir (a form outside that enumeration) is research's question, and §11 PII Scrubbing's standing warning says the three application sites do not bound every channel.
- A per-target `RUST_LOG` directive replaces the default rather than adding to it, and neither form may be set for a run that also executes the test suite (per obs-plan §6 Per-module log levels). Binds the drive shell and the harvest/gate runs that follow it in one session.
- Journal and self-obs stamps come from wall-clock `std::time`, never tokio's virtual clock (per obs-plan §11 Project-specific bans; §5 Per-surface / per-path metrics) — relevant to any window arithmetic the series section pre-registers against journal stamps (the quiet windows).

## Patterns to follow
- Harvest-tier grading over the SUT's own lines / the scrubbed capture, with Conductor's envelope left at the declare-only shape — the precedent the restart-suppression, severity-lifecycle and delegated-timing families all follow (per obs-plan §4 Scenario: Restart-suppression; §4 Scenario: Severity-lifecycle; §4 Known-residual → Delegated-timing family).
- Read each Pulse-side quantity from its OWN exact field, and expect a Pulse field to read as a redacted placeholder live where Pulse's default-deny allowlist predates it (per obs-plan §4 Scenario: Restart-suppression → Required log fields; §4 Scenario: Severity-lifecycle → Required log fields). Whether `skip_reason` and the posture-confirming lines read unredacted at Pulse `5f77859` is research's question — obs-plan states nothing about either at that HEAD.
- Pulse coordinates in the plan are dated point-in-time reads that expire when its HEAD moves (per obs-plan §4 Known-residual → Delegated-timing family, closing sentence); the new section re-pins what it relies on rather than inheriting a coordinate from the plan.
- A scenario whose declared posture differs from the gate's posture is recorded scenario-level `Blocked` with one `info` line on `message`, before the ready check — never a sixth precondition (per obs-plan §4 Real-model posture). A drive that lands this way is a recorded outcome with its envelope, not a harness fault.
- The self-obs stream for a headless drive is the agent-mode file sink, one writer at a time, JSON on every writer (per obs-plan §3 Logging stack; §3 Log file location).

## Anti-patterns to avoid
- NEVER widen the bounded span-name set or add an OTel SDK / W3C trace context / self-obs OTLP export to witness the drives — the only OTLP is the product fault stream (per obs-plan §11 Spans / Traces; §11 Telemetry Strategy; §11 Universal).
- NEVER leak absolute host paths or internal struct names into logs / run report / `runs.db`, and never forward an unsanitized panic message or backtrace into an artifact (per obs-plan §11 Logs; §11 Error Reporting).
- NEVER let malformed read-back / transport input panic or go uncaptured — it is a typed `Blocked`, and there is no retry-once that masks a failure (per obs-plan §11 Error Reporting; §11 SLO). Aligns with the scope's no-retry-until-pass boundary.

## Contract bindings
- obs ↔ tests: the envelope and `CheckRecord` formats are owned by test-plan §3; obs aligns to it (per obs-plan §3 Log format JSON schema; §6). The run-journal conformance gate asserts key presence, closed sets and host-path freedom over the drives' journals.
- obs ↔ tests (harvest tier): the plan places interpretation grading in the `conductor-run` harvest target, outside the envelope (per obs-plan §4 Real-model posture) — the verdict test and the conditional ref test are tests-domain artifacts that obs constrains only by what they may NOT read.
- obs ↔ security: obs-plan's redaction layer governs Conductor-generated artifacts (per obs-plan §11 PII Scrubbing); it states no rule for the capture's scrub chain, which the scope attributes to security-plan — the security extract owns that claim.
- obs ↔ tests/CI: the walks-tree marks touch the two repository-hygiene gate sources; their output discipline — one line per hit naming a repo-relative location and rule, never the matched text, job log only, never a telemetry artifact — must survive the edit (per obs-plan §9 Pipeline integration → Repository-hygiene gates).
- obs ↔ CI: a `-D warnings` clippy red is blocking in `agent-run run`'s bundled default and in the `rust` job (per obs-plan §10 Build / deploy failure conditions) — binds the new series module and harvest test.
