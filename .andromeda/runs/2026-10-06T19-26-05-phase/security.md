# security extract

## Relevance
relevant — the chunk commits a new set of real-model captures (untrusted SUT output, including corpus-rendered model text) under the ONE ratified Data Protection exception, on a host whose path shapes no prior series exercised.

## Constraints
- **Scrub chain, in order, written once.** security-plan §Input Validation (real-model capture ingest row) requires every line the capture prints to pass `mask_workspace_key` FIRST, then `redact_value`, then `mask_host_paths`, then `elide_fingerprints`, with the output buffered and written once. Corpus-rendered report text may enter this chunk's committed `evidence/` tree ONLY through that chain (per security-plan §Security Anti-Patterns → Data Protection); a line hand-copied from a report into the attempt ledger, the new contract section, the chunk report or a test has not passed the chain and is outside the exception. The chunk uses "the capture tool as committed" — any edit to the scrub path is a change to this boundary, not a leg convenience.
- **Digest-pinned, graded from the file, no capture text in test source.** security-plan §Input Validation (same row) and §Security Anti-Patterns → Data Protection (the remedied 2026-09-29 breach) require each committed capture to be held by a sha256 pin over its LF-normalized content, graded only after the digest matches, loaded from `CARGO_MANIFEST_DIR` plus a hard-coded path with no `CONDUCTOR_*` handle. This binds the new series module, the verdict test and the conditional ref test alike.
- **Fingerprint and workspace-key zeros hold for the new population.** security-plan §Input Validation (same row) requires every committed `rm-capture*.txt` to carry zero un-elided keyed `fingerprint_hex=` values and to be a fixed point of the elision, with the population pinned BY COUNT beside an inverse control — so the count pin moves by exactly the captures this chunk commits. The data-dir leaf must occur zero times in each capture, the report's rendering witnessed by the one class-only line, never the value. The plan states the leaf matches the key only under a launch whose workspace detection falls back to the data dir, and pins that derivation at Pulse `fcc31b2` / `a2addb3`; whether it is unchanged at `5f77859`, and whether this host's launch posture takes the fallback, is research's question.
- **Both path handles through the shared guards.** security-plan §Input Validation (env-var path-handle row; real-model capture ingest row) and §Security Anti-Patterns → Input require `CONDUCTOR_RUNS_DIR` to resolve through `capture_paths::runs_dir_from` → `resolve_under` (absolute or parent-escaping rejected) and `ANDROMEDA_PULSE_DATA_DIR`'s value to be canonicalized and required to be a directory before `logs/` is joined, every rejection a path-free reason. The duty binds per READER: any test-binary reader this chunk adds is recorded, never assumed. Whether the code at HEAD already routes every reader the leg touches through those guards is research's question.
- **No host path in committed evidence — and the scrubber's host coverage is unmeasured here.** security-plan §Security Anti-Patterns → Logging requires the per-chunk `evidence/` tree to carry no absolute host path. This chunk's ledger rows have several host-path-valued subjects new to it: the two model env handles' values, the data dir's parent, the built binaries' locations, and whichever sidecar the inherited `PATH` resolves. Record handle NAMES, the leaf, a sha256 or a boolean — never the value. All three prior series ran on the Windows host; whether `mask_host_paths` masks this host's home-rooted and temp-rooted absolute forms is research's question and must be answered BEFORE d1, because a capture is written once.
- **The refusal arm and the sidecar name stay as shipped.** security-plan §Security Anti-Patterns → Universal requires `run --live real-model` to lead with `conductor preconditions --for real-model-interpretation`, graded under the real-model posture (the L4 deterministic handle ABSENT or falsy under the union truthiness rule, per §Input Validation, declaration-only read-set row), refusing at exit 1 with no leg fired; the selector is a closed allowlist (§Input Validation, CLI-arguments row). The sidecar is a fixed program NAME resolved through the inherited `PATH` (§Security Anti-Patterns → Input), so "the sidecar is proven before d1" means proving the binary `PATH` selects — never repointing the spawn at a path. Whether sourcing the model env script leaves the L4 handle undeclared in the drive's shell is research's question.
- **Supply-chain gate read from the world's state.** security-plan §Dependency Security requires the porcelain check on the local advisory-db checkout (or a fresh clone under `--db`) to PRECEDE classifying any `cargo audit` red as external, both `cargo audit` and `cargo deny check advisories bans licenses sources` green, and `Cargo.lock` committed and un-drifted. The chunk declares no dependency; should one appear, the plan's new-dependency condition applies.

## Patterns to follow
- The class-only witness form: Pulse's lines are read fields-only (`skip_reason`, `decision`, `severity`, `digest_kind` — closed enums), and the workspace rendering is one line from a closed four-value set (per security-plan §Input Validation, real-model capture ingest row). The ledger's "`skip_reason` for every digest it did not surface" takes this form.
- The workspace key is taken once from the guarded data-dir path's parent leaf, never from a raw read of the handle; absent or rejected means no key while `workspace=` lines are masked regardless (same row).
- The declaration-only read set is three named handles (per security-plan §Input Validation, declaration-only read-set row). The two model env handles are not in it: keeping their pre-leg check a session-level act that records presence keeps the set unchanged; a Conductor reader of either (binary, test binary or harness shell) is a new reader the plan does not yet describe.
- A bounded ingest: the MCP re-read goes through the hardened `ReadbackClient::connect`, with the plan's stated poll and id-sweep bounds (same capture ingest row) — unchanged by a new series.
- The secret-scan gate's own test spawn is a fixed program with a fixed argv and adds no governed form (per security-plan §Security Anti-Patterns → Code Patterns); a `andromeda:walks-tree` comment token on that file is a comment only and must leave the spawn, the rule set and the exact-set allowlist untouched (§Secret Management → Secret-scan gate shape).

## Anti-patterns to avoid
- NEVER open, copy or read Pulse's corpus file, and NEVER stage a corpus row to steer a drive — corpus access is the MCP tool surface only, and anything read from it is persisted nowhere but the scrubbed `evidence/` captures (per security-plan §Security Anti-Patterns → Data Protection). A skipped digest is explained from Pulse's log fields, never from the database.
- NEVER add a committed spawn to the harness shells, the driver stack or the CI workflow to give this host its forms of the process census, the model hash or the Pulse launch — that is a ninth governed form and escalates before it lands; and never as a shell string carrying an operator value (per security-plan §Security Anti-Patterns → Code Patterns, rule (b)).
- NEVER treat a red `cargo audit` as an external fault, add a `deny.toml` ignore for it, or proceed on it, before the local advisory-db copy's state has been read (per security-plan §Dependency Security).

## Contract bindings
- security ↔ tests: the harvest arms (digest pins, the capture population count and its inverse control, the no-capture-text-in-test-source arm, the path-guard target) are the tests domain's bodies holding this domain's invariants; the capture itself is operator-gated `live-pulse`, never a CI stage (per security-plan §Input Validation, real-model capture ingest row).
- security ↔ obs: the redaction boundary governs Conductor-generated artifacts and the committed `evidence/` tree; Pulse's own log is read fields-only and never committed raw (per security-plan §Security Anti-Patterns → Logging).
- security ↔ arch: the real-model posture's `shell-absence` run-contract term and the posture contract's new section meet at the preconditions arm (per security-plan §Input Validation, committed SUT-facing manifests row). The plan's evidence-hygiene ban names the `evidence/` tree and run artifacts; it does not name `contracts/` documents, so how the new section writes this host's launch paths is the plan author's call, not a mandate extracted here.
- security ↔ CI: the `rust` job's secret-scan gate and the audit/deny steps read whatever this chunk commits, new evidence and digests included (per security-plan §Secret Management; §Dependency Security).
