## Patterns to follow
- One harvest verdict test per series, named for the series and its outcome (the prior one is `v3_09_is_not_met_by_the_2026_10_06_series`); a NOT MET series carries no ref test and no further drive. The ref test asserting `Identified` plus the real-model witnesses has no shipped precedent in the plan — every recorded series reads not met — so its shape is P4's to design, not a pattern to copy (per test-plan §6 Scenario: Fingerprint-storm — Real-model interpretation leg).
- Pin-then-grade with its two controls: a one-byte tamper arm showing the pin can fail (naming the file, never the text) and a source arm holding that no capture text sits in test source. Synthetic arms cover every outcome class; Pulse's `skip_reason` rides each `canary:` line as a trailing field, recorded and never graded (per test-plan §6 Scenario: Fingerprint-storm — Real-model interpretation leg).
- Captures are EVIDENCE under the chunk's `evidence/` tree — read-only, `CARGO_MANIFEST_DIR`-anchored, digest-checked before any grade reads them — never a fixture copied elsewhere (per test-plan §7 Self-bootstrapping requirement).
- A `live-pulse`-gated target owes its own lint line, and that line already sits in `agent-run run`'s bundled default; a new target under the feature is covered by it, the feature adds zero package nodes, and the lock's package total is read from `Cargo.lock`, never from prose (per test-plan §9 Live-Pulse scenarios).
- The quiet windows the series pre-registers are firing-form waits BETWEEN drives reproducing Pulse's dedupe window (120 s idle + a 30 s resolver tick), not synchronisation inside a test (per test-plan §11 Test Anti-Patterns — E2E).

## Anti-patterns to avoid
- NEVER run the live-Pulse leg as a CI gate, and NEVER fake Pulse's reaction as a CI verdict — the stub proves wiring only, so the series verdict rests on the live captures alone (per test-plan §11 Test Anti-Patterns — CI; §11 Test Anti-Patterns — Test Strategy).
- NEVER treat `Blocked` / `ManualCheck` / `CalibrationRegion` as a non-zero process exit: a `NotIdentified` drive is a reported state, so a drive's exit code is not its grade — the grade is the harvest's reading of the capture (per test-plan §11 Test Anti-Patterns — E2E; §3 `run` Exit code semantics).
- NEVER add a retry policy or set nextest `retries`, and never skip a quality gate "just this once"; at series grain the same ban reads as no re-fire beyond the one uncounted pipeline-fault re-fire (per test-plan §11 Test Anti-Patterns — Quality; §9 Live-Pulse scenarios).
