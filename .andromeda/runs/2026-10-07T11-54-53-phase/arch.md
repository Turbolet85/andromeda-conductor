## Constraints
- architecture.md §Occupied Resources → Environment variables (the `ANDROMEDA_PULSE_MODEL_PATH` · `ANDROMEDA_PULSE_LLAMA_CUDA_BIN_PATH` entry) requires that Conductor neither set nor read either handle. Under vehicle (A) that entry stays unamended, so no committed Conductor file (harness shells, crates, test binaries, scenarios) may set one, read its value, or name the operator's pass-through as a program. Whether any shipped or test code path already touches either handle is research's question.
- architecture.md §Occupied Resources → Environment variables (the `ANDROMEDA_PULSE_L4_DETERMINISTIC` entry) requires that the shell launching Conductor be the one that launches `pulse-app`, with the L4 handle read for ABSENCE under the real-model posture. The only launch term that moves is the env file that shell sources, so Conductor's own process INHERITS the operator's handles without reading them; whether any Conductor path echoes inherited environment into an artifact is research's question.
- architecture.md §Occupied Resources → On-disk artifacts / database (the `contracts/pulse-real-model-leg-posture.md` entry) requires every drive series to be an add-only section fixed before its first drive, and states that the document names only already-registered environment handles, mints none, and registers no `agent-run` verb, flag or arm. The capture-run record therefore lands add-only and before d1; if it comes to name `PC_L4_REAL_LLAMA_BIN` (an operator variable no entry registers), that statement stops holding and a registration is owed at wrap. Whether the entry's dated-series description still describes the document once a non-series capture section sits beside the series is the wrap's amendment question.
- architecture.md §Established Decisions [Read-Back Dependency Posture] requires the real-model leg to be driven only as the pre-stated series its posture contract fixes before the first drive, each counted drive graded against a rule committed before it fires. A capture run of three drives is bound by the same order of acts even though it claims no verdict.
- architecture.md §Occupied Resources → On-disk artifacts / database (the `runs/live-suite/{leg}.jsonl` entry) requires the real-model arm's three files to be cleared non-recursively before each leg, with no `CONDUCTOR_*` handle of their own. Each drive's capture is therefore overwritten by the next invocation and must reach the chunk's `evidence/` between drives; how the earlier series carried a per-drive capture out is research's question.
- architecture.md §Standard Contracts → Readiness gate requires the real-model canary to be three distinct storms 90 s apart inside every leg's preflight, ahead of the scenario's own emission. Model invocations therefore begin BEFORE the envelope's `journal_emitted_at`, so a drive's start/end instants offered as the bracket for the operator's per-invocation stamps must span the whole leg, not the envelope's two instants. Which stamp bounds the leg's start is research's question.
- architecture.md §Cross-cutting Patterns → Scope law lists Pulse process management as a non-goal, and §Cross-cutting Patterns → Trust boundary limits Conductor's children to the MCP sidecar it spawns over piped stdio. Launching and stopping `pulse-app` stays an operator-side act under the posture contract, never a harness-shell or crate function; the pass-through is Pulse's child, never Conductor's.

## Patterns to follow
- Fire each drive through the existing `run --live real-model` arm — a selector of `--live`, headless only, the gate evaluated under the scenario's declared posture (architecture.md §Design Philosophy, the headless-drivable-core principle; §Standard Contracts → Readiness gate).
- Grade at the harvest/test tier and record outside the envelope: the scenario is declare-only from birth and its interpretation claim is graded in `conductor-run`'s test tier, with a non-degraded success row landing `ManualCheck` (architecture.md §Standard Contracts → Run report envelope; §Established Decisions [Probabilistic-Assertion Policy]). The chunk's "observation" grades ride the attempt ledger, not a new envelope state.
- Digest pins over committed captures use the already-locked test-only `sha2` dev-dependency of `conductor-run` — no new package (architecture.md §Stack and Technologies → Hashing / digest). Whether a non-verdict capture needs a pin in the harvest module is research's question.
- Instants in the report are colon-delimited RFC-3339 UTC, sourced from `std::time` stamps, with the hyphen form reserved to `run_id` (architecture.md §Standard Contracts → Timestamp formats; §Cross-cutting Patterns → Determinism discipline).
- The posture contract is a `contracts/` member with no Rust reader, addressed outward; an edit to it carries no load path, bounds check or `CONDUCTOR_*` handle (architecture.md §Infrastructure Patterns → Directory structure (crate-per-seam Cargo workspace); §Occupied Resources → On-disk artifacts / database).

## Anti-patterns to avoid
- A Conductor leg, script or test that sets a model-binary handle, reads what the pass-through recorded, or spawns the pass-through — the widening the two-handle registration excludes (architecture.md §Occupied Resources → Environment variables; §Cross-cutting Patterns → Trust boundary).
- Minting surface for the capture: a sixth harness command, a new `--live` arm or flag, a `CONDUCTOR_*` handle, a `Verdict` / `ReportState` variant or an envelope key (architecture.md §Stack and Technologies → Operator instruments, the unchanged 5-command surface; §Established Decisions [Probabilistic-Assertion Policy]).
- Driving first and fixing the record afterwards, or rewriting an earlier dated series section instead of adding beside it (architecture.md §Occupied Resources → On-disk artifacts / database, the posture-contract entry).

## Contract bindings
- arch ↔ security: the two-handle registration (§Occupied Resources → Environment variables) is the architecture half of the boundary whose other half is security-plan's corpus-persistence clause; vehicle (A) leaves both unamended, and the report's naming of the operator's capture path is security's host-path call.
- arch ↔ tests: the harvest tier (`conductor-run` tests) and the `run --live real-model` artifact contract (§Occupied Resources → On-disk artifacts / database) bind how a per-drive capture is carried, pinned and graded.
- arch ↔ obs: `runs/live-suite/rm.jsonl` is the leg's frozen self-obs stream (§Occupied Resources → On-disk artifacts / database), a candidate source for whole-leg start/end instants; its line schema is obs-plan's.
- arch ↔ wrap: any §Occupied Resources amendment (a handle registration, the posture entry's series description) is sized by `scripts/arch-registry-check.py` (§Stack and Technologies → Operator instruments), so it first frees bytes there.
