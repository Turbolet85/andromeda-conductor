# obs extract

## Relevance
partial — the chunk ships three live real-model drives, a contract record and evidence, and (as scoped) no instrumentation; obs binds on the envelope those drives land, on where the drive instants come from, and on host-path hygiene of the telemetry artifacts.

## Constraints
- obs-plan §1 Obs Scope Summary (tier Minimal; Instrumentation scope, the Pulse MCP server row) classes Pulse as Boundary-only: Conductor's self-observation stops at the read-back response and its timing. No obs mandate asks Conductor to record what the model received, so vehicle (A) leaves no obs requirement unmet and adds none.
- obs-plan §4 Scenario: Headless deterministic scenario run with MCP read-back verification (the Real-model posture paragraph) requires a real-model scenario to ride the existing chain with no new critical path, span name or span attribute, the eleven-field envelope, `verdict` null, and a non-degraded read-back landing `ManualCheck`. The capture run's three drives are bound by the same shape.
- obs-plan §4 Scenario: Headless deterministic scenario run with MCP read-back verification (the Real-model posture paragraph) requires the interpretation to be graded at the harvest tier over the scrubbed capture, never through the envelope. The chunk's per-drive grades, recorded as observations, therefore stay out of the envelope's `verdict`/`state` and out of any self-obs field.
- obs-plan §6 Log Coverage (Required fields) requires all eleven envelope keys PRESENT on every envelope record, null values included, with key presence asserted by the run-journal conformance gate. Whether the gate reaches the run journals these three drives write is research's question.
- obs-plan §3 Log format JSON schema requires the envelope's `journal_emitted_at` / `read_back_observed_at` as ISO-8601 from `std::time::SystemTime` and the self-obs line's `timestamp_ms` as epoch millis from the same clock. The report's per-drive start and end instants (scope item 5) must come from one of these wall-clock sources or from Pulse's own log stamps; which source is used, and whether its form brackets the operator's `started-utc` unambiguously, is research's question.
- obs-plan §11 Obs Anti-Patterns (Logs) and §9 CI Integration (Log conformance check) require that no absolute host path reach a log line, the run report or `runs.db`. The posture note and the operator's capture path are document content of the chunk; they must not enter a Conductor-generated telemetry artifact of the drives.
- obs-plan §11 Obs Anti-Patterns (PII Scrubbing) requires treating the three redaction sites as not bounding every host-path channel. The launching shell's model-binary handle now points at a file under the operator's folder; whether that path reaches any text Pulse logs and Conductor's capture or self-obs stream ingests is research's question (scope item 8 already names it).

## Patterns to follow
- The series precedent in obs-plan §4 Scenario: Headless deterministic scenario run with MCP read-back verification (the Real-model posture paragraph): each live series records in its `evidence/attempt-ledger.md` how every drive's envelope landed (state, `verdict` null, eleven keys) and that the chunk added no span, log line or field. This run records the same three facts per drive.
- The span-lifecycle line of obs-plan §3 Log format JSON schema (`span`, `span_event` `new`/`close`, `timestamp_ms`) is a self-obs source for a `scenario.run` open and close instant. Obs-plan §4 Scenario: Headless deterministic scenario run with MCP read-back verification (Cleanup) opens that root at `execute_scenario`; whether the preflight canary's storms, and the model invocations they cause, precede that open is research's question, since a bracket read from `scenario.run` alone would then exclude them.
- Obs-plan §4 Scenario: Headless deterministic scenario run with MCP read-back verification (the Real-model posture paragraph) records that the capture's `canary:` line count is not the storm count. The number of model invocations a drive's time bracket must contain is therefore not readable from the capture's `canary:` lines; the report should state the bracket, not an invocation count inferred from them.
- Obs-plan §3 Logging stack and §3 Log file location fix the agent-mode sink as the single file `logs/agent-latest.jsonl`. Whether each of the three drives rewrites it, so that a drive's self-obs instants must be read before the next drive starts, is research's question.
- Obs-plan §6 Log Coverage (Per-module log levels) requires pairing the global level with any per-target `RUST_LOG` directive, because a bare target directive replaces the default. The launching shell for the drives keeps the default filter, or the lines the instants are read from go dark.

## Anti-patterns to avoid
- Carrying the disclosure, a drive's grade or the capture tie on a new span name, span attribute, log line or envelope extra: obs-plan §11 Obs Anti-Patterns (Spans / Traces) bounds the span-name set, and obs-plan §4 Scenario: Known-residual classification path (Required span attributes) states that a field outside the allowlist is dropped at the processor stage.
- Taking a drive's start or end instant from tokio's clock or any scheduling value: obs-plan §11 Obs Anti-Patterns (Project-specific bans) reserves journal timestamps to `std::time::SystemTime`.
- Letting an absolute host path (the pass-through's, the capture folder's, the data dir's) into `logs/agent-latest.jsonl`, the run journal, the run report or `runs.db`: obs-plan §11 Obs Anti-Patterns (Logs).

## Contract bindings
- obs ↔ tests: the eleven-field envelope and the `CheckRecord` line are owned by test-plan §3, and key presence is asserted by `conductor-run`'s `journal_conformance` (per obs-plan §3 Log format JSON schema). The drives' journals are read against that contract, never re-typed here.
- obs ↔ security: host-path redaction is one layer shared with security-plan §Error Handling (per obs-plan §11 Obs Anti-Patterns (PII Scrubbing)); the capture scrub chain for committed evidence is security's, and the question whether the pass-through's path reaches ingested text lands on both.
- obs ↔ arch: the self-obs sink's location rides `CONDUCTOR_RUNS_DIR` (per obs-plan §3 Log file location), the same handle the live leg's capture paths are guarded through.
- obs ↔ a11y: (none)
