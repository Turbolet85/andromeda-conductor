# security extract

## Relevance
relevant — the chunk commits three scrubbed real-model captures under the one ratified corpus-content exception, runs beside an operator-owned recording pass-through whose output the Data Protection ban keeps out of every Conductor artifact, and carries the standing supply-chain gate.

## Constraints
- security-plan §Security Anti-Patterns → Data Protection requires that Pulse corpus content is never persisted into a Conductor artifact, with exactly ONE exception: corpus-rendered model text the real-model capture re-reads over MCP, entering a chunk's committed `evidence/` tree only, and only through the four-stage scrub chain. The exception names one route and one destination; the plan names no second route. The operator's recorded prompts are not that route, so nothing read from them — the bytes or a fact derived from them (a count, a digest, a section diff) — may enter the pre-registered record, the attempt ledger, the report, a capture or test source. The plan does not name model prompts as a class; the scope reads the ban as covering them, and the exception admits them under neither reading.
- security-plan §Input Validation (real-model capture ingest row) requires every printed capture line to pass `mask_workspace_key` FIRST, then `redact_value`, then `mask_host_paths`, then `elide_fingerprints`, with the output buffered and written ONCE; and requires the reader to load each committed capture from a hard-coded path under `CARGO_MANIFEST_DIR` (no `CONDUCTOR_*` handle), check its sha256 digest pin over the LF-normalized content, and grade only after the digest matches. This binds each of d1..d3's captures although the run is a capture and not a verdict. The same row has the harvest walk every committed `rm-capture*.txt` under `conductor-0.3.0/chunks/*/evidence/` with the population PINNED BY COUNT — three new files move that count; whether the harvest's population pin and per-file pins already admit a non-verdict chunk's captures, and what must change, is research's question.
- security-plan §Input Validation (real-model capture ingest row) fixes the CLASSES of Pulse log line the capture prints (storm lines, `canary:` lines, the digest-corpus-retrieval line, the fields-only `interpretation.incident.skipped` lines) and requires Pulse's witnesses to be read fields-only. The chunk's one launch difference is the model-binary handle pointing at the pass-through, whose path is home-rooted; whether any already-printed line class carries the model binary's path or its argv (the prompt rides on argv), and whether the chain reduces it, is research's question. A new printed line class would be a new ingest the row does not record, and the masters are read-only in this chunk.
- security-plan §Input Validation (real-model capture ingest row) requires the workspace key to be the data dir's basename taken from the guarded `capture_paths::pulse_logs_dir_from` path, every `workspace=` value masked whatever it holds, and the leaf to occur zero times across the committed captures (its rendering witnessed by one class-only line). The new data-dir leaf P4 names is therefore a scrub input as well as model input; the row records that the leaf matches only under a launch whose workspace detection falls back to the data dir — whether this launch does is research's question.
- security-plan §Input Validation (env-var path handles row) requires the test-binary readers of `CONDUCTOR_RUNS_DIR` and of `ANDROMEDA_PULSE_DATA_DIR`'s value to resolve through the shared `conductor-run/tests/capture_paths` guards before any read, every rejection a path-free reason. The drives must reach those readers through the existing guarded path; a drive-instant source the chunk adds for the time tie may not join either handle unguarded.
- security-plan §Input Validation (the `ANDROMEDA_PULSE_*` declaration-only read-set row) enumerates Conductor's read set as three handles and requires that no value of them becomes a path, an argv element or a log value; under the real-model posture the L4-deterministic handle must be absent or falsy. Neither model-binary handle is in that set. A Conductor file that set one, read one, or recorded its value would extend the enumerated set, and the disclosure note must name handles by NAME only. Whether any Conductor code or script already references either handle is research's question.
- security-plan §Security Anti-Patterns → Logging requires committed evidence records and run-report artifacts to carry no absolute host path. The disclosure note, the ledger's pre-leg check rows and the report's naming of the folder the Pulse builder reads and of the data dir must be rendered in a form that is not an absolute host path. How the fifth series rendered its data dir and which hygiene gates sweep the posture contract and the chunk's `report.md` is research's question.
- security-plan §Dependency Security requires the advisory-db checkout's porcelain check (or a fresh `--db` clone) to PRECEDE any reading of `cargo audit`, and `cargo deny check advisories bans licenses sources` to run beside it, verified green rather than assumed; security-plan §Security Anti-Patterns → Universal requires a committed, un-drifted `Cargo.lock`. The chunk plans no dependency delta; that is stated as a package count, to be measured.

## Patterns to follow
- Scrub, then pin, then grade from the file: each drive's capture enters `evidence/` through the scrub chain, is held by a sha256 digest pin, and no capture text sits in test source (security-plan §Input Validation, real-model capture ingest row; security-plan §Security Anti-Patterns → Data Protection, the remedied 2026-09-29 breach).
- Class-only and names-only witnesses: a posture is stated as a class or a handle NAME, never a value — the shape of the `pulse-report workspace rendering` line and of the precondition probe's output (security-plan §Input Validation, real-model capture ingest row and declaration-only read-set row). The disclosure note follows it.
- The time tie needs no scrub change: the elision rule passes an unkeyed all-digit run — a stamp — by design, so the per-interpretation stamps the tie relies on survive the chain as specified (security-plan §Input Validation, real-model capture ingest row); the drive instants come from `std::time` stamps, never tokio's virtual clock (security-plan §Security Anti-Patterns → Logging).
- Reuse the closed selector: the drives go through the existing `run --live real-model` arm, a closed allowlist that leads with `conductor preconditions --for real-model-interpretation` and refuses at exit 1 before any sidecar spawn (security-plan §Input Validation, CLI arguments row; security-plan §Security Anti-Patterns → Universal). No new token, verb or handle is needed for a capture run.
- Porcelain first, then audit and deny as an overlap, each exit read from the bare command (security-plan §Dependency Security).

## Anti-patterns to avoid
- Persisting corpus content anywhere but the one ratified route — including prompt-derived facts in a ledger or report, and capture text as literals in test source (security-plan §Security Anti-Patterns → Data Protection).
- A Conductor-committed file naming an operator-supplied value as a spawn PROGRAM, or composing one into a shell string — the pass-through, or the real binary named by the operator's own variable for the pre-leg runtime check. The harness-spawn rule governs eight forms; a new crossing is an escalation, never routine (security-plan §Security Anti-Patterns → Code Patterns). Whether the fifth series' pre-leg checks were session acts or a committed script is research's question.
- An absolute host path, or a handle's path VALUE, in the committed captures, ledger, report or contract section (security-plan §Security Anti-Patterns → Logging).

## Contract bindings
- security ↔ tests: the harvest (`real_model_harvest`) carries the digest pins, the population count pin with its inverse control, and the `no_committed_capture_text_sits_in_test_source` arm; `capture_paths_guard` holds the handle guards (security-plan §Input Validation, real-model capture ingest row and env-var path handles row). The `rust` job's secret-scan gate runs over git's cached plus untracked-not-ignored listing, so the new evidence files are in its subject (security-plan §Secret Management → Secret-scan gate shape).
- security ↔ architecture: the env-handle registry and the clause that Conductor neither sets nor reads the model-binary handles are architecture's (§Occupied Resources); security's side is the enumerated three-handle read set and the every-handle-is-non-secret invariant (security-plan §Input Validation, declaration-only read-set row; security-plan §Secret Management). Whether a committed Conductor document comes to name the operator's variable, and so owes a registration, stays the scope's item 10.
- security ↔ the posture contract (`contracts/pulse-real-model-leg-posture.md`): the pre-registered record and its posture note are committed prose under the host-path ban (security-plan §Security Anti-Patterns → Logging) and under the Data Protection ban (security-plan §Security Anti-Patterns → Data Protection).
- security ↔ obs: wall-clock stamps for the drive instants from `std::time` (security-plan §Security Anti-Patterns → Logging).
