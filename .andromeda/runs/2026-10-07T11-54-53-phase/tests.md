# tests extract

## Relevance
relevant — the chunk fires three operator-gated `run --live real-model` drives and commits three scrubbed captures the default-suite harvest tier must hold; it adds no CI stage and no deterministic-tier scenario.

## Constraints
- **The only vehicle for a drive is the existing selector.** test-plan §3 `run` specifies `agent-run run --live real-model` as a fixed sequence (the posture-scoped `preconditions --for` probe, the capture pre-build, the non-recursive removal of the three `runs/live-suite/rm*` files, the rule record written BEFORE the leg, the leg, then the capture) that adds no port, env var or `CONDUCTOR_*` handle and keeps the command count at five with identical `.sh`/`.ps1` semantics. The chunk drives it unchanged; anything it wants beside a drive (the drive's start and end instants) is read from artifacts that sequence already writes, never by a new verb, selector or harness-read handle. Whether those artifacts already carry instants in a form that brackets the operator's stamps is research's question.
- **The three `rm*` files are per-invocation.** test-plan §3 `run` requires their removal at the head of every `--live real-model` invocation, so each drive's capture is scrubbed and committed (or frozen aside) before the next drive fires; a capture left in place is destroyed by the next drive. How the fifth series' plan ordered this is research's question.
- **Pre-statement before the first drive, no replacement.** test-plan §9 Live-Pulse scenarios requires the real-model selector to be driven only as a run pre-stated in `contracts/pulse-real-model-leg-posture.md` and fixed before its first drive, every drive recorded and never replaced, with a single re-fire admitted only for a Conductor-side environment or pipeline fault, and the pickup recorded as a measurement, never budgeted. That section words the unit as "the pre-stated series"; whether a non-verdict capture run recorded beside the dated series sections satisfies that wording as written, or owes a wrap-time amendment, is research's question (the masters are read-only in this chunk).
- **Every committed capture is digest-pinned and graded from its file.** test-plan §6 Scenario: Fingerprint-storm → Real-model interpretation leg requires each committed capture to be held by a sha256 pin over its LF-normalized content, graded only after the digest matches, with a tamper arm that names the file and never the text, and a source arm holding that no committed capture text sits in test source. Three new captures under this chunk's `evidence/` owe three pins. A grade written into the attempt ledger as an observation is the harvest's grade over the pinned file, never a reading by eye; whether the series module's grading can be invoked for a run that states no `v3-09` verdict without minting a verdict test is research's question.
- **The committed-capture population is pinned by count.** test-plan §6 Scenario: Fingerprint-storm → Real-model interpretation leg requires a population arm holding every committed `rm-capture*.txt` at zero un-elided keyed fingerprint values and at a fixed point of the elision, with the population pinned by count beside an inverse control. Committing three more captures moves that population; how the arm discovers its members and what count it holds today are research's questions.
- **The grading rule does not move.** test-plan §6 Scenario: Fingerprint-storm → Real-model interpretation leg requires the recorded 2026-09-23 rule to stay a byte-exact prefix of the rule in force and the rule's span to be recorded into each capture ahead of its leg and asserted to predate it. The chunk changes neither the rule nor the design, and writes no ref test.
- **No new env reader, so no new coverage class.** test-plan §1 Coverage triggers (security-vector-coverage, Vector 1 — the fifth per-reader class) requires every test-binary reader of `CONDUCTOR_RUNS_DIR` and of the `ANDROMEDA_PULSE_DATA_DIR` value to resolve through the shared `capture_paths` guard, held by the default-suite `capture_paths_guard` target under both runners. A test or harness line that read a model-binary handle, or the operator's real-binary variable, would be a sixth class owing its own negative test; the chunk adds none. The new data-dir leaf reaches the capture's workspace-key mask through that same guarded read.
- **Both runners, zero retries.** test-plan §4 Framework requires any touched test to be green under `cargo nextest run` AND full `cargo test -p <crate>`; test-plan §10 Zero-flakiness budget bans nextest `retries` and treats a runner-dependent result as a defect. The live drives are exempt from neither as a source of flake: test-plan §2 Agent-runnable invariants carries the real-model selector only as an operator-local-gate exception, never as the deterministic tier.

## Patterns to follow
- **Harvest-tier grading over committed evidence** — the capture is read in place under the chunk's `evidence/` tree, read-only, `CARGO_MANIFEST_DIR`-anchored, digest-checked before any grade; it is evidence, never a fixture copied elsewhere (per test-plan §7 Self-bootstrapping requirement; test-plan §6 Scenario: Fingerprint-storm → Real-model interpretation leg).
- **A new pin proves it can fail in-suite** — a tamper or negative arm beside each added assertion, built at test time, no committed leak control (per test-plan §6 Scenario: Fingerprint-storm → Real-model interpretation leg; the same can-fail shape test-plan §6 Scenario: Coverage-matrix completeness gate requires of its static legs).
- **Test commands the chunk's plan lists** — deterministic: `cargo nextest run -p conductor-run --test real_model_harvest --profile ci`, `cargo nextest run -p conductor-run --test capture_paths_guard --profile ci`, `cargo test -p conductor-run`, then the bundled default `bash scripts/agent-run.sh run` (workspace nextest `ci` profile, doctests, workspace clippy, the two feature-gated clippy lines); operator-gated, never CI: `bash scripts/agent-run.sh run --live real-model`, once per drive (per test-plan §3 `run`; test-plan §4 Framework; test-plan §9 Pipeline structure).
- **Feature-gated targets owe their own lint line** — if `real_model_live.rs` or any other `live-pulse` target is touched, `cargo clippy -p conductor-run --features live-pulse --all-targets -- -D warnings` is the line that sees it; the workspace pass does not (per test-plan §9 Live-Pulse scenarios).
- **A wait between drives is firing form, not synchronisation** — a quiet window between drives that reproduces Pulse's dedupe precondition belongs to the harness-level firing form; nothing inside a test sleeps to synchronise (per test-plan §11 Test Anti-Patterns → E2E). Which window the three-drive design carries is read from the posture contract and the fifth series' plan.

## Anti-patterns to avoid
- Never run a real-model drive, or any live-Pulse leg, as a CI gate, and never stand a synthetic capture in for a drive that did not fire — the stub proves wiring, never Pulse's reaction (per test-plan §11 Test Anti-Patterns → CI; test-plan §11 Test Anti-Patterns → Test Strategy).
- Never read a drive's grade from the process exit: `Blocked` / `ManualCheck` / `CalibrationRegion` are reported states, and a `--live real-model` invocation that exits 0 has stated no grade (per test-plan §11 Test Anti-Patterns → E2E).
- Never turn the pass-through's byte-equality into a Conductor test step or a manual smoke step: what the model binary received sits inside the SUT's own process boundary, which test-plan §1 Untestable zones flags as untestable from Conductor and bars from an invented driver; the operator's self-test is cited as theirs (per test-plan §1 Untestable zones; test-plan §11 Test Anti-Patterns → Universal).

## Contract bindings
- **tests ↔ the posture contract** — `contracts/pulse-real-model-leg-posture.md` is the pre-statement home test-plan §2 Agent-runnable invariants, §6 Scenario: Fingerprint-storm → Real-model interpretation leg and §9 Live-Pulse scenarios all name; the chunk's pre-registered record lands there before d1.
- **tests ↔ security** — the scrub chain a capture passes before it is committed, and the bar on corpus content entering a Conductor artifact, are security-plan §Input Validation's; the tests side is the digest pin, the no-text-in-source arm and the population arm (test-plan §6 Scenario: Fingerprint-storm → Real-model interpretation leg). No test, harness line or evidence file reads the operator's capture folder.
- **tests ↔ obs** — the drive instants the report gives come from `std::time`-stamped artifacts: the journal's `journal_emitted_at` and the self-obs stream's `timestamp_ms` (test-plan §3 Log format ↔ obs-plan §3). The envelope, the `status` disk read and the JSONL shapes stay untouched, so test-plan §3 `run` ↔ obs-plan §3 still agree.
- **tests ↔ arch** — test-plan §3 `run` holds the real-model selector to no added port, env var or `CONDUCTOR_*` handle; a handle the harness or a test binary came to read would owe an architecture §Occupied Resources registration as well as the per-reader class above.
- **tests ↔ security (supply chain)** — the gate form is the bare `cargo audit` beside `cargo deny check`, the tool floors being security-plan §Dependency Security's (test-plan §9 Supply-chain audit form).
