# obs extract

## Relevance
partial — the chunk drives the existing real-model chain three times and grades committed captures; obs-plan requires that it add no instrumentation, and binds how the drives' envelopes, self-obs lines and Pulse-side log reads are recorded.

## Constraints
- obs-plan §1 Obs Scope Summary sets the tier at Minimal (0): self-observation is `tracing` JSON lines only, no OTel SDK, no metrics backend. The series adds no instrumentation depth; nothing in scope items 1-11 calls for a new signal.
- obs-plan §4 Span / Trace Coverage (Scenario: Headless deterministic scenario run — Real-model posture) requires that the `real-model-interpretation` scenario add NO critical path, span name or span attribute: it rides `scenario.run` → `timeline.execute` → `emit.batch` → `verify.readback*`, with `report.generate` and `db.insert_run` as run-scoped siblings correlated by `run_id`.
- obs-plan §4 Span / Trace Coverage (Scenario: Headless deterministic scenario run — Real-model posture) requires the interpretation to be graded at the harvest tier over the scrubbed capture, never through the envelope. The envelope of a drive carries `verdict` null, and a non-degraded read-back lands `ManualCheck`; `Identified` / `NotIdentified` is therefore not an envelope value and must not be read from one. The plan names the harvest tier as `conductor-run/tests/real_model_harvest.rs`; where the sixth series' child module sits relative to that file is research's question.
- obs-plan §4 Span / Trace Coverage (Scenario: Headless deterministic scenario run — Real-model posture) requires a posture mismatch to surface as a scenario-level `Blocked` with one `info` line on the allowlisted `message` field, never as a sixth gate precondition. A drive whose envelope reads `Blocked` is a typed value to record in the attempt ledger as read; whether the `--live real-model` arm at this HEAD evaluates the real-model gate for all three drives is research's question.
- obs-plan §6 Log Coverage (Required fields) requires every ENVELOPE record to carry the eleven keys, where required means the key is PRESENT, not that its value is non-null. Each drive's envelope is held to key presence, so a `verdict` null row is conformant.
- obs-plan §6 Log Coverage (Per-module log levels) requires that a per-target `RUST_LOG` directive always be paired with the global level, and that neither form be set for a run that also executes the test suite. The drive launch environment and the harvest test run must not inherit a `RUST_LOG` set for diagnosis.
- obs-plan §11 Obs Anti-Patterns (Logs) requires that no absolute host path or internal struct name reach logs, the run report or `runs.db`. The chunk mints a fresh home-rooted data dir and commits captures plus a ledger; the dir is to be named by its leaf in every committed artifact, and whether the ledger and capture text as written stay path-free is the implement's measurement, not an assumption.

## Patterns to follow
- The per-series observation record: obs-plan §4 Span / Trace Coverage (Scenario: Headless deterministic scenario run — Real-model posture) holds one dated sentence per prior series and per the capture run, each stating the Pulse sha, what Pulse's own log read for `model_identity` and `prompt_version`, the three envelopes' `state` / `verdict` / key count, and that the chunk added no span, log line or field, each "as measured at" that chunk's `evidence/attempt-ledger.md`. The sixth series' ledger should record the same readings per drive so the same sentence can be measured for it. The plan's record stops at the 2026-10-07 capture run; adding a sixth-series sentence is the wrap's reconcile, since the masters are read-only in phase and implement.
- Reading Pulse-side evidence from Pulse's own tracing lines at the harvest tier, each from its own exact field: obs-plan §4 Span / Trace Coverage (Scenario: Known-residual classification path — Delegated-timing family) and §4 (Scenario: Restart-suppression) record that Pulse's default-deny allowlist renders some fields as `"<redacted>"` live and that field names are not uniform across lines. Scope item 6 needs Pulse's `skip_reason` for every digest not surfaced; whether `skip_reason`, `model_identity` and `prompt_version` read unredacted at Pulse `9bfefb8` is research's question.
- The read-back shape witness as the first diagnostic for an empty read: obs-plan §6 Log Coverage (Boundary-call wrappers) requires the `verify.readback` call to log the observed key set of each raw tool result (names only, on the `message` field), because the readers degrade to empty on an unrecognized shape. Pulse's product code moved between `f70be92` and `9bfefb8`, so a drive that reads empty is first checked against that witness before it is read as an empty corpus.
- The capture's `canary:` line count is not the storm count: obs-plan §4 Span / Trace Coverage (Scenario: Headless deterministic scenario run — Real-model posture) records three storms per drive against two `canary:` lines in the capture. A ledger row or harvest assertion that counts canary activity reads it on that basis; whether the shape holds at `9bfefb8` is research's question.
- The self-obs sink under agent mode: obs-plan §3 Log file location and §3 Logging stack place the CLI's self-obs stream at `logs/agent-latest.jsonl` under agent mode, one writer at a time. Three sequential drives share that path; whether a later drive truncates or appends to it is research's question, and any per-drive self-obs reading the ledger cites is taken before the next drive starts.

## Anti-patterns to avoid
- Adding a span name, span attribute or allowlist entry to carry a series fact (drive ordinal, corpus row count, model identity, the grade): obs-plan §11 Obs Anti-Patterns (Spans / Traces) bounds the span-name set, and §4 Span / Trace Coverage (Scenario: Known-residual classification path) states that an attribute outside `conductor-core::redact::ALLOWLISTED_FIELDS` is dropped at the processor stage and emits nothing.
- Reporting the envelope's `latency_ms` as the model's generation or interpretation time: obs-plan §4 Span / Trace Coverage (Scenario: Known-residual classification path — Delegated-timing family) states that `latency_ms` is `read_back_observed_at - journal_emitted_at` over the scenario's whole emission window, not a Pulse-internal duration, and obs-plan §5 Metric Coverage defines it the same way.
- Treating the three named redaction sites as bounding every host-path channel: obs-plan §11 Obs Anti-Patterns (PII Scrubbing) keeps that warning standing. A new data dir leaf, a rebuilt binary's path and a binary-proof record are each a fresh channel into committed evidence.

## Contract bindings
- obs ↔ tests: the envelope's format is owned by test-plan §3, and obs-plan §3 Log format JSON schema states that `conductor-run`'s `journal_conformance` asserts key presence, closed sets and host-path freedom, never key exclusivity. Each drive's `runs/<run_id>.jsonl` falls under that gate when the gate is pointed at its runs dir.
- obs ↔ tests: obs-plan §3 Log format JSON schema's reproduced block lists three `verdict` values and no null arm, while obs-plan §4 (Real-model posture) requires `verdict` null for this scenario and obs-plan §6 Log Coverage (Required fields) resolves it as key presence. The chunk does not settle that wording; it is flagged so a drive's null `verdict` is not read as a schema breach.
- obs ↔ security: obs-plan §11 Obs Anti-Patterns (PII Scrubbing) places redaction ownership in `conductor-core::redact` for Conductor-generated artifacts. The capture's own scrub chain (`mask_workspace_key` + `redact_value` + `mask_host_paths` + `elide_fingerprints`) is security-plan's; obs adds only that the self-obs stream and the envelope stay path-free alongside it.
- obs ↔ a11y: (none)
