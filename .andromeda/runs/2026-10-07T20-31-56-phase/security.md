## Patterns to follow
- Digest-pin-then-grade: each committed capture is held by a sha256 pin over its LF-normalized content and graded from the file only after the digest matches, with no capture text in test source (per security-plan §Input Validation, real-model capture ingest row; §Security Anti-Patterns → Data Protection).
- Fields-only reading of Pulse's own log: `skip_reason`, `decision`, `severity`, `digest_kind` and the corpus-retrieval row count are closed-enum or integer fields; the ledger's per-digest `skip_reason` rows stay in that shape (per security-plan §Input Validation, real-model capture ingest row).
- The sidecar is selected by `PATH` alone: the fixed program name resolves through the inherited `PATH`, so the rebuilt `andromeda-pulse-mcp` reaches the leg by which directory `PATH` names, and Conductor's own resolution returns a boolean-grade fact, never the resolved path. The sidecar's binary proof is therefore established outside Conductor's code, on the binary `PATH` resolves (per security-plan §Security Anti-Patterns → Input; §Security Anti-Patterns → Code Patterns, rule (a)).
- The secret-scan gate reads git's cached plus untracked-not-ignored listing, so the new captures, the ledger and the contract section fall under it as soon as they exist; it runs inside the workspace nextest (per security-plan §Secret Management → Secret-scan gate shape).
- The supply-chain reading order: the advisory-db checkout's porcelain is read before `cargo audit` is trusted, and `cargo deny check advisories bans licenses sources` is verified, not assumed (per security-plan §Dependency Security).

## Anti-patterns to avoid
- NEVER open, copy or stage a row into Pulse's `corpus.db`, in the new data dir or the three earlier ones, to shape what a drive retrieves — the corpus is reached through the MCP tool surface only, and staging a row to induce a SUT state is the banned route (per security-plan §Security Anti-Patterns → Data Protection).
- NEVER point the leg at a rebuilt sidecar through an operator-chosen command string, a config value or an argv element, and NEVER interpolate the data dir into argv or a shell — fixed name, inherited `PATH`, `.env(...)` only (per security-plan §Security Anti-Patterns → Input).
- NEVER read a preflight outcome as something else: an unmet precondition is a refusal that mints no verdict, and an invoked gate's failure is its own named `Blocked` precondition — neither is downgraded, and a `PATH` miss looks at row level like a SUT-side gate failure in ~0 s (per security-plan §Security Anti-Patterns → Universal; §Security Anti-Patterns → Input).
