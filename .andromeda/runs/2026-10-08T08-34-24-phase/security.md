partial — the chunk changes what one operator-gated TEST-binary ingest (the real-model capture's canary pairing) reads from untrusted SUT log lines and adds default-suite tests plus one dated contract note; it adds no boundary, handle, spawn, dependency or shipped-crate surface, so the security plan binds it through the capture-ingest row, the capture-text placement ban and the standing gates only.

## Constraints
- The canary pairing is part of the real-model capture ingest, which security-plan §Input Validation (real-model capture ingest row) classes as untrusted SUT output: it requires every printed line to pass `mask_workspace_key` FIRST, then `redact_value`, then `mask_host_paths`, then `elide_fingerprints`, with the output buffered and written ONCE. A `canary:` line that prints a different outcome after this change must still leave through that chain; whether the code routes the `canary:` lines through it today, and whether the widened pairing keeps them on it, is research's question.
- security-plan §Input Validation (real-model capture ingest row) requires Pulse's witnesses to be read fields-only, with what a `canary:` line carries drawn from closed enums Pulse's code writes (the row names the inference's `skip_reason` as its trailing field). The pairing reading lines stamped AFTER the emission instant widens which untrusted lines are consulted, never what may be printed from them: no free-text Pulse field, raw Pulse line, path, workspace key or fingerprint value may reach a `canary:` line. Which fields the pairing reads from the post-instant lines is research's question.
- security-plan §Security Anti-Patterns → Data Protection requires that no committed capture text sits in test source: every committed capture is held by a sha256 digest pin and graded from its file, and the harvest's `no_committed_capture_text_sits_in_test_source` arm holds the ban. The d1/d2/d3 fixtures and the failing-first control are therefore built from stamps and line SHAPES, never by copying lines out of a committed `rm-capture-d*.txt`. What that arm matches on (and so whether an expected `canary:` line written as a literal in a new test would trip it) is research's question.
- security-plan §Security Anti-Patterns → Data Protection scopes the one ratified exception to corpus-rendered model text inside a chunk's committed `evidence/` tree, through the four-function scrub; "anywhere else the ban binds unchanged". The new tests, any fixture file, this chunk's own `evidence/` and the dated note in `contracts/pulse-real-model-leg-posture.md` must carry no report-body or model text.
- security-plan §Input Validation (real-model capture ingest row) requires the harvest to walk every committed `rm-capture*.txt` under `conductor-0.3.0/chunks/*/evidence/`, its population pinned by count beside an inverse control, each file at a fixed point of the elision under its digest pin. A fixture this chunk commits must not enter that population (name or location) and no existing pin may move; whether a fixture placed in this chunk's `evidence/` would be walked is research's question.
- security-plan §Input Validation (env-var path handles row) binds the canonicalize/`resolve_under` duty per READER and records the capture's two handle reads as going through the shared `conductor-run/tests/capture_paths` module. If the tick selection moves into the shared module so a default-suite test can reach it, the moved code must take already-read lines as input and add no new reader of `CONDUCTOR_RUNS_DIR` or `ANDROMEDA_PULSE_DATA_DIR`; a new reader would need its own guarded resolution and its own record.
- security-plan §Security Anti-Patterns → Universal requires `cargo-audit` (and `cargo-deny`) green and `Cargo.lock` committed and un-drifted before any merge; security-plan §Dependency Security requires both gates because they overlap deliberately. The scope declares no dependency change, so the lock is expected unmoved; a new test target that needs a dev-dependency edge would move it and is named at review.

## Patterns to follow
- Untrusted SUT text is graded from fields, never echoed: the shape security-plan §Input Validation (real-model capture ingest row) records for the capture (fields-only witnesses, class-only rendering lines, closed-enum trailing fields) and (span-landing witness ingest row) for the witness that prints one integers-only line.
- Committed captures are read by a hard-coded path anchored from `CARGO_MANIFEST_DIR` with no `CONDUCTOR_*` handle and graded only after the digest matches — per security-plan §Input Validation (real-model capture ingest row). A test that needs a recorded shape follows the same no-handle resolution or builds the shape in memory.
- Path-free failure texts: every rejection and read failure names a fixed reason or an `io::ErrorKind`, never a resolved path — per security-plan §Input Validation (env-var path handles row). A new test's assertion and panic messages follow it.
- A boundary correction is recorded as a dated, add-only statement beside the dated history it supersedes, never as a rewrite of that history — the form security-plan §Security Anti-Patterns → Code Patterns uses for its own superseded readings; the contract's second dated note follows it.

## Anti-patterns to avoid
- NEVER place committed capture text (a report body, or a line copied byte-equal from a committed capture) in test source or anywhere outside a chunk's `evidence/` tree — security-plan §Security Anti-Patterns → Data Protection (the 2026-09-29 breach, remedied and never ratified).
- NEVER let committed evidence records or test fixtures leak absolute host paths (the canonicalized `CONDUCTOR_*` directories, `ANDROMEDA_PULSE_DATA_DIR`) or internal seam-crate struct names — security-plan §Security Anti-Patterns → Logging. A fixture line modelled on Pulse's log carries synthetic values in those positions, and no workspace key.
- NEVER let a test-binary reader join a `CONDUCTOR_*` handle or the Pulse data-dir handle unguarded — security-plan §Security Anti-Patterns → Input (the duty binds by READER, not by handle).
