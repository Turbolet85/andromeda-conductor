# design extract

## Relevance
partial — the chunk renders nothing and adds no surface; it removes the whole `desktop-webview` surface the plan specifies, and the plan's `cli` surface is what must stand unchanged once it is gone.

## Constraints
- The `cli` surface is the surviving design surface: design-system §Surface: cli requires its toolkit, line-oriented form and navigation to hold as specified; the removal may not alter any of it. Whether the code's cli output depends on anything inside the removed crate is research's question.
- design-system §Surface: cli §Tokens requires the ANSI status mapping, the per-stream TTY gate and the closed bracket-prefix set on cli output; the removal must leave each of them in place. That section also names a recessive pair the webview binds by custom-property name beside the cli's ANSI code: only the webview half leaves, the cli half stays.
- design-system §Color Palette requires every `Verdict` / `ReportState` to keep its distinct, non-collapsing treatment (the three report-only states never read as `Fail`); this binds the cli lines and the Markdown report after the removal exactly as before.
- design-system §Brand Identity names the signature element and gives it a cli mirror; design-system §Surface: cli §Component Patterns (pattern 1) requires that mirror (the count stops in place at the hold, never hides). With the titlebar placement gone, the cli mirror is the signature's only placement and must not leave with the window.
- design-system §Typography (Loading and Surface-conditional guidance) scopes the self-hosted font packages to the webview and requires the cli to set no face of its own; the vendored fonts therefore leave with the frontend. Whether any file outside the removed tree references those packages is research's question.
- design-system §Surface: desktop-webview §Tokens makes the `:root` custom-property bundle the binding contract of the webview surface alone; it leaves with the frontend stylesheet. Whether a file outside the removed tree binds one of those names is research's question.
- design-system §Spacing and design-system §Border Radius each carry a surface-conditional line limiting their tokens to `desktop-webview` and leaving cli placement terminal-controlled; the removal creates no spacing or radius obligation on the cli.

## Patterns to follow
- Counterpart map for the reachability reading (scope B4): design-system §Surface: desktop-webview §Component Patterns (patterns 2, 5, 6, 7 — operator-pause dialog, picker + start/stop, run-report view, operator-checklist) against design-system §Surface: cli §Component Patterns (patterns 2, 3, 4 — operator-pause prompt, results table, verdict / report-state lines including the manual-check item). The plan specifies a cli form for each; whether the code ships each one is research's question.
- design-system §Surface: cli §Component Patterns (pattern 2) requires the headless path to skip the operator-pause prompt under the non-interactive policy and record the decision; any function the window alone carried and this chunk re-homes follows that shape.
- design-system §Surface: cli §Component Patterns (pattern 5) fixes the stderr error form (labels, the two reused tints, sanitized content); a removed command's error path, if one is replaced, follows it and adds no color.
- design-system §Surface: cli §Navigation Pattern requires linear top-to-bottom output with no cursor manipulation; nothing that replaces a window affordance may depart from it.

## Anti-patterns to avoid
- No substitute interactive surface: design-system §Surface: cli records the full-screen TUI as deliberately omitted, so the window's retirement is not answered with one (also scope B5).
- design-system §Anti-Patterns §Per-Surface Bans (cli) bans color-alone status, emoji in piped output, an un-gated interactive prompt and a blocked headless path; a removal that drops a cli-side helper shared with the window must not open any of these.
- design-system §Anti-Patterns §Universal Bans forbids a styled credential surface on either surface; unchanged by the removal, and nothing re-homed to the cli may introduce one.

## Contract bindings
- design ↔ a11y: design-system §Depth Strategy (the focus ring asserted by the routine a11y arm) and design-system §Motion (the reduced-motion drop, bound to SC 2.3.3) are webview-only bindings whose asserting arms leave with this chunk; the not-color-alone binding (SC 1.4.1) in design-system §Surface: cli §Platform-Specific Notes survives and stays testable on cli output.
- design ↔ security: design-system §Surface: desktop-webview §Platform-Specific Notes carries the Tauri guardrails (capabilities file, no remote-origin iframes, version floor) by reference to the security plan; they leave with the crate. design-system §Typography (Loading) ties the font vendoring to the frontend dependency tree the scope's item 1 removes.
- design ↔ tests: design-system §Surface: desktop-webview §Component Patterns cites screen-reader rows and dated measurements as evidence for shipped strings; the suites that produced them leave here, so those citations become history, not live checks.
- design ↔ layouts: design-system §Surface: cli §Component Patterns (pattern 3) points at the cli primary screens for the coverage table's roll-up; per-screen layout is the layouts extract's.
- design ↔ wrap (scope B6): phase edits no spec source. The plan sections that describe only the retired surface — design-system §Surface: desktop-webview, the desktop half of design-system §Brand Identity's per-surface expression and signature placement, design-system §Typography's webview table and Loading, design-system §Spacing, §Depth Strategy, §Border Radius, §Iconography, the motion tokens in design-system §Motion, and design-system §Anti-Patterns §Per-Surface Bans (desktop-webview) — are expected amendments for the wrap; the full console restating belongs to a later route entry.

## Acceptance criteria contributions
- (design) After the removal, every cli status line still pairs its state with the ASCII bracket prefix, and piped output carries no ANSI — read from a run's captured output, not argued (per design-system §Surface: cli §Tokens)
- (design) The cli hold-point mirror is intact: the count stops in place at an operator-pause and the hold phase line prints above the prompt; whether an existing test already holds this is research's question (per design-system §Surface: cli §Component Patterns)
- (design) No file outside the removed tree references a webview custom property or a vendored font package; each remaining hit is named with its consumer and the entry that removes it (per design-system §Surface: desktop-webview §Tokens)
- (design) The chunk introduces no replacement interactive surface and no new color: the cli's token set after the removal equals the one the plan lists (per design-system §Surface: cli)
