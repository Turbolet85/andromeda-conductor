# layouts extract

## Relevance
partial — the chunk builds and modifies no surface element; it retires the whole `desktop-webview` surface (every region: titlebar, control row, coverage matrix, run-report card, go/no-go dialog, footer strip) and touches the `cli` surface only at the `scripts/agent-run.{sh,ps1}` stage flags, so the layouts domain contributes hold-the-cli-shape constraints and a surface-to-verb mapping, no wireframe or focus-order work.

## Constraints
- layout-templates §Surface: desktop-webview is the plan's TARGET description of the surface this chunk removes; nothing in it mandates work here, and the chunk must build or re-site nothing inside it. The plan still describing that surface after the removal is the wrap's amendment subject (scope B6), not a phase edit (per layout-templates §Surface: desktop-webview).
- The headless harness is required to stay a 5-command shape (`boot`/`run`/`status`/`cleanup`/`logs`) whose `run` takes stage flags as siblings, never a sixth command; the plan defines `--e2e` as the cross-surface stage that builds the Tauri bundle and drives the webview. Removing that arm must leave the five commands, `--unit`/`--integration`, the bundled default and `--live` with its `real-model` selector at the semantics the plan states. Which lines of the two scripts carry the webview arm is research's question (per layout-templates §Surface: cli › Primary screens (commands)).
- Both shells are required to ship at identical semantics; the webview arms must leave `agent-run.sh` and `agent-run.ps1` symmetrically, so the twin (scope B2) is not left diverged (per layout-templates §Surface: cli › Primary screens (commands)).
- The plan's refusal-versus-skip contrast names two host-tool handles (`CONDUCTOR_MSEDGEDRIVER`, `CONDUCTOR_NVDA`) and a strict arm (`CONDUCTOR_A11Y_STRICT`) as the SKIP class beside the live-Pulse REFUSAL class. Whether any non-window leg still reads those handles is research's question; if none does, the skip class empties and the live-Pulse refusal behaviour must stand unchanged (per layout-templates §Surface: cli › Primary screens (commands)).
- cli output structure is required to be stable across versions because downstream agents parse it; the removal must not change the stdout shape of any verb, and no column, flag or format may be added to compensate for the lost surface (per layout-templates §Surface: cli › IA notes).
- The run-level qualifier set and the coverage roll-up are specified as one shape "adapted per surface, never forked" across Markdown, cli and webview. Dropping the webview leg must leave the cli and Markdown legs byte-shape identical; the lamp set stays closed at six (per layout-templates §Surface: cli › Component — Primary content block 2 (verdict / report-state lines)).
- The coverage roll-up's `(N unbacked)` term is required to be sourced from `conductor_core::UNBACKED_AUTO` and never mirrored; the plan routes the webview's copy through an `unbacked_auto` command. Whether that command lives only in the window crate, and whether the cli and Markdown renders reach the constant without it, is research's question (per layout-templates §Surface: cli › Primary screens (commands)).

## Patterns to follow
- The cli verb set is "whichever `Commands` declares", never a baked sample; the surface-to-verb reading scope B4 asks for is taken from that declaration, with the plan's enumeration as the expected target (per layout-templates §Surface: cli › Component — Primary navigation (verb structure)).
- The window's operator path is a run-state sequence, not pages: pick scenario/suite, Start, Stop, answer the go/no-go hold (proceed/abort, checklist rows), read the run report, read the coverage matrix. That sequence is the function list B4 maps (per layout-templates §Surface: desktop-webview › Component — Primary navigation (single-station run control)).
- The plan's cli counterparts for that sequence are `run`, `suite`, `report <run_id>`, `coverage`, plus the TTY-gated `inquire` confirm for the hold; it enumerates no cli verb for listing scenarios and none for stopping a live run. Whether `Commands` declares either is research's question (per layout-templates §Surface: cli › Primary screens (commands)).
- An unknown `run` selector is specified to print a usage line and exit 2 before any probe, in both shells; a stage flag that no longer exists should fall under the scripts' existing usage handling, not a new message form (per layout-templates §Surface: cli › Primary screens (commands)).
- Human messages go to stderr as `error: <short>` + `hint: <fix>`, host-path-free; stdout stays raw artifact data (per layout-templates §Surface: cli › Component — Footer / terminator + error output).

## Anti-patterns to avoid
- Never replace the retired window with another interactive surface: the cli is line-oriented with the full-TUI option deliberately omitted, no cursor manipulation, no full-screen redraw (per layout-templates §Surface: cli).
- Never gate the agent-driven path on a prompt while re-homing a window function; an `inquire` prompt always checks `isatty` first (per layout-templates §Surface: cli › IA notes).
- Never add a `comfy-table` column, a bracket label or a seventh lamp to carry something the window showed; the results table is exactly six columns and the coverage table exactly four (per layout-templates §Surface: cli › Component — Primary content block 1 (results / SLO table)).
