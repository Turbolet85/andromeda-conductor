## Constraints
- No panel layout survives to preserve or mirror: the picker, dialog rows and run panel have no surface in the plan, which points only at `321dc8f` for them (per layout-templates §Surface: desktop-webview). So the plan gives no layout reason to keep `ScenarioSummary`'s shape, the dialog-row framing of `MAX_CHECKLIST_TEXT`, or the `RunEvent` payload. Any bound that stays rests on another domain's reason.
- A new catalogue-listing verb must be flat verb-noun and one level deep. The verb set is whatever `Commands` in `crates/conductor-cli/src/cli.rs` declares. Help is verb-prefixed: `conductor --help` shows the verb table and `conductor <verb> --help` shows that verb's flags. No man page or wiki link (per layout-templates §Component — Primary navigation (verb structure)).
- Every verb's output is enumerated under the plan's primary-screens list, and each entry names its shape. A new verb or flag therefore needs an entry there, with any table's column count and caption (per layout-templates §Primary screens (commands)). That entry is written by the wrap's amendments, not by a phase edit.
- Output structure must stay stable across versions because downstream agents parse it. Adding a `comfy-table` column without a `--format` flag is a breaking change (per layout-templates §IA notes). So a past run's load-envelope standing on `report` must not add a column to the 6-column results/SLO table.
- `[ENVIRONMENT-SUSPECT]` is a run-level qualifier, not a lamp. It prints ONCE per run, above the verdict lines it qualifies, in ANSI 246, outside the lamp column. It names the breaching emitting phase and which sustained term was left, and it is omitted entirely when the run is in-envelope or pinned exempt (per layout-templates §Output structure — `conductor run <scenario>`). Research must answer whether `conductor report <run_id>` already renders this qualifier from the journal; today the plan describes `report` as printing the results view only (per layout-templates §Primary screens (commands)).
- The headless path must never block on a prompt. Every `inquire` prompt checks `isatty` first (per layout-templates §IA notes). On the operator-pause, the `HOLD — operator pause` line prints above the confirm and carries the frozen count as text (per layout-templates §Component — Hero / signature output). Any `[[checklist]]` items printed at the CLI hold must keep both properties.
- Pipe discipline: raw artifact data goes on stdout and human messages on stderr. ANSI is auto-stripped when piped, `NO_COLOR` / `TERM=dumb` are honored, and piped output uses ASCII prefixes only, never emoji (per layout-templates §IA notes). Errors from a stopped or refused run go to stderr as `error: <short>` + detail + `hint: <fix>`, sanitized per the security plan (per layout-templates §Component — Footer / terminator + error output).

## Patterns to follow
- The indented-detail-line precedent: the `Blocked` precondition string, the `KnownResidual` note, the `[MANUAL]` row's indented `observe:` items and the per-check detail region. Each adds one indented plain-text line under its parent line, with no new column, no new bracket label and no new ANSI or token entry (per layout-templates §Component — Primary content block 2 (verdict / report-state lines)). This is the natural form for hold checklist items and for an envelope-standing detail.
- The `conductor cleanup` verb-addition precedent: a late-added verb that prints a plain line with the run id in the ID-cyan mapping. It mints no bracket label, lamp, `ReportState`, token or ANSI entry, and it never prompts (per layout-templates §Primary screens (commands)).
- The `conductor coverage` listing precedent: a static, manifest-derived `comfy-table` with its own column count and a plain roll-up caption. Its numbers are derived and never literals, and it is kept distinct from the 6-column results/SLO shape (per layout-templates §Component — Primary content block 1 (results / SLO table)). A catalogue listing is a third table shape and must be named as such, not conflated with either existing table.
- The run-level non-lamp qualifier SET (`[ENVIRONMENT-SUSPECT]`, `[PRECONDITION]`) is adapted per surface, never forked, and printed outside the lamp column (per layout-templates §Component — Primary content block 2 (verdict / report-state lines)). A past run's envelope standing reuses this set; it does not invent a label.
- The terminator is a single closing line, `run report → runs/<run_id>.md`, in the dimmed mapping (ANSI 146), with the path left uncolored when piped (per layout-templates §Component — Footer / terminator + error output). The plan does not specify whether a gracefully stopped run that keeps what finished ends in this terminator; that is for P4 to decide.

## Anti-patterns to avoid
- Minting a seventh lamp, a new bracket label, or a new ANSI/token entry for any of items 8-11. The lamp set is closed at six, and a qualifier is neither a lamp nor a `ReportState` (per layout-templates §Component — Primary content block 2 (verdict / report-state lines)).
- Putting an interactive gate on the agent-driven path, for example a checklist confirm or a stop confirmation that does not check `isatty`. It would silently break the release gate (per layout-templates §IA notes).
- Cursor manipulation, full-screen redraw, or a live-redrawn dashboard for a stop or listing view. The cli is line-oriented and ratatui is deliberately omitted (per layout-templates §Component — Primary navigation (verb structure)).

## Contract bindings
- layouts ↔ design-system: any styling on new output binds the palette by token name (`count-nominal` → 114, `count-hold` → 179, `status-fail` → 203, `count-blocked` → 60, `color-id-cyan` → 117, journal-text → 146). It never uses a bare new code (per layout-templates §IA notes).
- layouts ↔ test-plan §3: `scripts/agent-run.{sh,ps1}` is the 5-command harness at identical semantics in both shells. A new cli verb or flag is not a sixth harness command, and `--live` selectors are not new stage flags (per layout-templates §Primary screens (commands)).
- layouts ↔ a11y: every status pairs its color with an ASCII prefix, so it survives `NO_COLOR`, piping and screen readers. a11y / NO_COLOR compliance derives from this (per layout-templates §Surface: cli).
- layouts ↔ security-plan: error output on stderr is sanitized, with no absolute host paths, internal struct names or stack traces (per layout-templates §Component — Footer / terminator + error output).
