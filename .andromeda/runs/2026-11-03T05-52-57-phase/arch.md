## Patterns to follow
- A gate is the Rust test, and its CI step is only a presence-guarded invocation of that test target (per architecture §Established Decisions [CI/CD]). A step restated for Linux keeps that shape.
- The keyed directory layout already lists `scripts/agent-run.sh` alone as the headless entrypoint. Removing the twin moves the tree toward that layout (per architecture §Infrastructure Patterns → Directory structure (crate-per-seam Cargo workspace)).
- A crate-local committed fixture is read by its test binary, which resolves the workspace root from `CARGO_MANIFEST_DIR` with no `CONDUCTOR_*` override and no shipped reader. This is the precedent for carry 7's fixture folder inside `crates/conductor-run` (per architecture §Occupied Resources, the `contracts/scenario-audit-ledger.toml` entry).
- The harness clears files with a non-recursive `rm -f` by name and ships no recursive delete (per architecture §Occupied Resources, the `runs/live-suite/{leg}.jsonl` entry). This fits the scope's ruling that deletions are the founder's own hand step.

## Anti-patterns to avoid
- Restating a gate's assertion in shell inside `ci.yml` while porting a step to Linux. That creates a second copy that drifts (per architecture §Established Decisions [CI/CD]).
- Weakening a gate during the move: `continue-on-error`, `if:`, a dropped presence guard, or retries that mask flakes, which breaks the determinism invariant (per architecture §Infrastructure Patterns → Build system).
- Editing the masters (`.andromeda/architecture.md`, its contracts) from the phase. The Windows-named text in §Occupied Resources, §Cross-cutting Patterns, §Standard Contracts (Timestamp formats) and §Infrastructure Patterns → Build system is changed only through the wrap's amendments (per architecture §Occupied Resources (Service / process names)).
