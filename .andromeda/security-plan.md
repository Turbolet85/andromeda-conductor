## Threat Model Summary

_[ALL tiers — VERBATIM copy from threat-assessment.md]_

**Security tier:** `Minimal (0)`
_Justification: Every signal points to a minimal-tier local utility — a single-developer, local-only, no-cloud, no-multi-tenancy tool with no user accounts (auth "none"), where the only persisted data is self-generated synthetic test telemetry and run-metadata in an embedded SQLite index (`runs.db`) plus on-disk JSONL/Markdown artifacts (no PII/payment/health/credentials owned by Conductor), and there is zero network exposure — Conductor is a loopback gRPC/MCP client with no inbound listener of its own. With no compliance triggers, the residual risk classes that remain are exactly those Minimal tier covers: dependency/supply-chain audit (notably `bundled` SQLite compiled from C source and the OTLP/gRPC/MCP dependency tree), input validation on operator-supplied scenario config and `CONDUCTOR_*` env-var path overrides, and error sanitization at the `anyhow` binary edges and in run-report artifacts._

**Data classification:**

- **Type:** config — declarative scenario config (serde + garde, no DSL)
  - **Where:** `scenarios/` directory, deserialized into the owning seam crates; `contracts/` pinned MCP contract manifest (Conventions: Config conventions; Occupied Resources: On-disk artifacts)
  - **Volume:** aggregate (one config file per Pulse P-ID, over the SUT capability manifest's accepted set), transient at load

- **Type:** test-telemetry / run-metadata (synthetic, not user data) — emission journals, run reports, and the `runs.db` index (run_id · seed · scenario · P-IDs · verdict · fingerprints · timestamps)
  - **Where:** `runs/` directory (per-run `<run_id>.jsonl` journal + `<run_id>.md` report) and embedded SQLite `runs.db` (Occupied Resources: On-disk artifacts; Established Decisions: Run-History Persistence)
  - **Volume:** aggregate, persisted on disk (append-mostly); content is self-generated synthetic OTLP fault data (spans/metrics/logs Conductor emits), not user-derived

- **Type:** credential — **none owned by Conductor.** A keychain reference appears (`OsKeychainBackend("com.andromeda.pulse")`, Standard Contracts readiness gate), but it belongs to Pulse (the system under test): the sidecar opens Pulse's `corpus.db` (plaintext SQLite — the P-049 encrypted-at-rest assumption proved wrong when verified live 2026-06-27; the `OsKeychainBackend` reference is Pulse-side and not exercised for corpus access) as the *same OS user*. Conductor does not store, generate, or manage any secret; the architecture states explicitly "No secrets, no `DATABASE_URL`, no cloud credentials" (Cross-cutting Patterns: Trust boundary; Occupied Resources: Environment variables — "no secrets/cloud env vars (local-only tool)")
  - **Where:** N/A for Conductor (OS keychain access is Pulse-side, exercised via the spawned sidecar's canary)
  - **Volume:** N/A

- **Type:** PII — **none.** Project Intent: "Personal — solo developer, local dev host, no cloud, no multi-tenancy." No user accounts, no user-supplied content. The only identities are synthetic incident/fingerprint data Conductor itself emits.
- **Type:** payment — **none.** Stack lists no payment/billing SDK (no Stripe etc.); Project Intent describes no transactions.
- **Type:** health — **none.** No medical data in Stack or Intent.

Note: `corpus.db` (Pulse's incident corpus — **plaintext SQLite**, NOT encrypted-at-rest; the P-049 encryption assumption proved wrong live 2026-06-27) is **out of scope** — owned by Pulse (the SUT); Conductor only reads it via MCP read-back to prove wiring and never persists/exfiltrates it (Standard Contracts readiness gate).

**Attack surface:**

- **Vector:** CLI input — seed/scenario flags and env-var overrides on the `agent-run` / `conductor-cli` path
  - **Entry point:** `conductor-cli` binary args + `CONDUCTOR_*` env namespace (`CONDUCTOR_RUNS_DIR`, `CONDUCTOR_SCENARIOS_DIR`, `CONDUCTOR_CONTRACT_MANIFEST`, `CONDUCTOR_SEED`) (Occupied Resources: Environment variables; Cross-cutting Patterns: Config management)
  - **Trust boundary:** operator-supplied on the local host; CLI flag precedence over env; no untrusted/remote source

- **Vector:** config files (local file parsing) — scenario config + pinned MCP contract manifest read from disk
  - **Entry point:** `scenarios/` (serde deserialize) and `contracts/` manifest; `anyhow` at the CLI edge, `ConfigError` harness-fault class via garde `#[from]`
  - **Trust boundary:** garde validation at load (`range` rules: error fraction ∈ [0,1], non-negative durations, sane ramp factors; `#[garde(custom)]` cross-field: p50≤p95≤p99, severity-mix sums) (Conventions: Config conventions, Error handling). Source is operator-authored local files, not external input.

- **Vector:** Tauri IPC — internal in-app commands (`#[tauri::command]` start/stop/picker/run-report/operator-pause) + one `Channel` for live counters
  - **Entry point:** Tauri 2 webview→backend IPC, bundled webview (no frontend dev-server port) (Standard Contracts: Live update channel; Occupied Resources: Interface routes)
  - **Trust boundary:** in-process app boundary (backend↔bundled webview); not network-exposed. REST/GraphQL/tRPC are N/A.

- **Vector:** MCP read-back child-process stdout — Conductor spawns the Pulse MCP server (`andromeda-pulse-mcp`) via `TokioChildProcess` (stdio) and **trusts that child's stdout as the read-back source**
  - **Entry point:** hand-rolled line-delimited JSON-RPC client over stdio (rmcp removed 2026-06-27); version-pinned contract manifest + `initialize` preflight gate (Conventions: Inbound verification; Cross-cutting Patterns: Trust boundary)
  - **Trust boundary:** preflight readiness gate — negotiated protocol pinned at `2024-11-05`, required-tool presence vs. manifest, data-dir canary round-trip; mismatch/empty ⇒ **blocked** state. The child is a locally-spawned, co-located process under the same OS user (not a remote/untrusted peer); `tonic::Status` codes and MCP error responses are first-class typed verification inputs, not panics.

- **Vector:** OTLP/gRPC egress — outbound only to `127.0.0.1:4317` (Pulse's loopback ingest)
  - **Entry point:** tonic client; Conductor is the client, port owned by Pulse (Occupied Resources: Ports; Conventions: Outbound emission)
  - **Trust boundary:** loopback-only egress; a refused transport surfaces as `Result::Err` (harness fault), not a verdict

- **Vector (single deliberate exception):** port bind `:4317` — the port-occupier fault scenario intentionally binds `:4317` to exercise Pulse's reaction
  - **Entry point:** `conductor-faults` seam (Cross-cutting Patterns: Trust boundary; Occupied Resources: Ports)
  - **Trust boundary:** loopback only; the *sole* case where Conductor opens a port, and it is an intentional in-host fault, not a network listener accepting external input

- **Vector:** public API / file upload / OAuth / WebSocket / UGC / webhook — **none.** No web framework (Stack: "Backend Framework: None"), no HTTP surface (`:4318` unused, no `/health` or `/ready` HTTP endpoints), no SSE/WebSocket/polling, local-only deployment (Infrastructure Patterns: Deployment model — "No Docker/Compose/Kubernetes/serverless… execution is necessarily co-located on the dev host"). No external/internet exposure exists.

**Auth model:**
- **Approach:** none
- **Provider:** N/A
- **Scope:** N/A

**Reason:** Project Intent records "Personal — solo developer, local dev host, no cloud, no multi-tenancy" with no user accounts and no API consumers. Conductor exposes no network service (Stack: "Backend Framework: None"; Occupied Resources: "No inbound listener of Conductor's own"), so there is no authenticated surface to protect. Development Style is **agent-driven** — the headless `scripts/agent-run.sh` path is the source of truth and release gate (Cross-cutting Patterns: Development Style), which implies no interactive login UX. The only env flag is `ANDROMEDA_PULSE_MCP_ENABLED`, which Conductor explicitly asserts it does **not** set itself (it is a Pulse-side operator gate). Defaulting to JWT/session/OAuth here would contradict the single-user local model.

**Infrastructure:**
- **Hosting:** local-only — `cargo build --release` produces the `conductor-cli` binary run beside Pulse via `scripts/agent-run.sh`; optional Tauri 2 (v2.10.x) ~3 MB GUI bundle. Explicitly "No Docker/Compose/Kubernetes/serverless" (Infrastructure Patterns: Deployment model; Established Decisions: Deployment)
- **Database:** embedded — rusqlite 0.38.0 with `bundled` SQLite 3.50.4 (JSON1, via libsqlite3-sys 0.36.0), synchronous raw SQL, in-process `runs.db`; no DB port, no `DATABASE_URL` (Stack: Database; Occupied Resources: Ports + Environment variables)
- **Networking:** local only — egress is loopback OTLP/gRPC to `127.0.0.1:4317` (`:4318` unused) and a stdio child-process MCP session; no inbound listener, no public/VPN networking. Co-location is forced because Pulse binds loopback `:4317` (Cross-cutting Patterns: Trust boundary; Infrastructure Patterns: Deployment model)
- **CI/CD:** GitHub Actions on the dev OS target — `cargo build` / cargo-nextest (incl. golden tests) / `cargo clippy`, build + test gating only. Dynamic end-to-end scenario proof requires a live Pulse and is an explicit operator/local gate, not a CI gate (Infrastructure Patterns: CI/CD approach; Established Decisions: CI/CD)

**Compliance triggers:**
None — no compliance-regulated data detected. No payment data → no PCI DSS; no EU personal data / no user accounts → no GDPR; no health/medical data → no HIPAA; no children's data → no COPPA. The only persisted data is self-generated synthetic test telemetry and run metadata (`runs.db`, JSONL journals); Pulse's `corpus.db` (plaintext SQLite, P-049 encryption not active live) is out of scope and owned by the SUT.

## Input Validation

_[ALL tiers]_

**Boundary:** validate at ALL system boundaries — wherever untrusted data
enters the system. For Conductor every boundary is operator-supplied on the
local host (CLI args, env-var path handles, on-disk config, trusted-child
stdout); the controls below are the trust boundaries the architecture already
names (Conventions: Config conventions, Inbound verification; Cross-cutting
Patterns: Trust boundary).

| Boundary | What to validate | How (stack-specific) |
|----------|-----------------|---------------------|
| Scenario config files (`scenarios/`, serde deserialize) | error fraction ∈ [0,1]; non-negative durations; sane ramp factors; cross-field p50≤p95≤p99; severity-mix sums | garde 0.22.1 `#[derive(Validate)]` `range` rules + `#[garde(custom)]` cross-field, co-located with the serde structs in their owning seam crate; failed `Report` → `ConfigError` via `#[from]` (harness fault, not a verdict) |
| Pinned MCP contract manifest (`contracts/`) | expected protocol version `2024-11-05`; required-tool name set (`query_incident_list` · `retrieve_report` · `retrieve_telemetry_slice` · `mark_incident_resolved`) | serde deserialize of the manifest; assert against the `initialize` result's `protocolVersion` in the preflight gate (`conductor-verify`) — mismatch ⇒ `blocked`, never silent downgrade |
| Env-var path handles (`CONDUCTOR_RUNS_DIR` / `CONDUCTOR_SCENARIOS_DIR` / `CONDUCTOR_CONTRACT_MANIFEST`) | path exists / is a directory or file as expected; **canonicalize** and bounds-check at the CLI edge (these sit OUTSIDE garde's struct validation per security-research.md serde+garde finding) | `std::fs::canonicalize` + explicit type/existence check in `conductor-cli`; reject before any `runs.db`/journal write or manifest read |
| `ANDROMEDA_PULSE_DATA_DIR` (propagated into the spawned sidecar) | reject argument-injection metacharacters before spawn; treat strictly as an env value passed via the `.env(...)` builder, NEVER interpolated into argv or a shell (MCP-sidecar STDIO command/argument-injection class, CVE-2026-30623 / OX advisory) | validate the path string in `conductor-verify` before `TokioChildProcess` spawn; resolve the platform default (`%APPDATA%\andromeda-pulse` on Windows · `$XDG_CONFIG_HOME`/`~/.andromeda-pulse` on Linux) if Pulse leaves it unset |
| CLI arguments / stdin (`conductor-cli` seed/scenario flags) | `CONDUCTOR_SEED` parses to the seed integer type; scenario key maps to a known P-ID ("no scenario without a P-ID"); CLI flag precedence over env | the CLI arg parser in `conductor-cli`; `anyhow` at the binary edge for type-erased parse failures |
| MCP read-back child stdout (trusted-child boundary) | bounded line-delimited JSON-RPC decoding (serde_json is recursion-limited against decode-bomb depth; a soft per-line size bound on the child's stdout — no unbounded read); a JSON-RPC error or empty canary round-trip ⇒ `blocked`, never false pass | hand-rolled JSON-RPC client (`conductor-verify/src/jsonrpc.rs`) parses each response line to `serde_json::Value`; the verdict/error wall maps JSON-RPC errors / decode faults to typed inputs (`VerifyError::{JsonRpc,Decode,Transport}`), never panics; canary asserts `query_incident_list` returns the emitted incident |
| `runs.db` writes (rusqlite raw SQL, no ORM) | use **bound parameters** for `run_id`/`seed`/fingerprint-JSON1 writes — never string-formatted SQL (despite near-nil injection exposure because content is self-generated synthetic data, per security-research.md rusqlite finding) | rusqlite 0.38.0 parameterized statements in the `conductor-report` storage seam; fingerprint arrays written as a JSON1 TEXT array |

(See `## Security Anti-Patterns` § Input for input-validation bans.)

The obs service-identity env-handles `CONDUCTOR_SERVICE_NAME` / `CONDUCTOR_ENV` (obs-plan §3) are **non-path string labels** stamped into self-observation JSON log *values* (JSON-escaped by serde_json; no path / SQL / argv exposure), and `CONDUCTOR_AGENT_MODE` is a **non-path boolean trigger** (only its presence is read — `agent_mode = --agent-mode flag || env-set`; the value is unused, never stamped into a log or interpolated into a path); all three require **no validation**, unlike the `CONDUCTOR_*` *path* handles in the table above. (The agent-mode log path `logs/agent-latest.jsonl` is itself derived from `CONDUCTOR_RUNS_DIR` through the same `resolve_under` traversal guard as the other artifact handles — not from `CONDUCTOR_AGENT_MODE`.)

## Dependency Security

_[ALL tiers]_

This is the primary residual-risk class for Conductor's Minimal tier
(Threat Model Summary § tier justification: "dependency/supply-chain audit,
notably `bundled` SQLite compiled from C source and the OTLP/gRPC/MCP
dependency tree").

**Audit tool:** `cargo-audit` **≥ 0.22** (RustSec; installed 0.22.2) — the ecosystem-standard scanner and minimum bar; audits `Cargo.lock` against the RustSec advisory DB and uniquely flags unmaintained crates (covers the `bundled`-SQLite C version via the `libsqlite3-sys` crate advisory, plus the tonic/prost tree). Strongly recommended companion: `cargo-deny` **≥ 0.19** (Embark; installed 0.19.4) — superset that additionally gates banned crates, duplicate versions, untrusted sources, and license policy via a single `deny.toml`; the 2026 practice is `cargo-audit` report-only first, then `cargo-deny` with advisory blocking on high/critical. (Both from security-research.md § Dependency Audit Tools.) These are external CLI tools, **not `Cargo.lock`-pinnable dependencies** — the stated versions are **minimum floors**; the actual security signal is the RustSec advisory DB fetched fresh on each run plus the committed lock, so any tool at or above the floor running green satisfies the gate.
**Two distinct external-decay faults, two distinct remedies (do not conflate them):**
- A **TOOL fault** — the installed scanner is too old, or carries a bug a newer release fixes. Remedy: **raise the floor** to the fixed release (these tools are unlockable, so a floor is the only pin available).
- An **advisory-DATABASE fault** — the RustSec DB itself will not parse or fetch, so *no* released tool version can read it. A floor raise is **unexecutable** here and would look like compliance while changing nothing. Remedy: a **bounded wait** — re-check each chunk, and keep coverage meanwhile via the deliberate audit↔deny **overlap**, verifying `cargo deny check advisories bans licenses sources` actually ran green rather than assuming it. Never a `deny.toml` ignore (that suppresses a real signal class for a transient external fault), never a CI edit, never a silent accept.
  *Established empirically 2026-08-09* (`2026-08-09-interpretation-correctness-posture`): `duplicate advisory ID: RUSTSEC-2026-0244` failed byte-identically on the installed 0.22.1 **and** on the latest published 0.22.2 — the duplicate id is committed data in the advisory-db, so there was no fixed release to raise a floor to. Distinguishing the two cases is what keeps a red gate honest instead of papered over.
**Pinning:** `Cargo.lock` committed (makes the audit deterministic — security-research.md cargo-audit + tar-rs findings). Toolchain pinned in `rust-toolchain.toml` to **≥ 1.94.1** — **done** (channel `1.95.0`, workspace `rust-version = 1.94.1`), clearing the tar-rs symlink-chmod CVE-2026-33056 / RUSTSEC-2026-0033 in the `cargo build` extraction path.
**Update policy:** manual review for a single-developer tool; bump versions flagged by `cargo-audit`/`cargo-deny`. Specific pinned bumps from research: `tauri` (+ bundler) **≥ 2.10.3** (architecture pins 2.10.1 → exposed to origin-confusion CVE-2026-42184 on Windows); keep `libsqlite3-sys` current so SQLite patch bumps flow in. (rmcp removed 2026-06-27 — the read-back client is now hand-rolled JSON-RPC; the former rmcp ≥ 1.4.0 / GHSA-89vp-x53w-74fx stdio-client note no longer applies.)
**Accepted exceptions (deny.toml, each with a justifying comment):** the unmaintained-but-non-vulnerable transitive `number_prefix` (via `indicatif`; no upstream fix available) is ignored (RUSTSEC-2025-0119), and the `Zlib` license (`foldhash` via `rusqlite`→`hashbrown`; OSI-approved + FSF Free/Libre, permissive) is allowed — the documented mechanism for non-actionable advisories / permissive-license additions, with the audit/deny gate staying green (no unresolved CVE).
**CI integration:** add a `cargo install cargo-audit` + `cargo audit` step (and optionally `cargo deny check advisories bans sources licenses`) to the existing `.github/workflows/` that already runs `cargo build` / nextest / clippy (Infrastructure Patterns: CI/CD approach). Build fails on advisory hit.
**Critical CVE response SLA:** for a single-developer local tool — patch within ~1 week of disclosure for actionable advisories against the dependency tree; immediate bump for any advisory that touches the `cargo build` extraction path (tar-rs class) or the Tauri IPC surface, since those are the live build/in-process boundaries.

**Frontend (npm) supply chain:** the optional GUI adds an npm dependency tree under `crates/conductor-tauri/ui/` (React 19 / Vite / Tailwind v4.1 / Fontsource / TypeScript, plus the dev-only a11y/GUI test harness — axe-core / @axe-core/webdriverio / lighthouse / colorjs.io / @crabnebula/tauri-driver / webdriverio / tsx) that `cargo-audit`/`cargo-deny` do NOT cover. Gate it with **`npm audit --omit=dev` clean (0 PRODUCTION vulnerabilities)** before merging frontend changes, with **`package-lock.json` committed** (deterministic install + reproducible audit — mirrors the committed `Cargo.lock`). **Dev-only transitive advisories in the non-shipping test tooling are accepted at dev-tree grain** (the `--omit=dev` gate) — the npm analogue of the deny.toml accepted-exceptions mechanism — since that tooling never ships in any binary and the production tree stays strictly clean (e.g. the a11y harness pulls `@opentelemetry/core <2.8.0` via `lighthouse→@sentry/node` + `serialize-javascript <=7.0.4` via `@wdio/mocha-framework→mocha`, none fixable non-breaking). Fonts are vendored locally (Fontsource WOFF2) — **no runtime CDN** (Minimal-tier offline hardening). A **production**-dependency npm-audit advisory drives the same floor discipline as cargo (e.g. Vite was bumped 6→8.0.16 to clear esbuild GHSA-gv7w-rqvm-qjhr in 2026-06-15-design-token-typography-bundle); no rigid dependency allowlist is imposed (Minimal-tier personal tool — the `--omit=dev` audit-clean gate is the control).

_Supply chain integrity subsection (signed artifacts / SBOM / base-image scanning):
**SKIP** — Standard + Hardened only; Conductor is Minimal tier with no
container/cloud deployment. Optional additive note only: `cargo-auditable` 0.7.4
(security-research.md) can wrap the release build as `cargo auditable build
--release` to embed the dependency list into the shipped `conductor-cli` binary
for later `cargo audit bin <binary>` when the binary is run beside Pulse on
another dev host — low priority, purely additive, not a gate._

(See `## Security Anti-Patterns` § Code Patterns for supply-chain bans.)

## Secret Management

_[ALL tiers; expand for Hardened]_

**Conductor owns no secrets** (Threat Model Summary § Data classification:
credential "none"; architecture Cross-cutting Patterns: Trust boundary — "There
are no secrets, no `DATABASE_URL`, and no cloud credentials"). This section
therefore documents the *absence* and the env-handle discipline rather than a
storage/rotation regime.

**Storage:**
- **Production:** N/A — no secrets to store. Local-only tool; no cloud secret manager, no `.env` secret file.
- **Development:** N/A — no dev secrets. Only non-secret configuration handles exist under the reserved `CONDUCTOR_*` env namespace (`CONDUCTOR_RUNS_DIR`, `CONDUCTOR_SCENARIOS_DIR`, `CONDUCTOR_CONTRACT_MANIFEST`, `CONDUCTOR_SEED`) and the Pulse-side `ANDROMEDA_PULSE_MCP_ENABLED` / `ANDROMEDA_PULSE_DATA_DIR` flags.
- **Production / dev separation:** N/A — no secret values exist in either.

**Never in code:** no credentials exist to hardcode; the OS keychain reference (`OsKeychainBackend("com.andromeda.pulse")`) is Pulse-side and accessed by the spawned sidecar as the same OS user — Conductor never reads, stores, or embeds keychain material.

**Secret scanning in CI:** optional defense-in-depth to guarantee the no-secrets invariant holds over time — a CI gate that fails the build if any secret-shaped string is ever introduced into the `conductor-*` workspace. ## Error Handling

_[ALL tiers]_

**External responses (to the operator / GUI surface):** sanitized — no stack
traces, file paths, internal hostnames, or library versions exposed. Conductor's
"external" surface is the `conductor-cli` stderr and the `#[tauri::command]`
return values to the bundled webview; the type-erased `anyhow` edge must not
surface absolute filesystem paths (e.g. canonicalized `CONDUCTOR_RUNS_DIR`) or
internal seam-crate struct names to those surfaces.

**Internal logging (for debugging):** full typed error detail stays inside the
seam crates as `thiserror` 2.0.18 enums (`EmitError`, `VerifyError`,
`ContractMismatch`, `ConfigError`); the verdict/error wall keeps `Result::Err`
strictly for harness faults (config parse, transport down, MCP unreachable) and
keeps verification outcomes as typed VALUES (`Verdict { Pass, Fail,
CalibrationRegion }` / `ReportState { Pass, Fail, ManualCheck, KnownResidual,
Blocked }`) returned as `Ok(...)`.

**Error format:** stack-native — `thiserror` typed enums per seam crate collapsed
to `anyhow` only at the `conductor-cli` / `#[tauri::command]` boundaries
(architecture Conventions: Error handling). RFC 7807 / GraphQL error extensions
are N/A (no HTTP/GraphQL surface). `tonic::Status` codes and MCP error responses
are first-class typed verification inputs, never panics.

**Run-report artifact sanitization:** the `<run_id>.md` report and `runs.db`
rows are agent-parseable ground truth — they must record verdict/state/identity
fields (`run_id`, `seed`, `scenario`, `p_ids`, `slo_tier`, `latency_ms`,
`fingerprints`) WITHOUT leaking absolute host paths (the canonicalized
`CONDUCTOR_*` directories, `ANDROMEDA_PULSE_DATA_DIR`) or internal struct/field
names from the seam crates. A `blocked` row populates only identity fields with
the named precondition string; measurement fields are JSON `null`.

(See `## Security Anti-Patterns` § Logging for error-disclosure bans.)

## Security Anti-Patterns (NEVER do these)

_[ALL tiers — single source of truth for all security bans]_

### Authentication

_Conductor has no live auth surface today (auth approach = none — single-user
local tool). These are forward-guardrails: IF any auth/recovery surface is ever
added (e.g. a remote-controllable mode), these bans apply._

- NEVER reveal whether an account exists in a recovery/login flow (account enumeration) — applies the instant any identity surface is introduced.
- NEVER use weak recovery questions ("mother's maiden name") as a sole recovery factor.
- NEVER skip rate limiting on auth endpoints (brute-force) — if Conductor ever grows an authenticated control surface beyond local IPC, gate it.
- NEVER add interactive login to the headless `scripts/agent-run.sh` source-of-truth path — it is agent-driven by design (Cross-cutting Patterns: Development Style); an auth prompt there would silently break the release gate.

### Input

- NEVER use the `CONDUCTOR_RUNS_DIR` / `CONDUCTOR_SCENARIOS_DIR` / `CONDUCTOR_CONTRACT_MANIFEST` env path handles without `std::fs::canonicalize` + bounds-check at the `conductor-cli` edge (path traversal) — these sit OUTSIDE garde's struct validation (security-research.md serde+garde finding).
- NEVER interpolate `ANDROMEDA_PULSE_DATA_DIR` (or any operator-supplied value) into the `andromeda-pulse-mcp` argv or a shell string — pass it strictly via the `.env(...)` builder and reject argument-injection metacharacters first (MCP-sidecar STDIO command/argument-injection class, CVE-2026-30623 / OX advisory; e.g. the `npx -c` allowlist bypass).
- NEVER spawn the MCP sidecar from an operator-chosen command — spawn `andromeda-pulse-mcp` as a fixed, hard-coded program path only (MCP-sidecar STDIO design flaw).
- NEVER use string concatenation / `format!` to build SQL for `runs.db` — use rusqlite 0.38.0 **bound parameters** for `run_id`/`seed`/fingerprint-JSON1 writes (raw SQL, no ORM — security-research.md rusqlite finding), even though content is self-generated synthetic data.
- NEVER deserialize scenario config without garde validation at load — garde's `range` + `#[garde(custom)]` cross-field rules ARE the trust boundary (error fraction ∈ [0,1], p50≤p95≤p99); an unvalidated `serde` deserialize bypasses it.
- NEVER decode prost/protobuf from the child's stdout without bounded recursion on the read-back path (protobuf-decode DoS lineage RUSTSEC-2020-0002 / RUSTSEC-2024-0437); an empty canary round-trip MUST become `blocked`, never a false pass-as-empty.

### Data Protection

- NEVER use deprecated crypto algorithms (MD5, SHA-1, DES, RC4, ECB mode) — if any fingerprint/hash is ever added to `runs.db` or the journal, use a modern hash.
- NEVER have Conductor's production code directly open, copy, or exfiltrate Pulse's `corpus.db` (plaintext SQLite — P-049 encryption not active live; corpus access is via MCP read-back ONLY) — it is owned by Pulse (the SUT); never persist its content into Conductor artifacts (Standard Contracts: Readiness gate).
- NEVER persist real secrets or credentials into the unencrypted `runs.db` / JSONL journals — they store only self-generated synthetic telemetry; treat them as world-readable local files.
- NEVER disable TLS verification or downgrade to plaintext on any surface that is ever promoted beyond loopback — today egress is `127.0.0.1:4317` loopback-only, but a non-loopback target must not silently skip transport verification.

### API

_Conductor exposes no network API today (no inbound listener; Backend Framework =
none). These are forward-guardrails: IF a network surface is ever added, these
bans apply._

- NEVER expose internal error details (stack traces, file paths, library versions, internal struct names) in any response — the `anyhow` edge and run-report artifacts must stay sanitized (Error Handling above).
- NEVER skip request size limits (DoS via large payloads) — if Conductor ever adds a network surface beyond loopback/IPC, it MUST enforce request size limits and bounded decoding before parsing.
- NEVER trust `X-Forwarded-For` (or any client-supplied origin/IP header) without verifying the proxy chain — relevant only if a network listener is ever introduced.
- NEVER promote the port-occupier fault bind on `:4317` (the single deliberate `conductor-faults` port bind) into a general-purpose inbound listener accepting external input — it is an intentional in-host fault, not an API surface.

### Secrets

- NEVER commit `.env` files or any secret-shaped string to the `conductor-*` workspace — Conductor owns no secrets and that invariant must hold (enforced by the optional secret-scanning CI gate; see Secret Management).
- NEVER hardcode credentials in source code — there are none to hardcode; the OS keychain reference is Pulse-side, accessed by the spawned sidecar, never embedded in Conductor.
- NEVER put credentials in URL query strings or argv — use the `.env(...)` builder for the sidecar's `ANDROMEDA_PULSE_DATA_DIR` (which is a non-secret path handle, not a credential).
- NEVER introduce a `DATABASE_URL` or cloud-credential env var — the SQLite path is a local file and the tool is local-only (Occupied Resources: Environment variables — "no secrets/cloud env vars").
- NEVER skip the secret-scanning CI gate — it is the only thing that enforces the "no secrets ever" invariant over time for this workspace.

### Logging

- NEVER log secrets, tokens, or `Authorization` headers — there are none in Conductor, and this ban keeps it that way if any future integration introduces them.
- NEVER expose stack traces, absolute file paths, or internal struct/field names to the operator via `conductor-cli` stderr or `#[tauri::command]` returns — sanitize at the `anyhow` edge (Error Handling above).
- NEVER let run-report artifacts (`<run_id>.md`, `runs.db` rows, JSONL journals) leak absolute host paths (canonicalized `CONDUCTOR_*` directories, `ANDROMEDA_PULSE_DATA_DIR`) or internal seam-crate struct names — they are agent-parseable ground truth shared across hosts, so they must carry verdict/state/identity fields only.
- NEVER write the journal/report wall-clock stamps from tokio's virtual clock — use `std::time::SystemTime`/`Instant` so journal-relative SLO math stays correct (Cross-cutting Patterns: Determinism discipline); a wrong clock source corrupts the ground-truth artifact.

### Code Patterns

- NEVER spawn the MCP sidecar (or anything) via a shell / `eval`-equivalent with operator-supplied input — fixed program path + `.env(...)`, no config-into-argv (MCP-sidecar STDIO design flaw, CVE-2026-30623).
- NEVER use the Tauri `shell-open` plugin with scenario-config-derived strings — if the GUI ever opens paths/URLs, set an explicit allow-scope; the unscoped plugin enables RCE via dangerous protocols (`file://`/`smb://`/`nfs://`, CVE-2025-31477 CVSS 9.3). Prefer avoiding the plugin entirely.
- NEVER embed remote-origin iframes in the bundled Tauri webview — iframes can bypass origin checks for IPC even in isolation mode (GHSA-57fm-592m-34r7); combined with custom-protocol origin confusion (CVE-2026-42184) this re-exposes the IPC surface the threat model assumes is in-process-only.
- NEVER ship Tauri commands without a minimal capabilities file — author deny-by-default capabilities allowing ONLY the actual commands (start/stop, scenario/suite picker, run-report view, operator-pause) plus the one live-counter `Channel`; a permissive default exposes unintended IPC.
- NEVER pin the read-back client to a strict newer protocol default — it MUST negotiate DOWN to `2024-11-05` by reading the `initialize` result's `protocolVersion` (Pulse's hand-rolled server version) and tolerate minimal capabilities; a strict-newer default is the silent-mismatch class the preflight exists to prevent (Established Decisions: MCP Read-Back Client).
- NEVER follow symlinks when changing permissions during crate extraction on a pre-1.94.1 toolchain — bump `rust-toolchain.toml` to ≥ 1.94.1 to clear the tar-rs symlink-chmod flaw in the `cargo build` extraction path (CVE-2026-33056 / RUSTSEC-2026-0033) and keep `Cargo.lock` committed.

### Universal

- NEVER run `cargo build --release` (the release gate) or merge to the dev OS target without `cargo-audit` (and recommended `cargo-deny`) green — the dependency/supply-chain audit IS the Minimal-tier residual-risk control for the `bundled`-SQLite-from-C + OTLP/gRPC/MCP tree (Threat Model Summary § tier justification).
- NEVER let `Cargo.lock` drift or go uncommitted — it makes the `cargo-audit`/`cargo-deny` scan non-deterministic and lets the `bundled` SQLite C version float past advisory tracking (security-research.md cargo-audit + rusqlite findings).
- NEVER add a scenario without a Pulse P-ID, and NEVER introduce an inbound network listener of Conductor's own — both violate the architecture's scope law / trust boundary and silently widen the attack surface beyond the loopback-client model (Cross-cutting Patterns: Scope law, Trust boundary).
- NEVER let a malformed child/transport input panic — `tonic::Status` codes and MCP error responses are first-class typed verification inputs routed through the verdict/error wall (`Ok(Verdict/ReportState)` vs `Result::Err` for harness faults only); a panic on the read-back path corrupts run classification.
- NEVER silently downgrade a failed preflight (version mismatch / missing tool / empty canary / keychain read-while-write fault) to pass/fail/manual-check — it MUST surface as the distinct `blocked` state with the named precondition string, never a false pass (Standard Contracts: Readiness gate).
- NEVER add `unsafe` across the OTLP/gRPC/SQLite FFI boundary without review — safe Rust + `current_thread` tokio give memory/data-race safety for free, but the `bundled`-SQLite C and raw-protobuf/tonic codegen are the FFI surface the language cannot check (use `cargo-geiger` 0.13.0 ad-hoc to map `unsafe`; keep `libsqlite3-sys` current — security-research.md Rust/tokio + cargo-geiger findings).
- NEVER skip bumping a pinned dependency flagged by research — `tauri` ≥ 2.10.3 (origin-confusion CVE-2026-42184) and the toolchain ≥ 1.94.1 (tar-rs) are required bumps over the architecture's current 2.10.1 / MSRV 1.88.0 pins.
