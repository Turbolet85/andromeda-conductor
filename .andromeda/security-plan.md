## Threat Model Summary

_[ALL tiers — VERBATIM copy from threat-assessment.md]_

**Security tier:** `Minimal (0)`
_Justification: Every signal points to a minimal-tier local utility — a single-developer, local-only, no-cloud, no-multi-tenancy tool with no user accounts (auth "none"), where the only persisted data is self-generated synthetic test telemetry and run-metadata in an embedded SQLite index (`runs.db`) plus on-disk JSONL/Markdown artifacts (no PII/payment/health/credentials owned by Conductor), and there is zero network exposure — Conductor is a loopback gRPC/MCP client with no inbound listener of its own. With no compliance triggers, the residual risk classes that remain are exactly those Minimal tier covers: dependency/supply-chain audit (notably `bundled` SQLite compiled from C source and the OTLP/gRPC/MCP dependency tree), input validation on operator-supplied scenario config and `CONDUCTOR_*` env-var path overrides, and error sanitization at the `anyhow` binary edges and in run-report artifacts._

**Data classification:**

- **Type:** config — declarative scenario config (serde + garde, no DSL)
  - **Where:** `scenarios/` directory, deserialized into the owning seam crates; `contracts/` pinned MCP contract manifest (Conventions: Config conventions; Occupied Resources: On-disk artifacts)
  - **Volume:** aggregate (one config file per Pulse P-ID, over the SUT capability manifest's accepted set), transient at load

- **Type:** test-telemetry / run-metadata (synthetic, not user data) — emission journals, run reports, and the `runs.db` index (run_id · seed · scenario · P-IDs · verdict · fingerprints · timestamps)
  - **Where:** `runs/` directory (per-run `<run_id>.jsonl` journal + `<run_id>.md` report) and embedded SQLite `runs.db` (Occupied Resources: On-disk artifacts; Established Decisions: Run-History Persistence)
  - **Volume:** aggregate, persisted on disk (append-mostly); content is self-generated synthetic OTLP fault data (spans/metrics/logs Conductor emits), not user-derived

- **Type:** credential — **none owned by Conductor.** A keychain reference appears (`OsKeychainBackend("com.andromeda.pulse")`, Standard Contracts readiness gate), but it belongs to Pulse (the system under test): the sidecar opens Pulse's `corpus.db` (plaintext SQLite — the P-049 encrypted-at-rest assumption proved wrong when verified live 2026-06-27; the `OsKeychainBackend` reference is Pulse-side and not exercised for corpus access) as the *same OS user*. Conductor does not store, generate, or manage any secret; the architecture states explicitly "No secrets, no `DATABASE_URL`, no cloud credentials" (Cross-cutting Patterns: Trust boundary; Occupied Resources: Environment variables — "no secrets/cloud env vars (local-only tool)")
  - **Where:** N/A for Conductor (OS keychain access is Pulse-side, exercised via the spawned sidecar's canary)
  - **Volume:** N/A

- **Type:** PII — **none.** Project Intent: "Personal — solo developer, local dev host, no cloud, no multi-tenancy." No user accounts, no user-supplied content. The only identities are synthetic incident/fingerprint data Conductor itself emits.
- **Type:** payment — **none.** Stack lists no payment/billing SDK (no Stripe etc.); Project Intent describes no transactions.
- **Type:** health — **none.** No medical data in Stack or Intent.

Note: `corpus.db` (Pulse's incident corpus — **plaintext SQLite**, NOT encrypted-at-rest; the P-049 encryption assumption proved wrong live 2026-06-27) is **out of scope** — owned by Pulse (the SUT); Conductor reaches it through the MCP TOOL SURFACE only — read-back **plus the `mark_incident_resolved` lifecycle write** (first production caller 2026-08-31, `conductor_run::probe_resolve_lifecycle`) — never the file, and never persists/exfiltrates its content (Standard Contracts readiness gate).

**Attack surface:**

- **Vector:** CLI input — seed/scenario flags and env-var overrides on the `agent-run` / `conductor-cli` path
  - **Entry point:** `conductor-cli` binary args + `CONDUCTOR_*` env namespace (`CONDUCTOR_RUNS_DIR`, `CONDUCTOR_SCENARIOS_DIR`, `CONDUCTOR_CONTRACT_MANIFEST`, `CONDUCTOR_SEED`, and — dev-harness-only, read by `wdio.conf.ts` on the driver legs (the `agent-run … --e2e` routine arm, the `npm run a11y:driven` driven arm and the operator-local `sr` / `sr-empty` / `sr-error` screen-reader suites) and never by a Conductor binary — `CONDUCTOR_MSEDGEDRIVER` · `CONDUCTOR_NVDA`; and — dev-harness-only in a THIRD shape, SET by `wdio.conf.ts` and READ by a `conductor-run` TEST binary rather than by wdio, never by a shipped binary — `CONDUCTOR_E2E_SEED_DIR`) (Occupied Resources: Environment variables; Cross-cutting Patterns: Config management)
  - **Trust boundary:** operator-supplied on the local host; CLI flag precedence over env; no untrusted/remote source

- **Vector:** config files (local file parsing) — scenario config + pinned MCP contract manifest read from disk
  - **Entry point:** `scenarios/` (serde deserialize) and `contracts/` manifest; `anyhow` at the CLI edge, `ConfigError` harness-fault class via garde `#[from]`
  - **Trust boundary:** garde validation at load (`range` rules: a bounded error fraction — the shipped `error_percent` ∈ 0..=100 — non-negative durations, sane ramp factors, bounded per-phase occurrences; `#[garde(custom)]` cross-field: p50≤p95≤p99, severity-mix sums, the per-shape emission rules, the `[phases.fault]` closed `kind` enum + the scenario-level fault ⇒ `occurrences = 0` silence rule; plus the load-path `Scenario::check_*()` arm for sibling-spanning rules garde cannot express — `check_capabilities`; `check_budgets` for `budget_ms` bounded `1..=MAX_BUDGET_MS` and cross-checked against the scenario's own `slo_tier`; and `check_checklist`, which rejects a `[[checklist]]` declared beside a non-empty `expected`, all faulting as `CoreError::Config`), diving into nested spec structs rather than skipping them (Conventions: Config conventions, Error handling). Source is operator-authored local files, not external input.

- **Vector:** Tauri IPC — internal in-app commands (`#[tauri::command]` start/stop/picker/run-report/operator-pause) + one `Channel` for live counters
  - **Entry point:** Tauri 2 webview→backend IPC, bundled webview (no frontend dev-server port) (Standard Contracts: Live update channel; Occupied Resources: Interface routes)
  - **Trust boundary:** in-process app boundary (backend↔bundled webview); not network-exposed. REST/GraphQL/tRPC are N/A.

- **Vector:** MCP read-back child-process stdout — Conductor spawns the Pulse MCP server (`andromeda-pulse-mcp`) via `TokioChildProcess` (stdio) and **trusts that child's stdout as the read-back source**
  - **Entry point:** hand-rolled line-delimited JSON-RPC client over stdio (rmcp removed 2026-06-27); version-pinned contract manifest + `initialize` preflight gate (Conventions: Inbound verification; Cross-cutting Patterns: Trust boundary)
  - **Trust boundary:** preflight readiness gate — negotiated protocol pinned at `2024-11-05`, required-tool presence vs. manifest, data-dir canary round-trip; mismatch/empty ⇒ **blocked** state. The child is a locally-spawned, co-located process under the same OS user (not a remote/untrusted peer); `tonic::Status` codes and MCP error responses are first-class typed verification inputs, not panics.

- **Vector:** OTLP/gRPC egress — outbound only to `127.0.0.1:4317` (Pulse's loopback ingest)
  - **Entry point:** tonic client; Conductor is the client, port owned by Pulse (Occupied Resources: Ports; Conventions: Outbound emission)
  - **Trust boundary:** loopback-only egress; a refused transport surfaces as `Result::Err` (harness fault), not a verdict

- **Vector (single deliberate exception):** port bind `:4317` — the port-occupier fault scenario intentionally binds `:4317` to exercise Pulse's reaction
  - **Entry point:** `conductor-faults` seam (Cross-cutting Patterns: Trust boundary; Occupied Resources: Ports)
  - **Trust boundary:** loopback only; the *sole* case where a SHIPPED Conductor binary opens a port, and it is an intentional in-host fault, not a network listener accepting external input. The dev-only webview driver legs — the routine `agent-run … --e2e` arm, the operator-local `npm run a11y:driven` arm and the operator-local `sr` / `sr-empty` / `sr-error` screen-reader suites (host-gated on Windows + an NVDA build named by `CONDUCTOR_NVDA`, skipping at exit 0 elsewhere; never a CI stage, no `agent-run` verb), all firing the same `wdio.conf.ts` driver stack — additionally bring up harness-lifetime loopback listeners `127.0.0.1:4444` (tauri-driver) and `127.0.0.1:4445` (native WebDriver), distinct from `:4317`, bound only for the leg's duration and never present in `conductor-cli` / `conductor-tauri`

- **Vector:** public API / file upload / OAuth / WebSocket / UGC / webhook — **none.** No web framework (Stack: "Backend Framework: None"), no HTTP surface (`:4318` unused, no `/health` or `/ready` HTTP endpoints), no SSE/WebSocket/polling, local-only deployment (Infrastructure Patterns: Deployment model — "No Docker/Compose/Kubernetes/serverless… execution is necessarily co-located on the dev host"). No external/internet exposure exists.

**Auth model:**
- **Approach:** none
- **Provider:** N/A
- **Scope:** N/A

**Reason:** Project Intent records "Personal — solo developer, local dev host, no cloud, no multi-tenancy" with no user accounts and no API consumers. Conductor exposes no network service (Stack: "Backend Framework: None"; Occupied Resources: "No inbound listener of Conductor's own"), so there is no authenticated surface to protect. Development Style is **agent-driven** — the headless `scripts/agent-run.sh` path is the source of truth and release gate (Cross-cutting Patterns: Development Style), which implies no interactive login UX. The only env flag is `ANDROMEDA_PULSE_MCP_ENABLED`, which Conductor explicitly asserts it does **not** set itself (it is a Pulse-side operator gate). It must nonetheless be present in **Conductor's own process environment**, where the operator exports it and the spawned sidecar receives it by environment **inheritance** — Since 2026-09-03 an absent declaration is ALSO observed UPSTREAM — as a `[PRECONDITION]` subject of `conductor preconditions` and as the run contract's `mcp-enabled` `shell-declaration` term — so it is named before any spawn, rather than only downstream as the sidecar starting and immediately exiting with every read-back measuring the unreachable path. Conductor still never SETS the flag, and inheritance remains the sole channel to the child: `spawn.rs` passes only `ANDROMEDA_PULSE_DATA_DIR` through the `.env(...)` builder, so inheritance is the sole channel for this flag. Absent it, the sidecar starts and immediately exits (`env_var_mcp_enabled: false` with `feature_flag_enabled: true`) and every read-back measures the unreachable path — verified live 2026-08-13. Defaulting to JWT/session/OAuth here would contradict the single-user local model.

**Infrastructure:**
- **Hosting:** local-only — `cargo build --release` produces the `conductor-cli` binary run beside Pulse via `scripts/agent-run.sh`; optional Tauri 2 (v2.10.x) ~3 MB GUI bundle. Explicitly "No Docker/Compose/Kubernetes/serverless" (Infrastructure Patterns: Deployment model; Established Decisions: Deployment)
- **Database:** embedded — rusqlite 0.38.0 with `bundled` SQLite 3.50.4 (JSON1, via libsqlite3-sys 0.36.0), synchronous raw SQL, in-process `runs.db`; no DB port, no `DATABASE_URL` (Stack: Database; Occupied Resources: Ports + Environment variables)
- **Networking:** local only — egress is loopback OTLP/gRPC to `127.0.0.1:4317` (`:4318` unused) and a stdio child-process MCP session; no inbound listener, no public/VPN networking. Co-location is forced because Pulse binds loopback `:4317` (Cross-cutting Patterns: Trust boundary; Infrastructure Patterns: Deployment model)
- **CI/CD:** GitHub Actions on the dev OS target — `cargo build` / cargo-nextest (incl. golden tests) / `cargo clippy`, build + test gating only. Dynamic end-to-end scenario proof requires a live Pulse and is an explicit operator/local gate, not a CI gate (Infrastructure Patterns: CI/CD approach; Established Decisions: CI/CD)

## Dependency Security

_[ALL tiers]_

This is the primary residual-risk class for Conductor's Minimal tier
(Threat Model Summary § tier justification: "dependency/supply-chain audit,
notably `bundled` SQLite compiled from C source and the OTLP/gRPC/MCP
dependency tree").

**Audit tool:** `cargo-audit` **≥ 0.22** (RustSec; installed 0.22.2) — the ecosystem-standard scanner and minimum bar; audits `Cargo.lock` against the RustSec advisory DB and uniquely flags unmaintained crates (covers the `bundled`-SQLite C version via the `libsqlite3-sys` crate advisory, plus the tonic/prost tree). Strongly recommended companion: `cargo-deny` **≥ 0.19** (Embark; installed 0.19.4) — superset that additionally gates banned crates, duplicate versions, untrusted sources, and license policy via a single `deny.toml`; the 2026 practice is `cargo-audit` report-only first, then `cargo-deny` with advisory blocking on high/critical. (Both from security-research.md § Dependency Audit Tools.) These are external CLI tools, **not `Cargo.lock`-pinnable dependencies** — the stated versions are **minimum floors**; the actual security signal is the RustSec advisory DB fetched fresh on each run plus the committed lock, so any tool at or above the floor running green satisfies the gate.
**Two distinct external-decay faults, two distinct remedies (do not conflate them):**
- A **TOOL fault** — the installed scanner is too old, or carries a bug a newer release fixes. Remedy: **raise the floor** to the fixed release (these tools are unlockable, so a floor is the only pin available).
- An **advisory-DATABASE fault** — the RustSec DB itself will not parse or fetch, so *no* released tool version can read it. A floor raise is **unexecutable** here and would look like compliance while changing nothing. Remedy: a **bounded wait** — re-check each chunk, and keep coverage meanwhile via the deliberate audit↔deny **overlap**, verifying `cargo deny check advisories bans licenses sources` actually ran green rather than assuming it. Never a `deny.toml` ignore (that suppresses a real signal class for a transient external fault), never a CI edit, never a silent accept.
  *Established empirically 2026-08-09* (`2026-08-09-interpretation-correctness-posture`): `duplicate advisory ID: RUSTSEC-2026-0244` failed byte-identically on the installed 0.22.1 **and** on the latest published 0.22.2 — the duplicate id is committed data in the advisory-db, so there was no fixed release to raise a floor to. Distinguishing the two cases is what keeps a red gate honest instead of papered over.
  **Admitting a NEW dependency while the fault persists (2026-08-16):** the wait was originally justified partly by the tree being static — a zero-delta chunk cannot have caused an external failure. That no longer holds once a dependency lands, so the condition is explicit: **a dependency delta MAY land under a red audit, but only on a `cargo deny check advisories bans licenses sources` VERIFIED green over the NEW `Cargo.lock`** — verified, never assumed, because the deny overlap is then the sole coverage for the added packages, and any new license/advisory it surfaces takes the justified-exception mechanism above. State the changed basis when re-pinning the deferral: "no dependency delta" stops being available as a reason. First applied when `blake3` (+ `arrayref`/`arrayvec`/`constant_time_eq`/`cpufeatures`) landed at `2026-08-16-canary-fingerprint-derivation-aligned` against the 22nd consecutive red audit.
**Pinning:** `Cargo.lock` committed (makes the audit deterministic — security-research.md cargo-audit + tar-rs findings). ## Security Anti-Patterns (NEVER do these)

_[ALL tiers — single source of truth for all security bans]_

### Authentication

_Conductor has no live auth surface today (auth approach = none — single-user
local tool). These are forward-guardrails: IF any auth/recovery surface is ever
added (e.g. a remote-controllable mode), these bans apply._

- NEVER reveal whether an account exists in a recovery/login flow (account enumeration) — applies the instant any identity surface is introduced.
- NEVER use weak recovery questions ("mother's maiden name") as a sole recovery factor.
- NEVER skip rate limiting on auth endpoints (brute-force) — if Conductor ever grows an authenticated control surface beyond local IPC, gate it.
- NEVER add interactive login to the headless `scripts/agent-run.sh` source-of-truth path — it is agent-driven by design (Cross-cutting Patterns: Development Style); an auth prompt there would silently break the release gate.

### Input

- NEVER use the `CONDUCTOR_RUNS_DIR` / `CONDUCTOR_SCENARIOS_DIR` / `CONDUCTOR_CONTRACT_MANIFEST` env path handles without `std::fs::canonicalize` + bounds-check at the `conductor-cli` edge (path traversal) — these sit OUTSIDE garde's struct validation (security-research.md serde+garde finding). THREE reserved-namespace path handles sit outside this rule, in two classes. `CONDUCTOR_MSEDGEDRIVER` and `CONDUCTOR_NVDA`: no Rust code reads either, so their equivalent duty is discharged at the wdio harness edge — existence + `isFile` + shell-metacharacter rejection before the spawn (the driver's and NVDA's respectively). `CONDUCTOR_E2E_SEED_DIR` IS read by Rust, but only by a test binary (`conductor-run/tests/envelope_fixture.rs`) and never by a shipped one, and its value is a harness-owned repo-relative constant rather than operator input — so there is no operator-supplied value to reject, the repo-relative discipline lives at the wdio caller that sets it, and the seeding test is a no-op when the handle is unset. **The residual is explicit:** the test applies no `resolve_under` / canonicalize guard of its own, so that discipline holds only while no shipped binary reads the handle. The canonicalize duty above still binds every handle a shipped binary reads.
- NEVER interpolate `ANDROMEDA_PULSE_DATA_DIR` (or any operator-supplied value) into the `andromeda-pulse-mcp` argv or a shell string — pass it strictly via the `.env(...)` builder and reject argument-injection metacharacters first (MCP-sidecar STDIO command/argument-injection class, CVE-2026-30623 / OX advisory; e.g. the `npx -c` allowlist bypass).
- NEVER spawn the MCP sidecar from an operator-chosen command — spawn `andromeda-pulse-mcp` as a fixed, hard-coded program NAME resolved through the inherited `PATH` (never a config-derived or operator-supplied command string) (MCP-sidecar STDIO design flaw). `PATH` is therefore BOTH a spawn-resolution input AND, since 2026-09-03, the subject of a second NON-SPAWNING resolution of the same const: `conductor_verify::sidecar_resolves_on_path()` walks `std::env::split_paths(PATH)` + `PATHEXT` for `PULSE_MCP_PROGRAM`, constructs no `Command`, and returns a boolean-grade fact — the resolved path is never returned, logged or rendered, and never becomes the spawn program. On the `agent-run boot` path a `PATH` miss is now named upstream as a `[PRECONDITION]` subject instead of only surfacing as the ~0s `[BLOCKED]` row measured 2026-08-20. The original rule stands: `PATH` is a spawn-resolution input: the environment selects WHICH binary the fixed name resolves to. Measured 2026-08-20 — a `PATH` entry split on a drive-letter colon resolved the sidecar nowhere and the run reported `[BLOCKED]` in ~0s, indistinguishable at row level from a genuine SUT-side gate failure.
- NEVER use string concatenation / `format!` to build SQL for `runs.db` — use rusqlite 0.38.0 **bound parameters** for `run_id`/`seed`/fingerprint-JSON1 writes (raw SQL, no ORM — security-research.md rusqlite finding), even though content is self-generated synthetic data.
- NEVER deserialize scenario config without validation at load — garde's `range` + `#[garde(custom)]` rules AND the load-path `Scenario::check_*()` cross-field checks called from `from_toml_str` TOGETHER are the trust boundary (`budget_ms` ≤ its scenario's own `slo_tier` deadline is one such rule); NEVER write a SIBLING-reading invariant as `#[garde(custom)]` — in garde 0.22.1 it receives `(&field, &())`, sees no sibling, and would look enforced while never testing the invariant (a bounded error fraction, shipped as `error_percent` ∈ 0..=100; p50≤p95≤p99; the `[phases.fault]` closed `kind` enum + fault ⇒ `occurrences = 0`); an unvalidated `serde` deserialize bypasses it. NEVER mark a nested spec field `#[garde(skip)]` — garde does not descend into it, so its rules never run and the boundary is silently bypassed even though the rules exist; `dive` is the only correct annotation (`PhaseSpec.emission` carried the historical `skip`; `PhaseSpec.fault` dives from birth).
- NEVER decode prost/protobuf from the child's stdout without bounded recursion on the read-back path (protobuf-decode DoS lineage RUSTSEC-2020-0002 / RUSTSEC-2024-0437); an empty canary round-trip MUST become `blocked`, never a false pass-as-empty.

### Data Protection

- NEVER use deprecated crypto algorithms (MD5, SHA-1, DES, RC4, ECB mode) — the ban is now ACTIVE, not hypothetical: `conductor_emit::exception::fingerprint` ships a **blake3** derivation (first 16 bytes / 32 hex), replacing the retired non-cryptographic FNV-1a. Note the run-report `fingerprints[]` column is fed from read-back `Observation#fingerprints`, never from that derivation — the two never meet.
- NEVER have Conductor's production code directly open, copy, or exfiltrate Pulse's `corpus.db` (plaintext SQLite — P-049 encryption not active live; corpus access is via the MCP TOOL SURFACE only — read-back plus the `mark_incident_resolved` lifecycle write — never the file) — it is owned by Pulse (the SUT); never persist its content into Conductor artifacts (Standard Contracts: Readiness gate). The ban is on FILE access, not on the sanctioned write tool: staging a corpus row directly to induce a SUT state (e.g. Pulse's `DeclinedStale`) is the banned route, and is why that arm is stub-proven instead.
- NEVER persist real secrets or credentials into the unencrypted `runs.db` / JSONL journals — they store only self-generated synthetic telemetry; treat them as world-readable local files.
- NEVER disable TLS verification or downgrade to plaintext on any surface that is ever promoted beyond loopback — today egress is `127.0.0.1:4317` loopback-only, but a non-loopback target must not silently skip transport verification.

### API

_Conductor exposes no network API today (no inbound listener; Backend Framework =
none). These are forward-guardrails: IF a network surface is ever added, these
bans apply._

- NEVER expose internal error details (stack traces, file paths, library versions, internal struct names) in any response — the `anyhow` edge and run-report artifacts must stay sanitized (Error Handling above).
- NEVER skip request size limits (DoS via large payloads) — if Conductor ever adds a network surface beyond loopback/IPC, it MUST enforce request size limits and bounded decoding before parsing.
- NEVER trust `X-Forwarded-For` (or any client-supplied origin/IP header) without verifying the proxy chain — relevant only if a network listener is ever introduced.
- NEVER promote the port-occupier fault bind on `:4317` (the single deliberate `conductor-faults` port bind) into a general-purpose inbound listener accepting external input — it is an intentional in-host fault, not an API surface.

### Secrets

- NEVER commit `.env` files or any secret-shaped string to the `conductor-*` workspace — Conductor owns no secrets and that invariant must hold (enforced by the optional secret-scanning CI gate; see Secret Management).
- NEVER hardcode credentials in source code — there are none to hardcode; the OS keychain reference is Pulse-side, accessed by the spawned sidecar, never embedded in Conductor.
- NEVER put credentials in URL query strings or argv — use the `.env(...)` builder for the sidecar's `ANDROMEDA_PULSE_DATA_DIR` (which is a non-secret path handle, not a credential).
- NEVER introduce a `DATABASE_URL` or cloud-credential env var — the SQLite path is a local file and the tool is local-only (Occupied Resources: Environment variables — "no secrets/cloud env vars").
- NEVER skip the secret-scanning CI gate — it is the only thing that enforces the "no secrets ever" invariant over time for this workspace.

### Logging

- NEVER log secrets, tokens, or `Authorization` headers — there are none in Conductor, and this ban keeps it that way if any future integration introduces them.
- NEVER expose stack traces, absolute file paths, or internal struct/field names to the operator via `conductor-cli` stderr or `#[tauri::command]` returns — sanitize at the `anyhow` edge (Error Handling above).
- NEVER let run-report artifacts (`<run_id>.md`, `runs.db` rows, JSONL journals) or committed evidence records (the per-chunk `evidence/` tree, incl. `nvda-pass.json`, whose `heard` text is transcribed third-party speech scrubbed to `<host-path>` before it is written) leak absolute host paths (canonicalized `CONDUCTOR_*` directories, `ANDROMEDA_PULSE_DATA_DIR`) or internal seam-crate struct names — they are agent-parseable ground truth shared across hosts, so they must carry verdict/state/identity fields only.
- NEVER write the journal/report wall-clock stamps from tokio's virtual clock — use `std::time::SystemTime`/`Instant` so journal-relative SLO math stays correct (Cross-cutting Patterns: Determinism discipline); a wrong clock source corrupts the ground-truth artifact.

### Code Patterns

- NEVER spawn a child via a shell / `eval`-equivalent with operator-supplied input. Two rules, by spawn class: **(a) the MCP sidecar** — fixed hard-coded program NAME resolved through the inherited `PATH` + `.env(...)`, no config-into-argv — the same const also has a NON-SPAWNING sibling resolution (`sidecar_resolves_on_path`, a directory walk returning a boolean-grade fact) which constructs no `Command`, therefore opens no console window and adds no absolute-exe-path disclosure channel of the class named below (MCP-sidecar STDIO design flaw, CVE-2026-30623) — AND the spawn must suppress the child's console window (a `CREATE_NO_WINDOW`-class creation flag on Windows): `Command::new(PULSE_MCP_PROGRAM)` with no creation flags (`conductor-verify/src/spawn.rs:80`) raises a terminal pane titled with the sidecar's ABSOLUTE exe path that seizes the OS foreground ~200 ms after `Start` — a host-path disclosure channel outside the `sanitize_error` / artifact-hygiene edges, **measured 2026-09-02 (NVDA spoke the pane's title, SR pass row S1-01) and recorded as a routed product defect, not yet shipped**. **(b) any HARNESS spawn** (the dev-only driver stack, on the `--e2e` routine arm, the `a11y:driven` driven arm or the `sr*` screen-reader suites) — four governed forms, none a shell string: the repo-vendored driver's PROGRAM is a repo-derived resolved constant (`require.resolve('@crabnebula/tauri-driver/cli.js')`), never a bare PATH name and never operator-chosen; a FIXED OS program with a fixed argv (`spawnSync('powershell.exe', ['-NoProfile', '-ExecutionPolicy', 'Bypass', '-File', <repo script>, '-Title', <constant>])` — the window-activation step, no operator input anywhere in the vector); an operator-supplied HOST-TOOL path as the program (`CONDUCTOR_NVDA`) ONLY after the existence + `isFile` + shell-metacharacter guard, as an array-form detached spawn with a fixed argv; and the FIXTURE-SEED spawn — a fixed toolchain program with a fixed argv (`spawnSync('cargo', ['test', '-q', '-p', 'conductor-run', '--test', 'envelope_fixture', '--', '--nocapture'], { cwd: repoRoot })`) carrying `CONDUCTOR_E2E_SEED_DIR` in the child's **env map**, never in argv and never through a shell, with a non-zero exit or a missing journal THROWING rather than seeding silently (added 2026-09-02). In every form an operator-supplied VALUE appears only as a separate element of an **array-form argv**, after shell-metacharacter rejection, never inside a shell string, and never as the program except through the guarded host-tool form.
- NEVER use the Tauri `shell-open` plugin with scenario-config-derived strings — if the GUI ever opens paths/URLs, set an explicit allow-scope; the unscoped plugin enables RCE via dangerous protocols (`file://`/`smb://`/`nfs://`, CVE-2025-31477 CVSS 9.3). Prefer avoiding the plugin entirely.
- NEVER embed remote-origin iframes in the bundled Tauri webview — iframes can bypass origin checks for IPC even in isolation mode (GHSA-57fm-592m-34r7); combined with custom-protocol origin confusion (CVE-2026-42184) this re-exposes the IPC surface the threat model assumes is in-process-only.
- NEVER ship Tauri commands without a minimal capabilities file — author deny-by-default capabilities allowing ONLY the actual commands (start/stop, scenario/suite picker, run-report view, operator-pause) plus the one live-counter `Channel`; a permissive default exposes unintended IPC.
- NEVER pin the read-back client to a strict newer protocol default — it MUST READ the `initialize` result's `protocolVersion` (Pulse's hand-rolled server version) and HOLD it against the manifest-pinned `2024-11-05`, surfacing a difference as the distinct `Blocked` precondition, and tolerate minimal capabilities. The hand-rolled client does not negotiate a version down from a default of its own — it reads what the server reports and asserts against the pin; a strict-newer default is the silent-mismatch class the preflight exists to prevent (Established Decisions: MCP Read-Back Client).
- NEVER follow symlinks when changing permissions during crate extraction on a pre-1.94.1 toolchain — bump `rust-toolchain.toml` to ≥ 1.94.1 to clear the tar-rs symlink-chmod flaw in the `cargo build` extraction path (CVE-2026-33056 / RUSTSEC-2026-0033) and keep `Cargo.lock` committed.

### Universal

- NEVER run `cargo build --release` (the release gate) or merge to the dev OS target without `cargo-audit` (and recommended `cargo-deny`) green — the dependency/supply-chain audit IS the Minimal-tier residual-risk control for the `bundled`-SQLite-from-C + OTLP/gRPC/MCP tree (Threat Model Summary § tier justification).
- NEVER let `Cargo.lock` drift or go uncommitted — it makes the `cargo-audit`/`cargo-deny` scan non-deterministic and lets the `bundled` SQLite C version float past advisory tracking (security-research.md cargo-audit + rusqlite findings).
- NEVER add a scenario without a Pulse P-ID, and NEVER introduce an inbound network listener of Conductor's own **into the shipped binaries** — both violate the architecture's scope law / trust boundary and silently widen the attack surface beyond the loopback-client model (Cross-cutting Patterns: Scope law, Trust boundary). The dev-only driver stack's harness-lifetime loopback ports (`4444`/`4445`) — bound by the `--e2e` routine arm, the `a11y:driven` driven arm and the `sr*` screen-reader suites alike — sit outside this ban: they belong to tauri-driver / the native WebDriver, exist only for the leg, and are absent from `conductor-cli` / `conductor-tauri`.
- NEVER let a malformed child/transport input panic — `tonic::Status` codes and MCP error responses are first-class typed verification inputs routed through the verdict/error wall (`Ok(Verdict/ReportState)` vs `Result::Err` for harness faults only); a panic on the read-back path corrupts run classification.
- The ban below scopes to a preflight that is INVOKED. `scripts/agent-run.{sh,ps1}` `boot` runs `conductor preconditions` as a leading arm and short-circuits on non-zero, SKIPPING the preflight entirely — so on that path an unmet precondition mints no `ReadyState`, no `Verdict`/`ReportState` and no `blocked` row. The probe's own properties are unaffected and stand: it is non-mutating (client-only `:4317` connect, no spawn, no env write) and exits non-zero naming every unsatisfied subject. **The "not a downgrade" reading HOLDS again as shipped, and the withdrawal is retired:** the probe grades the PATH-valued `ANDROMEDA_PULSE_DATA_DIR` by presence through `conductor_core::handle_declared` (the two flag handles keeping the truthy gate via the value-only `flag_declared`), so `handles-declared` is satisfiable, the short-circuit fires only on a genuinely unmet subject, and `boot` reaches the MCP readiness gate. As measured at `conductor-0.2.0/chunks/2026-09-04-preconditions-probe-reads-path-handles-by-presence/report.md`: `conductor preconditions` exit 0 (2026-09-04T17:07Z), then `ReadyState` emitted with `ready: true` / `canary_round_trip: "ok"` / `blocked_precondition: null` / 4-of-4 tools / `data_dir: "<redacted>"` in BOTH harness shells (bash 17:07:17→17:08:04Z · pwsh 17:11:16→17:12:03Z), zero `skipped preflight` lines in either, with no edit to `scripts/agent-run.sh` or `.ps1`. This SUPERSEDES the 2026-09-04T06:41Z `sr-findings-remediation` reading, which measured the pre-fix state.
- NEVER silently downgrade a failed preflight to pass/fail/manual-check — each of the gate's FIVE named preconditions (version mismatch / missing tool / no incident opened after the canary storm was emitted / app-sidecar workspace-key agreement / unmet run-contract terms) MUST surface as the distinct `blocked` state with its own named precondition string, never a false pass and never the generic corpus-empty string (Standard Contracts: Readiness gate). The run-contract arm composes ONE string naming each unmet term individually, carrying the condition AND its candidate causes — a term whose truth lives on the SUT's side is recorded `declared-not-observable` and never blocks, because blocking on it would assert a measurement Conductor cannot make. The keychain read-while-write fault is NOT among them — the P-049 encrypted-at-rest assumption was disproved live (`corpus.db` is plaintext SQLite), so that canary mode does not apply.
- NEVER add `unsafe` across the OTLP/gRPC/SQLite FFI boundary without review — safe Rust + `current_thread` tokio give memory/data-race safety for free, but the `bundled`-SQLite C and raw-protobuf/tonic codegen are the FFI surface the language cannot check (use `cargo-geiger` 0.13.0 ad-hoc to map `unsafe`; keep `libsqlite3-sys` current — security-research.md Rust/tokio + cargo-geiger findings).
- NEVER skip bumping a pinned dependency flagged by research — `tauri` ≥ 2.10.3 (origin-confusion CVE-2026-42184) and the toolchain ≥ 1.94.1 (tar-rs) are required bumps over the architecture's current 2.10.1 / MSRV 1.88.0 pins.
