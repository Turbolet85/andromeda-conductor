**Test tier:** `Minimal (0)`
_Justification: The passed `security_tier` is Minimal (0) (single-developer, local-only, no-cloud, no-auth, zero network exposure, only self-generated synthetic data) and the product is effectively a single primary surface (the cli release gate) with no persistent USER data — the lone store (`runs.db` + JSONL) holds only synthetic telemetry classified `low`. These place it below Standard. However, this is Minimal at the upper boundary: 8 workspace crates plus several capability surfaces (>5 entities), 7 critical paths, and a Creator-Brief mandate for "production-grade verification rigor" with a determinism hard-bar and an assertion-policy split — so the Minimal baseline is augmented with the Section 5 coverage triggers (security-vector negative-tests, deterministic-replay property/golden tests, MCP contract test, cross-surface parity, bounded fault-injection) without escalating to Comprehensive (which the project disqualifies itself from: NOT a load-tester, no multi-target/distributed, local-only, mobile N/A)._

**Test harness requirements:**

- **5-command requirements:**
  - `boot` — Conductor itself has **no daemon / no inbound listener** (security: "zero network exposure ... no inbound listener of its own"); `boot` reduces to a **preflight readiness gate** (arch Standard Contracts) that asserts the MCP `initialize` handshake (protocol `2024-11-05`), required-tool presence vs. pinned manifest, and a data-dir canary round-trip. Readiness signal: preflight returns `ready:true`; `ready:false` ⇒ all dependent scenarios report `blocked` (never silently downgraded — security). Precondition: live Pulse + `mcp-server` feature reachable (Creator Brief prerequisite).
  - `run` — invokes the scenario catalog: per-P-ID scenarios (over the manifest’s accepted set) and/or the three named dynamic scenarios (`error-baseline-spike`, `fingerprint-storm`, `restart-suppression`) plus `pii-scrub`, `connection-lifecycle`, `severity-lifecycle` (Creator Brief Must-Work). Exit-code semantics: 0 = all checks Pass; non-zero = at least one hard `Fail`; `blocked`/`ManualCheck`/`KnownResidual`/`CalibrationRegion` are reported states, NOT process-failure exits (assertion-policy split: model-interpretive claims are "calibration-region checks + report-for-human, never hard-failed" — Creator Brief Risk Tolerance). Runs `cargo build` + `cargo nextest`/`cargo test` (incl. golden tests) + `cargo clippy` in CI (arch CI/CD).
  - `status` — structured-state query via the Run report envelope (arch Standard Contracts), polled per-check. Fields the agent polls: `run_id`, `seed`, `scenario`, `p_ids`, `verdict ∈ {Pass, Fail, CalibrationRegion}`, `state ∈ {Pass, Fail, ManualCheck, KnownResidual, Blocked}`, `latency_ms`, `slo_tier`, `journal_emitted_at`, `read_back_observed_at`, `fingerprints`. Mechanism: read the `runs.db` row (embedded SQL) and/or the per-run JSONL journal — no HTTP endpoint exists (no listener).
  - `cleanup` — teardown of per-run on-disk artifacts (`runs/<run_id>.jsonl`, `runs/<run_id>.md`) and `runs.db` rows; must be idempotent (re-running a clean state is a no-op). Conductor must NOT touch Pulse (Creator Brief: "NO Pulse process management"). The `:4317` port-occupier fault (security Vector 6) must release its bind on cleanup. Agent verifies cleanup via file-absence check + `runs.db` row-count query.
  - `logs` — the **emission journal** is ground truth: per-run `<run_id>.jsonl` under `runs/`, wall-clock-stamped via `std::time::SystemTime`/`Instant` (security: "Writing journal/report wall-clock stamps from tokio's virtual clock — rejected") — this is "the left side of every SLO check" (Creator Brief). Plus sanitized stderr (Design System cli "Error output"). Retention: per-`run_id`, append-mostly on disk.
- **Status endpoint shape:** No HTTP/IPC status *endpoint* (no listener). The agent-parseable equivalent is the Run report envelope JSON / `runs.db` row: `{ run_id: string, seed: number, scenario: string, p_ids: string[], verdict: "Pass"|"Fail"|"CalibrationRegion", state: "Pass"|"Fail"|"ManualCheck"|"KnownResidual"|"Blocked", latency_ms: number, slo_tier: string, journal_emitted_at: timestamp, read_back_observed_at: timestamp, fingerprints: ... }` (arch Standard Contracts, Run report envelope). Artifacts must NOT leak absolute host paths or internal struct names (security).
- **Log format:** Structured JSONL — per-run journal is one JSON object per line (arch Test-Relevant Conventions: "per-run JSONL journals stemmed by `run_id`"); agent-parseable with jq / serde. Markdown report (`<run_id>.md`) is the human/agent prose mirror sharing the same envelope fields.
- **PID file location:** N/A — no daemon (security: "no inbound listener of its own"; arch: `conductor-cli` is a one-shot `#[tokio::main(flavor="current_thread")]` binary, not a long-running service).
- **Test data strategy:** Self-bootstrapping via **deterministic seeded synthetic generation** — `conductor-timeline` produces the same stream shape for the same scenario+seed (Creator Brief: "Deterministic under a seed"); no developer-seeded DB. Config fixtures are declarative scenario files (serde + garde) one-per-P-ID under `scenarios/` (arch Test-Relevant Conventions). Golden tests assert envelope/journal shape via cargo-nextest (security data-classification hint). Two scenario families (P-032/P-036) require a real git workspace with known recent commits (Creator Brief environment requirement).

## 3. Test Harness Contract

_[ALL tiers — central agent-driven mechanism; Section consumed by
setup-project to materialize scripts/agent-run.{sh,ps1}]_

Architecture committed to the harness pattern: **agent-driven — the headless `scripts/agent-run.sh` path is the source of truth and the release gate; the GUI is a thin shell over the same core commands** (upstream-context arch Test Harness Commitment). This section specifies the concrete contract. Conductor has **no daemon and no inbound listener** (security: "zero network exposure ... no inbound listener of its own"), so `boot` is a preflight readiness gate and `status` reads disk artifacts — there is no HTTP/IPC status endpoint.

### 5-command implementation

**`boot`** — preflight readiness gate (no daemon to start):
- Command body: `cargo run -p conductor-cli --bin conductor -- preflight --json` — runs the MCP `initialize` handshake through the hand-rolled JSON-RPC client over the spawned sidecar's stdio (arch Standard Contracts: asserts the `protocolVersion` read back from that result against the pinned `2024-11-05`, required-tool presence vs. pinned `contracts/` manifest, then round-trips a canary incident via `query_incident_list` to prove data-dir wiring). In CI the live-Pulse leg is unavailable, so `boot` runs against the hand-rolled `stub_pulse_mcp` child binary (test-research Mocking) which returns a `ready:true` canary; the live-Pulse leg is `workflow_dispatch`/local-only gated on `ANDROMEDA_PULSE_MCP_ENABLED`.
- Readiness signal: stdout JSON `{"ready": true}`; `ready:false` ⇒ every dependent scenario reports `state="Blocked"` with the named precondition string (security anti-pattern: never silently downgrade a failed preflight to pass/fail/manual-check).
- Exit code: 0 on `ready:true` within timeout; non-zero on handshake failure (transport refused surfaces as `Result::Err`, a harness fault — security Vector 5).
- Timeout: **two budgets, both derived — never a literal.** (a) The *in-process* canary poll: `CONDUCTOR_PREFLIGHT_TIMEOUT` seconds (default 30) for the MCP `initialize` + canary round-trip, raised to the run contract's effective floor — `contracts/pulse-run-contract.toml` `[incident_formation].min_canary_poll_seconds`, which must outlast Pulse's L3 digest cadence — so the live-Pulse leg must allow at least that floor. (b) The *wall-clock wrapper* `scripts/agent-run.{sh,ps1}` `boot` applies around `conductor preflight`: both shells derive it per invocation from the same contract as `warmup_ms/1000 + poll + margin`, because the warm-up pre-roll runs BEFORE the poll starts and a wrapper set to the poll alone kills the run mid-poll. A missing contract term is a hard exit 2, never a silent default; a lowered `CONDUCTOR_PREFLIGHT_TIMEOUT` clamps up to the floor. The stub leg still completes in <1s (it drives `CanaryPoll::immediate()`, so no real clock is involved).

**`run`** — invoke test suites + scenario catalog:
- Command body (CI build+test gate, arch CI/CD): `cargo nextest run --workspace --profile ci` (cargo-nextest 0.9.137 → JUnit XML at `.config/nextest.toml` `[profile.ci.junit]`) then `cargo test --workspace --doc` (nextest does not run doctests — test-research baseline-fallback note) then `cargo clippy --workspace --all-targets -- -D warnings`. Scenario invocation: `cargo run -p conductor-cli --bin conductor -- run <scenario|P-ID> [--seed <s>]` for the named dynamic scenarios (`error-baseline-spike`, `fingerprint-storm`, `restart-suppression`, `pii-scrub`, `connection-lifecycle`, `severity-lifecycle`) and per-P-ID scenarios; `conductor suite` for the full catalog. The harness scenario leg (`SCENARIO=<name|P-ID> [SEED=<n>] scripts/agent-run.{sh,ps1} run`) appends `--seed` ONLY when `SEED` is explicitly set — with it unset the TOML-declared seed governs (arch files-over-env-defaults precedence; identical `.sh`/`.ps1` semantics) and the envelope records the effective seed.
- Exit code semantics: 0 = all checks `Pass`; non-zero = at least one hard `Fail` (cargo-nextest `NextestExitCode` 100); `blocked`/`ManualCheck`/`KnownResidual`/`CalibrationRegion` are reported states in the envelope, NOT process-failure exits (Creator Brief assertion-policy split: model-interpretive claims are "calibration-region checks + report-for-human, never hard-failed").
- Output format: machine-parseable — cargo-nextest `ci` profile JUnit XML (parsed by `dorny/test-reporter` into PR annotations) for the test gate; the Run-report envelope JSONL/`runs.db` row for the scenario leg.
- Test selection (fast iteration): `cargo nextest run -p conductor-<seam>` for a single seam crate; `cargo nextest run -E 'test(<name>)'` for a single test; `conductor run <P-ID> --seed <s>` for one scenario.
- CI stage selectors: the `run` command takes mutually-exclusive `--unit` / `--integration` / `--e2e` flags so the Section 9 pipeline can split it into parallel stages (`--unit` ⇒ the `cargo nextest run --workspace --profile ci` leg only — `cargo test --workspace --doc` and `cargo clippy` are their own separate Section 9 stages (Doctest / Lint), NOT folded into `--unit`; `--integration` ⇒ the hand-rolled MCP stub + `tauri::test` mock-runtime + in-memory/`TempDir` `runs.db` leg; `--e2e` ⇒ ensure-frontend, then a release build with `--features tauri/custom-protocol` (a plain `--release` binary loads `devUrl` and measures nothing — the feature, not the profile, decides bundle embedding), then the tauri-driver `wdio run` leg — the ROUTINE suite only (wdio default `specs` narrowed to `accessibility.e2e.ts` on 2026-09-01; the `driven` suite sits outside the 5-command harness as the operator leg described in §6/§9), with the tauri-driver child spawned at `cwd` = the workspace root so the app's `resolve_under` can reach `scenarios/` (it rejects absolute paths and `..`, so the launch cwd is the only lever), and the mocha ceiling raised 60s → 15min because wdio enforces `mochaOpts.timeout` itself — headless under `xvfb` on Linux CI, headful on the Windows host). **The leg SEEDS its own subject before the session** (2026-09-02): `wdio.conf.ts`'s `seedFixtureRuns()` clean-re-creates the gitignored `runs/e2e-fixture/` and invokes `cargo test -q -p conductor-run --test envelope_fixture` with `CONDUCTOR_E2E_SEED_DIR` naming that repo-relative dir, so the subject — the committed lamps journal's records PLUS an over-envelope `run_envelope` row — is written through the production writer (`conductor_run::persist`) rather than copied; a non-zero exit or a missing journal THROWS rather than seeding silently. The tauri-driver spawn then carries `CONDUCTOR_RUNS_DIR=runs/e2e-fixture` (repo-relative — `resolve_under` rejects absolute handles), because `/runs/` is gitignored and an unseeded clean tree gives the coverage rows no run record to render; without it the populated-lamp assertions would have no subject on CI and would read host-local run residue on a dev box. The 5-command surface, the `status` disk read and the envelope/JSONL shapes are unchanged, so §3 ↔ obs-plan §3 still agree. With no flag, `run` executes the full aggregate (nextest + doctest + clippy + scenarios); per-stage target mapping is the Section 9 pipeline table.

**`status`** — query product state (disk artifact read; no listener):
- Command body: `jq -e '<predicate>' runs/<run_id>.jsonl` for a shell-level CI smoke gate (jq -e exits 1 on a `false`/`null` last output, 4 on parse error — test-research serde_json+jq), OR an in-process `rusqlite::Connection::open` + bound-parameter `SELECT` of the `runs.db` row for typed assertions. No `curl`/HTTP — there is no inbound listener.
- Polled fields: the Run-report envelope (see Status endpoint shape below) — `run_id`, `seed`, `scenario`, `p_ids`, `verdict`, `state`, `latency_ms`, `slo_tier`, `journal_emitted_at`, `read_back_observed_at`, `fingerprints`.

**`cleanup`** — tear down per-run artifacts:
- Command body: `rm -f runs/<run_id>.jsonl runs/<run_id>.md` + bound-parameter `DELETE FROM runs WHERE run_id = ?1`, `DELETE FROM run_check WHERE run_id = ?1` and `DELETE FROM run_envelope WHERE run_id = ?1` on `runs.db` — teardown covers every table a run writes, or cleanup leaves orphans (rusqlite bound parameters — security anti-pattern bans `format!`-built SQL). In tests this reduces to dropping the `assert_fs::TempDir` sandboxing `CONDUCTOR_RUNS_DIR`. Conductor must NOT touch Pulse (Creator Brief: "NO Pulse process management"). The `:4317` port-occupier fault (security Vector 6) releases its `TcpListener` bind on cleanup.
- Idempotency: cleanup MUST be idempotent — re-running against a clean state is a no-op (file-absence is not an error; `DELETE` of zero rows succeeds).
- Verification: `assert_fs` `.assert(predicate::path::missing())` on `runs/<run_id>.{jsonl,md}` + `SELECT count(*) FROM runs WHERE run_id = ?1`, `... FROM run_check ...` and `... FROM run_envelope ...` each returning 0 + a `TcpListener::bind("127.0.0.1:4317")` succeeding (proving the port-occupier released).

**`logs`** — fetch product logs (emission journal is ground truth):
- Command body: read `runs/<run_id>.jsonl` (the per-run emission journal — "the left side of every SLO check", Creator Brief) directly; sanitized stderr from the CLI subprocess captured by `assert_cmd` `.get_output().stderr`. The journal is emitted via `tracing_subscriber::fmt().json().flatten_event(true)` (test-research Structured Log Parsing), one JSON object per line, with wall-clock stamps from `std::time::SystemTime`/`Instant` (NOT tokio's virtual clock — security anti-pattern).
- Format: see Log format below.
- Retention window: per-`run_id`, append-mostly on disk; tests read the whole journal file for the run under assertion (no rotation needed — bounded synthetic runs).

### Status endpoint shape

```json
{
  "run_id": "string", "seed": 0, "scenario": "string", "p_ids": ["P-001"],
  "verdict": "Pass | Fail | CalibrationRegion",
  "state": "Pass | Fail | ManualCheck | KnownResidual | Blocked",
```

### Log format

- **Format:** structured JSONL — one JSON object per line (arch Test-Relevant Conventions: "per-run JSONL journals stemmed by `run_id`"), emitted by `tracing-subscriber` 0.3.x `format::Json`.
- **Required fields:** `journal_emitted_at` (ISO-8601 from `std::time::SystemTime` — NOT virtual clock), plus the envelope identity fields (`run_id`, `seed`, `scenario`, `p_ids`, `verdict`, `state`, `latency_ms`, `slo_tier`, `fingerprints`). NO absolute host paths, NO internal struct names (security anti-pattern; asserted by a negative test on the journal).
- **Agent parsing:** `runs/<run_id>.jsonl` carries TWO report-seam record shapes — the **run envelope line** (the eleven envelope fields, byte-unchanged) and the **per-check `CheckRecord` line** (`run_id` · `scenario` · `check_index` · `kind` · `verdict` · `state` · `latency_ms` · `deadline_ms` · `budget_ms`; `budget_ms` null when the check inherits its tier, and a blocked or declare-only scenario emits none). Every line is parseable with `jq -c`; a typed parse DISCRIMINATES the shape — `serde_json::from_str::<RunReportEnvelope>(line)` targets the envelope line specifically, not every line. Both are report-seam records, so obs-plan §3's self-obs-line vs run-report-envelope split is unaffected. NEVER multi-line — `tracing` JSON flattening serializes everything onto one line.
- **Self-obs stream is a distinct artifact:** the `tracing` self-observation log stream (cli: stderr / `logs/agent-latest.jsonl`; Tauri backend: `logs/conductor-tauri.jsonl`) carries per-line base fields — `timestamp_ms`, `level`, `target`, service-identity (`service.name`/`service.version`/`deployment.environment`), `run_id` — per obs-plan §3. It is SEPARATE from this per-run emission journal (`runs/<run_id>.jsonl`, the SLO ground truth + the Run-report envelope above); the two schemas must not be conflated. The stream carries **two line variants over that one base set**: the **event line** (any `tracing` event record — `message` plus its allowlisted fields — at whatever level obs-plan §11's policy assigns that call site, so a hot-path line sits at `debug` where `info` is banned) and the **span-lifecycle line**, which adds `span` (the bounded §4 span name), `span_event` (`new` | `close`), an optional `parent` (the enclosing span's name, absent on a root), and — on the `new` line only — the span's own allowlisted attributes. Both variants are still the self-obs base line, so obs-plan §3's two-record-shapes split (self-obs line vs Run-report envelope) is unchanged, and a span attribute is gated by the same `conductor-core::redact` allowlist as any event field.

## 4. Unit Test Strategy

**Framework:** cargo-nextest 0.9.137 (`cargo nextest run`; `nextest-metadata` 0.12.x for the machine-readable contract) as the primary runner — stable `NextestExitCode` enum + `ci`-profile JUnit XML; `cargo test --doc` (Rust toolchain ≥ 1.94.1) as the doctest fallback nextest does not run. **`cargo test -p <crate>` (full, non-doc) is additionally a standing runner-portability gate** — the suite must be green under BOTH runners, and only the shared-process runner can produce that evidence: a test relying on nextest's per-test process for isolation passes there and fails here, which is a determinism break under §10, not a runner quirk.
**Coverage tool:** cargo-llvm-cov 0.8.7 (`cargo llvm-cov nextest --lcov`) — first-class nextest integration, LCOV/Cobertura/JSON output, `--fail-under-lines` exit-code gate.
**Mutation instrument:** cargo-mutants 27.1.0 — an operator/local audit instrument, NOT a CI stage (§9) and NOT a numeric threshold (§10). Run discipline, each item measured rather than assumed: `-f` resolves from the **workspace root**, so always pass the full crate path (`-f crates/<crate>/src/<file>.rs` — a package-relative path under `-p <crate>` silently matches nothing); `--test-tool=nextest` is REQUIRED (the default `cargo test` aborts the run in an unmutated tree wherever a test is not runner-portable); **`Found 0 mutants to test` is a NO-OP, never a pass** — it exits 0 with only a `WARN` and is indistinguishable from a clean run unless the tallies are read; **the exit code carries no verdict in either direction — a NON-zero exit reflects surviving/timeout CLASSES, not run failure** (measured **exit 3** on a run that fully met its acceptance — 0 missed, every named survivor killed, the non-zero owed entirely to two pre-existing timeouts), so gate on the tallies read out of `mutants.out/` (`missed.txt` empty + the named survivors present in `caught.txt`), never on the exit code; output goes to a gitignored `mutants.out/` (the audit skill redirects with `--output`, an ad-hoc scoped re-run does not).
**Coverage target:** see Section 10 Quality Gates for the Minimal-tier threshold.

**Tool-version policy:** the external-CLI tool versions named in this section (cargo-nextest, cargo-llvm-cov, cargo-mutants) are reference floors, not exact pins — they live outside `Cargo.lock`, so any install that runs the gate green satisfies it (the same floor logic the security-plan applies to cargo-audit / cargo-deny, §Dependency Security). The crate dev-deps (rstest · proptest · insta · assert_cmd · assert_fs · predicates) are caret-resolved with `Cargo.lock` authoritative; their exact resolved versions drift build-to-build and are not pinned in this prose.

**Conventions** (from upstream-context Test-Relevant Conventions):
- Test file location: crate-local `#[cfg(test)] mod tests` inside each `conductor-<seam>` source file, plus crate-local `tests/` for slower in-crate integration (arch per-seam isolation).
- Test function naming: snake_case `fn` under `#[test]` / `#[tokio::test]` / rstest `#[rstest]`.
- Test grouping: per-seam crate boundary is the primary grouping (`cargo nextest run -p conductor-<seam>`); rstest `#[case]` rows group table-driven variants (P-ID catalog, garde valid/invalid matrix).

**Fixture pattern at unit level:** rstest 0.26.1 — `#[fixture]` for the seeded `conductor-timeline` generator (no developer-seeded DB), `#[rstest]` + `#[case]` for table-driven P-ID and garde-config matrices, `#[once]` for the in-memory `runs.db` schema, and `#[future]` + `#[awt]` for async fixtures matching `#[tokio::test(flavor = "current_thread")]` on `conductor-timeline`/`conductor-verify`.

**What unit tests cover** (per testable entity from test-scope Sec 1):
- **conductor-core:** engine logic in isolation (pure library; `cargo nextest run -p conductor-core`).
- **conductor-timeline:** deterministic phase scheduling under `#[tokio::test(flavor="current_thread", start_paused=true)]` + `tokio::time::advance` — same seed ⇒ same stream shape (also the property-test target, Section 7).
- **conductor-emit:** OTLP struct construction + byte-level encoding in isolation (egress liveness is local-gate-only, not unit).
- **conductor-faults:** ramp/silence/fingerprint generators as pure seeded functions (same seed ⇒ same shape); the `:4317` port-occupier bind/release is a chaos/integration concern (Section 8).
- **conductor-verify:** verdict logic + preflight state mapping (`ready:false ⇒ blocked`, `degraded_mode ⇒ KnownResidual`, an empty corpus OR a stale one — no incident newer than the canary's emission stamp — ⇒ `blocked`) against the hand-rolled `stub_pulse_mcp` (`conductor-verify/tests/common/mod.rs`).
- **conductor-report:** Run-report envelope serialization + JSONL journal shape + `runs.db` row mapping (canonical line shape golden-locked via exact-string `assert_eq!` at unit level — matching the `verdict.rs`/`report_state.rs`/`scenario.rs` serialization-golden pattern; insta is the E2E journal-golden mechanism with `run_id`/timestamp redaction, §6/§7).
- **conductor-tauri/ui (frontend SPA):** no Rust/nextest unit tests — the React 19 + Tailwind token bundle is **build-gated** (`tsc --noEmit` + `vite build` + `npm audit` + a `vite preview` render smoke). **That gate does NOT prove ESM loadability:** `__dirname` in a `"type": "module"` package typechecks cleanly under the node types and still fails to load on every host (measured 2026-09-01, on a `wdio.conf.ts` that had been committed since 2026-06-27), so the e2e harness config and its members are proven only by EXECUTING the wdio leg that LOADS them, never by the build gate — `--e2e` proves the routine suite, `npm run a11y:driven` proves the `driven` suite, `npm run a11y:sr` / `a11y:sr-empty` / `a11y:sr-error` prove the screen-reader members (`nvdaExe` / `startNvda` / `stopNvda` / `invokedSuites` / `SR_SUITES` / the per-suite spawn env — 3/3 sessions 2026-09-02), and a `wdio.conf.ts` member reachable from NONE of them is as unproven as it was under the build gate (default `specs` narrowed to the routine file 2026-09-01). A JS/TS unit runner is not adopted (GUI is convenience-only — §12 Decisions Log); frontend coverage (webview E2E via tauri-driver) is deferred to Epoch 9. Realized in 2026-06-15-design-token-typography-bundle.
- **Scenario-config validation surface:** garde `range` + `#[garde(custom)]` cross-field rules with valid/invalid fixtures (also property-tested, Section 7).
- **Error-handling surface:** thiserror typed per-seam enum mapping + the `anyhow` edge sanitization invariant (no internal details leaked).
- **Scenario catalog + coverage-matrix:** static assertion that every catalog scenario carries a P-ID and the generated `coverage-matrix.md` enumerates every capability in the SUT capability manifest with zero unclassified entries.
- Edge cases + invariant assertions per seam.

**What unit tests do NOT cover** (handled at higher levels):
- Integration boundaries — MCP read-back stub stdio, Tauri command/Channel, `runs.db` cross-process (Section 5).
- E2E flows — cli subprocess + desktop-webview critical paths (Section 6).
- External services — live Pulse / `andromeda-pulse-mcp` sidecar (mocked via the hand-rolled MCP stub at unit/integration; live leg is local-gate-only).

## 11. Test Anti-Patterns (NEVER do these)

_[ALL tiers — single source of truth for all test bans]_

### Test Strategy

- NEVER violate the test pyramid — heavy E2E with sparse unit tests is slow + brittle; the per-seam `cargo nextest run -p conductor-<seam>` unit layer is the bulk, E2E is the 7 critical paths only.
- NEVER over-mock at integration level (you stop testing the integration — e.g., do not fake the `runs.db` instead of using rusqlite `open_in_memory()`).
- **(stack-specific)** NEVER fake Pulse's *reaction* as a CI verdict — the hand-rolled stub canary proves MCP wiring only; Pulse's actual behavior is a live/local-gate assertion (Creator Brief: validates Pulse "from the outside, as a real workload").
- **(stack-specific)** NEVER escalate to load/saturation testing — bounded P-060 "typical/high" profiles only; 50k+ spans/sec is Pulse's `perf_load_profiles.rs`, explicitly out of Conductor scope.

### Unit

- NEVER test implementation details (private fns / internal struct fields) — test the public seam API + observable behavior (envelope/verdict/state output).
- NEVER write brittle assertions against fixture-internal values — assert on the Run-report envelope contract.
- **(stack-specific)** NEVER assert on a real wall-clock duration in a `conductor-timeline` test — drive `tokio::time::advance` under `start_paused = true` and assert scheduled ordering/shape, not real elapsed time.

### Integration

- NEVER mock the DB at integration level — use rusqlite `open_in_memory()` (in-memory) or `assert_fs::TempDir` (file-backed for cross-process), never a hand-rolled SQL fake.
- NEVER skip cleanup between integration tests — fresh in-memory `runs.db` per test (nextest per-process model); never share a mutable file DB across parallel tests without per-test `TempDir`.
- **(stack-specific)** NEVER build `runs.db` SQL via `format!`/string concatenation — use rusqlite bound parameters even for synthetic data (security anti-pattern); a negative/static test asserts this.
- **(stack-specific)** NEVER rely on nextest's per-test process to isolate a test from a **process-global, first-install-wins singleton** — the `conductor_core::init_observability` subscriber is the shipped case. A per-test `TempDir` sink does NOT isolate it: whichever test installs the subscriber first owns the sink, and every concurrent sibling's events land in that file. The remedy is a test binary of its own (`cargo test` gives each `tests/*.rs` its own process, and nextest is already process-per-test, so one file per such test holds under BOTH runners) — never serializing the file (`--test-threads=1` / a profile knob), which hides the shared-state defect rather than removing it (§10). The nextest-per-process rationale restated in §3 / §5 / §7 / §9 stays valid for `runs.db` / `TempDir` isolation; it is not a guarantee for process-global state.

### E2E

- NEVER use xpath selectors — use role / data-testid / text + brand anchors (`[PASS]`/`[FAIL]`/`[HOLD]` labels, `role="alertdialog"`, `aria-live`, "HOLD — operator pause" heading text, P-ID tokens).
- NEVER use `sleep(N)` for synchronization — wait for an explicit signal (envelope `state` field, JSONL journal line, element role/`aria-live`, exit code).
- NEVER use brittle selectors that drift across iterations (hashed Tailwind/CSS class names) — the Color-Only a11y rule guarantees text/role pairing, so use that.
- **(stack-specific)** NEVER treat a `blocked`/`ManualCheck`/`KnownResidual`/`CalibrationRegion` state as a non-zero process exit — those are reported envelope states, not hard `Fail` exits (Creator Brief assertion-policy split); only a hard `Fail` is a non-zero exit.

### Test Data

- NEVER use production data in tests — only self-generated synthetic OTLP from the seeded `conductor-timeline` generator (there is no user data; synthetic-only by classification).
- NEVER share mutable state across parallel tests — in-memory `runs.db` / `TempDir` per test.
- NEVER use non-deterministic generators without seed control — `conductor-timeline` seed + proptest strategies with `proptest-regressions/` persistence.
- **(stack-specific)** NEVER stamp the emission journal/report from tokio's virtual clock — use `std::time::SystemTime`/`Instant`; a paused-clock leak into the ground-truth artifact corrupts SLO checks (security anti-pattern) and must be caught by a golden test.

### Mocking

- NEVER mock what you don't own without an abstraction layer — wrap the live Pulse behind the hand-rolled JSON-RPC stdio client seam; do NOT monkey-patch `andromeda-pulse-mcp`.
- NEVER over-stub (you stop testing real behavior) — the cli release-gate scenarios run the real binary via assert_cmd.
- NEVER monkey-patch production code at runtime — use DI (stdio-transport injection into the hand-rolled client, tokio built-in virtual clock, ephemeral-port tonic server).
- **(stack-specific)** NEVER force-fit wiremock-rs onto the gRPC OTLP egress — `tonic` is gRPC, not HTTP/1; use an in-process tonic test server or turmoil; reserve wiremock for any future HTTP surface only.
- **(stack-specific)** NEVER interpolate `ANDROMEDA_PULSE_DATA_DIR` (or any operator value) into the sidecar argv/shell — pass strictly via `.env(...)` after rejecting injection metacharacters; spawn `andromeda-pulse-mcp` as a fixed hard-coded program NAME resolved through the inherited `PATH` (rmcp STDIO injection class CVE-2026-30623); a negative test asserts argv-injection rejection.

### CI

- NEVER run sequentially when parallelizable — unit + integration are parallel-safe under nextest's per-test process model with proper `runs.db`/`TempDir` isolation.
- NEVER skip dependency caching (`~/.cargo` + `target/` keyed on `Cargo.lock`) — slows the agent feedback loop.
- NEVER ignore flaky tests — quarantine and fix immediately; do NOT set nextest `retries`.
- **(stack-specific)** NEVER merge / `cargo build --release` without `cargo audit --deny warnings` + `cargo deny check` green and a committed un-drifted `Cargo.lock` (Minimal-tier residual-risk control); NEVER run the live-Pulse scenarios as a CI gate (operator/local only — `workflow_dispatch`, `scripts/agent-run.sh`, a cargo-feature-gated test invoked directly, or an npm-script wdio suite such as `a11y:driven`, per §9).

### Quality

- NEVER add retry-once policies for flaky tests (masks real failures; determinism is enforced upstream).
- NEVER lower the coverage threshold to pass the build (raise quality, not the bar — keep `--fail-under-lines 60`).
- NEVER skip quality gates "just this once" (audit-green + coverage + clippy are binding).

### Universal (agent-driven specific)

- NEVER use Percy / Chromatic / Applitools (visual regression with human review) — assert role/text/`aria-live` only; `drive+observe` visual go/no-go is the flagged-untestable operator step.
- NEVER include a manual smoke step ("developer verifies before deploy") — except the explicitly-flagged `drive+observe` operator checklist, which is a product feature, not a test step.
