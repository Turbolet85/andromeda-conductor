## Gotchas

## MCP protocol version is READ from `initialize` and held against the pinned 2024-11-05
**What breaks:** Pulse's MCP server is hand-rolled JSON-RPC speaking the older `2024-11-05` protocol with a minimal `capabilities` object; pinning a strict newer protocol default silently mismatches and read-back fails (the exact silent-mismatch class the preflight exists to catch).
**How to avoid:** Pin the expected version at `2024-11-05` in the `contracts/` manifest and READ the negotiated one from the `initialize` result — Conductor's client is hand-rolled line-delimited JSON-RPC (rmcp removed 2026-06-27), so there is no client-library default to drift from; the preflight asserts the negotiated version.
**Fix if broken:** Surface as `Blocked` with the named precondition — never a silent pass.
**References:** architecture.md §Established Decisions [MCP Read-Back Client] / §Standard Contracts; `crates/mcp-server/src/jsonrpc.rs:7` (Pulse).

## Pulse's `tools/call` is non-MCP-compliant — expect a RAW result
**What breaks:** Pulse's sidecar returns the raw tool payload as the JSON-RPC `result`, with no `{content:[…]}` envelope. A typed MCP SDK deserializes that into `ServerResult` and rejects it as `UnexpectedResponse` on *every* live call — which is exactly why rmcp 1.7.0 was removed on 2026-06-27 (it exposes no raw-result escape).
**How to avoid:** Keep the read-back client hand-rolled (`conductor-verify/src/jsonrpc.rs` + `client.rs`) and keep tool results as raw `serde_json::Value`. Test stubs must be faithful to the raw shape, or they will pass against a shape the live sidecar never sends.
**Fix if broken:** Do not re-introduce a typed MCP SDK on this seam.
**References:** architecture.md §Established Decisions [MCP Read-Back Client].

## Data-dir mismatch ⇒ silently-empty read-back
**What breaks:** The sidecar filters incidents by the corpus `workspace` column (**not** a `workspace_root` column). Its VALUE is the key `pulse-app` publishes to `{data_dir}/run/workspace-key` — its detected root — and falls back to `data_dir` only when that file is absent or invalid (measured 2026-09-01, Pulse HEAD `83d4060`), so the old `= data_dir` equality holds only in the fallback case; if `ANDROMEDA_PULSE_DATA_DIR` passed to the spawned `andromeda-pulse-mcp` ≠ the live Pulse's, every `query_incident_list` comes back empty (false pass-as-empty / perpetual blocked). The sidecar keys on `ANDROMEDA_PULSE_DATA_DIR` while `pulse-app` keys incidents on its *detected workspace root*, so a divergence returns zero rows forever — and that is byte-identical on the wire to "Pulse raised no incident", which is why the preflight names both candidate causes rather than claiming a measurement Conductor cannot make.
**How to avoid:** Propagate the live Pulse's `ANDROMEDA_PULSE_DATA_DIR` to the sidecar via `.env(...)`; if Pulse leaves it unset, resolve the identical platform default. The preflight canary round-trips a known incident to prove the wiring before any scenario trusts read-back.
**Fix if broken:** Correct the data-dir; re-run the canary.
**References:** architecture.md §Occupied Resources (Environment variables) / §Standard Contracts (readiness gate); `refs/pulse-mcp-contract.md`.

## Never stamp the journal from tokio's virtual clock
**What breaks:** SLOs are measured journal-relative (`read_back_observed_at − journal_emitted_at`). Stamping from tokio's virtual clock (used for `start_paused` scheduling determinism) corrupts the ground-truth artifact and breaks every SLO check.
**How to avoid:** Wall-clock stamps come ONLY from `std::time::SystemTime`/`Instant`; the virtual clock is scheduling-only. A golden test catches a paused-clock leak into the journal.
**Fix if broken:** Re-stamp from `std::time`; invalidate affected runs.
**References:** architecture.md §Cross-cutting Patterns (Determinism discipline); security-plan §Logging; test-plan §11 (Test Data).

## tonic 0.14 moved prost codegen to tonic-prost-build
**What breaks:** tonic 0.14 split codegen into the `tonic-prost-build` crate; build scripts mining Pulse's prior-art injectors (which predate the split) won't compile against the old build-script API.
**How to avoid:** Use `tonic-prost-build` in build scripts; budget a small adjustment when porting Pulse's `inject_demo.rs` / `load_profiles.rs` patterns.
**Fix if broken:** Migrate the build script to the `tonic-prost-build` API.
**References:** architecture.md §Infrastructure Patterns (Build system).

## bundled SQLite recompiles C from source
**What breaks:** `libsqlite3-sys` with `bundled` compiles SQLite C from source → longer cold builds; a stale/floated C version can drift past advisory tracking.
**How to avoid:** Expect longer first builds; keep `libsqlite3-sys` current so SQLite patch bumps flow in; keep `Cargo.lock` committed so `cargo-audit` can track the C version deterministically.
**Fix if broken:** Bump `libsqlite3-sys`; re-run `cargo audit`.
**References:** architecture.md §Stack (Database); security-plan §Dependency Security.

## Blocked ≠ Fail; null-measurement rows must be excluded from aggregates
**What breaks:** Treating `Blocked`/`ManualCheck`/`KnownResidual`/`CalibrationRegion` as failures, or letting blocked rows (with null `latency_ms`/`fingerprints`) leak into cross-run latency/percentile or P-036 fingerprint-recurrence queries, produces phantom values and false failures.
**How to avoid:** The five report states are distinct; only a hard `Fail` is a non-zero exit. Cross-run queries MUST exclude null-measurement rows. P-032 ships as the first `KnownResidual` (not a surprise failure).
**Fix if broken:** Reclassify; add the null-exclusion predicate to the query.
**References:** architecture.md §Standard Contracts (Run report envelope) / §Established Decisions [Read-Back Dependency Posture]; test-plan §6 (P-032).

## The `:4317` port-occupier is the ONLY deliberate bind
**What breaks:** Promoting the port-occupier fault into a general-purpose listener, or forgetting to release it on cleanup, violates the loopback-client trust boundary and leaves `:4317` occupied for the next run.
**How to avoid:** It is an intentional in-host fault only (P-003); `cleanup` releases the `TcpListener` bind. Conductor's SHIPPED binaries otherwise open NO inbound listener. The dev-only webview a11y legs are the one qualification — the routine `--e2e` arm, the operator-local `a11y:driven` arm and the operator-local `sr*` screen-reader suites, three suite families over the ONE WebdriverIO + tauri-driver stack: their driver stack binds loopback `4444`/`4445` for the harness's lifetime and tears them down with itself — never in `conductor-cli` / `conductor-tauri`. The screen-reader leg additionally spawns the host NVDA named by `CONDUCTOR_NVDA` (no listener).
**Fix if broken:** Release the bind; verify `TcpListener::bind("127.0.0.1:4317")` succeeds post-cleanup.
**References:** architecture.md §Cross-cutting Patterns (Trust boundary); security-plan Vector 6; test-plan §3 (cleanup).

## Tauri generate_context! resolves ui/dist at compile time
**What breaks:** `conductor-tauri`'s `tauri::generate_context!` reads `tauri.conf.json`'s `build.frontendDist` (`ui/dist`) at COMPILE time — so any workspace `cargo build`/`nextest`/`clippy` that compiles `conductor-tauri` FAILS if the webview bundle isn't built first (`ui/dist` is git-ignored → regenerated per environment). A bare `cargo build` does NOT run `beforeBuildCommand` (only the Tauri CLI does).
**How to avoid:** Build the frontend (`npm run build` in `crates/conductor-tauri/ui`) before the cargo gate — wired as the `ensure_frontend` step in `scripts/agent-run.{sh,ps1}` (the `run` verb) + the CI Rust job. Also gitignore `crates/conductor-tauri/gen/` (tauri-build regenerates it each compile) and keep valid `bundle.icon` files present (PNG + ICO — `generate_context!` validates them at compile time).
**Fix if broken:** Run the frontend build, then re-run the cargo gate.
**References:** architecture.md §Infrastructure Patterns (Build system); `.claude/rules/frontend.md`.

## A red `cargo audit` may be the LOCAL advisory-db checkout, not the world
**What breaks:** `cargo audit` fetches INTO the existing `${CARGO_HOME:-$HOME/.cargo}/advisory-db` clone, and a fetch never deletes UNTRACKED files — so a file upstream has moved leaves a stale copy behind and the parse fails on a duplicate advisory id. It reads exactly like an external advisory-database fault and reproduces byte-identically on every tool version, which is what makes it costly: a `duplicate advisory ID: RUSTSEC-2026-0244` red was carried as an external fault for 52 readings across 4 weeks before the checkout itself was inspected (upstream had moved that file to `crates/gettext-rs/` on 2026-08-09, the deferral's first day).
**How to avoid:** Read the checkout's CURRENT state before classifying any parse failure as external — `git -C "${CARGO_HOME:-$HOME/.cargo}/advisory-db" status --porcelain` must print nothing. A clean-checkout witness settles it the other way: CI passed the same step throughout. Only a red reproduced from the world's state enters the tool-fault-vs-database-fault fork.
**Fix if broken:** Clean the checkout (or bypass it — `cargo audit --db <empty dir>` clones fresh), then re-run; a residue red disappears with no dependency change. Post-clean this workspace measures exit 0 (1239 advisories, 562 packages, 17 `deny.toml`-adjudicated allowed warnings — re-measured 2026-09-07 after the indicatif 0.18 bump dropped `number_prefix` and its RUSTSEC-2025-0119 ignore).
**References:** architecture.md §Infrastructure Patterns (Build system); security-plan.md §Dependency Security; `.claude/rules/security.md` (2026-08-09 entry, corrected 2026-09-05).
