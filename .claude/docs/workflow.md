# Development Workflow

_How to work on Conductor day-to-day. Andromeda planning system + agent-driven build loop._

## Git workflow
- **Branch naming:** `feature/{desc}` · `fix/{desc}` · `chore/{task}` · `refactor/{area}`.
- **Commit format:** conventional commits (`feat:`/`fix:`/`chore:`/`refactor:`/`docs:`/`test:`/`perf:`/`build:`/`ci:`).
- **Main branch:** `main`. **Never force-push** main. Feature branch per task.

## Andromeda workflow

This project was planned with the Andromeda greenfield pipeline.

**Initial planning (done):**
1. `/andromeda-arch` — architecture (`.andromeda/architecture.md`).
2. `/andromeda-security`, `-design`, `-tests`, `-obs`, `-a11y` — the 6 specialist plans.
3. `/andromeda-route` — per-version `working-route.md` + seeds `master-route.md`.
4. `/andromeda-setup-project` — this CLAUDE.md ecosystem + harness + operational artifacts.

**Per chunk (main build loop):**
1. `/andromeda-phase` — promote + plan the next chunk from `conductor-0.1.0/working-route.md` (mints its `[marker]`, appends to `master-route.md`).
2. Implement the chunk — write code + tests; drive via `scripts/agent-run.sh`.
3. Verify end-to-end (the chunk is not done until the harness is green and behavior is confirmed).
4. Repeat for the next pending chunk.

The "where am I" cursor is **derived** from `master-route.md`'s last `complete` marker (not stored in state.yaml).

## Daily session lifecycle
- **Start:** `/new-session` (when available) — reads `session-handoff.md`, shows the Andromeda dashboard + the 14 health checks, proposes the next action. If a fresh invocation, read `.claude/session-handoff.md` manually.
- **During:** follow the current chunk's plan; edit → test → iterate; when corrected, the learning is captured at wrap.
- **End / milestone:** `/wrap-session` — commits work, overwrites `session-handoff.md`, reconciles the living docs, curates learnings into the right tier (CLAUDE.md `USER:session-learnings` / `.claude/rules/* ## Session Additions` / `.claude/docs/session-learnings.md`).

Don't skip session boundaries — they keep CLAUDE.md + project knowledge fresh.

## The agent-driven invariant
The headless `scripts/agent-run.sh` path is the source of truth and the release gate; the Tauri GUI is a thin shell over the same core. Every feature must be harness-runnable by an agent reading exit codes + structured JSON — no human-in-the-loop checkpoints (the sole exception is the `drive+observe` operator checklist, which is a product feature, not a build step).

## Code review
- `.claude/agents/code-reviewer.md` is installed — invoke via "review this" / "does this make sense?".
- For significant changes, check alignment with `.andromeda/architecture.md` §Established Decisions.

## Release process
- `cargo build --release` (with `cargo audit` + `cargo deny` green, `Cargo.lock` committed) → optional `cargo tauri build`. Dynamic end-to-end proof against a live Pulse is an operator/local gate, not CI.

## Troubleshooting
- Tests failing? → `.claude/rules/testing.md` + `.claude/rules/verification-harness.md`.
- Hooks not running? → `.claude/settings.json` + verify the tool is installed.
- CLAUDE.md stale? → `/new-session` health check, possibly re-run `/andromeda-setup-project`.

## Philosophy
Reference-based CLAUDE.md: a thin index (≤200 lines) with deeper content in `.claude/docs/` (on-demand) + `.claude/rules/` (path-scoped). `GENERATED:setup:*` is regenerated by setup-project; `USER:*` + `## Session Additions` are preserved across re-runs.
