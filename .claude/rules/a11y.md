# Accessibility Rules

Path-scoped rules for the desktop-webview UI (Tauri 2 React 19 + Tailwind v4.1 + shadcn/ui). The cli surface is NOT a11y-assertable (no DOM) — its ASCII status prefixes are output-stream discipline (see `testing.md`/`observability.md`), not ARIA.

**Authoritative source:** `.andromeda/a11y-plan.md` — §3 Harness Contract, §4 ARIA Patterns, §5 Keyboard, §6 Visual, §11 Anti-Patterns. Minimal tier; zero-WCAG-AA-violations on the four must-be-accessible paths.

## Semantic HTML first, ARIA second
- Native elements over `<div role>`: `<button>` (start/stop, Proceed/Abort, titlebar controls), `<input>` (scenario/seed), native checkbox (operator-checklist rows). Use shadcn `AlertDialog`/`Command`/`Select` over Radix for `alertdialog`/`combobox`/`listbox` semantics — never hand-roll them.
- Landmarks: `main` (console/report body), `contentinfo` (footer status strip — designed, NOT in the shipped DOM as of 2026-09-02: the measured landmark set is `banner` + `main` + two `region`s; a route-owned gap), `banner` (frameless titlebar). Virtual-scrolled coverage-matrix rows MUST stay reachable/announceable.

## Keyboard (SC 2.1.1 / 2.4.3 / 2.1.2)
- Every interactive control reachable via Tab/Shift+Tab in visual order; first-class start/stop/proceed/abort shortcuts must not override platform shortcuts.
- Operator-pause `alertdialog` traps focus, is Escape-escapable (no keyboard trap), and restores focus to the trigger on close. Radix supplies the trap + Escape but NOT the restoration: the hold arrives over a Tauri `Channel`, so there is no Radix `Trigger` and focus lands on `<body>` unless the dialog restores it explicitly (`onCloseAutoFocus` + a `restoreFocusTo` accessor) — and the invoking control must stay focusable (`aria-disabled`, never native `disabled`) to be a valid target. Never `tabindex` > 0.

## Visual — never color-alone (SC 1.4.1 / 1.4.3 / 1.4.11)
- The six verdict/report-state lamps (`Pass`/`HOLD`/`Fail`/`Blocked`/`Manual`/`Residual`) MUST each carry a text label + glyph — never color alone. This assertion keys on the LAMP labels only: `--status-residual` is also reused on the coverage matrix's out-of-scope Mode cell, which is a coverage-mode classification (its `not-conductors` label is its signal, no glyph) and must NOT be treated as a seventh lamp state.
- Contrast: text ≥4.5:1 (`--text-primary`/`--color-base` …); status lamps + focus ring ≥3:1 (`--count-nominal`/`--color-base`, `--color-focus`/`--color-base`). Verify via axe-core `color-contrast` + colorjs.io token-pair assertions.
- Visible focus ring on every control (`--color-focus`, SC 2.4.7); `outline:none` only with a `:focus-visible` replacement. Selection vs focus distinct (`--border-emphasis`).

## Motion (SC 2.3.3 / 2.3.1)
- Respect `prefers-reduced-motion: reduce` — the count tint, focus-ring fade-in, status-light transition, and operator-pause dialog fade all drop. Enforce CSS-native via Tailwind `motion-reduce:` + `@theme` tokens (no framer-motion in stack); ASSERT it from the compiled `@media (prefers-reduced-motion: reduce)` rule, because `browser.emulate` has no reduced-motion scope on any driver (webdriverio 9.x ships six: clock/geolocation/userAgent/device/colorScheme/onLine) — that proves the rule ships and is shaped right, not that the OS preference was exercised. The `Fail` lamp is motionless (no flashing). Motion is never the only signal for the hold-point (paused count + phase-line text + `aria-live="assertive"`).

## Status messages (SC 4.1.3)
- `aria-live="assertive"` on the HOLD phase-line flip; `role="status"`/`aria-live` on verdict lamps + live counters — updates must NOT steal focus. Empty states are real prose — the shipped strings `No scenarios found.` (empty CATALOG) / `No scenarios match.` (the PICKER's filter miss, announced from a persistently-mounted `aria-live` region — a region that mounts together with its text announces nothing) / `No run yet` (no "Run in progress" prose ships: the titlebar label `Conductor · live` + count carry the live state, measured 2026-09-02) — never a gray skeleton, never downgraded to `Fail`.

## Testing
- axe-core via `@axe-core/webdriverio` injected into the tests' `@crabnebula/tauri-driver` + WebdriverIO session — THREE suite families over that ONE stack: the unattended routine arm (`--e2e`; axe, contrast, not-color-alone, reduced-motion), the operator-only driven arm (`npm run a11y:driven`; trap, Space toggle, Escape→NoGo, focus restoration — needs a live Pulse and its full firing form, test-plan §6) and the operator-only screen-reader leg (`npm run a11y:sr` / `a11y:sr-empty` / `a11y:sr-error`; NVDA's own speech log graded against `crates/conductor-tauri/ui/test/a11y/screen-reader/nvda-pass-spec.md`, `CONDUCTOR_NVDA` naming a portable NVDA — unset ⇒ skip at exit 0 — the operator reviewing the record; browse-mode rows are findings pending OS-level key injection, never passes and never a manual arm; Windows + NVDA host only) (ONE webview-automation stack — Linux+xvfb in CI, and headful on the Windows WebView2 host under `CONDUCTOR_MSEDGEDRIVER`, unset ⇒ skip at exit 0; never a second puppeteer/CDP stack) + colorjs.io + WebdriverIO keyboard. Operator/local-gated (needs live Pulse), folds violation JSON into the obs envelope. Screen-reader verification is supplemental only: NVDA agent-driven via its speech log (measured 2026-09-02), VoiceOver/Orca declared not-runnable-on-this-host. `withTags(['wcag2a','wcag2aa','wcag21aa'])` — no `wcag22aa` (no escalation trigger).

## Session Additions
_This section is owned by `/wrap-session`. setup-project preserves content added here on re-run._
- 2026-09-04: **A live region announces a CHANGE, so a region that mounts together with its text announces nothing.** Measured twice in one chunk against NVDA. (a) The four `role="alert"` load-error nodes were rendered inside the same conditional as their message, so the original load error was silent and only a RELOAD (with NVDA already tracking the window) spoke it. (b) The picker's filter-miss prose had the same shape. Both fixes are identical: mount the region unconditionally and EMPTY at first paint, then let the text arrive into it. Corollary for the region's ROLE: prefer `aria-live` over `role="status"` unless the status semantic is wanted — `role="status"` is reserved here for the operator-checklist roll-up, and the a11y suite reads a bare `[role="status"]` as "a hold is raised" (see testing.md). a11y-plan §4 permits either, so the cheaper choice is the one that does not collide.
