# Accessibility Rules

Path-scoped rules for the desktop-webview UI (Tauri 2 React 19 + Tailwind v4.1 + shadcn/ui). The cli surface is NOT a11y-assertable (no DOM) — its ASCII status prefixes are output-stream discipline (see `testing.md`/`observability.md`), not ARIA.

**Authoritative source:** `.andromeda/a11y-plan.md` — §3 Harness Contract, §4 ARIA Patterns, §5 Keyboard, §6 Visual, §11 Anti-Patterns. Minimal tier; zero-WCAG-AA-violations on the four must-be-accessible paths.

## Semantic HTML first, ARIA second
- Native elements over `<div role>`: `<button>` (start/stop, Proceed/Abort, titlebar controls), `<input>` (scenario/seed), native checkbox (operator-checklist rows). Use shadcn `AlertDialog`/`Command`/`Select` over Radix for `alertdialog`/`combobox`/`listbox` semantics — never hand-roll them.
- Landmarks: `main` (console/report body), `contentinfo` (footer status strip — designed, NOT in the shipped DOM as of 2026-09-02: the measured landmark set is `banner` + `main` + two `region`s; a route-owned gap), `banner` (frameless titlebar). Virtual-scrolled coverage-matrix rows MUST stay reachable/announceable.

## Keyboard (SC 2.1.1 / 2.4.3 / 2.1.2)
- Every interactive control reachable via Tab/Shift+Tab in visual order; first-class start/stop/proceed/abort shortcuts must not override platform shortcuts.
- Operator-pause `alertdialog` traps focus, is Escape-escapable (no keyboard trap), and restores focus to the trigger on close. Radix supplies the trap + Escape but NOT the restoration: the hold arrives over a Tauri `Channel`, so there is no Radix `Trigger` and focus lands on `<body>` unless the dialog restores it explicitly (`onCloseAutoFocus` + a `restoreFocusTo` accessor) — and the invoking control must stay focusable (`aria-disabled`, never native `disabled`) to be a valid target. Never `tabindex` > 0.
- **Every a11y-plan §5 keyboard/focus claim has exactly one stated owner** (since 2026-09-17), committed as data in `crates/conductor-tauri/ui/test/a11y/claim-ownership.ts` and held to reality by `npm run a11y:ownership` — which FAILS if a named owner's spec is missing or asserts nothing, so a title can never stand in for coverage. The hold-dependent half (trap entry, containment, restoration) is owned by the DRIVEN arm, which CI cannot run; a11y-plan §11 *Strategy* states what gates in its place. Three claims — run-console-live and idle-with-report coverage-matrix row navigation, and the first-class shortcuts — are asserted by NO suite and stand recorded as gaps with a route owner. Adding or moving an assertion means updating that enumeration in the same change.

## Visual — never color-alone (SC 1.4.1 / 1.4.3 / 1.4.11)
- The six verdict/report-state lamps (`Pass`/`HOLD`/`Fail`/`Blocked`/`Manual`/`Residual`) MUST each carry a text label + glyph — never color alone. This assertion keys on the LAMP labels only: `--status-residual` is also reused on the coverage matrix's out-of-scope Mode cell, which is a coverage-mode classification (its `not-conductors` label is its signal, no glyph) and must NOT be treated as a seventh lamp state.
- Contrast: text ≥4.5:1 (`--text-primary`/`--color-base` …); status lamps + focus ring ≥3:1 (`--count-nominal`/`--color-base`, `--color-focus`/`--color-base`). Verify via axe-core `color-contrast` + colorjs.io token-pair assertions.
- Visible focus ring on every control (`--color-focus`, SC 2.4.7); `outline:none` only with a `:focus-visible` replacement. Selection vs focus distinct (`--border-emphasis`).

## Motion (SC 2.3.3 / 2.3.1)
- Respect `prefers-reduced-motion: reduce` — the count tint, focus-ring fade-in, status-light transition, and operator-pause dialog fade all drop. Enforce CSS-native via Tailwind `motion-reduce:` + `@theme` tokens (no framer-motion in stack); ASSERT it from the compiled `@media (prefers-reduced-motion: reduce)` rule, because `browser.emulate` has no reduced-motion scope on any driver (webdriverio 9.x ships six: clock/geolocation/userAgent/device/colorScheme/onLine) — that proves the rule ships and is shaped right, not that the OS preference was exercised. The `Fail` lamp is motionless (no flashing). Motion is never the only signal for the hold-point (paused count + phase-line text + `aria-live="assertive"`).

## Status messages (SC 4.1.3)
- `aria-live="assertive"` on the HOLD phase-line flip; `role="status"`/`aria-live` on verdict lamps + live counters — updates must NOT steal focus. Empty states are real prose — the shipped strings `No scenarios found.` (empty CATALOG) / `No scenarios match.` (the PICKER's filter miss, announced from a persistently-mounted `aria-live` region — a region that mounts together with its text announces nothing) / `No run yet` (no "Run in progress" prose ships: the titlebar label `Conductor · live` + count carry the live state, measured 2026-09-02) — never a gray skeleton, never downgraded to `Fail`.

## Session Additions

- 2026-09-04: **A live region announces a CHANGE, so a region that mounts together with its text announces nothing.** Measured twice in one chunk against NVDA. (a) The four `role="alert"` load-error nodes were rendered inside the same conditional as their message, so the original load error was silent and only a RELOAD (with NVDA already tracking the window) spoke it. (b) The picker's filter-miss prose had the same shape. Both fixes are identical: mount the region unconditionally and EMPTY at first paint, then let the text arrive into it. **[corrected 2026-09-07 (`2026-09-07-sr-findings-fixed`, SR row R0-01 graded twice): identical is right for the PICKER's filter-miss and for any region whose text arrives at an arbitrary time — but NOT for the LOAD-ERROR region, where the empty mount is necessary and NOT sufficient. NVDA binds a window on its FIRST FOCUS EVENT, which necessarily follows a load-time paint, so a message already present lands in a region nobody is listening to yet and the row stayed `not-announced` with `heard: []`. The shipped shape re-asserts after that first focus: the VISIBLE copy sits OUTSIDE the `role="alert"` region and the region carries a visually-hidden re-assertion alone, inserted once on the first `focusin`. Keeping both inside made NVDA read the region WHOLE and speak the message twice — so a duplicate node is the wrong shape for a re-announce, and the fix is a single node in an otherwise-empty region.]** Corollary for the region's ROLE: prefer `aria-live` over `role="status"` unless the status semantic is wanted — `role="status"` is reserved here for the operator-checklist roll-up, and the a11y suite reads a bare `[role="status"]` as "a hold is raised" (see testing.md). a11y-plan §4 permits either, so the cheaper choice is the one that does not collide.
- 2026-09-17: **Integrity's SIGN is configuration-bound — a remedy measured to FIX the driven session on one runtime/image can be the thing that BREAKS it on another, so bind such a finding to its configuration rather than stating it as a property of the harness.** Measured across two: a Medium-integrity launch was what created a session at WebView2 runtime 153 on the dev host, and on hosted `windows-2022` at a coherent 131.0.2903.86 pair it is what PREVENTS one — both HIGH driver-alone cells created a session (status 200, port and pipe) while both MEDIUM cells failed with `from chrome not reachable` (run 35191569653), and the arm then ran green at HIGH with no launcher (run 35208593666). The corollary that costs days if missed: **driver/runtime COHERENCE and the missing-endpoint cause are different failure modes and must not be conflated** — an incoherent pair is REFUSED outright with an explicit version error (`only supports Microsoft Edge version N`; driver 151.0.4129.107 against runtime 131.0.2903.86 at run 35186499514), whereas the `windows-2025` failure was the silent absence of `DevToolsActivePort` under a pair that already cohered, which is why skew stays retired as THAT cause while coherence is still required for a session to be attempted at all. State every such verdict with its image, its runtime, its driver and their coherence; the next image bump can move any of the four.
