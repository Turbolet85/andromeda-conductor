# Accessibility Rules

**Retired 2026-10-11** (`2026-10-11-conductors-window-retired`, intent R1): Conductor has no interface — the `conductor-tauri` crate and its `ui/` webview left the tree, so no file these paths name exists — and no assertable a11y surface remains. The cli is not a11y-assertable (no DOM or widget tree) — its ASCII status prefixes and NO_COLOR text pairing are output-stream discipline, never an a11y verification path. Source: `.andromeda/a11y-plan.md`. The entries below are history.

## Session Additions
_This section is owned by `/wrap-session`. setup-project preserves content added here on re-run._
- 2026-09-04: **A live region announces a CHANGE, so a region that mounts together with its text announces nothing.** Measured twice in one chunk against NVDA. (a) The four `role="alert"` load-error nodes were rendered inside the same conditional as their message, so the original load error was silent and only a RELOAD (with NVDA already tracking the window) spoke it. (b) The picker's filter-miss prose had the same shape. Both fixes are identical: mount the region unconditionally and EMPTY at first paint, then let the text arrive into it. **[corrected 2026-09-07 (`2026-09-07-sr-findings-fixed`, SR row R0-01 graded twice): identical is right for the PICKER's filter-miss and for any region whose text arrives at an arbitrary time — but NOT for the LOAD-ERROR region, where the empty mount is necessary and NOT sufficient. NVDA binds a window on its FIRST FOCUS EVENT, which necessarily follows a load-time paint, so a message already present lands in a region nobody is listening to yet and the row stayed `not-announced` with `heard: []`. The shipped shape re-asserts after that first focus: the VISIBLE copy sits OUTSIDE the `role="alert"` region and the region carries a visually-hidden re-assertion alone, inserted once on the first `focusin`. Keeping both inside made NVDA read the region WHOLE and speak the message twice — so a duplicate node is the wrong shape for a re-announce, and the fix is a single node in an otherwise-empty region.]** Corollary for the region's ROLE: prefer `aria-live` over `role="status"` unless the status semantic is wanted — `role="status"` is reserved here for the operator-checklist roll-up, and the a11y suite reads a bare `[role="status"]` as "a hold is raised" (see testing.md). a11y-plan §4 permits either, so the cheaper choice is the one that does not collide.
- 2026-09-17: **Integrity's SIGN is configuration-bound — a remedy measured to FIX the driven session on one runtime/image can be the thing that BREAKS it on another, so bind such a finding to its configuration rather than stating it as a property of the harness.** Measured across two: a Medium-integrity launch was what created a session at WebView2 runtime 153 on the dev host, and on hosted `windows-2022` at a coherent 131.0.2903.86 pair it is what PREVENTS one — both HIGH driver-alone cells created a session (status 200, port and pipe) while both MEDIUM cells failed with `from chrome not reachable` (run 35191569653), and the arm then ran green at HIGH with no launcher (run 35208593666). The corollary that costs days if missed: **driver/runtime COHERENCE and the missing-endpoint cause are different failure modes and must not be conflated** — an incoherent pair is REFUSED outright with an explicit version error (`only supports Microsoft Edge version N`; driver 151.0.4129.107 against runtime 131.0.2903.86 at run 35186499514), whereas the `windows-2025` failure was the silent absence of `DevToolsActivePort` under a pair that already cohered, which is why skew stays retired as THAT cause while coherence is still required for a session to be attempted at all. State every such verdict with its image, its runtime, its driver and their coherence; the next image bump can move any of the four. **Extended 2026-09-30: on the dev host the Evergreen runtime moves between sessions under an unchanged `CONDUCTOR_MSEDGEDRIVER`, so read both versions before firing an `--e2e` leg — the refusal only surfaces after the full release build.**
- 2026-09-30: **Send a modifier through `SendInput` in its OWN call and release it only after NVDA has handled the key it modifies** — one batched Shift+Tab left NVDA holding Shift, so every later OS key arrived as `shift+tab` and its browse-mode Shift+Tab moved focus backwards; confirm the OS key state reads up afterwards.
- 2026-09-30: **NVDA's browse caret follows the last DOM focus, and NVDA binds the document only at its first OS-path focus change, so an `sr*` browse row is walked FORWARD from a focused control just before its node** — never from BODY after a Tab cycle, which leaves the caret at the cycle's last stop; text before every focusable is reached from a blank test-only focus target held first in `<body>`, after the first OS Tab.
- 2026-09-30: **Browse mode never reads an `aria-label` on a role-less element — NVDA spoke a named count's bare digits — so name such text with visually-hidden text inside it and `aria-hidden` the visible value.**
- 2026-09-30: **An NVDA started while another window holds the foreground can stay bound to it for the whole leg even after the app is activated and the OS-key foreground guard passes** (its log reads "Foreground took too long to change"), so start `sr*` legs on a cleared desktop and treat such a session as void, never graded.
