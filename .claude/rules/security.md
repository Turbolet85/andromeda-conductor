# Security Rules

Universal security requirements (Minimal tier — local-only loopback tool, no network service, no secrets). Applies to all files; loads unconditionally (no `paths:` frontmatter).

**Authoritative source:** `.andromeda/security-plan.md` — §Input Validation, §Dependency Security, §Error Handling, §Security Anti-Patterns.

## Secrets
- Conductor owns NO secrets — never introduce one. Never commit `.env*`, `*.p12`, `*.pem`, `*.cer`.
- No `DATABASE_URL` or cloud-credential env vars — the SQLite path is a local file. Only the non-secret `CONDUCTOR_*` and Pulse-side `ANDROMEDA_*` env handles exist.
- The OS keychain reference (`OsKeychainBackend("com.andromeda.pulse")`) is Pulse-side — never read, store, copy, or embed keychain material. Pulse's `corpus.db` is plaintext SQLite (P-049 encryption not active live, verified 2026-06-27) — Conductor's production code reaches it through the MCP TOOL SURFACE only: read-back **plus the `mark_incident_resolved` lifecycle write** (first production caller 2026-08-31). Never the file — never directly open, copy or exfiltrate it, and never persist its content. Staging a corpus row directly to induce a SUT state is the banned route, which is why the declined-write arm is stub-proven.

## Input validation (§Input Validation)
- Validate ALL scenario config at load with garde (`range` + `#[garde(custom)]` cross-field: a bounded error fraction — the shipped `error_percent` ∈ 0..=100 — non-negative durations, bounded per-phase `occurrences`, p50≤p95≤p99, severity-mix sums, the per-shape `[phases.emission]` rules, the `[phases.fault]` closed `kind` enum + fault ⇒ `occurrences = 0`, the `[[expected]]` `budget_ms` bound `1..=MAX_BUDGET_MS`, the `[[checklist]]` items' `induced`/`observation` halves bound `1..=MAX_CHECKLIST_TEXT`). An unvalidated serde deserialize bypasses the trust boundary.
- A rule spanning a field and its SIBLING is the second, co-equal arm — garde 0.22.1's field-level `custom` receives `(&field, &())` and cannot see a sibling, so it ships as `Scenario::check_*()` invoked from `from_toml_str` (`check_capabilities`; `check_budgets` for `budget_ms` ≤ its scenario's `slo_tier` deadline; `check_checklist` rejecting a `[[checklist]]` declared beside a non-empty `expected`) and raises `CoreError::Config` — a harness fault at load, never a verdict (`CoreError::Validation` is `#[from] garde::Report` and carries no hand-written message). NEVER write such a rule as `#[garde(custom)]`: it would look enforced while never testing the invariant.
- A nested spec field must `#[garde(dive)]`, NEVER `#[garde(skip)]` — garde does not descend into a skipped struct, so its rules never execute and the boundary is silently bypassed even though the rules exist (`PhaseSpec.emission` was `skip` until the emission dispatcher; `PhaseSpec.fault` dives from birth). `kind` on `[phases.emission]` is required whenever the table exists — no inferred shape default; `[phases.fault]`'s `kind` is a closed enum (unknown kind = parse error) and a fault-declaring phase must be silent (`occurrences = 0` — the occupier port is never a config field).
- Committed SUT-facing manifests read at a fixed path (`contracts/pulse-capabilities.toml` · `contracts/pulse-load-envelope.toml` · `contracts/pulse-run-contract.toml`) are bounds-checked at load and resolved via `default_path()` → `resolve_under` with deliberately NO `CONDUCTOR_*` override; read faults carry `e.kind()` only (never the path), and absent/malformed is a hard harness fault — never defaulted, never a silent widen. `pulse-run-contract.toml` additionally has readers OUTSIDE `conductor-core` — `scripts/agent-run.{sh,ps1}` parse `warmup_ms` + `min_canary_poll_seconds` for the `boot` budget and carry the same rule: a missing term is a hard exit 2, and a lowered `CONDUCTOR_PREFLIGHT_TIMEOUT` clamps UP to the contract floor, never down.
- `ANDROMEDA_PULSE_L4_DETERMINISTIC` is a declaration-only READ with nothing to validate — Conductor tests whether its OWN environment affirmatively declares it (the run contract's `shell-declaration` proxy) and the value never becomes a path, an argv element, or a log value.
- The RUST-READ `CONDUCTOR_*` path handles sit OUTSIDE garde — `std::fs::canonicalize` + bounds-check at the `conductor-cli` edge before any `runs.db`/journal write or manifest read (path traversal). `CONDUCTOR_MSEDGEDRIVER` and `CONDUCTOR_NVDA` are the exceptions: no Rust code reads either, so their duty is discharged at the wdio harness edge (existence + `isFile` + shell-metacharacter rejection, then an array-form spawn — the driver path as a separate argv element, the NVDA path as the program of a detached fixed-argv spawn; unset or not-a-file ⇒ the `--e2e` leg / the `sr*` suites skip at exit 0). A THIRD class arrived 2026-09-02: `CONDUCTOR_E2E_SEED_DIR` is SET by `wdio.conf.ts` and READ by a `conductor-run` TEST binary, never by a shipped one — its value is a harness-owned repo-relative constant, so neither the canonicalize rule nor the wdio guard applies; it rides the spawn's env map (never argv, never a shell) and the seeding test is a no-op when unset, with the repo-relative discipline resting on the wdio caller. The screen-reader speech log the `sr*` leg ingests is untrusted third-party text: bounded, closed enums, host paths scrubbed to `<host-path>` + a `security_finding` before the record is committed.
- `runs.db`: rusqlite BOUND parameters only — never `format!`/string-concatenated SQL, even for synthetic data.
- Bound the line-delimited JSON-RPC decode on the MCP read-back path (serde_json is recursion-limited + a soft per-line size bound) — an empty/malformed/errored canary ⇒ `Blocked`, never a false pass.

## Subprocess & MCP (§Security Anti-Patterns)
- Spawn `andromeda-pulse-mcp` as a FIXED hard-coded program NAME resolved through the inherited `PATH` — never an operator-chosen or config-derived command string. `PATH` is a spawn-resolution input: an entry that fails to resolve the sidecar surfaces as `[BLOCKED]` in ~0s, which at row level looks exactly like a genuine SUT-side gate failure. The spawn must also suppress the child's console window (`CREATE_NO_WINDOW` class) — SHIPPED 2026-09-04: `build_command` applies `.creation_flags(console_suppressing_flags())` under `#[cfg(windows)]`, held by a `#[cfg(windows)]` unit test. A flagless `Command::new` raised a terminal pane titled with the sidecar's absolute exe path that took the OS foreground ~200 ms after `Start` — a measured host-path disclosure (2026-09-02, spoken by NVDA) — and the live re-run measured that pane gone (SR row S1-01 free of the `<host-path>`/`pane` utterances; 0 `security_finding` rows). The APPLIED flag is not unit-assertable (`std::process::Command` has no creation-flags getter), so its effect is SR-leg evidence.
- Pass `ANDROMEDA_PULSE_DATA_DIR` strictly via the `.env(...)` builder after rejecting injection metacharacters — never interpolate into argv or a shell (MCP-sidecar STDIO injection class, CVE-2026-30623).
- The read-back client MUST READ the `protocolVersion` from the `initialize` result (Pulse's hand-rolled server version) and HOLD it against the manifest-pinned `2024-11-05`, surfacing a difference as the distinct `Blocked` precondition — never pin a strict newer default, and never negotiate down from one.
- Never silently downgrade a failed preflight — each of the gate's FIVE named preconditions (version mismatch / missing tool / no incident opened after the canary storm / app-sidecar workspace-key agreement / unmet run-contract terms) surfaces the distinct `Blocked` state with its own named precondition string, never the generic corpus-empty one. The run-contract arm composes ONE string naming each unmet term individually with its causes; a term true-or-false entirely on the SUT's side is `declared-not-observable` and never blocks. The keychain read-while-write mode does NOT apply (`corpus.db` is plaintext; the P-049 assumption was disproved live).

## Dependencies (§Dependency Security)
- Audit: `cargo audit` (RustSec) + recommended `cargo deny` (`deny.toml`); build fails on advisory hit.
- `Cargo.lock` committed + un-drifted (makes the audit deterministic). Toolchain ≥1.94.1 (tar-rs CVE-2026-33056); `tauri` ≥2.10.3 (origin-confusion CVE-2026-42184); keep `libsqlite3-sys` current.
- Never `cargo build --release` or merge without `cargo-audit` (+ `cargo-deny`) green.
- Frontend (`crates/conductor-tauri/ui`, npm — cargo-audit/deny do NOT cover it): `npm audit --omit=dev` clean (0 production vulns; dev-only test-tooling advisories — e.g. the a11y harness's lighthouse/webdriverio tree — accepted at dev-tree grain, the npm analogue of deny.toml exceptions) + `package-lock.json` committed before merging frontend changes; fonts vendored (Fontsource WOFF2), no runtime CDN.
- Never add `unsafe` across the OTLP/gRPC/SQLite FFI boundary without review (`cargo-geiger` to map it).

## Error handling (§Error Handling)
- thiserror typed per-seam enums collapse to `anyhow` only at `conductor-cli` / `#[tauri::command]` edges.
- Never leak stack traces, absolute host paths, or internal struct/field names to the operator (cli stderr / Tauri returns) or into run-report artifacts (`<run_id>.md`, `runs.db`, JSONL) — sanitize at the edge + field-allowlist redaction.
- `tonic::Status` codes and MCP error responses are first-class typed verification inputs, never panics (verdict/error wall).

## Tauri GUI (§Code Patterns)
- Deny-by-default capabilities file — allow ONLY start/stop · scenario/suite picker · run-report view · operator-pause + the one live-counter `Channel`.
- No `shell-open` plugin with scenario-derived strings; no remote-origin iframes; Tauri ≥2.10.3.

- 2026-06-23: A green `cargo audit` does NOT imply a green `cargo deny check`. `cargo audit` exits 0 on `unmaintained`/license advisories (it reports them as *allowed warnings*), whereas `cargo deny` (deny.toml schema-v2 defaults) **denies** unmaintained advisories AND any non-allowlisted license. So the supply-chain gate MUST run BOTH (CI's `ci.yml` has separate `cargo audit` + `cargo deny check` steps); a chunk that checks only `cargo audit` can leave `cargo deny` latently red — this chunk found `foldhash 0.2.0`'s `Zlib` license had been failing `cargo deny check licenses` on HEAD, unnoticed because the prior session ran only audit. When a NEW dep pulls a non-actionable item, extend `deny.toml` with a JUSTIFIED entry (never a silent skip — the file mandates a comment): `[advisories] ignore` for an unmaintained-but-non-vulnerable transitive with no upstream fix, `[licenses] allow` for a permissive (OSI+FSF) license. - 2026-08-09: External supply-chain state DECAYS under a static dependency tree, and the response is a BOUNDED DEFERRAL — not a suppression. Two flavors seen: a new advisory lands against a tree you never touched (2026-08-08: RUSTSEC-2026-0194/-0195/-0204 → lock-only bumps), and the advisory DATABASE itself breaks (2026-08-09: `cargo audit` exit 1, "error loading advisory database: parse error: duplicate advisory ID: RUSTSEC-2026-0244" — reproduced identically with a fresh fetch and with `-n` against the cache, so the RustSec DB simply would not parse). When the chunk's dependency delta is ZERO and both lockfiles are un-drifted, a red supply-chain gate is not the chunk's defect: re-check at the next chunk, and if it persists the remedy **forks on which fault it is** — a **TOOL fault** (scanner too old / a bug a newer release fixes) → raise the TOOL'S FLOOR to the fixed release (dev CLI tools can't be pinned in `Cargo.lock`; security-plan states floors); an **advisory-DATABASE fault** (the DB itself will not parse or fetch, so NO released version can read it) → the floor raise is **unexecutable** and would look like compliance while changing nothing, so the remedy is the bounded WAIT alone, re-checked each chunk, with the audit↔deny overlap **verified** green rather than assumed. **Prove which before prescribing:** install the latest published tool and re-run — an identical failure means the data, not the tool. (Extended 2026-08-09, interpretation-correctness-posture: the third consecutive red check installed cargo-audit 0.22.2, the latest, and got a byte-identical `duplicate advisory ID: RUSTSEC-2026-0244` — the duplicate id is committed data in RustSec's advisory-db, so the floor-raise this entry originally prescribed had nothing to raise to.) Do NOT reach for `deny.toml` — the entries above prescribe a JUSTIFIED `[advisories] ignore` when a **new dep** pulls a non-actionable item, which is the disjoint case; suppressing a whole signal class to paper over a transient EXTERNAL fault is not the same act.
