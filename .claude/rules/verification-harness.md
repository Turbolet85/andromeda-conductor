# Verification Harness Rules

Path-scoped rules for the agent-driven verification harness — the `scripts/agent-run.*` driver, the CLI release-gate path, and the MCP read-back / preflight layer.

**Authoritative sources (bound):** `.andromeda/test-plan.md` §3 (Test Harness Contract) + `.andromeda/obs-plan.md` §3 (log format / service identity). The harness consumes the obs JSON log format; keep both sides in sync.

**Critical adaptation — Conductor has NO daemon and NO inbound listener.** `boot` is a precondition probe followed by a preflight gate (not a daemon start) — the probe leads and short-circuits on an unmet subject, skipping the preflight rather than paying it — `status` reads disk artifacts (no HTTP/IPC endpoint), there is NO PID file, and there is no long-running heartbeat. Do not reintroduce daemon/PID/endpoint machinery.

## 5-command discipline (`scripts/agent-run.{sh,ps1}` — exactly 5, identical semantics across .sh and .ps1: a property of the SCRIPTS together with the invoking environment, since a caller preempting native-command exits diverges the `.ps1` leg with zero script delta — measured 2026-09-07)
- **`boot`** — precondition probe, THEN the MCP preflight readiness gate. The leading arm is `conductor preconditions`: `:4317` reachability (connect-and-drop, client only), `andromeda-pulse-mcp` resolvable on the inherited `PATH` (a directory walk, never a spawn), and the three `ANDROMEDA_PULSE_*` handles read for an affirmative declaration. **That last subject is SATISFIABLE** — each handle is graded by the KIND of value it carries (`conductor_core::handle_declared`): the PATH-valued `ANDROMEDA_PULSE_DATA_DIR` by presence-after-trim, the two flags by an affirmative `"true"`/`"1"` through the value-only `flag_declared`. Non-zero SHORT-CIRCUITS `boot`, skipping the preflight invocation and its two derived budgets rather than paying it — no `ReadyState` JSON is emitted, which is how a skip is told from a failure — but that fires only on a genuinely unmet subject: under a satisfied environment `boot` reaches the gate and emits `ReadyState` (measured 2026-09-04 in both shells — `agent-run.sh` 17:07:17→17:08:04Z, `agent-run.ps1` 17:11:16→17:12:03Z, both exit 0 with `ready:true`, zero `skipped preflight` lines). `conductor preflight --json` remains a valid direct entry point. It fires no canary, so it primes none of the state a preflight's canary would. Identical semantics in `.sh` and `.ps1`; the command count stays five. Then the gate itself: `conductor preflight --json` runs the `initialize` handshake over the **hand-rolled line-delimited JSON-RPC client** (`conductor-verify/src/jsonrpc.rs` + `client.rs`; rmcp removed 2026-06-27 and absent from `Cargo.lock`) — assert the negotiated protocol `2024-11-05` READ from the `initialize` result + required-tool presence vs the pinned `contracts/` manifest + the run-contract terms + the canary round-trip. `ready:true` → exit 0; `ready:false` ⇒ every dependent scenario reports `Blocked` under one of the FIVE named preconditions (never a silent downgrade, never the generic corpus-empty string). CI uses the in-process `stub_pulse_mcp` child binary behind the `stub-server` feature (returns `ready:true`); the live-Pulse leg is `workflow_dispatch`/local only. Timeout: TWO derived budgets — (a) the in-process canary poll, `CONDUCTOR_PREFLIGHT_TIMEOUT` (default 30s) raised to the run contract's floor (`contracts/pulse-run-contract.toml` `[incident_formation].min_canary_poll_seconds`, which must outlast Pulse's L3 digest cadence), and (b) the wall-clock wrapper both shells apply around the CLI, derived per invocation from the same contract as `warmup_ms/1000 + poll + margin` — the warm-up pre-roll runs BEFORE the poll starts, so a wrapper set to the poll alone kills the run mid-poll. A missing contract term is a hard exit 2, never a silent default; a lowered env value clamps up to the floor. The stub leg still finishes in <1s on `CanaryPoll::immediate()`.
- **`run`** — `cargo nextest run --workspace --profile ci` + `cargo test --workspace --doc` + `cargo clippy --workspace --all-targets -- -D warnings`; scenario leg `SCENARIO=<name|P-ID> [SEED=<n>] … run` → `conductor run <scenario|P-ID> [--seed <s>]` (`--seed` rides ONLY an explicitly set `SEED`; the TOML-declared seed governs otherwise — arch files-over-env-defaults) / `conductor suite`. Exit 0 = all `Pass`; non-zero = a hard `Fail` (nextest 100). Stage flags `--unit`/`--integration`/`--e2e`/`--live`. `--live` is the operator-gated live-Pulse suite (never a CI gate, never reachable from a bare `run`): a leading non-priming `conductor preconditions` probe refuses at exit 1 on an unmet subject with no leg fired, then the ordered leg set `live_leg_order` owns in both shells (2026-09-07: leg H `halo-hue-encoding` first, then B1 → B2 → a 150s quiet window → A) → the driven a11y arm, freezing each leg's `logs/agent-latest.jsonl` to `runs/live-suite/{leg}.jsonl` because that sink truncates per invocation. A missing HOST-TOOL handle still SKIPS its leg at exit 0 — an incomplete live-Pulse env refuses, a missing host tool skips.
- **`status`** — read the Run-report envelope from `runs/<run_id>.jsonl` (`jq -e`) or the `runs.db` row (rusqlite bound-param SELECT). **Target the NEWEST ENVELOPE line, never the file's last line**: the journal carries two report-seam shapes, so a run that graded checks ends on a `CheckRecord` and a last-line read reports ITS fields as the envelope (measured 2026-09-06 — `seed: null`, `slo_tier: null`, exit 0). Both shells select it by the envelope-only `seed` key. No `curl`/HTTP — there is no listener.
- **`cleanup`** — `rm -f runs/<run_id>.{jsonl,md}` in the shells, then `conductor cleanup <run_id>` — **the shells issue no SQL** (2026-09-06). The three bound-param deletes (`DELETE FROM runs`, `DELETE FROM run_check`, `DELETE FROM run_envelope`, each `WHERE run_id=?1` — teardown covers every table a run writes, or it leaves orphans) run inside the binary as literal statements in one transaction (`RunsDb::delete_run`); the `sqlite3` CLI has no bind facility and is present on neither this host nor any CI runner. Plus release of the `:4317` port-occupier bind. Idempotent (re-run on a clean state is a no-op). NEVER touch Pulse (no process management).
- **`logs`** — read `runs/<run_id>.jsonl` (the emission journal — the left side of every SLO check; wall-clock `std::time` stamps) + sanitized stderr.

Do not add a 6th command without a test-plan amendment — the harness is small by design.

## Status envelope contract
- The Run-report envelope (`run_id`, `seed`, `scenario`, `p_ids`, `verdict ∈ {Pass,Fail,CalibrationRegion}`, `state ∈ {Pass,Fail,ManualCheck,KnownResidual,Blocked}`, `latency_ms`, `slo_tier`, `journal_emitted_at`, `read_back_observed_at`, `fingerprints`) is serialized identically into the Markdown report, the `runs` row, and the envelope JSONL line. Per-check detail is a separate finer grain, not an envelope extension: the `run_check` table keyed `(run_id, scenario, check_index)` plus its own `CheckRecord` journal lines and an indented per-check line in the Markdown report.
- A `blocked` row populates identity fields only (measurement fields `null`); cross-run latency/percentile + P-036 fingerprint queries MUST exclude null-measurement rows.
- Artifacts MUST NOT leak absolute host paths or internal struct names.

## Headless invariant (agent-driven)
- The headless source-of-truth path is NEVER blocked on an interactive prompt — `inquire` operator-pause prompts are `isatty`-gated; when stdin is not a TTY the prompt is skipped per the non-interactive policy and the decision recorded to the artifact. An auth/interactive gate there silently breaks the release gate.
- Integration tests drive the same contract as production (the `stub_pulse_mcp` stub over stdio — faithful to Pulse's RAW `tools/call` result shape, since a typed-envelope stub would pass against a shape the live sidecar never sends; `Command::cargo_bin` for the cli) — no pixel-scraping, no UI automation depending on screen geometry.

## Determinism
- Same scenario+seed ⇒ same stream shape (seeded `conductor-timeline` + `start_paused` for scheduling). Journal stamps from `std::time::SystemTime`/`Instant`, never the virtual clock. Zero nextest retries.
