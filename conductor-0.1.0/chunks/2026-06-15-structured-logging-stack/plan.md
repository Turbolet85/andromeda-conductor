## Goal
Stand up Conductor's self-observation logging foundation: a `tracing` + `tracing-subscriber` **JSON** stack
exposed as a runtime-agnostic init surface in `conductor-core`, called identically by the `conductor-cli` and
`conductor-tauri` bins (per arch §Design Philosophy "Headless-drivable core, thin shells" + obs-plan §3). This
realizes three of obs-plan §3's named bootstrap phases — `logger-stack-install`, `service-identity-wire`,
`run-id-correlation-wire` (CLI side) — plus the **zero-unlogged-panics** SLO invariant (obs-plan §10) via
`std::panic::set_hook`. Self-observation is `tracing` JSON to stdout/file only; it uses **no OTel SDK** — the
only OTLP Conductor speaks is the PRODUCT fault stream to Pulse `:4317` (Epoch 3), a wholly separate path
(obs-plan §11 ban; arch §Established Decisions [OTLP Emission Strategy]).

**Scope decision (user-approved at P4): lean + parameterized seam.** Emit JSON to **stderr** now; the core
init **accepts a writer/sink** so the file sink (`logs/agent-latest.jsonl`) + `--agent-mode` selection drop in
when the Epoch 8 agent-run harness lands (it owns `CONDUCTOR_RUNS_DIR` + the clap flag). Matches the
working-route line (JSON + service-identity + panic hook) and "build the seam so it can attach."

**Explicitly NOT in scope** (deferred, per scope.md): field-allowlist redaction + `anyhow`-edge sanitization
(next chunk, _Log + error-boundary redaction_); the file sink / agent-mode wiring (Epoch 8); the scenario-result
envelope fields `verdict`/`state`/`latency_ms`/`slo_tier`/`fingerprints`/`journal_emitted_at` — those are the
test-plan §3 schema populated by downstream timeline/verify/report chunks. This chunk guarantees the subscriber
renders flat JSON lines **compatible** with that schema, carrying `service.*` + `run_id` on *every* line.

## Implementation notes
- **Once-only global vs testability.** A global `subscriber.init()` can be set only once per process; nextest
  is process-per-test but in-binary `#[cfg(test)]` tests share one process. Provide a *buildable* subscriber +
  injectable writer (assert via `tracing::subscriber::with_default`/a local guard) distinct from the bins' global
  install path, so tests don't fight the once-only global.
- **Flat top-level fields.** `tracing` supports dotted field names (`service.name = …`), and `flatten_event(true)`
  flattens *event* fields; span fields nest under `"span"`/`"spans"`. Getting `service.*` + `run_id` as
  **top-level** keys on every line likely needs a small custom `Layer` (or equivalent constant-field injection)
  rather than a root span — confirm the chosen mechanism yields top-level keys (research Open Q2).
- **`run_id` home.** Kept as an accept-or-mint helper in core for reuse; `run_id` is ultimately the `runs.db`
  primary key (report seam, Epoch 6) — flagged for possible later relocation, not a blocker (research Open Q1).
- **Panic hook hygiene in tests.** Installing the global hook can leak across in-process tests; scope/restore it
  (save + restore the prior hook) so panic-capture tests don't perturb others.
- **Core stays sync.** The init is synchronous; no tokio dependency enters `conductor-core` for this chunk
  (preserves core's no-async property — only the "no I/O" clause is the documented exception).
