## Goal
Close Epoch 1 (Foundation) by standing up the project's first **GitHub Actions CI workflow** — the build + test
+ lint + supply-chain + coverage + frontend gate — and confirming the agent-run harness it exercises. Research
established that `scripts/agent-run.{sh,ps1}` already implement the full 5-command discipline to the test-plan §3
contract (setup-project Phase 4 generated them), so the harness is **verify-don't-rewrite**; the only genuinely
new artifact is `.github/workflows/ci.yml` (no `.github/` exists today).

Per the resolved scope decisions: CI runs on **`windows-latest`** (arch §CI/CD "the dev OS target" + this tool's
Windows-specific invariants — `run_id` filename safety, `%APPDATA%` data-dir default, bundled-SQLite/MSVC build),
and the test+lint leg **dogfoods the source-of-truth harness** by invoking `scripts/agent-run.ps1 run` rather than
re-listing cargo commands — honoring arch §Cross-cutting "agent-run is the release gate". The workflow wires every
Epoch-1 tool already pinned: `cargo build` (per arch §Infrastructure Build-system), `nextest --profile ci`
(zero-retry + JUnit, per test-plan §3/§10 + `.config/nextest.toml`), `clippy -D warnings`, `cargo test --doc`,
`cargo audit` + `cargo deny` (per security-plan §Dependency Security), `cargo-llvm-cov` (measure only), and the
frontend `npm ci`/`npm audit`/`npm run build` gate for `crates/conductor-tauri/ui` (per security-plan §Frontend npm).

Boundaries (val-1 anchor = `scope.md`): base CI does **not** invoke `boot`/`preflight` — `conductor-cli`'s bin is a
no-op stub with no `preflight`/`run` subcommand (research `main.rs:3-5`), so preflight is deferred to Epoch 5 and the
live-Pulse leg stays `workflow_dispatch`/local (per verification-harness.md). Coverage **thresholds**, JUnit/coverage
**artifact upload**, the obs-conformance gate, and the a11y gate are all **Epoch 10**; full harness command bodies
are **Epoch 8**. This chunk wires the *runs*, not the *thresholds/uploads/conformance*.

## Implementation Steps
1. **Create `.github/workflows/ci.yml`.** Name it (e.g. `CI`); triggers `push` + `pull_request`; reserve
   `workflow_dispatch` (commented or empty) for the future live-Pulse/operator leg. Two parallel jobs:
2. **Job `rust` (`runs-on: windows-latest`):**
   - `actions/checkout`.
   - Toolchain: rely on `rust-toolchain.toml` auto-install via the rustup shim (channel 1.95.0 ≥ MSRV 1.94.1;
     components clippy + llvm-tools-preview come from the file). Do not hardcode a toolchain version.
   - `Swatinem/rust-cache` (bundled SQLite + tonic/prost cold builds are slow on Windows — caching is near-mandatory).
   - Install the external cargo subcommands via `taiki-e/install-action` (prebuilt binaries, not `cargo install`):
     `cargo-nextest`, `cargo-audit`, `cargo-deny`, `cargo-llvm-cov`.
   - `cargo build --workspace --locked` — `--locked` enforces the committed, un-drifted `Cargo.lock` invariant
     (fails CI if the lockfile would change) per security-plan §Dependency Security.
   - **Dogfood the harness:** `.\scripts\agent-run.ps1 run` — this is the authoritative test+lint gate
     (`nextest run --profile ci` + `test --doc` + `clippy -- -D warnings`). JUnit lands at
     `target/nextest/ci/junit.xml` automatically (`.config/nextest.toml:11-13`).
   - `cargo audit` (RustSec) — fail on advisory hit.
   - `cargo deny check` (advisories + bans + sources + licenses against `deny.toml`) — fail on hit.
   - `cargo llvm-cov nextest --workspace --profile ci --summary-only` — measure coverage, **no `--fail-under`
     threshold** (threshold + artifact upload are Epoch 10).
3. **Job `frontend` (`runs-on: windows-latest`):** `actions/checkout` → `actions/setup-node` (with npm cache
   keyed on `crates/conductor-tauri/ui/package-lock.json`) → in `crates/conductor-tauri/ui`: `npm ci` →
   `npm audit` (must report 0 vulnerabilities) → `npm run build` (= `tsc --noEmit && vite build`).
   (Implementer's option: this job MAY run on `ubuntu-latest` since npm is OS-agnostic — saves Windows quota;
   default to `windows-latest` for consistency.)
4. **Verify (do not rewrite) the agent-run scripts.** Confirm `.\scripts\agent-run.ps1 run` (and
   `bash scripts/agent-run.sh run`) exit 0 headlessly: the scenario leg is `SCENARIO=`-gated and the `conductor`
   bin no-ops, so `run` exercises only nextest+doctest+clippy. **Do not** add a 6th command (verification-harness.md).
   Make a script edit *only* if CI surfaces a portability defect — then it is a fix, never a rewrite.
5. **Confirm green on the current tree** (local-equivalent run of every gate below), then validate the workflow
   on a branch push and observe the Actions run.

## Implementation notes
- **Double test run:** dogfooding `agent-run run` (plain) + a separate `cargo llvm-cov nextest` (instrumented)
  runs the suite twice. Acceptable for a base CI; **Epoch 10** ("CI quality-gate config") consolidates to one
  instrumented run + the coverage threshold + JUnit/coverage artifact upload + PR annotation.
- **Toolchain auto-install** pulls the uncommitted `rust-analyzer` component (it's in `rust-toolchain.toml`) —
  a minor CI install-time cost with no CI use. Decide whether to drop it from the file (see P5 flag); not blocking.
- **Use prebuilt tool binaries** (`taiki-e/install-action`) for cargo-nextest/audit/deny/llvm-cov + `Swatinem/rust-cache`;
  `cargo install`-from-source + bundled SQLite would make windows-latest runs very slow.
- **Shell:** windows-latest has both `pwsh` and Git Bash; dogfood via `.\scripts\agent-run.ps1 run` (native). The
  `.sh` is the Linux equivalent if the runner ever changes.
- **Do NOT** add (all Epoch 10): coverage `--fail-under` threshold, flakiness budget, JUnit/coverage artifact
  upload, obs-conformance grep, a11y axe/contrast gate. **Do NOT** add the live-Pulse dynamic leg (operator/local only).
