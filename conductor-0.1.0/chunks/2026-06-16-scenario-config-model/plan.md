## Goal
Extend the existing `conductor-core` scenario *identity* model into a declarative **per-phase emission spec**, and wire a validated `Scenario` into the `conductor-timeline` seeded scheduler. Today `Scenario` carries only `{ name, p_ids, seed, slo_tier }` (`scenario.rs:50`); its own doc reserves this chunk ("the declarative per-phase emission spec is a later chunk … garde validation attaches here", `scenario.rs:5-6,66-67`). This chunk adds an ordered phase sequence (each phase: a legible label, a timing contribution, and a minimal forward-compatible emission descriptor) plus a scenario-level jitter bound, all serde-deserialized from TOML and garde-validated at load — per arch §Established Decisions [Validation Library] + §Conventions [Config conventions] and security-plan §Input Validation.

The second half is the bridge: a total, deterministic, order-preserving `From<&Scenario> for PhaseTimeline` conversion living in `conductor-timeline` (which owns `PhaseTimeline` and already depends on core — the seam direction makes this the only legal home). After this chunk a TOML scenario under `scenarios/` deserializes → validates → converts into the `PhaseTimeline` that `run_timeline(&PhaseTimeline, seed)` (built last chunk) already consumes, with same scenario + seed ⇒ identical phase sequence shape (arch §Design Philosophy [Determinism]; obs-plan §4).

Strictly data + validation + conversion: no OTLP, no emitter, no journal. The emission descriptor is **declarative data only** and intentionally minimal — Epoch 3 ("Emission primitives") owns the concrete taxonomy (error spans, severity, fingerprints, latency p50≤p95≤p99, ramps); this chunk only gives it a forward-compatible place to grow (scope §Out of scope; research open-Q #3).

## Implementation notes
- **Breaking field add:** required new `Scenario` fields invalidate every existing struct literal — update `scenario.rs` tests + `scenario_with` helper + the `error.rs` validation test in the same commit, or the workspace won't compile.
- **Conversion home is forced by the seam:** `conductor-core` must NOT depend on `conductor-timeline`; the `From<&Scenario> for PhaseTimeline` impl therefore lives in `conductor-timeline` (orphan rule: it owns `PhaseTimeline`). Keep timeline serde-free.
- **jitter_ms bound:** keep it modest relative to gaps (the scheduler already clamps a jittered gap at 0, `scheduler.rs:71`) so jitter perturbs without inverting the declared sequence's meaning.
- **Determinism test:** use ≥2 fixed seeds known to diverge over multiple draws (not a single-draw coincidence); drive the virtual clock with `start_paused` + `tokio::time::advance` — never assert real elapsed time (testing.md).
- **No journal writes here:** the per-run JSONL journal + `std::time` stamps are Epoch 2 chunk 3 — this chunk reads no clock and writes no artifact.
- **`toml` crate:** MIT/Apache, RustSec-clean; confirm `cargo deny` license + advisory checks pass after adding it.
