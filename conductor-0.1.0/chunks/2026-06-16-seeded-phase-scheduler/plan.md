## Goal
Build the determinism core of the timeline engine in `conductor-timeline`: a seeded phase scheduler that
sequences an ordered list of timeline phases on a `current_thread` tokio runtime via `tokio::time`, applying
**bounded seed-derived jitter to each inter-phase gap** so the same scenario+seed reproduces the same
emission-stream *shape* (ordering + relative timing) and a different seed yields a different — but still
fully reproducible — shape (user decision, phase P4). This is the determinism substrate every later
emission/fault chunk drives.

The scheduler is a **runtime-agnostic library** (a plain `async fn`, no `#[tokio::main]`): both the headless
CLI release-gate path and the optional Tauri shell call it identically, and `current_thread` (zero
work-stealing) is the caller's responsibility. It *sequences* and *surfaces phase-boundary transitions* to a
caller-provided sink — it does **not** emit OTLP, write a journal, or parse scenario config (those are the
emit seam / journal chunk / next chunk). Per architecture §Design Philosophy (determinism under a seed) +
§Established Decisions [Async Runtime Flavor] (current_thread) + [Module Boundaries] (crate-per-seam); the
seed flows from `conductor_core::Scenario.seed` (`u64`, already modeled). This chunk establishes the
seed→`ChaCha8Rng`→schedule path end-to-end and the first `timeline.execute` self-obs span (obs-plan §4).

3. **Phase model (minimal)** — define `Phase` (a named string id + a base gap/hold `Duration`) and an ordered
   `PhaseTimeline` (the phase list + the jitter bound), plus a `PhaseTransition` event (phase id + sequence
   index + virtual-elapsed marker) surfaced to the caller. Keep it minimal — the rich declarative per-phase
   *emission* spec is the **next** chunk; this is only the timing skeleton.
4. **Seeded RNG wiring** — construct `ChaCha8Rng::seed_from_u64(seed)` once at scheduler init; the seed is a
   `u64` the caller passes (sourced from `conductor_core::Scenario.seed`). The RNG is the *sole* source of
   non-determinism; hold it in the scheduler, not the public phase type.
5. **Scheduler core** — a runtime-agnostic `async fn` that iterates phases in declared order; for each
   inter-phase gap, draw a bounded jitter delta from the RNG, compute `effective_gap = base ± jitter` clamped
   to `[0, base + bound]`, `tokio::time::sleep(effective_gap).await`, then hand a `PhaseTransition` to the
   caller sink. Choose the simplest decoupled sink form (a returned `Vec<PhaseTransition>` or an `FnMut`
   callback) — keep it runtime-agnostic and unit-testable; the Tauri `Channel` binding is Epoch 9, do not build it here.
6. **Error type** — `TimelineError` (thiserror 2.0.18) for harness faults only (verdict/error wall: outcomes
   are values, `Result::Err` is harness-only). No `panic!`, no `unsafe`. Most config validation is the next
   chunk, so keep the enum lean (e.g. an empty/degenerate-timeline guard if warranted).
7. **Observability** — annotate the scheduler entry with `#[tracing::instrument(name = "timeline.execute", …)]`
   carrying a `phase_count` field; plain `tracing` only (no OTel SDK, no exporter, no async worker). Defer the
   `emission_count` attribute (obs-plan §4) until the emit chunk. Scheduling stays on the tokio virtual clock;
   span wall-clock timing is the subscriber's concern — do NOT read `std::time` on the schedule path.
8. **Public surface** — replace the `lib.rs` placeholder with module declarations + re-exports of `Phase`,
   `PhaseTimeline`, `PhaseTransition`, the scheduler fn, and `TimelineError`.
9. **Tests** (`#[tokio::test(flavor="current_thread", start_paused=true)]` + `tokio::time::advance`; rstest
   fixture for a seeded timeline):
   - **determinism** — same `(timeline, seed)` ⇒ identical `PhaseTransition` sequence + identical jittered gap deltas;
   - **seed-sensitivity** — a different seed ⇒ a different jitter sequence (still reproducible on re-run);
   - **timing** — each gap lands at `base ± jitter` within the declared bound; assert via `advance`, never real wall-clock;
   - **clamp/bound** — jitter never yields a negative gap and respects the bound;
   - **(optional) insta golden** — snapshot the transition sequence for a fixed `(timeline, seed)` (assert mode, no auto-write).

## Implementation notes
- **User decision (P4):** "seeded gap jitter" — the seed must *materially* affect timing, not merely be held.
  `scope.md` DoD was reconciled to match (intent-incompleteness, recorded for P5).
- **RNG = `rand_chacha::ChaCha8Rng`** via `seed_from_u64` — its algorithm is stable across platforms/versions
  (reproducible), which a determinism substrate requires; `StdRng` gives no such stability guarantee.
- **tokio features:** the library needs only `time`; tests need `test-util` (for `start_paused`) + `macros` +
  `rt` + `time`.
- **Keep the phase model minimal** — resist modeling per-phase *emission*; the jitter *bound* is a scheduler
  (timing) concern, distinct from the next chunk's per-phase emission spec.
- **Sink shape** — prefer the simplest decoupled form (returned `Vec` or `FnMut` callback); a `tokio::sync::mpsc`
  / Tauri `Channel` binding is Epoch 9, do not over-build now.
- **Determinism pitfalls** — any `HashMap` iteration order, system entropy, or `std::time` read on the schedule
  path breaks the seed contract; route ALL non-determinism through the `ChaCha8Rng`. A golden/`insta` snapshot
  catches a paused-clock or ordering leak.
