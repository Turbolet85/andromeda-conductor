## Goal
Turn the architecture's headline invariant — *same scenario + seed ⇒ identical emission-stream shape* (arch
§Design Philosophy; test-plan §1 "determinism as a hard quality bar") — from a property the existing tests only
check *relatively* into one that is **frozen absolutely and generalized across the seed space**. The timeline
seam already exists and works: `run_timeline` (seeded `ChaCha8Rng`, `scheduler.rs`), the `Phase`/`PhaseTimeline`/
`PhaseTransition` model, and `From<&Scenario> for PhaseTimeline` (`convert.rs`) all ship with unit + integration
tests. What no test does today is (a) pin the **exact** `Vec<PhaseTransition>` a fixed scenario+seed produces, or
(b) assert reproducibility for **arbitrary** seeds/timelines rather than a handful of hand-picked ones. This
chunk adds both, entirely as test code in `conductor-timeline` — **no production change, no new dependency**
(`insta` + `proptest` are already dev-deps; `tokio` dev carries `test-util`).

Two additions (per scope §Intent anchor + tests/arch extracts): an **insta golden** that drives the full
`scenarios/error-baseline-spike.toml` → `Scenario::from_toml_str` → `PhaseTimeline::from(&s)` → `run_timeline`
pipeline and snapshots the resulting transition sequence (the on-disk tripwire for any drift in the ChaCha8 RNG
algorithm, the jitter formula, the gap mapping, or the conversion — the cross-version stability promise that
justified choosing ChaCha8 over StdRng, per arch §Established Decisions [Determinism RNG]); and a **proptest**
suite generalizing the *replay* property (`∀ seed: run_timeline(&tl, seed)` twice ⇒ identical) plus the
structural invariants (each gap ∈ `[base−jitter, base+jitter]` clamped ≥ 0; `elapsed_ms` monotonic
non-decreasing; one transition per phase, in order) across the seed space and arbitrary valid timelines, with a
committed `proptest-regressions/`. Everything runs under tokio's **virtual clock** (`start_paused`) so it is
instant and zero-flake, and the golden captures **only** the seeded/virtual dimension — never the `std::time`
journal stamps (test-plan §3; obs §11), which are deliberately non-reproducible.

A research finding sharpens the design: `elapsed_ms` is an internal accumulator of jittered gaps
(`scheduler.rs:45-55`), **not** a clock read — so `run_timeline`'s output is a pure function of (timeline, seed),
the golden's values are stable, and a future regression that switched `elapsed_ms` to a real-clock read is
exactly what the assert-mode golden would catch (testing.md "a golden test catches a paused-clock leak").

## Implementation Steps
1. **Create the integration test file** `crates/conductor-timeline/tests/replay.rs` (sibling of the existing
   `determinism.rs`, which stays as-is). Module doc: this is the *replay harness* — absolute golden freeze +
   seed-space property generalization — distinct from `determinism.rs`'s hand-picked invariant unit tests.
2. **Golden A — full-pipeline stream shape (fixture seed).** A `#[tokio::test(flavor = "current_thread",
   start_paused = true)]` that loads `scenarios/error-baseline-spike.toml` via the established idiom
   (`std::fs::read_to_string(concat!(env!("CARGO_MANIFEST_DIR"), "/../../scenarios/error-baseline-spike.toml"))`
   → `conductor_core::Scenario::from_toml_str` → `.expect("fixture valid")`), converts with
   `PhaseTimeline::from(&s)`, runs `run_timeline(&tl, s.seed)` (the scenario's **own** seed, 424242), and
   `insta::assert_debug_snapshot!` on the returned `Vec<PhaseTransition>`. Uses `PhaseTransition: Debug` — **no
   `Serialize` derive, no production change**.
3. **Golden B — contrasting-seed freeze.** Same loaded timeline, `run_timeline(&tl, 7)` (a seed known to diverge
   from 424242 per `convert.rs` precedent), `assert_debug_snapshot!` on the result. Freezes that a *different*
   seed yields a *different but equally stable* shape — pinning seed-sensitivity, not just one seed. (Give the
   two snapshots distinct names so insta files don't collide, e.g. via `assert_debug_snapshot!("fixture_seed_424242", …)` / `("fixture_seed_7", …)`.)
4. **Author + commit the snapshots.** Generate the initial `.snap` files locally (`cargo insta accept -p
   conductor-timeline`, or `INSTA_UPDATE=always cargo nextest run -p conductor-timeline` as a fallback), eyeball
   the pinned values (Golden A: two transitions `baseline`≈[1950,2050]ms then cumulative `spike`, monotonic),
   and **commit** `crates/conductor-timeline/tests/snapshots/replay__*.snap`. CI never authors — insta detects
   the `CI` env and runs assert-only (security extract; test-plan §4).
5. **proptest strategy.** An `arb_timeline()` strategy: `prop::collection::vec(0u64..=10_000, 1..=6)` for per-phase
   base gaps + a `0u64..=1_000` jitter bound, `prop_map`-ped into a `PhaseTimeline` whose phases are
   `Phase::new(format!("p{i}"), Duration::from_millis(gap))` (index-derived names — no string-regex strategy
   needed). Bounds stay modest (the runtime `Phase`/`PhaseTimeline` are not garde-validated, so the strategy owns
   its ranges; they sit well under `MAX_GAP_MS`/`MAX_JITTER_MS` from `phase_spec.rs`). The strategy never yields
   an empty timeline (1..=6 phases), so `run_timeline` never returns `EmptyTimeline` here (that harness-fault path
   is already covered in `determinism.rs`).
6. **Property — replay determinism.** `proptest! { #[test] fn replay_is_deterministic(seed in any::<u64>(), tl in
   arb_timeline()) { … } }`. Because `run_timeline` is async and needs a paused clock, build the runtime *inside*
   the case: `tokio::runtime::Builder::new_current_thread().enable_time().start_paused(true).build().unwrap()`,
   then `rt.block_on(async { let a = run_timeline(&tl, seed).await.expect("non-empty"); let b = run_timeline(&tl,
   seed).await.expect("non-empty"); prop_assert_eq!(a, b); Ok(()) })?;`. (The `#[tokio::test]` macro cannot wrap a
   `proptest!` block — the manual `start_paused(true)` builder is the required pattern; `test-util` is already a
   dev-feature.)
7. **Property — structural invariants.** A second proptest case over the same strategy asserting, for one run:
   `transitions.len() == tl.phases.len()`; names equal the phases' names in order; each gap delta
   (`elapsed_ms[i] − elapsed_ms[i-1]`) ∈ `[max(0, base−jitter), base+jitter]`; and `elapsed_ms` is monotonic
   non-decreasing. This generalizes `determinism.rs`'s fixed-seed bound/negative-gap tests to ∀ seed.
8. **Do NOT** add a `∀`-quantified "different seeds diverge" proptest — divergence is probabilistic (a short
   timeline can coincide for two seeds), so it stays a fixed-seed assertion (already covered by
   `determinism.rs::different_seeds_yield_different_shapes` + `convert.rs::different_seeds_diverge`). Scope §Surfaces
   + testing.md session note.
9. **Commit `proptest-regressions/`.** Run the suite; if proptest persists a counterexample to
   `crates/conductor-timeline/tests/proptest-regressions/replay.txt`, that is a *real* determinism break to fix
   (never a flake to retry) — fix the underlying issue and commit the regression file. `.gitignore` ignores only
   `/target/`, so the directory tracks by default (research §Conventions).
10. **Green the gates.** Ensure `cargo nextest run -p conductor-timeline` and the full dogfood gate
    (`scripts/agent-run.{ps1,sh} run` = nextest `--profile ci` zero-retry + `test --doc` + `clippy --all-targets
    -D warnings`) pass; keep the new test code clippy-clean.

## Implementation notes
- **insta authoring vs asserting.** The `.snap` must exist + be committed for the test to pass; author it once
  locally (`cargo insta accept`, or `INSTA_UPDATE=always …` if `cargo-insta` is not installed), verify the values,
  commit. CI sets `CI=true`, which makes insta assert-only — so a missing/edited snapshot fails CI rather than
  silently rewriting (the intended guardrail).
- **proptest search RNG is intentionally not pinned.** proptest seeds its *search* from entropy; this does not
  threaten determinism because the properties are universally true (∀ seed/timeline), so the search cannot produce
  a flake — any counterexample is a genuine determinism break, persisted to `proptest-regressions/` and replayed
  deterministically thereafter. This is the one place "randomness" is not seed-pinned, and it is the test search
  strategy, not the system under test (whose seed is fully controlled). If stricter reproducibility is ever wanted,
  `PROPTEST_RNG_SEED` can pin it without code change.
- **Async-in-proptest pitfall.** `prop_assert*` must run inside a closure returning `Result<_, TestCaseError>`;
  return `Ok(())` from the `block_on` async block and propagate with `?`. Do not use plain `assert_eq!` inside
  proptest (it panics instead of shrinking).
- **Clock independence.** Because `elapsed_ms` is an accumulator, `start_paused` is needed for *speed*
  (no real waits across ~256 proptest cases × goldens), not for output correctness — but keeping every test on the
  virtual clock is the discipline that makes the "no real-clock leak" golden meaningful.
- **Snapshot stability across hosts.** The Debug snapshot of `elapsed_ms` (a `u128` accumulator under ChaCha8) is
  platform/version-stable by the RNG choice; the committed golden is the cross-version tripwire (no multi-OS CI job
  is added — scope §Boundaries).
