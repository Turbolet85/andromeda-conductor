## Goal
Extend the `conductor-emit` raw OTLP scaffold with the first *fault-meaningful* span content: the ability to
mark a span errored via OTel `Status.Code=ERROR` (the P-005 hard signal) and to place that error at a chosen
depth in an intra-trace span tree — root span vs a deep child (the emission side of P-008's root-vs-deep
weighting). This is the emission primitive the later P-005/P-008 *scenarios* and verdict logic (Epoch 5/7)
will drive; this chunk builds construction only, no verdict logic (per scope.md DoD + arch extract Contract
bindings).

The central new concern is **deterministic span/trace ID generation**. The scaffold hardcodes
`trace_id: vec![1;16]` / `span_id: vec![1;8]` (`message.rs:50-51`) — fine for one span, unusable for a tree
where children need *distinct* span_ids under a *shared* trace_id. Per the convergent arch/security/obs/tests
extracts and the established timeline pattern (`scheduler.rs:43,64`), IDs must derive from a seeded
`ChaCha8Rng` that the builder takes **as input** (no global entropy, no clock read) so "same scenario+seed ⇒
same trace shape" holds (arch §Established Decisions [Determinism RNG]; obs-plan §4; test-plan §2). `rand_chacha`
+ `rand_core` are already `[workspace.dependencies]`, so conductor-emit gains only dep *edges* — no new
external crate, no new audit surface (security-plan §Dependency Security).

The egress path is reused unchanged: `TraceEmitter::export()` and `count_spans()` already handle multi-span
requests (`client.rs:41,47`), and `EmitError` stays as-is — an ERROR-status span is a normal emitted *value*,
not a harness fault, so the verdict/error wall is untouched (arch + security + obs extracts).

## Implementation Steps
1. **Add the RNG dep edges** — `rand_chacha.workspace = true` + `rand_core.workspace = true` to
   `crates/conductor-emit/Cargo.toml` `[dependencies]`. Regenerate `Cargo.lock` (no new external crate; edges
   only). Keep audit/deny green.
2. **Introduce seeded ID generation** — a helper that, from `seed: u64`, constructs
   `ChaCha8Rng::seed_from_u64(seed)` and emits one 16-byte `trace_id` (per trace) plus N distinct 8-byte
   `span_id`s via `RngCore::fill_bytes` — mirroring `scheduler.rs:43` (seed at entrypoint) + `:64` (`&mut
   ChaCha8Rng` threaded into pure helpers). Decision (research OQ1): the **public builder takes `seed: u64`**
   and owns the local RNG; per-span id generation takes `&mut ChaCha8Rng`. Spec-floor: trace_id/span_id must
   be non-zero (OTLP) — ChaCha8 output is effectively never all-zero; do not reintroduce hardcoded zeros.
3. **Generalize span construction** — refactor `ok_span()` (`message.rs:47`) into a shared `pub(crate)` span
   constructor parameterized by status (code + optional message), `trace_id`, `span_id`, and `parent_span_id`.
   `trace_request` (the OK baseline, `message.rs:20`) keeps its public signature/behavior (decision, research
   OQ3: refactor-and-keep, not replace). Reuse `service_resource()` (make `pub(crate)` if the tree logic moves
   to a new module).
4. **Build the intra-trace span tree** — assemble a linear parent→child **chain** of depth N: root at index 0
   (empty `parent_span_id`), each child's `parent_span_id` = its parent's `span_id`, all sharing the one
   `trace_id`. A chain is the minimal well-formed structure for "root vs deep child"; branching breadth is not
   required by P-005/P-008 and is out of scope (scope.md boundaries).
5. **ERROR-status + placement selector** — a placement parameter (recommend an enum `ErrorPlacement { Root,
   DeepChild { depth } }`, or a span-index) selects exactly which span carries
   `Status { code: STATUS_CODE_ERROR, message }`; all other spans carry the baseline `OK` status (consistent
   with the scaffold). Validate the requested depth against the chain length.
6. **Public builder + re-exports** — add a public entry (recommend `error_trace_request(service_name, seed,
   depth, placement, message) -> ExportTraceServiceRequest`) assembling
   `ResourceSpans → ScopeSpans → Span[]` with the chain + the single ERROR span at the requested position.
   Re-export it + `ErrorPlacement` from `lib.rs` alongside the existing exports.
7. **Tests** — in-crate `#[cfg(test)]` unit tests for tree/status/placement/determinism + a loopback-stub
   integration test reusing the `CapturingService` pattern (`egress.rs:18-47`). See Test Commands + Acceptance.

## Implementation notes
- **Mirror the RNG idiom exactly** — `ChaCha8Rng::seed_from_u64(seed)` at the builder entry; thread
  `&mut ChaCha8Rng` into id helpers, like `jittered_gap(…, rng: &mut ChaCha8Rng)` (`scheduler.rs:64`).
- **Timestamps stay wall-clock** (`unix_nanos()` ← `SystemTime::now()`): do **NOT** add a full-byte `insta`
  golden over the whole request — it would flake on `start/end_time_unix_nano`. Assert *structurally* (span
  count, parent/child topology, ERROR at the expected index) + *id-determinism* (research OQ2). This matches
  the determinism-replay precedent (golden the seeded shape, not the clock).
- **`EmitError` untouched** — ERROR-status is an emitted value, not a harness fault; do not add a variant.
- **Multi-span egress already works** — `count_spans()`/`emit.batch` sum across spans (`client.rs:47`); no
  `client.rs` change needed.
- **Zero external blast radius** — the P3 code-graph query shows every `conductor-emit` symbol ref is
  intra-crate or in `tests/egress.rs`; no other crate consumes the seam yet (run_timeline wiring deferred).
- **Boundary discipline** — Status field ONLY this chunk: no `exception.*` span events / fingerprints
  (next chunk P-006/P-017/P-018), no `SeverityNumber` logs (P-007), no cross-service topology / W3C
  propagation (later "Multi-service topology" chunk, P-027).
