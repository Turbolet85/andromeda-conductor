## Goal
This chunk builds the foundational emission-primitive layer in `conductor-emit` — the seam every P-005..P-060 emission scenario stands on. It establishes two things: hand-constructed **raw OTLP trace messages** built directly from opentelemetry-proto 0.32.0 structs (NOT the opentelemetry-otlp SDK exporter), and a **tonic 0.14.6 gRPC `TraceServiceClient`** that ships them to Pulse's loopback OTLP ingest at `127.0.0.1:4317`. Raw structs are the deliberate choice (arch §OTLP Emission Strategy + security §Input Validation): byte-level field control is what fault injection requires, and the SDK exporter's hidden batch tasks + opaque fingerprint/severity/status handling would defeat it.

The seam is intentionally minimal and forward-compatible. It is the Epoch-3 emission seam the core descriptor already anticipates — it reads `conductor_core::Signal::Traces` (`phase_spec.rs`, `#[non_exhaustive]`) and builds the unperturbed base request; the concrete fault taxonomy (ERROR status, exception events/fingerprints, severity logs, latency shaping) lands in later chunks that extend this base. Transport behavior obeys the verdict/error wall (arch §Error handling; mirrors the three existing seam-error precedents `CoreError`/`TimelineError`/`JournalError`): a connect/transport refusal is a typed harness `EmitError` (`Result::Err`) — the "OTLP egress liveness equivalent" at this layer — and a server `tonic::Status` is a first-class typed input, never a panic.

Scope boundaries are firm: traces only (logs/metrics deferred to their chunks), no fault injection, no `:4317` port-occupier bind, no MCP/preflight gate, and **no edit to `run_timeline`** — research confirms the timeline seam is documented to emit nothing and stays pure; the per-transition emit wiring is a later chunk / the CLI runner (scope grants this latitude). The end-to-end emit path is proven against a loopback gRPC stub in tests (determinism discipline: loopback stubs only in tests), never the live `:4317`.

## Implementation notes
- **No `tonic-prost-build` / `build.rs`.** opentelemetry-proto's `gen-tonic` feature ships the generated `TraceServiceClient` + trace structs; there is no local `.proto` to compile — the arch's "budget for tonic-prost-build" note does not apply here (no build script exists in the workspace).
- **Never bind `:4317`.** Conductor is a gRPC *client* here; the only deliberate `:4317` bind is the Epoch-4 port-occupier fault. Tests use an in-process duplex or an ephemeral `127.0.0.1:0` stub.
- **Test stub ≠ rmcp.** The OTLP-egress loopback stub is a tonic `TraceService` server; rmcp is the MCP read-back path (Epoch 5) — the tests-extract's "rmcp in-process stub" phrasing refers to that later seam, not this one.
- **`std::time` for span nanos.** Span start/end timestamps come from `std::time::SystemTime` (unix-nanos), never tokio's virtual clock — consistent with `obs.rs` `now_rfc3339`/`mint_run_id`.
- **Feature minimalism.** Enable only `["gen-tonic", "trace"]` now; `logs` (P-007) and `metrics` are added by their chunks (`EmissionSpec`/`Signal` are `#[non_exhaustive]`, so no rework).
