## Goal
Add the **exception-event + fingerprint-control** emission primitive to `conductor-emit`, building directly on
the error-span scaffold (`span_tree.rs` / `message.rs`). Two capabilities: (a) attach an OTel `exception` span
event (`exception.type` / `exception.message` / `exception.stacktrace`) onto an error span (P-006), and (b)
compute the **path+line-insensitive expected fingerprint** Conductor will later cross-check against Pulse's
derived fingerprint (P-017 / P-018). Per the authoritative spec (input.md §Capabilities 56-58 + §Scenario
catalog 108, **amended P-017 clause (c)**): **identical · path-variant · line-variant ⇒ the SAME fingerprint**;
**type-variant · frame-variant ⇒ a DIFFERENT fingerprint**. Storm-cue thresholds (6/12 per 30s) are the
Epoch-7 fingerprint-storm scenario and are out of scope.

Per the ratified crate-seam decision, **both the builder and the fingerprint fn live in `conductor-emit`** (a
new `exception.rs`), co-located with the exception content they derive from — mirroring the error-spans
"builder-in-emit" precedent. `conductor-faults` stays an empty stub until Epoch 4; the Epoch-7 fingerprint-storm
fault will depend on emit and compose this primitive. No new crate-dependency edge is added.

Determinism follows the established split (arch §Determinism RNG; testing.md): the exception span's **identity
bytes** come from a seeded `ChaCha8Rng` (exactly as `error_trace_request`), while the **fingerprint is a pure
function of exception CONTENT** (type + frame-function signatures) — NOT seed-driven — and must be **stable
across Rust versions/platforms** (no `DefaultHasher`/SipHash, mirroring the ChaCha8-over-StdRng cross-version
choice). Outcomes are values; serialize/transport faults stay `Result::Err`/`EmitError` (the verdict/error
wall). The fingerprint output feeds the already-declared `RunRecord.fingerprints: Option<Vec<String>>` envelope
field (`run_record.rs:42`) — no envelope reshape, and `fingerprints` is already in the redact allowlist
(`redact.rs:46`).

## Implementation Steps
1. **Exception + variant model** — in a new `crates/conductor-emit/src/exception.rs`, define the exception
   identity: an `ExceptionSpec` (exception type, message, and an ordered set of stack **frames**, each carrying
   a function signature + file/module path + line) and a `FingerprintVariant` enum over the five
   transformations relative to a base: `Identical`, `PathVariant`, `LineVariant`, `TypeVariant`, `FrameVariant`.
   Bound frame count + string lengths (security: bounded stacktrace, no unbounded recursion). The title's
   "identical/path/line" are the same-fingerprint triple; `TypeVariant`/`FrameVariant` are the different-fp
   contrast required by the both-directions test (research §Open Q2, decided: include).
2. **`fingerprint(spec) -> String`** — the path+line-insensitive identity: normalize by **dropping each frame's
   file/module path and line number**, keeping `exception_type` + the ordered frame-function signatures; encode
   the normalized identity into a **cross-version-stable** string (impl picks the scheme — normalized-identity
   string or a stable digest e.g. FNV-1a / truncated sha2 — NOT `std::hash::DefaultHasher`). Property:
   identical/path/line ⇒ equal; type/frame ⇒ unequal.
3. **`exception_trace_request(service_name, seed, spec, variant, …) -> ExportTraceServiceRequest`** — mirror
   `error_trace_request` (`span_tree.rs:37`): seed a local `ChaCha8Rng::seed_from_u64(seed)`, draw trace/span
   ids via `gen_id`, set `Status.Code=ERROR` on the span (reuse `error_status`), and attach an OTel `exception`
   span event — `opentelemetry_proto::tonic::trace::v1::span::Event { name: "exception", attributes: [exception.type,
   exception.message, exception.stacktrace] as KeyValue/StringValue, time_unix_nano: wall-clock }`. Render the
   stacktrace string from the frames with **no absolute host paths**.
4. **Attach events on the span** — `message.rs`'s shared `span()` (`message.rs:51`) currently builds with
   `..Default::default()`, leaving `events` empty. Either extend `span()` to accept `events: Vec<span::Event>`
   (and update its sole non-test caller `span_tree.rs:65`) **or** add a `span_with_events()` sibling the
   exception builder uses (leaving `span()` for OK/error ancestors). Keep timestamps wall-clock `std::time`
   (`unix_nanos`) — the seed governs identity only.
5. **Re-export** — in `lib.rs`: `mod exception;` + `pub use exception::{exception_trace_request, fingerprint,
   ExceptionSpec, FingerprintVariant}` (final names at impl discretion).
6. **Tests** —
   - Unit (`#[cfg(test)]` in `exception.rs`): the five fingerprint relationships (identical/path/line equal;
     type/frame unequal); both-directions determinism (same spec ⇒ same fp; ≥2 distinct identities ⇒ distinct
     fp); exception-event shape (event name `exception`, all three attributes present, `Status.Code=ERROR`,
     seeded ids reproducible on a shape-projection); stacktrace carries no `C:\` / `/Users/` host path.
   - Integration (`crates/conductor-emit/tests/exception_events.rs`): ship an exception trace over the loopback
     gRPC `TraceService` stub (the `tests/egress.rs` / `tests/error_spans.rs` harness on `127.0.0.1:0`) and
     assert the exception event round-trips. NEVER bind real `:4317` (reserved for the Epoch-4 port-occupier).

## Implementation notes
- **Fingerprint is content-derived, NOT seed-derived.** The seed drives only the exception span's identity bytes (like `error_trace_request`); do not route the fingerprint through `ChaCha8Rng`. "Same seed ⇒ same fingerprint" holds trivially because the fingerprint ignores the seed entirely.
- **Normalization is the crux:** collapse {file path, line} (path + line insensitivity) while preserving {exception type, ordered frame functions} (type + frame sensitivity). Get this wrong and either path/line variants diverge or type/frame variants collide.
- **Determinism on a shape-projection, never a byte golden** — span timestamps are wall-clock and would flake an `insta`/full-payload `assert_eq!` (testing.md 2026-06-17 / error-spans). Project to (ids, linkage, status, event name+attrs).
- **`EmissionSpec` is NOT extended this chunk** — scenario-config wiring (the `#[non_exhaustive]` extension at `phase_spec.rs:44`) is the Epoch-7 scenario catalog's job; this is a standalone builder like `error_trace_request`.
