## Goal
Add a **latency-shaping emission primitive** to `conductor-emit`: given a per-operation **target latency
profile** (p50/p95/p99 in milliseconds), produce concrete span **durations** — realized as
`start_time_unix_nano` / `end_time_unix_nano` on the existing raw-OTLP `Span` — so an emitted multi-span
stream for an operation realizes the targeted percentile distribution. This is the controllable latency input
Pulse's **P-011** (per-operation latency baseline — "no direct user signal; baseline feeds P-012") and
**P-012** (latency-regression detection) consume: a steady known p50/p95/p99 (the baseline) and a shifted
profile (e.g. 3× p99, the regression) are both just target profiles fed to the same primitive. The primitive
must be able to emit ≥ Pulse's **latency exclusion floor of 50 samples/window** per operation (the spec value
— distinct from the error-rate floor of 10, and a known Pulse spec/code divergence at `MIN_EWMA_SAMPLES = 10`).

The shape follows the established Epoch-3 precedents exactly (per arch §OTLP Emission Strategy + §Determinism
RNG): a **seeded builder** mirroring `span_tree.rs:error_trace_request` (`ChaCha8Rng::seed_from_u64(seed)`,
threaded `&mut rng`), and a **constructor-validated typed wrapper** mirroring `logs.rs:Severity::new`. The
`LatencyProfile` type and its `p50 ≤ p95 ≤ p99` check live in `conductor-emit`, NOT core: `phase_spec.rs:6-8`
places the concrete OTLP taxonomy ("…latency targets, ramps") in the Epoch-3 emission seam, extending
`EmissionSpec` (`#[non_exhaustive]`) *later* without reshaping the scenario model — and `Severity` set the
precedent of an emit primitive self-validating its bounded input rather than deferring to core's garde.

This is a **standalone primitive** like every other Epoch-3 chunk: the code-graph shows **zero workspace
edges to/from conductor-emit** (research §Graph impact), so it is not scenario/timeline-wired and has no
downstream blast radius. The latency-regression *orchestration* (90s baseline → 3× p99 90s → candidate after
60s persistence), the ±15% tolerance/calibration-region routing, and the scenario-config garde wiring are
explicitly **out of scope** (Epoch 7 / Epoch 5 / the later EmissionSpec extension respectively — per scope.md
§Boundaries).

## Implementation Steps
1. **`LatencyProfile` type** (`latency.rs`) — a `Copy` struct holding `p50_ms` / `p95_ms` / `p99_ms`, built
   via `LatencyProfile::new(p50, p95, p99) -> Option<Self>` that returns `None` unless `p50 ≤ p95 ≤ p99`
   (the constructor-validated precondition, mirroring `Severity::new`'s `1..=24` check at `logs.rs:32`). This
   is the primitive's local precondition — core remains the authoritative *scenario-config* validator for the
   future EmissionSpec field (per arch §Config conventions + scope §Boundaries). No `garde` here.
2. **Seeded duration sampler** (`latency.rs`) — a function taking `(profile, sample_count, &mut ChaCha8Rng)`
   and returning the per-sample durations whose realized percentiles converge to the profile targets over
   `sample_count ≥ 50`. Recommended (implement's final call): a piecewise inverse-CDF anchored at
   0.5→p50 / 0.95→p95 / 0.99→p99 (plus a `0` floor and a bounded tail past p99) sampled through a seeded
   uniform — hits the anchor percentiles by construction. The sampler reads **no clock** — durations are a
   pure deterministic function of `(profile, seed)` (per arch §Determinism discipline; the wall-clock/seeded
   split at `message.rs:65-89`).
3. **Duration-aware span constructor** (`message.rs`) — add `pub(crate) fn timed_span(name, trace_id,
   span_id, parent_span_id, status, duration_nanos)` that sets `start = unix_nanos()` and
   `end = start + duration_nanos` (today's `span()` / `span_with_events()` set `start == end`, i.e. zero
   duration — `message.rs:76-88`). **Additive** — leave the existing zero-duration constructors untouched so
   the OK/error/exception builders are unaffected (no existing-symbol signature change ⇒ no caller impact;
   the OK builder `ok_span` and `span_tree`/`exception` callers of `span()` keep their contract).
4. **`latency_trace_request` builder** (`latency.rs`) — top-level
   `latency_trace_request(service_name, seed, operations: &[…])` where each operation pairs an operation name
   (the span `name`), a `LatencyProfile`, and a sample count. Mirror `span_tree.rs:37-78`: seed one
   `ChaCha8Rng::seed_from_u64(seed)`, then for each operation emit `sample_count` spans named by the
   operation, each carrying a seeded-sampled duration via `timed_span`, reusing `gen_id::<16>/<8>` (span_tree,
   `pub(crate)`) for trace/span ids and `service_resource` (message) for the resource. Returns a raw
   `ExportTraceServiceRequest` — consumed by the **existing** `TraceEmitter` (no new emitter; per research).
5. **Re-exports** (`lib.rs`) — `mod latency;` + `pub use latency::{LatencyProfile, latency_trace_request, …}`
   alongside the existing `message` / `span_tree` / `logs` re-exports (`lib.rs:17-22`).
6. **No `Cargo.toml` change** — the `trace` opentelemetry-proto feature is already enabled and
   `rand_chacha` / `rand_core` are already deps (`Cargo.toml:10,14-15`); latency reuses trace types.
7. **No self-obs span / no SDK** — keep the primitive a pure function (no I/O, no tokio task, no
   `#[tracing::instrument]`): this avoids touching the bounded self-obs span-name set (observability.md §Spans)
   and upholds the no-OTel-SDK invariant (obs §3). Emission itself stays the caller's concern via `TraceEmitter`.
8. **Unit tests** (in-module `#[cfg(test)]`) — profile-ordering rejection; determinism both-directions on a
   **duration-sequence projection** (exclude wall-clock `start`/`end`); realized-percentile convergence over
   ≥50 samples; per-operation independence. **Integration test** (`tests/latency_shaping.rs`) — drive the
   shaped request through the loopback `TraceService` stub and assert per-operation durations + refused
   transport ⇒ `EmitError`.

## Implementation notes
- **Seeded vs wall-clock split is the crux** (testing.md 2026-06-17 error-spans): the *duration* (`end −
  start`) is the seeded, determinism-governed output; the absolute `start`/`end` come from `unix_nanos()`
  (`SystemTime::now()`). Project to durations in the determinism test — a whole-`Span` golden would flake on
  the timestamps.
- **Floor is producer-capacity, not a judgement** — the ≥50-sample floor here only means the builder must be
  able to emit ≥50 spans/operation; the *exclusion-floor decision* is Pulse-side / conductor-verify (Epoch 5).
  Don't add tolerance/SLO logic here (verdict/error wall — that's a value the verify seam computes).
- **Profile-type location** is a deliberate decision (emit, not core) settled by `phase_spec.rs:6-8` + the
  `Severity` precedent — see P5 review. The future scenario-config wiring extends `EmissionSpec`
  (`#[non_exhaustive]`) and adds the garde `p50 ≤ p95 ≤ p99` invariant noted at `scenario.rs:97`; not this chunk.
- **Sampling algorithm + test tolerance** are implement-time choices (research §Open questions); the plan
  fixes the WHAT (realize the percentiles deterministically over ≥50 samples), not the exact inverse-CDF math.
