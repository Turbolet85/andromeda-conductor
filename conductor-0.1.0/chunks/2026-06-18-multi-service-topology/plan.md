## Goal
Add a `conductor-emit` primitive that constructs OTLP traces spanning **multiple emulated services** — the
emission side of P-027 (service constellation) and the cross-service face of P-008 (root-vs-deep error
placement). One `ExportTraceServiceRequest` carries **≥2 `ResourceSpans`, each with a distinct `service.name`
Resource attribute** (the constellation Pulse renders as service dots), with a **single shared `trace_id`** and
**cross-service `parent_span_id` linkage** (a downstream service's span parents to an upstream service's span)
— W3C Trace Context propagation realized in raw OTLP fields, not header shims (per arch §Conventions + obs-plan
§3 Correlation). An optional cross-service error placement sets `Status.Code=ERROR` on exactly one service's
span (root service vs a deep downstream service), extending the single-service root-vs-deep placement already
shipped in `span_tree.rs`.

This is a **distinct builder**, not an extension of `error_trace_request` (`error_trace_request @
span_tree.rs:37`, referenced only in-crate — zero cross-crate callers per research §Graph impact): there the
chain length is driven by the error depth, whereas a topology's chain length is the number of services
(independent of where the error sits). It lives in a new `topology.rs` module and **reuses** the shared
`pub(crate)` primitives `service_resource` / `gen_id` / `span` / `ok_status` / `error_status`, mirroring how
`latency.rs` and `logs.rs` compose them. Per the established sibling pattern (`LatencyProfile::new`,
`Severity::new`), the topology input self-validates in-crate (returning `Option`); the `conductor-core` garde
layer is the later scenario-wiring validator (deferred to the scenario epoch — per scope boundaries). No new
dependency, no new Cargo feature (reuses the enabled `trace` proto types); no new self-obs span (pure function;
`emit.batch @ client.rs:43` already covers export — obs bounded span-name set unchanged).

## Implementation Steps
1. **`ServiceTopology` validated type** (`topology.rs`) — a thin wrapper over an ordered, root-first list of
   service names. `ServiceTopology::new(services) -> Option<Self>` accepts only **≥2 services, all distinct**
   (it is *multi*-service, and the constellation is the distinct-name set); `None` otherwise. Mirror
   `LatencyProfile::new`/`Severity::new` (`latency.rs:32`, `logs.rs:32`): `Option`, not `Result`; expose
   accessors (`services()`, `len()`). No panics.
2. **`service_topology_request` builder** (`topology.rs`) — signature in the family of `latency_trace_request`:
   `service_topology_request(topology: &ServiceTopology, seed: u64, placement: Option<ErrorPlacement>, message:
   &str) -> ExportTraceServiceRequest`. Reuse `ErrorPlacement` (`pub`, re-exported via `span_tree`): `None` =
   healthy all-`OK` trace (pure P-027 constellation); `Some(Root)` = `ERROR` at the root service (index 0);
   `Some(DeepChild{depth})` = `ERROR` at service `depth` (the deep downstream service — P-008 cross-service).
3. **Build the trace** — `let mut rng = ChaCha8Rng::seed_from_u64(seed)`; draw `trace_id = gen_id::<16>` once;
   then for each service `i` in order: `span_id = gen_id::<8>`; `parent_span_id` = empty for `i==0` else the
   previous service's `span_id`; `status` = `error_status(message)` iff `i` is the placement-selected index
   else `ok_status()`; build the span via `span(...)` (`message.rs:55`, wall-clock `start=end`); place that one
   span in **its own** `ResourceSpans { resource: Some(service_resource(name)), scope_spans: [ScopeSpans{spans:
   [span], ..}], .. }`. Result: `topology.len()` ResourceSpans, one per service. (Span `name`: a stable
   role/service label — implement's choice; product span names are unconstrained by the self-obs bounded set.)
4. **Out-of-range placement** (research §Open questions) — when `ErrorPlacement::DeepChild{depth}` has `depth ≥
   len`, **saturate the error to the deepest service** (`depth.min(len-1)`) and document it (consistent with
   `timed_span`'s `saturating_add`); no panic, no `Result`. (Alternative — validate the pair — is acceptable;
   pick one and document.)
5. **Re-export** — `lib.rs`: add `mod topology;` and `pub use topology::{ServiceTopology,
   service_topology_request};` (`ErrorPlacement` is already public via `span_tree`).
6. **In-crate unit tests** (`#[cfg(test)] mod tests` in `topology.rs`) — assert on a `shape()` projection (ids
   + linkage + status, excluding wall-clock) per the error-spans precedent: ≥2 distinct service names ⇒ ≥2
   ResourceSpans; one shared `trace_id` across all services; cross-service parent linkage (each service span's
   `parent_span_id` == the upstream service span's `span_id`; root empty); error placement lands on the right
   service with all others `OK`; healthy (`None`) ⇒ all `OK`; `ServiceTopology::new` rejects <2 / duplicate
   names. Both-directions seed check: same seed ⇒ identical shape; ≥2 seeds ⇒ divergent identity (per
   testing-rule 2026-06-16 + 2026-06-17).
7. **Loopback integration test** (`tests/multi_service_topology.rs`) — copy the `CapturingService` +
   `start_stub()` ephemeral-port pattern (`tests/error_spans.rs:36`, **never `:4317`**); export a 3-service
   topology with a deep error; assert the captured request has 3 distinct `service.name` ResourceSpans, one
   shared `trace_id`, valid cross-service linkage, `ERROR` on the deep service; add a `refused_transport ⇒
   Err(EmitError::Transport(_))` case (`tests/egress.rs:73`).

## Implementation notes
- **Distinct builder, not an extension:** leave `error_trace_request` untouched (`error_trace_request @
  span_tree.rs:37` — in-crate callers only; no need to perturb the single-service P-005/P-008 path).
- **One span per service** (linear chain) is the intentional minimal model that satisfies P-027 (distinct
  names) + P-008 (cross-service root-vs-deep) + W3C propagation; richer topologies (fan-out, multi-span
  services) are out of scope and deferred.
- **`gen_id` draw order matters for determinism** — fix the order (trace_id once, then per-service span_id in
  chain order) and lock it with the shape golden, since reordering draws changes the seeded bytes.
- **Reuse, don't re-derive:** `service_resource` (`message.rs:35`), `gen_id` (`span_tree.rs:80`, `pub(crate)` —
  import via `crate::span_tree::gen_id`), `ok_status`/`error_status`/`span` (`message.rs`) — all in-crate.
- **Deferred (still open, not this chunk):** `opentelemetry-proto` `default-features = false` to drop the
  dormant transitive `opentelemetry_sdk` — this chunk again makes no `Cargo.toml` change, so not the moment.
