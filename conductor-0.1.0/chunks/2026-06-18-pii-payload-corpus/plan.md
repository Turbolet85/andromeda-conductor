## Goal
Build the emission-side **PII payload corpus**: a deterministic, seeded generator of synthetic-but-structurally-valid
sample values across the seven P-047 categories — email, JWT, bearer token, API key, credit-card PAN, SSN, and a
secret-like `key=value` — plus the raw-OTLP builders that embed that corpus into all three signal types (span
attributes, log-record body/attributes, exception event message/stacktrace). This is the last data-shaping
emission primitive Pulse's PII scrubber (P-035) keys on; a downstream `pii-scrub` scenario (Epoch 7, conductor-verify)
will read the corpus back via MCP and assert Pulse scrubbed each category while preserving surrounding structure —
**that verification is out of scope here** (per arch extract Anti-patterns; scope.md Boundaries).

The module is a near-twin of the existing `topology.rs` sibling: a self-validating value type + free builder
functions composing the shared `pub(crate)` raw-struct primitives in `message.rs` (`string_kv`, `service_resource`,
`span`/`span_with_events`, `gen_id`), with identity seeded by `ChaCha8Rng::seed_from_u64` (per architecture
§Established Decisions — Determinism RNG; research.md §Patterns). No new dependency: `rand_chacha`/`rand_core` and
the `tokio`/`tokio-stream` dev-deps are already present (research.md §Files inspected — Cargo.toml). The corpus
values are synthetic fixtures by construction — never host- or env-derived (per security-plan §Data Protection /
§Secret Management) — and never logged to self-obs nor leaked into run-report artifacts (per obs-plan §11;
security-plan §Error Handling).

## Implementation notes
- **Per-category structural shapes (synthetic):** email `local@example.com` (reserved domain); JWT three
  dot-separated base64url segments `h.p.s`; bearer `Bearer <token>` (OAuth scheme prefix); API key a
  provider-style shape (e.g. `sk_live_<alnum>` or `AKIA<UPPER>`); credit card 16 digits **Luhn-valid** (compute
  the check digit — do NOT random the 16th digit); SSN `NNN-NN-NNNN`; secret `key=value` with key one of
  `password` / `api_secret` / `token`. Seed drives the variable bytes; keep all values in reserved/test ranges.
- **Determinism boundary:** the seed governs the corpus VALUES + span/trace identity, not wall-clock stamps
  (`unix_nanos()` stays `SystemTime`-sourced) — assert determinism on a wall-clock-excluding projection
  (topology.rs:151 / error-spans testing.md 2026-06-17), never a full-payload byte golden.
- **No `conductor-core` garde wiring this chunk** — declaring a PII spec in `scenarios/*.toml` is deferred to
  the scenario epoch (same posture as the `ServiceTopology` garde follow-up; scope.md Boundaries).
- **Logs stub:** `tests/multi_service_topology.rs` only stubs `TraceService`; the logs leg needs a
  `LogsServiceServer` capture stub — mirror the existing severity-logs integration test's stub.
