## Goal
Add the OTLP **log-record** emission primitive to `conductor-emit` — the logs analogue of the existing trace
path — so Conductor can drive Pulse's severity-boundary hard-signal detection (P-007). Pulse treats
`SeverityNumber ≥ 17` as an error-grade signal; the "17-boundary" is the OTel WARN(13–16)→ERROR(17–20) cut.
The primitive must construct `LogRecord`s with a **caller-controlled `SeverityNumber` and its canonical matching
`SeverityText`**, and place records on **either side** of the boundary (the tightest case `16/WARN4` vs
`17/ERROR`) so a later scenario can prove Pulse fires on `≥17` and not on `≤16`.

Two surfaces ship: (1) a raw `ExportLogsServiceRequest` **builder** in a new `logs.rs`, hand-built from
`opentelemetry-proto` `logs` raw types (never the SDK exporter — per arch §Established Decisions [OTLP Emission
Strategy]), reusing the `pub(crate)` helpers in `message.rs` (`service_resource`/`string_kv`/`unix_nanos`); and
(2) a `LogsEmitter` over `LogsServiceClient<Channel>` mirroring `TraceEmitter` (`client.rs`), shipping over the
same loopback gRPC egress to `127.0.0.1:4317`. Transport faults stay on the **verdict/error wall**: a
refused/malformed channel is a typed `EmitError` (`Result::Err`); a collector `tonic::Status` is a typed input,
never a panic (per arch §Cross-cutting Patterns + security §Error Handling). Severity is **spec-controlled, not
seed-derived**; wall-clock stamps come from `std::time` via `unix_nanos()`, never tokio's virtual clock (per
obs §2 + security §Error Handling).

Per the code-graph query (research §Graph impact), **no other crate consumes `conductor-emit` yet**, so this is
a purely additive primitive with zero blast radius and — like its three sibling chunks — is **not
timeline/journal-wired** (journal integration is deferred; there is no consumer to journal into). Scope
boundary #1 (the `opentelemetry-proto` `default-features = false` trim) is resolved **deferred** by user
decision: this chunk adds only the `"logs"` feature, keeping `Cargo.lock` un-drifted.

## Implementation notes
- **17-boundary precision:** to test the *tightest* boundary, hit `16` (WARN4) and `17` (ERROR), not the coarse level-floors `13`/`17`. The `SeverityText` for `16` is `"WARN4"`, for `17` is `"ERROR"` — derive text from number, don't hand-pass it.
- **Severity is spec-controlled — no seed.** Unlike `error_trace_request`/`exception_trace_request` (which seed span identity), a severity `LogRecord` has thin identity; the builder is a pure function of its inputs (mirror seedless `trace_request`). So the determinism test is reproducibility + boundary-distinctness, NOT a seed-divergence (both-directions) test — there is no seed to diverge (research Open-Q 2). If trace-correlation identity is added later, *then* add the both-directions test per testing.md.
- **`EmitError` is reused unchanged** — do not add a variant; `#[non_exhaustive]` already anticipates this and `Transport`/`Status` cover the logs egress faults identically.
- **Deferred (tracked, not this chunk):** `opentelemetry-proto` `default-features = false` to drop the dormant transitive `opentelemetry_sdk` — keep deferred per user decision; do opportunistically in a later emission chunk.
- **Downstream-only (not now):** if severity-driven verdicts later reach the run report, `≥17` maps to the `Fail` lamp / `[FAIL]` and must pair color with its text label (layouts extract; not in this emit-side chunk).
