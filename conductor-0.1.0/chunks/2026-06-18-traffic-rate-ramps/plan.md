## Goal
Add the last Epoch-3 emission primitive: a deterministic, seeded **traffic-rate curve** in `conductor-emit`
that produces, per abstract time window, the number of spans to emit so the resulting OTLP throughput rises
and falls on a reproducible curve — a linear **ramp** and a periodic **breathing** oscillation. This is the
rate analogue of the already-shipped latency-shaping primitive (which seeds per-span *durations*); here the
seed drives per-window *counts* (per arch §Established Decisions [Determinism RNG] + research §Patterns
"seeded-sampling primitive").

It exists to exercise Pulse's **P-026 "halo breathing"**: in the constellation view a service-dot's halo
pulses at a rate tracking the service's live traffic. P-026 is a visual / operator-checklist claim with **no
MCP read-back** (arch extract §Relevance), so this chunk *produces the emission shape only* — verification
routes to a later epoch (ManualCheck). Per the crate-per-seam law the primitive stays a pure builder in
`conductor-emit`: it returns counts + a `TraceService` request and does **not** depend on `conductor-timeline`
(which owns wall-clock driving); the window→wall-clock mapping is the later timeline driver's concern
(arch §Inherited Defaults; research §Graph impact confirms the emit builders are leaves with no current
caller, so blast radius is nil).

## Implementation Steps
1. **`RateCurve` type** in a new `src/rate.rs`, mirroring `LatencyProfile`'s self-validating-constructor shape
   (`latency.rs:24-54`). An enum with two variants exposed through validating constructors returning
   `Option<Self>`:
   - `RateCurve::ramp(from_rate, to_rate, windows)` — linear target rate from `from_rate` to `to_rate` across
     `windows`; reject `windows == 0`.
   - `RateCurve::breathing(center_rate, amplitude, period_windows, windows)` — target
     `center + amplitude·sin(2π·w/period)`; reject `period_windows == 0`, `windows == 0`, and
     `amplitude >= center_rate` (a negative target rate is invalid — the constructor is the guard, mirroring
     latency's p50≤p95≤p99 invariant). Rates are a plain integer unit (spans per window).
2. **Seeded count sampler** — a **public** `RateCurve::window_counts(&self, seed: u64) -> Vec<u32>`:
   seed one `ChaCha8Rng::seed_from_u64(seed)` (arch §Determinism RNG), and for each window `w` compute the
   curve's target rate, multiply by a **bounded seeded jitter** (≈ ±15%, one seeded draw per window via a
   local uniform-`[0,1)` helper mirroring `latency.rs:142 next_unit`), round, and clamp `≥ 0` → `u32`.
   The jitter is **required, not cosmetic**: per the determinism-both-directions convention (testing rule +
   session-learning 2026-06-16) the seed must materially drive output, so different seeds must yield different
   count sequences — an un-jittered exact-target sequence would make the seed inert and the diverge test
   unpassable (research §Open questions OQ-jitter). `window_counts` is public (unlike latency's private
   sampler) because the count sequence *is* the meaningful P-026 "breathing shape" artifact and is asserted
   directly in both unit and integration tests (research §Open questions OQ-window-visibility).
3. **`rate_trace_request(service_name, seed, curve, span_name) -> ExportTraceServiceRequest`** — compute
   `curve.window_counts(seed)`, then emit that many root `OK` spans **per window, in window order**, as one
   flat span list under a single `service_resource(service_name)` / `ScopeSpans` (the latency-builder shape,
   `latency.rs:72-104`). Reuse the shared `pub(crate)` primitives `service_resource`, `ok_status`, `span`
   (`message.rs`) and `gen_id::<16>`/`gen_id::<8>` (`span_tree`) off the same RNG for seeded ids. Timestamps
   stay wall-clock (`unix_nanos`) — the seed governs counts + ids, never the clock (research §Patterns
   "wall-clock isolation"; security-plan §Anti-Patterns Logging clock-source).
4. **Re-export + module-doc** — in `lib.rs`: add `mod rate;`, `pub use rate::{rate_trace_request, RateCurve};`,
   and extend the module-doc trace-request enumeration to list `rate_trace_request` (research §Files to
   modify). Add a `rate.rs` module-doc stating the determinism contract + the rate-analogue-of-latency framing
   and that P-026 is verified visually downstream, not here.
5. **In-crate unit tests** (`#[cfg(test)] mod tests` in `rate.rs`) — plain `#[test]` + helper loops (the crate
   has **no rstest** dev-dep; match the pii/latency convention — do NOT add a dev-dep). Cover: constructor
   validation (reject zero windows / zero period / amplitude≥center; accept valid); same-seed ⇒ identical
   `window_counts`; ≥2 fixed seeds ⇒ divergent `window_counts`; ramp realization (mean of the first third <
   mean of the last third for a rising ramp, within tolerance); breathing realization (min < center < max and
   mean ≈ center within tolerance); `rate_trace_request` emits exactly `Σ window_counts(seed)` spans under the
   service name, all `OK`, well-formed ids (16/8 bytes, empty parent), in window order.
6. **Loopback integration test** (`tests/traffic_rate_ramps.rs`) — mirror `tests/latency_shaping.rs`:
   `CapturingService` + ephemeral-`127.0.0.1:0` stub + `TraceEmitter::connect`. Export a ramp and a breathing
   curve; assert the captured request's total span count equals `curve.window_counts(seed).iter().sum()` and
   is reproducible across two builds with the same seed. **Never bind `:4317`** (reserved for the Epoch-4
   port-occupier — testing session-learning 2026-06-17). The refused-transport `EmitError` case is already
   covered by `latency_shaping.rs`; do not duplicate.

## Implementation notes
- **Jitter is a correctness requirement, not polish** — without seeded per-window jitter the seed is inert and
  the `different_seeds_diverge` assertion cannot pass (and the component would silently fail the "seed is
  wired through" intent). Keep the band small (≈±15%) so the realized counts still track the curve within the
  tolerance the realization tests assert.
- **`window_counts` is public on purpose** (a deliberate divergence from latency's private `sample_durations_nanos`):
  the per-window count sequence is the P-026 "breathing shape" itself, so it is the asserted contract surface
  for both unit and integration tests — this resolves how the integration test sees per-window structure
  without abusing `ScopeSpans` as window buckets or adding window attributes.
- **Breathing constructor guards the sign** — reject `amplitude >= center_rate` in the constructor (the
  `LatencyProfile`-style invariant) so a window's target rate can never go negative; counts still clamp `≥ 0`
  defensively after jitter.
- **Self-contained seeded-uniform helper** — `rate.rs` carries its own small `[0,1)` draw mirroring
  `latency.rs next_unit`; hoisting a shared helper into `message.rs` is a non-goal for this chunk.
- **Match crate test convention** — plain `#[test]` + `PiiCategory::all()`-style loops; the crate has no
  rstest/proptest dev-dep and this chunk does not add one (the tests extract's rstest suggestion does not fit
  conductor-emit).
