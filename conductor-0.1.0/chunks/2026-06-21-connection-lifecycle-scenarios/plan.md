## Goal

Author the first real entries of the `scenarios/` catalog — four declarative TOML scenarios keyed one-to-one to
Pulse's connection-lifecycle capabilities **P-001..P-004** (per `refs/pulse-capability-spec.md` §1 Connection &
Health Awareness): the receiver lifecycle state machine (P-001 Listening→Receiving→Idle→Stalled), last-span-ago
tracking (P-002), the ReceiverFailed surface via port conflict (P-003), and orthogonal health domains (P-004).
Each carries a single `p_id`, a phase sequence encoding the lifecycle timing, an SLO tier, and — the carried
follow-up (d) work — a declarative `expected` read-back block.

To carry those read-back targets, extend the core `Scenario` model with an additive `expected: Vec<ExpectedCheck>`
field (per arch §[Scenario Config Format] + obs-plan §3): `#[serde(default)]` so existing TOML (and
`error-baseline-spike.toml`) stays valid, `#[garde(dive)]` so each check validates at load (the verdict/error
wall — bad config is `CoreError`, never a panic; security-plan §Input Validation). `ExpectedCheck`/`ClaimClass`/
`ComparisonKind` already exist and are exported (`expected.rs`, `lib.rs:33`); this chunk wires them into the
scenario config carrier — it does **not** build the live read-back run (the Epoch-8 CLI driver consumes
`scenario.expected`) nor the visual badge (Epoch 9). `holds` stays deferred: drive+observe timing claims need no
operator go/no-go, and the visual lifecycle-badge claim routes to the `ManualCheck` report-state, not a `HoldPoint`.

The deliverable is the four TOMLs + the `expected` model wiring + round-trip/validation tests proving each
scenario deserializes, garde-validates, and produces a valid `PhaseTimeline` — the established
`error-baseline-spike` fixture pattern (`scenario.rs:279`), extended.

- **Blast radius** is 3 test struct-literals (`Scenario @ scenario.rs` `scenario_with`, `convert.rs:37`,
  `error.rs:51`) — additive append only; the field defaults empty so production paths and the existing
  `error-baseline-spike.toml` fixture test stay green.
- **Realization is deferred, by design.** The TOMLs declare timing (phase gaps + legible names), identity, tier,
  and read-back targets. The on/off emission + silence (Listening = no spans; Idle/Stalled = stopped) and the
  P-003 `:4317` bind are realized by the Epoch-8 CLI driver over the existing emission + `conductor-faults`
  machinery — not here. If faithful in-config silence is later wanted, `EmissionSpec` is `#[non_exhaustive]`
  (`phase_spec.rs:44`) and is the natural extension point (a follow-up, not this chunk).
- **`slo_tier` is scenario-level** (one per scenario). Per-state sub-deadlines (Receiving ≤1s, ReceiverFailed
  ≤2s, Stalled >60s) ride in phase gaps + the `expected` targets; fine-grained per-claim timing is the Epoch-8
  evaluator's concern.
- **Do not extend `ComparisonKind`** for the P-002 ±1s tolerance window this chunk — express the tracker target
  with the closest existing kind and leave the tolerance to the evaluator (keep the model change additive-minimal,
  matching the user's "wire expected" scope, not "extend the comparison vocabulary").
- **`holds` deferred** — no `HoldPoint` wiring; the drive+observe visual claim is a `ManualCheck` report-state
  the Epoch-8/9 surfaces render, not an operator go/no-go gate.
