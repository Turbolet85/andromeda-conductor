## Goal

Build the generator that produces **`coverage-matrix.md`** — Conductor's definition-of-done artifact: every
Pulse capability **P-001..P-060 enumerated with zero gaps**, each re-classified into exactly one **Conductor
verification mode** — `auto` (Conductor drives AND asserts: journal + MCP read-back + timing), `drive+observe`
(Conductor induces the state, the operator confirms the visual/UX claim via the checklist), or `static-only`
(no dynamic telemetry dimension — stays with Pulse's own test matrix; Conductor does not duplicate it). The
classification source is `input.md` §Coverage classification, seeded at authoring time from the audit verdict
tables in `.andromeda/refs/` (`capability-verification-matrix.json` + `pulse-v0_2_0-capability-audit-2026-06-12.md`).
Per design-system §Anti-Patterns ("the lens shift"), the audit's *Pulse-side* modes (`automated-nextest` /
`by-construction` / …) are **re-mapped** to Conductor's three lenses, never copied.

Scope was confirmed **classify-only** (user decision at P4): the Epoch-6 artifact is the static classification
table (mode per P-ID) — **no `runs.db` reads and no `Lamp` usage** this chunk, per the arch + layouts extracts
("no live-status in the Epoch-6 classification model"; "no live-status columns before Epoch 7"). There is no
per-P-ID run index and no scenarios until Epoch 7, so a live status column would be ~all em-dashes. `Lamp`
reuse (carried follow-up (c); `lamp.rs:9-10` already names the coverage matrix a Lamp consumer) is the
**Epoch-8 CLI table + Epoch-9 desktop view** status-overlay seam, where real run data exists — documented here,
not wired now.

Structurally this mirrors the `RunReport` seam (per arch extract + research): the **model** (`CoverageMode`
enum + the committed 60-row table) lives in `conductor-core` (the dep-root that Epoch-8/9 surfaces will reuse),
and the **Markdown render + artifact write** live in `conductor-report` — a pure clock-free `render()` →
exact-string golden, like `RunReport::render` (report.rs:57). The classification is **code-native** (a
committed Rust `const`/fn, the source of truth) — NOT read from the refs JSON at runtime — so the render stays
pure, deterministic, golden-testable, and free of any new untrusted input boundary (per security extract).

## Implementation Steps

1. **`CoverageMode` enum + capability row (conductor-core, new `mod coverage`).** Define `CoverageMode {
   Auto, DriveObserve, StaticOnly }` with `#[derive(…, Serialize, Deserialize)]` and `#[serde(rename = "auto"
   / "drive+observe" / "static-only")]` (the wire form is the single source of truth for the Markdown spelling,
   mirroring report.rs:160 `wire()`), plus a `label()`/`as_str()`. Define a `CapabilityRow` carrying the P-ID,
   title, category, and `mode` (titles/categories sourced from the refs JSON). Keep it `&'static str`-backed
   so the table is a `const`/fn with no allocation and no IO.
2. **The 60-row classification table (conductor-core).** A `pub fn coverage_matrix() -> &'static [CapabilityRow]`
   (or `[CapabilityRow; 60]`) enumerating **P-001..P-060 in canonical order**, each classified per the rules
   below. This is the chunk's substance — authored from the seed, validated by the completeness test.
   - **Classification rules** (per input.md §Coverage classification):
     - `static-only` — the named set is binding: **P-038 (clipboard), P-040 (MCP-independence), P-046 (export
       UI), P-049 (encryption-at-rest), P-051 (storage UI), P-054 (four-host matrix)** — plus any other
       capability with no dynamic telemetry dimension (pure-UI / by-construction / host-matrix). These stay
       with Pulse's matrix.
     - `drive+observe` — visual/UX claims Conductor induces but the operator confirms via checklist (halo
       hue/breathing P-025/P-026, widget invariants P-024/P-028/P-029, dropdown order, no-notification P-030,
       constellation visuals P-027, in-app report surface P-037). The JSON's "Dynamic-verification (Conductor)"
       notes mark capabilities where Conductor owns the *timing* bound but the *visual* is operator-observed.
     - `auto` — everything Conductor drives AND asserts via journal + MCP read-back + timing (hard signals
       P-005..P-008, anomaly/baseline P-009..P-014, patterns P-015..P-018, severity lifecycle P-019..P-023/P-060,
       diagnostic quality with MCP read-back P-031..P-036, memory/learning P-041..P-045, etc.).
3. **Completeness self-test (conductor-core).** Assert: exactly 60 rows; the P-ID set equals `{P-001..P-060}`
   contiguous with **no gaps and no duplicates**; the named static-only anchors (step 2) are `StaticOnly`.
   This IS the "definition of done, zero unclassified" gate — a missing/duplicate P-ID is a defect.
4. **`CoverageMatrix` render (conductor-report, new `mod coverage`).** `CoverageMatrix::render() -> String` —
   a **pure, clock-free** Markdown builder (mirror report.rs:57): a title, a summary line (per-mode counts in
   fixed order — deterministic, no map iteration, mirroring report.rs `lamp_counts`), and a table with one row
   per P-ID (`P-ID | Title | Category | Mode`), the `Mode` rendered via the serde wire string. No `Lamp`, no
   status column.
5. **`CoverageMatrix` write (conductor-report).** `CoverageMatrix::write(out_path) -> Result<PathBuf, ReportError>`
   — **atomic deterministic overwrite** (`.tmp` → rename), NOT `create_new`. The coverage matrix is a
   regenerated project-root singleton (definition-of-done), so regeneration MUST succeed; same classification ⇒
   byte-identical file. Reuse `conductor_report::ReportError` for the IO fault (it is `#[non_exhaustive]`,
   `Io(#[from] std::io::Error)` — the report-seam harness-fault type; the verdict/error wall). The caller passes
   an already-resolved path (project-root `coverage-matrix.md`); `CONDUCTOR_*` path resolution is a cli-edge
   concern deferred to Epoch 8.
6. **Wire the exports.** `conductor-core/src/lib.rs`: `mod coverage;` + `pub use coverage::{CoverageMode,
   CapabilityRow, coverage_matrix};`. `conductor-report/src/lib.rs`: `pub use coverage::{CoverageMatrix};`.
7. **Render + write + hygiene tests (conductor-report).** Exact-string golden for `render()` (`assert_eq!`,
   not insta — per tests extract + 2026-06-16 amendment); a `no_host_paths_or_struct_names_leak` test
   (mirror report.rs:293 — no `C:\`, `/Users/`, `/home/`, no `CoverageMatrix`/`CoverageMode`/`CapabilityRow`);
   a determinism test (two renders byte-identical); a write round-trip (write then read equals render) and a
   **re-write-succeeds** test (second write to the same path overwrites cleanly — the inverse of the run
   report's never-overwrite, asserting the singleton-regeneration semantics).

## Implementation notes
- **Classify-only is user-confirmed** (P4 AskUserQuestion). Do NOT add a runs.db query or a Lamp status column
  this chunk — that is the Epoch-8 (CLI table) / Epoch-9 (desktop view) status overlay.
- **Write semantics differ from the run report on purpose:** `RunReport::write` is `create_new` (per-run
  immutable, never overwrite); `CoverageMatrix::write` is overwrite (a single regenerated definition-of-done
  file). The security + tests extracts said "loud-never-overwrite consistent with the run-report seam" — that
  borrowed assumption is wrong for a regenerated singleton; use atomic overwrite and assert re-write succeeds.
- **Code-native classification, not a runtime JSON read:** the refs JSON + input.md are the authoring seed; the
  committed Rust table is the source of truth. This keeps the render pure and avoids a new input boundary
  (security extract). If the audit JSON drifts later, regenerate the table by hand (it is the def-of-done).
- **obs instrumentation is DEFERRED:** the obs extract proposed a `report.coverage_matrix_generate` span +
  `coverage_percent`/`missing_p_ids` runs.db columns — this conflicts with the handoff's already-deferred
  `report.generate` obs span (lands with the Epoch-8 cli/timeline caller). Do NOT add self-obs spans or new
  runs.db columns here; the Epoch-6 generator is a pure render + write primitive with no driver yet.
- **Mode is not a Lamp:** render the `CoverageMode` as its plain serde wire word (`auto`/`drive+observe`/
  `static-only`); do not invent `[AUTO]`-style prefixes that would collide with the `[PASS]`-style Lamp ASCII
  prefixes (status is a different axis, deferred).
