## Goal

This chunk supplies the two pieces the prior chunk (`verdict-assertion-policy-split`) explicitly deferred:
`classify(class, matched, observed, expected) → Assessment` takes `matched` as a **pre-computed** bool and
carries **no timing** at all. Here we build (a) the declarative **expected-outcome model** that says what a
check expects to observe and which comparison to apply, and (b) the **journal-relative SLO timing model** that
turns two instants into a within/exceeded deadline result — then the **evaluator** that resolves both into the
`(matched, ClaimClass)` the existing `classify` consumes (per arch §Timing-Tolerance Model + §Probabilistic-
Assertion Policy).

The data model lives in `conductor-core` next to the scenario model — serde + garde, validated at load — so
the claim class is *declared up front, never guessed at runtime* (arch §Probabilistic-Assertion Policy). That
requires moving the existing `ClaimClass {Hard, CalibrationRegion}` from `conductor-verify` into core (a core
verdict-vocabulary type beside `Verdict`); verify re-exports it for source-compatibility. The evaluator
(comparison application + SLO deadline check + the `classify` hand-off) lives in `conductor-verify` beside
`verdict.rs`, importing only `conductor_core` (star topology preserved, per arch §Module Boundaries).

Reuse, not re-create: **`SloTier {Tier5s,Tier20s,Tier90s}` already exists** in core (`scenario.rs`) and the
**`RunRecord` envelope already carries `latency_ms: Option<i64>` + `slo_tier`** — this chunk *computes* those
values; it does not reshape the envelope (Epoch 6 serializes/persists it) and does not add a comparison flow's
end-to-end wiring (Epoch 6/8), matching the prior chunk's "ship standalone, defer wiring" pattern. The
evaluator stays **infallible** (returns values; no new `VerifyError` variant) — the verdict/error wall; the only
`Err` path is the model's garde load-time validation, which is core's existing `CoreError::Validation`.

## Implementation Steps

1. **Move `ClaimClass` to core.** Relocate the enum from `conductor-verify/src/verdict.rs` into a new
   `conductor-core/src/expected.rs`. Add `Deserialize` (it is config now) alongside the existing `Serialize`;
   keep the canonical-name spelling golden (`"Hard"`/`"CalibrationRegion"`). Re-export from `core/lib.rs`. In
   `verify/verdict.rs`, delete the local definition and import `conductor_core::ClaimClass`; `verify/lib.rs`
   re-exports `conductor_core::ClaimClass` so `conductor_verify::ClaimClass` still resolves for callers and the
   prior chunk's tests (research §Graph impact: `ClaimClass` has no external callers yet — blast radius is
   `verify/verdict.rs` + `verify/lib.rs` only).

2. **Define the comparison model in core** (`expected.rs`). A closed `ComparisonKind` enum — the deterministic
   comparison primitives drawn from the spec (candidate set: `Exact`, `Contains`/membership, `Present`,
   `Absent`, `CountAtLeast` sample-floor; finalize variants + wire spelling against test-plan §5 / arch
   §Probabilistic-Assertion Policy). Lock its serde wire form with an exact-string golden, following the
   `SloTier`/`Signal` closed-enum precedent (research §Patterns). An `ExpectedCheck` struct carries the
   declared `kind: ComparisonKind`, the declared `class: ClaimClass`, and the expected target value(s) —
   `#[derive(Serialize, Deserialize, garde::Validate)]` with field/cross-field rules (non-empty target where
   the kind requires one; numeric floor parses for `CountAtLeast`). garde validation runs at load and surfaces
   as `CoreError::Validation` (the established `Scenario::from_toml_str` discipline, research §Conventions).

3. **Add the SLO deadline bound to core.** An additive `impl SloTier { fn deadline_ms(self) -> i64 }` mapping
   `Tier5s→5_000 / Tier20s→20_000 / Tier90s→90_000` (the tier IS the tolerance band; arch §Timing-Tolerance
   Model). Purely additive — **does not touch the `Scenario` struct** (the P4 constraint), it adds an impl
   block beside the existing `SloTier`.

4. **Build the SLO timing evaluator in verify** (new `conductor-verify/src/slo.rs`). `evaluate_slo(tier,
   journal_emitted_at, read_back_observed_at) → SloOutcome { latency_ms: i64, within_tolerance: bool }`:
   `latency_ms = read_back_observed_at − journal_emitted_at` (journal-relative, `i64` ms, sourced from
   `std::time` — never tokio's virtual clock; arch/obs/security extracts); `within_tolerance ⇔ latency_ms ≤
   tier.deadline_ms()`. Guard the clock-anomaly edge (observed-before-emitted / negative latency). A runtime
   *hardware-profile* tolerance scaler is OUT of scope — the three tiers are the hardware-profile-aware buckets
   (flagged; see Implementation notes).

5. **Build the comparison + combiner in verify** (`slo.rs` or a sibling). `compare(check: &ExpectedCheck,
   observed) → bool` applies `check.kind` deterministically and infallibly. The combiner takes the
   `ExpectedCheck`, the observed value, and the two timestamps, and resolves: `matched = value_matched &&
   slo.within_tolerance` for a `Hard` claim; a `CalibrationRegion` claim (or an unmet `CountAtLeast`
   sample-floor) routes to `CalibrationRegion` and is **never hard-failed** (arch §Probabilistic-Assertion
   Policy). It calls `classify(class, matched, observed, expected)` and returns a result carrying the
   `Assessment` + the journal-relative `latency_ms` + the `within_tolerance`/`slo_tier` (the values the Epoch-6
   `RunRecord` envelope will consume). `observed`/`expected` redaction is already applied inside `classify`
   (`redact_value`); ensure the evaluator passes through, not around, that edge (security extract).

6. **Wire the verify surface.** `verify/lib.rs`: `mod slo;` + re-export the evaluator's public types
   (`SloOutcome`, `evaluate_slo`, `compare`, the combiner + its result), plus the `ClaimClass` re-export from
   step 1; reword the module doc to add the timing/comparison layer.

7. **Tests** (in-module `#[cfg(test)]` + a `conductor-verify/tests/` integration file). Comparison-kind matrix
   (`#[rstest] #[case]` over every `ComparisonKind` → expected `matched`), SLO tier/deadline matrix (each tier:
   within vs exceeded, boundary at `deadline_ms`, the clock-anomaly guard), determinism (same inputs ⇒
   identical `Assessment` + identical `SloOutcome`), redaction (a host-path observed ⇒ `<redacted>` in the
   `Assessment`), and exact-string serialization goldens for `ComparisonKind` + the moved `ClaimClass`. garde
   valid/invalid `ExpectedCheck` matrix in core (`expected.rs` tests).

## Implementation notes
- **`ClaimClass` move is the one cross-symbol change.** Re-export it from `verify` (`pub use conductor_core::ClaimClass;`) so `conductor_verify::ClaimClass` keeps resolving; it gains `Deserialize` (config now). No external callers exist yet (research §Graph impact), so the move is low-risk — but the full-workspace gate is in the test list to catch any straggler.
- **Comparison/SLO combine into `matched`** for a `Hard` claim as `value_matched && within_tolerance`; a `CalibrationRegion` claim ignores `matched` (classify routes by class). An unmet `CountAtLeast` sample-floor forces `CalibrationRegion` regardless of the declared class (sample-count floors never hard-fail — arch §Timing-Tolerance Model).
- **Tolerance = the tier bound** (`within ⇔ latency_ms ≤ deadline_ms`); a *runtime hardware-profile* scaler is intentionally NOT built here — the three tiers are the hardware-profile-aware buckets. If a future chunk needs per-host scaling, it extends `deadline_ms` then. Surface this trim at the P5 review.
- **Clock-anomaly edge:** observed-before-emitted (negative latency) must not silently pass — guard it (e.g. `within_tolerance = false` + the raw `latency_ms` retained for the human-facing delta).
- **Determinism:** the evaluator reads no clock itself — the two instants are inputs — so "same inputs ⇒ identical outputs" holds trivially; assert it both directions in tests (the seeded-component testing learning).
- **Scenario/TOML untouched:** Epoch 7 ("scenario catalog") wires the per-P-ID `expected` blocks into the scenario files (and may add the optional `Scenario.expected` field then, per the EmissionSpec forward-compat precedent).
