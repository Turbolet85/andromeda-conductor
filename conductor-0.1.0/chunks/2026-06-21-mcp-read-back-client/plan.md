## Goal
Fill the `conductor-verify` seam (today a one-line stub) with its foundational **MCP read-back client/transport
layer**: an rmcp 1.7.0 client that spawns the Pulse MCP sidecar over stdio, negotiates the protocol version
*down* to Pulse's hand-rolled `2024-11-05`, and exposes a typed tool-call surface for the four consumed
read-back tools. This is the session foundation only — the preflight gate (version assertion + tool-presence +
data-dir canary, `Blocked` on mismatch), the OTLP egress liveness check, and verdict classification are later
Epoch-5 chunks that build on this handle (per architecture §Established Decisions [MCP Read-Back Client] +
§Read-Back Dependency Posture).

Two invariants shape the design. First, **subprocess-spawn hardening** (per security-plan §Anti-Patterns §Code
Patterns + §Input Validation): the sidecar is launched from a FIXED hard-coded program path via
`TokioChildProcess`; `ANDROMEDA_PULSE_DATA_DIR` is propagated strictly through the `.env(...)` builder *after*
rejecting injection metacharacters — never interpolated into argv or a shell (the rmcp STDIO injection class,
CVE-2026-30623) — and the platform default is resolved when the live Pulse leaves it unset. Second, the
**verdict/error wall** (per architecture §Conventions Error handling, mirrored from `conductor-faults`): a
`VerifyError` thiserror enum carries only *harness faults* (spawn failure, transport down, rejected config,
bounded-decode failure); a protocol-version difference or an absent tool is exposed as DATA (an accessor the
*gate* chunk later maps to `Blocked`), NOT a `VerifyError` — keeping gate semantics out of this chunk.

Per the P4 scope decision (test depth), this chunk ships the full client API but proves it with an **rmcp
in-process duplex stub** (session / negotiation / tool-call logic) plus **pure unit tests** (metacharacter
rejection, data-dir default resolution, error mapping); the real `TokioChildProcess` child-spawn integration
test is deferred to the preflight/boot chunk that first needs it (and CI's `ready:true` stub leg).

2. **`VerifyError` enum** (`src/error.rs`) — mirror the `FaultError` template (`faults/error.rs:13-38`):
   `#[derive(Debug, thiserror::Error)] #[non_exhaustive] pub enum VerifyError` with struct-like variants +
   per-variant `#[error("…")]` + `#[source]`-chained underlying errors. Harness-fault variants only — e.g.
   `SpawnFailed { #[source] source: io::Error }`, `Transport { … }` (rmcp/service error), `DataDirRejected
   { … }` (metacharacter found), `Decode { … }` (bounded-decode failure). NO "version mismatch" / "tool
   absent" variant (those are gate-mapped values, per the wall). One Display unit test per variant.
3. **Hardened sidecar spawn** (`src/spawn.rs`) — pure, unit-testable spawn *config*: (a) a `data_dir`
   resolver that returns the caller-supplied dir or the platform default (`%APPDATA%\andromeda-pulse` on
   Windows · `$XDG_CONFIG_HOME`/`~/.andromeda-pulse` on Linux); (b) an injection-metacharacter validator
   that rejects `$`, backtick, `|`, `;`, `&`, `<`, `>`, `\n`, etc. → `VerifyError::DataDirRejected`; (c) a
   builder that assembles the `TokioChildProcess`/`Command` config from the FIXED hard-coded
   `andromeda-pulse-mcp` program path + `.env(ANDROMEDA_PULSE_DATA_DIR, validated)` — never argv/shell. The
   constant program path lives here.
4. **rmcp read-back client** (`src/client.rs`) — the `ReadbackClient`:
   - `connect(data_dir)`: build the spawn config (step 3), set `ClientInfo` so the handshake **negotiates to
     `2024-11-05`** and tolerates Pulse's minimal capabilities (NOT a strict newer default — the silent-mismatch
     guard, per architecture §[MCP Read-Back Client] + security-plan §Anti-Patterns), then `serve_client()`
     over the child stdio; map spawn/transport failures to `VerifyError`.
   - `negotiated_protocol_version()`: accessor reading `peer_info()` — the value the gate chunk asserts.
   - typed `list_tools()` + per-tool `call_tool` wrappers for the four consumed tools, keyed by name consts
     `QUERY_INCIDENT_LIST` / `RETRIEVE_REPORT` / `RETRIEVE_TELEMETRY_SLICE` / `MARK_INCIDENT_RESOLVED`
     (define the consts here; the contracts manifest chunk references them). Bounded decode on results; rmcp
     errors → `VerifyError`, never `unwrap`/`expect`/panic.
   - `#[tracing::instrument]` spans named `verify.readback*` on `connect` + each tool call (per obs-plan §11
     bounded span set + observability rule); error logs sanitized of host paths.
5. **Re-exports + crate doc** (`src/lib.rs`) — replace the stub line: `mod error/spawn/client;` + `pub use`

6. **Tests** (`#[cfg(test)]` modules + `tests/readback.rs`) — per the P4 decision + testing rule:

## Implementation notes
- **rmcp feature names (open Q1):** `client` is confirmed; the child-process transport feature must be verified against rmcp 1.7.0's actual `Cargo.toml` (likely `transport-child-process`). `TokioChildProcess` lives behind that feature.
- **Negotiation is configured, not just observed:** rmcp's `serve_client()` performs the `initialize` handshake; if the client defaults to a newer protocol it can fail against Pulse's `2024-11-05` server. Set `ClientInfo`/protocol version so the handshake *succeeds* at `2024-11-05` — this is the concrete realization of "negotiate DOWN", and the silent-mismatch the preflight exists to prevent.
- **Verdict/error wall discipline:** resist adding `VersionMismatch`/`ToolAbsent` to `VerifyError` — they are gate-decided values. This chunk only *reports* the negotiated version + tool list.
- **`Cargo.lock` drift is expected** on first rmcp resolve; the gate is re-committing it un-drifted with audit/deny green (rmcp pulls a large transitive tree — real supply-chain checkpoint).
- **Determinism:** transport I/O is not seeded; no tokio virtual clock here. Latency stamping (`std::time`) is the SLO-timing chunk's job, not this one.
- **Stub reuse:** the in-process duplex stub built here is the seed of the fuller rmcp stub the preflight/boot chunk (+ CI `ready:true` leg) will extend to a `TokioChildProcess` child binary (deferred per the P4 decision).
