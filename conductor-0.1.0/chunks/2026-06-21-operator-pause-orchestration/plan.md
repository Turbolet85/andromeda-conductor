## Goal

Ship the runtime-agnostic **operator-pause hold/resume mechanism** — the typed hold-point, the go/no-go
decision, a resolver abstraction, and the headless never-block default — as a self-contained, CI-testable
unit in `conductor-core`. A hold represents a **non-Conductor action** (a Pulse restart for P-015, a manual
observation of a visual claim that terminates in `ReportState::ManualCheck`, any go/no-go gate before a
committed step) that Conductor will not perform itself; the mechanism lets a future run driver pause, await a
`Decision`, and resume. Per the research, **no higher-level run orchestrator exists yet** (`run_timeline` is
called only by tests), so this chunk builds the mechanism in isolation with a stub/headless resolver; threading
it into a full preflight→emit→timeline→verify run and surfacing it on the CLI/Tauri shells is **Epoch 8/9**
(deferred consumers). The data + trait mirror the `expected.rs` (closed-enum + garde) and verify `classify→
Assessment` (infallible, redacted, serializable-value) precedents, and uphold the verdict/error wall, the
determinism bar (a hold is a wall-clock gap only, outside the seeded virtual clock), the star topology, and the
artifact-hygiene redaction edge.

## Implementation Steps

1. **Create `crates/conductor-core/src/pause.rs`** with the operator-pause vocabulary (mirror the
   `expected.rs` definition style — closed enums, garde struct, canonical-serde + round-trip tests):
   - `Decision` — closed enum `{ Go, NoGo }`, `#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize,
     Deserialize)]`, serializing to canonical PascalCase (`"Go"`/`"NoGo"`). Give it a `label()` (e.g.
     `"Go"` / `"No-Go"`) so downstream cli/desktop rendering never relies on color alone (the universal
     status invariant); the `[HOLD]` amber phase-line itself is the shells' concern (Epoch 8/9) — note
     `[HOLD]` is already `Verdict::CalibrationRegion`'s glyph, so do NOT reuse a verdict prefix for `Decision`.
   - `HoldPoint` — the hold description: scenario identity (reuse `conductor_core::PId` for the P-ID if its
     shape fits cleanly, else a garde-validated `String`) + a `scenario` name + a step/label + a
     human-readable `prompt` (the non-Conductor action) + an `allow_no_go: bool`. `#[derive(Debug, Clone,
     PartialEq, Eq, Serialize, Deserialize, Validate)]`; garde `length(min = 1)` on the non-empty text
     fields (a malformed hold at load → `CoreError::Validation`, the only `Err` on this path).
   - `HoldResolution` — the recorded outcome **value** (mirror `Assessment`): `#[derive(Debug, Clone,
     PartialEq, Eq, Serialize)]` carrying the `decision: Decision`, the scenario/P-ID echo, and the
     **redacted** prompt (`redact_value` applied at construction, exactly like `classify` redacts
     observed/expected) so no absolute host path / struct name reaches a log line or the Epoch-6 artifact.
   - `PauseResolver` — the resolver trait. **Declare the method with RPITIT, not `async fn`**, to avoid the
     `async_fn_in_trait` lint under the `-D warnings` clippy gate:
     `fn resolve(&self, hold: &HoldPoint) -> impl Future<Output = Decision>;`. Impls may use `async fn`.
     Doc it as "how a hold is answered"; the CLI (`inquire`, Epoch 8) and Tauri (dialog, Epoch 9) resolvers
     are deferred implementors named in the doc.
   - `HeadlessResolver` — the never-block default: holds a configurable `default: Decision`
     (`HeadlessResolver::new(Decision)` + ergonomic `::proceed()`/`::abort()` constructors — never hardcode
     a single outcome, per design extract, so tests can exercise both branches). `impl PauseResolver` returns
     `self.default` immediately (an already-ready future) — it **never awaits user input** (the headless
     invariant: the agent path is never blocked on a prompt; the decision is recorded to the artifact).
   - `resolve_hold<R: PauseResolver>(resolver: &R, hold: &HoldPoint) -> HoldResolution` — the async
     orchestration primitive: `await`s `resolver.resolve(hold)`, builds and returns a `HoldResolution`
     (redacting the prompt). **Infallible** — a value, never `Result::Err` (the verdict/error wall). Generic
     over `R` (no `dyn`, no boxing, no `async-trait`).
   - **Do NOT** add a `#[tracing::instrument]` span yet (see Implementation notes — the `hold.wait_resolve`
     bounded-span name is deferred to Epoch 8 to avoid an obs-plan §11 amendment for an immediately-resolving
     headless call).

2. **Wire the module into `crates/conductor-core/src/lib.rs`** — add `mod pause;` and
   `pub use pause::{Decision, HoldPoint, HoldResolution, HeadlessResolver, PauseResolver, resolve_hold};`
   (alphabetized with the existing re-exports). Update the crate doc-comment: the "no async" characterization
   gains the operator-pause resolver as the one async *abstraction* (the crate is otherwise still
   data-only + the sync obs/path guards; no async runtime dep is added).

3. **Add a `tokio` dev-dependency to `crates/conductor-core/Cargo.toml`** (`[dev-dependencies]`,
   `tokio = { workspace = true, features = ["rt", "macros", "test-util"] }`) — needed only to execute the
   async tests. The runtime `[dependencies]` are unchanged (core stays runtime-async-dep-free; `Future` is
   from `core`). `tokio` is already a vetted workspace dep, so cargo-audit/deny stay green.

4. **In-module unit tests** (`pause.rs` `#[cfg(test)]`) — match the `expected.rs`/`report_state.rs` test shape:
   - `Decision` serializes to canonical names (`"Go"`/`"NoGo"`) + round-trips through JSON.
   - `HoldPoint` garde: a well-formed hold validates; an empty `prompt` (and empty scenario) is rejected.
   - `HoldResolution` redacts a host-path prompt (`C:\Users\...` → `<redacted>`), mirroring
     `verdict.rs::observed_and_expected_are_redacted`.
   - `HeadlessResolver::proceed()`/`::abort()` carry the configured `Decision`.

5. **Integration test `crates/conductor-core/tests/operator_pause.rs`** — `#[tokio::test]` (current_thread):
   - go path: `resolve_hold(&HeadlessResolver::proceed(), &hold)` ⇒ `Decision::Go`; no-go path ⇒ `Decision::NoGo`.
   - never-block / determinism-under-virtual-clock: under
     `#[tokio::test(flavor = "current_thread", start_paused = true)]`, `resolve_hold` with the headless
     resolver **completes without any `tokio::time::advance`** — proving the hold awaits no timer and consumes
     no virtual time (the pause is wall-clock-only, outside the seeded clock).
   - determinism: same `HoldPoint` + same resolver ⇒ identical `HoldResolution` (both-directions style:
     a `Go` resolver and a `NoGo` resolver produce different decisions — proving the resolver drives the result).
   - redaction at the artifact edge: a `HoldPoint` whose `prompt` embeds an absolute host path yields a
     `HoldResolution` whose serialized form contains `<redacted>` and no `C:\Users` / `/home/`.

## Acceptance Criteria

- (arch) `HoldPoint`, `Decision`, `HoldResolution`, `PauseResolver`, `HeadlessResolver`, `resolve_hold` all
  defined in `conductor-core` and re-exported from `lib.rs`; star topology preserved — core adds **no seam
  dependency and no new runtime dependency** (only a `tokio` dev-dep) (per arch extract; research Cargo.toml).
- (arch) Hold resolution is a typed **value** (`HoldResolution` / `Decision` in `Ok`), never `Result::Err`;
  the only `Err` on the path is a garde-invalid `HoldPoint` at load (`CoreError::Validation`) (verdict/error
  wall — arch + security + a11y extracts).
- (arch/layouts) The `HeadlessResolver` **never blocks** — `resolve_hold` completes under
  `start_paused = true` with no `tokio::time::advance` (proven by test); the pause is wall-clock-only,
  outside the seeded virtual clock (headless invariant + determinism — arch/layouts/obs extracts).
- (tests) Determinism: same `HoldPoint` + same resolver ⇒ identical `HoldResolution`; a `Go` vs a `NoGo`
  resolver diverge (both-directions, per the 2026-06-16 testing learning).
- (security/obs/a11y/design) Redaction: the `HoldResolution` prompt is passed through `redact_value`, so an
  absolute host path is masked (`<redacted>`) and no internal struct name leaks (`Display`/serde, never
  `Debug`) into the serialized value (security §Error Handling; obs §11; verdict.rs precedent).
- (design) `Decision` is a closed enum with canonical PascalCase serde + JSON round-trip and a text `label()`
  (status never color-alone); `[HOLD]`/amber rendering is reserved to the shells (design extract).
- (tests) `cargo nextest run -p conductor-core` returns 0 with the canonical-serde, garde valid/invalid,
  determinism, never-block, and redaction tests present.
- (obs) No OTel SDK introduced; no new tracing span added this chunk (the bounded `hold.wait_resolve` name is
  deferred — see notes), so no obs-plan §11 amendment is forced.
- (cross-cutting) `cargo nextest run --workspace --profile ci` returns 0 and
  `cargo clippy --workspace --all-targets -- -D warnings` is clean after implementation.

## Implementation notes

- **Trait shape (clippy gate):** declare `fn resolve(&self, hold: &HoldPoint) -> impl Future<Output =
  Decision>;` (RPITIT), NOT `async fn resolve(...)` — the latter triggers `async_fn_in_trait` which the
  `-D warnings` gate rejects. Implementations (`HeadlessResolver`, and later the shells) use `async fn`,
  which satisfies an `-> impl Future` trait method. Keep `resolve_hold` generic over `R: PauseResolver`
  (no `dyn`, no `Box`, no `async-trait` crate).
- **Core stays runtime-dep-clean:** `Future` comes from `core::future`; only a `tokio` **dev-dep** is added
  for the test executor. Do not add tokio to `[dependencies]`.
- **Headless default is configurable:** `HeadlessResolver::new(Decision)` (+ `proceed`/`abort` helpers). The
  agent-run default outcome is `Go` (proceed), but tests must exercise both branches — never hardcode a single
  outcome (design extract).
- **`PId` reuse:** prefer `conductor_core::PId` for the hold's P-ID field if its public shape composes cleanly
  with serde+garde here; otherwise a garde-validated `String`. Confirm at implement (a minor local choice).
- **Deferred (carry to wrap → later epochs):** (i) the `hold.wait_resolve` bounded tracing span — add when
  `resolve_hold` is awaited around real work (Epoch 8); adding it WILL need an obs-plan §11 amendment, so
  surface it at that wrap, not now. (ii) `Scenario.holds` config field + per-P-ID hold blocks → Epoch 7.
  (iii) `Decision`/`HoldResolution` → `ReportState::ManualCheck` mapping + runs.db/Markdown surfacing →
  Epoch 6. (iv) CLI `inquire` resolver → Epoch 8; Tauri dialog resolver + paused-count `Channel` → Epoch 9.
