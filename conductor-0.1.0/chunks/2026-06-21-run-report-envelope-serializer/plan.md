## Goal
The run-report **envelope** (`RunRecord` in `conductor-core`) and its **JSONL serialization** already exist
— built two epochs early by `2026-06-16-emission-journal-writer`, which needed the schema to write a journal
line. Verified in P3: the 11-field struct, canonical serde with a golden-locked wire form (`run_record.rs:99`),
`RunRecord::blocked(...)` + the Blocked-row null rule, JSON round-trip/determinism, and
`conductor-report::JournalWriter` appending it to `runs/<run_id>.jsonl` with hygiene tests — all present and
green. So this chunk does NOT re-build the type/serde/JSONL.

Per the P4 scope decision (**re-scope to the producer side**), this chunk closes the genuine remaining gap:
the canonical way to **produce a *measured* envelope**. Today only `::blocked()` is a blessed constructor; a
measured `RunRecord` is built ad-hoc via struct literal (test-only), there is no `Verdict → ReportState`
mapping, and the verify-side outcome (`CheckOutcome`/`Assessment`, `conductor-verify/src/slo.rs`) has no
bridge to `RunRecord` (P3 code-graph: `CheckOutcome` has zero cross-seam references). This chunk adds (1) a
`RunRecord::measured(...)` constructor mirroring `::blocked()`, (2) a default `Verdict → ReportState` mapping
helper in core, and (3) the `CheckOutcome → RunRecord` producer bridge in `conductor-verify` — making the
existing envelope the canonical *produced* shape that Epoch-6 chunks 2 (runs.db) and 3 (Markdown) consume.

Per arch §Standard Contracts (envelope shape) + §Probabilistic-Assertion Policy (verdict classes) + the
verdict/error wall (all new fns are infallible values, never `Result::Err`). The envelope continues to carry
`verdict` and `state` as **independent** fields — they are never flattened (report_state.rs doc; design §Color
Palette) — so `measured(...)` takes `state` explicitly and the mapping helper is the auto-path *default*.

## Implementation Steps
1. **`Verdict::default_report_state(self) -> ReportState`** (core, `verdict.rs`) — the auto-verified-path
   default mapping: `Pass → Pass`, `Fail → Fail`, `CalibrationRegion → ManualCheck` (per the P4 decision).
   Named to signal it is a *default* (state is independently settable on the envelope), not a total `From`
   equivalence. Pure/infallible.
2. **Widen `ReportState::ManualCheck` doc** (core, `report_state.rs`) — broaden the doc comment from
   "Visual/operator-checklist claim with no programmatic read-back" to also cover "an auto-measured but
   model-interpretive (calibration-region) check" — both are "terminal, awaits a human go/no-go". Do NOT add
   a sixth state: arch locks `state ∈ {Pass,Fail,ManualCheck,KnownResidual,Blocked}`. Label/prefix unchanged
   (`[MANUAL]`).
3. **`RunRecord::measured(...)`** (core, `run_record.rs`) — mirror `::blocked()` for the happy path. Params:
   `run_id`, `seed`, `scenario`, `p_ids`, `verdict: Verdict`, `state: ReportState`, `journal_emitted_at: String`
   (RFC-3339), `read_back_observed_at: String` (RFC-3339), `latency_ms: i64`, `slo_tier`, `fingerprints:
   Vec<String>`. Sets the five measurement fields to `Some(...)` (the inverse of `::blocked`'s `None`). `state`
   is explicit (a producer with a context-specific state — e.g. `degraded_mode → KnownResidual` — supplies it
   directly); the default helper from step 1 is what the bridge applies. Infallible.
4. **`CheckOutcome → RunRecord` bridge** (verify) — a producer helper that assembles a measured envelope from
   a `CheckOutcome` plus the run/scenario context the outcome does not carry. It maps `assessment.verdict →
   verdict`, applies `verdict.default_report_state() → state`, `slo.latency_ms → latency_ms`, `slo_tier →
   slo_tier`; the caller supplies `run_id`, `seed`, `scenario`, `p_ids`, the two RFC-3339 instants, and
   `fingerprints`. It must NOT copy `Assessment.observed/expected/delta` into the envelope — those are
   Assessment-internal and are not envelope fields. Lives in `conductor-verify` (which already depends on
   `conductor-core::RunRecord`); core gains no new dependency (star topology preserved).
5. **Exports** (verify, `lib.rs`) — re-export the bridge (and `CheckOutcome`/`SloOutcome` if not already
   public) so Epoch-8 wiring and tests can reach it through the crate's public API.
6. **Tests** — see Acceptance Criteria; reuse the existing exact-string golden discipline (NOT insta).

## Implementation notes
- **Graph impact (additive):** `RunRecord#` is referenced at `conductor-core/src/lib.rs:35` (export) +
  `conductor-report/src/journal.rs` (consumer); `measured(...)` is purely additive — no field/signature
  change, the existing consumer is untouched. `CheckOutcome @ conductor-verify/src/slo.rs:52` has no
  cross-seam refs, so the bridge is a clean new edge `conductor-verify → conductor-core::RunRecord`.
- **latency_ms is supplied, not recomputed:** it comes from `SloOutcome.latency_ms` (integer-ms,
  journal-relative). Do NOT re-derive it from the second-precision RFC-3339 instant strings — they cannot
  reconcile exactly, and the strings are the human/display encoding while `latency_ms` is the SLO ground
  truth (arch §Data model conventions).
- **verdict ⟂ state:** the envelope carries both independently; `measured(...)` takes `state` explicitly. The
  default mapping is a convenience the bridge applies for the auto path — `KnownResidual` (degraded_mode) /
  explicit `ManualCheck` producers call `measured(...)` with the context state directly (Epoch 7/8 scenarios).
- **Keep the golden byte-identical:** field order is the struct declaration order; the constructor must not
  reorder. Re-expressing the test fixture through `measured(...)` must leave `run_record.rs:99` unchanged.
- **CalibrationRegion → ManualCheck** widens `ManualCheck`'s meaning (step 2) — update its doc; never add a
  6th `ReportState` (arch locks the five).
- **Carried follow-up (c)** (`Decision → ReportState::ManualCheck` for operator-pause holds) is RELATED but
  distinct (it maps the pause `Decision`, not `Verdict`); it stays deferred — this chunk only maps `Verdict`.
