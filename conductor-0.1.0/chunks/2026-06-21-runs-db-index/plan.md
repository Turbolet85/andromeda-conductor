## Goal
Build the embedded **SQLite cross-run index** (`runs/runs.db`) inside **conductor-report** — the thin,
synchronous convenience layer over the JSONL journal ground truth (per arch §Run-History Persistence). The
seam's `lib.rs` doc already promises *"…+ `runs.db` (rusqlite) storage seam"*; this chunk delivers the
`runs.db` half as a sibling to the existing `JournalWriter`. It adds a `RunsDb` storage type that opens/creates
`runs.db`, bootstraps a fixed-column schema with raw `CREATE TABLE IF NOT EXISTS` SQL (no migration framework,
per arch [ORM] None), and persists one `conductor_core::RunRecord` per `(run_id, scenario)` check via
**bound-parameter** writes (per security-plan §Input Validation), honoring the **Blocked-row NULL rule** (per
arch §Standard Contracts) and storing `fingerprints` + `p_ids` as **JSON1 TEXT arrays** (per arch §Data-model
conventions) so the deferred Epoch-7 P-036 recurrence query can index them.

The envelope (`RunRecord`) already exists in conductor-core with golden-locked serde + `::blocked()` /
`::measured()` constructors; this chunk only maps that struct onto the column contract — no new envelope, no
parallel shape (per obs-plan §6). The write path is the focus; a minimal read (`get` by key) is included only
to prove round-trip in tests (and is forward-useful for the Epoch-8 `status` command). Cross-run aggregation
(latency/percentile, P-036 recurrence) and the `db.insert_run` obs span are explicitly **out of scope** (later
epochs). Code-graph confirms `RunsDb` is an **additive 3rd consumer** of `RunRecord` (after `journal.rs` ×18
and verify `record.rs` ×15) — it changes no existing symbol signature, so blast radius is isolated.

**P4 user decision (timestamp representation):** store the two instant columns as **TEXT RFC-3339** (verbatim
from the JSONL envelope) and `latency_ms` as **INTEGER** (the value the SLO math consumes). Dep-free and
lossless. This **deviates from arch §Data-model conventions' literal "integer-millisecond offsets, not ISO
strings"** wording for those two columns — recorded as a wrap doc-reconcile (see Implementation notes + the
scope.md resolution amendment).

## Schema (the fixed column contract)
```sql
CREATE TABLE IF NOT EXISTS runs (
  run_id                TEXT    NOT NULL,
  seed                  INTEGER NOT NULL,   -- u64 stored as i64 bit-cast (see notes)
  scenario              TEXT    NOT NULL,
  p_ids                 TEXT    NOT NULL,   -- JSON1 array, e.g. ["P-009","P-010"]
  verdict               TEXT,               -- "Pass"/"Fail"/"CalibrationRegion"; NULL for blocked
  state                 TEXT    NOT NULL,   -- "Pass"/"Fail"/"ManualCheck"/"KnownResidual"/"Blocked"
  journal_emitted_at    TEXT,               -- RFC-3339 (P4 decision); NULL for blocked
  read_back_observed_at TEXT,               -- RFC-3339; NULL for blocked
  latency_ms            INTEGER,            -- journal-relative ms (SLO math); NULL for blocked
  slo_tier              TEXT    NOT NULL,   -- "<5s"/"<20s"/"<90s"
  fingerprints          TEXT,               -- JSON1 array; NULL for blocked
  PRIMARY KEY (run_id, scenario)
);
```
Column order is identity-first (not the envelope's serde order — irrelevant for a table). PK `(run_id,
scenario)` is the natural key — no synthetic UUID/serial PK (per arch §Data-model conventions). The five
NULL-able columns are exactly the Blocked-row NULL set, so cross-run queries exclude unmeasured rows cheaply
via `WHERE latency_ms IS NOT NULL`.

## Field mapping (RunRecord → row)
- `seed: u64` → `INTEGER` via `as i64` bit-cast on write / `as u64` on read (rusqlite rejects `u64 > i64::MAX`).
- `p_ids: Vec<PId>` / `fingerprints: Option<Vec<String>>` → JSON1 TEXT via `serde_json::to_string`; `None` →
  SQL `NULL`. (`PId` is serde-transparent → `["P-009",...]` bare strings, per `scenario.rs:18`.)
- `verdict`/`state`/`slo_tier` → their **serde wire string**, derived via `serde_json::to_value(&v)?.as_str()`
  (single source of truth = the `#[serde(rename)]`/variant spelling — no hand-written match that could drift;
  `SloTier` renames to `<5s`/`<20s`/`<90s` per `scenario.rs:40`). `state` is non-NULL; `verdict` is NULL for
  blocked.
- `journal_emitted_at`/`read_back_observed_at: Option<String>` → `TEXT` verbatim; `None` → `NULL`.
- `latency_ms: Option<i64>` → `INTEGER`; `None` → `NULL`.

## Implementation notes
- **Timestamp representation (P4 user decision):** TEXT instants + INTEGER `latency_ms`. **Deviates from arch
  §Data-model conventions' "integer-ms offsets, not ISO strings"** for the two instant columns → a wrap
  **doc-reconcile** (val-1 "intent-incomplete": arch under-specified the columns given the envelope only
  carries second-precision RFC-3339 + a precomputed `latency_ms`; `latency_ms` IS the integer the SLO math
  consumes and is stored as INTEGER, satisfying the convention's intent). scope.md gets a Resolution amendment.
- **`db.insert_run` obs span is DEFERRED to Epoch 8** — the obs extract lists it as a must-trace path, but
  conductor-report has no `tracing` dep and the sibling `JournalWriter` carries no library-level span; the
  span is meaningful only in a run_id-scoped traced context (the cli/timeline caller). Wiring it here would add
  `tracing` to the seam inconsistently. Carried as a follow-up (mirrors the handoff's `hold.wait_resolve` →
  Epoch 8). Surface at P5.
- **enum→TEXT via serde, not a match** — `serde_json::to_value(&v)?.as_str()` keeps the stored spelling
  identical to the JSONL wire form (the `#[serde(rename)]` is the single source of truth); a hand match would
  silently drift if a rename changes.
- **Conflict policy:** PK `(run_id, scenario)` + plain `INSERT` — a duplicate `(run_id, scenario)` raises a
  constraint error (a loud `RunsDbError`, never a silent clobber); append-mostly, one row per check.
- **`bundled` cold-build cost:** first build of `conductor-report` now compiles SQLite C from source (per arch
  §Infrastructure Patterns) — budget a longer initial `cargo build -p conductor-report`.
