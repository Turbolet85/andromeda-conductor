## Goal
Build the verdict-classification mechanism in `conductor-verify` that realizes the architecture's two-state
probabilistic-assertion policy (arch §Established Decisions [Probabilistic-Assertion Policy]): **deterministic
claims** classify to hard `Verdict::Pass`/`Verdict::Fail`; **model-interpretive claims** route to
`Verdict::CalibrationRegion` and are reported-for-human, **never hard-failed on exact values**. The `Verdict`
enum already exists in `conductor-core` (`verdict.rs:13`, with `label()`/`status_prefix()`); this chunk is its
first `conductor-verify` consumer — the logic that *produces* a verdict, not the type.

Per the P4 scope decision (**Option A — minimal split + delta**), the deliverable is two things: (1) a
`ClaimClass { Hard, CalibrationRegion }` policy enum that declares an assertion's class **up front as a
property of the claim, not guessed at runtime** (design-system §Anti-Patterns + layouts contribution); and (2)
a `classify(...)` function returning an `Assessment` outcome **value** — the `Verdict` plus the redacted
observed/expected and a `delta` populated only on the calibration-region path. The hard path is a deterministic
compare (`matched: bool` supplied by the caller) → `Pass`/`Fail`; the calibration-region path always yields
`CalibrationRegion`, capturing the observed-vs-expected delta as the human-facing signal (obs-plan §6 —
CalibrationRegion carries the delta, never hard-fails). Concrete per-scenario `expected` blocks, typed
comparison kinds, and SLO timing tolerance are **explicitly deferred** to the next chunk ("Expected-outcome +
SLO timing model").

Classification is pure and deterministic — no wall-clock read, no RNG (test-plan §2 + security-plan §Logging) —
returns its value infallibly (the verdict/error wall: no transport here, so no harness fault; `VerifyError`
gains no variant). It mirrors the `ReadyState` outcome-as-value pattern already in `preflight.rs:51-75`, and
adds no new crate edge (`conductor-verify → conductor-core` stays the only one; star topology preserved).

## Implementation notes
- **Mirror `ReadyState`** (`preflight.rs:51-75`): `#[derive(Debug, Clone, Serialize)]` outcome struct + accessor,
  `pub` fields, Serialize-only (add `Deserialize` only if a round-trip test demands it).
- **`VerifyError` gains NO variant** — classification is infallible; keep `#[non_exhaustive]` as-is. Do not
  reach for `Result` where a plain value is correct (the wall: `Err` is harness-only).
- **`matched: bool` is the caller's deterministic comparison result** — this chunk does NOT define *what* is
  compared (that is the next chunk's per-scenario `expected` blocks). Keep `classify` generic over the bool +
  the human-readable observed/expected, so the next chunk plugs concrete comparisons in without reshaping it.
- **`delta` only on `CalibrationRegion`** (per the chosen preview); hard `Pass`/`Fail` carry `delta: None` —
  the `Verdict` itself is the hard signal.
- **Do NOT touch** `run_record.rs` / `report_state.rs` — the `Verdict → ReportState` mapping + envelope wiring
  is Epoch 6 (report seam). This chunk stops at producing the `Verdict`/`Assessment`.
- **Keep classification light on instrumentation** — follow the prior chunk's "probe un-instrumented" precedent;
  avoid hot-path `info` logging (obs rule). If a tracing event is emitted for the calibration delta, use a
  bounded `verify.readback`-family name at `debug`, not a per-claim name.
