Per §P-017 (pulse-capability-spec.md:252–260) the fingerprint is a hash of `exception.type` + the first three
normalized stack frames, **insensitive to source path and line** (the amended clause (c)) but **sensitive to
exception type and frame function**. §P-017's observable is explicitly *"no direct user signal — identifier
infrastructure for P-018"*, so P-017 is verified **through** P-018's storm detection: the identical/path/line
triple must aggregate into ONE fingerprint (so a mixed-variant storm counts toward one threshold), while
type/frame variants must stay distinct (so they do NOT aggregate). Per §P-018 (262–270) the same fingerprint
occurring ≥5×/30s emits an attention cue (default hint Suggested), ≥10× escalates to Autonomous; **final
severity is model-determined per P-020**, so — following the unanimous catalog precedent (error-baseline-spike /
latency-regression / activity-floor / restart-suppression all assert the deterministic detector token Hard and
defer model-side severity to P-020) and the **P4 decision (defer-to-P-020 / all-Hard)** — this chunk asserts only
the deterministic **`RetryStorm`** detection token and records the 6→Suggested/12→Autonomous escalation
**declare-only** in TOML comments for the Epoch-8 evaluator + the later P-020/P-021 severity-lifecycle chunk.

Outcome-coherence (a scenario's `expected` evaluates against ONE read-back with no per-check scoping) forces a
**two-file split**: `Contains "RetryStorm"` (the storm fires) and `Absent "RetryStorm"` (distinct fingerprints
do not aggregate) contradict on one token and cannot co-exist in a single file — the same rule that split
activity-floor's P-013/P-014 (per `.claude/rules/testing.md` + the prior chunk's wrap learning).

## Implementation notes
- **`RetryStorm` is an inferred token** (§P-018 uses prose, no canonical PascalCase name) — exactly the
  `LatencyRegression` precedent; `Contains` is substring-tolerant; flag it in the TOML as an Epoch-8 calibration
  point alongside the `<20s` tier and the model-mediated surfacing.
- **30s-window constraint:** all 6 (then 12) occurrences must fall inside one 30s rolling window — keep the storm
  phases' `gap_ms` small enough that the cumulative storm stays within ~30s; note that the Epoch-8 live run owns
  the spec-faithful emission cadence (the activity-floor "Epoch-8 owns convergence" precedent).
- **Distinct-fp counts stay sub-floor:** each of base/type-variant/frame-variant must be < 5 occurrences, else a
  single variant would itself storm and surface a `RetryStorm`, contradicting the `Absent` check.
- **Declare-only legs** (severity escalation; per-fingerprint counts) are recorded in TOML comments only — no
  `[[expected]]` — because `EmissionSpec` carries no count/severity field and the single-read-back evaluator
  cannot disambiguate them (restart-suppression precedent).
- **No golden re-baseline / no silent test join:** seeds 4317017/4317018 feed no golden; each loader case is an
  explicit `#[case]` stem (per the prior chunk's seed-named-golden + new-files-feed-no-golden learnings).
