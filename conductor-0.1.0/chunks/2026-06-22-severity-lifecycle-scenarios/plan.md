## Goal

Author the **severity-calibration + lifecycle family** of the `scenarios/` catalog (P-019..P-023, P-059, P-060)
as declarative TOML consumed by `Scenario::from_toml_str` + garde, plus the per-family loader/guard tests in

family**. Per architecture §Probabilistic-Assertion Policy, *severity choice* (P-019/P-020) is
`CalibrationRegion` (routed to `ManualCheck`, never hard-failed on exact values), while *lifecycle timing*
(P-022 120 s auto-resolve, P-023 cool-down) and *tier→SLO routing* (P-060) stay `Hard`.

Per Q1 (user) the family is **5 TOMLs**: three per-tier severity scenarios that co-satisfy P-019/P-020 (severity
choice, CalibrationRegion) **and** P-060 (each carries a distinct `slo_tier` — `<5s`/`<20s`/`<90s` = Tier-1/2/3);
one auto-resolution scenario (P-022 Hard lifecycle + P-059 CalibrationRegion summary); and one ack-cooldown
scenario. Per Q2 (user) ack-cooldown asserts only the drivable **after-cooldown new-incident** leg as Hard and
declares-only the within-suppression + the ack mechanism (the activity-floor "assert the provable side"
precedent, since "acknowledge" has no clear tool in the pinned 4-tool MCP contract — `mark_incident_resolved` =
resolve, not ack).

This is **catalog wiring over stimuli that already exist** (error-spans / error-rate / latency / fingerprint-storm
/ abrupt-silence / emission-gap-resume from Epoch 3/4): a tier is produced by an existing signal at a calibrated
magnitude (realized by phase NAME at Epoch-8, since `PhaseSpec` carries no count/magnitude field — research.md);
auto-resolution is "trigger then cease". **Target: zero model change, zero dependency, no golden re-baseline**
(per arch + security + tests extracts; research confirms `ComparisonKind {Exact,Contains,Absent,CountAtLeast}`
covers every leg — `Contains "Resolved"` + `CountAtLeast "2"` express the lifecycle-status assertions, scope Q3
closed). **No live MCP run here** (Epoch-8 driver / Epoch-10 E2E).

## Implementation notes
- **Phase NAMES carry the semantics** — `PhaseSpec = {name, gap_ms, emission(default)}` has no count / variant /
  magnitude / tier / ack field (research.md). The Epoch-8 driver realizes tier-calibration, the 120 s cease, the
  cool-down, and the ack action FROM the phase names; the TOML only times + labels phases. Name phases explicitly
  (`hard-signal-error`, `medium-cue-error-rate`, `weak-transient-cue`, `cease-signal`, `wait-auto-resolve-120s`,
  `retrigger-within-cooldown`, `retrigger-after-cooldown`).
- **Outcome-coherence holds** — no file mixes `Absent` + `Contains` of one token; different-token `Contains`
  checks coexist against the single `query_incident_list` read-back (the P-007 precedent; research.md). The
  P-023 within/after contradiction is resolved by Q2 (assert after via `CountAtLeast`, declare-only within), not a
  file split.
- **CalibrationRegion encoding** follows the P-008 precedent exactly: `kind="Contains"` + `class="CalibrationRegion"`
  + a representative token; the *tendency* / model-choice is the Epoch-8 evaluator's, never encoded in
  `ComparisonKind` (`root-span-error-scope.toml`).
- **`CountAtLeast` + `Hard` is correct** for met floors — `conductor-verify::slo` softens an UNMET `CountAtLeast`
  to the calibration-region at eval time (the 2026-06-22 testing.md learning), so the unmet case is the
  evaluator's, not a hard fail here.
- **Epoch-8 calibration points** (record in TOML comments + the wrap notes): the inferred read-back tokens
  (`Autonomous`/`Suggested`/`Curious`/`Resolved`/`resolution summary`); the ack drivability (does
  `mark_incident_resolved` serve as ack?); the within-cooldown suppression + corpus-records leg; the spec-faithful
  long `gap_ms` (120 s / 5 min / 10 min) vs a compressed runtime variant; the per-tier latency *measurement*
  (the TOML only declares the tier).
- **Out of scope (forward-looking, per design/a11y/obs extracts):** the lamp/CLI rendering of tiers + `Resolved`
  (Epoch 9 + operator checklist); the obs runtime spans (`scenario.run`/`verify.readback_*`, Epoch-8); the live
  model decision + SLO latency measurement (Epoch-8/10); P-020 graceful-degradation / model-off (P-045 family).
