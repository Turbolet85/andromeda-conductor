## Goal

Ship the **CLI interactive resolver** for operator pauses — the `conductor-cli` half of the hold/resume
mechanism `conductor-core` built in Epoch 5 (`pause.rs`: `HoldPoint` · `Decision{Go,NoGo}` · `trait
PauseResolver` · `resolve_hold` · `HeadlessResolver`). The core already defined the seam and the
headless-never-block default; this chunk supplies the interactive answer and the gate that chooses between
them. The integration point is **not new**: `pipeline.rs:141` already resolves the operator-checklist
`HoldPoint` via a hardcoded `resolve_hold(&HeadlessResolver::proceed(), &hold)`. The work is to (1) introduce
a tty-gated resolver that prompts the operator with `inquire` when stdin/stdout is an interactive terminal and
falls back to the headless never-block default otherwise, (2) freeze the live `indicatif` heartbeat while the
operator answers (the CLI mirror of the Epoch-9 Tauri paused-count titlebar signature), and (3) render the
`[HOLD]` phase-line with the established amber overlay — status never color-alone.

This is a **zero-model-change** chunk (arch §Established Decisions [Outcomes are values]): no new
`Verdict`/`ReportState`/`Decision` variants, no new emission/verify/scheduling logic. It reuses ch3's render
seam (`stdout_color()` `IsTerminal` gate, `lamp_code(Lamp::Hold)=179`, the `*_styled(…, color)` split) and
adds exactly one new dependency, `inquire`, whose `crossterm` backend is already in the lock (so the marginal
supply-chain surface is small) — per arch §Stack + security-plan §Dependency Security. The headless invariant
is the hard contract: the agent / piped source-of-truth path is **never** gated on a prompt (verification-
harness §Headless invariant; design-system §cli "headless never blocks"), and determinism is preserved because
the operator pause is wall-clock-only, outside the seeded virtual clock (arch §Design Philosophy).

2. **Create the CLI resolver seam — `crates/conductor-cli/src/pause.rs`** (new):
   - `struct PromptResolver { spinner: Option<ProgressBar> }` implementing `PauseResolver`: render the hold's
     human-readable action (`HoldPoint::prompt`) + `scenario` / `p_id.0` / `step` context, then ask an
     `inquire::Confirm`. When `allow_no_go == true`, map `Ok(true)→Decision::Go`, `Ok(false)→Decision::NoGo`;
     when `allow_no_go == false`, render a **proceed-only** acknowledgment and always return `Decision::Go`.
     Because `PauseResolver::resolve` is **infallible** (`-> impl Future<Output = Decision>`), collapse any
     `InquireError` (operator Esc / Ctrl-C) into a `Decision` — **D2**: `Err ⇒ NoGo` when `allow_no_go` else
     `Go` (a cancelled prompt is the operator backing out, the safe non-proceed). The prompt closure runs
     inside `spinner.suspend(|| …)` when a spinner is present, so the heartbeat freezes at its current count
     during the prompt and resumes after (**D3**: `ProgressBar::suspend` is the indicatif primitive; the literal
     "stop-in-place" titlebar freeze is the Epoch-9 Tauri surface — `suspend` preserves the count and is the
     faithful CLI mirror).
   - `enum CliResolver { Interactive(PromptResolver), Headless(HeadlessResolver) }` implementing
     `PauseResolver` by match-dispatch (the trait is **not** object-safe — `-> impl Future` rules out
     `&dyn` — so an enum, not a trait object).
   - `CliResolver::select(spinner: Option<ProgressBar>) -> CliResolver` — the **isatty gate**: return
     `Interactive(PromptResolver{spinner})` iff `std::io::stdin().is_terminal() && std::io::stdout().is_terminal()`,
     else `Headless(HeadlessResolver::proceed())` (the same `IsTerminal` primitive `render::stdout_color()`
     already uses — reuse, do not invent a second tty check).
   - In-crate `#[cfg(test)]`: assert `select(None)` yields `Headless` under the test harness (stdin not a
     tty); assert the enum dispatch (inject `HeadlessResolver::abort()`/`proceed()` through `CliResolver` and
     `resolve_hold`, checking the `Decision`); assert no real TTY wait is reached. NEVER spawn a real prompt.

## Implementation notes
- **The hold is only reachable on a ready gate.** `execute_scenario` returns `Blocked` before the hold when
  `!pf.ready` (pipeline.rs:106). So in hermetic CI (read-back forced unreachable per cli_smoke.rs's
  `pulse;injection` data-dir) the operator-checklist hold is never hit — existing E2E tests are unaffected,
  and the new headless-gate proof is a **unit** test on `CliResolver::select` + dispatch, not an E2E run.
  The live interactive prompt is exercised only with a live Pulse / rmcp stub (operator/local — Epoch-10).
- **No `--agent-mode` flag yet** (that is ch5). The never-block gate here is pure `IsTerminal` detection; if a
  later `--agent-mode` lands, `select` should also force `Headless` when it is set.
- **`inquire` Confirm vs Esc:** confirm the `Err`→`Decision` mapping (D2) against `inquire`'s actual error
  variants at implementation time (`OperationCanceled` / `OperationInterrupted`); both map per D2.
- **Determinism:** add no timing assertions around the prompt; the `spinner.suspend` wait is wall-clock and
  must not be folded into any seeded math (the timeline already ran by the time the hold fires).
- **Size guard:** this is a small, surgical chunk (1 new file, ~6 small edits) — consistent with the
  zero-model-change Epoch-8 pattern.
