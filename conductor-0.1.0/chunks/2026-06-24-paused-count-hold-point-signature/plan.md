## Goal

Make the design-system **Signature** — the *Paused-count hold-point* — real in the titlebar. The ch1
frameless-window-shell shipped a STATIC titlebar count (`Titlebar.tsx` → `00:00:00`, `type-data`,
`--count-nominal`) and explicitly deferred the freeze/tint/resume heartbeat to "the NEXT chunk." This chunk
gives that count its run-state behavior: a subtle CSS heartbeat while `live`, a **freeze + amber tint**
(`--count-nominal`→`--count-hold`) when an operator-pause hold is active, a **resume** to nominal on proceed,
and a motionless **slate dim** (`--count-blocked`) on abort — "the absence of motion is the event" (per
design-system §Signature / frontend.md §Signature). The hold is signalled non-color-alone: the titlebar
phase-line text flips to a `HOLD` label carrying `aria-live="assertive"`, and `prefers-reduced-motion: reduce`
(already global in `tokens.css` L78–83) drops the motion while the static tint/dim + text remain legible (per
a11y-plan §6 §11 Motion / §Status messages).

Run-state is driven LOCALLY this chunk (the live Tauri `Channel` is Epoch 9 ch4): a typed `RunState` is lifted
to `App` (`useState`), passed to `Titlebar` as a prop, and exercised by a **DEV-only keyboard cycler**
(`import.meta.env.DEV`-gated, stripped from the production bundle). This both demonstrates the signature in the
running app now (the GUI is still visually unverified — handoff follow-up) and fixes the exact prop contract
ch4's Channel will plug into. The change is UI-only: **zero Rust / engine / seam change** — `conductor-tauri/
src/main.rs` is a thin shell with no `#[tauri::command]` / `Channel` / webview state (per research §main.rs),
and `capabilities/default.json` is untouched (per arch §Established Decisions — seam-gated permissions).

## Implementation Steps

1. **Define the run-state type.** Add `export type RunState = 'idle' | 'live' | 'hold' | 'aborted'` co-located
   in `Titlebar.tsx` (the component owns its prop contract; `App` imports it). No separate module needed unless
   it grows.
   - `idle` — dormant: count static, `--count-nominal`, no heartbeat.
   - `live` — heartbeat pulse, `--count-nominal`.
   - `hold` — FROZEN (no animation), tint `--count-hold`; label flips to the HOLD text.
   - `aborted` — motionless, dim `--count-blocked`.
   - *(proceed = the hold→live transition, demonstrated by the cycler; not a discrete state.)*

2. **`Titlebar.tsx` — accept props + render per state.** Change the signature to
   `function Titlebar({ runState, count = '00:00:00' }: { runState: RunState; count?: string })`.
   - **Count:** `className={`type-data titlebar__count titlebar__count--${runState}`}` — the per-state class
     drives color + animation (keep `data-tauri-drag-region`, keep the placeholder count value; the real value
     is ch4).
   - **Phase-line label (the non-color signal):** derive the label text from `runState` (e.g.
     `idle`→`Conductor · idle`, `live`→`Conductor · live`, `hold`→`Conductor · HOLD — operator pause`,
     `aborted`→`Conductor · aborted`). Put **`aria-live="assertive"`** on the `.titlebar__label` span so the
     HOLD flip is announced (per a11y-plan §11 Motion / §Status messages — motion is never the only hold
     signal). Keep the existing min/close `<button>`s untouched.

3. **`Titlebar.css` — heartbeat keyframes + per-state classes (tokens by name).**
   - `@keyframes titlebar-heartbeat` — a gentle **opacity breath** (e.g. `0%,100% { opacity: 1 } 50% { opacity:
     ~0.55 }`); opacity-only (calm, GPU-cheap, no layout). Optionally a sub-pixel scale, but opacity alone is
     preferred at expression 0.3.
   - Base `.titlebar__count` gains `transition: color var(--motion-micro) var(--ease-quiet)` so the
     nominal→hold tint shift animates (and drops under reduced-motion → instant, still legible).
   - `.titlebar__count--idle { color: var(--count-nominal); }` (no animation).
   - `.titlebar__count--live { color: var(--count-nominal); animation: titlebar-heartbeat var(--motion-heartbeat)
     var(--ease-quiet) infinite; }`.
   - `.titlebar__count--hold { color: var(--count-hold); animation: none; }` (FROZEN — the still tinted count is
     the event).
   - `.titlebar__count--aborted { color: var(--count-blocked); animation: none; }` (motionless dim).
   - **All values by token NAME** — no raw hex/px/ms (per design-system §Motion + arch §Conventions). No
     per-component `prefers-reduced-motion` block: the global `tokens.css` L78–83 kill-switch already drops the
     heartbeat + tint transition (per research §Patterns + a11y extract — "no re-declaration needed").

4. **Add the `--motion-heartbeat` token (the one new token — see Implementation notes).** `tokens.css` `:root`
   gains `--motion-heartbeat: ~1600ms` (period of the breath; final value tuned by feel at implement). This is a
   small, justified design-system §Motion addition (the existing set has no long-period token; tokens-by-name
   forbids a raw ms). Wrap reconciles it into design-system §Motion (drift→amendment). **Flagged for P5/user
   approval** (scope.md said "no new tokens"; this adds exactly one motion token for the signature period).

5. **`App.tsx` — lift state + DEV cycler + pass the prop.**

   - `const [runState, setRunState] = useState<RunState>('live')` (default `live` so the heartbeat shows on load).
   - **DEV-only cycler:** `useEffect(() => { if (!import.meta.env.DEV) return; … }, [])` — a `keydown` listener
     on `window` that advances through a demonstrative order `idle → live → hold → live → aborted → idle`

6. **Strict-TS typing for `import.meta.env.DEV`.** Ensure `vite/client` types are in scope (the build is

## Implementation notes
- **The `--motion-heartbeat` token is the one deliberate scope deviation.** scope.md said "introduces NO new
  tokens"; the heartbeat period genuinely has no existing token (`--motion-micro` is 150ms — a flicker), and
  tokens-by-name forbids a raw ms. Adding one motion token is the disciplined resolution; it surfaces at wrap as
  a design-system §Motion amendment. If the user prefers zero token change at P5, the fallback is a clearly-
  commented constant + a deferred design-system token follow-up (less clean — leaves a raw ms in component CSS).
- **No component-test runner in `ui/`** (package.json: only `tsc`/`vite`) — the state rendering is "exercised"
  via the DEV cycler (manual/visual) + the future tauri-driver E2E (closing Epoch-9 chunks), not a unit test.
  Keep class names explicit/non-hashed (`.titlebar__count--hold`) for that later E2E selector stability (per
  test-plan §11).
- **DEV cycler discipline:** `import.meta.env.DEV`-gated (never in the production bundle); one key that doesn't
  override platform/browser shortcuts (per a11y §5); listener cleaned up on unmount. It is scaffolding, not the
  shipped signature — ch4's Channel replaces it, preserving the `runState` prop contract.
- **`aria-live="assertive"` placement:** on the phase-line `.titlebar__label` (its text change on the HOLD flip
  is the announced event). All four label changes will announce; acceptable for a 4-state titlebar and faithful
  to "assertive for the HOLD flip."
- **Order sensitivity:** `ensure_frontend` must build `ui/dist` before any workspace `cargo` compile of
  `conductor-tauri` (`generate_context!` resolves `ui/dist` at compile time) — already wired into
  `agent-run.{sh,ps1}` + CI by ch1; no change needed, but a bare `cargo build` without the frontend build will
  fail (per frontend.md Session Additions).
