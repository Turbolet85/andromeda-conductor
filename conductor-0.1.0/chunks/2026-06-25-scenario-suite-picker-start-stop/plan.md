## Goal

Stand up the desktop panel's first interactive control surface: a scenario/suite **picker** and **Start/Stop** controls, plus the `#[tauri::command]` contract behind them — the commands the frameless-window-shell scope (ch1) explicitly deferred ("start/stop, scenario/suite picker … are later Epoch-9 chunks, each brings its own capability permission"). The picker is real: a read-only `list_scenarios` command, backed by a new shared `conductor_core` catalog helper, enumerates the 31 `scenarios/*.toml` (per arch §Standard Contracts / §Occupied Resources) and the webview renders them via shadcn Command/Select over Radix (per frontend.md / design-system §Component Patterns §5). Start/Stop wire to `start_run`/`stop_run` commands that drive a backend run-lifecycle state (Idle/Running/Aborted) which feeds the titlebar `RunState` prop ch2 already renders (idle→live→aborted).

Per the P4 decision, **`start_run` validates the selection and transitions state but does NOT execute the run pipeline** (`preflight`/`execute_scenario`/`coarse_emit` are bin-local in `conductor-cli`; running them from Tauri requires a library extraction + a core-owned `current_thread` runtime under Tauri — research §Graph impact confirms `execute_scenario` has only the 2 CLI callers). That execution, the pipeline-to-library extraction, and the live emission Channel land together in **ch4 (Live-counter Channel stream)**, where a run becomes observable and the run-state-driver swap already CARRYs. This keeps ch3 a coherent control-surface chunk over the unchanged core (matching ch2's defer-backend precedent), with **zero engine/seam MODEL change** and the headless `agent-run` release gate untouched (per Design Philosophy §Headless-drivable core; scope.md boundaries).

Security + a11y are first-class: the selection is validated against the known catalog before any use (per security-plan §Input Validation — the scenario string never reaches argv/shell), the deny-by-default ACL is not widened (per security-plan §Tauri GUI), the picker is fully keyboard-operable via Radix/cmdk and not-color-alone (per a11y-plan §Keyboard/§Visual), and the new `ui/` deps clear `npm audit` with a committed `package-lock.json` (per security-plan §Dependency Security §Frontend).

2. **Selection-validation as a pure fn** — a `validate_selection(catalog: &[ScenarioSummary], sel: &Selection) -> Result<…>` (in core or the tauri commands module) that resolves a picked scenario name / P-ID / the "suite (all)" sentinel against the catalog and rejects anything unknown — the testable security boundary (per security-plan §Input Validation). The command wraps this; the scenario string is validated, never interpolated into argv/shell (per security.md §Subprocess & MCP).

3. **Tauri commands module** (`crates/conductor-tauri/src/commands.rs`):
   - `list_scenarios() -> Result<Vec<ScenarioSummary>, String>` — resolve the scenarios dir from `CONDUCTOR_SCENARIOS_DIR` via `conductor_core::resolve_under` (the traversal guard `paths.rs` uses), call `conductor_core::list_scenarios`, map errors to a **sanitized** `String` (Display, no host paths / struct names — per security-plan §Error Handling).
   - `start_run(selection) -> Result<RunState, String>` — `validate_selection` against the catalog; on success set the managed lifecycle to `Running` and return the run-state; on an unknown selection return a sanitized error. **No pipeline execution** (P4 decision A).
   - `stop_run() -> Result<RunState, String>` — transition the managed lifecycle to `Aborted`/`Idle`, return it.
   - Each command `#[tracing::instrument]` with a bounded `tauri.command.*` span name, logging method + latency + result at info to `logs/conductor-tauri.jsonl` (per obs-plan §3/§4; observability.md). No OTel SDK.

4. **Managed run-lifecycle state** — a `Mutex<RunLifecycle>` (`Idle`/`Running`/`Aborted`; `hold` is operator-pause, ch8) `.manage(...)`-ed in `main.rs`; the commands read/mutate it. It maps to the frontend `RunState` ('idle'/'live'/'aborted'); 'hold' stays driven by the ch2 DEV cycler until ch8/ch4.

5. **Wire the backend** (`crates/conductor-tauri/src/main.rs`) — add `.manage(Mutex::new(RunLifecycle::Idle))` + `.invoke_handler(tauri::generate_handler![list_scenarios, start_run, stop_run])` to the existing `Builder`. ## Implementation notes
- **Bin-local pipeline** — do NOT try to call `conductor_cli::pipeline::execute_scenario` from Tauri (it's in a bin crate + takes `&CliResolver`). Option A avoids this entirely; ch4 does the extraction. Resist scope-creeping execution in here.

- **No live run yet** — `status`/`logs` need a `run_id` from a live run (none until ch4/Epoch-10); the smoke is `agent-run run` only (per verification-harness.md §Session Additions 2026-06-23 / hard-signals precedent).
- **not-color-alone everywhere** — picker rows, disabled buttons, and run-state all carry text, never tint alone (design + a11y hard ban).
