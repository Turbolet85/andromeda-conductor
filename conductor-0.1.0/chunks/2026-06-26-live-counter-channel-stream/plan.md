## Goal

Turn the GUI's option-A control scaffold (ch3) into a real, streaming run surface. Three intertwined
deliverables: (1) extract conductor-cli's bin-local composition root `pipeline.rs` into a NEW `conductor-run`
library crate that sits above the seams (timeline/emit/verify/report) and below both bins — the
architecturally clean home (conductor-core is impossible: it is the base every seam depends on, per arch
§Compiler-enforced module seams + research §Patterns); (2) wire a core-owned `current_thread` tokio runtime
under Tauri (arch §Established Decisions [Async Runtime Flavor]) so `start_run` drives the real pipeline on a
background thread and streams lifecycle/target-status events to the webview over a Tauri 2 IPC `Channel` (arch
§Real-time Strategy — in-app only, no per-message JSON overhead, no OS toasts); (3) retire the DEV-only
run-state cycler and drive the existing `Titlebar runState` + count props from that Channel (frontend.md
prop-contract rule — the cycler was shipped so the Channel plugs into the same prop).

Because there is no live Pulse, every run resolves **Blocked** at the preflight gate and emits nothing
(`pipeline.rs:109` short-circuits before `coarse_emit`) — so this chunk proves the EXECUTION wiring, the real
`RunRecord` persistence (runs.db + JSONL journal, identical to the CLI = test-plan Path 7 parity), and the
streaming Channel CONTRACT; the per-emission counters stay 0 until the Epoch-10 live-Pulse proof adds a
pipeline progress hook. The resolver dependency generalizes via a **generic bound** (`execute_scenario<R:
PauseResolver>`), NOT a trait object — `PauseResolver::resolve` returns `impl Future` and is deliberately not
object-safe (core/pause.rs:95 + research §Graph impact); the "trait object" wording in the working-route is
corrected to generics, matching the existing `resolve_hold<R: PauseResolver>` (core/pause.rs:137). Tauri passes
the core `HeadlessResolver::proceed()` (no live interactive pause leg this chunk — that is a later Epoch-9
chunk). Zero engine/seam MODEL change; headless `conductor` (CLI) behaviour stays byte-identical.

## Implementation notes
- **Build-order gotcha** (frontend.md 2026-06-24): `generate_context!` resolves `ui/dist` at COMPILE time — `npm run build` MUST run before any `cargo build`/`nextest`/`clippy` that compiles conductor-tauri (`ensure_frontend` already wired into `agent-run` `run` + CI).
- **Name-collision gotcha** (deferred learning): a Tauri command fn named identically to an imported fn makes `generate_handler!` bind the wrong signature (cryptic `IpcResponse`/`blocking_kind` errors) — keep `start_run`/`stop_run` distinct from any `conductor_run::*` import, or call the lib fn fully-qualified.
- **Blocked-path reality:** `execute_scenario` returns `RunRecord::blocked` BEFORE `coarse_emit` when `!pf.ready`, so the abort flag + per-emission counters are mostly forward-looking; the Channel's observable content this chunk is the lifecycle + target-status transitions. Do not fake non-zero counters.
- **Parity is the regression test:** the CLI must stay byte-identical post-extraction — drive the `agent-run.sh run` smoke + the Path-7 parity test, not just compilation.
- **Determinism stamps** come from `std::time` (`now_ms`/`now_rfc3339`), never the virtual clock — preserved by relocating the functions unchanged.
