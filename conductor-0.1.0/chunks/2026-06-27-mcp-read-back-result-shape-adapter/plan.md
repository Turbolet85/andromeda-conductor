## Goal
Make MCP read-back actually work against the live Pulse sidecar. conductor-verify uses rmcp 1.7's typed `call_tool`, which requires the MCP `CallToolResult` envelope `{content:[…]}`. Pulse's hand-rolled `andromeda-pulse-mcp` returns the **raw tool payload** as the JSON-RPC `result` (`jsonrpc.rs` `success(id, result: Value)`, no envelope), so rmcp fails `ServiceError::UnexpectedResponse` on every call (live-verified). Research confirmed rmcp **cannot** surface the raw result — it deserializes into the typed `ServerResult` enum before returning, and exposes no transport escape (`service/client.rs:282-327`, `service.rs:442`).

So this chunk **replaces the rmcp read-back client with a minimal hand-rolled line-delimited JSON-RPC stdio client** (per arch §[MCP Read-Back Client] reversal — Pulse is itself hand-rolled JSON-RPC, so a hand-rolled client is the faithful match). It reuses the hardened spawn (`spawn.rs`), preserves the `2024-11-05` version pin (now read from the `initialize` result) + the manifest tool-presence check + the preflight gate's three legs, and routes call/parse failures through the verdict/error wall (typed `Blocked` with the TRUE precondition — fixing `run_preflight`'s `_ => Failed` catch-all that masked call errors as "incident not found in corpus"). The test stub is rebuilt to emit Pulse's **raw** result shapes (the fidelity gap that hid the bug). conductor-verify already depends on `tokio` (`process`/`io-util`) + `serde_json`, so **no new dependency**; rmcp is dropped (no new crate edge — a removed one). This unblocks the de-promoted Live-Pulse E2E proof (its canary bridge + 5-family read-back need a working call).

## Implementation notes
- **ARCH REVERSAL (flag for wrap's amendment):** removes rmcp, reversing arch §[MCP Read-Back Client] (rmcp was chosen to avoid hand-rolled JSON-RPC + re-deriving version negotiation). Justified: Pulse's sidecar is itself hand-rolled JSON-RPC and **non-MCP-compliant for `tools/call`**, so rmcp's typed layer is unusable; the version negotiation rmcp provided reduces to reading one field from the `initialize` result.
- **Reuse `spawn.rs` verbatim** — fixed program path + `.env` data-dir + injection rejection; add NO new spawn code (security).
- **Signature stability** — keep `ReadbackClient::{connect, negotiated_protocol_version, list_tools}` + the 4 wrapper names; only the wrapper RETURN type (`CallToolResult` → `Value`) changes, so `run_preflight` + `execute_scenario` + the preflight verb need minimal edits.
- **Bounded read** — cap the stdout read-line length (DoS-bound on child output); a malformed/oversized line → typed `Decode` error → `Blocked`/`Err`, never a panic.
- **Not in scope:** the canary EMISSION + faithful per-family extraction (the re-promoted Live-Pulse E2E proof). This chunk proves the call returns usable data; full `ready:true` still needs the canary emission.
