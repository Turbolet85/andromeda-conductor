## Goal

Layer an **observability conformance gate** onto the existing `rust` job in `.github/workflows/ci.yml` — the obs analogue of the coverage + flakiness gates the `2026-06-27-ci-quality-gate-config` chunk added. Today CI never produces Conductor's self-observation artifact (`agent-run` runs without `$SCENARIO`, so `logs/agent-latest.jsonl` is never written — research §`ci.yml`/`agent-run`). This chunk (1) **produces** that artifact in CI via a no-Pulse Blocked agent-mode run, (2) **asserts** every line conforms to the self-obs base schema and the redaction boundary, (3) **asserts** zero unlogged panics, and (4) **uploads** it as a CI artifact — implementing obs-plan §9 ("Log conformance check" + "Zero-unlogged-panics gate") and the §10 always-required zero-unlogged-panics SLO.

The gate asserts the **self-obs base-line schema** (per obs-plan §3 "two record shapes" + the `observability.md` rule): `timestamp_ms`, `level`, `target`, `service.name`, `service.version`, `deployment.environment`, `run_id` — the exact flat fields `JsonObsLayer::on_event` emits on every line (`crates/conductor-core/src/obs.rs:247-268`). The run-report **envelope** fields (`verdict`/`state`/`latency_ms`/`fingerprints`) live in `runs/<run_id>.jsonl`, NOT on self-obs lines, and are a separate, out-of-scope gate — the scope's §3↔§3 open question, **resolved by research**. The redaction boundary (obs-plan §6/§11 + security-plan §Error Handling) **does** apply here because `agent-latest.jsonl` is Conductor's OWN artifact — explicitly unlike the third-party `lcov.info` the prior chunk found outside the boundary (security.md Session Addition 2026-06-27).

Strictly **CI-config only**: the obs sink + panic hook it asserts are read-only (`init_observability` has 3 bounded consumers, none touched — research §Graph impact). No new crates, seams, deps, or model change — mirroring the `ci-quality-gate-config` precedent.

## Implementation Steps

1. **Add the producer step** to the `rust` job in `.github/workflows/ci.yml`, placed after the existing build/test/coverage steps (the workspace is already built + cached, so `cargo run` reuses it). It runs the headless agent-mode CLI against a committed scenario with the read-back path forced unreachable:
   - command: `cargo run -q -p conductor-cli --bin conductor -- run error-baseline-spike --seed 424242 --agent-mode`
   - `env: ANDROMEDA_PULSE_DATA_DIR: pulse;injection` — the hermetic no-Pulse Blocked lever (`verification-harness.md` 2026-06-23; `cli_smoke.rs:29`): `conductor-verify` rejects the injection metacharacter **before** any sidecar spawn → `Blocked` envelope → **exit 0**. Deterministic on any host, no live Pulse.
   - effect: `init_observability` (agent mode) opens `logs/agent-latest.jsonl` and writes the `"observability initialized"` startup line + all self-obs lines, each carrying the 7 identity fields + `run_id`, even though the run is Blocked (`obs.rs:71-86`, `main.rs:44-50`, proven by `cli_smoke.rs:109-136`). `logs/` lands at repo root (sibling of the default `runs/`); `open_log_file` creates the parent dir.
   - `error-baseline-spike` chosen because it is the scenario the `cli_smoke` Blocked-producer E2E already uses and is committed under `scenarios/` (present at the CI checkout root — no TempDir needed, unlike the E2E).
   - This is a normal (fail-fast) step: a non-zero exit here is a real regression (a Blocked run must exit 0).

2. **Add the conformance + zero-panics gate step** (`shell: bash`, mirroring the flakiness-budget + coverage gate idiom at `ci.yml:56-62, 84-94`), after the producer. It performs, with machine-parseable `::error::` annotations + non-zero exit on any violation (test-plan §10 "zero silent passes"):
   - **(a) artifact present + non-empty** — fail if `logs/agent-latest.jsonl` is missing or empty.
   - **(b) per-line required-field assert (jq)** — for every line, assert all seven base fields are present and non-null: `.timestamp_ms`, `.level`, `.target`, `."service.name"`, `."service.version"`, `."deployment.environment"`, `.run_id` (the quoted keys are dotted field NAMES, not nested paths). Any line failing → `::error::` + exit 1. Reuses the `jq -e` machine-assert the `status` verb already relies on (`agent-run.sh:86`); `jq` is preinstalled on the `windows-latest` runner.
   - **(c) host-path leak scan (grep)** — fail on any absolute-host-path token, anchors mirroring `redact.rs::is_host_path_token` (`redact.rs:104-124`): drive-letter `[A-Za-z]:[\\/]`, `/home/`, `/Users/`, `\Users\`, `/root/`, `%APPDATA%`, `%USERPROFILE%`, `%LOCALAPPDATA%`, `$HOME`, `~/`, `.cargo[\\/]`, `.rustup[\\/]`. MUST NOT flag `::` module paths (`conductor_core::obs`) or repo-relative `crates/…` source paths — by construction the anchors above don't (`redact.rs` test `module_and_type_names_are_not_over_redacted`). This asserts the in-process redaction held end-to-end (defense-in-depth on Conductor's own artifact).
   - **(d) zero-unlogged-panics scan (grep)** — fail on any line matching `^thread.*panicked` (the unstructured default-panic shape). The `set_hook` path emits a **structured** `tracing::error!(panic=…)` JSON line (`obs.rs:163-169`) that does NOT match this pattern, so a properly-captured panic passes; only an unstructured backtrace fails (obs-plan §10).

3. **Add the upload step** — `actions/upload-artifact@v4` with `if: always()` (so the artifact is available even when the gate failed, for debugging), name `obs-conformance`, path `logs/agent-latest.jsonl`. Third instance of the `if: always()` upload idiom the coverage + JUnit steps established (`ci.yml:96-110`).

4. **Self-verify locally (/+implement P3)** — dogfood the producer + gate on this Windows host: run the producer command (with the injection env) to emit `logs/agent-latest.jsonl`, run the jq/grep assertions against it to confirm **PASS**, then craft a negative line (a fake `C:\Users\…` path in an allowlisted field, and a `thread 'main' panicked …` line) in a scratch copy to confirm the gate **FAILS** — proving the gate gates, not just passes. Confirm `ci.yml` is valid YAML.

## Implementation notes
- **Redaction means the leak scan normally passes** — `redact_value` already masks absolute host paths to `<redacted>` at the subscriber stage (`redact.rs:63-91`), so even a CI-runner path (`D:\a\…`) in an allowlisted field would be redacted before write. The gate asserts the invariant held (catches a redaction-bypass regression); it is not expected to fire in the green path.
- **Don't over-match the drive-letter anchor** — `run_id` (`YYYY-MM-DDTHH-MM-SS-mmm`) and `target` (`conductor_core::obs`) contain no `X:[\\/]`, so the drive-letter grep is clean against real self-obs lines; keep the anchor to `[A-Za-z]:[\\/]` (a colon + slash), not a bare `:`.
- **Step ordering** — the producer must precede the gate; the gate is fail-fast; the upload is `if: always()` so a gate failure still surfaces the artifact. Put the producer after the coverage steps to reuse the warm build cache.
- **`shell: bash` on Windows** — the multi-command gate must be `shell: bash` (not the default pwsh) so it fails-fast on the first non-zero like the `.sh` `set -e` (session-learnings: the Windows multi-command-step fail-fast → `shell: bash`).
- **jq availability** — preinstalled on `windows-latest` (and assumed by the existing `status` verb); if absent locally during /implement self-verify, run the same jq the runner uses or validate via a quick serde check — do not add a jq install step to CI.
- **Scope discipline** — resist widening to also conformance-check `runs/<run_id>.jsonl` (the envelope) or `logs/conductor-tauri.jsonl` (the Tauri sink); both are separate gates (envelope = a test-plan §10 gate; Tauri sink = no CI producer yet). This chunk is the `agent-latest.jsonl` self-obs gate only.
