Justified: the planned `HoldPrompt` `Serialize` derive needs serde (conductor-tauri had no direct serde dep), the planned `oneshot` bridge needs tokio `sync`. Both are the chunk's own crate plumbing; Cargo.lock drift is a single benign `+serde` edge (no new package).
- **`TauriResolver` constructed in `start_run`, not `run_thread`** (plan said run_thread). Justified: clippy `too_many_arguments` (run_thread hit 8/7); passing the cohesive resolver (replacing `gate`+`on_hold`) brought it to 7 — cleaner than a lint suppression, identical behavior.
- **Gate bridge extracted into `HoldGate::arm`/`deliver`**, tested at that seam (plan said "unit-test the resolver decision-capture"). Justified: constructing a Tauri `Channel`/`State` in a unit test is awkward; `arm`/`deliver` isolate decision-capture + abort-default for synchronous testing without Tauri DI — the thin `Channel.send` defers to ch9's mock-runtime test exactly as scoped.
- **Resolve command logs the decision in the message string**, not a structured `decision` field. Justified: a non-allowlisted `decision` field would be dropped by the obs redaction allowlist; the message (always emitted) records it without an out-of-scope `redact.rs` edit. The span carries no `run_id` (a stateless decision-post — consistent with the existing nullary command spans `list_scenarios`/`coverage_matrix` that carry `count`/`latency_ms`, not `run_id`).
- **Faithful boundary (not a deviation, noted):** a `NoGo` does not halt the run today — `execute_scenario`'s operator-checklist path logs the decision and returns a `ManualCheck` record unconditionally (pre-ch8 behavior); acting on NoGo to halt is Epoch-10 live-Pulse semantics, out of scope. The decision is captured + posted.
