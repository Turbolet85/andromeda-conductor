## Goal
Bring the two remaining headless run surfaces — the per-scenario run report and the ManualCheck operator
checklist — into the Tauri control panel as desktop views, the desktop twins of `conductor-report`'s Markdown
render and the CLI `report` verb. The **run-report view** lists a run's `RunRecord`s as verdict lines (P-ID(s) ·
scenario · verdict-first `StatusLamp` · latency · SLO tier), reusing the shipped `StatusLamp` + the `lampForRecord`
projection (per arch §Probabilistic-Assertion Policy verdict-first precedence, design §Component Patterns §4/§6,
layouts §Primary content block 2). The **operator-checklist view** reuses the `OperatorChecklist` primitive
(induced-state ⇢ expected-observation rows) with a header + unticked-count footer roll-up (design §7, a11y §4).

Per the **P4 data-source decision (AskUserQuestion → "live journal read now")**, the run-report view is sourced
live: a thin read-only `run_report(run_id?)` `#[tauri::command]` reads the latest `runs/<run_id>.jsonl` and returns
`Vec<conductor_core::RunRecord>`, mirroring the CLI `report` verb (`conductor-cli/src/commands/report.rs`) and the
`coverage_matrix`/`list_scenarios` command shape. Research confirmed this is cheap: `RunRecord` already derives
`Serialize` (`run_record.rs:16`) and lives in `conductor-core` (already a `conductor-tauri` dep), and the CLI sources
RunRecords from the **JSONL journal, not runs.db** — so there is **no new crate edge and no new `RunsDb` query**
(the runs.db "latest per P-ID" query the handoff flagged stays an Epoch-10 concern for the *coverage* per-P-ID join,
a different need). The journal reader (`latest_run_id` + `read_journal`, currently bin-private in the CLI) lifts to
`conductor-core` so the CLI and Tauri share one reader (frontend.md single-source rule; the `conductor_core::scenario_files`/`list_scenarios` IO-in-core precedent). Because `start_run` already writes a journal,
the GUI gains a real run→report loop now — Blocked rows surface immediately, real verdicts arrive with the Epoch-10
live-Pulse runs, no rewiring.

The **operator-checklist view is presentational/sample-driven** this chunk (a stated non-goal boundary): there is no
structured induced/observation model in `conductor-core` — the DriveObserve scenarios (P-025/026/027/P-032) are
declare-only with empty `expected` and carry their checklist text only in TOML comments (`scenario.rs` tests
:718/:750). Wiring live checklist items needs a scenario-model field (an engine change), so it defers; this chunk
ships the reusable view exercised in the DEV gallery, ready for that later source. UI + one read-only command + a
small `conductor-core` lift; zero engine/seam *model* change (the journal reader is a read accessor, not a model edit).

## Implementation Steps
1. **Lift the journal reader to `conductor-core`** — move `latest_run_id` + `read_journal` from
   `conductor-cli/src/commands/report.rs` into a new `conductor-core` module (e.g. `run_journal.rs`), re-exported at
   the crate root like `scenario_files`/`list_scenarios`. Return a **typed `Result` (no `anyhow` in the lib** — the
   verdict/error wall; map IO + `serde_json` parse failures to a `CoreError` variant / a dedicated error enum,
   `#[from]`). Behavior-preserving: lexicographically-greatest `<run_id>.jsonl` stem = latest; skip blank lines;
   parse each line as `RunRecord`.
2. **Repoint the CLI report verb** — `conductor-cli/src/commands/report.rs` calls the new core fns (adapting the
   typed error to `anyhow` at its edge). Keep the rendered output identical (the `cli_smoke`/report E2E must stay
   green).
3. **Add the `run_report` command** — in `conductor-tauri/src/commands.rs`, a `#[tauri::command] pub fn run_report(run_id: Option<String>) -> Result<Vec<RunRecord>, String>` mirroring `coverage_matrix` (manual
   `tracing::info_span!("tauri.command.run_report").entered()` + `count`/`latency_ms` info line; resolve `runs_dir()`;
   call the core reader with the latest-or-given run_id; `sanitize_error` edge). Register it in
   `conductor-tauri/src/main.rs`'s `generate_handler!`.
3a. **Validate the `run_id` arg** — if `Some`, it is a filesystem stem; resolve it under `runs_dir` through the same
   `resolve_under` traversal guard `commands.rs` already uses (reject traversal/absolute escapes) before reading
   (security §Input). `None` ⇒ latest.
4. **Build `RunReport.tsx` (+ `.css`)** — a presentational view `{ records: RunRecord[] }` mirroring
   `CoverageMatrix.tsx`: a dense token-bound `<table>` of verdict lines (P-ID(s) · scenario · `StatusLamp` via
   `lampForRecord(state, verdict)` · latency_ms · slo_tier · fingerprint count), `type-data`/`type-label`/`type-body`
   classes, `aria-label` + scroll `role="group"`. **Blocked rows render measurement cols as `—`/null** (never red;
   the lamp is the hollow-ring Blocked glyph). Add a `RunRecord` TS interface to `lamp.ts` (or a local type) mirroring
   the 11-field core shape — never re-author the verdict/state spellings (reuse the `Verdict`/`ReportState` unions
   already in `lamp.ts`).
5. **Operator-checklist view** — compose the existing `OperatorChecklist` primitive with a header + an unticked-count
   footer roll-up (`role="status"`/`aria-live`, design §7 / a11y §4). HOW (a standalone `OperatorChecklistView.tsx`
   wrapper vs. a ManualCheck-row expansion inside `RunReport`) is an implement decision; either way reuse the
   primitive, drive items from props, exercise in the gallery.
6. **Mount in `App.tsx`** — add a "Run report" `<section>` (a `type-heading` `<h2>`) that `invoke<RunRecord[]>('run_report')` in a `useEffect`, rendering the loading / error (`role="alert"`) / empty
   ("No run yet" real prose) / `<RunReport records=…/>` states exactly like the coverage section.
7. **DEV exercise in `Gallery.tsx`** — `SAMPLE_RECORDS: RunRecord[]` spanning Pass / Fail / CalibrationRegion→Hold /
   ManualCheck / KnownResidual / Blocked (exercise `lampForRecord` over all six lamps); render `RunReport` + the
   operator-checklist view with sample items.
8. **Gates** — `tsc --noEmit` + `npm run build` + `npm audit` (frontend) · `cargo nextest -p conductor-core` (the
   lifted reader's new unit tests) · `bash scripts/agent-run.sh run` (release-gate: workspace nextest + doctest +
   clippy `-D`; proves `conductor-tauri` compiles against a fresh `ui/dist`).

## Implementation notes
- **No `anyhow` in `conductor-core`** — the lifted reader returns a typed error (verdict/error wall); only the CLI/`#[tauri::command]` edges erase it (`anyhow` / `sanitize_error`). Don't drag `anyhow::Context` into the lib.
- **Behavior-preserving lift** — keep the lexicographic-latest + skip-blank + per-line-parse semantics byte-identical so the CLI report golden/E2E doesn't move; if a CLI test references the moved fns, repoint it.
- **Blocked vs Fail** — the Blocked lamp + `—`/null cells are the single most-likely visual bug; assert it in the gallery across the six-lamp spread.
- **`run_report` is read-only + nullary-ish** — like `coverage_matrix`, kept `Result` for a uniform command surface; an absent/empty runs dir ⇒ `Ok(vec![])` → App's "No run yet", not an error.
- **`RunRecord` TS shape** must track the 11-field core order; a drift shows as a missing column, not a type error (the `invoke<T>` is unchecked) — keep it beside `lamp.ts`'s other mirrors.
