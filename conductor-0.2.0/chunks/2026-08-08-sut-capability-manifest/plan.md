## Goal

Conductor's accepted Pulse-capability set is a compile-time constant. `pid_format` in
`crates/conductor-core/src/scenario.rs:23-34` validates a P-ID with `(1..=60).contains(&n)` and rejects
anything else with `"expected P-NNN with NNN in 001..=060"`, so a scenario naming any capability Pulse
shipped in its v0.3.0 (the ledger now reaches P-082) fails garde validation at load. Every downstream proof
this version plans is aimed at a stale target until that constant stops being the source of truth. This is
the keystone chunk of the keystone epoch.

This chunk replaces the constant with a **versioned, committed, runtime-parsed manifest** at
`contracts/pulse-capabilities.toml`, loaded and bounds-checked by a new `conductor-core` module that mirrors
the shipped `ContractManifest` loader (per arch §Established Decisions [Module Boundaries] + §Stack; the
in-repo precedent is `crates/conductor-verify/src/manifest.rs`). The intent's requirement is that **a Pulse
release becomes a data update, not a code change** — so the deliverable is judged by whether bumping Pulse's
capability set requires editing only the TOML artifact.

Failure handling follows the **two-tier split the same precedent already demonstrates** (operator-decided at
P4): the *loader* returns a typed `conductor-core` harness fault — read/parse/bounds failure is
`Result::Err`, never a verdict, never a panic, never a silent widen back to `1..=60` (per arch §Conventions
Error handling + security-plan §Input Validation + §Anti-Patterns Universal); the `Blocked` **ReportState**
with its named precondition stays the *gate/run* surface's job, where the identity fields a blocked row
requires (`run_id`/`seed`/`scenario`/`p_ids`/`slo_tier`) actually exist. This chunk builds only the loader
tier. The classification universe (`coverage.rs`) and the drift check are explicitly **not** here.

## Implementation notes

- **`Scenario::from_toml_str(&str)` must keep its signature, and `PId`'s shape must not change.** The
  code-graph reports **41 call sites** for `from_toml_str` across 6 files in 5 crates — production ones at
  `conductor-cli/src/paths.rs:78`, `conductor-tauri/src/commands.rs:78`,
  `conductor-core/src/scenario_catalog.rs:46` (graph lines are 0-indexed) — and **82 references to `PId`**
  across 16 files in 6 crates, 50 of them outside `scenario.rs`. Threading a manifest parameter through
  `from_toml_str`, or altering `PId`'s shape, turns a contained validator change into a workspace-wide
  ripple. The accepted set must reach the validator without a parameter on that function; only the *rule
  inside* `pid_format` (1 reference — its own garde attribute) may change.
- **Reading the code-graph — the durable lesson from this chunk's planning.** SCIP symbols are matched **by
  descriptor**, so a Rust-style path (`Scenario::from_toml_str`) matches nothing while `%from_toml_str%`
  matches everything. Two corollaries, each of which cost a wrong conclusion during this plan's drafting:
  **attribute a row count to the query that produced it** (the `rows=1` in this chunk's trace is
  `pid_format`'s, not `from_toml_str`'s), and **never read a truncated view as the result** — a `LIMIT` in
  the SQL or a `head` on the output silently narrows it, while the trace's own `rows` field records the true
  count. The graph is the authority on call sites; grep over-counts, matching the `pub fn` definition, test
  function *names* containing the symbol, and doc comments.
- **garde 0.22.1 context slot.** `pid_format(value: &str, _ctx: &())` — the unused `_ctx` is garde's Context
  parameter and is the sanctioned channel for handing an accepted set to a field validator without a global
  (the same amendment that pinned 0.22.1 established `Context` as the cross-field mechanism). Whatever
  mechanism is chosen, it must let a test supply a fixture set (step 5) and must not introduce hidden mutable
  process state, which would break both determinism and per-test isolation.
- **Two manifests now live under `contracts/`.** Keep their loaders visibly parallel but separate —
  `conductor-core` must NOT depend on `conductor-verify` to reuse `ContractManifest`'s loader; that is a
  forbidden cross-seam edge that will not compile (arch §Established Decisions [Module Boundaries]).
- **No `CONDUCTOR_*` override handle is planned.** The manifest resolves from `default_path()` like
  `ContractManifest` does. If /implement finds a reason to add one, it must be `CONDUCTOR_*`-namespaced,
  resolved through the existing `conductor_core::config_path::resolve_under` at the **cli edge** (never
  inside the seam loader), carry `..`/absolute/symlink-escape rejection tests, and be registered in arch
  §Occupied Resources at wrap — do not add it quietly.
- **Ordering.** The manifest artifact (step 1) must exist before the loader tests can load the committed
  file, and the loader (steps 2–3) before `pid_format` can source from it (step 4). The test re-key (step 8)
  is last — it is what proves the widening actually took effect.
