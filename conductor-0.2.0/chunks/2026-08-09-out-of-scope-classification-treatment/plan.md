## Goal

The SUT capability manifest accepts 82 capabilities, of which 16 are **not Conductor's to verify** — Pulse's
UI/visual set and its own tooling, outside Conductor's remit by standing non-goal. That boundary shipped as a
recorded decision last chunk (`CoverageMode::NotConductors`, wire `not-conductors`, counted by `tally()`), but
on every rendered surface an out-of-scope row is typographically identical to an in-scope one, and the roll-up
counts it into an undifferentiated denominator. A reader scanning the wall cannot tell remit from outcome
without cross-referencing — and 16 rows that were never in play read as 16 rows nobody has gotten to.

This chunk makes the out-of-scope classification **visually distinct** on all three render surfaces and gives
the roll-up an honest **in-scope denominator**, while guaranteeing by test that an out-of-scope row never
reads as `Fail` or `Blocked`. Coverage mode stays orthogonal to the verdict axis: no new `ReportState`, no
sixth lamp, no envelope field (per architecture.md §Standard Contracts + a11y-plan §6 crosswalk). The
treatment reuses the shipped `--status-residual` ↔ ANSI 246 name-pair — the one recessive tier that already
exists on both surfaces — so nothing is minted (per design-system.md §Surface: cli / Tokens + §Anti-Patterns).

Scope is presentation only. The classification, the row set, the wire spelling and `tally()`'s arithmetic are
read, never remodelled; `check_sut_drift` and `contracts/pulse-capabilities.toml` are untouched. The P3
code-graph query (260 rows) confirms the blast radius: `coverage_matrix` @ `conductor-report/src/coverage.rs:25`,
`render.rs:162` and `commands.rs:124` are the only render consumers, while `drift.rs`'s 5 rows read the same
static and must stay unaffected.

**Operator decisions taken at P4:** (1) the roll-up names an in-scope denominator alongside the full row count,
and the CLI gains a roll-up for the first time (today only Markdown and the webview carry one); (2) the
treatment binds `--status-residual` / ANSI 246 rather than a text tier, because `--text-*` has no ANSI
counterpart and `--text-muted` is pixel-identical to `--count-blocked`.

9. **Add the negative-guarantee tests** (the scope's item 4, and the chunk's tested deliverable). On each

## Implementation notes

- **One spelling across all three surfaces.** `CoverageMode::label()` returns `not-conductors` and every
  surface prints it verbatim today. Keep that single source — do **not** mint a second, prettier display form
  (`not-Conductor's`) for the webview only, or the surfaces diverge and the never-color-alone text selector
  stops matching across them. `layout-templates.md:126`'s `not-Conductor's` stays prose naming the value.
- **The `--text-muted` trap.** In the dark block, `--count-blocked`, `--text-muted` and `--border-emphasis`
  are all `#565F89`. A "just dim it" treatment built on `--text-muted` renders pixel-identical to `Blocked` —
  the exact confusion this chunk exists to prevent. `--status-residual` (`#9A93A8`) is the chosen distinct
  recessive tier, and it must be bound **by token name**, never by hex.
- **Residual is a different column.** Reusing the Residual tier on the Mode cell does not collide with
  `KnownResidual`, whose identity is carried by its dashed-ring glyph in the **lamp** column; the Mode cell is
  a separate column and its text label discriminates. Non-lamp reuse of ANSI 246 is established precedent
  (`hint:` in `render.rs:121`). Do not add a Residual glyph to the Mode cell.
- **Order sensitivity:** `npm run build` must precede any workspace cargo build that compiles
  `conductor-tauri` (`generate_context!` → `ui/dist` at compile time).
- **Golden re-baseline, not relaxation:** `summary_line_format_is_exact` locks the roll-up over a *synthetic*
  4-row fixture on purpose — so the shape is golden-tested without baking the live capability count. Update the
  expected string; keep the fixture synthetic.
