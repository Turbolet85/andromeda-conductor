## Goal

Pulse's DuckDB append path stalls after ~10 minutes of sustained 10k/s storm: ingest keeps receiving while
`duckdb.append` stops, so `viz.query.traces` returns 0 rows and no new incidents form until restart (intent
§Theme 1 F4). Conductor's whole method is sustained shaped load, so the harness can induce that stall itself —
and today nothing distinguishes "Pulse is broken" from "we drove Pulse outside its proven-good region." A long
storm run would report the SUT for a fault the harness caused. This chunk closes that attribution hole from
both ends: it **records the envelope where scenario authors meet it and asserts the catalog against it**
(`v2-06`), and it **classifies an over-envelope run as environment-suspect rather than Fail** (`v2-07`).

Two P4 decisions shape the build, both operator-confirmed.

**The envelope is asserted on its derivable axis, with the un-derivable axis recorded rather than faked.**
Research established that the committed scenario model carries no rate or occurrence-count field at all
(`phase_spec.rs` — `PhaseSpec{name, gap_ms, emission}`, `EmissionSpec{signal}`), so the storm-rate half of the
envelope simply is not derivable from committed data; `fingerprint-storm.toml` records in-file that the driver
infers per-phase counts from *phase names*. A duration-only bound would also be actively wrong: `activity-floor`
runs 3900s but fifty of its sixty-five minutes are deliberate quiet gaps, and the SUT stalls on sustained
throughput, not elapsed time. So the envelope artifact carries **both** terms with their provenance, the gate
asserts the derivable one (total scenario duration), and the two predominantly-quiet scenarios are **exact-set
pinned exemptions carrying their reason** — the project's own established move for a gate that must go live
before the work making it green exists (`.claude/rules/testing.md` 2026-08-09; the `KNOWN_UNCLASSIFIED` /
`UNBACKED_AUTO` ledgers at `drift.rs:38,61`). The rate axis is named as owed to Epoch 2's *Faithful emission
dispatcher*, which is what will make it derivable. This keeps the chunk inside its scope boundary — it must not
pre-build Epoch 2 — while making the un-assertable axis visible instead of silently absent.

**`environment-suspect` is a run-level qualifier, not a sixth `ReportState`.** The code-graph puts 204
`ReportState` references across 16 files in 6 crates, plus the webview `LAMP_META` mirror; arch is explicit that
widening `state ∈ {Pass, Fail, ManualCheck, KnownResidual, Blocked}` is an architecture amendment with lockstep
fan-out (per architecture.md §Standard Contracts). Five of seven distillers independently landed on the
qualifier: obs cites the `(N unbacked)` precedent for a qualifier riding alongside a closed set, layouts and
a11y both cite the out-of-scope Mode-cell precedent where a reused token deliberately did *not* become a
seventh lamp state, and tests calls it "the cheaper binding" because it leaves the polled envelope fields
intact. The qualifier therefore scopes to the **run**, leaves `RunRecord`'s eleven fields and the `runs` table's
eleven columns provably untouched, and never alters any per-check `state`.

## Implementation Steps

1. **Commit the envelope artifact** — `contracts/pulse-load-envelope.toml`, mirroring
   `contracts/pulse-capabilities.toml`'s shape: `sut_version` · `captured_at` · a `provenance` string naming
   intent §Theme 1 F4 as the transcribed SUT record (nothing in `.andromeda/refs/` carries the stall — the
   artifact must say plainly it is transcribed, not Conductor-measured) · an `[envelope]` table with the
   sustained-rate term, the sustained-storm-duration term, and the derivable `max_scenario_duration_ms` proxy ·
   an `[[exempt]]` array of `{scenario, reason}`.
2. **Load + validate it** in a new `crates/conductor-core/src/load_envelope.rs`, following the
   `CapabilityManifest` precedent exactly (per security-plan §Input Validation): a fixed `default_path()`
   resolved through the shipped `config_path::resolve_under` guard with **no `CONDUCTOR_*` override handle**,
   `load()` returning a named `CoreError` on absent/malformed/unparseable, and read faults carrying `e.kind()`
   only — never the path. Bounds-check at load: non-empty version/date/provenance, positive terms, no duplicate
   exemption scenario.
3. **Add the gate** `check_load_envelope(&LoadEnvelope, &[Scenario]) -> Result<()>` in the same module, built on
   the `drift.rs:79-136` template: pure `BTreeSet` set-algebra over committed artifacts, failing on three
   disjoint conditions — a scenario over the duration term and not exempt; an exemption whose scenario is now
   inside the envelope (**ledger rot**); an exemption naming no scenario in the catalog (**lost subject**). The
   message is identity-only (scenario names + the envelope's `sut_version`/`captured_at`), never a path, never
   an internal type name (per `drift.rs:100-101`).
4. **Surface the constraint where scenarios are authored** — the envelope terms and the exemption discipline
   land in the scenario-authoring surface, not only in `.andromeda/`. Name the SET/terms, never a fresh literal
   that re-stales (the standing derived-count discipline; four separate amendments cited in the layouts
   extract).
5. **Classify the run** in `conductor-run`: at run composition, evaluate the resolved scenario against the
   envelope and produce a run-scoped value — in-envelope, or environment-suspect carrying its breach cause. This
   is a **typed value on the `Ok` path**, never `Result::Err` (the verdict/error wall); only a malformed/absent
   envelope artifact is `Err`. It must not touch any per-check `verdict` or `state`.
6. **Persist it run-level** — a NEW `run_envelope` table in `crates/conductor-report/src/db.rs`
   (`run_id` PK · classification · cause), created by the same additive `CREATE TABLE IF NOT EXISTS` bootstrap.
   A separate table, not a column on `runs`: the existing eleven-column table and its `(run_id, scenario)` PK
   stay byte-identical, which is what makes "`state ∈ {…}` provably unchanged" checkable. Bound parameters only.
7. **Render it on all three surfaces**, outside the lamp column, reusing the recessive `KnownResidual` register
   with no new token (per design-system §Color Palette + layout-templates §Component — Primary content block 1
   Mode bullet): the Markdown report header banner naming the breach cause; the CLI summary caption with an
   always-rendered ASCII text label that survives `NO_COLOR`/piping; and a run-level banner in the existing
   webview RunReport view with a DOM text label (never color-alone). Never `--status-fail`, never
   `--count-blocked` (it shares its hex with `--text-muted` and would read as `Blocked`), motionless.
8. **Wire the gate into the test suite** as a static assertion over the committed catalog, beside the existing
   `check_sut_drift` / `check_scenario_backing` gates.
9. **Discharge the folded PREREQ** — re-run `cargo audit` (fifth consecutive check) and **observe**
   `cargo deny check` green. No floor raise, no `deny.toml` ignore, no CI edit. Close the deferral only if the
   advisory database now parses.

## Implementation notes

- **The exemptions are a debt, not an excuse.** `activity-floor` (3900s; 10+10+30 min of deliberate quiet) and
  `incident-auto-resolution` (731s lifecycle wait) are exempt because their duration is *idle*, not storm. Each
  exemption states that reason in the artifact. When Epoch 2's dispatcher makes intensity derivable, the gate
  should assert emitting-phase duration and both exemptions should retire — name that owner in the artifact,
  the way `UNBACKED_AUTO` names its retiring chunks (`drift.rs:56-60`).
- **`MAX_GAP_MS` is 3_600_000** (`phase_spec.rs:15`) — a single phase may already be one hour, so garde's
  existing bounds offer no envelope protection at all. This gate is the first one; do not assume any prior
  bound narrows the input.
- **Envelope schema ownership.** `run_record.rs:11` pins the eleven-field envelope as owned by test-plan §3 and
  reproduced in obs §3 / a11y §3. This chunk deliberately does **not** add a field there — the qualifier is
  run-level and lands in its own table — so no reproduction needs to move. If implementation finds it cannot
  avoid touching `RunRecord`, stop and surface it rather than editing the reproductions.
- **Do not open Pulse's `corpus.db`.** The envelope's terms are transcribed from intent §F4; Conductor's
  production code never reads the SUT's database directly (per security-plan §Data Protection).
- **Expected amendments (wrap):** `architecture.md` §Occupied Resources — register
  `contracts/pulse-load-envelope.toml` as a new on-disk artifact (additive; the capability-manifest row is the
  template). `test-plan.md` §3 — record the run-level `run_envelope` table beside the `runs` index if the status
  read touches it. `layout-templates.md` §Component — Primary content block 2 + §cli Primary screens — the
  run-level banner/caption placement. `design-system.md` §Surface: cli Tokens — the reused-token entry, if the
  out-of-scope Residual-mute row does not already cover it. `a11y-plan.md` §6 — the crosswalk entry recording
  the qualifier as orthogonal to the lamp set.
- **Order sensitivity:** land the artifact + loader + gate (steps 1-3) before the render surfaces (step 7), so
  the gate's failure modes are provable against the real catalog before anything depends on the classification.
