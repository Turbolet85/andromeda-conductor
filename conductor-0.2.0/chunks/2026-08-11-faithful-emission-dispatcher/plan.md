## Goal

Replace `conductor-run::coarse_emit` — which sends one OTLP signal per phase boundary, after the entire
timeline has already elapsed — with a per-phase dispatcher that emits each phase's **declared** shape over
the ten `conductor-emit` primitive families, **at that phase's boundary, during the timeline walk**.

Two facts from research set the design, and both were falsified premises going in. First, the shape the
dispatcher is supposed to dispatch on does not exist: `EmissionSpec` carries exactly one field (`signal`),
33 of 35 scenario TOMLs declare nothing at all, and the real shape is encoded in phase *names*
(`storm-same-fp-6x`) by a convention `fingerprint-storm.toml` documents. So this chunk builds the declaration
as well as the dispatcher — resolved at P4 in favour of declarative `EmissionSpec` fields validated by garde,
per architecture.md §Established Decisions [Validation Library] + security-plan §Input Validation. Second,
`run_timeline` sleeps through every gap and **returns** — closing `timeline.execute` — before any emission
happens, so today's emissions reach the wire in an instant burst after the scenario's timing has been spent.
Pulse's detectors are windowed (L2 needs ≥5 same-fingerprint inside a rolling 30s; P-015 needs a ≥20s silence
gap), so emission timing is load-bearing and is currently discarded. Emitting at each boundary during the walk
is what makes the shape faithful — and it also makes obs-plan §4 CP1's `timeline.execute` → `emit.batch`
parent→child chain true, which it is not today.

The seam must stay extensible to the families Epoch 3 will live-prove, and it must not buy that with a
cross-seam edge: `conductor-timeline` depends only on `conductor-core` and must not gain a `conductor-emit`
edge (architecture.md §Established Decisions [Module Boundaries]). The per-boundary emission therefore enters
`run_timeline` as a caller-supplied hook, with the dispatcher itself living in `conductor-run` where
`conductor-emit` is already a dependency.

## Implementation Steps

1. **Extend the emission model** (`crates/conductor-core/src/phase_spec.rs`). Keep `signal: Signal`
   unchanged and additive-default everything new so the four existing fixture sites keep compiling.
   Add an occurrence count (how many emissions this phase produces — `0` expresses a deliberate silence
   window) and a discriminated shape selecting the primitive family with its parameters:
   - **plain** — the current `trace_request` behaviour (the default).
   - **error** — placement (root vs deep child) + the **error fraction** of the phase's occurrences
     (`ErrorPlacement`, `error_trace_request`).
   - **exception** — fingerprint variant mix over `FingerprintVariant` (`identical`/`path`/`line` vs
     type/frame variants) (`ExceptionSpec`, `exception_trace_request`).
   - **severity** — the **severity mix** across `SeverityNumber` values (`Severity`, `severity_logs_request`).
   - **latency** — p50/p95/p99 targets (`LatencyProfile`, `latency_trace_request`).
   - **pii** — the `PiiCategory` set to embed (`PiiCorpus`, `pii_trace_request` / `pii_logs_request`).
   - **rate** — the ramp/breathing curve (`RateCurve`, `rate_trace_request`).
   - **topology** — the service set + shared-trace linkage (`ServiceTopology`, `service_topology_request`).
2. **Make the validation actually run.** `PhaseSpec.emission` is currently `#[garde(skip)]`, so nested
   rules would never execute — change it to dive and add the rules beside the structs: occurrence and
   percentile bounds via `range` consts in the `MAX_GAP_MS` style, and the cross-field invariants
   (p50≤p95≤p99, error fraction ∈ [0,1], severity mix sums, non-empty category/variant sets) via
   `#[garde(custom)]` field validators using the `Context` pattern — garde 0.22.1 has no container-level
   `custom` (per security-plan §Input Validation; arch amendment 2026-06-15-config-validation-surface).
3. **Carry the declared count into the timeline** (`crates/conductor-timeline/src/convert.rs`,
   `src/phase.rs`). `PhaseTimeline::from(&Scenario)` deliberately drops the emission descriptor today
   ("the timeline carries timing only … it rides in the config model for the Epoch-3 emission seam") —
   this chunk **is** that seam. Give `Phase` its declared occurrence count so the timeline can total it;
   carry no emit types across the boundary (the count is a plain number from `conductor-core`).
4. **Add the per-boundary hook** (`crates/conductor-timeline/src/scheduler.rs`). Keep
   `run_timeline(timeline, seed)` as the existing signature (its callers and tests are unchanged) and add a
   sibling that takes a caller-supplied async hook invoked at each phase boundary after that phase's gap has
   elapsed. The hook is generic — `conductor-timeline` gains no `conductor-emit` edge. Extend the
   `timeline.execute` span to `fields(phase_count = …, emission_count = timeline.total_occurrences())`,
   computed in the attribute position exactly as `phase_count` and `emit.batch`'s own `emission_count`
   already are (`client.rs:66`) — **never** `field::Empty` + a later `record()`, which `JsonObsLayer`
   drops silently (no `on_record`; the CARRY). Note deliberately: this attribute is the **declared** total,
   the same provenance as `phase_count`; the **observed** per-batch count stays on `emit.batch`.
5. **Build the dispatcher** (`crates/conductor-run/src/dispatch.rs`, new). One entry point taking the
   scenario and a connected emitter pair, returning a per-phase closure for the hook. It looks the phase's
   `EmissionSpec` up by `PhaseTransition.index`, maps the shape to its primitive family, paces the phase's
   occurrences inside the phase, and lazily connects `LogsEmitter` only when a logs-signal phase is first
   reached (preserving `coarse_emit`'s existing laziness). A shape the primitives cannot realize is a typed
   harness fault (`Result::Err`), never a downgraded verdict and never a panic — the verdict/error wall
   (architecture.md §Established Decisions [Error Handling]).
6. **Rewire `execute_scenario`** (`crates/conductor-run/src/lib.rs:292-294`). Delete `coarse_emit`; call the
   hook-taking timeline runner with the dispatcher's closure. **`execute_scenario`'s public signature is
   unchanged** — it has 3 production callers across 2 crates (`conductor-cli/src/commands/run.rs:23`,
   `conductor-cli/src/commands/suite.rs:30`, `conductor-run/src/lib.rs:498`), none of which may need editing.
7. **Migrate the scenario catalog** (`scenarios/*.toml`, 35 files). Give each phase whose shape is currently
   carried by its name an explicit `[phases.emission]` block matching what the name asserts
   (`storm-same-fp-6x` → 6 occurrences, exception shape, identical/path/line variant mix). Preserve the two
   existing `emission = { signal = "logs" }` declarations. Phase names stay as authored — they become labels,
   and the comments that explain the name-encoding convention are updated to point at the declaration.
   Every committed scenario must still load-validate.
8. **Re-state the load-envelope rationale** (`crates/conductor-core/src/load_envelope.rs:16-18, :48-52`).
   Both the module prose and the `max_sustained_rate_spans_per_s` field doc say the rate terms are "declared,
   not derivable … the scenario model has no rate field" — which stops being true the moment step 1 lands.
   Correct the wording to state that the rate is now derivable but **not yet asserted**, and do **not** add
   the assertion to `check_load_envelope` here: widening its term set touches the exemption ledger's
   exact-set equality across all 35 scenarios and is its own decision (architecture.md §Occupied Resources;
   security-plan §Anti-Patterns never-claim-a-measurement). Per-phase occurrence bounds from step 2 are what
   keeps an absurd declared rate unexpressible in the meantime.
9. **Tests** (per test-plan §2 / §4 / §7). Unit cases join the existing `conductor-run` module at
   `lib.rs:513` and the `phase_spec.rs` garde trio at `:73`. Per-family wire assertions go through the
   loopback tonic `TraceService`/`LogsService` stub on an ephemeral `127.0.0.1:0` port, following
   `crates/conductor-emit/tests/egress.rs` + `traffic_rate_ramps.rs` — **never** `:4317`, never a live Pulse.
   Scheduling is driven with `#[tokio::test(flavor="current_thread", start_paused=true)]` + `tokio::time::advance`,
   never a real elapsed duration. Add valid/invalid garde `#[case]` rows for every new field, and a case
   asserting all 35 committed scenarios still validate.
10. **Run the standing `cargo audit` re-check** (the PREREQ, 10th consecutive) — see Implementation notes.

## Acceptance Criteria

- (core) Each scenario family's phases declare their shape in `EmissionSpec`, and against the loopback tonic
  stub the emitted stream matches that declaration per phase — occurrence count, signal class, and the
  family's shape parameters (exception/fingerprint variant mix, severity mix, latency percentiles, PII
  categories, error placement + error fraction, rate curve) — rather than one signal per phase
  (`verification-matrix.json#v2-08`).
- (core) Emissions occur at their phase's boundary **during** the timeline walk, so a phase's declared
  occurrences reach the wire inside that phase's window rather than in a burst after the timeline completes
  (`verification-matrix.json#v2-08`).
- (arch) The dispatcher lives in `conductor-run` consuming `conductor-emit`'s public API; the model change is
  confined to `conductor-core`; **no new workspace crate and no new cross-seam dependency edge** — in
  particular `conductor-timeline` gains no `conductor-emit` edge (per architecture.md §Established Decisions
  [Module Boundaries]).
- (arch) Every non-deterministic choice in the emitted stream derives from the seeded `ChaCha8Rng`; no clock
  read, no unordered-map iteration (per architecture.md §Established Decisions [Determinism RNG]).
- (arch) No new `CONDUCTOR_*` env var, port, or on-disk artifact; scenario shape stays declarative TOML
  bounds-checked by garde 0.22.1 beside its serde struct (per architecture.md §Occupied Resources · §Conventions
  Config conventions).
- (security) Every new emission-shape field has a garde rule that **actually executes** — `PhaseSpec.emission`
  dives rather than skips — and a malformed scenario TOML (out-of-range fraction, inverted percentile order,
  non-summing severity mix) fails at load as `Result::Err`, never as a verdict (per security-plan §Input Validation).
- (security) PII-family payloads trace to seeded synthetic construction (`PiiCorpus::seeded`) only, and no
  dispatcher-produced artifact carries an absolute host path or internal seam-crate struct name (per
  security-plan §Data Protection + §Error Handling).
- (security) `cargo audit` re-run and its result recorded; `cargo deny check` verified green as the overlapping
  signal — no floor raise, no `deny.toml` ignore, no CI edit (per security-plan §Dependency Security).
- (obs) `timeline.execute` emits both `phase_count` and `emission_count` **on an actual JSONL span-lifecycle
  line** in `logs/agent-latest.jsonl` — asserted on the emitted record, not merely present in `fields(...)`
  (per obs-plan §4 Critical Path 1 + §3).
- (obs) Every span name the dispatcher opens is a member of the bounded set, and any new attribute name is in
  `conductor-core::redact`'s allowlist and observed on the line; no OTel SDK, exporter, or metrics instrument
  is added; dispatch-loop logging stays off `info` per emission (per obs-plan §11 + §6).
- (layouts) `conductor run` / `conductor suite` stdout keeps its shipped shape — no new lines, columns, or
  bracket labels; the six per-P-ID labels plus the single run-level `[ENVIRONMENT-SUSPECT]` qualifier remain
  the complete stdout label set, and emission counting surfaces only inside the existing `indicatif` heartbeat
  (per layout-templates §Surface: cli — Primary content block 2 + Hero / signature output).
- (tests) Per-family wire assertions run against the loopback stub on an ephemeral `127.0.0.1:0` port, never
  `:4317`, no live Pulse; scheduling asserted under `start_paused`, never real elapsed time (per test-plan §2 + §11).
- (tests) All 35 committed `scenarios/*.toml` still validate at load; new fields ship valid + invalid garde

## Implementation notes

- **The `[inferred]` scope bullets were re-verified against research first.** Confirmed first-hand: the model
  extension is required (`phase_spec.rs:45`, one field); the catalog migration is real (3 declarations across
  35 files); the load-envelope consequence is real and quotable (`load_envelope.rs:16-18`, `:48-52`); the
  goldens boundary holds (the next working-route entry owns them). Still conditional: whether a new dependency
  lands — `conductor-run` has no RNG dep today (`Cargo.toml`: core/timeline/emit/verify/report + anyhow/tracing/
  serde/tokio-time), so seeded intra-phase shaping either threads `conductor-timeline`'s existing `ChaCha8Rng`
  or adds `rand_chacha` here. Prefer threading the existing one; if a dep is added, the standing audit
  deferral's "audit SURFACE unchanged" basis must be re-stated at wrap, not re-pinned verbatim.
- **The CARRY's two options were both unusable as stated, and the P4 decision dissolves it.** `on_record` would
  record into a closed span, and "compute before opening" could not work while `PhaseTimeline` carried no
  emission data and `run_timeline` emitted nothing. With the declared count on the timeline (step 3) and
  emission moved inside the walk (step 4), `emission_count` is computed in the `fields(...)` position from the
  argument — the idiom already shipping at `client.rs:66`. **`JsonObsLayer` still has no `on_record`**; do not
  introduce a post-open `record()` anywhere, it will vanish silently.
- **Faults stay out.** `conductor-run` does not depend on `conductor-faults` and must not gain that edge here —
  fault application (silence, ramp, port-occupier as *faults*) is the Epoch 3 "Fault-application spans" entry.
  A deliberate silence window is expressible as a phase with zero declared occurrences, since the timeline's
  gap already produces the silence.
- **Order sensitivity:** steps 1→2 before 3→4 before 5→6; the catalog migration (7) must land in the same
  commit as the model (1), or every committed scenario fails to load between them.
- **Determinism is not yet golden-frozen** — the next chunk owns that. Any shape-lock added here is unit-tier
  exact-assert, not a premature insta snapshot (per test-plan amendment 2026-06-16-emission-journal-writer).
- **Expected amendments (wrap):** `architecture.md` §Occupied Resources (`contracts/pulse-load-envelope.toml`)
  — the sentence "the rate terms are declared-not-derivable, because the committed scenario model carries no
  rate or occurrence-count field" stops holding once `EmissionSpec` declares occurrences; direction: the rate
  terms become derivable-but-not-asserted, with the assertion still unowned. Possible second: `obs-plan` §4 CP1
  `timeline.execute` `emission_count` — record that it is the DECLARED total (same provenance as `phase_count`)
  while `emit.batch` carries the observed per-batch count, if wrap judges the distinction unstated.
