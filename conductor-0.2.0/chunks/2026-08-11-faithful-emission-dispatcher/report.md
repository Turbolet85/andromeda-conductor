## Deviations from intent

1. **Wire tests live in `crates/conductor-run/tests/`, not `crates/conductor-emit/tests/`** as research and plan specified. Justification: `conductor-emit` has no dependency on `conductor-run`, so the dispatcher is not reachable from there — the planned path could not compile. Cost: three mirrored dev-deps plus tokio's `test-util`.
2. **`EmissionShape` is deliberately not `#[non_exhaustive]`.** The compiler forced the choice (cross-crate exhaustive matching); keeping it would have required a wildcard arm in the dispatcher, letting a future shape emit nothing at all. Exhaustive matching is now the compiler-enforced link between a declarable shape and a primitive that realizes it.
3. **Error fraction ships as `error_percent: u32` (0..=100), not an f64 fraction.** An f64 would drop `Eq` from `PhaseSpec`/`Scenario`; integer percent preserves it and matches the catalog's own authored convention (`bypass-relative-12x-4pct`).
4. **Every emission block declares `kind` explicitly**, including `kind = "plain"`. serde requires an internally-tagged enum's tag whenever the flattened table exists; the upside is that shape is always declared rather than inferred.
5. **FOUR files were modified outside the plan's Files-to-modify list**: `crates/conductor-run/Cargo.toml` (the `thiserror` edge the typed `DispatchError` needs + test dev-deps), `crates/conductor-timeline/Cargo.toml` (the `serde_json` dev-dep for reading the self-obs line back), and the `lib.rs` re-export lines in `conductor-core` and `conductor-timeline` for types the listed files create. Each is the owning crate of listed work and unreachable without it; judged in-scope helpers rather than a soft-exit.
6. **The obs acceptance criterion's artifact location was mis-specified, and the substance was proven elsewhere.** The plan pinned `timeline.execute`'s `phase_count` + `emission_count` to a JSONL line in `logs/agent-latest.jsonl`, but `execute_scenario` short-circuits to `Blocked` at the preflight gate **before** the timeline runs — with no live `ready:true` Pulse that span never opens, and the artifact carries only `verify.readback.connect`, `scenario.run`, `db.insert_run`, `report.generate`. Satisfied instead by `crates/conductor-timeline/tests/obs_span.rs`, which installs the real `ObsSink::File` sink, runs the timeline and reads the record back — proving the attribute survives onto a line rather than sitting inertly in `fields(...)`. **This is not drift: obs-plan §4 CP1's `timeline.execute` → `emit.batch` chain is now TRUE because this chunk made it true** (emission moved inside the timeline walk). The location was the mis-specification, not the requirement. `v2-08`'s acceptance clauses never cite `agent-latest.jsonl`, so no matrix action follows.
7. **The load-envelope close-out did not land here.** `contracts/pulse-load-envelope.toml:40-42` names this chunk as the retire point for both `[[exempt]]` entries plus the switch from total-duration to emitting-phase-duration assertion; plan step 8 (ratified at the P5 review) deliberately declined it to keep the version's largest chunk from widening further. ## Decisions & corrections

- **Three design forks resolved by the operator at phase P4**, all recommendation-first: shape is **declared** in `EmissionSpec` (not parsed from phase names); the dispatcher emits **during** the timeline walk (not after it); the chunk covers **all** families so it can claim `v2-08` in full.
- **Emitting during the walk was the load-bearing call.** Before it, `run_timeline` slept every gap and returned, and only then did `coarse_emit` fire everything back-to-back — for `fingerprint-storm`, ~24s of silence followed by 2 instant spans. Pulse's detectors are windowed (L2 needs ≥5 same-fingerprint in a rolling 30s; P-015 needs a ≥20s gap), so emission timing is load-bearing and was being discarded. A phase's occurrences are now paced across its own jittered gap, and total elapsed per phase is unchanged — both determinism goldens still pass byte-identically.
- **Load-envelope close-out is chunk work, not amendment flow** (operator ruling this wrap): re-scoping `check_load_envelope` to emitting-phase duration, retiring both `[[exempt]]` entries per the contract's stated end state, and reconciling the contract sentence all belong to a chunk. Pinned as a CARRY on the next markerless entry ("Dispatcher determinism goldens"). `contracts/pulse-load-envelope.toml` text is NOT amended this wrap; `load_envelope.rs`'s module comment already records the gap honestly.
- **The first smoke pass inspected a stale artifact, and the plan's Test Commands are why.** The plan listed a bare `bash scripts/agent-run.sh run` as the producer for the `emission_count` criterion, but the harness fires its scenario leg only under a `SCENARIO=` env prefix (`scripts/agent-run.sh:69-70`) — so the bare verb ran nextest/doctest/clippy and left `logs/agent-latest.jsonl` untouched. The first pass therefore read a **six-hour-stale artifact from the span-tree chunk**; only the file mtime revealed it. Re-run as `SCENARIO=exception-event-capture SEED=4317006 bash scripts/agent-run.sh run`, which produced a fresh artifact and exposed deviation 6.
- **P4 console counts were wrong and are corrected here from `git status`** (operator correction): the migration touched **23** scenario TOMLs, not 20; and **four** files sat outside the plan's list, not three.
- **`cargo audit` — TENTH consecutive red, re-pinned silently** under the operator's L5 ratification (origin `2026-08-08-sut-capability-manifest`).
