## Goal

Today `execute_scenario` calls `query_incident_list`, discards the response, and substitutes the literal
`"incidents-listed"` as the observed value for every check in the scenario (`conductor-run/src/lib.rs:302-305`).
Everything downstream of that line is already correct and shipped — `compare`'s four `ComparisonKind` arms, the
tier-scaled journal-relative SLO math, `classify`'s redaction, the max-severity fold. The harness therefore
grades a placeholder and reports a verdict that says nothing about Pulse. This chunk builds the missing
extraction: the layer that turns Pulse's raw read-back payloads into the values those shipped functions consume,
leaving them unmodified (per architecture.md §Established Decisions [Error Handling] · v2-09).

The extraction is grounded in wire shapes **verified first-hand against the live SUT** rather than against the
spec's description of it (`research.md` §Premise verification). Two premises came back different from how the
specs phrase them, and both change the design: `retrieve_report` takes `{incident_id}` and **returns**
`degraded_mode: bool` — it is a response field Conductor observes, not an argument Conductor passes — and
`query_incident_list` takes no arguments at all, so its item fields (`status`, `severity`, `title`) are the only
per-incident signal available without a second call.

Three shape decisions were taken at P4 review. **Per-check resolution derives from `ComparisonKind`** —
`ExpectedCheck` carries no selector and the scope bars a model change, so text kinds grade against a composed
per-incident observation while `CountAtLeast` grades against a numeric one; passing a composed blob to
`CountAtLeast` would fail `parse::<i64>()` on all seven catalog floor-checks and soften them to
`CalibrationRegion` — the same placeholder failure one layer down. **`degraded_mode` routes at record level**,
because `degraded-mode-report.toml` (P-053, the one scenario naming this residual) declares an empty `expected`
and never reaches `evaluate_check`; a per-check-only override would leave the capability's own scenario
untouched. **`fingerprints` gets populated** from `retrieve_telemetry_slice.fingerprint_refs` — the call is
already being made, arch names it the fidelity carrier, and leaving it `Vec::new()` inside this chunk would
preserve a placeholder while claiming to remove them.

## Implementation Steps

1. **Add the extraction module** — `crates/conductor-verify/src/extract.rs`. It holds one observation type
   carrying: the composed text, an evidence count, the degraded flag, and the fingerprint list. Build it from the
   three verified result shapes via field-tolerant readers in the shipped style (`preflight.rs:357-378` —
   `.get(key).and_then(as_array).map(…).unwrap_or_default()`, never `unwrap`, an absent or unexpected shape
   degrading to empty rather than erroring).
2. **Promote the two existing readers** — `incident_ids` and `fingerprint_refs` currently sit private in
   `preflight.rs`. Move them into `extract.rs` and re-point their two call sites (`preflight.rs:329`, `:336`).
   `assert_canary`'s behavior must not change; it is the shipped canary bridge and has its own tests.
3. **Compose the observation across incidents.** List incidents, then per incident call `retrieve_report`
   (markdown + degraded flag) and `retrieve_telemetry_slice` (span/fingerprint refs). The text observation is the
   union across incidents — union is what makes `Absent` a real scrub proof, since a token leaked by any incident
   must fail the check. The degraded flag ORs across incidents; fingerprints union.
4. **Resolve per check by kind** — a small accessor mapping `ComparisonKind` to the observation slice:
   `Contains` / `Absent` / `Exact` → the composed text; `CountAtLeast` → the evidence count rendered as a decimal
   string (`compare` parses it with `observed.trim().parse::<i64>()`, so the rendering must be a bare integer).
5. **Guard the empty corpus.** Zero incidents must yield `Blocked` with its named precondition, **not** a graded
   record — an `Absent` check against an empty observation would otherwise trivially pass, which is exactly the
   false-pass-as-empty ban (per security-plan §Security Anti-Patterns → Input). A read-back call error likewise
   yields `Blocked`, never `Result::Err` and never a panic.
6. **Wire it into `execute_scenario`** — replace `lib.rs:301-305`. The public signature stays byte-unchanged, so
   its three production callers need no edit. Feed each check its resolved observed value in the `:328-333` fold;
   the max-severity `severity_rank` selection is unchanged.
7. **Route `degraded_mode` at record level** — when the observation is degraded, the `RunRecord`'s `state`
   becomes `KnownResidual` with the measured `verdict` preserved (they are independent fields; `Lamp::for_record`
   already gives `KnownResidual` state-driven precedence, so no render site changes). Apply it on **both**
   branches: the empty-`expected` path that today builds `manual_record` (`lib.rs:347`) and the measured path.
   Only `degraded-mode-report` (P-053) and `project-context-grounding` (P-032) declare a KNOWN-RESIDUAL; the
   other seven empty-`expected` scenarios are operator-checklist and must keep rendering `ManualCheck`.
8. **Populate `fingerprints`** — pass the observation's fingerprint list into `to_run_record` in place of the
   `Vec::new()` at `lib.rs:341`. Entries stay selector/ID-shaped strings (per a11y-plan §3).
9. **Instrument the extraction** with a bounded-set `{module}.{operation}` span in the shipped
   `verify.readback.*` family (`client.rs` already spans every `call_tool` with an `mcp_tool` field). Follow the
   `emit.logs_batch` precedent for adding a conforming member (per obs-plan §11); log the degraded observation at
   `warn` (per obs-plan §6 Log levels). **Do not** build `degraded_mode_requested` — see Implementation notes.
10. **Extend the stub** — add `StubConfig` knobs alongside the existing six for the degraded, malformed, and
    empty-corpus legs, emitting Pulse's raw unenveloped shapes (`tests/common/mod.rs:76-110`), never an MCP
    `{content:[…]}` envelope.
11. **Test the legs** — per-kind resolution (rstest `#[case]` rows over the `ComparisonKind` × source matrix),
    the degraded → `KnownResidual` routing on both branches, empty/malformed/errored → `Blocked` with no panic,
    the seven operator-checklist scenarios still `ManualCheck`, and the redaction negative test on the composed
    observation.
12. **Re-run the standing supply-chain PREREQ** (`cargo audit`, twelfth) and record its result with
    `cargo deny check` verified green as the overlap — see Implementation notes for the exact standing remedy.

## Implementation notes

- **`retrieve_report` has zero call sites today** (code-graph, 0 rows) despite being pinned in
  `contracts/mcp-contract.toml` and asserted present by the preflight gate. This chunk is its first caller — do
  not assume any prior wiring exists.
- **`degraded_mode` cannot be requested.** Pulse computes it as `parsed_l4.is_none()` and returns it
  (`tools.rs:372`, `:380`); the request struct is `{incident_id}` only. Any design that passes
  `degraded_mode: true` as an argument is building against a spec phrasing the SUT does not implement.
- **Order sensitivity:** step 5's empty-corpus guard must land with step 4, not after it. Between them, an
  `Absent` check would pass against an empty observation — a false pass that looks like a green verdict.
- **`Exact` is unused across the whole 35-scenario catalog** (kinds in use: `Contains` 22, `Absent` 8,
  `CountAtLeast` 7). Resolve it with the text kinds for completeness; do not design around it.
- **The stub's item key is `incident_id`, the SUT's is also `incident_id`**; the shipped `incident_ids` reader
  tolerates `id` first. Keep the tolerance — do not narrow it to one key.
- **`CountAtLeast` floors mean different things** across the catalog (10 error spans, 50 latency samples, 2
  incidents) and there is one numeric slot. Unmet floors route to `CalibrationRegion` by the shipped evaluator,
  which is architecture's stated posture for sample floors (§Timing-Tolerance Model) — expected, not a defect.
- **Expected amendments (wrap):** `obs-plan.md` §4 (Known-residual classification path) — obs-plan specifies a
  `verify.readback_degraded_mode` span carrying `degraded_mode_requested` + `response_received`. `degraded_mode`
  is a **response** field, so `degraded_mode_requested` describes a call Conductor cannot make; the attribute is
  unbuildable as written. Direction: re-word the attribute pair to the observed-response shape. Related, smaller:
  §4 names `mcp_method` while the shipped `client.rs:125` span field is `mcp_tool`. Neither is a plan touchpoint —
  spec masters are never modified through /implement.
