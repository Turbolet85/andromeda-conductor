## Goal

The preflight canary's spans reach Pulse, pass its ingest invariants, and enter its buffer channel — and
then almost none of them are stored. Research settled why: Pulse's `spans` table is
`PRIMARY KEY (trace_id, span_id)` (`schema.rs:38`), and Conductor's `ok_span` builder stamps a **constant**
identity — `vec![1; 16]` / `vec![1; 8]` — on **every** call (`message.rs:151`). The first such span appends;
every subsequent one violates the primary key, returns `Error::Append`, and is logged-and-skipped by
`run_consumer` (`consumer.rs:76-82`). This is exactly the producer-dependence the previous chunk measured
but could not explain: `inject_demo` derives `trace_id(seq)` / `span_id(seq)` per sequence, so it never
collides.

The defect is **not canary-only**. `trace_request` also backs the scenario emission dispatcher at
`dispatch.rs:82` and `:95`, so every scenario phase emitting a Plain-trace or a non-error Error-shape
occurrence has been sending the same `(trace_id, span_id)` too. This chunk therefore fixes one shared
builder and repairs both paths at once, giving each emitted span a distinct, **seeded** identity in the
discipline every sibling builder already uses (`exception_trace_request` / `error_trace_request` /
`latency_trace_request` / `rate_trace_request` all take a seed as their second parameter) — never an
unseeded random id, which would introduce a second non-determinism source (per architecture §Established
Decisions [Determinism RNG] + §Cross-cutting Patterns).

**The primary-key mechanism does not explain everything, and the plan does not pretend it does.** The
storm's 12 spans carry distinct seeded ids and *should* have appended, predicting `rows_ingested ≈ 13`
against the measured `1`; the consumer does not coalesce messages (one export = one `dispatch_batch` = one
append, `consumer.rs:55-90`), so that gap is a **second, independent unknown**. This chunk's fix is
expected to repair the warm-up and the dispatcher-wide defect; it is **not** expected to dissolve the
second unknown on its own. The live leg is therefore instrumented rather than merely re-run: Pulse already emits `duckdb.append` with
`reject_reason` on every failed dispatch and `rows_appended` + `table_name` on every success
(`consumer.rs:176-190`) — an instrument no canary capture has ever included. The leg captures it, so if the
fix is again necessary-but-insufficient, the capture **names** the remaining cause instead of leaving it to
be inferred from counters that are never written. `v2-10` is claimed only if that leg actually reaches
`ready:true` (per architecture §Standard Contracts Readiness gate).

## Implementation Steps

1. **PREREQ — re-check the supply-chain gate.** Run `cargo audit`; if it still fails on the
   advisory-database parse fault, record the byte-identical message as the **20th pin** preserving its
   origin, and **verify** (never assume) `cargo deny check` true exit 0 across all four classes as the
   covering overlap. Close the deferral the moment the database parses (per security-plan §Dependency
   Security, two-fault split).

2. **Give `ok_span` a seeded, per-call identity** (`crates/conductor-emit/src/message.rs`). Replace the
   constant `vec![1; 16]` / `vec![1; 8]` with ids derived exactly as `exception_trace_request` derives
   them — a `ChaCha8Rng` seeded from a caller-supplied `u64`, feeding the crate's existing 16-byte and
   8-byte id generator. Surface the seed through `trace_request`'s signature so it matches its four sibling
   builders (service, seed, …). Update the two `message.rs` unit tests, and add one asserting that two
   different seeds yield different `(trace_id, span_id)` while the same seed reproduces them — the
   both-directions check the determinism rules require.

3. **Thread the seed at the dispatcher's two call sites** (`crates/conductor-run/src/dispatch.rs:82`, `:95`).
   `dispatch()` already computes `let seed = emission_seed(self.scenario.seed, index, point.occurrence)` at
   `:69` — a per-occurrence deterministic seed **already in scope at both sites**. Pass it. Same
   scenario + seed still yields the same stream shape; only the identity bytes move, and they move
   deterministically.

4. **Thread a per-emission seed through the canary warm-up** (`crates/conductor-run/src/lib.rs:225-240`).
   `warm_up_canary_service` currently emits `warmup_emissions` spans through one unseeded call. Give each
   iteration its own seed derived from the same `base` the storm uses, in a range **disjoint** from the
   storm's `base.wrapping_add(i)` for `i in 0..CANARY_STORM_COUNT`, so a warm-up span can never share an
   identity with a storm span. The canary's `base` stays wall-clock (`now_ms()`) — the canary needs
   per-preflight uniqueness, not determinism-under-seed, and that is existing, correct behaviour.

5. **Assert identity distinctness on the wire** (`crates/conductor-run/tests/canary_wire.rs`). The existing
   assertions prove events arrive intact against Conductor's own collector — a check structurally blind to
   a primary-key collision at a receiver, which is why the defect survived. Add an assertion over the
   captured set that every emitted span's `(trace_id, span_id)` pair is unique across the whole canary
   emission (warm-up **and** storm together), and that each id is the correct 16/8-byte length.

6. **Re-lock affected goldens.** Step 3 changes the dispatched wire's identity bytes, so the seeded stream
   goldens that project identity must be re-locked under `crates/*/tests/snapshots/` — CI is
   fail-don't-write, so this is a deliberate, reviewed re-baseline, not a `cargo insta review` sweep (per
   test-plan §7 Golden artifacts).

7. **Run the instrumented live leg** (operator/local gate, never CI). With a live deterministic-L4 Pulse:
   drive `scripts/agent-run.sh boot`, capturing Conductor's `emit.batch` wire-shape witness via the
   **additive** `RUST_LOG=info,conductor_emit=debug` form.
   **CAPTURING PULSE'S OWN LOG OUTPUT IS MANDATORY, NOT OPTIONAL — it is the decisive evidence of this
   chunk, and Conductor's own logs cannot supply it.** Redirect/tee the running `pulse-app`'s
   stderr/log for the whole duration of the leg and keep it as an evidence artifact: the
   `duckdb.append` **`reject_reason`** lines are emitted at ERROR level by `run_consumer`
   (`consumer.rs:79-85`) and are the only signal that names why an append failed. A leg run without that
   capture cannot settle the second unknown below and must be re-run.
   Record, as the leg's evidence: ingest `span_count`, buffer `rows_ingested`, the `span_events_seen` /
   `fingerprints_computed` / `observer_invocations` trio, **every `duckdb.append` line — both the
   `rows_appended` successes and the `reject_reason` failures** — and whether an incident formed.

8. **Record the outcome honestly.** "Fix landed, storm still absent" is an **expected possible outcome of
   this leg, not a surprise** — see the second-unknown note below. If the leg reaches `ready:true`, that is
   the measurement `v2-10` has always required. If it does not, the `duckdb.append` capture names the
   remaining cause — write that into the chunk's report and leave `v2-10` pooled. Never claim on the
   argument that the known obstacles are gone; this capability was un-claimed one chunk ago on exactly
   that error.

## Implementation notes
- **Order matters:** land step 2 before steps 3–4 — the signature change is what forces every caller to be
  visited, so a compile error is the enumeration mechanism. Do not add a defaulted overload that lets a
  caller keep the old constant-identity behaviour silently.
- **Disjointness, not just distinctness:** the warm-up's seeds must not overlap the storm's
  `base.wrapping_add(i)` range. Overlapping ranges would reintroduce exactly the collision being fixed,
  and `canary_wire.rs`'s new assertion (step 5) is what catches it.
- **THE SECOND, INDEPENDENT UNKNOWN (operator-verified addendum).** The consumer loop does **not** coalesce
  channel messages — one export = one `dispatch_batch` = one `RecordBatch` append (verified at
  `consumer.rs:55-90`) — and the storm's seeds are time-based per leg (`base = now_ms()`, `lib.rs:212`).
  So the primary-key mechanism **fully** explains the warm-up collapse and the dispatcher-wide scenario
  defect, but it does **not** explain the 12 distinct-id storm spans appending zero rows. That is a
  **second, independent unknown**, and this chunk's fix is not expected to dissolve it by itself.
  Consequently: **treat "fix landed, storm still absent" as an expected possible outcome of the live leg,
  not a surprise or a regression.** The leg's job is as much to *name* that second cause (via Pulse's
  ERROR-level `duckdb.append` `reject_reason` lines) as it is to test the fix.
- **A `0` in the trio is the never-written state.** `record_feed_counts` sits *after*
  `if trace_ids.is_empty() { return Ok(None) }` (`appender.rs:392-415`), so `span_events_seen: 0` is
  consistent with three different upstream causes and cannot by itself prove the enumeration ran and found
  nothing. Read the leg's `duckdb.append` lines for the positive signal; do not re-infer from the counters.
- **`ok_span` carries no events**, so a warm-up span can never contribute to `span_events_seen` regardless
  of whether it appends — do not read a warm-up-only append as evidence about the fingerprint feed.
- **Reading the storm-detector telemetry (standing rules):** `tracked_fingerprints_count` is a 60s-windowed
  gauge over DISTINCT fingerprints sampled after eviction, so a healthy 12-occurrence identical-fingerprint
  storm reads **1, never 12**, and a late sample reads 0 on a healthy path; `storms_detected_total`
  increments on both the Suggested and Autonomous branches so it discriminates storm PRESENCE, never TIER;
  `severity_hint` on `triage.pattern.storm.detected` is what names the tier.
- **Expected amendments (wrap):** `.andromeda/architecture.md` §Occupied Resources
  (`contracts/pulse-run-contract.toml` bullet) — the "second gap" paragraph currently localizes the gap
  between OTLP ingest receipt and buffer span-event enumeration and calls it producer-dependent without a
  mechanism. Direction: replace with the measured mechanism — a span-identity collision against Pulse's
  `spans` `PRIMARY KEY (trace_id, span_id)`, with the producer-dependence explained (`inject_demo`'s
  per-sequence ids never collide) — and reconcile whatever the instrumented leg adds. Route this through
