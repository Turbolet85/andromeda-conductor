## Goal

Conductor's preflight canary emits a storm sized to clear Pulse's *cue* floor but not its *incident-forming*
threshold. `CANARY_STORM_COUNT = 6` sits in the Suggested band (`5 ≤ 6 < 10`), and Pulse's Tier-1 coordinator
accepts **only** Autonomous cues — so no incident can form, `query_incident_list` returns empty forever, and
`conductor preflight` can never reach `ready:true` no matter how healthy Pulse is. This chunk raises the
constant past the Autonomous threshold, corrects the doc comment that encoded the insufficient rationale, and
runs the operator-gated live leg that proves the result.

Research settled the question that decides the chunk. Conductor has recorded for two chunks that Pulse's
3,600 s `BootstrapState::Ready` gate is what starves the canary. **The citation was right and the attribution
was wrong**: that gate is the *only* one in `crates/triage/src/`, and it sits inside
`evaluate_service_went_silent` — the P-014 silence cue. The RetryStorm path has no baseline or bootstrap
dependency at all (`storm.rs:245-285`), which is why Pulse measured two incidents with `baseline_state`
holding zero rows. All three causes `v2-10`'s decline note names are therefore dissolved, and the count is
genuinely the last blocker (research.md §The corrected premise).

The change itself is a leaf edit — the code-graph puts every reference to the constant inside its own crate
(`rows: 5`). The weight of the chunk is in the live leg's evidence discipline, per arch §Standard Contracts

## The margin arithmetic (directive 3 — stated, not assumed)

- **Floor:** `count >= detector.autonomous_threshold` (`pattern/storm.rs:245`) against
  `DEFAULT_AUTONOMOUS_THRESHOLD = 10` (:78) ⇒ **10 suffices; the margin sits above 10, not above 11.**
  Measured live by Pulse: `occurrence_count=10 severity_hint=autonomous`.
- **Detection-window ceiling:** `DEFAULT_DETECTION_SUB_WINDOW_SECONDS = 30` (:69) bounds the trigger
  population. `emit_canary_storm` is an **unpaced** loop — `for i in 0..N { traces.export(…).await }`, no
  sleep (unlike the warm-up, which does sleep) — of sequential loopback unary RPCs, one span with one
  exception event each. At a deliberately pessimistic ~10 ms per round trip, N = 12 completes in ~0.12 s:
  **~250× inside** the window. Not a binding constraint at any plausible margin.
- **Load-envelope ceiling:** `max_sustained_rate_spans_per_s = 10000`, `max_sustained_storm_ms = 600000`.
  12 spans in ~0.12 s ≈ 100 spans/s ⇒ **~100× under** the rate term; the burst is ~5000× under the duration
  term.
- **Chosen: 12.** Clears the floor by 2, so losing an occurrence does not drop the storm to Suggested; and it
  is the project's own established "reaches Autonomous" number — `scenarios/fingerprint-storm.toml`'s second
  phase already uses `occurrences = 12` for exactly this transition. **Leaned per
  `scenarios/fingerprint-storm.toml`.**
