## Goal

This chunk inherited the preflight-green blocker role for the third time (count → primary key → derivation),
and P3 falsified the mechanism it was scoped around. Conductor's fingerprint and Pulse's genuinely differ in
algorithm, input and width — but that difference is **not** what blocks the gate. The gate compares against
`retrieve_telemetry_slice.fingerprint_refs`, which is populated from the **L4 model's** `evidence_refs`
(`pulse-app/src/inference_runtime.rs:684-701`), hardcoded to `[]` under the deterministic-L4 mode every live
leg requires (`deterministic_inference.rs:35`), and never carries the buffer's computed fingerprint at all.
Pulse's real fingerprint lands in the `span_events.fingerprint` BLOB column, which **no MCP tool reads** — the
surface is exactly 8 tools and none touches that table. Conductor's fingerprint has no read-back surface at
any width, so the canary's final precondition was unsatisfiable independent of derivation.

Per the standing rule that a falsified *mechanism* does not falsify the *goal*, the chunk keeps the goal
(preflight reaches `ready:true`) and changes the mechanism. Two pieces, both operator-ratified at P4:

   one whose `opened_at_unix_nano` postdates the canary's emission stamp. That field is verified present on
   `query_incident_list`'s items (`andromeda-pulse crates/mcp-server/src/tools.rs:348-354`). This proves the
   two things the gate exists for — the sidecar reads the live Pulse's corpus, and this run's storm caused a
   new incident — without claiming a payload fidelity that deterministic L4 makes impossible.
2. **Adopt Pulse's derivation anyway.** It no longer serves preflight, but Conductor's fingerprint encodes its
   *prediction of how Pulse groups exceptions*, and the two predict differently: Conductor hashes up to
   `MAX_FRAMES = 64` frames, Pulse only the first 3 normalized lines. Exceptions differing at frame 4+ are

architecture.md §Cross-cutting Patterns Verdict/error wall + security-plan §Security Anti-Patterns → Universal).
