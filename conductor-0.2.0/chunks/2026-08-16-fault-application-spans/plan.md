## Goal

Make a scenario's fault phases observable in the self-observation stream. obs-plan §4 (Fault-injection spans)
has specified three spans since the plan was written — `fault.silence`, `fault.ramp`, `fault.port_occupier`,
each carrying `fault_type` / `fault_duration_ms` / `fault_start_offset_ms` plus `ramp_factor` or `port` — and
obs-plan §11 already reserves all three names in the bounded span-name set. None is emitted today: the fault
phases run, and nothing in `logs/agent-latest.jsonl` says so.

Research changed how this gets built. The obvious reading of obs-plan §4 — "each fault span wraps the fault
application phase in `conductor-faults`" — is unreachable: the code-graph shows `conductor-faults` has **zero
crate edges in either direction** and **zero references from outside itself**, because the shipped design
expresses faults declaratively (`phase_spec.rs:60-62`: `occurrences: 0` is how a quiet phase is expressed
"without reaching for a fault helper"). Meanwhile the only phase boundary in the run path lives in
`conductor-timeline`'s `run_timeline_with`, which is **shape-blind by design** (`phase.rs:5-7`) and offers no
per-phase hook at all — `on_emit` fires once per declared occurrence, and a silence phase (`emissions == 0`)
calls nothing (`scheduler.rs:97-107`, `:122-125`).

So the chunk lands in three parts: a **per-phase observation hook** on the timeline that hands the caller each
phase's window without teaching the scheduler what a fault is; **fault classification in `conductor-run`**,
the one place holding both the scenario's shapes and the `std::time` journal basis (`lib.rs:338`); and the
**five attribute names added to `conductor-core::redact::ALLOWLISTED_FIELDS`**, without which every attribute
is dropped silently and a presence-only test would pass vacuously (per obs-plan §4 Required-span-attributes +
test-plan §3 Log format). `fault.port_occupier` is instrumented at its RAII site by operator decision, with
its parentage limit recorded rather than claimed.

2. **Add a per-phase observation hook to the scheduler** — `conductor-timeline` gains an entry point that
   calls an observer once at each phase's start, receiving the phase index, its name, and the **effective

   Keep the existing `run_timeline_with` signature working (delegate to the new form with a no-op observer)

3. **Classify fault phases in `conductor-run`** — in `execute_scenario` (`lib.rs:344`), supply the observer.
   For each phase read `scenario.phases[index].emission`: `occurrences == 0` → `fault.silence`;

4. **Derive the attribute values** — `fault_type` is the bounded label (`"silence"` / `"ramp"`);

## Constraints & rejected approaches
- **Do not instrument the other `conductor-faults` helpers** (`AbruptSilence`, `EmissionGap`, `BurstyTrain`) —
  the graph proves nothing calls them, so a span there fires on no run. Only the port-occupier is
  instrumented, because the operator chose to and its limit is recorded.
- **Do not wire a port-occupier driver into the run path** — that is new fault behavior, excluded by scope,
  and matrix `v2-15` assigns it to the connection-lifecycle live-proof entry.
- **Do not give `Phase` a fault-kind field** — it would push fault vocabulary into a timing model that
  `phase.rs:5-7` deliberately keeps shape-free, and would still need the journal basis threaded in.
- **Do not open the fault span from `Dispatcher::dispatch`** — per-emission, so it never fires for a silence
  phase and would yield one span per emission rather than one per fault window.
- **Do not add a `fault.breathing` span** — `EmissionShape::Breathing` is a sibling rate curve, and the
  bounded span-name set is exactly three fault names (obs-plan §11).
- **Do not extend `PortOccupier::occupy` with a journal-basis/hold-window parameter** — designing API for a
  caller that does not exist; the driver chunk supplies those when it lands.
- **Do not implement `on_record` on `JsonObsLayer`** to carry a late attribute — out of scope here; the
  witness-on-`message` pattern already covers the one late value (obs-plan §6).

## Implementation notes
- **Create the fault span, do not enter it.** A span created inside `run_timeline_with`'s instrumented body
  takes `timeline.execute` as its parent at creation, and `JsonObsLayer` emits `new` on creation and `close`
  on drop regardless of entering (`obs.rs` `on_new_span`/`on_close`). Entering it would reparent every
  `emit.batch` raised during that phase onto the fault span, changing obs-plan §4 Critical Path 1's
  `scenario.run → timeline.execute → emit.batch` chain — which this chunk must not do.
- **Two clocks, two jobs.** `fault_duration_ms` is the scheduler's effective *virtual* gap (the declared
  window); `fault_start_offset_ms` is wall-clock `std::time` against the journal basis. Under `start_paused`
  the wall-clock barely advances, so tests assert the offset's basis and monotonicity, never a value.
- **The spans reach `logs/agent-latest.jsonl` only on a ready preflight.** `execute_scenario` returns a
  Blocked record at `lib.rs:325` *before* the timeline runs, so a headless no-Pulse run emits no fault span
  at all. That is why every acceptance criterion above is asserted at the test tier on rendered JSON; the
  artifact-level sighting rides the live-proof entries later in Epoch 3. Do not add a criterion asserting the
  file's contents from a Pulse-free run — no listed command can produce it.
- **Order sensitivity:** step 1 (allowlist) before any span work, or the tests assert against silently
  dropped attributes and fail in a way that looks like a derivation bug.
- **`ramp_factor` denominator:** `max(from_rate, to_rate)` is zero only if both rates are zero; garde bounds
  the ramp shape at load (`shape_is_realizable`), and `RateCurve::ramp` already rejects zero windows
  (`dispatch.rs:139-141`) — handle the degenerate case as `0.0` rather than a panic (the verdict/error wall).

  - `obs-plan.md` §4 Fault-injection spans — the placement sentence ("each fault span wraps the fault
