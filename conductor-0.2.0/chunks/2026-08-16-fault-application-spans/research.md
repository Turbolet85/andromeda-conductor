## Patterns detected
- **Span-at-the-composition-root** (`conductor-run/src/lib.rs:309`): the two production spans that carry scenario identity are opened where the data lives (`scenario.run` in run, `timeline.execute` in the scheduler), with attributes computed at open — `timeline.execute`'s `emission_count` is derived by `PhaseTimeline::total_emissions()` (`phase.rs:60-62`) precisely so it is knowable at `new`.
- **Attributes on the `new` line only** (`conductor-core/src/obs.rs:295`, `:327-363`): `JsonObsLayer` gates every span attribute through `is_allowlisted`. A non-allowlisted name is dropped silently — the failure is invisible, which is why the allowlist edit is part of the deliverable rather than a follow-up.
- **Shape-blind timing seam** (`phase.rs:5-7`, `convert.rs:22-27`): the timeline receives counts and durations, never semantics. Any fault vocabulary reaching the scheduler is a deliberate widening of that seam, not an incidental one.
- **Declarative faults, no helper** (`phase_spec.rs:60-62`): the doc comment states `occurrences: 0` "is how the activity-floor family expresses a quiet phase **without reaching for a fault helper**" — the shipped design deliberately bypasses `conductor-faults`, which is why that crate is an island.
- **RAII fault lifecycle** (`conductor-faults/src/port_occupier.rs`): `occupy()` → hold → `release()`, exercised only by `tests/port_occupier.rs:39-49`.
