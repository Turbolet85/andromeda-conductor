## Goal

Pulse changed its exception-fingerprint normalization to **token-leading**: a path token counts as absolute
only when it starts a token, so relative path structure is identity-significant at every depth and only a
token-leading absolute is stripped — to nothing. Conductor's derivation is a transcription of the *previous*
scanner, so the two no longer agree.

The chunk's core is therefore smaller and sharper than "re-aim some tests": **transcribe the token-boundary
guard**, which is what makes `fingerprint()` predict Pulse's grouping again. Research measured the drift on
the committed base fixture itself — `src/worker.rs` normalizes to `at …(src)` here and `at …(src/worker.rs)`
at the SUT, so every fingerprint Conductor computes for a slash-bearing path is currently wrong. Nothing in
this repo catches that, because every gate compares Conductor against Conductor; the derivation is the SUT's
choice, not Conductor's, per architecture.md §Established Decisions [Read-Back Dependency Posture] and the
Pulse-consistency mandate in §Stack and Technologies.

Everything else follows from the guard. `PathVariant` stops being a same-fingerprint variant — under
token-leading no path variation can preserve identity — so the storm's same-fp membership is redrawn onto
the two axes that survive for a relative-path base: **identical and line**. That restores the threshold
arithmetic the scenario's phase names claim (all 18 occurrences on one fingerprint, `>=5` Suggested at the
first boundary, `>=10` Autonomous cumulative) instead of the measured 12/6 split into two storms. The
superseded P-017 clause rides to wrap as an expected amendment, never as a touchpoint.

This is the drive-half unblock for Pulse's P-075 blocker 2, which records that the re-alignment executes here.

## Implementation Steps

1. **Transcribe the token-boundary guard** into `conductor-emit`'s `is_absolute_path_start`
   (`exception.rs:292-300`), mirroring Pulse's `crates/buffer/src/fingerprint.rs` at HEAD `efabe8e`: a path
   token is absolute only at position 0 or when the preceding byte is not a path char. Do this FIRST — it
   changes every computed fingerprint for a slash-bearing path, so every later step must be re-aimed against
   the corrected derivation, not the old one.
2. **Redraw `FingerprintVariant` membership** (`exception.rs:96-149`). Same-fp becomes `{Identical,
   LineVariant}`. `PathVariant` and `RelativePathVariant` both become different-fp members and both survive
   — together they witness "path is significant at every depth" at two different depths, which is precisely
   the new truth. `PathVariant::derive` no longer needs to preserve a leading segment; it must still stay
   **relative** so the artifact-hygiene invariant holds.
3. **Retire `leading_path_segment`** (`exception.rs:46-48`) — it exists only to model the superseded rule,
   and its two consumers (`PathVariant::derive`, the path test) are both being re-aimed.
4. **Re-aim the four affected unit tests**: `same_fingerprint_variants_match_the_base` (`:381-396`) drops
   `PathVariant`; `the_path_variant_differs_below_an_unchanged_leading_segment` (`:413-424`) becomes an
   assertion that the variant differs while staying relative; `only_the_leading_path_segment_reaches_the_preimage`
   (`:428-435`) is replaced by a pin on the NEW normalization fact; `relative_path_is_fingerprint_significant`
   (`:401-408`) keeps its name and meaning but is no longer the narrow half of a split.
5. **Add the replacement pinning test** mirroring the SUT's own axis tests: a relative path differing at any
   depth yields a different fingerprint (`src/a.rs` vs `src/b/c.rs` vs `other/a.rs`), and a token-leading
   absolute path normalizes to the empty form. This is the transcribe-and-pin shape the prior derivation
   chunk established.
6. **Correct the prose that states the superseded rule** in `conductor-emit`: the module doc (`:8-12`),
   `fingerprint()`'s doc (`:156-158`), `Frame`'s field docs (`:51-61`), and `normalize_frame`'s doc
   (`:248-250`). Record the new SUT HEAD (`efabe8e`) where the old one is cited.
7. **Follow the enum's doc comments** in `conductor-core` (`phase_spec.rs:141-159`) — each
   `FingerprintVariantSpec` member's doc states its same/different-fp relationship, and `Path`'s is now false.
8. **Thread the callers enumerated from the graph**: `dispatch.rs:216-223` (`wire_variant` — all six members
   survive, so the mapping's shape holds; confirm rather than assume) and `dispatch_wire.rs:239`, `:240`,
   `:402` (the three `FingerprintVariantSpec` construction sites).
9. **Re-aim `scenarios/fingerprint-storm.toml`**: the P-017/P-018 prose (`:5-21`) and both `variants` lists
   (`:55`, `:63`) to `["identical", "line"]`. Leave `occurrences`, `gap_ms`, `seed` and `slo_tier` untouched —
   that is what keeps the load envelope and both committed goldens unmoved.

## Implementation notes

- **Order is load-bearing.** Step 1 (the guard) changes every fingerprint value for a slash-bearing path. Doing
  it first means the re-aimed tests assert the corrected derivation; doing it last means every intermediate
  test run is measuring the old semantics.
- **The 12/6 split is the pre-fix baseline, not a target.** With `["identical","path","line"]` the dispatcher's
  positional cycling (`variants[occurrence % variants.len()]`, `dispatch.rs:101-103`) puts 4 base + 2 path in
  phase 1 and 8 base + 4 path in phase 2. After the redraw the whole 18 land on one fingerprint.
- **Both goldens were measured variant-independent** (`pacing__*` carries only `EmissionPoint` + elapsed ms;
  `dispatch_wire__*` projects span shape with the event *name* only, zero stacktrace content). Treat a moved
  golden as evidence the projection carries something research did not see.
- **The scenario leg runs without a live Pulse, and that is sufficient here.** With no Pulse the run takes the
  Blocked spine and the envelope carries null measurements — but it still writes the journal, the `runs.db`
  row and `logs/agent-latest.jsonl`, which is exactly what the artifact-hygiene criterion asserts on. That
  criterion is about redaction, not about a passing verdict, so a Blocked leg satisfies it. Do not read a
  Blocked envelope from this leg as a chunk failure.

  records that this project has twice landed a supersession at §Established Decisions and had to re-apply it
