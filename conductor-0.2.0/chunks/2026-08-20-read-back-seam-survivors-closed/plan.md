## Goal

Close the last five mutation survivors the 2026-08-20 code audit surfaced in `conductor-verify`, so that
every audit-surfaced survivor across the workspace is either **killed** or **classified
accepted-deliberate** before the next boundary's trend measurement has to mean something. This is the
§B2 remainder after `2026-08-20-verifier-self-hardening` dispositioned its four named families.

The five are not five independent bugs — they are **three distinct observation gaps**, and research showed
each one is a place where the existing test harness is structurally incapable of seeing the behaviour, not
a place where an assertion was merely forgotten. (1) The shared duplex stub **echoes back the id it
received** (`tests/common/mod.rs:145`), so it answers a mutated id sequence (`1,0,-1…` or `1,1,1…`) exactly
as agreeably as the correct one — correlation never breaks, and the difference is observable *only* as the
id values on the wire. (2) `notify`'s single call site discards its result by design (`client.rs:93`,
`let _ = …`, "Pulse tolerates its absence"), and the stub `continue`s on any line with no `id`
(`:82-84`) — so the `notifications/initialized` line already reaches the wire in tests and is simply never
observed. (3) `ShapeWitness::list`'s only effect is one `tracing::info!` line via `extract::log_observed_keys`,
so it is witnessable only on the self-obs artifact, which forces the capture into its own test binary.

The work is therefore **test-support first, assertions second**: teach the stub to record what it received,
then assert on it through the public `ReadbackClient::connect_transport` seam. No production behaviour
changes and no visibility widens — per test-plan §11 (Unit) the assertion surface is the public seam, and
per architecture.md §Established Decisions [Module Boundaries] crates are the compiler-enforced visibility
boundary, which is why the route entry ruled widening out in the first place. The chunk claims **no
capability**: all 15 unclaimed matrix entries need a live Pulse leg, an a11y/webview surface, or another
route entry's work, and this chunk drives none of them.

1. **Extend the shared stub additively with a recorder.** In `crates/conductor-verify/tests/common/mod.rs`,
   add a way for a test to observe what the stub received: the ordered sequence of request `id` values, and
   the `method` of each id-less notification line. Additive only — the 7 existing `connect_transport` call
   sites and the 15 existing `tests/preflight.rs` legs must keep compiling and passing untouched. The file
   already carries `#![allow(dead_code)]` and `StubConfig` already has 11 knobs with a `Default`, so the
   established extension shape is a new knob/handle plus a recording variant of `serve_stub`, not a change
   to the existing signature. Keep the wire behaviour byte-identical to today's stub — per architecture.md
   §Established Decisions [MCP Read-Back Client], the stub's fidelity to Pulse's hand-rolled line-delimited
   JSON-RPC with RAW `result` payloads is what makes any kill meaningful.

2. **Assert the id sequence (kills `jsonrpc.rs:41:22` ×2).** Drive ≥3 requests through the public seam on
   one session — `connect_transport` alone spends `initialize`, and `run_preflight` adds `tools/list` plus
   one `query_incident_list` per attempt — and assert the recorded ids are **strictly increasing from 1 with
   no repeats**. `-=` yields `1,0,-1…` and `*=` yields `1,1,1…`; both fail that assertion, and neither can be
   caught any other way against a faithful echoing stub. Prefer the structural property (strictly
   increasing, repeat-free — the property that makes a response pairable to exactly one request) over a
   hard-coded `[1,2,3,4,5]`, so a future preflight arm-order change does not make the test lie.

3. **Add the correlation complement (semantic proof, same site).** Have the stub emit one **stale decoy
   response** carrying an earlier id immediately before the real answer to a later request. Correct code
   skips it via the id-mismatch guard at `jsonrpc.rs:49-51` (whose comment states exactly this purpose);
   `*=`-mutated code, pinned at id 1 forever, consumes the decoy as its answer. This makes correlation the
   carrier rather than arithmetic, which is what the route entry asked for. It is a **complement, not a
   replacement** — it kills `*=` but not `-=` (whose echoed `id:0` still pairs correctly), so step 2 remains
   the load-bearing assertion.

4. **Assert the notification reached the wire (kills `jsonrpc.rs:65:9`).** Assert that a line with

   present and merely unasserted. Assert its arrival and its ordering relative to `initialize`; do not
   assert a response, because the protocol defines none.
