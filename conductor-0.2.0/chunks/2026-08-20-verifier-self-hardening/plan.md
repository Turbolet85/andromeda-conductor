## Goal

Conductor's job is to assert a live Pulse. The 2026-08-20 code audit measured that Conductor's own
asserting machinery is under-asserted: `conductor-run` scores 58.82% and `conductor-verify` 72.97% on
mutation, meaning covered lines execute with nothing checking their behaviour. This chunk closes the
**22 survivors across four named families** with killing tests, and removes the cause of a suite that
passes under one test runner and fails under another.

Three of the four families sit on controls the specs mandate by name: the read-back per-line size bound
(security-plan §Input Validation), the run-contract `shell-declaration` predicate that decides whether an
unmet term surfaces as a distinct `Blocked` (arch §Standard Contracts, security-plan §Input Validation),
and the canary freshness comparison a whole prior chunk proved live (arch §Established Decisions
[Read-Back Dependency Posture]). The fourth — the two journal-stamp helpers — carries the
journal-relative SLO arithmetic every measurement rests on (obs-plan §11, arch §Cross-cutting Patterns).
Each mutant that survives is a mandate with no enforcing test.

The runner-portability half is a determinism defect, not a quirk: test-plan §10's zero-flakiness budget
and §11 Test Data's ban on shared mutable state across parallel tests both bind it. Research measured the
mechanism directly (alone it passes; `--test-threads=1` passes; only concurrent-with-siblings fails), so
the fix removes the cause rather than documenting it.

1. **Split the env-and-subscriber-dependent test into its own integration-test binary.** Move

   `crates/conductor-run/tests/`. Under `cargo test` each `tests/*.rs` file is a separate process, and
   nextest is already process-per-test — so the test gets a private process under **both** runners. This
   is what makes its existing SAFETY comment (*"nextest runs each test in its own process"*) true rather
   than aspirational, and it preserves the production `init_observability` path obs-plan §3 requires.
2. **Scope the witness count by its own `run_id`.** Belt-and-braces for step 1: the witness lines already
   carry `run_id` (the test asserts the field's presence) and the test names itself `canary-witness`.
   Filter the counted lines on that discriminator so the assertion cannot be perturbed by a future sibling
   added to the new file. Keep the assertion reading a real artifact from the real init path.
3. **Kill the `declares` family (6).** Drive the public `readiness()` entry (`conductor-run/src/lib.rs:75`)
   against the stub sidecar with the run-contract's observed env varied across a matrix — `true`, `1`,
   mixed case, surrounding whitespace, `false`, an unrelated value, and absent — and assert the returned
   `ReadyState` names the specific unmet term in its blocked precondition. This kills the wrapper survivor
   (`:206:5 observe_run_contract -> Default::default()`) in the same pass. Put this test in its own
   integration-test file too: it manipulates process env, which is the same isolation hazard step 1 fixes.
   Arch's arm ORDER makes this cheap — the run-contract arm precedes the canary arms and skips the canary
   poll, so the test does not pay the poll budget.
4. **Kill the `MAX_LINE_BYTES` family (5).** Exercise the read-back line reader on both sides of the
   bound: a line at exactly `MAX_LINE_BYTES` is accepted, a line one byte over yields the typed
   `VerifyError::Decode`. Both sides are required — the at-limit case is what kills the two constant-
   expression mutants at `:18`, and the over-limit case kills the guard and comparison mutants at `:79`.
   Assert the typed variant, never a panic (arch §Conventions, security-plan §Error Handling).
5. **Kill the canary freshness boundary (1).** Cover the degrade direction security-plan calls the
   security-relevant half: an incident opened strictly after the emission stamp proceeds; one opened at
   exactly the stamp, or before it, is NOT fresh and reaches `NotFound::StaleCorpus`; an empty list reaches
   `NotFound::EmptyCorpus`. The equal case is the one that kills `>` → `>=`.
6. **Kill the poll-loop guard family (4).** These are **timing-observable only** — the mutants change how
   many times the loop sleeps and leave the return value untouched, so an outcome assertion cannot kill
   them. Use the house idiom: `#[tokio::test(flavor = "current_thread", start_paused = true)]` with tokio's
   auto-advance, asserting observed virtual time across a known attempt count. Do not import an explicit
   `tokio::time::advance` — the workspace does not use one.
7. **Kill the journal-stamp family (6).** Both helpers are crate-private and arch bans widening visibility
   for a test seam, so assert through a public observable that carries the stamp — the envelope's
   `journal_emitted_at` / `read_back_observed_at` produced by `execute_scenario`, or
   `CanaryMarker.emitted_at_unix_nano`. Assert a *plausible wall-clock magnitude*, not merely non-zero:
   both helpers end `unwrap_or(0)`, so a mutant returning `0` is otherwise indistinguishable from the
   genuine error path. Never reach for the virtual clock here (obs-plan §11, test-plan §11 Test Data).
8. **Remove the unused dependency.** Drop `tracing.workspace = true` from `crates/conductor-cli/Cargo.toml:19`
   and commit the resulting `Cargo.lock`. The CLI surface keeps its obs-plan §4 hook through
   `conductor_core::init_observability` (`main.rs:28`) — the subscriber lives in `conductor-core`.
9. **Run the scoped mutation re-run and confirm the named survivors are killed** (see Test Commands for the
   firing form). Record the `stub_pulse_mcp` exclusion in the next audit ledger record, per the operator ruling.
