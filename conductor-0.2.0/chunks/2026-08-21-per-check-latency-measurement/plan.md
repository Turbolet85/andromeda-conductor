## Goal

Give a scenario's expected-outcome checks their own timing budget and their own place in the run-report
envelope. Today `SloTier` floors the deadline ladder at 5 seconds (`<5s`/`<20s`/`<90s`,
`conductor-core/src/scenario.rs:50`), so no check can be held to a finer bound — and the four
delegated-timing capabilities the next route entry targets need 2s/5s/2s/1s. This chunk adds an optional
per-check `budget_ms` **beneath** the closed tier set (never widening it — arch §Data model conventions
pins the enum, and the code-graph measures 150 refs across 18 files behind it), validated at load by garde
one altitude up on `Scenario::expected` per security-plan §Input Validation.

The second half is attribution. `execute_scenario` evaluates every check against one instant pair, then
`.max_by_key(severity_rank)` keeps a single `CheckOutcome` and **discards the rest**
(`conductor-run/src/lib.rs:414-437`) — so a scenario's row shows only its worst check, and the other
checks' verdicts, observed values and SLO outcomes reach no sink at all. This chunk persists every check's
outcome with its own effective deadline and verdict.

**One premise was corrected at P3 and shapes everything below.** `observe()` is called **once** per
scenario and composes **one** `Observation`; each check grades a *projection* of it
(`conductor-verify/src/extract.rs:53-62`). There is therefore exactly one observation instant, so per-check
`latency_ms` values are necessarily **equal** — a genuinely per-check *instant* would require per-check
read-back calls, a read-back-architecture change far outside a `method: unit` capability. What makes the
per-check half real is the **deadline**: two checks in one scenario share a latency but declare different
budgets, so they can reach different timing verdicts. This is the operator-selected design (P4 round 1) and
it is the concrete form v2-19's acceptance is refined to at P5.

## Implementation Steps

1. **Declare the per-check budget.** Add an optional integer-millisecond budget to `ExpectedCheck`
   (`conductor-core/src/expected.rs`), serde-defaulted absent so every existing `[[expected]]` block keeps
   parsing unchanged. Bound it with a garde `range` rule. Follow the `EmissionShape::Error { error_percent:
   u32 }` integer discipline so `ExpectedCheck`/`Scenario` keep `Eq` (per architecture.md §Established
   Decisions [Validation Library]). It is a scalar `Option`, not a nested struct — the `dive`-never-`skip`
   mandate applies to nested structs and is not triggered here, but the negative test in step 8 asserts the
   rule executes.

2. **Assert budget ≤ tier one altitude up.** `ExpectedCheck` carries no back-reference to the scenario's
   tier, and garde 0.22.1's `custom` is field-level only, so the cross-field invariant lands as a
   `#[garde(custom(...))]` on `Scenario::expected` — the shipped `fault_phases_are_silent`-on-
   `Scenario::phases` template (`conductor-core/src/scenario.rs:96`). A budget exceeding its tier's
   `deadline_ms()` fails at load as `CoreError::Validation` — a harness fault, never a verdict (per
   security-plan §Input Validation + architecture.md §Conventions "Error handling").

3. **Make the deadline the compared quantity.** In `conductor-verify/src/slo.rs`, `evaluate_slo` currently
   reads `tier.deadline_ms()` directly — the single place a budget must intercept. Give the SLO evaluation
   an *effective deadline* (`budget_ms` when declared, else `tier.deadline_ms()`) and carry that value on
   `SloOutcome` so a reader can see what the check was actually held to. `evaluate_check` passes the check's
   own budget through. Impact is one production call site: `evaluate_slo @
   crates/conductor-verify/src/slo.rs:74`; `evaluate_check @ crates/conductor-run/src/lib.rs:417`.

4. **Add the per-check envelope record.** Beside `RunRecord` in `conductor-core/src/run_record.rs`, add a
   per-check record carrying its identity (`run_id`, `scenario`, the check's ordinal index in
   `scenario.expected` — `ExpectedCheck` has no name, so the ordinal is the stable key), its `latency_ms`,
   its effective deadline, its declared `budget_ms` (nullable), its `verdict` and its `state`. Keep the
   integer-milliseconds + RFC-3339 split already in force (per architecture.md §Conventions "Data model
   conventions"). **`RunRecord` itself keeps exactly its eleven fields in declaration order** — the
   scenario-level envelope is unchanged.

5. **Retain every check outcome.** In `conductor-run/src/lib.rs`, keep the full `Vec<CheckOutcome>` instead
   of collapsing to one. `.max_by_key(severity_rank)` still chooses the scenario-level `RunRecord` (the
   worst verdict still governs the row and its lamp — verdict-first precedence is untouched), but each
   outcome also projects into a per-check record. Have `execute_scenario` return the record **and** the
   per-check rows. Declare-only scenarios (zero `expected`) and blocked rows produce **zero** per-check rows
   — never a synthesized or inherited value on something that was never measured (per architecture.md
   §Standard Contracts).

6. **Persist at the check grain in its own table.** Add a third table to `conductor-report/src/db.rs`'s
   `SCHEMA` const under `CREATE TABLE IF NOT EXISTS`, keyed `(run_id, scenario, check_index)`, written with
   bound parameters only. This is the `run_envelope` precedent applied at a finer grain: that table's own
   doc states the rule — *"Deliberately NOT a column on `runs`: the qualifier is run-level, and the
   eleven-column check row plus its `(run_id, scenario)` key stay exactly as they are"*
   (`crates/conductor-report/src/db.rs:113-119`). A per-check qualifier is check-level, so `runs` keeps its
   eleven columns and its `(run_id, scenario)` key, and `state` stays the closed five-variant set.

7. **Thread the rows to the three sinks.** `persist` and `RunReport::write` gain the per-check rows;
   the JSONL journal appends them after their scenario's record; the Markdown report renders them as
   **indented detail lines under the scenario row**, not a new column. `drive_run` collects them internally
   and **keeps its public signature** (`anyhow::Result<Vec<RunRecord>>`), so `conductor-tauri` is not
   touched. Admit any new field name to `conductor-core::redact::ALLOWLISTED_FIELDS` in the same edit,
   beside the existing "reserved Run-report envelope fields" block (per obs-plan §4 + §11).

8. **Test at unit tier.** An rstest valid/invalid `#[case]` matrix over budget declarations (absent,
   equal-to-tier, under-tier, over-tier → `CoreError::Validation`); an exact-string serialization golden for
   the per-check record; a two-check fixture sharing one instant pair with different budgets proving
   different timing verdicts; assertions that declare-only and blocked scenarios emit zero per-check rows;
   and a re-lock of the unchanged eleven-field `RunRecord` golden at `run_record.rs:135`. Assert the tier
   *rule*, not the millisecond literals (per test-plan §1 de-hardcode precedent).

## Constraints & rejected approaches
- **Widening `SloTier` to express a finer budget — REJECTED.** arch pins the closed TEXT enum, and the graph
  measures 150 refs across 18 files behind it; every render surface would gain a fourth value its spec
  forbids. The budget sits beneath the tier instead.
- **A 12th column on `runs` — REJECTED.** arch states column types are "fixed on first write (no migration
  framework to coerce later)"; the `run_envelope` doc records the same reasoning for a differently-grained
  qualifier.
- **Row-per-check inside `runs` (changing the PK) — REJECTED.** It breaks `(run_id, scenario)`, a11y's
  single-row-per-P-ID matrix contract and the §6 lamp→journal-row join, and multiplies the virtualization
  exposure a11y §11 bans.
- **A 7th lamp or 6th `ReportState` for a budget breach — REJECTED.** The lamp set is closed at six; a
  breached budget is an existing `Fail` verdict on that check (per layout-templates §cli block 2).
- **A new `comfy-table` column — REJECTED.** layouts calls that a breaking output-contract change absent a
  `--format` flag; the indented detail line is the sanctioned per-row-extra-fact carrier.
- **Per-check read-back calls to obtain per-check instants — REJECTED.** It would multiply MCP round-trips
  per scenario and re-architect `observe()`, far outside a `method: unit` capability. See the Goal's premise
  correction.
- **Editing catalog scenario TOMLs to declare budgets — OUT OF SCOPE.** Scope forbids re-tiering the
  catalog; the differing-budget proof lives on constructed unit fixtures. Catalog scenarios still gain
  per-check attribution rows automatically, with no TOML edit.
