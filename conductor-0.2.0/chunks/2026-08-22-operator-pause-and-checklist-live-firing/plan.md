## Goal

The operator-pause machinery has been complete and unit-proven since Epoch 8/9 of 0.1.0, on all three
resolver surfaces (`HeadlessResolver`, the CLI `PromptResolver`, the GUI `TauriResolver`). What has never
happened is a **live attended activation**: every hold that has ever fired was answered by
`HeadlessResolver`. This chunk makes `v2-29`'s three-part acceptance true by measurement against a running
Pulse, on the **desktop-webview surface** (operator-selected at plan review), and closes the one wiring gap
that measurement exposes.

Research found parts (1) and (2) are already structurally correct and need **exercising, not building**: the
GUI hold reaches the webview through `TauriResolver` → `Channel<HoldPrompt>` → `OperatorPauseDialog` →
`resolve_operator_hold`, and the titlebar count freezes by construction because `drive_run` emits its
`RunEvent` *after* `execute_scenario` returns, so no event flows while a hold is pending
(`conductor-run/src/lib.rs:774-777`). Part (3) is the real work: the `induced` / `observation` pair — which
a11y-plan §1/§4, design-system §Component Patterns 7 and layout-templates §Component — Operator-checklist all
mandate as a contract rather than free prose — exists **only** as `ChecklistItem` in
`ui/src/components/OperatorChecklist.tsx`, rendered solely from `Gallery.tsx:199` with hardcoded placeholders.
No Rust type carries it; the live hold sends one generic sentence.

So the chunk turns per-scenario checklist wording into declared data (arch §Conventions Config conventions
mandates declarative TOML + serde + garde; the `[phases.fault]` table is the shape precedent), threads it
core → `HoldPrompt` → the webview dialog, and drives the attended legs against a live Pulse. The wording
already exists as TOML comment prose in the halo scenarios ("hue shifted toward burgundy under error
pressure?"), labelled *Epoch-8/10 calibration points* — this chunk promotes it from comment to data.

## Implementation Steps

1. **Declare the checklist item as scenario config.** Add an optional per-scenario `[[checklist]]` array to
   the scenario model in `conductor-core` carrying `induced` + `observation` (both non-empty bounded
   strings). serde-deserialized, `#[garde(dive)]` from birth — never `skip` (security-plan §Input Validation;
   the `2026-08-11-faithful-emission-dispatcher` amendment exists because a shipped `skip` meant its rules
   never ran). Follow the `[phases.fault]` precedent: optional field, `#[serde(default)]` absent, bounded
   contents, an unknown key a parse error rather than an inferred default.

2. **Add the sibling-spanning load-path check.** A `[[checklist]]` is only meaningful on a scenario that
   routes to the checklist hold (`expected` empty). That rule reads `checklist` **and its sibling**
   `expected`, so under garde 0.22.1 it cannot be a `#[garde(custom)]` — it ships as
   `Scenario::check_checklist()` invoked from `from_toml_str`, raising `CoreError::Config`
   (arch §Established Decisions [Validation Library]; the `check_budgets` / `check_capabilities` precedent).
   Pin with a test that `from_toml_str` actually invokes it (security-plan §Bootstrap phases).

3. **Carry the items to the hold.** Extend the core `HoldPoint` (or a sibling field on it) so
   `execute_scenario`'s checklist hold at `conductor-run/src/lib.rs:394-411` populates the scenario's declared
   items instead of only the generic prompt sentence. A scenario declaring no `[[checklist]]` keeps today's
   generic sentence — the change is additive, and the other 22 declare-only scenarios must keep working
   unchanged.

4. **Project the items to the webview.** Extend `HoldPrompt` (`conductor-tauri/src/pause.rs:23-45`) with the
   items so `HoldPrompt::from_hold` projects them; it stays a pure projection that never re-authors the hold.
   Its `Serialize` derive carries them over the existing `Channel<HoldPrompt>` — **no new command, no new
   Channel, no capability-file change** (Tauri app-commands are not ACL-gated; see Constraints).

5. **Render them in the dialog.** In the webview, feed the projected items into the existing
   `OperatorChecklistView` / `OperatorChecklist` primitive inside `OperatorPauseDialog`, replacing nothing —
   the primitive already renders `induced` + `observation` per row with a native checkbox, Space-toggle and
   the announced unticked-count roll-up (a11y-plan §1 Critical paths, §4). The ticks are the operator's
   observation record; the go/no-go stays the dialog's Proceed/Abort.

6. **Correct the CLI's false resolution witness.** `conductor-run/src/lib.rs:403` logs
   `"operator-checklist hold resolved headless: {}"` unconditionally — false the moment an attended resolver
   answers — and at `tracing::debug!`, which the default `LevelFilter::INFO` (`obs.rs:79-80`) suppresses
   entirely. Make it state the resolution truthfully at the level obs-plan §6 assigns a state transition
   (`info`), carrying the decision on the already-allowlisted `message` field rather than minting a span
   attribute (obs-plan §4 allowlist constraint; the `verify.readback` / `emit.batch` witness precedent). The
   GUI side already does this correctly at `conductor-tauri/src/pause.rs`
   (`tracing::info!("operator hold resolved ({})", decision.label())`) — bring the CLI to parity.

7. **Declare the halo pair's items.** Promote the checklist wording already sitting in
   `scenarios/halo-hue-encoding.toml` and `scenarios/halo-breathing-encoding.toml` comments into their new
   `[[checklist]]` tables. **P-ID discipline:** `halo-breathing-encoding` carries **P-026**, not P-025 —
   scope corrected this against the file. Declaring a checklist item that OBSERVES a halo claim does **not**
   claim P-025, which stays deliberately unverified pending the Epoch-6 *Halo hue budget re-driven* entry.

8. **Drive the attended live legs** against a live Pulse (HEAD `f0c38f5`, fresh data dir + `pulse-app`
   restart, window open, deterministic L4), through the GUI. Suite selection: the sorted catalog holds at
   every one of its 24 declare-only scenarios, so successive holds fire at increasing counts — giving both a
   count-0 first hold and genuine nonzero frozen counts thereafter, and room to exercise **both** a real
   Proceed and a real Abort in one leg. Capture per leg: the frozen titlebar count at the hold and its
   resumed value after the decision, the rendered checklist item, and the run's `RunRecord` rows.

9. **Pin the legs at the harvest tier.** A new `conductor-run` integration test pins the captured artifacts
   verbatim as hard predicates, following the six-precedent shape (`*_harvest.rs`, most recently
   `delegated_timing_harvest.rs`) so the claim stays CI-replayable without a live Pulse
   (test-plan §6 scenario rows).

10. **Discharge the 38th `cargo audit` PREREQ** in probe-auto-satisfy form (see Test Commands). This chunk
    should admit **zero** packages — `Cargo.toml` / `Cargo.lock` byte-untouched.
