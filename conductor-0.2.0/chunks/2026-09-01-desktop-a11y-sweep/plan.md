## Goal

The predecessor proved the harness *runs* on this host. This chunk makes what it runs *true*, and splits the
leg in two along the line the working entry draws: **affordance proof is agent-driven; only the judgment
class stays operator-gated.**

**Arm A — the routine leg (`--e2e`, unattended, must exit 0).** P3 named the single red by measurement: it
is `color-contrast` (wcag2aa / SC 1.4.3), 18 nodes, and **every node is the same foreground token**,
`--text-tertiary` `#717aa0` — 3.50:1 on `--color-raised-2`, 3.78:1 on `--color-raised-1`, against 4.5:1. So
the defect is one token value, fixed at the token per design-system.md §Surface: desktop-webview → Tokens,
never per-site. Computing a11y-plan.md §6's nine required pairs shows axe saw only part of it: a third
background fails latently (`--text-tertiary`/`--color-base`, 4.06:1, used by six empty-state prose sites) and
a second token fails in **both** themes (`--text-muted`/`--color-inset`, 2.91:1 dark / 3.86:1 light). The
shipped contrast spec asserts 3 of the 9 pairs, which is why none of that was caught. Arm A therefore fixes
the tokens, widens the contrast assertion to the full §6 table in both themes, adds the not-color-alone and
reduced-motion assertions a11y-plan.md §10 names as gate-failure conditions in their own right, and gives the
two subject-absent specs the **context-skip shape** the CARRY prescribes.

**Arm B — the driven leg (operator/local, live Pulse).** A skip is not a pass (a11y-plan.md §11 SLO), and
`v2-22` is an affordance cap under `verification-matrix-contract.md` §Affordance honesty, so its keyboard
clauses are provable only with the subject on screen. P3 read the gating mechanism at source
(`conductor-run/src/lib.rs:533-543`): the hold fires only on a READY preflight with a non-`Blocked` read-back
and a declare-only scenario, and checklist rows need a `[[checklist]]` declaration — which `halo-hue-encoding`
(P-025, ~6s of phases) carries. Arm B drives that run through the real webview and asserts trap entry,
Tab/Shift+Tab cycling, Escape→NoGo, focus restoration and Space-toggle on the real dialog. This arm is what
makes `v2-22` claimable rather than hollow.

Both subjects are already correctly built — `role="alertdialog"` comes from Radix
(`OperatorPauseDialog.tsx:33`) and `OperatorChecklistView.tsx:18` already carries `role="status"
aria-live="polite"` — so **no component markup needs repair for specs 4 and 5**; only the token values do.

## Judgment-class disposition

`scope.md` §The display-gate question reserves the **judgment class** — the ManualCheck items and an
occasional holistic pass — to the operator. That promise is dispositioned here rather than dropped:

**No ManualCheck item on the four accessible paths is a gate of this chunk.** Checked against a11y-plan.md,
which designates exactly three manual methods, none of them this chunk's:
- **The screen-reader manual pass** (NVDA / VoiceOver / Orca, a11y-plan.md §3 Screen reader test pattern —
  "supplemental, never sole") is the only manual method a11y-plan places on these paths, and it is its own
  route entry (`v2-23`), explicitly outside this scope.
- **CLI keyboard verification** is manual-only *and out of harness scope* — a11y-plan.md §1 excludes the cli
  surface from §§2/4 as not-assertable (no DOM, no focus-trap concept), so it is not one of the four paths.
- **macOS VoiceOver** has no automated SR test, but there is no macOS surface on this host.

**One nuance worth stating, because it looks like a counter-example.** The driven arm *does* render a real
ManualCheck item — `halo-hue-encoding`'s declared checklist row, "hue shifted toward burgundy under error
pressure?". Its **content is a Pulse visual claim**, not a Conductor a11y judgment. This chunk asserts that
row's *a11y affordances* agent-driven (`aria-checked`, Space toggle, the `role="status"` roll-up) and does
**not** ask the operator to adjudicate Pulse's halo — that adjudication belongs to the P-025 scenario's own
operator-checklist path, not to the a11y sweep.

**The holistic pass stays at the operator's discretion and is not a chunk gate** — no acceptance criterion
depends on it, and none should, since a discretionary look is not a reproducible verdict.
