## Goal

The desktop coverage matrix renders classification only. Every row's Status cell reads "Not yet run" on
every launch, forever, because `App.tsx:246` never passes the `lamps` prop that `CoverageMatrix.tsx:44`
already declares. This chunk closes that loop: after a run, each capability row carries the verdict state
its run records actually produced, and a capability with no record keeps a not-yet-run treatment that is
visibly distinct from a failure (matrix `v2-30`).

It also absorbs the CARRY the route has held since `2026-08-09-sut-load-envelope`. The desktop is the one
of Conductor's three report surfaces that never got the load-envelope signal, so a GUI user cannot tell an
over-envelope run from a clean one — the run reads as evidence about the SUT when it is not. The cli
caption and the Markdown banner shipped; `v2-07`'s `ref` names the Markdown test, so no shipped capability
covers the webview leg. Both halves land on one surface and are proved by one `--e2e` leg, which is why
they ride one chunk.

The join must go through `lampForRecord` — verdict-first, never a `state`-only switch (per architecture.md
§Established Decisions [Probabilistic-Assertion Policy] + a11y-plan.md §6 State-naming crosswalk). The
envelope must be READ from its persisted `run_envelope` standing rather than re-derived, so the GUI cannot
diverge from the cli caption and the Markdown banner, which share one basis (per architecture.md §Occupied
Resources — `contracts/pulse-load-envelope.toml`). Neither half widens a closed set: `ReportState` stays
five, `LAMP_META` stays six, the envelope stays a run-level qualifier outside the lamp column (per
layout-templates.md §Component — Primary content block 2 + design-system.md §Surface: cli / Tokens).
