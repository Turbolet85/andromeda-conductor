## Goal

Make the shipped desktop-webview specs actually run on this host, under agent drive, through the real Tauri
window — and record the measurement that says they can. Every downstream verification surface in Epochs 5
and 6 (the a11y sweep, the verdict lamps, the screen-reader spec, the CI gate) is currently aimed at a
Linux+xvfb runner that does not exist and is not planned, because the operator ruled this host Windows-only
on 2026-08-22 and made agent-driven GUI verification the default.

P3 measured the premise that framing rested on and found it **false**. A Windows x64 `tauri-driver` prebuilt
(`tauri-driver.win32-x64-msvc.node`, 4,030,976 bytes) has been installed since the 2026-06-27 harness chunk,
runs at exit 0, and advertises `--native-driver PATH`; the operator's host carries a matching
`msedgedriver` (Microsoft Edge WebDriver **151.0.4129.101**) against a WebView2 Runtime at
**151.0.4129.107 / .78** — same major *and* build. The five specs in `test/a11y/accessibility.e2e.ts`
already drive real `Escape`/`Space` keypresses, a focus trap, axe and token contrast. Nothing needs
authoring and no platform blocks the path.

What blocks it is three ordinary defects: `wdio.conf.ts` spawns the bare name `tauri-driver`, which PATH
cannot resolve here; it passes no native driver, which Windows requires; and its own header declares the
config unrunnable on this host. Alongside those, `agent-run.{sh,ps1}`'s `--e2e` selector runs
`cargo nextest -p conductor-cli` where test-plan §3 (`:152`) and §9 (`:456`) both define it as *the
tauri-driver `wdio run` leg* — so the chunk also closes a code-vs-spec divergence rather than inventing a
stage. Per arch §Design Philosophy the result stays an **operator/local gate**: the GUI never becomes the
release gate, and per a11y-plan §11 this chunk claims **no WCAG conformance** — a green session proves the
window is drivable, not that it is conformant.

## Constraints & rejected approaches

- **Committing the operator's absolute driver path into `wdio.conf.ts` — REJECTED.** It would place a
  host-specific absolute path in a committed artifact and break on any other machine; the `CONDUCTOR_*` env
  handle is the reserved mechanism (architecture.md §Occupied Resources — Environment variables).
- **A network fetch inside the verification leg — REJECTED (operator-resolved 2026-09-01).** The host
  already has a driver, so the chunk reuses it and adds no acquisition machinery; auto-fetch survives only
  as the RECIPE printed by the skip arm, with its Edge-vs-WebView2 keying nuance named. A verification leg
  that downloads a binary makes its own result depend on a CDN and on a version-matching assumption that is
  currently false on this host.
- **Failing hard when the driver is absent — REJECTED (operator-resolved 2026-09-01).** Unset or
  not-a-file skips at exit 0 with the recipe, mirroring the proven guard shape; a hard failure would make
  an unconfigured host indistinguishable from a genuine defect.
- **A puppeteer/CDP or second WebDriver stack to attach on Windows — REJECTED.** a11y-plan §11 (CI) bans it
  outright; the whole point is one session that `@axe-core/webdriverio` can inject into.
- **Making the GUI bundle a precondition of the headless release path — REJECTED.** The headless
  `agent-run` path is the release gate and the GUI is convenience (architecture.md §Design Philosophy;
  §Established Decisions [Deployment]).
- **Adding the headful leg to the CI build+test job — REJECTED.** Host-bound dynamic proof is an
  operator/local gate (architecture.md §Established Decisions [CI/CD]); the a11y CI gate is v2-24's, and it
  is `BLOCKED-ON: a Linux runner`.
- **Relaxing a webview guardrail to make the window drivable — REJECTED.** No re-enabled context menu or
  devtools, no remote-origin iframe, no unscoped `shell-open`, no new Tauri capability
  (security-plan §Security Anti-Patterns → Code Patterns; layout-templates §IA notes). The shipped
  `capabilities/default.json` already allows exactly three window permissions and needs no change.
- **`sleep(N)` synchronization or xpath/hashed-class selectors — REJECTED**, and no retry policy may be
  introduced to make a flaky leg pass (test-plan §11 E2E; §10 Zero-flakiness budget).
- **Claiming WCAG conformance from a green session — REJECTED** (a11y-plan §11 Strategy/Universal).

## Implementation notes

- **Order sensitivity is the main trap.** `npm run build` → `cargo build --release -p conductor-tauri` →
  drive. A debug binary loads `devUrl` (`localhost:5173`) and will open on `ERR_CONNECTION_REFUSED` without
  a Vite server; only a release build reads `frontendDist` (verification-harness.md 2026-08-22 (b)).
- **In PowerShell, use `scripts/agent-run.ps1`** — `bash` there resolves to the WSL relay and dies with
  `execvpe(/bin/bash) failed` (verification-harness.md 2026-08-22 (c)).
- **This leg needs no live Pulse.** It drives Conductor's own window; the live-Pulse a11y sweep is v2-22's.
  Do not pair it with `boot` (verification-harness.md 2026-08-19 (a)).
- **A `[BLOCKED]`-in-~0s result is a resolution failure, not a SUT verdict** — check driver resolution first
  (verification-harness.md 2026-08-20).
- **The Edge-vs-WebView2 version divergence is REAL on this host, not hypothetical — measured 2026-09-01.**
  The `edgedriver` npm package keys its download on the **Edge browser** version, but the driver must match
  the **WebView2 Runtime** that Tauri actually embeds. On this host those have separated by a full major:
  `Edge/Application` carries `152.0.4191.53` (installed 2026-08-29) beside `151.0.4129.78`, while
  `EdgeWebView/Application` carries only `151.0.4129.107` (2026-08-26) and `151.0.4129.78`. An auto-fetch
  would therefore acquire a **152** driver for a **151** runtime. The host binary the chunk reuses is
  `151.0.4129.101` — matching WebView2's major *and* build (151/4129). This is precisely why REUSE beats
  fetch here, and why the skip message must state the nuance rather than presenting auto-fetch as turnkey:
  **verify the runtime version at fetch time; do not assume Edge's version speaks for it.**
- **Measured but out of scope:** all 7 `#[tauri::command]` sites (`commands.rs` · `main.rs` · `pause.rs`)
  carry **zero** `#[tracing::instrument]`, against obs-plan §4's requirement of a `tauri.command.*` handler
  span with `run_id` correlation. It does not block this chunk (the specs assert DOM state, not logs), and
  closing it is a code change outside this scope — surface it to the operator as a route candidate rather
  than absorbing it here.

- **Source-side twin of the CARRY is executed by step 9, not by the amendment flow.** The
  `crates/conductor-run/tests/lifecycle_harvest.rs:23` module doc restates the over-scoped claim, and no
