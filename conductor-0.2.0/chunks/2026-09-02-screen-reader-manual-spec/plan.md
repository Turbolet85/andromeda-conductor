## Goal
Author the per-state screen-reader pass spec the a11y plan has required since its first draft (a11y-plan §3
_Screen reader test pattern_ + §3 Bootstrap `screen-reader-test-spec-setup`) and record ONE NVDA pass against
it on this Windows / WebView2 host — the judgment-class sibling of the automated sweep `v2-22`. The spec
enumerates, for each of the four run states the shipped webview actually renders (`idle` — including its
report-populated sub-state — `live`, `hold`, `aborted`; research.md §Scope premise closure 1), every
must-announce item as a row: the producing action, the carrying node (role · accessible name · live-region
mechanism), the expected NVDA output, the WCAG SC it evidences, and the result. The pass is supplemental to
the axe / colorjs.io / WebdriverIO baseline and claims no WCAG conformance (a11y-plan §2, §11 Universal).

**The pass is agent-driven, with zero new dependencies; the operator reviews** (operator relay, 2026-09-02;
scope.md §Re-shape). NVDA 2026.2 is present on this host as a portable copy, and its own speech log records
every utterance sent to the synthesizer (`-l 12`). So the leg the harness already owns — one WebdriverIO +
tauri-driver session against the release bundle, the driven arm's live-Pulse form — drives the states while
NVDA logs what it would speak, and `evidence/nvda-pass.json` is produced by the leg from that log and the
leg's own action timeline, never by hand. The operator's role is REVIEW of the evidence, done remotely, and
the review is recorded in it. Two things are measured at implement rather than assumed: whether NVDA attaches
to the WebView2 window while WebDriver holds the session, and which rows the driver's injected keys can make
NVDA speak (focus and live-region rows should; browse-mode reading rows may not — research.md §Addendum). Any
row the agent arm cannot produce falls to the documented fallback, the operator's manual pass, and the
evidence records which ARM produced every row.

The spec names what SHIPS. Research measured four places where the three UI masters describe target state the
release bundle does not have — the a11y-plan's four-state naming (no `aborted`; a `report-terminal` that is
idle with a report), the operator checklist's second render site (only the dialog site ships), the footer /
`contentinfo` landmark (absent), the dialog title shape — plus must-announce prose whose shipped strings
differ from the plan's. Each becomes a spec row recorded against the shipped DOM and a finding for wrap; none
is fixed here (scope §Boundaries — a recorded pass, not a green one). Research also falsified the a11y-plan's
stated reason the pass is manual: an NVDA automation library exists on npm. It stays rejected here (NVDA's
built-in log suffices — no dependency delta) and rides wrap's route-resolve as a route candidate.

The harness is EXTENDED, never relaxed (the `v2-22` clause; F14 forbids re-authoring, not extension): three
`sr*` suites over the ONE stack, one new spec, one node-built-ins parser, one host-tool env handle guarded
exactly like `CONDUCTOR_MSEDGEDRIVER`, NVDA start / quit bracketing the driver, and per-suite subject env at
the one spawn site. The routine arm's spec set, both existing specs and both dependency trees are untouched.

## Constraints & rejected approaches
- **Guidepup or any SR driver package — rejected.** `@guidepup/guidepup` 0.34.0 exists and is maintained, but
  NVDA's built-in speech log suffices with zero new dependencies; a package would be a second automation
  stack (architecture §Scope law, test-plan §6, a11y-plan §11) and a dependency delta under the standing
  advisory-DB deferral (security-plan §Dependency Security). By operator ruling it is surfaced at wrap's
  route-resolve as a ROUTE CANDIDATE — see ## Implementation notes.
- **A manual operator pass as the DEFAULT — rejected (it was v1's shape).** The standing default is
  agent-driven wherever a driver exists; the manual pass is the documented FALLBACK, per row, with the arm
  recorded.
- **Hand-written heard values — banned.** The parser assigns utterances by timestamp from NVDA's own log;
  an unrun row is `not-run-here` with its reason (the identity-only Blocked-row precedent).
- **Fixing the not-announced findings in-chunk — rejected as the default.** The acceptance is a recorded pass;
  a remedy is a route entry. The three candidates (a `status` role on the lamp or its cell; an accessible
  name on the titlebar count; a `contentinfo` footer) stay an operator pull-in option.
- **Per-row VoiceOver / Orca columns — rejected.** No macOS / Linux surface exists on this host.
- **Running `agent-run boot` before the leg — rejected.** Its canary primes the incident the app's own
  preflight dedupes against (measured 2026-09-01: two 12-minute runs lost).
- **The full catalog as the live subject — rejected.** The hold sits ~76 minutes deep in sorted order; the
  trimmed repo-relative dir puts it at count 0 (verification-harness 2026-08-19 / 2026-08-22).
- **A debug or bare `--release` binary — rejected.** Both open `devUrl`; only `--features tauri/custom-protocol`
  serves the bundle.
- **A single-scenario live subject — rejected for `aborted`.** `drive_run` polls the abort flag only between
  scenarios.
- **Touching the routine spec set, either existing spec, any `.rs` / `.tsx`, or any `.andromeda/` master —
  banned** unless the operator pulls a remedy in (then the touched `.tsx` re-runs `npm run build` + the
  routine arm).
- **Passing `CONDUCTOR_NVDA` or the log path through a shell string — banned.** Array-form spawn, separate
  argv elements, the `nativeDriver()` guard shape.

## Implementation notes
- **NVDA wording is version-bound.** The parser grades on REQUIRED TOKENS (the name, the state word, the
  text), not on NVDA's connective phrasing; the operator's review is the judgment over the graded rows.
- **The assertive titlebar region announces changes, not initial content.** On launch nothing is announced
  from it; the S0 label row is `browse`, the S1 / S2 / S3 label rows are the announced transitions. Do not
  record the launch silence as a defect — but a silent log through the S0 `focus` rows (the picker, the
  buttons) IS the attach failure signal (`attach_observed: false`).
- **Interrupt ordering at the hold.** The label flips to `HOLD — operator pause` (assertive) and the dialog
  opens in the same tick; NVDA may speak either first. Both `announced-as-expected` if both are present in the
  row window; the parser assigns by timestamp, so the two rows are stamped as one window and split by token.
- **Focus-restore target.** The hold arrives on a Channel with focus wherever the driver left it; the spec
  activates `Start` by keyboard so the restore row can expect `Start`.
- **The count is a scenario counter, not a clock** (`RunEvent.count`); `00:00:00` is the idle placeholder.
- **Two holds, two resolutions.** Hold #1 (`halo-hue-encoding`) is resolved with Enter on `Proceed` after a
  Space toggle; hold #2 (`halo-breathing-encoding`, reached even after `Stop` because the abort is polled
  between scenarios) with Escape — so both resolution paths are captured in one session.
- **Sessions order.** `sr-empty` → `sr-error` → `sr`: the no-run subjects warm NVDA up and fire no canary; the
  live subject fires exactly one. A second live session needs ≥150 s of quiet.
- **Latent flake closed in passing (operator finding at the second P5 card).** Before this chunk the spawn
