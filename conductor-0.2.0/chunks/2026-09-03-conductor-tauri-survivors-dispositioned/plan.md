## Goal

The `conductor-tauri` mutation tier produced its first score at
`2026-09-02-mutation-tier-restored-for-conductor-tauri` — 43 planned, 43 tested — and deliberately
dispositioned none of its survivors, because that chunk's criterion was authored when the survivor set was
unmeasurable by construction. This chunk closes that ledger: every named survivor ends **killed** or
**classified accepted-deliberate against a cited standing rule**, with no numeric `--fail-under` and no CI
gate on the score (per test-plan §10 Mutation-survivor disposition, §9 Scoped mutation audit).

The work is entirely test-side. Research measured that the survivors are not a scattering of weak
assertions but four distinct mechanisms, and each has a different remedy. The **parameterised helpers**
(`resolve_handle`, `resolve_selection`, `load_all`, `list_scenarios_impl`) take their base path or default
as an argument, so both arms are reachable with no staged repo root and no `unsafe { set_var }` — the
scope's inherited hypothesis that a staged root was required is falsified. The **run-data commands** are
tested at exactly their empty case, which is the mutants' own return value; their traversal-guard arm makes
correct code return `Err` where every mutant returns `Ok`, killing them with no fixture at all. The three
**`pause.rs` timeouts** are a hang, not a blind spot — two shipped tests block forever on a oneshot the
mutant never fires, so bounding those awaits converts timeout → caught. And `main.rs` carries **no test
module at all**, which is why all three of its mutants survive.

Six survivors sit in the security-plan §Input Validation forbidden domain and are killed, never accepted:
`resolve_handle:38` is the `resolve_under` traversal guard, `scenarios_dir:44` / `runs_dir:48` /
`manifest_path:52` are its three callers, and `run_report:168` / `run_envelope:224` are the `run_id`-class
commands the same row governs (per security-plan §Input Validation `:123`). Three survivors are
accepted-deliberate against cited rules. Production code is unchanged.

## Constraints & rejected approaches

- **Rejected: a seeded runs dir for the run-data commands' populated arm.** `run_report` / `run_envelope`
  resolve through `runs_dir()`, whose base is the process CWD (the crate dir under `cargo test`), and
  `resolve_under` rejects both absolute candidates and `..` — so a `TempDir` cannot be reached, and pointing
  the handle at a crate-relative fixture would need `unsafe { std::env::set_var }`, which edition 2024 makes
  unsafe precisely because it races (`.claude/rules/testing.md:67`; test-plan §10 zero-flakiness). The
  traversal-guard arm kills both mutants with no fixture at all. The populated arm is already covered
  elsewhere by `envelope_fixture.rs::the_persisted_standing_round_trips_through_the_production_reader` and
  the `--e2e` arm.
- **Rejected: adding `assert_fs` to `conductor-tauri`'s dev-deps.** With the fixture read-only and no temp
  dir needed, it buys nothing, and it would be a package-level dependency delta under a red audit.
- **Rejected: extracting `build_app()` from `main` to make the wiring killable.** It would not kill
  `main:18` — the mutant removes the call too — so it trades a production refactor for no disposition change.
  Considered and declined at P4 with the operator.
- **Do not relax the guard to kill a guard mutant.** Clamping an absolute or `..` candidate instead of
  rejecting it would satisfy a weaker test while violating security-plan §Input Validation `:123`.
- **Do not add a `#[tauri::command]` or widen the capabilities file** to make a survivor observable
  (security-plan §Security Anti-Patterns → Code Patterns).
- **Do not introduce a numeric mutation threshold, `--fail-under`, or a CI stage for the tier** — the score
  moves as a consequence of dispositioning named survivors and is never itself the acceptance (test-plan §10).
- **Do not change production behavior.** A survivor killable only by changing production code is a finding to
  surface, not a licence to refactor.

## Implementation notes

- **Read the tallies from the artifact, not the exit code.** `cargo mutants` has measured **exit 3** on a run
  that fully met its acceptance; and because it always creates `mutants.out/` *inside* `--output`, a
  pre-existing output dir yields a stale, plausibly-clean tally (`.claude/rules/testing.md:77`). Use the fresh
  directory named in Test Commands.
- **Expect the headline to read 21 or 22.** `pause.rs:85 TauriResolver::kind -> "xyzzy"` classified missed on
  one run and unviable on another over an identical tree; its sibling `-> ""` was missed on both. One
  disposition unit, two mutants.
- **`invoke` panics on a dispatch error.** The existing helper (`commands.rs:385`) unwraps; the traversal-arm
  tests need a sibling that returns the error response instead.
- **`start_run` needs two `Channel` arguments through the IPC body.** Keep its assertion on the early-return
  error path so no background thread is spawned; if constructing the channels through `InvokeRequest` proves
  impractical, `start_run:260` falls back to the same accepted-deliberate citation as `:263:8` — record which
  actually happened rather than reporting a kill.
- **Order matters for the tier re-run:** it must run *after* the unit gates are green, since cargo-mutants
  requires a passing unmutated baseline and reports `cargo test failed in an unmutated tree` otherwise.
- **`ui/dist` must exist before any workspace cargo build that compiles `conductor-tauri`** —
