## Goal

Give the loop a **non-mutating, non-priming precondition probe** over the live-Pulse toolchain, so an absent
SUT is named once at scheduling time instead of being rediscovered and absorbed by each chunk, gate and wrap
in turn. The Epoch-5 diagnosis counted five in-epoch instances of that absorption plus four more in Epoch 4
(one a soft-exit), and every instance was *correct* per-instance behaviour — which is exactly why it never
halted and never accumulated a visible cost.

The probe answers three subjects and reports them: `127.0.0.1:4317` reachable, `andromeda-pulse-mcp`
resolvable on the inherited `PATH`, and the three `ANDROMEDA_PULSE_*` handles declared in Conductor's own
environment. It **reports and never launches** (Conductor does no Pulse process management by scope law), it
**binds nothing** (`:4317` is contacted as a client only — per architecture.md §Occupied Resources — Ports
and security-plan.md §Threat Model Summary), and it **must not be, or invoke, `conductor preflight` /
`agent-run boot`**, because preflight fires its own canary storm and Pulse dedupes against any open incident
on the `(kind, scope, scope_id)` tuple — a `boot` used as a cheap go/no-go primes exactly the state the
following leg collides with, measured at two 12-minute runs lost (`verification-harness.md:53(a)`, extended
2026-09-01).

Research settled the shape. `probe_egress` already *is* subject 1 (connect-and-drop, no export, `Err` on
refusal) and its own doc assigns the remainder to this chunk: *"orchestrating the gate into a run is the
CLI's job."* Core's `RunContract::evaluate` already demonstrates the mandated env-sourced-gate shape — a pure
function of injected values with the environment read at the caller (per testing.md:67), which the probe
extends rather than reinvents. Two operator rulings fix the rest: the probe owns subjects 1+2 itself while
the contract gains **one** `ShellDeclaration` term for the genuinely-missing `ANDROMEDA_PULSE_MCP_ENABLED`
handle; and the probe ships **both** as a standalone `conductor` verb and as `boot`'s leading short-circuit
arm — the shipped arch precedent (the fifth named precondition already sits before the canary arms and skips
the poll rather than paying it) applied one rung earlier.

## Constraints & rejected approaches
- **Rejected — building the probe on `conductor preflight` / `agent-run boot`.** Preflight fires its own canary storm and Pulse dedupes on the `(kind, scope, scope_id)` tuple, so a probe built on it primes the state the next leg collides with; measured cost two 12-minute runs (`verification-harness.md:53(a)`). The probe reuses core's pure `evaluate` seam, never `canary_gate`.
- **Rejected — spawning the sidecar to test resolvability.** `Command::new(PULSE_MCP_PROGRAM)` carries no creation flags at HEAD, so a spawn opens the measured console-pane host-path disclosure channel. A `PATH` lookup answers the same question with no process.
- **Rejected — the `which` crate.** ~15 lines of `std::env::split_paths` answers it; adding a dependency under the standing red-audit deferral would oblige a fresh `cargo deny` verification over a new `Cargo.lock` and retire "no dependency delta" as the deferral basis, for no gain (per security-plan.md §Dependency Security).
- **Rejected — a new `CheckKind` for live host observations, and re-classifying `sidecar-built`.** Operator-selected at P4: it threads a new kind through `evaluate`/`observed_env` and the fifth named precondition string, and puts Conductor's own measurements into an artifact whose `provenance` field scopes itself to a transcribed SUT record. - **Rejected — a 6th `agent-run` command.** `verification-harness.md:24` forbids it without a test-plan amendment, which phase cannot author. `boot` gains a leading arm instead; the count stays five.
- **Do not** mint a new bracket label, lamp state, `ReportState` variant, palette row or ANSI entry; **do not** emit a `[BLOCKED]` per-P-ID row for a scenario that was never run.
- **Do not** read the environment inside the evaluator — every input arrives as a value, so no test needs `unsafe { set_var }` (per testing.md:67).

## Implementation notes
- **Order sensitivity:** step 1 (the pure evaluator) before step 4 (the observation site), and step 6 (the contract term) before the set-equality pin in step 10 — otherwise the pin fails on the term it is meant to cover.
- **The `sidecar-built` term is knowingly left standing.** Its `causes` reads "reaching term evaluation at all proves it", which measurement contradicts: a `PATH` miss short-circuits to `[BLOCKED]` in ~0 s *upstream* of term evaluation, so the term is satisfied by construction exactly when it is false — the same failure shape already recorded for `warmup_ms`. Operator-selected to surface rather than silently re-classify, because re-classifying moves what the preflight gate can block on.
- **Read every gate's exit from the bare command.** `cmd | head` / `| tail` reports the pipe's last stage; redirect to a file and inspect the file (host-win32).
- **A green exit is not evidence on its own** — `verification-harness.md:58` records that a guard designed to skip at exit 0 makes the exit code unable to distinguish a pass from a total skip, and testing.md:74 that a gate's failure must say WHAT it observed. The probe therefore prints every subject's state, not a count, on both the satisfied and unsatisfied paths.
