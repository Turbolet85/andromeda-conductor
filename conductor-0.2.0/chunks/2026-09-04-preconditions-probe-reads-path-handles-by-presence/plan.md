## Goal

`conductor preconditions` cannot exit 0 under any environment, however correct. Its `handles-declared`
subject grades all three `ANDROMEDA_PULSE_*` names through one truthy-only predicate, and one of them —
`ANDROMEDA_PULSE_DATA_DIR` — carries a **path**, not a flag, so it can never declare. Because
`agent-run boot` runs the probe as a leading short-circuit arm, **no environment has reached the MCP
preflight through `boot` since `480bc66`** (measured 2026-09-04T06:41Z: `egress-reachable` and
`sidecar-resolvable` both satisfied, `handles-declared` unmet naming `DATA_DIR` alone, exit 1, with a child
process independently confirmed to receive the value intact).

This chunk grades each handle by the **kind of value it carries** — presence for the path handle,
affirmative truthiness for the two flags — so the subject becomes satisfiable and `boot` reaches the gate.
architecture.md §Standard Contracts (Liveness equivalent) states this fix in exactly those terms and names it
route-owned; security-plan.md §Security Anti-Patterns → Universal carries the withdrawn "not a downgrade"
bullet naming the same remedy. The change is confined to how the observation is BUILT: the pure evaluator
(`Preconditions::evaluate`) and its ten tests are correct and stay untouched.

Two constraints shape the design more than the fix itself. First, `declares()` has a **second caller** —
`observe_run_contract` (`lib.rs:350`), grading the run contract's `shell-declaration` terms over a narrower,
**flag-only** set where truthiness is correct — so loosening the shared predicate would silently widen a
preflight gate, which security-plan §Input Validation bans outright. `declares()` is therefore left byte-
unchanged and the probe gets its own grading path. Second, the env read must stay at the caller with the
graded value passed in (`.claude/rules/testing.md` 2026-08-10), so the new predicate is pure and both arms
are reachable with no `unsafe { set_var }` — the shape `conductor_verify::sidecar_resolves_on_path` /
`resolves_on` (`spawn.rs:98-123`) already ships, whose doc comment names this exact rationale.

1. **Add TWO pure predicates to `conductor-core/src/preconditions.rs`, beside `OBSERVED_HANDLES`**
   (operator-selected placement; architecture.md §Occupied Resources sanctions core or run, and core wins
   because `OBSERVED_HANDLES` is already pinned there by exact-set equality — a handle added to the list in
   core would otherwise be graded by a fallback in another crate that no gate sees). Both take
   already-read values and read no environment, no filesystem, no socket — the module's stated purity
   property must survive this chunk. The split into two is load-bearing, per step 5:
   - **`flag_declared(value: Option<&str>) -> bool`** — the affirmative-truthiness rule, taking a value and
     **no name**: true when the trimmed, lowercased value equals `"true"` or `"1"`. This becomes the single
     definition of truthiness in the workspace.
   - **`handle_declared(name: &str, value: Option<&str>) -> bool`** — the per-handle dispatch: the
     PATH-valued `ANDROMEDA_PULSE_DATA_DIR` is declared when its value is present and **non-empty after
     trim** (`declares` already trims, and an empty or whitespace-only data-dir cannot satisfy the
     precondition it stands for); **every other name delegates to `flag_declared`**.
2. **An explicit `false` must still decline.** Because the two flag handles route through `flag_declared`,
   `ANDROMEDA_PULSE_L4_DETERMINISTIC=false` / `ANDROMEDA_PULSE_MCP_ENABLED=false` still declare the opposite
   of the term they would otherwise satisfy (security-plan §Threat Model Summary → Auth model). This is the
   property the non-widening witness in Acceptance Criteria pins.
3. **Grade an unknown name by the FLAG rule, never by presence.** `handle_declared` is total, and its

## Constraints & rejected approaches
- **Loosening `declares()`'s RULE — REJECTED; delegating it is what ships.** Making `declares` itself
  presence-tolerant, or routing it through the name-keyed `handle_declared`, would let a path-valued
  run-contract term be satisfied by mere presence — a silent gate widening security-plan §Security
  Anti-Patterns → Universal bans. Step 5 does something different: `declares` keeps the truthiness rule
  exactly, delegating it to `flag_declared`, which takes a value and no name and therefore cannot reach the
  presence arm. Semantics move, they do not weaken; the non-widening witness is what proves it.
- **Duplicating the truthiness rule in the new core predicate — REJECTED.** An earlier draft froze
  `declares()` and re-implemented `== "true" || == "1"` in core. Two copies of one rule can drift, and the
  freeze also made this plan self-contradictory: all four accepted `declares` mutants live on the frozen
  line (`:360:11/21/26` are its `==`/`||`, `:358:5` its body), so the roster could not have shrunk while
  step 8 claimed it would. Caught at review; one rule, delegated.
- **`unsafe { std::env::set_var }` to reach the env read in a test — REJECTED.** `.claude/rules/testing.md`
  (2026-08-10) prescribes reading env at the caller and passing a typed value; the arms it forecloses are
  exactly the four currently classified accepted-deliberate, and killing them by env mutation would
  reintroduce the hazard the rule was minted to remove.
- **Changing `OBSERVED_HANDLES`'s TYPE to carry the kind — REJECTED.** It has 12 ref sites across two
  crates and a both-directions pin test; a sibling predicate adds the kind without moving any of them.
- **Grading an unknown handle by presence — REJECTED.** It would make a future handle satisfiable by mere
  existence, the silent-widen class security-plan §Input Validation forbids. Unknown names take the flag rule.
- **Proving the `boot` reach with a stand-in listener on `:4317` — REJECTED.** `:4317` is reserved for the
  port-occupier fault (`.claude/rules/testing.md` 2026-06-17 bans binding it in a test), and a faked
  sidecar on `PATH` would be spawned by the preflight that follows. The honest witness is a live leg.
- **Do NOT treat a `ready:false` boot as a failed criterion.** The criterion is that the preflight RAN;
  `verification-harness.md:45` makes `ready:false` the by-design outcome whenever the gate's own
  preconditions are unmet.
