## Goal

Close the last measured host-path disclosure channel in Conductor's shipped binaries. The MCP sidecar
spawn builds `Command::new(PULSE_MCP_PROGRAM)` with no creation flags (`conductor-verify/src/spawn.rs:81`),
so on Windows a console-subsystem child gets its own terminal pane — titled with the sidecar's ABSOLUTE exe
path — which seizes the OS foreground ~200 ms after `Start`. Two harms, one fix: a keyboard or screen-reader
user loses focus to a window they did not open, and the pane's title publishes a host path that sits outside
`sanitize_error`, the tracing field allowlist and the artifact-hygiene edge alike. The duty is written into
security-plan §Security Anti-Patterns → Code Patterns rule (a) and restated at obs-plan §11 (twice), all
three recording it as route-owned and **not yet shipped**.

The fix is one builder call under `#[cfg(windows)]`, in the shared seam crate so the headless release-gate
path gets it and not just the GUI (per architecture §Design Philosophy "Headless-drivable core, thin shells").
Everything else about the spawn is mandated unchanged — fixed program NAME through the inherited `PATH`,
`ANDROMEDA_PULSE_DATA_DIR` via `.env(...)` only after metacharacter rejection, and the child's piped stdio as
the JSON-RPC read-back transport (per architecture §Established Decisions [MCP Read-Back Client]).

Beside the fix the chunk discharges four CARRYs it inherited and re-measures the SR leg the defect was found
on. Two of those CARRYs are corrections to claims the repo makes about itself; one is a build-config guard
that bounds this chunk's own edit churn; the fourth is an open investigation whose mechanism is not yet
identified, planned here as **measure-then-fix-or-record**, never as a promised fix.
