## Goal

Give Conductor ONE named, re-runnable, operator-gated invocation that fires the live-Pulse proof legs in a single
correct shape and lands a durable evidence record — so a live proof stops being a hand-assembled paste of env
blocks whose partial forms fail silently as a ~0s `[BLOCKED]` indistinguishable from a genuine SUT-side gate
failure (research.md §Conventions; verification-harness 2026-08-20/2026-08-22). Today that surface is scattered
across **six firing-form families / eight invocations** with different env blocks, orderings and evidence
destinations. The suite composes them behind `agent-run run --live`, shipped at identical semantics in both
shells, and it is **never a CI gate** (per test-plan §9 + architecture.md §Established Decisions [CI/CD], one
rule with two homes).

Second, it buys behavioural coverage the mutation tier structurally cannot. Three `conductor-run` survivors are
accepted-deliberate because no hermetic test can reach their sites — a fixed `http://127.0.0.1:4317` endpoint
const, a crate-private `Preflight`, a `PATH`-resolved sidecar absent on a hermetic host (all three re-derived at
HEAD, research.md §Scope premise closure) — but their OBSERVABLES are live-path facts a driven run can assert
from persisted records. Landing them does **not** retire the tier acceptances: the mutants stay
accepted-deliberate and test-plan §12's roster is untouched by this chunk.

The chunk claims **no capability**. Each of the six pooled matrix entries is owned by a different route entry
(see §Implementation notes); nothing here makes any of them fully verifiable.

## Implementation Steps

1. **Add the `--live` stage flag to `agent-run run`, in `scripts/agent-run.sh`.** It is a STAGE FLAG under the
   existing `run` verb beside `--unit` / `--integration` / `--e2e`, never a sixth command — the 5-command
   discipline forbids a sixth without a test-plan amendment (per test-plan §3; verification-harness "Do not add
   a 6th command"). It must not be reachable from `run` with no flag, so a bare `agent-run run` (the CI gate)
   never fires a live leg.

2. **Make the leading arm the shipped `conductor preconditions` probe, not a new one.** `--live` invokes the
   existing verb first and short-circuits on a genuinely unmet subject, printing the `[PRECONDITION]` unmet arm
   — one line per unmet subject naming its statement and candidate causes, host-path-free (per layout-templates
   §Surface: cli `conductor preconditions [--json]`; design-system §Surface: cli / Tokens). It is the correct
   probe because it is non-mutating and **fires no canary**, so it primes none of the state the legs then
   collide with. Do not mint a second precondition report shape and do not add a seventh bracket label.

3. **Refuse on a partial env rather than proceeding.** A short-circuit exits non-zero with the named subjects;
   it never degrades to a silent `[BLOCKED]` row and never writes a run record. Conductor must NOT materialize
   a missing handle: `ANDROMEDA_PULSE_*` are READ-only to Conductor (per architecture.md §Occupied Resources —
   Environment variables). Distinguish the two classes explicitly — an absent HOST-TOOL handle
   (`CONDUCTOR_MSEDGEDRIVER`, `CONDUCTOR_NVDA`) SKIPS its own leg at exit 0 with a fetch recipe naming the
   handle, never its value (per a11y-plan §3 / §9), while an incomplete live-Pulse env REFUSES the suite.

4. **Add the purpose-built silent scenario `scenarios/auto-resolve-idle-window.toml`.** The mechanism observable
   1 depends on is **measured, not derived**: `observe` (`crates/conductor-verify/src/extract.rs:76`) calls
   `query_incident_list(None)` with **no filter** and returns `EmptyCorpus` only when `incident_ids` is empty,
   while the run's own preflight canary incident stays open until Pulse auto-resolves it (120s idle + a 30s
   tick — Pulse's `DEFAULT_INCIDENT_AUTO_RESOLVE_WINDOW_SECS = 120`,
   `andromeda-pulse crates/triage/src/incident/persistence.rs:42`). The live proof is leg E of 2026-08-21,
   pinned at `crates/conductor-run/tests/severity_harvest.rs:505-513`: an `ack-cooldown` run (370s of phases,
   **no emission tables at all**) emits no incident-forming stimulus, so the only incident is the preflight
   canary's, it auto-resolves 120s + a tick later, the 370s scenario outlasts it, and read-back finds an empty
   active list → `AutoResolved`.
   **So reuse is REACHABLE, and the bound is per-scenario, not universal:** the SHORT declare-only scenarios
   (2–75s of phases) read back well inside the canary incident's idle window and yield `Graded` →
   `manual_record` → `ManualCheck`, never `AutoResolved`; `ack-cooldown` at 370s does reach it. The new
   scenario is chosen over reusing `ack-cooldown` for two reasons, neither of them reachability: **wall clock**
   (165s roughly halves leg A against 370s) and **declared intent** (a scenario whose stated purpose is the
   idle window, rather than one whose P-023 cool-down semantics are incidental to this use). The new scenario
   is ONE silent phase long enough for the
   canary's own incident to auto-resolve before read-back: `p_ids = ["P-022"]` (Pulse's auto-resolution
   capability, already classified and already backed by `incident-auto-resolution`), `slo_tier = "<90s"`, zero
   `[[expected]]` blocks (declare-only), and a single phase with `gap_ms = 165000` and
   `[phases.emission] kind = "plain", occurrences = 0` — the exact silence-window shape
   `scenarios/incident-auto-resolution.toml`'s `wait-auto-resolve` phase already uses. A phase declaring no
   occurrences emits nothing, so the load-envelope's two sustained terms (judged per EMITTING phase) do not
   bind it.
   **The file MUST carry a `LOAD ENVELOPE` header comment**, or
   `load_envelope::tests::every_committed_scenario_points_authors_at_the_envelope`
   (`crates/conductor-core/src/load_envelope.rs:525-536`) fails: it asserts every committed scenario's text
   contains that literal string as an author-facing pointer to the envelope contract. Copy the two-line header
   the existing scenarios open with.

5. **Compose the legs in this order — it is load-bearing, and each leg's outcome is predicted.**
   - **B1 — a short declare-only leg** (`degraded-mode-report`, 2 phases × 3000ms ≈ 6s). Its canary forms an
     incident, the gate reaches ready (observable 3's ABSENT arm), and read-back finds that incident still open
     → `Graded` → `manual_record` → a row carrying `latency_ms`. **This leg is observable 2's subject.**
   - **B2 — fired IMMEDIATELY after B1**, inside the 120s window while B1's canary incident is still open. B2's
     own canary dedupes against it on the `(kind, scope, scope_id)` tuple (Pulse's dedupe path calls
     `observe_reemission`, `inference_runtime.rs:815`), no fresh incident forms, and the gate goes
     **not-ready-but-connected** — the only state that reaches `canary.rs:59`. **This leg is observable 3's
     PRESENT arm.** Its row is `Blocked`.
     **`ANDROMEDA_PULSE_L4_DETERMINISTIC=true` is LOAD-BEARING here, not just for reproducibility.** Under
     deterministic L4 the canary incident forms in ~2s (the 2026-09-04 boot measured 47s = 45s warm-up + ~2s),
     so B2's storm lands ~57s after B1's — comfortably inside the 120s window. With the real model, formation
     took ~110s (`lifecycle_live.rs` header), which would push B2's storm outside the window and silently cost
     observable 3's present arm. An env without this flag does not just make the leg slow; it makes it wrong.
   - **Quiet window ≥150s**, counted from B2's storm (≥120s idle + the 30s resolver tick).
   - **A — the silent scenario** from step 4. Its canary forms a fresh incident and the gate reaches ready
     (observable 3's ABSENT arm again); the 165s silent phase then outlasts the canary incident's idle timeout,
     so read-back finds an EMPTY active set → `EmptyCorpus` + declare-only → `AutoResolved` → `KnownResidual`
     plus the `declare-only read-back empty: no active incident outlived the emission window` self-obs line.
     **This leg is observable 1's subject.**
   - **The driven a11y arm** (`npm run a11y:driven`). No extra quiet window is needed: A's own canary incident
     has already resolved by A's read-back.
   - **CRITICAL — B2 exiting 0 with a `[BLOCKED]` row is the EXPECTED outcome, not a failure.**
     `exit_code` (`crates/conductor-cli/src/commands/mod.rs:28-34`) returns non-zero only on `Lamp::Fail`;
     every other reported state exits 0. `scripts/agent-run.sh:18` sets `set -euo pipefail`, so a non-zero B2
     would **abort the whole suite**. The assertion failure to guard is the inverse: a READY gate on B2 means
     the dedupe did not happen and observable 3's present arm was never produced.

6. **Mirror the whole flag in `scripts/agent-run.ps1` at identical semantics.** Both shells ship every verb at
   parity (per test-plan §3; layout-templates §Surface: cli). PowerShell operators cannot fall back to `bash` —
   it resolves to the WSL relay and dies with `execvpe(/bin/bash) failed` (verification-harness 2026-08-22 (a)).

7. **Freeze each leg's self-obs BEFORE the next leg runs — the sink truncates.**
   `logs/agent-latest.jsonl` is opened with `.truncate(true)` (`crates/conductor-core/src/obs.rs:108-111`, its
   doc at `:59`), so every `--agent-mode` invocation WIPES the previous leg's lines. Grading "what the legs left
   on disk" at the end would see only the last leg. After EACH leg, copy `logs/agent-latest.jsonl` into the
   chunk's `evidence/` under that leg's name — the harvest tier's frozen-lines precedent — and grade the copies.
   A per-leg `CONDUCTOR_RUNS_DIR` does **not** solve this: `agent_log_path` (`crates/conductor-cli/src/paths.rs:87-88`)
   resolves the logs dir as `runs_dir.parent()/logs`, so `runs/leg-a` and `runs/leg-b` both land in `runs/logs`.
   The per-run `runs/<run_id>.jsonl` journals and `runs.db` rows are per-run and DO survive.

8. **Add `crates/conductor-run/tests/live_suite.rs` behind the existing `live-pulse` feature.** It PRINTS its
   observations rather than asserting pinned expectations — the capture is the deliverable — exactly as
   `lifecycle_live.rs:30` states for its own pair. Reuse the feature already declared (`live-pulse = []`,
   `crates/conductor-run/Cargo.toml`); declaring no dependency keeps `Cargo.lock` byte-unchanged and the target
   off every default `nextest` / `clippy` / release path (per test-plan §9). Its module header carries the full
   one-paste firing form, as `lifecycle_live.rs` does.

9. **The artifacts come from the CLI, never from an in-process test.** `logs/agent-latest.jsonl` is written only
   when `conductor-cli`'s `main` selects the file sink — `obs_sink(agent_mode)` at
   `crates/conductor-cli/src/main.rs:26,44-45`, where `agent_mode = --agent-mode flag || CONDUCTOR_AGENT_MODE

   subscriber and produces NO such file. So the graded half reads the frozen per-leg copies from step 7 and the
   per-run journals; it must not try to mint them. Equally, `boot` writes no run artifacts at all
   (verification-harness 2026-08-16), so the producing leg is a SCENARIO leg or nothing.

10. **Capture observable 1 — the `AutoResolved` degraded route — from leg A's persisted records.** Read the
    envelope's `state` from `runs/<run_id>.jsonl` with a typed parse that DISCRIMINATES the envelope line from
    the nine-key `CheckRecord` line (a file-wide parse-to-envelope is a false negative on any run emitting check
    rows, per test-plan §3 Log format → Agent parsing). **There is no `degraded` field to read**: `RunRecord`'s
    eleven fields carry none and `degraded_mode_response` occurs nowhere under `crates/`. The discriminator is
    the state mapping — `manual_record` (`execute.rs:245-266`) sets
    `state: state_for(observation, ReportState::ManualCheck)` and `state_for` (`:233-235`) returns
    `KnownResidual` iff `observation.degraded`, so on a declare-only scenario `state == KnownResidual` ⟺
    `degraded == true`. Pair it with leg A's frozen `declare-only read-back empty: no active incident outlived
    the emission window` line (`execute.rs:92-94`), which fires only on the `AutoResolved` arm and is what
    separates that route from the degraded-read-back route B1 takes.

11. **Capture observable 2 — the manual-path latency subtraction — as a BOUNDED equality, from leg B1.** Assert
    `|latency_ms − 1000·(read_back_observed_at − journal_emitted_at in whole seconds)| < 1000` against the
    persisted envelope. It cannot be an exact equality: `conductor_core::obs::now_rfc3339` (`obs.rs:212-219`)
    formats from `d.as_secs()`, so both instants are second-truncated while `latency_ms` is millisecond-grained

    conventions). The bound still discriminates `execute.rs:136:25`'s `-` → `+` / `/` mutants, whose outputs
    miss by far more than one second. State it as a subtraction, never a sum or quotient (per obs-plan §5).

12. **Capture observable 3 — the readiness-gate self-obs line — on BOTH arms, from the frozen per-leg copies.**

13. **Add `crates/conductor-run/tests/live_suite_harvest.rs` as the graded half — with the per-leg lines pinned

15. **Size the suite's wall-clock wrapper above the real budget.** Each preflight pays a 45s warm-up

## Constraints & rejected approaches
- **Per-run canary identity — REJECTED (operator-decided at P4).** Salting the canary's `scope_id` would remove
  the `(kind, scope, scope_id)` dedupe collision by construction, but the quiet window is the recorded reliable
  shape (test-plan §6) and that same collision is the lever producing observable 3's negative arm at leg B2.
  Declining keeps shipped canary behaviour unchanged.
- **A new `conductor-cli` verb — REJECTED.** Not a member of test-plan §9's sanctioned live-leg SET (`:464`).
- **A sixth `agent-run` command — REJECTED.** The 5-command discipline forbids it; `--live` is a stage flag.
- **A per-leg `CONDUCTOR_RUNS_DIR` to separate self-obs — REJECTED, it does not work.** `agent_log_path`
  resolves the logs dir as `runs_dir.parent()/logs` (`paths.rs:87-88`), so every per-leg runs dir under `runs/`
  lands in the same `runs/logs`. Freezing a copy per leg is the working fix.
- **Reusing `ack-cooldown` for leg A — REJECTED on cost and intent, NOT on reachability.** It does reach the
  `AutoResolved` arm: 370s of phases with no emission tables, proven live at leg E on 2026-08-21
  (`severity_harvest.rs:505-513`). The purpose-built 165s scenario is chosen because it roughly halves leg A's
  wall clock and because its declared purpose IS the idle window, where `ack-cooldown`'s P-023 cool-down
  semantics would be incidental. The SHORT declare-only scenarios (2–75s) are genuinely unreachable — they read
  back inside the canary incident's idle window — so the bound is per-scenario, never a property of the family.
- **Composing the `sr*` suites — OUT OF SCOPE.** A screen-reader proof, not a live-Pulse proof; they need
  `CONDUCTOR_NVDA` plus a fifth `CONDUCTOR_SCENARIOS_DIR` handle. They keep their own npm invocations.
- **Do NOT retire or edit the accepted-deliberate mutation roster.** The three survivors stay accepted-deliberate
  and test-plan §12 is untouched — a live leg is never a CI gate, so it cannot discharge a tier acceptance.
- **Do NOT stage a row in Pulse's `corpus.db`** to induce a not-ready gate (per security-plan §Anti-Patterns →
  Data Protection). B2's dedupe produces that state through the SUT's own behaviour.
- **Do NOT set an `ANDROMEDA_PULSE_*` handle from Conductor** to complete a partial env — they are READ-only.
