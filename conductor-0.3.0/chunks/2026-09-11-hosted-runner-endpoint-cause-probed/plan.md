three named one-line probes to the `a11y` job and recording what each returns on a real CI run. The runtime-major

§Established Decisions [CI/CD] holds the cause OPEN with "a hosted-image policy or session property the leading
unmeasured candidate". This chunk is the successor measurement for exactly that candidate pair, plus the third
unmeasured one: what module the host processes actually loaded, as opposed to what EdgeUpdate reports installed.

The deliverable is **the reading, not a fix**. Every probe is diagnose-only (`continue-on-error: true`, exits 0
whatever it finds) and cannot decide the job's verdict — the posture test-plan §9's E2E row and a11y-plan §11 (CI)
both require, and the shape the job's four existing diagnostics already take. A probe that returns nothing is
recorded as having returned nothing; a reading that contradicts the expected cause is recorded unchanged.

The probes live in a **repo script the workflow calls** (operator-selected at the P4 fork), not inline. The reason
is `v3-01`'s second acceptance half: the readings must be "sufficient to decide whether the endpoint failure is
remediable or permanent", which a CI reading alone cannot do — it needs a dev-host control to compare against. A
script produces both readings from the same code, so the control is measured rather than hand-approximated.
Precedent exists in this workflow: `ci.yml` already calls `.\scripts\agent-run.ps1` at `:80` and `:375`.

## Implementation Steps

1. **Create `scripts/webview2-cause-probe.ps1`** — a read-only PowerShell probe printing three labelled sections
   and nothing else. It takes one optional `-OutFile` parameter (a project-root-relative path); when given it
   writes the same text there as well as to stdout. It **always exits 0**, including on an access error.
   - **(1) policy state** — `Test-Path` + `Get-ItemProperty` over the Edge / EdgeUpdate / EdgeWebView policy keys
     in both the machine and user hives. For each key print either `present … value-names: {N}` or `ABSENT`.
     Print the *names* of any values found, never their contents — a policy value can itself be a path.
   - **(2) loaded module versions** — `Get-Process` + `.Modules` over `msedgewebview2`, reporting each matching
     module's `ModuleName` and `FileVersionInfo.FileVersion`. `.Modules` can throw Access Denied for a process
     owned by another account: catch it and print `ACCESS DENIED` as the reading. Report `no live process` when
     none is running. Print module NAMES and versions only, never `FileName`.
   - **(3) session identity** — `[System.Diagnostics.Process]::GetCurrentProcess().SessionId`,
     `[Environment]::UserInteractive`, and `[Security.Principal.WindowsIdentity]::GetCurrent()`'s
     `AuthenticationType` / `IsSystem` / `IsAuthenticated`, plus the Administrator role via `WindowsPrincipal`.
     **Read no environment variable** — see Constraints.
   - End with the literal line `[probe] complete: 3/3 sections`, which is the gate's assertion target.

   Change no existing step's logic, ordering, `if:`, or `continue-on-error` posture.

4. **Commit, then push `build/conductor-0.3.0`.** `ci.yml` triggers on `on: push:` with no branch filter

5. **Read the run** — capture the run's log to `runs/webview2-probe/a11y-job.log` via the `leg = 'operator'` entry, then

6. **Author `evidence/reading.md`** — the recorded reading. For each of the three probes: what the hosted runner
