## Goal

`crates/conductor-report/tests/matrix_ledger_gate.rs` asserts, over every version directory carrying both
ledger files, that `requirements.md` and `verification-matrix.json` declare the same id set, that the matrix's
ids are unique, and that no Pulse `P-NNN` sits in an id position. Its module header (`:13-16`) records that the
version directories are resolved BY SCAN rather than named, because "a baked `conductor-0.2.0` would silently
stop covering the ledger at 0.3.0, which is the failure mode this gate exists to prevent." One line then bakes
the **id space** anyway — `:49` filters `requirement_ids` by `starts_with("v2-")` — so at `conductor-0.3.0`'s
eleven `v3-` ids the required set is empty and the gate's own anti-vacuity assertion fires. The failure the
header claims the design prevents arrives one axis over.

This chunk generalises the id-space predicate so coverage tracks every version on the same basis the directory
scan already does, and `conductor-0.4.0` needs no edit here. It owns the RED workspace gate — 906 run / 905
passed / 1 failed — that landed in `b3b51e6` and was dispositioned not-theirs by the two chunks since.

The predicate is a **lexical shape**, not a prefix list, per the project's standing de-hardcoding ruling: when
the accepted P-ID set outgrew its compile-time `(1..=60)` bound, the operator's ruling was to de-hardcode
rather than substitute the newer literal, "precisely so the next transition needs no edit" (per architecture.md
§Established Decisions [Accepted Capability Set]; test-plan §1 Critical Path 6 and §6 forbid the literal-count
form for the same reason, and §6 Selector strategy states the rule directly — name the SET, because "a new
literal re-stales on the next SUT release"). Substituting `v3-` for `v2-` would reproduce the defect on a
three-month timer; enumerating `{v2-, v3-}` reinstates the class the ruling retired.

The filter is load-bearing and must not simply be deleted: `requirements.md` bolds prose titles beside declared
ids (0.3.0 declares 14 such list items for 11 ids, 0.2.0 33 for 32, and 0.1.0 bolds a title in all 31), and
`requirements.md` is immutable, so the whole repair lives in the gate.

## Constraints & rejected approaches

- **Substituting `v3-` for `v2-`** — rejected: reproduces the identical defect at `conductor-0.4.0` and is the
  literal form test-plan §1 Critical Path 6 / §6 forbid and architecture.md §Established Decisions [Accepted
  Capability Set] retired.
- **Enumerating known prefixes (`v2-` OR `v3-`)** — rejected: a compile-time enumeration of an id space that
  grows with the project, i.e. the same class one step weaker.
- **Deleting the filter entirely** — rejected, and this one is FALSIFIED by measurement rather than by
  principle: `requirements.md` bolds prose titles beside ids, so an unfiltered read admits 3 non-ids at 0.3.0
  and 1 at 0.2.0, and the set-equality arm would fail against matrices that are in fact correct. Basis:
  `grep -c '^- \*\*' conductor-0.3.0/requirements.md` → 14 against 11 matrix entries; 0.2.0 → 33 against 32.
- **Deriving the required set from `verification-matrix.json`** — rejected: collapses a two-source integrity
  comparison into a self-check (per architecture.md §Established Decisions [Accepted Capability Set], the
  standing `check_sut_drift` precedent).
- **Adopting `rstest` for a table-driven predicate matrix** — rejected despite being the test-plan §4 fixture
  pattern: `rstest` is a workspace dependency (`Cargo.toml:81`) but NOT one of `conductor-report`'s
  `[dev-dependencies]` (which carries `assert_fs` alone), so adopting it adds a manifest line and moves
  `Cargo.lock`. The file's own idiom is an inline assertion block (`:250-252`), which costs nothing and keeps
  the zero-dependency-delta property this chunk's acceptance asserts.
- **Adding a `.gitattributes` LF rule for `requirements.md`** — rejected as unnecessary: `str::lines()` strips
  a trailing `\r` and the id is extracted by `strip_prefix("- **")` + `split_once("**")` before end-of-line,
  so a CRLF checkout cannot contaminate an id. Both committed `requirements.md` files are LF-only today. The
  existing rule is scoped to `coverage-matrix.md` because that gate byte-compares a rendered artifact; this
  one parses line-wise.
- **Do not widen scope to the latent `dir.display()` at `:116`** — it is the `label` fallback when
  `file_name()` returns `None`, unreachable in practice for a `read_dir` entry, and it is the file's only
  `display()`. Recorded in research as an observation; fixing it is not this chunk's boundary.
- **Do not weaken, delete or make conditional the anti-vacuity assertion** to reach green.
