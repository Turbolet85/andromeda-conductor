## Goal

The `a11y` CI job's routine arm has never reached its assertions: the hosted runner gives the app no
WebView2 debugging endpoint, and the predecessor chunk established WHY — the mandatory **integrity label**,
not the administrator role, decides whether WebView2 grants one (varied with a control on both sides across
three dev-host legs). It also retired both remedies it built, by mechanism rather than exhaustion:
`RunLevel Limited` cannot lower the label on an account with no filtered token, and `runas /trustlevel`
strips the Administrators group while leaving the label untouched.

This chunk replaces the launch mechanism inside the registered seventh governed spawn form with the one
remedy that can actually move the label — `CreateRestrictedToken` + `SetTokenInformation(TokenIntegrityLevel)`
+ `CreateProcessAsUser` — then **measures on the runner** whether that opens the endpoint, using the ci-probe
the operator authorized for this chunk. The measurement, not an argument, decides which terminal the chunk
closes on: a green routine arm whose printed verdict is asserted (per a11y-plan §11 Anti-Patterns → CI +
test-plan §3 `--e2e`), or the CI half closed as a ratified permanent exclusion resting on the measured cause
and naming its owner. Both arms are legitimate; the plan commits to reaching one, not to which.

Two things research settled that shape the work. **Matrix obligation 2 is dissolved** — the unbuilt console
`contentinfo` footer cannot redden the routine arm, because axe runs only WCAG A/AA-tagged rules and every
landmark-family rule in axe-core 4.12.0 is `best-practice` (68 of 105 rules selected, none of the seven).
The green terminal is therefore not exposed to that second cause. And **the remedy needs no new host**: the
token APIs load from PowerShell 7 through `Add-Type` P/Invoke, so the work stays inside the existing
`scripts/` CI-only script with zero dependency delta (per arch §Infrastructure Patterns — Directory
structure, which bans a new workspace crate for a CI-only mechanism).

## Implementation notes

- **`runs/a11y-e2e.log` is UTF-16 with a `ff fe` BOM** (a PowerShell-redirected capture). `grep` returns a
  silent zero on it, which reads as "the leg never got that far" — decode before concluding
  (`raw[:2] == b'\xff\xfe'` → `.decode('utf-16')`). Basis: `.claude/rules/verification-harness.md:66`,
  measured at `2026-09-11-hosted-runner-endpoint-cause-closed`.
- **GitHub Actions echoes each step's own source into the job log**, so a literal inside a `Write-Output
  "…"` template appears TWICE — once unexpanded in the echo, once for real. Any count over a captured job
  log needs a `| grep -av 'Write-Output'` stage; the tell that a hit is an echo is the unexpanded `$var`.
  Same basis as above.
- **`SE_ASSIGNPRIMARYTOKEN` is not required for this call shape** — `CreateProcessAsUser` needs it only when
  the token is not a restricted version of the caller's own primary token, and `CreateRestrictedToken`
  produces exactly that. `SE_INCREASE_QUOTA` is still needed and is held by the runner's account. Basis:
  the Win32 contract for `CreateProcessAsUser`; the reachability half was measured at P3 (P/Invoke probe:
  `OpenProcessToken` ok, `CreateRestrictedToken(LUA_TOKEN)` ok, `SetTokenInformation` ok). If the runner
  disagrees, the probe's `[precondition]` line names the failing API and its error code — which is a
  measurement for the exclusion arm, not a defect to hide.
- **An integrity level may be lowered, never raised** — so setting Medium on the runner's High token is
  permitted, while the P3 probe (already Medium) could not exercise that direction. Do not report the local
  unit gate as proof of the lowering.
- **Read the token, not the role predicate.** `IsInRole` returns False for a deny-only `BUILTIN\Administrators`
  under a split token, and `.NET`'s `WindowsIdentity.Groups` omits the `S-1-16-*` SID entirely; the witness
  reads `whoami /groups` by ABSOLUTE path for exactly this reason (`.claude/rules/host-win32.md`
  2026-09-16; `scripts/a11y-token-witness.ps1:52-73`).
