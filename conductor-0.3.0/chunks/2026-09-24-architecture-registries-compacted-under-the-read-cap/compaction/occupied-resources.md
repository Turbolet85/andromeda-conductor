## Occupied Resources

**Ports:**
- `127.0.0.1:4317` — OTLP/gRPC **egress target** (Pulse's loopback ingest). Conductor is the client; the port is owned by Pulse, but Conductor must be co-located with it. The port-occupier fault scenario also binds `:4317` to exercise Pulse's reaction.
- `:4318` (OTLP/HTTP) — not used; gRPC-only loopback is the pinned path.
- `https://msedgedriver.microsoft.com` — **CI-JOB-SCOPED egress**, the project's only non-loopback outbound target and the only registered one no shipped binary reaches (operator-ratified; the non-loopback egress count is ONE). `.github/workflows/ci.yml`'s `a11y` job fetches the msedgedriver build in its `Pin msedgedriver to the image's WebView2 runtime (gate)` step — UNCONDITIONALLY (the gate carries no `if:`), HTTPS with certificate verification intact — at the version DERIVED from the image's own WebView2 runtime registry reading, and admits the download only through a pre-execution `Get-AuthenticodeSignature` gate (status `Valid` AND an `O=Microsoft Corporation` signer). It binds no port; the loopback-only client model holds unchanged for every shipped binary and every dev-host harness leg.
- No inbound listener of Conductor's own **in the shipped binaries** (no API port, no DB port — SQLite is embedded/in-process, no frontend dev-server port — the Tauri webview is bundled **when built with `--features tauri/custom-protocol`; a bare `cargo build --release` loads `devUrl` (`http://localhost:5173`) instead, occupying no port of Conductor's own either way** — see §Infrastructure Patterns — Build system).

- `contracts/pulse-load-envelope.toml` — the pinned SUT load envelope: the proven-good storm bounds a scenario must stay inside (`sut_version` · `captured_at` · `provenance` · an `[envelope]` table · an `[[exempt]]` ledger of `{scenario, reason}`). Its terms are a **transcribed SUT record, never a Conductor measurement**, which the `provenance` field states so a reader can tell how far to trust them. Runtime-read and bounds-checked at load; resolved from a fixed `LoadEnvelope::default_path()` through `resolve_under` with deliberately NO `CONDUCTOR_*` override handle (the capability-manifest precedent). The **two sustained terms are the asserted ones**, judged PER EMITTING PHASE: no phase declaring occurrences may run longer than `max_sustained_storm_ms` nor emit faster than `max_sustained_rate_spans_per_s`. **The rate term counts WIRE RECORDS, and is an upper BOUND:** `phase_rate_exceeds` judges `occurrences × EmissionSpec::max_spans_per_dispatch() × 1000 > max_rate × gap_ms` (`conductor-core/src/load_envelope.rs`), exact integer math with no division. The per-dispatch count is measured PER `EmissionShape` arm against the dispatcher's own arm — `Ramp`/`Breathing` emit `sum(window_counts)`, `Latency` its `samples`, `Error` `depth + 1`, `Pii` 2 spans on traces or one record per category on logs, `Topology` one span per service, every other shape 1. It is a BOUND rather than an exact count because the rate curves' per-window counts carry seeded jitter (`conductor-emit/src/rate.rs`, ±15 %) while the static catalog gate has no seed, and a ceiling is the conservative direction for a load bound. Under the shipped mapping the catalog's worst case is `halo-breathing-encoding` at ~232 records/s, ≈43× under `max_sustained_rate_spans_per_s = 10000`. The term keeps its name and its value because it transcribes a SUT record about wire load. `max_scenario_duration_ms` is **recorded but no longer asserted** — elapsed time is not storm time. `check_load_envelope` (the static catalog gate) and `LoadEnvelope::classify` (the per-run judgment behind the `[ENVIRONMENT-SUSPECT]` caption) read ONE shared basis BY CONSTRUCTION — `phase_rate_exceeds` has exactly one caller, `phase_breach`, whose only two callers they are — so the gate and the caption cannot mean different things. The `[[exempt]]` ledger — held at exact-set equality in both directions, so it can only shrink under compulsion — is **empty**: every catalog scenario passes the asserted terms unaided. The storm term bounds the longest single emitting window, never the SUMMED emitting-phase duration: summing disjoint bursts separated by quiet is not *sustained*.
- `contracts/pulse-run-contract.toml` — the pinned Pulse run contract: the launch conditions under which a live Pulse can be verified at all (`sut_version` · `captured_at` · `provenance` · an `[incident_formation]` table of the harness's own obligations · a `[[term]]` list of `{id, statement, check, env?, posture?, causes}`). Runtime-read and bounds-checked at load; resolved from a fixed `RunContract::default_path()` through `resolve_under` with deliberately NO `CONDUCTOR_*` override handle (the capability-manifest precedent). - `CONDUCTOR_SCENARIOS_DIR` — overrides the default `scenarios/` config directory.
- `CONDUCTOR_CONTRACT_MANIFEST` — overrides the default pinned MCP contract manifest path under `contracts/`.
- `CONDUCTOR_SEED` — seed override for headless runs (equivalent CLI flag on conductor-cli takes precedence; env supports scripts/agent-run.sh parameterization).
- `CONDUCTOR_SERVICE_NAME` — overrides the self-observation `service.name` field (default `conductor` / `conductor-tauri`); obs-plan §3.
- `CONDUCTOR_ENV` — self-observation `deployment.environment` field (default `local`); obs-plan §3.

Set by the `--agent-mode` CLI flag OR exported by `scripts/agent-run.{sh,ps1}`; Conductor READS it (`agent_mode = flag || env-set`) and main never WRITES it — avoiding edition-2024 `unsafe std::env::set_var` — so the observable mode matches obs-plan §3 without the write. obs-plan §3.
- `CONDUCTOR_PREFLIGHT_TIMEOUT` — preflight readiness-gate timeout in seconds (default `30`), read by `scripts/agent-run.{sh,ps1}` `boot` wrapping `conductor preflight`. **`boot` runs `conductor preconditions` as a LEADING arm and short-circuits on non-zero, so the preflight invocation — and therefore this timeout — is SKIPPED rather than paid on an unmet precondition** (the skip is told from a failure by the absence of `ReadyState` JSON). **That skip is CONDITIONAL: it fires only on a genuinely unmet subject** (§Standard Contracts — Liveness equivalent); under a satisfied environment the timeout is REACHED and PAID (~47s wall-clock in both shipped shells, as measured at `conductor-0.2.0/chunks/2026-09-04-preconditions-probe-reads-path-handles-by-presence/report.md`). Invoking `conductor preflight --json` directly remains a valid entry point, not a required workaround. The run contract raises it to an effective FLOOR (`[incident_formation].min_canary_poll_seconds`), because the bare default is shorter than Pulse's own L3 digest cadence; the env handle still overrides upward.
- `CONDUCTOR_MSEDGEDRIVER` — the operator-owned native-WebDriver path the webview a11y leg hands to tauri-driver via `--native-driver`. Read ONLY by `crates/conductor-tauri/ui/wdio.conf.ts` (never by a shipped binary) — the ONE config all three suite families fire, so it gates the routine `--e2e` arm, the operator-local `a11y:driven` arm and the `sr*` screen-reader suites alike — never written by Conductor, and never interpolated into a shell: it is validated at the harness edge (existence + `isFile` + shell-metacharacter rejection) and passed as a separate argv element of an array-form spawn. Unset — or not an existing file — the requesting arm **SKIPs at exit 0** with a host-path-free precondition plus a fetch recipe; under an affirmative `CONDUCTOR_A11Y_STRICT` it exits NON-ZERO instead, because a CI gate that can pass by skipping is banned. With `CONDUCTOR_NVDA` one of the TWO handles in this namespace naming a HOST dev-tool this document does not define, both validated and spawned the same way, so neither value is ever committed.
- `CONDUCTOR_NVDA` — the operator-owned path of a PORTABLE NVDA executable the screen-reader leg starts and quits around the driver (`startNvda` / `stopNvda` in `crates/conductor-tauri/ui/wdio.conf.ts`, the ONLY reader — never a shipped binary). Validated at the harness edge exactly like `CONDUCTOR_MSEDGEDRIVER` and used only as the program of an array-form, detached spawn with a fixed argv (`-m --no-sr-flag -c <leg config dir> -l 12 -f <leg speech log>`, then `-q`), never interpolated into a shell. Unset — or not an existing file — the `sr` / `sr-empty` / `sr-error` suites **SKIP at exit 0** with a host-path-free precondition plus a fetch recipe naming the handle, never its value; both skip sites route through one `exitUnresolvedHandle()`, so an affirmative `CONDUCTOR_A11Y_STRICT` makes it exit non-zero too. The value is never logged, echoed into an artifact, or committed.
- `CONDUCTOR_E2E_SEED_DIR` — the repo-relative fixture runs dir the webview `--e2e` arm seeds its subject into. SET by `crates/conductor-tauri/ui/wdio.conf.ts`'s `onPrepare` to a harness-owned constant; READ only by `crates/conductor-run/tests/envelope_fixture.rs`, never by a shipped binary. The THIRD handle class in this namespace: the value is not operator-supplied, so no `isFile` / shell-metacharacter guard applies, and it never reaches the `conductor-cli` `canonicalize` edge — the repo-relative discipline lives at the wdio caller. Unset, the seeding test is a **no-op**, so an ordinary `cargo nextest` / `cargo test` run never writes into the repository. Unlike `CONDUCTOR_MSEDGEDRIVER` / `CONDUCTOR_NVDA`, which name HOST dev-tools, it names a path this document defines.
- `CONDUCTOR_A11Y_STRICT` — the CI strictness flag that inverts the a11y leg's unresolved-handle behaviour. **A FOURTH handle class:** FLAG-valued (affirmative `"true"` / `"1"`, mirroring `conductor_core::flag_declared`), never a path, so neither the `std::fs::canonicalize` rule nor the wdio-edge `isFile` + shell-metacharacter guard applies. Unset or falsy, the leg keeps its skip-at-exit-0 so an unconfigured dev host is never read as a defect; affirmatively declared, an unresolved `CONDUCTOR_MSEDGEDRIVER` / `CONDUCTOR_NVDA` exits NON-ZERO, which stops the CI a11y gate reporting success by skipping. - `ANDROMEDA_PULSE_MCP_ENABLED` — Pulse-side flag that gates the live MCP read-back path (operator/local gate); asserted **not** set by Conductor itself. Conductor READS it in its own environment as the run contract's SECOND `shell-declaration` term (`mcp-enabled`) and as one of the three `ANDROMEDA_PULSE_*` declaration subjects `conductor preconditions` observes. The probe REPORTS name-only (a finding names handles, never values) and GRADES per handle by kind: this flag and `ANDROMEDA_PULSE_L4_DETERMINISTIC` by the truthy `"true"`/`"1"` gate (`conductor_core::flag_declared`) under the deterministic posture — under the real-model posture the L4 handle is graded for ABSENCE (its entry below) — and the PATH-valued `ANDROMEDA_PULSE_DATA_DIR` by presence-after-trim (`conductor_core::handle_declared`), so all three subjects are meetable (§Standard Contracts — Liveness equivalent). An absent declaration of THIS handle is named upstream as an unmet contract term AND at the probe: `ANDROMEDA_PULSE_MCP_ENABLED=false` leaves `handles-declared` naming that handle alone.

Asserted **not** set by Conductor itself; Conductor READS it in its own environment — the shell that launches Conductor is the one that launches `pulse-app` — under BOTH L4 postures (2026-09-22).
