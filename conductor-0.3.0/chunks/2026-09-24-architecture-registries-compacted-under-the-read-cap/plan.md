   **The sentence splitter (shared by `ledger-init` and arm (f)).** It splits a section's text into sentences. The
   boundary is `.`, `;` or `:` followed by whitespace, never inside a backtick span; bullet and paragraph breaks are
   boundaries too. Each sentence is normalized (whitespace collapsed, trimmed), and its id is the first 12 hex of the
   blake2b digest of the section name, a NUL byte, then the normalized text. The splitter only has to be DETERMINISTIC, not linguistically
   right: `ledger-init` and arm (f) share it, so they always agree on the sentence set. The split counted

   - `ledger-init --before-rev REV --out PATH`: writes a ledger skeleton to a repo-relative PATH: one
     `[[sentence]]` table per BEFORE sentence of both sections, carrying `id`, `section`, `head` (the first 72
     characters, for orientation) and an empty `disposition`. It refuses to overwrite an existing file (exit 2).
   - `ledger-show --before-rev REV --drafts DIR [--judgment]`: report-only; always exits 0 when its inputs resolve.
     It prints each ledger row's full BEFORE sentence (recovered from REV by id) beside its disposition target: the
     AFTER anchor, the sidecar entry heading, or `kept` / `moved`. `--judgment` limits the output to the judgment
     rows. The last line is the tally.
   - `measure (--rev REV | --file PATH)`: prints one line per section with its bytes, estimated tokens, percent
     of cap and `within target` / `OVER target`.
     - Last line: `registries: within target` or `registries: OVER target`.
     - Exit 0 / 1 to match.
   - `status --drafts DIR`: report-only; always exits 0.
     - Per section, prints the working-tree master's bytes, the draft's bytes, and
       `applied: yes|no` (byte-equality of the master's section with the draft file).

     sections replaced by `DIR/established-decisions.md` and `DIR/occupied-resources.md`. Each draft file starts
     with its own `## ` heading. It then reports every finding under six arms:

     - **(b) labels** — the ordered list of `- **[Label]` decision labels and `**Label:**` sub-registry labels,
       derived from BEFORE, appears in AFTER byte-identical, in the same order, each exactly once.
     - **(c) registry names** — the body must keep every name. The name set is derived from BEFORE:
       - every Occupied Resources bullet's leading backtick span (the registered handle / artifact / port);
       - every `conductor-*` crate name;
       - every `host:port` / `:port` token.

       Each one appears in the AFTER section it came from. On top of that, every qualifier phrase in the
       script's closed `QUALIFIERS` tuple that a BEFORE bullet carries is still carried by the AFTER bullet of
       the same leading handle. The tuple's contents are listed in Implementation notes.

       one of: the AFTER sections, the `REV` sidecar, or `DIR/moved-history.md`. This is a FLOOR, not the
       no-fact-lost proof. Measured at P5 (run dir `armd-reach.py`, HEAD `f0d92bd`): 247 of 356 / 271 of 406 distinct

       span at all. So (d) alone would pass a body that lost most of its prose. Arm (f) carries the proof.
     - **(e) hygiene** — no drafted file carries a host path: a drive-letter path (`X:\` or `X:/` not followed by
       `/`, so an `https://` scheme is not a hit), `/Users/` or `/home/`.
     - **(f) disposition ledger** — `DIR/disposition-ledger.toml` must carry exactly one row per BEFORE sentence:
       set equality between the splitter's ids and the ledger's ids, so no missing row, no extra row, no duplicate.
       Each row carries exactly one disposition, and each disposition is checked as follows:
       - `kept` — the normalized sentence occurs verbatim in the normalized AFTER section it came from.
       - `moved` — it occurs verbatim in normalized `DIR/moved-history.md`.
       - `in-sidecar` with `marker = "M"` — the `REV` sidecar has at least one entry headed `## M — …`, and every
         backtick span of the sentence occurs inside the text of those entries (their union), not anywhere in the
         sidecar. A marker can head several entries: 12 do at HEAD, per
         `grep -oE '^## [0-9]{4}-[0-9]{2}-[0-9]{2}-[a-z0-9-]+' architecture-amendments.md | sort | uniq -c`. Of the
         110 `## ` headings, 107 are marker-shaped (`## M — …`), and only those can be named. A span-less sentence
         passes on the entry's existence alone. The row is then flagged `judgment` in the output.
       - `rewritten` with `anchor = "…"` — the anchor (≥ 24 characters, verbatim) occurs in the AFTER section the
         sentence came from, and every span of the sentence that is in arm (c)'s registry-name set also occurs in
         that AFTER section. The row is always flagged `judgment`: whether the rewrite is faithful is a reading,
         not a predicate.

       No other disposition exists. In particular there is no `dropped`: history moves or is already in the sidecar,
       and current truth is kept or rewritten. `check` also prints the judgment tally, `judgment rows: N
       (rewritten R · span-less in-sidecar S)`, as the line before its verdict.

     Output and exit:
     - Each finding names its arm, the section and the offending NAME, never a filesystem path.
     - Last line: `arch-registry-check: PASS` or `arch-registry-check: FAIL (N findings)`, with N the finding count.
     - Exit 0 / 1 to match.

     - pad §Established Decisions past the threshold (size);
     - rename its first label (labels);

     - disposition ledger, three sub-mutations, each of which must be detected:
       - delete one ledger row;
       - flip a row whose sentence is absent from AFTER to `kept`;
       - repoint one `in-sidecar` row carrying a span to a marker whose entry lacks that span. Pick it from the
         real ledger; if no row qualifies, the selftest SYNTHESIZES one against the first sidecar entry whose text
         lacks the sentence's first span.

     It asserts that `check`'s logic reports each mutation under the right arm.
     - Last line: `selftest: every arm detected` or `selftest: ARM NOT detected` naming the arm.
     - Exit 0 / 1 to match.

   Input handling:
   - `REV` must match `^[A-Za-z0-9_.~^/-]+$` and is read by `git show REV:PATH` (PATH the hard-coded subject) as an argv list, never
