## Goal
`scripts/mutation-gate.py` today grades one tally, `missed.txt`. It reads `caught.txt` only to print a count and never
opens `timeout.txt`, so a caught→timeout regression passes it silently (`:137-142`; test-plan §12 `:619` records the
gap). This chunk makes the gate grade EVERY tally the verdict rests on. It adds four arms:
- `timeout.txt` compared, as a coordinate-free multiset, against a new timeout class in `scripts/mutation-roster.toml`,
  keyed exactly as `missed` is (per test-plan §4 Mutation instrument; §12 roster member IDENTITY).
- Each tally file's parsed line count held equal to the tool's own count in `outcomes.json`.
- The four counts held summing to `total_mutants`. So a truncated tally, an unparsed line or a mutant absent from every
  tally can no longer pass unseen. `unviable` enters only these counts and is never rostered: it moves on host link
  contention alone (per test-plan §10 Zero-flakiness budget).
- A missing tally file fails closed (per security-plan §Input Validation's fail-closed model).

The grading moves into a function that takes a tally directory and a roster path, so it can be proven WITHOUT a
mutation run. A new `selftest` verb drives it over committed synthetic fixture trees, one arm per verdict path, and
asserts each arm's verdict, its named finding and its finding count. This is the project's precedent for proving a
Python operator instrument (`arch-registry-check.py selftest`, research §Patterns). The gate stays operator-local:
no CI step invokes it and it adds no sixth `agent-run` command (per architecture §Stack and Technologies "Operator
instruments" row; test-plan §9 Scoped mutation audit).

No conductor-emit timeout row ships. Timeout identity collides within a helper (research §Patterns), and the raw tally
that could key the fifteen is gone. A roster row rests on a measured tally, so the next epoch-boundary audit seeds them.
Until then its `mutation-gate.py conductor-emit` run FAILs closed with one `TIMED OUT, not in roster` line per
timeout, and that failure is the measured input the rows are written from.

3. **The grading function** (`scripts/mutation-gate.py`, replacing the inline block `:125-153`).
   - Signature: a tally directory, a unit and a roster path in; a verdict and the list of lines to print out. `main()`
     prints the lines, so `selftest` can read the same lines without a subprocess.
   - `parse_tally`'s `  UNPARSED: {line}` notice (`:54`) joins that returned list instead of going straight to stdout.
     The text is unchanged, so an unparsed line is one of the grade's indented findings.
   - It performs, in order:
     a. **Completion** — the existing `complete()` markers, unchanged in logic. A failure ends grading with
        `MUTATION GATE {unit}: FAIL — tally not readable`.
     b. **Empty population** — `total_mutants == 0` ends with the existing `0 mutants generated; a no-op run is never a
        pass` FAIL.
     c. **Presence** — `missed.txt`, `caught.txt`, `timeout.txt` and `unviable.txt` each exist. An absent one is a
        finding `  TALLY MISSING: {name}`. Today `parse_tally` returns an empty Counter for an absent file (`:45-46`),
        which is what lets a missing tally read as clean.
     d. **Per-class count** — each present file's PARSED line count (the Counter's total, so an `UNPARSED` line drops
        out of it) equals `outcomes.json`'s `missed` / `caught` / `timeout` / `unviable`. A difference is
        `  COUNT MISMATCH {class}: {name} has {n}, outcomes.json says {m}`.
     e. **Conservation** — `outcomes.json`'s own `missed + caught + timeout + unviable == total_mutants`. A difference is
        `  NOT CONSERVED: missed+caught+timeout+unviable = {s}, total_mutants {t}`.
     f. **Missed multiset** — the existing `SURVIVED, not in roster` / `ROSTERED, did not survive` lines, byte-unchanged.
     g. **Timeout multiset** — `  TIMED OUT, not in roster (x{n}): {f}: {m}` and
        `  ROSTERED, did not time out (x{n}): {f}: {m}`.
   - Steps c-g COLLECT every finding before the verdict; they do not stop at the first.
   - The summary line becomes
     `missed {m} · caught {c} · timeout {t} · unviable {u} · total {T} · expected missed {em} · expected timeout {et}`.
   - The verdict line stays `MUTATION GATE {unit}: PASS` / `MUTATION GATE {unit}: FAIL`, and it is last.

6. **`selftest`** (`scripts/mutation-gate.py`, a new function).
   - It reads `{DIR}/arms.toml`. Each `[[arm]]` carries `name`, `unit`, `verdict` (`PASS`/`FAIL`), `contains` and
     `findings` (the count of two-space-indented lines the grade must print), plus an optional `roster` file name
     under `DIR` (default `roster.toml`).
   - For each arm it grades `{DIR}/arms/{name}/` against that roster. The arm is DETECTED only when all four hold:
     - the verdict matches;
     - some printed line contains `contains`;
     - the indented-line count equals `findings`;
     - no printed line carries the absolute `ROOT` path, in either slash form.
   - It prints `  {name}: detected` or `  {name}: NOT detected — {which condition failed}`.
   - It then validates the REAL `scripts/mutation-roster.toml` through the same loader and prints
     `  real roster: {n} rows, schema ok`, or a NOT-detected line naming the defect.
   - Last line: `selftest: every arm detected` (exit 0) or `selftest: ARM NOT detected — {names}` (exit 1).
   - It spawns no process and writes no file.
