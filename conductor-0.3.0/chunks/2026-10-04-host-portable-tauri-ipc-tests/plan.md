## Goal
Make `conductor-tauri`'s mock-runtime IPC tests host-portable: the same test source passes on the Linux dev host and
on Windows CI, with no test skipped, `#[ignore]`d, `cfg`-excluded or retried. Today two `#[cfg(test)]` sites build an
`InvokeRequest` with the Windows-only literal `http://tauri.localhost` (`commands.rs:417`, `pause.rs:243`). Tauri
treats a request as local only when its scheme and domain match `tauri_protocol_url`, and that is `http://tauri.localhost`
on Windows/Android but `tauri://localhost` everywhere else (tauri 2.11.3 `manager/mod.rs:339-346`,
`webview/mod.rs:1698-1706`). So on Linux every dispatch resolves as a REMOTE origin and the ACL refuses it with
`"<cmd> not allowed. Plugin not found"` (research.md §The mechanism).

The literal reaches nine tests. Six fail on Linux (named in research.md, measured `20 passed, 6 failed`). Three more
— the `invoke_expecting_error` callers — PASS VACUOUSLY on Linux, because the ACL denial is itself the non-empty error
they assert. The fix therefore has two halves: derive each request's origin from the window it is dispatched to,
which the mock resolves through the same `get_app_url` → `tauri_protocol_url` path `is_local_url` checks against
(research.md §The equality); and make the error-expecting path refuse an ACL denial as its error, so a wrong origin can
never again satisfy a mutation-killing error test. A new host-independent test pins the other direction: a foreign
origin is still refused on every host, so the origin check is made correct and never made irrelevant (per
security-plan §Threat Model Summary → Attack surface, Tauri IPC; test-plan §11 Mocking "NEVER over-stub").

Test code only: no production command, capability file, `tauri.conf.json`, frontend, manifest or lock change (per
architecture §Established Decisions → [Module Boundaries]; security-plan §Security Anti-Patterns → Code Patterns), and
no new CI job — CI stays Windows-only and the Linux leg is this dev host (per test-plan §9 Matrix builds; architecture
§Infrastructure Patterns → CI/CD approach).

## Constraints & rejected approaches
- A `cfg!(any(windows, target_os = "android"))` literal pair (tauri's own doc example, `test/mod.rs:216-223`) — rejected:
  it restates the framework's per-OS rule by hand and silently rots if Tauri moves it; the window's URL is the value
  `is_local_url` is checked against, by construction.
- Widening `capabilities/*.json`, adding a remote/URL scope, or any origin-agnostic dispatch — banned (security-plan
  §Security Anti-Patterns → Code Patterns; scope §Boundaries): the tests must still fail on a wrong origin.
- `#[ignore]`, `#[cfg(windows)]` on a test, a skip, or nextest `retries` — banned (test-plan §10/§11; scope §Boundaries).
  The `#[cfg(windows)]` precedent in `conductor-verify` (2026-09-04) is a Windows-only FLAG's test, not a template here.
- Moving `request()` to a shared `pub(crate)` test-support module so `pause.rs` can call it — not needed: each site holds
  its own window, and the single source is the mock webview's URL itself.
- Keying the step-3 guard on `"Plugin not found"` alone — rejected: that suffix names the not-found-plugin branch of one
  denial shape; `"<cmd> not allowed"` is the prefix every ACL refusal of an app command carries (`ipc/authority.rs:356,
  409, 414, 432`).
- Any production-code change, dependency, Linux CI job or new env handle — out of scope (architecture §Occupied
  Resources; test-plan §9 Matrix builds).

## Implementation notes
- The equality the fix rests on (research.md §The equality): for `mock_context(noop_assets())` (`build: Default`, no
  dev/dist URL) and a window at `WebviewUrl::default()` (= `App("index.html")`), the mock webview's URL is
  `get_app_url(false)` → `tauri_protocol_url(false)` (`manager/webview.rs:443-458`, `manager/mod.rs:353-365`), stored
  verbatim and returned by `url()` (`mock_runtime.rs:210, 609-611`). Both test sites build their window that way
  (`commands.rs:403-407`, `pause.rs:230-232`). If `window.url()` ever disagrees with what `is_local_url` accepts, the
  six tests fail loudly — never a silent pass.

  path-resolution / manifest-read failure (comments at `commands.rs:667-670, 683, 696-698`), none of which renders the
  `"<cmd> not allowed"` prefix. A trip there is a finding to report, never a reason to loosen the key.
