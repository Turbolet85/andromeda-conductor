## Test Commands
- **The live round** is the block's `round` and `live` entries, fired by `gate.py run --live-legs --entry N`, one
  drive at a time (step 12). The wrap never re-runs it; it re-verifies from `evidence/`.

  canary. There is no `boot` before any drive: it would prime the incident the drive's own canary dedupes against

  ledger: the Pulse git probes, the old-side control, the builds, the new-side control, the dir listing, the env
  checks. `pulse-app` is launched between them and the round (step 11); the agent starts it and stops it, inside
  the operator's grant.

  asserting entry passes when the rebuilt `pulse-app` no longer hashes as the recorded `f70be92` build and both
  binaries' mtimes follow `9bfefb8`'s commit time. Over the `f70be92` builds on disk it prints the old digest and
  exits 1 (measured at P4). It asserts no named token, because none exists (research.md §The binaries on this

  Pulse's own log, as every prior series' ledger was. The criteria that read it are held by the harvest

- **Night rule:** only the three `live` entries are GPU runs. Every other entry runs at any hour.
- **Pulse builds and binary probes** run in the Pulse tree inside a subshell `cd`: cargo reads its config from the
  cwd, and the session's Bash guard passes a subshell `cd` and blocks a top-level one.
- **Host paths:** every Pulse binary probe runs from inside `target/release` with bare file names; the model digest
  entry prints the digest alone. Nothing an entry prints names a host path beyond what the gate tool respells.
- **Controls owed at implement** (red before green, one-shot): step 13's `measured` table. Its readings go to the
  report.
- **The operator pass** (hygiene, the pre-CI commit, the guarded push, the CI read) is the operator's. The agent
  performs it only on the operator's explicit word, and records it as made on that word.
