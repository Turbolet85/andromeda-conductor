## Goal
Retire what intent R1 lists, outside the removed crate, as "types shaped for the panel" (`intent.md:88-90`). The
run-event channel payload (`RunEvent` / `RunStage`), the desktop framing of the envelope read, the picker-only
selection guard (`SUITE_SELECTION` / `validate_selection`), the dialog-row justification of the checklist bound,
the Tauri log-sink text and the two webview fixtures all leave. A type that still serves a function is re-framed
for the command line, never kept for a panel (per architecture §Design Philosophy "Headless-drivable core, thin
shell").

Then give the four functions that lost their only entry point when the window left (the CARRY,
`2026-10-11-conductors-window-retired/research.md` §Function reach) a command-line entry. Each is a thin
`conductor-cli` surface over an existing library function, so nothing is left unreachable (`inputs#I2` §2):
- **The catalogue listing.** A new verb, `conductor scenarios`, named by the operator (`inputs#I3`). It runs over
  `conductor_core::list_scenarios` and the manifest-checked load `run` / `suite` already use (per architecture
  §Established Decisions [Accepted Capability Set]).
- **A graceful mid-run stop.** The first Ctrl-C during `conductor suite` lets the running scenario finish and keeps
  every finished record. A second Ctrl-C ends at once. A stopped suite exits 130 (`inputs#I3`). `suite` now drives
  through `conductor_run::drive_run`, whose abort flag had no CLI caller.
- **A past run's load-envelope standing.** `conductor report` prints the stored `[ENVIRONMENT-SUSPECT]` caption above
  its table, read through `conductor_run::read_envelope` (per layout-templates §Output structure).
- **A hold's `[[checklist]]` items.** These print as indented lines under the CLI `HOLD` line (per layout-templates
  §Component — Primary content block 2, the indented-detail-line precedent).

Nothing Conductor reads of Pulse moves (`inputs#I2` §4). The read-back, preflight and emission paths are outside the
write set (research.md §Files to modify). No listener, handle, place on disk or credential is added (per
security-plan §Security Anti-Patterns → Universal; architecture §Occupied Resources).

## Constraints & rejected approaches
- A `conductor stop` verb or a stop file — rejected: it needs a second process to reach the running one, either a
  socket, pipe or listener (security-plan §Security Anti-Patterns → Universal) or a new place on disk (`inputs#I2`
  §3).
- A `--envelope` flag on `report` — rejected: the run-level caption already prints by default on `run` / `suite`.
  A flag would fork one qualifier into two forms (layout-templates §Component — Primary content block 2: "adapted
  per surface, never forked").
- Deleting `drive_run` and keeping `suite`'s own loop — rejected: the loop has no abort poll, and test-plan §5's
  in-process parity arm needs a library composition. Re-using `drive_run` gives the stop and the arm one home.
- Deleting `read_envelope` — rejected: it is the reader CARRY item 3 needs.
- Dropping the checklist bound or switching `checklist` to `#[garde(skip)]` — banned (security-plan §Security
  Anti-Patterns → Input).
- A `db.*` read span or a new log attribute for the listing or the report read — banned (obs-plan §11 Spans; the
  `message` field precedent).
- A seventh lamp, a new bracket label or a new ANSI code for any new output — banned (layout-templates §Component —
  Primary content block 2).
- Touching `conductor-verify`, `conductor-emit`, `canary.rs` or `execute.rs` — out of bounds (`inputs#I2` §4).
- `libc::kill` through a `libc` dev-dependency for the SIGINT test — not taken: the call is an `unsafe` FFI call,
  and the security rules say never to add `unsafe` across an FFI boundary without review. The fixed-argv `kill`
  spawn needs neither the dependency nor the `unsafe` (`inputs#I4` (1) offered both).
